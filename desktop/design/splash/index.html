Selenite · 启动页 四版

lifediary-harness / desktop
2026-11-14

现在壳里那张 connectingPage 只有一行「正在连接 lifediary 服务」和一个脉冲小蓝点， 底色写死 #0f1115——而业务页默认是纸白 #fdf9f2。 于是每次启动都这样：黑屏几秒 → 忽然一片白，中间没有任何「它在动」的证据； 等超过 10 秒（首次编 tsx 很常见），用户分不清是慢还是死了。 四版都想解决这两件事：别闪、让人知道它还在跑。信息源不造假——只给「已等几秒、探测几次、走到哪一步」。

看哪种状态
下面的画面是活的：动画在跑，秒数在走。切换会重新加载四个窗口。
A

冷光

石头被点亮

把首页题头那枚水晶搬上来，呼吸 + 一道冷光扫过晶面；主线是不确定进度的墨线，不冒充百分比。 代价：比现在多一张 512 图（已裁透明边），要么随壳打包，要么内嵌成 base64。

B

题头

一张纸，一句话

没有图形，只有纸、一行宋体、一道从 0 长到满的铜线。元素最少，最不像「程序出错」，切进业务页几乎无跳变。 代价：品牌感最弱，慢启动时可看的信息也最少。

C

夜航

唯一的黑场

深靛开场：光环呼吸、一小段弧绕石头转。取色就是 indigo 主题，所以从这张脸切进深色业务页是连续的。 代价：只配深色主题；默认纸白主题下用它会「黑一下再白」，正是现在要消灭的那种闪。

D

轨道

四步，一目了然

左边四步对应壳里真实发生的四件事，右边是这几秒里值得看的日志。卡住时能一眼看出卡在哪一步。 代价：信息密度最高、纸感最弱；日志栏想真有用，得让壳把服务的前几行吐过来。

怎么选

维度A 冷光B 题头C 夜航D 轨道
第一眼认得出是 Selenite安静、像书扉页有仪式感，最抓眼像仪表台，最快理解
慢启动时好：多一行解释一般：只能说「再等会儿」好：动画本身耐看最好：卡在哪一步写出来
与主题一致纸白 / 白 都行纸白 / 白 都行只配 indigo / black纸白 / 白 都行
实现成本低（一张图 + 一个遮罩）最低（纯文字）中（SVG 弧 + 三层动效）中高（要壳推步骤）
最坏情况图没打进去就是一块空白太素，被误读成加载失败浅色用户被黑一下步骤是假的就变成撒谎

一、不再闪

底色跟主题走，默认纸白。三版共用同一个 40px 自绘标题栏（同一个 --backdrop、同一个品牌字位），切进业务页时只有内容区变。

二、进度不造假

没有百分比。只有「已等 N 秒 / 探测 M 次」这种能对得上的账，加一条不确定进度的墨线。超过 9 秒换成解释句，不动布局。

三、壳要推状态

现在这张页是死的：LoadHTML 之后只能干等到 waitHealthy 返回。要做 A/C 的换句、D 的步骤，得让 loadService 在探测间隙 Page.Eval 推一次 phase。
