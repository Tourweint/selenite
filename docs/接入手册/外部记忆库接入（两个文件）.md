# 外部记忆库接入（两个文件）

**日期**：2026-11-23
**适用**：Lifediary 设置 → 注入 → 索引 → 「记忆库」卡（2026-11-24 起恒在；旧总闸 `MEMORY_BANK` 已删除）
**契约来源**：`docs/设计方案/2026-11-23-外部记忆库接入边界（一读一写·两文件）.md`

你只需要提供**两个入口文件**：读入口 `ask`（查）和写入口 `repair`（写）。Lifediary 不打开你的
数据库、不跑 SQL、不知道表名——它只起进程、传 argv、读 stdout。

> **入口不限语言**（2026-11-23）：文件名固定为 `ask` / `repair`，扩展名决定运行器——
> `.py` → `python`（`PERSONA_PYTHON`）、`.js`/`.mjs`/`.cjs` → node、`.sh` → bash、
> `.ps1` → powershell、其他或无扩展名 → 直接执行该文件（需可执行 / 有 shebang）。
> 下面的例子都用 Python；换成 `ask.js` 只是换运行器，契约一字不改。
> 界面「操作手册」里的同一段说明可直接复制。

## 一、目录形状

```text
my-memory-bank/
  ask.py      # 读：检索 + 库边界（也可以叫 ask.js / ask.sh / ask.exe / ask）
  repair.py   # 写：一张表（可选；没有 = 只读库）
  data/...    # 你自己的库文件，随便放
```

- 读入口查找顺序：`<root>/ask.<ext>` → `<root>/analysis/ask.<ext>`；扩展名按
  `.py → .js → .mjs → .cjs → .sh → .ps1 → .exe → 无扩展名` 依次找，先命中先用。
- 写入口只找读入口**同目录**（同名规则）；没有它 = 这个库只读（切过去后 `remember`
  会明确回「写入未开启 / 这个库只读」，不会退回原生库）。
- 子进程的**工作目录 = 库根目录**，入口里写相对路径没问题。
- root 必须是**绝对路径**且存在；入口解析后必须仍在 root 内（`..` / 软链逃逸会被拒）。
- Lifediary 界面上选目录 → 「检测」→「接入」→「切换到外部」。检测会真跑一次
  读入口 `--catalog-only`，跑不通就不让接入。

## 二、读入口契约

### 2.1 检索

```bash
python ask.py <question> --json --limit <N> [--vector]
```

- 用 argv 数组调用，**不经 shell**；`question` 是用户问题原文。
- **两种模式**：不带 `--vector` = **普通检索**（默认，与旧版逐字节相同）；带 `--vector` = **向量检索**
  （`--vector` 是可选布尔开关，2026-11-24 命名统一前叫 `--deep` / 深检索，已改名）。
- `--vector` 只出现在 argv **末尾**：Lifediary 只在接入时勾了「支持向量检索（这个库理解 `--vector`）」
  才会附加。它的语义是「这一路检索**走向量召回**」——Lifediary 不承诺、也不感知库内具体怎么做
  （embedding / 重排 / 混合召回都行），只负责把请求传下去。
- 旧库不认识 `--vector`：Python `argparse` 会以**退出码 2** + usage / `unrecognized arguments` 到
  stderr 拒绝。**harness 会自动兜底**：命中这个特征时去掉 `--vector`、用同一命令重试一次**普通检索**，
  结果照常返回并在日志里留一行「库不认识 --vector，已改用普通检索」（结果对象带
  `vectorUnsupported:true` 标记）。**只重试一次**；超时不重试，其它失败也不重试。
  手写 argv 解析的入口仍可能**静默忽略** `--vector`，表现为"勾了没效果"——勾选前先确认库版本。
- 成功：退出码 0，stdout 是一段 JSON（不要往 stdout 打日志；日志走 stderr）。
- 失败：非零退出码；Lifediary 会把它当「查不了」处理，不打断对话，也不会偷偷改用别的库
  （唯一的例外就是上面 `--vector` 被拒的那一次自动退回）。
- 超时：**两档**（2026-11-24）——工具调用（`recall`）默认 **15 秒**，每轮轻召回默认 **8 秒**；
  两个值可在 Lifediary「记忆库」卡的「记忆工具时长」里改（存 `memory-bank.json` 的 `timeouts`）。
  超时会被 kill；工具调用会把「检索超时（Ns）」转给模型，轻召回静默跳过本轮。
- **密钥边界**：`--vector` 所需的检索密钥（例如 embedding 的 API key）由**库自己保管**
  （库从自己的环境变量读），Lifediary **不读、不存、不传**。接入配置里只有一个布尔 `vector`；
  不要把 key 放进 argv、stdout 或任何交给 Lifediary 的文件里。

输出只要求这些字段：

```json
{
  "groups": {
    "<组名，随意>": [
      { "id": "...", "date": "...", "title": "...", "text": "...", "why": "..." }
    ]
  },
  "coverage": {},
  "unknown": "..."
}
```

- `id` **必填**（页面和日志只记 id）；`date / title / text / why` 可缺；`body` / `name` 分别作为
  `text` / `title` 的别名。
- 组名不固定：Lifediary 按 `Object.entries(groups)` 扁平化，组名原样带出做展示标签；
  **`groups: {}` 是合法空结果**，不是失败（配合 `unknown` 说明「查不到 ≠ 没有」）。
- `unknown` 用来解释「查不到 ≠ 没有这回事」，会原文转给模型。
- `coverage` 可选，`gaps` / `gap_months` 会显示成「记忆库在这些时段没有记录」。
- Lifediary 在槽位层还会再截断（轻召回 ≤3 条 / 800 字；工具调用按 `--limit`），
  不要依赖 `--limit` 做安全边界。

### 2.2 库边界（catalog）

```bash
python ask.py --catalog-only
```

- stdout **纯文本**，最多 20 行；Lifediary 缓存 10 分钟，失败 = 空 + 保留旧文本，不阻塞对话。
- 建议写：有哪些类型的记录、覆盖哪些年月、有哪些人物 / 主题。这段会进模型每轮的
  固定前缀（裁剪到 ≤600 字），让模型知道「这个库大概有什么」。

## 三、写入口契约

```bash
python repair.py statement <body> [--about <YYYY-MM|YYYY-MM-DD>] [--tag <短标签>] --why <原因>
```

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `body` | 是 | ≤500 字 | 用户原话，不改写不总结 |
| `why` | 是 | ≤200 字 | 写进 `change_log` 的原因（Lifediary 固定传「用户让记住」） |
| `about` | 否 | `YYYY-MM` / `YYYY-MM-DD` | 事情发生时间 |
| `tag` | 否 | 短标签 | 如「时间修正」「错认主体」 |

- 成功：退出码 0，stdout 一行确认（例如 `已记：<body 前 50 字>`）。
- 幂等：同一 `body` 重跑必须落同一行（`INSERT OR REPLACE` / upsert），不能新增。
  Lifediary 本地按 `stmt_id = "us-" + sha1(body)[:10]` 对账，建议你也用同一个 id。
- 失败：非零退出码；Lifediary 把原因转给模型，**绝不悄悄改写进原生记忆库**。
- Lifediary 的 `remember` 没有 `about` / `tag` 参数，本批不会传这两个；`kind / scope /
  project / importance / expiresInDays / taught` 在外部模式下都不生效。

## 四、最小模板（SQLite 单表）

下面是一份能直接跑的最小实现：一张 `external_note` 表，`ask.py` 用 `LIKE` 检索，
`repair.py` 建表 + upsert。**按需改；表结构归你。**

### 4.0 换语言怎么写（不用 Python 也可以）

把同样的契约写成任何能读 argv、写 stdout 的程序，文件名改成 `ask.js` / `ask.sh` / `ask.exe`
（`repair` 同理）即可，**不需要改 Lifediary**。例：

```javascript
// ask.js —— node 运行
const args = process.argv.slice(2);
if (args.includes("--catalog-only")) {
  console.log("外部记忆库：N 条记录");
  process.exit(0);
}
console.log(JSON.stringify({ groups: { notes: [{ id: "n1", text: "..." }] }, unknown: "" }));
```

注意三点：**别往 stdout 打日志**（会被当 JSON 解析）、**退出码 0 = 成功**、
**JSON 字段名不变**（`groups` / `id` / `text` / `date` / `why` / `unknown`）。

### 4.1 `repair.py`

```python
#!/usr/bin/env python3
"""写外部记忆库：一张表 + 同 body 幂等。"""
import argparse
import hashlib
import sqlite3
import sys
from datetime import datetime, timezone
from pathlib import Path

DB = Path(__file__).resolve().parent / "data" / "external.db"

SCHEMA = """
CREATE TABLE IF NOT EXISTS external_note (
  id         TEXT PRIMARY KEY,
  body       TEXT NOT NULL,
  why        TEXT NOT NULL,
  about      TEXT,
  tag        TEXT,
  created_at TEXT NOT NULL
);
"""


def main() -> int:
    parser = argparse.ArgumentParser()
    sub = parser.add_subparsers(dest="cmd", required=True)
    stmt = sub.add_parser("statement")
    stmt.add_argument("body")
    stmt.add_argument("--about")
    stmt.add_argument("--tag")
    stmt.add_argument("--why", required=True)
    args = parser.parse_args()

    body = args.body.strip()
    why = args.why.strip()
    if not body or len(body) > 500:
        print("body 为空或超过 500 字", file=sys.stderr)
        return 2
    if not why or len(why) > 200:
        print("why 为空或超过 200 字", file=sys.stderr)
        return 2

    # 与 Lifediary 本地对账一致：us- + sha1(body)[:10]
    stmt_id = "us-" + hashlib.sha1(body.encode("utf-8")).hexdigest()[:10]
    DB.parent.mkdir(parents=True, exist_ok=True)
    with sqlite3.connect(DB) as conn:
        conn.executescript(SCHEMA)
        conn.execute(
            "INSERT OR REPLACE INTO external_note(id, body, why, about, tag, created_at) "
            "VALUES (?, ?, ?, ?, ?, ?)",
            (
                stmt_id,
                body,
                why,
                args.about,
                args.tag,
                datetime.now(timezone.utc).isoformat(),
            ),
        )
        conn.commit()
    print(f"已记：{body[:50]}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

### 4.2 `ask.py`

```python
#!/usr/bin/env python3
"""读外部记忆库：QUESTION + --json --limit N；或 --catalog-only。"""
import json
import sqlite3
import sys
from pathlib import Path

DB = Path(__file__).resolve().parent / "data" / "external.db"


def connect() -> sqlite3.Connection:
    # 只读打开：ask.py 绝不写库（建表是 repair.py 的事）。
    conn = sqlite3.connect(f"file:{DB}?mode=ro", uri=True)
    conn.row_factory = sqlite3.Row
    return conn


def catalog_only() -> int:
    if not DB.exists():
        print("外部记忆库：还没有记录")
        return 0
    with connect() as conn:
        total = conn.execute("SELECT COUNT(*) FROM external_note").fetchone()[0]
        months = [
            row[0]
            for row in conn.execute(
                "SELECT substr(created_at, 1, 7) AS m FROM external_note "
                "GROUP BY m ORDER BY m DESC LIMIT 6"
            )
        ]
        recent = [
            row[0]
            for row in conn.execute(
                "SELECT substr(body, 1, 24) FROM external_note ORDER BY created_at DESC LIMIT 5"
            )
        ]
    print(f"外部记忆库：{total} 条用户亲口记录")
    print(f"覆盖月份：{'、'.join(months) or '（无）'}")
    print("最近记录：")
    for text in recent:
        print(f"- {text}")
    return 0


def search(question: str, limit: int) -> int:
    if not DB.exists():
        print(json.dumps({"groups": {}, "unknown": "外部记忆库还没有记录"}, ensure_ascii=False))
        return 0
    # 最小实现：整句 + 按空格拆词做 LIKE。要更好用就换 FTS5 / 向量（由你定）。
    words = [word for word in question.replace("？", " ").replace("?", " ").split() if word]
    if not words:
        words = [question]
    clauses = " OR ".join("body LIKE ?" for _ in words)
    params = [f"%{word}%" for word in words]
    with connect() as conn:
        rows = conn.execute(
            f"SELECT id, body, why, created_at FROM external_note "
            f"WHERE {clauses} ORDER BY created_at DESC LIMIT ?",
            (*params, max(1, min(limit, 20))),
        ).fetchall()
    hits = [
        {
            "id": row["id"],
            "date": (row["created_at"] or "")[:10],
            "title": "用户亲口确认",
            "text": row["body"],
            "why": row["why"],
        }
        for row in rows
    ]
    print(
        json.dumps(
            {
                "groups": {"external_note": hits} if hits else {},
                "unknown": "只查了用户亲口记录的这张表；查不到 ≠ 没有这回事" if not hits else "",
            },
            ensure_ascii=False,
        )
    )
    return 0


def main() -> int:
    # Windows 控制台默认不是 UTF-8，显式切一下，避免中文 JSON 乱码。
    try:
        sys.stdout.reconfigure(encoding="utf-8")
        sys.stderr.reconfigure(encoding="utf-8")
    except AttributeError:
        pass

    args = sys.argv[1:]
    if "--catalog-only" in args:
        return catalog_only()

    limit = 5
    if "--limit" in args:
        try:
            limit = int(args[args.index("--limit") + 1])
        except (IndexError, ValueError):
            limit = 5
    args = [arg for i, arg in enumerate(args) if arg not in ("--json", "--limit") and (i == 0 or args[i - 1] != "--limit")]
    question = " ".join(args).strip()
    if not question:
        print(json.dumps({"groups": {}, "unknown": "问题为空"}, ensure_ascii=False))
        return 0
    return search(question, limit)


if __name__ == "__main__":
    sys.exit(main())
```

### 4.3 接入前自检

```bash
python ask.py --catalog-only
python ask.py "去年住院的是谁" --json --limit 5
python repair.py statement "住院的是我姥姥" --why "用户让记住"
python repair.py statement "住院的是我姥姥" --why "用户让记住"   # 再跑一次：应仍是同一行
python ask.py "住院" --json --limit 5
```

两次 `repair.py` 之后 `SELECT COUNT(*) FROM external_note;` 必须还是 1。

换成 JS 入口时把上面的 `python ask.py` 换成 `node ask.js`，其余一字不变。

## 五、必须提供什么（一张表说完）

| 必须 | 要求 | 不满足会怎样 |
|---|---|---|
| 一个目录 | 绝对路径，能读 | 检测直接拒 |
| 读入口 `ask.*` | 吃 `argv[1] = 问题`、`--json`、`--limit N`；stdout 一行 JSON；退出码 0 | 检测不过 / `recall` 回「查不了」 |
| 读入口 `--catalog-only` | stdout 纯文本 ≤20 行 | 检测不过（这条是硬门槛） |
| JSON 形状 | `groups` 对象，每组数组；每项至少 `id` | 结构不符 = 当失败 |
| 写入口 `repair.*`（可选） | 吃 `statement <body> --why <原因>`；同一 body 幂等 | 没有它 = 只读库（`remember` 回「只读」） |
| stdout 纪律 | 只有结果，日志走 stderr | stdout 混日志 = JSON 解析失败 |

## 六、接进 Lifediary 之后

- **只有一套工具**（2026-11-24 旧形态退役）：`recall`（读）/ `remember`（写）恒为 2 个，
  没有 `persona_recall` / `persona_write`。切换只换后面的库，工具名 / schema 不变。
- 群聊跳过个人记忆（两个库都一样）。
- 外部模式的 `remember`：
  - `AGENT_TOOL_POLICY=read-only` 会被拦（它要起进程写你的库）；
  - 审批档 `ask-all` / `ask-critical` 都会弹审批（`none` 是用户显式选择，不弹）；
  - `PERSONA_WRITE_ENABLED=false`（默认）时直接回「写入未开启」，**不 spawn**。
- 外部读失败返回 `memory_unavailable`，不抛、不悄悄回落到原生库。
- 想切回原生库：在「记忆库」卡里切「原生（本机）」或「移除」外接库即可（不需要重启）。
  旧形态（`MEMORY_BANK=false` + 两个 persona 工具）已退役，没有回到它的开关。
  清空 `memory-bank.json` 等于未接入；若 `.env` 里还留着 `PERSONA_MEMORY_ASK`，下次读配置会
  按它**重新播种**一条 external 记录（`active` 仍是 builtin），不播种就去掉这个 env。

## 六、边界（Lifediary 不做什么）

- 不打开你的数据库、不跑 SQL、不知道表名 / 字段 / 库内 id 规则。
- 不触发内化、不等待内化、不知道内化时间表。
- 不推断你的打分 / 排序；读多少条、怎么截断由 Lifediary 槽位层定。
- 不提供 `get` / 全文回读；页面只展示读入口返回的片段。
- 不要求你传表名 / 字段名；要改读入口的 JSON 字段名或写入口的 argv 形状，
  按跨仓契约走（先改文档再改两端）。

## 七、建议（非约束）

1. **想让写进去的东西立刻被召回，就把它接进读入口的检索源**（FTS / 向量），
   否则要等你的内化任务跑完。
2. `stated` / `inferred` 分开存；别让助手推断落进「用户亲口确认」的层。
3. 内化按 `note_id + rev` 幂等；旧 rev 降权 / 标失效，不物理删；写 `change_log`。
4. 派生表随便重建，但 staging / 源表不要被 `build_*` 删。
5. 读入口的 JSON **只增字段、不改名**；改名算契约变更。
