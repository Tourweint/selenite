# 员工化现状盘点：谁要你亲手填，谁能自己长

> 一句话：这套东西已经不是"一个会聊天的助手"，而是一个有身份、有岗位、有目标、有履历、会攒记忆、会自己开巡逻、能被你教一次就改行为的"员工"——**但真正跑满这套的只有一个示例员工**（纪要员），另外两个执事只填了一句人设，总管还停在测试文案上。

盘点时间：2026-11-14。口径以代码与真实库为准，设计文档只作旁证；文档与代码冲突处以代码为准。
配套阅读：`docs/调研/2026-11-14-记忆系统现状盘点（全链路）.md`（那篇只讲记忆，这篇讲"员工"整体）。

## 1. 一个"员工"现在由哪几层构成

先把"员工"拆成五层。后面所有字段都落在这五层里，不会串。

| 层 | 回答什么 | 里面有什么 | 谁产生 |
|---|---|---|---|
| 身份层 | 它是谁 | `SOUL.md`（人格正文）、名字、头像、领域、口头禅 | 你填 |
| 岗位层 | 它管什么、现在奔什么 | `CONTRACT.md` 四节（职责/决策分级/验收/汇报对象）、`currentGoal`、接派单开关、日记执事开关 | 你填 |
| 能力层 | 它靠什么干活 | 备选模型链、技能手册（`skills/*.md`）、例行规则、工具（10 基线 + 12 条件）、派活/群组/递话、电脑与浏览器操作 | 你填 + 它自己写 |
| 记录层 | 它攒下了什么 | 记忆（7 种 kind）、工作履历（`work`）、会话、日记镜像 | 它自己攒（少量你教） |
| 治理层 | 它能自己决定到什么程度 | 权限三档、写操作确认轴、自主轮三档、高危工具审批、自动化永不扩权、裁判/验收 | 你设 + 机制强制 |

关键设计（不是"顺手做的"，是当初刻意定的）：

- **岗位与人分家**。SOUL 和 CONTRACT 是两个文件、两套语义：改岗位是"调岗"（版本化、低频、下一轮生效），改人格是"改人"。混在一个文本里，改职责会顺手把人格也动了。
- **履历只由结算写**。模型不能 `remember(kind=work)`，导入白名单也不含 `work`，语义整理还专门剔除它。能被模型随手写一条的"履历"不是履历。
- **两层状态别混**。"在办"是现在时（扫 chancellor 的 `runs/`，零新存储），"履历"是过去时（结构化查 `work`）。同一个 system 注入点、两段数据，不互相推算。
- **自动化永不扩权**。自主轮里 `routine_manage` / `partner_manage` / `group_manage` / `send_to_agent` 是**结构性 block**（不是弹审批），理由统一："自动化不能给自己扩权"。
- **不搞 KPI**。回顾用自然语言总结、不打分；给员工打分既不可靠也不必要（2026-11-08 方案 §五.5 明确不做）。

## 2. 核心：谁填、谁攒（一张总表）

你说的"主动的/被动的"，我拆成四种来源，避免混：

- **A 你手填**：配置，稳定，改完下一轮生效；
- **B 你教一句**：半自动，它落库/写文件；
- **C 它干活留下**：全自动，确定性写入；
- **D 它自己开口**：全自动，会主动找你。

### 2.1 A 类：要你亲手填（9 项）

| 内容 | 存在哪 | 进不进提示词 | 改的口子 | 备注 |
|---|---|---|---|---|
| 人设正文 SOUL | `partners` 版本快照 + 家目录 `SOUL.md` | **每轮进**（instructions） | `PATCH /partners/:id {soul}` / 设置→人设页 | 64KB；空串=不改 |
| 岗位契约 CONTRACT | `partner_versions.contract_source` + `CONTRACT.md` | **每轮进**（`【岗位契约】` 段） | `PUT /partners/:id/contract` | 四节固定；版本化；空=撤岗 |
| 当前目标 | `partners.current_goal` | **每轮进**（`【当前目标】` 一行） | `PATCH {currentGoal}` | 不版本化；空=清除 |
| 名字 / 领域 / 头像 | `partners` 列 | 名字单聊**不进**，群聊会以"你是『X』"出现；领域只用于派单；头像纯界面 | `PATCH` | 领域只收小写 ASCII |
| 口头禅 tagline | `partners.tagline` | **不进** | 字段与接口还在，页面已撤 | 留着是怕以后要注入 |
| 备选模型链 | `partners.modelChain` | **不进**，主模型失败时按链换 | `PATCH {modelChain}` | 最多 5 条，只存变量名，点一下即保存 |
| 接派单 / 日记执事 | `dispatch_authority` / `diary` | **不进**，行为开关 | `PATCH` | 日记执事全局至多一个 |
| 权限档 | `policy.json` / env | **不进** | 设置→权限 | `read-only` / `no-shell` / 黑名单 |
| 例行规则 | `routines` 表 | **不进**，按触发器单独起轮 | 设置→定时任务 / `POST /routines` | 也可让员工自己建（B 类） |

页面上的三个标记就是按这张表来的：只有**正文、契约、目标**标了"每轮进提示词"，其余都不进。

### 2.2 B 类：你说一句，它落下来（3 项）

| 你说的话 | 它做什么 | 落成什么 | 保护 |
|---|---|---|---|
| "以后都先给结论" / "记住……" | 调 `remember(kind=preference, taught=true)` | 一条偏好，`source=taught` | 偏好/打算/经验/履历**永不淘汰**，巩固层不会衰减掉 |
| "这类活应该先小结再列待办" | 有派发权时写 `partner_skill_write` | 一本 `skills/<活的名字>.md`，第一行是索引摘要 | 写盘即生效；下次同类任务书可引用 |
| "每周五下午四点自己盘点" | 调 `routine_manage(create)` | 一条例行规则（cron/interval/once/event） | 高危，第一次要人点头；每员工活动规则 ≤10 条 |

口径是"规矩进偏好、方法进技能，两件事不互斥"。这也是 2026-11-08 E3 的原话。

### 2.3 C 类：它干活时自己留下（6 条写入路径）

| # | 来源 | 触发 | 落什么 | 开关/上限 |
|---|---|---|---|---|
| 1 | 对话规则抽取 | 每轮 `done` | `episode`（只取 user 的话；噪声过滤掉命令句/问句/合成指令） | `MEMORY_ENABLED`；`MEMORY_EXTRACT_NOISE` |
| 2 | 对话模型抽取 | 每轮 `done` | `preference`（≤5）/ `experience`（≤3），置信度 <0.6 丢，4 字引文校验 | `MEMORY_EXTRACT=auto/llm/rule` |
| 3 | 派单结算 | 任务真终态（done/failed/aborted/canceled） | 一条 `work` 履历（票号稳定 id、200 条/scope 封顶） | `PARTNER_WORK_RECORD` |
| 3b | 派单成功时 | 同上 | 结果 ≥40 字 + 含动作词 → 一条 `experience`（"下次同类活可以这样做…"） | 不达门槛不写 |
| 4 | 日记镜像 | 任务近况读取时 | `episode`（`id=diary:<entryId>`，前 200 字） | 30s 节流；最近 3 天、≤50 条 |
| 5 | 批量导入 | `POST /memory/import` | 只 `fact/episode/preference/entity`，`veracity=imported` | 单次 ≤5000 |
| 6 | 外部一生库 | `persona_recall` | **不写**，只返回证据 | 只读 |

另有三个"行为记录"，不是记忆但也是它自己留的：

| 记录 | 落点 | 谁看 |
|---|---|---|
| 例行跑批 | `routines.json` 的 `runs[]`（status/summary/quiet） | 定时任务页、人设页 |
| 观察记录 | `.data/autonomy-observe.jsonl`（`observe` 档才写） | `GET /healthz` 计数、诊断 |
| 守门记录 | `.data/gate-blocks.jsonl` | 排查"为什么没执行" |

### 2.4 D 类：它主动开口（4 种）

| 行为 | 什么时候 | 会不会打扰 | 默认 |
|---|---|---|---|
| 例行轮 | 你配的触发器到点 | 只在员工会话里起一轮；没内容就 `[[no-update]]`（<40 字且无数字/链接/日期判 quiet，run 记 quiet） | 看你配没配 |
| 自主轮提醒 | stuck 10 分钟 / 等审批 5 分钟 / 上游报错 / 用量受限 / 兜底 sweep | 写一条 ≤140 字枚举文案进会话，**不经模型**；执事会话不是观察对象（防自己叫醒自己） | `AUTONOMY_ENABLED` 2026-11-13 起默认 **on** |
| 每晚整理 | 每天 03:30（本地） | 只写建议、不应用、不删除；某个 scope 不足 2 条就打模型都不会打 | `MEMORY_NIGHTLY_REVIEW` 默认开 |
| 主动提起旧记忆 | 与当前话题零关键词交集、≥7 天没召回、importance ≥0.7，最多 2 条 | 排在注入的最后（"也许值得提起"） | `MEMORY_PROACTIVE` 默认 **关** |

## 3. 真实状态（2026-11-14 实测，不是文档承诺）

### 3.1 角色：4 个，只有 1 个跑满

| 角色 | 人设 | 契约 | 目标 | 技能 | 履历 | 记忆 |
|---|---|---|---|---|---|---|
| 总管 `chief` | "测试：短句、先给结论。"（v12） | 无（刻意不播种） | 无 | 0 | 0（总管不接派单） | 走 `global` |
| 阅读助手 | "你是帮我整理读书笔记的安静助手"（v6） | 无 | 无 | 0 | 0 | 0 |
| 记账助手 | "你是帮我记录日常开销的细心助手"（v2） | 无 | 无 | 0 | 0 | 0 |
| 纪要员 | 34 字，带工人干活只回一行结论 | **180 字四节** | **"把例会纪要整理流程跑顺，本周内产出一份可复用的三段模板"** | **1 本** `minutes-template.md` | **3 条** | **4 条** |

两点值得说：

1. **总管的人设还是测试文案**（"测试：短句、先给结论。"），而且版本号被探针推到 v12。它每天在替你说话——这是当前最该修的一处"真实内容"。
2. **家目录里有 80+ 个 `partner-homes/<uuid>`**，其中绝大多数是探针/验收残留（每个都有同样的 195 字 SOUL + 141 字 CONTRACT + `daily-brief.md`）。真实员工只有 4 个目录。清理口径要按 `partners` 表反查，不能按目录数判断。

### 3.2 记忆：73 条，但结构失真

| 维度 | 实测 |
|---|---|
| 总数 | 73 |
| 按 kind | `episode` 64、`work` 4、`fact` 2、`entity` 2、`preference` 1；**`experience` 0、`intention` 0** |
| 按来源 | `extract:heuristic` 57、`diary` 6、`user` 5、`work` 4、`taught` 1；**`extract:preference` 0** |
| 按 scope | `global` 6；其余散在 30 多个 `session:*`（最多的 7 条）与 `partner:*`（纪要员 7 条） |

这不是"记忆没工作"，是**规则抽取太能写、模型抽取没产出**：`MEMORY_EXTRACT` 现在是 `llm`（`.data/agent-flags.json`，2026-11-14 20:48 改），但库里一条 `extract:preference` 都没有。要么切档之后还没有新对话跑到 `done`，要么模型调用没成功（超时/没配 aux 模型/被 faux 挡掉）。这条需要单独验一次，不能当成"已经好了"。

另一个坑：记忆页默认 scope 是 `global`（6 条），你打开页面只看到 6 条，不是库空了，是作用域分开了——这也是 2026-11-14 加"一排人页签"的原因。

### 3.3 履历：真实只有 3 条，全在纪要员

`work` 共 4 条：纪要员 3 条（种子时经正式端点+直插写入）、另一个 `partner:840e…` 1 条（探针残留，该 id 不在 `partners` 表）。
真机验收过的是"派两单 → 一单 canceled、一单 done → 两条 work，一单一账"（2026-11-08 刀二真模型五线），但那批数据不在当前库里。

### 3.4 例行与定时：三套东西并成了一张清单

- 个人提醒（`/agent/reminders`）
- 员工例行（`/routines`，含员工自建的）
- 每晚记忆整理（不是表里的记录，是进程内定时器，`/agent/memory/nightly`）

2026-11-14 把它们并成一张"到点叫一个人"的清单，按人筛选，一套"改时间"弹窗。执行仍按模式分流：**只发一句**（不跑模型）vs **自动执行**（真起一轮）。

实测 `routines.json` 里有一条纪要员的"每周五盘点"跑过一轮，`outcome=quiet`（它判断没值得报的，按安静契约不汇报）。安静契约生效了，但也说明"自建巡逻"目前更像"到点自查、没事就闭嘴"。

### 3.5 外部记忆库：接上了，没介入

- 读：`persona_recall` 已配置（`.env` 指 `persona-metric/analysis/ask.py`），只读、超时 15s、失败降级不抛；库边界页脚有，**但不提供查询入口**。
- 写：每轮导出 JSONL 代码有，`PERSONA_EXPORT_ENABLED` 默认关；导出文件 15 行、voice.db 里 `source=lifediary` 4 轮、persona 侧 **0 条**。
- 每轮自动注入、多 provider、"删除传播"都没做。

所以"一生记忆库"现在的真实能力是：**你主动问"去年""2024 年"时，它可能去查**。它不会自己想起来。

### 3.6 权限与治理：骨架早就不止骨架

| 机制 | 现状 |
|---|---|
| 访问档 | `read-only` / `no-shell` / 黑名单 |
| 写操作确认 | `AGENT_CONFIRM_WRITES` 独立轴（默认关） |
| 高危工具 | `routine_manage` / `partner_manage` / `group_manage` / `send_to_agent` / `persona_recall`（起进程）等进 `WRITE_TOOLS` |
| 自主轮 | 三档 off/observe/on；默认 on；写文件/跑命令/派活一律弹卡、禁"记住"；四类扩权工具结构性拒绝 |
| 裁判/验收 | 派单要有验收项、以文件变更为准、父单收口、证据裁判循环 |
| 数据红线 | 日记域永不删改；主人配置只读；引原话标日期、不打分 |

## 5. 现在明显不对 / 没闭环的地方

按"会不会影响你明天用"排序：

1. **总管人设是测试文案**。它每天替你说话，正文却是"测试：短句、先给结论。"——先填这个，比再加十个功能有用。
2. **两个真执事（阅读助手/记账助手）是空壳**。只填了一句人设，没契约、没目标、没技能、没履历。员工化的机制在它们身上没有落点。
3. **偏好抽取零产出**。`MEMORY_EXTRACT=llm` 已切，但 `extract:preference` = 0；现在 64/73 是 episode，记忆结构更像"抽取器日志"。
4. **履历依赖 `originConversationId`**。总管代转、老单、从别的会话发起的单都不落履历；`work` 不进召回，只能去记忆页按人看。
5. **外部记忆库只读半条**。导出默认关、导入要手动跑、persona 侧 0 条 lifediary；"删除不传播"是当前最大的隐私一致性缺口。
6. **每晚整理只出建议，没人点**。现在有 1 条待决建议（两条"同步链路"日记重复），说明建议制在工作，但"应用"这个动作还没形成习惯。
7. **偶发"看起来像 bug"的口径**：记忆页默认只显示 `global` 6 条；`day`/`topic` scope 只有类型没有写入路径；总管没有契约/目标注入。这些是刻意的，但看页面的人容易误判成缺失。
8. **残留**：80+ 个探针 `partner-homes`、`settings-employee.js` 里还有一页四分段（无入口）、口头禅字段还在但页面撤了、`tagline` 不进提示词。都属于"先记账、别让后来者当成缺陷"。

## 6. 如果只做三件事（最短闭环）

不建议一上来做"通用记忆平台"或"多 provider 注册表"，按投入小、闭环短排：

1. **把真实员工的档案填满**：总管正文重写；阅读助手/记账助手各写四节契约 + 一条当前目标 + 一本技能。这一步不改代码，直接把"员工"从演示变成在用。
2. **验一次偏好抽取**：开一个新会话说 3 句带"以后/记住/下次"的话，看 `memory.db` 是否落 `preference`/`taught`、来源是否 `extract:preference`。没落就查 aux 模型与超时，别让 `MEMORY_EXTRACT=llm` 变成一个"设了但没生效"的开关。
3. **让履历能被看见一次**：从纪要员派一单真的活，看记忆页该员工的"工作履历"多一条、`【当前在办】` 里"近 10 单"数字变化、`work` 不进召回但结构化能查到。三条同时成立，才算"履历闭环"。
