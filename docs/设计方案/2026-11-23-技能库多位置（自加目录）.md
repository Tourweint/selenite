# 2026-11-23 技能库多位置（自加目录）

> 状态：已落地（2026-11-23）。
> 现行口径以 `docs/基线文档/接口-端点7-权限技能与开关.md`、`接口文档.md` §6 为准；
> 本文留的是取舍与边界。

## 背景

用户在「注入 → 技能」页提出：**技能库只有一个默认位置**，希望能**添加多个位置**，
并且在新建 / 编辑 / 删除技能时**选择位置**。

现状（2026-11-23 核对代码）：

- `resolveSkillsDir()` 的读取链写死：`AGENT_SKILLS_DIR` / `~/.lifediary/skills` → `~/.agents/skills`（只读）→ `apps/server/skills/`（内置）；
- `PUT/DELETE /api/v1/agent/skills/:name` 只写 / 只删主目录（`resolved.dir`）；
- 页面上只有一行「位置：<主目录>」，没有增删入口；
- `skillStore` 在模块加载时扫一次目录，运行期加目录 / 加文件都不生效（要重启）。

## 结论

**技能库从「一条写死的链」变成「主目录 + 若干自加位置 + 两个只读来源」**，
自加位置在界面里增删，写入目标可在新建 / 编辑时选择。

| 项 | 结论 |
|---|---|
| 读取链顺序 | 主目录 → 自加位置（按添加顺序）→ `~/.agents/skills`（只读）→ 内置目录（只读），同名先到先得 |
| 自加位置存储 | `.data/skills-dirs.json`＝`{dirs:[{path,label?}]}`；`AGENT_SKILLS_DIRS_PATH` 可换 |
| 写入目标 | 默认仍是主目录（老客户端零改动）；带 `dir` 时可写任一**可写**来源（主目录 / 自加位置） |
| 删除目标 | 同上，默认主目录；带 `dir` 时只删该位置里的扁平 `<名>.md` |
| 运行时生效 | 增删位置 / 增删技能后重建技能库；**已开会话仍按冻结的索引**（不中途追加 system），新会话按新链 |
| 回滚 | `SKILLS_EXTRA_DIRS=false/0/off` → 忽略自加位置、`/agent/skill-dirs` 两个端点 404；已存的 dirs.json 保留 |

### 契约

| 端点 | 变化 |
|---|---|
| `GET /api/v1/agent/skills` | `dirs[]` 每项加 `label?` / `removable`；根上新增 `extraDirs: boolean`（多位置能力是否开着）；`items[]` 每项加 `dir`（实际来源目录） |
| `GET /api/v1/agent/skills/:name` | 可带 `?dir=`，读指定来源；不带仍按读取链第一个 |
| `PUT /api/v1/agent/skills/:name` | body 可带 `dir`；不带 = 主目录（旧行为）；`dir` 必须来自可写来源，内置 / `.agents` → 400 |
| `DELETE /api/v1/agent/skills/:name` | 可带 `?dir=`；不带 = 主目录；非可写来源 → 400 |
| `POST /api/v1/agent/skill-dirs` | body `{path, label?}`：登记一个位置。绝对路径、必须已存在且是目录、不与现有来源重复、最多 20 个；成功 `{ok, path, label}` |
| `DELETE /api/v1/agent/skill-dirs?path=` | 移除登记。只删登记，磁盘文件一个不动；不在登记里 → 404 |

`origin` 新增取值 `custom`（自加位置）。主目录 / `.agents` / 内置的语义不变。

### 取舍

- **主目录永远是第一位**，自加位置排在它后面。理由：主目录是「我的技能」的默认落点，
  让自加位置顶到最前，会让「同名时谁的生效」变得不可预测。
- **默认写主目录，不默认写最后添加的位置**。新建弹窗把位置做成显式选择，默认项 = 主目录。
  这样老习惯（不选位置）不变，只有主动选位置才会落到别处。
- **移除位置只删登记**：与「项目移除文件夹」同一条纪律——登记与磁盘分离，
  避免在设置页里误删一整个目录。
- **不做位置排序 / 设为主位置**：先到先得的口径下，位置顺序决定同名归属；
  允许拖动排序等于让用户手工维护一个契约，第一版不做。需要换顺序就移除后重加。
- **不把设置页当作文件管理器**：位置里「不存在」如实显示（可移除），不自动创建、不自动清理。
- **助手侧不重启**：`skillStore` 改成可重建的稳定壳（保持对象身份，`reload()` 就地重扫），
  执行器 / 工具引用同一份；老会话的索引不因重建而改写。
- **总管私技能目录不在本页管理**：它仍由 `chiefSkillsDir()` 前置在总管会话的读取链里，
  不属于「全局技能库位置」这一层。

## 明确不做

- 不做跨位置搬移 / 合并同名技能（要搬自己把文件放过去，同名先到先得）。
- 不做按位置过滤列表（第一版位置只用于「来源展示 + 写入选择」）。
- 不改 `partner_skill_write` / 执事个人技能的写目标（仍写执事私有目录）。
- 不自动扫描未知目录、不递归子目录（一个位置 = 一层目录，与现有扫描器一致）。

## 验证

- `pnpm typecheck`；`pnpm --filter @lifediary/server test` 相关用例；
- `node --check` 修改过的前端模块；
- 浏览器（真服务）：位置区块列出主 / 自加 / `.agents` / 内置；添加一个临时目录后新会话索引多出它的技能；
  在新建弹窗选该位置 → 文件落在那；移除位置后列表与索引恢复；编辑 / 删除带 `dir` 只动那一份。
- 排版：技能页标题（技能库 + 计数）与两个动作按钮同一行；位置卡五列（来源 / 路径 / 个数 / 可写只读 / 移除）
  对齐成表，长路径省略；各块竖向间距由 `.set-sec` 的 gap 统一，窄屏不折成两行。

## 回滚

- 界面级：移除自加位置（每个位置一次 `DELETE`）。
- 能力级：`SKILLS_EXTRA_DIRS=false`（忽略自加位置 + 端点 404），无需改代码。
- 代码级：revert 本批提交；`skills-dirs.json` 留在 `.data` 不影响旧逻辑（旧代码不读它）。
