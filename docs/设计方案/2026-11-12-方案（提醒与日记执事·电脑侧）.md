## 0. 一句话

提醒从「设置页里的孤立条目」升级成「某个执事会话里的定时消息」；
日记 = 一个普通执事（用户叫它「小记」）+ 每天一条提醒 + 原文归档；
桌面和手机读同一份服务端提醒，点通知落同一条执事会话。

## 1. 现状（2026-11-12 核实）

| 块 | 现在是什么 | 缺口 |
|---|---|---|
| 提醒本体 | durable 任务 `lifediary.reminder`，`wait` 睡到点、`deliver` 写一条 `lifediary.reminder` entry；重启不丢 | entry 没有消费方（web / 手机都不渲染），到点用户其实看不见 |
| 手动新建 | `POST /agent/reminders` 不带 `conversationId` 时走 `openChat(undefined)`，**每次新开一个空会话** | 设置页不记它挂在哪；点通知也没有会话可落 |
| 契约 | 只有 `{ conversationId?, text, at }`；GET 只回 `{ id, text, at, until, status, conversationId }` | 没有 `repeat` / `partnerId` / 取消接口 |
| 桌面通知 | `maybeNotify` 只覆盖对话完成 / 出错 / 待处理；点击 `openConversation` | 提醒到点不触发桌面通知 |
| 手机提醒 | 手机本地 `ReminderScheduler` 的「每日问题」，与 harness 提醒不是一回事 | 与电脑完全没合并 |
| 执事 | `PartnerRow` 有 name / domain / avatar / tagline / currentGoal / dispatchAuthority | 没有「日记执事」标记 |

补充：`ReminderSummary.id` 与 `POST` 返回的 `taskId` 都是 durable 内部自增整数。
这违反 `AGENTS.md` 的「对外 id 一律 uuid」，这次契约扩展正好一并修掉（见 §3.2）。

## 2. 目标模型

```
提醒 = { 提醒 id(uuid), 文案, 首次时间 at, 重复 none|daily, 目标会话 }
目标会话 = 执事主会话（partner canonical）；没建过就先 ensurePartnerSession
到点   = 往目标会话写一条「提醒卡」entry（不调模型）
daily  = 同一任务直接睡到次日同一时刻（id 不变，便于取消）
通知   = 标题=执事名 / 正文=文案；手机本地闹钟排下一次；点击打开该执事会话
日记   = partner.diary=true 的执事 + 一条 daily 提醒（文案默认「今天想聊点什么？」）
```

关键取舍：**提醒到点不调模型**。主方案已定「AI 只接话，不代写」；提醒的确定性比润色重要。
真要一句话由 AI 生成，以后作为「提醒文案可选生成」单独立项。

## 3. 契约增量（先改 shared + 接口文档，再改两端）

### 3.1 执事：`diary`

| 字段 | 类型 | 语义 |
|---|---|---|
| `diary` | `boolean`，默认 false | 这个执事是否作为日记执事；全局至多一个 |

- `PartnerProfileSchema` 纯增量字段（列表 / 详情都带）；`PartnerRow` + partners 表加列。
- `PATCH /api/v1/partners/:id` 接受 `diary`：置 true 时**同一事务**把其他执事置 false
  （DB 用 `WHERE diary = 1` 的部分唯一索引兜底）；置 false 允许。
- 不 bump 身份版本，不进 SOUL / CONTRACT，不影响派活与领域路由。
- 回滚开关：`DIARY_PARTNER_ENABLED`（默认先关，手机侧上线时开）。关 = 投影不带该字段、
  PATCH 忽略该字段。

### 3.2 提醒

`POST /api/v1/agent/reminders` 请求体与 `GET` 返回项：

| 字段 | 类型 | 语义 |
|---|---|---|
| `repeat` | `"none" \| "daily"`，默认 `none` | daily = 每天同一本地时刻重复；到点交付后续排次日 |
| `partnerId` | `string \| null` | 目标执事；有值 = 建在该执事主会话里，交付也写那里；null = 只提醒 |
| `partnerName` | `string \| null` | 仅 GET 返回的投影，列表显示用 |
| `id` | **uuid** | 对外提醒 id；内部 durable id 不外泄 |

- **新增** `DELETE /api/v1/agent/reminders/:id`：取消一条；`{ ok: true }`；找不到 → 404。
  取消 = `scheduler.abort(taskId)`，同时覆盖 daily 的后续。
- 创建校验：
  - `partnerId` 必须存在且 `status === "active"`；暂停 / 归档 → 400 带说明；
  - `daily` 时 `at` 的**日期无意义**，只取本地时刻；第一次触发 = 今天该时刻未过就用今天，否则明天；
  - 不传 `conversationId` 且不传 `partnerId` 时，**不再新开空会话**：落到总管最近一条会话
    （或固定「提醒」会话，二选一在实施时定；见 §6 待定）。
- uuid 的落法：`ReminderInput` 加 `reminderId: uuid`，listReminders 直接投影。
  老任务没有 uuid → 用 `(server secret, taskId)` 哈希成 uuid 形状（同 `messageIdOf` 的做法），
  不需要数据迁移。

### 3.3 会话里的提醒卡

`TranscriptMessageSchema` 纯增量：

| 字段 | 类型 | 语义 |
|---|---|---|
| `kind` | `"reminder"` 可选 | 只有提醒消息带；老客户端忽略 |
| `text` | 已有 | 仍写提醒文案，老客户端最差也能看见一句话 |

- 服务端 `readTranscript` 把 `lifediary.reminder` entry 映射成
  `{ role: "assistant", kind: "reminder", text, at }`。
- 电脑端渲染成一张「到点了」卡片（不冒充 AI 说话）；手机端同样渲染成提醒卡，
  点击进入该会话（已经在该会话里就无需跳）。
- **不要**用 `role: "system"`：`role` 是 enum，老客户端整份 transcript 会解析失败。

## 4. 服务端实现落点

| 文件 | 改什么 |
|---|---|
| `ts/packages/shared/src/index.ts` | PartnerProfile.diary；Reminder 字段；TranscriptMessage.kind |
| `ts/apps/server/src/reminder.ts` | input 加 reminderId / repeat / partnerId；deliver 续排 daily；abort 结束 |
| `ts/apps/server/src/agent/session.ts` | `addReminder` 支持目标会话；`listReminders` 新投影；`cancelReminder` |
| `ts/apps/server/src/index.ts` | POST/GET/DELETE 路由与校验 |
| `ts/apps/server/src/partners.ts` | diary 列 / 唯一性 / 投影 |
| `ts/apps/server/src/companion-api.ts` | PATCH diary；建执事可选 diary |
| `ts/apps/server/src/agent/session.ts`（readTranscript） | reminder entry → 提醒卡消息 |

目标会话：优先 `partnersStore().sessionIdOfPartner(partnerId)`；没有就
`ensurePartnerSession(partnerId)`（partner-runtime 已有，index 里正在用）。
不把建会话逻辑塞进 partners store（存储层只读约定）。

## 5. 电脑端页面（v2-3b）

- 手动弹窗：加「每天」开关与「目标执事」下拉（默认 = 日记执事，没有就「不指定」）。
- 待触发列表：每行带「每天」标记与执事名；行尾一个取消按钮（DELETE，二次确认）。
- 「让 Agent 帮你记」不变：Agent 侧 `set_reminder` 补 `repeat` / `partnerId` 参数，
  仍按当前会话归属。
- 桌面通知：v1 **不做**。页面开着时列表本身能刷新；窗口关掉没有推送通道（见 §7）。
  手机通知承担「到点叫你」。

## 6. 待定（实施前拍板）

1. 不指定执事的提醒落哪：总管最近一条会话，还是固定一条「提醒」会话？
2. 取消按钮放行尾还是长按/菜单？（桌面提醒页刚减字，倾向行尾小按钮）
3. 日记执事的提醒文案默认值：主方案写「今天想聊点什么？」，是否随执事口头禅走？

## 7. 明确不做

- 不做推送通道 / 后台桌面通知（`系统架构.md` 的「刻意没有」继续成立）。
- 不做多日记执事；不做 AI 代写、润色、总结、起标题。
- 不做提醒的时区设置：只按服务器本地时区；跨时区用户以后再说。
- 不做旧提醒数据迁移（老任务按 §3.2 哈希出 uuid，够用）。
- 不做「提醒已读 / 未读」状态机。
