# 方案：搜索分页与历史窗口（2026-11-13 落地）

> 状态：**已落地**（2026-11-13）。结论已下沉到 `docs/基线文档/接口文档.md` §2.5
> 与 `docs/变更记录/2026-11-12-搜索独立成页（一个输入·按对话分组）.md` 的追记；
> 两处与本文冲突时，以长期文档为准。
>
> 上位：用户口径「搜索历史上限默认一年，查看更多就在下面显示一下；会话多了要不要翻页你考虑」。

## 结论

| 项 | 结论 |
|---|---|
| 默认窗口 | 界面默认 **最近 365 天**（请求 `days=365`）；接口默认仍是 30（给 `recall_sessions` 工具收着用，不变） |
| 更早的历史 | 底部「搜索更早的历史（一年以前）」→ `days=36500`（约一百年 = 实际不设下限），从第一页重来；扩过之后底部显示「已搜索全部历史」 |
| 分页 | `offset + limit`：单页仍是 20（服务端上限），`offset` 默认 0、上限 1000000；底部「查看更多（还有 N 处）」按已加载条数取下一页，追加进同一份结果重新分组 |
| 计数 | 响应新增 `total`（未分页的命中总数）；与分页在同一次扫描里算出，不额外跑一遍 |
| 重置 | 换查询词 = 窗口回一年、`offset` 归零、累计结果清空；清空输入回到空态 |
| 向后兼容 | 老客户端不传 `offset`、不看 `total`，行为与之前一致（`total` 只是多一个字段） |

## 为什么是 offset，不是 cursor

- 检索结果是**按消息时间倒序**的全量命中，排序键是 `at`（毫秒）+ 会话；个人库写入频率低，
  翻页期间插入新消息导致错位的概率很小。错位的后果只是"某条重复/漏一条"，刷新即恢复。
- cursor 要在响应里再带 `(at, conversationId)` 游标、服务端按游标续扫，契约与实现都更重；
  这个页面是"翻翻旧对话"，不是信息流，不值得为完美一致性付这份复杂度。
- 真要严格一致，FTS + 稳定 rowid 是更彻底的方案（见下），不在这一版做。

## 会话多了怎么办（可扩展性）

- **当前代价**：每次搜索逐会话打开读 context（与 `listChats` 同口径），O(全部会话)。
  本机约 100 个会话实测 26–32ms/次；会话上千或单会话很长时会线性变慢。
- **不加缓存**：搜索是显式、低频动作；缓存要处理失效（新消息、删除、归档），
  省下的几十毫秒不值这份状态。翻页会重扫，但用户点"查看更多"本来就是低频操作。
- **内存边界**：一次扫描把命中收进数组再排序；分页只切数组，不额外复制正文
  （snippet ≤200 字）。常见词命中很多时，数组是主要内存开销，个人规模可接受。
- **下一步（触发条件写死）**：当出现 **>500 个会话** 或 **单次搜索 >500ms**，
  立项做 SQLite FTS5 索引（durable 消息表或旁路索引），检索核心换实现、HTTP 契约不动
  （`q/days/limit/offset/total` 语义保持）。届时 `offset` 仍可用，或顺势换 cursor。

## 备选与否决

- **一次返回全部命中**：否决。payload 与界面都不可控，且用户只需要"先看最近的 20 条"。
- **cursor 分页**：暂缓（理由见上）。
- **服务端结果缓存（q+days 键）**：暂缓。搜索低频，缓存失效规则比省下的时间更贵。
- **搜索历史 / 筛选 / 排序**：不做，先把"一处搜、点得到、能翻页"做对。
- **语义搜索 / 跨设备检索**：不做；本机只读检索，未引入向量与远程。

## 契约变更清单（已回写 §2.5）

1. `GET /api/v1/agent/sessions/search` 新增查询参数 `offset`（默认 0，0–1000000，非法回落默认）；
2. `days` 上限从 365 放宽到 36500（默认仍 30，1–36500）；
3. 响应新增 `total`（number，未分页命中总数）；`hits` 形状不变；
4. `aroundIndex` 仍只对当前页的命中补算，语义不变；
5. 工具侧 `recall_sessions` 不感知分页：`searchSessions` 仍返回数组，默认 30 天。

  `days/limit/offset`、`searchSessionsPage` 与工具侧形状分离。
- 页面（内嵌浏览器 + `fetch` mock，不进真库）：首屏 `已显示 20/45 处` +「查看更多（还有 25 处）」；

  请求 `days=36500&offset=0`、回到第一页、底部变「已搜索全部历史」。
