## 一、用户纠出的模型（本方案的根）

上报链是 **工人→执事→总管**，不直接跟用户上报；"需要我处理的"= **总管发来的消息**
（转达验收请求 / 等点头 / 提问）。点「去处理」= 回到那条对话里处理。第 1 轮把
needs_you 工单直接画成"待你处理"状态卡，是受旧看板影响的错口径。

## 三、「等你回话」数据口径（身份诚实优先）

- **来源**：needs_you 工单（父单聚合灯 ask，含审批单）。数据全从现 `GET /tickets` 派生，v1 零契约。
- **who 标注**：卡的说话人默认**总管**；但 v1 拿不到总管的原话（见 §五），引文先用有据字段
  （任务说明 prompt 摘要 + 单上已有的状态原因）。**没有总管亲口说的话，就不许写成总管的口气**
  ——此类卡标「系统代发」小标（呼应"自动化必须有身份"，2026-11-13 核实 `delegation-wake.ts`
  的唤醒轮确实会让总管把问题提出来，但那条消息的时间戳/原文现在没存进单子）。
- v2 落地后才显示真·总管留言原文（quote 随锚点字段一起带出）。
- **多条**（示意稿 12）：一条对话一组（与"一张卡=一条对话"同构）；组按**等最久**排，组内留言时间
  正序叠气泡；超过 3 组自动收进"更早的"折叠条；组头「去处理」进对话，气泡本身可点=定位到那句。

## 四、跳转与定位（两步走）

**现有机制（2026-11-13 读码核实）**：搜索能定位是因为索引时给每条消息存了时间戳；
`openConversation(id, { anchor: { at, role? } })` 打开会话后由 `jumpToAnchor()`（app.js:5050）
按 `.msg[data-at]` 滚到那句并闪一下，最近 200 条没有就整段重放（deep）。锚点不命中绝不猜位置。

- **v1（零契约）**：去处理 = `openConversation(conversationId)` 不带锚点 → 落在最新处。
  用户口径："点过去一般都是最新的"，多数场景够用。
- **v2（小契约，另批）**：工单加 `needsYouAnchor = { at, role, quote }`——唤醒链
  （`flushDelegationWake` 的 `runTurn` 完成且 phase 含 needs_you）后回填总管留言的时间戳与原文；
  顺序照 `接口文档.md` §7：先改 `shared` + 接口文档，再两端实施。实施细节（runPartnerTurn
  是否回传消息游标）到时核实，不在此拍死。
- **不做**：用搜索接口"猜"总管那句（可能命中执行端汇报而不是总管留言，违背"绝不猜位置"）。

## 五、今日回顾（F）

- **数据**：现 `GET /tickets` 按 `updated_at` 分日渲染，无新接口；"每天零点翻新"=按日分组天然成立。
- **汇总数字只用有据的**：派活次数 / 完结对话数 / 出错数 / 等你回话数（全部可从单列表现算）。
  ~~改了 N 个文件~~ **不做**——回执（delegation-receipts）没有 changedPaths，无数据源
  （2026-11-13 核实），不编数字；哪天产物透传（B4）落地再考虑。
- 时间线混排：完结✓（回原对话）/ 派活（工具徽章）/ 总管留话（等你回话跳同款）/ 出错。
- 日期切换：前一天/后一天/今天，后一天无数据则禁用。
