二、交互消息 · Agent 回复里嵌可交互 / 动画的 HTML

名字可以叫「交互卡片」。模型写 ```html 围栏，聊天里直接变成一张活的卡片。ZCode 同款机制已核实：沙箱 iframe，allow-scripts + no-referrer。

01 触发回复里出现 ```html 围栏即触发；只认助手消息，用户贴的 html 照旧当代码块
02 沙箱iframe sandbox=allow-scripts、无 same-origin、no-referrer；拿不到 cookie 和父页
03 高度卡内脚本量出内容高度报给父页，自适应到 480px 上限，超出内部滚动
04 流式围栏没写完先显示普通代码块，写完闭合再升级成卡片，不闪半截白屏
05 回滚CHAT_HTML_CARDS=false 一行退回普通代码块；手机端暂不渲染，显示代码
安全边界：模型产的 HTML 按不可信处理 —— 无 same-origin 拿不到存储与凭据，no-referrer 不回传来源；不拦截外链图片/字体（本地单人服务），表单提交默认关。纯前端改动，契约不动（消息还是 markdown 文本）。

形态 1 · 内联自适应卡

高度按内容撑，动画和交互直接在消息流里活着。

适合：小而活的图 —— 环形图、步骤演示、可点的小部件。

默认只给一段定高预览，底部渐隐，点「展开」看全部；不打断阅读节奏。

适合：高的动画、长流程图 —— 知道有这东西就行，需要时再点开。
