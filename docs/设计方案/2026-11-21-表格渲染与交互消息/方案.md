# 表格渲染（C 卡片版）与交互消息（html 卡）

**状态**：已落地（2026-11-21，前端改动刷新即生效）
**拍板**：表格选 C 圆角卡片版；交互卡选形态 1 内联自适应——无工具条、无标题、无源码按钮，直勾勾渲染，只留一层圆角边界。源码按钮经用户否决（"看源代码根本也没啥用"）。
**冲突以本文与基线文档为准**；本目录 `对比页.html` 是选版时的对照稿，只留档。

## 表格（C 卡片版）

- `.table-wrap` 升级成卡片：hairline 外框 + `--r-md` 圆角 + 卡底色，`width: fit-content` 收窄表、超宽内部横滚（圆角裁切靠 overflow-x:auto 自带 clipping）。
- 行间发丝线、表头 `--card-high` 浅底小字、行 hover 微墨。
- 渲染器配套（`web/markdown.js`）：
  - **修 GFM 兼容**：分隔行 `-{2,}` → `-+`，单横线 `:-:` 不再把整张表塌成段落（2026-11-21 实测过）。
  - 短单元格（≤8 字符，或无空格且 ≤26 字符的非 CJK token 如单号/路径）挂 `nw` 不折行——`42m`/`10:12` 断成两行的根因。
  - 全数字列（条数/耗时/退出码这类）自动右对齐（`tabular-nums`），只在用户没写对齐时生效。

## 交互消息（html 卡）

模型在回复里写 ` ```html ` 围栏 → 聊天里直接渲染成一张活的卡片。

- **触发**：只认助手消息里**闭合**的 html 围栏（流式没写完先显示普通代码块，闭合后升级，不闪半截）。用户消息不走 markdown，天然不受影响。
- **渲染**：`renderMarkdown` 只产出占位符 `<div class="html-card" data-srcdoc="…">`（不产 iframe）；`web/html-cards.js` 全局 MutationObserver 发现占位符后挂 `sandbox="allow-scripts"`、`referrerPolicy="no-referrer"` 的 iframe（srcdoc = 模型代码 + 注入的报高脚本）。
- **安全边界**：模型产的 HTML 按**不可信**处理——无 same-origin（拿不到 cookie/存储/父页 DOM）、no-referrer、不给 allow-forms/allow-popups。不拦外链图片/字体（本地单人服务）。纯前端改动，契约不动（消息还是 markdown 文本），手机端暂不渲染卡、显示代码块。
- **高度**：注入的报高脚本 postMessage 上报，iframe 自适应到 `72%` 视口高上限（约 500–700px），超出内部滚动。高度按 srcdoc 内容缓存，重建后免闪。
- **宽度**：非气泡 = 整行宽；气泡模式 = 480px 定宽（≤ 气泡最窄档的内容宽），卡片比气泡主体略窄一格。
- **流式保活**：`stream-reveal.js` 的 reconciler 按「元素+属性一致」保节点——html 卡在同 srcdoc 时原地跳过，模型在卡后面继续写字不会让 iframe 重建重载。
- **回滚**：插件页新增 `CHAT_HTML_CARDS`（ui 组，默认开）。关 = 新渲染退回普通代码块；已挂出的卡到刷新为止（开关是渲染期读的，热翻转只影响之后的消息）。

## 明确不做

- 卡上不放工具条 / 标题 / 源码按钮 / 新窗打开（用户拍板"直勾勾地渲染"）。
- 不做 HTML 白名单/消毒（沙箱已隔离；消毒反而让人误以为卡里的 HTML 是"安全的"）。
- 不做高度配置项、不做手机端渲染（手机端先看代码块，要了再立项）。
- 工具灰块 / 地图页里的 html 围栏走同一渲染（不区分来源）；工具块自身的限高滚动兜住。
