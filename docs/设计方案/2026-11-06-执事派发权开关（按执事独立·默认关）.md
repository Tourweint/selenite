# 执事派发权开关（按执事独立·默认关）

- 日期：2026-11-06
- 状态：**已落地**（同日实现，见变更记录 2026-11-06 同名篇）
- 下沉落点：字段与端点 → `docs/基线文档/接口文档.md` §2.11 / §6；闸门位置 → `docs/基线文档/系统架构.md`（执事/派活一节）。冲突以长期文档为准。

## 目标

给带 domain 的执事加一个独立的「派发权」开关：关着时，`delegate(domain=x)` 命中该执事**不注入其身份**——总管以自己的名义（chancellor 默认无分管路径）直接把活派下去。默认关，且提供 env 总闸双层回滚。

## 现状核对（2026-11-06）

- 派活身份注入点：`ts/apps/server/src/tools.ts` 的 `localIdentityHit(domain)`（唯一装配进 `DelegationRuntime.identityHitFor`，见 delegation.ts L87/L247）；命中 → `buildManagerIdentity` 组装 `ChancellorRequest.managerIdentity`，chancellor 走分管宰相路径。
- 存储在 `partners.sqlite` 的 `partners` 表；已有 `domain`、`avatar` 两次 PRAGMA+ALTER 补列先例。
- 管理面：`companion-api.ts` 的 `PATCH /api/v1/partners/:id` + Web 侧栏花名册（`web/app.js` `renderRoster`）；模型侧 `partner_manage` 工具。
- chancellor 契约（跨仓，本次不动）：`managerIdentity` 缺省 = 不带分管身份，按 v0.3 总管直派 worker。这正是"关着仍接单但不以执事名义派"的现成语义——**不需要改跨仓契约**。

## 决策与取舍

### 1. 闸门语义：不注入身份，而不是拒单

- **选定**：开关关 → `localIdentityHit` 返回 `null` → 请求不带 `managerIdentity` → chancellor 以默认路径（总管直派）完成这张单。
- 备选 A「直接拒单」：宿主在 `startDelegation` 前拦截报错。否决——派活是主人显式发起的动作，领域里没有分管时旧领域本来就能派；只因执事关了开关就让主人的活失败，语义过重，且要新增错误码、动更多调用面。
- 备选 B「执事接单后 chancellor 不再下派」：需要 chancellor 感知新字段，改跨仓契约。**明确不做**（本次 chancellor 仓库不动）。
- 结论：关闭的语义 = "该领域暂时没有分管负责人"，活照办，不以该执事的名义。与"查不到 domain 照旧"的兼容口径完全同构，零新错误路径。

### 2. 字段放哪

- `partners` 表新列 `dispatch_authority INTEGER NOT NULL DEFAULT 0`（0=关）。沿用 `avatar` 的 PRAGMA + ALTER 旧库补列惯例；新建表 DDL 同步加列。
- `PartnerRow.dispatchAuthority: boolean`；`toPartner` 映射（null/undefined → false，防御旧行）。
- 只对带 domain 的执事有意义：普通执事不在派活链路上，toggle 请求对无 domain 档案返回 400（`该执事不带 domain，没有派发权可切`）。

### 3. 双层开关命名

- 每执事：`partners.dispatch_authority`（默认 0）。
- env 总闸：`MINISTER_DISPATCH_AUTHORITY`，**默认开**（读法同 `CHANCELLOR_ENABLED`：只有明确 `false`/`0` 才关）。总闸关 = 所有执事一律视为无派发权。默认开的理由：若总闸也默认关，每执事字段永远不生效，功能等于没做；总闸定位是**回滚开关**（一行 env 退回上一形态），不是第二个默认关。
- 判定收敛成纯函数 `ministerDispatchAllowed(store, domain)`（放 `partners.ts`，紧挨 `partnerIdentityForDomain`）：总闸关 / 查无执事 / 开关关 → false。`tools.ts` 的 `localIdentityHit` 先过它再查身份。

### 4. 契约与端点

- shared `PartnerProfileSchema` 增 `dispatchAuthority: z.boolean().optional()`（纯增量可选；投影只对带 domain 的执事给，普通执事不带，同 `domain` 字段口径）。旧客户端忽略未知字段。
- `PATCH /api/v1/partners/:id` 接受 `dispatchAuthority: boolean`（带 domain 才接受；普通执事 400）。不新开端点——它本质是档案的一个属性，PATCH 已是既有契约面。
- `GET /api/v1/partners` / `:id` 投影对执事附带 `dispatchAuthority`，界面与手机端状态一目了然。
- 模型侧 `partner_manage` 工具增 `set_dispatch` action（`partnerId` + `enabled`），核心实现与端点共用 `partner-manage.ts` 的新函数，避免"端点一套、工具一套"。
- `listMinisterPartners` 投影增 `dispatchAuthority`。

### 5. Web 界面

- 侧栏花名册（`renderRoster`）：带 domain 的执事行、状态点左侧加一个小拨杆按钮（「派」字，亮=有权）；点它 toggle，`stopPropagation` 不触发行点击进会话。关着的执事显示灰态，鼠标悬停提示"派发权已关：派单不经过该执事"。

### 6. 安全与回滚

- 安全用例：默认关（新建执事即 0）；关着时 `localIdentityHit` 不命中（派单不带其身份，行为等同旧领域）；开/关切换立即生效（派单时实时查库，无缓存）；重启后持久（SQLite 列）；总闸一行 env 全关；密钥/对话内容不经过此链路（只是布尔列）。
- 回滚：`MINISTER_DISPATCH_AUTHORITY=false` → 一律不注入，回到本改动前形态；代码回退只需删列逻辑不破坏旧库（多余列无害）。

## 明确不做

- 不改 chancellor 仓库与跨仓契约（`managerIdentity` 语义照旧）。
- 不做按 domain 粒度的"部分派发"（一个执事一个 domain，字段已是最小粒度）。
- 不做开关变更的审计日志（布尔列，变更记录在 `partners.updated_at` 已体现）。
- 不把 `dispatchAuthority` 加进 `partner-manage.ts` 的建执事入参：建时恒为默认关，之后显式打开——"默认最小权"不留捷径。

## 验证表

| 项 | 用例 |
|---|---|
| 默认关 | 新建执事 `dispatchAuthority === false`（store + 投影） |
| 切换 | `setDispatchAuthority` true/false 往返；无 domain 档案 400 语义 |
| 持久 | 关掉 store 重开，值保留 |
| 闸门 | `ministerDispatchAllowed`：总闸关=false；开关关=false；开=true；无 domain=false |
| 链路 | 关着时 delegate 装配的 `identityHitFor` 不命中（借 tools.ts 同款缝测判定函数） |
