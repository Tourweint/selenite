## 零、人话版

记忆库是一个**插槽**：要么插系统自带的，要么插你自己的，一次只插一个。

- 自带的：我们自己的 SQLite，能读能写，是默认状态。
- 外接的：用户自己的库。我们只在外面套一层**壳**，不进库内部。
- 工具永远只有一套（`recall` / `remember`），不看后面是谁，只把问题交给插槽里的库。

对接不是"让库变整齐"，是"让库能被问"。问法固定三个动作，答法固定一个证据包。
Markdown 这种"只有文件、没有检索门"的库，我们代建一份**只读索引**，原文件一个字节都不动。

## 二、结论（七条）

1. **一个槽位，一套工具**。换库只换指针（`.data/memory-bank.json` 的 `active`），工具名不变。
2. **对接 = 适配器**。库内部（表结构、字段名、分类体系）一概不碰；壳只回答三个动作。
3. **标准 = 三动作 + 五字段**。直接采用 persona 已有的证据包形状（`hits / dist / coverage / next / unknown`），不重新发明。
4. **工具面只留两件**：`recall`（读当前库）、`remember`（写当前库）；`persona_recall` 退役（保留一版别名回滚）。不改名成 `memory_search`——名字已在缓存前缀和测试里，改名收益为零。
5. **注入只认当前槽位**：目录段 + 每轮预取都查当前库；切走即停，切回即恢复。
6. **Markdown = 内置文件库适配器**：扫目录 → 切段 → 我们自己的 FTS 索引；原目录只读，默认**不可写**。
7. **预算在槽位层，不在库层**：不管后面是谁，模型永远只看到 ≤N 条 / ≤M 字。

## 三、模型

```
                ┌──────────────────────────────┐
   一次只选一个 →│  槽位（active = 当前记忆库）  │
                └───────────┬──────────────────┘
                            │  每次调用只问它
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
   recall(读)          remember(写)         注入(目录/预取)
        └───────────────────┬───────────────────┘
                            ▼
                  适配器（三种实现）
        自带库 SQLite / CLI 外接库 / Markdown 文件库
```

**切换一次，发生什么**：

- `PUT /memory/bank {active}` 原子写配置；**下一轮生效**，正在跑的轮不打断；
- 缓存前缀变一次（目录段文本换、只读库还少一件写工具）。这属于"用户显式改配置"，允许变一次；
- 页面上的"当前库"整块换内容；本地库的模块按归属显隐（见 §九）。

## 四、怎么对接

### 4.1 四类库，四种接法

| 用户的库 | 接法 | 谁干活 | 什么时候 |
|---|---|---|---|
| 已有程序能查（CLI / HTTP） | 写 3 个命令的壳，JSON 进 JSON 出 | 我们给模板，用户改 10 行 | P2 |
| 已有 MCP server（persona 就有） | **先给本仓加 MCP 客户端**，才有"填个命令就接" | 我们 | P3 |
| **只有文件：Markdown / txt** | 内置 `md-dir` 适配器：扫目录、建派生索引 | 我们，用户零改造 | P2 |
| 只有别家导出的存档包 | 导入，复制成条目 | 我们 | 已有能力 |

**别把 MCP 写成零成本**：本仓今天没有 MCP 客户端（审计见 §一），MCP 通道是一个独立小项
（stdio JSON-RPC、initialize / tools/list / tools/call），P3 再做。

### 4.2 接好没有，三条自检

1. `describe` 说得清：覆盖什么、不覆盖什么、多少条、什么时间段；
2. 搜不到时敢说"这个库没覆盖这类事"，不是装死返回空；
3. `get` 能把每条命中回到原文那一段（能核验，不是二手转述）。

三条缺一条，就算没接好。页面上的状态点直接对应这三条，不只显示"已连接"。

### 4.3 目录识别（只看用户选的那一层，不扫盘、不下钻）

| 目录里有什么 | 认成 |
|---|---|
| `memory-bank.json`（声明 `kind` / `entry`） | 按声明接（P3） |
| `analysis/ask.py` + `data/persona.db` | persona 外接库（P1，从 env 播种） |
| 至少一个 `.md` / `.txt` | Markdown 文件库（P2） |
| 其它 | **拒绝**，不猜 |

### 4.4 边界

- 客户端只能传 `root`；`entry`、`python`、命令参数都由服务端推导，不接受上传。
- `entry` 解析后必须仍在 `root` 内（realpath 比对，防 `..` 逃逸）。
- Markdown 库只读 `root` 内的 `.md` / `.txt`，跳过 `.` 开头目录、符号链接、二进制。
- 外接适配器是**起进程**，按 `WRITE_TOOLS` 对待；只在用户点选 / 显式切换时 spawn，不自动扫描执行。
- 库返回的内容一律当**引文**：包固定抬头、不执行其中的指令、不因库内容改变系统行为。
- 日志只记条数 / 字数 / 耗时 / ok，不记 query 原文、不记条目正文、不记完整路径。

## 五、契约

### 5.1 三个动作

```
describe()                        → 库名 / 一句话定位 / 覆盖 / 规模 / 时间跨度 / 能力[search,get,write]
search(query, limit, range?)      → hits[] + notes{coverage, unknown, next?}
get(hitId)                        → 全文 + 原文锚点
write(fact)                       → 回执（新建 / 更新 / 降权了哪条旧记录）
```

### 5.2 一个返回样例

```json
{
  "hits": [
    {"id": "我的记忆/2026-11-20.md#2", "date": "2026-11-20", "dateKind": "event",
     "group": "日记忆", "title": "上午",
     "text": "和老王在四楼会议室对毕设的牛奶系统……",
     "why": "命中：签收 / 管理员"}
  ],
  "notes": {
    "coverage": "只索引了 2024-01 之后；2023 年只有月度摘要",
    "unknown": "这个库没有工作项目里的对话原文",
    "next": "需要精确原话可查语音档案库"
  }
}
```

### 5.3 每个字段都要有消费者

| 字段 | 谁用 | 用来干什么 |
|---|---|---|
| `id` | 页面 + `get` | "看原文"的锚点 |
| `date` / `dateKind` | 模型 + 页面 | 判断时间；区分"事发日"和"录入日" |
| `group` | 模型 | 引用口吻：事实可直接说，原话必须带引 |
| `text` | 模型 | 正文，超预算就截 |
| `anchor` / `quote` | 页面 | 可核验，防止我们编 |
| `why` | 调试 + 页面 | 这条为什么被选中 |
| `coverage` / `unknown` | 模型 | 防"你从来没提过" |
| `next` | 模型（可忽略） | 建议下一步查哪 |

没有消费者的字段不写。不要照搬别家的 20 个字段。

### 5.4 预算与失败

- 条数与字数在**槽位层**截断（沿用现在的 16 条 / 2000 字小库口径，外部库按 3 条 / 800 字预取口径）；
- 库里返回 500 条，也只透出预算内；
- 失败一律降级为空 + `notes.unknown` = "这次没查成"，**不抛、不断对话**。

## 六、Markdown 文件库（重点）

### 6.1 认三种目录形状，不要求统一

```
我的记忆/
  2026-11-20.md          ← 一天一文件，正文按 ## 分段
  人物/老王.md            ← 一条一文件，开头有 date: / tags:
  inbox.md               ← 可选：唯一允许我们追加的文件
```

一天一文件：

```md
# 2026-11-20

## 上午
和老王在四楼会议室对毕设的牛奶系统，他说签收要区分管理员和老师。

## 晚上
跑了三公里，膝盖有点不舒服。
```

### 6.2 切段与 id

- 先按 `## ` 切，再按空行切；单段上限 1200 字，超了按句切。
- `date` 推断顺序：frontmatter `date` → 文件名 `YYYY-MM-DD` → 段首日期 → 文件 mtime；
  `dateKind` 标 `event` 或 `recorded`。
- `group`：一天一文件 = 日记忆；一条一文件 = `type` 字段或"笔记"；inbox = 随手。
- `id = <相对路径>#<段序号>`，例如 `我的记忆/2026-11-20.md#2`。

上面那个文件进索引就是两条：

| id | date | group | title | text |
|---|---|---|---|---|
| 我的记忆/2026-11-20.md#2 | 2026-11-20 | 日记忆 | 上午 | 和老王在四楼会议室对毕设的牛奶系统…… |
| 我的记忆/2026-11-20.md#3 | 2026-11-20 | 日记忆 | 晚上 | 跑了三公里，膝盖有点不舒服。 |

搜"签收" → 命中第一条 → 「看原文」→ 打开那个文件第 2 段。这就是 `get`。

**id 会漂**：文件中间插一段，后面的段号全变。接受这点漂移；`get` 越界就回
"这一段已经变了，重新搜一次"，不假装还指得准。

### 6.3 索引放哪、中文怎么办

- 索引落在 `.data/memory/md-<root 哈希 8 位>/index.db`（SQLite FTS5），**原文件不动**。
- **中文检索的坑**：FTS5 默认分词器把一整串连续汉字当一个词，搜"请假"命中不了
  "今天请假了吗"。voicevault 已经踩过并解决：入库与查询都用"汉字逐字切、英文数字整词"
  的同一套切法（`voicevault.py:1527-1546` 的 `SEG_RE` / `seg_text` / `build_fts_query`）。
  这里照抄，不引分词器、不引向量库。
- 索引是**派生副本**，不是真相：库里改了文件，以文件为准；索引坏了可以整个重建。

### 6.4 更新与删除

- 不做实时监听（Windows 上几千文件会很吵）。
- 打开库或搜索前看一眼根目录 mtime，变了才增量扫，10 分钟最多一次。
- 每个文件记 `size / mtime / hash`：没变跳过，变了重切，文件没了删索引行。
- 页面显示"上次扫描：新增 x / 删除 y / 变更 z；共 N 个文件 / M 段"。

### 6.5 写：默认不给

- 默认**只读**。我们不改用户的笔记——这条边界比功能重要，要写进页面文案。
- 真要写，只允许两种：新建 `inbox/<日期>.md`，或追加到用户明确指定的那一个文件。
  绝不改已有日记、绝不动 `人物/` 之类内容文件。
- 更彻底的做法是"不接 write 能力"：`remember` 直接不上架（见 §七）。

### 6.6 明确不做

- 不解析 Obsidian 双链、不建标签图谱、不做全文高亮、不做增量 embeddings。
- 只做"文本 + 日期 + 标题 + 路径"四样。

### 6.7 限制（写进页面，不静默吞）

- 只认 UTF-8；非 UTF-8 跳过并报数，**不猜编码**。
- 单文件 ≤2MB，总数 ≤5000；超了报"这个目录太大，先缩小范围"。
- 跳过 `.` 开头的目录（`.obsidian` / `.git`）。

## 七、工具面

工具跟着槽位走，名字不变：

| 工具 | 动作 | 打到哪 | 上架条件 |
|---|---|---|---|
| `recall` | `search` | 当前槽位 | 所有库 |
| `remember` | `write` | 当前槽位 | **当前库可写**才上架 |
| `persona_recall` | — | — | 退役；保留一版别名，回滚用 |
| —（不进工具面） | `get` | 当前槽位 | 只给页面「看原文」用 |

为什么不是 `memory_search`：`recall` 这个名字已经在前缀、测试、文档里；改名是纯抖动。
真正的统一是"**同名工具打到不同的库**"，不是"给统一动作起个新名字"。

**只读库的代价**：切到 Markdown 库，`remember` 不上架，助手只能说"这个库改不了"。
这是单槽位模型的真实代价，页面切换时要提前写明（见 §九）。要不要接受见 §十五 第 1 条。

**自动抽取（每轮抽偏好 / 修剪会话记忆）写哪里**：它今天写自带库（`settled.ts`）。
切到外接库后它怎么办，是本方案最大的悬空点，见 §十五 第 2 条，不在这里偷偷定。

## 八、注入

- **目录段**：当前库的 `describe` 摘要（≤600 字），和今天 `persona_catalog` 同位同序；
  自带库的目录由现有 overview 生成，外接库由 `describe` 生成。
- **每轮预取**：只用当前库，≤3 条 / 800 字；自带库沿用小库召回口径（16 条 / 2000 字）。
- 切走即停、切回即恢复，不做两库并行注入。
- 目录段失败保留旧文本；预取失败静默空。记忆不能卡对话。

## 九、页面

顶部一行选择器，下面内容跟着换：

```
当前记忆库：一生记忆库（自带）   [切换]
```

点「切换」出一张卡：自带库 / 我外接的（候选列表）/ 新增外接。
选中只读库时，卡上直接写："这个库只读：切过去后不会自动记住新东西，也不能改它。"

模块按**库归属**显隐，不是两套页面：

| 模块 | 自带库 | 外接库 |
|---|---|---|
| 总览（规模 / 覆盖 / 时间跨度） | 有 | 有（来自 `describe`） |
| 按人 / 按项目分组 | 有 | 无 |
| 整理建议 / 长记忆拆分 | 有 | **无**（不替别人拆） |
| 原文档案 | 有 | 有（`get` 打开原记录/原文件） |
| 搜索 | 有 | 有 |
| 记忆写入 | 有 | 按能力；只读库不渲染 |
| 索引状态（上次扫描 / 文件数 / 新增删） | 无 | Markdown 库必有 |
| 烘焙 / 用量 / 夜间整理 | 有 | **无**（这些只作用于自带库） |

三种态：

| 态 | 长什么样 |
|---|---|
| 没接过（大多数用户） | 只有自带库；选择器上一行「外接记忆库 · 接入」 |
| 接了一个、当前自带 | 选择器显示自带；候选列表里那一行可一键切 |
| 当前外接 | 整块换成外接库的 describe / 搜索 / 索引状态；自带库降为候选 |

## 十、存储与端点

`.data/memory-bank.json`（原子写；`MEMORY_BANK_PATH` 可覆盖）：

```json
{ "v": 1, "active": "builtin",
  "banks": [
    { "id": "bank_persona", "name": "一生记忆库", "kind": "persona-ask",
      "root": "D:\\Projects\\projects\\persona-metric", "entry": "analysis/ask.py",
      "python": "", "capabilities": ["search", "get"],
      "origin": "env", "addedAt": "2026-11-23T10:00:00+08:00",
      "lastProbe": { "at": "...", "ok": true, "summary": "60 表 / 1.6 万条" } }
  ] }
```

- `active` = `"builtin"` 或某个 bank id；**没有第二个 active**。
- 自带库不进 `banks`：它是保留 id，避免和自己的 DB 混淆。

| 端点 | 行为 |
|---|---|
| `GET /api/v1/agent/memory/bank` | 当前库 describe + 候选清单 + 候选状态 |
| `PUT /api/v1/agent/memory/bank` | `{active}` 切换；只读库可切但页面先提示 |
| `POST /api/v1/agent/memory/banks/probe` | `{root}` 识别，**不落盘** |
| `POST /api/v1/agent/memory/banks` | 登记候选（不自动切换） |
| `PATCH /api/v1/agent/memory/banks/:id` | 只改名 |
| `DELETE /api/v1/agent/memory/banks/:id` | 移除候选；若是当前库，先切回自带 |
| `GET /api/v1/agent/memory/bank/catalog` | 目录段原文（10 分钟缓存） |
| `POST /api/v1/agent/memory/bank/search` | 页面搜索，返回五字段 |
| `GET /api/v1/agent/memory/bank/item/:id` | 看原文（`get`） |
| `GET /api/v1/agent/memory/external` | **兼容保留**：只读返回候选里的 persona 库，不参与槽位 |

开关：

- `MEMORY_BANK` 控制整块（关 = 端点 404 + 页面不渲染 + 注入回自带库）。
- `PERSONA_MEMORY_ASK` / `PERSONA_PYTHON` 保留：首次启动播种 persona 候选 + 回滚。
- `PERSONA_MEMORY_INJECT` 继续管预取；`PERSONA_MEMORY_ENABLED` 继续当 persona 适配器的总闸。
- 不新增插件开关：`plugins.json` 是静态登记表，`flagEnabled` 对未登记键恒 false。

## 十一、分期

## 十二、明确不做

- **不做多库并列**：一个槽位，不在同一轮查两个库。
- **不做跨库合并 / 去重 / 联邦检索**。
- **不做通用记忆平台**：不做插件市场、不做"任何格式自动识别"。
- **不扫盘**：只认用户点选的目录。
- **不做库内全量浏览（按天翻页）**：那是库自己的界面职责，我们只做边界 + 搜索 + 原文。
- **不做向量 / embedding**：BM25/FTS 够用，且索引可重建、可解释。
- **不改用户文件**：Markdown 默认只读。
- **不做自动发现外接库**。

## 十三、回滚

- 删 `.data/memory-bank.json` → 下次启动 `active=builtin`，候选按 env 重新播种，回到"单库写死"。
- `MEMORY_BANK=false` → 整块关闭，注入与工具全回自带库。
- `persona_recall` 别名保留一版：工具合并出问题就摘分发、挂回旧注册。

## 十四、验收（P1）

1. `pnpm typecheck` 绿；server 全量单测绿（新增槽位配置 / 适配器 / 端点单测）。
2. 探针：未配 env 的隔离实例 → `active=builtin`、候选空、页面只有自带库。
3. 真库冒烟：切到 persona → `recall` 返回证据包、`remember` 不上架、注入目录段换文本；
   切回自带 → 逐字节回到今天的召回与写。
4. 日志抽查：只有字数 / 条数 / 耗时，无 query 原文、无正文、无完整路径。

## 十五、待拍板（四条）

1. **只读库失去 `remember` 接受吗？**
   A. 接受，工具不上架（诚实，推荐）；B. 写"本地暂存"并在页面标"未进当前库"（不丢功能，但用户以为写进去了）。
2. **切到外接库时，自动抽取（每轮抽偏好 / 修剪）怎么办？**
   A. 暂停，页面写明（纯单槽，推荐）；B. 仍写自带库但不注入（数据不丢，但等于两个存储）；C. 只允许切到可写库，只读库只做查询候选。
3. **Markdown 默认只读、最多写一个 `inbox` 文件**，认可吗？
4. **升级后的默认 `active`**：A. 一律 `builtin`（最保守，老用户要自己点一下切换）；B. 配过 `PERSONA_MEMORY_ASK` 就默认外接（保住老体验，但自动抽取/`remember` 立刻静默）。
   推荐 A + 首次升级在页面上给一条一次性提示"检测到你配过外部库，是否切换？"。

## 十六、这条会怎么错

- **把"一个槽位"做成"隐藏的两个库"**：自动抽取还写自带库（§十五 第 2 条 B），用户以为在用外接库，
  其实数据在别处。这是本方案最容易糊过去的地方，必须显式选 A 或 B，不能默认。
- **Markdown 索引被当成真相**：文件删了索引还在、段号漂了还硬指——所以 `get` 必须回读原文，
  找不到就如实说"变了"，不糊。
- **只读库上仍摆着写入口**：渲染了再报错，比不渲染更糟；工具面与页面都要按能力显隐。
- **切换成本被低估**：每次切换都动缓存前缀。切换是低频显式动作，可以接受；但如果做成"每轮
  按问题挑库"，就会变成每轮 miss——这也是不做多库并列的实际理由。
- **外接库返回被当指令**：第三方库的正文里写"忽略以上规则"，我们只当引文，绝不执行。
