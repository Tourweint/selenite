# 对话设置抽屉改造方案（右上角齿轮 → 右侧抽屉）

- 日期：2026-11-07
- 状态：设计期（未落地）
- 前置：`docs/设计方案/2026-11-07-对话设置抽屉调研（cindy实现）.md`（必读，本文不重复其代码细节）
- 现版实现：commit 583b6a0，`ts/apps/server/web/{app.js,index.html,style.css}` 的 `#chat-settings-btn` + `#chat-settings-menu`（齿轮下弹面板 = 模型切换 + 一行一个批量加模型）
- 下沉落点（落地后）：界面机制 → `系统架构.md`；变更记 → `变更记录/`

## 1. 问题（用户口径）

现版对话右上角设置三个不满：齿轮外画了黑色圆圈（不知道在干啥）；点开是下弹面板、太单薄；且只有模型相关内容。期望参照 cindy：**裸图标入口 + 右侧滑入抽屉 + 首页一列设置行**。

## 2. 方案（按调研结论执行，备选只记取舍）

调研报告已给出唯一正确形状，本文不再摆"抽屉 vs 弹窗"的伪备选——下弹面板正是要被替换的反模式。两个真实取舍点如下：

- **状态挂 URL（`#/settings/chat` 式 hash 深链）还是内存变量？** —— **推荐内存变量 + `aria-expanded`，不挂 URL。** 理由：对话现场的快捷抽屉不是页面级路由，刷新后重新打开是合理预期；现有 hash 子路由（`#/settings/外观`）管的是全屏设置页，混进来会互相干扰。cindy 挂 URL 是因为它抽屉可达深层页面（语音/例行任务），我们首版只有四行，不值得。
- **抽屉动画用 Web Animations API 手写滑入滑出**（cindy 没做、thread 面板做了），250ms ease-out，`motion-reduce` 归零；关闭动画播完再卸载（参照调研 §2.2 的 `animateThreadPanelWidth` 做法）。成本约 30 行，做。

### 2.1 入口（`index.html` + `style.css`）

- 换图标：内联 lucide `Settings2` 路径（无依赖、无构建，直接拷 path，与现有其他内联 SVG 同做法）。
- `.top-gear` 改为：28×28 命中区、图标 15px、平时无底无边（`color: var(--text-3)`）、hover 才出浅底（`background: var(--card)`）+ 字色提亮；**删掉现版常驻的圆圈/描边**。补 `aria-label="对话设置"`（已有）。

### 2.2 抽屉（新增 `#chat-settings-drawer`，替换 `#chat-settings-menu`）

几何与材质照抄调研 §2.1，翻译成无构建的原生 CSS：

- `position: fixed; inset: 0 0 0 auto; width: 100%; max-width: 448px;` 全高贴右，`border-left: 1px solid var(--border)`，无圆角无阴影（是"板"不是"卡"）。
- 遮罩：全屏 `rgba` 实色压暗；**不开 backdrop-filter**（WebView2/低端集显黑块与掉帧教训，调研 §五.4）。
- 结构 `flex-col`：56px 头部（标题"对话设置" + X 关闭，17px 图标 40px 命中区），内容区 `overflow-y:auto`。
- **打开时底层聊天保持挂载不卸载**——只切 class 不动 DOM，天然满足。
- 关闭三通道：Esc（`event.isComposing || keyCode === 229` 豁免输入法组合键）、X、点遮罩。首版四行无草稿，不做关闭前确认守卫（见"明确不做"）。

### 2.3 首页：四行设置清单（已读代码核实，全部现成）

每行 = 图标 + 标题 + 副文本 + 右侧 `ChevronRight`（14px），行高 ≥48px，hover 浅底，行间 1px 分割。**行只是入口，控件全在二级页**（反模式清单 ③）。返回按钮回首页，抽屉不关。

| 行 | 副文本（动态） | 二级页内容 | 复用 |
|---|---|---|---|
| 模型 | 当前模型名（`GET /agent/model`） | 现版模型菜单整体搬入：供应商分段 + 模型行 + 思考档位分段 + 「一行一个批量加模型」表单（原样保留，只是住进二级页） | `renderModelMenu` / `chatSettingsPreferred` 逻辑零改动，宿主容器从 pop 换成抽屉容器 |
| 权限档 | 当前档名 | 三档分段（完全访问/只读/不跑命令）+ 「写操作逐次确认」开关 + 待处理审批计数与列表入口 | `GET/PATCH /api/v1/agent/policy`（app.js:7009-7046 已有），`policy-switch` 渲染逻辑复用；审批列表先给"计数 + 去设置页看全部"跳转，不在抽屉里重做列表 |
| 通知 | 开/关 + 当前时机 | 桌面通知开关 + 三时机选择（完成/出错/待你处理） | `KEY_NOTIFY` localStorage 逻辑（app.js:3380 起）复用 |
| 全部设置 | — | 直接跳转 `#/settings`（关抽屉、走现有全屏设置页路由） | 零成本 |

**不新增任何端点**：四个二级页只用现有接口，无契约改动，`pnpm typecheck` + 手工点验即可，不触发 HTTP 探针重跑。

### 2.4 兼容

- composer 上的模型 pill 与其菜单照旧（它自己也是 `renderModelMenu`，不受宿主迁移影响，app.js:4275 的 providerchange 事件注释已说明双方解耦）。
- 全屏设置页（`#/settings/*`）不动；`#open-settings` 侧栏齿轮不动。
- 点外关闭逻辑从"点 `#chat-settings-menu` 外"改为"点遮罩外即遮罩本身"，原 document 级监听（app.js:5401）删除。

## 3. 明确不做

- **不做草稿守卫**：首版四个二级页要么即时生效（模型/权限档）要么即时落 localStorage（通知），没有未保存草稿，不需要 cindy 那套 `beforeClose` 闸；引入了再补。
- **不搬伙伴级全套设置行**（资料卡/记忆/例行任务…）：这是"对话现场快捷设置"，全套在 `#/settings`，行尾入口已覆盖。
- **不做 URL 深链**（理由见 §2 取舍）。
- **不做遮罩背景模糊**。
- **不动模型 pill、全屏设置页、批量加模型的交互语义**——只换宿主，不改行为。
