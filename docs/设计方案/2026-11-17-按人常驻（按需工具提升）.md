# 按人常驻：把「按需工具」提升成常驻（2026-11-17）

## 状态

**已落地（同日）**。机制下沉 `docs/基线文档/系统架构.md`（`partner-tools.ts` 模块行）与
`接口-端点4-执事例行与自主轮.md` §2.11（GET/PUT 形状与校验）。冲突以长期文档为准。

## 背景

2026-11-16 工具裁剪 C 段把 8 个低频工具做成 deferred（`tool_index` 一句话清单 + `tool_search`
按需加载），固定前缀省了 25%。代价是：**名单是代码常量**（`DEFERRED_TOOL_NAMES`，源码注释
自承"改清单 = 改代码"），而人设页只能「用 / 不用」，没有「常驻 / 按需」。

2026-11-17 工具调用计数落地后，`count`（真执行）与 `loads`（被搜出来）能回答"到底是谁被藏错了"。
本批补最后一环：**给一个人改得动的手**。

## 决策

**按人、在人设页改、存 `partners.promoted_tools`、下一轮生效、不重启。**

- 内核 deferred 的本质是「延迟 − 已 offer」：把工具名写进会话 `modelTools.add` 就等于常驻
  （完整定义进请求前缀），**不需要改内核、不需要重建 extension**。
- `applyPartnerToolSelection` 每轮已经在写 `modelTools`（含把已加载的 deferred 带回 `add`），
  扩一个"提升名单"是顺路，改动面最小。
- 全局改名单要重建 harness（重启），且"一个人高频"不代表所有人都该背这份前缀。

## 契约

| 面 | 变化 |
|---|---|
| 存储 | `partners.promoted_tools TEXT`：JSON 数组，只存被提升的 **deferred** 工具名；空 = 全按需（= 现状）。不版本化（不是身份） |
| GET `/partners/:id/tools` | `tools[]` 每项加 `promoted: boolean`（仅 deferred 有意义；非 deferred 恒 false）。`enabled` 语义不变 |
| PUT `/partners/:id/tools` | body 扩 `{disabled, promoted?}`。**不带 `promoted` 字段 = 不改原名单**（旧客户端保存勾选不会顺手清掉提升）；带 = 全量替换 |
| 校验 | promoted：非数组/非字符串/`>64`/未知名 → 400；**非 deferred 工具** → 400（它们本来就常驻，无需提升）；与 `disabled` 冲突（既取消又提升）→ 400 |
| 依赖守卫（新增） | 目录里有 `tool_search` 时，取消它 → 400：否则所有按需工具永久不可达 |

## 运行时规则（`applyPartnerToolSelection`）

期望 offer 集合 = 非 deferred 且未取消 ∪ （**已加载** ∪ **已提升**）且未取消。

- `disabled` 优先于 promoted（端点已挡冲突，运行时仍按 disabled 兜底）。
- 早退判据从"非 deferred 集合"改为"目录内期望 offer 集合 vs 当前 offer 集合"——否则提升
  变化不会触发写。
- 已加载（tool_search 拉过）与已提升都进 `add`；整体替换语义不变，避免勾选保存抹掉加载结果。
- 无取消、无 add → `configure({modelTools:null})` 恢复默认。

**已知边界（2026-11-17 登记）**：内核只认「延迟 − 已 offer」，区分不出"被 tool_search 加载"
和"被人提升"。所以**收回提升只对还没 offer 过它的会话（新会话）生效**；某个会话里它已经
被 offer 了，收回后仍留着——与 tool_search 加载过即不可逆是同一语义。提升则立即对下一次
请求生效（含老会话），因为写 add 是幂等的。

## 前端（人设页 · 工具弹层）

- deferred 行加「按需」标签 + 「设为常驻 / 收回按需」切换（非 deferred 行不显示）。
- 同一行显示账本数字「用过 N 次 · 搜出 M 次」（读 `/agent/tool-usage`；读不到就不显示，
  旁路数据不许挡保存）。
- 保存时把 `promoted` 一起提交。

判据（给人看的，不做自动动作）：`count` 高 → 该常驻；`loads` 高而 `count` 低 → 每次都要搜，
要么常驻、要么取消勾选。

## 刻意不做

- **不改全局名单**：全局高频仍要改代码；先看按人提升够不够用，不够再立"全局名单配置"。
- **不做自动提升/自动收敛**：账只给判据，人来点（既定的"自动化必须可见"口径）。
- **不开放"常驻 → 按需"给非 deferred 工具**：把常驻工具塞进 deferred 等于改全局名单，
  是另一件事；本批的"收回按需"只是把人提升过的还原。
- **不动工具描述与注册顺序**（prompt-cache 前缀资产）；不动内核。

## 验证

- 单测：视图带 `promoted`、apply 把 promoted 写进 `add`、disabled 压过 promoted、
  sanitize 拒绝非 deferred / 未知名、tool_search 守卫、不带 promoted 不改原名单。
- `pnpm typecheck` + server 全量单测；人设页弹层走隔离实例浏览器验收。
