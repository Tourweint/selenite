# 定时主动轮（隐藏触发消息）

## 〇、一句话与原则

定时到点不再写一条写死的助手消息，而是**让目标执事真跑一轮模型、主动说一句**；触发这一轮的指令带着专用隐藏标记，回读历史时把那条"用户消息"跳过，于是用户只看到对面自己冒出的一句话。两条定时路并存：**例行任务（触发可见，不动）** 和 **本方案的定时主动轮（触发隐藏）**。

**口径规矩**：只删"不调模型的闹钟行为"，不浪费调度骨架；派活唤醒一律不碰；不改契约为先。

## 一、现状（2026-11-17 核实）

| 环节 | 现在是什么 | 缺口 / 落点 |
|---|---|---|
| 定时提醒 deliver | `reminder.ts:155-188` 写 `lifediary.reminder` entry（:158）+ 调 `setReminderDeliverer`→`sayInConversation` 写写死的 assistant 消息（:180-187） | 不调模型，话是预设文本——本批要换掉 |
| 调度骨架 | `ReminderTask` 的 `sleepUntil`（:154）+ 重复规则 `nextReminderAt`（:125）+ 周期续排（:163-170） | 可复用，不用新造 |
| 创建入口 | `set_reminder` 工具（`tools.ts:701`）、4 个 HTTP 提醒端点（`index.ts:2228+`）、nudge 动态 import（`partner-proactive.ts:186`） | 都指向旧行为，需随改造切换 |
| 前端定时页 | `web/settings-reminders.js` **已走** `/api/v1/routines`（跑模型），不再读提醒端点 | 路 1 已就绪；路 2 靠工具/端点入口 |
| 隐藏能力 | 回读折叠 `session-transcript.ts:137` 无隐藏判据；`session-search.ts:314` 直读 entries；系统输入无 SSE 回显帧 | 折叠 + 搜索两处补判据即可，前端零改动 |
| 自主标记 | `autonomy-state.ts` 进程内 Set + `runPartnerTurn` 的 `turnAuthority: autonomous` 文本头 | 该头例行/唤醒都在用，**不能当隐藏标记** |

## 二、目标形态

| | 触发 | 模型 | 触发消息界面可见 |
|---|---|---|---|
| 路 1 例行任务 | 到点 | ✅ 跑 | 可见（本批不动） |
| **路 2 定时主动轮（新建）** | 到点 | ✅ 跑 | **隐藏，只见模型回复** |
| 派活唤醒 | 别人派活 | ✅ 跑 | 可见（本批不碰） |

做法：**把旧闹钟的调度骨架改造成路 2**——复用 `sleepUntil`/重复规则/HTTP 端点/工具，只把 deliver 行为从"写死消息"换成"跑一轮模型 + 隐藏触发"。这样"删除闹钟"= 删掉不调模型的行为，调度能力不浪费，也不打断依赖它的 nudge。

## 三、设计

### 3.1 deliver 改为跑模型（`reminder.ts`）

`ReminderTask.deliver`（`reminder.ts:155-188`）：
- 删：写 `lifediary.reminder` entry（:158-161）；周期续排**保留**（:163-170）。
- 加：解析目标执事 → 跑一轮自主模型。partnerId 取值顺序：`task.input.partnerId` → `partnersStore().partnerIdOfSession(runtime.conversationId)`（`partner-store.ts:870`）→ 兜底 `CHIEF_PARTNER_ID`（`"chief"`）。
- 跑轮复用 `runPartnerTurn(partnerId, prompt, { authority: "autonomous", sessionMode: "persistent", quiet: false })`（`partner-runtime-run-partner-turn.ts:208`），它已含 autonomous 透明头、无人值守标记、工具闸门，**不新造路径**。`quiet:false` 必带：到点就是要"主动说一句"，不能套例行轮的安静契约（否则短回复被判 quiet 剔除、界面只剩空 assistant，同派活唤醒口径）。
- **循环依赖处理**：`reminder.ts` 不直接 import `runPartnerTurn`（reminder→agent→lifecycle-harness→reminder 成环）。沿用现有回调注册思路，新建独立回调模块 `scheduled-run-deliverer.ts`（无 import 依赖，纯回调槽），`index.ts` 装配时把"跑模型 + resolve partnerId"的实现注入，`reminder.ts` 只调回调。这样既解环，又保留"回滚分支"落点。

### 3.2 隐藏触发消息（标记 + 折叠跳过）

- **专用唯一标记**：`@lifediary/shared` 导出常量 `PROACTIVE_HIDDEN_MARKER = "[lifediary.proactive]"`（固定字节、仅本路使用；是常量不是契约字段）。`prompt = ${PROACTIVE_HIDDEN_MARKER}\n${text}`。它与 autonomous 头并存：模型靠 autonomous 头知道"自主"，折叠靠这个标记知道"隐藏"。
- **折叠跳过**（`session-transcript.ts:150-187`）：pi.user 分支读到 `raw` 后（:161）判 `hidden = raw.split("\n").some(line => line.trim() === PROACTIVE_HIDDEN_MARKER)`——**判"独立成行"而非整条文本的行首**：因为 `runPartnerTurn` 会把 `[Scheduled run context]\nturnAuthority: autonomous` 透明头拼在正文之前，标记落在头之后的独立行。**不在 :159/:174 处 continue**（会连带丢掉回答的步骤与 workMs），而在 :186 `messages.push(outgoing)` 外包 `if (!hidden)`；`:175` 的 `turnStartAt = at` 保留。`parseFileManifest` 之后判定，标记不影响文件清单解析。
- **全局搜索补判据**（`session-search.ts:314`）：它绕过 fold 直读 entries，`lines.push` 前对 `pi.user` 文本判同一标记并跳过，否则"完全不可见"有漏。
- 不改 `TranscriptMessageSchema`、不改 `ChatEvent`、不改前端渲染：系统触发输入本就没有乐观气泡，只改折叠即可当场不可见。

### 3.3 回滚开关

`plugins.json` 新增 `SCHEDULED_TASK_MODEL_RUN`（boolean，默认 `true`，hot，`group:"autonomy"`，`requires:["COMPANIONS_ENABLED"]`）。消费处 `flagEnabled("SCHEDULED_TASK_MODEL_RUN")` 懒读（`flags.ts:314`）。
- `true`（默认）= 新行为：到点跑模型、隐藏触发；
- `false` = **逐字节回到旧行为**：写 `lifediary.reminder` entry + `sayInConversation` 写死消息（旧逻辑不删，收进 `if (!flag)` 分支，满足 AGENTS.md"回滚形态不删"硬约束）。回调模块据此分流。

### 3.4 挂念(nudge) 连带

`partner-proactive.ts:186-219` 的 `sendViaExistingReminder` 动态 import `ReminderTask`；改后 nudge 跟着走"跑模型 + 隐藏触发"——正是"对面主动找你"，保留。在变更记录登记此行为变化（nudge 从此调模型，成本上升）。

## 四、契约增量

无 schema 字段改动。唯一新增：`@lifediary/shared` 导出常量 `PROACTIVE_HIDDEN_MARKER`（供服务端生成器与折叠层共用，固定字节）。接口文档无需新增字段表，只需在定时端点说明"到点跑模型、触发消息对客户端不可见"。

## 六、取舍与备选

| 取舍 | 备选（弃） | 为什么 |
|---|---|---|
| 复用旧调度骨架改 deliver | 新建独立"定时主动轮"任务类型 | 复用 sleepUntil/端点/工具/nudge，改动最小、不打断挂念 |
| 专用隐藏标记 | 复用 `turnAuthority: autonomous` | 该头例行与唤醒都在用，会误伤要保留的两条路 |
| 折叠层隐藏 | 新增 `hidden` 契约字段让前端藏 | 系统输入本就无乐观气泡，折叠跳过即可，契约零改动 |
| 回调模块解环 | reminder 直接 import runPartnerTurn | 直接 import 成环，编译/运行皆险 |
| 默认开 + false 回滚 | 物理删除旧闹钟代码 | AGENTS.md 要求新能力留回滚形态 |

## 七、明确不做（本批别顺手做）

1. 不改例行任务（路 1）任何行为；不碰 `delegation-wake.ts`。
2. 不加 `ChatEvent` 事件、不改 `TranscriptMessageSchema`。
3. 不改手机端（只读 transcript，隐藏自动生效）。
4. 不把 routine 也改成隐藏——两条路并存是需求本身。
5. 不新增前端入口大改；弹窗加勾选项若改动面过大则挪后续，核心机制不依赖它。

## 八、已知边界（落地后登记进 `系统架构.md`）

- 回复落在**目标执事主会话**（与例行一致），不再是建提醒的原会话——行为变化需让用户知晓。
- nudge 从此调模型，成本上升；其 `【名字】` 身份前缀原在写死正文里，现落在隐藏触发指令里，模型现场回复是否复述不保证（但回复落在该执事自己的会话，仍可辨认来源）。回滚形态逐字节保留身份前缀。
- 全局搜索只跳过带标记的触发输入；历史旧数据里的旧提醒 entry（`lifediary.reminder`）不受影响。
- 标记靠文本前缀，理论上用户手打同样前缀会被隐藏——概率极低，接受。
