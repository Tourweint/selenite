# 2026-11-04 思考强度档位：快/深 → 关 / 低 / 中 / 高（按模型）

> 状态：**已落地（2026-11-04，后端+界面 v2 同日落）**。下沉落点：档位表/别名/回退 → `接口文档.md` §2.4.1；模型目录形状 → §2.8；env → §6；行为变化与已知边界 → `变更记录/2026-11-04-界面v2与思考档位落地.md` §4。冲突以长期文档为准。
> 口径来源：用户 2026-11-04 指示「快/深按钮取消，思考强度放进换模型菜单按模型调节；现在的快档 = 关闭思考；档位对齐模型真实推理档」。

## 背景（2026-11-04 全链路审计）

- 现状：快/深 = 同一基座模型的两个**派生变体** `#think-on/#think-off`，经 `samplingParams` 注入唯一差异 `enable_thinking: true/false`（方案 D1/D2，probe 已断言 body 形状）。存储在 durable 会话 `agent.model`；粘性记账 `thinkingSwitched`；`X-Mode` 头 > 粘性 > Jev gate > 默认 fast；D3 首次调工具自动切一次 deep。
- 内核已备好全档位：pi-ai `ThinkingLevelSchema = off/minimal/low/medium/high/xhigh/max` + `thinkingLevelMap`（档位→供应商取值）+ `samplingParamsByThinkingLevel`；pi-durable 有原生 `conversation.configure({ thinkingLevel })` 会话持久化（服务端未使用）。
- 上游实证（手机端 `ReasoningEffort` 注释，实测 2026-11 前后）：`low`/`high` 被 glm-5.3、deepseek-v4.1-flash、qwen3.8-flash 接受；**`medium` 对 glm-5.3 直接 400**（`InvalidParameter`）。其余已配模型（kimi/MiniMax/stepfun）对 `reasoning_effort` 未逐一实测。
- 手机端不调 `/mode`、不发 `X-Mode`（2026-11-04 grep 确认零命中），本轮契约改动不连带手机端。
- 文档欠账顺手修：`/mode` 端点从未登记进 `接口文档.md`（文档滞后即 bug）。

## 决策

| # | 决策 | 理由 / 取舍 |
|---|---|---|
| D1 | **契约档位集 = `off / low / medium / high` 四值**（进 shared 包 schema） | 对齐内核档位子集；`minimal/xhigh/max` 刻意不做（上游无实证、UI 无需求） |
| D2 | **逐模型支持域**：`providers.json` 每模型新增**可选**字段 `thinkingLevels?: ("off"|"low"|"medium"|"high")[]`，**缺省 = `["off","low","high"]`**（不含 medium） | medium 对 glm-5.3 实测 400，只对声明支持的模型在 UI 出现；直接调 API 传未声明档位 → 400 `bad_request`。schema 加可选字段向后兼容，`schemaVersion` 不动。哪天真用了 medium 再逐模型实测声明 |
| D3 | **参数映射沿用派生模型机制**：变体 `#think-off/#think-low/#think-medium/#think-high`；`off → enable_thinking:false`（现行为），`low/medium/high → reasoning_effort:<档>`；`model` 字段照旧盖回真实模型名 | 备选「改用 pi-durable 原生 thinkingLevel + kernel compat.thinkingFormat」被否：要连动 X-Mode/D3/粘性/模型名匹配一整条链，且 qwen 系 thinkingFormat 只会写 `enable_thinking`、表达不了 low/high，最后还是得写按档 samplingParams——收益配不上改动面。旧变体名 `#think-on` 读兼容（按 high 处理） |
| D4 | **API**：`POST /mode` body 扩为 `{ thinking: "off"|"low"|"medium"|"high" }`，旧 `{ mode: "fast"|"deep" }` 兼容映射（fast→off、deep→high）；响应 `{ ok, thinking }`。`X-Mode` 头同步扩值 + 旧值别名 | 端点路径不动，减少 churn |
| D5 | **D3 自动切档目标 deep → low**；`AGENT_THINK_ON_TOOL=false` 回滚开关保留，新增 `AGENT_THINK_TOOL_LEVEL`（默认 low）可调 | 旧语义"开思考"，新档位下 low 是最小可用思考档，成本可控 |
| D6 | **新会话默认 off**（与今天默认 fast 一致）；粘性语义泛化（切过非 off 即保持） | 行为延续，用户无感迁移 |
| D7 | UI：快/深 pill 取消；**思考强度选择器进模型菜单**（按当前模型的支持域渲染），上下文环旁不再放档位控件 | 用户 2026-11-04 口径 |
| D8 | 换模型时当前档不在新模型支持域内 → 自动落回支持域内 **≤ 当前档的最高档**（off 兜底），UI 提示 | 用户 2026-11-04 批准方案时口头确认的兜底；避免换模型后档位失效报错 |
| D9 | `GET /api/v1/agent/model` 的 `models[]` 行从裸字符串升级为 `{id, thinkingLevels[]}`；`POST /agent/model` 响应 `models` **保持扁平字符串数组不变** | UI 需要逐模型支持域才能渲染选择器；POST 是保留旧字段，不动以缩小破坏面。providers.json 载体用供应商级 `modelThinkingLevels: Record<modelId, tiers>`（对 `.strict()` schema 侵入最小，文档"每模型可选字段"按此理解） |

## 明确不做

- 不做 `minimal/xhigh/max`；不做思考 token 预算（thinking budget）的 UI 或配置。
- 不动任务通道（`taskModelRef` 一律思考开，维持现状）。
- 不动手机端；`runtime.json` 结构不变（仍只存模型）。
- 不做逐模型计费/价格展示（cost 照旧全 0）。
