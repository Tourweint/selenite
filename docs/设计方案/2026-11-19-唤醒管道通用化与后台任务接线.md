# 唤醒管道通用化与后台任务接线（2026-11-19）

**状态**：设计已拍板（用户 2026-11-19："第四个非常好做，做一下"；要学 ZCode 派后台任务、终端有变化或 agent 回话就拿到消息继续）。
**下沉落点**：落地后唤醒来源清单 → `系统架构.md` 派活/自主段。

## 背景与拍板

"完成即唤醒"管道是工业级的（防抖、忙退避、落盘恢复、重排、链保险丝），但**只接了派活汇报一个来源**；后台任务注册表已有，**完成只写 assistant 记录不开轮**——模型永远看不到结果，直到下次有人说话。本次：把信封泛化，把后台任务接上，加终端变化检测。

## 方案

### 1. 信封泛化（管道最小改动）
- `WakeEnvelope = { source: "delegation" | "bgjob" | "agent-message", targetPartnerId, payload }`。
- delegation 路径**行为逐字节不变**（回归 = 现有 delegation-wake 单测全绿）；guard 改成按 source 分支：delegation 仍锁 canonical，其余按 targetPartnerId 路由 + 通用存在性检查。

### 2. bg-jobs 接唤醒
- `onFinished`（`lifecycle-harness.ts:980`）在写记录之外投一条 `source=bgjob` 信封（target=发起任务的会话所属执事/主会话），payload=命令摘要+exit code+尾部输出（截断 ≤400 字，沿用 bg log 管理面可见口径）。
- 执事被唤醒后自己决定说不说、怎么汇报（不在信封里替它写话——dim 教训：调度器只递纸条不代写）。

### 3. 终端变化检测（ZCode 式，第二步）
- 运行中的 bg job 开输出监听：新字节到达且距上次唤醒 ≥ `BG_JOB_WATCH_INTERVAL_S`（默认 0=关，仅完成唤醒）→ 投信封（带 tail）。
- 监听挂在 liveJobs 进程句柄上，进程结束/卸载即撤；不建独立 watcher 注册表。

### 4. agent→agent 消息唤醒
- `send_to_agent` 到达对端时若对端会话空闲无人值守，投 `source=agent-message` 信封唤醒（执事"接收别人的信息，有自己的行为"）。
- 实施时先核实 send_to_agent 现有到达路径，若已写消息不开轮则接 wake，若已有等价机制则只补空缺会话。

## 明确不做

- 投递状态机/结算/重试预算（批5 拍板：点到为止，沿用现有落盘恢复）；
- 内核 23-subagent-background 范式整体引入（子代理体系另立项）；
- bg 输出实时流式进上下文（只 tail 唤醒，不常驻）。

## 回滚

- `WAKE_PIPELINE_V2=false` → 回 delegation-only 路径；
- `BG_JOB_WAKE_ENABLED=false` → 后台任务回"只写记录"；
- `AGENT_BASH_BG_TIMEOUT` 维持默认关（转后台本身仍 opt-in）。

## 验收

1. 现有 delegation-wake 单测全绿（回归底线）+ `pnpm typecheck` + 服务端单测；
2. http 探针：起长命令（sleep+echo）转后台 → 完成 → 目标会话被唤醒且输入带输出尾部；kill 后不唤醒；
3. 变化检测：开 `BG_JOB_WATCH_INTERVAL_S=10` → 长命令期间输出变化触发一次 tail 唤醒；
4. 浏览器真模型：执事会话发起后台命令，完成后执事主动汇报一句。
