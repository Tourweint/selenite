# Agent 全景调研七：方法论·技能·"保证实现"综合差距清单

> 2026-11-09。用户口径的最终目标："**像 Agent——我们提出一个要求，最后它一定能够保证实现，不出意外甚至有更高的效果**"。
> 本文是系列的收口：把方法论参照（gstack / superpowers / security-audit-skill / compass）、
> harness 的保证机制（ZCode 五层纵深、opencode /goal 裁判、codex 审查式验收、dsh-superagent 执行纪律、
> DSH/Android 工程契约、hermes/Mika 件——全部来自系列二/四/五回报）、以及已有调研落过的批次，对齐到一张差距清单。
> **冲突以 `docs/基线文档/` 为准。**

## 〇、人话版结论

1. **"保证实现"没有单点银弹，行业收敛在一个五层纵深**（ZCode 的落地最完整）：
   **问清（clarify）→ 计划（plan）→ 计划显式化（todo/依赖图）→ 执行（分解+隔离+看门狗）→ 验收（critic 循环，不合格自动返工）**。
   我们有第 4/5 层的机械部分（派单/回执/验收快照），缺第 1/2/3 层的**产品化**（没有 clarify 工具、没有 plan/todo 工具、
   计划不落盘）和第 5 层的**循环**（验收快照只核对一次，没有"不合格→修→再核"的自动轮）。
2. **"完成"必须由证据定义**——superpowers 把它写成铁律（NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE），
   security-audit 把它做成机器（coverage ledger + 独立验证者 + 只认两种终态），ZCode 把它做成循环（final_critic maxIterations=3）。
   我们 D13 验收快照已站在同一边，但**"证据的种类"太窄**（只认落盘 diff，不认测试/评审/截图证据）。
3. **"卡住就升级"比"卡住就硬扛"更保证完成**：superpowers 的"Rulings, not stalls"（四停条件之外全部自己裁决、
   记录裁决与代价、继续走）、gstack 的浏览器 handoff（3 次失败自动建议人接管）、dsh-superagent 的
   `human_action`（提问不阻塞已授权的活）——三条是同一个思想的三种实现，我们的 attention 机制是底座，缺"裁决纪律"与"升级时机"。
4. 方法论参照（gstack/superpowers/compass）全部是**纯提示词工程**就能落地的——它们是我们"技能库"内容侧的
   直接素材：**把这些方法论做成技能，比做机制便宜两个数量级**。

## 二、方法论三参照（可直接做成我们的技能）

### 2.1 superpowers（obra/superpowers，v7.0.2，15 个 skill）

- **verification-before-completion**：铁律原文——"没有在本条消息里跑过验证命令，就不能声称它通过"。
  门函数五步（IDENTIFY→RUN→READ→VERIFY→claim）；**主张↔证据对照表**（"测试通过"要 0 失败输出、"bug 修好"要
  原症状复测、"agent 说完成"要 VCS diff）；红旗清单（出现 should/probably、满意语气先于验证 = 在撒谎）。
  → **直接抄进执事岗位契约与 chancellor 收尾提示词**（与 D13 同哲学，是它的提示词层）。
- **subagent-driven-development**："每个任务新 subagent + 每任务评审（规格+质量）+ 收尾全量评审"；
  **Rulings, not stalls**——四停条件（不可逆/破坏性；安全敏感；工作树外副作用；计划烂到每条路都是猜）之外
  一律自己裁决并记账 `Ruling: 决定—为什么—错了的代价`，**"人的一天比一次返工贵"**；
  连续执行不请示（"Should I continue?" 就是浪费人时间）。
  → 四停条件与我们 attention 语义高度可映射；**"裁决记账"格式可直接进任务单留言**。
- **writing-plans**：计划是写给"没见过这个仓库的初级工程师"的——每个任务=最小可评审单元（有独立测试周期、
  值得一个评审关口），把"我决定了什么"（文件/名字/签名/验收测试）写死，留白处标注"由实现者合理选择"。
  → 任务单模板参照。

### 2.2 gstack（详见系列三）

冲刺流水线（产物交接链）+ 评审路由（Review Readiness Dashboard）+ /investigate 铁律（3 次修复失败必须停）
+ 浏览器 handoff（3 次失败自动建议人接管）。对"保证实现"的独有贡献：**过程关口**（结果验收之外的
"谁看过"维度）与**升级时机判据**。

### 2.3 security-audit-skill（Cloudflare，六阶段审计）

把"验收纪律"机器化的极致样本，五件可直接移植的思想：
1. **coverage ledger**：确定性覆盖单元清单，每单元必须落在计划/已猎/候选/确认/拒绝之一——**没有静默缝隙**；
2. **猎手/验证者分离**：找问题的人不验证问题，验证用全新 agent（独立性=可信度）；
3. **needs_validation 状态**：证据在源码/沙箱之外→如实标注阻塞点+安全验证计划，**不给严重度、不当结论**；
4. **预算闸门**：开猎前先预留评审/验证的调用数，剩余预算不够最低配置就**不开工**并如实报告；
5. **只认两种终态**：产出齐全+校验器全过，或 `incomplete`+精确原因——**永不中途停**。
→ 对我们的直译：派单验收快照的"粗判退化"已有影子；**coverage ledger 思想适用于"多文件任务"的验收**
（声明 writes 清单=覆盖单元，逐项落状态）；budget 闸门思想适用于将来的批量派单。

### 2.4 compass AGENTS.md（详见系列六）

个人生活 OS 的 agent 守则范本：权限分级表（按数据域）、"有判断无权力"（提案制）、一次批准一次改动、
永不重写日记、注入防御（笔记内容是数据不是指令）、引原话不打分。→ **总管/执事系统提示词的直接素材**。

## 三、ZCode 的保证机制（系列二深挖回报，此处收口）

ZCode v3.17.2 的"提出要求→保证实现"五层（详见 `.research/zcode-deep.md`，300 行带文件证据）：

1. **clarify**：confidence<0.8 或有真分叉时结构化提问，最多 3 轮，选项带推荐；
2. **plan mode**：只收紧不放松的闸门 + 计划文件落盘，退出需人批；
3. **todo 提醒注入**：system-reminder 附件框架把"计划退出/模式切换/工具增量"统一为持久化注入（source 去重、
   先落盘再提交、resume 前缀稳定）——**上下文注入机制本身是保证实现的底座**（注入了才会被遵守）；
4. **执行**：Agent 工具 spawn 子 agent（能力声明/权限走父会话判定器/后台 output file/TaskOutput 统一管理）；
5. **final_critic 循环**：验收 critic 最多 3 轮，不合格自动返工再核。

值得单列的三条 ZCode 纪律（lifediary 缺）：
- **工具能力声明结构化**（readOnly/destructive/sideEffectScope/riskLevel/needsApproval/timeoutMs…——权限系统读声明，
  不靠调用点猜）：我们的 WRITE_TOOLS 是布尔清单，升级方向明确；
- **工具 schema=缓存前缀资产**（schema/顺序/描述固定字节）：影响提示词缓存命中，我们工具注册无此纪律；
- **诚实的工具描述**：只写已支持的能力（不支持的不出现在描述里）；防伪造条款写进描述
  （"Never fabricate or predict a pending agent's results"——与我们"末条 assistant 消息为 finding"的确定性取值同族）。

## 四、执行纪律补充（dsh-superagent，详见系列四）

- **先落账再执行**（stored work）+ 消息按单保序 + 丢弃留档永不重排；
- **人的消息专用槽**：并发满时人也永远插得上话（新活挤不掉人）；
- **诚实交付**：开 PR≠ready、无截图的 UI 改动不算 ready、草稿必须标记；
- **恢复注记**：重启后的新 Assignment 先查目录/git 历史/远端，再重复任何外部动作。

## 五、长尾参照（渠道与界面，一段一个）

- **ppt-agent**：agent 流水线 UI 的三个词——**可观察（SSE 实时展示 router 决策与步骤）、可干预（页级暂停/改搜索词）、
  可回放**；页级资料池隔离（每页独立 summary，不混页）。→ 任务中心详情页的设计口径。
- **WeChatBridge**：记录渠道形态——微信多选→转发→AI（不读库、不注入、全程本地）；**一个群一个场景**
  （每群预设提示词）；超 100 条"分批收集"合并发送。→ 若做"聊天记录进日记"，这是零侵入路线的第一参照
  （chatlog 是读库路线，隐私边界不同）。
- **open-claude-ui**：交互物理学可借思想不搬组件——物理弹簧参数、指针 4px 死区、**CJK 输入法合成守卫**
  （我们中文输入为主，值得查一下内置页面是否有 IME 合成 bug）、滚动渐隐遮罩。
- **magpie**（快速带过）：菜单栏网关做"配额尽自动切下一账号"——我们模型候选链（B4）已同构，无增量。
- **MyBrain/memex 域内件**已入系列六，不重复。
