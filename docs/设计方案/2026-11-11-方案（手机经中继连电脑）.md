# 方案：手机连电脑三通道（USB / 同网直连 / 经中继）——免配对·免手输地址

状态：设计期，2026-11-11 实测齐 + cindy 调研齐（蓝本：`reference/cindy` device-link 三件套 + `docs/self-hosted-relay-plan.md`）。**三条路都要做**（用户 2026-11-11 拍板）。

## 实测结论（2026-11-11 全部亲手验证）

| 通道 | 状态 | 说明 |
|---|---|---|
| USB（adb reverse） | ✓ 已验 | 手机存 `127.0.0.1:39847` 即通；开发调试形态保留 |
| 同网直连（校园网/热点） | ✓ 已验 | 手机改 `serverBaseUrl` 指向电脑 IP 即通：校园网 10.31.160.217 已连；**手机开热点→PC 连入→手机连 192.168.137.1 全链路通**（发 ping 回 pong、服务端落库） |
| 手机5G → 公网中继 | ✓ 已验 | 纯流量开 `<VPS_IP>:8084/api/relay/info` 返回名册 JSON——手机↔公网中继天然通 |
| 手机5G → 经中继找电脑 | ✗ 缺 | 现架构手机只会直连 harness HTTP；中继没有手机加入/REST 反代——**本方案补齐的核心** |

其他实测事实（排障依据）：
- 校园网 **ICMP 全禁**（网关/DNS/跨段 ping 全不通），判连通性只能用 TCP。
- PC `hostednetwork` 需管理员且状态不可用；**手机开热点 + PC 连入**是可行的热点形态（Windows Wi-Fi Direct 自动成网 192.168.137.x）。
- vivo 装包：流式 install 卡死 → `push /data/local/tmp + pm install`；弹"非官方商店"确认页要人工点「继续安装」。
- Git Bash 吃 adb 远端路径前缀 → adb push/shell 涉 `/data|/system` 必须 `MSYS_NO_PATHCONV=1`。
- ADBKeyboard 广播在 vivo 真机有效（AOSP 模拟器无效）；`input text` 直注也可（无纠正字符时）。

## 目标形态（用户口径）

> 手机设置页一个「中继/连接」界面：USB、同网、中继三路都通；不用配对、不用手输地址；USB 只剩开发调试用。

## 架构（哑中继 + 设备直连 WS，抄 cindy 最小集）

```
手机 App ──WS(/ws, Bearer deviceToken)──► relay(<VPS_IP>:8084) ◄──WS── harness(书房主机, 已直连)
   │                                          │
   └── REST /api/v1/*（经 relay 反代 → WS invoke → harness 内部 handler → 原路回包）
```

关键决策：
1. **中继加 `/api/v1/*` 反向代理**（R1）：REST 收 → WS invoke 指定设备 → harness 处理 → 原路回。手机端**第一版只换 base 地址**（`http://<VPS_IP>:8084/api/v1`）——业务零改动、鉴权映射一次。
2. **扫码加入**（R2+M1，cindy 同款）：电脑「添加设备」→ 一次性加入码（10min TTL）→ 二维码 `lifediary://relay/join?u=<地址>&c=<码>` → 手机扫 → 提交 → deviceToken 一次性签发（只存 sha256）→ 手机落 Keystore 永久直连。
3. **presence 广播**（R3）：hello/bye 全量名册推给所有连接——手机「多端」区实时化。
4. **同网自动发现**（M2 增强，服务性优化）：手机设置页「扫一扫」扫电脑端二维码**直接带 serverBaseUrl+令牌**（现有配对码升级：二维码 payload 从 `pair/redeem` 改为含 base+token 的完整形态），扫完即「已连接」——校园网/热点形态的用户操作从"手输 IP+令牌"降为"扫一次码"。

## 改动清单（分批派活）

### 批R（中继，harness 仓 ts/apps/relay）
- R1 `server.ts`：`/api/v1/*` 反代（目标设备可指定/默认唯一主机；离线 502；帧大小沿用上限；日志只记计数）。
- R2 `pairing.ts`：`POST /relay/join`（码+设备信息 → deviceToken 一次返回）+ 加入码签发开放给已连设备（或 owner）。
- R3 `hub.ts`：presence 广播帧（复用名册投影，帧小频低）。
- 契约：shared +`RelayJoinRequest/Response`、反代透传无需 schema（body 原样）。

### 批H（电脑端 harness+web）
- H1 `relay-channels.ts`：白名单 +`mobile/proxy` 通道（收 invoke 帧 → 调内部 handler → 回包；fail-closed 不变）。
- H2 web 设置页：「添加设备」弹窗（加入码+二维码）+ 配对二维码升级为完整连接形态。

### 批M（手机端 lifediary）
- M1 `core:pairing`：+`RelayJoinApi`（解析深链/手填 → join → deviceToken 落 Keystore）；Preferences +`relayBase/relayToken`。
- M2 设置页「连接」区块重构：三选一形态展示（USB 仅提示 / 同网扫码 / 中继扫码）；「扫一扫配对」升级为解析两种二维码（旧配对码/新连接形态）；深链 `lifediary://relay/join` 注册。
- M3 抽屉「多端」区接 presence（可选二批）。

### 用户操作流（做完后）
- **中继路**（任意网络）：电脑点「添加设备」→ 手机扫 → 完事。手机在 5G/外地/公司都能用。
- **同网路**（热点/校园网）：电脑设置页出「连接码」二维码 → 手机扫 → 直连 IP 自动填好。
- **USB**：开发时 `adb reverse` 照旧，不做成 UI（登记"刻意没有"）。

## 明确不做
- Ed25519 设备签名（二期可加；中继覆写 src+哈希凭证第一期够）。
- SSH 一键部署向导（relay 已部署）。
- 手机经中继的 SSE 仿真（先通"发→回读"；流式体验后续按 invoke 回包实测再定）。
- USB 形态的 UI 化（保持开发工具属性）。

## 验证口径（全部亲手复测）
1. 中继路：手机纯 5G + 扫码加入 → 设置页「经中继·已连接」→ 发消息收回复 → 审批可批 → USB 全程不插。
2. 同网路：热点/校园网 + 扫码 → 直连 IP 自动填 → 发消息收回复。
3. 回归：USB reverse 形态不受影响；桌面端 web 设置页的连接不受影响。
