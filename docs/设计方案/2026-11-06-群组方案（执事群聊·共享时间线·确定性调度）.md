## 〇、一句话（2026-11-06 用户拍板）

群组 = **主人 + 2–6 名执事在同一条会话里聊**。谁发言由宿主代码按确定性规则编排：
**@点名 > @所有人 > 值日执事**（用户拍板：不 @ 就是值日执事回，建群时必选、可改）。
每个执事仍是独立 agent（自己的会话、SOUL、模型链、闸门），群里只有一条共享时间线。

**反面教材（四家参考仓库全部明示）**：不是"一个 prompt 塞多个执事人格让模型分角色输出"，
也不是"让模型互相 @ 抢话"。排序交给模型在多方场景必乱，这是 DS-Bot 设计文档写明的两个
根本难题之一（另一难：每个发言成员 = 一次完整模型调用，成本线性增长，所以默认少叫人）。

## 一、四路参考调查结论（2026-11-06，Qoder 只读调查；全文见
`2026-11-06-群组参考调查（cindy·DS-Bot·lobehub·OpenMausBot）.md`，同目录）

| 来源 | 架构形态 | 抄什么 |
|---|---|---|
| cindy `bot-group-chat` | 宿主确定性编排 + 每 bot 隐藏 group lane 会话 + 消息作者快照 | 消息四件套、时间线四形态 UI、@picker（纯文本+发送时重解析）、5 分钟同作者合并、`NO_REPLY` 哨兵思想、round-end 防刷屏 |
| DS-Bot `room` | 共享时间线 + 每成员每群隐藏会话（懒建）+ 确定性路由器 | 路由纯函数、`seen` 游标增量投递、群公告、私聊内容不自动进群、事件行一等公民 |
| lobehub `chat_groups` | supervisor（LLM 路由）+ 上下文按观看者投影 | **投影思路**：别人的话降级 user + speaker 标签；成员表只存 order/role/enabled（不复制人格）；沉默协议 `NO_REPLY/STAND_DOWN` |
| OpenMausBot `WireGroup` | 共享记录窗口 + 每成员独立 session/记忆/计量 + 纯函数响应者决策 | `defaultResponder` 枚举、@ 解析（最长优先、歧义拒绝不猜）、`MAX_GROUP_HOPS=1`、串行队列 + spoken 去重、窗口 30 条 |

**四家共识（本方案的骨架）**：
1. 群 = 共享时间线 + 成员表；成员各自独立上下文。
2. 发言顺序由宿主代码决定（lobehub 用 LLM supervisor 是唯一例外，我们 v1 不学——多一次模型调用 + 延迟，且排序仍要确定性兜底）。
3. 消息作者落**快照**（改名/离群/删档后历史不烂）。
4. @解析是纯文本纯函数：最长标签优先、歧义拒绝、发送时按正文重解析。
5. 防刷屏靠机制不靠提示词：串行、轮数/跳数上限、去重。

## 二、设计

### 2.1 数据模型（`partners.sqlite` 加三张表，群 id = uuid）

```sql
groups        (id TEXT PK, name ≤40字, notice ≤500字 公告,
               responder_kind 'member'|'everyone'|'mentions',
               responder_partner_id, createdAt, updatedAt)
group_members (group_id, partner_id, position, joined_at,
               UNIQUE(group_id, partner_id))          -- 成员=真实执事档案行引用，不复制人格（lobehub 教训）
group_messages(id TEXT PK=uuid, group_id, seq 群内单调,
               kind 'message'|'system',
               author_kind 'user'|'partner'|'system',
               author_id,  author_name 快照,           -- cindy 四件套：快照不 join，改名离群历史不变
               content ≤8000字, at, round_id)
```

- `group_messages.seq` 是群内单调序号（同 SSE seq 口径，序号可对外），回读分页用 `beforeSeq`。
- 成员上限 2–6（cindy 同款）；总管可被拉进群当普通成员（chief 也是 partner 行，无特判），**不做路由者**。
- 删除执事 → 级联删 `group_members`，群历史靠作者快照照常渲染；正在跑的该执事发言跳过并落 system 行。

### 2.2 成员会话（每成员每群一条，懒建，复用全部既有机制）

- 外部 id：`partner-<partnerId>-group-<groupId>`；`partner_session_links.role` 枚举扩一型
  `group`，`routeKey = group:<groupId>`（现有 `UNIQUE(partner_id, role, route_key)` 已覆盖，无约束变更）。
- `partner-` 前缀让现有过滤自动生效：不进会话列表（`app.js:2065` 前缀过滤），身份对齐复用
  `ensurePartnerSession` 同款逻辑（版本快照 configure，改 SOUL 下一轮生效）。
- 发言轮走 `chatStream` 主链路：闸门 / 审批 / 工作区边界 / 防打转 / 回合上限**原样生效**
  （D14 红线：执事不是第二套权限系统，群不改变这一点）。
- **群会话不参与记忆引擎**（召回与抽取都跳过，判定 = 链接表存在 role='group' 行）：
  群聊不写个人记忆防串台（DS-Bot 群记忆独立教训的 v1 最简形态）；群内连续性靠会话历史
  本身 + 群时间线，不靠记忆。**刻意没有**：群内长期记忆（§七）。

### 2.3 发言路由（纯函数，可单测）

```
resolveGroupSpeakers(text, group, members) → speakerIds[]（按正文出现顺序）
  1. 解析 @：最长标签优先、要求词边界、歧义（重名）→ 400 拒绝不猜（OpenMausBot 口径）
  2. @点名 ≥1 → 被点名者（按出现顺序串行，去重）
  3. @所有人 → 全体成员按 position 串行
  4. 无 @   → responder_kind：member=值日执事 / everyone=全员 / mentions=无人回（落 system 行提示）
```

- `responder_kind` 建群必填，默认 `member`（值日制，用户拍板）；UI 占位文案明示
  "不 @ 就发给 X"（cindy 同款）。
- 自动选人（小模型路由）v2 再议，v1 不做（§七）。

### 2.4 回合执行（串行编排器，一个群同时最多一个回合）

```
POST /groups/:id/chat {text}
  → 落用户消息（作者快照 user）
  → resolveGroupSpeakers
  → 逐个成员串行：
      懒建/打开群会话 → 对齐身份
      拼 input = 成员名册 + 群公告 + 群内新消息（首建带最近 30 条窗口，之后只增量）
                + 指令尾「以「<名字>」身份直接回话」
      chatStream 跑一轮（SSE 帧全程带 sender）
      终稿落 group_messages（作者快照 partner）
  → 回合结束
```

- 他人消息在成员视角是 **user 角色带说话人标签**（`主人: …` / `小秘: …`），自己的历史回复
  仍是 assistant——不污染语气，模型不会把别人的话当成自己说过（lobehub GroupRoleTransform 同思路）。
- 增量投递 = 每次只喂"该成员上次发言之后群里的新消息"（DS-Bot seen 游标思想），
  群会话前缀稳定可吃缓存；从不发言的成员永远零成本（懒建）。
- **断线 ≠ 取消**（D4 延伸）：客户端断开回合照跑完落库，重连拉 `GET messages` 补时间线。
- 执事互聊 **0 跳**：成员回复里 @ 别人不触发，本轮到此为止（OpenMausBot 是 1 跳，
  cindy 是 5 轮后停；v1 取最严，登记 §七）。
- running 时再发 → `409` 带说明（v1 不做排队；UI 发送键变停止键，既有 composer 模式同款）。
- `POST /groups/:id/stop`：停当前发言成员（复用会话 stop 链）并作废本轮剩余队列，finishReason=aborted。

### 2.5 SSE 契约（纯增量，老客户端零感知）

- `start` 事件加可选 `sender?: { kind: "partner"|"user"; id?: string; name?: string }`
  ——一轮一个 start，客户端据此归属整个气泡（delta/thinking/progress/tool/done 跟随当前 start）。
- 新事件 `{ type: "notice"; text: string; seq? }`：系统行（成员被停用跳过 / mentions 无人回 /
  岔路说明），同时落 group_messages(kind='system')，回读可复现。
- v1 群流**不做 seq 断点重放**（回读走 REST 时间线补，登记 §七已知边界）。
- 手机端 v1 **零改动**：新端点老客户端不认识 = 不用；SSE 事件纯增量可忽略。

### 2.6 UI（web，cindy 四件套先行）

- 收起轨道群组按钮与展开侧栏"群组"节从占位转真功能（E5 已定顺序：执事花名册 → 群组）；
  页面 `#/groups`（列表）+ `#/group/:id`（会话视图）。
- 时间线四形态：自己右对齐 / 成员左对齐（头像列 28px + 名字行 + 时间）/ 系统行居中发丝线 /
  5 分钟内同作者合并 + 跨天分割。发言中成员显示"正在思考 / 正在用工具"（progress/tool 事件按 sender 归属）。
- @picker：textarea 叠浮层（候选 = 所有人 + 成员），键盘 ↑↓/Enter/Esc，纯文本发送时重解析；
  不引入富文本（cindy 同款，改造成本最低）。
- 建群弹窗：群名 + 多选执事（2–6）+ 值日执事 + 可选公告；群设置：改名 / 公告 / 加减成员 /
  换值日 / 删群（硬删：群 + 成员关系 + 消息；成员群会话遗留无害，登记 §七）。
- 群头像 v1 用首字圆钮（同执事），复合头像几何（cindy BotGroupAvatars）批三再说。

### 2.7 开关与回滚

- `GROUPS_ENABLED`（**默认开**）`=false`：群端点一个不挂（404 语义 = 未启用，同 COMPANIONS 口径）、
  rail 回到禁用占位——一行回滚到今天。
- `COMPANIONS_ENABLED=false` 时群组随之不可用（成员都没了）：两个开关都查，任一关即 404。

## 六、刻意不做（登记防补齐）

- **执事互聊接力（0 跳）**：成员回复 @ 别人不触发。后续若要，照 OpenMausBot 加 `MAX_GROUP_HOPS=1` + spoken 去重，单独立项。
- **自动选人路由**（小模型/LLM supervisor 决定谁回）：v1 只有 @ 与值日两种确定性路径。
- **群内长期记忆**：群会话不进记忆引擎；跨会话群记忆（DS-Bot `memory/groups/<roomId>` 形态）不做。
- **群级人格 prompt**：群只有公告（notice），不给群叠加第二身份——成员人格 = 各自 SOUL。
- **互发消息 / 分工编排**：执事私聊互发、群内派活卡（cindy work/plan 卡、lobehub delegate）不做——群只管"一次会话内的多执事协作"，长活走既有派单链。
- **排队**：running 时 409，不做可见队列（OpenMausBot 形态后续再说）。
- **群流 seq 断点重放**：回读走 REST 补。
- **话题/引用/已读回执/表情回应/悬停名片**（cindy §10 多账号群那套）：单人多执事场景不需要。
- **删群可恢复**：硬删（群+成员+消息），登记。
- **群级超时看门狗**：靠既有回合上限（D7）兜底，OpenMausBot 的 turn-timeout/stall 分离不做。
- **手机端群聊**：契约纯增量，App 零改动；手机接入另立方案（跨仓库契约先行）。

## 七、开放风险

- **成本**：每个发言成员 = 一次完整模型调用；@所有人 ×6 是最贵路径（串行还慢）。
  值日制天然省钱；UI 在 @所有人发送前可提示（批二做不做随缘，不做也行）。
- **重名执事**：@ 歧义直接 400（"群里有重名，请先改名"），v1 不做点选消歧（cindy/OpenMausBot 的
  @ 列表点选进批三候选）。
- **成员群会话膨胀**：增量投递下每成员每群会话持续增长，压缩机制复用既有会话压缩（D12 同源），
  v1 不专门处理，观察后再议。
