## 前置事实

- 前端本地队列：`web/app.js:580-582`（`queue: []`，注释"忙时发的消息先在这里排队，本轮结束后依次真发"）；轮末补发逻辑与队列消费处自己定位（搜 `queue`）。
- 插话快速路（steer）已存在：消息即引导批落的，找到它的提交调用（应带 `whenBusy:"steer"`）。
- 忙判定：前端现有"活跃轮"判断（队列的入队条件处）。
- 服务端：忙时 POST `/agent/chat` 带 `whenBusy:followUp` → 受理并落 durable（http 探针 §19 有现成断言）。

## 逐项

1. **忙时 Enter 改立即提交**：入队点改为直接走既有发送函数，body 带 `whenBusy:"followUp"`；乐观渲染保留（发即上屏），followUp/steer 事件帧回流的既有渲染路径负责归位。
2. **本地队列退役**：删本地数组、轮末补发、相关的"排队中"本地状态文案；若"排队中"灯依赖本地队列，改为跟服务端事实（transcript 里的 followUp 条目就是排队的真相）。
3. **steer 快速路回归**：确认改造后快速路行为不变（探针/手验）。
4. **回读一致性**：页面加载/刷新后的回读路径本来就会画出历史 user 消息——确认忙时提交的插话在刷新后以正确顺序出现在时间线（如投影缺时间序字段，如实记录并汇报，别硬造）。
