# 扫尾批 6 方案：记忆巩固深化 + 已存记忆导入

> 状态：**方案随批实施（2026-11-08）**。上位：扫尾计划批 6（B5 拍板：巩固"肯定要做"、导入"做成一个功能"）。
> 与 D18 的关系：D18（2026-11-06 登记）拒绝的是**自动语义消解/自动删改**（误杀代价 >> 脏）；
> 本方案沿用该理由——巩固 = **强化、衰减、给建议**，凡"删/取代"一律要么确定性同义收敛、要么**人拍板**。用户 2026-11-08 拍板推翻的是"巩固整体观望"，不是 D18 的安全底线。

## 一、确定性巩固（自动，无模型，进 ingest/recall 主链路）

1. **重复收敛升级**（consolidate.ts 现有规则 1 的自然延伸）：同 scope + 同 kind + **规范化后全等**
   （trim、空白折叠、全半角统一、句末标点剥除）→ 不新增，importance +0.1（现行为只认原始全等）。
   仍不碰"意思相近但措辞不同"的（那是 §二 LLM 建议的事）。
2. **时间衰减**（遗忘曲线的保守版）：importance 按距 `lastRecallAt`（无则 `createdAt`）的天数温和衰减
   （乘性，日衰减系数默认 0.99，env `MEMORY_DECAY_DAILY` 可调，`0`=关=回滚），**下限 0.1、永不删除**。
   落点：读写路径惰性计算（取时修正并写回），**不做扫描 cron**（既有"刻意没有"不变）。
3. **使用强化**：recall 命中即 `touchRecall`（已有）之上 importance +0.05（封顶 10）——常用的记得更牢。

## 二、模型辅助巩固（半自动，人拍板，设置页入口）

- 设置→记忆页新按钮「**整理记忆**」（按 scope：global / 各 partner）→ 服务端一次 LLM 调用
  （默认模型链，复用偏好抽取的调用范式）把该 scope 最近 ≤200 条喂给模型，**只输出建议**：
  `{proposals:[{action:"supersede", keepId, dropId, reason}]}`——**一条都不自动执行**。
- 前端渲染建议卡（保留句 → 被收编句 + 理由），逐条「应用 / 忽略」；应用走既有 `supersede` 链路
  （旧记录保留可追溯，D18 兼容）。
- 回滚：`MEMORY_CONSOLIDATE_LLM=false` → 端点 404、按钮不渲染。
- 成本护栏：单次喂入条数上限 200、结果 proposals ≤ 50、超时/失败如实报错不假装。

## 三、已存记忆导入（做成功能）

- 契约：`POST /api/v1/memory/import`，body `{ scope: "global"|"partner:<id>", items: [{text, kind?, createdAt?, importance?}] }`
  → 逐条走 ingest 同一套校验与巩固（规范化等价 = 跳过并计数），`source="imported"`、缺省 importance 0.5。
  返回 `{ok, added, skipped, total}`。**只增不改**：绝不覆盖/删除已有记录。
- 前端：设置→记忆页「导入记忆」→ 选 `.json` 文件 → 预解析预览条数 → 确认导入 → 结果行。
  文件格式（对象或裸数组均可）写进接口文档；用户真实旧格式若不同，届时给转换脚本（本批先立通用口）。
- 回滚：`MEMORY_IMPORT=false` → 端点 404、按钮隐藏。
- 安全：imported 记录照常参与召回，但**不参与"重复收敛"去重别人**（只被别人收敛它），防止导入批次
  互相踩踏。

## 四、明确不做

语义去重自动化（措辞不同意思同的交给 §二建议制）、自动冲突消解、自动删除/归档、Dream 式后台巩固
cron、embedding、跨设备同步、记忆编辑 UI（既有"标过时"保留）、手机端。

## 五、验证

- `pnpm memtest`：规范化收敛（全角/空白/标点变体）、衰减下限与开关、使用强化封顶、
  导入跳过/计数/source、建议制端点契约（假模型）。
- 探针/单测：LLM 建议端点用注入假模型走通"建议→应用（supersede 落库）→ 忽略（无副作用）"；
  回滚开关三处（DECAY=0 / CONSOLIDATE_LLM=false / IMPORT=false）。
- `pnpm typecheck`、server 单测、http 探针全量。
