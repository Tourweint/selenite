## 零、目标（四件）

1. 索引页（设置 → 注入 → 索引）顶部能切换：**原生库 / 外部接入**。
2. 切换只换后面的库，**工具名不变**：`recall` 读当前库、`remember` 写当前库。

## 一、冻结契约

### 1.1 配置

`.data/memory-bank.json`（原子写；`MEMORY_BANK_PATH` 可覆盖）：

```json
{
  "v": 1,
  "active": "builtin",
  "external": {
    "id": "bank_xxxxxxxx",
    "name": "外部记忆库",
    "root": "D:\\Projects\\projects\\persona-metric",
    "ask": "analysis/ask.py",
    "repair": "analysis/repair.py",
    "python": "",
    "origin": "env",
    "addedAt": "2026-11-23T20:00:00+08:00"
  }
}
```

- `active` 只能是 `"builtin"` 或 `"external"`。**本批只支持一个外接库**，不做多候选列表。
- `external` 可为 `null`。
- `ask` / `repair` 存**相对 root** 的路径；解析后必须仍在 root 内（realpath 比对，防 `..` 逃逸）。
- 首次启动且文件不存在时：若 `PERSONA_MEMORY_ASK` 已配置，按它播种 `external`，但 `active` 仍为 `"builtin"`。
  文件一旦存在，文件是唯一事实源，env 不再偷偷改写。
- 查找顺序：`<root>/ask.py` → `<root>/analysis/ask.py`；`repair.py` 取 `ask.py` 同目录。
  找不到 `ask.py` = 不能接入；找不到 `repair.py` = 只读库。

### 1.2 端点（都挂 `/api/v1/agent/memory`，走现有鉴权）

| 端点 | 行为 |
|---|---|
| `GET /bank` | 当前状态：`{enabled, active, external:{...status, capabilities}, tools}` |
| `PUT /bank` | body `{active:"builtin"|"external"}`；切外部前校验文件存在 |
| `POST /bank/probe` | body `{root}`；识别 + 跑一次 `ask.py --catalog-only`，**不落盘** |
| `PUT /bank/external` | body `{root, name?}`；探测通过才保存（不自动切换） |
| `DELETE /bank/external` | 移除外接库；若当前是 external，先切回 builtin |
| `GET /bank/catalog` | 当前 external 的 catalog 文本（10 分钟缓存）；builtin 时 400 |
| `POST /bank/search` | body `{query, limit?}`；页面搜索，返回扁平 hits + coverage/unknown；builtin 时 400 |

- `GET /bank` 的 `status`：`ok` / `missing_ask` / `missing_repair` / `error`；只看文件存在性 +
  上次 probe 结果，**不每次起进程**。
- `capabilities`：`{read: bool, write: bool, catalog: bool}`；`write` 还要求 `PERSONA_WRITE_ENABLED=true`。
- 旧的 `GET /api/v1/agent/memory/external` **保留不动**（兼容老页脚/老客户端）。

### 1.3 读路由

- `active=builtin`：`recall` 走今天的 `engine.recall`，逐字节不变。
- `active=external`：`recall` 调当前 bank 的 `ask.py`（argv 数组、`--json --limit N`、15s 超时）。
  外接库 `groups` 组名不固定：解析成扁平 `hits`（`hit.group` 原样带出；`groups:{}` = 合法空结果），
  渲染用 `renderExternalBankAsk()`；输出仍是 `{count, message}`，**工具 schema 不变**。
- 外部读失败：返回 `err("memory_unavailable", ...)`，不要抛、不要悄悄回落到内置库。
- 群聊跳过个人记忆的现有规则对两个库都保留。
- 注入：
  - `active=external`：`persona_catalog` + 轻召回走当前 bank 的 `ask.py`；内置的
    `memoryRecallProvider`（个人记忆召回）跳过。
  - `active=builtin`：`persona_catalog` + 轻召回不注入；内置 `memoryRecallProvider` 照旧。
  - `projectIndexProvider` / `taskMemoryProvider` **不动**（它们不是个人记忆库）。
  - `MEMORY_BANK=false`：完全回到今天的注入行为（env + `PERSONA_MEMORY_INJECT`）。

### 1.4 写路由与闸门

- `active=builtin`：`remember` 走今天的 `engine.remember`，不变。
- `active=external`：`remember` 调当前 bank 的 `repair.py statement`：
  - `body = args.content`（原话；≤500 字）
  - `why = "用户让记住"`（固定原因；≤200 字）
  - `about` / `tag`：本批不传（`remember` 没有这两个参数）
  - `kind` / `scope` / `project` / `importance` / `expiresInDays` / `taught` 在外部模式下**不生效**；
    返回消息里加一句「外部记忆库只收原话；kind/scope 等参数未生效」。
- 写失败：返回 `err`，**绝不回落到内置库**。
- 闸门（硬约束，必须做）：
  - 外部模式下 `remember` 是「起进程 + 写外部库」，在 `lifecycle-harness` 的调用前闸门里按写工具对待：
    `AGENT_TOOL_POLICY=read-only` 必须拦下（错误文案说明切回原生/换档）。
  - 审批：外部模式下 `remember` 按 critical 处理（`ask-critical`/`ask-all` 都弹审批；
    `approval=none` 是用户显式选择，不弹）。内置模式行为不变。
  - `PERSONA_WRITE_ENABLED=false`（默认）时，外部 `remember` 返回「写入未开启」，不 spawn。
- `persona_write` / `persona_recall` 在 `MEMORY_BANK=true` 时**不再注册**（`recall`/`remember` 已覆盖）；
  `MEMORY_BANK=false` 时按今天注册。工具面变化要进 `变更记录`（缓存前缀资产）。

### 1.5 工具面

- `MEMORY_BANK=true`：无论 `active` 是 builtin 还是 external，工具名都是
  `recall` / `remember`（外部只读库时 `remember` 仍注册，但调用返回只读错误；**不动态摘工具**）。
- `MEMORY_BANK=false`：今天的 `recall` / `remember` / `persona_recall` / `persona_write` 原样。

### 1.6 开关

- 新增 `MEMORY_BANK`（boolean，默认 `true`，`hot:false`，memory 组）：总闸/回滚。
  - `false` = 旧形态（`persona_recall`/`persona_write` + env 注入 + 内置库）。
- `MEMORY_BANK_PATH`：配置文件路径覆盖（env，非界面开关）。
- `PERSONA_MEMORY_ENABLED` / `PERSONA_MEMORY_INJECT` / `PERSONA_WRITE_ENABLED` 语义保留：
  - `PERSONA_MEMORY_ENABLED=false`：外部读/注入全停；`recall` 外部返回「外部记忆库已关闭」。
  - `PERSONA_WRITE_ENABLED`：外部写总闸，默认关。
- `MEMORY_EXTERNAL` 保留原义（老页脚/旧端点显隐），不要改它的语义。

## 四、接入手册（Agent A 写）

`docs/接入手册/外部记忆库接入（两个文件）.md`：

- 你只需要提供两个文件：`ask.py`（查）与 `repair.py`（写）。
- 目录形状：
  ```text
  my-memory-bank/
    ask.py      # 读：query + catalog
    repair.py   # 写：一张表
    data/...
  ```
- `ask.py` 契约：`ask.py <question> --json --limit N` 的 JSON 形状（`groups[].id/text/date/why` +
  `coverage` + `unknown`）；`ask.py --catalog-only` 纯文本 ≤20 行；15s 超时；失败退出码非 0。
- `repair.py` 契约：`repair.py statement <body> [--about] [--tag] --why`；一张表；同 body 幂等；
  `--why` 必填；成功 exit 0 + 一行确认。
- 明确：**你会创建一张新表；建议定时内化；这张表要进 `ask.py` 的召回（怎么进由你定，harness 不管）。**
- 给一份最小模板（SQLite 单表 `external_note`，`ask.py` 用 LIKE/FTS，`repair.py` 建表 + upsert）。
- 说明：工具名不变（`recall`/`remember`），切换只换后面的库；不要直接改 `persona.db`。
