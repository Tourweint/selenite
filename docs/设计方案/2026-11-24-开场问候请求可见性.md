## 零、结论先行

用户的问题是「新建执事后那条主动问候，我在设置 → 注入 → 上下文的实际注入里看不到，
它的系统提示词有没有加入？」

**没有丢记录，缺的是入口。** 问候生成跑在一条隐藏会话 `task-greeting-<canonical内部id>-<attempt>` 里
（`partner-runtime-do-open-partner-conversation.ts:194`），那次请求的固定前缀（SOUL + 问候要求）、
消息、token 用量都在 durable 里；但上下文页的会话下拉只列 `listChats` 的会话，
`task-` 前缀全部被排除（`agent/session-index.ts:359-361`），所以这一页从来没读到过它。
而正正式会话里只写回一条 `usage=0` 的 `pi.assistant`（`partner-runtime-do-open-partner-conversation.ts:320-341`），
请求列表又按 `promptTokens > 0` 过滤（`request-stats.ts:196-197`），所以正式会话的请求列表里也不会出现这一条。

**做法（最小面）**：新增一个只读端点定位这次隐藏会话，人设页给一个入口，
上下文页支持按会话 id 深链选中它；请求详情沿用现有的 `context-inspect` / `requests` 两条只读链路。
不改问候生成、不改存储、不把隐藏请求混进正式会话的清单。

## 一、现状盘点（2026-11-24 只读审计）

### 1.1 问候那次请求实际发了什么

| 项 | 值 | 证据 |
|---|---|---|
| 生成会话 | `task-greeting-<conversationId(内部)>-<attempt>`，不在侧栏、不在上下文页下拉 | `partner-runtime-do-open-partner-conversation.ts:194` |
| 系统提示词 | 执事当前 SOUL + `GREETING_REQUIREMENTS`（第一次说话、2–3 句、最多一个问题、不报模型名、不宣称外部服务、不调工具） | 同文件 `:229`；`partner-runtime-run-partner-turn.ts:557-563` |
| 工具面 | 空（`configureTaskChat` 固定 `tools: []`） | `agent/session-open.ts:136-150` |
| 用户消息 | `GREETING_REQUEST`（「请按上面的要求，现在写下这句开场问候。」） | `partner-runtime-run-partner-turn.ts:565` |
| 写回正式会话 | 一条 `pi.assistant`，`usage` 全 0，`api/model = lifediary.say` | `partner-runtime-do-open-partner-conversation.ts:320-341` |

### 1.2 为什么设置里看不到

1. **上下文页下拉**：`chatChoices()` 读 `state.chats`（`settings-context.js:129-147`），
   来源 `listChats`；后者硬排除 `task-`（`agent/session-index.ts:359-361`，`index.ts:2601` 同口径）。
2. **请求列表**：按会话读 `pi.assistant` 且只收 `promptTokens > 0`（`request-stats.ts:188-197`）；
   问候写回 canonical 的那条是 0 用量，天然不列。
3. **注入预览**：`GET /partners/:id/injection-preview` 只现拼纪律 / 在办 / 履历三段
   （`companion-api.ts:1048-1075`），本来就不是完整请求，不含问候。
4. **端点本身不挑前缀**：`openChat` 按外部 id 解析（`agent/session-open.ts:312`），
   `context-inspect` / `requests` 对任意存在的会话都能读（`index.ts:2801-2854`）。
   缺的只是「把这条隐藏会话指出来」的入口。

## 二、方案

### 2.1 只读端点：定位那次请求

`GET /api/v1/partners/:id/greeting`

- 返回 `{ ok: true, enabled: boolean, conversationId: string | null }`。
- `enabled` = `PARTNER_GREETING_ENABLED`（只用于界面解释；关掉不影响历史记录是否可读）。
- `conversationId`：读 durable `Chats.byExternal` 快照，匹配
  `task-greeting-<sessionIdOfPartner(id)>-<n>`，取**最大 attempt**；还没有 canonical 会话或没有生成过 → `null`。
- 不存在执事 → 404 `not_found`。
- **回滚**：`CHAT_CONTEXT_INSPECT=false` → 404（与上下文页同一行；页面入口也一并失效）。
- 只读：不建会话、不动 doc、不触发模型。

口径：这是「指路」，不是第二份记录。正文（系统提示词 / 消息 / token）一律走已有的
`/api/v1/agent/chat/:conversationId/context-inspect` 与 `/requests`，不复制第二套。

### 2.2 人设页入口

在 `设置 → 执事 → 人设页`的「每轮固定注入」之后新增一个小节：
- 标题「一次性请求」，悬停说明：跑一次就结束，不属于每轮注入。
- 一张卡「开场问候」，点开弹层：
  - 已生成过：说明这次请求在隐藏会话里，并提供「在上下文页看这次请求」按钮，
    跳到 `#/settings/context?chat=<外部id>&label=开场问候`。
  - 还没生成：说明「新执事的问候在第一次打开专线时生成；如果已经打开过仍没有，
    可能是当时 `PARTNER_GREETING_ENABLED` 关着或生成失败」。
  - `PARTNER_GREETING_ENABLED=false`：额外一句「问候开关当前关着，不会再生成；历史记录仍可看」。
  - 卡与弹层写明口径：这是服务端替助手发起的**一次性**请求（类似定时任务到点让它自跑），
    不是每轮注入；**首条请求是冷前缀**（与正式会话的缓存互不影响），第一次打开会等它写完，
    命中率 0 / 稍慢属预期，整条请求只跑一次。

### 2.3 上下文页深链

`#/settings/context?chat=<会话外部id>&label=<显示名>`：

- 只在**本次渲染**里把这条会话合成一个选项（`chats` 里没有时），并优先选中；
  不并入 `state.chats`、不列其它 `task-` 会话。
- 强制回到「当前会话」模式（否则会被「没有真实会话 → 默认开销」的兜底冲掉）。
- 选中后照常拉 `context-inspect` + `requests`：请求详情里能看到 `instructions` 段
  （SOUL + 问候要求）原文、工具面 0 个、用户消息、助手回复与 token / 命中率。
- 回滚同上：`CHAT_CONTEXT_INSPECT=false` 时这一页本来就 404。

## 三、明确不做

- **不列全部隐藏会话**（例行 `task-routine-*` / 唤醒 / 池 / 隔离生成会话）。
  它们数量多且各自有生命周期，硬塞进下拉会变成第二张不可解释的清单；要做另立项。
- **不改问候生成 / 投递**，不动 `lifediary.partner-greeting` doc，不改幂等状态机。
- **不把隐藏请求混进正式会话的请求列表**：请求列表的语义是「一个会话里的模型请求」，
  混进来以后「这条请求属于哪条会话」就说不清了。
- **不动导出 / 记忆 / 手机端**；不新增存储、不新增 env。

## 四、备选与取舍

| 方案 | 取舍 |
|---|---|
| **A. 本方案（问候一条 + 深链）** | 范围最小，直接回答「这次请求在哪」；新增面只有一个只读端点 + 两个前端入口。 |
| B. 上下文页列全部隐藏会话 | 更通用，但要定隐藏会话的标签规则 / 数量上限 / 与任务专线的区分，动的是上下文页的会话清单本身；本次不做。 |
| C. 只在人设页做静态模板预览 | 最便宜，但不是「记录」：看不到实际发出去的那份系统提示词与用量；不满足用户「这次请求」的诉求。 |

## 五、验收

- `GET /api/v1/partners/:id/greeting`：无 canonical → `conversationId:null`；建过问候 →
  返回最新 attempt 的隐藏会话 id；未知执事 404；`CHAT_CONTEXT_INSPECT=false` → 404。
- 人设页：卡在「一次性请求」区；弹层按已生成 / 未生成 / 开关关三种情况给对应文案；
  已生成时按钮跳到上下文页并选中隐藏会话。
- 上下文页：深链打开后请求列表出现该次请求，详情里 `instructions` 段是 SOUL + 问候要求原文，
  工具 0 个，用户消息是 `GREETING_REQUEST`。
- 回归：普通会话的上下文页行为与下拉清单不变（深链参数缺席时逐字不变）。
