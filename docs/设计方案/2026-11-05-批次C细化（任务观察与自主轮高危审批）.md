## 〇、一句话

C1 = 一个纯程序级观察表订阅现行事件口（phase/tool/delegation/onSettled），产生六类事件并做
防风暴去重，宿主直接把"需要你"写进会话（手机拉 transcript 可见，不经模型）；
C2 = 自主轮（例行任务/事件唤醒的轮次，批次B 注入 `autonomous` 标记）里六类高危工具调用
强制走手机审批且禁"记住"——判定是纯函数 + 进程内标记，代码生效，不靠提示词。

## 一、目标与明确不做

**做**：卡住/等审批/出错/用量到顶四类可判事件有提醒且有上限；自主轮的派单/定时唤醒/写文件/
跑命令必须过手机审批；防自叫醒、防风暴三件套；开关关闭零行为。

**不做（v1 明确砍掉）**：
- **finished（交付完成）事件**：本仓库无"模型主动报交付"机制（已核实：grep 交付/deliverable
  零命中；完成判定全在 chancellor REPORT.md）。聊天轮次 done ≠ 交付，会把每次回答都当事件。
  v1 以"**派单终态 done 的回灌时刻**"为 finished 唯一来源，聊天完成不触发；
- **远程任务观察**（cindy 的跨机 glance）：单机无此形态；
- **推送通道**：本仓库无服务器推送（手机全靠拉），不新建推送——"等审批"手机轮询全局待办
  本来就可见，C1 增量提醒走**写会话行**（`sayInConversation`，桌面/手机拉 transcript 均可见）；
- **新 SSE 事件类型**：v1 提醒不进事件流（无前端消费场景），只写会话 + 日志；
- 自主轮的例行任务管理工具：B3 的 routine 管理是 HTTP 端点，模型没有对应工具——
  "授予常驻指令/删除自动化/恢复暂停"三类在模型工具面**暂不可达**，本批登记为
  "结构上不存在"，将来给模型开 routine 工具时必须同时进 C2 风险表（写进 D14 备忘）。

## 三、C1 设计：任务观察层（新文件 `src/autonomy.ts`）

### 3.1 订阅与数据源

- 消费批次B 加的 `watchAllEvents(cb)`（phase/tool/delegation 三发射口广播）+ `onSettled`
  回调登记口；观察表为进程内 `Map<conversationId, ConversationWatch>`：
  - `lastActivityAt`（任何事件刷新）、`workingSince`（phase=working 时刻，phase 切换重置）、
    `toolInFlight`（tool start 无 end）、`runStartedAt`（chatStream 提交时刻）；
- 派单终态来自 delegation 事件（phase: done/failed/needs_you）；用量到顶来自
  `unanswered` 结算 + **复用批次B4 的 reason 归类器**（连接/鉴权/配额/容量才判 usage-limit，
  其余归 errored）。

### 3.2 六类事件（v1 落地五类）

| 事件 | 判据（纯程序级） | 提醒动作 |
|---|---|---|
| stuck | working 持续 > `AUTONOMY_STUCK_MIN_S`（默认 600s）且无 tool end；toolInFlight 时放宽到 2700s（照 cindy 45min） | 写会话行："任务卡住了：会话 N 已无进展超过 X 分钟" |
| waiting | approvals 存在 pending 且 age > 300s | 不重复写（手机全局待办已可见）；仅计入 sweep |
| errored | onSettled unanswered（非配额类）或 delegation failed | 写会话行："上一轮没有生成回复/派单失败：<枚举原因>"（原因枚举不透传上游原文） |
| usage-limit | unanswered 且 reason 属配额/容量类 | 写会话行："模型用量受限（配额/容量），稍后再试或换候选模型" |
| finished | delegation done 回灌 | **不写行**（`formatReport` 已写"已完成"）——只结清该任务的观察状态 |
| sweep | 兜底：`needsSweep()`（有观察对象且存在未结清状态）时按 2h 时间桶发 | 写会话行："有 N 件事等你处理：…"（≤140 字，枚举不含正文） |

- sweep 定时器：**按需 setInterval（30s）**——`needsSweep()` 为假即 clearInterval。
  这是观察层例外，不是通用 cron：落地时在 `系统架构.md` D14 备注里写明
  "观察层 sweep 不属于'定时扫描型 cron 刻意没有'的范畴（无任务图、无持久队列）"。

### 3.3 防风暴三件套（照抄 cindy，全部落盘）

- **事件 id** = `类型:会话号:进入该状态的时刻`——同一状态只提醒一次，跨重启稳定；
- **上限**：同会话同类型 24h 内最多 6 次（第 7 次起只记日志，occurrence 计数供排查）；
- **sweep 桶**：按 会话号+2h 时间桶分 id；引擎层回执表 24h 滑窗去重兜底重启；
- 状态落盘 `.data/autonomy-state.json`（原子写，照 approvals.json 惯例；只存 id/计数/时刻，
  **不含对话内容与工具参数**，对齐 D8）。

### 3.4 防自叫醒与对象范围

- 观察对象 = **主人主会话 + 派单事件**；伙伴专线会话（`partner_session_links` 可识别）v1
  **全部排除**（没有跟进者，观察它只会自己叫醒自己）——批次C v1 不建内置"跟进"规则，
  内置跟进留待"伙伴认主机/多端同步"阶段一并做（那里才有"谁跟谁"的归属问题）；
- `task-` 前缀任务会话照 listChats 口径排除。

## 四、C2 设计：自主轮高危审批

### 4.1 自主轮标记（双轨，进程内为事实源）

- **进程内事实源**：批次B3 执行例行轮时把 conversationId 加入进程内
  `autonomyTurns: Set<number>`，`onSettled` 移除——判定读这个 Set，**不解析消息文本**
  （代码生效原则）；
- **文本注入（透明性）**：投递指令头仍保留一行 `[Scheduled run context] turnAuthority: autonomous`
  （模型可解释为什么被要求审批），但该文本**无判定效力**。

### 4.2 风险表（纯函数 `src/autonomy-risk.ts`，六类映射到本仓工具面）

```ts
// 输入：(tool, 是否自主轮)；输出：force-ask / normal
// 自主轮 + 下列工具 → 一律强制 ask，且本次不许 remember（禁"记住"绕过）
RISK_TOOLS = {
  "set_reminder":     "schedule",     // 调度命令/常驻指令（定时唤醒是常驻载体的现成形态）
  "delegate":         "new_task",     // 新建完全访问任务（派单）
  "propose_project":  "new_task",     // 新建项目请求
  "write"/"edit"/"bash"/"powershell": "write",  // 写/执行（现行 ask 面在自主轮收紧为必问）
  "partner_skill_write": "write",     // 伙伴技能写入
}
```

- 六类中**结构上不可达**的三类（授予常驻指令的 routine 工具 / 删除自动化 / 恢复暂停执行）
  登记进 D14 备忘："给模型开 routine 工具前，先把它加进 RISK_TOOLS"；
- "代主人回答权限请求"的等效实现（更严）：自主轮内出现的审批 ask **一律**转全局待办
  等人答复，且 `isRemembered` 对自主轮**恒 false**、答复端点 `remember` 参数对自主轮
  记录**忽略**——自主轮不能通过任何路径自答或免审；
- 判定插桩：beforeTool 现行审批段（agent.ts:582-603）前加一步：
  `if (autonomyTurns.has(api.conversationId)) verdict = riskVerdict(call.name)`
  （force-ask 优先于一切 allow，含 policy.confirmWrites=false 与 remembered）；
- 普通（非自主）轮行为**完全不变**——`AGENT_CONFIRM_WRITES` 默认关的口径不动。

### 4.3 审批卡呈现

复用现行 approval 事件与全局待办（approval 帧加一个可选字段 `origin: "autonomous"`，
纯增量，老客户端忽略）；卡片文案前缀"【例行任务】"（`formatReport` 同款 ≤80 字纪律）。

## 六、安全与纪律自查

- 日志/落盘：autonomy-state.json 与日志只含 会话号/枚举/计数/时刻，不含对话内容与工具参数（D8）；
- 提醒行 ≤140 字、枚举化（照 `formatReport` ≤80 字先例的口径自定上限并写死常量）；
- fail-closed：自主轮审批无答复 = 超时拒绝（复用现行 120s 与 fail-closed 语义）；
- 回滚：`AUTONOMY_ENABLED=false`（envFlag 惯例）→ 观察表不建、事件口不订阅、
  `autonomyTurns` 恒空、riskVerdict 不生效，行为与改动前完全一致。

## 七、验证

- 新探针 `scripts/autonomy-probe.ts`（骨架照 approval-probe.ts，隔离 env 照 http-probe :36-56）：
  1. `AUTONOMY_ENABLED=false`：例行任务照常跑、零提醒行、零强制审批（零行为回归）；
  2. 自主轮调 delegate → 全局待办出现 `origin:"autonomous"` 卡 → 不答复超时 → 拒绝文案入轮；
  3. 自主轮 `remember` 过的工具再调 → **仍弹卡**（禁 remembered 生效）；
  4. 非自主轮同工具在 `AGENT_CONFIRM_WRITES` 关时不弹（普通轮行为不变）；
  5. stuck：env 注入 `AUTONOMY_STUCK_MIN_S=2` 跑一个挂着的 faux 轮 → 会话行出现；
  6. 防风暴：同会话同状态重复触发 7 次 → 会话行只有 1 行 + 日志 occurrence=7；
  7. 重启：state 文件回执去重生效（同事件 id 不重提醒）；
- `pnpm typecheck` + `pnpm probe` 全量不回归；`pnpm --filter @lifediary/server phone` 探针
  （确认全局待办新增字段不破坏现有断言）。

## 九、风险与坑（提前登记）

- **提醒写会话行 = 落库内容**：文案必须枚举化，严禁把工具参数/错误原文拼进去
  （上游原文可能带 key 片段，只进服务端日志）；
- **stuck 误伤长工具**：bash 长任务（默认 900s 超时）会比 stuck 阈值（600s）先被观察——
  toolInFlight 放宽 2700s 的判据就是为此（照 cindy 实测值），探针场景 5 用注入小阈值绕开；
- **自主轮标记的生命周期**：chatStream 抛错路径也要清 `autonomyTurns`
  （try/finally，对齐 `stopChat` 的 expireAll 兜底，agent.ts:1587-1592）；
- **cindy 阈值直搬的假设差**：cindy 10min/45min 是 Electron 前台交互节奏，我们 Bash 默认
  900s——落地时若探针发现误伤，先调阈值常量再考虑判据，不先加白名单。
