## 〇、一句话结论

**核心循环不用补。** 我们锁的 `pi-durable@1.4.0` 内核已经带齐了行业标配的底盘：compaction（含 overflow 压缩后原地重试）、指数退避重试、崩溃续跑（restartLimit）、忙时收件箱排队（steer/followUp）、`fork`/`reset`/手动 `compact()`、`sleepUntil` 定时——且大部分已接。真正的缺口集中在四类：

1. **审批闭环没有"ask"**：权限只有 allow/deny（三档+黑名单），没有"逐次等人确认"流——D6 自己写明"接 IM/公网前必须升级"，这是登记在案的欠账；
2. **记忆召回窗口太窄**：召回路径根本不经过 SQL（`recall.ts:27-30` 取最新 50 条候选 → JS 双字片段 `includes` 打分；`store.ts` 的 LIKE 是没人调的死分支），老记忆超出 50 条窗口就永远召不回；FTS/向量未做（审查实测：FTS5 trigram 对 2 字中文查询**零命中**，而现有策略恰以 2 字词为主力，上 FTS 必须配短查询回落）；
3. **工具侧无超时，旋钮全空**：真正无上限的是 bash（内核"no default timeout"，`bash.js:8`），一条挂死命令能把整轮钉住；模型请求侧未设 `stream.timeoutMs` 时走 OpenAI SDK 默认 10 分钟（`pi-ai types.d.ts:88-92`、`openai-completions.js:194` 只在显式传时设 timeout）；`settings` 其余旋钮全吃内核默认且无一显式化；
4. **派活映射不落库**：ticketId↔conversationId 只在进程内存（tools.ts:190），重启后终态状态写不回原对话（架构 §7 已知边界）。考古（变更记录 2026-11-02）确认"不落库"只论证了 **resume 接续**不需要映射，没论证**回灌**——两者拆开：resume Map 保持内存，回灌映射单独落回执库。

其余"参考 agent 都有而我没有"的东西，要么已有等价物（排队/后台任务/扩展点），要么 coding 专属不适用，见 §四 分级。

- 落法（概要，2026-11-04 审查修订后）：
  - **ask 做成独立轴，不并进三档**：三档是"能力边界"（能写吗/能跑命令吗），ask 是"确认策略"，压成一个枚举会无法表达"只读+确认"。用 policy 里独立布尔 `confirmWrites`（默认 false，回滚时字段被忽略即旧行为）；**未知档位一律落到最严档 read-only**（现状代码未知值会落到 base.access=full，是 fail-open，必须改）。
  - pending 审批必须**落库**（callId/会话/工具/参数摘要/截止时间）+ `GET .../approvals` 重连续看 + 答复端点幂等；审批与 `/stop`、abort、并行工具多请求挂起的交互语义要写清。
  - **隐私口径**：审批事件要带参数摘要才能让人判断，但 AGENTS.md 要求日志不含对话内容——写明"只进 SSE/事件流，不进日志"。
  - 契约影响清单要含**内置 web**（web/app.js 分段控件三按钮 + index.ts:277-279 三值校验）+ shared 事件 + 接口文档 §7 + 手机端。
  - 验证：审批判定做成可测纯函数（参照 `readOnlyBlockReason` 先例）+ probe 断言，不只靠 http 探针。
- 量：M-L。回滚开关：`confirmWrites` 默认 false = 旧行为。

**A2. 记忆召回质量** —— 日记 agent 的核心资产（2026-11-04 审查修订：病因与落法全改）
- 真实病因（审查核实）：召回不经过 SQL 检索——`recall.ts:27-30` 只取**最新 50 条**候选（`Math.max(limit*5, 50)`），关键词是 JS 双字片段 `includes`（recall.ts:72-89）；`store.ts:143-146` 的 LIKE 是死分支。老记忆超出 50 条窗口永远召不回。
- 分两步：
  - **A2-S（小，并入批次一）**：候选窗口下限 50 → env `MEMORY_CANDIDATE_FLOOR` 可调（默认提到 200），不动打分权重、不碰抽取层；memtest 补"超过 50 条库里旧记录能召回"用例。
  - **A2-F（中，单列批次）**：真正的文本检索入口（`store.search` 接 text 或 FTS5）。**约束（审查实测）**：FTS5 trigram 对 2 字中文查询零命中，而现有策略以 2 字词为主力——查询 <3 字必须回落现有 JS/双字路径；memtest 必须补 2 字/3 字/中英混排三组。**抽取层本次不动**（HeuristicExtractor 纯规则），触发条件：FTS 上线后仍召回不佳再立项。
- 参考实现索引：oh-my-pi 记忆工具族+可插 backend；cindy MakerMemoryManager（FTS 检索）。
- 量：S + M。回滚开关：`MEMORY_CANDIDATE_FLOOR=50` 即旧行为；FTS 检索入口做成 `MEMORY_RETRIEVER=fts|js` 退回。
