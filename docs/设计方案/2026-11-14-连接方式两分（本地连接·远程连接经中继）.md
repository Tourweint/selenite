# 2026-11-14 连接方式两分（本地连接 · 远程连接经中继）

> 用户原话：「在同一个 WiFi 下和不在同一个 WiFi 下需要区别。我用数据线连接它，也算同一个 WiFi 吧？就叫『本地连接』『远程连接』吧。远程连接需要加上『经过中继』这一块。一连机设备时，显示它使用什么连接方式，最近连接时使用什么方式。」

**状态：已落地 2026-11-14**（下沉落点见文末表；冲突以长期文档为准）

## 结论

1. **页面分节改名，按"怎么连"分，不按"在不在一个 WiFi"分**：
   - **本地连接**：同一 WiFi、USB 数据线（adb reverse 到 127.0.0.1）、USB 共享网络——物理上够得着这台电脑的都算。
   - **远程连接**：跨网络，唯一现实路径是**经过中继**，所以这一节的第一行就叫「经过中继」（出一次性加入码 + 中继名册）。
2. **设备行带连接方式**：每条设备显示「现在·本地连接 / 现在·远程连接（经中继）」+ 最近活跃时间；如果用别的路连过，再补一句「上次走数据线（2 小时前）」。
   连接方式**不由手机上报**，由服务端按"这条请求从哪个地址进来"判定并落盘，改动只在 harness 一侧。
3. **「看不到连接」的根因补上**：用主令牌（`AGENT_TOKEN`）从非本机地址连进来的设备，既不进本地配对名册、也不进中继名册，于是页面一片空白。现在这类请求单独记一条「未配对设备（用主令牌直连）」，页面上列出来并提示扫码配对——看得见，才知道去修什么。

## 判定口径（服务端）

| 请求从哪来 | 方式 | 依据 |
|---|---|---|
| 本机回环 + 设备令牌（配对换来的） | 本地连接（数据线/本机转发） | `getConnInfo` 的 `127.0.0.1` / `::1`；手机经 `adb reverse` 就是这样到的 |
| 内网地址 + 设备令牌 | 本地连接（同一 WiFi / USB 共享网络） | 10/8、172.16/12、192.168/16、169.254/16、IPv6 ULA/link-local |
| 公网地址 + 设备令牌 | 远程连接（公网直连） | 其余地址；只有自己做了端口映射才会出现 |
| 经中继进来的请求 | 远程连接（经中继） | 中继名册（`/api/v1/relay/overview` 的 `devices[]`），不参与地址判定 |
| 主令牌 + 非本机地址 | 未配对设备 | 鉴权中间件里"共享令牌通过但来源不是本机" |

落盘字段（`pairing.ts` 的 `StoredDevice`，只增不改）：
`lastTransport`（`local` / `usb` / `direct`）、`lastTransportAt`、`transportAt`（三种方式各自最后一次的时刻，供「上次走…」）。

## 取舍 / 备选

| 备选 | 不选的理由 |
|---|---|
| 让手机在上报里带 `transport` | 跨仓库契约（手机端 Kotlin），老版本 App 不认；而且手机自己并不知道自己在走哪条路 |
| 把"数据线"作为第三种独立方式 | 用户口径就是"数据线也算本地"；单独列会变成三种连接方式，页面更绕。判定里仍区分 `usb`，只为把"上次走数据线"说清楚 |
| 两套名册合并成一张（pair 指纹 + relay deviceId） | 2026-11-14 已拍板不合并（deviceId 由令牌派生、指纹由 id+tokenHash 派生，不是同一种身份）。这里只在**同一个列表里并排显示 + 打标签**，id 不互换 |
| 把 `online` 做成真在线表（每次请求打点） | 不值当：`lastSeenAt` 已经在每次请求刷新，90 秒窗口当"在线"足够区分"刚刚用过/早就断了" |

## 明确不做

- 不改手机端任何代码与协议；手机不需要知道自己被标成什么。
- 不做连接方式的历史曲线、不做断连统计（这些是运维指标，不是这一页要回答的问题）。
- 不合并两套名册的 id；中继设备仍以 `deviceId` 为主键，本地设备仍以配对 `id` 为主键。
- 不把「未配对设备」的 IP 明文展示（只说"来自局域网/公网"+ 时间）。
