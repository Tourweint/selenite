# 本机自动连接与令牌门

> 2026-11-03。首次打开要求填 `AGENT_TOKEN`，但令牌只对跨设备有意义。
> 桌面壳和本机 Node 服务本来就在同一台机器上，不该让人抄令牌。

**状态：已落地（2026-11-03）。冲突以 `docs/基线文档/` 为准。**

| 结论 | 下沉落点 |
|---|---|
| 本机页面用进程内 cookie 自动放行，远程仍需令牌 | `接口文档.md` §1、§6 |
| 鉴权三档：共享令牌 / 配对设备凭据 / 本机页面 cookie | `系统架构.md` 模块表、D1 |

## 改之前是什么样

- `AGENT_TOKEN` 由启动服务的人通过环境变量设置，不生成、不落库、不下发；空 = 只放行 loopback。
- 配了 `AGENT_TOKEN` 后，**所有** `/api/v1/*` 都要 `Authorization: Bearer`，包括 loopback。
- 桌面壳只有在自己的进程环境里读到 `AGENT_TOKEN` 时，才会把它拼进页面 URL 的 fragment；
  壳里没有这个变量，页面就会 403 并弹出令牌门。
- 令牌门还有「取消」，点掉以后页面看着能用，但每个数据接口仍 403。

## 方案

1. 服务启动时随机生成一枚进程内秘密，从 loopback 打开 `/` 时下发为 `lifediary_local` cookie：
   `HttpOnly`（页面 JS 读不到）、`SameSite=Strict`（别的网站发来的请求带不上）、`Path=/`。
2. 鉴权中间件：来自 loopback **且带这枚 cookie** 的请求直通；其余请求仍按共享令牌 / 设备凭据校验。
3. 令牌门去掉「取消」，只保留一个动作按钮；文案改成「本机打开不需要它」。

## 为什么不是别的做法

| 备选 | 不采用的原因 |
|---|---|
| loopback 一律免令牌 | CORS 是 `origin: *`，任何网页都能跨域读写本机 API；会把「本机」变成后门 |
| 服务端提供「取令牌」接口 | 等于把密码交给任何能访问该接口的人，比手填更糟 |
| 桌面壳自动生成并持久化令牌 | 浏览器直接打开仍拿不到；还多一份要轮换、要防泄漏的本地状态 |
| 复用 localStorage 里旧令牌 | 只解决同一浏览器的旧会话；换壳、换浏览器、清缓存都会再次弹门 |

## 明确不做

- 不改 `AGENT_TOKEN` 的生成方式（仍由人设置，仍只走环境变量）。
- 不做账号体系、不做远程免登录。
- 不改托盘相关文件。
