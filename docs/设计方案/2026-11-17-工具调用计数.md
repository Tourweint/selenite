# 工具调用计数（含 deferred 与 loads）+ 技能斜杠漏计补齐（2026-11-17）

## 状态

**已落地（同日）**。机制下沉：账本与口径见本文「口径与存储」；端点契约下沉
`docs/基线文档/接口-端点2-杂项日记与项目.md` §2.5（`GET /api/v1/agent/tool-usage`）。
冲突以长期文档为准，本文留"当时怎么想的"。

## 背景与目标

工具面已经有"按需加载"（2026-11-16 工具裁剪 C 段：8 个管理型工具 defer，
系统提示只留 `tool_index` 一句话清单，模型要用先调 `tool_search`）。技能侧
2026-11-10 批 17 起有用量账（`recordSkillUse` → `.data/skill-usage.json`，技能页
展示「用过 N 次」），但工具调用没有任何计数。

用户目标：**按真实使用频率动态调整上下文**——"有些技能或工具可能被隐藏了，但
可能还用了很多"，这要有账可查。本批只立数据底座，调整策略本体（提升常被用的
deferred / 收敛常驻）另立项。

## 口径（计什么、不计什么）

| 事件 | 是否记账 | 说明 |
|---|---|---|
| 模型发起的工具调用**真实执行完** | `count` +1（成败都算），`err` 分桶 | 挂 `lifecycle-harness.ts` afterTool，`call.parent === undefined`（嵌套调用今天不存在，过滤是钉口径不是削数据）；内核 bash/read/write/edit、deferred 加载后的调用、worker 会话的调用全走这条，天然覆盖 |
| `tool_search` 命中加载一个 deferred | `loads` +1 | `loads ≠ count`：搜出来没调用也留痕——这正是"被藏起来但老被要用"的信号 |
| 被闸门拦下 / 工具不存在 / 参数校验失败 | **不计** | 内核 `tool.js` call phase 提前 settle，不经 afterTool；拦下另有 `gate-blocks.jsonl` 审计（AGENT_GATE_AUDIT），两本账不重复 |
| 斜杠 `/技能名` 调用技能 | **补计**（此前漏计） | `skillSlashProvider` 取到手册后 `recordSkillUse(name)`；dryRun（injection-preview）不记，审计不许污染账本 |
| skill 工具取手册 | 已有（批 17），不动 | |

## 存储与形状

`.data/tool-usage.json`（仿 `skill-usage.json` 全套惯例）：

```json
{ "usage": { "bash": { "count": 12, "err": 1, "loads": 0, "lastUsedAt": "…" } } }
```

- 每次写前重读整份 + tmp+rename 原子写（`flags.ts:23` 既定拍板：单进程 + 原子写足够，不做文件锁）；
- 坏 JSON / 缺字段当空账或补 0，写失败只 warn 不挡主流程（旁路审计不能挡主动作）；
- **永不删除**（同 skill-usage：工具删了记录留着无害，重装同名接得上）；
- 模块 `ts/apps/server/src/tool-usage.ts`；测试路径 env `AGENT_TOOL_USAGE_PATH`。

## 端点与前端

- `GET /api/v1/agent/tool-usage` → `{tools:[{name,count,err,loads,lastUsedAt}]}`，按 count 降序；
  `TOOL_USAGE=false` → 404（与账本停记同一行回滚）。
- 用量页（设置→用量）第四张卡「工具调用」：工具 / 执行 / 失败 / 按需加载 / 最近使用；
  **同日调整**：这张卡已撤，工具用量统一放「设置 → 工具」页的「用量」列
  （用户拍板，见 `变更记录/2026-11-17-工具调用计数.md`）；端点仍是同一份。
  **全部累计，不随上面的 7d/30d 区间走**；404 / 没记录 / 读取失败 → 整节隐藏，不出空卡。
- 复用 `skillLastUsedText`（skills-settings.js）做"N 天前"文案。

## 备选与取舍

- **挂哪**：afterTool 钩子（选定）vs `watchAllEvents` 订阅者（index.ts 现有 routineEngine/
  autonomyObserver 同款）。后者零侵入 agent/，但只拿到过了闸门的 UI 事件、拿不到
  `call.parent`，且 `emitTool` 是给前端的展示通道，计数贴着它耦合没必要。钩子处
  failure-streak/loop-guard 记账已在，是既定的记账位置。
- **离线统计**（扫 `pi.tool-result` 的 `toolName`）可答同样的题，但每问一次扫全库，
  不适合做实时主路径；留作将来回填历史的手法（模式照 `usage-range.ts`）。
- **维度**：只记全局按工具名一本账。动态调上下文要的是全局频率；分人设/项目维度
  等真有需求再扩账本结构（`err`/`loads` 就是这么加上去的）。
- **开关形态**：env-only `TOOL_USAGE`（仿 `SKILL_USAGE`），不进 plugins.json——
  计数是纯旁路，不值得占一个设置行。

## 刻意不做

- **不回填历史**：账从部署日起积累。要历史就写一次性脚本扫 durable `pi.tool-result`
  entry 的 `toolName`（`model[0].toolName` 就带名），不进本批。
- **不做动态调整本体**：提升/收敛策略要另立方案（它改的是上下文构成，是契约级动作）。
- **不动工具描述与注册顺序**（prompt-cache 前缀资产）；日志零内容（只落计数枚举）。
- **不计"被拦"次数进这本账**：口径是"执行了几次"，不是"试了几次"；审计在 gate-blocks。
