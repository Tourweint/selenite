七原则：① 每个元素回答三问之一（有需要我的吗 / 系统健康吗 / 这活经历了什么）；
② 数字等于它链接的列表长度；③ 标签说"在等谁、需要什么"、不露内部状态码；
④ 用领域词不用内部 id；⑤ 诚实状态（不与另一处事实矛盾）；⑥ 默认安静；⑦ 控件一致。

## 一、任务中心看板

| 原则 | 结论 | 处置 |
|---|---|---|
| ① 三问 | 符合 | 三列 = 有需要我的吗；统计条 = 系统健康吗；派活行/详情 = 这活经历了什么。保留"派活"计数（规模指标，副行与统计条同源）。 |
| ② 数字=列表长度 | **已改** | 任务详情的「验收记录」标题写的是 `reviews.length`，列表却 `slice(-6)` —— 数字比列表长。改成逐条全渲染（改后标题叫「验收证据」）。其余：列头计数 = 该列卡片数、已完结横条计数 = 其列表长度、统计条与对应列同步计算，均一致。 |
| ③ 不露内部状态码 | **已改** | 验收记录的 `stage` 原样印 `process / report / artifacts / llm`（mono 字体，像调试信息）。改成中文「过程 / 汇报 / 产物 / 模型」。状态 chip、灯文案本来就是人话。 |
| ④ 领域词 / 不用内部 id | 部分符合，暂不改 | 任务单号是**对外 uuid**（可引用、可贴给人看），不是内部自增 id；子单行与详情里的「任务单 …」保留它。理由：去掉后用户没法指认"就是这一单"，且替换需要新的短号体系（存储与契约改动），超出本批。 |
| ⑤ 诚实状态 | **已改** | ①「已完成」的统计把**已作废**的单也算进去（作废单按既有口径归入已完结折叠区），等于把"作废"说成"干完了" → 统计条、聚合灯、已完结横条统一改叫「已完结」，横条去掉「（已完成）」。② 标题副行「N 次派活」原来用 `tickets.length`（把子单也算成一次派活），与统计条「派活」的算法不一致 → 两处统一走 `dispatchedCount()`（父单一行算一次）。 |
| ⑥ 默认安静 | 符合 | 一张单都没有时统计条与筛选整块隐藏；健康态不额外横幅。列内空只写一行「无」。不再动。 |
| ⑦ 控件一致 | 符合 | 看板动作走 `.tk-act` / `.ghost`，状态片统一 `.tk-chip`，无孤立样式。 |

## 二、审批浮窗

| 原则 | 结论 | 处置 |
|---|---|---|
| ① 三问 | 符合 | 整块只在"有需要我的"时出现。 |
| ② 数字=列表长度 | 符合 | 「还有 N 条待处理」是队列提示，不是指向某个列表；处理掉上面 3 条后自动补位。 |
| ③ 说"在等谁、需要什么" | 符合 | 来源行（`approvalSourceLabel`）说谁在等；参数预览说在等什么；ask_user 卡直接给问题和选项。 |
| ④ 领域词 / 不用内部 id | 部分符合，暂不改 | 抬头印的是工具原生名（`bash` / `write`）。改成中文要一张**会变的**工具名表（`TOOL_KINDS` 只覆盖一部分），且对话流里的审批卡必须同时改，否则两处说法不一致。属内容资产，单独立项，本批不动。 |
| ⑤ 诚实状态 | 符合 | 倒计时按 `approvalMode` 分支：blocking 才写秒数，async 只写「等待处理」，不编截止时间。 |
| ⑥ 默认安静 | 符合 | 无待办时整个 host `hidden`，不占角落。 |
| ⑦ 控件一致 | 符合 | 批准 / 拒绝 / 带说明拒绝与对话流卡同款 `.ghost`；忽略是一个 ×，语义与对话流卡一致。 |

## 三、明确不做的

- **不重排视觉**：三列、统计条五块、折叠区的位置与密度都不动。
- **不改工具中文名**（见上：会变的清单 + 两处必须同步）。
- **不给技能加归档按钮**（批 18 §4.2）。
- **不做独立审批列表页**：浮窗的「还有 N 条」目前没有跳转落点，需要新页面才成立，不在本批。

## 四、与本批其他条目相关但不算七原则的（写在这里备查）

- 任务详情**没有**裁判结论（`judge.json`）：`GET /api/v1/tickets/:id` 未投影该文件，
  本批不加端点，界面上就没有这一块（见本批变更记录）。
- 验收证据**没有**结构化的"改了哪些路径"：`changedPaths` 只在 `run.json`，reviews 表只有
  `seq / slug / verdict / reason / stage`；artifacts 阶段的 `reason` 文本里带路径清单，
  界面原样呈现，不另编字段。
