## 二、设计

### 2.1 A：汇报带产物指针（唤醒轮的最后一厘米）

`DelegationReport`（`delegation.ts:79`，服务端内部结构，**不是 shared 契约，手机端不感知**）加可选字段：

```ts
export interface DelegationReport {
	ticketId: string;
	domain: string;
	phase: DelegationPhase;
	text: string;              // 80 字口径不动
	productDirs?: string[];    // 新增：任务产物目录（result.tasks[].dir，最多 3 个，缺省无此字段）
}
```

- `formatReport`（`delegation.ts:446`）从 `result.tasks[].dir` 填充：`filter(Boolean).slice(0, 3)`，与 work-record 同口径。
- `buildWakePrompt`（`delegation-wake.ts:125`）每行追加落点：有指针时渲染

  ```
  - 单 3f2a91…（done）：登录页改完，探测 12 项全绿
    落点：runs/3f2a91/task-1-login
  ```

  无指针时逐字节与今天一致（旧调用方、faux 链路不破）。
- 汇报正文（`report.text` / 镜像【汇报】行）**不动**：80 字口径与镜像内容是既有决定，指针只进唤醒提示词。
- 回滚开关：不新增——指针只出现在唤醒提示词里，`DELEGATION_WAKE_ENABLED=false` 即整体回到改动前。

### 2.2 B1：远端单台账 TTL 落实（兑现自己的注释）

`relay-matrix.ts` `RemoteDelegationStore`：

- 常量 `REMOTE_LEDGER_TTL_DAYS` 默认 7，env `REMOTE_DELEGATIONS_TTL_DAYS` 覆盖；**0 = 不清理（回滚形态）**。
- 清理点：`list()` 读时惰性清扫——`finishedAt` 已设且距今超过 TTL 的行直接从 Map 删掉，删了就 `save()`。读侧清扫覆盖所有消费方（手机代理、状态端点），无需定时器。
- 语义与注释一致："状态查询仍可问目标机"——台账行只是发起端镜像，清掉不丢事实。
- 纯函数 `sweepRemoteRows(rows, now, ttlDays)` 拆出来单测。

### 2.3 B2：任务卡陈旧提示（文案层，纯前端）

`web/app.js`：

- "执行中"相位（`accepted/planning/running/reviewing`，即非终态）且 `now - updated_at > 24h` → 卡片时间行追加"（很久没动静）"。
- 不改灯语义、不加 class 以外的样式体系、**不加任何契约字段**（`updated_at` 已在 payload 里）；终态卡不加（终态就是终态，`needs_you` 等人 ≠ 陈旧）。
- 详情页"心跳"行同规则追加一句。
- 阈值 24h 写成常量 + 注释（"陈旧提示是文案不是状态：它只改变人看到什么，不改变机器判什么"）。

### 2.4 C：寒暄禁令入册（用户 2026-11-10 拍板）

`系统架构.md` "刻意没有的"加一条：

> **不做工人定期上报进度 / 派活前打招呼确认这类点对点通报。** 痕迹协作口径（2026-11-10，源自 stigmergy 讨论）：状态写进环境（任务卡、回执、REPORT.md、work 履历），想看的人自己去看；中间进度靠执行端写回，不靠消息传。谁再提"定期上报"先来读这条。

### 2.5 已知边界（随变更记录登记）

1. 前端陈旧提示阈值 24h 是文案层：卡了 25h 的单提示"很久没动静"，但状态机不降级、不通知。
2. 远端单台账 TTL 7 天：清掉后发起端看不到历史行，事实仍可问目标机（与既有注释同口径）。
3. 运行中任务无超时收割（见取舍3）：进程活着就挂着，死了等重启恢复。

## 三、取舍与备选

| # | 取舍 | 备选（弃） | 为什么 |
|---|---|---|---|
| 1 | 指针只进唤醒提示词 | 汇报正文 80 字里挤目录路径 | 80 字口径与镜像内容是批 29 定的，动它要另过方案；唤醒轮是"接住结果"的那一轮，指针给到正主就够 |
| 2 | TTL 走读侧惰性清扫 | 定时器周期扫 | 少一个常驻机制；台账本来就低频写、读时清足够；定时器要管生命周期，惰性清扫天然免维护 |
| 3 | 不做运行中收割器 | N 天无心跳自动转 failed/死信 | 收割=强杀，误伤长任务风险大；观察面已有三层（SSE 停滞审计、心跳文案、本批陈旧提示），先让"看得见"跑一阵，真有痛再立项 |
| 4 | 陈旧提示纯文案 | 改灯语义 / 卡片降级 / 转死信 | 灯是状态语义资产（CINDY 四档），文案层提示零风险先落；状态层变更进取舍3的"真有痛再立项" |
| 5 | 技能用量不进注入排序 | 按使用频次排 L1 索引 | 注入顺序是缓存前缀资产（AGENTS.md 硬约束），收益小风险大；用量旁证已进批 30 建议，够用 |
| 6 | 本批不动 chancellor 仓 | 顺手改 chancellor 轮询退出条件 | B2 顺带发现远端离线轮询无上限（15s 一轮到永远），但那是 chancellor 协议对面的事，跨仓改动单独立项；本批只治发起端台账 |

## 四、明确不做（本批不做，别顺手做）

1. **运行中任务收割器 / 状态自动降级**（取舍3）。
2. **技能 L1 索引按用量排序**（取舍5，缓存前缀资产）。
3. **chancellor 侧远端轮询退出条件**（取舍6，跨仓单独立项）。
4. **汇报正文加落点 / 80 字口径调整**（取舍1）。
5. **死信节扩容**（只收"父终态后迟到的子单"现状不动；卡死单进死信属状态层变更，随取舍3观望）。
6. **记忆巩固层任何改动**——升权/衰减/召回强化已完整（`memory/src/consolidate.ts`、`decay.ts`、`recall.ts`），本批零触碰。
7. **任何 shared / 手机端改动**——A 的 `DelegationReport` 是服务端内部结构，出不了 server 包。
