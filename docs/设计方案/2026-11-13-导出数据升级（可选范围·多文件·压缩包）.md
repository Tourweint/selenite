# 导出数据升级：可选范围 · 多文件 · 压缩包

> 一句话：把设置页「导出全部数据」从"一个巨大 JSON"改成"勾选要带哪几块 → 打成一个 zip，
> 里面按会话/记忆/内容/团队/配置分成多个 md + json + jsonl 文件"。

状态：已落地（代码 + 测试 + 文档；未 commit）
上位：用户口头需求（2026-11-13「继续打磨导出数据」）
下沉落点：`docs/基线文档/接口-端点2-杂项日记与项目.md`（§2.5 导出）、

## 结论

现状（2026-11-13 核实）：`GET /api/v1/agent/export` 只出**一份 JSON**，前端 `exportAllData()` 拿到
blob 后走 `<a download>`，落点由浏览器决定（桌面壳里就是系统下载目录）。三个问题：

1. **不可选**：想要"只要会话"也得连带整份记忆与配置。
2. **不可读**：一个几百 KB 的 JSON，人打不开；图片是 base64，撑大了整个文件。
3. **不完整还看不出来**：`listChats` 天然排除**已归档会话**与任务专线，导出文件里没有任何一处说明
   "少了什么"；单会话 500 条上限也没有截断标记。

本批做法：新增 `format=zip` 形态，**`format=json` 原样保留**（老客户端零改动、可回滚），
zip 内部按"一个会话一个文件夹 + 四类独立目录"组织；每个包根上放 `README.md`（人读）
与 `manifest.json`（机读，逐块记条数、上限、失败原因）。前端改成"勾选范围 → 导出"的弹层，
桌面壳内优先弹系统另存为对话框。

## 一、接口（契约）

```
GET /api/v1/agent/export?format=zip&parts=conversations,memory,library,team,config&images=1
```

| 参数 | 取值 | 缺省 | 说明 |
|---|---|---|---|
| `format` | `json` / `zip` | `json` | `json` = 2026-11-05 的老形态，逐字节不变；`zip` = 本批新形态 |
| `parts` | 逗号分隔，枚举同上 | 全选 | 未知值 / 空值 / 重复 **400 `bad_request`**；`format=json` 时忽略 |
| `images` | `0` / `1` | `1` | 只作用于会话里的图片；`0` = 不写图片文件，`messages.json` 里只留 `{mimeType, bytes, sha256}` |

响应头：`Content-Type: application/zip`、`Content-Disposition: attachment; filename="selenite-export-<本地 YYYY-MM-DD-HHmm>.zip"`、
`Cache-Control: no-store`；降级时加 `X-Export-Partial: 1`；成功时 `X-Export-Files` / `X-Export-Bytes` 只给计数。

回滚开关 `EXPORT_BUNDLE`（默认开；`false` → `format=zip` 404 `not_found`，`json` 不受影响）。

失败口径：**逐块隔离**——某一块读失败只在 `manifest.json` 里标 `failed` + 一句原因（不含正文），
其余块照常出包，HTTP 仍是 200 + `X-Export-Partial: 1`；只有**所有请求的块都失败**时整体
`503 export_failed`（与老端点同码）。总量超过 `EXPORT_MAX_BYTES`（默认 256MB 未压缩）→ `413 export_too_large`。

## 二、包内结构

```
selenite-export-2026-11-13-1430/
├── README.md                      人读：这是什么、怎么打开、哪块空/失败了、刻意没带什么
├── manifest.json                  机读：formatVersion / exportedAt / 逐块 status·counts·limits·notes / excluded
├── conversations/
│   ├── index.json                 会话清单（含 archived / pinned / project / 条数 / 截断标记 / 目录名）
│   └── <YYYY-MM-DD>-<标题slug>-<id8>/
│       ├── messages.json          结构化消息（含步骤、图片引用、时间 ISO）
│       ├── transcript.md          人读：分段正文 + 步骤名（不含工具输出全文）
│       └── images/0001-<hash8>.png
├── memory/
│   ├── index.json                 总数 + 按 scope / kind 的计数 + 是否触顶
│   └── records.jsonl              一行一条完整 MemoryRecord（含已取代的，保留演化链）
├── library/
│   ├── projects.json              工作区 + 项目 + 待确认提案
│   ├── topics.json                课题 + 提案（含 findings）
│   ├── diary.jsonl                一行一条日记（wire 原形）
│   └── routines.json              例行定义（触发/条件/完成条件）
├── team/
│   ├── partners.json              名册（头像改成 avatars/ 相对路径）
│   ├── groups.json                群定义 + 成员
│   ├── group-messages.jsonl       一行一条群消息
│   ├── souls/<partnerId>.md       SOUL.md 当前值
│   ├── contracts/<partnerId>.md   岗位契约当前值（有才有）
│   └── avatars/<partnerId>.png
└── config/
    ├── providers.json             供应商 + 模型目录（无 keyEnv / 无密钥）
    ├── usage.json                 按模型的 token 用量
    └── flags.json                 开关现值 + 是否被界面覆盖
```

### 为什么这么分

| 决定 | 理由 |
|---|---|
| 会话**一会话一文件夹** | 想单独把某段对话发给别人，直接拿那个文件夹；不用在大文件里翻 |
| md + json 各一份 | md 给人看（可粘给任何 AI 继续聊），json 给程序读；两者同一份数据，不互相引用成死链 |
| 集合类用 **jsonl** | 记忆 / 日记 / 群消息条数大、只追加；一行坏掉不毁整份，`grep` 友好 |
| 图片落成**真文件** | base64 会把 JSON 撑爆且人打不开；`messages.json` 只留 `{mimeType, path, bytes, sha256}` |
| 文件名带日期 + 标题 + id 前 8 位 | 人能认出是哪个会话；id 保唯一；标题只做 slug（去 `\/:*?"<>|`、压空格、截 40 字） |
| 时间：JSON 用 ISO 8601（UTC），正文用**本地时间** | 机器消费稳定；人读不该换算时区。README 里写明这条 |
| `manifest.json` 逐块记 status | 失败/为空/被截断都留痕，不冒充完整（「状态如实」口径） |

### 数据结构要点

- `conversations/index.json`：`{ exportedAt, total, entries: [{ id, title, chatKind, createdAt, lastAt,
  turns, pinned, archived, archivedAt, project:{id,name}|null, dir, messages, truncated, images }] }`，
  `dir` 是包内相对路径（`conversations/<日期>-<标题 slug>-<id8>`），拿它直接能找到那个文件夹。
- `messages.json`：`{ id, title, chatKind, createdAt, lastAt, messages: [...] }`，单条消息 =
  `{ role, at, text, id?(仅 user), images?: [{mimeType,path,bytes,sha256}], steps?, workMs? }`；
  `steps` 原样保留（与 §2.2 同结构，输出已按 2000 字符截断，`manifest` 里写明 `stepOutputChars`）。
- `memory/records.jsonl`：`MemoryRecord` 原字段（`kind/scope/content/importance/veracity/source/createdAt/
  validUntil/expiresAt/supersededBy/recallCount/lastRecalledAt/usageCount/lastUsedAt`）。
- `manifest.json`：`{ format:"lifediary-export", formatVersion:1, exportedAt,
  parts:[{id,label,status:"ok"|"empty"|"failed",files,bytes,counts,limits,notes}],
  totals:{files,bytes}, limits:{...}, excluded:[{what,why}], redactions:[...] }`。

## 三、前端

设置 → 会话 → 「导出数据」一行，按钮打开弹层：

- 五个复选框（会话 / 记忆 / 内容 / 团队 / 配置），默认全选；会话下挂一个"带上图片"二级开关。
- 弹层里逐项写清"这一块会出哪些文件"，不是抽象名词。
- 导出时保存位置：① 浏览器支持 `showSaveFilePicker` → 系统保存框；② MyGo 壳内调 `Shell.SaveExport`
  → 系统另存为（壳没重编时自动跳过）；③ 都不行 → 老路 `<a download>`（下载目录），并提示实际落点。
- 部分失败 → toast 写明"部分数据没导出，打开 manifest.json 看原因"。

## 四、明确不做

- **不碰 `format=json`**：老形态连字段顺序都不动；zip 是新增分支，回滚只需开关。
- **不导任务专线（`task-` 前缀）**：首句是机器指令不是用户的话，与侧栏口径一致；`manifest.excluded` 里写明。
- **不导密钥 / 配对码 / 设备令牌 / 服务端日志**：`providers.json` 用现成投影（无 `keyEnv`），
  这就是把它写进 `manifest.redactions` 的原因。
- **不导提醒（reminder）**：durable 里的排程任务，会随执行自然消失；当运行状态处理，不当档案。
- **不做导入 / 恢复**：这份包是"存档 + 可程序消费"，不是备份格式；恢复要另立项（字段可能要回填、图片要回灌）。
- **不写服务端磁盘**：仍是"一次性响应体"，用户选位置由壳/浏览器负责，服务端不落盘。
- **不做流式打包**：整包在内存里拼完再返回；超过 256MB 直接 413（当前数据量级远未到）。
