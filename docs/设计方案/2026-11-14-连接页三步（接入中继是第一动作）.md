# 2026-11-14 连接页三步：接入中继是第一个动作

> 状态：**已落地（2026-11-14）**。下沉落点：`接口文档.md` §2.13（`/relay/link`、`/relay/unlink` + status 四字段）、
> `系统架构.md`（连接页三步 + 中继 owner 鉴权修复）、`ts/apps/relay/README.md`（公网必配 owner 令牌）。

## 结论

链路是单向的：**中继是门牌，电脑先登记，手机才有码可扫**。
所以页面只能按「电脑 → 中继 → 手机」排，**第一步的动作必须长在页面里**。
把第一步放 `.env` 里，等于把它藏起来——第二步（出码）就只能灰着，用户看到一个灰按钮和一段教程，
教程说的还是"去改 .env 重启"，这不是入口，是说明书。

2026-11-14 用户原话：「我不应该在没连上的时候就输入地址吗」「这逻辑不符合正常人操作」。

## 现状五病（2026-11-14 核对代码）

| # | 病 | 证据 | 用户看到的 |
|---|---|---|---|
| 1 | 第一步没有入口 | `relay/status` 只读数；接入只认 `.env`（2026-11-13 变更记录"刻意不在网页里改"） | 「未连上」但页面上没有任何输入地址的地方 |
| 2 | 第二步是死路 | `settings-connection.js:53` `addButton.disabled = !connected` | 唯一的操作按钮是灰的，旁边三行教程 |
| 3 | 地址框长在第三步 | `settings-connection.js:106` 弹窗顶部"中继地址"，填的却是**手机**该访问的地址 | 「我点添加设备怎么让我输地址」 |

| 5 | 状态只读一次 | `loadRelayStatus` 只在进页时跑，无轮询 | 中继后来连上了，页面还是灰的 |

## 正常人的三步

| 步 | 谁做 | 手上的东西 | 做完看到什么 |
|---|---|---|---|
| 1 | 电脑接中继 | 中继地址（`http://vps:8084`）+ 主令牌（VPS 上 `RELAY_OWNER_TOKEN`） | 链路图中间格变绿，显示设备名 |
| 2 | 中继 | 不需要人操作 | — |
| 3 | 手机加入 | 电脑出的一次性加入码（扫码） | 「经中继的手机」里出现设备，带在线点 |

## 方案

**端点（新增两个，纯增量）**

- `POST /api/v1/relay/link` `{address, ownerToken, deviceName?}`：
  探活 → 用主令牌签一枚加入码 → `/api/relay/join` 换本机自己的设备令牌 →
  落 `.data/relay-link.json`（0600）→ 起客户端 → 最多等 7s 回 `{ok, connected, deviceId, relayUrl, deviceName}`。
  失败分三档：`relay_unreachable` / `relay_forbidden` / `join_failed`，别让"地址错"和"令牌错"共用一句话。
- `POST /api/v1/relay/unlink`：停客户端、删文件。配置文件来自 `.env` 时拒绝（`from_env`），
  口径是"`.env` 优先，页面别偷偷覆盖部署配置"。

**启动顺序**：`.env` 配齐 → 用 `.env`；否则读 `.data/relay-link.json`；两者都没有 = 未接入（正常态，不是错误）。

**status 加四字段**：`configured`（有没有客户端）、`relayUrl`（对外 http 地址）、`deviceName`、`source`（`env`/`file`）。
`enabled` 改为 `configured || RELAY_ENABLED`，老调用方语义不变。

**页面五段（顺序 = 操作顺序）**

1. **连接状态**：三格链路 + 一行断点 + 一个「下一步」按钮（接入中继 / 添加手机）
2. **中继（VPS）**：未接入 = 地址 + 主令牌 + 设备名三行 + 「接入并连接」；已接入 = 地址一行 + 「换地址」「断开」
3. **同一个 WiFi**：原二维码卡，不动
4. **不在同一个 WiFi**：添加手机按钮（**永不置灰**：未接入时文案是「先接入中继」，点了直接开接入弹窗）+
   出码弹窗 + 下方「经中继的手机」名册（在线点 + 最近使用）
5. **已连接的设备**：原局域网配对列表，不动

**地址框搬家**：从添加弹窗顶部，挪进「手机连不上？改对外地址」折叠项——它管的是手机往哪连，
不是电脑往哪连，放在出码弹窗顶上就是语义错位。

**轮询**：停在连接页时 10s 刷一次 status，灰/绿不再靠"重进页面"。

## 取舍

| 选项 | 结论 | 理由 |
|---|---|---|
| 页面接入 vs 只写 `.env` | **页面接入** | 第一步必须有入口。密钥纪律靠"0600 落盘 + 日志不记 + 页面不回显"守，不是靠不让填 |
| 填主令牌 vs 填加入码 | **主令牌** | 加入码要先有主令牌才能签发；让用户拿主令牌一步到位，少一次 SSH |
| 换来的令牌自己存 | 存 | 主令牌只用于签发加入码，日常连的是设备令牌；两个都落同一个 0600 文件 |
| VPS 一键部署 | 不做 | 沿用 2026-11-13 拍板：SSH 凭据不进桌面程序 |
| 自动发现中继 | 不做 | 跨公网没有可用发现机制；"扫描"在公网侧不存在 |
| 合并两套名册身份 | 不做 | `pair` 指纹与 relay `deviceId` 是两份事实；本次只分组展示，不合并、不互认 |

## 顺手修（安全，同批）

中继 `isOwner`（`ts/apps/relay/src/server.ts:62`）在未配 `RELAY_OWNER_TOKEN` 时用
`header("x-forwarded-for") ?? "127.0.0.1"` 判 loopback——**没带这个头的公网请求会被当成 127.0.0.1**。
实测：本机从公网调 `POST /api/relay/join-code` 直接签出码（2026-11-14）。
后果不是"能签码"这么轻：手机/任何客户端拿码 join 后，harness 会把设备令牌映射成自己的 `AGENT_TOKEN`
（批H H1 口径），**等于公网任何人都能拿到这台电脑的全部接口**。
修法：改用真实对端地址（`getConnInfo`），拿不到就按"非 loopback"（fail-closed）；
非 Node 上下文（`app.request` 自测）退回旧口径。

## 这条会怎么错

- **主令牌落本机**：本机被拿走 = 中继管理员被拿走。缓解是 0600 + 不回显；彻底解法是
  "只存设备令牌，加入码改由设备身份签发"（要动中继鉴权口径，另立方案）。
- **两套名册**：分组展示会让人以为"本地配对"和"经中继"是两种设备；它们其实是同一台手机的两条身份。
- **7 秒等待**：中继慢或网络差时接口会回 `connected=false` 但客户端随后连上，页面靠轮询补。
