# 方案：派活完成即唤醒（汇报闭环的最后一环）

> 来源：2026-11-10 用户定调——**谁派的活，终态那一刻把谁叫起来接结果**；最终兜底是"不管跟总管还是执事说，结果必须让用户知道"。
> 状态：**已落地（2026-11-10 批 29，含 canonical 返工一轮）**。执行：CodeBuddy，验收：总管。
> 下沉落点：契约与开关 → `接口文档.md` §4 delegate 段 + §6 env 表；模块与机制 → `系统架构.md` §3 `delegation-wake.ts` 行 + 已知边界"批 29"条；落地记 → `变更记录/2026-11-10-批29（派活完成即唤醒）.md`。**冲突以长期文档为准**，本文留"当时怎么想的"。
> 关联：`系统架构.md` D9（派单异步受理，2026-11-03）——本方案是它的下半环。

## 〇、一句话与原则

派活异步受理（D9）解决"不能钉住对话"；汇报写回解决"结果不丢"；但**写回 ≠ 知道**——汇报躺进会话，
派活方要等下一次开口或下一次巡逻才看见，闭环是半扣的。本方案补最后一环：

> 任务到终态的那一刻（汇报写回之后），把派活的那条会话**叫起来跑一轮**，把结果接住：
> 该转述的转述、该问的问、需要继续派的按自主轮规矩派。

口径规则只有一条，所有细节从它推出来：**汇报写了就唤醒，没写就不唤醒。**

## 二、设计

### 2.1 挂点（一处，覆盖两条结算路径）

`agent/lifecycle.ts` 的 `reportDelegation` 回调（:536）写完汇报后追加一次唤醒触发：

```ts
reportDelegation: (conversationId, report) => {
    void reportDelegationResult(conversationId, report);
    void wakeOnDelegationReport(conversationId, report);   // 新增
},
```

为什么挂这里不挂 `delegation.ts` 结算内：结算处已经有 `runtime.report` 可选缝，再加一个 `runtime.wake`
是第二个缝，两条路径都要记得调；挂在装配回调里，**汇报发了唤醒就发**，"汇报写了就唤醒"由结构保证，
不是靠两处调用纪律。

`DELEGATION_AUTO_REPORT=false` 时 report 根本不发 → 唤醒自然不发（规则同一条：没汇报就没唤醒）。

### 2.2 新文件 `src/delegation-wake.ts`（与 routines.ts 平级）

```
wakeOnDelegationReport(conversationId, report)
  └─ 守卫链（顺序即语义，任何一关不过 → 静默返回，行为 = 今天）
     1. DELEGATION_WAKE_ENABLED 关 → 返回（回滚形态，逐字节回到今天）
     2. COMPANIONS_ENABLED 关 → 返回（唤醒轮跑不了：runPartnerTurn 需要 partner 体系）
     3. partnerIdOfSession(conversationId) 为 null → 返回（群会话 / task- 专线 / 未知会话不唤醒，见取舍4）
     4. partner 不存在或 status ≠ active → 返回
  └─ 合并：report 追加进 pending Map<conversationId, Report[]>，该会话没有定时器就排一个
  └─ flush（防抖 2 秒后）：
     a. 忙退避：conversationIsBusy → 是则 2 秒后重查，上限 150 次（≈5 分钟）；
        超限放弃 + 一条 warn 日志（登记已知边界，汇报本身已在会话里不丢）
     b. 取走 pending（取走即清空），buildWakePrompt(reports)
     c. runPartnerTurn(partnerId, prompt, { authority: "autonomous", quiet: false, sessionMode: "persistent" })
     d. 跑完若期间又有新汇报落 pending → 循环 flush（while pending），每轮都过守卫链
```

- **为什么忙时空闲才起轮、不直接排队**：autonomous 标记是**会话级**的（`markRoutineTurn` /
  `markAutonomyTurn` 在 `runPartnerTurn` 开头、`chatStream` 排队等待之前就生效）。若直接提交，
  唤醒轮在队列里等的时候，用户正在跑的那一轮也会被这两个标记罩住——无人值守策略开着时
  用户自己的写盘 / 派活工具会被"跳过"。先等空闲再标记，风险为零。
- **日志纪律**：只记条数 / 枚举 / 耗时 / 会话 id（`[wake] 会话 12 唤醒轮 ok tickets=2 耗时4.1s`），
  不记汇报正文，不含对话内容。
- **防抖 2 秒**：多个并行单同一时刻结算时合成一轮。纯函数拆出来（collectPending）便于单测。

### 2.3 唤醒提示词 `buildWakePrompt`（固定字节，可单测）

```
[Delegation wake context]
turnAuthority: autonomous

以下后台任务刚到终态，执行端汇报已写进本会话。逐条接住：
- 完成了：一两句向主人转述结果与落点，不复读执行端原文；
- 失败了：说清原因与下一步建议；
- 需要主人拿主意的：把问题明确提出来。
不要重新派同样的活。没有要补充的就一句话收尾。

本批终态：
- 单 3f2a91…（done）：登录页改完，探测 12 项全绿
- 单 8c04d2…（failed）：依赖安装超时，建议换 registry 重试
```

- 单号取 `ticketId` 前 6 位 + `phase` + `text`（`text` 上限 80 字已由上游保证）。
- `turnAuthority: autonomous` 文本头与例行轮同款（透明性：模型知道这轮是谁发起的；判定事实源在进程内标记）。
- "不要重新派同样的活"是纪律层；结构层由自主轮 delegate 强制审批兜底（双保险，不依赖提示词自觉）。

### 2.4 两处小改（既有文件，各一行级）

| 文件 | 改动 | 为什么 |
|---|---|---|
| `partner-runtime.ts` `PartnerTurnOptions` | 加 `quiet?: boolean`；quietEligible 改为 `(opts.quiet ?? (authority === "autonomous")) && routineQuietEnabled()` | 唤醒轮必有内容（接住汇报就是内容），不适用"没新进展就闭嘴"的安静契约；缺省不传 = 现行为逐字节不变 |
| `agent/session.ts` | `conversationIsBusy` 加 `export` | 唤醒的忙退避要用；函数本体零改动 |

### 2.5 开关与界面

- env：`DELEGATION_WAKE_ENABLED`，默认 **true**；`false` = 回滚形态（只写汇报不唤醒，与改动前逐字节一致）。
- `flags.ts` `FLAG_DEFS` 加一行 `{ key: "DELEGATION_WAKE_ENABLED", values: ["true","false"], defaultValue: "true", hot: true }`
  （消费处懒读 env → 设置页切换即生效，无需重启）。
- 唤醒轮本身**不新增契约字段、不动 shared、不动手机端**：它就是那条会话里普通的一轮助手发言，
  SSE / 任务中心 / 记忆抽取全部走现有管线。

## 三、取舍与备选

| # | 取舍 | 备选（弃） | 为什么 |
|---|---|---|---|
| 1 | 汇报写了就唤醒，`needs_you` 也唤醒 | `needs_you` 跳过唤醒省一轮模型费 | 规则复杂化换省钱不值；执事接住后能补充上下文、把问题问得更完整。canceled 不写汇报 → 自然不唤醒，无需特判 |
| 2 | 唤醒合并走**进程内** pending Map | 照 TopicTask 范式落 durable 闹钟（重启不丢唤醒） | v1 控改动面：汇报本身 durable 不丢，丢的只是"主动那一轮"（那个边缘的后果 = 今天的默认行为）。真出现重启丢唤醒影响体验再升级，登记已知边界 |
| 3 | 忙时退避等空闲 | 直接排队（durable followUp 语义） | 见 2.2：会话级标记会污染排队期间用户正在跑的轮 |
| 4 | 只有执事体系会话（总管主对话 / 执事主会话）唤醒 | 全会话类型唤醒 | 群会话有值日制与确定性调度，"无人指令的自主轮"在群里语义未定义；task- 专线是无人值守任务会话。先窄后宽，放开要另过方案 |
| 5 | 唤醒轮关安静契约 | 复用 routineQuiet | 唤醒必有产出；安静契约的 run 记录体系（RUN_SOURCE / 例行 run 表）也不该混进派活账 |

## 四、明确不做（本批不做，别顺手做）

1. **durable 化唤醒任务**（重启续唤醒）——取舍2，出现真实影响再立项。
2. **群会话 / task- 专线会话的唤醒**——取舍4。
3. **运行中 attention 唤醒**（`need_input` / `need_decision` / `need_action` 中途到达）——只认终态；中途的问题继续走现有 attention 徽章。
4. **bash 转后台（`bash-background.ts`）终态回灌的唤醒**——另一条链路，同病另治，单独立项。
5. **唤醒轮独立 UI 标识 / 状态灯特判**——普通助手轮，透明性靠文本头。
6. **任何 shared / 契约 / 手机端改动、任何工具增删与注册顺序调整**——缓存前缀资产不动。

## 五、已知边界（落地后随变更记录登记进 `系统架构.md`）

1. settle 后、唤醒跑之前进程重启 → 汇报在会话里不丢，但"主动那一轮"丢了（下次开口才被看见）。
2. 会话连续忙超 5 分钟（150 次退避）→ 本次唤醒放弃，warn 日志一条，汇报仍在会话里。
3. 唤醒轮里重派会再唤醒 → 合法链，靠自主轮 delegate 强制审批收口；审批调到"全不问"档位时由用户自担。
4. 唤醒轮费用 = 每次终态一轮模型调用（合并后 ≤ 每会话每 2 秒窗口一轮）。
