## 〇、一句话（2026-11-05 用户定调）

自动分发从"挑最闲"改成"**主机优先、溢出才外流**"：先设一台主机吃大部分活；主机满载或
离线才按忙碌度挑其余设备；设备描述（存储机/计算机/手机）**只给人看**，自动逻辑不读它。
手机本来就先排除在候选外（被操控端）。

## 一、设计

### 1.1 主机（home device）

- **谁设**：用户在中继管理面手动指定（`POST /api/relay/home-device`，owner 或设备令牌），
  body `{deviceId}`（`null` = 清除）；名册投影与 harness 侧同步可见。
- **存哪**：中继名册文件（路由元数据，与伙伴路由表同层——中继仲裁的又一例）；
  全矩阵**唯一主机位**（同刻只有一台）。
- **变化可见**：中继 meta `devices` 快照里带 `isHome` 位；`relay/overview` 透传。

### 1.2 决策器 v2（`selectAutoDevice` 升级，仍纯函数）

```
候选过滤（不变）→ 若有主机：
  主机未满载 → 永远选主机（busy 不参与比较——"大部分工作都是主机用"）
  主机满载或离线 → 其余候选按 busy 升序（tie-break 不变）挑最闲
无主机 → 沿用 v2 前行为：全员 busy 升序挑最闲
```

- `no_candidate`（零候选）与 `all_busy`（全满载）fallback 本机，语义不变；
- **确定性保持**：主机唯一 + tie-break 链不变，同名册同输入同输出。

### 1.3 设备描述（只给人看）

- 中结名册条目加可选 `description`（≤200 字，配对时带或 `POST /api/relay/devices/:id/description` 改）；
- 用途：`relay/overview`、设置页、delegate 工具返回的设备清单里显示——**人点名时参考**
  （"派给那台存储机"）；自动决策器**不读它**（口径：描述不参与挑选）。

## 三、刻意不做

- 描述不参与自动匹配（用户定调"只给人看"）；
- 多主机/主机权重；伙伴的 homeDeviceId 与此主机位是**两个概念**（伙伴归属 vs 任务主机位），
  不合并；
- 主机位不做自动抢占（必须用户手动设——"先去设置这个主机"是用户明确要求）。

## 四、验证

- `selectAutoDevice` 单测扩：有主机时无视 busy 差异永选主机 / 主机满载外流 / 主机离线外流 /
  无主机回落旧规则 / 描述字段不影响决策；
- matrix 探针：设主机 → auto 永选主机；主机 busy 打满 → 外流乙机；杀主机进程 → 外流乙机；
- `relay/overview` E2E：`isHome` / `description` 透传断言。
