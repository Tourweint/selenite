## 一、要做的七件

### 1. 验证铁律（七 #2 之一，superpowers verification-before-completion）

新增常量 `VERIFICATION_IRON_LAW`（建议放 `agent/turn-gate.ts`，与回合收尾纪律同族），
注入到**总管 persona 段之后**与**执事轮输入**两处。

内容要点（中文、≤500 字，照原文精神改写，不要机翻腔）：

- **铁律**：没有在**这一轮里真的跑过**验证，就不许说"完成了 / 修好了 / 通过了"。
- 五步门：认清"哪条命令能证明这句话" → 真跑 → 读完整输出（看退出码、数失败数）→ 对账 →
  **才**敢下结论。
- **主张 ↔ 证据对照表**（做成 4~6 行的表或清单）：
  - 说"测试通过" → 要有 0 失败的输出；"上次跑过""应该能过"不算。
  - 说"改好了" → 要复现原症状已消失；只改了代码不算。
  - 说"做完了" → 要有落盘的改动；自己说做完了不算。
  - 说"要求都满足了" → 要逐条对着清单打勾；测试全绿不算。
- **红旗**（出现即在撒谎，回头去跑）：说"应该 / 大概 / 看起来没问题"；没跑就先说"很好 / 完成 / 搞定"；
  想"就这一次不用验"；累了想收工。

### 2. 裁决记账与四停条件（七 #2 之二，superpowers subagent-driven-development）

新增常量 `RULING_DISCIPLINE`（同样放 `agent/turn-gate.ts`），注入执事轮输入 + `delegate` 工具描述尾部一小段。

内容要点：

- **继续干，别反复请示**："要不要我继续"这句话是在浪费人的一天；计划里的事一口气做完。
- **四停条件（只有这四种停下问人）**：
  ① 不可逆或破坏性的操作；② 安全敏感的动作；③ 工作目录之外的副作用（合并、推共享分支、发布）；
  ④ 计划烂到往前每一步都是猜。
- **四停之外一律自己裁决**，并记一行账：`裁决：<决定了什么> — <为什么> — <错了的代价>`。
  这句写进给主人的汇报或任务单留言里，让人事后看得见、能推翻。
- 一句定调："一个错的裁决，人看得见、也能让我改；一个卡着等回答的会话，花掉的是人一整天。"

### 3. 委派回报四行格式（七 #42，nightly-labs）

改 `delegation.ts` 里给执事/总管看的**汇报**口径（`formatReport` 相关文案旁加常量 `REPORT_FOUR_LINES`），
并在 `delegate` 工具描述里补一句"派活前告诉工人按四行回报"。

四行格式：

```
状态：完成 / 部分完成 / 卡住
结果：一句话说清做成了什么（不是过程）
证据：拿什么证明的（改了哪个文件 / 跑了什么命令 / 看到什么输出）
解锁：卡住时，下一步需要谁做什么；没卡住就写「无」
```

外加两条：回报**开头是队友的名字**（"给总管："）；**不把任务发回给来源**（谁派的活别原样退回给他）。

### 4. 同类失败三次→建议人接管（七 #6 = 三#5）

**这一条要写代码**（勘察结论：现无可用机制）。

4.1 新增 `ts/apps/server/src/failure-streak.ts`：纯状态（可序列化），按
`(来源, 类别)` 记连续失败次数；类别取现有枚举的粗分（`tool-error` / `timeout` / `rejected` /
`needs_you` / `unresolved`）。成功一次即清零。

4.2 触发：同一 `(来源, 类别)` 连续达 **3 次** → 产出一次"建议人接管"信号。

4.3 落点：在 `agent/turn-gate.ts` 加常量 `TAKEOVER_HINT`，在 `attention` 卡片文案旁追加一句
"这类问题已经连着 3 次没解决，建议你来接手，或者换个说法重新派一次。"

4.4 落点文件：`delegation.ts` 的 attention 事件发出处（`540-548` 附近）与汇报行（`349-350` 附近）各接一次。

4.5 开关 `AGENT_TAKEOVER_HINT`（默认 true，false = 不追加那句话）。
4.6 单测：3 次触发 / 中间成功一次则不触发 / 不同类别互不干扰 / 开关旁路。

### 5. 执事契约的调查铁律（三#2）

`partners.ts` 的 `partnerContractTemplate()` 四节标题**不动**（标题逐字、有测试守着），
但在**「决策分级」**节里补一段默认正文（新执事播种时就有，存量执事不动）：

- 没有调查不许改：先复现、再看现象、再动手；猜着改三次不如查一次。
- 同一条思路连修 3 次还不行 → **停下**，把已查明的事写成一段话交上去，别继续硬修。
- 交付物要**自带验收证据**（四#3 剩余的那半条）：说"做完了"要能指出凭什么。

> ⚠️ 注意：`partnerContractTemplate()` 现在生成的是**只有标题、没有正文**的空模板，
> 改它会影响新执事。**存量执事的 CONTRACT.md 一律不动**（不越权改人家的文件）。

### 6. 干活期间沉默 + 交付物自含证据（四#3 剩余）

新增常量 `WORK_SILENCE_DISCIPLINE`（放 `delegation.ts`，与 attention 口径同族），注入执事轮输入：

- 接单确认**只发一次**，点名要干什么；干活期间**不说话**（不播报"我正在…"）。
- 再开口只有三种情况：有结果了 / 需要人做决定 / 干不完要交代。
- 交付物必须**自己带着验收证据**：改了哪个文件、跑了什么、看到什么。没有证据的"做完了"不算完成。

### 7. 注意力纪律 + 拒绝概念登记法（四#4 + 四#7）

7.1 常量 `ATTENTION_ONE_QUESTION`（放 `delegation.ts`，挨着 `ATTENTION_REPLY_GUIDANCE`）：

- 一次只问**一个**具体问题，别把三个问题塞进一段话。
- 问题必须**点名对象与期望**（"第 2 条的标题你想要哪种：A / B"），不要问"这样可以吗"。
- 问题若是**因为某条消息/某个文件**引起的，要**点名那条消息**，别让人自己去回忆。

7.2 「拒绝概念」登记法（**文档**，不是代码）：在 `docs/基线文档/系统架构.md` §7 补一小节
「我们刻意不做的事（含"为什么不做"）」，格式照 dsh-superagent 的拒绝概念表——
两列：`不做什么` / `为什么不做（以及什么条件下会翻案）`。把现有散落在各处的"刻意没有"
归拢成一张表（至少收 10 条，从 §7 现有内容里摘，**不要凭空编**）。
