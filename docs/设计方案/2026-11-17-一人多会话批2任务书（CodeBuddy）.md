## 一、目标（用户原话口径）

- 插件 `PARTNER_SIDE_SESSIONS` 默认开；开了以后，**前端有人设的地方就有"会话"按钮**。
- 点按钮 → 选「主对话 / 某条副会话 / 新建会话」；选旧的直接打开，选新的建完打开。
- 一个主会话 + 多个副会话；人设、记忆、项目照旧，不按会话重配。
- 总管也要能选（总管没有链接表，走 `chatKind=chief` 的多条会话）。

## 三、按钮入口（三处）

1. **执事花名册行**（`web/partner-roster.js` 的 `renderRoster`）：
   - 在 `.roster-busy` 之后追加一个小图标按钮 `.roster-sessions`，`aria-label="选择会话"`，
     `title` 同文案；用现有 icon 体系（照 `.roster-*` 其它图标，不要引新库）。
   - 点击：`event.stopPropagation()` + `event.preventDefault()`，打开选择器（§四），**不要**触发 `openPartnerChat`。
   - 插件关 → 按钮不渲染。
2. **总管固定条目**（`web/partners-status.js` 渲染总管/花名册处）：
   - 同样追加 `.chief-sessions` 小按钮；点击 `stopPropagation` 打开选择器（`partnerId = "chief"`）。
   - 插件关 → 不渲染。
3. **对话顶栏**（`web/chat-open.js` 填 `el.title` 的分支）：
   - 当前会话是 canonical / side 时，`el.title` 可点击打开同一选择器；
     加 `cursor:pointer` 与 `title="选择会话"`，不要影响 worker/chief 的现有行为。
   - canonical 显示人设名（现状不变）；**side 显示 `人设名 · 会话标题`**
     （标题用 `partnerSessionLabel`，空会话 = 「新会话」）。

## 四、选择器（新建 `web/partner-sessions-ui.js`）

用现成的 `openModal(title, build, { className })`（`ui-atoms.js`，不要新造浮层），
标题 = `${人设名}的会话`。

数据：`GET /api/v1/partners/:id/sessions`（id 为执事 id 或 `"chief"`）。
- 400 `side_sessions_disabled` → toast「副会话插件已关闭（设置 → 插件）」并关闭。
- 404 / 409 / 其它错误 → toast 一句人话，不吞。

内容（从上到下）：
1. **主对话行**：
   - 执事：取 `role === "canonical"` 的条目；没有 canonical 条目（还没开过）→
     渲染一行「主对话（还没开始）」，点击走 `POST /partners/:id/open`，用返回的 `conversationId` 打开。
   - 总管：`kind === "chief"` 的第一条（服务端已按 `lastAt` 倒序）= 主对话；
     一条都没有 → 点击走「新建会话」（`POST /partners/chief/sessions`）。
2. **副会话行**：`role === "side"`（总管为 kind=chief 的其余条目），按服务端顺序；
   每行：标题 + 次要信息（turns>0 时「N 轮 · 相对时间」，否则「新会话」）。
   当前打开的会话加 `aria-current="true"` 并禁用点击（或点击只关闭弹层）。
3. **底部主按钮「新建会话」**：
   - `POST /api/v1/partners/:id/sessions`（不带 title；首条消息会自动写标题）；
   - 成功 → `closeModal()`，`go("chat")` + `openChat(conversationId)`；
   - 失败 → 留在弹层，toast 错误。
4. 点任一条旧会话 → `closeModal()` + `go("chat")` + `openChat(conversationId)`；
   顺手 `void loadChats()`（如果模块能拿到，避免新增会话没进列表；拿不到就跳过）。

**不要**在选择器里发消息、不要发问候、不要建重复会话（服务端建就是建一条新的）。

## 五、身份解析修正（本批最容易漏的地方）

现在多处用 `partner-` 前缀直接 `slice`，副会话会被当成一个叫 `x-side-1a2b3c4d` 的执事。
全部改成 §二 的解析器：

1. `web/route.js` 的 `currentPartnerLineId()`：canonical / side 都返回真正 partnerId；
   group 仍返回 `""`（群成员会话不算执事专线，保持现状）。
2. `web/partners-status.js`：
   - `chatIdentityName()` / `chatIdentityFace()`：side 要解析出 partnerId，显示真名与头像；
   - 忙因 / 待办胶囊的身份判定（现在只认 canonical 与 `-group-` 两种 id 形态）：用解析器，
     side 也算到这个执事头上。
3. `web/chat-open.js`：顶栏（见 §三.3），side 用「人设名 · 会话标题」。
4. `web/settings-drawer.js` 的 `csResolveTarget()`：side 解析到该执事档案；
   group 保持现状。
5. `web/chat-open.js` 里其它 `startsWith("partner-")` 后直接 slice 的地方，一并换解析器。

**不要改** `chats-list.js` 的 `partner-` 过滤：副会话不进「最近会话」，从人设入口进（本批口径）。

## 六、顺手修一个真 bug

`web/partners-status.js` 的 `openChiefChat()`：注释写「打开最近一条总管会话」，
但 `state.chats` 已是服务端 `lastAt` 倒序，代码又 `.reverse()` 后取 `[0]`，实际打开**最旧**一条。
改成按「置顶优先，其次 `lastAt` 最新」取第一条；没有才 `startNewChat("chief")`。
（`chats-list.js` 的最近会话排序**不要动**，与本批无关；只在交付说明里提一句它显示的是最早 5 条。）
