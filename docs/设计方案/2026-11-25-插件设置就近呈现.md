## 0. 先说三件与任务书不一样的事

1. **清单里是 89 个 flag，不是 87。** `S/plugins.json` 共 89 条：7 个分组定义覆盖 81 条，
   另有 `GOAL_MODE` / `GOAL_MAX_ROUNDS` 两条（`group: autonomy`，但 `groups` 里没有对应分组定义，
   界面落「其他」兜底组，`W/settings-switches.js:708-709`），再加 6 条 `surface: "settings"`。
   87 = 不含 `GOAL_*` 两条。本表 **89 条全列**，另加常开卡 1 张。
2. **`AGENT_TOOL_POLICY`（工具权限限制）这张卡的档位不驱动真实闸门。** 证据：
   - 真实闸门是 `S/agent/policy.ts:101` 的模块级 `export let policy = loadPolicy()`，在 **import 期**求值；
   - `.env` 在 `S/index.ts:322` 才加载、插件存储在 `S/index.ts:331`（`loadFlagOverrides`）才写进 `process.env`，
     两者都在 import 之后；`index.ts:36-71` 静态 import `agent.ts`，`agent.ts:11` 静态 import `policy.ts`；
   - 全仓没有第二处给 `policy` 赋值、也没有从 env 回灌的函数（grep `^\s*policy = |reloadPolicy|syncPolicyFromEnv` 只命中 `:101`）；
   - 运行期唯一能改它的是 `POST /api/v1/agent/policy`（`S/index.ts:1237-1242` → `setPolicy`）。
   结论（**按代码走查，未起服务验证**）：卡上拨「只读 / 在工作区内修改 / 完全访问」后，`.data/agent-flags.json`
   与 `process.env` 会变，但闸门不变；真正生效的是 `.data/policy.json`（会话页「权限」卡）。
   这是"代码与文档矛盾"，按 AGENTS.md 应先还原当初为什么再决定改哪边 → **本轮不改**，进待立项（§5.1），
   本卡的面板只**回显**实际生效值并指路，不给第二个可写控件。
3. **`EXECUTOR_PROBE` 不在任务书的 87 项口径里但在清单里**（普通助手组第 1 条），已一并审计。

## 3. 设计

### 3.1 入口与展开

- 卡尾 `.flag-item-foot` 左侧加一个「设置」按钮（默认收起）。点开在**卡内**展开小面板，不新开模态。
- 按钮是 `.flag-item-foot` 里的独立 `<button>`（foot 本来就在卡体按钮 `.flag-item-main` 之外，`W/style-14-settings-pages.css:515` 的注释口径），
  所以不存在按钮套按钮；点击仍 `stopPropagation`，保证不触发「点卡看详情」。

  「设置」二字（卡内最小宽 215px，估算 183px），所以不做图标版；**真机未验**，挤了再改。

### 3.2 模块

- 新增 `W/plugin-settings.js`：一张声明式表 `PLUGIN_SETTINGS[key] = { hint, link?, render? }`。
  - `link`：`{ href, label }`，渲染成普通 `<a href="#/settings/…">`（与 `surfaceEmptyMarkup` 同一做法，`W/settings-router.js:59`），不 import `route.js`，避免多一层循环依赖。
  - `render(panel)`：可选，内联控件；只调既有函数/端点/存储键。

### 3.4 回滚

任务书写的 `PLUGIN_INLINE_SETTINGS=false` 是 env。本能力**纯前端**，env 到不了浏览器，
要让它生效得往 `/agent/policy` 或 `/agent/flags` 加一个投影字段 = 改契约。
本轮判断**不加投影**，回滚走两层本地开关：

1. `W/plugin-settings.js` 顶部 `const INLINE_SETTINGS = true` 改 `false` → 所有「设置」入口不渲染；
2. 控制台 `localStorage.setItem("lifediary.pluginInlineSettings", "0")` 后刷新 → 同效，不用改代码。

env 形态列进待立项（§5.1）。

### 3.5 明确不做

- 不新建端点、不改 `plugins.json`、不改任何开关语义与分组。
- 不把复杂流程（上传壁纸、名单编辑器、Markdown 编辑器、槽位表单）搬进卡内。
- 不动 `surfaces.js` 的显隐规则；不动 `plus-menu.js`、`partner-profile.js`、`desktop/*`、`theme.js`、`style-01-tokens.css`、`index.html`。
- C 类不拉数据做"当前值摘要"——只给一句说明 + 链接（摘要要多打一串请求，收益小，留待以后）。
- 链接指向的页面若被对应开关关掉，会落到该页自己的空态说明（`surfaceEmptyMarkup`，`W/settings-router.js:59`），不在卡里另行拦截。
