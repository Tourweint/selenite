状态：**已落地**（2026-11-13；用户选定原型 A 版，主会话直接实施 + 自验收）。
下沉落点：契约 → `接口文档.md` §2.15 / §6；机制 → `系统架构.md` §7 记忆节；
实施记录 → `docs/变更记录/2026-11-13-记忆页A版与整理任务化.md`。冲突以长期文档为准。
落地偏差：①外部库页脚只做只读 `--catalog-only` 状态与「查看」弹层，未做查询页/通用 provider
（用户拍板后续独立）；②导入在 A 版只占位（端点与旧页文件导入保留）；③整理 POST 保留同步

## 背景（2026-11-13 核对）

- 设置页「记忆」现在是一张设置卡 + 五个分组卡片；分组全展开、每行两个文字按钮，
  经历（episode）只增不减，页面很快会被日常经过淹没。
- 「整理记忆」是同步请求：按钮只在当前 DOM 里变「整理中…」。切页回来页面重渲染，
  在飞请求的结果写进已脱离文档的卡片；用户回来看到的既不是进度也不是结果，
  再点一次就是第二次模型调用。待决建议其实已落 `.data/memory-proposals.json`，
  但**只有写、没有读口**；「忽略」也只删客户端卡片，刷新就回来。
- `experience` / `work` 没有中文标签，`renderMemoryList` 把认不出的 kind 一律
  归进「事实」组——经验、履历会被显示成事实。
- `memoryOverview.total` / `byKind` 是**当前返回窗口**（默认 300 条）的计数，
  不是库里真实条数；库大了会低报。
- 规则抽取器把用户每一句 ≥6 字的文本都写成 episode，审批续跑注入的
  「用户已批准 `write`：…」「不要换成别的工具…」也进了记忆（生产库可查）。
- 外接 persona-metric 只有模型工具 `persona_recall`（且本机 `.env` 未配
  `PERSONA_MEMORY_ASK`，实际未上架），设置页完全看不见；导出侧也默认关。
- 巩固审计 diff（`GET /memory/consolidate/diff`）已存在但从没有界面消费。

## 用户拍板（2026-11-13）

1. **页面按原型 A「档案卡」做**：大数字概览在最好；经历默认收起。
2. **筛选只留一套**：顶部分类计数片（同时可筛选）+ 搜索框；删掉右侧「全部类型」下拉。
3. **导入先占位**：现在没有统一的记忆格式，导入以后再做；按钮保留，点了说明现状。
4. **外接记忆库后续独立**：这一轮只在页脚留一条极简状态（库边界），不做查询页；
   绿点不要，解释文字尽量少。接口方向仍按「可接不同记忆库」设计，先留最小只读状态。
5. **写入噪声要治**：审批续跑等合成指令不再写成经历；`MEMORY_EXTRACT=rule` 保留旧行为。

## 前端：A 版结构

```text
记忆                                        [导入] [整理记忆 ?]
┌ 概览 ─────────────────────────────────────────────────────┐
│ 86 条记忆        [全部 86] [偏好 8] [打算 3] [事实 14] …     │
│                                   上次整理 3 天前 · 2 条待看 │
│                                   系统自检：2 可合并 · 3 久未用│
└────────────────────────────────────────────────────────────┘
（运行中：进度条「正在整理 86 条 · 已 12s」）
（有建议：整理建议卡，逐条应用/忽略；应用后才 supersede）
[搜索记忆内容…]                         [范围/执事下拉]
▸ 偏好 8   每轮都会想起
▸ 打算 3   未兑现的，优先想起
▸ 事实 14                        （默认收起）
▸ 经验 5                         （默认收起）
▸ 人事物 12                      （默认收起）
▸ 经历 44  日常经过 · 默认收起      （默认收起）
────────────────────────────────────────────
一生记忆库 · 2020-09 至今 · 100 事件 / 294 人物      [查看]
```

规则：

- **偏好 / 打算默认展开**；事实 / 经验 / 人事物 / 经历默认收起。分组标题显示真实计数、
  一句短提示（悬停出完整解释）。分组内先 20 条，「加载更多」按 offset 追加。
- **筛选只有一套**：分类片点击 = 只显示该类（再点「全部」恢复）；搜索框对服务端 `q`
  做 250ms 防抖。不设第二个「全部类型」下拉。
- **行**：正文首行 + Why/How 次行（有才显示）+ 日期/来源/被想起次数；「标过时 / 删除」
  收成悬停出现的图标钮（键盘 focus 也出现），确认框沿用 `openConfirm`。
- **整理**：
  - 悬停按钮（含 `?`）出说明：整理是回看记忆和原始对话找重复/过时，只给建议，
    逐条点应用才改，不会自动删；
  - 空闲：状态行显示上次整理时间与待处理建议数；
  - 运行中：按钮禁用 + 进度条 + 已耗时；切页回来从服务端状态恢复并继续轮询；
  - 完成：建议卡从服务端读回（含当次内存里的出处引文；重启后从待决文件读回，
    引文不落盘，卡片注明「存档建议」）；
  - 失败：状态行显示失败原因与「重试」；同一 scope 在跑时再点不会重复调模型。
- **导入**：按钮保留；点击弹说明「现在没有统一记忆格式，导入以后再做」。
  既有 `POST /memory/import` 与旧页导入逻辑保留（回滚页仍可用）。
- **外接库**：页脚一行，**无绿点**；已配置显示 `ask.py --catalog-only` 的首行边界，
  「查看」弹层显示全部边界行；未配置显示「未连接 · 在 .env 配 PERSONA_MEMORY_ASK 后重启」。
  不做查询框、不做独立页（后续独立立项）。
- **回滚**：`MEMORY_PAGE_A=false` 渲染旧页（旧 DOM/旧逻辑整套保留）。

## 后端契约（新增/变更）

### 1. `GET /api/v1/agent/memory`（增量参数，默认行为兼容）

新增 query：

| 参数 | 说明 |
|---|---|
| `q` | 正文子串搜索（`instr(lower(content), lower(?))`，≤200 字） |
| `kind` | 逗号分隔的 kind 列表；未知值 400 |
| `excludeKinds` | 逗号分隔，排除某些 kind（设置页传 `work`） |
| `offset` | 0..1000000，默认 0 |
| `limit` | 0..2000，默认 300；**0 = 只回计数、不回 items** |

响应新增/改语义：

```jsonc
{
  "ok": true, "enabled": true, "extract": "llm", "scope": "global",
  "total": 86,                       // 真实匹配数（不是本页条数）
  "counts": {
    "all": 86,                       // 活跃、匹配 q、已应用 excludeKinds
    "byKind": { "preference": 8, "episode": 44 }, // 忽略 kind 过滤，给分类片用
    "superseded": 4                  // 同条件下已被取代的条数（只报数）
  },
  "items": [], "offset": 0, "limit": 50, "hasMore": true,
  "canConsolidate": true, "canImport": true,
  "consolidateJob": true             // 后端是否支持后台整理（UI 决定用 202 还是旧同步）
}
```

`items[]` 增加 `lastRecalledAt`、`usageCount`、`expiresAt`（纯增量）。
`byKind` 语义从「本页窗口计数」改为「真实匹配计数」——旧界面只是显示数字，不受影响。

### 2. 整理任务（同一端点 + 状态端点）

```text
POST /api/v1/agent/memory/consolidate/review?background=1
  → 202 {ok:true, scope, running:true, startedAt, alreadyRunning?:true}
  → 若同 scope 已在跑：202 + alreadyRunning:true（不重复调模型）
  → 若 background 缺省：保持旧同步响应（兼容旧页/旧探针）

GET  /api/v1/agent/memory/consolidate/state?scope=global
  → {ok, scope, running, startedAt, generatedAt, proposals, source, error, audit}
     source = "live"（本次进程结果，含 evidence）| "pending"（重启后从待决文件读回，无 evidence）| "none"
     error  = {at, error, message} | null
     audit  = 上次确定性审计 {generatedAt, kept, merged, retired} | null

POST /api/v1/agent/memory/consolidate/dismiss {scope, keepId, dropId}
  → {ok, dismissed:boolean}   // 忽略持久化：从待决文件与内存结果里一起摘掉
```

- 单飞：模块级 `Map<scope, {startedAt, promise}>`；完成后结果留在内存供 `state` 读，
  进程重启后只剩待决文件（无 evidence，符合 2026-11-10「引文不落盘」口径）。
- `apply` 成功同样从内存结果与待决文件移除；`dismiss` 不写库、不删记忆。
- `POST /consolidate/pass` 仍在后台成功回调里跑；失败只影响 diff 文件。
- `MEMORY_CONSOLIDATE_JOB=false`：即使带 `background=1` 也回到同步等待（一行回滚）。

### 3. 外接记忆库最小状态

```text
GET /api/v1/agent/memory/external
→ {ok, configured, ready, provider:{id:"persona", name:"一生记忆库"}, catalog:{lines:[...]}, error?}
```

- 只读：`ask.py --catalog-only`（不碰 persona.db、不调模型），15s 超时，结果缓存 10 分钟；
  未配置 `PERSONA_MEMORY_ASK` 不 spawn，直接 `configured:false`。
- 日志只记行数/耗时/ok；不记边界文本。
- 通用 provider 接口（多种外部记忆库）**不在本轮**；本轮先把这个只读状态做成
  可替换的窄口，后续独立立项再加 provider 注册与查询页。

## 写入规则：合成指令过滤（`MEMORY_EXTRACT_NOISE`，默认开）

规则抽取器（`HeuristicExtractor`）增加质量闸，只挡确定性噪声，不做语义判断：

1. 跳过已知合成前缀：`用户已批准` / `用户拒绝` / `主人回答了你刚才的问题` /
   `本轮工具调用已达上限` / `已连续重复完全相同的工具调用` / `这个操作在等用户批准`；
2. 跳过指令句：以 `请/帮我/给我/麻烦/不要/别/直接/用/把/写/改/查/找/跑/运行/执行/
   生成/总结/翻译/解释/列出/打开/关闭/删除/安装/创建/整理/分析/比较/告诉/回答/说说` 开头；
3. 跳过问句（`?` / `？` 结尾）；
4. 每轮最多 5 条，同轮规范化同文去重。

- `MEMORY_EXTRACT=rule` 仍走旧规则（逐字节回滚口径不变）；`MEMORY_EXTRACT_NOISE=false`
  让 `auto/llm` 档也回到不过滤。
- 既有脏数据不自动删（D18）；用户可在页面上逐条删/标过时。

## 回滚开关（全部默认开）

| 开关 | 关掉回到 |
|---|---|
| `MEMORY_PAGE_A` | 旧记忆页 DOM/逻辑 |
| `MEMORY_CONSOLIDATE_JOB` | 同步等待整理（`background=1` 也同步） |
| `MEMORY_EXTRACT_NOISE` | 规则抽取不过滤合成指令 |
| `MEMORY_EXTERNAL` | 记忆页不显示外接库页脚（端点仍只读） |

## 明确不做

- 不做导入流程（占位；统一格式另外立项）。
- 不做外接库查询页 / 通用 provider 注册 / 每轮自动注入（后续独立）。
- 不改 D18：不自动整理 cron、不自动应用、没有「全部应用」、不自动删。
- 不做记忆编辑、向量检索、跨设备同步。
- 不改 `shared` 包、不涉手机端（本页只属于电脑端设置）。
