## 一、B3 设备活豁免（harness 侧，本批做）

- 现状：`DELEGATION_PROJECT_REQUIRED=true`（默认）时 `delegate` 对无项目派活回 `needs_project`（tools.ts:340、projects.ts `resolveDelegationProject`）——手机/设备类活（执行体是 phone worker，不落本机磁盘）天然没有项目，被硬拦。
- **规则**：派活执行体为设备 worker（`worker=phone` / 带明确 `targetDevice` 的设备派发，以代码实际判别字段为准，实现时先定位）→ **豁免项目前置**：`project` 可省，按无项目单受理（设备活不进 worktree/租约语义，chancellor 侧本就按设备通道处理）；电脑 worker（codebuddy/qoder 等本机执行体）照旧必须带项目。
- 豁免不改变 D10 的其余边界（工作区 realpath 校验等只对本地执行体有意义）。
- 回滚：`DELEGATION_DEVICE_PROJECT_EXEMPT=false` → 设备活也要项目（回到现行为）。
- 探针：delegate 探针补场景——设备活无项目受理成功；本机活无项目仍 `needs_project`；回滚开关双向。
- 文档：接口文档 delegate 工具节 + env 表；系统架构 D10 行注记豁免规则。

## 二、手机侧本批（P1 三件，全缺→补齐；每件独立可验收）

1. **文件浏览**：`FilesApi` 客户端（`GET /api/v1/files`、`/api/v1/files/content`）+ 新屏（项目→目录→文件三级浏览 + 文本预览）。模块归属按手机仓《模块边界》裁定并**先改该文档再写代码**（候选：core:pairing 扩 harness 通道，或新 core 模块——实现者按边界文档的独占权表定，汇报写明理由）。UI 走 `DevicesNavKey` 三步法 + `LdGroupCard` 分组皮肤。
2. **模型切换**：`ModelApi` 客户端（`GET /api/v1/agent/model` 投影 + `POST` 切换 + `GET /api/v1/agent/providers`）+ 设置页新区块（当前模型 + 可选列表 + 切换）。替换"模型名硬编码常量"的使用面时保持聊天请求体 model 字段现状（服务端忽略该字段的分流语义不动，接口契约 §3.2）。
3. **课题列表与简报**：`TopicsApi` 客户端（`GET /api/v1/topics`、`/topics/:id`、`/:id/close`、`/:id/run_now`、proposals accept/decline）+ 新屏（进行中课题列表 + 详情含 findings 简报 + 关闭/立即查一轮）。入口挂抽屉多端分区或设备页（2026-11-05 海拔结论：不加顶级入口）。
- 共同纪律（手机仓硬规则）：MockWebServer 契约测试照 `AgentApprovalApiTest` 范式；失败不抛异常（查询 null/动作 Boolean）；kotlinx.serialization；Truth + Turbine；`spotlessCheck` + `testDebugUnitTest` + `assembleDebug` 必过；单文件 ≤500 行；变更记录按手机仓惯例。
- **明确不做（手机侧本批）**：任务中心屏、远端会话入抽屉、聊天派活入口、执事管理/dispatchAuthority UI、跨机相位主动推送、审批通知、home/overview 消费（后批逐项）。

## 三、契约面结论

- **新契约只有一处**：B3 豁免行为 + 回滚 env（harness 接口文档 delegate 节）。其余全部复用既有端点（files/model/providers/topics 在 `接口文档.md` 均已登记）。
- relay 投影带 `dispatchAuthority`（为后批执事管理铺底）：`/api/v1/relay/overview` 或设备投影补字段——**顺带做**（一行投影 + 探针断言），手机本批不消费。
- 手机仓 `接口契约.md` §5 表：新接端点从"未接"改"已接"，§0 总表补行（手机仓侧文档改动归手机任务书）。
