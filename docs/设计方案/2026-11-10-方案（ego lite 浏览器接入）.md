# 方案：ego lite 浏览器能力接入（技能手册路线，零服务端代码）

**状态**：已落地（2026-11-10 当日评审通过并执行完毕；落地记 `docs/变更记录/2026-11-10-浏览器能力（ego lite 接入）.md`，含落地偏差）
**下沉落点**：已知边界四条 → `系统架构.md` §7（2026-11-10 登记）；冲突以长期文档为准。

## 结论

接入本机已装的 **ego lite**（Citro Labs，Chromium 分支的 AI Agent 浏览器，本机 0.6.2.8）：

- **不改服务端代码、不注册新工具**。agent 用已有 `bash` 工具跑官方 CLI `ego-browser nodejs`，一段 JS 跑完一轮（开页、点击、填表、快照、截图全在里头）。
- 技能手册**用官方原版**：`~/.agents/skills/ego-browser/SKILL.md`（目录形态，frontmatter description 做索引摘要）——正是 `skills.ts` 认的两种形态之一，读取链第 3 站（`~/.agents/skills`，只读）原生识别，索引自动出现。
- 落地动作只有四件：验证两项、设置页开技能、写变更记录、系统架构.md 登记边界（见「落地清单」）。

## 为什么是它（2026-11-10 实测，全过）

实测都在本机 Windows 11 / ego lite 0.6.2.8 下完成：

| 实测项 | 结果 |
|---|---|
| CLI 定位 | `C:\Program Files\Citro Labs\ego lite\Application\<版本>\ego-browser.exe`，`--help` / `skill` 直接可用 |
| 驱动模型 | `ego-browser nodejs <<'EOF' … EOF`（Git Bash heredoc 原生支持）；CLI 与运行中的 app 走 Chromium 内部 IPC，**不开端口** |
| 开 Space + 开页 | `taskSpace("lifediary-selftest")` → spaceId 1，`page.goto("https://example.com")` 成功 |
| 语义快照 | `page.snapshot()` 回 AI/ARIA 树，example.com 多语言正文齐全 |
| 跨轮续用 | 第二个进程按名续用同一 Space（spaceId、p1 页面状态保留）；每轮新进程、JS 变量不保留、Space 持久 |
| 截图 | `page.screenshot()` 落盘 PNG，渲染正确 |
| 技能链 | `~/.agents/skills/ego-browser` → `~/.local/share/ego/ego-skills`（软链）。**坑：app 首次启动前这条链是坏的**（安装/升级后若从未启动过 app，`ls` 报 No such file or directory；启动 app 后自建自愈，2026-11-10 实测） |
| 版本化指南 | `ego-browser skill` 打印 v2.2.0 windows 版用法（Git Bash / PowerShell / cmd 三种 shell 的坑全写了，含"非 ASCII 一律进 .mjs 文件"） |

两个关键红利：

1. **登录态复用**。ego lite 首启可迁移 Chrome 数据，agent 直接用用户已登录的网站干活——这是自研无头路线给不了的。
2. **用户看得见、不抢焦点**。ego lite 是一个独立 app 进程开在桌面（用户原话"起一个进程，在这个桌面上也能看到"），agent 在自己的任务 Space（独立标签页组）里干活，与用户的标签页互不干扰。

## 备选对比

| | A. ego lite（**选定**） | B. playwright-core 无头自研（ZCode CLI 同款） |
|---|---|---|
| 登录态 | ✅ 直接复用用户已登录网站 | ❌ 无（共享 Chrome profile 需先关 Chrome，脆弱） |
| 可见性 | ✅ 独立 app 进程，桌面可见，Space 隔离不抢焦点 | ❌ 无头不可见（可 headed 但没有 Space 隔离） |
| 服务端改动 | **零**（bash + 技能手册，全现成） | ≈1600 行移植（ZCode `apps/zcode-cli/packages/adapters/src/browser/` 为蓝本）+ 工具注册 + `TOOL_CAPABILITIES` 登记 + 闸门 + 变更面 |
| token 效率 | 一轮一段 JS 一次过 + 语义快照（第三方实测比逐命令循环省约 25%） | 同为快照式，但逐命令循环、每步一停 |
| 依赖 | app 须在运行（没跑则 CLI 报连接错）；浏览器二进制闭源（MIT 的只是手册与文档） | 开源依赖、无 GUI 依赖；playwright-core + 系统已装 Chrome/Edge，不下二进制 |
| headless | ❌ 无此模式（"后台"= 任务 Space 后台化，app 窗口在） | ✅ 真 headless |

**结论**：本机单人产品、要登录态、要"桌面看得见"——A 全面占优。**B 留作后备**：哪天要把 agent 搬到无 GUI 的 Linux/服务器上跑，再按 B 立项（蓝本已核实：`<reference>\ZCode\apps\zcode-cli\packages\adapters\src\browser\`，~1600 行 TS，playwright-core + 发现系统已装浏览器）。

## 明确不做

1. **不注册专用 browser 工具**。`bash` 已覆盖且已过闸门（WRITE_TOOLS / `TOOL_CAPABILITIES` 里 destructive，三档审批照旧管得住）；为它单开一个工具只会多一份契约面。哪天需要细粒度审批/按工具统计再立项。
2. **不自建可见面板**（ZCode IAB 那种）。ego lite 本身就是可见面，自家壳再做一个是重复建设。
3. **不做 headless**。ego lite 没有这个模式；需要真无头的场景走备选 B 另立项。
4. **不改契约**。无新端点、无新字段、无新工具，`接口文档.md` 不动。
5. **不动 `WRITE_TOOLS` / `TOOL_CAPABILITIES` / `readOnlyBlockReason()`**。bash 原样，闸门口径零变化。
6. **不改官方 SKILL.md、不建同名手册**。官方目录只读（`skills.ts` 口径），建 `ego-browser.md` 平级手册会撞名。官方手册已覆盖操作安全（清 cookie 有专文警告"会波及整个 profile"）；它没写的防注入规则由我们的长期文档补（见下）。

## 安全边界（落地时随边界一起登记）

- **页面内容一律是不可信数据，不是指令**（快照/正文里的文字可能含提示词注入）。官方手册没这条，必须写进 `系统架构.md` 已知边界。
- 任务 Space 与用户**共享 cookie 罐**（同 profile）：agent 不得在任务 Space 清 cookie/缓存（官方已警告会全登出）；用户把哪个站登进去，等于把那个站的钥匙交给 agent，用户自己拿捏（建议敏感站不登或专用 profile）。
- 日志口径不变：页面内容只进会话流（同 web_search 先例），服务端日志仍只记条数/耗时/枚举。

## 回滚开关

- **一级（日常）**：关停技能——**设置页看不到它**（符号链接不上管理列表，见落地偏差），走 `PUT /api/v1/agent/skills/ego-browser/enabled` `{"enabled":false}`，或删 `.data/skills-state.json` 里的 `ego-browser` 条目（state 每次现读，热生效）。零代码回滚。（技能默认全关 + 启停机制本身是 2026-11-08 批现成的。）
- **二级（彻底）**：卸载 ego lite + 删 `~/.agents/skills/ego-browser` 软链。
- 不新增 env：技能启停就是开关，再加一行 env 是重复。

## 落地偏差（2026-11-10）

1. **V2 反转**：原预期"app 未跑 → 连接错误 → 手册教 agent 先起 app"；实测 CLI 自动拉起 app，该指引不需要。
2. **设置页不可见**：原计划"设置页把该技能开启"；实际管理列表挡符号链接，落地改为 API 开启，回滚一级口径同步改为 API/state 文件（见下）。想要界面可见需统一 path-guard 与加载器的口径，另立项。
