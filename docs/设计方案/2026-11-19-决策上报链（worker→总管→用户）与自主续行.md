# 决策上报链（worker→总管→用户）与自主续行（2026-11-19）

**状态**：设计已拍板（用户 2026-11-19：权限管理不动——已开放；要做的是"哪些事需要往上问、需要上级决策"，比如问问题；自报完成的质检用派 worker+提示词实现，不写代码）。
**下沉落点**：落地后上报事件契约 → `接口文档.md` §端点4（执行例行与自主轮）；续行与上报状态机 → `系统架构.md` 派活段。

## 背景与拍板

用户口径：延长自主性 = worker 一次跑更久、人管得少。缺的不是权限（已全开放），是**上报决策的通道**：worker 遇到要决策/要问的事，先报总管；总管定不了再报用户。质检=派质检 worker（提示词就够）。续行=预算内自动接轮。

## 方案

### 1. 统一上报形状：escalation
worker 侧新增上报工具 `escalate`（native worker 工具面加一个）：`{question, context, options?, urgency}`。取代/收编裸 `attention.question`（旧格式兼容读）。
**分级不由代码判**：一律先报总管；总管自己决定"我能答"还是"升级"（升级=它调升级动作，或答复里明说答不了）。涉及花钱、用户私事、总管没上下文的，靠总管提示词约束升级，不写死规则。

### 2. 上报路由（契约先行）
- 新 SSE 事件种类 `escalation`（shared `ts/packages/shared/src/index.ts` 先改 + `接口文档.md` §端点4 再动实现）。
- 上报 → 投**派活方会话**（复用 attention/任务专线通道）：上报卡 = 问题+上下文+两个动作「总管代答 / 升级给用户」。
- 总管代答 = 在总管会话起一轮（复用 delegation-wake 的 `runPartnerTurn` 路径，autonomous 标记）→ 答复经 **批1 worker 插话通道**（steer）投回 worker → worker 续跑。
- 升级 = 转投用户（用户所在的主会话出卡，走 ask_user 形态）→ 用户答复 → 同路投回 worker。
- 限流：每 worker 同时 1 条活跃上报；每任务上报上限 `ESCALATION_MAX_PER_TASK`（默认 5），超限直达用户。
- 审计：谁答的（总管/用户）、答了什么，记进任务台账与最终汇报。

### 3. 自主续行
- worker 等上报答复期间挂起不退（waiting + escalation pending），答复到即续跑。
- 无上报时撞 turn 上限 → 预算内自动接轮：`WORKER_TURN_BUDGET`（默认 3 段续轮），用外部再 submit（现成模式）或内核 `onYield`，实施时择一（内核钩子更干净，优先试它）。
- **无进展保险丝**（抄 dim）：连续 3 轮无工具调用 → 停止续行并上报"做不动了"。
- 环绕：每段续轮重过任务 still-active 检查；任务被取消/验收方会话关闭 → 立即停。

### 4. 质检 worker（用户拍板：提示词实现，不写代码）
- 派活设置加"质检方式"选项：`内部一次请求（现状，默认）/ 派质检 worker（新）`。
- 选"派质检 worker"：worker 自报完成 → chancellor 以质检模板再派一单（同一 worker 池），质检提示词模板文件落 `ts/packages/chancellor/src/templates/qa.md`（可编辑，含"亲自验证、别信汇报、结论 DONE/CONTINUE/BLOCKED"）。
- 质检结论 CONTINUE → 以续行输入投回原 worker；DONE → 走既有验收收单；BLOCKED → 走上报链。
- 0 新逻辑代码：只有模板 + 分支调用既有派单器。

## 明确不做

- **总管代批工具调用**（审批代批）——用户明确权限侧不动；审批闸本就不在 worker 管线里。
- 外部 CLI 的上报/续行（进程外锁死，边界写脸：没做）。
- 上报的持久化状态机（点到为止：上报列表读会话事件即可，不做投递结算——参照批5 拍板）。

## 回滚

- `ESCALATION_CHAIN_ENABLED=false` → 回现状 attention 直达人；
- `WORKER_TURN_BUDGET=0` → 不续行；
- `WORKER_ESCALATE_TOOL=false` → escalate 工具不上架。
