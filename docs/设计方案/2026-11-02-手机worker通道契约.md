# 手机 worker 通道契约

> 2026-11-02。电脑和手机之间就这四个接口，两边照着做，不要各自发挥。

## 结论

四个接口，手机全部**主动发起**，电脑不开入站、手机不开端口。

| 接口 | 谁调 | 干什么 |
|---|---|---|
| `POST /api/v1/worker/poll` | 手机 | 长轮询要活 |
| `POST /api/v1/worker/model` | 手机 | 干活时调模型（电脑代理 key） |
| `POST /api/v1/worker/result` | 手机 | 交结果 / 报卡住 |
| `POST /api/v1/worker/shell` | 手机 | 把 App 拉到虚拟屏（白名单内的 adb shell） |

鉴权：全部用现有设备凭据（`Authorization: Bearer <deviceToken>`），跟聊天接口一样。
**鉴权失败一律 403 空体**，不区分原因。业务拒绝（比如 shell 白名单）是 400，带说明。

## 一、要活

```
POST /api/v1/worker/poll
Authorization: Bearer <deviceToken>
{ "timeoutS": 30 }
```

电脑有活 → 立刻返回；没活 → 挂起最多 `timeoutS` 秒后返回 204。

有活时：

```json
{
  "taskId": "w-20261102-211900-ab12",
  "goal": "打开设置，进入关于手机，告诉我 Android 版本号",
  "doneWhen": "回答里明确说出 Android 版本号，且取自「关于手机」页面",
  "budgetMs": 600000
}
```

**只传任务，不传动作。** worker 拿到 goal 自己看屏、自己判断、自己点。

## 二、调模型

```
POST /api/v1/worker/model
Authorization: Bearer <deviceToken>
{
  "taskId": "w-...",
  "messages": [{"role":"user","content":"..."}],
  "tools": [ ... 可选，工具定义原样透传 ... ]
}
```

电脑把 key 加上，转发给模型商，**把模型商的响应原样返回**（不解析、不改写）。

失败时返回 `502` + `{"error":"upstream_failed","detail":"..."}`。
**不要**把模型 key 或上游原始错误里的敏感信息带出去。

## 三、交结果

```
POST /api/v1/worker/result
Authorization: Bearer <deviceToken>
{
  "taskId": "w-...",
  "status": "done" | "blocked" | "failed",
  "summary": "一句话说清干了什么、结果是什么",
  "attention": { "kind": "need_action", "question": "..." }   // 仅 blocked 时
}
```

| status | 含义 |
|---|---|
| `done` | 干完了，`summary` 是结果 |
| `blocked` | 卡住要人，`attention.question` 是它要问的 |
| `failed` | 试过了，干不成，`summary` 说清为什么 |

**worker 不许说「我过了」。** 它只说干了什么、屏幕现在什么样；过没过由电脑验收。

## 四、受限 shell（白名单）

手机做「后台虚拟屏」时，建屏、截图、读屏、点击都在 App 内完成，
**只有「把 App 拉到虚拟屏上」这一步需要 shell**（`am start --display <id>`）。
所以借电脑的 adb 执行一条**白名单内**的命令。一次任务通常只需要一次。

```
POST /api/v1/worker/shell
Authorization: Bearer <deviceToken>
{ "argv": ["am","start","--display","2","-n","com.android.settings/.Settings"] }
```

成功：

```json
{ "ok": true, "exitCode": 0, "stdout": "...", "stderr": "" }
```

失败：`{ "ok": false, ... }`（命令执行了但退出码非 0）或 400 / 403 / 409 / 502 / 503 / 504。

**这是白名单，不是通用 shell。** 只允许这几种 argv 形状：

| 允许 | 说明 |
|---|---|
| `am start --display <n> -n <pkg/Activity> ...` | 把 App 启到指定屏（必须带 `--display` 与 `-n`） |
| `am force-stop <pkg>` | 停 App |
| `input -d <n> tap <x> <y>` | 在指定屏点 |
| `input -d <n> swipe <x1> <y1> <x2> <y2> [ms]` | 在指定屏滑 |

**必须拒绝（400，并记日志，且不创建子进程）**：

- 任何不在上表的 argv
- `am start` 但没有 `--display`（会启到主屏，绕过虚拟屏意图）
- 含 `;` `&&` `|` `$(` 反引号等 shell 元字符的参数
- 参数数量异常、数字参数不是数字
- 路径类参数（`/`、`..`）——这条接口不该碰文件

**实现方式**：`spawn` 直接传 argv 数组（实际是 `adb -s <serial> shell <argv...>`），绝不拼字符串走 shell。

电脑侧配置：

- `ADB_PATH`：adb 路径，默认 `C:/Users/<user>/AppData/Local/Android/Sdk/platform-tools/adb.exe`
- `ADB_SERIAL`：设备序列号；不配则取 `adb devices` 里唯一那台，多台直接报错（不猜）
- 超时 10 秒，超时杀掉子进程

adb daemon 在这台机器上会被反复杀掉：每次调用都不依赖上一次的 daemon 状态，
命令失败且看着像 daemon/设备掉线时，先 `adb start-server` 再重试一次；不缓存「设备在线」。

## 五、电脑侧怎么接

手机 worker 是 chancellor 的**一种雇员**（`employee: "phone"`），走同一套派活/验收/续跑。

```
delegate(requirement)
  → 宰相拆单
  → 每件事派给 phone 雇员
      → 入队，等手机来 poll
      → 手机交结果 → 组装成 EmployeeOutcome
  → 验收（跟原生/雇佣兵同一套）
```

| 手机交的 | 变成 |
|---|---|
| `done` + summary | `ready`，summary 落 `result.md` |
| `blocked` + attention | `blocked` + `attention{kind:need_action}`，进 `needs_you` |
| `failed` | `failed` |
| 超过 `budgetMs` 没交 | `idle`（不判失败） |

## 六、队列怎么存

**先放内存，不落库。** 理由：这是原型，落库要处理过期、重启恢复、多实例。
内存队列重启就丢，丢了的单子由 chancellor 那边判 `idle`——可接受。

代价写清：**电脑重启后，正在手机上的活会丢**（手机交结果时会 404）。
这时手机应当放弃当前任务，重新 poll。

## 七、这条会怎么错

1. **如果 poll 返回动作序列**（点这里、点那里），那就退化成遥控机械手了。**只传任务。**
2. **如果模型响应被改写**，手机那边的提示词就白调了。原样透传。
3. **如果 worker 能自己判"过了"**，就破了"不许自己判自己"。它只能说干了什么。
4. **如果队列落库**，原型阶段是白付复杂度。先内存。
5. **如果手机开端口**，就多一个被攻击的面。**只准主动 poll。**
6. **如果 blocked 当失败处理**，用户永远等不到那张「需要你」的卡片。
7. **如果受限 shell 退化成通用 shell**，手机就不再只是「操作虚拟屏」，而是能读写这台电脑的文件。白名单必须按 argv 形状判，不能按前缀放行。
