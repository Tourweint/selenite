# 会话级模型切换（主模型只读一次）（2026-11-19）

**状态**：已落地（2026-11-19）；结论已下沉 `接口文档.md` §6 / `接口-端点3` §2.8 /
`接口-端点1` §2.1 / `系统架构.md` D34。
**冲突口径**：落地后以 `docs/基线文档/接口文档.md`、`docs/基线文档/接口-端点1-对话与兼容层.md` §2.1 / §2.8、
`docs/基线文档/系统架构.md` 为准；本文保留"当时怎么想的"。

## 1. 背景

用户 2026-11-19 确认：

- 对话框里的模型 pill **随时能改**，不需要非得改全局；
- 默认在**建会话时读一次全局默认模型**就行，之后这个会话自己记自己的模型；
- 右上角「对话设置」里再放一个「主选模型」是重复的，应该删掉；
- 右上角只留执事的「备选模型」（用户口述里也叫"次要模型"）——它是主模型不可用时的兜底重试，
  不是第三条模型车道。

现状（2026-11-19 代码核实）：

- 模型 pill 和右上角「主选模型」都走 `POST /agent/model` → `setRuntimeModel()` → 写
  `.data/runtime.json` **一个全局选择**；2026-11-04 的方案里明确写了「不做 per-会话 override」。
- 每条会话开跑前 `syncConversationModel()` 读 `readLlmConfig()`，把会话 configure 到全局模型。
  会话自己虽然存着模型引用，但每轮会被全局值覆盖，所以不是"本会话自己的设置"。
- 唯一的 per-执事 模型是「备选链」（`model-chain.json`），只在执事试跑 / 例行任务轮次的
  `unanswered` 时自动换下一条重跑，主对话不读它。

## 2. 目标与非目标

### 目标

1. **主模型只在建会话时读一次**：新会话用当时的全局默认（或客户端在新建时显式选的模型）；
   之后全局默认再变，已有会话不追。
2. **每个会话自己记模型**：pill 只改当前会话；同一会话可以来回换；额度用完不影响别的会话。
3. **右上角不再重复**：删「主选模型」卡和首页「模型」值格；执事只留「备选模型」链，
   非执事不再出现模型入口。
4. **新会话屏也能选**：在还没落盘的欢迎屏选模型，先记在本地，第一条消息随建会话带上去；
   不写全局默认。

### 非目标（本批明确不做）

- 不做「跟随默认模型」的会话开关：会话模型就是自己的，不追全局。
- 不改执事备选链的语义（仍是自动重试，不是主模型；不把链里的模型写进会话主模型）。
- 不做 group 会话、任务专线、例行任务的新模型选择 UI；它们的会话模型仍按建会话时取到的值走
  （`ensureConversationModel` 只修坏引用，不主动改）。
- 不改全局默认模型页（设置 → 模型）的接口和布局。
- 不改手机端：`ChatRequest.model` 是纯增量可选字段，手机不发 = 继续用全局默认。

## 3. 决策

### D1 存储：不新增会话模型表

durable 会话本来就存着自己的模型引用（`conversation.configure({ model })`）。
本批**不新增** `ChatModels` 文档：建会话时写进去，之后不再被全局覆盖，这就是"会话自己的模型"。
- 旧会话：保留它当前存的模型；如果它之前被全局对齐过，那个值就是它的模型。
- 不需要迁移；不需要把"是否显式选过"记成额外标记。

### D2 运行时：停止全局对齐，只修复坏引用

把 `syncConversationModel()` 改成 `ensureConversationModel()`：

- 会话有模型且模型在当前目录里（含思考变体 / 基座可用）→ **什么都不做**；
- 会话模型缺失 / 供应商被删 / 模型不在目录 / 思考变体没注册 / 当前档不在新模型支持域
  → 才 configure 一次：优先保留基座与档位，做不到就回退全局默认；日志说明是修复，不是对齐。
- 每轮开跑前仍调用一次（`session-stream.ts`），但正常路径是零 configure。

### D3 新建会话：默认读全局，可带一次客户端选择

- `ChatRequestSchema` 增可选 `model: { providerId, modelId, thinking? }`（纯增量）：
  - 不带 / 不是新会话 → 服务端用 `chatModelRef("off")`（当前全局默认）；
  - 新会话带 → 校验供应商 / 模型，按 `thinking` 派生思考变体，作为这条会话的初始模型。
- 只影响这一条新会话，不写 `.data/runtime.json`。
- 手机端不发送该字段 → 行为不变。

### D4 已有会话切模型：一条专用端点

`POST /api/v1/agent/chat/:conversationId/model`

- body `{ providerId, modelId, thinking? }`；
- 校验模型在目录里；`thinking` 缺省 = 保留会话当前档位，按新模型支持域 clamp；
- `conversation.configure({ model: chatModelRefFor(...) })` + `rememberLevel`；
- 只改这一条会话，下一轮生效；不写全局；
- 返回 `{ ok, provider, model, thinking, thinkingLevels }`。

`GET /api/v1/agent/model?chat=<对外会话 id>`：

- 返回模型目录 + `current` = 这条会话的基座模型 + `thinking` = 当前档位 + `thinkingLevels`；
- 不带 `chat` = 现有全局投影（设置页默认模型卡继续用）。

### D5 思考档

- 会话的思考档仍存在会话引用的 `#think-<level>` 变体里（+ 进程内粘性），本批不新增存储；
- 切模型时保留当前档，落到新模型支持域内（`clampThinkingLevel`）；
- `POST /mode` 改为按**当前会话模型**的支持域校验，不再按全局模型；
- 前端 pill 的档位显示以 `GET /agent/model?chat=` 返回的 `thinking` 为准；打开会话时同步一次。

### D6 前端：pill 是唯一模型入口

- pill 菜单加 `scope=session`：
  - 已有会话 → `POST /agent/chat/:id/model`，只改这一条；
  - 新会话屏（无 `conversationId`）→ 记本地 `pendingModel`，不发请求；第一条消息把
    `model` 放进 `ChatRequest`，建会话后清掉 pending。
- 打开会话 / 新建会话时刷新 pill（`GET /agent/model?chat=`，不带 chat 用全局）。
- 设置页的默认模型卡仍是全局（`scope=global`，走原 `POST /agent/model`）。
- 右上角「对话设置」：
  - 删首页「模型」值格和模型二级页的「主选模型」卡；
  - 执事保留「备选模型」值格 → 二级页只编辑备选链，文案写明：
    **主模型在输入框左下角切换；这里只配自动重试顺序**；
  - 非执事会话不再出现模型入口。
- 右上角的「备选模型」不叫「次要模型」：代码 / 文档 / 备份链已经有稳定名字，
  用户也确认「就留这个你叫的备选模型」；含义就是兜底重试。

### D7 全局默认

- 设置 → 模型的默认模型继续写 `.data/runtime.json`；
- **只影响之后新建的会话**，已有会话不追；
- 新建会话不带 `model` 时读它一次。

### D8 回滚

`CHAT_SESSION_MODEL=false/0/off`：

- `ensureConversationModel()` 回到旧的全局对齐行为（每轮把会话拉到全局默认）；
- `POST /agent/chat/:id/model` → `400 session_model_disabled`；
- `GET /agent/model?chat=` 只回全局投影，带 `sessionModel:false`；pill 据此回到旧的全局切换，
  新会话屏不再记 pending；
- `ChatRequest.model` 被忽略（仍按全局默认建会话）。

## 4. 影响面 / 风险

- **行为变化**：全局切模型不再把所有已有会话带走；这是用户明确要的。
- 旧会话如果引用被删的供应商 / 模型，`ensureConversationModel` 会回退全局默认并记日志。
- 群成员会话 / 例行任务会话没有 pill，建会话后不会再有 UI 改模型；需要时再单独立项。
- `ChatRequest.model` 是 shared 契约的纯增量字段；手机端不发，行为不变；契约快照要更新。
- 备选链仍只在执事试跑 / 例行任务轮次生效，主对话不自动换；用户在主对话要换就点 pill。
- `ensureConversationModel` 正常路径零 configure；只有在模型损坏 / 档位越界时才写一次，
  不影响上下文缓存之外的运行成本。

## 5. 验证

- 单测：
  - `chatModelRefFor` / 模型可用性；
  - `ensureConversationModel` 三种路径（有效不动 / 变体缺失或档位越界修复 / 坏引用回退全局）；
  - `POST /agent/chat/:id/model` 只改一条、`GET /agent/model?chat=` 回本会话模型；
  - shared 契约快照新增 `model` 字段。
- `pnpm typecheck`；`pnpm --filter @lifediary/server test`；`pnpm probe`；`pnpm http`。
- 浏览器：两条会话各自切模型互不影响；新会话屏选模型后第一条消息按它起；
  右上角只剩执事「备选模型」；全局默认只影响新建会话。
