## 1. 背景与用户口径

用户确认「领域没有任何用处」，选择**先关入口、不删代码**：

- 总管派活不再带领域，不再起「领域负责人」（分管宰相）；
- 执事身份、执事档案里的领域标签、任务中心花名册分组、同领域串行锁**先保留**，确认没人用再彻底清；
- 不做一次性大删除（manager 模块 / lane 同领域锁 / 跨仓契约都不动）。

## 2. 方案

### D1. 默认关闭领域派活入口

新增 env `CHANCELLOR_DOMAIN_DISPATCH`，默认 `false`（关）：

- `false`：`delegate` 的工具描述与参数**不暴露** `domain`；即使旧调用方/旧会话带 `domain`，路由层也忽略它，一律按「无领域」直派 worker（`managers:false`）。
- `true`：恢复改动前的完整行为（领域参数、领域负责人、分管路径）。
- 回滚就是一行 env，不改代码。

### D2. 不删的代码

- `chancellor/src/employee/manager.ts`、`manager/` 注册表、`ChancellorRequest.domain`、`TicketOptions.domain`、`resolveDelegateRouting` 的领域分支：全部保留。
- 执事（partner）的领域标签、花名册按领域分组、同领域串行锁（`lane.ts`）：保留；`CHANCELLOR_DOMAIN_DISPATCH=true` 时照旧生效。

### D3. 提示词与文案

- `delegate` 描述去掉「领域负责人」；`domain` 参数在关闭时不进 schema（模型看不到）。
- `ts/apps/server/skills/delegate.md` 若提到领域，改为「领域派活已停用（默认），直接派 worker」。
- `partner_manage` 的就位文案去掉 `delegate(domain=...)` 的提法，改为「直接派给它」。
- 派活结果文案里的 `（领域：xxx）` 自然不再出现（domain 为空）。

### D4. 执事路由不变

执事的「在自己领域内直派 / 跨领域拒绝」仍按执事身份判断（`callerDomainOf`），不依赖 `delegate.domain` 参数；关闭入口后执事仍能正常派活。

## 3. 明确不做

- 不删 manager 模块、lane 同领域锁、执事领域字段、前端花名册分组。
- 不改跨仓契约（手机端不读 domain）。
- 不做「领域迁移 / 数据清理」。

## 4. 验证

- 开关关（默认）：`delegate` 不带 `domain` 正常派工；旧调用带 `domain` 也不起 manager（ticket 的 `domain` 为空、`managers:false`）。
- 开关开：原有领域测试与行为不回归。
- `pnpm typecheck`、全套 `pnpm --filter @lifediary/server test`。
- 文档：接口文档 `delegate` 参数表与 env 表补 `CHANCELLOR_DOMAIN_DISPATCH`；变更记录。
