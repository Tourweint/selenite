# 2026-11-21 普通助手技能选择（worker 独立命名空间）

> 状态：已落地（2026-11-21）。
> 下沉落点：`docs/基线文档/接口-端点7-权限技能与开关.md`（端点与语义）、
> `docs/基线文档/接口-端点4-执事例行与自主轮.md`（worker-tools 加 `escalate`）、
> `docs/基线文档/系统架构.md` §4.1（普通助手页）、`docs/变更记录/2026-11-21-普通助手页重做（三段·工具收一行）.md`。
> 冲突以长期文档为准。

## 为什么

用户口径：普通助手也应该能**选技能**，像执事个人页那样；不是只看一个「已开 N / 共 M」的计数。

## 现状（2026-11-21 核实）

- 技能可见性 = 全局启停位 + `partners.<partnerId>` 覆盖层，同一份 `.data/skills-state.json`。
- 语义：全局开 → 所有人都有、按人锁死；全局关 + 该人覆盖开 → 只对该人可见。
- worker 会话**没有自己的键**：`skillPartnerOf()` 回落 `effectivePartnerIdOfSession()` → `chief`；
  `skill` 工具也走同一条回落。也就是说普通助手一直在间接套用总管的按人可见性。
- 普通助手页只读计数、点击跳全局技能页，没有任何按人选择入口。

## 决定

1. **复用同一份状态，加保留键 `worker`**：`skills-state.json` 的
   `partners.worker.enabled.<name>`。零新文件、零新表；`worker` 不是 partners 档案，不会与 uuid / `chief` 撞键。
2. **读写端点**：
   - 读：复用 `GET /api/v1/agent/skills?partnerId=worker`（已有 `partnerEnabled` / `partnerOverride` 形状）。
   - 写：新增 `PUT /api/v1/agent/worker-skills/:name/enabled`，语义对齐执事个人页：
     全局已开 / core → 409；技能不存在 → 404；只写覆盖层，不改技能文件。
3. **注入侧**：
   - `skillPartnerOf(ctx)`：`chatKind=worker` → `worker`，其余保持（执事 uuid / 主对话 chief）。
   - `skill` 工具：`createTools` 新增可选依赖 `skillOwnerOf(conversationId)`，由 lifecycle 装配层实现
     （worker → `worker`；执事 → 真实 uuid；其它 → `chief`）。不传 = 旧行为，单测 / 探针零改动。
4. **界面**：普通助手页「技能」行点击开弹层，两段——**全局已开（锁死只读）** /
   **全局未开（只给普通助手开，逐条开关）**。不做「他自带的技能」段（普通助手没有自己的家目录）。
5. **回滚**：`WORKER_SKILL_SCOPE=false/0/off` → worker 会话回到回落 `chief` 的旧形态，
   新写端点一律 409；已存覆盖位保留，重开后恢复。

## 行为变化（写进长期文档）

升级前 worker 会话会顺手继承**总管私开**的技能；升级后只看「全局开 + 普通助手自己的覆盖」。
需要沿用某条，就在普通助手页给它开一次。已在跑的会话索引按会话冻结，下一个会话生效。

## 明确不做

- 不给普通助手「自带技能目录」：没有 partner home，技能仍只有全局库一条来源。
- 不做按会话的技能选择：技能可见性本来就是全局 / 按人两层，不按会话。
- 不改派活工人：native 工人不读技能索引（TASK.md 的「你是谁」段），外部 CLI 用自己的工具。
- 不在这个弹层里加「新建技能」：新建仍在「注入 → 技能」，避免两条创建流程。

## 备选与取舍

| 备选 | 为什么没选 |
|---|---|
| 新文件 `.data/worker-skills.json` | 多一份状态、两次原子写、与 `skills-state.json` 可能打架；复用 partners 层零成本 |
| 复用 `/api/v1/partners/worker/skills/...` | 该组路由要求 partners 表里有真实档案行（不存在 404）；伪造一行会进花名册 / 执事列表 |
| 只在前端把 worker 映射到 chief | 会改到总管的技能可见性，语义错误 |
| 新开一套 worker 技能管理页 | 与「注入 → 技能」重复；用户要的是「像执事一样能选」 |

## 验收

- `skills.test.ts`：写覆盖层 / 关掉删除 / core / 全局已开 / 不存在 / 非法名各自断言。
- `agent/injection.test.ts`：`chatKind=worker` 的索引含 worker 独开技能；chief 索引不含。
- IAB：技能行显示「全局 20 · 独开 0」；弹层两段 20 / 140；开一条 → `partners.worker` 落盘、
  行内变「独开 1」；关回去状态清空。
