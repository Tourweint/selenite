# 方案：手机 IM 式首页与会话列表重构（2026-11-12 用户拍板）

> 状态：**设计定稿，分 V1~V3 串行实施**（每批验收 + 提交）。
> 拍板：IM 列表页当首页（二选一拍板）；模仿 QQ；"单个会话"要进 IM 列表；测试用模拟器 Pixel_6a；参考 cindy mobile。
> 契约影响：**零 shared 改动**——只消费既有端点（§2.14 群组、/agent/chats、/partners）。

## 一、现状（2026-11-12 核对）

- 进 app 直落 `ChatNavKey`（今日对话全屏，无 Tab 栏），列表在 ☰ 抽屉：顶部快捷行（当前对话/日记本）→
  执事分区（总管置顶 + 执事行，2026-11-10 批D）→ 历史对话按「今天 / 近 7 天 / 更早」时间桶（批M）→ 多端分区。
- 手机**无群组支持**：无 GroupsApi 客户端、无群会话屏（"手机端群聊 UI"原登记刻意没有，见 §五翻案）。
- 数据可得性：`RemoteChat{conversationId, firstText, lastAt, chatKind(chief/worker/partner)}`（lastAt 即 IM 排序键）；
  `PartnersApi` 已解析 `avatar`（data URL）；`PartnersScreen.PartnerAvatar`（data URL 解码 + 首字兜底）已有先例但埋在 feature/settings 未共享；
  服务端 `GET /api/v1/groups`（含成员投影）/ `GET /groups/:id/messages`（时间线）/ `POST /groups/:id/chat` SSE 契约现成（接口文档 §2.14）。

## 二、设计（模仿 QQ 的会话列表）

首页 = 会话列表页，自上而下：

| 分区 | 行内容 | 去向 |
|---|---|---|
| ① 总管（置顶） | 头像（avatar 或「总」首字）+ 档案名 + 副行（最近一句或「说吧，我在。」） | 总管对话（现有） |
| ② 群组（有群才渲染） | 群名 + 成员数 + 最近活跃 | 群会话屏（**V2 交付**；V1 数据未接整段不渲染——与执事区"空则不渲染"同口径，不出死链接） |
| ③ 执事 | 头像 + 名字 + 领域 + 忙闲 | 执事对话（现有 PartnerChatScreen） |
| ④ 最近对话 | **一行一条杂事会话**：首字头像 + firstText 摘要 + 相对时间 + 刚刚活跃绿点，按 `lastAt` 降序、**无时间桶** | 对应对话 |

**「单个会话」的 QQ 式处理**（用户点名的难点）：每条杂事会话就是列表里普通一行（同 QQ 临时会话/我的设备形态），
不再藏进时间桶——排序靠 `lastAt`，身份靠首字头像 + 摘要，不造"联系人"假象。

顶栏：左 ☰（抽屉保留）· 右 ＋（新开杂事对话）· 设置齿轮（U1 已对齐桌面）。
导航：进 app 落 `ConversationListNavKey`（**V3**）；对话页从列表行进入；返回栈行截至列表页。
**抽屉与首页共用**一份 `ConversationListContent`（分区 + 行渲染单实现）；抽屉顶部快捷行与多端分区保留。

## 三、分批（串行）

| 批 | 内容 | 验收 |
|---|---|---|
| V1 | 头像组件下沉共享（feature/settings → designsystem）；抽屉重构：去时间桶 → 最近对话区、总管/执事行补头像、排序与活跃点纯函数化；群组分区本批不出现（数据在 V2） | 构建 + 单测 + 模拟器 screencap |
| V2 | GroupsApi 客户端 + 群会话屏（回读 + 发送 + SSE + 说话者名）+ 抽屉/列表群组分区接活 | 同上 |
| V3 | 首页 IM 化：`ConversationListNavKey` + 导航重排 + 顶栏「＋」新对话 + 返回行为 | 同上 |
| 其后 | U3 设置分块（cindy 蓝本：header + 分组卡 + footer 说明）、U4 对话中间话折叠（对齐桌面批32） | 同上 |

模拟器验收口径：Pixel_6a 启动 → adb install → 导航到目标页 → `screencap` 看渲染。**若复现 ATD 黑屏**（渲染层黑、
截图黑），如实记录并退回"构建 + 单测 + 代码自检"验收，视觉留真机——不硬凑。

## 四、刻意没有（登记防补齐）

- 未读徽章 / 角标：无推送通道，不假装有"新消息"。
- 会话搜索、自定义置顶排序、群通知提醒：列表成型后看真实需要。
- 群会话屏不做编辑重发 / 思考档 / 产出文件卡（1:1 专属能力）；群屏数据源独立，不进 1:1 对话同步拉取管线。

## 五、翻案登记

- **"手机端群聊 UI"原登记刻意没有**（接口文档 §2.14 群组刻意没有表）——用户 2026-11-12 点名要群组分区，
  V2 交付时该条改注"已翻案（2026-11-12 用户拍板，方案见本文）"。

## 六、备选（当时想过，弃）

- 杂事会话折叠成一行入口 → 信息藏层，IM 感弱。
- 群组行点击提示"去电脑上聊" → 违背拍板意图。
- 进 app 直落最近一个会话 → QQ/微信都无此形态，列表才是 IM 的家。
