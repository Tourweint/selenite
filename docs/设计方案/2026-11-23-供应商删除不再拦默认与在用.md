# 供应商删除不再拦「默认」与「在用」

> 2026-11-23。用户口径：设置 → 模型里默认供应商删不掉，但"不需要这个默认的供应商了，没供应商也没关系"。
> **状态：已落地。** 下沉落点：
> - 契约 → `docs/基线文档/接口-端点3-模型任务与供应商.md` §2.10（DELETE 不变量表）；
> - 决策 → `docs/基线文档/系统架构.md` D41；
> - 落地记录 → `docs/变更记录/2026-11-23-供应商删除不再保护默认与在用（没供应商也能跑）.md`。
> **与长期文档冲突时以长期文档为准。**

## 一、为什么原来拦着

2026-11-04 批次五把供应商 CRUD 定为带不变量的形态（设计方案 §二.4 / 接口文档 §2.10）：

- 删除 `defaultSelection` 指向的供应商 → 400 `provider_is_default`（提示"先改 defaultSelection"）；
- 删除当前选中的供应商 → 400 `provider_in_use`（提示"先切走"）。

当时的意图是"别让选择悬空"。但同一批落地记录自己写了一条：
`providers.json` 的 `defaultSelection` **没有修改端点**（只能删/建后按第一个模型兜底）。
两条放在一起就是死结：默认供应商永远删不掉，而"先把默认切到别家"在界面上根本做不到
（只有删除当前默认之外的那家、或等 `defaultSelection` 恰好为空时才可能变）。

`provider_in_use` 同样挡路：`resolveSelection()` 的兜底顺序是
运行时选择 > `defaultSelection` > 第一家，所以"当前选中"在大多数时候就是默认那家——
即使只删 `provider_is_default`，删默认仍会撞上 `provider_in_use`。

## 二、决策

1. **DELETE 不设前置保护。** 默认供应商、当前选中的供应商、最后一家供应商都可以删。
   删除是用户明确动作，系统负责把后续状态落到确定的位置，而不是要求用户先绕一圈。
2. **删默认后默认顺延。** 若删的是 `defaultSelection.providerId` 指的那家：
   - 剩余供应商里第一家 `models[]` 非空的 → `{providerId, modelId: models[0]}`；
   - 一家都没有（或都还没模型）→ `defaultSelection: null`。
   与 `resolveSelection()` 的既有兜底（"第一个有模型的供应商"）一致，不引入第二套规则。
3. **零供应商是合法状态。** `providers: []` + `defaultSelection: null`：
   `readLlmConfig()` 返回 null，对话走 mock 回显（与"没配 LLM_API_KEY"同一条路），
   服务照常起、设置页显示空态。文件还在就不会按 env 重新播种——删掉的东西不会重启后自己长回来。
4. **清掉失效的运行时选择。** 删除时如果 `runtime.json` 里的 `model` 指向这家，一并写掉
   （保留 `thinking`）。否则是条死引用；更隐蔽的是同 id 重建后旧选择会"复活"。
5. **编辑不变量保留。** `selected_model_missing`（把当前/默认选中的模型移出 `models[]`）不动——
   那条不是死结：用户还能切到别家或直接删掉这家。

## 三、备选与取舍

| 备选 | 取舍 |
|---|---|
| 加一个「设默认供应商」端点，让用户先改默认再删 | 否决：为了保住一道不必要的闸新增契约面；用户要的是能删，不是多一步操作 |
| 删默认后置空，不自动顺延 | 否决：`resolveSelection` 反正会兜底到第一家，不落 `defaultSelection` 只会让徽章与有效选择不一致；顺延把"系统实际会用什么"写明白 |
| 保留 `provider_in_use`，只删 `provider_is_default` | 否决：多数时候当前选中 = 默认，等于没解除死结 |
| 删最后一家时拒绝 | 否决：与用户口径冲突；零供应商 = mock 是既有支持状态 |

## 四、明确不做

- 不做"多默认"或按项目 / 按场景的默认供应商。
- 不改 `defaultSelection` 的语义（仍是"新会话创建时读一次的全局默认"）。
- 不加重命名输入一类的删除确认仪式；确认弹窗只说清删掉后的结果。
- 不在删除时顺带清理旧会话里的模型引用：会话下一轮由 `ensureConversationModel()` 修复
  （供应商被删 → 回退全局默认；全局也没了 → 该轮不跑模型，/chat 在入口处走 mock）。

## 五、验证

- `provider.test.ts`：删默认 → 顺延；删最后一家 → `providers: []` / `defaultSelection: null` / `current: null`。
- `providers-probe.ts`：真 HTTP 删「当前选中」与「默认」；默认顺延到下一家；删到零后
  `/healthz` 降为 mock、对话走 mock 回显、重启仍是零供应商。
