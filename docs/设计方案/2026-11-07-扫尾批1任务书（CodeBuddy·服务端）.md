## 逐项

### 1. A1 取消/重试端点（方案 §一，照做）

- `delegations.sqlite` 新表 `delegation_cancellations(ticket_id TEXT PK, canceled_at TEXT, conversation_id INTEGER)`；store 范式照 delegation-receipts（原子写、幂等 upsert）。
- `POST /api/v1/tickets/:id/cancel`：终态 `done/failed/aborted` → 400 带说明；其余（含 needs_you / canceled）→ 记作废位回 200。新表挂在现有 delegations 库打开处，别新开库文件。
- `POST /api/v1/tickets/:id/retry`：仅 `failed/aborted/canceled`；从原单 chancellor 工作目录 `ticket.json` 读重派所需字段走 `startDelegation`，新 `requestId` 用 `retry:<原单id>:<重试次数>` 防撞幂等键；回执 accept 带原单 conversation_id（新单回写进同一条对话）。字段不够 → 400 如实报。**先读 delegation-api 现在怎么从工作目录读单据，复用同一套读取。**
- 取消生效四点（方案 §一）逐点实现：settle 跳过回写、emitProgress 停发、delegation-api 投影加 `canceled:true` + `status:"canceled"`（原值放 `originStatus`）、SSE 不再为该单发事件。
- 回滚开关 `DELEGATION_CANCEL=false`：两个端点都不挂（404）。
- 前端：`workRow` 行内 + 详情页动作区；非终态显示「取消」、`failed/aborted/canceled` 显示「重试」；取消带确认弹窗（说明"执行端可能继续跑完，但不再汇报、不写回对话"）；操作后本地置态 + 刷新列表。开关关时不渲染。
- 契约回写：接口文档任务中心节（§2.13 附近）补两个端点条目 + env 表 `DELEGATION_CANCEL`；系统架构派单相关段补一句作废位机制。

### 2. B1 手动压缩（方案 §二）

- `POST /api/v1/agent/chat/:conversationId/compact`（body `{instructions?}`，`?wait=1` 可选）：受理即回 `{ok:true,taskId}`；wait 时 `waitForTask` 上限 `AGENT_COMPACT_WAIT_MS`（默认 60000）。404/503 口径与 `/mode` 一致。env 进 §6 表。
- 前端 composer：提交内容 trim 后匹配 `/^\/compact\b/i` → 不发消息、调端点（把剩余文字作 instructions）、wait=1、结果气泡提示；其余 `/xxx` 原样发送。**不做命令系统**。
- 契约回写：接口文档 chat 相应节补条目。

### 3. A4 项目接口（方案 §三）

- `PATCH /api/v1/projects/:id`（改名）、`POST .../archive|unarchive`、`DELETE ...`（守卫：非终态在飞单 → 400；只删登记不动磁盘）。列表默认滤掉 archived，`?includeArchived=1` 带上。
- 前端项目页：归档折叠区 + 行内改名/归档/恢复/删除（删除确认弹窗文案明说"只删登记，不删磁盘目录"）。
- 契约回写：接口文档项目节补端点。

### 4. session 记忆保留（方案 §四）

- memory 包：store 加 `countByScope(scope)` 与 `pruneOldest(scope, keep, {protectKinds, protectReferenced})`——最旧优先（created_at），保护 `preference` 与被 `supersededBy` 引用的行；`global` scope 拒绝修剪（断言抛错）。
- server：记忆写入路径末尾按 `MEMORY_SESSION_CAP`（默认 200，0=关）修剪 session 与 `partner:` 前缀 scope；删除只记条数不记内容（D8）。env 进 §6 表。
- `pnpm memtest` 加用例：超限删旧、偏好不删、被引用不删、cap=0 不动、global 不动。
