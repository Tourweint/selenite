## 起因

用户口径（2026-11-12，桌面端 设置 → 项目）：

- 工作区根和项目目录应该是**平级**的，不是"主项目 / 子项目"的上下级；项目不要求落在工作区下面。
- 项目路径要能直接改，不能只能删了重加。
- 项目动作看不懂「归档」；希望统一成：目录叫「移除」，会话叫「归档」。
- 对照 ZCode：ZCode 的项目是一组 roots（其中一个是主要目录，其余是平级附加目录），
  所有 roots 都可读可写；项目没有「归档」，只有移除/恢复；归档是会话的概念。

## 旧口径（被本文替代）

2026-11-04 定调：**最大工作区 = 物理硬边界**，`write`/`edit` 的 realpath 必须落在唯一工作区根内；
项目必须建在工作区内；`完全访问`只是审批档，不能绕过路径守卫。
（旧方案：`docs/设计方案/2026-11-04-侧边栏工作区与当前项目.md`，不删，留"当时怎么想的"。）

本次不是推翻"物理边界"本身，而是把边界从**一个根**改成**一组用户显式登记的根**。

## 决策

1. **工作区根 = 默认目录（primary root）**：仍是新会话/杂事态的默认 cwd，也是首选的兜底目录；
   但它不再"包含"项目。
2. **项目 = 平级的附加根（additional roots）**：可以是任意绝对路径，不要求在工作区内；
   一个项目仍是一个磁盘目录（不是 ZCode 的"项目容器多 roots"——我们暂不做多目录项目）。
3. **边界 = 所有已登记且未移除的根之并集**：`write` / `edit` 落任一根内即放行；都不在才硬拒。
   审批档与边界解耦：`全不问`不会绕过边界；要访问新位置就把该目录加为项目。
4. **路径可改**：`PATCH /api/v1/projects/:id` 接受 `rootPath`，只改登记，不动磁盘；
   旧路径目录保留。新路径必须存在、可写、非盘符根/主目录/系统目录，且不与其他项目重叠。
5. **移除 / 恢复**：项目动作统一叫「移除」（软删除，`archived=1`），可恢复；
   界面不再提供「删除登记」按钮（`DELETE` 接口保留作程序化面）。
6. **会话叫归档**：会话列表的「从列表移除」改叫「归档」，设置页叫「已归档的会话」；
   仍是软操作，会话与记忆都在。
7. **文件浏览按根**：`GET /api/v1/files*` 增加可选 `projectId`；带它时 `path` 相对该项目根，
   缺省仍相对工作区根。项目在外部也能在界面里看文件。
8. **术语收敛**：设置页只留一节「项目」，工作区根与项目同一种行、同一字号；工作区行标「默认目录」。

## 备选与为什么不选

| 备选 | 为什么不选 |
|---|---|
| 保持单根，只改视图/文案 | 用户明确要求项目不必须在工作区下；纯改视图会把"加不进来的仓库"继续挡在外面。 |
| 完全访问档绕过路径守卫（"全开"=可写任意位置） | 把审批档和物理边界混成一层，误开一次就无边界；且现有守卫在审批之前，绕过它等于删掉硬边界。多根让"访问哪"仍然是一次显式登记。 |
| 做 ZCode 式"一个项目多 roots" | 我们的项目登记表目前一项目一根；先解决"根可以不在工作区下"，多根项目另立项。 |
| 项目移除时连带归档项目内所有会话 | 目前只有派活回执/任务单带 projectId，普通会话没有项目归属，做不到"项目内所有会话"；先保证不删任何记录，按会话归档仍是独立动作。 |

## 安全与回滚

- 根校验沿用工作区口径：绝对路径、存在、目录、可写；拒绝盘符根、用户主目录及其上级、系统目录；
  全部 realpath 后再入集合（含符号链接祖先逃逸识别）。
- 项目之间不允许重叠（同路径 / 在别的项目内 / 包含别的项目都拒绝），避免同一文件被多个项目租约/合并。
- 回滚开关：`PROJECT_OUTSIDE_WORKSPACE=false` 恢复旧口径——项目必须在工作区内，
  根集合也只在工作区内收项目；界面仍可输入外部路径，但服务端会明确拒绝。
- 不自动发现、不扫盘；只有用户显式登记/确认的目录才进边界。

## 明确不做

- 不做"项目容器 + 多目录"（ZCode 的多 roots 项目形态），一个项目仍对应一个目录。
- 不做项目内会话归属/项目树；普通会话仍不按项目分组。
- 不做"完全访问 = 任意路径可写"；边界只随登记根扩展。
- 不改审批策略、不改派单权限模型；本次只改目录范围与项目页交互。

## 契约变化（落地后已下沉）

- `POST /api/v1/projects`：`path` 支持绝对路径（必须已存在）；相对路径仍是"相对工作区根、可新建"。
- `PATCH /api/v1/projects/:id`：新增 `rootPath`（可与 `name` 同时给）。
- `POST /api/v1/projects/:id/remove` / `restore`：移除/恢复；旧 `/archive` `/unarchive` 保留为别名。
- `GET /api/v1/files*`：新增可选 query `projectId`。
- 环境变量：`PROJECT_OUTSIDE_WORKSPACE`（默认开；`false` 回滚到单根口径）。
