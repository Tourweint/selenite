# 立项：打手扩展——更多 CLI 适配（低优先级）

**状态**：立项待排期（2026-11-13 用户提出"可以先立项"，当次不实施）。
**优先级**：低。用户原话："这属于大工程，而且我自己不用。"
**冲突口径**：本文与 `接口文档.md` / `系统架构.md` 冲突时以后者为准。

## 背景

- 任务中心打手区目前写死四张卡：CodeBuddy / Qoder 国际 / Qoder 国内 / 手机
  （`ts/apps/server/web/app.js` 的 `TASK_HITTERS`；执行者枚举在 `EMPLOYEE_LABEL`）。
- 本机 CLI 手册（`<local-docs>\CLI工具更新\非交互模式调用说明.md`，2026-11-04 精简版）
  清点现存 **6 个** CLI：前三个走自家账号登录（有免费额度）= 现有打手；
  另外三个走本地 magpie 网关：
  | CLI | 非交互入口 | 依赖 |
  |---|---|---|
  | Claude Code | `claude -p` | magpie 网关（网关一停即废） |
  | Codex | `codex exec` | magpie 网关 |
  | OpenCode | `opencode run` | 开箱可用，仍走网关 |

## 动机（用户口径）

有些用户喜欢底层的东西、喜欢这些 CLI 工具；三个登录型 CLI 有免费额度，但额度因人而异，
不适合当默认卖点。做成"能插拔接入更多执行者"的能力，谁想要谁接。

## 目标（做的时候长什么样）

1. **打手适配层插拔化**：新增一个 CLI 执行者 = 一份适配器（spawn 命令 + 结果解析）+ 一条注册配置，
   不改 shared 契约、不改任务中心骨架。参照既有原则"接真服务只换适配层、不改契约"。
2. **任务中心打手区从写死变动态**：`TASK_HITTERS` 四卡改为"可用执行者"列表，
   没接的 CLI 不显示（不是灰卡占位）。
3. **网关健康可见**：走 magpie 的执行者要能显示"网关不在"这类状态，别让派单静默失败。

## 关键约束（做的时候必须过）

- 新执行者是"会写文件 / 起进程"的工具链路：过闸门（`WRITE_TOOLS` / `readOnlyBlockReason()`）。
- 回滚开关一行 env，例如 `EXTRA_HITTERS_ENABLED=false` 退回四卡。
- 密钥口径不变：CLI 各自的登录态是它们自己的事，harness 不存账号、不管 token。
- 打手工具描述属缓存前缀资产：动注册顺序要进 `变更记录/`。

## 明确不做

- **本轮不实施**（本立项只登记）。
- 不做登录态管理 / 账号体系 / 额度查询——那是各 CLI 自己的登录。
- 不承诺"免费额度"作为产品话术。
- 不为适配而适配：三个网关系 CLI 里 OpenCode 开箱可用最先接，Claude Code / Codex 看需要。

## 验证口径（做的时候）

`pnpm typecheck` + `pnpm --filter @lifediary/server http` + 手工各派一单真跑通；
打手区回归 `… providers` 探针不涉及，走 http 探针 + 浏览器实点。
