## 背景

第一轮（同日）把导入弹窗做成了"一行一个来源 + 每行一个导入按钮 + 从文件导入"。
用户看后的原话：

## 一、ChatGPT / Claude 为什么没适配（先把事实说清）

不是"漏做"，是**记忆不在本机**：

| 产品 | 记忆存哪 | 本机能读到吗 |
| --- | --- | --- |
| ChatGPT（网页 / 桌面） | OpenAI 账号服务端 | 不能。本机只有会话缓存/导出文件，没有记忆条目库 |
| Claude（网页 / 桌面） | Anthropic 账号服务端 | 不能。本机只有会话缓存/导出文件，没有记忆条目库 |
| Claude Code | `~/.claude/projects/<项目>/memory/*.md` | **能**，本轮接上（本机 4 条） |
| Codex CLI | `~/.codex/memories_1.sqlite` | **能读**，但本机 `stage1_outputs` 0 行，灰态 |

会话记录 ≠ 记忆：会话是"说过什么"，记忆是"关于你留下了什么"。把整段会话当记忆导入，
等于把临时上下文变成长久人格（上一版方案已明确不做会话蒸馏）。ChatGPT / Claude 的云端
记忆在**取消文件导入之后**就是取不到；按用户 2026-11-15 的明确要求，这两个来源已从清单
删除，不再占灰卡位置。Claude Code 的本地项目记忆不受影响。

## 三、解析口径（统一到 `memory-import-sources.ts`）

- 统一产出 `{text, kind, createdAt}`；kind 只落 `fact / preference / episode`，下游
  `importMemory` 再做长度上限、规范化去重、打码。
- `frontmatter`：剥壳后用正文；正文空则用 `description`；`metadata.type` / `type`
  `user/feedback/preference` → preference，`project/reference/fact/memory` → fact。
- `index`：`MEMORY.md` 是索引时，按 `- [标题](文件) — 摘要` 逐行收；**同目录有条目文件时
  索引不参与**（避免索引摘要 + 正文两份重复）。
- `headings`：按 `#/##/###` 分节，每节正文前加【小节标题】，保证脱离文件也自含。
- `section`：awareness 的 `§` 分隔。
- 文件 >2MB、0 字节、模板占位（OpenClaw 的 "Learn about the person..." 等）跳过。
- 单个文件读失败/单个来源目录不存在都只返回空，不让整批扫描报错。

### 3.1 逐条分类（2026-11-15 补）

**旧口径的问题**：kind 是文件级/来源级 fallback——整份 `MEMORY.md` 一个 kind，
`type: preference` 一压一整份，标题里的「完成情况 / 用户偏好」不参与判断。结果本机 193
条导入记录是 `事实 163 / 偏好 30 / 经历 0`，项目日志、用户偏好大量被压进事实，经历一条
都没有。

**现行口径**：`parseSourceFile` 对每个 section 调 `classifySourceKind(text, fallback, {file,
explicit})`，按这一条内容判，文件级 kind 只做兜底。优先级：

1. 显式 `metadata.type = episode`、或 `episodes/ session/ daily/` 类文件 → episode；
2. 标题含「任务 / 执行 / 完成 / 进度 / 每日 / 对话 / 记录」；正文含
   「完成了 / 修复了 / 已落地 / 已提交 / 处理了」、日期动作、`mermaid`、英文完成时 →
   episode；
3. 含「偏好 / 不喜欢 / 反对 / 希望 / 不希望 / 配色 / 沟通方式」，或
   「用户 + 要求 / 希望 / 不要」、`USER.md / feedback / preference` 文件 → preference；
4. 含「实现 / 规则 / 路径 / 配置 / 接口 / 代码」等技术事实，或没有偏好信号的普通正文 →
   fact；
5. 占位模板、空索引、只有一行标题的条目直接跳过。

同一条项目记忆里出现「用户不喜欢紫色」时，即使文件级 fallback 是 fact，也会落
preference；反过来「Android 按钮保持组件风格一致」里的「风格」不算用户偏好，仍落 fact。
这是有意的保守边界：宁可把设计约束留在事实，也不把技术文本刷成偏好。

**已有 193 条导入记录的回填**：只回填**明确可判**的条目（任务描述 / 执行过程 / mermaid /
【完成情况】/ 日期+已修复 / 短小的用户偏好陈述），不整库重刷，避免把长项目日志误判成偏好。
回填后 `import:%` 为 `偏好 31 / 事实 153 / 经历 9`（回填前 30 / 163 / 0）；新导入走完整
逐条分类器。


## 四、前端形态（A 版记忆页）

- 弹窗标题仍「导入记忆」，宽度 680px（`.modal-import`）。
- 正文是**小方框卡片网格**：每个来源一个 checkbox 卡片（名称 + 条数 + 一行说明）。
  - 有货（`count > 0`）：默认勾选，可取消；
  - **同一 Agent 的全局 / 项目来源合成一个可展开组**：组头显示总条数与
    `全局 x · 项目 y`，点击展开后是两张带「全局 / 项目」小标签的子卡；
    目前 Qoder CLI、Qoder IDE、CodeBuddy 三组有全局+项目双来源。
  - 只有一个来源的 Agent 仍是一张普通卡，不为了统一多套一层点击；
  - 云端（ChatGPT / Claude）已按用户要求删除，不再有「云端记忆」分组；
  - 其余 `count = 0`：折叠组"未检测到本地记忆（N）"，默认展开、灰卡。
- 底部 sticky 操作条：`已选 N 个来源 · 约 M 条` + 关闭 + **一键导入**。
  弹窗高度按视口约束（`max-height: calc(100dvh - 2rem)`），正文滚动，底条常驻可见；
  面板底部不留 padding，footer 贴住面板内底，避免按钮下半截被滚动边界裁掉。
- 头部「导入 / 整理记忆」统一 32px 高、12.5px 字、12px 横向内边距；
  只保留 ghost 与实心的主次差别。「整理记忆」不再带小问号，解释文案改由按钮 `data-tip`
  在悬停/聚焦时显示。
- 一键导入 = 按勾选顺序逐个 `POST /sources/:id`，每张卡就地显示"新增 X · 跳过 Y"；
  一个来源失败不挡后面的，最后 toast 汇总；完成后刷新当前记忆列表。
- **从文件导入整段删除**（选择器、JSON 解析、`POST /memory/import` 调用全删）。
  legacy 旧设置页保持原样（`MEMORY_PAGE_A=false` 才可见），不在本轮范围。
- 勾选/全选/全不选全在前端本地状态，不新增端点、不改响应形状。

## 五、契约增量

`GET /api/v1/agent/memory/import/sources` 响应形状不变：

```json
{ "ok": true, "sources": [{ "id": "…", "name": "…", "note": "…", "count": 12 }] }
```

- `count` = 该来源**可解析出的条目数**（不是文件数）；`0` = 没检测到 / 空库。
- 来源清单从 6 条扩到 **36 条**（25 个可解析 + 11 个灰态，ChatGPT / Claude 已删），
  顺序服务端固定；前端只按 `count` 分组，并按 id 的 `-projects` 后缀把同一 Agent 的
  全局/项目来源折进同一组。
- `POST /sources/:id` 行为不变：解析 → 项目匹配 → `importMemory`；响应
  `{ok, source, added, skipped, total}`。批量由前端循环，不在服务端加批处理端点。
- **跨 scope 去重（2026-11-15 新增）**：来源导入时把 `global` + 所有登记项目视为同一个
  "已有记忆池"，同一 `kind + 规范化正文` 已经在任一 scope 存在时直接计入 `skipped`；
  避免同一句话从全局和项目各落一份。手工 `POST /memory/import` 仍只查目标 scope，
  行为不变。

## 明确不做

1. **ChatGPT / Claude 云端记忆的在线拉取**：没有官方本地接口，需要账号导出。
   A 版已取消文件导入，两个来源条目已从清单删除；要接另立"导出文件适配器"。
2. **会话蒸馏**（Claude Code jsonl / Codex rollout / Trae session_memory）：
   上一版已明确不做，本轮仍不碰；Trae 只收用户画像。
3. **新增批量端点**：循环 POST 足够，少一个要维护的契约。
4. **图标 / 品牌色**：来源卡片只放名字与条数，不引第三方 logo 资产。
5. **legacy 旧页的文件导入**：`MEMORY_PAGE_A=false` 的回滚形态不动。

## 这条会怎么错

- **条数会漂**：`count` 是解析后的条目数，跟各家自己的"记忆条数"不一定一一对应；
  同一段内容可能在索引和正文里各出现一次（已用"有正文就不收索引"降重）。
- **灰态清单会过时**：各家目录名会变；本表是 2026-11-15 本机实测，路径改了要重盘。
- **项目笔记会进个人记忆**：WorkBuddy / 千帆的每日笔记偏项目事务，不是"关于你"，
  导入后可能显得杂；卡片说明已写明来源，用户可只勾个人画像类来源。
- **默认全选**：有货来源默认勾选，图的是"一键"；如果用户只想导一家，要先取消其余。
  这是交互取舍，不是数据策略（导入只增不改、重复跳过）。
