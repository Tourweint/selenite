# 整理建议证据引文退役（MEMORY_REVIEW_EVIDENCE）

状态：已落地（2026-11-17 当日）
下沉落点：契约 → `接口文档.md` §2.15.1（`evidence` 字段删除）+ §6（`MEMORY_REVIEW_EVIDENCE` 行删除）+ `接口-端点6-记忆课题与搜索.md` + 模块与机制 → `系统架构.md`；冲突以长期文档为准。

## 为什么退役

- 证据引文是 2026-11-10 对标 Anthropic「做梦」加的：整理建议的 drop 端正文回**原始会话记录**里逐字反查当初的原话，命中挂 `evidence` 上卡、可点回原对话；查不到显示「未找到原始出处（导入或日记来源的记录不在对话里）」。
- 2026-11-16 记忆原子化后前提塌了：原子条目是拆分 / 改写过的，正文与对话原话不再逐字对应（该检测靠归一化逐字匹配）；来源导入（`import:*`）的条目又已被藏起来。两条路都命中不了 → 引文条条 miss，那句「未找到原始出处」变成每张卡都有的噪声。
- 用户拍板（2026-11-17）：「找来源这件事不用做了，把这个提示删掉，不用检测了」；重复记忆直接靠整理建议收编、人工逐条应用，核对引文这个环节不再需要。

## 取舍

- **删的是整条检测链**，不是只删前端提示：留着后端扫描，每条建议仍要白扫 ≤200 会话 × ≤200 条（还经常全空跑一遍），纯成本无产出。只删提示不删检测 = 「未测量的不冒充已知」反着犯——留一个永远 miss 的机制装作还能用。
- **`MEMORY_REVIEW_EVIDENCE` 开关一并退役**（不留回滚开关）：这条是硬约束「新能力给回滚开关」的例外——回滚开关保护的是**新能力**，这里退役的正是能力本身；恢复它等于恢复整个功能（git 历史里有），不是改一行 env 的事。
- **共享函数保留**：memory 包的 `locateEvidence` / `normalizeForGrounding` 还有抽取侧引文校验（`groundedInUserText`）在用，不删；server 侧 `session-evidence.ts` 的 `searchTranscripts`（旧事页搜索）与 `listArchivedChats` 照旧，只退役 `findEvidence` 与 `EvidenceHit`。
- **明确不做**：不给「应用」流程补别的核对手段——整理建议卡上 keep/drop 两端正文本来就全文摆着，人直接看正文决定就够了。
