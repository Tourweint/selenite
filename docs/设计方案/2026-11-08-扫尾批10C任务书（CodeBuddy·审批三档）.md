## 语义（用户拍板的三档）

- **`ask-all`（全部问我）**：每个写/命令操作都确认（= 现 confirmWrites on 的行为）。
- **`ask-critical`（只问重要的）**：高危类问人，其余自动放行。**critical 清单**（env `AGENT_APPROVAL_CRITICAL_TOOLS` 可覆盖，缺省）：`bash`、`powershell`、`delegate`、`partner_manage`、`send_to_agent`（会起执行/烧 token 的都算）；文件 write/edit 等常规写自动放行。
- **`none`（全不问）**：完全放任（= 现 confirmWrites off）。
- 与 8c 无人值守形态**正交**：ask-all/ask-critical 触发的审批照旧走"等待态落库+答复续跑"。

## 逐项

1. **契约**：`agent/policy.ts` 的 `confirmWrites` 布尔升级为 `approvalLevel: "ask-all"|"ask-critical"|"none"`；**旧布尔兼容**（POST `confirmWrites:true/false` 映射 ask-all/none；GET 同时回 `confirmWrites`（派生）与 `approvalLevel`）；落盘 policy.json 存新字段、读旧字段兼容。接口文档 §2.18/§2.5 同步。
2. **闸门**：`needsApproval`/审批判定按三档——ask-all 照旧全问；ask-critical 只问清单内；none 放行。放行决策进单测（三档 × 各工具类矩阵）。
3. **前端**：设置页审批轴改**三档按钮**（单选），对话抽屉里的审批开关同步（两处同源 /policy）；文案：全部问我 / 只问重要的 / 全不问。
4. **探针**：三档 × {write, bash, delegate} 行为矩阵；旧 confirmWrites POST 兼容映射；critical 清单 env 覆盖；8c 六场景在 ask-all 下回归。
5. **文档**：接口文档/系统架构（D6 行补三档）/变更记录《2026-11-08-扫尾批10-C（审批三档）》。
