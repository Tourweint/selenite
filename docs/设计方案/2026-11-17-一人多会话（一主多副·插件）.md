# 一人多会话：一主 + 多副（插件化）

> **状态**：2026-11-17 用户拍板 C 版。本轮只落**批1（服务端 + 契约 + 开关 + 测试）**；
> 批2（电脑端 UI）与批3（从回答分叉）另派。落地后把契约下沉到 `docs/基线文档/接口文档.md`
> 与分册、机制下沉到 `系统架构.md`（新决策 D29）；**与长期文档冲突时以长期文档为准**。

## 结论

1. **每个执事 = 1 条主会话（canonical）+ N 条副会话（side）。** 主会话仍是
   `partner-<partnerId>`，副会话是 `partner-<partnerId>-side-<8位hex>`。
2. **总管不建链接**：它的"多会话"就是现成的多条 `chatKind=chief` 会话；
   选择器把最新一条当主对话，其余当副会话（只影响界面排序，不改身份）。
3. **副会话与人设共享**：SOUL、人格模块、岗位契约、纪律、当前目标、负责项目、
   工具取消/常驻名单、`partner:<id>` 记忆、挂载项目记忆。**不需要复制人设**。
4. **副会话不参与自动流程**：派活唤醒、定时主动轮、提醒到点执行、`send_to_agent`
   默认目标、人格活模块结算，全部仍落主会话。这是 C 版与全并行 A 版的分界线。
5. **插件开关 `PARTNER_SIDE_SESSIONS` 默认开、即时生效**；关掉 = 不列、不建，
   已存在的副会话仍可按 id 打开（不丢数据）。
6. **分支（会话分叉）复用这套底座**：从任一条回答开分支 = 在同一人设下新建一条
   side 会话并复制前缀，主线不动。批3 再做，技术口径沿用
   `docs/设计方案/2026-11-17-会话分叉（从某条回答另开一支）.md` 的复制一节。

## 为什么是 C，不是 A 或 B

| 形态 | 解决什么 | 代价 | 结论 |
|---|---|---|---|
| **A 全并行** | 多条会话完全对等、谁都能被叫醒 | 记忆、心情、唤醒、派活回灌四套规则全要重定 | **先不做**；C 跑顺后可升级 |
| **B 复制并接替** | 上下文聊爆了换一条主线 | 不解决"同时干两件事"；旧主线冻结 | 已有方案，不在本轮 |
| **C 一主多副** | 上下文隔离 + 同时多条 | 副会话不被叫醒、不涨人格 | **本轮做这个** |

C 的关键取舍：**主会话是"身份的代表"，副会话是"这个人的工作台"**。
所以三条自动流程不用改语义，只需保证它们继续只认 canonical——现有代码本来就是
这样，改动集中在"别把副会话误折回主会话"和"界面能选会话"。

## 数据模型

- `partner_session_links.role` 增加 `side`（现有 `canonical | routine | topic | delegation | group`）。
- 副会话的 `route_key` = 副会话外部 id（`partner-<id>-side-<token>`），
  直接复用现有 `UNIQUE(partner_id, role, route_key)`，**不改表结构、不加列**。
- 副会话外部 id：`partner-<partnerId>-side-<crypto.randomUUID().slice(0,8)>`
  （小写 hex，够短、可读、碰撞概率可忽略；重复就重生成一次）。
- 内部 id（durable 自增）照旧不外泄；对外一律 uuid 这条不变。
- `applied_version` 按 `(partner, session)` 记账，副会话也走同一套身份对齐。

## 接口（批1）

### 1. `GET /api/v1/partners/:id/sessions`

列某个人设的会话，供选择器用。

```json
{
  "ok": true,
  "partnerId": "diary",
  "kind": "partner",
  "sessions": [
    { "conversationId": "partner-diary", "role": "canonical",
      "title": "今天怎么样", "firstText": "今天怎么样", "lastAt": 1763..., "turns": 12, "pinned": false },
    { "conversationId": "partner-diary-side-1a2b3c4d", "role": "side",
      "title": "装修那摊事", "firstText": "装修那摊事", "lastAt": 1763..., "turns": 3, "pinned": false }
  ]
}
```

- 排序：canonical 永远第一，其余 `lastAt` 倒序；已归档的**不返回**。
- `id=chief`：返回所有非 `partner-` 前缀的 `chatKind=chief` 会话，
  `kind: "chief"`，每条的 `role` 也是 `"chief"`（不伪造 canonical），
  按 `lastAt` 倒序；界面把第一条当主对话。
- `PARTNER_SIDE_SESSIONS=false` → 400 `{ error: "side_sessions_disabled" }`。
- 执事不存在 → 404；暂停/归档 → 409 `partner_inactive`。

### 2. `POST /api/v1/partners/:id/sessions`

新建一条副会话，**不发问候、不写任何消息**。

- body 可选 `{ "title": "装修那摊事" }`（≤80 字，写进 `chat-meta.titles`）。
- 执事：建 `partner-<id>-side-<token>`，登记 `role='side'`，按当前身份装配
  `instructions`（SOUL + 人格模块 + 技能索引 + 运行边界），并把工作目录钉到主工作区
  （与 canonical 同口径）。
- 总管：建一条普通 `chatKind=chief` 会话，不登记任何链接。
- 返回 `{ ok: true, conversationId, role: "side" | "chief" }`。
- 开关关 → 400；执事暂停/归档 → 409。

### 3. `GET /api/v1/agent/chats` 增量字段

每条增加（**只增不改，老客户端忽略即可**）：

| 字段 | 值 |
|---|---|
| `partnerId` | 该会话归属的执事 id；无链接（总管/worker）不返回 |
| `sessionRole` | `canonical` / `side` / `group` / `routine`；无链接不返回 |
| `isCanonical` | 仅 canonical 为 `true` |

注意：群成员会话、fresh 例行专线本来就有链接，会开始带 `partnerId`；
前端的历史过滤逻辑不改也不会出问题（仍按 `partner-` 前缀过滤）。

### 4. `POST /api/v1/agent/chat` 续话语义

`kind === "partner"` 时按链接角色分流：

| 链接角色 | 行为 |
|---|---|
| `canonical` | 保持现状：对齐到该执事 canonical（等价于同一条） |
| `side` | **不再折回 canonical**；开关开 → 对齐这条副会话并继续；开关关 → 409 `side_session_disabled` |
| `group` / `routine` | 保持现状（折回 canonical），本轮不动 |
| 无链接 | 保持现状（chief / worker） |

副会话每次续话都要跑一遍身份对齐（`applied_version` + 人格签名），
否则改 SOUL / 口吻后副会话永远停在旧提示词。

## 路由规则表（谁落哪）

| 流程 | 落点 | 是否改动 |
|---|---|---|
| 派活完成唤醒 | 主会话 | 不改（`canonicalPartnerIdOfSession` 只认 canonical；副会话派的活**不唤醒**） |
| 定时主动轮 / 提醒到点执行 | 主会话 | 不改（`runPartnerTurn(persistent)` 天然 canonical） |
| 例行任务（persistent） | 主会话 | 不改 |
| 例行任务（fresh） | 每次新专线 | 不改 |
| `send_to_agent` | 目标执事主会话 | 不改 |
| 挂念提醒 / 自主轮 | 主会话 | 不改 |
| 人格活模块（印象/心情/学习） | 只结算主会话 | 不改（副会话不涨人格，C 版刻意） |
| 显式 `remember` | `partner:<id>` | 不改（副会话共享） |
| 自动抽取的事实 | `session:<副会话 id>` | 不改（副会话之间不共享） |
| 偏好抽取 | `partner:<id>` | 不改（共享） |
| 项目记忆 | 跟人走 | 不改（全部会话共享） |
| 在办扫描 | `sessionIdsOf(partner)` | 已覆盖副会话，不改 |

## 明确不做（v1，登记防补齐）

- **副会话不被叫醒**：不接派活唤醒、不接定时主动轮、不接 `send_to_agent` 默认目标。
- **副会话不涨人格**：印象、心情、表达习惯、学习只由主会话结算。
- **不提供会话级人设 / 会话级项目挂载 / 会话级工具名单**：人设永远一份（D23 不变）。
- **不做副会话永久删除**：只能归档；永久删除仍只对普通 worker 会话开放。
- **不改 canonical 唯一性**：`UNIQUE(partner_id, role, route_key)` 不动，主会话永远一条。
- **不做全并行 A**：等 C 跑顺再立项。
- **手机端本轮不做选择器**：副会话会出现在手机"最近对话"里（按普通会话可续聊），
  但没有执事顶栏与身份标识；手机端分组另立项。

## 回滚

- `PARTNER_SIDE_SESSIONS=false`（插件页可关；env 同名变量兜底）：
  - 选择器端点 400，新建入口消失；
  - 已有副会话**历史仍可读**（按 id 打开），但不能继续发消息（`/agent/chat` 409）；
    不做"关开关 = 数据消失"；
  - 三条自动流程完全不受影响（本来就不碰副会话）。

## 风险与对策

- **列表 N+1**：`GET /agent/chats` 每条都查链接表会多 50 次查询。批1 用一次
  `sessionLinksMap()` 快照（`SELECT partner_id, role, session_id FROM partner_session_links WHERE session_id > 0`）。
- **前缀解析**：`partnerId` 本身可能含 `-`，禁止用 `split("-")` 猜。新增
  `parsePartnerExternalId()`：先匹配 `-side-<8hex>`，再匹配 `-group-`，最后整段当 canonical；
  任务侧栏与前端都走它（前端批2 镜像一份）。
- **误放行**：`chatKind=partner` 包含 group/routine，分流必须看链接 `role`，不能只看 kind。
- **并发建会话**：外部 id 随机生成 + `INSERT OR IGNORE`；理论上撞了就重生成一次。
- **老会话无链接**：保持现状回落 chief，不回溯、不猜。
