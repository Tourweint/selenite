> 病根（两轮核实）：2026-11-04《验收以文件变更为准》后，规划器仍给手机任务声明 writes → 没挂 project：scheduler 清 writes 不拍快照、review 拿原始 writes 判 → blocked→needs_you（review.ts:118-126）；挂了 project：快照拍了但手机不写项目文件 → 0 变更 fail（review.ts:134-143）。

## 结论

**手机任务整体改走"汇报验收"**：规划器对手机雇员**确定性强制 writes=[]**（不靠提示词祈祷）；review 的文件对比分支对手机雇员整体跳过（含无快照与 0 变更两条路），降级为既有 LLM 验收（读 REPORT/result.md 定夺 pass/fail/blocked）并记 warning；**goal 目标核对（第三道闸门，前稿漏了）对手机单把 result.md 全文带入材料、以汇报为准**，无法从汇报判断 → inconclusive → needs_you（不是 failed）。硬底线不动：REPORT.md 缺失仍 fail、验收模型 blocked 仍 needs_you、验收模型三次失败 fail-closed。

## 为什么（含诚实声明）

用户明确接受"汇报即证据"：手机任务是生活任务（开个开关、查个东西），文件级验证天然不可能，人自己会在桌面看结果。**代价如实登记为已知残余风险：对手机任务不存在独立产物——result.md 就是 worker 的 summary（phone.ts:150-162），"产物 > 自述"对手机单是空转，验收模型可能把自吹自擂当真。** 缓解：验收提示词对手机加一条专规——"没有独立产物不构成 fail；但汇报与用户原话/done_when 缺少可核对的对应事实时，判 blocked（报人），不要静默 fail"；env 回滚开关留退路。

## 改动

1. **确定性根修**：`planTicket` 拿到 parsePlan 结果后（plan.ts:160-168），对 `employee === "phone"` 的任务**强制 `writes=[]`**；`phone.ts:42-48` 注记同步补"交付物在任务目录，writes 恒空"。新单两条误杀路就此消失。
2. **review 防御（兜续跑/老单）**：`review.ts` 文件对比分支（:104-149）对 `run.employee === "phone"` 整体跳过 → 落 `reviewWithLlm`（:294-366）+ `Review.warnings` 记"按汇报验收"（artifacts→warning 先例 :251-264）；0 变更 fail（:134-143）对手机单不适用。**回滚开关**：env `REVIEW_TRUST_REPORT`（默认 true，config.ts 照 CHANCELLOR_* 惯例）——false 时手机单恢复"无快照 blocked / 0 变更 fail"旧行为；只控此一处，不回滚第 1 条的 writes 置空。
3. **goal 闸门**：goal 核对材料（goal.ts:97-145）对手机单**追加 result.md 全文**（截断照既有摘录口径）；判定口径：汇报明确未达成 → failed；汇报说完成但**无从核对**（材料与目标完全对不上）→ inconclusive → needs_you（stage.ts:112 既有映射）；其余按汇报定。
4. **warnings 可见性**：`Review.warnings` 落 review.json，`/api/v1/tickets/:id` 已返回 reviews——桌面任务详情天然可查，不另开契约（本批不加 UI）。
5. **文档（按 chancellor 模板重排：结论/为什么/改动/验收标准/这条会怎么错）**：`chancellor/docs/设计方案/2026-11-04-验收按雇员口径与降级.md`；实施后变更记录（贴真实命令与输出，其 AGENTS.md:82）；下沉 `docs/基线文档/系统架构.md` §手机雇员约定（:184-206"验收仍然只认任务目录"更新为"按雇员口径：手机走汇报验收，本地走文件变更"）。

## 验收标准

1. chancellor `pnpm typecheck` + harness `pnpm typecheck` + 全量单测。
2. **确定性用例**（不靠真模型）：假 `CHANCELLOR_QODER_BIN` 返回固定 verdict（或抽纯函数）断言：手机单 plan.json `writes==[]`；无快照手机单 review.json 含"按汇报验收" warning 且 verdict 来自 LLM 验收；挂 project + 手机不写文件（0 变更）同样降级；`REVIEW_TRUST_REPORT=false` 恢复 blocked；REPORT.md 缺失仍 fail。
3. **红灯证据与新信号**：实施前贴 `pnpm --filter @lifediary/server phone` 真实输出（`[done]` needs_you，2026-11-04 已复现）；实施后同探针 **done 翻绿 = 本批核心验收**。
4. 回归：`tasks` 黄金 12 例（提示词改动后实跑记录是否漂移；漂移=note 泄漏到非 phone 分支，要修）、`delegate-chain`、`http`、`probe`、`providers`。真机不做，如实记录。

## 这条会怎么错

- 验收模型信了自吹自擂 → 用户桌面看结果兜底；真发生误判 → `REVIEW_TRUST_REPORT=false` 一行回退（手机单恢复报人）。
- 提示词改动泄漏到非 phone 分支 → 黄金 12 例漂移会当场暴露。
- 父单闸门 `enforceChildClosure`（stage.ts:135-178）依赖子单无 blocked——子单经汇报验收 done 后父单正常收口；子单被验收模型判 blocked 照旧报人，语义不变。
- 已知相邻边界（非本批引入，登记）：`enforceChildClosure` 把 idle 当终态，超时子单不拦父单 done。
