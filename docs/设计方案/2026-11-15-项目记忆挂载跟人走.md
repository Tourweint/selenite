## 1. 问题

2026-11-15 上午的项目记忆方案（`2026-11-15-项目记忆与外部导入区.md`）把"会话归属项目"做成了
**建会话那一瞬间的隐式快照**（`session-open.ts` 读全局"当前项目"），带来三个麻烦：

1. **不可感知**：界面上"选中项目"只说"下一个新对话落在这个项目里"，没提记忆也跟着挂；
2. **不可改**：挂上之后没有任何入口能摘 / 换；
3. **一个开关背两件事**："当前项目"同时决定新会话的干活目录（cwd 快照）与记忆归属，
   聊杂事的会话只要之前选过项目就带着那个项目的记忆。

## 2. 拍板（2026-11-15，用户）

- **挂载跟着"身份"走，不跟着"会话"走。** 身份是长期的，挂一次管名下所有对话；
  会话不再需要做"挂不挂"的选择。
- **打手 / 干活会话**："打手就是在这个文件夹工作的"——保持现状（文件夹挂载）。
- **总管 / 执事（人格层）**：在**人设二级页**给这个人格选"负责哪个项目的记忆"。
- **普通杂事会话**：不挂。

## 3. 模型：三种身份，三种挂法

| 谁 | 挂不挂 | 挂载来源 |
|---|---|---|
| 打手 / worker 会话 | 照常挂 | `ChatProjects` 绑定（建会话时的当前项目快照 / 编辑分叉继承）——**现状不动** |
| 总管 / 执事（人格） | **默认不挂，人选** | 档案上的 `projectId`（人设二级页选），对该人格的**全部对话**生效 |
| 普通杂事会话 | 不挂 | 无身份无文件夹，天然不挂（worker 类不继承总管的挂载） |

挂载的效果 = 该项目键空间**并进**召回候选（`recallContext` 的 scopes 与 `recall` 工具），
并在 `remember scope=project` 时成为写入目标。执事自己的 `partner:<id>` 键空间**照旧**——
挂项目只是"额外多想起一摊"，私人记忆不受影响。

## 4. 契约（纯增量）

`PartnerProfileSchema` 加一个字段（先例：`tagline` / `diary` / `dispatchAuthority`）：

```ts
projectId: z.string().uuid().nullable().optional(),
```

- 语义：uuid = 负责的已登记项目（projects.sqlite 的项目 uuid）；`null` = 不挂。
- `GET /api/v1/partners/:id`（列表与详情投影）与 `PATCH` 均带；
  **`PARTNER_PROJECT_MEMORY=false` 时投影整个字段不出现**——前端按 `"projectId" in partner`
  判定显隐（同 `contractOn = "contract" in detail` 惯例），旧客户端忽略未知字段零改动。

## 5. 机制

### 5.1 挂载解析（`agent/project-scope.ts`，保持零依赖）

```
personaProjectScopeOfConversation(conversationId):
  1. 会话链接到执事（partnerIdOfSession）→ 该执事档案的 projectId
  2. 未链接且 kind=chief（总管主对话）→ 总管档案的 projectId
  3. kind=worker → null（干活会话跟文件夹走，不吃总管的挂载）
```

- kind 判定与现有 `chatKindOfInternal` 同语义：链接表先行（sync、live），
  否则看 `ChatKinds`——**不是显式 worker 就算 chief**（缺缓存时同口径，30 秒自愈，
  与现有项目 scope 缓存的降级口径一致）。
- `ChatKinds` 快照源由 lifecycle-harness 注入（`setChatKindsSource`），本模块照旧
  不 import lifecycle / assist（环与测试加载面的坑见该文件头注释）。
- `partners.ts` / `partner-contract.ts` 的传递加载与 `tools.ts` 既有加载面重合，
  不加重 partner-work 测试的临时目录握持。

### 5.2 写入解析（`remember scope=project`）

文件夹绑定优先，人格挂载兜底：`projectIdOfConversation() ?? personaProjectScopeOfConversation()`。
两路都空才报错，报错话术改成引导（"总管 / 执事可以在人设页选负责的项目"）。

### 5.3 存取（`partners.sqlite`）

`partners` 表加 `project_id TEXT` 列（CREATE TABLE + 旧库 `ALTER TABLE` 补列，惯例同
`tagline` / `diary`）；`setProjectId(id, projectId)` 一条 UPDATE，**不版本化**
（不是身份，同 `currentGoal` / `tagline` 口径）。

`PATCH /api/v1/partners/:id`：省略 = 不改；`null` = 清除；字符串 = 设置，
必须命中已登记项目（`listProjects(true)`，含归档——记忆还在，只是项目不再活跃），
不存在的 uuid 业务 400。校验在写前拦（防半写，同本端点既有惯例）。

## 6. UI（人设二级页）

`web/partner-profile.js`「岗位」段、「当前目标」之后加一块**负责项目**：

- `<select>`：不挂（默认）+ 项目列表（`GET /api/v1/projects`，未归档；
  当前挂的是归档项目时把那一项补进下拉并标注）；
- 保存 = `PATCH { projectId: 值 || null }`，独立提交（不与 SOUL / 目标混批）；
- `PARTNER_PROJECT_MEMORY=false` 时整块不渲染（`"projectId" in partner` 判定）。

## 7. 明确不做

- **会话级手动挂载**（侧栏 / 会话设置里选"这个会话属于哪个项目"）——挂载跟人走后不再需要；
- **+ 号旁边加项目选项**——每次新建都逼人做决定，最重；
- **Agent 自动判断该挂哪个项目 / Agent 挂载工具**——猜错比不猜更糟；真觉得手动烦了二期再说；
- **整理（consolidate）碰项目 scope**——`validTargetScope` 仍只收 global / partner:<id>，项目二期；
- **手机端显示"负责项目"**——契约纯增量，手机忽略未知字段，展示二期；
- **记忆页项目分组展示**——先核对现有记忆页（按人看）够不够用，有缺口另批。

## 8. 回滚与迁移

- 回滚：`PARTNER_PROJECT_MEMORY=false` → 投影不出字段、召回不并、remember 不认、页面整块隐藏，
  退回"只有文件夹挂载"的上午形态。
- 迁移：**存量 `ChatProjects` 绑定一律不动**（已挂项目的旧会话不丢记忆），
  只是人格挂载成为新的一层；两层并存、互不干扰。
- `openChat` 的现状隐式挂载**本方案不动**（那是文件夹挂载，跟"打手在哪个文件夹干活"同源）；
  它的感知性问题若后续还想治，单独立批。
