## 1. 问题

现在界面上只有两个口子能看上下文：

- composer 的「上下文容量」卡：只给 `已用 / 窗口` 和按字符占比的六段构成，**看不到任何原文**；
- `GET .../injections` 审计：只回 `{id, source, scope, channel, length}`，**刻意不回正文**。

结果是：用户知道自己每轮带着人设、工具、技能、记忆，但不知道它们**具体长什么样、占多少、哪一段是变的**。想学、想调，只能去翻代码。

## 2. 拍板（2026-11-16，用户）

1. 设置里**新开一个分区**，名字就叫「上下文」。
2. 只做**每轮固定进入**的那部分：系统提示词、工具定义、技能、记忆。
3. **不学 magpie 留最近十条**：不做请求历史、不做时间线。
4. 会变的部分**另分一块**，只提示"这里会变"，不展开正文。

## 3. 页面模型

一页 = 一个会话的**当前装配**（下一次请求会带上的那段开头），不是一串历史快照。

| 块 | 看什么 | 数据源 | 变不变 |
|---|---|---|---|
| 系统提示词 | `persona / verification_iron_law / clarify_contract / injection_guard / current_project / topics` 各段原文 + 字符数 | `conversation.context()` 重放后的当前 system message | 结构固定；`current_project` / `topics` 内容会变，挂「每轮现算」标 |
| 工具定义 | 每个工具的名字、说明、JSON Schema + 字符数 | 同上，当前 `toolsAdded` | 会话内固定（换权限 / 换模型才变） |
| 技能 | 技能索引原文、条数、字符数 | 系统段里的 `skills` | 按会话冻结 |
| 记忆 | 上一轮第一次请求实际注入的 `memory_recall` 原文、条数、字符数；预算 `limit / maxChars` | 进程内记录（见 §4.2） | 按本轮消息召回，挂「会变」标 |
| 会变的部分 | 对话消息 / 工具调用 / 工具结果各几条、几字；其它临时注入 id + 字数 | `conversation.context()` 计数 + 注入记录 | 只报数量，不展开正文 |

页面顶部一条按四块字符占比的分段条（复用现有 `--ctx-seg-*` 单色阶，不新造语义色），旁边给上一轮真实 `used / window` token。每段可展开读原文。

## 4. 机制

### 4.1 固定部分：读当前装配，不重新渲染

新增 `ts/apps/server/src/context-inspect.ts`：

- 用 `@earendil-works/pi-ai` 的 `getCurrentSystemMessage(view.messages)` 重放所有 system 消息（`content` 追加、`sections` 按名覆盖、tools 增删），拿到**当前真正会发出去**的 system prompt 与工具集，避免自己再跑一遍 provider（会重渲染、会碰副作用）。
- 把 `skills` 段从系统提示词里单拎出来作为「技能」块；其余 section 按 `LIFECYCLE_SECTIONS` 顺序给中文名与稳定性标签。
- 字符口径与 `contextBreakdownOf` 一致：正文按 `String.length`，工具按 `JSON.stringify(tool)`，空段不计。
- 会变部分只统计：user/assistant 文本条数与字符、assistant `toolCall` 次数与参数字符、`toolResult` 条数与字符。**不收正文**。

### 4.2 记忆：记首轮实文，不在读端点重跑召回

记忆注入是 `beforeRequest` 里的临时 system 消息，不在 `conversation.context()` 里；而 `buildContext()` 会回写 `lastRecalledAt / usageCount`，读端点不能为了预览去跑它。

做法：

- `lifecycle-harness.ts` 的 `beforeRequest` 在**一轮的第一次模型请求**（`used === 1`）把 `collectInjections(LIFECYCLE_MESSAGE_PROVIDERS, …).message` 的 `{id, text}` 记进 `context-inspect.ts` 的进程内表；
- 每个会话只留**最新一轮**，最多 64 个会话（LRU），不落盘、不进日志；
- 读端点只读这份记录，**不重新召回**，所以不会改任何记忆的强化计数；
- 进程重启后记录为空：页面如实说「当前进程还没跑过这一轮」，不拿旧数据冒充。

### 4.3 端点（契约）

`GET /api/v1/agent/chat/:conversationId/context-inspect`

- 鉴权同其它 `/api/v1/*`；响应 `cache-control: no-store`。
- 未知会话 → `404 {"error":"unknown_conversation"}`；未启用 → `404 {"error":"not_found"}`。
- 响应（字段细节以代码为准，文档回写 §2.2.4）：

```json
{
  "conversationId": "uuid",
  "title": "会话标题",
  "chatKind": "chief",
  "usage": { "used": 48321, "window": 128000 },
  "system": {
    "content": "",
    "chars": 6210,
    "sections": [
      { "key": "persona", "label": "人设", "stability": "fixed", "chars": 4120, "text": "…" }
    ]
  },
  "tools": {
    "count": 24,
    "chars": 13820,
    "items": [
      { "name": "bash", "description": "…", "chars": 980, "schema": "{…}" }
    ]
  },
  "skills": { "count": 19, "chars": 3889, "text": "…" },
  "memory": {
    "enabled": true,
    "limit": 16,
    "maxChars": 2000,
    "last": {
      "at": 1763..., "items": 3, "chars": 486, "text": "…",
      "others": [{ "id": "project_index", "chars": 90 }]
    }
  },
  "changing": {
    "messages": { "count": 12, "chars": 9830 },
    "toolCalls": { "count": 4, "chars": 312 },
    "toolResults": { "count": 4, "chars": 1204 }
  },
  "updatedAt": 1763...
}
```

- `memory.last = null` = 这个进程里还没有该会话的首轮记录；`text = ""` = 记过，但那一轮没召回。
- `system.content` 是 system message 的基础正文（通常空）；单独展示为「系统底稿」。
- `sections` 不含 `skills`；`stability` 只取 `fixed | session | turn`，前端据此挂徽标。

### 4.4 前端

- 新分区 `context`，位于「会话」之后（上下文是会话级的东西）。
- 顶级一行会话选择 + 刷新；选择来自 `state.chats`，默认当前会话。
- 四个块各自一张卡片，段/工具行可点开读原文；工具块带名称/说明过滤与「展开全部」。
- 技能、记忆卡片右上角给「管理技能 / 管理记忆」按钮，走 `go("settings", …)`；系统提示词卡片给「改人设」入口。**不在本页做在线编辑。**
- 会变块用更轻的排版，只列数字 + 一句说明。
- 无会话 / 端点 404 / 请求失败各有明确一句话，不留白屏。

## 5. 明确不做

- **不做最近 N 条请求历史**：不存快照、不做时间线、不做回放；只在进程内留最新一轮的注入实文。
- **不做在线编辑**：提示词、工具定义是缓存前缀资产，改它们要改代码；人设 / 技能 / 记忆走现有设置页。
- **不展示会变正文**：对话消息、工具结果只报条数与字符，避免把整段历史复制到设置页。
- **不重跑记忆召回**：读端点无副作用是硬约束，宁可显示"这一轮没记录"。
- **不估 token**：字符口径沿用现有容量卡；顶部 `used / window` 用真实 usage，不拿字符数换算。
- **不做手机端页面**：本页只在 Web 设置里；端点仍是服务端契约，手机以后要消费再加。

## 10. 续加：默认开销（2026-11-16 同日，用户）

### 10.1 用户口径

原会话版完成后，用户明确补了一句：**“我默认的开销也算”**，并且要能看**不同人的不同开销**——
“就属于一个默认开销。我没有上下文，不聊天也能知道的那种。”用户接受“做不出来就算了，就这样也可以”，
所以这是一个**可尝试项**，不是把会话版推翻重做。

因此 §3 的“一页 = 一个会话的当前装配”扩成两档：

| 模式 | 回答的问题 | 依赖聊天记录？ |
|---|---|---|
| 当前会话 | 这一轮真正进入的固定前缀是什么 | 是，读 `conversation.context()` |
| 默认开销 | 不聊天、不开会话时，某个角色默认要花多少 | **否**，按角色现装配 |

没有普通会话时自动进「默认开销」，有会话时默认「当前会话」；顶部两个模式按钮可随时切。
（实现上“只有 `state.chats` 为空、选择器里只剩兜底的‘当前会话’也算没有普通会话”，会直接进默认。）

### 10.2 默认基线的边界

“默认”只算**每轮都会带的固定/半固定前缀**：

- 总管：人设、验证铁律、开工前问清、注入防线、当前项目、课题、技能；
- 普通 worker：worker 人设、验证铁律、注入防线、当前项目、技能；
- 执事：执事身份（SOUL + 静态人格 + 主人画像 + 执事技能索引 + 运行边界）、岗位契约四节（职责范围 / 决策分级 / 验收标准 / 汇报对象，逐节成行，空节保留 0 字槽位）、当前目标、执事纪律、注入防线、当前项目、技能。

**不算**：当前在办、工作履历、印象 / 心情 / 心里话（这些要扫任务中心 / 记忆，属于会话期动态）；
**只报预算**：记忆 `limit / maxChars`，不伪造召回正文；**不报 token**：`usage=null`，字符口径与容量卡一致。

### 10.2a 字段粒度与可编辑边界（2026-11-16 追加）

默认页不再把 `buildPartnerTurnContext(...).text` 填成一个 `partner_context` 大块。原因：这个 `text`
是「岗位契约 + 当前目标 + 纪律 + 表达习惯 / 主动性」的 provider 拼接文本，可编辑的契约和纪律
混在同一张卡里，看起来像整块都不能改。

| 展示字段 | 来源 | 可编辑 | 说明 |
|---|---|---|---|
| 系统底稿 | `system.content` | 否 | system message 的基础正文；空也保留 0 字槽位 |
| `partner_contract_scope` / `_decision` / `_acceptance` / `_report` | `CONTRACT.md` 四个固定二级标题 | 是 | 按 `splitContractSections()` 拆开，不改写正文；空节保留为 0 字槽位 |
| `partner_goal` | `partner.currentGoal` | 是 | 档案页可改 |
| `partner_verification` / `partner_ruling` / `partner_work_silence` / `partner_grounding` / `partner_artifact_handoff` / `partner_brief_card` / `partner_attention` | 宿主默认纪律 + 每执事 `DISCIPLINE.md` 覆盖，逐节成行 | 是 | 每节独立字段；删空 = 这一节不注入；没写的节仍用宿主默认 |
| `partner_owner_data` | 宿主固定红线 | **否** | 单独一行只读，不参与 `DISCIPLINE.md` 覆盖 |
| `partner_learning` / `partner_proactivity` | 表达习惯 / 主动性 provider | 否（档案页管模块） | **空也保留 0 字槽位**，不再因为内容为空或很短而隐藏 |
| `partner_soul` | SOUL 正文 | **否**（档案页改） | 单独成行，空也保留 0 字槽位 |
| `partner_voice` / `partner_values` / `partner_scenario` | 静态人格三块：口吻 / 里子 / 处境 | 否（档案页模块开关与内容） | 从身份大块里拆出；**口吻字段名「说话方式（口吻）」**；空模块也保留 0 字槽位 |
| `partner_owner_profile` | `memories/USER.md` | 否 | 主人画像，空也保留 0 字槽位 |
| `partner_skill_index` | 执事自己的技能索引 | 否 | 空也保留 0 字槽位；与独立 `skills` 块用途不同 |
| `partner_boundary` | 运行边界 | 否 | 固定宿主文本 |

- 可编辑入口：默认页每节字段下方「改这一节」直接打开这一节的编辑弹层；保存只改当前标题，
  其他已有覆盖保持原样；「恢复这一节默认」从 `DISCIPLINE.md` 移除当前标题。
  系统卡底部仍保留「去档案页逐节改」→ `#/settings/partners/<partnerId>`；档案页的「岗位」卡点开是契约 / 目标编辑弹层，
  保存走 `PUT /api/v1/partners/:id/contract`（下一轮生效）；「每轮固定注入 → 纪律」卡点开是**七节逐节编辑弹层**，
  每节独立 textarea +「保存这一节」/「恢复这一节默认」，整段覆盖走 `GET/PUT/DELETE /api/v1/partners/:id/discipline`。
- 空字段 / 不适用字段：默认页对所有角色使用同一份 28 字段清单（页面加系统底稿 = 29 字段）；
  `ContextSectionView.empty=true` + `chars=0` 保留一行，当前角色不适用的字段也这样显示（例如总管页的「说话方式」）。
  这一页不再写“真实请求不会带空标题进来”一类解释文案；徽标与 `0 字` 已表达槽位为空。
  `system.chars` 只加真实字符，空槽位加 0。纪律某节被删空后仍保留这个 0 字槽位，
  人还能点「改这一节」把它加回来或恢复默认；表达习惯 / 主动性也始终留槽位。
- **按真实字段，不硬切任意文本**：`PartnerTurnContext.disciplineFields` 已按固定块拆开；
  `context-defaults` 每节写一个独立 section key，`context-inspect` 给每节独立 label 和 `editable`；
  红线段单独为 `partner_owner_data`，不标可编辑。

技能默认走 `previewIndex`，按当前目录 + 该人可见性渲染，**不写会话冻结表**；真实会话首轮仍按 `indexFor` 冻结。
工具取真实 extension（`CodingTools.tools` + `lifediaryExt.tools`），过滤 `deferred`、按名去重，不手抄清单。

`GET /api/v1/agent/context-defaults?role=chief|worker|partner:<id>`

### 10.6 纪律覆盖：宿主默认 + 人写覆盖（2026-11-16 追加）

旧员工化文档把纪律设计成**宿主固定**：`员工模板-我的执事.md` 写“系统已经管死的，不用填”，
`员工人格模块` 把“主人数据红线”列为必选核心，`接口-端点4` 也确认必选核心不进开关。
用户不接受这个结论：**遇到明显不满意的系统内容，不能改就没有出路**。

这里把“宿主常量”改成“宿主默认 + 每执事人工覆盖”，只把安全边界留下：

| 纪律标题 | 可覆盖 | 说明 |
|---|---|---|
| `## 验证铁律` | 是 | 可整节改写；删空 = 这一条不注入 |
| `## 裁决纪律` | 是 | 四停规则可改写 |
| `## 干活期间` | 是 | 安静规则可改写 |
| `## 答案接地` | 是 | 原话 / 日期 / 不编造可改写 |
| `## 产物交接` | 是 | 落盘交接可改写 |
| `## 汇报卡` | 是 | 三条固定规则可改写 |
| `## 提问纪律` | 是 | 一次一问可改写 |
| `## 主人数据红线` | **否** | 数据域分级 / 有判断无权力 / 日记域只追加 / 引原话标日期；宿主固定注入 |

存储与合并：

- 每执事家目录 `DISCIPLINE.md`；**缺失 = 全用宿主默认**，不存在“半套默认”。
- 只认上面七个固定二级标题；无标题正文 / 未知标题 → `PUT` 400，避免把一段自由文本伪装成纪律。
- 标题存在但节内为空 = 删掉这一条；没写的标题仍用宿主默认。
- 红线不参与覆盖：文件里出现 `## 主人数据红线` 直接拒绝；界面单独只读展示。
- 文件 ≤ 64KB，原子写；空内容删除文件，回到宿主默认。
- 注入仍在 `disciplineBlocks()` 同一位置；覆盖只是替换块文本，不新增段、不改顺序。
  用户改文件会改变提示词固定前缀字节，这是**人工编辑的预期结果**，不再把“缓存前缀稳定”当拒绝编辑的理由。
- 回滚：`PARTNER_DISCIPLINE_EDIT=false` / `0` → 不读、不写 `DISCIPLINE.md`，纪律回到纯宿主常量。

默认页逐节入口（2026-11-16 再追加）：

- `buildPartnerTurnContext()` 带 `disciplineFields`：七个行为节 + `partner_owner_data` 各一个 `{id,title,text}`，
  删空的节也保留 `text:""`，所以默认页能显示 0 字槽位、还能点回来。
- `context-defaults.ts` 每个 `disciplineFields` 写一个独立 section key，不再写合并 `partner_discipline`。
- `context-inspect.ts` 给七个节 `editable:true`，给 `partner_owner_data` 只读。
- 默认页每节下面的「改这一节」打开局部编辑弹层：读取 `GET /discipline`，只把当前标题的正文放 textarea；
  保存时把当前标题合并回 `DISCIPLINE.md` 的已有覆盖（其他节不动），清空正文 = 删除这一节；
  「恢复这一节默认」= 从覆盖里移除当前标题；整段清空仍可用档案页的「恢复宿主默认」。

端点：

- `GET /api/v1/partners/:id/discipline` → `{ok, editable, defaultDiscipline, override, redLine}`
- `PUT /api/v1/partners/:id/discipline` body `{discipline}` → 校验标题 / 64KB / 红线，写 `DISCIPLINE.md`；
  返回 `override`、`defaultDiscipline`、`discipline`
- `DELETE /api/v1/partners/:id/discipline` → 清覆盖，返回 `override:null`、`defaultDiscipline`、`discipline`
- 开关关闭时三个端点都 400 并带说明。

  预填 `override ?? defaultDiscipline`；每节「保存这一节」只把当前标题合并进 `DISCIPLINE.md`，
