## 改动项

### 1. 方法论技能包（P0，纯内容）

在 `ts/apps/server/skills/` 下新增 **4 个技能文件**（格式照现有 `meeting_guide.md` / `recall_guide.md`：
**第 1 行 = 索引用摘要**，一句话，不带标题符号；正文是给人/给模型看的操作手册）：

| 文件名 | 技能名 | 内容要点 |
|---|---|---|
| `writing_plan.md` | 写计划 | 计划写给"没见过这个仓库的人"：每个任务 = 最小可评审单元；把"我决定了什么"（文件/名字/签名/验收测试）写死；留白处标注"由实现者选择" |
| `executing_plan.md` | 执行计划 | 一次只做一步；每步做完先自检再进下一步；**四停条件之外自己裁决**：不可逆/破坏性、安全敏感、工作树外副作用、计划烂到每条路都是猜——这四条停下问人，其余自己拍板并记账 `裁决：决定—为什么—错了的代价` |
| `verifying_done.md` | 验证完成 | 铁律：**没有在这一轮里真的跑过验证，就不能说"完成了"**。五步：认清要验什么 → 真的跑 → 读输出 → 对账 → 才敢说。给一张"主张 ↔ 证据"对照表（说"测试通过"要有 0 失败输出；说"改好了"要复现原症状已消失；说"做完了"要有落盘 diff）。红旗清单：出现"应该/大概/应该没问题"、语气满意但没跑过 → 就是在撒谎，回头去跑 |
| `debugging.md` | 系统化调试 | **没有调查不许改**；先复现、再定位（读数据流/打印/二分）、再假设、再验证；**同一条思路连修 3 次仍失败必须停下**，把已经查明的写成一段话交回去，别继续硬修 |

要求：
1.1 中文、**裁剪到生活/个人域**（原文是编码域，例子换成"整理文件 / 写文档 / 查资料 / 记日记"这类）。
1.2 每个文件 ≤ 2500 字，**结构是清单不是散文**（模型照着能干）。
1.3 第 1 行摘要 ≤ 40 字，形如 `写计划：把要求拆成能一条条核对的动作`。
1.4 不改 `skills.ts` 任何逻辑（现有加载器已支持扁平 md）。
1.5 单测：`scanSkillDir` 能读到这 4 个新技能，摘要取自第 1 行（若已有同类测试，加断言即可）。

### 2. 记忆凭据打码（P1）

2.1 新建 `ts/packages/memory/src/redact.ts`：`redactSecrets(text: string): string`。
   - 识别并替换为 `«redacted»`：形如 API key / token / 密码的串——
     `sk-…`、`Bearer xxx`、`api[_-]?key\s*[:=]\s*\S+`、`token\s*[:=]\s*\S+`、
     `password\s*[:=]\s*\S+`、`密码\s*[:=：]\s*\S+`、长度 ≥32 的 base64/hex 连续串。
   - **故意放行**：手机号、生日、地址、人名——这些是日记里该记住的东西（不是敏感物）。
   - 纯函数，零依赖，可单测。
2.2 **唯一收口点**：`MemoryEngine` 的写入路径（`store.ts` 里 `remember()`/`insert()` 落盘前）。
   在这一处调用 `redactSecrets`，让**所有写入方**（工具 / 抽取 / 导入 / 巩固）都受益。
   **不改** `content` 之外的字段；打码后的内容就是入库内容。
2.3 开关 `MEMORY_REDACT`（默认 **true**）；`false` 时直通（回滚）。
2.4 单测：≥12 个正例（各种 key 形态）+ ≥6 个反例（手机号/生日/正常句子不被误伤）+ 开关旁路。
2.5 **不要在召回或读取路径再打码**（只治理写入），否则会把已经打码的内容二次处理。

### 3. 记忆 `intention` 类型（P1）

3.1 `MemoryKind` 增加 `"intention"`（前瞻意图："我打算下周开始跑步"）。
   同时给 `MemoryRecord` 加**可选** `expiresAt?: string`（ISO；只有 intention 用）。
3.2 **语义**：`intention` 过期（`expiresAt` 早于现在）后**降级为 `fact`**（原地改 kind，不删）。
   降级在**召回/列表读取时**做（惰性，不新建定时器），或在一个既有的巩固入口里做——二选一，
   **必须写清选了哪条、为什么**。
3.3 `remember` 工具加可选参数 `expiresInDays?: number`（1..365），只在 `kind=intention` 时有意义；
   给 `MEMORY_KINDS` 加 `intention`，描述补一句"我打算…"的用法。
3.4 召回：**未过期的 intention 优先注入**（与偏好同组或紧随其后），过期的按 fact 走普通召回。
   若现有注入是"偏好 + 其它两组"，加第三组 `intention` 更清楚。
3.5 设置页记忆区（`web/app.js`）加 `intention` 的中文标签与徽章（"打算"）；**只加这一个 kind 的映射**。
3.6 巩固/衰减：intention **不参与**合并与时间衰减（与 `work` 同待遇，改 `protectKinds` 或等价判断）。
3.7 单测：写入带 expiresAt / 过期后读到 kind=fact / 未过期优先注入 / 巩固不碰 intention。

### 4. 会话考古：跨会话检索（P2）

4.1 新工具 `recall_sessions`：参数 `{ query: string, days?: number (默认 30, ≤365), limit?: number (默认 5, ≤20) }`。
   行为：在**本机 durable 的 transcript** 里检索（所有会话，含执事/群/任务专线），返回
   `[{ conversationId, title, at, snippet }]`，snippet ≤ 200 字（命中处前后各 100 字）。
4.2 实现要求：
   - **只读**，不进 `WRITE_TOOLS`；
   - 复用既有搜索基建（`search.ts` / `search-api.ts` 已有单会话搜索的 SQL/FTS 做法，先读，
     能复用就复用，不能就照它的形状写**跨会话**版本）；
   - **不做向量检索**，就是 LIKE/FTS；
   - 走开关 `AGENT_RECALL_SESSIONS`（默认 **true**），false → 工具不上架；
   - 是**条件注册**工具（不进基线 10 个），接口文档 §4 登记。
4.3 隐私边界：只查本机自己库；结果里**不含** key/凭据（用 §2 的 `redactSecrets` 过一遍 snippet）。
4.4 单测：跨两个会话建数据 → 命中两条 → snippet 截断正确 → days/limit 生效 → 无命中返回空数组不发散。
