## 二、注入框架 批 A（#7，只建框架 + 审计 + 接管一个注入）

2.1 新增 `ts/apps/server/src/agent/injection.ts`：
   `	s
   export interface InjectionEntry {
     id: string;        // <source>:<key>
     text: string;      // 固定字节，不含时间/会话 id
     order: number;     // 稳定顺序
     scope: "session" | "once" | "turn";
     channel: "system" | "message";
   }
   export type InjectionProvider = (ctx: unknown) => InjectionEntry | InjectionEntry[] | undefined;
   export function collectInjections(providers: InjectionProvider[], ctx: unknown): {
     system: InjectionEntry[];
     message: InjectionEntry[];
   };
   `
   行为：收集 → 按 `order` 升序排序（同 order 按 id 字典序，保证稳定）→ 按 `id` 去重（后者覆盖前者）→ 按 `channel` 分流。

2.2 **本批只接管 `injection_guard`**（`agent/injection-guard.ts` 的 `INJECTION_GUARD`）。
   其余 6 个 section 与 5 处 `extra.push` **一律不动**。

2.3 审计端点 `GET /api/v1/agent/chat/:conversationId/injections`：
   返回本轮注入清单 `[{id, source, scope, length}]`，**不返回正文**（正文可能含记忆内容）。
   开关 `AGENT_INJECTION_AUDIT`（默认 true）。

2.4 **验收硬标准**：接管后 `injection_guard` 注入的**内容与位置必须与改造前逐字节一致**。
   单测直接断言：`collectInjections([guardProvider], ctx).system[0].text === INJECTION_GUARD`。

2.5 单测：
   - 条目形状合法；
   - 排序稳定（打乱输入顺序，输出一致）；
   - 同 id 去重（后者覆盖）；
   - **只接管了一个**：断言 lifecycle 里 section 数量与改造前一致（除 injection_guard 改走新通道）；
   - 审计不返正文。
