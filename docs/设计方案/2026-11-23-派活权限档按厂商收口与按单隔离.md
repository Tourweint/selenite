## 1. 背景与用户口径

1. **权限档按厂商给啥用啥**：不自己做只读沙箱。当前界面对所有外部 CLI 都画「只读 / 可改 / 全权」三段，
   但厂商并不都有这三档——豆包只有 `ask_always / ask_risky / always_allow`，没有只读；
   OpenCode 的 `edit` / `full` 都走 `--auto`。硬套三段会让用户以为「只读」是只读。
2. **worktree 隔离按需选**：不硬性全开，由派活的人（总管 / 执事）按单决定。
   现状是全局 `CHANCELLOR_TASK_ISOLATION=worktree|direct`，`delegate` 工具没有参数可传——
   只在提示词里说「按需开」没有落点。

## 2. 方案

### D1. 内部契约不动，界面按厂商裁剪并显示厂商自己的档名

- 引擎内部仍只认 `read / edit / full` 三值（`EmployeeProfile`、`.data/executor.json`、ticket 快照都不变），
  避免为 UI 改跨包契约。
- `ExecutorKindInfo` 增加 `permissionOptions?: { value: EmployeePermission; label: string; hint?: string }[]`，
  由后端给每档列出「实际可选 + 厂商原生档名」：

| 执行器 | 界面档位 | 映射 |
|---|---|---|
| Claude Code | 只读 / 可改 / 全权 | `plan` / `acceptEdits` / `dangerously-skip` |
| Codex | 只读 / 可改 / 全权 | `read-only` / `workspace-write` / `danger-full-access` |
| OpenCode | 只读 / 全权 | `--agent plan` / `--auto`（edit 与 full 同档，不再画第三段） |
| 豆包 | 风险确认 / 全部允许 | `ask_risky` / `always_allow`（**不画「只读」**） |
| CodeBuddy / Qoder | 固定全权（`null`） | 不变 |

- 前端 `settings-executor.js` 改用 `permissionOptions` 渲染分段；没有该字段时回落旧 `permissions`。
- 旧配置里 `permission:"read"` 的豆包单仍按 `ask_risky` 执行（后端映射不改），只是界面不再提供这个选项。

### D2. `delegate` 增加 `isolation` 参数（三态）

- 工具参数：`isolation?: "auto" | "worktree" | "direct"`，默认 `auto`。
  - `auto` = 现有逻辑：跟随全局 `CHANCELLOR_TASK_ISOLATION`，且只在 git 项目上开 worktree。
  - `worktree` = 这张单强制隔离（非 git 项目回落 direct，并如实说明）。
  - `direct` = 这张单直接在项目目录干，不起 worktree。
- 传递链：`tools.ts`（参数）→ `DelegationKick.isolation` → `ChancellorRequest.isolation` →
  `TicketOptions.isolation`（建单快照）→ `scheduler` 的 `options.isolation`。
- 续跑 / 崩溃恢复沿用原单快照，不跟当前默认走。
- 工具描述与 `skills/delegate.md` 增加规则：多单并行改同一项目建议 `worktree`；只读查证 / 单张小改可用 `direct`。
- 回滚：不传 = `auto`，行为与改动前一致；`CHANCELLOR_TASK_ISOLATION` 仍是全局缺省。

### D3. 文档与缓存资产

- `delegate` 参数增加会改工具描述（缓存前缀资产），必须记 `docs/变更记录/`。
- 接口文档：执行器权限档口径、delegate 参数表补 `isolation`。

## 3. 明确不做

- 不做真正的只读沙箱（没有厂商原生档就不假装有）。
- 不做界面「按单选择执行器」（用户口径：先全局默认，后期再说）。
- 不把 worktree 当安全边界：它只隔离文件改动，不防危险命令。
