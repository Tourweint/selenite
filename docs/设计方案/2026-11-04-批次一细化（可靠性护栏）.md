## 二、A3a：回执表加 conversation_id

**目的**：把 ticketId→会话的映射随受理落库，为 A3b（跨仓库恢复回灌）备好数据；本步无行为可见面变化。

1. `delegation-receipts.ts` 构造函数建表后加迁移（对旧 `.data/delegations.sqlite` 安全）：
   - `PRAGMA table_info(delegation_receipts)` 检查无 `conversation_id` 列时 `ALTER TABLE delegation_receipts ADD COLUMN conversation_id INTEGER`（可空；**旧行永远 NULL，A3b 无法回填**——这句写进代码注释）。
   - `CREATE INDEX IF NOT EXISTS idx_delegation_receipts_ticket ON delegation_receipts(ticket_id);`
2. `DelegationReceipt` 接口加 `conversationId: number | null`；`toReceipt` 映射（NULL→null）。
3. `accept(requestId, ticketId, conversationId?: number)`——第三参可选；提供与否用 `!== undefined` 判断（不用 truthy，防 id=0 类边界）。**两个调用点 tools.ts:412 与 416 都补传** `conversationId`（定义在 tools.ts:301，两处同在 execute 闭包内）。
4. 新方法 `lookupByTicket(ticketId: string): DelegationReceipt | null`——`ORDER BY updated_at DESC, rowid DESC LIMIT 1`（同毫秒并列时取最后写入）。**标注 `@internal` + 注释"A3b 专用，当前无生产调用方"**（诚实标记，不假装不是过渡态）。
5. **回滚开关**：env `DELEGATION_MAP_PERSIST`（默认 true；`false` 时 accept 不写会话列）。**每次调用 accept 时读 env**（不缓存在构造函数），单测才能同进程切换开关。
6. 幂等语义零改动：`begin`/`lookup`/`markFailed`/`reinsert` 不动。

## 三、A4：settings 显式化 + bash 默认超时（经 beforeTool 注入）

**目的**：把"现在是什么行为"写清楚；给真风险点（bash 无默认超时）加护栏。**唯一行为变化 = bash 默认超时**。

1. **新建 `ts/apps/server/src/reliability.ts`**（不 import agent.ts——agent.ts 模块加载即建 memoryEngine/skillStore，单测 import 会有副作用）：
   - `buildHarnessSettings(env)`：env 全空时返回 `undefined`（**干脆不传 settings**，"不改变行为"是构造上的保证，不靠"显式值恰好等于默认值"的推理）；`AGENT_STREAM_TIMEOUT_MS`（正整数）非空时返回 `{ stream: { timeoutMs } }`；`AGENT_AFTER_FAILED_RUN` 枚举 `keep|continue|withdraw` 非空时并入。其余旋钮（retry/compaction/toolExecution/steeringMode/followUpMode/restartLimit）不传，函数注释引 `pi-durable/dist/harness/agent.js:41-61` 默认值表 + 指向调研方案 §四 A4。
   - `AGENT_STREAM_TIMEOUT_MS` 的注释**只写可验证事实**（CodeBuddy 实读 openai SDK 7.19.0）：不设 = SDK 默认 10 分钟；该超时对流式请求主要约束连接/响应头等待，**响应头到达后即清除**（`openai/client.js:1008-1025, 543-547`），不约束整段生成时长。**不许写"心跳保活/设小掐断深档"之类未验证的机制解释**。
   - `bashTimeoutSeconds(env)`：`AGENT_BASH_TIMEOUT_S` 解析，默认 `900`（15 分钟——慢机器上 install/构建可能超 10 分钟，2026-11-04 审查建议区间取值）；`0` 或非法值 = `0` = 禁用。
2. `agent.ts` 装配：`Harness.open` options 加 `...(settings ? { settings } : {})`。
3. **bash 默认超时注入：用现有 `lifediaryExt` 的 `beforeTool` 钩子（agent.ts:432-451），不用新扩展、不用 wrap**。内核 `ToolHooks.beforeTool` 返回 `{ arguments }` 会**替换参数并重新校验**（`pi-durable/dist/harness/types.d.ts:807-812`、`tool.js:59-80`）：
   ```ts
   if (call.name === "bash" && bashTimeoutS > 0) {
     const a = call.arguments as { timeout?: number };
     if (a.timeout === undefined) return { arguments: { ...a, timeout: bashTimeoutS } };
   }
   ```
   注意事项（审查实读内核）：注入发生在工具 start 事件之后，UI 显示模型原始参数——这是想要的；**`timeout=0` 绝不能注入**（内核 `validateTimeout` 对 `<=0` 抛 `Invalid timeout`，bash.js:21-27），禁用=跳过注入。**若实现时发现该路径与内核行为不符，停下来如实汇报，不许绕过校验自造。**
4. 启动日志一行，打印**实际解析值**：`[可靠性] bash默认超时=900s|禁用 stream.timeoutMs=未设(SDK默认10min)|123456 afterFailedRun=keep|未设`。
5. `ts/apps/server/.env.example` 补**全部 5 个**新 env（`AGENT_STREAM_TIMEOUT_MS`、`AGENT_AFTER_FAILED_RUN`、`AGENT_BASH_TIMEOUT_S`、`MEMORY_CANDIDATE_FLOOR`、`DELEGATION_MAP_PERSIST`），各带一行注释；**同步补进 `接口文档.md` §6 env 表**（契约一致性硬约束）。

## 四、A2-S：召回候选窗口 50→200（可调）

**目的**：让超出旧窗口的老记忆有机会进入打分。真修复（文本检索入口）在批次三。

1. `recall.ts:32`：`WeightedRetriever` 构造函数加可选 `{ candidateFloor?: number }` 默认 `200`；`recall()` 里 `limit: Math.max(limit * 5, candidateFloor)`。打分权重、`extractKeywords`/`keywordScore`、`slice(0, limit)` 全部不动。
2. 装配链路（**server 不直接构造 WeightedRetriever**）：`createMemoryEngine`（`memory/src/index.ts:17-26`，现只收 `{dbPath, enabled}`）加可选 `candidateFloor` 透传到 `MemoryEngineOptions`（engine.ts:32-38）→ `new WeightedRetriever({ candidateFloor })`（engine.ts:51 现为无参构造）。**env 规则：召回层不读 env（`createMemoryEngine` 读 `MEMORY_DB_PATH` 是现状、不动），`MEMORY_CANDIDATE_FLOOR` 由 server 装配处（agent.ts:258-261）读后传入。**设 50 = 旧行为。
3. 残余上限写进代码注释：200 是 **global+当前会话合并后**的总窗口，近期会话记忆多时仍可能把老 global 记忆挤出窗口。
4. **测试（selftest 是顺序脚本 + `process.exit(1)`，不是测试框架）**：在 `packages/memory` 的 selftest 里加一节——
   - 显式构造**严格递增**的 `createdAt`（同毫秒并列会让排序不稳定，假通过/假失败）；
   - 120 条记忆，最老一条含查询关键词、importance 平平；`limit` 设 ≥120（否则 `slice(0, limit)` 把它切掉，测的还是切不切而不是窗口）；
   - **同一脚本里建 floor=50 与 floor=200 两个引擎**，断言前者**不含**、后者**含**该老记录（不搞"跑两遍进程期望失败"）。
