# 关于我：全局固定注入 + 每 Agent 读取开关（2026-11-19）

## 状态

**已落地（同日）**。契约下沉 `接口-端点4-执事例行与自主轮.md` §2.11、机制下沉
`系统架构.md`（模块行 / §4.1 / §4.3 / D32），落地记录 `变更记录/2026-11-19-关于我（全局固定注入）.md`。
冲突以后者为准。

## 背景

记忆层是**按相关度召回**：重要性 0.45 + 新鲜度 0.3 + 关键词 0.2 + 召回次数 0.05，
默认每轮 16 条 / 2000 字（`memory-inject.ts`）。这解决的是"说到才想起"，解决不了
"每轮都必须在"的**用户固定背景**——例如：

- 我常用语音输入，文字里可能有识别错字，先按意思理解，不确定再问；
- 称呼、说话禁忌、工作节奏这类稳定习惯。

这类东西有三个硬要求：

1. **不靠召回**：语音输入错字恰好会让查询文本本身带错，关键词命中率低，越该想起越容易漏；
2. **不是人设**：SOUL 说的是"他是谁"，不是"我是谁"；写进人设会让每个人格都变成主人的说明书，
   而且 N 个执事要改 N 份，迟早不一致；
3. **不是每个 Agent 都需要**：主人大部分时间不和普通 Worker 说话，不希望每个会话都背一份。

现有槽位都不合适（2026-11-19 核对）：

| 槽位 | 每轮必带？ | 为什么不合适 |
|---|---|---|
| 记忆（global / partner） | 否，打分召回 | 见上；预算内还可能被别的记忆挤掉 |
| SOUL / 人设 | 是 | 是人格不是用户档案；逐人一份、会漂移 |
| 执事「印象」 | 是 | 每个执事一份；只取最近 4 条"对主人"的，自动长出来的致谢/纠正会把常驻条目挤掉；总管主对话不吃 |
| 执事「主人画像」`memories/USER.md` | 是（随身份进 instructions） | 每个执事一份；没有编辑入口 / 没有写入方（本机 496 份全是空模板）；总管主对话不吃；改文件要等重配 instructions 才生效 |

## 结论

新增一个**全局一份**的「关于我」页面：

- 内容存 `.data/user-profile.md`（纯文本，原子写，≤8192 字节；`USER_PROFILE_PATH` 可覆盖）；
- **每个 Agent 一个读取开关**（`partners.user_profile_read`，默认读；总管也是 partners 行）；
- 普通 worker 会话与派活工人**固定不读**，不设开关；
- 注入为 **system 段** `user_profile`，紧跟 persona（`INJECTION_ORDER.user_profile = 5`），每轮现读；
- 设置新增一级页面「关于我」，内容编辑 + "谁读" 开关都在这一页；
- 上下文页（设置 → Agent → 上下文）的默认开销与当前会话都要能看到这一段。

一句话：**关于我 = 客观、稳定、手维护的固定背景；印象 = 每个 Agent 对你的主观判断（自动长）。**

## 设计

### 存储

```
.data/user-profile.md      主人手写的 Markdown / 纯文本；空文件 = 不注入
                           USER_PROFILE_PATH 覆盖（测试 / 隔离实例）
partners.user_profile_read 每 Agent 开关；INTEGER NOT NULL DEFAULT 1
                           1 / NULL = 读，0 = 不读；不版本化（不是身份）
```

为什么用磁盘文件而不是记忆库：

- 不参与召回排序、不进记忆列表、不被巩固/合并/衰减；
- 与 `worker-persona.md` 同款（纯文本、原子写、每轮现读），改完下一轮生效；
- 避免"记忆里还有一份副本"的两套真相。

### 注入

新增 `lifecycle-injections.ts` 的 `userProfileProvider`：

- 仅在 `USER_PROFILE_ENABLED`（缺省开）且内容非空时产出；
- **群会话跳过**（`ctx.group`）；
- **worker 会话跳过**（`ctx.chatKind === "worker"`）；
- 其余按 Agent 判定：执事用自己的 id，主对话 / 未链接会话回落总管；
  该行 `userProfileRead === false` 时不注；
- 正文 = `【关于我】` 头 + 内容；只当背景，不当指令；
- `scope: "session"` / `channel: "system"`，与 persona 同一层，不写进对话历史。

### 页面

设置左栏「Agent」组新增「关于我」：

- 一段正文编辑区（保存 / 撤销 / 字数 / 8192 字节上限）；
- "谁读这份档案"列表：总管 + 所有在职执事，逐行开关；普通 worker 固定显示"不读"；
- 说明只写短句：每轮作为系统提示词注入、不进记忆、不参与召回、改完下一轮生效。

### 上下文显示

- `DEFAULT_SECTION_KEYS` 在 `persona` 后加 `user_profile`（同时移除已退役的
  `partner_owner_profile`，字段总数仍 30）；
- `context-defaults.ts` 用同一个 `userProfileProvider` 现渲染，空内容保留 0 字槽位；
- `context-inspect.ts` 的 `SECTION_META` 加「关于我」，当前会话的系统段自动显示；
- `injection-registry.ts` 登记该 provider，审计端点能看到 id / 长度。

### 旧「主人画像」退役

`partners/<id>/memories/USER.md` 不再进执事身份（`renderPartnerIdentityParts` 去掉
`partner_owner_profile` 段），避免与全局「关于我」两份真相。文件与本机存量不删
（`ensureHome` 仍按原样播种，`readUserMd` 保留兼容），只是不再注入。
存量内容如需保留，手工复制到新页面；本机核对全部为空模板，无需迁移。

## 契约

| 面 | 变化 |
|---|---|
| `GET /api/v1/agent/user-profile` | `{ok, enabled, editable, content, chars, limit, agents:[{id,name,kind,read}], workerReads:false}`；`cache-control: no-store`；鉴权同其它 `/api/v1/*` |
| `PUT /api/v1/agent/user-profile` | body `{content: string}`；trim 后空串 = 删文件；>8192 字节 → 400；`USER_PROFILE_ENABLED=false/0/off` → 400；成功返回同 GET 形状 |
| `PUT /api/v1/agent/user-profile/agents/:id` | body `{read: boolean}`；只接受在职 / 暂停的 partners 行（含 chief）；`worker` 或未知 id → 400 / 404；开关不版本化；成功返回同 GET 形状 |
| 环境变量 | `USER_PROFILE_ENABLED`（缺省开）、`USER_PROFILE_PATH`（缺省 `.data/user-profile.md`） |
| 回滚 | `USER_PROFILE_ENABLED=false` → 整段不注、端点只读；或逐 Agent 关开关 |

## 明确不做

- **不自动抽取 / 不自动改写**：不做第二个记忆层，也不让模型替主人维护这份档案；
- **不按项目 / 会话分片**：全局一份，v1 不做覆盖；
- **不注入群会话**：多人上下文里不带个人档案，先跳过；
- **不接派活工人 TASK.md**：工人只认单；普通 worker 会话也不读；
- **不做手机端编辑页**：手机端只受注入影响，设置入口只在电脑端；
- **不把内容写进记忆库 / `recall` 索引**：避免同一条事实既有固定注入又可能被召回；
- **不做结构化字段**（称呼 / 习惯 / 雷区分栏）：v1 一个自由文本框，先降低填写门槛；
- **不做自动置顶 / 自动遗忘**：手动维护，内容空 = 零成本。

## 备选与否决

| 备选 | 否决理由 |
|---|---|
| 记忆加 `pinned` 标记，置顶注入 | 记忆层从此有"永不召回失败"的例外，与"按相关度"的产品口径打架；巩固 / 整理 / 拆分都要跟着豁免 |
| 复用执事「印象」 | 每执事一份、4 条上限、自动印象会挤掉常驻条目；总管主对话不吃 |
| 复用/开放 `memories/USER.md` 编辑 | 每执事一份，正是"改所有人"的痛点；且身份 instructions 重配时机不直观 |
| 写进 SOUL | 人格变成用户说明书，N 份漂移；SOUL 的语义被破坏 |
| 每个 Agent 各写一份 | 用户明确说"不是人设"，且大部分 Agent 不常聊，维护成本高于收益 |

- `user-profile` 存储 / 端点单测（空串删文件、8192 上限、开关、disabled）；
- 注入单测（总管 / 执事开关 / worker / 群会话 / 空内容 / disabled）；
- `context-defaults` 字段数仍 30、`user_profile` 位置与空槽位；
- `pnpm typecheck`、`pnpm --filter @lifediary/server test`、`pnpm --filter @lifediary/server http`；
