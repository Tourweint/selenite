# 一轮对话时间线 + 提交前契约体检（2026-11-17）

## 状态

**已落地（同日）**。本方案记"当时怎么想的"；现行口径以下沉落点为准：
- 时间线账机制与开关 → 本文「时间线」段 + `docs/基线文档/系统架构.md`
- 端点契约 → `docs/基线文档/接口-端点2-杂项日记与项目.md`（`GET /api/v1/agent/turn-timeline`）
- 提交钩子 → 本文「提交门禁」段 + `.githooks/pre-commit`（自注释）

## 背景与目标

用户拿到一段"企业级 Agent 平台"的 JD 文案，逐条核查后发现：仓库真正的强项是
单机有状态 / 四层记忆 / 上下文工程，而"全链路 Trace 归因""回归门禁"是拔高话术。
讨论后明确**不追**那些与企业级概念绑定的能力（多租户、真分布式、自动自演进闭环），
只补两件"投入小、对我（AI 编码代理）自己有用"的工程卫生：

1. **串账**：排查"这一轮调了什么工具 / 被哪道闸拦了 / 跑了几回合 / 花了多少 token /
   怎么结束"要翻 tool-usage、gate-blocks、usage、server.log 四本账做连线题。给每轮
   一个单号，把节点聚合成一条时间线。
2. **提交前体检**：AGENTS.md §验证 的规矩全靠手动跑，没有东西拦住"改完直接提交"。
   加一个轻量 pre-commit，每次提交守住"契约只有一份"。

明确**不做**（用户拍板）：工具用量账（上一批刚落地）接自动调整策略——"现在先看数据，
后期手动调整，自动调整就算了"。

## 时间线

### 单号从哪来
复用 `/chat` 已有的 SSE `start/done.id`（`index.ts` `crypto.randomUUID()`，uuid，符合
"对外 id 一律 uuid"）。**不新增 SSE 字段、不改 shared 契约、不发新帧、不动手机端**。
日志里的 `[chat ${id}]` 与对外单号是同一个值，搜一个号看全一轮。

### 关联方式（为什么不用 AsyncLocalStorage）
钩子（beforeTool/afterTool/beforeRequest）拿不到 `/chat` 的流 id，只能拿到内部自增
`conversationId`（与 gate-audit 同一个值）。但 pi-durable 的钩子可能在跨 async 边界被调用，
ALS 上下文未必稳；改用一张进程内小表 `internalId → turnId`：`beginTurn` 在 `/chat` 入口
登记，钩子按 internalId 反查。单会话一轮一跑（忙时排队），不并发覆盖；表上限 512 条防无界。
**取舍**：只有走 `/chat` 的轮会进账；autonomous / 派活 / openai-compat 等 10 处 chatStream
入口本期不覆盖（钩子反查不到单号就跳过）——这是刻意的范围，不是漏洞。

### 记什么 / 不记什么（硬约束）
落 `.data/turn-timeline.jsonl`（追加写，一行一个 JSON）。只记枚举 / 计数 / 字数 / 耗时：
`start / round / tool / gate / usage / done / error` 七类。

| 绝不记 | 原因 |
|---|---|
| 工具 `args` / `output` / `diff` | 含 write 正文 / edit diff（ToolEvent 自带），AGENTS.md「日志不含对话内容」 |
| `beforeRequest` 的 `userText` | 对话正文 |
| 原始错误 message / detail | 可能带上游地址甚至 key 片段（index.ts 既有口径：原始错误只进服务端日志） |
| approvals 的 `args` | 含对话内容，approvals.ts 明说永不进日志 |
| 内部整数 conversationId（**仅 GET 投影**） | 猜得到就能读别人历史；jsonl 里保留排障用，对外不投影 |

写失败只 warn，绝不挡主流程（旁路审计）。

### 开关与回滚
`TURN_TIMELINE=false|0|off` → 一行不写、GET 端点 404（一行回滚，仿 TOOL_USAGE）。
测试隔离 `AGENT_TURN_TIMELINE_PATH`。

## 提交门禁

### 定位：安检，不是硬门禁
仓库多会话共享工作区、精确暂存是纪律；全量 typecheck/test 读的是整个工作树，别人的
在途坏代码会把它染红。硬拦会逼大家天天 `--no-verify`，钩子就形同虚设。所以：

| 检查 | 钩子行为 | 理由 |
|---|---|---|
| 契约形状快照 `packages/shared/src/snapshot.test.ts` | **硬阻断** | 只读 Zod 形状、确定性、秒级、几乎不被并行碰，守"契约只有一份"（AGENTS.md §硬约束） |
| `tsc --noEmit` | 仅告警 | 最容易被他人在途代码误杀 |
| 全量单测 / probe / http / memtest | 不进钩子 | 太慢 / 真起服务，留手动验收（AGENTS.md §验证"最小充分"） |

`tool-schema-guard`（缓存前缀资产）暂不进钩子：它同样容易被并行在途的 tools.ts 改动染红；
其自动守卫仍在全量 test 里跑，本次不削弱。

### 挂法
- 版本化 `.githooks/pre-commit` + `core.hooksPath=.githooks`（装一次覆盖所有会话，可 review）。
- `.gitattributes` 钉 `.githooks/*` 与 `*.sh` 为 LF——本机 `core.autocrlf=true`，不钉会
  `bad interpreter: /bin/bash^M`。
- 一键安装：`pnpm hooks:install`（跑 `scripts/install-hooks.sh`）。
- 跳过：`git commit --no-verify`（git 原生，pre-commit 会被跳过），不加额外 env 开关。
- 依赖未装（干净 clone）：告警放行，不卡死提交。
