## 〇、一句话

退役的是「课题」这个独立实体、独立调度、独立界面，不是「长期研究」这件事。长期研究改由 **普通项目（档案）+ 普通执事（执行者）+ 定时任务（钟）** 承接；不新增实体、不改执事、不改权限。

## 一、为什么退役（2026-11-20 核对）

- **使用量**：`.data/topics.json` 只有 1 条课题（2026-11-19 11:35 建，dig 型，周一 20:00），`findings=0`、`lastRunAt=null`——第一轮都还没跑过。
- **调度层完全同构**：`TopicTask` 文件头自认「触发层照 routines.ts 的 RoutineTask」；睡醒对 revision、同事务排下一次、fire-and-forget 执行，逐条一样。课题没有自己的钟。
- **独有三样，其中两样是补丁**：findings 档案（真差异）、确定性收尾（可靠性补丁）、pendingPush 简报（可见性补丁）；只读专线可以用「专用执事 + 工具勾选 + fresh 会话」复刻。
- **概念成本**：1 个实体 + 8 个端点 + 2 段注入（`topics` / `topics_live`）+ 1 个工具（`propose_topic`）+ 1 张插件卡 + 侧栏分区 + 提议卡 + 时间线。
- **历史包袱**：`web_search` 自 2026-11-07 起绑在 `TOPICS_ENABLED` 下注册；搜索 2026-11-12 已独立成 10 家源，这个耦合必须解开。

## 二、决策

### D1：全量删除课题栈

**服务端删除**：`topics.ts` / `topic-runtime.ts` / `topic-api.ts` / `topics.test.ts` / `scripts/topic-probe.ts`。

**服务端改动**：
- `index.ts`：摘掉 `mountTopics`。
- `agent/lifecycle-harness.ts`：摘掉 `topics` section、`TopicTask` 注册、`researchExt` 安装、`deps.topics`。
- `agent/lifecycle-injections.ts`：删 `topicsProvider` / `topicsLiveProvider` / 课题嗅探文案。
- `agent/injection-registry.ts` / `context-defaults.ts` / `context-inspect.ts`：删对应登记与中文名。
- `agent/session-open.ts` / `agent/session.ts` / `agent/lifecycle.ts`：删 `configureResearchChat` 与 `researchExt` 导出。
- `tools.ts`：删 `propose_topic`；`web_search` 改由搜索依赖决定注册（见 D2）。
- `tool-pool.ts`：按需名单删 `propose_topic`。
- `tool-capability.ts`：删 `propose_topic` 能力项（保留 `web_search`）。
- `export-bundle-collect-conversations.ts`：导出包不再收集 `library/topics.json`。
- `plugins.json`：删「长期课题」卡与分组 key。
- `package.json`：删 `topic` 探针脚本与测试清单里的 `topics.test.ts`。
- 兼容保留：`partner-session-role` / `partner-types` 里的 `role="topic"` 枚举值不删——历史会话可能带这个值，读路径照旧折回 canonical；只是不再有新写入方。

**前端删除**：侧栏课题分区 / 轨道钮 / 悬停卡 / 提议卡 / 课题详情与时间线 / `loadTopicsSidebar` / `topics_live` 相关 UI。

**明确保留**：`search.ts` / `search-vendors.ts` / `search-config.ts` / `search-api.ts` / 设置 → 模型 → 搜索源整页 / `web_search` 工具。

### D2：`web_search` 解耦

注册条件从「`TOPICS_ENABLED && deps.topics && deps.search`」改为「`deps.search` 存在」。工具描述去掉「课题研究」措辞（工具描述是缓存前缀资产，变更进变更记录）。未配搜索源时照旧返回 `search_not_configured` 引导错误，不造假结果。

### D3：替代配方（不新增代码）

| 原来课题里的东西 | 现在用什么 |
|---|---|
| 课题实体 / 户口本 | **普通项目**：一个长期问题一个项目，档案放项目里的 `<题>.md`；项目行就是侧栏里的书架 |
| 每周到点研究 | 给一个**普通执事**建 routine，cron 照写 |
| 只读研究沙箱 | 执事页「能用的工具」只勾 `read` + `web_search`（现成开关，不是必做） |
| 每次新开、不污染 | routine 的 `sessionMode=fresh`（编辑器「每次新开」） |
| 接着上次往下查 | routine prompt 里写「先读 `<项目>/<题>.md`，把新结论追加到末尾」；文件比 findings 回放更全、不截断 |
| 研究时间线 | 打开项目看文件；或 routine 用 `persistent`，历次研究就是同一条对话 |
| 下次你说话时报简报 | **刻意没有等价物**：结果留在项目文件 / 执事会话里，要你主动去看 |

配方只写进文档，不预置项目、不预置执事、不预置 routine（用户口径：自己建）。

### D4：项目「研究」标记 = 纯前端

- 存储：`localStorage["lifediary.researchProjects"] = [projectId, …]`。
- 显示：侧栏项目行、设置 → 项目卡片上的「研究」小标签（`.proj-tag.is-research`）。
- 开关：项目行右键菜单 / 项目卡 ⋯ 菜单里的「标记为研究项目 / 取消研究标记」。
- 边界：不写服务端、不进契约、不影响模型；换浏览器或清缓存会丢；不同步手机。以后要同步再立项。
- 项目本身仍是普通项目：可改名、加文件夹、归档、删除登记，行为零变化。

### D5：数据处置

- `.data/topics.json` **不删不读**；代码里不再有 reader。现有 1 条课题的问题原文抄在 §附，用户自建项目时可直接取用。
- 不写迁移脚本、不自动建项目/执事/routine。
