## 〇、一句话

三批把 cindy/DS-Bot 择优落地：**批次A** 是两件不依赖伙伴的通用加固（防打转、回执补差），
**批次B** 立起"伙伴"最小可用（档案双层存储+记忆隔离+例行任务引擎+模型候选链），
**批次C** 给伙伴装主动性（任务观察+自主轮高危审批，默认关闭）；子代理与 auto-bridge 进后置池。

## 二、七条设计原则（两家踩坑换来的，每批方案都要对照）

1. **代码不用提示词**：生命周期、去重、禁套娃、归属判定全部宿主实现，提示词只做纪律补充；
2. **fail-closed**：审批送达不了就拒绝；权限读不到就当要问；
3. **先落盘再记账**：回执、结果文件、状态跃迁，一律先持久再动作；
4. **中断不自动重放**：外部副作用无法断言是否已发生时，一律标 interrupted 交人；
5. **边界写死**：伙伴/子任务/派单三形态互不冒充，handler 层拒绝 + 提示词强调双保险；
6. **新主动性默认关闭**：自主跟进类能力 env 默认 off，用户显式开；
7. **回滚开关一行 env**：每批至少一条退回上一形态的路（硬约束）。

## 三、批次A：通用加固（不依赖伙伴层，可先行）

### A1 防打转守卫（ToolLoopGuard 移植）

- **做什么**：移植 cindy `loop-guard.ts:279-694`（~200 行纯类，零依赖零 IO）进 server；
  挂在 agent.ts 工具调用循环上。阈值照抄：连续 4 次完全相同 / 12 滑窗 distinct≤2 /
  16 滑窗 distinct≤4 → 疑似；30 次完全相同 / 同结果 60min / 长读窗口轮转 → 铁证直接中断。
- **v1 裁剪**：疑似只**告警**（SSE 提示 + 日志记枚举，不含对话内容），铁证才中断；
  "辅助模型复核"后置（需要挑便宜模型的口径，单独立项）。
- **豁免清单**：等待/轮询类工具不计（我们自己的等待类工具在细化方案里盘点列全）；
  距上次调用 ≥30s 的节奏轮询不计。
- **回滚开关**：`TOOL_LOOP_GUARD=off`。
- **验证**：纯类单测（各阈值+豁免+窗口滑动）挂 `pnpm --filter @lifediary/server test`；
  typecheck；probe 冒烟确认正常长任务不误伤。

### A2 派单回执补差（防重复派活的两个洞）

- **补差 1**：回执行补 `bootId`（进程代号）：**pending 状态的回执跨 boot 一律按 uncertain 处理**
  （发送途中死掉的派活不许自动重发，交人判断）——DS-Bot `requests.js` 的核心教训。
- **补差 2**：死信路径：父单 aborted 后才到达的子单结果落死信记录（不丢、不并入、计入变更，
  可查），补 delegate-chain-probe 断言。
- **验证**：`delegate-chain-probe` 扩三场景（跨 boot pending→uncertain / conflict / 死信）；
  `recovery.test.ts` 补用例；typecheck。
- **回滚开关**：无需——两处都是把行为收紧（防重复副作用），无形态退回问题；
  若细化方案认定有行为面变化再补。

## 四、批次B：伙伴最小可用（长期身份+记忆+例行任务）

**总开关**：`COMPANIONS_ENABLED=false` → 工具不注册、端点不挂载、引擎不启，回到无伙伴形态。

### B1 记忆隔离（半天级，最先做）

`ts/packages/memory` 存储层加 scope key（如 `partner:<uuid>`），四层（存储/抽取/巩固/召回）
原样复用，键空间隔离。验证：`pnpm memtest` 扩 partner scope 用例（隔离性+召回不串）。

### B2 档案双层存储（DB 行 + 磁盘家 + 版本快照）

- **表**（落点：独立 `.data/` SQLite，对齐 delegations/projects 惯例；字段细化方案定）：
  `partners`（id **uuid**、name、status、soulVersion、canonicalSessionId 唯一）+
  `partner_versions`（SOUL 正文冻结快照 + 能力 JSON——**任务启动认版本号，整轮不变，
  改完下一轮生效**）；
- **磁盘家** `.data/partners/<id>/`：`SOUL.md` / `memories/USER.md` / `workspace/`（唯一默认可写区）/
  `memories/` / `skills/`。单槽 64KB 上限；全原子写（临时文件+rename）；播种幂等，
  SOUL.md 最后写=家建好的标志；
- **权限边界**：模型的原始文件工具只挂 `workspace/`；memories/skills 的写工具是**新工具，
  必须进 `WRITE_TOOLS` 过 `readOnlyBlockReason()`**；家目录不整体可写；
- 伙伴创建/暂停/删除是**用户操作**（HTTP 端点），不走模型；对外 id 一律 uuid。

### B3 例行任务引擎（RoutineEngine 整包移植）

- cindy `routine-engine.ts` 783 行纯逻辑、deps 注入，直接适配：执行回调 = 起一个 Harness
  会话轮；`sessionMode` persistent（固定专线会话）/ fresh（每次新会话跑完关，空壳回收）；
- 触发四种：cron / interval / once / **event**（事件源 = 我们的会话状态变化 + 派单回执事件；
  24h 回执去重 + originRoutineId 防自环；OR 命中合并同一次执行）；
- 可靠性铁律照抄：终态落盘失败期间后续触发只能排队不能执行；重启 running→interrupted
  **不自动重放**；每规则串行 lane；伙伴忙 deferred 30s；
- **mock 不空转**：`LLM_PROVIDER=faux` 下例行任务必须走真实 durable 会话链路 + 假模型。

### B4 模型候选链（~100 行纯函数）

- 伙伴档案存 ≤5 条候选路由，主模型**不可用**（连接/鉴权/配额/容量/模型缺失）才切用户
  显式配置的下一项；**三种情况不切**：额度耗尽（切了同死）、用户主动断开、权限拒绝/
  上下文超限（切了掩盖真因）；fallback 只改当前轮，不暗改档案；
- **密钥纪律**：链项里的凭证引用只存 env 名（keyEnv 模式），不存值——照抄我们 providers 的
  现行口径，不学 cindy 存完整连接。

### 契约影响（硬约束"契约只有一份"的执行顺序）

1. 先改 `ts/packages/shared/src/index.ts`：PartnerProfile / PartnerVersion / Routine /
   RoutineRun 的 Zod schema + REST 端点形状 + SSE 事件类型；
2. 同步 `docs/基线文档/接口文档.md`（新 § 伙伴与例行任务）；
3. 再改两端实现；**手机端本批不消费新端点**（契约兼容即可，不破坏现有手机链路）。

### 验证

typecheck；memtest（B1）；新 `partner` 探针 + `routine` 探针（真起服务+真 HTTP：建伙伴→改
SOUL→下一轮生效、建例行任务→cron/事件触发→faux 链路跑通→重启 interrupted 不重放）；
`providers` 探针（B4 切链）；全量 `pnpm probe` 不回归。

## 五、批次C：主动性与自主审批（默认关闭）

**总开关**：`AUTONOMY_ENABLED` **默认 false**——这批的全部行为在 false 时必须为零
（不装观察表、不发事件、不弹卡）。

### C1 任务观察层（taskWatch 移植）

- 纯程序级状态表盯会话状态/终态/派单回执事件，六类事件照抄：stuck（无活动超时）/ waiting
  （等审批）/ errored / usage-limit / finished（须模型主动报"有最终交付"）/ sweep 兜底；
- **防风暴三件套**照抄：事件 id 含进入状态时刻（同状态只发一次）、同任务同类 24h 限 6 次、
  sweep 按 2h 时间桶；**伙伴/主会话永远不是自己的事件对象**（防自叫醒）；
- 内置"跟进"规则跑 persistent 例行专线；"没人在跟的等你"由宿主直接推手机，不经模型。
  （批次C细化 v1 调整：①内置"跟进"规则留多端阶段，v1 只做观察提醒不做跟随；②"推手机"
  改为写会话行——本仓库无服务器推送，手机拉 transcript 可见。见批次C细化 §一/§3.2/§3.4。）

### C2 自主轮高危审批（六类风险表接手机审批）

- 自主轮（例行任务/事件唤醒的轮次）上下文注入一行身份标记（autonomous/entrusted）；
- 六类操作必弹手机审批卡：调度命令 / 新建完全访问任务 / 授予常驻指令 / 删除自动化 /
  代主人回答权限请求 / 恢复暂停执行（50 行纯函数判定，细化方案里把六类映射到我们的
  工具与端点）；许可一次性消费，确认期间定义变更旧许可作废；
- 事件文案最小化（cindy 红线）：只有标题+一句话（≤140 字）+分钟数，不含正文与参数。

### 契约影响

SSE 新增 autonomy 事件类（走 seq 重放同机制）；手机审批弹卡复用现通道；接口文档回写。

### 验证

`phone-worker` 探针扩弹卡场景（自主轮高危→手机收到→批准/拒绝两路）；`AUTONOMY_ENABLED=false`
回归验证（零行为）；`pnpm probe` 全量不回归。

## 六、后置池（首批明确不做，理由留档）

| 不做 | 理由 |
|---|---|
| 子代理工具（模型派后台子任务） | chancellor 派活已覆盖"把活交出去"；子代理的审批/用量并账/进度流是一整条新链路，等真实需求 |
| auto-bridge 派活消息化（欠回报账本+自动回传） | 要动 chancellor 跨仓链路，动静大；A2 补差后回执已够可靠，等派活形态升级时一并做 |
| 群聊分工（多伙伴接力） | chancellor 已覆盖单主多子；接力编排是另一条产品线 |
| 云漫游 / 多设备伙伴 | 单机产品；但"能力引用随行、凭证不随行、权限档不随行"的判词在跨设备方案时引用 |
| 伙伴间互发消息 | 防风暴复杂度高（DS-Bot 的上限体系全为此设）；事件驱动只唤醒一个跟进者已够 |
| 公网触发 / IM 渠道绑定 | 安全面大、需求未现 |
| 伙伴专属上下文压缩 / 回复后复盘 | cindy 明确废除；整理只走夜间学习（若做，也走宿主校验+撤销备份） |

## 八、登记"刻意没有"

本蓝图落地后，`系统架构.md`"刻意没有的"补一条：**伙伴不做公网触发、不做伙伴间互发、
不做回复后复盘、自主跟进默认关闭**——与后置池一致，防止后来者当缺失去补。
