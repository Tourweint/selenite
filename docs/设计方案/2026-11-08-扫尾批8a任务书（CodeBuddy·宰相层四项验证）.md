## 四项逐一实测

1. **Windows 下 `pid` 存活判断是否可靠**：造"pid 已被回收后复用"的场景（起进程→杀掉→立刻起别的进程占同 pid 的概率低，改用"杀掉后 process.kill(pid,0) 行为"实测）——结论写清：现用判法在哪类情况下会误判活/死。
2. **`harness.resume()` 遇到未收尾提交是否会被新输入顶掉**：faux 会话里制造"未收尾提交"（对照 durable 语义：submit 后未跑完），再 resume + 新输入，观察旧提交命运（顶掉/排队/报错），记录真实行为。
3. **worktree 残留清理**：真起一个 git 项目派单（CHANCELLOR_TASK_ISOLATION 非 direct），正常完成、失败、崩溃模拟（杀进程）三条路各走一遍，查 worktree 目录残留情况与清理时机。
4. **60% 阈值下"压缩还是换段"的判定准确率**：构造逼近窗口 60% 的会话（faux，注入长上下文），观察 D12 的实际走向（换段=交接笔记 handoff.md / 压缩），重复若干次统计，结论给"判定是否如设计"。
