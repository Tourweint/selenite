# 2026-11-17 新建对话选目录 + 派活工作目录

> 一句话：把"先选当前项目、再自动挂载"换成"新建时直接选目录"；总管建 worker 走派活，加两个字段。

## 结论

| 事 | 做法 |
|---|---|
| 新建 worker 对话 | 输入框左下角、加号旁边一个「选项目」pill（用户 2026-11-17 拍板的位置）：选项目即把该项目主文件夹定为会话 cwd；不选沿用「当前项目」。`POST /api/v1/agent/chat` 的 `dirPath` 承这个值。服务端校验"目录存在 + 落在已登记根集合内"，反推出所属项目（最长根匹配；推不出就只绑目录、不绑项目），写成会话 cwd。不传 `dirPath` 时行为与现在逐字节一致。 |
| 派活 | `delegate` 加 `workdir`、`permission` 两个字段，**不新建工具**。`workdir` 相对 `project` 主文件夹解析，绝对路径也收，但必须落在已登记根集合内；`permission` 走 `EmployeeProfile.permission`（read / edit / full）。 |
| 总管建 worker | 仍走 `delegate`。总管只要在派单里填 `project` + `workdir` + `permission` 即可，不需要新工具。 |

## 为什么现在这样不行

- 新建 worker 的目录来自全局单值 `currentProject()`：用户得先在界面上"选中项目"，会话才自动挂到主文件夹——多一步，且这个全局值随手可改（2026-11-17 早上那次事故就是它被手滑改了）。
- 派活只能指定项目，不能指定项目里的哪个目录；工具权限只能由全局 executor profile 决定，总管没有按单说话的余地。

## 边界与取舍

- **不放开 path-guard 边界**：`dirPath` 与 `workdir` 都必须是已登记根（主工作区 / 非归档项目根）内的目录。选目录不等于选权限。
- **允许"只选目录、不绑项目"**：目录不属于任何项目时，会话 `ChatProjects` 不写；记忆走全局 / 执事挂载。这是"直接选目录"的必要代价。
- **`dirPath` 只在新建 worker 生效**：续话带上它 → 400，不隐式改 cwd（会话 cwd 是创建时快照，2026-11-13 的口径不变）。
- **`workdir` 只影响这张单**：落 `ticket.options.workDir` 快照，续跑沿用；不改项目登记。
- **`permission` 只对支持权限参数的雇员生效**（Claude / Codex / OpenCode）；CodeBuddy / Qoder 仍全权（chancellor 现有口径）。

## 回滚

- `CHAT_DIR_PICK=false`：`dirPath` 一律不生效（回到"只认当前项目"）。
- `DELEGATE_WORKDIR=false`：`workdir` / `permission` 字段收下但不生效（不改变旧派单）。

## 这条会怎么错

- 前端目录选择器如果直接调文件系统树，可能把整盘暴露出来；只列登记根 + 一层子目录，深层用路径输入。
- "只选目录不绑项目"的会话，项目记忆是空的——用户可能以为选了目录就自动带上记忆，需要在 UI 上明说。
- `workdir` 落在项目根的**子目录**时，`snapshotDeclaredPaths` 仍按项目根拍快照（验收口径不变），大项目会更慢。
