## 一、A10 附件/图片（契约级）

### 契约（shared，唯一 schema 变更点）

- `ChatMessageSchema.content`（shared/src/index.ts:23）：`string` → **`string | Part[]`**，
  `Part = { type:"text"; text:string } | { type:"image"; mimeType:string; data:string }`
  （data=base64，对齐内核 pi-ai 的 `ImageContent`，条目层零改动）。旧客户端纯 string 照旧（union 兼容）。
- 回读：`TranscriptMessageSchema`（:114-127）加可选 `images?: [{mimeType, data}]`（文本仍走 `text`，渲染向后兼容）。
- **SSE 不动**：delta/thinking 本就是输出侧纯文本；附件是输入侧，不进任何事件帧。

### 服务端行为

- `index.ts:688` 取"最后一条 user"处：content 为数组 → 文本部分拼接为 `text` 传 chatStream，图片部分随 parts 下传；
  `agent.ts` chatStream 提交改 `submit({type:"input", content: parts|text})`（内核原生收，`UserMessage.content: string | Parts`）。
- 限制：单图原始 ≤ 8MB（base64 后 ~10.7MB）、单条 ≤ 4 图、纯图片无文本允许；超限 400 带说明。
- **不新增 blob 存储**：图片 base64 直接进 durable 条目（会话库体积增长 = 已知边界，登记）。

### 前端（web）

- composer：粘贴/拖拽/选择器三入口 + 缩略图预览 + 可移除；占位按钮（index.html:317）接真。
- 回读渲染：user 消息带 `images` 时渲染缩略图（点击看大图，纯前端 lightbox）。
- **手机侧本批不做**（后批；契约 union 天然兼容）。

### 回滚

`AGENT_ATTACHMENTS=false` → 服务端对 parts content 回 400（指引用文本），前端隐藏附件按钮；schema union 保留（无害）。

## 二、A11 编辑重发（B 组 fork/rewind 透传的落地形态）

### 语义决策：走 `fork(at)`，不做"就地改写"

- 内核 append-only、无 truncate/edit；两条路 = `fork(at)`（复制新会话，内核一等 API）vs head/ContextEdit 写提交（就地改活动上下文，语义需自证）。**主选 fork**：零内核风险、语义清晰（老会话完整保留）；"真就地重写"登记为将来项。
- **编辑重发** = `fork(最后一条 user 条目之前) + submit(新文本)` → 产生**新会话**；前端 `openConversation(新id)` 无缝切换，用户感知就是"那条话改了重说"。老会话不去删（登记：会在列表留一条分叉前的旧会话——**已知边界**，用户可手动移除）。
- 手动 compact 已由批 1 落地，本项不重复。

### 契约

`POST /api/v1/agent/chat/:conversationId/edit`，body `{ "messageId": string, "text": string }`：
- 校验 messageId 属于本会话且是 user 消息 → fork 到该条目之前 → 新会话提交新文本（走 chatStream 主链路，SSE/用量/记忆全继承既有行为）；
- 返回 `202 {ok:true, conversationId:<新uuid>}`（流式响应在新会话上收）；消息不属于本会话 / 不是 user / 会话在跑（running 409，同插话口径）。
- 回读帧/`GET messages` 的 message id 已存在（前端有 messageId 才能定位编辑点——侦察确认条目 id 可达，实现时核对投影字段名）。

### 前端（web）

- 自己发的最后一条 user 消息 hover 出「编辑」→ 行内改为输入框 → 提交 → 新会话无缝接管；其余历史消息不提供编辑（登记刻意没有）。

### 回滚

`AGENT_EDIT_RESEND=false` → 端点 404、前端不渲染编辑入口。
