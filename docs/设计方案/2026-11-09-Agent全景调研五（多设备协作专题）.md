## 〇、人话版结论

1. **多设备协作有三条技术路线**，行业里各有人做：①**能力下沉**（DSH-Android/Mika：agent 跑在手机上，
   直接操作手机 App）；②**遥控**（dsh-Go/DS-Bot 桌面/我们手机 worker：手机是瘦客户端，agent 在电脑）；
   ③**能力代理**（mobile-mcp：电脑上的 agent 经 MCP 操控手机）。我们现有路线=②+中继矩阵，
   将来若要"手机上的活手机办"，①③是扩展面。
2. **pinekin 是"会话连续性"的独立流派**：跨 7 家 AI 客户端读会话→打一包"不绑定目标 App 的 Markdown 接续文件"
   →粘贴到下一个 App 接着聊。它的三条产品纪律值得抄：**默认不存正文（不是档案库）**、
   **状态如实（部分可读不冒充完整、复制成功≠对方收到）**、**长会话分段加载不拒读**。
   对我们的直译：执事/派单的"接续"（resume ticket / 上游产物路径注入）已有同构；缺的是"跨 harness 迁移"
   （将来换机/多机时，一份接续文件就是全部状态）。
3. **OpenCLI 把"工具可靠性"做成了契约**：统一 JSON 返回 `{ok,data}/{ok:false,error:{code,message,hint}}`、
   日志走 stderr、错误带 hint——与 gstack"错误写给 AI 看"同族。我们工具的错误返回没有统一形状（各工具自定义）。
4. **magpie 的配额切换**=我们模型候选链（B4）已落地同构，无增量；它多一个"账号池轮换"维度（我们刻意没有，
   单 key 边界已登记）。

## 二、三条路线与我们现状对照

| 路线 | 代表 | 适合的活 | 我们对应 |
|---|---|---|---|
| ① 能力下沉（agent 在手机） | DSH-Android、Mika | 操作手机 App、随手拍随手记、离线 | 无（手机是瘦客户端）——**lifediary 记录场景其实最贴近这条**（记录发生在手机上） |
| ② 遥控（agent 在电脑） | dsh-Go、DS-Bot 桌面、我们的手机 App | 重活（文件/长任务/大模型） | ✅ 现行（HTTP+SSE+配对） |
| ③ 能力代理（电脑 agent 操控手机） | mobile-mcp | 电脑上的 agent 帮忙操作手机（自动化测试/群发） | 无——将来若做"手机 worker 执行体"，mobile-mcp 的无障碍快照路线是现成参考 |
| ④ 中继/矩阵（多机互联） | cindy 自建中继、我们哑中继+设备矩阵 | 多台电脑/跨网 | ✅ 现行（主机优先制/busy 位/auto 决策器） |

**判断**：我们的"记录"主场景（手机随手记）目前是②路线服务①场景——每条记录都要电脑在线。
若将来做"离线记录后同步"，方向是①或"手机本地队列+联网回灌"（数据面下沉，agent 面不上手机）。
🚧 DSH-Android/dsh-Go 回报后补充两家的具体取舍。

## 三、pinekin：会话连续性的产品纪律（本轮最值得抄的产品观）

- 形态：读已授权客户端本地会话 → 生成**一份接续 .md**（角色、原文、读取说明俱全）→ 复制粘贴到任何 App；
- **"它不是档案库"**：默认不复制、不保存正文，不自动建会话、不自动发送——工具只做搬运；
- **状态如实三条**：不支持的会话标注原因；**部分可读不冒充完整**；**复制成功不等于目标已接收**；
- **长会话不拒读**：列表只读元数据、点开才解析、分段加载；
- 安全：只读固定位置（macOS 沙箱 / Windows 只读 VFS）、历史 Markdown 白名单渲染、不执行历史命令。
→ 对我们的直译：
1. **导出接续文件**：我们的会话导出（§2.5 Markdown 导出）可升级为"接续文件"形态——带角色标注+读取说明+
   记忆/偏好摘要，用于换机或给其他 agent 用（S-M）；
2. **"状态如实"三条直接进接口文档口径**（我们导出/回读的边界描述）；
3. 七类来源的"本地会话读取器"是将来"把微信/chatlog 生活流导入"的同一类工程（授权固定位置、只读、白名单渲染）。

## 四、OpenCLI：工具契约与适配器工程

- **统一命令契约**：默认 JSON `{ok:true,data}` / `{ok:false,error:{code,message,hint}}`，stdout 数据/stderr 日志分离，
  `list` 返回分页能力清单——**agent 用同一种方式消费所有工具结果**；
- 三层能力：内置适配器（B 站/知乎/小红书…确定性命令）+ 通用 browser 原语（任意页面）+ **适配器创作技能**
  （opencli-adapter-author：从侦察→字段解码→代码→测试全流程带教）；
- 会话管理：`--session` 隔离页面作用域、登录保活。
→ 对我们的直译：我们 17 个工具的返回形状各自为政；统一 `{ok,data|error{code,message,hint}}` 契约是
S-M 级改造，收益是**模型处理错误结果的行为一致性**（hint 字段=告诉模型下一步干什么，gstack"错误写给 AI"的
同族实践）。将来接浏览器自动化时，"适配器+创作技能"的分层值得照抄。

## 五、手机执行体三方对照：mobile-mcp / DSH-Android / Mika

| | mobile-mcp | DSH-Android | Mika |
|---|---|---|---|
| 形态 | MCP 服务器（电脑 agent 调用） | DSH 跑在手机（profile+插件+17 补丁） | 独立 Android 助理 App |
| 感知 | **无障碍快照**（首选）或截图坐标 | 无障碍 + 设备工具组（deferred 加载） | 无障碍 + **画面指纹**（元素列表哈希） |
| 操作 | 快照定位→点按/输入 | 引擎生命周期完整（重启退避/熔断/断网挂起） | **虚拟屏**（createDisplay ≤10fps）+ 自连 ADB |
| 高危授权 | — | approval seam（fail-closed） | **ConfirmationGate：同意绑定屏幕证据**（系列四 §9.2） |
| 对我们 | 将来接 MCP 时的手机能力面 | **手机 worker 生命周期的直接范本**（系列五 §7.1） | "替用户操作 App"的完整路线图；ConfirmationGate 是闸门下一代语义 |

结论：我们的手机 worker 现在是②路线（遥控电脑）；若做"手机上的活手机办"，**感知学 DSH-Android、
执行学 Mika、授权学 Mika ConfirmationGate、接入学 mobile-mcp（观望 MCP 口径不变）**。

## 六、cindy 中继与我们的设备矩阵（已有调研结论引用）

cindy 自建中继三原则（2026-11-05 调研，已进我们多端方案）：哑路由+盖章 src、通道白名单默认拒绝、
设备签名防冒充；凭证只存哈希。我们的落地（2026-11-05 三阶段，探针全绿）：中继哑路由+盖章 src、
事件镜像走重放库轮询、矩阵派活轮询回报+离线 fail-fast、执事路由 CAS 在中继+降级 fail-closed、凭证不随行。
已知边界：事件重放库只收 HTTP 发起轮次；远端锚点/执事专线会话在 durable 列表快照的可见性未定。
→ 本轮无新增；dsh-Go 的"遥控电脑 DSH"协议回报后与我们对表（配对/心跳/任务流三处）。

## 七、DSH-Android / dsh-Go（DeepSeek 家族回报）；Mika 🚧

> 完整报告：`.research/deepseek-family.md`。

### 7.1 DSH-Android：手机执行体的生命周期范本

DSH-Android 把 harness 引擎完整跑在手机上（profile+插件+17 个补丁，不 fork）。对"手机 worker"最可抄的是
**引擎生命周期**一段（ENGINE-CONTRACT.md）：
- **重启策略包**：RestartPolicy 1/2/4s 指数退避 + 10 分钟 3 败熔断——我们 MyGo 壳的探活守护（10s 探活、
  失联重拉）可借"退避+熔断"参数，防止"服务起不来时无限重拉"；
- **崩溃 resume 提示**：恢复后向模型提示"别重做已成功的"（**每任务限一次**）——与我们"自动续跑最多一次
  resumeCount"（架构 §7）完全同构，互证设计正确；
- **断网进入"等待网络"状态**：不持唤醒锁（省电），网络恢复自动续——手机端弱网语义的现成状态机；
- **唤醒锁随会话续期**：有活才持锁，空闲释放；
- **"防骗"注入**：模型嘴上说"下一轮自动继续"但 todo 有未完项 → 注入 android-continue 提示（每轮 ≤8 次），
  turn/end 前落 turn-outcome 记录驱动 App 的"继续"结束卡（:352-374）——**"模型承诺"与"账面事实"对账**，
  与我们"完成由证据定义"同族，是手机端防话术跑飞的具体机制。
- **延迟加载工具**（deferred tools + load_tools）：全量设备组一句"Hi"~19k token（90% 是 schema），按需加载后 ~5k
  （详见系列二 §8.3）。

### 7.2 dsh-Go：遥控协议的纪律清单

dsh-Go 是安卓客户端+遥控电脑 DSH（连 Web API，不 fork）。Remote 协议五条纪律，逐条对表我们的手机通道：
| dsh-Go 纪律 | 我们现状 | 判词 |
|---|---|---|
| Noise IK E2EE + **指纹 pin fail-closed**（键变更在任何 socket 打开前即拒） | 配对令牌只存 sha256，无指纹呈现 | 补"指纹呈现"（人眼核对）与键变更拒绝（S） |
| **两段式配对**：扫码 + 人往电脑输 8 位码，**手机绝不代确认** | 一次性配对码→换长期凭据 | 同构；"两端都有人确认"更严，登记为可选升级 |
| `CONNECTION_REPLACED` 终态粘滞不抢连接 | — | 防双端互抢连接的粘滞终态（S，等双端登录场景） |
| **compact history**：历史工具参数/输出转摘要，模式与 client 生死绑定 | 无（transcript 全量回读） | 手机弱网回读优化（M，等真实痛点） |
| 超时单一真源 + App 侧 deadline−5s 必答 | 各处散配 | 手机 worker 通道适用（S，见系列二 §8.2） |

## 九、不建议抄 / 暂不抄

| 机制 | 理由 |
|---|---|
| mobile-mcp/MCP 全套接入 | MCP 观望口径不变（2026-11-04 登记）；出现第一个"想接的外部工具"再立项 |
