## 一、两个参考项目怎么处理工具

- **DS-Bot**：普通工具**不进对话**，只在底部一条 activity row 里换短语（`ds-bot/src/client/activity-row.js`、`cells.js:1110-1260`）。回复一开始流式，row 就让位；工具结束，row 消失。只有 `ask_user`、`send_to_bot` 这类需要人看的调用才在正文里留一行。它的强项是"安静"。
- **ZCode**：工具压成**一行摘要**（`ToolCallBlocks/ToolSummaryRow.tsx`、`ToolLayout.tsx`），有 icon、kind、target、状态、diff count；详情点开才有。运行中用文案扫光 + 64px 进度条表达，不用转圈图标（`ToolCallProgressIndicator.tsx`）。它的强项是"一行能读"。

咱们现在的"工作过程块"介于两者之间：有步骤行，也有"说"行，但工具和中间话混在一个块里，工具一多就吵；收尾后整块折成一行，但运行中的层次不够清楚。

## 二、原型与三轮反馈

| 版 | 名字 | 核心 | 运行中 | 点击后 | 状态 |
|---|---|---|---|---|---|
| A | 安静活动行 | 工具不在正文留痕，底部一条活动行换短语 | 活动行：圈环 + 短语 + 步数 | 展开「已工作 Ns · M 步」总结 | 保留参考 |
| B | 分组线程 | 竖线串起"话"和"工具"，每段一组 | 节点脉冲、竖线流光 | 每组折成 chip | **用户排除** |
| C | 工作卡堆栈 | 每个工具一张卡，运行展开、完成压缩 | 卡展开命令 + 进度条 | 卡片压成一行 | **用户排除** |
| D | 悬浮胶囊 | 执行状态收进输入框上方胶囊 | 胶囊 + 进度点；说话时缩成小圆点 | 胶囊变「已工作 Ns」→ 向上抽屉 | 方向保留，浮框不要 |
| E1a | 灰块 + 内联详情 | E1 主界面只留灰块，不写步数/耗时 | 运行中的小块变色 + 底边扫光 | 在那一行下面原地展开详情（命令/用时/输出/diff） | **第三轮新增，默认** |
| E1b | 灰块 + 附近小窗 | 同上，主界面只留灰块 | 同上 | 灰块旁边弹一张详情小卡，不挤正文，点外/Esc/滚动关闭 | **第三轮新增** |

### 三轮反馈（2026-11-13，以此为准）

- **第一轮**：B/C 明确排除；只看 A/D。D 方向更好，但"不太美观"。
- **第二轮**：D 的整体方向保留；**不喜欢底部正在进行的悬浮小圆框/浮起来的框**；工具调用作为"小灰色小块"是好的；要结合 A。
- **第三轮**：**E1 定稿**；主界面的"走了几步 / 进行了几秒"这类解释文字太多，去掉；**点灰块应该能看到具体细节**；细节表示待定——附近小窗还是原地展开。已做 E1a（内联）/ E1b（小窗）。

### 定稿（2026-11-13 第四轮）

- **E1a / E1b 都保留，进设置让用户选**：设置 → 外观 新增「工具详情」一行，`原地展开`（默认）/ `附近小窗`。纯前端 localStorage，不走服务端开关。
- **详情面板限高**：`max-height` 约 260px，超出在面板内部滚动。思考内容、长输出、长 diff 一视同仁。
- **灰块折叠**：超过 8 个只显示前 8 个，其余收进「+N」，点开铺全部；运行中的那块始终可见。
- **主界面不写解释文字**：步数、耗时只进详情，不在块上、不在消息里再写一遍。

### 第三轮方向：E1a 内联为主，E1b 小窗备选

- **ZCode 的既有做法就是"点摘要行 → 原地展开"**（`ToolLayout.tsx` 用 `Collapsible`，`ToolContent` 在摘要行下方，展开/收起 300ms）。详情里是 input/output 分区，长内容在内部滚动。这是 E1a 的直接依据。
- **DS-Bot 不是每个工具一个小窗**：它的详细面板是"某个 Bot/会话"的侧抽屉（`details-drawer.js`），普通工具调用根本不进正文。所以"附近小窗"在参考项目里没有直接对应，属于我们自己的轻量变体。
- **推荐 E1a（内联）**：与 ZCode 同路；输出、diff 这类内容可能很长，内联面板可以在正文宽度里滚动，不会盖住别的消息；点开的灰块保持 accent 边框，和面板的对应关系清楚。代价是展开会把下面内容往下推。
- **E1b（小窗）**：适合"只想瞥一眼"，不挤正文；但会盖住附近内容，滚动/流式时不稳定，长 diff 也不舒服。可以作为窄屏或快速查看的补充。
- 待定点：E2 的行内活行要不要进一步缩成"小块内的一行字"（那就接近 E1）；灰块要不要显示耗时；每段末尾的「N 步 · Ns」要不要保留。

### 设计期推荐：B（分组线程，已被用户排除）

理由：

1. 它直接解决你说的"执行了什么 → 补一句 Agent 的话 → 又执行了什么"：**话留在正文，工具按段折成一行**，阅读顺序变成"话 → 2 步 → 话 → 2 步 → 总结"。
2. 运行中仍然看得见过程：节点、扫光、竖线流光都在，不是 A/D 那种把过程藏起来。
3. 实现成本中等：现有 `createWorkPanel` 的 start/end 事件已经够用，主要是把"一个面板"拆成"按说话切组的多个组"，加竖线与折叠动画；不需要重写工具链路。
4. 收尾后的观感最接近 ZCode：工具是低调的脚注，Agent 的话是主角。

**可选的组合**：B 作为默认；A 的"活动行"作为长会话的安静模式（或"工具活动"开关的第二档）；D 的胶囊以后可用于手机端或"专注模式"；C 留给需要逐步审计的干活场景。

## 三、明确不做（本轮原型）

- 不改生产代码、不改契约、不加依赖。
- 不搬 DS-Bot 的 mascot/fidget/poke。
- 不做逐帧高度动画；折叠用 grid-rows / WAAPI，单次 ≤320ms。
- 不在原型里接真实 SSE；剧本是假数据，只为比较表现。
