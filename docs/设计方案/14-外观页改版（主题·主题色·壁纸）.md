# 外观页改版：主题 / 主题色 四版草图 + 壁纸扩展

> 一句话说清这篇回答什么问题：设置→外观里「主题 + 主题色」这一块怎么重排才好看，四版各是什么路数，以及要为「换壁纸」把这块扩到什么形状。

## 结论

1. **主推 B（大预览 + 右侧列表）**。理由不是因为它最花哨，而是它把「选主题」这件事变成了「看效果」：左边那张预览用的就是我们真实的气泡、工具块、composer 样式，右边四行只负责切换。Cindy 的外观页也是这个路数（主题家族列表 + 模式分段 + 壁纸 + 字体），信息架构可以直接对齐。
2. **A（缩略界面卡）作为轻量备选**。只换一个分段控件，不动页面结构，改动量最小；缺点是四张小缩略图在 1280 宽下每张只有 270px，只能看出「深/浅」，看不出「纸」和「炭」的差别。
3. **C（明暗分段 + 两个家族）需要先拍板一件事**：把四套主题拆成「纸（米黄/暖白）× 夜（靛蓝夜/炭黑）」两族 + 浅/深/跟随系统。这是 Cindy 的模型（`ThemeSelection = { mode, familyId }`），语义最干净，但会让「主题」从 4 张卡变成 2 组 × 2 张，且跟随系统要能真的跟着系统深浅走（我们目前没有这个能力，得靠壳侧或 `prefers-color-scheme`）。
4. **D（材质色带）留着当"色板视图"**，不单独做一版：它的价值是让人一眼看出四套主题的"材质差"，但看不出信息层级，单独用会像调色板工具。
5. **壁纸按 Cindy 的能力口径做，但先只做静态**：无 / 内置 / 自定义图三选一 + 可见度 + 模糊两条滑杆；动态（内置场景动画、自定义 MP4）列为第二期，理由见下文"能做什么"。

## 四版对比

| 版 | 结构 | 一眼看懂什么 | 改动量 | 主要缺点 |
|---|---|---|---|---|
| A 缩略界面卡 | 四张 270px 卡，每张一个微缩界面 + 名字/单字标签 | 深/浅、有没有侧栏 | 小：只换 `settings-router.js` appearance 分支里那一段 | 缩略图太小，"纸 vs 暖白"几乎分不出来 |
| B 大预览 + 右侧列表 | 左 400px 真实预览 + 右四行列表（三段色带 + 名称 + 浅/深标签 + 圆点） | 换这套主题之后长啥样 | 中：新增一个预览面板，纯前端 | 占竖向空间大（约 220px + 卡片标题）；窄窗口（手机端）要降级成上下堆叠 |
| C 明暗分段 + 两家族 | 顶部浅/深/跟随系统，下面「纸」两格、「夜」两格 | 先定明暗，再定气质 | 中大：要动主题模型（家族 × 模式） | 需要 `prefers-color-scheme` 或壳侧系统深浅通知；家族划分是我们自己定的，用户可能不认这套命名 |
| D 材质色带 | 四条竖色带（底/卡/字/强调） | 四套主题的材质差 | 小 | 没有信息层级，最像色板不像设置项 |

四版的部件与颜色全部取自仓库现有 token（`style-01-tokens.css` 的四套主题 + 三档 accent），所以不存在"草图好看、落地变样"的落差。

## 和 Cindy 的对照

| Cindy | 我们 | 这轮怎么做 |
|---|---|---|
| Theme（家族列表，带 Light only / Dark only 标记）+ Appearance Mode（Light/Dark/Auto） | 四套并列主题，没有模式维度 | 选 B/A：先并列；选 C：拆家族 + 模式 |
| Wallpaper：None / 内置场景 / 自定义（PNG·JPEG·WebP ≤20MB、MP4 ≤100MB）+ Display 静态·动态 + Visibility 0–100% + Blur | 完全没有 | 按三选一 + 两条滑杆先落地，动态缓一期 |
| Fonts：UI / Code / Terminal 三套 + 字号区间 | 只有「字体：修改」一个按钮 | 不在本轮；等壁纸落地后，把字体也拆成"界面字体 / 代码字体"两行 |
| density 0.75–1.25、motion 0–2、Reply Animation | 无 | 不做。我们的动效 token 已经写死"单次不超过 360ms"，再开一个全局倍率只会让页面抖 |

## 壁纸怎么落（我们的技术栈）

Cindy 是 Electron，壁纸走 `cindy-media://` 协议直读本地文件。我们是 Go 壳 + 本地 web 服务，没有这类协议，所以走**服务端存一份 + 端点回传**：

| 环节 | 做法 |
|---|---|
| 存储 | `.data/appearance/wallpaper.<ext>`，单文件覆盖写；元数据（是否启用、可见度、模糊、显示模式）进现有的 `appearance.json` 一类设置文件，跟主题/主题色同源 |
| 上传 | 浏览器上传走 `POST /api/v1/appearance/wallpaper`（multipart，校验 MIME + 体积上限）；桌面壳里用原生文件选择器拿路径，复用壳已有的路径读取能力直接落盘 |
| 读取 | `GET /api/v1/appearance/wallpaper` 回传字节 + `ETag`；前端把它写进 `--wallpaper-url`，避免每次设置完重新解码 |
| 铺法 | `body::before` 一层固定背景（`background-image: var(--wallpaper-url)`，`cover`），可见度 = 这层的不透明度；气泡、卡片、composer 保持不透明，只让**空隙**透出壁纸 |
| 模糊 | 壁纸层自己 `filter: blur(var(--wallpaper-blur))`，同时把图放大 8% 避免边缘露白；模糊值按 0–24px 取，0 就是关 |
| 可见度 | 0–100%，默认 38%（全不透明的壁纸会把米黄纸的"纸感"冲掉，见截图） |
| 性能 | 静态图无成本；`filter: blur` 在移动端 GPU 上会掉帧，所以**只对静态图开模糊**，视频/动画场景默认不叠模糊 |
| 不做动态的理由 | 设备上放 MP4 要处理 loop、静音、窗口隐藏暂停、系统减弱动效，还要避免和"逐字淡入"抢帧；先做静态，等有人真的抱怨没有动态再说 |
| 回滚 | `AGENT_APPEARANCE_WALLPAPER=0` 关掉整块（按 `AGENTS.md` 的规矩，新能力给一行 env 开关） |

一个必须先想清楚的点：**壁纸和四套主题的兼容**。靛蓝夜/炭黑上，浅色壁纸会把对比压没；所以壁纸层要跟主题一起取，切到深色主题时给壁纸压一层 `color-mix(in srgb, var(--bg) 55%, transparent)` 的罩，罩的浓度算进"可见度"里，而不是让用户在两种主题下各调一次。

| 项目 | 值得看什么 | 适合这轮哪一块 |
|---|---|---|
| Cindy（`reference/cindy`） | `help-knowledge/appearance.md` 的能力清单写法、`AppearanceDefinition` 的字段切分（主题/壁纸/字体/密度/动效各自独立） | 信息架构、字段命名 |
| open-claude-ui（`reference/open-claude-ui`） | Claude 设计系统的还原：无卡片化、hairline 分隔、低饱和强调色只落在交互态；仓库里有 `对比展示.html` 记录它的对照方法 | 让"纸感"更克制：少一层卡片、少一条描边 |
| oil-ui（`reference/oil-ui`） | 它是"给 AI 的设计方法论"skill，不是界面库。三条判据最有用：多个方向之间布局/字体/色彩/主图**最多共用一样**；预览出来后并排眯眼看明暗形状；最后一轮只做减法 | 用来审这四版——A 和 D 共用"平铺色块"，其实算半个同一方向，这也是我不推荐两条都做的主因 |
| lobehub（`reference/lobehub`） | 设置里主题色那类选项的成熟做法：色点 + 名称 + 即时预览，选中态只用一个描边环 | 主题色那一行的交互细节 |
| ZCode（`reference/ZCode`） | 用户已看过，外观页没有超出 Cindy 的东西 | 不学 |

`reference` 里剩下的大部分是工具、脚本、数据导出（`chatlog`、`wechat-decrypt`、`tdl` 等），跟外观无关，不用扫。

## 这条会怎么错

- **"好看"是主观的，四版可能一版都不中。** 真正的分歧往往不在版式，而在"要不要保留卡片"。如果四版都被否，下一步不是再画四版，而是先定一条：这块要不要做成"一整块卡 + 里面分行"，还是"搭在页面上的裸设置项"。
- **B 的预览面板是纯前端假数据。** 它用真实样式但不接真消息流，所以将来某次改气泡样式，预览可能跟主界面脱节。要么预览直接复用主界面的组件，要么在预览上标注"仅示意"。
- **壁纸会跟"纸感"打架。** 米黄主题的价值就在那层底色的暖度，压一张照片上去立刻变普通。所以默认可见度给到 38% 而不是 100%，且内置项里必须有一档"宣纸纹"这种几乎只是质感的图。
- **家族命名（纸/夜）是我替用户起的。** 用户认不认这套词，是 C 版唯一的真风险；B/A 不引入新词，只保留"米黄/暖白/靛蓝夜/炭黑"四个现成名字。
- **环境开关只加在壁纸上。** 主题版式改坏了没有开关可退——但版式是纯前端，`git checkout` 一个文件就能退，不值得再给一行 env。
