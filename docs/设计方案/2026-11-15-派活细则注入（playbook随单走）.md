# 设计方案 · 派活细则注入（playbook 随单走）

- 日期：2026-11-15
- 状态：待实施（本方案先落，下一轮实施）
- 需求方口径：Grok 小镇的 bot prompt 细节写得好，但那是"活法细节"，不该塞进执事人设——
  执事做成**区域领导**（管方向、派活、验收），细节作为**派活时注入给打手的提示词**。
  打手（worker 会话）生命周期短，细则必须**跟着单走**。

## 一、思路

- 执事家目录新增一份**岗位细则**（playbook）：他这一摊的活法细节（盯价格的 30/7 天节奏、
  邮件三档分类、周报三段式……）。平时**不进执事自己的提示词**（太长、缓存不友好），
  只在**派活时**拼进任务文本，跟着单注入给 worker。
- worker 生命周期短 → 不需要把细则教给 worker 记住；细则就是这一单的操作说明书，
  单结束即随会话退场，不占任何长期记忆。

## 二、链路（零 chancellor 契约改动）

- 派活的任务文本在**工具层**拼：`DelegationKickoff.requirement` 就是调用方拼好的字符串
  （2026-11-15 核对 delegation-delegation-kickoff.ts）。细则注入 = 拼进 requirement：
  `requirement + "\n\n【本单细则】\n" + playbook`。
- chancellor 拿到的 requirement 自然带细则，worker 的任务里就有；**chancellor 仓库零改动**。
- 注入点：delegate 工具实现处（派活方为总管/执事时，读取**该执事**（或发起会话所属执事）
  的 playbook）；总管自己派活时也可带自己域的细则（有则带）。

## 三、存储与界面

- 存储：执事家目录 `PLAYBOOK.md`（照 CONTRACT.md 模式：磁盘当前值，纯增量能力）。
  回滚开关 `PARTNER_PLAYBOOK=false` → 端点 404、派活不拼、卡片不渲染。
- 界面：档案页人格模块「岗位」组加一张**无开关卡「派活细则」**（点卡进弹层编辑，同契约弹层形态；
  摘要 = 字数或"没写"）。模板里大管家/巡官/日记官/书童四张带 playbook 种子（把 Grok 式细节
  写进种子——细则就是给打手看的操作说明，这里才需要具体到动作）。
- 上限：照契约 64KB 槽位护栏；建议软限 8KB（细则超长说明执事该拆岗了）。

## 四、明确不做

- 不做细则的自动生成/学习（那一档是员工学习模块的活）。
- 不做按单挑细则（一执事一份 playbook；多细则=多设执事）。
- chancellor 侧不动、不新增跨仓契约。

## 五、验证口径

- 单测：playbook 读写 + 派活 requirement 拼接（有/无/开关关三态）。
- 浏览器：档案页卡 + 弹层编辑 + 试跑派活看 worker 任务文本带细则。
