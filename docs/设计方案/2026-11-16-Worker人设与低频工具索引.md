## 一、Worker 人设：全局一份，可编辑

### 1.1 现状（2026-11-16 核查）

- Worker 人设是代码常量 `WORKER_PERSONA`（`agent/assist.ts`），一句话定位 + 三条行为 + 三条工具提示。
- 人设页（设置 → 人设）列表只有总管与执事；点 worker 会话的「人设」抽屉显示
  「它的身份由服务端固定，没有可改的人设」。
- Worker 默认固定前缀（活服务实测）：系统 642 token / 工具 7,127 / 技能 758，合计 ≈8,527；
  其中 persona 仅 179 token。

### 1.2 存储与默认值

- 文件 `.data/worker-persona.md`（纯文本，原子写，≤ 8KB；路径可用 `WORKER_PERSONA_PATH` 覆盖）。
- 文件不存在 / 空 → 回落代码默认 `WORKER_PERSONA`（**默认文案同时改写**，见 §1.3）。
- 新增 `worker-persona.ts`：
  - `workerPersonaDefault()` → 代码常量；
  - `readWorkerPersona()` → 文件优先，读失败/空回落默认；
  - `writeWorkerPersona(text)` → trim 后写；空串 = 删文件（回默认）；
  - `workerPersonaEditEnabled(env)`：`WORKER_PERSONA_EDIT=false/0/off` → 只读（PUT 400），provider 只读常量。
- `agent/assist.ts` 的 `personaProvider` worker 分支改成 `readWorkerPersona()`（每轮现读，改完下一轮生效）。
- `context-defaults.ts` 的 worker 分支同样走 `readWorkerPersona()`，默认开销页看到的就是当前正文。

### 1.3 默认文案（新增「任劳任怨」定位）

在原五句基础上补一句，其余不动（固定字节，改文案会打掉一次缓存）：

> 你是一个普通任务助手，负责把交到你手上的具体事情办完。
> **交代的事一定办到底：不推、不挑、不抱怨；办不成要说清卡在哪一步、缺什么。**
> 说话直接、克制、就事论事，给结论也给依据；不冒充总管，也不代表任何执事。
> 涉及真实文件、真实数据、真实日程或当前时间的事，必须先用工具去看，不许凭印象回答或编造；看不到就说明缺什么。
> 没有预设的私人档案，也不主动建立执事身份。
> 需要长期记住的事用 remember；想不起对方说过什么用 recall；要定时提醒用 set_reminder。

### 1.4 端点

- `GET /api/v1/agent/worker-persona` → `{ok, persona, isDefault, editable, limit, chars}`；`limit` = 8,192。
- `PUT /api/v1/agent/worker-persona` body `{persona}`：
  - 非字符串 / 超 limit → 400；空串 = 恢复默认（删文件）；
  - `WORKER_PERSONA_EDIT=false` → 400 带说明；
  - 成功返回同 GET 形状。

### 1.5 人设页 UI

- 设置 → 人设的列表**顶部**加一张「普通助手」卡（固定条目，不是执事行）：
  名字「普通助手」+ 一句「所有 Worker 会话共用这一份人设」+ 「全部 Worker 共用」标签。
- 点进去 `#/settings/partners/worker`（`currentPartnerProfileId` 的字符类已允许 `worker`）。
  `settings-router` 在 `profileId === "worker"` 时走新的 `renderWorkerProfilePage()`，不请求 `/partners/worker`。
- 这一页**只有两块**：
  1. 人设正文（textarea + 字数 + 撤销 / 保存 / 「恢复默认」）；
  2. 一句只读说明：Worker 不参与执事的人格模块 / 记忆召回 / 工具勾选（这些是执事专属）。
- 不要把人设页那套七节身份、人格模块、纪律、负责项目、工具卡复制过来。
- 顶部返回按钮回「总管与执事」列表。

### 1.6 明确不做

- 不做每 worker 会话一份人设（用户拍板「所有 Worker 用一种」）。
- 不做 worker 的人格模块 / 印象心情 / 纪律覆盖 / 工具勾选。
- 不改 worker 的其它注入（验证铁律、注入防线、当前项目、技能）——它们与总管共用同一份逻辑。

## 二、C：低频工具索引（`deferred` + `tool_search`）

### 2.1 机制（内核已支持，不引第三方）

- 注册时给低频工具加 `deferred: true`：内核**不把它放进请求**（`modelTools` 缺省 = 除 deferred 外全部）。
- 新增 `tool_search` 工具（非 deferred）：入参 `{name}`，返回
  `{output: [工具名 + 完整描述 + 参数摘要], control: {addTools: [name]}}`。
- 内核在这一轮工具跑完后把名字追加进会话 `modelTools.add`；**从下一轮起**完整 schema 才进请求。
- 追加在末尾、前面字节不动 → 缓存前缀不被打掉。

### 2.2 低频清单（8 个，用户拍板）

`routine_manage` / `partner_manage` / `group_manage` / `save_skill_advice` /
`partner_skill_write` / `propose_project` / `propose_topic` / `send_to_agent`。

预计省下 ≈2,600 token（实测口径），新增工具索引 ≈300、`tool_search` 自身 ≈150，净省 ≈2,150。

### 2.3 工具索引段（新 prompt section）

- 新 section key `tool_index`，**排在 `topics` 之后**（末尾追加；这是缓存前缀变化，记变更记录）。
- 内容 = 标题一行 + 每个 deferred 工具一行 `- name：一句话摘要`，
  并写明「要调用其中某个工具，先调 `tool_search({name})`，下一轮起它才可用」。
- 索引里**只列当前会话实际启用且未被取消勾选的** deferred 工具；一个都没有 → 整段省略。
- 开关：`AGENT_TOOL_INDEX=false/0/off` → 不注册 `tool_search`、不给任何工具加 deferred、
  不渲染 `tool_index`（一行回滚到 22 个全量工具）。

### 2.4 与「工具勾选」（B）的交互（必须处理）

- `modelToolCatalog()` 现在过滤 `deferred`；改成**包含** deferred 并标 `deferred: true`，
  人设页工具列表才能看到并取消它们；`enabled` 语义不变（可调用性）。
- `applyPartnerToolSelection()`：
  - 比较时只看**非 deferred** 工具（deferred 的加载状态不归它管）；
  - 写 `modelTools` 时**保留已加载的 deferred 名字**：
    `{ remove, add: 当前 agent.tools 里属于 deferred 目录的名字 }`，
    否则每次勾选保存都会把 tool_search 加载过的工具抹掉。
- `context-defaults.ts` 的 `defaultTools()` 仍不含 deferred（新会话初始前缀里确实没有它们），
  但要把 `tool_index` 段算进默认开销。

### 2.5 能力声明与闸门

- `tool-capability.ts` 新增 `tool_search`：`readOnly: true`、`destructive: false`、
  `sideEffectScope: "none"`、`riskLevel: "low"`、`needsApproval: "never"`、`concurrentSafe: true`。
  **不进 `WRITE_TOOLS`**（它只改会话工具面，不动工作区、不起进程）。
- `tool-capability.test.ts` 的双向集合等值会因此红 → 同步登记。

## 三、明确不做

- 不做按模型/供应商切词表的精确 token；不做工具懒加载的 UI 进度。
- 不做「自动判断哪些工具低频」（清单是代码常量，改清单 = 改代码）。
- 不把 `tool_index` 做成可编辑内容（它是工具目录的投影，手改会和注册表打架）。
- 手机端不改。

## 四、验证

- Worker：文件读写往返 / 空串删文件回默认 / `WORKER_PERSONA_EDIT=false` PUT 400 /
  provider 与默认页读到文件值 / 超限 400 / 人设列表出现「普通助手」/ `#/settings/partners/worker` 只渲染正文一块。
- C：`deferred` 工具不在 `context-inspect` 的工具列表里、`tool_index` 段列出它们；
  调 `tool_search({name})` 后下一轮该工具出现在列表且可调用；
  勾选保存后已加载的 deferred 工具不丢；`AGENT_TOOL_INDEX=false` 回到 22 个全量、无 `tool_search`、无索引段。
