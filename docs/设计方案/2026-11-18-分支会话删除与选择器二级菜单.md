## 结论

1. **选择器里的分支/副会话可直接永久删除**：一次危险确认，不输入标题，不先归档。
2. **可删范围**：执事/总管的 `role=side` 副会话；总管带 `ChatOrigins` 的分支副本。canonical 主对话、总管无来源的主对话、普通 worker 会话不动。
3. **有子分支的会话禁止直接删**：返回「先删掉下面 N 条分支」，不做级联。
4. **选择器按分叉关系缩进**：副本挂在母会话下面，主对话与无关副会话仍是顶层。
5. **画板不改**：一条会话 + 它的全部分支仍画在一张地图里——这是画板的用途，不是 bug。
6. **一个开关回滚**：`PARTNER_SESSION_MANAGE=false` → 平铺旧列表、无删除按钮、端点 400。
7. **归档页同步放行 side**（2026-11-18 追加）：已经归档掉的老副会话（例如空分支）也能在
   设置 → 归档里永久删除；canonical / 群 / 任务仍拒绝，有未归档子分支先拦（`has-branches`）。

## 为什么是"直接删"而不是归档

- 现状：副会话只能归档；归档页的永久删除又按 `kind` 挡掉所有 `partner` 会话（`durable-delete-plan-chat-deletion.ts` 的 kind 门槛），于是分支越攒越多、永远清不掉。
- 用户明确要"直接就删除"。分支是工作副本，不是身份承载（D29：canonical 才是身份代表），删掉一条副会话不会动人格 / 记忆 / 项目。
- 归档仍保留给普通 worker 会话（归档页那条两段式链路不变）；本次不给选择器加归档按钮，避免同一行出现两个"消失"动作。

## 为什么先拦子分支

- 分支关系存在 `ChatOrigins`，不存在 durable `parent`（D30）。一条分支再分叉时，子分支的 `origin.source` 指向它。
- 直接删母分支会留下"来源已不存在"的孤儿：母会话的地图里看不到子分支，子分支自己打开时会被当成根。
- 级联删除会把一次点击扩大成 N 条会话的永久删除，超出用户点那一下的预期。先拦下、让用户逐条删，代价低、可解释。
- **已归档的子分支不挡**：它已经不在选择器里，若也算死结，用户会看到一个数不出来源的「还有 2 条分支」。恢复后它就是一条独立副会话（来源已删，画板把它当根）。
- 子分支数量从 `ChatOrigins` 一次快照算，不需要新表。

## 为什么缩进挂在选择器而不是改地图

- 用户以为"一个会话一张地图"；实际是"一条会话 + 它的分支"一张地图，因为分支在存储上是独立会话，只能靠 `ChatOrigins` 关联。
- 画板的作用就是看这棵树；拆成"一条会话一张只画自己的图"会让分支彻底消失。
- 真正让关系变清楚的是**列表**：现在主对话和副本平级，看起来像两条无关会话。选择器把副本缩进到母会话下面，既不改存储，也不改画板。

## 契约

### `GET /api/v1/partners/:id/sessions` 增字段

```jsonc
{
  "ok": true,
  "partnerId": "…",
  "kind": "partner | chief",
  "sessionManage": true,          // 新：PARTNER_SESSION_MANAGE 生效值
  "sessions": [
    {
      "conversationId": "…",
      "role": "canonical | side | chief",
      "title": "…", "firstText": "…", "lastAt": 0, "turns": 0, "pinned": true,
      "origin": {                  // 新：只有分支副本才有
        "source": "母会话对外 id",
        "sourceTitle": "…",        // 可缺
        "at": 0,
        "atMessageId": "…"         // 老数据可缺
      },
      "deletable": true            // 新：side 或 chief 分支副本，且无未归档子分支、开关开着
    }
  ]
}
```

- `origin` 直接来自 `ChatOrigins.byExternal`，不派生 `branchFrom`（那是画板按回合算的，列表不付这个代价）。
- `deletable` 只表达"现在能不能删"，不表达"为什么"；真正的原因由删除端点返回。

### `POST /api/v1/partners/:id/sessions/:conversationId/delete`（新）

- `:id` = 执事 uuid 或 `chief`。
- 请求体为空。
- 成功：`{ ok: true, conversationId, deleted: { conversations, entries, tasks, submissions } }`。
- 失败：
  - `400 partner_session_manage_disabled`：开关关；
  - `400 chat_hard_delete_disabled` / `503 llm_unconfigured`：复用永久删除总闸；
  - `404 unknown_session`：不在 `Chats.byExternal`；
  - `409 not_side_session`：不是执事的 side，或不是总管的带 origin 副本；
  - `400 has_branches`：`ChatOrigins` 里还有以它为 source 的子分支；
  - `400 conversation_busy`：`LiveDoc.run` 存在。
- 鉴权沿用全局 `/api/v1`，失败 403 空体。

## 存储与清理

删除在 `runExclusiveMaintenance` 里做（与现有永久删除同一把闸）：

1. 重检目标仍是 side/副本、仍无子分支、仍不忙；
2. `closeHarnessForMaintenance()` → `deleteSubtreeRows(db, [internalId])`：清 conversations / entries / submissions / tasks / 该会话的 documents；
3. `purgeChatMappings()`：清 `Chats` / `ChatKinds` / `ChatProjects`，**本次补清 `ChatOrigins.byExternal[externalId]`**（否则画板幽灵节点；现有 worker 永久删除也顺带受益）；
4. `purgeChatMetaEntries([externalId])`：清标题 / 归档 / 置顶痕迹；
5. `PartnersStore.deleteSessionLinkBySessionId(internalId)`（新方法，只删 `role='side'`）。

**不删**：记忆、项目、附件文件、磁盘目录、派活回执。与现有永久删除口径一致。

## 界面

- 选择器行：`<div class="ps-item">` 包住原来的打开按钮 + 右侧垃圾桶（避免 button 套 button）。
- 有子分支的副本：渲染 `.ps-children`（左侧细线 + 缩进），默认展开；母会话不在列表里时退回顶层。
- 垃圾桶只在 `deletable` 行悬停时出现；点击把弹层内容换成确认视图（不叠加 `openModal`）。
- 确认成功：删的是当前会话 → 关弹层、回主对话；否则原地重拉 `/partners/:id/sessions` 并重绘。
- `hint` 区显示服务端原文（`has_branches` / `busy`），不关闭确认视图。

## 备选与否决

| 备选 | 否决理由 |
|---|---|
| 只做归档 | 用户明确要"直接删"；归档页的永久删除仍挡着 partner，问题只解决一半 |
| 归档 + 删除都给 | 一行两个消失动作，误触成本高；本次先给删除 |
| 级联删子分支 | 一次点击的删除范围不可见；先拦下更安全 |
| 把分支从列表里藏掉 | 分支是真实会话，藏掉后无法进入 / 管理 |
| 改画板为"一条会话一张图" | 分支会从画板上消失；画板的意义就是家族树 |

## 回滚

- `PARTNER_SESSION_MANAGE=false`（插件页「分支会话管理」卡，默认开、即时生效）：
  - 选择器回到平铺、不渲染垃圾桶；
  - 删除端点返回 400 `partner_session_manage_disabled`；
  - 已有数据不受影响。

## 验证

- 单测：临时 `.data` + 真 Harness，覆盖成功删除 / canonical 拒绝 / 无 origin 的 chief 拒绝 / 有子分支拒绝 / busy 拒绝 / 开关关拒绝；断言 conversations、entries、Chats、ChatOrigins、partner_session_links、chat-meta 都不留。
- 纯函数：选择器树构建（父子挂载、母会话缺失时退回顶层、环保护）。
- `pnpm typecheck` + `pnpm --filter @lifediary/server test`。
- 浏览器：选择器缩进、删叶子分支、删有子分支被拦、开关回滚。
- HTTP 探针：列表新字段 + 删除端点成功/拒绝。

## 明确不做

- 不做「一个会话一张地图」；画板保持家族视图。
- 归档页永久删除不扩到 canonical / chief / 群 / 任务；side 副会话已放行（见结论 7）。
- 不做级联删除、批量删除、手机端选择器。
- 不给选择器加归档按钮。
- 不改 `CHAT_HARD_DELETE` 的既有语义。
