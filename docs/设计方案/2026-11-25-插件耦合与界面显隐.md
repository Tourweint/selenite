## 二、三个决策

### 决策 A：`MEMORY_IMPORT` 已登记 + 九条边（B0，已落地）

**A8 登记形状（与当前清单一致）**

| 项 | 值 | 依据 |
|---|---|---|
| `scope` | `plugin`（清单未写 `scope`，缺省即 plugin，`flags.ts:275`） | `plugins.json:1358-1371` |
| `defaultValue` | `true` | 同上 |
| `requires` | `["MEMORY_ENABLED"]` | 同上 |
| `group` | `memory` | `plugins.json:1361`、`27-43` |
| `hot` | `true` | 同上 |
| 子边 | `MEMORY_IMPORT_SOURCES.requires += "MEMORY_IMPORT"` | 清单 `1374` 起 |

**登记带来的两条周边代价（必须写进长期文档）**

1. **部署 env 变成「缺省」，JSON 覆盖它**。`storedFlagValue` 对 `scope=plugin` 先读 `.data/agent-flags.json`，
   文件没写才回 env / 清单默认值（`flags.ts:274-280`）。也就是说，部署里写 `MEMORY_IMPORT=false`
   只表达「初始关」，用户可以在插件页把它改回 true 并长期生效。这不是 bug，是「登记」的语义变化，
   要写进 §四 与 §6.2，避免运维以为 env 仍是硬闸。
2. **回滚不安全，必须原子回滚**。`memoryImportEnabled()` 已经从 env 改成 `flagEnabled("MEMORY_IMPORT")`
   （`memory-consolidate-parse-proposal-json.ts:28-30`），而 `flagEnabled` 对未知键返回 `false`
   （`flags.ts:324-328`）。只删清单项、或把 `AGENT_PLUGINS_PATH` 指到旧清单，记忆导入会**永久关闭**，
   env 也救不回来。因此回滚必须同时做两件事：恢复清单项（或保留键）**并**把消费点改回 env 读法。
   只删清单项的回滚不接受。

**读侧父判的定位**

`memory-import-sources.ts:40-42` 只调用 `flagEnabled("MEMORY_IMPORT_SOURCES")`；父门由清单边
`MEMORY_IMPORT_SOURCES ← MEMORY_IMPORT ← MEMORY_ENABLED` 递归生效。若要再补一行显式父判，
标为**冗余防御，不是生效来源**；保留时必须在注释里写明，不保留也不算漏。

**G7（软依赖）已定：进 `requires`**

清单只有一种边，`requires` 不分软硬；UI 表现为锁 + `PUT` 400，与「后端其实没有输入源」一致。
代价：`AGENT_ASK_USER` 是 `hot:false`，弹窗必须写「连带打开，重启后生效」。

**备选：合并键（`CHAT_CACHE_STATS` 并进 `CHAT_CONTEXT_INSPECT`）——不采纳**

| 理由 | 说明 |
|---|---|

### 决策 B：前置连开 + 父项连带关（契约 v2）

用户已拍板交互：**点被锁的子项 → 弹窗列出缺的前置（递归、拓扑序）与会被连带恢复的兄弟项 → 确认后一次性打开**。
v1 的契约有四处会让「关闭核心开关」「连带恢复」做错，本版全部吸收。

#### B1 端点契约（v2）

| 端点 | 请求 | 成功响应 | 语义 |
|---|---|---|---|
| `GET /api/v1/agent/flags/:key/enable-plan` | — | `{ key, missing: [{key,label,value,hot,willWrite}], revive: [{key,label,value,hot,willWrite:false}], needsValue: [{key,label,choices}] }` | 只读推演，不写任何值 |
| `POST /api/v1/agent/flags/:key/enable` | `{ confirm: true, values?: { KEY: value } }` | `{ ok: true, changed: [{key,value,hot}], revived: [{key,value,hot,willWrite:false}] }` | 服务端重新推演后按拓扑序写入 |
| `GET /api/v1/agent/flags/:key/disable-plan` | — | `{ key, disableable, offValue, affected: [{key,label}] }` | 只读推演；枚举 / 数值键没有可用关值时 `disableable: false`，该形态不带 `offValue` |
| `POST /api/v1/agent/flags/:key/disable` | `{ confirm: true }` | `{ ok: true, changed: [{key,value,hot}], affected: [...], alreadyOff?: true }` | 写关值；不清子项存储值 |

**开值规则（v2 新增：`enable` 不能只有 `confirm`）**

逐键按顺序决定（`plannedValueOf`，`flags.ts:635-641`）：

1. `values[key]` **只对 `plan.needsValue` 列出的键生效**——实现是逐项读 `needsValue` 再取 `values`（`flags.ts:875-889`）；
   给了、且通过 `flagValueAllowed`、且不是关值 → 用它。清单里不存在的键、这次不需要选值的键，传了也**不生效、不报错**。
2. 布尔键 → `"true"`（布尔判定：`type === "boolean"`，或 `values` 只有 `true/false`、**没写 `type` 也算**）。
3. 枚举 / 数值键：自己的存储值不是关值就**原样保留**（只解锁、不换档）；存储值本身是关值 → 用 `defaultValue`
   （须通过校验且不等于关值；`MEMORY_EXTRACT` 的 `auto`、`PARTNER_LEARNING_FREQUENCY` 的 `weekly` 走这条）。
4. 否则 → 该键进 `needsValue`，带 `choices`（`value` + 中文 `label`），前端必须让用户选档。

`AGENT_TOOL_POLICY` 这类「默认值就是关值（`full`）」的键靠第 3 条排除，避免拿默认当打开值。

**字段定义（三个词必须在实现里一致，不然前端文案会撒谎）**

- `missing`：从目标键沿 `requires` 递归收集、当前 `effectiveValue` 为关的**祖先**（不含目标自身），
  **拓扑序**（最深祖先在前）。父自己「存储值是开、但被它的父锁着」时同样要列出来，并继续上溯。
  每项带 `value`（按开值规则算出）、`hot`、`willWrite`（= 该键**自己的存储值就是关值**，必须写；
  存储值本来是开、只是被父锁着 → `false`，父一开它自动恢复，本轮不写它自己的值）。
- `待打开集合` = `missing ∪ {key}`，按拓扑序写入；每个键被写时父已开，可以直接复用 `setFlag`，
  不会撞 `flag_locked`。
- `revive`：**排除 `missing ∪ {key}`**，只统计「不在待打开集、但会因父打开而变开」的键。判据三条同时成立：
  (a) 当前 `effectiveValue` 为关；(b) 它自己的**存储值不是关**（用户没主动关，只是被父锁着）；
  (c) **模拟待打开集写完之后**，它的 `effectiveValue` 变成开。
  (c) 必须真推演，不能只看「闭包与待打开集相交」：多父场景下相交不等于会变开
  （`MINISTER_DISPATCH_AUTHORITY` 在 `COMPANIONS_ENABLED` 仍关时不会复活）。每项 `willWrite: false`，排序按 `plugins.json`。
- `affected`（disable）：`requires` 闭包包含目标键的**所有后代**，且当前 `effectiveValue` 为开；排除目标自身，
  排序按 `plugins.json`。

**关值规则（v2：布尔键一律可关）**

- 关值 = `def.offValue ?? (布尔键 ? "false" : null)`。
- 布尔键（`type === "boolean"` 或 `values` 只有 `true/false`、含无 `type` 的老清单）**永远可关**。
  这条是 P0：87 个键里绝大多数布尔键没有 `offValue`，包括四个核心闸。
- 只有**枚举 / 数值键且没有 `offValue`** 才 400 `flag_not_disableable`（数值键如 `AGENT_COMPACT_TRIGGER_PERCENT` 同样命中）；
  `disable-plan` 对同一类键返回 `disableable: false`（该形态不带 `offValue`）。
- `disable` 时目标已经 effective 关（包括被父锁）→ **200 `{changed: [], affected: [], alreadyOff: true}`**，
  不写值、不撞 `flag_locked`。其余情况写关值，子项存储值保留（父重开自动恢复）。

**错误码**

| 场景 | 状态 | `code` | 备注 |
|---|---|---|---|
| 鉴权失败 | **403 空体** | — | 沿用 `/api/v1` 口径，不区分原因；**不另做鉴权分支** |
| 未知键 | **404** | `flag_not_found` | 与旧 `PUT` **不一致**：旧 `PUT` 对未知键是 404 + `{error:"bad_request"}`（`flags.ts:513/841`）。本次**不改 `PUT`**，差异写进接口文档 |
| `confirm` 缺失 / 非 `true` | 400 | `needs_confirm` | 两个 POST 都要求 |
| 缺打开值 | 400 | `needs_value` | `needsValue` 非空却没给 `values`；响应体 `{error:"needs_value", keys: [{key,label,choices}]}`（**字段名是 `keys`**，`needsValue` 只用于 `GET enable-plan` 的成功响应），前端据此就地补选 |
| 枚举 / 数值键无 `offValue` 调 disable | 400 | `flag_not_disableable` | 布尔键不会命中 |
| 门关 | 404 | — | `FLAG_CASCADE_ENABLE=false` → 四条端点整组不挂 |
| 目标自身被锁却调旧 `PUT` | 400 | `flag_locked` | **不变**，见 B4 |

**原子性**

逐键写入**不是事务**：`setFlag` 每次读整个 map 再原子写（`flags.ts:404-419`、`547-549`）。
中途 IO 失败 → 500，路由必须自己 catch（`setFlag` 不 catch），响应如实带**已写入的 `changed` 前缀**，
前端据此重拉 `GET /agent/flags` 收口，不假装整体成功。

**计划过期**

`GET plan` 与 `POST confirm` 之间如果别的标签页改了父键，客户端手里的 plan 就过期了。
本次不做 plan 版本号；**POST 一律重新推演**，只认当时状态。文档写明「确认后以当时状态为准」，
客户端多传的、不在待打开集里的键一律忽略。

**门与投影**

- `FLAG_CASCADE_ENABLE`（默认 `true`）：`false` → 四条端点整组不挂（404），插件页退回「点一下 → toast 400 `flag_locked`」的旧形态。
- `/agent/policy` 增加两个布尔：`flagCascade`、`pluginSurfaces`；投影口径
  `flagsUiEnabled() && 对应门`，门关或 `AGENT_FLAGS_UI=false` 时为 `false`。
- 前端「打开这些前置」按钮按 `policy.flagCascade` 隐藏，不靠「打一下 404 再藏」。

**挂载点**

四条端点写在 `mountFlags` 内（`flags.ts:850-976`：enable-plan `850` / enable `857` / disable-plan `957` /
disable `976`），继承 `/api/v1` 鉴权与 `AGENT_FLAGS_UI` 早退（`flags.ts:829`）；**不另做鉴权分支**。

#### B2 为什么不静默自动开

| 风险 | 具体 |
|---|---|
| 会打开用户主动关掉的兄弟项 | 父一开，所有 `stored=on` 的子键同时复活（「本项自己的存储值保留」就是这个设计，`flags.ts:77-81` 注释） |
| 用户看不到变化 | 关掉的可能是「记忆主动提起」「设备矩阵派活」这种有副作用的键；静默打开＝在用户不知情时改变行为 |
| 无法解释 | 事后没人知道「我明明关过它，为什么又开了」 |

所以必须：**先 plan 展示 → 勾选/确认 → 一次写**。弹窗固定三段：
「需要打开的前置」（拓扑序）、「会一起恢复的项」（`revive`）、「不会动你的其它设置」（一句话）。

#### B3 前端交互（实施归属见 B1.5）

- 锁态卡（`lockedBy` 非空）控件仍是 `disabled`（`settings-switches.js:208-213`），但**卡面可点**：
  现有 `data-flag-detail` 按钮 + `openFlagDetail`（`settings-switches.js:250`、`302`）已经能打开弹层，
  只需在弹层底部加「打开这些前置」。
- 确认按钮文案写清代价：「打开 3 项，其中 2 项会连带恢复」；`needsValue` 未选完时按钮不可点。
- 关父项：`disable-plan` → 弹窗列出 `affected` → 确认 → `POST disable`；写明「子项存储值保留，父重开自动恢复」。

#### B4 现有 `PUT` 语义不变

- 单键、`{value}`、父关时 400 `flag_locked`、未知键 404（body 仍是 `bad_request`）、取值非法 400
  （路由 `flags.ts:833-845`，取值校验在 `setFlag` `flags.ts:506-552`）。
- 本次**不**给 `PUT` 加 confirm，也**不**让它自动开父——自动开父就是 B2 否掉的那件事。
- 旧前端（含手机端）继续用 `PUT`；新端点只是多一条「批量、有确认」的路。向后兼容。

### 决策 C：界面显隐注册表（已存在，按 v2 扩展）

`ts/apps/server/web/surfaces.js` **已经存在**（2026-11-25 复核 12 条，`29-49`：首批 4 条
`#rail-partners` / `#sec-partners` / `#skill-advice-run` / `#settings-export-all`，第二批 8 条为左栏两项、
注入页 5 个 tab、项目「添加」、派活「检测」）。本决策是**扩展**这个文件，不是新建。

```js

{ id, selector, requires: [flagKey], mode: "hide"|"disable"|"empty", emptyCopy?: string, offValue?: string }
// 「不许藏」不在行字段里：`PINNED` 是模块级选择器集合（`surfaces.js:56-66`），见下方白名单
```

**四条铁律（写进文件头注释，别靠口头）**

1. **只读 `effectiveValue`**（父闸已含，`flags.ts:487`），**并用 `offValue` 判定**。
   `AGENT_TOOL_POLICY` 的关值是 `"full"`，只认 `false/0/off` 会把「关」当成「开」。
   正确口径：`row.offValue ? value === row.offValue : false/0/off`；可复用
   `settings-switches.js:65-88` 的 `flagOffValue` / `flagIsOff` 口径，不要造第二套。
2. **缺键 fail-open**：payload 里没有这个键（还没拉到 / 拉失败 / `AGENT_FLAGS_UI=false`）→ 按「开」处理，**不隐藏**。
   避免「开关页被关掉 → 整站界面空掉」。
3. **门在 applier 内部**：`PLUGIN_SURFACE_HIDE=false` 时，`applySurfaces` / `refreshSurfaces` 直接返回，
   不改任何 `hidden/disabled`。门必须放在 `surfaces.js` 里，因为调用点有三个：
   `app.js:214`、`settings-router.js:780`、`settings-switches.js:650`；只加在 `app.js` 等于没加。
4. **永不隐藏「回去的路」**：白名单见下表，落点是 `surfaces.js` 里的模块级 `PINNED` 选择器集合
   （不是行上的 `pinned: true`）；单测校验它们**不许出现 `hide`**。

**动作语义**

| mode | 做法 | 为什么 |
|---|---|---|

| `disable` | `disabled = true` + `aria-disabled="true"` + 可选 `data-tip` 说明原因 | 入口还在但按不动，用户知道「这里原本有东西」 |
| `empty` | **保留容器**，只换内部内容为 `emptyCopy` | 深链进来不能是一片空白；容器留着，路由与选择器都不破 |

## 四、明确不做

1. **不给 21 项部署级 env 开关做面板**：`MEMORY_IMPORT` 已按拍板登记（§决策 A），其余 20 项继续只走环境变量、
   不进插件页（部署级总闸单独立项）。
2. **不全局改 `flagValue` 的父门语义**。`flagValue` 被枚举档位消费（`MEMORY_EXTRACT` 在 `memory-extract.ts:43`、
   `ARCHIVE_AUTO_DAYS` 在 `auto-archive.ts:62`、`AGENT_COMPACT_*` 走动态键 `compaction-settings.ts:57`），
   套上父门会让「父关子档仍返回档位值」变成「返回 false」，`false` 不是合法档位 → 会把枚举消费点打坏。
   只给确有需要的消费点单独补父判（本次没有必需的消费点）。
3. **不为每个插件做「安装 / 卸载」概念**。只有开关：关了 = 能力停 + 界面收，不是卸载（文件、数据、历史都不动）。
4. **不改手机端**。
5. **不改 `PUT` 语义、不删既有 `requires` 边、不重排 `plugins.json` 分组**（`groups` 顺序就是插件页渲染顺序，
   重排会打散用户对卡片墙的空间记忆）。
6. **本次不做按 group 整组显隐**。注册表不按 group 工作（schema 只有 `id/selector/requires/mode`），
   且 `archive` / `compaction` 那 6 个键是 `surface:"settings"`，本来就不进插件页
   （`settings-switches.js:489` 的 `surface !== "settings"` 过滤）。将来要做，先给注册表加 `group` 字段并单独立项；
   本次不改 `groups[]`。

## 六、风险与未决

### 6.1 会真正影响本次的两条

| # | 疑点 | 证据 | 对本次的影响 | 处置 |
|---|---|---|---|---|
| R1 | `hot` 承诺不成立：`MEMORY_ENABLED` 标 `hot:true`，但引擎是模块常量，启动关→运行开不重建 | `assist.ts:103-104`；`index.ts:747` 注释已承认「要重启」 | 界面会**先收**、能力可能还在；反之亦然 | 不改 `hot` 标注（§四.2）；界面用 `pendingRestart` 徽标如实说明；`hot` 标注问题单独立项 |

| 项 | 现状 | 后果 |
|---|---|---|
