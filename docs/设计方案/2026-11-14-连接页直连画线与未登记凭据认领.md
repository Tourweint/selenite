# 2026-11-14 连接页：直连设备必须画到本机 · 没登记的凭据可认领 · 每行都有出口

> 用户原话：「我们还是得继续深挖一下连接，包括手机连接、本地连接和中继连接……比如现在，有一个未知平距（未知凭据），这应该是我的平板，它应该直接连接了我的电脑，所以图里应该画出它连的是电脑，而不是经过中继。你现在什么都没画，它是一个孤立的状态，对吧？……至少，如果我的平板连接我电脑，只能控制我电脑，那就只把这两个设备的连接标出来就行。」「已经移除的平板自检可以删除。还有，你连接的设备为什么只有它，我这个手机有移除，别的没有移除？」

## 结论

1. **直连 = 线连到「本机」**。凡是从这台电脑的门进来的（本地配对、没登记但直连、公网直连），星形上就画一条到「本机」的线；只有登记在中继名册里的才连到中间那个圆。以前名册外的活口只画一个圆、不画线，读起来就是"它飘着、什么都没连"——这是错的。
2. **布局按通路分簇**：直连设备排在本机旁边（左上半圈），经中继的排右半圈；本机→设备的线走椭圆外缘的曲线，不穿过中继那个圆。原来均分一圈的排法会把"只连本机"的设备摆到右边，线得绕过大半个图、还贴着别的节点，最容易读错成"它经中继"。
3. **"在线"只写真的**：`live` 表在读的时候按 5 分钟 TTL 剪一次（以前只在"有新请求进来"时才清，设备停了之后页面会把二十分钟前的记录写成"现在在线"）；名册里已经被删掉的设备不再出现在 `live` 里（否则它会被套上"未知凭据"的壳，看着像另一台不认识的设备）。页面按真实秒数写「现在在线 / N 分钟前回话」。
4. **新增 `unclaimed`：来过、但本机没登记的凭据**。平板隔几分钟才发一次请求，5 分钟活口撑不到用户打开这一页——"我平板明明在线，列表里却没有它"一半是这么来的。这枚哈希落 `.data/pairing.json`（只存 sha256 + 方式 + 时间，最多 5 枚、7 天过期），页面就有东西可显示。
5. **每行都有出口**：活动设备「移除」（撤销凭据）；已撤销的残壳「删除记录」（**新端点**，连记录一起抹掉）；没登记的凭据「认领」（**新端点**，把它的哈希登记成设备，立刻生效、不用重扫码）；用主令牌直连的「去配对」（出码并滚到二维码）。
6. **不做"一台设备操控所有相连设备"**。控制 = 打到某一个 harness；设备连哪台就只能用哪台的 Agent。要让一台设备驱动多台机器，现有唯一成立的路是 harness→harness 的中继矩阵派活（`POST /relay/matrix/delegate`，点名另一台设备执行），不是设备直连多台。做设备级转发要新增跨主机信任委派与权限收敛，是另一个方向，不在这一轮。

## 取舍 / 备选

| 备选 | 不选的理由 |
|---|---|
| 名册外活口继续只画圆、不画线 | 它确实连着这台电脑；不画线等于说"什么都没发生"，用户看到的就是一个孤立的圆 |
| 直连画直线 | 本机在左、设备在右时直线穿中继圆，看着像"从中间接出去的"；曲线走外缘才读得对 |
| 认领改成"重新扫码才给用" | 用户手里的平板已经连着、只是凭据不是这台机发的；让他再扫一次是能省掉的步骤。认领是本机页面上的一个明确动作，不是自动放行 |
| 认领允许远程页面调 | 这等于把一枚陌生凭据升级成长期设备，必须人在本机点。非回环一律 403 |
| 只认 5 分钟内活口才能认领 | 平板不一定一直在问；点的时候它刚好没说话就认不了。所以 `unclaimed` 留 7 天，也允许认领 |
| 已撤销残壳只"藏起来" | 藏起来记录还在，用户以为删了；`/delete` 才真的从名册里删 |
| `unclaimed` 只放内存 | 重启就没，"隔一天再看"又空白；落盘只多几个哈希，且 7 天自清 |
| 删掉的设备继续留在 `live` | 记录已经不存在，它再来会被当成未知凭据；留着只会多画一个幽灵节点 |

## 明确不做

- 不做设备间转发 / 接力控制（见结论 6）。
- 不做"真在线表"：这套是 HTTP 请求，没有长连接，服务端只能回答"最近有没有人来过"。
- 不改手机端：认领是电脑端的事，手机不需要知道。
- 不合并两套名册的主键（配对 id 与中继 deviceId 各自保留），只合并展示行（沿用 2026-11-14 首轮口径）。
- 不动中继：这一轮只读中继名册，不调它任何写接口。
