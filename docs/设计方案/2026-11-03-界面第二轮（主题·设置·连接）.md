# 界面第二轮：配色归队、设置页、手机连接

> 2026-11-03 晚。第一轮把功能跑通了，但配色是抄 cindy 的纯灰阶——那是别人的脸。
> 这一轮把脸换回 lifediary 自己的，并补上设置与连接。

## 结论

五条：

1. **配色以手机端为准。** 直接用 `lifediary/core/designsystem/theme/Theme.kt` 里的
   Light/Dark 两套 Material3 色板，不再自造。桌面和手机得是同一个产品。
2. **按钮是 16px squircle，不是胶囊。** 手机端 2026-10-21 明确「按钮和设置页那个方框一样」，
   填充色用 `primaryContainer`。第一轮抄 cindy 抄成了 pill，错了。
3. **主题可切**：浅色 / 深色 / 跟随系统，外加主题色三选（靛蓝 / 暖金 / 琥珀，都是色板里现成的）。
   存 `localStorage`，不改服务端。
4. **加设置页**，同源 hash 路由（`#/settings`），不引前端框架。分区：外观 / 连接手机 / 服务 / 关于。
5. **去掉壳的菜单栏**（Edit / View / Window）。它是 MyGo 的 `Role*Menu`，对单窗口应用没用，
   还占一行。调试走浏览器（`ego-browser` 打 8082），不需要窗口里的 DevTools 菜单。

## 二、设置页

hash 路由，两个视图：`#/` 聊天、`#/settings` 设置。切视图不重载页面。

| 分区 | 内容 |
|---|---|
| 外观 | 主题（浅色/深色/跟随系统，分段控件）、主题色（靛蓝/暖金/琥珀，色块） |
| 连接手机 | 二维码（服务现出）、配对地址、说明「手机扫码后长期有效」 |
| 服务 | 地址、模型、鉴权状态（是否配了 AGENT_TOKEN）、token 用量 |
| 关于 | 版本、仓库用途一句话 |

行样式照手机端：**分组标题在卡片外面上方**（灰色小字），卡片内每行 56px，
行间 1px `outlineVariant` α.55 分割线，**组尾不画线**。

新增一个接口：`GET /api/v1/pair/qr` 返回
`{ url, dataUrl, machineName, expiresInSeconds }`——`/pair` 那张 HTML 页是给手机扫的，
桌面要在自己界面里显示，得有 JSON。

## 三、去掉的东西

- MyGo 的 `App.SetMenu(...)`：整个删掉，窗口只剩标题栏。
- 上一轮的 pill 按钮、cindy 的灰阶 token：全部替换。

## 四、验收

1. 浅色 / 深色切换即时生效，无需刷新；刷新后保持。
2. 主题色三选生效，刷新后保持。
3. 设置页能出二维码，手机扫码后 `/pair` 页给出的地址与界面里显示的一致。
4. 窗口顶部没有 Edit/View/Window。
5. 深色下分组卡能读出来（不是一片糊），浅色下不是刺眼纯白。

## 五、落地记录

做完的状态：

- `web/style.css` 换成两套 token（`:root` = 浅色，`html[data-theme="dark"]` = 深色），
  主题色用 `html[data-accent="indigo|gold|amber"]` 覆盖 `--accent` 三件套。
- `web/index.html` 里一段内联脚本在样式表加载前定 `data-theme`，避免白闪。
- 设置页 `#/settings`，四个分区；深链 `?view=settings`（壳的 `LIFEDIARY_VIEW` 走它）。
- 新增接口：`GET /api/v1/pair/qr`、`GET /api/v1/pair/devices`、
  `POST /api/v1/pair/devices/:id/revoke`（CORS 只放 GET/POST，所以撤销用 POST）。
- 壳删掉 `App.SetMenu`，窗口只剩标题栏。

验证方式：桌面壳截图（浅色）+ 浏览器 computed style（两套 token 的实际 rgb 值）。
ego 浏览器窗口当时不可见，`Page.captureScreenshot` 一直超时，所以深色没有截图，
只有 computed style 证据：`body` = `rgb(22,20,46)` / `rgb(229,226,240)`，卡片 = `rgb(27,31,60)`。

## 六、第三轮补充（同日）

### 主题色改成真的主题色

第一版只换了按钮底色，用户当场指出「你只是改了按钮颜色，不是主题颜色」。改法：

```css
--accent-soft: color-mix(in srgb, var(--accent) 13%, var(--bg));
--accent-line: color-mix(in srgb, var(--accent) 32%, transparent);
```

`--accent` 现在作用于：新对话按钮、发送按钮、分段选中、**用户气泡底色**、
**侧栏选中项**、链接、光标、状态点、焦点环、工具活动圆点。

验证（浏览器 computed style，同一页切 `data-accent`）：

| | 新对话按钮 | 用户气泡 | 选中会话 |
|---|---|---|---|
| indigo | `rgb(62,74,140)` | 淡靛蓝底 | 淡靛蓝底 |
| gold | `rgb(184,155,110)` | 暖金底 | 暖金底 |

### 补上的功能

| 功能 | 说明 |
|---|---|
| **工具输出** | `tool` 事件在 `end` 上带 `output`（截断 2000 字符），界面里点一行展开原文 |
| **会话改名** | 侧栏悬停出 ✎，就地输入，回车存、Esc 取消 |
| **从列表移除** | 侧栏悬停出 ✕。**不是删除**——durable 没有删除接口，会话与记忆都还在 |
| **恢复已移除** | 设置页「会话与行为」里出现「恢复」 |
| **搜索会话** | 侧栏搜索框，按标题/首句过滤 |
| **复制回答** | 助手消息悬停出「复制」 |
| **发送键** | Enter 发送 / Ctrl+Enter 发送（设置页可切） |
| **工具活动开关** | 设置页可整体隐藏活动行 |
| **提醒列表** | 设置页「提醒」分区，读 `/api/v1/agent/reminders` |
| **快捷键** | `Ctrl/Cmd+K` 新对话、`Ctrl/Cmd+,` 设置、`Esc` 退出设置 |

新增接口：`POST /api/v1/agent/chat/:id/rename`、`/hide`、`POST /api/v1/agent/chats/restore`。
改名的存储是 `.data/chat-meta.json`（和内核的表无关，避免升级时痛）。

## 七、第四轮微调

用户的反馈：「没看见他那个按钮颜色太抓眼了，这个好像也不需要改」——所以：

- **按钮退回 `accentContainer`**（新对话、发送、分段选中），主题色只在
  选中会话、用户气泡、链接、焦点环这些"该有色"的地方出现。
- **工具参数也能看了**：`tool` 事件 `start` 上带 `args`（JSON，单值截 200 字符、
  整段截 1200），界面里和 `output` 一起进可展开块。
- **消息时间戳**：写进 `data-at` 和 `title`，**不在界面上显示**（用户明确说没必要）。
- **进场动画**：切视图时 `.main` 走 `viewIn`（8px 上浮 + 淡入，260ms）；
  设置页的分组按 40ms 递增错开；`prefers-reduced-motion` 下全部关掉。

## 八、第五轮：首页态、侧栏动画、权限与档位

动效照两个参考项目来（`dsh-synapse` 的侧栏、`legacy-agent-orchestrator` 的 composer）：

```css
--dur-fast 120ms / --dur-base 200ms / --dur-slow 240ms / --dur-slower 360ms / --dur-enter 300ms
--ease-standard (.4,0,.2,1) / --ease-decelerate (0,0,.2,1)
--ease-accelerate (.4,0,1,1) / --ease-emphasized (.34,1.56,.64,1)
```

**首页态 composer**：一个实例，靠 `bottom` + `width` 双过渡在两种状态间移动，
不是两个元素交叉淡入。

| 状态 | bottom | 宽度 |
|---|---|---|
| 首页（没有消息） | `42vh` | 560px |
| 对话中 | `14px` | 700px |

用 `bottom` 不用 `top`：textarea 长高时向上长，不会顶出窗口。

**侧栏折叠**：外层 `overflow:hidden` + 内层**定宽**，内层不收窄，避免文字一路重排。
开=360ms 减速曲线，关=250ms 加速曲线；文字 `opacity + translateX(-10px)` 一起退。

> 踩过的坑：先按参考项目用 `grid-template-columns` 做过渡，属性切过去、`--side`
> 也算出 `0px`，但量出来一直停在旧值。换成 flex 子项的 `width` 之后行为稳定。

**消息进场**：用户从右侧 12px 滑入、助手从左侧，200ms `--ease-decelerate`。

**权限三档**（运行时；原来只认环境变量，改一次要重启）：

| 档位 | 拦什么 |
|---|---|
| 完全访问 | 不拦 |
| 只读 | `write` / `edit` / `bash` / `powershell` / `delegate` |
| 不跑命令 | `bash` / `powershell` |

存 `.data/policy.json`，`beforeTool` 每次调用重新判断，改完立刻生效。
接口 `GET/POST /api/v1/agent/policy`。

**思考档**：`快 / 深` 在标题栏右侧，写 localStorage；新会话在 `start` 事件后补发
`POST /api/v1/agent/chat/:id/mode`。手机端不做这个。

**服务隐藏启动**：壳探不到 `/healthz` 就自己拉起服务——
`node --import tsx src/index.ts`，Windows 上带 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`
+ `HideWindow`，**不出现控制台窗口**。服务不绑定壳的生命周期（`Process.Release`），
壳关了它照跑。`DASHSCOPE_API_KEY → LLM_API_KEY` 的映射在壳里补一次，密钥仍不写进 `.env`。

## 九、第六轮：只剩说话框、窗口比例、设置分区

**黑框的真相**：不是 node 弹的，是**壳自己**。Go 默认编出来是控制台子系统程序，
双击 exe 会先开一个控制台窗口。改成 `go build -ldflags="-H windowsgui"` 之后是 GUI
子系统，双击直接出窗口；服务那边本来就是隐藏进程（`visible-node-windows=0`）。

**窗口几何**：按屏幕比例算，不再写死像素。

| 边距 | 比例 |
|---|---|
| 左 | 25% |
| 上 | 15% |
| 宽 | 55% |
| 高 | 70% |

1920×1080 上实测 `(480,162) 1056×756`，与比例一致。拿不到屏幕信息时退回 1100×780。

**首页**：顶栏、问候语、提示词全删，只剩一个输入框（660px 宽、64px 高、竖屏居中）。
`?view=new` 可以直接落到这个状态（壳的托盘以后用得上）。

**设置页**改成两栏：左侧分区栏（外观 / 会话 / 提醒 / 连接 / 服务 / 关于），
`width: 26%`、收起时 `9%`——按百分比，内容区占比跟着变。
分区跳转用 `scrollIntoView`，高亮用 `aria-current`。

**搜索**从主界面挪进设置的「会话」分区：按标题或首句过滤，点结果直接开那个会话。

**主题**改成圆钮开关（`role="switch"` + `::after` 位移，200ms `--ease-emphasized`），
另有一个「跟随系统」开关；跟随时深色开关置灰。
