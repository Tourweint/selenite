## 结论

1. **画板只画一条会话的树**：进入谁的会话，就画谁的回合卡 + 它的分支；不做工作区画布、不装其它会话。
2. **一个回合两张卡**：问卡在上、答卡在下；工具调用不进卡片，只留一个「工具 N」计数。
3. **分支从分叉那一轮伸出**：子会话只画"分叉点之后"的新回合，第一张问卡的父节点是母会话那张答卡；坐标不参与血缘。
4. **布局是元数据**：拖动位置存浏览器 localStorage，删了只丢排版，不丢会话。
5. **画板是只读导航层**：看结构、看详情、进会话、从答卡再分一支；不在画板里写消息。

## 参照 dsh-synapse 的取舍

| 它怎么做 | 我们 |
|---|---|
| 事件流投影成 turn；一问一答两张卡；工具按 callId 折进答卡 | **学**。我们直接读 durable entries，投影成同样的回合结构 |
| 分支按 seed boundary / 显式 anchor 挂回母会话某一轮 | **学**。我们存 `atMessageId`；老数据按时间戳兜底 |
| 横向车道：一条会话一条车道，回合往右长；SVG 贝塞尔连线 | **学**。常量与曲线形状照抄（卡片略大，见下） |
| 缩放锚在鼠标、对数插值；拖拽平移；定位/整理 | **学**。范围 0.25–3，滚轮 ±5%，90ms 指数追赶 |
| 右侧详情抽屉（完整回答 + 工具过程） | **学**。只保留"问 / 答全文 + 进入会话 + 再分支"，不做工具展开 |
| 280 字预览 + 按需取正文 | **学**。地图接口只回预览；点开详情再取单条消息全文 |
| 工作区分组 / 侧栏会话树 / 归档同步 / 在 DSH 打开 | **不学**。画板作用域只接受一个会话 id |
| 草稿卡（继续追问 / 新分支输入框 / 常用短语） | **不学**。写消息回会话页；画板只做「从答卡分一支」 |
| 问/答四种相对方位的「排列」选择 | **不学**。固定问上答下，少一套坐标分支 |
| 子树折叠、卡片展开高度、工具过程展开 | **不学**。卡片固定高度，详情看全文 |
| 多会话画布 + 跨工作区切换 | **不学**。作用域写死在路由里 |

## 界面

### 入口与路由

- 会话顶栏（齿轮左边）加「会话地图」图标按钮；只在对话页顶栏出现（首页顶栏本来就隐藏）。
- 路由 `#/map/<conversationId>`：整页画板，侧栏与标题栏保留；返回按钮回 `#/chat/<id>`（当前看的那条会话）。
- 刷新后从地址恢复；`#/map/` 不合法时回会话页。

### 画板结构

```text
┌ 48px 顶栏：← 对话 | 地图 · <标题> · N 轮 / M 条分支 | 整理 定位 100% ┐
│                                                                  │
│  车道标签「主线 · 标题」                                          │
│  [问卡]──[答卡]──[问卡]──[答卡]        ← 同一会话往右长            │
│                 └──────┐                                          │
│  车道标签「分支 · 标题」  ↓                                        │
│                        [问卡]──[答卡]                             │
│                                                                  │
│                                          ┌ 详情抽屉（点卡片开） ┐ │
└──────────────────────────────────────────┴──────────────────────┴─┘
```

- **卡片**：252×104。问卡浅底无投影；答卡白底细边。顶部一行：`问/答` 徽标 + `第 N 轮` + `工具 N`（答卡）+ `自动`（隐藏触发那轮）。正文 3 行截断。底部悬停出「进入 / 分支」两枚小图标。
- **车道**：根会话第 0 道，分支按深度优先顺序每支一道，车道高 250px；车道起点有一枚标签（主线 / 分支 · 标题），点它进那条会话。
- **连线**：问→答用竖向 S 曲线；上一答→下一问用右中→左中的横向 S 曲线；分支边用强调色。拖动卡片时只重算与它相连的线。
- **空分支**：~~分叉后还没说话的副本，在母会话分叉答卡右侧放一张虚线占位卡「空分支 · 点开继续」，点它进副本。~~
  2026-11-18 起不再画空分支 / 已归档 / 丢失的节点（见 `变更记录/2026-11-18-会话地图收起与空分支隐藏.md`）；空分支只在选择器里管理，有了第一句话才进地图。
- **没有回合**：画布中央一句「这条会话还没有回合」。

### 交互

| 动作 | 结果 |
|---|---|
| 单击卡片 | 选中 + 右侧详情抽屉 |
| 双击卡片 / 详情里「进入会话」 | 切到 `#/chat/<该卡所在会话>` |
| 答卡「分支」/ 详情「从这里分支」 | `POST /chat/:id/branches`，成功后直接进新副本 |
| 拖卡片 | 保存位置（localStorage）；拖问卡带着答卡走 |
| 拖空白 | 平移画布 |
| 滚轮 | 以鼠标为锚缩放 |
| 顶栏「定位」 | 把当前会话最后一轮居中 |
| 顶栏「整理」 | 重新拉地图 + 清掉手动位置 + 回 100% 并居中 |
| Esc / 点空白 | 关详情抽屉 |

## 契约

### 1. `ChatOrigins` 多记一个分叉点

```ts
byExternal: Record<string, {
  source: string;
  sourceTitle?: string;
  at: number;
  atMessageId?: string;   // 新增：分叉点那条 assistant 消息的可寻址 id
}>
```

- `POST /chat/:id/branches` 写入；老数据没有该字段。
- 老数据兜底：在子会话里数"提问时间 ≤ `origin.at` 的回合"，这些是复制过来的前缀；分叉点 = 前缀最后一轮。

### 2. `GET /api/v1/agent/chat/:conversationId/map`

一次返回根会话 + 全部后代（按来源一跳链向上找根、向下 BFS）：

```json
{
  "rootId": "uuid",
  "truncated": false,
  "nodes": [
    {
      "id": "uuid",
      "title": "会话标题",
      "chatKind": "worker",
      "sessionRole": "canonical | side | null",
      "root": true,
      "branchable": true,
      "archived": false,
      "missing": false,
      "origin": { "source": "uuid", "sourceTitle": "…", "at": 1700000000000, "atMessageId": "uuid" },
      "branchFrom": { "conversationId": "uuid", "turnIndex": 3 },
      "startTurn": 4,
      "updatedAt": 1700000000000,
      "turns": [
        {
          "index": 4,
          "question": { "id": "uuid", "text": "…", "at": 1700000000000, "hidden": false, "hasAttachments": false },
          "answer": { "id": "uuid", "text": "…", "at": 1700000000000, "endedAt": 1700000000000, "tools": 2 }
        }
      ]
    }
  ]
}
```

- `turns[].index` 是**该会话内的绝对轮次**（从 0 起）；子会话只回分叉点之后的轮次，但 `index` 保持绝对，方便挂回母会话。
- 文本只回预览：问 400 字、答 1200 字；详情再取全文。
- 上限：节点 24 条、每节点回合 400 条、文本预览如上；超了 `truncated: true`，不悄悄截断而不说。
- `branchable` 与分支端点同一套判据：执事 canonical / side 看 `PARTNER_SIDE_SESSIONS`；群 / 例行 / 课题 / 派活 / task- 会话 false。
- `CHAT_MAP_ENABLED=false` 时整个端点 404 `chat_map_disabled`。

### 3. `GET /api/v1/agent/chat/:conversationId/messages/:messageId`

地图详情取单条消息全文。响应 `{ message: TranscriptMessage }`；找不到 404。与地图端点同受 `CHAT_MAP_ENABLED` 管。

### 4. 回滚

`CHAT_MAP_ENABLED=false`：地图端点 404、`GET /agent/policy` 的 `chatMap=false`、会话顶栏按钮不渲染、直链显示「会话地图已关闭」。前端文件留着不影响对话。

## 存放

- 拖动位置：`localStorage["lifediary.chatmap.positions.v1"]`，`{ "<会话id>:t<轮>:q|a": {x,y} }`。
- 不写服务端、不进 `.data`：换台机器/清缓存只是排版回到自动布局。

## 明确不做

- 不做工作区画布、跨会话总览、会话切换器。
- 不在画板里写消息 / 继续追问 / 草稿输入框 / 常用短语。
- 不做排列方位切换、子树折叠、卡片展开、工具过程展开。
- 不做实时流式更新（地图是进入时的快照；跑完一轮重进或点「整理」刷新）。
- 不画"身份接替 / retired"那条旧线（批 3a 已改成旁支副本，不存在接替主线）。
- 不改手机端；地图是电脑端功能。

## 会怎么错

- **长会话的一次性载荷**：预览 1200 字 × 400 轮 ≈ 480KB（未压缩）上限；再长就只回最后 400 轮并标 `truncated`。
- **老分支没有分叉点**：只能按时间戳猜前缀；如果时间戳缺失（0），分支会被当成"没有自己的新回合"，画成占位卡。如实标出来，不假装知道。
- **坐标与血缘分离**：拖动卡片不会改变分支关系；「整理」会清掉手动位置，用户要有心理准备（按钮文案不承诺保留）。
- **画板是只读快照**：会话还在跑时最后一张答卡可能显示"还没有回答"；不轮询、不假装实时。
