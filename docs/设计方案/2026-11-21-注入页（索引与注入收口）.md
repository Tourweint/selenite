# 2026-11-21 注入页（索引与注入收口）

> 状态：已落地（2026-11-21）。纯前端结构 + `context-inspect.ts` 一处 `editable` 元数据调整，零新端点。
> 本文留的是当时的取舍；现行口径以 `docs/基线文档/系统架构.md`、`接口-端点1` / `接口文档.md` 为准。

## 背景

用户对设置页的定位提出两件事：

1. **「记忆」这个名字不对**。记忆不是「存了什么就全量带上」，而是先挑、再按相关度注入；
   用户的原话是「先索引，然后再进行这个注入」。所以这一块应该叫「注入」，记忆只是其中的索引。
2. **注入内容要能在一个页面里改**。当时的 Agent → 上下文是只读的（2026-11-17 曾明确撤掉页内编辑），
   Agent → 工具只能改常驻 / 按需；「主要是用来看的，不是用来改的」。用户要求把可改的注入内容收进一处。

同一天用户还点名「工具也可以放在注入里」，随后又追加：**人设、技能也收进注入**，
Agent 只保留「派活」；注入排在左栏第二栏（Agent 组）第一个，tab 顺序按上下文位置来。

## 结论

左栏新增一级分区 **「注入」**，下挂六个 tab；Agent 分区只剩「派活」一项（不再挂 tab 条）：

| 顺序 | tab | route（保留旧 hash） | 口径 |
|---|---|---|---|
| 1 | 人设 | `#/settings/partners` | 它是谁：总管 / 各执事档案，点进去一页到底 |
| 2 | 工具 | `#/settings/tools` | 能力面：哪些工具常驻、哪些按需 |
| 3 | 关于我 | `#/settings/about-me` | 固定注入：全局一份主人档案，按 Agent 开关读取 |
| 4 | 索引 | `#/settings/memory` | 记忆索引：挑哪些值得长期记住；每轮只按相关度取几条 |
| 5 | 技能 | `#/settings/skills` | 操作手册：可开关、可导入；开关对新会话生效 |
| 6 | 上下文 | `#/settings/context` | 实际注入的账：一条请求装了什么；可编辑段就地改 |

- 左栏三组：日常 / Agent（**注入 → 模型 → 派活**）/ 系统；技能不再占一级。
- 左栏 10 项：日常 4 / Agent 3 / 系统 3。
- 六个旧 hash 原样保留为 tab 地址，老书签、抽屉「去编辑这个人」、技能页入口零改动。
  `currentSettingsPage()` 把六条旧子路由都认成 `inject`，`currentInjectTab()` 再从同一个 hash 认 tab。
- `#/settings/executor` 由 `SETTINGS_ALIASES` 落回 `agent`；`#/settings/avatars` 落 `inject`（人设 tab）。
- 不新造统一写接口：编辑弹层保存时写回各自源头，契约仍然是原来那几份。

## 可编辑矩阵（2026-11-21）

服务端 `SECTION_META` 的 `editable` 是字段级标记，页面再按当前角色过滤。

| 段 | 页面可改 | 写回 |
|---|---|---|
| `persona`（总管） | 是 | `PATCH /partners/chief { soul }` |
| `persona`（普通 worker） | 是 | `PUT /agent/worker-persona { persona }` |
| `user_profile` | 是 | `PUT /agent/user-profile { content }` |
| `partner_soul` | 是（2026-11-21 新增标记） | `PATCH /partners/:id { soul }` |
| `partner_contract_scope/decision/acceptance/report` | 是 | `PUT /partners/:id/contract`（整份四节一起写） |
| `partner_goal` | 是 | `PATCH /partners/:id { currentGoal }` |
| 七个行为纪律节 | 是 | `GET/PUT /partners/:id/discipline`（只合并当前一节；清空 = 这一条不注入） |
| `current_project` | **否**（2026-11-21 去掉标记） | 由会话所属项目派生，不是一段可单独改写的正文 |
| `verification_iron_law` / `clarify_contract` / `injection_guard` / `delegate_executor` / `tool_index` | 否 | 宿主代码常量 / 派生展示 |
| 技能索引、记忆召回 | 否 | 按会话冻结 / 每轮打分召回；开关与内容在隔壁 tab 或人设页 |
| 工具定义（名字 / 描述 / 参数） | 否 | 代码资产；这里只改常驻 / 按需 |
| 记忆正文 | 否 | 抽取出来的记录不改写；索引页提供「标过时 / 删除」 |

角色过滤：

- 总管 / worker 的默认开销会保留执事字段的 0 字槽位；这些槽位不给「可编辑」徽标和按钮，避免点开只能报错。
- 执事页的通用 `persona` 0 槽位也不给入口；身份由 `partner_soul` 那一行承载，不在两行上重复开同一个编辑入口。
- 当前会话模式同样可用：能认出执事就写执事，认不出按 `chatKind` 落总管 / worker。保存提示统一说
  「按源头的生效时机起效」——技能索引、当前项目这类按会话冻结的段要到新会话才变。

## 页面形态

- tab 条沿用 Agent 分区原来的 `.set-tabs` 卡片；六个 tab 在宽屏三列两行，窄屏两列。
- 人设 tab 保留原来的执事列表 / 二级档案页：点进 `#/settings/partners/<id>` 时不挂 tab 条，自带返回键。
- 技能 tab 原样搬运技能页（技能库、建议条、筛选、批量开关），只是外层从一级分区换成注入 tab。
- 上下文浮层里，`editable` 段在行头多一枚「可编辑」徽标；展开后有「改这一节」。
- 编辑弹层是统一的宽档 textarea：契约显示整份（四节一起改），纪律只显示当前一节，
  其余按源头直接填。保存成功后关弹层、重拉这一页；失败留在弹层里显示原因。
- 总管 / 执事 SOUL 不能清空（PATCH 的空串语义是「不改」，不是「清除」），空值直接禁用保存并提示。

## 明确不做

- **不新增统一写端点**：`POST /inject/section` 之类会把「各源头的版本、校验、回滚」再包一层，
  当前五个源头各有自己的端点与护栏，复用即可。
- **不在这一页改记忆正文**：记忆是抽取产物，改字会绕过抽取与巩固；要改就标过时重记。
- **不改工具描述 / 参数**：它们是提示词前缀资产，改文案要走代码与变更记录。
- **不把按人工具勾选搬进来**：仍留在「注入 → 人设 → 某人 → 能用的工具」；工具页标题的悬停里给了指路。
- **不自动应用整理建议、不自动删除**：继承 D18。
- **不恢复 2026-11-17 撤掉的请求历史 / 时间线**：本批只把编辑入口加回来。
