# 2026-11-23 外部记忆库接入边界（一读一写 · 两文件）

> **状态：边界定稿（2026-11-23 晚，用户口径）；实现未开始。**
> 本文只定 harness 与外部记忆库之间的读写边界。**库内表结构、打分、内化、定时任务归库主**，
> 本文不规定、不实现、不碰。
> 与《2026-11-23 外部记忆库接入（单槽位·适配器·Markdown文件库）》冲突处，以本文为准：
> `get`、库内化、多动作写入不在 harness 范围。

## 一、一句话

外部库只暴露两个 Python 文件：`ask.py` 读、`repair.py` 写。harness 只起进程、传 argv、读 stdout，
**不打开数据库、不知道表名、不参与内化**。

## 二、读（ask.py）

### 2.1 检索

命令（argv 数组，不经 shell）：

```
python ask.py <question> --json --limit <N>
```

harness 只用到的字段：

```json
{
  "groups": {
    "<组名>": [
      { "id": "...", "date": "...", "title": "...", "text": "...", "why": "..." }
    ]
  },
  "coverage": { },
  "unknown": "..."
}
```

- `id` 必填（页面 / 日志只记 id）；`date / title / text / why` 可缺。
- `dist / next / qtype / window` 等字段可以有，harness 今天不消费；以后要用再说。
- 组名不固定，harness 按数组扁平化，不按组语义分支。

### 2.2 目录 / 边界

```
python ask.py --catalog-only
```

- stdout 纯文本，最多 20 行；harness 缓存 10 分钟。
- 失败 = 空 + 旧文本保留；不阻塞对话。

### 2.3 失败与预算

- 非零退出 / 超时（15s）/ 非 JSON / 缺 `groups` → `ok:false`，按空结果处理，**不抛、不断对话**。
- harness 在槽位层再截断（轻召回 ≤3 条 / 800 字；工具调用按上限），不信任 `--limit`。
- 日志只记字数 / 条数 / 组数 / 耗时 / ok，不记 question 原文、不记正文、不记路径。

## 三、写（repair.py）

### 3.1 命令

```
python repair.py statement <body> [--about <YYYY-MM|YYYY-MM-DD>] [--tag <短标签>] --why <原因>
```

- 默认路径 = `ask.py` 同目录的 `repair.py`；可用 `PERSONA_REPAIR` 覆盖。
- 库主要换成别的脚本 / 表可以，**argv 形状和回执不变**即可；harness 不改。

### 3.2 字段

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `body` | 是 | ≤500 字 | 用户原话，不改写不总结 |
| `why` | 是 | ≤200 字 | 进 `change_log` 的原因 |
| `about` | 否 | `YYYY-MM` / `YYYY-MM-DD` | 事情发生时间 |
| `tag` | 否 | 短标签 | 如「时间修正」「错认主体」 |

### 3.3 回执与幂等

- 成功：exit 0，stdout 一行确认；`stmt_id = "us-" + sha1(body)[:10]`（harness 本地同式计算，便于对账）。
- 同一 `body` 重跑 = `INSERT OR REPLACE` 同一行，不新增。
- 失败：非零退出 / 超时 / 启动失败 → 返回 `ok:false` + 原因给模型；**绝不悄悄改写成内部记忆**。
- 每次写必过审批（`needsApproval: critical`），`PERSONA_WRITE_ENABLED` 默认关。

## 四、边界（谁不做什么）

harness 不做：

- 不打开 `persona.db`，不跑 SQL，不知道表名 / 字段。
- 不触发内化、不等待内化、不知道内化时间表。
- 不推断库的打分 / 排序；读多少条、怎么截断由 harness 槽位层定。
- 不提供 `get` / 全文回读；页面只展示 `ask.py` 返回的片段。

库主不做（对 harness 的约束）：

- 不要求 harness 传表名 / 字段名 / 库内 id 规则。
- 不改 `ask.py` 的 JSON 字段名、`groups` 结构、`repair.py` 的 argv 形状；
  要改按跨仓契约走（先改文档再改两端）。
- 不把内化失败暴露成读失败；读只认 `ask.py`。

## 五、开关与回滚

- `PERSONA_MEMORY_ASK` / `PERSONA_PYTHON`：读路径；未配置 = 读工具不上架。
- `PERSONA_REPAIR`：写路径；缺省同目录 `repair.py`；缺失 = 写工具不上架。
- `PERSONA_MEMORY_ENABLED` / `PERSONA_MEMORY_INJECT`：沿用现有口径。
- `PERSONA_WRITE_ENABLED`：写工具默认关。
- 回滚 = 清空上述 env 或 `MEMORY_BANK=false`，回到自带库。

## 六、建议（给库主，非约束）

1. **想让写进去的东西立刻被召回，就把它接进 `ask.py` 的检索源**（FTS / 向量）；否则要等内化。
   今天 `ask.py` 只做 BM25 / LIKE，向量在 `search_rag.py`，且 `search_rag.py` 不查 `user_statement`
   ——这是「亲口说的召不回」的真实原因。
2. `stated` / `inferred` 分开存；别让助手推断落进 `conf=user` 的层。
3. 内化按 `note_id + rev` 幂等；旧 rev 降权 / 标失效，不物理删；写 `change_log`。
4. 派生表随便重建，但 staging / 源表不要被 `build_*` 删。
5. `ask.py` 的 JSON 只增字段、不改名；改名算契约变更。

## 七、验收（边界层）

1. harness 代码里搜不到 `persona.db` / `sqlite`（外部库路径只有 argv）。
2. 读：未配置 → 工具不上架；配置 → 返回 hits；超时 / 坏 JSON → 空 + unknown，对话继续。
3. 写：同一 `body` 连写两次只有一行；无 `--why` 被拒；失败回给模型，内部记忆不新增。
4. 日志抽查：无 question / body / 路径。
5. 切走外接库后，内化完全不动（harness 侧无定时器 / 无调用）。
