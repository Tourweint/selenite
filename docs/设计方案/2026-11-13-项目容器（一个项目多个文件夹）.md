# 项目容器：一个项目 = 一个名字 + 一组文件夹（其中一个是主文件夹）

日期：2026-11-13
状态：**已落地**（2026-11-13，服务端 + 桌面端 web；手机端只保证字段纯增量）。
实施记录见 `docs/变更记录/2026-11-13-项目容器（一个项目多个文件夹·会话cwd快照）.md`；
结论已下沉到 `docs/基线文档/系统架构.md` §7 与
`docs/基线文档/接口-端点2-杂项日记与项目.md` §2.7 / §2.7.0a。

> 一句话：把「项目」从"一个目录"改成"一个有名字的容器，里面装着若干文件夹，
> 其中一个标为主文件夹"；会话在创建时钉死自己用哪个文件夹，从此不会走错路。

## 结论

| # | 定了什么 | 为什么 |
|---|---|---|
| 1 | 项目 = 名字 + `1..N` 个文件夹，恰好一个 `primary`（主文件夹） | 用户口径："它可能涵盖多个文件夹，然后有一个主要文件夹" |
| 2 | 会话**绑定即快照**：新建会话时把主文件夹路径写进会话，此后该会话只认这一条 | 现状 cwd 是全局单值，切项目会改掉所有会话的路——"分不清路"的主因 |
| 3 | 默认工作区只服务"没有项目的杂事态"，不再混进项目列表 | 工作区不是项目，摆在项目位置上就是把两种东西当一种 |
| 4 | 物理边界仍是"所有已登记根之并集"，根数量由项目内的文件夹决定 | 边界逻辑不动，只换根的来源 |
| 5 | 相对路径的唯一基准 = 主文件夹；附加文件夹必须写绝对路径 | 多根下"这个 `README.md` 指哪一份"必须有唯一答案 |

## 起因（用户原话）

2026-11-13，桌面端：

- "咱们这个项目就是一个项目，它可能涵盖多个文件夹，然后有一个主要文件夹，就可以设置的那种。"
- "现在只能设置一个工作区的根目录，以及其他的目录，也就是子项目吧，它啥都可以干的。咱们不应该这样，子项目应该有项目名称，然后可以添加多个文件夹。"
- "如果我们用我的这个智能体进行一些开发任务呢？那不就可能会分不清路嘛。"
- "这个侧边栏也需要改……这个改动可能比较大，主要是前端交互的逻辑。"

要的不是"再加一个目录字段"，是**项目的语义变重**：项目成为一个能被人叫出名字的工作单位，
目录只是它的零件。旧形态里"一个项目 = 一个目录"，所以项目名其实只是目录名，多几个目录就多几行，
助手也从来没有"我此刻在哪个项目里"这个确定的事实。

## 现状（2026-11-13 核对代码）

| 位置 | 现在是什么 | 为什么不够 |
|---|---|---|
| 存储 | `projects(root_path)`，一项目一根（`projects.ts` `SCHEMA`） | 一个项目装不下第二个文件夹 |
| 边界 | `workspaceRootsReal()` = 工作区根 ∪ 每个项目根 | 逻辑可复用，只是每项目只贡献一根 |
| cwd | `sessionCwd()` = 全局 `currentProject()?.rootPath ?? WORKDIR`（`agent/shared.ts`） | **全局单值**：所有会话共用一个 cwd，切一次项目全部会话换路 |
| 归属 | `ChatProjects`（内嵌 id → projectId）只在新建 `worker` 时写（`agent/shared.ts`） | 记了归属，却没有任何执行逻辑读它 |
| 侧栏 | 「项目」分区第一行是工作区根，标「默认」，后面才是项目（`web/app.js` `syncProjectRows`） | 工作区不是项目，占了项目的位置，两种语义混在一列 |
| 设置页 | 工作区卡 + 每项目一张卡、一行路径（`projectCardMarkup`） | 一行只能放一个目录，加一个文件夹就得再建一个"项目" |
| 文件浏览 | `GET /api/v1/files*` 带 `projectId` 时 `path` 相对项目根（`files.ts`） | 多根时"相对哪个根"没有答案 |
| 派活 | `ProjectRef.rootPath` 单值（`resolveDelegationProject`） | 多根时 worktree 与验收基线落在哪根不明 |
| 切换 | 2026-11-06 起侧栏撤掉切换，`PUT /workspaces/current-project` 保留为程序化面 | 于是 `current_project_id` 长期为空，所有会话的 cwd 事实上都停在默认工作区 |

最后一行是这次的真问题：**"当前项目"在库里存在、在提示词里注入、在 cwd 里生效，但界面上已经没有入口**。
它不是被删了，是被留在半空中——想让它有用却没人能设，想让它没用却还影响每一条会话。

## 决策

### D1 三层概念，各归各位

| 层 | 是什么 | 有几个 | 出现在哪 | 用途 |
|---|---|---|---|---|
| 默认工作区 | 用户自选的目录，没有项目名 | 全局 1 个 | 设置页一栏；侧栏只在"还没项目"的空态里提一句 | 没有项目时的新会话 cwd、兜底可写目录 |
| 项目 | 用户起的名字 + 一组文件夹 | 0..N | 侧栏「项目」分区、设置页项目列表、归档页 | 人用来称呼"我在干的这件事" |
| 文件夹（root） | 一个绝对路径，`primary` 或 `extra` | 每项目 ≥1，其中 primary 恰好 1 | 项目卡内部、悬停浮卡 | 物理边界的实际单位 |

默认工作区不再提供"浏览文件 / 资源管理器"的项目行；它退成设置页的一条，原因见 D3 与视图部分。

### D2 会话绑定即快照（这条是"分不清路"的正解）

现状的 cwd 解析链是：`会话显式 cwd` →（无）→ `全局当前项目` → `WORKDIR`。
全局那一环让路会漂。改成：

```
1. 会话显式 cwd（历史能力，保留最高优先）
2. 会话绑定的项目快照：{ projectId, rootPath }   ← 新建时写入，此后只读
3. 默认工作区 WORKDIR
```

- **写入时机**：`openChat` 新建会话时（`worker` 与 `chief` 都写；`task-` / `partner-` / 群不写，
  它们的目录由各自通道决定）。存进 durable doc（`ChatProjects` 扩成 `ChatBinds`，一条含 projectId + 主文件夹路径）。
- **读取范围**：`sessionCwd()` 改成 `sessionCwd(conversationId)`；`path-guard` 的 `cwd`、
  `current_project` 提示注入、bash 的默认 cwd，全部改读快照。全局 `currentProject()` 只剩一个用途：
  **新建会话时的默认项目**（用户没显式选就用它，它为空就用默认工作区）。
- **冻结而非跟随**：项目主文件夹以后被改，老会话仍在旧路径上跑（快照），新会话走新路径。
  理由是确定性：能让路自己变的机制，就是这个 bug 本身。想换路就新建会话。
- **快照失效**：目录被删 / 项目被归档 / 项目被硬删 → 该会话这轮退回默认工作区，
  并在 `current_project` 注入里写明"原项目目录已不可用（路径 X），本会话暂用默认工作区"，
  不要静默换目录让模型以为还在原地。

> 待落地时核对：`Harness.open` 的 `env: ({ cwd }) => ...` 已支持按会话给 cwd（`lifecycle.ts` 2026-11-13 核对），
> 但"新建会话时怎么把 cwd 写进 durable 的会话配置"还需在 pi-durable 1.4.0 的会话 API 上确认一次；
> 若写不进去，就完全走 `ChatBinds` 快照 + 每次 `env` 里查表，两条路结论一致，不必二选一。

### D3 路径纪律：一个基准，其余写全

- **相对路径的唯一基准 = 主文件夹**。`read` / `write` / `edit` 的 `path` 相对它解析，`bash` 的 cwd 也是它。
- **附加文件夹必须写绝对路径**。系统提示里逐条列出绝对路径，并明写这句纪律，例如：

```
当前项目：lifediary-harness
主文件夹（相对路径的基准，也是命令的 cwd）：
  <repo>
其他文件夹（与主文件夹并列，不是它的子目录；要读写请直接用绝对路径）：
  - 后端：<lifediary 手机仓>-backend
  - 手机端：<lifediary 手机仓>
两个文件夹里可能有同名文件（如 README.md）；不带路径的 README.md 一律指主文件夹里的那份。
```

- **不做 `@别名` 路径改写**。在 `beforeTool` 里把 `@app/x.ts` 换成绝对路径看着聪明，
  但审批记录、diff、工具回显、失败日志会同时出现两种路径写法，事后对不上；模型还会以为磁盘上真有这个路径。
  备选保留，首批不做。

### D4 物理边界：并集不变，重叠校验扩到"任意两根"

- `workspaceRootsReal()` 改为遍历 `projects → roots`，把每个存在的根 realpath 后去重入集合；
  默认工作区仍排第一（只影响展示顺序，不影响判定）。
- 重叠校验从"项目之间"扩到"任意两个已登记根之间"（含同一项目内的两个根）：
  同路径 / 一根在另一根内 / 一根包含另一根，一律 409。理由不变：同一文件被两个根同时认领，
  派活的 worktree、验收 diff、租约都会打架。
- 默认工作区与项目根之间：允许项目根落在工作区内（旧口径常态），但工作区根本身不能被登记成项目根。

### D5 数据模型

```
projects(id, name, created_at, archived, workspace_id, root_path?)   -- root_path 降级为 primary 的缓存列
project_roots(id, project_id, path, label, role, vcs, head, created_at, missing?)
  role: 'primary' | 'extra'
  唯一索引：UNIQUE(project_id) WHERE role='primary'（SQLite 部分索引）
```

- **为什么保留 `projects.root_path`**：它是 `Project.rootPath` 的来源，被派活、文件浏览、验收 diff、
  手机端 `ProjectsApi` 一起消费。保留它 = 这些消费方零改动；由 store 在写 primary 时同步维护，
  只当缓存，不当事实源（事实源是 `project_roots`）。
- `vcs` / `head` 从项目层移到根层（每个文件夹可能是不同仓库），项目层显示聚合（如"3 个仓库"）。
- `label` 可空，空则取 `basename(path)`；同名 label 在同一项目内拒绝（提示用户改名），
  因为侧栏浮卡里要靠它区分。
- 根 id 一律 uuid（对外 id 规矩不变）。

### D6 接口（契约变化）

| 端点 | 变化 |
|---|---|
| `GET /api/v1/projects` | 每项新增 `roots: [{id, label, path, role, vcs, head, exists}]`；`rootPath` 仍返回 primary（兼容） |
| `POST /api/v1/projects` | proposal 增加 `folders: [{path, label?}]` + `primaryPath`；旧的 `{name, path}` 仍可用（等价于单根） |
| `POST /api/v1/projects/:id/roots` | 新增：`{path, label?, role?}` 添一个文件夹；不建目录，只登记已存在的绝对路径 |
| `PATCH /api/v1/projects/:id/roots/:rootId` | 新增：改 `path` / `label`，只改登记不动磁盘 |
| `POST /api/v1/projects/:id/roots/:rootId/promote` | 新增：设为 primary，原子交换 role |
| `DELETE /api/v1/projects/:id/roots/:rootId` | 新增：移除登记；剩最后一个根时 400 `last_root` |
| `PATCH /api/v1/projects/:id` | 保留 `rootPath`（= 改 primary），语义不变 |
| `GET /api/v1/files*` | 新增可选 `rootId`；缺省 primary，`projectId` + `rootId` 一起给才切根 |
| `GET /api/v1/agent/chats` | 每项新增 `projectId` 与 `projectName`（会话归属可读） |
| 新错误码 | `root_not_found` / `duplicate_root` / `root_overlaps_root` / `last_root` / `root_missing` |

`POST /projects` 的 proposal 仍是"先申请、人确认"两段（这是既有的闸，不动）。

## 前端视图

### 一、设置 → 项目

```
┌ 设置 · 项目 ────────────────────────────────────────────────┐
│ 默认目录                                                     │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ <本地项目区>                                           │   │
│  │ 没有项目时，助手在这里干活。            [保存]         │   │
│  └──────────────────────────────────────────────────────┘   │
│                                                              │
│ 项目                                          [＋ 新建项目]  │
│ ┌──────────────────────────────────────────────────────┐    │
│ │ lifediary-harness           3 个文件夹    git: 2 个仓库 │    │
│ │  ● 主  lifediary-harness  <本地项目区>\...\harness  [改] │    │
│ │    ○   atlas              <本地项目区>\...\atlas    [改] │    │
│ │    ○   手机端              <本地项目区>\...\lifediary [改]│    │
│ │    ＋ 添加文件夹              [归档项目]                 │    │
│ └──────────────────────────────────────────────────────┘    │
│ ┌──────────────────────────────────────────────────────┐    │
│ │ atlas                                   1 个文件夹    │    │
│ │  ● 主  atlas  <本地项目区>\...\atlas                   │    │
│ └──────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────┘
```

- **只新增一种卡**：项目卡里套文件夹行，文件夹行不再是"卡片里的一行路径"，而是可增删的行。
- 路径平时是等宽只读文本，行尾「改路径」把它换成输入框 + 保存（沿用 `proj-path-input` 的既有交互）。
  多行时四个常驻输入框太重，所以默认不占输入框的视觉重量。
- 附加行的额外动作是「设为主」与「移除」；主行没有「移除」（要删就删整个项目）。
- 「设为主文件夹」= 一次 `promote`，弹一句确认：**"之后新建的会话会在新文件夹里干活；
  已经在跑的会话仍留在原文件夹。"**（快照语义必须当面说，否则用户会以为旧会话跟着变）
- 项目名可改；归档仍在项目级，文案与 2026-11-12 一致（磁盘不动、会话一起归档、可恢复）。
- 目录丢失的根：整行标黄「文件夹不在了」，不给「设为主文件夹」，允许「移除」或改路径。
- 空态：`还没有项目。新建一个，或者先只用默认目录。`
- 术语：一律叫「文件夹」而不是「目录 / roots / 根」，界面上不出现 roots / rootPath 这类字段名。

### 二、侧栏「项目」分区

```
项目                                    [＋]
┌───────────────────────────────────────┐
│ ▣ lifediary-harness              3 ⌄  │   ← 三行浮卡展开文件夹
│   会话：a、b、c                        │
└───────────────────────────────────────┘
┌───────────────────────────────────────┐
│ ▣ atlas                           1 ⌄ │
└───────────────────────────────────────┘
  还没有项目（用默认目录 <本地项目区>）    ← 空态一行，仅在没有项目时出现
```

- **工作区行从这里撤掉**。分区里只放项目；默认目录只在空态里以一句说明出现，需要改就去设置。
- 项目行右侧是文件夹数徽标（`3`），**点开是浮卡，不是新页面**（72px 轨道放不下内联列表，
  现有 `syncRailProject` 的浮卡机制正好复用）。
- 浮卡内容：每个文件夹一行 = 角色点（实心=主）+ label + 路径（等宽、可截断）+ 两个图标按钮
  （浏览文件 / 在资源管理器中打开）。主文件夹那行额外标「主」。
- **行为变化**：项目行从"只读总览"变成"可选中的总览"——
  点行 = 选中该项目（单选高亮），选中态决定**下一个新对话**落在哪个项目；
  行尾 `＋` = 直接在这个项目里新建对话。取消选中回到"杂事 / 默认目录"。
  这是对 2026-11-06「不用切换」的一次反向修正：那时项目只是目录，切换确实没意义；
  现在项目有名字、有多个文件夹、并且决定 cwd，**选中就是在告诉助手"我在这个项目里干活"**，
  所以它重新变得必要。它依然是"低摩擦单选"，不做出"每个会话各自一套项目树"的重型切换器。
- 收起轨道（`syncRailProject`）：按钮悬停直接浮同一张项目卡，不新增形态。

### 三、对话里的归属（配套，最小）

- 输入框上方 / 会话标题旁，一个弱 pill：`lifediary-harness · 主文件夹`，hover 出全部文件夹。
- 点它开一个小面板，只有一项动作：**「改用另一个项目（仅本会话之后）」**，
  它写的是"之后"——因为快照是冻结的，中途换项目只影响本会话余下的轮次，不回改历史。
  不做"把历史搬到新项目"这种数据改写。

### 四、视觉与交互约束（沿用既有语言）

- **只吃现有 token，不新造颜色**：卡面 `--surface` + `--composer-border` 细边 + `--r-sm`；
  控件照 `.ghost` / `.set-input` / `.btn-primary` / `.proj-tag`；字用 `--font`（宋体），路径用 `--mono`。
  强调色只在三处出现：主文件夹的实心点、选中的项目行、主按钮。
- 设置页默认目录卡刻意比项目卡淡一档（`--surface-low` + 虚/细边），让它一眼看出不是项目。
- 不给每根配一种颜色——颜色会被读成"这些根是不同类别"，而它们只是同一项目的并列零件。
- 浮卡阴影用 `--shadow-menu`，不引入第二套阴影；不新增卡片形态。
- 原型：`docs/设计方案/原型/15-项目容器-侧栏与设置.html`（配色与卡片照 `web/style.css` 的 Paper 主题）。

| `src/agent/lifecycle-injections.ts` | `current_project` 注入改成"主文件夹 + 全部文件夹清单 + 同名文件纪律" | 注入文本是缓存前缀资产：改了要进变更记录（既有硬约束） |
| `src/agent/session.ts` | `openChat` 写 `ChatBinds`（worker 与 chief 都写） | 不能写失败就拦建会话；失败退化为"无归属" |
| `src/files.ts` | 增加 `rootId`，缺省 primary | 路径解析要复用根校验，别自己拼 |
| `src/delegation*.ts` | `ProjectRef` 增加 `roots[]`，worktree / 验收基线只认 primary | **附加根不进 worktree**：并发写无隔离，登记为已知边界 |
| `src/projects.ts` HTTP 层 | 新增 4 个 roots 端点；`GET /projects` 带 roots；`GET /chats` 带 projectId | 手机端只读 `rootPath`，字段纯增量，不破坏 |
| `web/app.js` + `style.css` | 侧栏项目卡与浮卡重写；设置页项目卡重写（从"一行路径"到"多行文件夹"） | 现文件 1MB 单文件，改动集中在这两段函数，不顺手重构别的 |
| `docs/基线文档/接口-端点2…` | 端点表 + 错误码 | — |

**改动量判断**：后端约 3 个文件实质改动 + 4 个文件小改；前端是两段渲染函数与一套 CSS 的重写。
真正的成本在"迁移 + 旧消费方回归"，不在于加字段。

## 备选与为什么不选

| 备选 | 为什么不选 |
|---|---|
| 只改视图：项目行下面把已有项目"分组"成多目录（不改存储） | 分组是假的：边界、cwd、派活都不认这层分组，一跑任务就露馅 |
| 保留全局 `currentProject` 做 cwd，只在设置里补一个切换入口 | 切换改的是**所有会话**的路。这正是"分不清路"的来源，不该被修好入口 |
| 一个项目内多个根，但 cwd = "最近一次操作过的根" | 隐式状态：模型和人都无法预测下一句会在哪跑；调试时无法复现 |
| 一个项目就是一个 git 仓库（多根一律不许） | 用户的真实项目就是跨仓（主干 / 前端 / 手机端），挡掉等于让他继续造多个"项目" |
| `@别名` 前缀改写路径 | 见 D3：双写法污染审批与日志 |
| 项目 = 目录集合，但取消默认工作区 | 没有项目时总得有个落点；删掉它会让杂事态的 cwd 变成进程目录 |

## 影响面与分期

| 批 | 内容 | 出口条件 |
|---|---|---|
| 批 1（后端骨架） | `project_roots` + 迁移 + `roots[]` 读接口 + `workspaceRootsReal` 遍历根 + 重叠校验 | `pnpm typecheck`、`projects.test.ts`、`path-guard.test.ts` 全绿；旧库迁移后列表不变 |
| 批 2（会话快照） | `ChatBinds` + `sessionCwd(id)` + 注入改写 + `chatKind=chief` 也写归属 | `http` 探针：两会话不同项目互不干扰；重启后各自仍在自己项目里 |
| 批 3（写接口） | add / patch / promote / remove 四个端点 + 错误码 + `files?rootId` | `http` 探针覆盖四个动作与五个错误码 |
| 批 4（界面） | 侧栏项目卡 + 浮卡 + 设置页项目卡 + 对话归属 pill | 浏览器实机；截图归档 |
| 批 5（跨仓） | 手机端只读列表按 primary 显示（不改多根 UI） | 手机端能连上、文件入口只指 primary |

批 1、2 可以并行（2 依赖 1 的 `roots` 读取，但可以先按 `rootPath` 兼容跑）。

## 安全与回滚

- 每个新根都走 `validateProjectRoot` 同一套：绝对路径、已存在、可写、非盘符根 / 主目录及其上级 / 系统目录，
  realpath 后再判重叠。
- 回滚开关 `PROJECT_MULTI_ROOT=false`：只读 `projects.root_path`（= primary），忽略 `project_roots` 的多余行，
  写 roots 的端点返回 `400 multi_root_disabled`，cwd 退回全局 `currentProject()` 的旧形态。
  一行 env 回到本次改动之前，不需要改代码。
- 迁移只加表不删列；旧库与新库都能被同一份代码打开（迁移幂等，`IF NOT EXISTS` + 只在 `project_roots` 为空时灌数据）。

## 明确不做

- 不做"项目内文件夹之间的代码搜索 / 全项目符号索引"——跨根检索是独立能力，另立项。
- 不做"一个会话可以在项目间自由漂移"——归属是创建时钉死的；要换就是新会话。
- 不做"把主文件夹的历史会话迁移到新主文件夹"这类数据改写。
- 不做"附加根进 worktree / 合并 / 独立租约"：只有 primary 的 git 仓库参与隔离，
  附加根是共享读写（并发写冲突不在本次解决范围）。
- 不做项目树、不做嵌套项目（项目之间仍平级）。
- 不改审批策略、不改派单权限模型；不顺手重构 `web/app.js` 的其他部分。

- 单测：`projects.test.ts`（多根增删改、promote 原子性、重叠拒绝、`last_root`、回滚开关）、
  `path-guard.test.ts`（根集合含附加根）、`files.test.ts`（`rootId` 缺省 / 显式）、
  `session` 侧（两会话不同项目 cwd 不串）。
- `pnpm typecheck`；`pnpm --filter @lifediary/server test`。
- `pnpm --filter @lifediary/server http`：真起服务 + 真 HTTP，覆盖四个 roots 端点与五个错误码。
- 隔离实例：旧 `projects.sqlite` 副本迁移后列表 / 根数 / primary 不变，再依次加根 → promote → 移除 → 归档 → 恢复。
- 浏览器实机：侧栏浮卡、设置页多行文件夹、promote 确认文案、对话 pill。

## 这条会怎么错

- **快照冻结会被当成"没生效"**。改了主文件夹，老会话还在原地，用户第一反应会是"没改成功"。
  对策只靠把话说在前面（promote 的确认文案 + 会话 pill 上标"创建时绑定"），不靠改机制。
- **多根 + 同名文件仍可能让模型读错**。提示词能降低概率，不能根除。
  真出问题时表现为"改了一个文件，diff 里没这行"——需要靠 `write` 的绝对路径回显排错，而不是靠猜。
- **迁移期的双份事实源**（`projects.root_path` 缓存 vs `project_roots`）会漂。
  只能靠"所有写路径只走 store 的一个方法"约束住；绕过 store 直接 UPDATE 就会漂。
- **`chief` 会话也开始绑定项目**，可能与"总管是全局人格"的既有口径冲突（总管此前刻意不按项目分组）。
  如果落地后发现总管被绑死在某个项目里造成了"杂事不好问"，就把 chief 的归属降级为"只影响 cwd、不影响注入"，
  这一步留作可调参数，不进首版。
