## 一、问题与结论

执行器池（2026-11-22，D37）已经是宿主的默认：`executor-config.envEmployee()` 缺省返回
`pool`，前端「新建任务」强制 pool，manager 子单经 loopback 池桥也进池。池有一进程一票、
跨票复用、车道 / 准入 / 重试 / 取消等调度秩序。

`native` 档（`ts/packages/chancellor/src/employee/native.ts`，每张单 spawn 一个
`worker-main.ts` 子进程）只剩三个作用：

1. 设置页里的「旧：每票一进程（回滚用）」；
2. `CHANCELLOR_EMPLOYEE=native` 的整体回滚；
3. 池不可用时（典型：只拷 dist 单文件产物、没有源码 `pool-main.ts`）的自动兜底。

用户口径（2026-11-23）：池已经承担本机派活，旧档没有保留价值，删掉。

结论：**删除 native 执行器这一档**。本机派活统一走池；外部 CLI（CodeBuddy / Qoder /
Claude Code / Codex / OpenCode / 豆包）完全不受影响。`worker-main.ts` 保留——分管宰相
（`--role manager`）仍在用它。

## 二、删除范围

### 2.1 chancellor 包

- 删 `src/employee/native.ts`（spawn / stdout-stderr / stdin 插话 / 进程注册表 / 模型 env）。
- `employee/index.ts`：去掉 native 的能力声明、工厂、导出；`createEmployee("pool")`
  不再回落 native——未接线时由 `createPoolEmployee().run()` 返回结构化失败
  （`池执行器未接线…`），不把单派进起不来的进程。
- `types.ts`：`EmployeeKind` 去掉 `native`；`EmployeeProfile.modelRoute` 注释改为本机
  运行时（池）共用。
- `config.ts`：`readEmployee()` 白名单去掉 native，缺省改 `pool`；`resolveProfile` /
  `profileEnv` 的 native 分支并入 pool。
- `index.ts` `workerKindOf()`：历史 `ticket.json.employee="native"` **映射到 pool**，
  避免老单恢复时被环境变量带去外部 CLI。
- `worker-tools-source.ts`：删只有 native 用的 `workerToolsArgValue()`。
- `worker-main.ts` 保留（manager 入口）；worker 角色与 `--tools` 解析暂留，属于死分支，
  不在本批拆（见 §五）。

### 2.2 宿主

- `executor-config.ts`：`EXECUTOR_KINDS` / `SELECTABLE_EXECUTOR_KINDS` / `EXECUTOR_KIND_INFO`
  去 native；native 的「干活模型 + providerId」解析改名并只服务 pool；`executorLine` /
  `executorSummary` 去 native 文案。
- `worker-control.ts`：去 native stdin 转发；`employee=pool` / 历史 `native` / 无 employee
  字段（老单）统一走池控制面。
- `delegation-actions.ts`：去 `abortNativeWorker`；没有票级控制器时统一 `abortPoolTicket`。
- `index.ts`：池入口不存在时的日志改为「本机派活不可用」，不再说回落 native；
  `POOL_MANAGER_BRIDGE` 退役（见 §三）。
- `executor-probe.ts`：native 的「本机内核不在这里探测」分支改挂 pool。
- 设置页 `settings-executor.js`：去掉 native 卡；`providerId` 的读写改挂 pool。

### 2.3 探针与单测

- 探针 `escalation-probe` / `delegate-wake-probe` / `delegate-chain-probe` / `matrix-probe`
  的 `CHANCELLOR_EMPLOYEE` 从 native 改 pool；池用 `WORKER_POOL_DB_DIR` 隔离到临时目录，
  上报脚本改用池的 `WORKER_POOL_FAUX_MODE=escalate`。
- `worktree-cleanup-probe` 只把持久化标签 `employee: "native"` 改 `"pool"`（runner 是替身，
  不真起 worker）。
- 单测：`executor-config.test.ts` / `cli-employees.test.ts` / `worker-control.test.ts` /
  `delegation-actions.test.ts` / `delegation-steps.test.ts` / `worker-persona-source.test.ts` /
  `worker-tools-source.test.ts` 里的 native 档改 pool 或删除（只保留 pool 覆盖）。

### 2.4 保留

- `worker-main.ts`（manager 角色）、`worker-persona.ts`、`worker-tools-source.ts`（池在用）、
  `worker-continue.ts`、`escalation-payload.ts`、`worktree` 隔离。
- 车道名 `native`：它是「本机运行时」的车道键，pool 仍在用
  （`laneNameOf("pool") === "native"`，`CHANCELLOR_LANE_CAPS=native:4` 不破坏）。

## 三、兼容与迁移

- **`CHANCELLOR_EMPLOYEE=native`**：映射到 pool；不报错。宿主与 chancellor 两侧都按
  「非法值 → 缺省 pool」处理，并在日志里留一行（不刷屏）。
- **`.data/executor.json` 的 `employee: "native"`**：读时映射到 pool。若文件里只有
  `profiles.native` 而没有 `profiles.pool`，把 native 的模型 / 权限 / providerId 当作
  pool 的缺省读出来，避免用户之前的「干活模型」设置凭空消失。
- **历史 `ticket.json.employee="native"`**：`workerKindOf()` 映射到 pool；续跑 / 崩溃恢复
  按池重跑（同内核、同 REPORT 契约；native 的会话号本来就不参与续接）。
- **`POOL_MANAGER_BRIDGE` 退役**：删 native 后 manager 子单没有可回落的第二运行时；
  保留 `false` 等于留一个「关掉必坏」的假回滚。改为池可用即起桥。
- **回滚口径**：本批之后 native 没有代码级回滚；池出问题用 git revert，或把
  「设置 → 派活」切到外部 CLI。这一条写进变更记录，不假装还有 env 开关。

## 四、取舍与备选

| 选项 | 结论 |
|---|---|
| 保留 native 只做池不可用兜底 | 不选。用户明确要删；兜底路径半年不用一次，却要维护两套 spawn / 插话 / 超时 / 上报。 |
| 把池打包进 dist，让 dist 也能本机派活 | 本批不做（见 §五）。 |
| 把 `worker-main.ts` 的 worker 角色一起拆掉 | 本批不做。它和 manager 角色共用 Harness / 工具 / 续行循环，拆它是独立手术。 |
| 车道 `native` 改名 `pool` | 不做。`CHANCELLOR_LANE_CAPS` 是运维口径，改名只为好看，代价是破坏已有配置。 |

## 五、明确不做

- **不把池打进 dist 单文件产物**：`node dist/index.js` 下池入口（源码 `.ts` + tsx）不存在，
  本机派活直接报「池执行器未接线」。桌面壳与日常都走源码态
  （`node --import tsx src/index.ts`），dist 仍只保证「能起、能服务」。要支持就把
  `pool-main.ts` 加成第二构建入口——单独立项。
- **不拆 `worker-main.ts` 的 worker 角色**：删 native 后它不可达，但和 manager 共用主体；
  等 manager 侧也换实现时一起收。
- **不改外部 CLI、MCP、手机（phone）档**。
- **不改 `WORKER_POOL_SIZE` / 车道 / 准入 / 重试等调度口径**。

## 六、验证口径

- `pnpm typecheck`（chancellor + server）。
- `pnpm --filter @lifediary/server test` 全量单测。
- 相关探针：`escalation`（池上报 + 答复回到池）、`delegate-wake`、`worktree`
  （worktree 生命周期不依赖执行器档）。
- 手工核对：设置 → 派活只剩一个本机档（池）；`CHANCELLOR_EMPLOYEE=native` 起服务
