# 全局工具池：设置 → 工具页（统一改）+ 按人覆盖（2026-11-17）

## 状态

**已落地（同日）**。契约下沉 `接口-端点7-权限技能与开关.md` §2.22 / §2.22.1；
机制下沉 `系统架构.md`（`tool-pool.ts` 模块行、`tool-index.ts` 行）。冲突以长期文档为准。

## 背景

工具面已经是「全局默认 + 按人覆盖」的形状，但只做了一半：

- 2026-11-16 C 段把 8 个低频工具做成 deferred（按需），**名单是代码常量**；
- 2026-11-17 上午给按人页加了「按需 → 常驻」提升（`partners.promoted_tools`）；
- **没有全局界面**：要把一个工具从"常驻"改成"按需"（或反向），只能改代码 + 重启。

用户要的是项目里统一的那套模式：**全局配一份默认，按人还能额外设置，新人跟随全局**。
工具和人都照这个思路来。

## 内核约束（决定了形态）

2026-11-17 核对 `pi-durable/dist/harness/agent.js:222-245`：

- `deferred` 是**工具注册期属性**（`tool.deferred === true`），只在 `openHarness()` 里
  `markDeferred()` 时打上；
- `modelTools` 只能按名字 `add/remove`，**改不了 deferred 属性**；
- 所以：**全局池改动必须重开 Harness（= 重启服务）才生效**；
- **按人只能"提升"**（deferred → `add`，下一轮生效）。按人把常驻降为按需做不到：
  `remove` 掉之后工具既不被 offer、也不在 `tool_search` 的可加载清单里，等于"取消勾选"。

用户拍板：保存后**只提示"重启服务后生效"**，不在页面里做重启按钮 / 自动重开 Harness。

## 设计

**全局池存"按需例外名单"**，与 `worker-tools.json` 的 `disabled`、原 `DEFERRED_TOOL_NAMES`
同一套"缺省明确"的思路：文件缺失 = 代码默认 8 个；新增工具默认常驻。

```
.data/tool-pool.json      { "deferred": ["routine_manage", …] }     AGENT_TOOL_POOL_PATH 可换
```

- 空数组合法 = 全部常驻（此时不注册 `tool_search`，也没有 `tool_index` 段）；
- 坏 JSON / 缺字段 → 回落代码默认（配置坏了不能把工具面搞没）；
- tmp+rename 原子写；读取带 mtime+size 缓存（每轮工具面判断会读几次）。

**两池模型**（页面语言）：每个工具落在「常驻」或「按需」；默认常驻，只有名单里的进按需。
**生效**：保存 → 提示重启；重启后 `markDeferred` 按新名单重建工具面。
**按人**：人设页勾选 = 能不能用；「按需/常驻」胶囊 = 把按需工具单独提升（下一轮生效）。
新人 `promotedTools` 为空 → 天然跟随全局。

## 契约

| 面 | 变化 |
|---|---|
| 存储 | `.data/tool-pool.json` `{deferred: string[]}`；默认值 = 代码里的 8 个 |
| `GET /api/v1/agent/tool-pool` | `{ok, enabled, deferred, defaults, applied, restartPending, tools:[{name,group,summary,chars,tokens,deferred}]}`；`applied` = 当前 Harness 实际用的名单（null = 还没装配）；`restartPending` = configured ≠ applied |
| `PUT /api/v1/agent/tool-pool` | body `{deferred: string[]}` 全量替换；非数组 / 非字符串 / >64 / 未知名 → 400；**`tool_search` → 400**（自锁）；`AGENT_TOOL_INDEX=false` → 400。只写文件，不重开 Harness |
| 运行时判定 | `isDeferredTool` / `markDeferred` 读配置；但 `partner-tools` 的 apply **改认注册对象上的 `tool.deferred`**（配置已改、Harness 未重开时不能口径漂移） |
| 前端 | 设置新增「工具」页（侧栏放在「上下文」后）：工具 / 分组 / 摘要 / 定义 token / 用量 / 池切换；保存 + 「恢复默认」；`restartPending` 时常显提示 |

## 为什么不做「按人降级」

见上面内核约束。按人的"取消勾选"已经把工具从该人的工具面拿掉，只是它同时也不可被
`tool_search` 加载——语义是"不可用"，不是"可搜"。要做真正的按人按需，得把所有工具改成
注册期 deferred、用 `add` 表达常驻，那是另一个架构（每个会话都必须有工具面配置，
风险高），另立项。

## 刻意不做

- **页面内重启按钮 / 自动重开 Harness**（用户拍板；重开会 abort 正在跑的轮次）。
- **按人降级**（内核做不到，理由见上）。
- **让 `tool_search` 进按需**（自锁死）。
- **不动 worker 工具面**（`worker-tools.json` 语义不同，另立项）。
- **不动工具描述 / 注册顺序 / 内核**。
