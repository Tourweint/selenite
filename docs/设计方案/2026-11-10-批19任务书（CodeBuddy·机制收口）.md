## 一、总管 clarify 契约（七 #4）

1.1 `ask_user` 工具已落地（批 11）。本批给它加**"开工前必问"的契约**：
   新增常量 `CLARIFY_CONTRACT`（`delegation.ts`），注入总管 persona 段之后：
   - **大活**（要改 3 个以上文件 / 要跑命令 / 涉及不可逆操作）开工前，**先用 `ask_user` 确认三件事**：
     ① 对象是什么（哪个文件/哪个 App/哪段时间）② 你期望的结果长什么样 ③ 怎么算做好了；
   - **一次只问一个**，别把三个问题塞进一次；
   - **小活不问**（一句话能答的、单文件小改）——问多了是骚扰。
1.2 开关 `AGENT_CLARIFY_CONTRACT`（默认 true）。
1.3 单测：常量被注入；固定字节。

## 二、VerifiedAnswer：提问答案沉淀（二 §六）

2.1 `ask_user` 的答复（走 `POST /approvals/:callId/answer`）成功后，把
   `{ question, answer }` 作为一条 `kind=fact`、`source="verified_answer"` 的记忆写入
   （scope 用发起会话的 scope）。
2.2 目的：同一个问题下次不用再问（"这个主人已经答过"）。
2.3 开关 `AGENT_VERIFIED_ANSWER`（默认 true）。
2.4 单测：答复后落一条记忆；开关旁路；群会话不落（群不进个人记忆）。

## 三、执事"产物交接"习惯（三 §四#1）

## 四、任务中心"过程关口"投影（三 §四#3）

4.3 开关 `TICKET_GATES`（默认 true；false → 不返回该字段，前端不显示）。

## 五、多副本对齐（三J）

5.1 场景：同一个请求同时派给 ≥2 个执事（扇出）。
5.2 语义：**请求方等最后一个副本结束再一起消费**；但**人的消息不等**（立即进）。
5.3 实现范围**收紧**：只做"同 `requestId` 的多张单可以归并展示"——
   在 `delegation-api.ts` 的列表/详情里，把同 `requestId` 的单标一个 `groupId`（= requestId），
   前端把同 group 的单显示成一张卡（"3 个副本，已完成 2"）。
   **不做**自动等待/自动消费（那是更大的机制，留待有真实场景再做）。
5.4 开关 `DELEGATION_FANOUT_GROUP`（默认 true）。

## 六、授权依据 + 恢复前重验（四 §4.3）

6.1 批 16 已给回执加了 `authority {level, at}` 列（还没写入方）。
6.2 本批**补写入方**：派单受理时把当时的审批档位写进回执（`approvalLevel` + 时间）。
6.3 **重验**：`resumeTicket`（续跑）时，比对"当时的档位"与"现在的档位"：
   - 现在更严（`none` → `ask-critical`/`ask-all`）→ **允许续跑但记 warning**（不阻断，避免打断人）；
   - 现在更松 → 直接续跑；
   - 档位读不到 → 按"更严"处理。
6.4 开关 `DELEGATION_AUTHORITY_RECHECK`（默认 true）。
6.5 单测：写入 authority / 更严时记 warning / 更松时直接跑 / 读不到按更严。

## 七、ConfirmationGate：世界状态重验（四 §9.2）

7.1 现状：审批放行绑的是**工具参数指纹**（8c）。
7.2 本批加一个**轻量版**：对 `write` / `edit` 这两个高危写工具，批准后执行前，
   **重新确认目标路径仍然存在且未被别人改过**（对比批准时的 `mtime+size`）；
   不一致就**拒绝执行**并回一句"目标文件在你批准之后变过了，请重新确认"。
7.3 **只对 write/edit**，不对 bash（命令的世界状态无法确定）。
7.4 开关 `AGENT_CONFIRM_WORLD_STATE`（默认 **false**——这是收紧行为，先观望）。
7.5 单测：文件未变 → 放行；文件变了 → 拒绝且文案正确；开关旁路。
