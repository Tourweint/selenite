# 定时任务重做（可编辑内容 · 统一触发器）

## 〇、一句话

**一条定时任务 = 到点叫一个人，拿一段可编辑的指令自己跑一轮。** 定时任务页和人设页共用一张清单、一个编辑器、一套触发词；手动新建统一走提醒/主动轮引擎（保住手机本地闹钟），Agent 建的高级例行规则仍在 routines 里，同清单显示、内容可改、高级触发只读。

## 一、现状与根因（2026-11-17 核实）

| 用户感受 | 代码事实 | 根因 |
|---|---|---|
| "改不了内容" | `routineProjection`（`companion-api.ts`）只回 `id/partnerId/name/triggers/sessionMode/enabled/revision/...`，**没有 `prompt`** | 例行列表拿不到指令正文，前端想改也没有原料 |
| "改不了内容" | `PATCH /agent/reminders/:taskId` 文档与实现都写着只收时间规则，**不含 `text`** | 提醒类任务（含手动新建的隐藏任务）只能改时间 |
| "它到底是做什么" | 列表只显示 `name`（新建时=文本前 40 字）+ 谁 + 频率 | 看不到完整指令，也看不到上一轮跑成没跑成 |
| "触发类型还不一样" | 定时任务页新建：单日/区间/每天/每周/每月；人设页例行新建：`cron / interval / once / event` 原文 | 两套表单、两套词汇 |
| "例行任务只能暂停、改时间" | 人设页例行列表只有 `启用/立即跑/展开历史/删除`，没有编辑；定时任务页只有 `改时间/暂停/删除` | 两个页面各缺一半 |

另外发现两处顺带修正：

1. 手动新建选"总管"时 `partnerId` 传 `null`，`POST /agent/reminders` 会 `openChat(undefined)` **新建一个空会话**，任务并不落在总管主会话。改成显式 `partnerId="chief"`。
2. 可见触发的例行/定时任务，回读会话时会把模型侧透明头 `[Scheduled run context] turnAuthority: autonomous` 原样显示给用户。这是给模型看的，不是给人看的。

## 二、目标形态

```text
设置 → 定时任务 / 人设 → 定时任务（同一套行与编辑器）

┌────────────────────────────────────────────────────────────┐
│ 明天 09:00   每天早上问安             编辑 暂停 立即跑 历史 删除 │
│             阅读助手 · 每天 09:00 · 触发可见                     │
│             指令：用你自己的话跟他说一句早安……                │
└────────────────────────────────────────────────────────────┘
```

### 2.1 一个编辑器

- **做什么**：多行 textarea。下方固定一句：
  "到点后，TA 会拿这段话自己起一轮：能查就查、能做就做，然后把结果回在你们的主会话；做不了会回一句。不是照念这段话。第一次可以先点『立即跑』试一次。"
- **到点叫谁**：总管 / 某个执事。新建可选，编辑只读（换人请删了重建；提醒任务换人会换会话归属，本次不做）。
- **什么时候**：单日 / 区间 / 每天 / 每周 / 每月（复用现有日历 + 滚轮）。不再暴露 cron/interval/event 原始字段。
- **触发消息**：
  - `可见`（默认）：会话里留一条你发的指令，做完再回你；
  - `像 TA 主动找我`：触发指令隐藏，只看到模型回复。
- 例行规则额外：名称（≤40）、`接着聊 / 每次新开`。`interval` / `event` / 多触发器 / 复杂 cron 只读显示，内容照改；改时间请交给 Agent。

### 2.2 一张清单

行内统一：下次时间、标题、谁 · 频率 · 触发可见/隐藏、**指令预览**；操作 `编辑 / 暂停·启用 / 立即跑 / 历史 / 删除`。`整理记忆` 行是独立调度器，保留 `改时间 / 暂停 / 删除`。

## 三、为什么手动新建走提醒（而不是全部改成 routine）

| 方案 | 暂停/历史 | 手机本地闹钟 | 代价 |
|---|---|---|---|
| **A. 手动新建 → `/agent/reminders`（采用）** | 本次给提醒补齐 | **保留**（手机只同步 reminders） | 要给提醒补 runs/run_now/PATCH 字段 |
| B. 手动新建 → routines + visibility | 现成 | **新建任务不再有手机闹钟** | routines 加列、改执行链；手机端还得另接 |
| C. 只补编辑，两套能力继续不一致 | 不一致 | 提醒保留 | 没解决"对齐" |

用户要的是界面与能力对齐，不是换存储引擎。A 的代价可控，且不制造手机端回归。

## 四、契约增量

### 4.1 routines：把内容放出来（纯增量）

- `GET /api/v1/routines` 与 POST/PATCH 响应里的 `routineProjection` 增加 **`prompt`**（完整指令，≤100k）。
- `PATCH /api/v1/routines/:id` 补 `name` / `prompt` 校验：非空、`name` ≤40、`prompt` ≤100k，与 POST 同口径。
- 不新增列、不改执行链、不碰 triggers。

### 4.2 reminders：补五个能力（纯增量，老数据零行为变化）

`ReminderInput` 新增：

```ts
enabled?: boolean;                    // 缺省 true；false = 暂停（到点只续排，不跑模型）
visibility?: "hidden" | "visible";    // 缺省 hidden（旧行为）
```

端点：

| 端点 | 变化 |
|---|---|
| `GET /agent/reminders` | 列表项多 `enabled`、`visibility`；新增 `?includePaused=1`。**不带该参数时过滤 `enabled=false`**——手机端不传，继续只同步真会响的任务 |
| `POST /agent/reminders` | body 可带 `enabled` / `visibility`；201 回显 |
| `PATCH /agent/reminders/:taskId` | 支持 `{text?, enabled?, visibility?, at?, repeat?, weekdays?, dayOfMonth?, until?}`。只给 `enabled`/`text` 时用原规则重排，不强制前端传时间。仍是"取消原任务 + 同一 `reminderId` 重排"，下一次触发时间按规则归一化 |
| `POST /agent/reminders/:taskId/run_now` | 新增。找活任务 → 跑一轮模型 → 记历史 → `{ok,text,error}`。`SCHEDULED_TASK_MODEL_RUN=false` → 400 |
| `GET /agent/reminders/:reminderId/runs` | 新增。返回最近执行记录（≤20），字段 `{id, reminderId, partnerId, trigger, status, at, endedAt, summary?}` |

`status` 不变；暂停用 `enabled` 表达，不新增状态枚举，避免手机端 `isLive` 误判。

### 4.3 执行历史存储

新增 `.data/reminder-runs.json`（`REMINDER_RUNS_STATE_PATH` 可改）：

- 同步读改写（进程内单线程，避免并发丢更新），全局上限 500 条；
- 只记枚举 + ≤200 字摘要，**不存原始错误**（日志纪律：原始错误只进服务端日志，可能含上游地址）；
- `trigger` = `scheduled` / `manual`。

## 五、前端

- `settings-reminders.js` 原地演化：`openReminderModal` → `openScheduledTaskModal`，四种入口（新建 / 编辑提醒 / 编辑例行 / 改记忆时间）共用日历与滚轮。
- 新建**统一** `POST /agent/reminders`（可见/隐藏都走这套）；删除原来的"可见→routines、隐藏→reminders"分叉。
- 编辑例行：`PATCH /routines/:id` 带 `prompt`/`name`/友好时间；简单触发器改时间时**合并保留** `if` / `ends.after` 等额外字段；复杂触发只读、保存时不动 `triggers`。
- 新增 `renderScheduledTaskList()`：统一行、按人筛选、行内历史、删除确认、行里指令预览。
- `partner-routines.js`：新建表单换成「新建定时任务」按钮；列表同时拉 routines 与该人的 reminders。
- `partner-profile.js`：例行卡改「定时任务」，计数 = 两类之和；记忆块改时间走同一编辑器。
- 列宽/按钮换行与 `.rm-instr` / `.rm-runs` 样式补在 `style-14-settings-pages.css`。

## 六、可见触发的技术头

新增 `scheduled-run-context.ts`：

- `SCHEDULED_RUN_HEADER = "[Scheduled run context]\nturnAuthority: autonomous"`；
- `stripScheduledRunHeader(text)` 只用于**回读展示/搜索**，模型上下文不变；
- `session-transcript.ts`、`session-search.ts` 应用；隐藏标记判据不变。

## 七、取舍与备选（弃）

| 取舍 | 备选 | 为什么 |
|---|---|---|
| 手动新建继续走 reminders | 全部 routines + visibility | 手机本地闹钟只在 reminders 上；不制造手机回归 |
| 友好五档 + 高级只读 | 保留 cron/interval/event 高级折叠 | 用户明确说"触发类型要统一"；普通用户不该看到技术字段 |
| 提醒补 runs 状态文件 | 从 durable 终态任务反推 | 终态只说明"投递过"，说不出模型跑成没跑成；用户问的就是"可能做也可能做不到" |
| 图片/事件不手动编辑 | 全部暴露 | 事件触发是 Agent 自建巡逻的能力，手动 UI 没有合适语义 |
| 一次性提醒不给暂停 | 也实现暂停 | 一次性没有可恢复的持久定义；UI 不显示该按钮，避免"暂停后消失" |

## 八、明确不做

1. **不合并 reminders / routines 两套引擎**，不迁移已有提醒。
2. 不改手机端；暂停的任务不进默认 reminders 列表，因此不会推本地闹钟。
3. 不给 `set_reminder` / `routine_manage` 加参数（工具描述与注册顺序是缓存前缀资产）。
4. 不做事件/间隔的手动编辑；不做批量编辑、任务模板。
5. 不做"换到点叫谁"：编辑时目标只读。
6. 不把可见触发的提示词改写成"用户口吻"——它本来就是用户写的指令，只剥技术头。

## 九、已知边界（落地后登记进 `系统架构.md`）

- 编辑提醒文本会重排任务，下一次触发时间会按规则归一化；如果刚好跨过下一次触发点，那一跳会被跳过（与现有改时间同口径）。
- 一次性提醒没有暂停；`enabled=false` 的一次性任务到点会静默终止。
- 例行规则的 `interval` / `event` / 多触发器 / 复杂 cron 在编辑器里只读；内容可改，触发不可改。
- 提醒执行历史从本批上线后开始记；旧任务没有历史。
- 手动新建选总管 → `partnerId="chief"`；手机端历史上传 `null` 的提醒不迁移。
