## 〇、一句话结论

聊天主链路（流式/停止/回读/后台跑完/派活/切模型）已经齐了；差距集中在四块：
**消息级操作**（代码块复制、思考展示、编辑重发）、**会话资产**（置顶/分组/导出/内容搜索）、
**桌面集成**（通知、排队插话、壳的守护与告知）、以及两件**契约级大工程**（附件多模态、消息重写三件套）——
后者内核表面都有接口，是"没接"不是"做不到"，按用户口径**慢做**。

## 二、"必备"的判定标准

桌面 Agent ≠ 网页聊天套壳，差异在四件事，缺了就是"网页套壳"：

1. **会话是长期资产**——要能置顶/找回/导出，不只是"最近聊过"的流水。
2. **窗口常驻**——人不在窗口前它也在干活，所以要有系统通知、托盘、守护、中断恢复。
3. **消息是可操作的对象**——复制只是底线，编辑重发/回滚/分支是 Agent 特有的刚需
   （它动过文件、跑过命令，错了要能退）。
4. **密度与即时性**——token/上下文/速率要看得见，不然"烧了多少钱、还剩多少上下文"全靠猜。

## 三、我们已有的（不重复做）

流式 SSE、停止（同槽）、后台跑完+回读、Markdown 极简渲染、工具活动行（args/output 可展开）、
attention 待你处理卡、会话列表（重命名/移除/恢复/标题搜索）、思考档快/深、权限三档、
模型运行时切换（§2.8）、提醒列表、配对/设备管理、令牌门、主题三态+主题色、发送键配置、
壳：单实例/托盘/关窗隐藏/探活拉起/令牌注入/自绘标题栏。

**内核已具备但没接的**（`pi-durable/dist/types.d.ts` 实读）：`history: "rewindable"`、
`fork: "asOf"|"current"|"initial"`、`QueueMode`、`ContextView`——
消息重写三件套、排队插话、上下文占用，内核侧都有表面，缺的是 harness API + 前端。

## 四、差距清单（按批次）

### 批次一：小而必备，可一次落地（前端为主，微契约）

| # | 能力 | 参考（判定） | 我们现状 | 做法 | 量 |
|---|---|---|---|---|---|

| 3 | **会话置顶** | cindy/deepseek 加分，但"找回常用会话"对个人记录工具是刚需 | 无 | `chat-meta.json` 加 `pinnedAt`（rename/hide 同套基础设施），侧栏顶部"置顶"段；轨道无感知 | S |
| 4 | **导出对话 Markdown** | cindy 没有 md 导出（有加密包/图片/链接三件套，重）；oh-my-pi 有 /export | 无 | 前端把 `readTranscript` 拼成 md 下载即可，无后端改动。个人记录工具的合理刚需 | S |
| 5 | **错误重试 + 中断标记** | cindy ErrorBanner 必备；deepseek interrupted 标记 | 错误只有一行灰字，中断无痕迹 | error 消息行加"重试"（重发最后一条 user 文本）；`finishReason=aborted` 的轮尾显示"已中断" | S |

### 刻意不做（参考项目里判"鸡肋"，登记防返工）

消息赞/踩（cindy 都没有）、朗读、分享为图片、macOS 灵动岛/配额面板、跨设备 device-link、
代码块语言标签与折叠、独立 regenerate 按钮（编辑重发已覆盖其语义）、导出加密分享包。

## 五、这条会怎么错

1. **把"加分"当"必备"一次全做** → 每项都摊薄审查精力；按批次走，每项落地有变更记录。
2. **微契约不守规矩** → `done` 加 usage、新增 thinking 事件虽是"向后兼容"，也必须先改接口文档再改代码；手机端靠"忽略未知类型/字段"兜底，但要在适配说明里登记。
3. **thinking 事件乱流** → thinking 正文可能很长，全量进 SSE 会挤占正文带宽；透出前先在内核侧核实 pi.live 的 thinking 块结构，必要时只发增量+截断策略。
4. **通知变骚扰** → 不做聚焦判定就上通知 = 每轮都响；cindy 的"窗口聚焦且正看该会话则静默"是前置条件不是优化项。
5. **排队 UI 假排队** → 前端自己缓存消息假装排队、后端其实拒了 → 断线即丢；必须以内核 QueueMode 为准，前端只是视图。
6. **rewind 凭感觉接** → cindy 的 preview（回滚影响哪些文件）是它踩坑后的产物；我们接 rewind 前先读 durable 语义，别做成"看起来退了，文件还在"。
7. **高亮库偷偷进依赖** → 无构建约束是仓库明面规矩；要么手写轻量版，要么明确立项改约束，不许"就引一个小库"。
