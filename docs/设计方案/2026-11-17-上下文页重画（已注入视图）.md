> 一句话：把「设置 → 上下文」从“五张卡各报各的数”改成“这一条请求到底装了什么”——
> 会话版只算已经进请求的东西，用一张棋盘格图看占比、点开浮层读原文；默认开销版列全部可注入字段（含 0）。

**前置**：`2026-11-16-设置上下文页（固定前缀查看）.md`（本页来源）、`2026-11-16-上下文页按token估算.md`（token 口径）

## 1. 问题（用户口径）

**第一轮（2026-11-17 上午）**

1. **「系统底稿」这一行没有意义**：`system.content` 在真实请求里恒为空，页面却单独占一行 0 token。
2. **0 token 的去留两套标准**：会话版藏 0（还看不出为什么），默认页全列但展开是空白；
   要的是「会话版藏 0；默认版全列，展开写一句『当前没有开销』」。
3. **工具描述是解释性文字**：一小段 description 占一整列，前端不该展示。
4. **这页看不出用途**：只报了 `对话 3 条 · 128 token` 这种数，**消息原文与工具调用看不到**；
   参考 magpie 的 Context 卡。

**第二轮（同日，看到分组列表之后）**

5. **分块还是不够清楚**：分组列表是文字，看不出“谁占大头”。
6. **要图形模式**：像 magpie 那样一张格子图，**点一块浮起卡片**能读内容。
7. **每次变化要有动画**：刷新、切模式、切会话时不是“闪一下换掉”。
8. **会话名要是执事的名字**（如「小记」），不要「未命名会话」，和「默认开销」的角色名尽量一致。
9. **不要在上下文页改内容**：“这一块尽量不在这里改……或者留链接到编辑这个人的地方就行”。

## 2. 拍板

| 项 | 决定 |
|---|---|
| 系统底稿 | 页面整行删掉（服务端 `system.content` 字段保留，只作兼容，不渲染） |
| 会话版 | 只显示**已经进请求**的行；0 token 整行隐藏，整组为 0 连图例一起隐藏 |
| 默认开销版 | 所有字段照旧全列（含 0）；0 token 的组点开写「当前没有开销」 |
| 工具描述 | 主页面不显示；只有点开浮层才是真实 JSON 定义 |
| 消息 / 工具调用 | **要能读原文**：新增会话条目（用户 / 助手 / 工具调用 / 工具结果），按真实顺序，点开读正文 |
| 图形 | 384 格棋盘（32×12 的逻辑分辨率），格子按组上色，**面积 = 占比** |
| 基准开关 | 工具栏一个两档小开关：**占比**（默认，等于已注入内容的组成）/ **窗口**（等于整条上下文，余量留白）。只在「当前会话」出现，默认开销不显示剩余 |
| 颜色 | 三主色 + 三混色（`--ctx-g1..g6`），不再用单色阶的 6 段深浅 |
| 交互 | 点格子 / 点图例 → 从触发点浮起卡片；卡片里点条目再展开原文 |
| 动画 | 格子只换 class、颜色 0.38s 过渡；卡片从触发点缩放展开；`prefers-reduced-motion` 全关 |
| 页内编辑 | **全部撤掉**（七个「改这一节」与纪律弹层一并删），只留一行跳执事档案页的链接 |
| 会话名 | 执事会话取执事名（「小记」），总管/worker 用角色名，与「默认开销」的角色选择器同一套口径 |

## 3. 页面模型

一页 = 一张卡：总量 + 上一轮真实用量 + 棋盘 + 图例 + 档案页链接。

```
[标题行]  (当前会话 | 默认开销)  [会话/角色选择]  (占比 | 窗口)  [刷新]

[卡]
  ≈8,423 token · 已注入                              上一轮 7.5K / 1.0M token · 1%
  会话 · 系统 6 段 · 工具 16 个 · 技能 21 个 · 记忆 16 条 · 对话 4 条
  ┌─────────────────────── 512×214 ───────────────────────┐   ● 系统提示词   ≈1,434 · 17%
  │ ████ 384 格，按组上色，面积就是占比                    │   ● 工具定义     ≈5,214 · 62%
  └───────────────────────────────────────────────────────┘   ● 技能         ≈798  · 9%
                                                              ● 临时注入     ≈812  · 10%
                                                              ● 对话         ≈86   · 1%
                                                              ● 工具结果     ≈79   · 1%
                                                                  全部      6 组
  这个执事的人设、纪律与岗位契约在档案页改：去 小记
```

| 分组 | 图例行 | 会话版 | 默认版 |
|---|---|---|---|
| 临时注入 | `memory_recall` + 其它注入按 id | 有则显示 | 不显示 |
| 系统提示词 | 每个 section 一行 | 只显示 `tokens > 0` 的 | 30 个字段全列，含 0 |
| 工具定义 | 每个工具一行（名字 + token） | 全部 | 全部 |
| 技能 | 技能索引一行 | 有索引才显示 | 有索引才显示 |
| 记忆 | 预算（16 条 / 2,000 字） | 并入系统组 | 单独一行，0 token |
| 对话 / 工具结果 | 用户 / 助手 / 调用 / 结果 | 全部 | 不显示 |

- 点格子或图例 = 打开这一组的卡片：组名 + 计数 + token，逐条列名字与 token，点条目展开原文。
- 「全部 N 组」= 一次列完所有组。
- 0 token 的组（默认开销里的「记忆」）没有格子：卡片正文写「当前没有开销」，悬停时**不压暗棋盘**。

## 4. 机制

### 4.1 契约（§2.2.4 / §2.2.5 已回写）

`ContextInspectView` 增加 `entries: ContextEntryView[]`：

```ts
interface ContextEntryView {
  kind: "user" | "assistant" | "toolCall" | "toolResult";
  label: string;       // 用户 / 助手 / 工具名
  index: number;       // 在 view.messages 里的序号（页面显示 #n，保住真实顺序）
  chars: number;       // 真实字符数（截断前）
  tokens: number;      // 真实估算 token（按截断前算）
  text: string;        // 正文 / 参数 JSON，超过 4000 字截断
  truncated?: boolean;
}
```

- 只从 `view.messages` 取 `user` / `assistant` / `toolResult`；system 消息属于“系统提示词”，不重复进条目。
- `assistant` 的文本与它发出的每个 `toolCall` 各成一条；调用 token 口径同 `changing.toolCalls`，
  组内相加 = Hero 的「对话」段。
- `MAX_CONTEXT_ENTRY_CHARS = 4000`：`chars` / `tokens` 按全文算，`text` 截断并标 `truncated`。
- `memory.last.others[]` 加 `text`（同截断）。
- `system.content` 保留但不渲染；默认开销 `entries: []`。

### 4.2 服务端

- `contextInspectViewOf` 一遍遍历同时产出 `changing` 与 `entries`，避免两套口径漂移。
- `SECTION_META` 补三个裸 key：`delegate_executor`（派活执行器）、`tool_index`（低频工具索引）、
  `instructions`（执事说明）。

### 4.3 前端

**棋盘（`paintWaffle`）**

- 384 个 `.ctx-cell` 在骨架里一次建好，之后**只改 className**（`is-g1..6` / `is-free`），
  颜色靠 `transition: background-color .38s` —— 数据一变是渐变，不是整块重画。
- 分配用最大余数法，每组至少 1 格；缩放基准是**请求总量本身**，所以格子总是填满，
  显示的是“组成占比”，不是“窗口用了多少”。窗口占用率在右上角「上一轮 7.5K / 1.0M · 1%」。
- **列数取 384 的约数**（96 / 64 / 48 / 32 / 24 / 16 / 12 / 8，取“格宽 ≥13px 的最大一个”），
  这样行数一定是整数，不会在最后一行剩几个空格子被看成“这组突然变长”；窗口变化时重排。
- 棋盘固定 `width: min(512px, 100%)`：512 宽 → 32 列 × 12 行、格子 14×16 近正方，
  图例竖排在右侧，和颜色一一对号。

**配色**

| 变量 | 取值 | 用途 |
|---|---|---|
| `--ctx-g1` | `--c-primary`（靛蓝） | 组 1（会话版=系统） |
| `--ctx-g2` | `--c-tertiary`（琥珀） | 组 2（工具） |
| `--ctx-g3` | `--c-secondary`（沙） | 组 3（技能） |
| `--ctx-g4` | primary 52% 混 surface | 组 4（注入 / 记忆） |
| `--ctx-g5` | tertiary 50% 混 surface | 组 5（对话） |
| `--ctx-g6` | secondary 50% 混 surface | 组 6（工具结果） |

全部 `color-mix`，换主题自动跟随。

**浮层（`openPopover`）**

- `visibility:hidden` 量尺寸 → 定位 → 强制一次 layout → 加 `is-open`（**不用 rAF**：
  标签页不在前台时 rAF 会停，卡片会一直停在 opacity 0）。
- 默认贴触发点下方，下方不够翻到上方并夹在视口内；`transform-origin` 落在触发格上，看起来从那块长出来。
- 点浮层外（含设置页侧栏、顶栏）、Esc、resize 关闭；卡片体可滚动（`max-height:62vh`）。
- 单条正文上限 `POP_TEXT_MAX=3000`，超出显示「卡片只显示前 3,000 字 · 共 N 字」；
  服务端已截断的显示「服务端已截断 · 共 N 字」。

**悬停**：`pointerover` 某组 → 其它格 `opacity .5`、本组格 `scale(1.06)`，图例行同步 `is-focus`。
0 token 的组没有格子，只亮图例行，不压暗棋盘。

**基准开关（占比 / 窗口）**

| | 占比（默认） | 窗口 |
|---|---|---|
| 384 格代表 | 这一条请求本身（已注入的全部） | 整条上下文窗口 |
| 已用部分 | 铺满 384 格 | 铺满 269 格（扣掉余量那条），组间比例不变 |
| 余量 | 没有 | **固定 115 格（30%）**，真实用量超过 70% 时按真实剩余收窄 |
| 图例 | 各组 token + 占请求的 % | 同左，另加一行「未使用 ≈N」（数字是真的，面积是示意的） |

- 余量为什么不做真比例：1M 的窗口里只用 6K 只有 0.6%，按真比例画出来几乎空图，各组大小全看不清。
  固定留一块是 magpie 的做法，用户认可“不符合事实但对调试好”；真实占用率仍由右上角「上一轮 6.3K / 1.0M · 1%」负责。
- 只在「当前会话」出现：默认开销没有会话、没有窗口，也不显示剩余。
- 选择存 `localStorage.lifediary.ctxScale`；会话还没跑过一轮（没有 usage）时「窗口」这一档置灰。

**会话名（`chatLabel`）**：`partner-<id>` → `state.partners` 里的名字（「小记」）；
`chief` → 「总管」；`worker` → 「普通 worker」；重名再补 `fmtAt(lastAt)`。

**编辑入口**：`DISCIPLINE_EDIT_SECTIONS`、`parseDisciplineSource` / `serializeDisciplineSource` /
`openDisciplineEditor` 全部删除；底部一行 `这个执事的人设、纪律与岗位契约在档案页改：去 小记`，
点击 `location.hash = #/settings/partners/<id>`。执事档案页的七节编辑能力原样保留。

## 5. 明确不做

- **不做请求历史 / 时间线**：只读“现在这一条请求”。
- **不估真实计费**：token 仍是 `≈`。
- **不在设置页改纪律 / 岗位契约**：页内编辑全部撤掉，只跳档案页。
- **不把默认开销做成会话**：默认版仍按角色现装配，`usage:null`、`memory.last:null`。
- **不做会话气泡 / 流式**：卡片里只有行与原文 `<pre>`。
