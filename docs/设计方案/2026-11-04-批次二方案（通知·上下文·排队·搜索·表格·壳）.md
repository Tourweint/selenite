## 一、系统通知（三时机）

**现状**：无任何通知。人不在窗口前时，回合完成 / 派单待你处理都悄无声息。

**目标**（对齐 cindy `notificationService` 的时机与静默口径）：

| 时机 | 触发 | 文案形态 |
|---|---|---|
| done | `done` 事件且该轮是后台跑完（页面此刻没在看这个会话） | 「Selenite 回复完成：〈会话标题〉」 |
| error | `error` / `done(finishReason=error)` | 「这一轮没答上来：〈会话标题〉」 |
| needs_you | `attention` 事件（任务单待你处理） | 「有任务单需要你：〈一行问题〉」 |

- **点击通知** → 聚焦窗口 + 打开对应会话（attention 另跳 `#/tasks?ticket=`，任务中心落地后）。
- **静默判定（前置条件，不是优化）**：`document.visibilityState === "visible"` 且当前打开的就是该会话 → 不发。
- **实现**：Web Notification API（WebView2 支持；请求权限放在首次「开启通知」设置开关时，不在启动时弹）。
  设置页「服务」分区加一行开关，存 `localStorage`；壳侧原生通知（托盘气泡）后置，见 §六。
- **回滚**：设置开关默认关；`NOTIFICATIONS=off` 不需要——不点开就不启用，权限拒绝时 UI 提示去系统设置。
- **明确不做**：macOS 灵动岛 / 角标；声音；每条 delta 触发通知。
- **验证**：mock 流（无 key）后台跑完一轮 → 通知出现；切回窗口当场发消息 → 无通知。

## 二、上下文占用提示

**现状**：用户不知道烧了多少上下文。内核表面已有 `ContextView`（`pi-durable/dist/index.d.ts` 实读）。

**目标**（对齐 cindy `ContextCapacityRing`）：

- 新只读端点 `GET /api/v1/agent/chat/:conversationId/context` → `{ used, window, ratio }`
  （读 durable 的 ContextView；`window` 取模型目录值，读不到返回 `window: null`，前端隐藏）。
- UI：标题栏右侧一个小徽标（文本形式起步：`12k/131k`），≥70% 变警示色、≥90% 变错误色；
  hover 出 tooltip 给百分比。**不做圆环**——极简 renderer 的体量撑不起画布控件，文本够用。
- 刷新时机：`done` 事件后拉一次；切会话时拉一次。
- **契约**：接口文档 §2 新增端点（只读，无状态变更）。
- **明确不做**：手动 compact 按钮（durable 的压缩策略是自动阈值）；按 token 计价显示。

## 三、运行中排队 / 插话

**现状**：`state.sending` 时前端禁发。人在对话中途想起补充，只能干等。

**内核事实**：durable 会话忙时 `submit` 会排队到本轮结束（接口文档 §4 的派活回灌已依赖该语义）；
`pi-durable` 表面导出 `QueueMode`（`dist/index.d.ts` 实读）。**排队是内核行为，缺的只是 UI。**

**目标**（对齐 cindy PendingQueuePanel 的最小集）：

- 流式中允许继续输入并发送：消息不进对话流，先落「队列面板」（composer 上方，FIFO 列表）。
- 每条队列消息：显示文本 + 撤回（本地移除即不 submit——队列条目在本地，发送发生在轮次结束后）；
  本轮 `done` 后**自动**依次 submit 队列首条，其余保持排队。
- **Stop 语义**：停止 = 中断当前轮 + 队列保持（面板给出「继续」按钮，cindy 同款）。
- 断线/刷新恢复：**队列只存内存**，刷新即丢——登记为已知边界（cindy 有持久队列，我们 v1 不做，
  避免又造一套落盘状态机；要做时挂 chat-meta 同套设施）。
- **契约**：无。submit 仍是现有 `/chat` 端点；排队只是前端时序。
- **这条会怎么错**：前端假排队而服务端其实拒了 → 必须在 done 后真的调用现有端点、以 SSE start 为成功依据；
  并发双开窗口时队列各自为政 → 接受（单人单机场景，登记已知边界）。
- **明确不做**：steering（把插话注入当前轮的上下文）；多设备队列来源标记；持久化队列。

## 四、内容级全局搜索

**现状**：只搜标题/首句（`listChats` 的元数据）。

**目标**：

- 新只读端点 `GET /api/v1/agent/search?q=&limit=20` → `{ hits: [{ conversationId, at, text }] }`。
- 实现：逐会话读 transcript 做 LIKE 过滤（复用 `readTranscript`，会话数大时慢——登记已知边界，
  同 `listChats` 的既有代价口径）；**FTS5 后置**，等真变慢再立项（记忆层召回的中文 LIKE 失效是前车之鉴，
  这里的区别：搜索是显式动作，慢一点可接受；召回是每轮隐式动作，必须快）。
- UI：设置「会话」分区的搜索框升级——命中后展示「会话 · 命中句（高亮）」，点击进会话。
- **鉴权**：走 `/api/v1/*` 中间件；`q` 最少 2 字符防全表扫。
- **明确不做**：FTS5、跨会话正则、命中排序调优。
- **验证**：faux 起服务建两轮对话 → 搜「其中一句话」命中并高亮。

## 五、表格渲染

**现状**：极简 renderer 不认表格，模型输出的表格出原始竖线文本。

**目标**：GFM 管道表格（`| a | b |` + 分隔行），解析为 `<table>`；对齐走 `:---`/`---:`。

- 落点：`renderMarkdown` 的行扫描里加一个「表格分支」（连续的 `|` 行 + 次行分隔线即成表），
  与代码块占位符机制互不影响。
- 转义沿用 `inline()`（单元格内容走 inline，支持加粗/代码）。
- CSS：`.body table` 边框用 `--divider`、表头 `--card-high` 底、`overflow-x: auto` 包一层防撑爆。
- **明确不做**：合并单元格、HTML 表格透传、表格排序。
- **验证**：让 mock 回复带一张示例表（同批次一给 mock 加代码块的先例），浏览器实测浅/深两套主题。

## 六、壳三小项（Go 侧，与 web 无契约）

对照 deepseek-harness 的 Electron 壳（`background-notice` / `quit-confirmation` / `single-instance` 等）：

1. **窗口几何持久化**：记住上次矩形 + 最大化态（`.data/window.json` 或壳自己的 userData）；
   启动时恢复，拿不到（换显示器等）回退现有比例算法。**量 S**。
2. **首次隐藏告知**：关窗=隐藏是现状，但用户不知道服务还在跑。第一次 OnClose 时弹一次
   「已最小化到托盘，服务继续运行」原生对话框（或 WebView 内确认条），ack 写壳本地文件，之后不再问。**量 S**。
3. **运行期服务守护**：现状只在启动探活一次。加：壳内 10s 轮询 `/healthz`，连续 3 次失败 →
   托盘图标变灰 + （批次二 §一落地后）发一条通知；托盘「重新连接」已有，补一个自动重拉（沿用 ensureService，
   加防抖：最多每 30s 一次，防疯狂重启）。**量 M**。
- **回滚开关**：`LIFEDIARY_SHELL_WATCH=off` 跳过守护轮询（env，一行回退）。
- **明确不做**：退出前向 Host 查任务（deepseek 有，等任务中心落地后跟进）；开机自启；全局快捷键（慢做清单）。
