# 桌面壳：用 MyGo 做一个客户端

> 2026-11-03。服务已经能跑（Hono + SSE + SQLite），缺的是「人坐在电脑前随手就能用」的入口。
> 手机端是独立仓库的 Kotlin 工程，不在这次范围内。

## 结论

五条：

1. **桌面端只做壳，不做第二套 Agent。** 内核、记忆、会话全部留在 Node 服务里。
2. **壳 = MyGo 单 exe + 系统 WebView2**（不打包 Chromium），前端通过 HTTP + SSE 直连本机服务。
3. **服务进程独立存活。** 关窗口不杀、退出壳默认不杀——手机要能连，`sleepUntil` 的提醒不能死。
4. **前端只有一份。** 放 `desktop/`，数据层收敛到唯一的 `src/api.ts`，浏览器、壳、（以后）手机 WebView 共用。
5. **分四期。** P0 半天，只验一件事：WebView2 里 SSE 能不能逐字出字。

## 一、为什么是壳

桌面端有三种做法，只有一种不重复劳动：

| 做法 | 代价 |
|---|---|
| Go 重写 Agent 内核 | 把 `pi-durable`、记忆四层、契约全搬一遍，几个月，且分裂成两套实现 |
| Electron 一体式（服务跑在主进程） | 窗口一关服务就没了，手机连不上、提醒全死；且自带一份 Chromium + Node |
| **壳 + 独立服务进程** | 多一层进程管理；其余全部复用 |

选第三种。壳的职责只有两件：让服务活着、把界面显示出来。

## 二、拓扑

```
┌───────── 桌面壳（Go，单个 exe，MyGo）─────────┐
│  窗口：系统 WebView2 ← 内嵌的 dist/            │
│  托盘 / 单实例 / 深链 / 菜单                   │
│  职责①：探 /healthz，需要时拉起服务            │
│  职责②：把 baseUrl 告诉页面（一次 Bind 调用）  │
└───────────────────┬───────────────────────────┘
                    │ 页面直接 fetch + EventSource
                    ▼
      ┌──── Node 服务（独立进程，:8082）────┐
      │ Hono · SQLite · pi-durable · SSE   │
      └──────────────┬─────────────────────┘
                     ▲ HTTP + SSE（同一份契约）
              ┌──────┴──────┐
              │ Android App │（独立仓库，不动）
              └─────────────┘
```

**要点**：窗口里的页面和 Android 打的是同一个 `8082`。壳换掉、前端换掉，都不影响任何一端。

## 三、四个决策

### D1 · 界面由服务发出，壳不内嵌（2026-11-03 当日更正）

界面文件在 `ts/apps/server/web/`（`index.html` / `app.js` / `style.css`，无构建步骤），
由 `src/web.ts` 挂在同一个 Hono 上，`GET /` 返回。

原来这一条写的是"前端放 `desktop/`，由 MyGo 的 `buildCommand` + `frontendDist` 内嵌进 exe"。
动手时改掉了，理由是**同源**：

| | 内嵌进壳（原方案） | 服务发出（现方案） |
|---|---|---|
| 跨域 | 壳是 `mygo://localhost`，打 API 要 CORS | 同源，无 CORS |
| 浏览器调试 | 必须起壳 | 直接开 `127.0.0.1:8082` |
| 手机/以后 WebView | 要再复制一份 | 同一个地址 |
| 构建链 | Vite + `mygo build` | 无（改完刷新） |

代价：界面不再随 exe 走。但服务本来就是必需的（Agent 在服务里），
所以这不是新增依赖——只是把"界面"归到了它天然该在的地方。

壳因此更干净：它只 `LoadURL`，一个字节的前端资源都不持有。

### D2 · 传输走 HTTP，不走 `mygo.Bind`

`Bind` 会把前端锁死在 MyGo 里，而这份前端以后要给浏览器和手机 WebView 用。

```ts
// src/api.ts —— 唯一出口，组件不许自己 fetch
const base =
  (await mygoConfig?.()) ??        // 壳里：Bind 给出的实际端口
  "http://127.0.0.1:8082";         // 浏览器里：写死兜底
```

`mygo.Bind` 只暴露一个 `Config() → { baseUrl, version }`，不传业务数据。

CORS 不用管：服务端已是 `origin: "*"`；`127.0.0.1` 按规范属于潜在可信源，
不算被拦的混合内容。

### D3 · 服务生命周期：壳探测，不拥有

```
启动 → GET /healthz
      ├─ 200  → 复用（绝不起第二个：会抢端口和 SQLite 锁）
      └─ 失败 → spawn 一个 detached 的 node 进程，等健康检查通过
退出 → 默认不杀服务
```

代价是要管 pid 文件和端口探测，放 P2。

### D4 · 关窗 = 隐藏，退出 = 托盘菜单

`OnClose` 里 `PreventDefault()` + `Hide()`；真退出走托盘菜单，此时才收服务。
Windows 上点 X 也是隐藏，第一次要给托盘气泡提示。

## 四、分期与验收

| 期 | 内容 | 验收（可测） | 估时 |
|---|---|---|---|
| **P0** | 装 Go 1.27.3+ → 最小 MyGo 项目 → 窗口加载 `http://127.0.0.1:8082/` | WebView2 里 SSE 逐字出字；能发、能停 | 半天 |
| **P1** | 界面从 `debug-page.ts` 换成真界面（`web/`，同源发出） | 浏览器和壳看到同一份；流式逐字出字 | ✅ 2026-11-03 |
| **P2** | 托盘、单实例、关窗隐藏、服务探测/拉起/pid | 关窗后手机仍能连；重启壳复用已有服务 | 1–2 天 |
| **P3** | `mygo build` 出 exe（图标、版本号、签名） | 干净机器双击能跑 | 1 天 |
| P4（可选） | Go native UI 做设置页 / 提醒弹窗 | — | 按需 |

**P0 必须先做**：它一次验三件不确定的事（WebView2 的 SSE、跨源 fetch、外链加载），
任何一件不通，后面的方案都要改，而它只要半天。

## 五、前置债：服务需要一个 build

P2 的「壳拉起服务」要求有一个能跑的产物。现在 `apps/server` 的 `start` 是
`tsx src/index.ts`——跑在源码上，依赖 devDependencies，等于把 tsx 和整份 TS 一起分发。

所以 P2 之前要加一个 build（esbuild/tsup → 单文件 `dist/index.js`，`node dist/index.js` 能起）。
这不是新工作：「一行命令下载」那条路本来就要做，顺手还。

## 六、风险

| 风险 | 影响 | 处理 |
|---|---|---|
| MyGo 是 v0.7.x、单人主导 | API 会变、查不到答案 | `go.mod` 锁 `v0.7.3`，不跟更新 |
| 强制 Go 1.27.3+ | 换机器可能装不上 | 与 mygo 版本一起写进 README |
| Node 运行时怎么带 | 别人机器可能没 Node | P3 先测 Node SEA；失败退化成内置 node 目录 |
| 两套界面（Kotlin + Web） | 长期维护成本 | 接受；但保证 Web 这份是唯一前端代码 |

## 七、落地记录（2026-11-03）

**界面**：`ts/apps/server/web/`（`index.html` / `app.js` / `style.css`），由 `src/web.ts` 挂载。
零依赖、零构建，改完刷新即可。

**视觉**取自 cindy（Apache-2.0，`<reference>\cindy`）的设计系统：

- 近乎纯灰阶：surface `#181818`、elevated `#1F1F1F`、边框 `rgba(255,255,255,.10)`；
- 文字四档全走 `rgba(255,255,255,.82/.55/.40/.30)`，不用实色灰；
- 强调动作是**反相中性**（`#EEEEEE` 底 + 深字），不是品牌色；
- 彩色只留语义：`#417CDD`（焦点环）、`#93C5FD`（链接）、错误红；
- 圆角只有 4 / 8 / 12 / 9999 四档，按钮一律 pill；
- **零阴影**，层次靠背景色差 + 1px 边框；助手消息无气泡、15px/1.6 左对齐。

注意：cindy 里**没有 WebGL**（全仓 0 处 shader，canvas 只用于截图标注）。
它好看来自克制的灰阶与排版，不是图形技术——所以这里也没有引入 WebGL。

**协议（新增，向后兼容）**：自有 SSE 原来把 `progress` 丢掉、只发 `start/delta/done/error`，
界面因此只能显示空白等 token。现在加了两类：

| 事件 | 载荷 | 界面表现 |
|---|---|---|
| `progress` | `phase: "thinking" \| "working"` | 一行斜体「正在思考」 |
| `tool` | `name` / `status: start\|end` / `label` / `ok` | 一行「read · ts/README.md」，一轮结束折叠成「已执行 N 步」 |

`label` 是**一个**参数（路径 / 命令 / 查询），不 dump 整个 arguments——
`remember`、`write` 的参数里是用户正文，不该进状态条。

兼容层（`openai-compat.ts`）同步加了非标准字段 `lifediary_tool`，手机 App 以后也能用。

## 八、明确不做

- 不做多用户 / 账号体系（与项目定位冲突）。
- 不改 `ts/` 里的业务逻辑，壳不碰 Agent 内核。
- 不为了「好看」用其他语言写原生界面再搬进 Go——搬不了，只搬 shadcn 那类源码组件。
- 不做 Electron。
