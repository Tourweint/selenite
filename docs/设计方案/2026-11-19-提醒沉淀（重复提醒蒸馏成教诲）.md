# 提醒沉淀：把用户的重复提醒蒸馏成教诲（2026-11-19）

**状态**：设计已拍板（用户 2026-11-18/19：用 Agent 时经常要反复提醒，把提醒总结一下注入提示词，让它能多往下走）。
**下沉落点**：落地后入口说明 → `系统架构.md` 记忆段一行。

## 背景

用户对 agent 的反复纠正/提醒是最高信号的教诲来源。现状：单轮有 `remember`（taught=true 偏好）与逐轮抽取（`memory-extract.ts`），但**没有"同一提醒反复出现 → 聚合成条目"的跨轮机制**。偏好每轮注入（16 条/2000 字预算，`memory-inject.ts:24-31`），沉淀进去 = agent 少犯同样的错 = 需要用户出手的次数变少——与决策上报链配套。

## 方案：走"引导 Agent 对话"通用模式（技能评估批30 同款）

1. **入口**：设置→记忆页 + 人设页各加一个按钮"沉淀我的提醒"（低频，图标小按钮，符合文案密度口径）。
2. **收集（0 token，代码做）**：确定性过滤近 30 天数据——用户消息含"以后/记住/下次/别再/不要"等模式词的句子 + memory 里 `taught=true` 的偏好 + ask_user 答复沉淀（`verified-answer.ts` 旁路）。产出候选清单（原文+出现次数），不调模型。
3. **预填对话**：跳转总管会话，预填提示词（候选清单内嵌），总管蒸馏成候选教诲条目（合并同类、去掉一次性语境）。
4. **落盘**：总管用现有 `save_skill_advice` 同款模式落建议（新工具或复用 `remember` 建议 variant）→ **人逐条采纳**才进偏好（taught=true，永不删保护）。
5. **D18 底线不破**：只建议、人应用；巩固/蒸馏不自动写库。

## 明确不做

- 自动聚合（不用户发起就跑）；
- 聚合计数落库（候选清单即时算，不留表）；
- 项目/执事分域蒸馏（v1 只做 global 偏好）。

## 回滚

- `REMINDER_DISTILL_ENABLED=false` → 入口与预填端点下架。

## 验收

- `pnpm typecheck` + 单测（收集过滤逻辑）；
- 浏览器：入口 → 预填对话出现候选清单 → 总管产出建议 → 采纳落偏好 → 下一轮注入可见。
