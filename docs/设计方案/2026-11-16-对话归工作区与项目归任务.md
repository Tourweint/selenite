## 起因

2026-11-16 用户发现侧栏项目行右边有一个小加号能建会话，问「这啥意思？和普通对话有什么区别？」。
核实（2026-11-16 全量审计）：

- 它不是新会话类型，是「切当前项目 + 开普通 worker 对话」的快捷按钮
  （`ts/apps/server/web/project-switch.js:306` `newChatInProject`）。
- 建 `worker` 会话时读全局当前项目，把主文件夹钉进 `pi.agent.cwd`，并写
  `ChatProjects` 归属（`ts/apps/server/src/agent/session-open.ts:218`）。
- 这个按钮是 silent 的（`selectProject(..., {silent:true})`），但它**改了全局
  「当前项目」**：之后所有新对话默认落在这个项目，用户无感知。
- 侧栏会话列表不返回项目字段（`session-index.ts:257`），所以「这个会话属于哪个
  项目」在界面上看不出来。

用户同日拍板（原话要点）：

- 「Worker 只在一个项目里工作，把这个对话改成任务吧。对话没啥必要了。」
- 「普通对话默认绑我的默认工作区……项目记忆当然可以设置，在人设这一页。默认没开
  就是全局的，开了就是带项目记忆。」
- 「我们的对话属于任务中心，这里分人，就能看谁派出的任务，以及隶属于哪一个项目。」
- 「工作区……我看不到它在哪里」→ 只在设置页/项目弹层加显眼入口，侧栏不占行。
- 「我们就只有一个搜索嘛，就是搜索全部的对话」→ 不做项目下搜索。

## 现状核实（2026-11-16）

| 事实 | 落点 |
|---|---|
| 当前项目是全局单值，只影响新 worker 会话的 cwd/归属 | `project-store.ts:447`、`session-open.ts:218` |
| 系统提示每轮现读当前项目，且**从未写过主工作区路径** | `agent/lifecycle-injections.ts:126` |
| 会话 cwd 快照优先，无快照回落「当前项目」再回落 `AGENT_WORKDIR` | `agent/shared.ts:61` |
| 派单**必须显式带 project**，不靠当前项目猜 | `project-store.ts:534` |
| 任务列表已有项目名与执行者，**没有派活人** | `delegation-summary.ts:141` |
| 派活人可由 `originConversationId` → `partnerIdOfSession` 反查 | `work-record.ts:175` |
| 手机端不调用 `current-project`，只读项目字段（纯增量安全） | `lifediary/ProjectsApi.kt` |
| 现有搜索是全局对话搜索，无项目维度 | `web/search-page.js` |

## 方案

### 1. 普通对话固定绑主工作区（服务端）

- `openChat` 新建 `worker` 时**不再**读当前项目、不再写 `ChatProjects`；
  改为把 `workspace.rootPath` 钉进 `pi.agent.cwd`（工作区快照）。
- `sessionCwd()` 优先级改为：会话快照（旧会话保留）→ 主工作区根 → `AGENT_WORKDIR`。
  删掉「全局当前项目」这一级。
- 旧会话不搬家：2026-11-13 至本方案落地前的会话继续留在原项目快照里。
- 主工作区没设时（极端情况）回落 `AGENT_WORKDIR`，与现在一致。

### 2. 系统提示写明主工作区与项目边界（服务端）

`currentProjectProvider` 退役「当前项目」口径，改为每轮现渲染：

```
主工作区：<名字> · <绝对路径>
已登记项目（需要时用绝对路径）：
- <项目名>：<主文件夹路径>
- …
默认在主工作区干活；项目任务以派单里的项目路径为准；
相对路径以主工作区为基准。
```

- 不注入「当前查看的项目」——那是 UI 状态，不该影响对话。
- 项目清单**全列**（名字 + 主文件夹路径；用户 2026-11-16 拍板：真实项目很少，不省这几行）；
  没有项目就不写这段。
- 这是提示词结构变化（工具/提示词是缓存前缀资产），变更记录必须写明。

### 3. 项目行去掉小加号（前端）

- 删除 `projectRowNode` 里的 `＋`（`project-switch.js:172`）。
- 点项目行 = 切换「当前查看的项目」，只影响文件浏览器/项目弹层/任务筛选；
  **不再影响任何对话落点**。
- 提示文案同步改：不再出现「下一个新对话落在这个项目里」。
- `PUT /workspaces/current-project` 保留，语义改为「记住上次查看的项目」；
  接口文档同步。

### 4. 任务中心按派活人分组（服务端 + 前端）

- `TicketSummary` 纯增量补 `dispatcher: { id: string | null, name: string, kind: "chief" | "partner" }`：
  - `originConversationId` → `partnerIdOfSession`；为空 = 总管；
  - 名字取花名册；查不到时兜底「总管」。
- 任务中心主视图按派活人分组：总管一块、各执事各一块；组内沿用现有时间/状态排序。
- 任务卡显示项目名（`project` 已有），执行者（`employee`）继续显示。
- **打手手风琴保留**（用户 2026-11-16 拍板），作为「按执行者看谁在跑」的次要视角。

### 5. 工作区可见性（前端）

- 设置页第一块（已有）保持。
- 项目弹层顶部加一行「主工作区：<名字> · <路径>」，带「去设置」入口。
- 侧栏不加行（用户拍板）。
- 默认路径沿用现状（`project-api.ts:defaultWorkspaceRoot`）：没设过 →
  `<用户目录>/lifediary`（Windows 即 `C:\Users\<用户名>\lifediary`），首次启动静默创建；
  用户随时可在设置页改。**必须是用户目录下的子目录**，不能直接把工作区设成用户目录
  本身——否则 path-guard 的读写边界会把桌面/下载/文档全圈进来。
- 显示名：工作区目前只有 `rootPath`，显示时用目录名兜底（如 `lifediary`）；本轮不加
  可改显示名。

## 取舍与备选

- **备选 A：保留「项目会话」概念**（会话绑项目、系统提示按会话走、列表显示项目徽章）。
  放弃原因：用户明确「对话没必要按项目」，项目是任务容器；三套项目口径并存会继续
  制造「当前项目 / 会话快照 / 任务项目」的歧义。
- **备选 B：只去掉加号，保留当前项目决定落点**。放弃原因：与「默认对话属于主工作区」
  冲突，系统提示「当前项目」与工作区不一致的问题仍在。
- **备选 C：工作区放侧栏**。放弃原因：用户选「只在设置页/弹层加显眼入口」，侧栏保持干净。

## 明确不做

- 不做「项目会话」类型；会话列表不按项目分组。
- 不做项目下搜索：现有全局对话搜索（`#/search`）保持，不新增按项目过滤。
- 不删旧数据：`ChatProjects` 与旧会话 cwd 快照全部保留。
- 不改派活契约：项目仍显式传，`options.project` 不动。
- 项目归档不再连带**新**会话（旧会话的连带保留）。
- 不改手机端；`GET /agent/chats` 本轮不加项目字段（纯增量也不加）。
- 不做「@别名」、不做项目内会话列表页。

## 影响与风险（要认账的）

1. **普通对话只带全局记忆**：新 worker 会话不再写 `ChatProjects` → 没有项目 scope，
   recall 池里没有项目记忆。项目记忆仍通过①总管/执事人设页「负责项目」②打手任务会话
   进入。普通对话里 `remember scope=project` 会报 `no_project_scope`。
2. **提示词是缓存前缀资产**：改注入结构会打掉上游 prompt cache，变更记录写明。
3. **两代会话行为不同**：旧会话仍在原项目 cwd，新会话在主工作区；不搬家是有意的。
4. **任务卡信息密度上升**：派活人分组 + 项目名 + 执行者，需控制卡片行数。

## 回滚

- `CHAT_WORKSPACE_ONLY=false` → 回到 2026-11-13 行为（当前项目决定 worker 会话
  cwd + `ChatProjects` 归属）。
- 前端去＋是纯 UI，回滚 = revert 对应提交。
