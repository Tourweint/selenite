## 背景一句话

relay（`ts/apps/relay`，已部署 <VPS_IP>:8084）目前只有设备间 WS 转发与名册。要补三件事让手机能"只连中继就用电脑"：①手机把 base 地址指到中继后，REST 请求经中继转给书房主机执行（反向代理）；②手机凭一次性加入码扫码注册拿 deviceToken（免配对）；③设备上下线广播（手机端多端区实时化）。

## R1：`/api/v1/*` 反向 HTTP 代理

请求形态：`GET|POST http://<relay>/api/v1/<path>?query`，头 `Authorization: Bearer <deviceToken>`（手机用自己 token；中继转发时不替换，让 harness 侧按现有鉴权处理——即手机 token ≠ harness token 的问题在本层不解决，第一版**要求手机配的 token 就是 harness 的 AGENT_TOKEN**，登记为已知简化）。

处理流程：
1. 鉴权：`deviceIdOf()`（现有函数）验 token，无效 403 空体（对齐既有口径）。
2. 找目标设备：**默认路由到 `isHome=true` 的主机**（名册取 homeDeviceId）；无 home 或不在线 → 502 `{"error":"device_offline"}`（JSON，不带敏感信息）。
3. 组 invoke 帧发 WS：`{ kind:"invoke", id:<uuid>, payload:{ method, path:"/api/v1/"+path, query, headers:{authorization}, body } }`（payload 里 authorization 换成 harness 的 token——中继不存 harness token，所以**手机 token 必须等于 AGENT_TOKEN**，见上）。
4. 等回包帧 `{kind:"invoke_result", id, payload:{status, body}}`，超时 15s 回 504。
5. 把 status/body 原样回给手机（Content-Type application/json）。

**帧契约**：`shared/index.ts` 加 `RelayInvokeFrameSchema` / `RelayInvokeResultFrameSchema`（`kind: "invoke"|"invoke_result"`、id、payload），`.strict()`，写入接口文档。

## R2：`POST /api/relay/join`（一次性加入码）

1. **加码**：`POST /api/relay/join-code`，鉴权 = owner（`isOwner()` 现有函数；RELAY_OWNER_TOKEN 空 = loopback 直通，部署机上从本机调）→ 返回 `{ joinCode, expiresAt }`：码 256 位随机、存 sha256、10 分钟 TTL、一次性（用后即删）、同时最多 5 个有效（对齐 cindy pairing.ts:25-30）。
2. **用码**：`POST /api/relay/join`，body `{ joinCode, deviceName, platform }` → 验码（哈希比对+TTL+未用）→ 走 store 现有 `createDevice`（或等价物）签发 deviceToken → **响应只回一次** `{ deviceId, deviceToken, protocolVersion }` → 立即删码。
3. 失败一律 403 空体或 400 带说明（码无效/过期/超额），不区分原因细节给调用方。

## R3：presence 广播

- hello 成功后（`acceptHello` 末尾）与 onClose 删名后：向**所有在线连接**广播 `{ kind:"presence", devices:[<全量名册投影>] }`（复用 `store.listDevices(now, onlineIds)`）。
- 帧契约：shared +`RelayPresenceFrameSchema`。老客户端收到未知 kind 必须静默忽略（这是协议既有约定，别破坏）。
