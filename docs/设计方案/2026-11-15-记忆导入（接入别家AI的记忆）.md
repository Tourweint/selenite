  不动记忆四层任何策略。

## magpie 的参照（<reference>\magpie，2026-11-15 读码）

三条机制，本批各取所需：

1. **存储**：一条记忆一个 md 文件（YAML frontmatter + 正文），meta.json 管账。
   字段：`scope`（global / project:<key> / agent:<id>）、`kind`（profile/preference/rule/
   reference/fact/procedure/episode 七种）、`origin`（user/agent/imported/inferred）、
   `status`（active/candidate/archived/superseded）、`pinned`。
2. **提取（memdistill，"从经过的请求里"的出处）**：读 16+ 家 agent 的本地会话文件
   （Claude Code jsonl、Codex rollout、ZCode、Pi、Cline、Droid、Cursor CLI……见
   `internal/sessions`）→ 只取 user/assistant 文本（user 截 4000 字、assistant 截 1200、
   总预算 24k 头 1/3 + 尾 2/3）→ 附上"Already known"已有记忆（≤80 条）防重复提议 →
   模型出 ≤5 条 JSON（text/kind/scope/why/quote）→ **quote 校验**：bare（只留字母数字小写）
   后必须出现在用户全部发言里，否则丢弃——挡住"模型复述助手指令"和"编造"→
   存为 inferred candidate 待审，带来源（agent/session/目录/引文）；候选 30 天没人审自动归档；
   夜间 Dream 合并同类、归档过时（用户手写的和 pinned 永不动）。
3. **导入**：自家 Bundle 格式（Export/Import"Bring in memory too"）；别家记忆服务
   （EverMe / Nowledge Mem）走 MCP 挂载，不读它们的库。

**本批吸收的口径**：外部条目进库不绕过既有校验；secrets 不进记忆（咱们由 redact 层兜底）；
同文去重由导入管线统一做。

## 本机货源盘点（2026-11-15，es.exe 全盘 + 逐家开文件核实）

### 接（global 语义，一键导入）

| 来源 | 路径（白名单常量） | 格式 → 解析 |
| --- | --- | --- |
| Qoder CLI | `~/.qoder/memories/<hash>/global/<分类>/*.md` | frontmatter(title/keywords)+正文；分类 `user_*` → preference，其余 fact |
| Qoder CLI（项目级） | `~/.qoder/memories/<hash>/projects/<slug>/<分类>/*.md` | 同上；slug 取尾段做【项目名】前缀（2026-11-15 补充轮放开，理由见下） |
| Qoder Work awareness | `~/.qoderworkcn/awareness/main/{MEMORY.md,USER.md}`（`.qoderwork` 变体同构） | 纯文本 `§` 行分隔条目；MEMORY.md → fact、USER.md → preference |
| Qwen Work awareness | `~/.qwenworkcn/awareness/main/{MEMORY.md,USER.md}`（`.qwenwork` 变体同构） | 与 Qoder awareness 同构，同解析器（2026-11-15 补充轮新增） |
| CodeBuddy | `%LOCALAPPDATA%/CodeBuddyExtension/Data/Public/.memories/*.mdc` | frontmatter(enabled/updatedAt)+正文；`enabled: false` 跳过，updatedAt → createdAt |
| ZCode（各项目） | `~/.zcode/cli/memories/projects/<项目-哈希>/memory/*.md` | frontmatter(name/description/metadata.type)+正文；`metadata.type`: user/feedback → preference、project/reference → fact；MEMORY.md 索引不收；条目带【项目名】前缀（哈希剥掉）（2026-11-15 补充轮新增） |
| 通用文件 | 用户手选 `.json`（现有 POST import 的 items 形状） | 覆盖 ChatGPT / Claude 服务端记忆导出、手工整理的条目 |

**项目级为什么放开（2026-11-15 补充轮翻案）**：首轮登记"项目级不接"的理由是 topic scope
是死数据——这个理由只对 topic 成立。global 的召回是**按相关性打分 + 窗口截断**
（`recall.ts`：FTS 候选 + importance/新近度/关键词加权，取 top-N），不是全量注入，
所以项目级条目进 global 后只在聊到相关话题时浮出来，不构成每轮刷盘。条目带【项目名】
前缀保证自含（脱离项目上下文的一句话没有用）。

## 契约（新增两个端点，挂 `/api/v1/agent/memory/import` 之下）

```
GET  /api/v1/agent/memory/import/sources
     → {ok, sources: [{id, name, note, found, count}]}
     只读扫描白名单路径；不收客户端传的任何路径。found=false 的也返回（前端灰态）。

POST /api/v1/agent/memory/import/sources/:id
     → {ok, source, added, skipped, total}
     解析该来源全部条目 → importItems（scope=global）。未知 id → 400；未检测到 → 404。
```

开关：`MEMORY_IMPORT_SOURCES`（默认开；`false`/`0`/`off` → 两端点 404、按钮不渲染）。
沿用既有两道闸：`MEMORY_ENABLED`、`MEMORY_IMPORT`。

## 映射规则

- 解析器统一产 `{text, kind, createdAt}`；createdAt 取文件 mtime / frontmatter updatedAt，
  交给 `resolveImportedTime`（非法 ISO 落 now，未来时间裁到 now）。
- kind 落既有白名单 `IMPORT_KINDS`（fact/episode/preference/entity），解析器只产 fact/preference。
- 长度上限（2000 字）、去重、redact 一律交给 `importMemories`，解析器**不重复做**——
  skipped 计数保持单一口径。

## 明确不做

1. **会话蒸馏导入**（Claude Code 23 个 jsonl、Codex 18 个 rollout，2026-11-15 数）：
   magpie memdistill 式"读会话 → 模型提炼 → quote 校验"是独立机制，且要花模型调用，
   另立项。本批不碰。
2. 别家记忆服务 MCP 挂载（EverMe / Nowledge Mem 式）。
3. legacy 版设置页不动（它已有 JSON 文件导入）；A 版弹窗里提供同一入口。
4. **超长条目不做切分**：ZCode 有 56 条超 2000 字（2026-11-15 实测），那是文档不是记忆
   粒度，按既有 `IMPORT_MAX_CHARS` 口径跳过并计数，不截半句进库。

## 备选与取舍

- 解析器放 `shared` 包 → 否：路径探测是本机细节，属 server 装配层，shared 是两端契约。
- 扫描走 Everything/全盘搜 → 否：白名单固定路径，快且可控，不给文件系统做大面扫描。
- 导入后进"候选待审" → 否：咱们没有 candidate 状态；沿用"只增不改、重复跳过"既有口径，
  不满意的条目删掉即可（记忆页已有一键删除）。
