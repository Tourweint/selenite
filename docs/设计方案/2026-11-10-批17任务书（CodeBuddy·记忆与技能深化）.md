## 一、执事履历升级：事实层 + 经验层（六 §七#3，七 #11 剩余）

1.1 现状：派单终态落一条 `kind=work` 的履历（append-only、不进召回）。
1.2 新增**经验层**：派单 `done` 时，除 work 履历外，再抽一条 `kind=experience` 的记忆：
   - 内容 = "这类活下次可以怎么做"（一句可复用的做法），**过价值门槛才存**；
   - 门槛（确定性，不调模型）：结果行长度 ≥ 40 字、且包含至少一个"具体动作词"
     （改/写/读/跑/查/整理/合并/删除/替换 等）；
   - 不过门槛就**不存**（宁缺毋滥）。
1.3 `MemoryKind` 加 `"experience"`：
   - **进召回**（与 fact 同组，权重略高）；
   - **不参与**时间衰减（经验不该过期）；
   - **参与**巩固合并（同 scope 相似经验可合并——与 work 不同）。
1.4 开关 `PARTNER_EXPERIENCE`（默认 true；false → 只落 work 履历，行为回到今天）。
1.5 单测：过门槛存 / 不过门槛不存 / 召回能取到 / 不衰减 / 开关旁路。

## 二、召回注入加 proactive 分组（六 §七#4）

2.1 召回注入目前是「偏好 / 打算 / 其它」三组。加第四组 **「也许值得提起」**：
   - 来源 = 命中但**未被当前话题直接需要**的旧记忆（importance ≥ 0.7 且超过 7 天未召回）；
   - 最多 2 条，每条 ≤ 80 字；
   - 只注入总管主对话，执事轮不注入（避免执事跑题）。
2.2 开关 `MEMORY_PROACTIVE`（默认 **false**——这是"主动开口"类能力，先观望）。
2.3 单测：高重要度老记忆进组 / 新记忆不进 / 最多 2 条 / 开关旁路 / 执事轮不注入。

## 三、记忆巩固借 codex 两阶段管线（七 #21）

3.1 现有巩固是"确定性三条 + 语义只出建议"。补两件**确定性**的：
   - **usage 排序**：`MemoryRecord` 加 `usageCount` 与 `lastUsedAt`（召回命中即 +1），
     巩固时**按 usageCount 降序 + lastUsedAt 降序**决定保留优先级；
   - **未用淘汰**：巩固时把"90 天未召回 且 importance < 0.5 且 kind 不是 preference/experience/work"
     的条目列入**淘汰建议**（仍然只出建议，不自动删）。
3.2 **审计 diff**：每次巩固产出一份 `{ merged: [...], retired: [...], kept: n }` 的差异摘要，
   落 `.data/memory-consolidate-diff.json`（只记 id 与一句摘要，不记正文），界面可查。
3.3 开关 `MEMORY_USAGE_RANKING`（默认 true）。
3.4 单测：usage 排序生效 / 淘汰建议只列不删 / diff 落盘形状 / 开关旁路。

## 四、技能 curator（七 #33）

4.1 技能使用计数：`skill` 工具每被调用一次，给该技能 +1（落 `.data/skill-usage.json`）。
4.2 列表端点（§2.19）加 `usageCount` 与 `lastUsedAt`（可选字段）。
4.3 **stale 归档**：超过 90 天未用的技能在列表里标 `stale: true`（**只标记，不删、不移**）。
4.4 **永不删除**：这一条是纪律，写进 `skills-api.ts` 注释——技能只能由人删。
4.5 开关 `SKILL_USAGE`（默认 true）。
