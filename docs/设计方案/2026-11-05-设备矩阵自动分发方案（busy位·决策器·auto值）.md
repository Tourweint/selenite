## 〇、一句话

`delegate` 的 `targetDevice` 不填时，现状 = 本机执行；本方案加第三态 **`auto`**：
按"在线 + 能力位 + 忙碌位"从中结名册自动挑一台远端电脑，挑不出就落本机——**永远有交代，
不做排队**。总开关 `DEVICE_AUTO_DISPATCH`，默认关。

## 一、现状基线（2026-11-05 审计）

| 已有 | 位置 | 对本方案的意义 |
|---|---|---|
| 点名派活全链路（targetDevice → 中继 invoke → 锚点会话 + 回执 + 轮询回报 + 汇报写回） | `relay-matrix.ts`、`tools.ts` 远程分支 | auto 只是**换一台的决策器**，投递链路零改动 |
| 中结名册（`online` + `capabilities`） | `relay/hub.ts`、`shared` `RelayDeviceView` | 候选过滤的第一手数据；**缺 busy 位** |
| 名册实时拉新 | `relay-client.ts` `refreshDevices()`（meta `devices`） | 决策前拉一次，与 E2E 已验证路径一致 |
| 远端忙碌度 | **无**。`delegation/status` 只有 per-request 相位 | 需新增目标机侧"在跑单数"查询 |
| 手机代理面 agent-delegate | `relay-mobile-proxy.ts` | 手机侧同样受益（`targetDeviceId: "auto"`） |

## 二、设计

### 2.1 触发面

- `delegate` 工具：`targetDevice` 新增取值 `"auto"`（工具描述同步：`auto` = 让电脑自己挑；
  **不填仍是本机**——对齐 cindy 的反向教育："用户没要求别传"）。
- HTTP `POST /api/v1/relay/matrix/delegate` 与手机代理面 `agent-delegate`：
  `targetDeviceId: "auto"` 走同一决策器。

### 2.2 决策器（纯函数，可单测）

```
selectAutoDevice(devices, selfId, busyMap) -> { deviceId } | { fallback: "local", reason }
```

1. **候选过滤**（平移 cindy `isExecutionDeviceCandidate`，适配我们字段）：
   在线 + capabilities 含 `matrix` + 非本机 + platform 非手机；
2. **忙碌度**：`busyMap`（目标设备 id → 在跑单数）升序；并列取 `lastSeenAt` 新者优先；
   再并列按 id 字典序（**决策必须确定性**，同输入同输出，可测可复现）；
3. **忙碌度阈值**：单机在跑单数 ≥ `DEVICE_MAX_ACTIVE_PER_DEVICE`（默认 3）视为满载剔除；
   全部满载 → fallback 本机；
4. **零候选 / 全满载 / 中继未连** → fallback 本机并给出 reason（写入汇报行，让人知道为什么没出去）。

**忙碌度从哪来**：目标机在跑单数 = 该机回执库中非终态单计数。通道 `delegation/busy`：
发起端 invoke 目标机，目标机读自己的 `delegations.sqlite` 返回 `{active}`（3 秒超时，
超时当 1——宁可低估忙碌也不把活派给查无响应的机器）。**决策在发起端**，中继保持哑。

### 2.3 落地改动面

| 文件 | 改动 |
|---|---|
| `ts/apps/server/src/relay-auto.ts`（新） | `selectAutoDevice` 纯函数 + `queryBusyMap`（并发 invoke `delegation/busy`，容错） |
| `relay-channels.ts` | 白名单 + `delegation/busy` 处理（读本机回执库 active 数） |
| `relay-matrix.ts` | `dispatchRemoteDelegation` 支持 `targetDeviceId === "auto"`：先 `refreshDevices` → 决策 → 记录 `pickedDevice` 进远端单台账 |
| `tools.ts` | `targetDevice` 参数描述 + `"auto"` 分支（挑不出时**不报错**，回"已在本机执行"语义——本机照常走既有本地派活路径） |
| `relay-mobile-proxy.ts` | `agent-delegate` 透传 `"auto"` |
| `shared/index.ts` | `RemoteDispatchInput` 无需改（targetDeviceId 本就是 string）；台账行加 `pickedBy: "explicit" | "auto"` 字段（JSON 台账，加可选字段零迁移） |

### 2.4 边界与刻意不做

- **不做排队**：全离线/全满载 → 本机执行。任务不会"存着等设备上线"（中继不存业务数据
  的红线不动摇）；
- **不回退重派**：派出去之后失败，不自动换一台再派（副作用防重复；沿用"中断不自动重放"）；
- **不做设备画像**（擅长什么/算力档）：忙碌位 + 能力位已够 v1；画像等真实需求；
- **挑不出必须可见**：fallback 本机时在 delegate 返回文本与台账里写明原因（`no_candidate` /
  `all_busy` / `relay_offline`）。

### 2.5 回滚与验证

- 回滚：`DEVICE_AUTO_DISPATCH=false`（默认）→ `"auto"` 值按非法参数处理（400），其余零变化；
- 单测：`selectAutoDevice` 各分支（零候选/并列确定性/满载剔除/非手机过滤）+ busy 通道容错；
- 探针：`matrix-probe` 扩三场景——两台在线挑 busy 少的；全离线 fallback 本机；
  `DEVICE_AUTO_DISPATCH=false` 时 `"auto"` 被拒；
- 手机代理面 E2E 复跑（`agent-delegate` 带 auto）。
