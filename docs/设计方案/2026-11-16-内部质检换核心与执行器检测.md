# 内部质检换核心与执行器检测（2026-11-16 续）

**状态**：已落地。
**冲突口径**：落地后以 `docs/基线文档/接口文档.md`、`docs/基线文档/系统架构.md` 为准；本文保留“当时怎么想的”。

## 1. 背景

2026-11-16 多 CLI 打手适配落地后，用户提出三件事：

1. **内部拆单 / 验收 / 目标核对不能用外部 CLI**。“咱们正常内部的东西应该都用我们核心的，就是我改的 PI。”
2. **设置 → 派活 的模型选不了**，希望有下拉/检测；权限默认全权可以接受。
3. **派活的人不知道派给谁**。当前 `delegate` 工具描述、技能手册、工具返回都没提执行器/模型/权限，
   总管只能说“已派发”，说不出“派给 Claude 的 opus、全权”。

调查还发现：本机 `~/.qoder/bin/qodercli/qodercli.exe` 指向的 `qodercli-1.1.81.exe` **已不存在**
（只剩坏软链；Qoder 国内版还在）。内部拆单仍在用 Qoder 国际版 → 现在真去派活，拆单会直接失败。

## 2. 为什么之前用 Qoder

chancellor 最早是独立小库，内部需要“一次纯文本 LLM 调用”（不挂工具，只让它输出 JSON）。
当时顺手借了 Qoder CLI 的 `-p`：`planTicket`、`reviewTask`、`checkTicketGoal` 都走
`runQoder({tools:"none"})`。这是历史捷径，不是设计上非它不可。

为什么不让总管/执事自己拆单验收：

- 主对话回合在 `delegate` 返回时就结束了；拆单/验收发生在后台，需要确定性。
- 拆单要把一段需求编译成结构化任务（`title / instruction / done_when / writes / dependsOn`），
  单独的“编译器”比让主对话在工具参数里直接吐 JSON 更容易校验、重试、记账。
- 验收要读 `REPORT.md` + 实际文件变化；让工人自评等于“自己判自己过”，证据没了。
- 执事是角色/人设，绑主对话；拿执事做内部质检会把角色上下文和成本带进来。

所以保留“拆单/验收/目标核对”这三个内部步骤，但把模型从 Qoder 换成核心 PI。

## 3. 方案

### D1. 内部质检走核心模型

- chancellor 新增 `src/internal.ts`：
  ```ts
  export type InternalAsk = (call: QoderCall) => Promise<QoderResult>;
  export function setInternalAsk(fn: InternalAsk | null): void;
  export function askInternal(call: QoderCall): Promise<QoderResult>;
  ```
  `planTicket` / `reviewTask` / `checkTicketGoal` 统一 `askInternal()`；
  没有注入时仍回 `runQoder`（standalone CLI / 旧测试行为不变）。
- harness 新增 `src/internal-model.ts`：
  - `coreInternalAsk` 用 `currentModels()` + `readLlmConfig()` +
    `models.completeSimple`（和 `partner-learning.ts` 的 `completeWithPartnerModel` 同款）；
  - 模型 = **主对话当前运行时模型**（`.data/runtime.json`；没有运行时选择时用 provider 缺省）；
  - 系统提示固定“只输出所要求格式”；`maxTokens`：plan 4000，review/goal 1600；
  - 超时 / 中止 / 空结果 / provider 未配置都回 `QoderResult` 形状的失败，由拆单/验收的重试逻辑处理。
- 启动时 `installInternalAsk()`：默认 `CHANCELLOR_INTERNAL=core` 注入；
  `qoder` 注入 null（回旧形态）。日志只打一行枚举。
- faux 模式不静默借 Qoder：明确失败“faux 模式没有内部模型；拆单/验收需要真实模型”。

### D2. 执行器知情：系统提示 + 工具返回

- 系统提示固定前缀新增 `<delegate_executor>` 段（`LIFECYCLE_SECTIONS`，`context-defaults` 同步）：
  `当前派活执行器：Claude Code（模型 opus，权限 全权）。新单按这个派；续跑沿用原单执行器。`
- `delegate` 工具返回带一句「已派发到 X（模型 Y，权限 Z）」；续跑只说“沿用原单执行器”，
  不谎报当前默认。
- `skills/delegate.md` 补一节“当前派活执行器”，告诉模型去哪里看。
- 这是**知情**，不是执行：模型名/权限档仍然只能通过 CLI 参数生效。

### D3. 模型检测

- 新端点 `POST /api/v1/agent/executor/probe`（`executor-mount.ts` + `executor-probe.ts`）：
  - `model` 留空：拉清单（OpenCode `models`、CodeBuddy `--help` supported、Codex config.toml、
    Claude 官方别名、Qoder `--list-models`；Qoder 路径不存在直接回“未安装”）；
  - `model` 非空：清单 + 一次极小真调（“只回复 OK”，不挂工具，60 秒）；
  - 显式人工点击；同进程 3 秒节流；`EXECUTOR_PROBE=false/0/off` → 400；
  - 失败只回脱敏分类（未安装 / 未登录 / 模型不可用 / 超时）；原始 stderr 只进服务端日志。
- 前端：模型输入改成“可输入 + datalist 可选”，旁边「检测」按钮；状态行在卡片内。
- 不自动探测登录状态：只在用户点“检测”时跑，避免启动变慢和意外额度。

### D4. Qoder 国际版：先明确报错，后修复本机安装

- `runQoderWith` 起进程前先判 `fs.existsSync(bin)`（只对像路径的值），不存在直接回
  “Qoder 国际版未安装：<路径> 不存在；请重装或在 设置 → 派活 换执行器”，不再只留 spawn ENOENT。
- 不静默把 Qoder 国际指向国内版（登录态/身份不同）。
- **本机已修复（2026-11-16 晚）**：全盘搜到真实二进制
  `<本地盘>\qoder\bin\qodercli\qodercli-1.1.81.exe`；
  `~/.qoder/bin/qodercli/qodercli.exe` 原来指向不存在的同目录版本文件，是坏软链；
  已重新指向/复制为 1.1.81（`--version` → `1.1.81`，`--list-models` 16 个，
  真调 `DeepSeek-Flash` 7.6 秒回 “OK”）。
- 内部流程已不依赖 Qoder；Qoder 只保留为工人选项。

## 4. 明确不做

- 让总管/执事自己拆单验收（理由见 §2）。
- 让工人自评/自验收。
- 把模型名/权限写进提示词当执行（换不了模型、解不开 CLI 权限）。
- 按单选择执行器 / 内部质检单独指定模型（用户 2026-11-16 明确两项都不做：
  拆任务就是拿已连接供应商发一次普通模型请求）。
- 自动探测登录状态 / 自动刷新模型清单（只在用户点检测时跑）。
- 下载/安装新的第三方 CLI：本机 Qoder 国际版是找到已有二进制并修复坏软链；
  其他机器路径不存在时仍明确报“未安装”，不静默换国内版。

## 7. 回滚

- `CHANCELLOR_INTERNAL=qoder` → 内部质检回 Qoder（需要 Qoder 可用）。
- `EXECUTOR_PROBE=false/0/off` → 检测端点 400，不 spawn CLI。
- 执行器配置本身仍由 `EXECUTOR_CONFIG=false` 回滚到 env。
- 系统提示 `delegate_executor` 段没有单独开关：它是只读信息，`CHANCELLOR_ENABLED=false`
  时不渲染（派活工具本身也不上架）。
