# 项目记忆多挂载（执事跨项目）

**状态**：方向已拍板（2026-11-15 用户两问拍板，见 §2），待实施。
**与前案关系**：不翻 `2026-11-15-项目记忆挂载跟人走.md` 的"跟人走"，把它**从单选扩成多选、给注入加闸门**；冲突处以本文为准（前案文首已补指向）。

---

## 1. 问题（2026-11-15 全量核实现状后的缺口）

1. **挂载单选**：`partners.projectId` 一个 uuid，执事横跨多个项目时只能挂一个，另一个项目的记忆**够不着**（recall 也不可查）。
2. **挂载项目无门槛进池**：召回打分里关键词只占 0.2、重要性 0.45 + 新鲜度 0.3（`memory/src/recall.ts`）。不聊挂载项目时，它最近 / 最重要的记忆照样可能挤进 1200 字预算——**"不聊不注"目前靠打分巧合不是规则**。挂载越多串味越重。
3. **写入缺口**：多挂载后 `remember scope=project` 没有明确落点（现行解析只兜"单值"）。
4. **澄清一个误会**：文件边界 = 工作区根 + **所有已登记项目根的并集**（系统架构「工作区多根模型」），挂载与文件权限无关——不挂载也写得进别的项目文件。本方案只管**记忆可达性**。
5. **"上下文爆炸"不成立**：每轮注入是候选池打分 + 总预算 1200 字（`buildContext`），挂 N 个项目不是多 N 份内容，只是换谁竞争同一份预算。真代价是 §1.2 的串味。

## 2. 拍板（2026-11-15，用户）

- 挂载改**多选**。
- 除当前会话绑定的项目外，其余挂载项目**"聊到才注入"**（字面命中才进候选）。
- `remember scope=project` **让模型按项目名指名**。

## 3. 模型：挂载 = 服务范围（可达性），不是"每轮搬进来"

| 层 | 现状（11-15 两批后） | 本方案 |
|---|---|---|
| 挂载数量 | 一人一个 | 一人多项目（`projectIds` 数组） |
| 每轮自动注入 | 挂载项目全权进池 | **绑定项目全权；其余挂载项目 gated（字面命中才进）** |
| recall 工具 | 绑定 + 单挂载 | 绑定 + **全部挂载**（主动查不受闸门） |
| remember scope=project | 绑定优先、单挂载兜底 | 绑定优先 → 唯一挂载兜底 → **多挂载按名指写** |
| 注入行归属 | 无（只 `[kind]`） | 项目来源带名：`- [atlas · fact] …` |
| 可达性感知 | 无 | 一行索引：负责项目清单 + 用法提示 |

三条不变：**跟人走**（挂载在档案上，对该人格全部对话生效）；**worker 跟文件夹走**（不吃人格挂载）；**群聊不进记忆**。

## 4. 机制

### 4.1 记忆包（`ts/packages/memory`）

- `RecallQuery` 加 `gatedScopes?: string[]`（scope key 数组）：
  - 候选池 = （文本命中 ∪ 最近窗口）覆盖 `scopes`，**gated 只走文本命中路径**（FTS pass 覆盖 scopes + gated；最近窗口只覆盖 scopes）；
  - gated 来源的候选再过一道**字面相关过滤**（复用 proactive 同款 `directlyRelevant` / `keywordScore`，关键词取自本轮用户文本）；text 为空或切不出关键词时 gated 一律不贡献；
  - 打分、1200 字预算、proactive、衰减全部不动。
- `InjectOptions` 加 `scopeLabel?: (scope: MemoryScope) => string | null`：project scope 的命中行渲染 `- [项目名 · kind] …`；缺省或返回 null 用旧格式（**不传 resolver 时输出逐字节兼容**）。

### 4.2 挂载解析（`agent/project-scope.ts`）

- `personaProjectIdOfSession` / `personaProjectIdOfConversation(+Async)` 升为多数版 `personaProjectIdsOf*`：返回 `string[]`；worker / 未接线 / `PARTNER_PROJECT_MEMORY=false` 语义不变（空数组）。
- 纯函数测试口径不变（收 store，喂临时库）。

### 4.3 注入组装（`agent/assist.ts`）

- `recallContext`：`scopes = [global, partner?, 绑定项目?, session]`；`gatedScopes = 挂载 − 绑定`（去重）。`PROJECT_MEMORY_GATE=false`（新回滚开关，默认开）时挂载并回 scopes 全权池 = 11-15 形态。
- `scopeLabel` resolver：项目 uuid → 项目名（项目库），查不到给 null。
- 新注入条目 **`project_index`**（order 95、channel message、scope turn）：非群、开关开、挂载 ≥1 时输出一行「负责项目清单 + recall 可查 / remember 指名」的用法提示；项目名来自项目库。`INJECTION_ORDER` 加常量（**缓存前缀资产**，变更记录登记）。

### 4.4 工具（`tools.ts`）

- `recall`：scopes 并入全部挂载项目（去重）；描述补一句"负责的项目都能查"。
- `remember`：加可选参数 `project`（项目名）。解析顺序：**显式指名 → 会话绑定项目 → 唯一挂载 → 报错引导**；指名未命中挂载清单、或多挂载未指名 → 报错并列出可写项目名（先精确后忽略大小写唯一命中）。工具描述改动 = **缓存前缀资产**，变更记录登记。

### 4.5 契约与存储

- shared `PartnerProfileSchema`：`projectId: uuid|null` → **`projectIds: string[]`**（uuid 数组）。投影 = 已挂清单（可空数组）；PATCH：省略 = 不改 / 数组 = 整体替换（去重、每个 uuid 须在项目库（含归档），未知 → 400 整批不写）/ 空数组 = 清空。字段 11-15 刚上线、手机端未消费，**直接换不留旧字段**。
- `partners.sqlite`：加 `project_ids TEXT`（JSON 数组）+ 一次性迁移（旧 `project_id` 非空 → `[旧值]`）；旧列保留不再读写（不 DROP，老库安全）。
- 开关：`PARTNER_PROJECT_MEMORY=false` 整字段不投影 / 不并召回 / 页面隐藏（沿用）；**`PROJECT_MEMORY_GATE=false`** 退回"挂载全权进池"（一行回滚注入闸门）。

### 4.6 UI（`web/partner-profile.js`）

- 负责项目单选 `<select>` → 复选（项目列表勾选），保存 = `PATCH { projectIds }`；`"projectIds" in partner` 判定显隐。

## 5. 明确不做

- **不翻"跟人走"**：会话级手动挂载仍不做（前案 §7 的三个理由照旧成立）；
- Agent 自动判断挂载 / 挂载工具——猜错比不猜更糟（沿前案）；
- 整理（consolidate）仍不碰项目 scope；
- 项目名匹配只做精确 / 忽略大小写唯一命中，不做拼音 / 别名 / 模糊；
- 不做"项目级简介整段注入"（索引一行 + 闸门先跑，不够再立）；
- 手机端展示负责项目仍二期（契约纯换，手机忽略未知字段）。
