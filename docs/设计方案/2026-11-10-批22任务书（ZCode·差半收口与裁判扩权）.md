## 三、#36 裁判能重跑测试（本批核心）

3.1 现状：裁判 bash 过 `isReadOnlyShellCommand` 纯读词表，`npm test` / `git` 全拒——
   裁判只能读代码和报告，**不能独立复核"测试通过"这一最关键的证据**（#36 原注记）。
3.2 **做法**：`judgeBashAllowed` 扩两级白名单：
   - 第一级（现行为，不变）：纯读词表；
   - 第二级（新增）：`DELEGATION_JUDGE_RETEST` 开（**默认关**——放宽类默认关，
     总验收报告方法论 #3）时额外放行：
     - `npm test` / `pnpm test` / `npx vitest run`（可带文件路径参数，不带旗标）
     - `npm run` / `pnpm run` **仅当脚本名含 "test"**（`test:unit`、`test-e2e` 算）——
       实现时收紧：`run` 任意脚本等于任意执行（deploy 也是 script），与裁判只读定位冲突；
     - `git status` / `git diff` / `git log` / `git show`（只读子命令；旗标只认一小撮
       纯展示项 `--stat --oneline --name-only --name-status -p --abbrev-commit`，
       `-c`/`--pretty=` 这类可执行口全拒）
   - 纪律不变：单条、无管道/重定向/通配/命令组合/命令替换（含这些字符一律照拒）；
     只读子命令之外的一切 git 动作（commit/push/checkout…）照拒。
3.3 实现落点：`delegation-judge.ts` 的 `judgeBashAllowed`（加第二级判定函数
   `isJudgeRetestCommand`，纯函数可单测）+ 裁判提示词 bash 行描述同步（固定字节；
   描述改动按 AGENTS.md 缓存纪律在变更记录登记——裁判是独立短会话，缓存影响一次性）。
3.4 开关：`DELEGATION_JUDGE_RETEST`（默认 false；`true`/`1`/`on` 开）。裁判本身仍受
   `DELEGATION_JUDGE` 总开关与 maxTools 硬上限约束。
3.5 单测：`delegation-judge.test.ts`——
   - 开关关：`npm test` / `git diff` 照拒（逐字节回归）；
   - 开关开：四种 test 形态 + 四个 git 只读子命令放行；`git commit` / `git push` /
     `npm install` / 管道 / 重定向 / 命令组合照拒；
   - 描述文本包含"可跑测试与 git 只读子命令"且不含日期/计数（固定字节断言）。
