# 2026-11-14 连接页星形拓扑与设备身份（多电脑 · 多设备 · 可移除）

> 用户原话：「这一页不只是这一台电脑，可能有多台电脑、多个设备。所以最上面的连接状态视图还要改，改成形状，像星星一样，也不算网状吧。……底下已连接的设备要给每个连接设备一个 ID。要是重复了就得合并，长期不用了也得能移除。现在电脑上我看没办法移除，你把这个做一下。」

## 结论

1. **顶部从"一条链"改成星形**：中间是「中继」，四周围着所有已知设备（本机电脑、其它电脑、手机/平板）。连到中继的画一条实线（经中继），只在本地的画一条虚线连到「这台电脑」。设备多时按椭圆均分角度，超过 8 个收成「+N」。
2. **每台设备给一个 ID**：本地配对用配对 `id`，经中继用中继 `deviceId`，页面上显示前 8 位（`#a1b2c3d4`），悬停看全名。**同一个名字出现在两套名册 = 同一台设备，合并成一行**（ID 都留着，标签两套都打，移除时两边一起撤销）。
3. **能移除**：本地配对设备沿用 `POST /api/v1/pair/devices/:id/revoke`；**中继设备新增 `POST /api/v1/relay/devices/:id/revoke`**，由 harness 用 owner 令牌代调中继（浏览器不直连中继、令牌不下发客户端），中继侧撤销并踢掉在线连接（4401）。
4. 长期不用的设备标「久未使用」（> 7 天），跟"移除"放在一起——这一页要回答的是"这台还留着吗"。

## 取舍 / 备选

| 备选 | 不选的理由 |
|---|---|
| 做真网状（设备之间互相连线） | 设备之间根本没有直接通路，全是经中继转，画网状是假的 |
| 用设备名当合并键之外再加平台字段 | 本地配对记录里没有平台字段（手机配对了才上报名字），按名字合并是唯一可用的键；合并行会标「合并 N 条记录」，合并错了看得见 |
| 让浏览器直连中继撤销 | owner 令牌绝不下发客户端（密钥纪律），必须由 harness 代调 |
| 移除改成"只从列表里藏起来" | 藏起来等于凭据还在、设备还能连，用户以为删了其实没删——必须真撤销 |

## 明确不做

- 不改手机端：设备 ID 只是页面展示，手机不需要知道自己的 ID 长什么样。
- 不合并两套名册的**主键**（配对 id 与 relay deviceId 各自保留），只合并**展示行**。
- 不做设备在线表、不做"踢下线"以外的运维动作（`revoke` 已经会踢）。
- 不做拓扑动画。
