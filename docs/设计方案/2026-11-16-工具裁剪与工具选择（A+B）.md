# 工具裁剪：delegate 手册进内置技能 + 人设页工具勾选（A+B）

**状态**：待实施（2026-11-16）。
**来源**：用户看完设置 → 上下文页后拍板：先做 A（把 `delegate` 的大段政策从工具描述挪进技能）
与 B（人设页按人勾选工具）；C（`deferred` + `tool_search` 懒加载）先不做。
**下沉落点**：`接口-端点1-对话与兼容层.md` §2.2.5、`接口-端点4-执事例行与自主轮.md`、
`接口-端点7-权限技能与开关.md`、`接口文档.md` §6、`系统架构.md`。与长期文档冲突时以长期文档为准。

## 1. 现状（2026-11-16 实测）

- 总管默认面 22 个工具 ≈7,922 token，占固定前缀 84%；其中**描述 ≈4,098 token、参数 schema ≈3,539 token**。
- `delegate` 一个 2,114 token：描述 1,316 + 参数 796；描述里堆了任务书四段、steps、resume、四行回报、裁决纪律。
- 工具在 extension 里**全局安装**，所有会话看到同一份；`AgentState.modelTools`（pi-durable 自带过滤）从未使用。
- 技能启停位默认**全关**；把手册放进普通技能，`delegate` 会失去说明 → 需要“内置技能（core）”例外。

## 2. A：`delegate` 政策进内置技能

### 2.1 内置技能（core）

- 新增 `apps/server/skills/delegate.md`（扁平形态：第 1 行摘要，其余正文），内容 = 从工具描述挪出的完整政策。
- 新增 `src/core-skills.ts`：`CORE_SKILL_NAMES = new Set(["delegate"])` + `isCoreSkill(name)`。
  只认代码内置名单，不让用户目录里的同名技能“自称 core”。
- `createSkillStore` 加可选 `isCore?: (name) => boolean`；`canSee` 改为 `isCore(name) || 启停位判定`。
  索引、`names()`、`manual()` 三处同一条规则；普通技能行为不变。
- 管理面：`GET /agent/skills` 的 item 增 `core: true`；`PUT /agent/skills/:name/enabled`
  对 core 返回 **400**（文案：系统内置技能，始终可用）；`enabled-all` 跳过 core。
- 前端技能页：core 行显示「内置」徽标 + 开关锁死（悬停说明）；按人技能弹层把 core 归到「全局已开」只读。
- 回滚：core 名单是代码常量；A 本身不是开关型能力，回退按提交回退（普通技能零影响）。

### 2.2 `delegate` 描述瘦身

保留（每次调用都要看见的）：
- 做什么 / 适合什么 / 不适合什么；
- **派出去立即返回、后台汇报、不要等 / 不要反复查 / 不要重复派**；
- `project` 必填与 `needs_project` 流程；`resume:true` 只写用户那句回答、不要重派；
- `domain` 小写 ASCII；`steps` 一句；相对路径 / 手机工人碰不到电脑文件一句；
- **“第一次派活前先调 `skill({name:"delegate"})` 读完整手册”**（显式名字，老会话没有索引也能取到）。

挪进技能手册（描述里不再逐字重复）：
- 任务书四段展开与岗位契约对应关系；
- steps 的完整规则；`need_input` 处理；
- resume 的全部细节（“对方这句话本身就是要交回的内容”等）；
- `REPORT_FOUR_LINES` 四行回报原文；
- `RULING_DISCIPLINE` 裁决纪律原文（执事会话另有纪律段，不重复计）。
- 设备 / 手机 caveat 的完整说明。

参数 schema 不动；工具顺序不动。描述改动会改一次缓存前缀，按既有规矩记 `变更记录/`。

## 3. B：人设页工具勾选

### 3.1 存储

- `partners` 表新增 `disabled_tools TEXT`（JSON 数组，未知/坏 JSON 当 `[]`）：
  **存“取消勾选”的名单，空数组 = 全开**。这样以后新增工具默认对所有人可用，不会因为老档案冻结而消失。
- `PartnerRow.disabledTools: string[]`；`toPartner` 解析；新增
  `setDisabledTools(id, names)`（一条 UPDATE，不版本化、不 bump 身份）。
- 团队包**不带**这项（与 `personaModules` / `projectIds` 同口径，团队包只带 SOUL / 契约 / 技能 / 记忆）。

### 3.2 工具目录与组

- 新增 `src/partner-tools.ts`：
  - `modelToolCatalog()`：从真实 extension（`CodingTools.tools` + `lifediaryExt.tools`）合并、
    过滤 `deferred === true` 与 `callers` 不含 `model` 的、按名去重、保持注册顺序；
  - `PARTNER_TOOL_GROUPS`：文件与命令 / 记忆 / 派活与任务 / 资料与技能 / 执事与群组 / 其他；
  - `toolSummaryOf(description)`：首句 / 首行截 80 字，给勾选列表一行说明；
  - `sanitizeDisabledTools(input, knownNames)`：数组、去重、未知名字返回 400 名单；
  - `applyPartnerToolSelection(chat, partner)`：见 §3.3；
  - `partnerToolsEnabled(env)`：`PARTNER_TOOLS_ENABLED=false` / `0` / `off` 时整组关闭。

### 3.3 运行时生效（下一轮）

- 在 `agent/session-stream.ts` 的 `chatStream` 入口、提交用户输入之前：
  解析这条会话的 owner——`partnersStore().partnerIdOfSession(internalId)` 优先；
  没有链接且 `chatKind === "chief"` 时按总管（`CHIEF_PARTNER_ID`）；worker / task 不处理。
- `applyPartnerToolSelection(chat, partner)`：
  - 读出当前 `agent.tools` 的名字集合；按 `catalog − disabled` 算期望集合；
  - 一样 → 不写；不一样 → `configure({ modelTools: { remove: 被取消的工具对象 } })`，
    名单为空时 `configure({ modelTools: null })` 恢复默认；
  - 只影响模型可见工具，不动 nested 调用 / 工具实现；失败只 console.warn，不挡对话。
- 覆盖：总管主会话、执事专线、执事群会话、例行会话都走 `chatStream`，一处生效。
  `worker` 开发会话与任务专线不参与（它们本来就不用 lifediary 工具面）。

### 3.4 端点

- `GET /api/v1/partners/:id/tools` → `{ok, enabled, disabled, tools:[{name, group, summary, enabled}]}`；
  `enabled=false` 时仍 200（页面据此隐藏卡），未知执事 404。
- `PUT /api/v1/partners/:id/tools` body `{disabled: string[]}` → `{ok, disabled}`；
  - 非数组 / 元素非字符串 / 超过 64 个 / 未知工具名 → 400 带 `unknown` 列表；
  - 重复名去重；空数组 = 全开；
  - `PARTNER_TOOLS_ENABLED=false` → 400 带说明；
  - 只写 `disabled_tools`，下一轮生效。
  - **依赖收口**：`delegate` 的描述要求先调 `skill` 读手册；目录里同时有 `delegate` / `skill` 时，
    只关 `skill` 不关 `delegate` → 400（两者一起关合法）。
- `GET /agent/context-defaults?role=partner:<id>` 与 `role=chief`：
  工具面按该人 `disabledTools` 过滤（默认页看的就是他真实能看到的工具）；`worker` 不变。

### 3.5 人设页 UI

- 新分区「能用的工具」（位于「按相关度召回」之后、「高级开关」之前）：
  一张卡显示 `已开 N / M` + 「管理」；总管与执事都有。
- 点开弹层：按组列出勾选框（勾 = 可用），每行 `name` + 一行摘要；底部
  「全选 / 恢复默认（全开）/ 取消 / 保存」；保存走 PUT，成功后 toast 并回写卡片计数。
- 空态 / 接口失败：卡片显示一句失败原因，不白屏；`enabled=false` 整段隐藏。
- 关掉某工具 = 下一轮起模型看不到、也调不了；页面不写长篇解释，只用标题悬停提示。

## 4. 明确不做

- **C（`deferred` + `tool_search` 懒加载）**：先不做；等 A+B 的效果与用户反馈再定。
- **不按角色自动推断工具面**（worker / 群 / 任务专线）：只做人设页手工勾选；worker 默认页仍按现有口径。
- **不改参数 schema、不改工具顺序**；A 只动 `delegate` 描述与新增手册。
- **不做每会话覆盖**、不做工具级权限审批（审批仍走现有闸门）。
- **不把 `disabledTools` 写进团队包 / 手机端**；手机端零改动。

- A：core 技能进索引、可按名取手册、启停端点 400、普通技能行为不变；
  `delegate` 描述不再包含四行回报 / 裁决纪律原文，手册包含；
  `prompt-discipline.test.ts` 的断言同步改到手册。
- B：store 往返；`modelToolCatalog` 与组；sanitize；`applyPartnerToolSelection`
  在名字不同时才 configure（含 remove → null）；GET/PUT 端点；`context-defaults` 过滤；
  typecheck + 单测 + HTTP 探针 + 浏览器（隔离实例建一个临时执事，勾掉一个工具，下一轮

- 性能：`chatStream` 每轮读一次 agent + 比较名字集合；无写入时不产生新 agent 条目。
