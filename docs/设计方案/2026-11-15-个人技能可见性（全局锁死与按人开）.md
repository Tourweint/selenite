# 个人技能可见性：全局锁死 + 按人开（2026-11-15）

## 状态

方案已定稿，当日落地。用户口径来自 2026-11-15 的四问四答；本方案只改「编辑这个人」页的技能区，
不改全局技能管理页的编辑能力，也不改工作区 / 总管改他人设置那两批。
落地验证与两处修复（状态形状、逃生门）见
[变更记录](../变更记录/2026-11-15-个人技能可见性（按人开与三层弹层）.md)。

## 背景

「编辑这个人」页的技能区现在只能看，不能配：

- 全局技能（内置 + `~/.lifediary/skills` + `~/.agents/skills`）由 `.data/skills-state.json` 的全局启停位过滤；
- 执事自带技能（`partner-homes/<id>/skills/*.md`）只列名字和摘要；
- 页面给的是两段只读清单，既不能按人挑全局技能，也没有新建入口。

用户拍板：

1. 全局已开启的技能对所有执事生效，**个人页锁死只读**，不能按人关。
2. 全局未开启的技能，可以在某个执事页**单独给他打开/关闭**。
3. 个人页新建技能**先落全局库（默认关）**，再自动只给当前这个人打开。
4. 「让他自己写」= 跳到这个执事的会话，输入框预填一句，让他把流程写成技能。
5. 个人页不做技能正文编辑；全局技能编辑仍归「设置 → 技能」。
6. 技能索引改成搜索式（`skill_search`）这批**不做**，索引仍按人过滤后整段注入。

## 数据模型

复用 `.data/skills-state.json`，向后兼容：

```json
{
  "enabled": { "skill-a": true },
  "partners": { "<partnerId>": { "enabled": { "skill-x": true } } }
}
```

- `enabled`：全局启停位，语义不变；文件里只存"开着"的。
- `partners.<id>.enabled`：按人覆盖层，只存"全局没开、但这个人要开"的技能。
- 判定：
  - 全局开 → 所有会话可见，个人页锁死；
  - 全局关 + 该人覆盖开 → 只对这个人的会话可见；
  - 全局关 + 无覆盖 → 不可见。
- `SKILL_STATE=false` 逃生门保持原义：全进索引、不过滤；此时按人状态不参与。

不新增文件、不新增环境变量；回滚 = 删 `partners` 字段或整个状态文件，行为回到本批之前。

## 生效链路

| 位置 | 改动 |
| --- | --- |
| `skill-state.ts` | 新增 `isEnabledFor / isOverridden / setEnabledFor / partnerNames`，仍懒建单例 |
| `skills.ts` | `SkillStore` 的 `names / manual / indexFor` 接收可选 `partnerId`；新增 `visibleFor(partnerId, name)`；索引冻结键改为 `conversationId + partnerId` |
| `agent/assist.ts` | `createSkillStore` 传入 `visibleFor`：`SKILL_STATE` 开时 `global || partner override` |
| `agent/lifecycle-injections.ts` | `skillsProvider` / `skillSlashProvider` 用 `ctx.partnerId`；主对话回落 `effectivePartnerIdOfSession`（= `chief`） |
| `tools.ts` 的 `skill` 工具 | `manual / names` 传当前会话的 effective partnerId；别的执事看不到这个人独开的技能 |
| `skills-api.ts` | `GET /api/v1/agent/skills?partnerId=` 每项追加 `partnerEnabled / partnerOverride`；不带参数时形状不变 |
| `companion-api.ts` | 新增 `PUT /api/v1/partners/:id/skills/:name/enabled`，body `{ enabled: boolean }` |

可见性只在**会话第一次渲染索引时冻结**（既有 D5 取舍）：改开关不影响已经在跑的会话，
下一个会话开始生效。UI 上要写这句，不假装即时生效。

## 端点

### GET /api/v1/agent/skills?partnerId=<id>

- `enabled`：全局启停位，不变。
- `partnerEnabled`：该人实际可用（`global || override`）。
- `partnerOverride`：全局没开、该人单独开。
- `partnerId` 不合法/不存在时按无覆盖处理，不新增错误分支。

### PUT /api/v1/partners/:id/skills/:name/enabled

- 鉴权同其它 companion 端点；`COMPANIONS_ENABLED=false` 时整组不挂。
- 执事不存在 → 404。
- 技能名不合法 → 400。
- 技能不存在 → 404（防止状态里堆无效名字）。
- 全局已开 → **409**，文案「全局已开启，所有人都有；个人不能关」。
- 全局未开 → 写/删该人的覆盖位，返回 `{ ok, partnerId, name, enabled }`。
- 只改状态，不改技能文件；不自动删技能。

## UI（编辑这个人 → 技能）

弹层分三段：

1. **全局已开（所有人都有）**：只读行，右侧「已开 · 锁」；不提供开关。
2. **全局未开（只给这个人开）**：每行一个开关，调上面的 PUT；关 = 删覆盖位。
3. **他自带的技能**：只读；每行给「让他改」按钮，跳他的会话并预填。

顶部两个按钮：

- **新建全局技能**：复用设置页 `openCreateSkillModal`；成功后自动调 PUT 给当前人打开，
  再刷新本弹层。新技能全局默认关，不影响别人。
- **让他自己写**：关闭弹层，打开这个执事的会话（总管走 `openChiefChat`，其他走
  `openPartnerChat`），在 `#input` 预填「帮我写一份技能：先把步骤、判据和常见坑问清楚，
  再落成技能；第一行写一句摘要。」

不提供：

- 全局技能正文编辑（个人页只读；归「设置 → 技能」）；
- 自带技能正文编辑（走「让他改」对话）；
- 从全局未开列表批量全选（逐个开关，避免误开）。

卡片摘要从「全局 已开/总数 · 自带 N」改成「全局 N · 独开 M · 自带 K」，
其中 M = 全局没开但给这个人开的数量。

## 刻意不做

- **搜索式技能索引**：用户明确说「第二个索引技能不用管了」。索引仍是名字 + 一行摘要，
  按人过滤后整段注入；技能正文仍走 `skill(name)` 按需取。
- **总管改其他员工的技能**：`partner_skill_write` 加 `partnerId`、`partner_manage update`
  这批跟「注册项目 + 会话级工作区」一起做，避免现在把权限口子开一半。
- **工作区改造**：执事 cwd 仍是当前项目/工作区，等注册项目落地再做会话级根。
- **个人技能写端点**：个人页不做正文编辑，就不新增 POST/PUT/DELETE；自带技能由执事
  自己用 `partner_skill_write` 写，或走对话引导。
- **技能包导出携带按人覆盖**：`partner-bundle` 只带技能文件，不带全局状态；跨机恢复后
  需要重新点开关，登记在案。

## 风险与回滚

| 风险 | 处理 |
| --- | --- |
| 按人过滤改了注入文本，影响所有会话的技能索引 | 只增加过滤条件；全局开 / 无覆盖时输出与改造前逐字节一致；`SKILL_STATE=false` 完全绕过 |
| 现有会话索引已冻结，改开关看不到变化 | 保留 D5 语义，UI 明示「下一个会话生效」；不为此破坏缓存前缀 |
| 全局开启后按人覆盖残留，之后全局关掉又冒出来 | 覆盖只在全局关时生效；全局开时 UI 不展示、判定走全局。残留是显式的，不是隐式继承 |
| 新端点写坏状态文件 | 复用 `skill-state` 的临时文件 + rename 原子写；读写都容错坏 JSON（按空处理） |
| 旧客户端不认识新字段 | `GET /agent/skills` 不带 `partnerId` 时字段不出现，形状不变 |

回滚：

- 代码回滚到本批之前即可；`.data/skills-state.json` 的 `partners` 字段对旧代码透明。
- 紧急逃生：`SKILL_STATE=false`（全进索引，按人状态不参与）。
