# 批 30 任务书：技能分类与开启建议（Agent 评估 + 分栏展示 + 逐条采纳）

日期：2026-11-10 · 状态：已落地（2026-11-10 当日实施+真模型验收；落地记 `docs/变更记录/2026-11-10-批30（技能分类与开启建议）.md`，含三处实测教训与偏差——超时 30s→90s、输出改紧凑数组、模型候选链）
上位需求：用户口径——"让 Agent 自己判断哪些技能适合开、哪些不适合开"；"基本有用、属于基础设施的技能肯定要留着，建议开启"；展示**预计使用频率**（技能是手册不"运行"，频率=预计多久用上一次）；**建议+用户确认**（逐条采纳或一键采纳"建议开启"栏）。

## 背景（2026-11-10 已核实）

- 技能默认全关（`skill-state.ts`），名单外不进索引、`skill()` 取不到 = agent 不知道有这能力。
- 技能 = 手册不"运行"，开着零成本（索引一行摘要）；**"预计使用频率"是给用户判断值不值得开的参考信息**，不是定时器。
- `.agents/skills` 有 123 条（用户装了大量第三方技能），其中不少是给**别的工具**用的（baoyu 系列是公众号/微博工具人、autoglm 系列依赖 ZCode 特有环境），对咱们的 agent 没用或跑不起来——正是"分栏"要解决的：把有用和没用分开。
- **本轮模型请求本身就看得到所有技能摘要**（L1 索引进 system）——但那是"开着"的；现在全关。所以建议生成时把**全量技能清单**（名称+摘要+当前启停+用量）直接喂给独立模型调用，不依赖索引。
- 旁证数据：管理端点已有 `usageCount` / `lastUsedAt` / `stale`（批 17/18 用量账），可一并喂给评估和展示。

## 设计

### 三栏口径（用户原话落地）

| 栏 | 判据 | 动作 |
|---|---|---|
| **建议开启**（keep） | 基础设施 / 常用能力，对本机 agent 有用且能跑 | 一键采纳 |
| **按场景**（scene） | 特定任务才用（如 browsing 类、写作类） | 用户自己逐条开 |
| **建议不开**（skip） | 依赖别的工具的环境（ZCode 特有）、面向别的平台（公众号/微博发布）、与本地 agent 形态冲突 | 不开 |

### 存储：`.data/skills-advice.json`（已 gitignore）

```json
{
  "generatedAt": "ISO",
  "model": "provider/modelId",
  "items": { "<skill-name>": { "bucket": "keep|scene|skip", "frequency": "daily|weekly|monthly|rare", "reason": "一句话理由（≤40 字）" } }
}
```

- `keep`=建议开启、`scene`=按场景、`skip`=建议不开。
- 不写启停位：建议归建议（`skills-advice.json`），开关归开关（`skills-state.json`），采纳那一刻才由前端逐条调既有 `PUT …/enabled`。
- 无 TTL、不自动刷新：建议是**快照**，用户点"让 Agent 重新评估"才重新生成。装新技能后建议缺这条 = 前端标"未评估"，不硬凑栏。

### 端点（挂 `mountSkills` 同一 router；回滚开关 `SKILL_ADVICE=false` → 路由不挂）

| 端点 | 方法 | 行为 |
|---|---|---|
| `/api/v1/agent/skills/advice` | GET | 读快照（无则 `{items:{}}`）。每次 GET 都把快照与当前技能名集合做差集：消失的技能名清掉，新技能标 `unevaluated`（快照生成后新装的技能）。 |
| `/api/v1/agent/skills/advice` | POST | 生成建议（独立模型调用，范式抄 `memory-extract.ts` generateOnce：`completeSimple` + `auxiliaryModel("advice")` + AbortController 超时 90s（2026-11-10 实测 123 条技能 flash 模型 30s 不够，静默超时后拉长并补日志））。**先算后写**（原子写同 skill-state 范式）：生成中旧快照保留可读（GET 旧+标记 `stale:true`），写完一次性替换。 |
| `/api/v1/agent/skills/advice` | PUT | 仅接受 `{"actions":[{name, enabled}]}`，**只写启停位**（复用 `skillState.setEnabled`）。**闸门：条目必须来自快照**（名字在 `items` 里）——防"伪造建议直接开技能"（管理面同理）。名字必须存在于技能目录。名字不在快照 → 400。 |

### 评估输入（POST 的模型输入，全量不截断：123 条不超上下文）

- system：角色（技能库管家）+ 三栏判据 + 输出契约（严格 JSON）+ "你评估的 agent 是：Windows 本机单人 agent（Hono 服务 + bash/write/edit 工具面，非 Claude Code/ZCode；技能的'运行环境'是本机 Windows + ego lite 浨览器；面向其他 agent 平台/环境的技能建议不开）"
- user：JSON 行清单：`{name, summary(截 200 字), enabled, usageCount, stale, origin}`。
- 判据（写进 system）：1) agent 可用性（本机 agent 用不上=skip）；2) 频率：`daily`=基础设施/常用、`weekly`=常规、`monthly`=场景类、`rare`=几乎用不上。`rare` 一律 skip（几乎用不上还占索引）。`rare` + `keep` 冻火不容——模型输出自相矛盾时前端标"待复核"，不该采纳进"建议开启"。
- 用量旁证：`usageCount`≥3 且 stale=false 且当前开着 → 默认 keep 值（模型可改判）。

### 前端（技能页，`web/app.js` 技能页渲染函数 `renderSkillList`）

- 技能页顶部加三个筛选 chip：**全部 / 建议开启 / 按场景 / 建议不开 / 未评估**（默认"全部"）。
- 卡片上：栏位徽章（keep=「建议开启」、scene=「按场景」、skip=「建议不开」、rare+keep 矛盾=「待复核」）。频率文案：`daily→每天会用到 / weekly→每周用上 / monthly→每月一次上下 / rare→几乎用不上`。理由 hover title。
- 顶部按钮「让 Agent 重新评估」：POST advice（生成中转圈 + 禁点，按钮文案"评估中…（技能多，最多 90 秒）"）。
- 顶部按钮「一键采纳：开启全部『建议开启』」（仅当 keep 栏非空才显示）：PUT advice actions，采纳后 toast + 刷新列表。
- 模型不可用/超时/faux → POST 返回 503 `{message:"模型不可用，评估没跑成"}`，前端 toast 不崩。

## 明确不做

- **不做自动刷新 / 定时评估**：建议是快照，装新技能标"未评估"即可；定时器是例行任务的事。
- **不做"Agent 直接改启停"**（用户拍板：建议+确认）。
- **不做 per-skill frequency 定时器**（技能是手册，没有运行时）。
- **不把建议写进技能目录**（`.agents/skills` 只读口径）。
- **不改 L1 索引结构**（建议不进 system——那是给 agent 的，不是给人看的）。
- **不评估符号链接技能**：ego-browser 这类软链技能不在管理列表（path-guard），评估输入以管理列表为准（`GET /agent/skills` 的 items）；软链技能不评估、栏位标"（不在评估范围）"。
- **不进总账/接口文档 §2**：纯管理面功能，无 agent 契约变化；变更记录即可。
