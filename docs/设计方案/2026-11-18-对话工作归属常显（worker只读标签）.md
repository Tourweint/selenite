# 2026-11-18 对话工作归属常显（worker 只读标签）

> 一句话：普通 worker 对话的输入框左下角**常显**它在哪个项目/工作区干活；新建时跟着左侧侧栏的当前选择，落盘后冻结为创建时快照，只读不可改。输入框里的「选项目」菜单退役。

状态：已实现（2026-11-18）。
下沉落点：契约 → `docs/基线文档/接口-端点1-对话与兼容层.md` §2.2；开关 → `docs/基线文档/接口文档.md` §6；机制 → `docs/基线文档/系统架构.md`「会话的 cwd 是创建时快照」条。与长期文档冲突时，以长期文档为准。

## 背景

2026-11-17 的「新建对话选目录」在输入框左下角放了一个「选项目」pill：只在**还没落盘**的新 worker 会话上出现，拿到 `conversationId` 后就收起（`chat-project.js` 的 `isNewWorkerChat`）。实际使用中有两个问题：

1. 用户发出第一条消息后，这条会话到底落在哪个项目/工作区就**再也看不见**了；活跃会话列表也不带项目字段。
2. 首屏空会话（没有落盘会话时的「普通对话」）连那一次都不显示——`app.js` 的启动路径只改标题，没有调 `syncChatProjectPill()`。

用户口径（2026-11-18）：左侧侧栏已经必须选一个项目（不选就是工作区），选中的就是这条新对话的落点；输入框里把项目名**写出来、不可改**就行。总管/执事派出来的 task 专线仍在侧栏按「总管 / 各执事」分组，不在本次范围。

## 结论

| 事 | 做法 |
|---|---|
| 新建 worker 对话 | 标签跟着左侧侧栏的「当前项目 / 工作区」实时变；数据没回来前不画，不闪「工作区」。 |
| 已落盘 worker 对话 | 用服务端 `GET /agent/chat/:id/messages` 新增的 `chatWorkdir`（创建时快照）显示；侧栏再换项目也不变。 |
| 只读 | `<button>` 改 `<span>`，删除菜单 / chevron / 点击 / `aria-expanded`；hover title 显示完整路径与「创建时固定」。 |
| 总管 / 执事 / task 专线 | 不显示（`chatKind !== "worker"` 直接收起）。侧栏分组现状不动。 |
| 首屏空会话 | `applyProjectData → syncChatProjectPill`，启动路径自然补上。 |
| 回滚 | `CHAT_PROJECT_LABEL=false`：服务端不下发 `chatWorkdir`、policy 投影 false、前端收起标签。**不恢复**输入框选项目菜单。 |

## 契约增量

`GET /api/v1/agent/chat/:conversationId/messages` 仅在 `chatKind === "worker"` 且开关开时多一个键：

```json
"chatWorkdir": {
  "kind": "project | workspace | dir",
  "name": "lifediary-harness",
  "path": "D:\\Projects\\projects\\lifediary-harness",
  "projectId": "uuid（仅 kind=project 时）"
}
```

- `project`：`ChatProjects` 有绑定且项目还在（归档项目也返回，名字照常）；
- `workspace`：没绑项目、cwd 是主工作区根（或完全没有 cwd），`name` 固定「工作区」；
- `dir`：只选了目录 / 项目被硬删，`name` 取目录 basename。

纯增量：旧客户端忽略未知键；开关关着时字段不出现，响应回到旧形状。

## 取舍与边界

- **cwd 仍是创建时快照**，本次不放开“中途改归属”。服务端只读 `pi.agent.cwd`，不写库。
- **项目名以服务端当前登记为准**：项目改名后标签跟着新名字；项目归档仍显示名字；项目硬删后落到目录名，不编项目名。
- **有项目绑定但 durable 没有 cwd 的旧会话**：path 回项目主文件夹，不拿 `sessionCwd()` 的「当前项目」顶替（那是运行期回落，不是创建时归属）。
- **`dirPath` / `CHAT_DIR_PICK` 契约保留**：桌面端不再发这个字段，但手机 / 外部 API 仍可用；不删共享 schema、不删服务端分支。
- **开关缺省开**（“做出来的功能默认开”）；hot 生效。

## 明确不做

- 不允许改已落盘会话的项目 / cwd。
- 不给总管 / 执事 / task 专线加这个标签；侧栏按派活人分组不动。
- 不把 task 会话绑到票的 project（要做得另立方案）。
- 不恢复输入框里的选项目菜单（用户的选项目入口回到左侧侧栏）。

## 这条会怎么错

- 左侧当前项目是「归档 / 目录丢失」时，`getCurrentProject()` 返回 null，标签会显示「工作区」，新对话也落工作区——这是服务端的真实落点，不是标签算错。
- 切换侧栏项目发生在发送请求与 `start` 帧之间：标签冻结的是 `start` 到达那一刻的侧栏选择，极端竞态下可能与服务端创建时的选择差一帧；刷新 / 重开会话会按 `pi.agent.cwd` 纠正。
- 老服务端没有 `chatWorkdir`：已落盘会话标签不显示；新建态仍能按侧栏显示（纯前端）。
