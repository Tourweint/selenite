## 二、现状核对（2026-11-12，代码 + 模拟器）

### 2.1 首页与导航

- 首页 `ConversationListScreen`（`feature/chat`）：顶部圆钮行（右对齐 ＋ + 齿轮）→ `LazyColumn`
  装 `conversationListContent`：总管置顶 → 群组 → 执事 → 「最近对话」（默认收起）。
  **没有**「对话 / 群组」小节标题（2026-11-12 用户口径，V3 之后）。
- 抽屉 `HistoryDrawerSheet` 已不挂联系人列表：新建 / 回忆 / 功能组（近期总结、工作区文件、课题）/
  多端 / 底部「⋯」设置。因此用户说的「联系人按钮」是**首页第一行（总管）**，不是抽屉行。
- 全局设置入口现状：首页齿轮 → `openSheet(SettingsNavKey)`；抽屉底部「⋯」→ 同一路径；
  主对话齿轮 → `SessionSettingsSheet`（思考档 / 全局模型 / 权限档 / 审批档 / 全部设置）。

### 2.2 对话页

- 主对话 `ChatScreen`：顶栏由 `MainActivity` 的 `LdTopBar` 统一画，标题恒为空；右上角
  只在 `ChatNavKey` 时给齿轮（本会话设置）。空态 `LdMoonInvite` 居中（月亮 + 轮播邀请语）。
- 执事对话 `PartnerChatScreen`（`feature/settings`）：无顶栏标题、无右上角按钮；思考档是
  composer 上方的一行文字按钮（「思考档 · 本条」）。空态「说第一句吧。」。
- 群聊 `GroupChatScreen`：内容区第一行是 `headlineSmall` 群名；成员消息上方有
  `labelSmall` 的说话者名；空态「说第一句吧。」。群没有右上角设置。
- 身份数据：`PartnerRow(id, name, avatar)`、`PartnerProfile(id, name, status, domain,
  dispatchAuthority, avatar, soulVersion)`、`PartnerDetail(profile, soul, soulVersion)`、
  `GroupMemberInfo(id/name/status/avatar/domain)`；**没有**「口头禅 / 签名」字段。

### 2.3 转场与滚动

- **旧首页「下拉感」的根因（2026-11-12 核对）**：`MainActivity` 里
  `homeOnTop = backStack.lastOrNull() is ConversationListNavKey`，顶部栏高度
  `globalTopBarHeight` 用 `animateDpAsState` 在 `homeOnTop` 时为 0、离开首页后动画到
  `TOP_BAR_CONTENT_HEIGHT`（44dp）。Scaffold 的 content padding 跟着这条高度走，
  所以**压栈进对话时，仍在画面里的旧首页整体被向下推 44dp**（返回时再向上抬 44dp）。
  新对话页自己也在同一条动画里，但它从右侧滑入，位移不易被注意到；旧页面是静止的，
  44dp 的下移就读成「被拉下去」。这不是列表滚动状态的问题。
- 首页列表 `rememberLazyListState()`（saveable）：实测「滚到中段 → 点一段会话 → 返回」位置保持。
- 对话页：`LazyColumn` 初始位置 0；消息加载后 `LaunchedEffect(state.messages.size)` 调
  `scrollToItem(messages.size)`（执事/群同款）。这是「进入后落到最新」的行为，**不是本次
  用户指的下拉问题**；但若消息不是首帧就有，会先看到顶部再跳到末尾，作为顺手修（P2）处理。

## 三、设计

### 3.1 首页与抽屉：只修重叠，不动结构

- 首页顺序保持：总管 → 群组 → 执事 → 最近对话（默认收起）。**不新增「联系人」小节标题**
  （2026-11-12 已拍板：总管上头不需要标注、群组也不需要）。
- 抽屉展开时，首页列表顶部加 **24dp 让位**：`ConversationListScreen` 接一个
  `drawerOpen: Boolean`，用 `animateDpAsState(if (drawerOpen) 24.dp else 0.dp)` 作为
  `LazyColumn` 的 `contentPadding.top`。只影响展开态；收起态版式不变。
  - 备选（弃）：把浮球在展开态往上挪 —— 球必须与内容卡左上角弧同心（2026-11-12 用户口径），
    挪了就破坏同心设计；把首页顶行整个加高 —— 收起态也变，浪费首屏。
- ＋ 保留（用途见 §3.3 与 §七）。

### 3.2 顶栏身份：名字常驻，不再靠猜

- `LdTopBar` 的 `title` 在对话页填身份：
  | 页面 | 标题 | 说明 |
  |---|---|---|
  | 主对话（总管） | `总管` | 今日对话就是总管对话（首页总管行进入） |
  | 执事对话 | 执事名（`PartnerChatNavKey.partnerName`） | 从首页执事行进 |
  | 群聊 | 群名（`GroupChatNavKey.groupName`） | 从首页群组行进 |
  | 普通杂事会话 | 该会话摘要（`RecentChatRow.title`） | 过长省略；无摘要回落「对话」 |
- `LdTopBar` 补一条通用约束：标题 `maxLines = 1` + `TextOverflow.Ellipsis` + 左右各留
  ~72dp 内边距，防止长名字压到返回键 / 右上角按钮。这是组件级修正，全 App 受益。
- **标题不参与滚动淡出**：现有 `chatTopBarAlpha` 会按 `chatScrollDepth` 把标题和返回键一起
  淡出；对话页的标题改为恒 1（返回键/浮球的淡出保留）。理由：用户要的是「一直知道在跟谁聊」。
- 可选副标题（暂不做，登记 §六）：执事 =「执事」、群 =「N 人」。一行标题已够；等真机看过
  再决定要不要第二行（`LdTopBar` 是 44dp 自绘栏，两行会挤）。

### 3.3 右上角：从「全局齿轮」改成「这个联系人/这个群的设置」

**首页**：删掉齿轮，只留 ＋。全局设置仍可从抽屉底部「⋯」进（唯一入口，功能不丢）。

＋ 的行为（2026-11-12 用户拍板：**弹面板二选一**）：
- 点 ＋ → 一个小动作面板（`ModalBottomSheet` 或锚在 ＋ 上的菜单，两行 44dp）；
- 「新对话」= 现有 `chatViewModel.startNewThread()` + `openChatNav()`（新开一段普通杂事会话）；
- 「新建人物」= `openSheet(PartnerEditNavKey(null))`，复用现有执事建档页（名字 / 领域 / 人设 /
  口头禅），建完刷新名册（走 `partnerSavedCount` 先例），新人出现在首页联系人列表。
- 面板里不放「建群」：群目前只能在电脑端建（§2.14 `POST /groups` 端点手机未接），不放假入口。

**主对话（总管）**：右上角图标 `LdSettingsIcon`（齿轮）→ `Icons.Filled.MoreHoriz`（「···」）。
点开仍是现有 `SessionSettingsSheet`，但弹层顶部加身份头：
`LdDataUrlAvatar(总管头像) + 「总管」 + 「本会话设置」`；弹层底部「全部设置」一行撤掉
（全局设置走抽屉，避免「每个页面都能进全局设置」的观感）。

**执事对话**：新增右上角「···」（此前没有），点开**执事设置弹层**：
- 身份头：头像 + 名字 + 领域（`domain` 为空则不显示）+ 状态；
- 「本会话设置」：思考档（现有 `PartnerChatViewModel` 的能力，从 composer 上方那行搬进来）；
- 「编辑档案」：`openSheet(PartnerEditNavKey(partnerId))`（设置纸页里已有建档/改档页）；
- 不做模型切换（执事对话没有全局模型概念，现有能力也没有，不硬加）。

**群聊**：新增右上角「···」，点开**群设置弹层**（v1 只读）：
- 群名 + 成员数；
- 成员列表：名字 + 领域（有则显示）+ 状态点；头像只在这个**列表**里用（列表行有空间），
  不进消息流；
- 群公告（`notice`，契约已有；空则不占行）；
- 改名 / 加人 / 减人 / 删群 **v1 不做**（群端点有 PATCH/DELETE，但手机端低频、误触代价高，
  留到有明确需求再立项）。

**其他页面**：日记本/设置子页等不再新增设置图标；已存在的「未登录态」设置按钮随
去账号化后的死分支处理（`NotebookHome` 的 `onOpenSettings` 只在游客页头；主栈恒
`loggedIn = true`，实际不可达——顺手清掉或保留注释，实施时核对）。

**图标**：统一用 Material `MoreHoriz`（三点），不用齿轮。理由：齿轮在用户心智里 = 全局设置，
与「这个联系人的设置」冲突；QQ/微信的会话右上角也是「···」。

### 3.4 说话人身份：只用文字，不用头像

用户已明确否掉消息流头像（屏幕小）。按「顶栏 + 署名 + 空态」三处建立身份：

1. **顶栏**（§3.2）：常驻名字，回答「我在哪个群聊 / 哪个员工」。
2. **群消息署名**：把现在的 `labelSmall` + `onSurfaceVariant` 提升为
   `labelMedium` + `FontWeight.Medium` + `onSurface`，位置仍在气泡上方（左对齐、距气泡 2dp）。
   - 每条成员消息都显示（包括连续发言），流式期间同样显示 `streamingSpeaker`；
   - 自己的消息不署名（右对齐 + primaryContainer 已能区分）；
   - 不做「按发言人分配多种颜色」：设计令牌里强调色只剩 `secondary`（§6.11），多色会破坏
     主题纪律；也不做首字小徽章（列表里已有首字头像，消息流再加会重复）。
3. **1:1 执事/总管**：消息气泡不加署名（顶栏已经说明是谁）；空态再给一次身份（§3.5），
   进入后的前几秒不会「不知道在跟谁说话」。
4. **群页头搬进顶栏**：删掉 `GroupChatScreen` 内容区第一行的 `headlineSmall` 群名，避免
   「顶栏一个标题、内容区一个标题」重复；成员数挪到群设置弹层。

### 3.5 空态：月亮 → 头像 + 一句常说的话

- **主对话（总管）**：删 `LdMoonInvite`。空态改成：
  `LdDataUrlAvatar(总管头像, fallback「总」, 72dp)` + 名字「总管」+ 一句口头禅
  （`tagline`，见 §四；没有则回落「说吧，我在。」）。
- **执事对话**：头像（`PartnerProfile.avatar`，fallback 名字首字，72dp）+ 名字 +
  口头禅（没有则「我在。」）。
- **群聊**：2×2 成员头像复合（契约 `members[].avatar` 现成，取前 4 位；没头像的成员用首字）
  或群名首字兜底 + 群名 + 「大家都在。」；不冒充某一个员工。
- **普通杂事会话**：没有「人」的身份，不硬塞头像；只留一句「说吧，我在。」（无月亮）。
- **离线/未配置**：沿用现有文案优先级（`transcriptOffline` → 「连上电脑才看得到」；
  `!isConfigured` → 「正在连接服务，稍等一下。」）；这些情况下头像仍显示（本地有就显示）。
- 动画：入场用 `ldSpringReveal`（淡入 + 轻微上浮），**不做**无限呼吸/浮动（月亮那套动效
  去掉，省电、安静）。头像和文字整体作为一块，不逐字轮播。
- 月亮组件 `LdMoonInvite` 只服务这一处；删掉调用后若无人使用，保留组件文件但标注「闲置」
  或删除（实施时二选一，不留在调用链里）。`LdBrandMoon` 继续服务登录/锁屏品牌页，不动。

### 3.6 转场：旧首页不再被顶栏交接「拉下去」（用户点名的 bug）

**根因**（§2.3）：顶栏高度是 Scaffold 的布局输入，不是纯视觉层。离开首页时它从 0 动画到
44dp，旧首页仍在画面里，于是整页被下推 44dp；返回时上抬 44dp。用户看到的「下拉感」是
这条布局动画，不是列表滚动。

**修法（首选：顶栏改覆盖层，内容 padding 不再跟顶栏高度联动）**：

1. `Scaffold` 的 `topBar` 不再占布局位（或高度恒 0），`NavDisplay` 的 padding 只留
   状态栏 + 底部导航栏；
2. 顶栏 `LdTopBar` 作为 `Box` 里的**覆盖层**画在最上层（`align(TopCenter)`），它的高度
   只决定自己画多高，不再推内容；
3. 各页自己让 44dp：
   - 首页 `ConversationListNavKey`：**0**（它本来就有自己的圆钮行，从状态栏下 6dp 起）；
   - 对话/执事/群/速记/深挖/日记本/设置子页等：固定 44dp（用 `pageTopInset` helper 统一包，
     避免十几个 entry 各写一遍）；
   - 日记本 `NotebookNavKey`：保留现有 44→0 的交接动画（它自己的页头接管）；
4. 效果：压栈进对话时，首页的 padding 不变、位置不动；顶栏覆盖层从「无」变成「返回 +
   标题 + ···」，盖住首页顶部那条圆钮行（被新页盖住是应该的），但**首页不再下移**。
   返回时顶栏覆盖层撤掉，首页原样露出。

**备选（最小改动，不推荐）**：保留 Scaffold 的 topBar 槽，给首页 entry 加
`Modifier.offset(y = -globalTopBarHeight)` 抵消下推。问题：offset 不增加测量高度，首页
列表底部会空出 44dp（滚到底时最后一行提前截止），除非再写自定义 layout 补高——比覆盖层
方案更 hack。

**顺带修（P2，不改行为）**：对话页进入时首帧就落在最后一条，不再「先画顶部再
`scrollToItem`」：
- 主对话：消息就绪后才组合 `LazyColumn`，`rememberLazyListState(initialFirstVisibleItemIndex =
  maxOf(0, messages.lastIndex))`；或消息到达时先 `requestScrollToItem` 再首帧。
- 执事/群：同款；群聊的上翻拼页锚定逻辑（`earlierPrepended`）原样保留。
- 流式跟随仍走现有 `LdStreamPin`（钉住才跟、用户上滚不抢视口），不改。
- 首页列表返回位置保持（已实测）；补一条回归清单，防后续改动破坏。
- **不**改成「进对话停在顶部/上次位置」：用户已澄清是转场下拉，不是这个语义。

## 四、契约：执事口头禅 `tagline`（批 B，纯增量）

### 4.1 为什么必须新增字段

- `soul` 是长文（≤64KB 的人设），不能截一句当口头禅（可能是指令、可能很长、可能泄隐私）；
- `currentGoal` 是「当前目标」，不是「常说的话」；
- 首次打开执事专线的 `greeting` 是模型生成的一条消息（可能很长、会落历史），不是稳定签名；
- 手机端硬编码几句「员工常用语」是假拟人，用户一眼能看出是模板。

### 4.2 形状（照 `currentGoal` 的先例，2026-11-08 刀二 E4）

- `tagline?: string | null`，**≤40 字**（中文按字计），trim；省略 = 不改；`null` / 空串 = 清除；
- **不版本化**：不是身份（不 bump `partner_versions`、不动 SOUL / 契约），现取现用；
- 落点：`partners` 表加 `tagline TEXT`（旧库 `PRAGMA` + `ALTER TABLE`，老行读 `null`）；
- 端点：
  - `PATCH /api/v1/partners/:id` 支持 `tagline`（与 name/status/avatar/currentGoal 同批校验，
    任一不合法整批 400、全不写）；
  - `GET /api/v1/partners`（列表）与 `GET /api/v1/partners/:id`（详情）投影都带 `tagline`。
    列表带出来是为了首页/空态**零额外请求**；桌面/手机老客户端忽略未知字段，纯增量。
- shared：`PartnerSummarySchema` / `PartnerDetailSchema` 加可选 `tagline`；接口文档 §2.11 补一行
  （文案、上限、清除语义、投影位置），§7 的顺序照旧：先 shared + 接口文档，再两端实现。
- 开关：无 env（纯数据字段，空 = 不显示，天然回滚）；不需要进 `WRITE_TOOLS`（不是工具）。

### 4.3 编辑入口

- 手机 `PartnerEditScreen`（建档/改档页）加一栏「口头禅（可选）」：单行、≤40 字、空 = 不设；
  创建（`POST /partners`）与保存（`PATCH`）都带上。这样用户能在手机里给员工写一句话。
- 桌面端不在本批范围；服务端字段先落，桌面后续按需接（不阻塞手机显示）。

### 4.4 回落规则（没有 tagline 时）

| 场景 | 文案 |
|---|---|
| 总管空态 | 「说吧，我在。」 |
| 执事空态 | 「我在。」 |
| 群聊空态 | 「大家都在。」 |
| 普通杂事会话 | 「说吧，我在。」 |

不做 AI 自动生成口头禅（不稳定、每次不同、还会漏隐私）；不做多句轮播。
