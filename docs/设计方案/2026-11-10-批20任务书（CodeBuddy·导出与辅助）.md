## 一、导出升级"接续文件"形态（五 §八#2）

1.1 现有会话导出（若有）升级为**接续文件**：一份 markdown，包含
   - 角色说明（"你是 X，这是和主人的历史"）；
   - **读取说明**（"这份文件可以直接粘给任何 AI 继续聊"）；
   - 记忆摘要（该 scope 的 preference + experience，最多 20 条）；
   - 最近 N 轮原文（默认 30 轮，`limit` 可调）。
1.2 新端点 `GET /api/v1/agent/chat/:conversationId/export?format=handoff&limit=30`。
1.3 **"状态如实"三条口径**写进接口文档：
   - 部分可读要标注原因，不冒充完整；
   - 导出成功 ≠ 对方已接收；
   - 默认不保存正文（导出的是一次性文件，不落盘到服务端）。
1.4 开关 `CHAT_EXPORT_HANDOFF`（默认 true）。

## 二、auxiliary LLM 一等化（七 #32）

2.1 现状：偏好抽取已经用"独立模型调用"，但是散的。
2.2 新增 `ts/apps/server/src/auxiliary.ts`：统一配置**杂活模型**：
   - 用途枚举：`title`（会话标题）/ `compact`（压缩）/ `review`（裁判）/ `extract`（偏好抽取）；
   - 每个用途可以 pin 一个模型（`AUX_MODEL_<USE>`，如 `AUX_MODEL_TITLE=deepseek-v4.1-flash`）；
   - 没配就回落到当前会话模型（行为不变）。
2.3 **本批只接两个**：`extract`（把现有的偏好抽取接进来）与 `title`（如果已有自动标题就接，没有就跳过）。
   其余用途留接口，**不接线**。
2.4 开关 `AUX_LLM`（默认 true；false → 全部回落当前模型，行为回到今天）。

## 三、eval tune/holdout 双池（七 #34）

3.1 新增 `ts/apps/server/src/eval-pool.ts`：给**纯判定函数**建小型回归集：
   - 池子里每条 = `{ id, input, expected, pool: "tune" | "holdout" }`；
   - 先给**两个函数**建集：`needsApproval()`（审批判定）与 `resolveUnattendedVerdict()`（无人值守三态）；
   - 每个函数 10-15 条，tune/holdout 各半。
3.2 单测跑两池，断言全过；**holdout 池只在发布前跑**（本批都跑，但代码里标清楚用途）。
3.3 这是**测试资产**，不是运行时功能，不加开关。

## 四、旧会话定点找回（六 §七#6 的后端一半）

4.1 现状：`recall_sessions`（批 11）能跨会话检索，但只能看 snippet。
4.2 新增只读端点 `GET /api/v1/agent/chat/:conversationId/context?aroundSeq=<n>&radius=5`：
   返回该会话第 n 条消息前后各 radius 条（含角色与时间），用于"从旧会话定点找回"。
4.3 **不做界面**（界面是后续批次），**不做 fork**（内核有面但没接，本批不碰）。
4.4 开关 `CHAT_CONTEXT_LOOKUP`（默认 true）。

## 附：前置勘察结论（2026-11-10 已核实，与任务书正文有出入时**以本节为准**）

1. **目前没有会话导出端点**（正文 §1.1 写"现有导出升级"是假设，实际不存在）。
   → 所以 §一 是**新建**端点，不是升级。新建时顺带把"状态如实"三条口径写进接口文档。
2. **偏好抽取的模型调用**在 `memory-extract.ts`，用的是 `readLlmConfig()` + `currentModels()` 拿当前会话模型。
   → §二 的 `extract` 接线点就是这里：把"当前模型"换成 `auxiliaryModel("extract")`，没配则回落。
3. **transcript 没有 `seq` 字段**（`agent/session.ts` 里搜不到 seq 相关实现）。
   → §四 的 `aroundSeq` 不可行。**改用 `aroundIndex`**（按消息数组下标，从 0 开始），
   端点签名改为 `GET /api/v1/agent/chat/:conversationId/context?aroundIndex=<n>&radius=5`，
   并在返回里带上 `total` 让人知道边界。**不要**为了这个去改内核加 seq。
4. **消息读取**：`GET /api/v1/agent/chat/:conversationId/messages?limit=&sinceSeq=` 已有（接口文档 §2.2）。
   → §一 的导出可以直接复用它的读取路径，不要另写一套 transcript 读取。
