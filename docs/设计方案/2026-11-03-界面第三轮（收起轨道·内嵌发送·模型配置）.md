## 一、调研：cindy 是怎么做的

> 审计日期：2026-11-03。调研对象 `<reference>\cindy`
> （Electron + React 19 + Tailwind + Tiptap，pnpm monorepo）。要点：

**侧栏是三态，不是二态**：完全隐藏 0（toggle/⌘B）→ 拖到 120px 以下触发**图标轨道 78px**
→ 展开（180~480px 可拖）。轨道内容自上而下：**「+ 新对话」圆钮在最顶**（36px 圆形，
纯图标 + 右侧 tooltip）→ 按用户自定义顺序的导航图标 + 「更多」菜单 → 伙伴入口 → 分隔线
→ 历史分组瓷砖（置顶会话平铺，hover 出预览卡）。底部是头像（点开出菜单，设置在菜单里）。
动画：外层 `width` 过渡 250ms + 内容层**定宽不重排**、200ms 渐隐——
这套「定宽内容 + 原地淡出」我们 2026-11-03 已经抄过来了，收起目标宽度从 0 改成轨道宽即可复用。

**Composer 是一个容器卡**：圆角 12px、1px 边框、focus-within 换焦点边框色、min-h 86px /
max-h 300px；textarea 在容器内**透明无框**；容器底部一条工具行，右下角是 **28px 圆形发送钮
（发送/停止同槽替换**，流式时图标换成 10px 圆角方块），左侧依次是模型 pill（30px 高、
裸态无框 hover 才有边框，点击向上弹模型面板，**每会话记忆所选模型**）、语音、附件。
设置页另有 providers 整页（供应商列表 + baseUrl + API key + 逐模型启停）。

**取舍判断**：cindy 的三态轨道靠"拖拽调宽"触发，我们根本没有拖拽调宽功能；
我们的收起只有 toggle 一个动作 → **二态即可**（展开 232px / 收起轨道 60px），不引入拖拽。
78px 是给 macOS 红绿灯让位的，我们标题栏全局自绘，不需要。

## 二、方案一：侧栏收起轨道

### 现状

`html[data-sidebar="closed"] .sidebar { width: 0 }` ——收起即整栏消失。
《2026-11-03-首页顶栏与浮层》"明确没做"里写着：没做图标 rail，因为当时侧栏没有图标导航。
现在有了理由：任务中心、领域负责人、群组都是跨对话的常驻入口，收起后仍要可达。

### 目标形态

```
展开（232px）                    收起（60px 轨道）
┌──────────────┐                ┌────┐
│ 对话          │                │ ＋ │ ← 新对话（真功能）
│ ＋ 新对话     │                ├────┤
│ [任务中心 3]  │                │ 📋 │ ← 任务中心（占位→等 #/tasks 落地转真）
│ 对话列表…     │                │ 🎓 │ ← 专家/领域负责人（占位，禁用）
│              │                │ 👥 │ ← 群组（占位，禁用）
│ ⚙ 设置       │                ├────┤
│ ● 连接中      │                │ ⚙  │ ← 设置（真功能）
└──────────────┘                │ ●  │ ← 状态点
                                └────┘
```

| 项 | 决定 | 理由 |
|---|---|---|
| 轨道宽 | `--rail: 60px`，新变量 | cindy 78px 是 mac 红绿灯；我们用不到。60 = 36px 钮 + 两侧 12px 呼吸位 |
| 按钮 | 36px 圆钮，纯图标 + `title` tooltip | 对齐 cindy 的 `SidebarIconButton`；我们无框架，原生 `title` 够用 |
| 「+」在最顶 | 收起态置顶，点击 = 直接新建对话并展开侧栏 | cindy 同位；新建是高频动作 |
| 任务中心 | 占位：真图标，点击提示「任务中心还没建好」 | 《宰相层》§5.9 已定侧栏常驻项 + 进行中数徽标；落地后占位转真，轨道上补数字徽标 |
| 专家 / 群组 | 占位：禁用态（半透明），tooltip 写「占位」 | 用户明确"先占位"；**不装能点**（同"mock 不许空转"的纪律） |
| 设置 + 状态点 | 底部真功能 | 侧栏底部设置入口是现状（《自绘标题栏》补记），收起后仍可达——顺带修掉它记的已知限制（"收起时设置入口不可达"） |
| 动画 | 沿用「外层 width 过渡 + 内层定宽原地淡出」，收起目标从 0 改 `--rail` | 机制 2026-11-03 已验证稳定，只改目标值 |
| 持久化 | 沿用 `localStorage["lifediary.sidebar"]`，`"closed"` 语义 = 轨道 | 键不变，语义收窄；无迁移成本 |
| 顶栏功能菜单 | 保留「新对话」不动 | 轨道已保证可达性，菜单留着不碍事 |
| 窄窗口 ≤800px | 维持整栏隐藏，不出轨道 | 现状如此，小屏塞轨道没收益 |

### 备选（不取）

- **cindy 三态（拖拽阈值进轨道）**：我们没有拖拽调宽，加它就是为抄而抄。
- **hover 展开侧栏**：cindy 也没有（hover 只弹面板）；轨道 hover 展开会让列表闪来闪去。

## 三、方案二：发送按钮内嵌输入框

### 现状

`.composer` 是 flex 行：textarea 自己带卡底、边框、圆角（`--r-lg`/首页 `--r-xl`），
`.send` 是 48px 的兄弟元素——**按钮在框外**。发送键成为视觉上第二个块。

### 目标形态（对齐 cindy ComposerCard）

一个容器卡，发送钮住进去：

```
┌────────────────────────────────────┐
│  说点什么…                          │   ← textarea 透明无框，只在容器上有边框/卡底
│                                    │      focus-within 时容器边框换 accent
│                        [ ↑ ]       │   ← 32px 圆钮，accent-container 底（第四轮口径）
└────────────────────────────────────┘      流式时同槽换「停止」方块图标
```

| 项 | 决定 | 理由 |
|---|---|---|
| 容器 | 现有 textarea 的边框/卡底/圆角/阴影**整体上移到 `.composer`**；textarea 改透明无框 | 一次搬家，而不是叠两层卡 |
| 发送钮 | 48px 缩到 **32px** 圆钮（`--r-full`），底部行右对齐；disabled 保持 opacity .45 | cindy 28px 配 15px 字号，我们的输入框更高（首页 128px），32px 视觉平衡 |
| 停止态 | **同槽替换**：流式时发送钮位置换成停止方块（cindy SendButton 做法），顶栏的 `.ghost #stop` 移除 | 两个停止入口必然不一致；cindy 验证过同槽手感 |
| 布局 | `.composer` 改纵向 flex：textarea 一行 + 底部控制行（只放发送钮，右对齐） | 留出左半边位置——以后模型 pill、附件有地方去（本轮不实现） |
| 首页态 | min-height 128、`--r-xl`、竖屏居中全保留；只是边框从 textarea 挪到容器 | 《首页顶栏与浮层》定的层级不动 |
| 键盘 | Enter / Ctrl+Enter 设置项不变 | 已有，别碰 |
| 工具行左边 | **本轮空着** | 附件、语音、权限选择器在 cindy 有，我们没有对应后端能力，加了就是空转 |

### 备选（不取）

- **绝对定位按钮浮在 textarea 右下**：长文换行时按钮压字，还得给 textarea 留 padding-right；
  工具行方案天然避坑，且是 cindy 实测结构。

## 四、方案三：设置页模型配置（服务分区升级）

### 现状

服务分区四行：地址 / **模型（只显示"真实上游/未配置 mock"，连模型名都没有）** / 鉴权 / 累计 token。
模型 = `LLM_MODEL` 环境变量，运行中不可换。

### 目标

服务分区的「模型」行升级为可配置：显示当前模型名 + 可选清单下拉；切换即生效。

**语义（先定死，后端照此落）：**

| 项 | 决定 |
|---|---|
| 切换范围 | **全局运行时覆盖**：改完下一轮对话就用新模型，进行中会话也切 |
| 存储覆盖值 | `.data/runtime.json`（与 `chat-meta.json` 同思路：不动内核的表，升级不痛）。env `LLM_MODEL` 始终是"出厂默认"；删掉文件即回默认 |
| 读取点 | `openai-compat.ts` 的 `upstreamConfig()`（现在每次调用都读 env，改为"env 默认 + 覆盖值"）——**后端会话的活** |
| 清单来源 | env `LLM_MODELS`（逗号分隔，新增，§6 登记）；没配 = 清单只有当前模型，选择器退化成只读行。**不让前端自由填写**——填一个上游没有的模型名只会 500，装能切不如不切 |
| 契约 | `GET /healthz` 扩展为 `{ ok, llm, model, models[] }`（`models` 缺省 `[model]`，向后兼容，前端已在消费 /healthz）；新增 `POST /api/v1/agent/model { model }`，值不在清单内 → 400 带说明 |
| 回滚开关 | `MODEL_RUNTIME_OVERRIDE=false`：POST 一律拒绝（400），前端探测到后隐藏选择器——回到纯 env 行为 |
| 缓存提示 | 切换成功后 UI 提示一次「切换后首轮回复会慢一些（上游前缀缓存重建）」 | 

**与既有设计的关系（都核对过，不冲突）：**

- **D1（快/深同款模型）**：D1 防的是"快/深两档各配一个模型、每轮切换把上游缓存反复清零"。
  本方案的切换是低频的用户显式动作，清一次缓存可接受；快/深两档**仍然共用当前模型**，只走 `enable_thinking`。
- **思考档（快/深）**：逻辑不依赖具体模型 id，不用改。
- **faux/mock**：`LLM_PROVIDER=faux` 时 POST /api/v1/agent/model 返回 400（假模型没有真模型可切）；
  mock（无 key）同理。UI 在这两种状态下显示"mock 流，无模型可切"。

**密钥与上游地址：刻意不做 UI 配置。** cindy 的 providers 页有 baseUrl + API key 表单，**照搬会违反
AGENTS.md 硬约束「密钥只走环境变量，不入库、不下发客户端、不进日志」**。换上游 = 改 `.env` 重启，保持现状。
这是"抄 cindy"的边界，写进「明确不做」。

### cindy 基础设置对照（哪些抄、哪些不抄）

> cindy 设置页 19 个分区（通用/外观/个性化/模型供应商/用量/语音/IM 机器人/快捷键/…）。
> 逐项判断（审计日期 2026-11-03）：

| cindy 有 | 抄不抄 | 理由 |
|---|---|---|
| 模型配置（providers 页） | **抄一部分**：模型名可切；供应商/baseUrl/key 表单不抄 | 密钥硬约束；单上游架构 |
| 发送快捷键切换 | 已有 | 《界面第二轮》第六轮补的 |
| 主题三选 + 主题色 | 已有 | 且已换回自家色板 |
| 会话搜索/恢复 | 已有 | |
| **界面字号滑杆** | 备选，本轮不做 | 有真实价值（信息密度），但不在这轮三个诉求里，单独立项 |

## 六、验收

1. 收起：出 60px 轨道；「+」可新建对话；专家/群组为禁用占位、tooltip 可读；设置与状态点可达；刷新后保持收起。
2. 展开：与现状一致（232px、列表、搜索位置不变）；开/关动画无文字重排。
3. composer：发送钮在容器内右下；容器 focus-within 换边框色；流式时同槽变停止、顶栏无停止钮；Enter/Ctrl+Enter 行为与设置一致；首页态 128px 保留。
4. 设置-服务：无 `LLM_MODELS` 时模型行为只读；配了清单 + 覆盖开关开 → 可切、切换后下一轮真用新模型（faux 下验证链路）、有缓存提示；`MODEL_RUNTIME_OVERRIDE=false` 时选择器消失。
5. `pnpm typecheck`；`node --check ts/apps/server/web/app.js`；浏览器（含 MyGo 壳）实测 1–4。

## 七、明确不做（本轮）

- 拖拽调宽、三态侧栏、hover 展开。
- 附件 / 语音 / composer 左侧工具行内容（无后端能力，不做空壳）。
- API key / baseUrl / 供应商管理 UI（密钥硬约束）。
- 每会话模型记忆、composer 模型 pill（等后端会话的会话契约稳定后另行立项）。
- 语言切换、通知、IM 机器人、用量计费（无对应能力）。
- 界面字号滑杆（有价值的备选，单独立项，不搭车）。
- 后端代码任何改动（本文档零代码；契约归属后端会话）。

## 八、这条会怎么错

1. **占位图标装能点** → 用户以为功能坏了；占位必须禁用态 + tooltip 写明占位。
2. **容器卡搬家漏了首页态** → 首页输入框双框（textarea 旧边框没摘干净）；验收 3 专门看首页。
3. **切换模型没校验清单** → 填错名 500，用户以为服务坏了；POST 校验 + 前端只出清单项。
4. **覆盖值写进内核的表** → 升级痛；放 `.data/runtime.json`，同 `chat-meta.json` 先例。
5. **快/深也跟着各自配模型** → 重新踩 D1 的缓存坑；快/深永远共用当前模型。
6. **和前端会话同时写 `web/`** → 冲突；按「〇、分工」的窗口建议执行，改动按区块小步提交。
