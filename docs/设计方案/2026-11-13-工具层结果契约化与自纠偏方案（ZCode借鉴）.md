# 工具层结果契约化与自纠偏方案（ZCode 借鉴）

- 日期：2026-11-13（同日修订：结果契约改为「外挂式、按执事/会话开关挂载」，见 §5）
- 状态：已落地（工具结果契约化 2026-11-13）；「自纠偏」半段没做就是没做（截至 2026-11-23 全量审计未见落地）。冲突以长期文档为准
- 前置：`docs/设计方案/2026-11-13-ZCode代码能力调研（为何强·可借鉴点）.md`（必读）
- 关键现状核实（2026-11-13，以 node_modules `@earendil-works/pi-durable@1.4.0` 实读为准）：
  - `read` / `write` / `edit` / `bash` / `powershell` 不在我们仓库，来自内核 `CodingTools`
    （`agent/lifecycle-harness.ts:424` `registry.install(CodingTools)`）；
  - **内核已做**：bash/powershell 输出尾部保留 + 超限溢出落盘给 `fullOutputPath`；非零退出标 isError
    带 exitCode；read 截断续读；edit 已有 **exact→fuzzy（trimEnd + NFKC）匹配阶梯**、行尾/BOM 保留、
    全部 edits 先验证后应用（`edit-diff.ts` `findMatch`）；
  - **内核没有**：失败头尾双保留、语义型非零退出豁免（grep/diff/test 一律 isError）、中断稳定标记、
    stale read 检测。

## 1. 总判断

四个方向里，**方向 3（编辑原子性）基本不用做**——内核已实现 ZCode 调研里最值钱的部分；缺的
stale read 检测在内核层，不 fork 就不抄（登记进"已知边界"）。方向 1 不是"从零建契约"，是**在内核
已有溢出/退出码机制上补三小块**。真正全新的是方向 4。

改法总原则：**不 fork 内核、不发上游 PR（本轮）**。内核五件的结果投影在我们仓库做**包装层**；
且按用户定稿口径（§5），包装层是**外挂式策略层**——内嵌一份实现，按会话/执事开关决定是否生效，
不是全局强制。

## 2. 批次（按性价比排序）

### 批次一：bash/powershell 语义退出码 + 中断标记（最高性价比）

**改哪里**：`ts/apps/server/src/` 新建 `tool-projection.ts`（投影逻辑 + 挂载开关判定，见 §5），
包装内核 bash/powershell；`agent/lifecycle-harness.ts` 安装处换包装版。单文件纯函数 + 单测，不动内核。

**做什么**：
1. **语义退出码白名单**：非零退出但命令是 `grep`/`rg`（无匹配）、`diff`（有差异）、`test`/`[`（条件为假）
   → 不标 isError，输出尾追加 `exit 1（语义型退出：无匹配/有差异/条件为假，不是错误）`。
   判定只看命令首词（含 `command -v` 后首词），解析不准就当普通失败，宁可保守。
2. **中断稳定标记**：timeout/abort 的 error 文本统一追加
   `<error>Command was aborted before completion</error>`。
3. 失败大输出**不做**头尾双保留：内核已落盘全量输出，增量是在 isError 的 hint 里写
   "完整输出在 <path>，用 read 续看"——一行 hint 达到 ZCode 头尾保留 90% 效果，零风险。

**验收**（单测 `tool-projection.test.ts`，纯函数）：
① `grep foo f.txt` exit 1 → 不 isError、有语义行；② `diff a b` / `test -d x` exit 1 → 同上；
③ `node bad.js` exit 1 → 仍 isError；④ timeout → error 含 `<error>Command was aborted…</error>`；
⑤ isError 且有 spillPath → hint 含路径；⑥ 开关关（§5 判定为不挂载）时返回原结果逐字节不变。
探针：`pnpm --filter @lifediary/server http`。

### 批次二：delegation 失败回执带可续接子会话 id（全新能力，第二性价比）

**改哪里**：`delegation-receipts.ts` + `delegation.ts`（失败回执构造）+ 读取方（审批待办 / 任务中心近况落盘口径）。

**做什么**：worker/子单失败时，回执（`DelegationReport` 失败分支）追加
`resume: { conversationId, partialReport }`（子会话 uuid + 部分报告）。对应 ZCode 教训（调研 §1.4）：
父模型拿不到 agentId，跑几十步的子代理无法续接。要点学它：**交接信息（给模型）与错误对象（给系统）分离**，
UI/事件流不多字段。

**验收**：单测：失败单有 resume.id 且为 uuid；成功单无；resume.id 能被 `GET /api/v1/tickets/:id` 查到；
回执 JSON 旧字段只增不改（手机端零改动）。探针 `... tasks` 重跑。

### 批次三：自纠偏对齐（失败不 skip + 撞上限前提示）

**改哪里**：`agent.ts` / `agent/turn-gate.ts` / `loop-guard.ts` 审计 + 小改；`tool-result.ts` 迁移收尾。

1. **审计"前序失败即跳过"**：核对 durable executor 与 turn-gate 是否有"某工具失败后跳过同轮后续调用"；
   有则对齐"错误原文回模型、后续由各自权限决定"。预期内核已如此，**没查出问题就不改代码**，
   审计结论写变更记录。
2. **撞上限前提示**：`AGENT_MAX_TURNS=100` 保留；剩最后 5 轮时 turn-gate 注入一行模型可见提示
   "即将到达轮次上限，请收尾并汇报"。
3. **tool-result 收尾**：未迁的 4 个工具（`remember`/`set_reminder`/`persona_recall`/`send_to_agent`）
   迁 `ToolResult` 形状（批 16 既定路线），失败路径统一带 `hint`。

**验收**：单测：第 96 轮起含收尾提示、≤95 轮不含；`AGENT_MAX_TURNS` env 仍生效；4 工具成功/失败形状断言；
`pnpm typecheck` + `pnpm probe`。

### 方向 3（编辑原子性）：不做代码，只做登记

内核已覆盖匹配阶梯、先验证后写入、行尾/BOM 保留。缺的 stale read 检测与原编码（GBK）回写是内核层能力——
登记进 `系统架构.md`"已知边界"；将来真被 stale read 咬了再立"上游 PR 或仓库内 read 状态记录"专项。

## 3. 明确不做

- 不 fork / 不 patch node_modules 内核、不发上游 PR（真需动内核语义时单独立项"升级 pi-durable"）。
- 不抄"无全局 tool call 上限"：`AGENT_MAX_TURNS=100` 是无人值守硬保险，保留。
- 不做头尾双保留截断器：内核溢出落盘 + hint 已够，自造截断器是第二份事实源。
- 不做 formal-proof / session-control 合同包 / 1000 测试密度（调研已判体量不符）。
- 不做 stale read 检测、多文件 patch、原编码回写（内核层，登记为已知边界）。
- 不改已迁 `ToolResult` 工具的形状与文案（批次三只收尾未迁的 4 个，口径照批 16 注释）。
- **不做两套工具注册表**（§5 定稿）：不建"裸 CodingTools / 包装 CodingTools"两份清单，只有一份实现。

## 4. 顺序与依赖

批次一与批次三互不触碰（一批在工具包装层、一批在 turn-gate/契约层）可并行；批次二独立。
建议派工顺序：**批次一 → 批次二 → 批次三**，一批一验，验收员对照本文验收标准逐条过。
落地后：机制下沉 `系统架构.md`，批次二回执形状属对外契约则同步 `接口文档.md`，变更记 `docs/变更记录/`。

## 5. 修订：外挂式挂载（2026-11-13 用户定稿，并入批次一）

用户口径：这套结果契约**不做全局强制**，做成按角色/执事可选挂载的策略层，像插件一样谁开谁生效。
已接受的取舍：**内嵌一份实现 + 按会话/执事开关挂载**，不做两套独立代码路径。

### 5.1 挂载点（在哪生效）

- **注册表层只装一份**：`lifecycle-harness.ts` 安装的 bash/powershell 永远是包装版（单一代码路径）。
- **执行层判定**：包装器在 `execute` 入口先问 `projectionEnabledFor(conversationId)`——
  开 → 走投影逻辑（改写 isError/追加标记/hint）；关 → **直接透传内核原结果**，逐字节不变
  （验收标准 ⑥）。工具 schema、描述、注册顺序一律不动（保 prompt cache 前缀稳定，工具清单两种
  会话下完全一致，只是结果投影不同）。
- 判定函数与 `path-guard.ts` 同风格：纯函数入参（conversationId、执事行、env 总开关），
  单测直接断言，不读全局状态以外的环境。

### 5.2 开关怎么存（对齐 partners 表既有模式）

- **新增列** `partners.tool_projection INTEGER`（可空），照 `dispatch_authority` 的既有先例
  （`partner-store.ts:139-141`）：启动时 `ALTER TABLE partners ADD COLUMN tool_projection INTEGER`
  缺列迁移；`setToolProjection(id, enabled|null)` setter；`companion-api.ts` PATCH
  （`body.tool_projection !== undefined` 才动，`null` = 恢复跟随默认）+ projection 字段透出；
  执事管理界面加一行开关（与派发权开关同位置同模式）。
- **三态语义**：`null` = 跟随默认（5.3）；`1` = 强制开；`0` = 强制关。执事独立粒度，
  界面可切——与派发权开关（`setDispatchAuthority`）完全同构。
- Worker / 验收子会话（delegation-judge 起 read-only 子会话等）没有 partners 行，
  跟随 5.3 的默认判定，不落库。

### 5.3 默认值

- **默认开**：执行代码活的会话——有 `domain` 的执事会话、worker/子单会话、验收子会话。
- **默认不开**：主人会话、聊天型伙伴（无 domain 的执事/伙伴）。
- 一句话：**干活的默认享受更好的结果契约，聊天的默认零变化**；任何默认都可被执事级三态覆盖。

### 5.4 回滚开关（三层，从小到大）

1. 执事级三态（`tool_projection` 列）：单个执事强制关。
2. `TOOL_PROJECTION=false`：判定函数恒 false，全部会话透传原结果——等于本次能力整体下线，一行回滚
   （硬约束：新能力给回滚开关）。
3. git revert 批次一 commit：注册表回到裸 CodingTools。

**修订带来的验收补充**：⑦ 主人会话跑 `grep` exit 1 → 结果与裸内核逐字节相同（默认不开）；
⑧ 有 domain 执事会话同命令 → 不 isError；⑨ `PATCH /companions/:id` 设 `tool_projection: 0` 后
该执事会话逐字节透传、设 `1` 后聊天伙伴也开；⑩ `TOOL_PROJECTION=false` 时 ⑧⑨ 全部回到透传。
