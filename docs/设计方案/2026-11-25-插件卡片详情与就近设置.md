## 1. 一句话结论

卡片放大、说明全文直出没有争议；真正要你拍板的是三件事：
**(a) 设置区放多少**（内联控件 vs 只给「去 XX 设置」的入口）、
**(b) `AGENT_TOOL_POLICY` 和权限页是两处入口两层存储**、
**(c) 会话页那 6 项要不要回到插件页**。三版对比稿就是给 (a) 试版式的。

## 4. 父子图体检

- 环：没有。
- 悬空父（requires 指向清单里不存在的键）：没有。
- 冗余边（直接父同时是经另一个父 reachable 的祖先）：MEMORY_INJECT_DEDUPE → MEMORY_ENABLED、MEMORY_PROACTIVE → MEMORY_ENABLED、MEMORY_IMPORT_SOURCES → MEMORY_ENABLED。
- 隐形父（代码里依赖、requires 里没写）：REMINDER_DISTILL_ENABLED → MEMORY_ENABLED（reminder-advice.ts:296）。
- 多父项：`MINISTER_DISPATCH_AUTHORITY`（COMPANIONS_ENABLED + CHANCELLOR_ENABLED）、`PARTNER_WORK_RECORD`（MEMORY_ENABLED + COMPANIONS_ENABLED）、`MEMORY_INJECT_DEDUPE`（MEMORY_ENABLED + PARTNER_MEMORY_RECALL）、`MEMORY_NIGHTLY_SPLIT`（MEMORY_NIGHTLY_REVIEW + MEMORY_SPLIT）、`PARTNER_LEARNING_FREQUENCY`（MEMORY_ENABLED + PARTNER_PERSONA_MODULES）、`MEMORY_PROACTIVE`（MEMORY_ENABLED + PARTNER_MEMORY_RECALL）、`MEMORY_IMPORT_SOURCES`（MEMORY_ENABLED + MEMORY_IMPORT）、`AGENT_VERIFIED_ANSWER`（MEMORY_ENABLED + AGENT_ASK_USER）。
- 有子插件的项（按子数降序）：`MEMORY_ENABLED` 12、`COMPANIONS_ENABLED` 12、`CHANCELLOR_ENABLED` 9、`CURRENT_PROJECT` 3、`AGENT_COMPACT_ENABLED` 3、`PARTNER_MEMORY_RECALL` 2、`PERSONA_MEMORY_ENABLED` 1、`SKILLS_ADMIN` 1、`TOOL_PROJECTION` 1、`AGENT_ASK_USER` 1、`ARCHIVE_AUTO_ENABLED` 1、`MEMORY_NIGHTLY_REVIEW` 1、`PARTNER_PERSONA_MODULES` 1、`GOAL_MODE` 1、`CHAT_CONTEXT_INSPECT` 1、`MEMORY_SPLIT` 1、`MEMORY_IMPORT` 1。

需要单独说的几条：

1. **三棵大树**：`MEMORY_ENABLED` 12 个直接子、`COMPANIONS_ENABLED` 12 个、`CHANCELLOR_ENABLED` 9 个。
   关这三个里的任何一个，都会连带一片——卡片上的「被依赖」chips 对这三张最有价值，对 34 张无父无子的卡是两个「无」字。
2. **两个「大总闸」必须重启**（`hot: false`）：`COMPANIONS_ENABLED`、`CHANCELLOR_ENABLED`。
   `CHANCELLOR_ENABLED` 在代码里是进程内常量（`agent/assist.ts:39`、`lifecycle-harness.ts:533,592`），所以关掉后界面显示关了、实际没变，要等重启。
   卡面必须把「重启后生效」放在显眼位置，不能只留在详情里。
3. **冗余边**（直接父已经被另一个父间接带上）：见上面清单。不建议改清单——改 `requires` 是契约变动，要走方案；
   但卡面上**不用重复画**，画直接父即可。
4. **隐形父**：`REMINDER_DISTILL_ENABLED` 在代码里依赖 `MEMORY_ENABLED`（记忆没开时采纳端点回 404，`reminder-advice.ts:296`），
   但 `requires` 里没写。所以记忆总闸关着时，这张卡**不会**显示「被父关」。
   修法是把它加进 `requires`（属于契约改动，本方案不含，建议单独立项）。
5. **两级总闸会盖住自己存的值**：`MEMORY_NIGHTLY_SPLIT` 同时挂 `MEMORY_NIGHTLY_REVIEW` 和 `MEMORY_SPLIT`，
   `MEMORY_IMPORT_SOURCES` 同时挂 `MEMORY_ENABLED` 和 `MEMORY_IMPORT`。卡上写「被 X 关闭」时 X 取服务端 `lockedBy`（第一个关着的父），
   和后端口径一致。

## 5. 卡片 v2 的信息设计

每张卡六块，从上到下：

| 块 | 内容 | 规则 |
|---|---|---|
| ① 头部 | 中文名 + `KEY`（mono 小字）+ 组名 + 状态徽标 | 徽标四选一：**开 / 关 / 被父关 / 常开**。原有「系统核心」「默认关」「待重启」「已改」照旧保留 |
| ② 完整说明 | `summary` 全文 | 不截断、不取第一句。卡可以高 |
| ③ 元信息 | 类型 / 当前 / 默认 / 生效 / 存储 | 「生效」两种：改完即时生效、**重启服务后生效**（有待重启改动时追加「待重启」）。「存储」三种：flag 覆盖、环境变量、没存覆盖走默认 |
| ④ 依赖区 | 「前置」chips + 「被依赖」chips + 被锁提示 | 前置 chip 显示名字 + 当前开 / 关；被依赖 chip 显示名字 + 开 / 关。都没有就写「无前置」「无子插件」，不留空。被锁时高亮一句「当前被「X」关闭：显示关、拨不动；它自己的存储值保留，前置打开后恢复」+「打开前置」 |
| ⑤ 设置区 | 按分类 | A：「没有额外设置」（有相关页的加一个「去 XX」）；B：内联控件；C：当前值摘要 + 「去 XX 设置」；D：「界面上没有可调项」+ env 名；E：不出设置 |
| ⑥ 底部 | 原开关 / 档位 + 「详情 ›」 | 控件不变。详情弹层**保留**，用途变成看长文和「当前 / 默认」，不再是唯一入口 |

点 chip：滚到对应卡并闪一下边（复用现成的 `.is-flash-hit`，`style-14-settings-pages.css:667`）。

**设置区到底内联什么**（这是 (a) 的具体建议）：

| 做法 | 适合 | 例子 |
|---|---|---|
| 内联可拨控件 | 设置本身就是同一组 flags、或是一个数 | 归档保留天数、压缩触发方式 / 百分比 / K、目标续跑轮数 |
| 内联「当前值 + 去那里改」 | 设置在别的存储里、或是一整块内容 | 执行器配置、壁纸、技能目录、工人人设 |
| 只写「没有额外设置」 | A 类 59 项 | 绝大多数卡片 |

不建议把别页的整块表单搬进来：那等于插件页再实现一遍派活页 / 技能页，两处都要维护，而且那些页有自己的上下文（选了哪个执事、哪个技能）。

**布局**：内容列宽 1000px 时，V1 / V2 两列（每列约 495px），V3 单列（每张卡内两栏）。
现行 245px 最小列宽放大到 400px（V1 / V2）或 560px（V3）。

**密度规则**（`style-14-settings-pages.css` 的 `.flag-grid` / `.flag-item`）：

- 网格 `repeat(auto-fill, minmax(380px, 1fr))`，`align-items: start`。卡不定高、不强制等高，同排顶部对齐。
- 最小列宽取 380 而不是任务书写的 320：内容列内宽 992px（`.set-page` 1000 − 左右各 4）下，
  320 能放下三列（3×320+2×10=980），与「1000px 两列」矛盾；380 时三列要 1160、两列要 770，两条都成立。
- 实测（无头 Edge，真实页面 + 真实 CSS + 接口假数据，2026-11-25）：窗口 1280 → 内容列 956px、两列、单卡 473px。
  纯开关卡 25 张，高 133–171px（中位 152），全部 ≤ 230px；有依赖的 49 张 163–290px；说明 1–5 行；头部、元信息都没折行。
  窗口 1100 → 内容列 776px，仍是两列但每列约 383px：12 张卡头部折行、28 张卡元信息折行、最高 317px。
  窗口 820 → 内容列 768px，折成一列。

**搜索**：检索串改成显式的——名字 / key / 说明 / 组名 / 父 key 与父名 / 子 key 与子名（`flagSearchHaystack`）；
卡内设置面板里的链接文字不在里面。代价：搜某个子插件的名字，也会带出它的父插件（例：「人设」会多出「派活（宰相）」）。

**回滚**：卡尾「设置」按钮与面板沿用 `localStorage.setItem("lifediary.pluginInlineSettings","0")`。
