## 结论

2026-11-13 核实：附件能力只有**图片**一种（2026-11-08 扫尾批 4a），上行是
`{type:"image", mimeType, data: 裸 base64}`，服务端把它当 pi-ai 的 `ImageContent`
直接交给模型；图片字节原样进 durable 条目（登记过的已知边界：会话库随之变大）。
非图片文件完全收不了（服务端 `mimeType` 必须 `image/` 前缀；前端 `accept="image/*"`）。

本批改成两条路，消息里**只带路径**：

| 场景 | 路径来源 | 字节去向 |
|---|---|---|
| 桌面壳里点「添加文件」 | `Shell.SelectFiles` 原生多选 → 绝对路径 | 零拷贝，服务端只做 `stat` 校验 |
| 浏览器 / 壳里拖入 / 粘贴截图 | `POST /api/v1/agent/attachments` 上传 → 服务端落 `.data/attachments/` → 返回绝对路径 | 单份落盘（内容 hash 去重） |

消息到达内核时，文件部分变成**一段机器可读的清单**（见 §二.3），模型据此用
`read` 工具按路径读；图片仍保留内联 base64 的老形状（粘贴截图没有路径，且模型直接看
比多一次工具轮更快）。**文件不会再被内联进 durable**，这是本批省空间的主要来源。

加号从「只会选图片」升级成菜单：`添加图片或文件 / 截图 / 新建目标`（方案 §五）。

## 一、契约

### 1. 上行内容分段（`ts/packages/shared/src/index.ts`）

`ContentPartSchema` 由 `TextPart | ImagePart` 扩成 `TextPart | ImagePart | FilePart`：

```ts
FilePart = {
  type: "file";
  /** 服务端可直接读取的绝对路径（壳原生选择器给出；浏览器上传后由服务端生成） */
  path: string;            // 1..4096
  /** 展示名（原文件名） */
  name: string;            // 1..255
  mimeType?: string;       // 未知就不给
  bytes?: number;          // 未知就不给
}
```

`ImagePart` 逐字节不变：老客户端（手机）继续发内联图片，服务端照旧收。

### 2. 回读（`TranscriptMessageSchema`）

```ts
files?: Array<{ path: string; name: string; mimeType?: string; bytes?: number }>;
```

文字仍走 `text`，图片仍走 `images`。纯文件消息 `text` 是空串（与纯图同口径）。

### 3. durable 里的形状

pi-ai 的 `UserInput` 只认 `TextContent | ImageContent`，文件没有自己的 part 类型。
所以服务端把文件列表写成**一段固定清单**放在用户正文最前面，随消息一起进 durable：

```text
[附件] 用户附上了以下文件，需要时用 read 工具按路径读取：[{"name":"a.pdf","path":"D:\\x\\a.pdf","mimeType":"application/pdf","bytes":1234}]

<用户正文>
```

- 清单固定一行、前缀固定 `[附件] `、内容是 JSON 数组（JSON 保证路径里的换行被转义，
  解析不会跨行跑偏）；
- `readTranscript` 只认**正文最前面这一行**，解析成功就折成 `files` 并从 `text` 里剥掉；
  解析失败（用户手打了同款前缀）原样当正文，不猜；
- 只有文件、没有文字时清单后不补空行，`text` 回读为空串。

### 4. 新端点（`POST /api/v1/agent/attachments`）

浏览器拿不到真实路径时的唯一入口。`AGENT_FILE_ATTACHMENTS=false` 时 404，`/agent/policy`
的 `fileAttachments` 为 false，前端把「任意文件」入口收掉（图片内联不受影响）。

```json
// 请求
{ "name": "报告.pdf", "mimeType": "application/pdf", "data": "<裸 base64>" }
// 成功
{ "ok": true, "file": { "path": "D:\\...\\.data\\attachments\\<hash>-报告.pdf",
                        "name": "报告.pdf", "mimeType": "application/pdf", "bytes": 1234 } }
```

- 单文件解码后 ≤ 32MB，`data` 必须是合法 base64（与图片同一套 `base64Bytes` 口径）；
- 文件名只取 `basename`、去控制字符，落盘名带内容 sha256 前 16 位（同内容不重复占空间）；
- 目录 `.data/attachments/`，可用 `ATTACHMENTS_DIR` 覆盖；超过 `ATTACHMENTS_MAX_MB`（缺省 512）
  时按 mtime 从旧到新删，只删这个目录里的东西；
- 日志只记张数/字节/耗时，不记文件名与路径正文。

### 5. 路径校验

服务端对 `file` part 逐条复核（纯函数）：

- 绝对路径（Windows 盘符或 `/` 开头），长度 ≤ 4096，不含 `\0`；
- `statSync` 必须是**已存在的普通文件**；不存在 / 是目录 → 400 带文件名；
- 一条消息最多 8 个文件（`MAX_FILES_PER_MESSAGE`），与图片的 4 张上限互不占用；
- 不给 `path` 加根目录限制：`read` 本来就能读绝对路径，壳里选的就是用户自己的文件；
  `path-guard` 的写边界不受影响（它只守 `write` / `edit`）。

## 二、服务端装配

`attachments.ts` 的 `assembleUserContent` 扩成三段：

1. 文本：多段用 `\n` 连（不变）；
2. 图片：张数 / 体积 / mimeType 校验（不变），仍进 `parts`；
3. 文件：校验后生成清单行，放在 `parts` 的**第一个 text part** 里；`text`（给记忆/日志
   的纯文本口径）**只留用户原话**，不把路径写进记忆。

返回值增加 `fileCount`。`parts` 里文件不占独立 part，全部折进那段 text；纯文件消息
`parts` 仍然只有一段 text。

## 三、Web UI

- **加号菜单**（`.composer-plus-menu`，从加号向上弹）：
  - 添加图片或文件：壳里 → `Shell.SelectFiles`（多选，任意类型）→ 路径 chip；
    浏览器 → `<input type=file multiple>` → 逐个 `POST /agent/attachments` → 服务端路径 chip；
  - 截图：`navigator.mediaDevices.getDisplayMedia` 抓一帧 → 内联图片（不可用的环境直接
    不渲染这一项）；
  - 新建目标：抄 cindy 的 `+ → 新建目标` 弹窗 — 把输入框里已有的文字预填进「目标」，
    保存到当前执事的 `currentGoal`（`PATCH /api/v1/partners/:id { currentGoal }`），
    下一轮起注入；普通助手会话没有执事身份，这一项不渲染。
- **附件预览在输入框上方**：`#composer-attachments` 挪到 `textarea` 之前；图片是缩略图，
  文件是「图标 + 文件名 + 体积」的小卡，右上角 × 移除。
- **消息里的附件在文字上方**：`mountMessageImages` 改挂到 `.body` 之前，文件 chip 一起渲染。
- **上下文环**：20px → 16px，环高 28px → 24px，描边 2.5 → 2.2。
- **模型 pill**：只显示模型名（去掉「供应商 ·」前缀）；思考档不再挂在 pill 上
  （原来的 `·高` 小点一并退役），当前档仍看菜单里的分段与 pill 的 title。

## 四、桌面壳

`desktop/main.go` 的 `Shell` 增加：

```go
// SelectFiles 弹系统文件选择器（多选），返回绝对路径；取消返回空切片。
func (Shell) SelectFiles() ([]string, error)
```

- `LIFEDIARY_SHELL_BINDINGS=off` 时不挂（整组 Shell 一起不挂），页面退化为浏览器上传；
- 壳需要重编（`powershell -ExecutionPolicy Bypass -File .\build.ps1`），旧壳里前端调用
  会失败并自动退回浏览器路径（不发 toast 打扰，选中后走上传）。

## 五、加号菜单的取舍

- **不抄 ZCode 的「目标模式」开关位**：我们的权限档 / 审批档已经在右上角抽屉里，
  再加一处会变成两处真相；加号只放「这条消息相关」的动作。
- **截图**只在 `getDisplayMedia` 存在时出现；壳的 WebView2 若不允许，会当场失败并提示
  「这个窗口不支持截屏，可以粘贴图片」，不留一个点了没反应的死按钮。
- **图片选择器在壳里也走路径**：选了图片不内联，和文件同一套；粘贴截图仍内联
  （没有路径，且模型直接看最快）。

## 六、明确不做

- 不把文件内容读进上下文（PDF/Word 解析、OCR 都不做）；只给路径，读不读由 Agent 决定。
- 不做文件浏览器 / 最近文件 / 目录选择（另有项目「浏览文件」）。
- 不给图片路径做缩略图服务：壳里选的图片显示文件卡，不显示预览；粘贴的截图仍有缩略图。
- 不做附件清理的定时任务：只在上传时按总量从旧到新删（§一.4）。
- 不迁移历史内联图片：老会话里的 base64 原样可读，不重写成文件。
