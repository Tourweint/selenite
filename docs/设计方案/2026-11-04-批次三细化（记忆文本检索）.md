> 实测底座（CodeBuddy 两轮实测，node:sqlite / SQLite 3.53.4）：FTS5 trigram 可建表；**MATCH 是短语/子串语义——整句查询恒 0 命中**（"我今天想吃红烧狮子头，帮我找餐馆" → 0；"红烧狮子头" → 命中）；2 字查询静默返回 0（不报错）。

## 〇、一句话（按审查重画后的机制；2026-11-04 验收再修：候选集=文本命中 ∪ 最近窗口，见 §六）

`SqliteMemoryStore` 建镜像 FTS5 trigram 虚表；`recall` 把查询**切成 3-gram 词袋 OR 匹配**做候选集（不是整句短语匹配——那是恒 0 命中的坑），**FTS 命中 0 或不可用或查询 <3 字时回落现有窗口路径**；打分权重不动。`InMemoryStore` 不支持 FTS、**完全忽略 text**——批次一的窗口用例因此原样保住。

## 一、store 层（`ts/packages/memory/src/store.ts`）

1. `SearchFilter.text?: string`——语义：**候选集来源提示，store 自行决定用不用**：ftsEnabled && `text` 规整后 ≥3 字 → FTS 路径；**否则静默忽略 text 走现有 SQL 原样**（这终结了 LIKE 死分支，也保住"短查询=窗口路径"的口径，审查 S5）。`MemoryStore` 接口加能力位 `ftsAvailable(): boolean`（`InMemoryStore` 恒 false）。
2. FTS 虚表（SqliteMemoryStore 构造内，try/catch 探测）：`CREATE VIRTUAL TABLE IF NOT EXISTS memory_fts USING fts5(content, content_id UNINDEXED, tokenize='trigram')`；失败 → `ftsEnabled=false`。
3. 镜像维护（审查建议 10）：`put` = FTS delete+insert；`patch(content)` 同；superseded 的记录**不入候选**（JOIN 里 `superseded_by IS NULL`，写进注释）；初始化对账 `count(memory_fts) != count(memories)` → `rebuildFts()`（清空重建，旧库无痛补索引）。content_id 无索引、delete 全表扫——本规模（个人记忆数千条）可接受，注释写明。
4. **查询构造（审查 S4 的核心修正）**：`text` → 清洗（复用 extractKeywords 的正则口径）→ 取**全部 3-gram**（连续三字滑窗，去重截 24 个）→ 每个双引号包裹（**内部 `"` 转义 `""`**，审查建议 11）→ ` OR ` 拼接 → `MATCH`；**MATCH 抛错 try/catch 回落窗口路径**；**命中 0 也回落窗口路径**（retriever 层做，见下）。3-gram 词袋会有噪声候选，由打分层+limit 兜——它只负责"把相关的老条目捞进池子"。
5. **单开关（审查可选意见采纳）**：`SqliteMemoryStore` 构造加 `fts?: boolean`（默认 true）；`MEMORY_RETRIEVER=js` → server 装配传 `fts:false` → store 无 FTS、search 忽略 text → **全链路逐字节回到批次一行为**。不设第二层 useText 开关。

## 二、recall 层（`recall.ts`）

1. `WeightedRetriever`：`query.text` 非空时透传 `store.search({..., text})`；**候选为空且带了 text → 回落再查一次不带 text 的窗口路径**（回落逻辑在 retriever，不在 store）。打分四项权重、`extractKeywords`/`keywordScore`、`slice(0, limit)` 全不动。
2. 接口 `Retriever`/`RecallQuery` 不动。

## 三、装配（server）

`agent.ts` 记忆装配处读 `MEMORY_RETRIEVER`（`auto|js`，默认 auto）→ `createMemoryEngine` → store 构造参数。`.env.example` + `接口文档.md` §6 各加一行。

## 四、测试（selftest 改为"内存 + Sqlite 双引擎"，审查 S6）

`packages/memory/scripts/selftest.ts` 现用 `InMemoryStore`（:22，头注释"不落盘"）——FTS 相关用例挂 **Sqlite 夹具**（`SqliteMemoryStore(':memory:')`，构造不支持就临时目录文件，实施时确认）：

1. **真实长句破窗**（替换原 §四.1 的"红烧狮子头"方便样本）：120 条递增 createdAt、最老一条正文含"红烧狮子头"、查询用**完整长句**"我今天想吃红烧狮子头，你能帮我找找附近的餐馆吗？" → floor=50（窗口外）仍必须召回它（3-gram OR 命中 + 回落兜底都挡不住它）。
2. **2 字查询回落**："妈妈" → 窗口路径，行为与批次一一致。
3. **中英混排**：混排串不抛错、正常返回。
4. **FTS 不可用**：`fts:false` 构造 → 忽略 text、行为同批次一。
5. **0 命中回落**：查询串与库内内容无任何 3-gram 相交 → 返回非空（窗口兜底），**不是空**（审查 S4 的"记忆注入整体消失"回归锚）。
6. **批次一回归必跑**：`pnpm memtest` 全量重跑（审查明说：text 透传实现错误会当场打挂批次一的"灯塔"窗口用例——这是最便宜的守门员）。
