## 一、问题

三刀落的能力（契约/目标/履历/状态感）全部藏在「对话设置抽屉」的人设页里，且履历/记忆/例行/技能**根本没有展示面**。用户要的是"员工档案"：一个执事的家底一页看全。

## 二、设计（最小面）

### 服务端（唯一新端点，只读）

`GET /api/v1/partners/:id/skills` → `{ ok, skills: [{ name, summary, updatedAt }] }`

- 读执事家目录 skills/（`store.skillsDirOf(id)`，既有函数）；`*.md` 一文件一技能：name=文件名去扩展、summary=**第一行**（技能手册既有口径：第 1 行=索引用摘要）、updatedAt=文件 mtime。
- 目录不存在/为空 → `{ skills: [] }`；执事不存在 → 404；`COMPANIONS_ENABLED=false` → 404（同执事端点既有口径）。
- 只读，不进 WRITE_TOOLS，无开关（无行为变化）。

记忆与履历**不加端点**：`GET /api/v1/agent/memory?scope=partner:<id>`（2026-11-09 核对 `memoryOverview` → `memoryEngine.list({scopes:[scope]})`，scope 键=`partner:<id>`，types.ts:43）本就支持按执事读全量条目（work + 四形态）。前端一次拉取，按 kind 分拣：`work` → 履历页，其余 → 记忆页。
例行规则：`GET /api/v1/routines?partnerId=`（已有）。

### 前端（web/app.js，全复用 cs 抽屉体系）

1. **抽屉 home 加「档案」组**，四个入口 → 新 csPage：`records`（工作履历）/ `memories`（记忆）/ `routines`（例行规则）/ `skills`（技能）。页面模式照 persona 页（返回/标题/空态话术）。
2. **工作履历页**：memory 数据里 `kind==="work"`，倒序逐条：content 原样（单号/摘要/终态/结果都在里面）+ createdAt + `source=work` 小徽章。空态："还没有结算过的单子——派出去的单完工后会自动记在这里。"
3. **记忆页**：非 work 按 kind 分组（偏好/事实/经历/实体，中文标签+徽章），条目显示 content + createdAt + 来源徽章（taught/imported/user 原样小字）。**刻意只读**：删除/整理沿用设置页记忆区既有入口，档案页不重复做。空态："还没有记忆。你教它的话（"记住…"）会落在这里。"
4. **例行规则页**：name + trigger 原样（cron/interval/once/event 表达式不翻译）+ enabled 徽章 + sessionMode。空态："还没有例行规则。"
5. **技能页**：新端点数据，name + summary + updatedAt。空态："还没有技能文件。"
6. **花名册直达**：每行加「档案」小按钮（Lucide 内联图标，与既有 37 处同口径）：点击 = 打开该执事会话 + 自动打开对话设置抽屉。若抽屉强依赖会话上下文（csResolveTarget），实现从简：开对话后由既有 toggleChatSettings 路径进入即可；**允许降级**为"开对话+开抽屉 home"，不强求直落档案页——在变更记录里写清实际做到了哪档。

### 刻意不做（登记）

- 档案页只读：编辑仍走人设页三卡（SOUL/契约/目标）与例行任务的既有编辑面；记忆删除/整理沿用设置页记忆区。
- 派单在办不进档案页（任务中心已有，避免两处真相）。
- 手机端不做（lifediary 仓另批）。
- 不做跨执事聚合视图（每执事一个抽屉页，够用）。
