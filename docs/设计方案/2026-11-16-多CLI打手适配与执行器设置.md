# 多 CLI 打手适配与执行器设置（2026-11-16）

**状态**：已落地（2026-11-16）。
**冲突口径**：落地后以 `docs/基线文档/接口文档.md`、`docs/基线文档/系统架构.md` 为准；本文保留"当时怎么想的"。

## 1. 背景与目标

任务中心现在能派的"外接 CLI 打手"只有 CodeBuddy / Qoder 国际 / Qoder 国内三档，
由 `CHANCELLOR_EMPLOYEE` 一个全局 env 在进程启动时冻结。用户要求：

1. 再适配三档社区常用 CLI：**Claude Code**、**Codex CLI**、**OpenCode CLI**（本机 `pi` 未安装，
   不凭空适配；留扩展位）。
2. 桌面端能配置：**用哪个 CLI**、**它用什么模型**、**权限档**。
3. 顺带回答：Claude Code 非交互模式消耗额度更快，参考项目怎么解决、要不要跟。

## 2. 调查结论（2026-11-16 核对）

### 2.1 参考项目不是 magpie 的任务中心

`<reference>\magpie` 是本地模型网关 + 各编码 Agent 的配置改写器，
**没有任务中心 / 派活队列**。它真正值得参考的是 `internal/claudetui/`：用 PTY 起一个
真正的交互式 Claude Code 进程，把提示词用 bracketed paste 打进 TUI，再从 transcript
读回复，伪装成 `-p` 的 stream-json 输出。

真正对应"任务中心派活给不同 CLI"的是同目录的 `<reference>\agent-autoloop`：

- `worker/agents.ts` 定义 `Adapter` 契约：`command(turn) / read(stdout, code, stderr) / link? / check?`
- `plugins/claude/agent.ts`、`plugins/codex/agent.ts`、`plugins/acp/agent.ts`、`plugins/command/agent.ts`
- 每个适配器只负责：拼 argv、解析 stdout、成败判定；任务结果仍由任务目录里的 `REPORT.md` 决定。

### 2.2 Claude Code 非交互为什么更费额度

社区实测（[anthropics/claude-code#97074](https://github.com/anthropics/claude-code/issues/97074)）：

- 交互式终端请求带 `cc_entrypoint=cli`，`claude -p` / Agent SDK 带 `cc_entrypoint=sdk-cli`；
- 订阅套餐按 entrypoint 加权，同一份工作 `-p` 消耗约为交互式的 **1.8–2.9 倍**；
- Anthropic 2026-06-15 曾公告把 `-p` 拆到独立 Agent SDK 额度，但官方随后**暂停**了该变更；
  截至 2026-10-07，订阅登录下的 `claude -p` 仍走订阅额度（[官方说明](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)）。
- `-p` 还从"没有交互式缓存"的状态起步；`--resume` 能续会话，但改不了 entrypoint 权重。

magpie 的对策是完整的交互式 TUI 桥（ConPTY / Unix PTY + 粘贴 + transcript 尾部读取 +
Bun `--preload` 抓 SSE 流），工程量约一个独立子项目，且只在订阅套餐下才有收益。

**本批决定：不实现交互式桥。** 理由：

1. 本机 Claude Code 当前未登录（`claude auth status` → `loggedIn:false`），无法验收；
2. 用 API Key 计费时该 2 倍权重不存在，交互式桥没有收益；
3. Windows 上要 ConPTY + 屏幕读取 + 会话文件尾部解析，任何一处不稳都会让派活变成"看起来在跑"；
4. 用户口径："我感觉非交互式的都已经够好用了"。

在设置页把这条边界写在 Claude Code 的模型卡上（订阅套餐约 2 倍，API Key 不受影响），
把"要不要上交互式桥"留给后续单独立项。

## 3. 方案

### D1. 适配器契约沿用现有 `Employee`，只加三种 kind

`chancellor/src/types.ts` 的 `EmployeeKind` 增加：

```ts
| "claude-code"
| "codex"
| "opencode"
```

三者都声明同一套能力：

```ts
{ artifacts: "taskDir", canWriteFiles: true, resumeWithSession: true }
```

即：产物只认任务目录的 `REPORT.md`；支持拿会话号续跑；不读 stdout 当任务结果。
新增适配器放在 `chancellor/src/employee/{claude,codex,opencode}.ts`，与 `codebuddy.ts` / `qoder.ts` 并列。

### D2. 执行器选择是"全局默认 + 建单快照"，不是按单选择

- 桌面端「设置 → 派活」选一个默认执行器，落 `.data/executor.json`。
- 每次新派单，harness 把 `employee` 与 `employeeProfile` 放进 `ChancellorRequest`；
  chancellor 落进 `ticket.employee` / `ticket.options.employeeProfile`。
- 续跑 / 崩溃恢复一律按**原单快照**，不跟当前默认走：换默认只影响新单，
  老单的会话上下文与模型不会中途换人。
- 不做"这张单用 Codex、那张单用 Claude"的按单选择：当前任务中心没有这个交互，
  先按用户真正要的"设置里能选"落地；按单选择等有真实需求再立项。

### D3. 模型与权限走 CLI 原生参数，不写进提示词

| CLI | 模型参数 | 权限参数 | 续跑 |
|---|---|---|---|
| Claude Code | `--model <name>` | `read`→`--permission-mode plan`；`edit`→`--permission-mode acceptEdits`；`full`→`--dangerously-skip-permissions` | `--resume <session_id>` |
| Codex | `-m <model>` | `read`→`-s read-only`；`edit`→`-s workspace-write`；`full`→`-s danger-full-access`；统一 `-c approval_policy="never"` | `codex exec resume <id> <prompt>` |
| OpenCode | `-m provider/model` | `read`→`--agent plan`；`edit`/`full`→`--auto` | `--session <id>` |
| CodeBuddy | `--model <name>` | 固定全权（`-y`），本批不暴露权限档 | `-r <id>` |
| Qoder 国际/国内 | `-m <model>` | 固定全权（`bypass_permissions`），本批不暴露权限档 | `-r <id>` |

权限档统一三值：`read` / `edit` / `full`，只对 Claude / Codex / OpenCode 生效；
CodeBuddy / Qoder 的界面卡显示"可写（固定）"，避免给出拨了不生效的档位。

模型留空 = 不传该参数，跟随 CLI 自己的配置（`~/.claude/settings.json` / `~/.codex/config.toml` /
`~/.config/opencode/opencode.json`）。这样不会把某个账号不可用的模型硬塞给 CLI。

### D4. 输出解析

- **Claude Code**：`--output-format json` 返回单个 `type=result` 对象，
  与 CodeBuddy/Qoder 同形（`result` / `is_error` / `permission_denials` / `session_id`），
  直接复用 `cli.ts` 的 `parseCliStdout` + `isCliSuccess`。
- **Codex**：`--json` 是 JSONL 事件流。解析 `thread.started.thread_id` 拿会话号，
  `turn.completed` 判完成，`turn.failed` / `type=error` / `item.type=error` 判失败；
  兼容未来 `method/params` 形态（`turn/completed` 等），解析器保持宽松。
- **OpenCode**：`--format json` 是 JSONL。`type=text` 收集文本与 `sessionID`，
  `type=error` 判失败。**实测退出码 0 也可能带 error 事件**（模型不可用），所以不能只看退出码。
- 三者都**不把 stdout 当交付物**：交付仍读 `task.dir/REPORT.md`。

### D5. Windows 启动：统一解析 npm shim

三个 CLI 在本机都是 npm 全局安装：

- `claude.cmd` → `node_modules/@anthropic-ai/claude-code/bin/claude.exe`
- `codex.cmd` → `node .../@openai/codex/bin/codex.js`（再由它拉起原生 exe）
- `opencode.cmd` → `node_modules/@opencode/cli/bin/opencode.exe`

Node 的 `spawn` 不能直接跑 `.cmd`（不加 shell）——CodeBuddy 已经踩过并写了 `resolveCodeBuddyLauncher`。
本批把这段解析做成 `cli.ts` 的 `resolveCliLauncher(bin, label)`，**新三档用它**：

1. 绝对路径存在 → 直接用；
2. 只给命令名 → 按 `PATH`+`PATHEXT` 找 `.exe/.cmd/.bat`；
3. `.cmd/.bat` 正文里找 `node_modules/...` 目标：`.exe` 直接起，`.js` 用 `node` 起；
4. `.js/.mjs/.cjs` 用 `node` 起；
5. Windows 上无扩展名的 POSIX shim → 找同目录 `.cmd`。

CodeBuddy 保留原有 `resolveCodeBuddyLauncher`（行为等价、已有单测钉住），
不为了统一去动一条已经实测过的链路；两套实现共用同一套"从 shim 找 node_modules 目标"的规则。

### D6. 提示词过长

- Claude / CodeBuddy / Qoder：沿用 `STDIN_PROMPT_THRESHOLD = 8000`，超过走 stdin。
- Codex：`codex exec -` / `codex exec resume <id> -` 从 stdin 读提示词。
- OpenCode：实测**不给 message 参数时从 stdin 读**（`printf ... | opencode run` 成功），
  超过阈值一律走 stdin。

### D7. 运行时配置与回滚

- 落点：`.data/executor.json`，形状：

```json
{
  "employee": "claude-code",
  "profiles": {
    "claude-code": { "model": "", "permission": "full" },
    "codex": { "model": "", "permission": "full" },
    "opencode": { "model": "", "permission": "full" },
    "codebuddy": { "model": "deepseek-v4.1-flash" },
    "qoder-intl": { "model": "DeepSeek-Flash" },
    "qoder-cn": { "model": "DeepSeek-Flash" }
  }
}
```

- 缺文件 / 字段缺失：回落到现有 env（`CHANCELLOR_EMPLOYEE`、`CHANCELLOR_MODEL`、
  `CHANCELLOR_CODEBUDDY_MODEL` 等），行为与改动前一致。
- 回滚：`EXECUTOR_CONFIG=false` → 不读文件、一律走 env（一行 env 退回上一形态）。
- 读文件带 mtime 缓存；每次派单懒读，改完不需要重启。
- 端点：`GET /api/v1/agent/executor`、`PUT /api/v1/agent/executor`；
  校验执行器白名单、权限三值、模型串长度；非法值 400 带说明。

### D8. 分管路径

`domain` 非空时 chancellor 起一个 manager 子进程，子单在子进程里创建。
本批把 `employee` / `employeeProfile` 也传给 `runManager`，由它写进 manager 子进程的 env
（`CHANCELLOR_EMPLOYEE` + 三档模型/权限 env），让分管派出的子单继承同一套默认。
子单仍各自落自己的 `ticket.employee`，续跑不受影响。

## 4. 明确不做

- **Claude Code 交互式 TUI 桥**（PTY / ConPTY + 粘贴 + transcript 解析）：见 §2.2，单独立项。
- **按单选择执行器**：见 D2。
- **PI CLI 适配**：本机没有 `pi`，没有可验证的二进制与参数；不凭文档写死。
  未来如果 `pi --print` 可用，可照 `opencode.ts` 复制一档。
- **模型清单在线拉取**：Codex 没有 `models` 子命令，Claude 只有别名；
  OpenCode 虽有 `opencode models`，但为它单开一个会阻塞设置页的端点不值得。
  本批用"自由文本 + 已知别名建议 + 留空跟随 CLI"。
- **权限档对 CodeBuddy/Qoder 生效**：它们的非交互模式本来就是全权，改了反而会挂起等授权。
- **执行器健康检查 / 登录状态探测**：设置页不主动起 CLI 探测（会拖延页面）；
  未登录导致的失败由任务中心的失败汇报如实显示。

## 6. 落地偏差与验证结果（2026-11-16）

### 6.1 落地时发现并修掉的偏差

1. **OpenCode 必须加 `--standalone`**：默认走后台常驻服务，那个服务的目录是它第一次启动的地方，
   会把产物写进宿主目录（冒烟实测写进了 `ts/apps/server`）。加 `--standalone` 每次起私有服务。
2. **`PWD` 必须对齐 spawn cwd**：OpenCode 2.1.1 在 Windows 上按继承的 `PWD` 认工作目录，不认
   `spawn` 的 `cwd`。统一在 `runCliProcess` 里把 `env.PWD = call.cwd`；这条对所有外部 CLI 生效，
   也顺手修掉了同类隐患。
3. **Claude `full` 用 `--dangerously-skip-permissions`**：比 `--permission-mode bypassPermissions`
   兼容性稳（后者在部分版本要求额外的 dangerous 开关）；`read` / `edit` 仍用 `--permission-mode`。
4. **`executorForDelegation` 对 native 返回空 profile**：界面仍会把 native 的空模型写进文件，
   但派单不把 `{model:"",permission:"full"}` 塞进 ticket，避免噪声快照。
5. **任务中心打手卡从 4 张变 7 张**：新执行器如果不进 `TASK_HITTERS`，派给它们的单不会出现在
   "打手"区，只在会话列表里可见；这是用户能看见的缺口，所以同批补上。
