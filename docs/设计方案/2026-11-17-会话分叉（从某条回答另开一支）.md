## 结论

1. **分支 = 复制，不是引用。** 把分叉点之前的条目逐条写进新会话，新会话有自己的记录；
   原会话删了也不影响副本。
2. **两种模式，按身份分**：
   - 普通对话 → **旁支副本**：原会话继续当主线，副本另开一条，列表里标"副本·来自…"；
   - 总管 / 执事 → **复制并接替**：副本接替成为该身份**唯一**的主线，原会话冻结保留（只读）。
     这样"一个身份只有一个会话"仍然成立，不需要造第二个总管。
3. **画板只画一条会话的树。** 进谁的会话，就只看谁的回合与分支；不做"整个工作区一张画布"。

## 为什么不直接复用 durable fork

| | durable `fork(at)` | 我们要的复制 |
|---|---|---|
| 历史 | 子会话通过 `parent` **引用**父会话的前缀 | 子会话**自有**一份条目 |
| 父被删 | 前缀没了，子会话跟着废（归档模块按子树删） | 子会话不受影响 |
| 上下文 | 完全一致 | 完全一致 |
| 用量 | 天然不重复 | 复制会重复，必须剥掉历史 usage |
| 身份 | agent 文档随 fork 复制 | agent 由身份装配层现算，不复制 |

所以复制不能设 `parent`——设了就是"父前缀 + 自拷贝"两遍。
分叉来源改记在宿主自己的表里（`ChatOrigins`），只用于展示与回跳，不参与历史解析。

## 从 dsh-synapse 学什么、不学什么

| 它的做法 | 我们 |
|---|---|
| 分支从"已完成的回答"切，跑着不给分 | 学。会话忙时直接 409，不排队 |
| 新会话换标题，来源按种子边界挂回那一轮 | 学。`origin` 存快照（标题 + 那一轮的时间） |
| 分支入口只有一个（顶栏），逐条不挂 | **不学**。我们要的就是"从这条回答分"，入口必须逐条；它那条是为了去重，场景不同 |
| 一张画布装整个工作区的所有会话 | **不学**。画板只装当前会话 + 它的分支 |
| 画布布局与分支锚点单独存，删了不丢会话 | 学。布局是元数据，不碰正文 |
| 删除/归档与宿主共用一套集合 | 学。副本也是普通会话，走同一套归档 |

## 复制的技术口径

### 复制什么

| 项 | 处理 |
|---|---|
| `pi.user` / `pi.assistant` / `pi.tool-result` 条目 | 原样重放（`model` 数组逐字复制，工具调用与结果配对不变） |
| `relay.message`（执事来信） | 连 `data.author` 一起复制，界面上仍是左侧来信卡 |
| `pi.compaction` | 复制，但 `head` 要重映射到新会话里对应的条目 id；不映射就是悬空指针 |
| `edits`（上下文覆盖） | `target` 同样重映射 |
| 时间戳 / `durationMs` | **保留原值**——副本里看到的仍是"当时几点说的、几点答完" |
| 历史 `usage` | **剥掉**。usage 账按条目扫，复制一份会让账单翻倍；上下文计量从下一轮重新记 |
| 会话种类 / 项目 / 工作目录 / 模型与思考档 | 继承原会话当时的值 |
| 附件图片 | 随 `model` 一起复制（base64 在条目里） |

### 怎么落库

1. 读原会话从 1 到分叉点的全部条目（含压缩条目），顺序不变；
2. `createConversation({ ownership, agent: { model }, init })`，在 **`init` 的同一个事务**里
   逐条 `tx.appendEntry` 到新会话，记 `oldId → newId` 映射；
3. 遇到 `head` / `edits.target` 用映射表改写；映射不到就退回 `"self"` / 丢弃该条 edit；
4. 事务里同时写 `Chats` / `ChatKinds` / `ChatProjects` / `ChatOrigins`；
5. 身份链接（总管 / 执事）在事务外补，失败可重试（SQLite 与 durable 不在一个事务里，
   幂等键用新会话 id）。

### 硬边界

- **不设 durable `parent`**，只在 `ChatOrigins` 记来源；否则历史两遍。
- 单次复制设上限（条目数 / 字节数，缺省 400 条、64MB）：超了拒绝并给一句
  "这条太长了，先压缩再复制"，不悄悄截断。
- 分叉点必须是**带正文的 assistant 条目**（`assistant` 消息需要补 `id`，现在只有 user 有）。
- 复制是 O(条目)，长会话一次几百毫秒；不阻塞别的会话。
- **先做一条探针再动界面**：拿一条含压缩（`pi.compaction`）的会话跑复制，确认
  `head` 重映射后新会话的上下文与旧会话逐条一致；若内核拒绝带 `head` 的裸 append，
  退回"只复制当前可见段"，并把"压缩前历史不在副本里"写进界面提示。

## 总管 / 执事只有一个会话，怎么办

这是这套设计真正的难点，也是不能用"旁支副本"一刀切的地方。

**答：不是新建第二个身份会话，而是让副本接替主线，旧主线退成只读快照。**

```
总管（canonical = 旧会话）
   └─ 复制并接替 → 新会话成为 canonical
                    旧会话 role 从 canonical 改成 retired（只读、可导出、可删）
```

- 身份仍然**只有一个**：`partner_session_links` 里 canonical 行始终只有一条；
- 人格、SOUL、记忆、工具权限全部照旧（记忆按 partnerId 存，不在会话里）；
- 旧会话冻结：不能再发消息、不再接收提醒/自主轮/派活回灌，界面上标
  "已由副本接替 →"；想回看随时能读；
- **不做"两条主线同时活"**（影子分支）：那会出现两个总管同时改记忆、同时被叫醒，
  规则要比复制本身复杂得多。真需要并行探索，先用普通对话的旁支副本。

### 接替时要注意的三件事

| 事 | 处理 |
|---|---|
| 旧会话上还有没跑完的轮次 | 忙 → 409，等空闲再换 |
| 已排的提醒 / 定时任务落在旧会话 | 换主线时把未触发的任务 `conversationId` 批量改到新会话；已结束的不动 |
| 派活单的 `originConversationId` 指向旧会话 | 历史单不回改；换线之后新单落新会话，回灌按 origin 找得到旧的（旧会话只读但可写回执） |

### 为什么普通对话不用接替

普通对话没有"身份唯一"的约束，保留两条线最省事：原线继续用，副本拿去试。
需要接替时，手动把副本置顶/改名就行，不必让系统改 canonical。

### 下一版（单会话画板）

学 dsh-synapse 的"回合卡片 + 分支车道"，但**作用域收死**：

- 从某条会话进入画板 → 只画这条会话的回合卡（一问一答两张卡）与它的分支；
- 分支从"分叉那一轮"的答卡伸出，连一条线，不按坐标猜；
- 点副本卡 → 进副本；点原卡 → 回主线；
- **不显示同工作区的其它会话**，也不做工作区切换器；
- 布局坐标单独存，删了不丢会话。

## 这条会怎么错

- **复制不是免费的。** 几百轮的会话会复制出几十 MB；如果用户习惯天天复制，磁盘会长。
  缓解：只有"不常用"才复制，加上限与"先压缩再复制"的提示；不自动清理副本。
- **接替主线的语义容易被误解。** 用户以为"旧会话还能继续问"，结果发现冻结了。
  所以冻结必须写在界面上，而不是只写在文档里。
- **提醒改投可能漏。** 提醒任务与 durable 任务两套账，改投要在一个可重放的迁移里做；
  漏一条就会在旧会话里被静默吞掉。探针要覆盖"换线前已排、换线后到点"。
- **画板一旦做成"看全部"，就会回到 dsh-synapse 的老问题。** 作用域必须写死在路由里：
  画板的数据源只接受一个根会话 id，不接受工作区。
- **分支再分支**：v1 允许，但只允许从当前会话再复制，来源链只存一跳（"来自谁"），
  不做完整族谱树；需要族谱时再上画板。
