# 扫尾批 8d 方案：执事间消息通道（send_to_agent 形态，防乒乓）

> 状态：**已落地（2026-11-08）**。下沉落点：工具契约与防乒乓口径 → `docs/基线文档/接口文档.md` §4 / §6；
> 通道定位与取舍 → `docs/基线文档/系统架构.md` D21；落地过程与验证 → `docs/变更记录/2026-11-08-扫尾批8d（执事间消息通道）.md`。
> **与长期文档冲突时以基线文档为准**；本文留的是"当时怎么想的"。
>
> 上位：扫尾计划 A21（用户拍板做）；形态参照 cindy `send_to_agent`。
> 与既有能力的关系：群聊（共享时间线）解决"多执事看同一处"；本通道解决"A 有话单独跟 B 说"。主人转述仍是兜底。

## 一、设计

1. **工具**：新模型工具 `send_to_agent`，参数 `{ target: string, message: string }`——target = 执事名或 domain（群组已有"最长标签优先"解析先例；重名歧义 400 报候选）。
2. **送达 = 向目标执事的会话提交一条 user 输入**（durable `submit` 持久化，天然防刷新丢；目标忙 → followUp 排队，空闲 → 立即触发目标一轮——与批 8a/8c 同套 durable 语义，**零新增存储**：消息本体就落在目标会话的 transcript 里，无信箱表）。
3. **消息包装**：送达正文 = `[来自执事 <A名>（<A域>）] <message>\n（这是执事间递话，主人看不到原文；需要主人知情或回话请用汇报或主人对话。）`——让 B 明确知道这是谁、主人不可见，且给 B 指明合法回话路径。
4. **防乒乓三闸**：
   - **hop 计数**：递话消息带 hop 标记（从 A 递出的 hop=1）；B 若要回 A，必须用**自己的话**新起（回递的内容里若含 hop≥1 标记引用，工具拒绝）——实现口径：`send_to_agent` 只允许执事在**主人发起或工具直发的轮次**使用，递话触发的目标轮次里**该工具不可用**（目标轮工具面摘除 `send_to_agent`）——结构上断乒乓，比提示词可靠（宿主确定性红线）。
   - **每 run 上限**：单个 run 内最多递 3 次（超出返回引导话术"把几件事合并成一条"）。
   - **hop 恒为 1**：目标轮摘除了工具，B 无法再递——即通道天然只有一跳。若将来要两跳，单独立案。
5. **目标轮工具面摘除的实现口径**：递话触发的 run 与普通轮同源（chatStream），在装配处按"本 run 由递话触发"标记摘除 `send_to_agent`（turn-gate 同款 beforeTool 拦截即可，不必重建工具面）。
6. **主人知情权**：递话发生时向**主对话**发一条轻量事件（`notice` 或既有 delegate 同款），主人时间线可见"执事 A → 执事 B：递了一条话"（正文不展示，防刷屏；点开看 B 的会话）。这是"主人不可见原文"与"主人知情"的平衡。
7. **权限**：`send_to_agent` 不进 `WRITE_TOOLS`（不写盘）；自主轮（例行触发）下**不可用**（递话是主人语境的行为，例行轮没有主人语境——批次C D14 备忘口径一致）。
8. **回滚**：`PARTNER_RELAY_ENABLED=false` 工具不上架（默认开？——新能力默认**开**但工具面小、有上限；不，按"新能力给回滚开关"惯例默认开 + 开关可关）。

## 二、明确不做

不做信箱/离线队列 UI、不做已读回执、不做自动谈判循环（hop=1 已断）、不做主人外触发、不做跨机递话（远端锚点会话不装配）、不做群内定向私聊。

## 三、验证

- 探针：①A→B 递话落 B 会话且主人对话有通知；②B 忙时 followUp 排队不丢；③B 回合内 send_to_agent 被拦（防乒乓实证）；④单 run 第 4 次递话被引导；⑤重名/不存在目标 400/引导；⑥回滚开关 404。
- 单测：目标解析（名/域/歧义）、hop 标记、上限计数。
- 真模型手验（派单人）：两执事真模型互递一轮，主人时间线可见通知。
