## 问题（用户原话）

> "如果我总管一直压缩，我的上下文不会爆炸，但你这个会爆炸呀。前端渲染不会爆炸，但肯定会让我的 GPU 爆炸。"

画板原实现每个节点最多回最后 400 轮、最多 24 个节点，前端把**所有已下发回合**都建成卡片和 SVG 连线（卡片有视口裁剪，连线没有）。一条用得久的总管会话几百轮就是几千张卡、几千条线；再多只能截断，用户明确不想要"截断"，要**折叠**：

- 默认只保留最近 5 / 10 / 15 轮，轮数可设置；
- 前面的回合折叠起来，点一点往前放一段，不要一次全开；
- 后边折叠是另一个功能（现有"收起这支"只藏分支后代），本批不做；
- 按天分页/跨天检索是更大的事，本批不做。

## 结论

1. **地图改窗口**：每个节点只回最近 N 轮（默认 10，可经 `?turns=` 指定，服务端夹在 1–100）。
   响应里补 `totalTurns` / `windowStart` / `hasEarlier`，前端不再需要靠"被截断"猜。
2. **折叠卡**：节点窗口前面还有自己的回合时，车道最左端放一张虚线"折叠卡"（更早 N 轮）。
   它不是回合卡、不进详情、不可拖；点它往前放一段（步长 = 当前窗口 N），一次一段。
3. **逐段取数**：新增 `GET /map/turns`，只重取一条会话的一段，不重拉整张地图。
   分支节点带 `floor = startTurn`，永远不会把复制前缀当成自己的回合展开。
4. **坐标按绝对轮次**：问卡自然 x = `ROOT_X + 轮次 * X_STEP`。窗口变化时已加载的卡片不移动；
   分支第一张问卡仍落在母会话分叉答卡右边一格（复制前缀保证轮次对齐）。
5. **`truncated` 只表示节点数超过 24**；回合窗口是正常视图，不再算"截断"。
6. **默认窗口存浏览器**：`localStorage["lifediary.chatmap.window.v1"]`，顶栏下拉可选
   5 / 10 / 15 / 20 / 30；改完重拉地图。服务端缺省与前端缺省都是 10。

## 契约

### `GET .../chat/:conversationId/map?turns=N`

- `turns` 缺省 10；夹在 1–100。响应回显 `window`。
- 每个节点新增：
  - `totalTurns`：这条会话的总轮次（绝对，含复制前缀）；
  - `windowStart`：本次下发窗口第一轮的绝对轮次；
  - `hasEarlier`：`windowStart > startTurn`，即窗口前面还有自己的回合。
- `turns` 只含 `[windowStart, totalTurns)`；`startTurn` 仍是"分叉点之后第一轮"（分支的 floor）。
- `truncated` 只在节点数超过 24 时为 true。

### `GET .../chat/:conversationId/map/turns?floor=&before=&limit=`

- `before`：取这个绝对轮次之前的一段（不含 `before`）；缺省/越界取到会话末尾。
- `limit`：单次条数，缺省 10，夹在 1–100。
- `floor`：这条会话自己的回合起点；画板传节点的 `startTurn`。服务端只做 `[0, totalTurns]` 夹取，
  **不重新解分叉**（省一次母会话全文读取）。不是安全边界：同一客户端本来就能读这条会话的全部消息。
- 响应：`{ nodeId, startTurn, totalTurns, windowStart, hasEarlier, turns }`；
  `hasEarlier` 表示这段窗口前面还有 `floor` 之后的回合。
- 与 `/map` 同受 `CHAT_MAP_ENABLED` 管；会话不存在 404 `unknown_conversation`。

## 前端

- 顶栏右侧新增 `最近 N 轮` 下拉（5/10/15/20/30），`data-tip` 说明"更早的在车道左端折叠"。
- 折叠卡：`role: "fold"` 的伪卡片，与回合卡同尺寸（连线几何不变）；虚线、无投影、`cursor: pointer`。
  头部「折叠 / 更早 N 轮」，正文「点开往前放 M 轮」，右上角常显 `+`。
- 展开：`expandEarlier(nodeId)` 取 `before = 当前窗口第一轮`，`limit = 当前窗口`，
  `floor = node.startTurn`；把返回的旧回合前插、按轮次排序、去重，重建模型。
  加载中折叠卡显示「展开中…」，重复点击忽略；路由已切换的旧请求直接丢弃。
- 折叠卡不参与拖动与位置持久化；展开不改变已加载卡片的手动位置。
- 收起节点（现有 `−`）优先：收起时只留一张问卡，不画折叠卡。

## 备选与取舍

| 备选 | 为什么不选 |
|---|---|
| 只在前端折叠现有 400 轮 | 400 轮载荷仍有 ~640KB/节点，且 400 轮以前永远看不到；前端折叠治不了服务端载荷 |
| 一次把窗口开到最早 | 用户明确"不要一次全开"；长会话会瞬间重建上万张卡 |
| 按天分页 | 地图要跨天看关联，按天切开就看不到；检索另立项 |
| 服务端只回 `totalTurns` 不读全文 | 现有 durable 读法没有 count/slice API；本批先保持"读全文再切窗口"，读放大记为已知边界 |
| 折叠卡按窗口相对坐标 | 展开会让整条车道位移，手动位置跟着错位；绝对轮次坐标最稳 |

## 明确不做

- **后边折叠**（逐轮尾部折叠）：现有"收起这支"只藏分支后代；逐轮尾部折叠另立项。
- **跨天检索 / 跳转到某天**：窗口可以一段段展开到最早，但不做检索与跳转。
- **连线视口裁剪**：默认窗口小；一段段展开很多次后仍会累积边，需要时再加。
- **服务端读放大优化**：每次展开 / 打开地图仍读整条会话再切片。
- **手机端**：地图仍是电脑端功能。

## 会怎么错

- **展开后新卡在视口左侧**：折叠卡在车道最左端；窗口默认聚焦最后一轮，用户要往左看或先缩放。
  顶栏的"最近 N 轮"是存在更早回合的提示。
- **展开步长 = 窗口**：上万轮会话要到达最早需要点很多次；这是"一点一点铺开"的直接代价，跨段跳转留给检索批。
- **localStorage 按浏览器**：换机器/清缓存回到默认 10。
- **手动位置**：展开不改已有卡片坐标；折叠卡本身不可拖。
- **分支 floor 由前端提供**：传错只会多看到复制前缀（显示问题），不越数据边界。
