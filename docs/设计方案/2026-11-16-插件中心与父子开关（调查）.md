# 插件中心与父子开关（已实现）

> 2026-11-16：行为开关拆成「设置 → 插件」之后，父子开关按非破坏语义落地到了哪一步、边界在哪。

## 结论

1. **拆页已完成**：设置 → 插件（34 张卡，六组），服务页只留通知 / 鉴权 / 运行时；开关判定、接口、白名单未动。
2. **父子语义按 A（非破坏）实现**：父关 → 子 `effectiveValue=false`、控件锁死、API `PUT` 返回
   `400 flag_locked`；**子自己的存储值保留**，父开恢复。没有把子闸清零。
3. **不是只锁 UI**：`GET /api/v1/agent/flags` 返回 `effectiveValue / lockedBy / requires`，`setFlag` 在落盘前
   拒绝被锁子项；`flagEnabled(key)` 给消费代码提供「父关也算关」的活读布尔。
4. **`MEMORY_ENABLED` 的运行时半真已修**：`/memory/*` 的 `enabled` 从启动布尔改成活读函数；召回、任务注入、
   项目索引、`recallContext` 都先看总闸。运行期关掉后，这些路径立即停。**边界**：`.env` 本来就是
   `MEMORY_ENABLED=false` 时引擎为 null，运行期再打开仍需重启；如果只是界面覆盖关掉、`.env` 仍为 true，
   引擎已装好，重开可直接用。
5. **全项目已登记的父子关系**：插件页 6 组、设置 → 会话 2 组、人物页 3 个跨层子项（见 §2）。
6. **已验证**：`tsc --noEmit` 通过；`flags.test.ts` 14/14、记忆 / 投影 / 人格相关 46/46；本机 39847 真浏览器
   验收了插件页锁态、API 400、`/memory` 404、归档天数、压缩档位、人物页三处跨层锁，以及 JSON 清单驱动的
   34 张卡 / 6 组 / 两个分段控件（结果见 §5）。
7. **清单从 JSON 读，且可运行期热更新（同日再续）**：`src/plugins.json` 提供 40 项清单、6 组分组、名称 /
   说明 / 档位；`GET /agent/flags` 同时返回 `groups` 和每项展示元数据，前端不再维护写死的 label / group /
   choice 表。清单按 `mtime + size` 重新装载，改名称 / 说明 / 分组不用重启；坏清单保留上一版并 warn。
   `scope` 只给 4 项系统核心加标记；前端仍是同一页、同一接口、同一张卡片。

## 1. 数据模型与接口

### 1.1 清单来源与 `FlagDef.requires`

**清单从 JSON 读**：`src/plugins.json` 是唯一清单位置，含 `groups`（6 个分组的标题 / 说明 / 键顺序）
与 `flags`（40 项的 key / 中文名 / 说明 / 分组 / 类型 / 档位 / 默认值 / scope / requires / surface）。
`flags.ts` 不再静态 import 清单，而是按 `mtime + size` 运行时读同一份 JSON；`FLAG_DEFS` 是运行期视图，
前端不再维护 `FLAG_LABELS` / `FLAG_GROUPS` / `FLAG_CHOICES` / `FLAG_SECTION_KEYS` 四张写死的表。
构建时把 `src/plugins.json` 复制到 `dist/src/plugins.json`，源码态和 dist 态都能直接改清单。

```ts
interface FlagDef {
  // 运行态字段
  key: string;
  values: string[];
  defaultValue: string;
  hot: boolean;
  // 展示字段（plugins.json 提供，listFlags 原样回给前端）
  label?: string;
  summary?: string;
  group?: string;
  type?: "boolean" | "enum" | "number";
  choices?: { value: string; label: string }[];
  surface?: "flags" | "settings";
  // 父子与分层
  scope?: "core" | "plugin";
  requires?: string[];
}
```

启动时 `validateFlagManifest()` 校验键唯一、取值 / 默认值合法、分组键存在且不重复；
`validateFlagRequires()` 校验父键必须存在、不能自指、DFS 不能成环；坏配置直接 throw，不留到运行期
表现成「某个开关永远锁着」。

### 1.2 `GET /api/v1/agent/flags`

顶层多一个 `groups`（标题 / 说明 / 键顺序），`flags` 每项带展示元数据、`scope`、父子字段和当前值：

```json
{
  "groups": [{ "id": "memory", "title": "记忆", "desc": "……", "keys": ["MEMORY_ENABLED"] }],
  "flags": [
    {
      "key": "MEMORY_EXTRACT",
      "label": "记忆提取方式",
      "summary": "每一轮聊完，怎么从对话里抓「经历」……",
      "group": "memory",
      "type": "enum",
      "choices": [{ "value": "auto", "label": "自动" }],
      "surface": "flags",
      "value": "llm",
      "effectiveValue": "false",
      "lockedBy": "MEMORY_ENABLED",
      "lockedByLabel": "记忆总闸",
      "requires": ["MEMORY_ENABLED"],
      "scope": "plugin",
      "defaultValue": "auto",
      "hot": true,
      "overridden": true,
      "pendingRestart": false
    }
  ]
}
```

- 前端用 `label / summary / group / type / choices / surface` 直接渲染，不再查本地映射表。
- 接口名仍是 `/agent/flags`（沿用既有路径，不另开 `/plugins`）；它现在返回的是插件清单 + 配置值 + 父子锁态。
- `surface = "settings"` 的 6 项在设置 → 会话有专属卡，插件页不重复显示（不再用前端 `FLAG_SECTION_KEYS` 黑名单）。
- 布尔子项：界面读 `effectiveValue`，父关时显示关。
- 枚举 / 数值子项：`lockedBy` 非空时控件灰掉；插件页把被锁的枚举卡直接画成「关」的禁用拨杆，
  不假装还有一个可选档位。
- 页首计数按 `effectiveValue`：`当前 N 开 / M 关 · K 个随总闸关闭`。

### 1.3 `PUT /api/v1/agent/flags/:key`

被锁子项在落盘之前拒绝（`scope=plugin` 只写 JSON；`scope=core` 才再同步 env）：

```http
400 { "error": "flag_locked", "message": "「记忆总闸」关闭时，这个开关不能单独打开；先打开总闸，原设置会保留。" }
```

直接打 API 不再能制造「界面关着、文件里开着」的脏状态。

### 1.4 `flagEnabled()` / `flagValue()`

`flags.ts` 导出 `flagEnabled(key)`：按 `effectiveFlagValue()` 判断，父关、显式 `false` / `0` / `off` 都算关。
另导出 `flagValue(key)`：返回原始存储值，给枚举 / 数值型消费代码用。两者按 `scope` 取数：
`plugin` 读 `.data/agent-flags.json`（文件没有该键才回落 env / 清单默认值），`core` 读 env。
`ensureFlag()`（前端）也改成优先读 `effectiveValue`。

### 1.5 `scope`（同日再续：一套展示、两层存储）

| scope | 键 | 含义 |
|---|---|---|
| `core` | `MEMORY_ENABLED` / `COMPANIONS_ENABLED` / `CHANCELLOR_ENABLED` / `AUTONOMY_ENABLED` | 系统核心；默认由部署 env 兜底，界面仍可读写，但明确标「系统核心」 |
| `plugin` | 其余清单项（含 `PARTNER_TEMPLATES`、`TOOL_PROJECTION`、聊天 / 界面开关） | 普通功能插件，走插件表覆盖层 |

`scope` 不只是展示元数据，它决定**取数路径**：

| scope | 键 | 存储 / 取数 |
|---|---|---|
| `core` | `MEMORY_ENABLED` / `COMPANIONS_ENABLED` / `CHANCELLOR_ENABLED` / `AUTONOMY_ENABLED` | 系统核心；部署 env 为主。启动时文件覆盖仍会写进 env，界面写仍走 `setFlag`（落盘 + 同步 env），保留历史兼容 |
| `plugin` | 其余清单项（含 `PARTNER_TEMPLATES`、`TOOL_PROJECTION`、聊天 / 界面开关） | 普通功能插件；`.data/agent-flags.json` 是唯一真源，运行时直接读（带 mtime 缓存），**文件缺键才回 env / 清单默认值**；`setFlag` 只写 JSON，不写 env |

`PARTNER_PROJECT_MEMORY` / `PARTNER_PERSONA_MODULES` 这类部署配置仍不进 `plugins.json`。
前端不另开接口、不另做缓存，只在同一份 `GET /agent/flags` 结果里读 `scope`。
单测 / 探针隔离：`pluginStoreApplies(env)` 仅在传入 `process.env` 或显式 `AGENT_FLAGS_PATH` 时读 JSON；
传普通 env 对象仍按纯 env 夹具处理，不会被开发机真实 `.data` 覆盖。

### 2.1 刻意不挂父

| 键 | 为什么 |
|---|---|
| `MEMORY_PAGE_A` | 记忆页 UI 变体；记忆关掉后仍可先选页面样式，不是记忆模块 |
| `CHANCELLOR_ENABLED` | 全局派活链路，不专属于执事体系 |
| `DEVICE_AUTO_DISPATCH` | 派活设备选择，不是执事专属 |
| `PERSONA_MEMORY_ENABLED` → `MEMORY_EXTERNAL` | 前者是外接库部署配置，后者只把 `MEMORY_ENABLED` 当硬父；不把外部库未启用伪装成「被父关」 |
| `PARTNER_PROJECT_MEMORY`、`PARTNER_PERSONA_MODULES` | 不在 `plugins.json` 清单；false 分别是「负责项目字段消失」「14 个模块回到全开旧行为」，不是页面父子。继续作为部署配置，不伪装成锁 |

### 2.2 `COMPANIONS_ENABLED` 下两条语义锁

`MINISTER_DISPATCH_AUTHORITY` / `PARTNER_TEMPLATES` 挂 `COMPANIONS_ENABLED` 是**页面 / API 语义锁**：
父关时执事路由不挂、执事页打不开，这两个开关没有可达入口；但它们的消费函数本身没有直接读
`COMPANIONS_ENABLED`。这层锁不是「底层函数门」，文档和 UI 不宣称它能让内部调用也停。要补真正函数门，
属于后续 P1。

## 3. `MEMORY_ENABLED` 运行时

### 3.1 已改的活读 gate

| 位置 | 改法 |
|---|---|
| `memory-api.ts` | `MemoryApiDeps.enabled` 支持 `boolean \| (() => boolean)`；`memoryApiEnabled()` 统一取；18 处 `if (!deps.enabled)` 改成 `if (!enabled())`；`sourcesAllowed` 同 |
| `index.ts` | `mountMemoryApi(app, { enabled: () => memoryEngine !== null && flagEnabled("MEMORY_ENABLED") })` |
| `agent/assist.ts` | `taskMemoryBlock` 总闸关直接返回 `""`；`memoryRecallOff` 先看总闸；`recallContext` 总闸关返回 `""`；`projectIndexProvider` 总闸关返回 `undefined` |
| `memory-ingest.ts` / `partner-living.ts` / `partner-proactive.ts` / `work-record.ts` | 原本就懒读 `MEMORY_ENABLED`，未改 |

运行期关掉总闸：`/memory/*` 立即 404，召回 / 任务记忆 / 项目索引停；已经装进内存的引擎不主动卸载，
但所有入口被 gate 住。运行期重新打开：只要 `memoryEngine !== null`，上述路径恢复。

### 3.2 启动顺序的边界（未改）

`loadFlagOverrides()` 在 `index.ts` 主体里调用（约 242 行），而 `memoryEngine` 在 `assist.ts` 模块顶层 IIFE
已经求值。因此：

| 启动时状态 | 引擎 | 运行期打开总闸 |
|---|---|---|
| `.env` `MEMORY_ENABLED=true`，界面覆盖为 false | 已创建（覆盖晚于引擎求值） | 直接可用，无需重启 |
| `.env` `MEMORY_ENABLED=false` | null | 仍要重启才上架 |

这是当前边界，不是「活读 gate 没生效」。要彻底统一，需要把引擎改成动态装配，或把 `loadFlagOverrides()`
提到所有模块求值之前；两者都会改变「启动时关着再打开」的体验，留作后续。

## 4. 前端

### 4.1 插件页

- 清单 / 标题 / 简介 / 分组 / 档位全部来自 `GET /agent/flags` 的 `groups` + `flags` 元数据；
  `settings-switches.js` 已删除 `FLAG_LABELS` / `FLAG_GROUPS` / `FLAG_CHOICES` / `FLAG_SECTION_KEYS`
  四张写死的表，新增普通插件只改 `plugins.json`。
- 子卡用 `effectiveValue ?? value` 画控件；`lockedBy` 非空时拨杆 `disabled` + `aria-disabled`，
  枚举卡直接画成禁用的「关」，卡片加 `is-locked`。
- 徽标「随总闸关闭」带 `data-tip`：显示关、拨不动、存储值保留、总闸重开后恢复。
- 页首计数按 effective；`state.flagsCache` 存整份行；父开关保存成功后，若其它行的 `requires` 包含当前 key，
  就 `loadFlagsSettings()` 整页回读。
- 默认关 / 待重启 / 已改徽标保留；被锁时不再显示「已改」，避免和「随总闸关闭」抢话。
- `scope === "core"` 的卡在标题区多一个描边小徽标「系统核心」，`data-tip` 写明「服务端环境配置是缺省；
  这里改的值会保存，重启后仍保持」；卡片本身仍可正常拨，不因为 core 就禁用。页脚补一句
  「带『系统核心』的开关由服务端环境配置兜底，其余是普通功能插件」。

### 4.2 设置 → 会话

- 自动归档：`loadAutoArchiveSettings()` 读 `ARCHIVE_AUTO_DAYS.lockedBy`，父关时 `disabled` +
  `aria-disabled`，并用 `data-tip` 说明「保留天数不生效；重新打开后按原值恢复」（原生 `title` 会被全局
  tooltip 剥掉，不能用作说明）。自动归档开关保存后重新回读。
- 自动压缩：`loadCompactionSettings()` 算 `enabledOn`；父关时禁用档位按钮 / 百分比 / token 输入，显示
  `.compact-lock` 提示；开关保存后重新回读。

### 4.3 人物页跨层锁

`pfLoadPluginFlags()` 读 `/api/v1/agent/flags`（失败返回空 Map，不挡页面）；`pfWirePersona()` 计算
`memoryRecallLock` / `memoryLock` / `projectionLock`，接到：

| 卡片 | 父 | 锁态 |
|---|---|---|
| 人格模块「学习」 | `MEMORY_ENABLED` | `disabled`、`aria-checked=false`、摘要「关（记忆总闸关闭）」、打开编辑层前提示 |
| 视图卡「记忆 + 项目记忆」 | `PARTNER_MEMORY_RECALL`（它自己还受记忆总闸约束） | `disabled`、摘要「关（…关闭）」 |
| 行卡「结果整理」 | `TOOL_PROJECTION` | `disabled`、摘要「关（工具结果整理关闭）」、点击守卫 |

这三处是 UI 锁；`companion-api` 的 persona / `tool_projection` 写入仍可保存存储值，但运行时被父闸 gate，
不会真的生效。要在服务端也拒绝这类跨层写入，需在 `companion-api` 补 `400 flag_locked`；当前没有做，
因为现有单测把「记忆关着时仍可保存人格模块」当作合法路径。

## 6. 这条会怎么错

- **`hot:false` 父的锁态早于运行时**：`COMPANIONS_ENABLED` 等父切到关闭后，`setFlag` 立即写 env，但消费代码
  要重启才装载；子卡会立刻显示「随总闸关闭」，而父自身还在「待重启」窗口。当前按「配置意图」锁，
  适合让用户先把一整套关好再重启；如果要求严格按「已装载值」锁，需要把 `effectiveFlagValue` 对
  `hot:false` 父改用 boot 值。
- **语义锁不是函数门**：`MINISTER_DISPATCH_AUTHORITY` / `PARTNER_TEMPLATES` 父关时页面不可达，但内部调用
  仍可能绕过；不要让文档把它写成「底层也停了」。
- **人物页直接 API**：跨层子项的服务端写入没有拦；运行时 gate 保证不生效，但存储值会变。若以后要
  「任何路径都不能打开」，再补 `companion-api` 的 400。
- **`.env` 关闭的启动边界**：`MEMORY_ENABLED=false` 写进 `.env` 后，运行期打开仍要重启；`hot:true` 的
  「即时」只覆盖「引擎已存在、只是界面覆盖关掉」这一种。
- **未上页的部署配置**：`PARTNER_PROJECT_MEMORY` / `PARTNER_PERSONA_MODULES` 不在插件页，父子锁管不到；
  继续在人物页写「部署配置」，不要伪装成锁。
- **`scope` 有真实存储差异，不是纯标签**：`plugin` 的配置读 `.data/agent-flags.json`，`core` 仍读 env。
  `core` 目前仍可被界面写（`setFlag` 保留落盘 + 同步 env 的历史兼容）；如果以后要求「系统核心只能改 `.env`、
  界面只读」，需要另加 `editable` 或 `scope=deployment` 的服务端拒绝，不能只靠徽标。
- **清单 JSON 是运行期输入**：`src/plugins.json` 按 `mtime + size` 重新装载，改名称 / 说明 / 分组 / 档位 /
  父子关系不需要重启；坏清单保留上一版并 warn。构建产物把清单复制到 `dist/src/plugins.json`，源码态和
  dist 态都走同一套相对路径。`hot:false` 的消费处仍在模块加载 / 路由挂载时冻结，所以这类开关本身改完
  仍要重启；清单热更新不等于消费代码热更新。
