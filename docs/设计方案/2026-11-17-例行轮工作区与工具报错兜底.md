# 2026-11-17 例行轮工作区与工具报错兜底

> 一句话：例行任务跑错目录、读失败还静默收场，怎么修。

## 结论

四件事一起做，缺一件都还会复发：

1. **执事会话的 cwd 钉在主工作区**，不再跟随界面里"当前项目"这个全局单值；
2. **执事会话不注入"当前项目 / 主文件夹"**，改给"默认目录 + 全部已登记项目 + 勾选只决定记忆召回、不限制目录"；
3. **路径类工具报错补一句"你在哪、主工作区在哪"**，让模型能自己重试；
4. **工具报错轮不许静默、不许推进游标**，主人至少能看见"这轮没跑成"。

## 发生了什么（2026-11-17 08:30，"早上问安"）

证据来自 `agent.sqlite`（会话 2903）、`partners.sqlite`（routines）、`.data/routines.json`：

| 节点 | 实际值 |
|---|---|
| 规则 | 小记 / `30 8 * * *` / `session_mode=persistent` |
| 注入 | `当前项目：student-milk-order`，`主文件夹：<local-project>` |
| 工具调用 | `read(path: "workspace")` |
| 结果 | `ENOENT ... open '<local-project>\workspace'` |
| 收尾 | 模型回 `[[no-update]]`，没有任何重试 |
| 记账 | `routines.json`：`status=success`、`summary="[工具报错:read] "`、**游标推进到 08:30** |

主人那边看到的是：早上没有招呼，也没有任何错误提示。

## 根因

| # | 根因 | 代码位置 |
|---|---|---|
| 1 | 执事会话没有自己的 cwd，每轮取 `currentProject()`；项目选择是**全局单值**，界面点一下就换，执事的例行轮跟着漂 | `agent/lifecycle-harness.ts` env 工厂 → `agent/shared.ts` `sessionCwd()` |
| 2 | 主工作区叫 `Workspace`，模型把 `workspace` 写成相对路径；cwd 是项目目录，于是拼成 `项目\workspace` | 模型侧，触发点是注入文本 |
| 3 | `read` 的 ENOENT 只回绝对路径，没有"当前会话工作目录 / 主工作区"线索，模型无法自行纠正 | `afterTool` 未加工路径类错误 |
| 4 | 安静判定被工具报错压制（`quiet=false`），但产出被 `[[no-update]]` 剔成空串 → 无消息；`shouldAdvanceCursor` 只看 `ok/quiet/skipped` → 失败被记成成功并推进游标 | `routine-quiet.ts` / `routines.ts` / `routine-conditions.ts` |

## 处置

| 项 | 做法 | 开关 |
|---|---|---|
| cwd | `openPartnerSession` / `ensureFreshPartnerSession` 里把 `cwd` 配成主工作区；已对齐就不写库；旧会话被项目污染时一次性纠偏 | `PARTNER_CWD_WORKSPACE=false` 回到旧形态 |
| 注入 | 执事 / 执事轮（判据 = 会话 cwd 就是主工作区，或非 chief 执事）：不写"当前项目 / 主文件夹"，写"默认目录（相对路径基准，不是边界）+ 全部已登记项目（都能去）+ 勾选项目只决定记忆召回"。**记忆挂载与目录可达性解耦**：`projectIds` 只进 `scopeOf`，path-guard 根集合始终是"主工作区 + 所有非归档项目根" | 无（跟随 cwd 修复） |
| 路径提示 | `afterTool`：`read/write/edit` 且 `isError`、输出含 `ENOENT`、参数是相对路径 → 在原错误后追加当前 cwd、主工作区、以及"要读主工作区请写绝对路径" | `PARTNER_PATH_HINT=false` |
| 兜底消息 | `runPartnerTurn` 收轮：有工具报错且正文为空 → 由服务端补一条可见消息（工具名 + 当前 cwd + 主工作区），并作为本轮产出返回 | `ROUTINE_ERROR_NOTE=false` |
| 游标 | `shouldAdvanceCursor` 增加 `toolErrorCount`，有报错不推进 | 无 |

## 刻意不做

- **不改项目选择交互**。`PUT /workspaces/current-project` 的契约本来就是"决定下一个新普通对话的项目归属"，问题在执事/例行轮错误地读了它，不在选择器本身。
- **不改 path-guard 根集合**。边界一直是"主工作区 + 所有非归档项目根"；勾选项目从来不是权限。（2026-11-17 用户拍板：记忆注入与目录可达性解耦。）
- **不改 worker 会话的快照语义**。开发会话创建时钉项目主文件夹是 2026-11-13 拍板的，照旧。
- **不猜文件**。路径失败只给事实（cwd、主工作区），不自动把 `workspace` 改成 `<主工作区>` —— 免得把"文件真的不存在"也吞掉。
- **不动既有会话历史**。纠偏只改 `pi.agent.cwd`，不重写 transcript。

## 这条会怎么错

- 执事默认目录是主工作区（相对路径基准），不是边界；所有登记项目绝对路径都能去，但模型可能仍懒得写绝对路径。
- 路径提示只认 `ENOENT`；权限拒绝（EPERM/EACCES）不在覆盖范围，仍按普通错误走。
- fresh 模式每轮都要配一次 cwd，多一次写库；已对齐时提前返回，常态不会每轮写。
- 兜底消息只在"有工具报错且正文为空"时触发；模型报错后仍写了别的正文时，按有内容处理，不重复补。
