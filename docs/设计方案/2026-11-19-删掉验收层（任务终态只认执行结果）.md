# 删掉验收层：任务终态只认执行结果（2026-11-19）

**状态**：已落地（2026-11-19）。用户拍板："把这个验收模块全删了吧。注意它引用的代码，这个应该没有啥用了，有时候可能还有负面效果。"依据：18 个参考项目调查——绝大多数没有完成后验收，只有 opencode/ZCode 在 `/goal` 模式里做一次文本自检；dim 是最重异类。
**下沉落点**：任务终态模型 → `系统架构.md` 派活段；接口字段删除 → `接口文档.md` 端点3。

## 新模型

任务结果**只由执行事实决定**（`classifyRun`，纯代码）：

| 执行事实 | 任务结果 | 单据走向 |
|---|---|---|
| 被停止 | aborted | aborted |
| 超时 / 进程失败 / 退出码非 0 / REPORT 缺失 | failed | failed |
| REPORT `status=failed` / `progress` | failed | failed |
| REPORT `status=blocked` | blocked | needs_you（有 attention → person/answer） |
| REPORT `status=waiting` | idle | idle（可续跑） |
| REPORT `status=ready` / `dropped` | ready / dropped | **done** |

- 不再有 `review` 阶段、`review.json`、`reviewing` 状态。
- 不再有返工轮（`DELEGATION_ACCEPT_ROUNDS`）、裁判（`DELEGATION_JUDGE*`）、整体目标核对。
- 不再有验收证据 / 过程关口 / 验收项逐项投影（API 与任务中心一并删）。
- worker 自报是终局依据（与 codex/pi/cindy/autoloop/dsh/deepseek 同款）。

## 保留（不是验收）

- `writes` 仍是计划字段：租约（并发写同一路径排队）、worktree 越权写入拦截、任务专线 `[[keyed:task:acceptance]]` 基线（提示词材料）。
- `artifacts` 仍可被 worker 报，作为下游依赖任务的上下文材料（不再判失败）。
- `classifyRun` / `decideBeforeReview`（改名 `decideOutcome`）是新的终态判定。
- 决策上报、自主续行、插话、唤醒全部不动。

## 影响（如实）

- 只读/写类任务都只认 `REPORT.status`；worker 自报 ready 即 done。没有宿主语义核对、没有文件变更核对。
- 返工轮消失：失败单直接 `failed`，要修由人/Agent 重新派。
- 旧单残留的 `review.json` / `reviews` 表 / `repairRound` 字段不读、无害；新代码不再写。
- 回滚 = git revert（无开关；这是删除）。
