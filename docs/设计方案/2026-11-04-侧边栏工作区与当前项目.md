## 现状（2026-11-04 核实）

- projects store 已有：单工作区根（`setWorkspace`）、项目登记表、proposals 确认流；`GET /workspaces`、`GET/POST /projects`。
- **无"当前项目"概念**；任务页只有筛选下拉。
- **写工具无路径校验**：`WRITE_TOOLS = write/edit/bash/powershell/delegate/propose_project`，没有任何 isInside/rootPath 检查；`AGENT_WORKDIR` 全局单值。

## 设计

### 两层模型

| 层 | 是什么 | 管什么 | 配置处 |
|---|---|---|---|
| **最大工作区**（已有概念，补上牙齿） | 单一根目录，项目都登记在它里面 | **物理边界**：write/edit 目标路径必须解析后落在根内，越界硬拒绝；bash/powershell 的 cwd 圈在根内 | 设置页（已有，低频） |
| **当前项目**（新增） | `currentProjectId: string \| null`（null = 主工作区/杂事态） | **逻辑归属**：会话默认 cwd、上下文注入、任务归属；不改变审批行为 | **侧边栏**（新增，高频） |

### 当前项目的三个实际效果

1. **执行目录**：每轮开跑时会话 execution env 的 cwd = 当前项目根（挂点 agent.ts:658，null 时保持 WORKDIR）。
2. **上下文**：系统提示注入一节「当前项目」（项目名 + 根路径），复用现有扩展 sections 机制；主工作区态注入「无特定项目，杂事模式」。
3. **归属**：新任务单自动挂当前项目名（实施时核对任务通道的 project 字段，没有就登记"刻意没有"）。

### 物理边界的诚实边界

- write / edit：路径守卫，硬拒绝（精确路径，拦得住），blockReason 说明"越出最大工作区"。
- bash / powershell：**cwd 圈定**；命令文本里写绝对路径逃逸**拦不住**——登记进 `系统架构.md` 已知边界，兜底靠审批（按需确认档下逐次 ask）。不做命令文本扫描（脆且易绕）。
- delegate：派单 prompt 里的路径同 bash 口径。

### 契约改动

- `GET /api/v1/workspaces` 响应加 `currentProjectId`；
- `PUT /api/v1/workspaces/current-project` body `{ projectId: string | null }`（null = 主工作区），校验：项目必须已登记、存在、在工作区内；错误 400 带说明；
- 手机端不接入（协议无关 JSON，Kotlin 暂不消费）——文档照登记。

### UI：侧边栏项目切换器

- 展开态：「+ 新对话」下方新增项目区——当前项目 pill（点开弹层：项目列表 + 「杂事 · 主工作区」项 + 当前高亮 + 「管理项目」入口跳设置）；数据源现拉 `GET /projects` 不缓存（同模型菜单口径）。
- 轨道态（收起）：一个项目图标按钮（当前项目首字/图标），点开同一弹层。
- 切换即 `PUT`，成功后 pill 更新 + toast「已切到 xx 项目」；无回滚确认（低风险操作）。

### 回滚开关

`CURRENT_PROJECT=false`：端点不接受切换（400）、UI 隐藏项目区、cwd 恒为 WORKDIR、系统提示不注入——一行 env 回到今天形态。

## 明确不做（本轮）

- 按项目/按会话的权限档位；"当前项目内写免审批"（审批行为完全不动，见待决问题）。
- bash 命令文本级越界检测（登记已知边界代替）。
- 多根工作区（次工作区仍在最大工作区内，不引入第二个根）。
- 专家团/负责人分配工作区、Agent 间通信（挂起中）。
- 手机端 UI。
