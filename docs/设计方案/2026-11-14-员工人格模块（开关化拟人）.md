# 员工人格模块（开关化拟人）

**状态**：设计期 → 批1 已派实施（2026-11-14 拍板）
**落地后下沉**：模块与机制 → `docs/基线文档/系统架构.md`；契约（PartnerRow 新字段、persona 端点）→ `docs/基线文档/接口文档.md` 对应分册；冲突以长期文档为准。

## 一、背景与拍板

- 2026-11-08「员工人格化三刀」方案明确**不做情感拟真**。2026-11-14 用户**翻案**：做情感拟真，且把每一块做成开关——干活执事没有情感是设定本身（他的配置就是一个只有岗位职责的存在），陪伴执事才长出印象、心情、日记。翻案理由在案：人格完整度成为每个员工的配置属性，像技能一样按需装配。
- 用户定调：①必选核心强制开，其余全部可开关（关 = 不进提示词、内容保留）；②字段尽可能多（定为 10 模块 44 可选字段）；③员工周报带"他自己的话"要做。
- 2026-11-14 用户三拍板：关系温度 = **五档文字**（不做数值好感度）；**分三批**交付；代码**派 CodeBuddy**，本会话负责任务书与验收。

## 二、调研来源（2026-11-14）

四条路收敛出同一张"定义一个人"的清单：

- **角色卡系**（SillyTavern 卡字段 / Character.AI / lobe-chat）：描述、性格、处境、开场白、示例对话、知识边界。**示例对话是各家验证最有效的口吻锚**；Character.AI 强制要一句定位语。
- **陪伴系**（Replika）：关系等级、以 AI 视角的日记（用户可赞/删）、模拟心情。哈佛商学院 2024 案例（De Freitas）：**身份连续性是陪伴关系的命根**——比聪明重要。
- **拟人群友系**（麦麦 MaiBot，读官方文档全文 2026-11-14）：按人存的人物画像、会衰减/加强的关系记忆、表达与黑话学习、话多话少开关（talk_value）、人设库 profiles。注意：旧博客流传的"心情/好感度数值系统"在现行官方文档中**不存在**，引用时以文档为准。
- **学术系**（Stanford Generative Agents 2023；McAdams 三层人格模型）：自述 + 记忆流 + 反思 + 计划；特质 → 适应 → 叙事身份三层。反思是"人在变化"的机制。

## 三、总设计

一个员工 = **必选核心（强制）** + **可开关模块（逐员工配置）** + **预设（一键填开关）**。

### 3.1 必选核心（不可关，全员一致）

| 项 | 内容 | 为什么不可关 |
|---|---|---|
| 身份节 | SOUL.md：名字/头像/自称/一句话定位/性格/出身故事（生日星座可空） | 没有它他不是"人" |
| 数据红线 | 纪律段中的主人数据红线条目 | 安全不谈判 |
| 教诲通道 | remember / preference（taught）机制 | 不能被教的人是坏掉的 |

### 3.2 可开关模块（10 模块 44 可选字段）

| 模块 id | 内容 | 类型 | 来源 | 生效批次 |
|---|---|---|---|---|
| `expression` | 说话风格、句长倾向、口癖清单、禁忌用语、示例对话×3、备用风格+切换概率、表情习惯、开场白（8） | 静态 | 酒馆+麦麦+Character.AI | 批1 |
| `values` | 在乎什么、他自己的底线、怕什么软肋、喜好/厌恶清单、什么让他来劲、价值观关键词×3（7） | 静态 | Replika | 批1 |
| `scenario` | 当前处境、知识边界（知道什么/不知道什么）、静态人物关系设定（3） | 静态 | 酒馆 scenario+世界书 | 批1 |
| `contract` / `discipline` / `goal` / `workHistory` / `currentWork` | 现有契约四节/纪律段/目标/履历/在办状态感收编为子开关（5） | 现有 | 2026-11-08 三刀 | 批1 |
| `impression` | 对主人的印象分条、关系温度（五档）、温度变化账、对群组成员的印象（4） | 活 | 麦麦人物画像 | 批2 |
| `mood` | 近况一句、心情（枚举+原因可见）、心情影响语气（子开关）、作息时段、闲聊意愿五档（5） | 活 | Replika+麦麦 | 批2 |
| `heart` | 员工日记（可赞/删）、周报末尾一句他自己的话、成长笔记（SOUL 附注层）、愿望清单（4） | 活 | Replika+Smallville | 批2 |
| `learning` | 学主人说话风格、黑话新词、反思频率（3） | 活 | 麦麦表达学习 | 批3 |
| `proactivity` | 追问建议、主动开口时机、挂念提醒（默认关）（3） | 活 | lobe+麦麦 | 批3 |
| `profiles` | 备用人设库+一键切换、场景变体（2） | 静态 | 麦麦 profiles | 批3 |

契约 schema（shared）一次性定义**全部 14 个模块 id**；批次只决定哪些注入生效，避免契约反复动。

### 3.3 开关语义

- **开**：静态字段进提示词，活机制生效。
- **关**：不注入、活模块停止更新；**内容保留**（重开即回，回滚友好）。
- **空字段一律不注入**，不给提示词灌水；每个字段有长度上限（zod 写时校验拦截）。

## 四、存储与契约

- `PartnerRow` 新增 `personaPreset`（`work` | `companion` | `custom`，默认 `work`）与 `personaModules`（JSON：模块 id → bool，缺省 = 预设默认）。
- 静态内容：伙伴家目录 `persona/style.json` / `values.json` / `scenario.json`（字段级 JSON，方便 UI 直填与上限校验）。**SOUL.md 不动**（身份节仍在 SOUL）。
- 端点：`GET/PUT /agent/partners/:id/persona`（读/写 preset + modules + 静态内容；鉴权同现有伙伴端点；对外 id 一律 uuid 口径不变）。
- 活内容（批2）：印象 → 记忆库新 `kind=impression`（带对象维度）；心情/近况 → 伙伴状态字段（系统更新、可手改）；温度 → PartnerRow 五档枚举，变化账进印象记录。
- 前端/手机端契约走 shared 单文件；电脑端先行，手机端批3。

## 五、注入设计

- 静态人格模块（口吻/里子/处境）进 **instructions**（`renderPartnerIdentity` 拼 SOUL 之后，固定顺序：口吻 → 里子 → 处境）——它们是"他是谁"，会话级稳定，利于缓存前缀。
- 岗位类（契约/纪律/目标/履历摘要/在办）维持现状走每轮 system（`buildPartnerTurnContext`），按 M8 子开关裁剪；**数据红线永不裁**。
- 顺序固定、不动态排序；开关切换 = 改缓存前缀，落地时在变更记录登记（工具描述与注册顺序本批不碰）。
- 活模块（印象/心情/近况）进每轮 system 的状态段（批2）。

## 六、活模块更新机制（批2）

- **印象**：会话结算钩子事件驱动更新（复用 work-record"唯一写入口"思路）；每条 ≤120 字、上限 20 条；档案页可见、可手改。
- **温度**：五档（生疏/认识/熟络/亲近/像家人）；系统按事件在同档内微调，跨档移动必须有可解释事件且档案页可见。
- **心情**：枚举（平静/愉悦/低落/烦躁/疲惫）+ 原因一句话 + 更新时间；规则可见（最近被谢→愉悦、连续失败→低落）、可手改；子开关决定是否影响语气。
- **日记/周报/成长笔记/愿望**：挂既有每周盘点例行（E4）扩展，不新造调度；日记用户可赞/删；成长笔记是 SOUL 附注层，**永不回写 SOUL 本体**。

## 七、预设映射

| 模块 | work（默认） | companion |
|---|---|---|
| expression | **关**（要口吻的执事单独开；存量执事提示词零变化） | 开 |
| values / scenario | 关 | 开 |
| contract / discipline / workHistory / currentWork | 开 | 关（红线强制保留） |
| goal | 开 | 开 |
| impression / mood / heart | 关 | 开（批2 生效） |
| learning / proactivity / profiles | 关 | 关（批3） |

`custom` = 用户自由配（服务端强制红线不可关）。预设只填开关与内容草稿，随时改。

> **落地对齐（2026-11-15 批1）**：本表初稿把 work 预设的 expression 写成"开"，任务书写"关"，实施按任务书（CodeBuddy 实测交付）。定案：**work 预设口吻关**——存量执事提示词零变化，开关语义下想要口吻的执事单独打开即可。已建执事存的是完整开关表，改预设默认值不会自动跟随。

## 八、回滚

`PARTNER_PERSONA_MODULES=false`：注入与端点整体退回现行为，UI 隐藏模块区（同 `AUTONOMY_ENABLED` 先例：缺省开，探针/单测覆盖显式 false）。

## 九、明确不做（落地时登记系统架构.md）

数值好感度/绩效化关系分（五档文字替代）；假装身体的生理状态；agent 回写 SOUL 本体；隐形情绪（一切活状态档案页可见+可手改）；员工间自动网状社交演化；工人建档。

## 十、分批与验收

- **批1**：契约（shared + 接口文档）→ 开关骨架与注入裁剪（含 M8 收编）→ 静态模块 M1/M2/M6 → 预设 → 档案页"人格模块"区 → 回滚开关。验收：typecheck + 单测（注入顺序/空跳过/关不注入/红线不可关/false 回旧/预设映射/上限校验）+ http 探针 + 浏览器。
- **批2**：`impression`/`mood`/`heart` 三活模块 + 结算钩子与每周盘点扩展 + 档案页活状态展示。
- **批3**：`learning`（默认关，含对话内容红线口径——风格样本落 persona 家目录、不进日志）、`proactivity`（挂念提醒默认关）、`profiles`、手机端。
