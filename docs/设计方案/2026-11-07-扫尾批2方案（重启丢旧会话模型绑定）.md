# 扫尾批 2 方案：重启后旧会话模型绑定丢失（no_model / not available）

> 状态：**方案随批实施（2026-11-07）**。上位：《2026-11-07-扫尾计划》批 2 / A2。
> 缘起：2026-11-07《长期课题跟进落地》验收记录——服务重启后旧会话报 `no_model null`，新建对话正常；
> 《侧栏调整计划》早有同源登记"真实供应商重启时派生变体可能尚未注册的问题未修"。

## 一、根因（2026-11-07 读码核实）

1. **会话创建即绑模型**：`openChat`（agent.ts:1598/1641）建会话时写 `agent: { model: chatModelRef("off") }`
   ——模型引用是**派生变体 id**（`<模型>#think-<档>`，provider.ts:708），随 durable 会话持久化，重启不丢。
2. **派生变体是懒注册**：`chatModelRef()` 只有被调用时才把变体注册进 Models 注册表（variantSpecs）。
   调用点 = 新建会话 / 切档（applyChatMode、思考档切换）。
3. **重启后注册表只剩基础模型**：旧会话 resume 不走创建路径、若也不切档，它的 `#think-off` 变体无人注册；
   内核跑一轮解析会话模型引用失败 → `Model provider/<模型>#think-off is not available`
   （kernel generation.js:273；ref 为空时 "No model is configured"）。表现为"旧会话全坏、新建正常、重启后才坏"。
4. 任务/研究专线的温度型变体（`<模型>#t…`）在每次派发时现派生现注册，随派自愈；但**重启后续跑**的历史专线会话同样暴露在同一洞上。

## 二、修法（主修一式 + 兜底一式）

**主修：变体随注册表重建确定性预注册。** 每次构建 / 换装 Models 注册表（含重启首建与 providers.json 热更新）
时，对目录里**每个模型**预派生并注册：
- `#think-off` 恒注册（创建路径对任何模型都用它）；
- `#think-low / medium / high` 按该模型 `modelThinkingLevels` 支持域注册（没声明的不注册，避免变体承载
  模型不支持的 reasoning_effort 参数被误配）；
- 任务温度变体若派生参数是确定性的（`taskModelRef` 的规范形），同样预注册；参数非确定性的登记边界（见 §四）。
- 注册动作复用既有 `chatModelRef`/变体派生函数，**不另写第二套派生逻辑**（防两套漂移）。

**兜底：resume 时的自愈检查（ Cheap 版）。** 在既有会话打开路径上，若能以现成 API 读到会话当前 model ref
且注册表查无此号：先按 id 前缀剥出基础模型与档位重新派生注册；基础模型也不在目录（供应商被删/改名）→
回落到当前运行时选择并 `configure` 回写会话，服务端日志记一条（只记 id 与动作，不含对话内容）。
若内核没有便宜的配置读取口，则**不做兜底**、登记已知边界（主修已覆盖聊天会话的全部实际形态）。
两条路里读不到/做不了都允许，实现者在汇报里写明走了哪条。

## 三、明确不改的语义

- **会话创建时绑模型维持现状**：旧会话修好后继续用它创建时的模型，不跟随全局运行时选择
  （"每个对话独立模型"的 UI 是登记过的刻意没有；全局切换影响新会话，现状如此）。
- 用户在会话里显式切模型（模型菜单）走 applyChatMode，照旧只改当前会话。
- 不做"重启后全量回填所有会话"的写库动作（自愈只在打开/运行路径按需触发）。

## 四、登记为已知边界（不修）

- 温度型变体参数若非确定组合，重启后该专线会话首跑前自愈兜底（若兜底实现了）或首跑报错一次后由
  派发路径重派生自愈；真实多供应商环境的逐模型组合不做穷举测试（等真实使用暴露）。
- 供应商被删/改名后的旧会话回落到"当前运行时选择"可能不是用户当初那个模型——这是供应商目录变更的
  自然后果，回落动作在日志可见。

## 五、验证

- 单测：模拟"重启"（注册表重建）后，任何目录内模型的全套应注册变体 id 直接可解析，包括从未被
  chatModelRef 碰过的模型（回归：修复前该用例红）。
- 探针：providers 探针（供应商/切模型链路的家）补"重启后旧会话模型可解析"场景；faux 路径跑通。
- 全量：`pnpm typecheck`、`pnpm --filter @lifediary/server providers`（或改后对应探针）、`pnpm probe`、单测、
  相关 http 探针段。真机真模型的最终确认由派单人验收时做（faux 能覆盖机制，覆盖不了真上游行为）。

## 六、回滚

`MODEL_VARIANT_PRESEEDED=false`（或等价一行 env）→ 回到懒注册形态（即回到本 bug），纯逃生门，预期用不上。
契约无新增端点、无 schema 变化；接口文档只在 env 表与相关节注记；系统架构 provider.ts 行补一句机制。
