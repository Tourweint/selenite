三刀方案的界面批落地后，用户续提三条方向：

## 一、高级开关（运行时开关层）

**调查结论**：16 个用户行为类 env 开关里，绝大多数是**函数内懒读** `process.env`（逐处核对见变更记录），
只有 6 个在启动期冻结（路由挂载 / 工具注册 / 模块常量：执事、群组、宰相、课题、技能管理、执事自建巡逻）。

**机制**（取最小改动面）：
- `.data/agent-flags.json`（`AGENT_FLAGS_PATH` 可换）存界面改过的开关；
- 启动 `loadFlagOverrides()` 把文件值**覆盖写进 process.env**（放在 loadEnvFile/injectProviderKeys 之后、路由挂载之前）；
- `setFlag` 落盘 + 同步写 env → 懒读的消费代码**零改动即热生效**；
- 界面只见白名单（FLAG_DEFS，路径/令牌/密钥类一律不收）；每项标 `hot`（即时 / 重启后生效），UI 如实标注。

**取舍**：不造第二套配置读取（消费代码不改 = 审查面最小）；env 仍是缺省来源，删文件即回滚；
`AGENT_FLAGS_UI=false` 端点不挂（回滚开关口径）。**明确不做**：文件锁、按执事的独立开关、把 AGENT_TOKEN/路径类搬进来。

## 二、技能启停位 + 斜杠调用

**挂载链已核（2026-11-09）**：技能索引（名字+首行摘要）按会话冻结注入系统提示（D5）；
agent 用 `skill` 工具按名字取全文照做——挂载与使用链路本就完整，缺的是启停与快捷入口。

**设计**：
- 启停存储 `.data/skills-state.json`（`AGENT_SKILLS_STATE_PATH` 可换）＝`{enabled:{name:true}}`，**名单外一律视为关**（默认全关口径）；
  `SKILL_STATE=false` 逃生门 = 回到全部进索引的旧行为；
- `createSkillStore` 加 `visible(name)` 过滤：索引 / `names()` / `manual()` 三处同源——关了的技能
  不进索引、工具也取不到（工具侧即时，索引按会话冻结 = 下一个会话生效，文案如实写）；
- 斜杠调用：**不改契约**——用户消息以 `/技能名` 开头（纯文本约定），lifecycle 既有 beforeRequest
  钩子解析（`skillSlashOf` 纯函数）后把手册整份作为本轮 system 注入；关着的技能同样不注入；
- 界面：技能卡加逐条开关 + 「全开/全关」批量（`PUT /skills/:name/enabled`、`PUT /skills/enabled-all`）；
  对话输入 `/` 弹**开着**的技能单（30s 缓存），↑↓/回车/点击补全成 `/名字 `，普通打字不受干扰。

**明确不做**：按执事的独立启停（索引本来就是全局一份）；把启停写进技能目录（`.agents/skills` 是别家的地盘）；
"/"自动展开手册进输入框（注入是服务端的事，客户端保持轻）。

## 三、悬停解释收口

ⓘ 图标退役，`data-tip` 直接挂**标签文字**（rowMarkup / 记忆组头 / 各区标题），悬停即出、光标 help 示意；
状态/结果类（保存中、错误、动态计数、带代码格式的变量名）仍常驻。开机自启、提醒「加一条」、扫码配对、
已登记项目、总管与执事、技能库六处手写常驻解释全部转悬停。
