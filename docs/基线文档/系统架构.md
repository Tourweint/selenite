# 系统架构（lifediary-harness）

> 状态：**2026-10-29 按 TS 实现重写**。当前实现 = `ts/`：Node + TypeScript + Hono + SSE，内核 `pi-durable@1.4.0`。
> 旧的 Java/Spring 版架构（2026-10-25 P1：无状态单体、JWT 与 backend 同密钥、先扣额再透传、`signal/session`）
> **已随实现退役，仅作历史**。契约见同目录 `接口文档.md`。

## 1. 定位

**一个人的通用 Agent。** 跑在自己机器上：模型、记忆、会话、密钥都不外流。
记录（日记、流水账、随手的想法）是它用得最多的场景，但**不是边界**——同一个 Agent 也读文件、翻历史、按指令动手。

```
手机 App（<lifediary 手机仓>，Kotlin/Compose）
   │  HTTP + SSE，Bearer <AGENT_TOKEN 或配对设备凭据>
   ▼
lifediary-harness（本仓库，:39847）
   ├ /api/v1/agent/*            自有协议：对话 / 回读 / 停止 / 用量 / 提醒
   ├ /api/v1/llm/chat/completions  OpenAI 兼容层（给现有 App，零改动接入）
   │        │
   │        ├→ pi-durable：会话 / 任务 / 压缩 / 崩溃恢复 / 用量（SQLite）
   │        ├→ @lifediary/memory：记忆四层（存储 / 抽取 / 巩固 / 召回）
   │        └→ 上游 LLM（百炼 OpenAI 兼容 / faux / mock）
   └ 工具 10 个（读写改跑 + 记住/回忆/提醒 + 技能 + delegate/propose_project）+ 条件注册 5 个（partner_skill_write / partner_manage / group_manage / web_search / propose_topic），执行环境 = 本机
```

| 服务端错误日志 | `.data/server-errors.log`（`AGENT_ERROR_LOG`） | 2026-11-07 起 `app.onError` 把未捕获异常的 message/stack 追加到这里（只记时间/方法/路径/错误，不记请求体与对话内容）。**为什么要文件**：桌面壳用 `cmd.Start()` 拉起服务且不重定向 stdout/stderr，"页面 500"否则完全无迹可查 |

**Harness 自愈（2026-11-07，长驻进程的硬要求）**：pi-durable 的 Session 把存储错误当**终局**——
第一次 `Storage` 抛错就让整份 Session 进 failed 态，此后每次 commit / 读快照都立刻 reject
（`SessionFailed: Session failed after a storage error; close and reopen it`）。
而 `getHarness()` 原来只在**首次**打开时开一次，从不重开；于是一次瞬时 IO 失败（WAL 被抢 /
磁盘抖动 / 杀毒扫描锁库）就会让进程进入"永久 500 到重启为止"的状态——现场表现正是
"页面 500、读历史失败"，同时 `/healthz`、`/policy` 这类不碰 Harness 的端点一切正常。
现在的口径（`agent.ts` 的 `discardHarness` / `getHarness`）：
- 订阅 `harness.closed`（也覆盖失败自动关闭），一旦兑现就丢掉这份并**在后台真正 close**；
- 新实例要等旧句柄交还（`closing`）后再开，避免两份挂在同一个 SQLite 文件上；
- 首次打开失败也不再缓存那份 rejected Promise，下一个请求重新尝试。

**没有做的**（刻意）：不做无限重试。重开后立刻又失败说明不是瞬时问题（磁盘满 / 库损坏），
继续重试只会把 500 变成慢 500；真实错误交给调用方与日志。

**旧口径"无状态、不建库、不落对话内容"已作废**：会话与记忆就是本服务的核心资产，落 SQLite 是刻意设计（关掉界面能继续跑、重启能恢复）。

## 4. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **单用户、无账号**，鉴权 = 一个共享令牌（+ 配对设备凭据；本机页面另有进程内 cookie，2026-11-03） | 个人自用；多用户是另一套系统。令牌是"密码"不是"通行证"，只能回答"你知道密钥吗" |
| D2 | **有状态**：会话/记忆落本机 | 关掉界面能跑完、杀进程能恢复、记忆能跨会话累积 |
| D3 | **历史在服务端**，客户端只发最后一条 user；OpenAI 协议无状态则用首句哈希/`X-Conversation-Id` 折中 | 两边协议并存，服务端适配比改客户端便宜 |
| D4 | **断开 ≠ 取消**：客户端断线只停推送，那一轮继续跑完并落库；真停走 `/stop` | "取消等待"不等于"取消工作"；记忆抽取挂在轮次结束上 |
| D5 | **记忆在 harness**（四层，按会话作用域） | 它是 Agent 的长期状态；手机端不再做记忆策展 |
| D6 | **工具闸门：三档 + 独立审批轴**（2026-11-04 批次二 A1；2026-11-08 扫尾批 8c 形态升级、10-C 审批三档）：`read-only` / `no-shell` / 黑名单照旧；审批轴三档 `ask-all`（写类 ∪ 高危清单全问）/ `ask-critical`（只问高危清单：bash、powershell、delegate、partner_manage、send_to_agent，`AGENT_APPROVAL_CRITICAL_TOOLS` 可覆盖）/ `none`（默认，旧行为）。**缺省 async = 等待态落库**：落 pending、回拒绝性答复、本轮照常收尾（零挂起），人答复后服务端自动 followUp 让模型原样重发，闸门按「工具 + 参数指纹」的一次性放行清单核销；pending 永不自动过期。`AGENT_APPROVAL_MODE=blocking` 回到旧的 120s 挂起 + 超时拒绝（回滚，旧路径整段保留） | pi 只留 `beforeTool` 钩子。三档是"能力边界"，确认是"动作策略"，压成一个枚举无法表达"只读 + 确认"。独立轴默认关 = 旧行为；手机不进聊天流，走全局待办轮询（2026-11-04 批次六统一口径）。**不做工具结果回填**（1.4.0 无此口）——用"模型重发"换零内核改动，代价是每次批准多一轮模型调用 |
| D7 | **回合上限**（默认 100，`AGENT_MAX_TURNS` 可调、0 不限）多路兜底：拦工具 + 指令收尾 + 3 轮后硬停 | 没人看着时模型陷循环会烧 token；再发一句话即新预算 |
| D8 | **日志不含对话内容**（只记条数/字数/耗时/枚举） | 隐私边界；原始错误只进服务端日志（可能含上游地址） |
| D9 | **派单异步受理**（2026-11-03）：`delegate` 立即返回任务单号，后台执行完再发 `delegate` / `attention` 事件并写一条汇报回会话 | 派单可能跑几分钟，不能钉住当前对话；任务本身也不该随这一轮结束而被取消（`DELEGATION_ASYNC=false` 可退回同步） |
| D10 | **项目是派单的硬前置**（2026-11-03）：新活必须带已登记 `project`，项目必须严格位于用户选定工作区内（`realpath` 复核）；新建项目根目录只提交待确认请求，用户确认后才建目录。**设备活豁免（2026-11-08 扫尾批 3-H）**：手机 worker（`CHANCELLOR_EMPLOYEE=phone`）/ 带明确 `targetDevice` 的设备派发不落本机磁盘，`project` 可省、按无项目单受理，本机执行体照旧（`DELEGATION_DEVICE_PROJECT_EXEMPT=false` 回滚，接口文档 §2.7） | 没有落点就不该动工；`..`/符号链接逃逸与"凭空建目录"都必须在受理前拦住（`DELEGATION_PROJECT_REQUIRED=false` 可回滚）；设备活不进 realpath/工作区复核 |
| D11 | **文件占用由调度器强制**（2026-11-04）：任务计划必须声明 `writes`；`(project, 相对路径)` 独占租约 + 30s 心跳；git 项目在 worktree 副本里改、按租约合并；未声明路径的改动判"越权写入"拒绝合并 | 负责人是模型，判断会漏；冲突与越权必须在调度层拦死。冲突进"等待文件"，同一路径不并发写 |
| D12 | **领域负责人上下文自动处理 + 崩溃恢复**（2026-11-04）：到窗口 60% 时正常收尾就换段（交接笔记 `handoff.md`）、未收尾就压缩，绝不问用户；每张单开工写 `inflight.json`，进程启动按四类结算，跨过合并点一律转「待你处理」 | 长会话不能顶到窗口；重启不能把"已改到项目里的活"自动重跑一遍 |
| D13 | **验收按落盘结果核对**（2026-11-04，chancellor 验收快照）：任务声明了 `writes` 时，执行后核对声明路径是否真实**新增 / 修改 / 删除**，任意一种即通过、全部没变才失败；`artifacts` 只做附加校对（对不上记 warning，缺失不判失败）；`dir/**` 先按 `mtime+size` 筛、只对疑似变化文件算 sha1，单目录超过 `CHANCELLOR_SNAPSHOT_COARSE_FILE_LIMIT` 时退化为粗判并记 warning；执行前快照落 `snapshot-before.json`，崩溃续跑读回后仍严格前后对比；子单 `failed` / `needs_you` / `aborted` 时父单不得进 `done`，改走 `needs_you` 并点名 | 把执行者当同事看：以落盘结果而不是自报清单收活；同时保住越权写入、合并失败、CLI 四条件这些硬边界 |
| D14 | **执事 = 普通会话 + 版本冻结身份提示词**（2026-11-05 批次B）：不引入第二套权限系统（闸门/审批/pathGuard 原样生效）；SOUL 双层（磁盘当前值 / 版本快照整轮不变）；例行任务触发层是 durable 任务不是扫描循环；例行轮是自主轮，高危工具强制审批（批次C）。给模型开 routine 管理工具前，必须先把它加进批次C 的 RISK_TOOLS（"授予常驻指令/删除自动化"两类高危才不会漏） | 宿主代码确定性实现生命周期（cindy 红线），提示词只做纪律补充；执事的身份编辑权在人手里 |
| D15 | **总管记忆口径**（2026-11-05 批次D）：主对话本体 = 总管（固定 id `chief`，`CHIEF_PARTNER=false` 回滚），记忆**继续读写 global+session**（主人现有记忆不动，他是主人第一人称助手）；`partner:<id>` 键空间只给执事。执事 = chancellor 宰相穿身份（`managerIdentity{name,soul}` 随派单注入，soul 取版本快照；宰相不接宿主记忆引擎，刻意没有）；`partner_manage` 工具（总管建/停执事）已进 `WRITE_TOOLS` 与自主轮风险表（D14 备忘兑现） | 总管是身份不是隔离对象；两套记忆硬混会互相污染；chancellor 依赖方向单向不破 |

## 6. 部署与安全

- 默认只在本机/局域网跑；`AGENT_TOKEN` 必须配（否则仅 loopback）。
- **CORS 当前 `*`**：上公网前必须收紧来源，否则等于把私人 Agent 敞开。
- 工具以**当前用户权限**执行：`write` / `edit` / `bash` 等价于"你愿意让自己的账号在这台机器上做什么"。
- 密钥只走环境变量（`LLM_API_KEY`），不入库、不下发给客户端、不进日志。

### 6.1 运行时的起停（2026-11-07）

**谁持有进程**：桌面壳（`desktop/runtime.go` 的 `runtimeCtl`）。它是唯一的进程状态
持有者，服务不再只是"探不到就拉一个"——那个函数（`ensureService`）已经退役，因为它
不会记住 PID、也不会停。

- **接口**：`Shell.RuntimeStatus / StopRuntime / StartRuntime / RestartRuntime`，
  设置 → 服务 → 运行时那张卡在用。**页面不能自己干这件事**：它要停的就是自己的后端，
  停下去之后所有 `fetch` 都失败，连状态都问不出来。
- **四态**：`running / starting / stopped / failed`。`stopped`（用户停的）与
  `failed`（自己挂的）必须分开——界面上是两句话。
- **认人**：`stopped` 闩挡住的是**自动路径**（开窗、`watchService` 的失联重拉）；
  托盘的「重新连接」是人的明确要求，**越过闩**。没有这个区分，停完服务后托盘就再也救不回来。
- **以端口为准**：查 PID 先 `netstat` 找监听该端口的进程，查不到才回落到自己记的数——
  PID 会被系统回收，端口上那个才是现在真在服务的。
- **`taskkill` 带 `/T`**：`tsx` 是 loader，会再 fork 真正的服务进程；不带 `/T` 会留孤儿
  占着端口，下次启动直接 `EADDRINUSE`。
- **回滚**：`LIFEDIARY_SHELL_BINDINGS=off` 时整组 `Shell` 不挂，卡片退化成
  「仅桌面端可操作」。
- **开机自启（2026-11-08 扫尾批 4b）**：设置 → 服务 → 运行时的「开机自启」开关走
  `Shell.OpenAtLogin / SetOpenAtLogin`（MyGo 写 HKCU Run，任务管理器可关）；自启的是**壳**，
  服务仍由壳拉起；`LIFEDIARY_SHELL_BINDINGS=off` 时状态读不到，开关键不渲染。

### 6.2 发布形态（2026-11-08 扫尾批 4b）

- **服务端产物**：`pnpm --filter @lifediary/server build`（`scripts/build.mjs`）→ `dist/`：
  esbuild ESM bundle 落 `dist/src/index.js`（与源码 `src/` 同深度，`../web|skills|prompts`
  的相对位才对得上），`dist/index.js` 只是一行入口；资源目录整份复制。`.data` / `.env` 照旧落 cwd。
- **壳**：`desktop/build.ps1` 出 `lifediary-shell.exe`，`-X main.version=<git describe>` 注入版本
  （托盘 tooltip 显示）。**壳仍用 `node --import tsx src/index.ts` 起源码**，`dist` 只保证"能起、
  能服务"，切到 dist 留待下一轮。

## 7. 已知边界与风险

- `pi-durable` 标 **Experimental**：锁版本（1.4.0），不跟 main；跳版本时改动面主要在 `agent.ts`。
- 鉴权只有共享令牌，**不带用户身份**；设备凭据（配对）已实现（2026-11-04 核对，`pairing.ts`）。
- 记忆**偏好已闭环、其余仍是框架**（2026-11-06 核对）：
  - 偏好：会话结束后由 `memory-extract.ts` 做一次**独立**模型调用，只抽"长期偏好"（≤5 条、
    置信度 <0.6 丢弃），落 `kind=preference` 并**改挂更宽的 scope**（主对话 → `global`、
    执事 → `partner:<id>`）——偏好换会话不该失效。每条正文形如
    `偏好\nWhy: …\nHow: …`（照 cindy `feedback` 类与 ZCode 的硬要求：没有"为什么"和
    "何时生效"的偏好，下次照样会错）。模型不可用 / `MEMORY_EXTRACT=rule` → 整条链路
    逐字节回到 2026-11-06 之前（`MEMORY_EXTRACT` 见接口文档 §6）。
  - 其余：事实/经历仍由规则抽取（按句切、一律 `episode`）；`fact` / `entity` 两个 kind
    目前只有 `remember` 工具能写，抽取层产不出来。这是**已知缺口**，不是 bug。
  - 巩固（2026-11-08 扫尾批 6 改口径）：**确定性部分**自动跑，只有三条——
    ① 同 scope + 同 kind + **规范化全等**（trim / 空白折叠 / 全半角统一 / 句末标点剥除）
    → 不新增、importance +0.1；② 时间衰减：importance 按距 `lastRecallAt ?? createdAt` 的天数
    乘性衰减（日系数 `MEMORY_DECAY_DAILY`，默认 0.99，`0` 关），下限 0.1、永不删除，
    读时惰性计算（召回候选打分 + 命中写回，**不做扫描 cron**）；③ 使用强化：召回命中
    `+0.05`、封顶 10（`reinforceImportance`，与 `touchRecall` 同点落地）。
    **语义部分**只出建议：设置页「整理记忆」→ 一次独立模型调用（该 scope 最近 ≤200 条、
    ≤50 条建议）→ 卡片上逐条「应用 / 忽略」；应用才走 `supersede()`（旧记录保留可追溯）。
    自动删改仍然没有（D18）。
  - 导入（2026-11-08）：`POST /api/v1/memory/import` 把旧记忆只增不改地并进来，
    规范化等价跳过并计数（批内也去重、已被取代的也算存在），`source/veracity=imported`，
    不参与去重别人。文件格式与字段见接口文档 §2.15.2。
  - 召回：JS 双字片段打分 + 候选窗口默认 200（`MEMORY_CANDIDATE_FLOOR` 可调，50 = 旧行为）；
    候选集在 SQLite 上走 FTS5 trigram 3-gram 词袋 OR（查询 ≥3 字才启用，0 命中 / 短查询 /
    FTS 不可用回落窗口路径，`MEMORY_RETRIEVER=js` 整体回到批次一行为，2026-11-04 批次三 A2-F）。
  - 注入：偏好单独成段排最前（渲染分组，不改召回算法）；**没有偏好时输出与旧版逐字节一致**。
  - embedding/向量未做——两家参考实现（cindy / ZCode）也都没做，靠"一条事实一个文件 +
    一行 hook + 按需读取"控预算（调研见 `设计方案/2026-11-06-记忆系统调研与用户偏好落地（cindy·ZCode）.md`）。
- 会话管理（列出/重命名/删除）尚未做——这正是"手机本地清单"方案要补的缺口。

### 7.1 我们刻意不做的事（拒绝概念表）

> 2026-11-10 从本节散落的「刻意没有」归拢成一张表，理由以各条原文为准，**不新增口径**。
> 新增「刻意不做」时先登记到这里，免得后来者当成缺失去补齐。

| 不做什么 | 为什么不做（以及什么条件下会翻案） |
|---|---|
| 记忆 embedding / 向量检索 | 两家参考实现（cindy / ZCode）都没做，靠「一条事实一个文件 + 一行 hook + 按需读取」控预算；只有召回质量在真实使用中明显不够、且有预算时再评估。 |
| 自动删改记忆 | 语义部分只出建议，应用 / 忽略由人点（D18）；只有拿到可回滚的删除审计、且用户明确要求时才谈。 |

| 手机寻址自动化（mDNS / DDNS） | 过渡期靠 DHCP 静态绑定或手动改地址；自建中继（固定地址）落地后这项自然不需要。 |
| 一个供应商配多把 key | 单人自用大概率等不到；需要按项目 / 按工作区发 key 时，把 `keyEnv` 升级成数组（有 `schemaVersion` 退路）。 |
| 宰相接宿主记忆引擎 / 吃 `partner:<id>` | 记忆仍靠 chancellor 会话续用 + handoff.md，两套记忆不混；只有 chancellor 侧出现稳定的按身份记忆接口时才改。 |
| 跨电脑执事 | 远程锚点会话不装配身份缝；要做先改跨仓契约（宿主 + chancellor），不是宿主单边加。 |
| 工人身份化 / 建档 | 用完即弃是刻意设计，复用走「续链」（后单带前单产物）；只有「同一工人跨单复用」成为明确需求且续链不够时再做。 |
| per-partner 硬权限档 | 闸门全局一套，契约只写「哪些要申请」，执行归闸门；只有多用户或执事互派需要分权时才拆。 |
| 情感 / 人格拟真 | 产品口径：助手是工具，不演人；不设翻案条件。 |
| 工人层网状互聊 | 执事层 `send_to_agent` 已通，工人规模没到；规模上来且执事层中继不够时再议。 |
| 回顾打分 / KPI 数字 | 周期盘点用自然语言说清「接几单、成几单、什么教训」；只有用户明确要量化展示时，作为可选视图加，不改盘点口径。 |
| 自动创建周回顾规则 | 静默自动轮 = 意外账单；规则由用户配，或主人说一句后执事经 `routine_manage` 自建（首次要人点头）。 |
| work 履历进召回 / 语义合并 / 衰减 | 它是 append-only 台账，每 scope 200 条封顶；只有履历量级大到自然语言检索不够时才考虑索引。 |
| 员工档案页做第二套编辑入口 | 编辑仍走人设页三卡（SOUL / 契约 / 目标）与例行任务编辑面，两处真相会打架；档案页只读是刻意。 |

| 裁判写代码 / 改文件 | 裁判一旦能写，就能把活干了再宣布通过，证据就没了；工具面只有 `read` + 只读白名单 bash 是这条设计的立身之本。只有"裁判 = 执行者"这种形态被明确否定前不改。 |
| 常驻 `/goal` 每空闲判一次 | 我们没有长跑目标会话，收益 < 成本；只做"派单收尾时判一次"（`DELEGATION_JUDGE` 默认关）。 |
| 多模型评审团（LLM-as-judge 互相评） | 单人自用没必要，成本翻倍；先把"能自己查"这条做实。 |
| MCP 外部控制面不暴露清单（2026-11-10 批 16 登记） | 我们**不把这四类能力挂成 MCP 接口**：**审批授权**（`POST /agent/approvals/:callId` 的 approve/reject、`ask_user` 的 answer）、**删除**（会话 / 记忆 / 任务 / 项目）、**凭据**（供应商 key、`AGENT_TOKEN`、设备令牌）、**电脑生命周期**（桌面壳的关机 / 重启 / 停服）。理由：外部控制面拿不到"这次点头是哪个人给、能不能核销"的粒度，一旦暴露就是**把人的判断力外包给一个持 token 的进程**；删除与凭据是单向门，生命周期会让"谁在何时关掉这台机器"失去本地可核对性。**什么条件下会翻案**：真要做 MCP 时先审这一条——必须先有与本地同档的**一次性授权凭据**（每次调用可核销、可审计、不落明文），且删除 / 凭据 / 生命周期三类仍**只留在本地**；否则只开只读与低危写。 |
