# 系统架构（lifediary-harness）

> 状态：**2026-10-29 按 TS 实现重写**。当前实现 = `ts/`：Node + TypeScript + Hono + SSE，内核 `pi-durable@1.4.0`。
> 旧的 Java/Spring 版架构（2026-10-25 P1：无状态单体、JWT 与 backend 同密钥、先扣额再透传、`signal/session`）
> **已随实现退役，仅作历史**。契约见同目录 `接口文档.md`。

## 1. 定位

**一个人的通用 Agent。** 跑在自己机器上：模型、记忆、会话、密钥都不外流。
记录（日记、流水账、随手的想法）是它用得最多的场景，但**不是边界**——同一个 Agent 也读文件、翻历史、按指令动手。

```
手机 App（<lifediary 手机仓>，Kotlin/Compose）
   │  HTTP + SSE，Bearer <AGENT_TOKEN 或配对设备凭据>
   ▼
lifediary-harness（本仓库，:8082）
   ├ /api/v1/agent/*            自有协议：对话 / 回读 / 停止 / 用量 / 提醒
   ├ /api/v1/llm/chat/completions  OpenAI 兼容层（给现有 App，零改动接入）
   │        │
   │        ├→ pi-durable：会话 / 任务 / 压缩 / 崩溃恢复 / 用量（SQLite）
   │        ├→ @lifediary/memory：记忆四层（存储 / 抽取 / 巩固 / 召回）
   │        └→ 上游 LLM（百炼 OpenAI 兼容 / faux / mock）
   └ 工具 7 个（读写改跑 + 记住/回忆/提醒），执行环境 = 本机
```

## 2. 进程与存储模型（**有状态**）

| 状态 | 位置 | 说明 |
|---|---|---|
| 会话 / 任务 / 工具结果 / 用量 | SQLite `AGENT_DB_PATH`（默认 `.data/agent.sqlite`） | `node:sqlite`，零三方 DB 依赖；每任务原子提交，重开进程接着跑 |
| 记忆四层 | 独立库 `MEMORY_DB_PATH` | `MEMORY_ENABLED=false` 可整体关闭（按无记忆运行） |
| uuid ↔ 内部 id 映射 | session 文档 `lifediary.chats`（`byExternal`） | 对外只给 uuid，内部自增整数不外泄 |
| 回合计数 / 撞上限标记 | 进程内 Map | 进程重启归零（可接受：上限是"别无人看管时无限跑"的兜底） |

**旧口径"无状态、不建库、不落对话内容"已作废**：会话与记忆就是本服务的核心资产，落 SQLite 是刻意设计（关掉界面能继续跑、重启能恢复）。

## 3. 模块（`ts/`）

| 路径 | 职责 |
|---|---|
| `packages/shared/src/index.ts` | **契约单文件**：请求/事件 Zod schema、SSE 编解码（增量解码器，处理任意 chunk 切分）。服务端与客户端共用一份 |
| `packages/memory/` | 记忆四层：存储 / 抽取 / 巩固 / 召回 + 引擎装配（作用域按会话） |
| `apps/server/src/index.ts` | 路由：`/agent/chat`、`/messages`、`/stop`、`/usage`、`/reminders`、`/healthz`、调试页 |
| `apps/server/src/agent.ts` | **核心装配**：`Harness`（一进程一份 SQLite）、会话创建与 uuid 映射、`chatStream`、`transcript`、提醒、用量、工具闸门与回合上限 |
| `apps/server/src/openai-compat.ts` | OpenAI 兼容层（会话 id 推导 / `X-Conversation-Id`） |
| `apps/server/src/auth.ts` | 共享令牌校验（保长比较；未配令牌只放行 loopback；失败 403 空体） |
| `apps/server/src/provider.ts` | 模型接入（百炼 / faux / 未配置→mock），key 只走环境变量 |
| `apps/server/src/tools.ts` / `reminder.ts` | `remember` / `recall` / `set_reminder`；`sleepUntil` 落库的定时任务 |

刻意**没有**的：账号/用户表、额度/计费、云同步、多租户隔离、数据库 ORM、定时扫描型 cron（用 durable 的 `sleepUntil`）。

## 4. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **单用户、无账号**，鉴权 = 一个共享令牌（+ 将来的配对设备凭据） | 个人自用；多用户是另一套系统。令牌是"密码"不是"通行证"，只能回答"你知道密钥吗" |
| D2 | **有状态**：会话/记忆落本机 | 关掉界面能跑完、杀进程能恢复、记忆能跨会话累积 |
| D3 | **历史在服务端**，客户端只发最后一条 user；OpenAI 协议无状态则用首句哈希/`X-Conversation-Id` 折中 | 两边协议并存，服务端适配比改客户端便宜 |
| D4 | **断开 ≠ 取消**：客户端断线只停推送，那一轮继续跑完并落库；真停走 `/stop` | "取消等待"不等于"取消工作"；记忆抽取挂在轮次结束上 |
| D5 | **记忆在 harness**（四层，按会话作用域） | 它是 Agent 的长期状态；手机端不再做记忆策展 |
| D6 | **工具闸门只是骨架**（`read-only` / 黑名单），无逐次确认 | pi 只留 `beforeTool` 钩子；接 IM/公网前必须升级为"等人确认" |
| D7 | **回合上限**（默认 30）多路兜底：拦工具 + 指令收尾 + 3 轮后硬停 | 没人看着时模型陷循环会烧 token；再发一句话即新预算 |
| D8 | **日志不含对话内容**（只记条数/字数/耗时/枚举） | 隐私边界；原始错误只进服务端日志（可能含上游地址） |

## 5. 与手机 App 的分工（2026-10-29 定稿）

| 数据 | 权威 | 手机是否留存 |
|---|---|---|
| 日记条目（成稿与派生） | **手机本地 Room** | 全量 |
| 会话清单（`conversationId` / 时间 / 首句 / 轮数） | **手机本地** | 只元数据 |
| 对话正文 | **harness** | 不留，按 id 回读 |
| 记忆 | **harness** | 不留 |

- **不做"列全部会话"接口**（会话多了太重）：手机本地存清单，点开带 id 取正文。
  例外：为"重装/换机恢复清单"，规划了轻量索引接口 `GET /api/v1/agent/chats`（只元数据，见接口文档 §5，**未实现**）。
- **配对**：harness 出一次性码二维码 → 手机换取长期设备凭据（设计见 App 仓库方案 §4.6，**未实现**）。
- **提醒**：方向 = harness 定时间（`sleepUntil` 落库不丢）+ 手机负责响（harness 无推送通道）。**方案待设计**。

## 6. 部署与安全

- 默认只在本机/局域网跑；`AGENT_TOKEN` 必须配（否则仅 loopback）。
- **CORS 当前 `*`**：上公网前必须收紧来源，否则等于把私人 Agent 敞开。
- 工具以**当前用户权限**执行：`write` / `edit` / `bash` 等价于"你愿意让自己的账号在这台机器上做什么"。
- 密钥只走环境变量（`LLM_API_KEY`），不入库、不下发给客户端、不进日志。

## 7. 已知边界与风险

- `pi-durable` 标 **Experimental**：锁版本（1.4.0），不跟 main；跳版本时改动面主要在 `agent.ts`。
- 鉴权只有共享令牌，**不带用户身份**；设备凭据（配对）尚未实现。
- 记忆"只有框架"：抽取是规则版、巩固只做去重、召回是加权打分（中文 `LIKE` 近乎失效，FTS5 待做）。
- 会话管理（列出/重命名/删除）尚未做——这正是"手机本地清单"方案要补的缺口。
- `AGENT_MAX_TURNS` 默认值文档（100）与代码（30）不一致，以代码为准。
