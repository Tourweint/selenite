# 系统架构（lifediary-harness）

> 状态：P1（2026-10-25 立项）。总方案与决策（D1~D8）在 backend 仓库
> `docs/设计方案/2026-10-25-Lifediary-Harness拆分方案.md`，本文只写 harness 侧的实现形态。

## 1. 定位

```
Android App（UI + 本地存储 + 动作执行器 + 本地兜底评估器）
   │  Bearer <登录 JWT>（与 backend 同密钥；AI 通道基址 = aiBaseUrl）
   ▼
lifediary-harness（AI 编排者，本仓库）
   ├ /api/v1/signal/session        信号评估（P1 ✅；advisory、不计额度）
   ├ /api/v1/llm/chat/completions  LLM 透传（P2 ✅；先扣额再透传）
   ├ /api/v1/agent/chat            P3 新增（指令协议）
        │  Bearer <上游 key>                    │
        ▼                                       ├→ 上游 LLM（百炼，SSE）
   TypeSafe Jev（经 Xray 出口代理，451 解法）    └→（内部调用）backend：扣额 / 拉配置
```

**无状态单体**：Spring Boot 3.5 + Java 17，无数据库、无持久化——对话上下文由 App 每轮带来，
即用即丢（D3）。可丢失状态只有两类内存态：频控桶（重启归零，与 backend 同限制）与
ai-config 快照（重启后重拉）。

## 2. 模块

| 包 | 职责 |
|---|---|
| `config` | HarnessProperties（环境变量注入）、**JwtAuthFilter**（与 backend 同 HS256 密钥；fail-closed：secret 未配/过短 = 全 403；校验后把 userId 放入请求属性） |
| `common` | ApiResponse（与 backend 同构）、BusinessException、全局兜底、**IpRateLimitGuard**（频次 + 并发，等价移植） |
| `signal` | SignalController / SessionSignalService（对照 backend 逐行迁移；Jev 四问、归一化、紧凑 state） |
| `llm` | **LlmProxyController**（先扣再转发 → SSE 逐块透传）、**InternalQuotaClient**（幂等扣额，200ms/1s，4029/4010 原样透传，其余 fail-closed 503）、ModelOverride |
| `ai` | **AiConfigPuller**（60s 缓存 + version 增量 + 失败沿用上次成功 + 内置默认） |

刻意**没有**的：Spring Security（纯过滤器足够，行为对齐 backend 的 403 口径）、
JPA/数据源（无状态铁律）、定时任务线程（配置拉取是惰性触发）。

## 3. 关键决策

1. **鉴权与 backend 同一把 JWT（D2）**：校验通过即放行，端点不消费 principal（信号是
   advisory、无用户态）。不建用户表——账号是否存在由 P2 的扣额闸门兜底（扣额 4010 = 拒绝）。
2. **无状态（D3）**：任何请求/响应体不落盘、不进日志；日志只记行数/字数/耗时/枚举结果/configVersion。
3. **密钥只走环境变量**：`TYPESAFE_API_KEY`、`TYPESAFE_PROXY` 绝不入库、绝不进 ai-config 下发
   （backend 后台规划 §2.3 同口径）；ai-config 只承载非秘密的 `ai.*` 策略参数。
4. **配置兜底链（D5）**：拉到新值 → 更新快照；失败 → 沿用上次成功值（日志标 configVersion）；
   从未成功 → 内置默认。每次上游调用日志必带 configVersion（D7 审计闭环）。
5. **自带频控（§8 分工）**：backend 的闸门只护它的 `/auth/**`；harness 的 AI 端点不得裸奔。
6. **契约逐字一致（§7.3）**：与 backend 并存期间，同一入参必须产出同一响应体
   （金样测试锚定 + 真机双端对比）。

## 4. 部署（与 backend 拆分方案 §9 对齐）

- 与 backend **同机或同 VPC**（内部接口延迟是 D1 的 1~5ms 前提）；
- 对公网只暴露本服务端点；backend 内部接口仍只绑内网；
- `JWT_SECRET` 两端同源注入，**换密钥必须同时换**（否则一端全 403）；
- Jev 451 解法随迁：`TYPESAFE_PROXY` 指向 Xray 出口，上线需真机复验；
- 可用性口径（D4）：harness 挂不影响登录/同步/计费；**backend 挂则 AI 链路一起挂**
  （P2 起扣额是前置闸门，fail-closed，接受）。
