# 系统架构（lifediary-harness）

> 状态：**2026-10-29 按 TS 实现重写**。当前实现 = `ts/`：Node + TypeScript + Hono + SSE，内核 `pi-durable@1.4.0`。
> 旧的 Java/Spring 版架构（2026-10-25 P1：无状态单体、JWT 与 backend 同密钥、先扣额再透传、`signal/session`）
> **已随实现退役，仅作历史**。契约见同目录 `接口文档.md`。

## 1. 定位

**一个人的通用 Agent。** 跑在自己机器上：模型、记忆、会话、密钥都不外流。
记录（日记、流水账、随手的想法）是它用得最多的场景，但**不是边界**——同一个 Agent 也读文件、翻历史、按指令动手。

```
手机 App（<lifediary 手机仓>，Kotlin/Compose）
   │  HTTP + SSE，Bearer <AGENT_TOKEN 或配对设备凭据>
   ▼
lifediary-harness（本仓库，:39847）
   ├ /api/v1/agent/*            自有协议：对话 / 回读 / 停止 / 用量 / 提醒
   ├ /api/v1/llm/chat/completions  OpenAI 兼容层（给现有 App，零改动接入）
   │        │
   │        ├→ pi-durable：会话 / 任务 / 压缩 / 崩溃恢复 / 用量（SQLite）
   │        ├→ @lifediary/memory：记忆四层（存储 / 抽取 / 巩固 / 召回）
   │        └→ 上游 LLM（百炼 OpenAI 兼容 / faux / mock）
   └ 工具 10 个（读写改跑 + 记住/回忆/提醒 + 技能 + delegate/propose_project），执行环境 = 本机
```

## 2. 进程与存储模型（**有状态**）

| 状态 | 位置 | 说明 |
|---|---|---|
| 会话 / 任务 / 工具结果 / 用量 | SQLite `AGENT_DB_PATH`（默认 `.data/agent.sqlite`） | `node:sqlite`，零三方 DB 依赖；每任务原子提交，重开进程接着跑 |
| 供应商配置 | `.data/providers.json`（`PROVIDERS_PATH`） | **无密钥结构**：只存 `keyEnv` 变量名；首启按 env 播种，之后以文件为准（§3 `provider.ts`） |
| 运行时模型选择 | `.data/runtime.json`（`MODEL_RUNTIME_PATH`） | `{model:{providerId,modelId}}`；优先级：运行时选择 > `defaultSelection` > 第一个供应商 |
| 记忆四层 | 独立库 `MEMORY_DB_PATH` | `MEMORY_ENABLED=false` 可整体关闭（按无记忆运行） |
| uuid ↔ 内部 id 映射 | session 文档 `lifediary.chats`（`byExternal`） | 对外只给 uuid，内部自增整数不外泄 |
| 回合计数 / 撞上限标记 | 进程内 Map | 进程重启归零（可接受：上限是"别无人看管时无限跑"的兜底） |
| 伙伴档案 / 版本快照 / 会话链接 / 例行任务定义 | SQLite `PARTNERS_DB_PATH`（默认 `.data/partners.sqlite`，批次B） | 家目录 `PARTNER_HOMES_ROOT`（SOUL/USER/workspace/skills，64KB 单槽、原子写）；SOUL 双层：磁盘=当前值、版本行=冻结快照（改完下一轮生效） |
| 例行任务执行账 | `.data/routines.json`（`ROUTINES_STATE_PATH`，原子写） | 回执去重 24h 滑窗 + runs ≤50 条；重启 running→interrupted 不重放 |
| 派单死信 | `delegations.sqlite` 的 `delegation_dead_letters`（批次A A2） | 父单终态后子单结果无处并入的记账；只增不改，主键幂等 |

**旧口径"无状态、不建库、不落对话内容"已作废**：会话与记忆就是本服务的核心资产，落 SQLite 是刻意设计（关掉界面能继续跑、重启能恢复）。

## 4. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **单用户、无账号**，鉴权 = 一个共享令牌（+ 配对设备凭据；本机页面另有进程内 cookie，2026-11-03） | 个人自用；多用户是另一套系统。令牌是"密码"不是"通行证"，只能回答"你知道密钥吗" |
| D2 | **有状态**：会话/记忆落本机 | 关掉界面能跑完、杀进程能恢复、记忆能跨会话累积 |
| D3 | **历史在服务端**，客户端只发最后一条 user；OpenAI 协议无状态则用首句哈希/`X-Conversation-Id` 折中 | 两边协议并存，服务端适配比改客户端便宜 |
| D4 | **断开 ≠ 取消**：客户端断线只停推送，那一轮继续跑完并落库；真停走 `/stop` | "取消等待"不等于"取消工作"；记忆抽取挂在轮次结束上 |
| D5 | **记忆在 harness**（四层，按会话作用域） | 它是 Agent 的长期状态；手机端不再做记忆策展 |
| D6 | **工具闸门：三档 + 独立审批轴**（2026-11-04 批次二 A1）：`read-only` / `no-shell` / 黑名单照旧；`confirmWrites`（默认关）开启后写类工具执行前挂起审批，SSE `approval` + HTTP 答复 + 超时默认拒绝 | pi 只留 `beforeTool` 钩子。三档是"能力边界"，确认是"动作策略"，压成一个枚举无法表达"只读 + 确认"。独立轴默认关 = 旧行为；手机不进聊天流，走全局待办轮询（2026-11-04 批次六统一口径） |
| D7 | **回合上限**（默认 100，`AGENT_MAX_TURNS` 可调、0 不限）多路兜底：拦工具 + 指令收尾 + 3 轮后硬停 | 没人看着时模型陷循环会烧 token；再发一句话即新预算 |
| D8 | **日志不含对话内容**（只记条数/字数/耗时/枚举） | 隐私边界；原始错误只进服务端日志（可能含上游地址） |
| D9 | **派单异步受理**（2026-11-03）：`delegate` 立即返回任务单号，后台执行完再发 `delegate` / `attention` 事件并写一条汇报回会话 | 派单可能跑几分钟，不能钉住当前对话；任务本身也不该随这一轮结束而被取消（`DELEGATION_ASYNC=false` 可退回同步） |
| D10 | **项目是派单的硬前置**（2026-11-03）：新活必须带已登记 `project`，项目必须严格位于用户选定工作区内（`realpath` 复核）；新建项目根目录只提交待确认请求，用户确认后才建目录 | 没有落点就不该动工；`..`/符号链接逃逸与"凭空建目录"都必须在受理前拦住（`DELEGATION_PROJECT_REQUIRED=false` 可回滚） |
| D11 | **文件占用由调度器强制**（2026-11-04）：任务计划必须声明 `writes`；`(project, 相对路径)` 独占租约 + 30s 心跳；git 项目在 worktree 副本里改、按租约合并；未声明路径的改动判"越权写入"拒绝合并 | 负责人是模型，判断会漏；冲突与越权必须在调度层拦死。冲突进"等待文件"，同一路径不并发写 |
| D12 | **领域负责人上下文自动处理 + 崩溃恢复**（2026-11-04）：到窗口 60% 时正常收尾就换段（交接笔记 `handoff.md`）、未收尾就压缩，绝不问用户；每张单开工写 `inflight.json`，进程启动按四类结算，跨过合并点一律转「待你处理」 | 长会话不能顶到窗口；重启不能把"已改到项目里的活"自动重跑一遍 |
| D15 | **总管记忆口径**（2026-11-05 批次D）：主对话本体 = 总管（固定 id `chief`，`CHIEF_PARTNER=false` 回滚），记忆**继续读写 global+session**（主人现有记忆不动，他是主人第一人称助手）；`partner:<id>` 键空间只给手下。手下伙伴 = chancellor 宰相穿身份（`managerIdentity{name,soul}` 随派单注入，soul 取版本快照；宰相不接宿主记忆引擎，刻意没有）；`partner_manage` 工具（总管建/停手下）已进 `WRITE_TOOLS` 与自主轮风险表（D14 备忘兑现） | 总管是身份不是隔离对象；两套记忆硬混会互相污染；chancellor 依赖方向单向不破 |
| D14 | **伙伴 = 普通会话 + 版本冻结身份提示词**（2026-11-05 批次B）：不引入第二套权限系统（闸门/审批/pathGuard 原样生效）；SOUL 双层（磁盘当前值 / 版本快照整轮不变）；例行任务触发层是 durable 任务不是扫描循环；例行轮是自主轮，高危工具强制审批（批次C）。给模型开 routine 管理工具前，必须先把它加进批次C 的 RISK_TOOLS（"授予常驻指令/删除自动化"两类高危才不会漏） | 宿主代码确定性实现生命周期（cindy 红线），提示词只做纪律补充；伙伴的身份编辑权在人手里 |：任务声明了 `writes` 时，执行后核对声明路径是否真实**新增 / 修改 / 删除**，任意一种即通过、全部没变才失败；`artifacts` 只做附加校对（对不上记 warning，缺失不判失败）；`dir/**` 先按 `mtime+size` 筛、只对疑似变化文件算 sha1，单目录超过 `CHANCELLOR_SNAPSHOT_COARSE_FILE_LIMIT` 时退化为粗判并记 warning；执行前快照落 `snapshot-before.json`，崩溃续跑读回后仍严格前后对比；子单 `failed` / `needs_you` / `aborted` 时父单不得进 `done`，改走 `needs_you` 并点名 | 把执行者当同事看：以落盘结果而不是自报清单收活；同时保住越权写入、合并失败、CLI 四条件这些硬边界 |

## 5. 与手机 App 的分工（2026-10-29 定稿）

| 数据 | 权威 | 手机是否留存 |
|---|---|---|
| 日记条目（成稿与派生） | **手机本地 Room** | 全量 |
| 会话清单（`conversationId` / 时间 / 首句 / 轮数） | **手机本地** | 只元数据 |
| 对话正文 | **harness** | 不留，按 id 回读 |
| 记忆 | **harness** | 不留 |

- **不做"列全部会话"接口**（会话多了太重）：手机本地存清单，点开带 id 取正文。
  例外：为"重装/换机恢复清单"，有轻量索引接口 `GET /api/v1/agent/chats`（只元数据，见接口文档 §5；2026-11-04 核对：已实现）。
- **配对**：harness 出一次性码二维码 → 手机换取长期设备凭据（设计见 App 仓库方案 §4.6；2026-11-04 核对：已实现，`pairing.ts`）。
- **提醒**：方向 = harness 定时间（`sleepUntil` 落库不丢）+ 手机负责响（harness 无推送通道）。**方案待设计**。

## 6. 部署与安全

- 默认只在本机/局域网跑；`AGENT_TOKEN` 必须配（否则仅 loopback）。
- **CORS 当前 `*`**：上公网前必须收紧来源，否则等于把私人 Agent 敞开。
- 工具以**当前用户权限**执行：`write` / `edit` / `bash` 等价于"你愿意让自己的账号在这台机器上做什么"。
- 密钥只走环境变量（`LLM_API_KEY`），不入库、不下发给客户端、不进日志。

## 7. 已知边界与风险

- `pi-durable` 标 **Experimental**：锁版本（1.4.0），不跟 main；跳版本时改动面主要在 `agent.ts`。
- 鉴权只有共享令牌，**不带用户身份**；设备凭据（配对）已实现（2026-11-04 核对，`pairing.ts`）。
- 记忆"只有框架"：抽取是规则版、巩固只做去重、召回走 JS 双字片段打分 + 候选窗口默认 200
  （`MEMORY_CANDIDATE_FLOOR` 可调，50 = 旧行为）；候选集在 SQLite 上走 FTS5 trigram
  3-gram 词袋 OR（查询 ≥3 字才启用，0 命中 / 短查询 / FTS 不可用回落窗口路径，
  `MEMORY_RETRIEVER=js` 整体回到批次一行为，2026-11-04 批次三 A2-F）；embedding/向量未做。
- 会话管理（列出/重命名/删除）尚未做——这正是"手机本地清单"方案要补的缺口。
- **后台派单的会话映射只覆盖新单**（2026-11-04，A3a/A3b）：受理回执落库时带上 `conversation_id`，
  **旧行无映射（无法回填）**。重启后靠 chancellor 的 `inflight.json` 结算任务单：
  已落库（A3a）+ 启动恢复终态状态行回灌（A3b，`DELEGATION_RECOVER_REPORT=false` 可关）；
  用户 resume 过的单（`resumeTicket` 不写回执，没有会话映射）与续跑中单的完成仍不回灌
  （登记为覆盖缺口，观察后再议）。
- **项目前置已到执行层**（2026-11-04）：worktree 隔离、路径租约、按租约合并已落地；`CHANCELLOR_TASK_ISOLATION=direct`
  只用于非 git 项目或明确串行场景，非 git 项目不允许并行写同一项目。
- **恢复不自动重派**（2026-11-04）：跨过「合并进项目」的单即使 `DELEGATION_RESUME_POLICY=auto-before-merge` 也转「待你处理」；
  自动续跑最多一次（`resumeCount`），防止重启—续跑—再中断的循环。
- **工作区变更不迁移项目**（2026-11-03）：单工作区，切换根目录后旧项目若落在新根外，派单时会按当前工作区拒绝。
- **一个供应商只配一把 key（单 `keyEnv`，刻意没有）**（2026-11-04 登记）：多把钥匙的场景——按项目/按工作区发 key 的服务（如 Clarity 类，一个令牌对应一个项目）、按 key 限速需要轮换——暂不设计。同一上游要用多把钥匙时，变通办法是登记成多个供应商条目（同 `baseUrl`、不同 `keyEnv`）手动切。底座 `envApiKeyAuth` 本就接受变量名数组，将来把 `keyEnv` 升级成数组有现成退路（`schemaVersion` 起步即可），但单人自用大概率等不到那一天，不预先抽象。
- **手机寻址自动化（mDNS/DDNS 等，刻意没有，等中继）**（2026-11-05 登记）：手机侧存的是电脑局域网地址
  （`serverBaseUrl`），电脑 IP 变动后手机会连不上，需在设置页手动改一次地址；配对令牌不随 IP 变
  （令牌无期限、落 `.data/pairing.json`，重启不丢），**不用重新配对**（2026-11-05 实读 `pairing.ts` /
  手机端 `PairingRepository` 确认"一次配对长期有效"）。自动发现电脑新地址的能力不做——后期自建中继节点
  统一解决：中继持固定地址，手机只连中继，电脑出站长连中继，电脑 IP 变动对手机无感；选型（frp /
  自建 Tailscale 等）与契约改动（手机端 + harness 两端）届时先写方案（现成蓝本：参考项目 cindy 的自建中继
  `docs/self-hosted-relay-plan.md`——哑中继、凭证只存哈希、设备签名防冒充，与本仓配对令牌只存
  sha256 同口径，2026-11-05 调研）。多端登录 / 任务跨设备 / 伙伴认主机的总体方案见
  `docs/设计方案/2026-11-05-多端同步与设备矩阵方案（多端登录·任务跨设备·伙伴认主机）.md`
  （**三阶段已于 2026-11-05 当日落地**，探针 relay/matrix/home 全绿；机制：中继哑路由+盖章 src、
  通道白名单默认拒绝、事件镜像走重放库 250ms 轮询、矩阵派活轮询回报+离线 fail-fast、
  伙伴路由 CAS 在中继+降级 fail-closed+凭证不随行。已知边界：事件重放库只收 HTTP 发起轮次，
  服务端直写帧不进推送流；远端锚点/伙伴专线会话在 durable 列表快照的可见性未定。
  测试教训：tools.ts 静态可达 agent.ts 的链路会破坏"先设 env 再加载"的测试——relay-matrix 对
  agent.ts 只做函数内懒加载，新模块照此办理）。过渡期变通：路由器 DHCP 静态绑定，
  或 IP 变动后手动改地址。
- **主机优先制（2026-11-05，方案 `docs/设计方案/2026-11-05-主机优先制方案（先主机·满溢外流·设备描述）.md`）**：
  中继名册存**唯一任务主机位**（`homeDeviceId`，与伙伴归属 `actors[].homeDeviceId` 是两个概念，
  刻意不合并），由用户经 `POST /api/relay/home-device`（owner 或设备令牌）显式设置、不做自动抢占。
  `targetDevice="auto"` 决策器（`relay-auto.ts`，仍是纯函数）升级 v2：主机在线且未满载**永远选主机**
  （busy 不参与比较——产品口径"大部分工作都给主机用"），主机满载才按 busy 外流，主机离线/未设回落 v1；
  返回带 `pickedHome`，台账同步记。设备 `description`（≤200 字）只进名册投影给人点名参考，
  **不进决策路径**。回滚仍是一条：`DEVICE_AUTO_DISPATCH=false` 关掉整个 auto（含主机优先）。
- **工作区两层模型（2026-11-04，方案见 `docs/设计方案/2026-11-04-侧边栏工作区与当前项目.md`）**：**最大工作区 = 物理硬边界**——`write`/`edit` 的目标路径经 realpath（含符号链接祖先逃逸识别）解析后必须落在工作区根内，越界硬拒绝（`path-guard.ts`，挂 beforeTool 审批之前 + 批准后复判；未设工作区旁路）；**当前项目 = 逻辑归属**（`currentProjectId`，主工作区=杂事态）——会话执行 cwd、系统提示注入、任务归属跟它走，侧边栏切换，审批行为不因项目改变（用户定调：默认按需确认）。**bash/powershell 不做命令文本扫描是已知边界**：cwd 圈在边界内，命令里写绝对路径逃逸拦不住，靠审批兜底；`CURRENT_PROJECT=false` 一行回滚到无当前项目形态。
- **手下伙伴 = chancellor 分管宰相（批次D D2，2026-11-05，契约见 `接口文档.md` §2.11）**：`POST /api/v1/partners` 带 `domain` = 建手下——宿主 `ensureManager(domain, { partnerId })` 建宰相目录 + 伙伴档案（SOUL 一句话播种）+ `partner_session_links` 记 `role='delegation'`；`delegate(domain=x)` 时按 domain 反查伙伴，命中则请求带 `managerIdentity={name, soul=当前版本快照}`（宿主截 ≤4KB、单次派单内不变），chancellor 只透传、原文注入分管提示词「## 你是谁」；删手下 = 删档案 + `archiveManager` 把领域目录改名 `.archived-`（runs 历史保留）。查不到的 domain 照旧，兼容旧领域。**刻意没有（登记防补齐）**：宰相不接宿主记忆引擎、不吃 `partner:<id>` 键空间（记忆仍靠 chancellor 会话续用 + handoff.md，两套记忆不混）；worker（codebuddy / qoder / phone）不是角色、不给身份（它们是手，宰相才是脸）；不做跨电脑手下（远程锚点会话不装配身份缝）；不做 D3 `partner_manage` 工具；`domain` 建后固定不可 PATCH 改。`partner_session_links` 的 delegation 行用 `session_id=0` 占位（不是真实宿主会话），`partnerIdOfSession` 以 `session_id > 0` 过滤。
