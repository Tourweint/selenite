### 2.18 权限策略（`/api/v1/agent/policy`，2026-11-03 访问档 / 2026-11-08 扫尾批 10-C 审批三档）

界面「权限档」三档（能力边界）与「审批档」三档（确认策略）的读写端点，与 §2.5 审批端点、§4 闸门同源
（`ts/apps/server/src/agent/policy.ts` 的 `getPolicy` / `setPolicy` / `readOnlyBlockReason`，
路由 `ts/apps/server/src/index.ts:422/424`）。`beforeTool` 每次调用都重判策略，
**改完立刻生效、不用重启**；选择落 `.data/policy.json`，下次启动沿用，env 只是初值
（`AGENT_TOOL_POLICY` → `access`、`AGENT_BLOCKED_TOOLS` → `blocked`、
`AGENT_CONFIRM_WRITES` → `approvalLevel` 的旧布尔映射，见 §6）。两轴独立：三档是能力边界，
`approvalLevel` 是确认策略；被档位拦下时不问直接拒（拦优先，`approval-policy.ts`）。

#### `GET /api/v1/agent/policy` —— 当前策略

```json
{ "access": "full", "blocked": [], "approvalLevel": "none", "confirmWrites": false, "label": "完全访问", "approvalMode": "async", "attachments": true, "fileAttachments": true, "editResend": true }
```

- `access`：`full` / `read-only` / `no-shell`；`read-only` 拦 `WRITE_TOOLS`（写/改/跑/派活/建群等），
  `no-shell` 只拦 `bash` / `powershell`，`blocked` 黑名单命中即「工具 X 已被禁用」（优先级最高）。
  2026-11-14 起两档都先试一次**查看命令**判定（`isViewOnlyShellCommand`：词表只有
  `cat`/`type`/`head`/`tail`/`ls`/`dir`/`grep`/`rg`/`find`/`wc`/`stat`/`file`，看旗标，
  路径必须落在已登记根集合内）——命中则放行，其余照旧拦。`AGENT_READ_VIEW_COMMANDS=0` 关掉回旧形态。
- `label`：`access` 的中文展示名（「完全访问」/「只读」/「在工作区内修改」），前端直接显示。
  2026-11-14 起 `no-shell` 的对外名字改成「在工作区内修改」（值不变，老客户端照旧）；界面上三档
  从左到右 = 只读 → 在工作区内修改 → 完全访问，完全访问恒在最右端。
  三档的副文与语义：只读 = 能看能查（ls / cat / grep 这类查看命令），不改文件；
  在工作区内修改 = 文件只改工作区和项目里的，命令也只限查看；完全访问 = 能改文件、能跑任何命令
  （抽屉里位置窄，写的是短句「能改文件、能跑命令」）。
- **`approvalLevel`（2026-11-08 扫尾批 10-C）**：审批三档——`ask-all`（全部问我：`WRITE_TOOLS` ∪ 高危清单全问，
  旧 `confirmWrites:true`）/ `ask-critical`（只问重要的：只问高危清单）/ `none`（全不问，旧 `confirmWrites:false`）。
  高危清单缺省 `bash` / `powershell` / `delegate` / `partner_manage` / `send_to_agent` / `routine_manage`，
  `AGENT_APPROVAL_CRITICAL_TOOLS` 可整体覆盖（§6）。
- **`confirmWrites`（派生字段，兼容旧客户端）**：`approvalLevel !== "none"` 时为 `true`。
  新客户端读 `approvalLevel`；旧客户端只认布尔，语义是"是否至少有一部分操作会问"。
- **`approvalMode`（2026-11-08 扫尾批 8c，纯增量只读投影）**：`async`（缺省，等待态落库、答复触发续跑）
  或 `blocking`（旧的 120s 阻塞形态）。来自环境变量 `AGENT_APPROVAL_MODE`（§6），**不落
  `.data/policy.json`、不可通过 `POST` 修改**。前端据此决定审批卡显示倒计时（blocking）还是
  「等待处理」（async）。
- **`attachments` / `fileAttachments` / `editResend`（纯增量只读投影）**：
  三个**环境变量**开关（`AGENT_ATTACHMENTS` / `AGENT_FILE_ATTACHMENTS` / `AGENT_EDIT_RESEND`，§6）
  的当前值，前端据此决定渲染不渲染附件按钮 / 任意文件入口 / 编辑入口。它们不可通过 `POST` 修改
  （改的是 env），`POST` 的响应也带这三个字段（形状同 `GET`，仍不含 `label`）。
  `fileAttachments` 是 2026-11-13 附件走路径新增：`false` 时上传端点 404、前端只留图片内联。

#### `POST /api/v1/agent/policy` —— 改策略（部分更新）

请求体字段都可选，只更新给出的；`blocked` 非数组时该字段忽略：

```json
{ "access": "read-only", "blocked": ["bash", "powershell"], "approvalLevel": "ask-critical" }
```

旧布尔仍收：`{ "confirmWrites": true }` → `ask-all`、`false` → `none`；同一请求里
`approvalLevel` 优先于 `confirmWrites`。成功回更新后的完整策略（**不含 `label`**，带审批形态与两个能力开关）：

```json
{ "ok": true, "access": "read-only", "blocked": ["bash", "powershell"], "approvalLevel": "ask-critical", "confirmWrites": true, "approvalMode": "async", "attachments": true, "fileAttachments": true, "editResend": true }
```

| 情形 | 返回 |
|---|---|
| `access` 不是 `full` / `read-only` / `no-shell` | `400 {"error":"bad_request","message":"access 只能是 full / read-only / no-shell"}` |
| `approvalLevel` 不是 `ask-all` / `ask-critical` / `none` | `400 {"error":"bad_request","message":"approvalLevel 只能是 ask-all / ask-critical / none"}` |
| 带 `confirmWrites` 但不是布尔值 | `400 {"error":"bad_request","message":"confirmWrites 只能是布尔值"}` |
| body 非 JSON / 空体 | 各字段都不更新，返回当前策略（`{ok:true, …}`） |
| 写 `.data/policy.json` 失败 | 仍 200，本次内存态生效（服务端日志告警；重启回落旧值） |

**落盘与读档兼容**：`policy.json` 存 `approvalLevel`（不再写 `confirmWrites`）；读档时新字段优先，
老文件只有 `confirmWrites` 就按 `true→ask-all / false→none` 映射，两者都没有才回落 env 初值。

**权限**：与其他 `/api/v1/*` 同——`Authorization: Bearer <AGENT_TOKEN>` 或本机页面 cookie（§1），
失败一律 **403 空体**。端点不回显任何密钥。前端调用：`web/app.js` 的 `loadPolicy()`
（全屏设置页 `#policy-switch` / `#policy-approval-level`）与抽屉版 `cs-policy-*`（`GET` 读档、`POST` 回写）。

### 2.19 技能管理（2026-11-08 扫尾批 9-S；2026-11-08 批 10-A 加标准用户目录与两种形态；`SKILLS_ADMIN` 默认开）

技能 = 给模型的操作手册，两种文件形态都认：

- **扁平 `<name>.md`**（本仓库原生形态）：**第 1 行 = 索引用摘要，其余 = 正文**；`name` 即文件名。
- **目录 `<name>/SKILL.md`**（标准 agent skill 形态）：`name` = 目录名，摘要 = frontmatter 的 `description`，
  正文 = frontmatter 之后的内容；frontmatter 其余字段**忽略**（只解析单行 `key: value`，不解析多行块）。
  同一目录里两种形态同名时**扁平优先**。

`name` 受管理面白名单约束（小写字母 / 数字 / 短横线 / 下划线，1-64 字符，不能以 `-`/`_` 开头，
与 `partner_skill_write` 的 slug 同一条正则）；白名单外的名字（含 `.agents` 里的点号名）模型侧照常加载，
只是不出现在管理列表里。

**读取链**（`ts/apps/server/src/skills.ts` 的 `resolveSkillsDir()`，**先到先得**，同名只有第一个来源生效）：

1. `AGENT_SKILLS_DIR` 显式指定（部署自选目录，不替用户创建；显式时**取代**用户目录槽位，不再建 `.lifediary\skills`）；
2. 用户目录 `%USERPROFILE%\.lifediary\skills`——**不存在则首次访问自动 mkdir**（管理界面写这里）；
3. 标准用户技能目录 `%USERPROFILE%\.agents\skills`——跨工具共享的 agent skills，**只读**（不存在就跳过）；
4. 应用目录 `apps/server/skills/` 兜底（内置手册）。

管理端点的**写/删只落主目录**（1 / 2，用户目录建不出来时才是 4）：`GET` 列表合并全链并给每个 item 标来源；
`GET :name` 任意来源都可读；`.agents` 里的技能**不提供写/删**（连"在主目录写一份同名影子副本"也拒绝，
否则用户会以为改的是那一份）；应用目录的内置手册仍允许被用户目录同名覆盖（9-S 就有的合并语义）。
`SKILLS_ADMIN=false` 时本节端点全部不挂（404 = 未启用）。

| 端点 | 说明 |
|---|---|
| `GET /api/v1/agent/skills` | `{ok, dir, origin, dirs:[{dir,origin,writable,exists}], items:[{name, summary, size, updatedAt, origin, writable, form, core, enabled, usageCount?, lastUsedAt?, stale}]}`；`dir`/`origin` = 主目录（写目标），`items` 按读取链合并；`form` = `flat` / `dir`；`origin` = `env` / `user` / `agents` / `app`，`writable=false` 即只读来源；`core`（**2026-11-16 工具裁剪 A**）= 是否代码内置技能，`core=true` 时 `enabled` 恒为 `true`（即使启停位里没有）；`enabled` = 启停位（2026-11-09，见下）；`usageCount` / `lastUsedAt` / `stale` = 技能用量账（2026-11-10 批 17，见下）。**2026-11-15** 可带 `?partnerId=<id>`：每项追加 `partnerEnabled`（该人实际可用 = 全局开 或 该人覆盖开；`core=true` 时恒 `true`）与 `partnerOverride`（全局没开、该人独开；`core=true` 时恒 `false`）；不带参数时形状不变 |
| `GET /api/v1/agent/skills/:name` | `{ok, name, content, origin, writable, form}`：按读取链取第一个同名技能，`content` = **原始文件全文**（目录形态含 frontmatter）；名字不合法 400、不存在 404 |
| `PUT /api/v1/agent/skills/:name` | body `{content}`；只写主目录，不存在即新建。成功 `{ok, name, created}`。名字不合法、正文超 64KB、只有一行（没有正文，不会进索引）、只读来源同名（`.agents`）→ 400。**新建默认 `enabled=false`（默认全关）** |
| `PUT /api/v1/agent/skills/:name/enabled` | body `{enabled: boolean}`（2026-11-09 界面细节批二）：开 = 进技能索引且 `skill` 工具可取；关 = 索引随**下一个会话**刷新（D5 按会话冻结），工具侧即时取不到。成功 `{ok, name, enabled, note}`；名字不合法 400、技能不存在 404；**core 技能一律 `400 {"error":"bad_request","message":"系统内置技能，始终可用，不能关闭"}`** |

| `DELETE /api/v1/agent/skills/:name` | 只删主目录；成功 `{ok, name}`，不存在 404（启停位另有，删除仍只删文件）；`.agents` 同名 → 400（不能在这里删） |

- **启停位（2026-11-09 用户拍板：技能默认全关）**：状态存 `.data/skills-state.json`（`AGENT_SKILLS_STATE_PATH`  可换）＝`{enabled:{name:true}, partners:{partnerId:{enabled:{name:true}}}}`，**名单外一律视为关**；`SKILL_STATE=false` 逃生门 = 回到全部进索引的旧行为（此时列表的 `enabled` / `partnerEnabled` 也按全开显示）。
  注入侧（`assist.ts` 的 skillStore filter）索引 / `names()` / `manual()` 三处同源过滤——关了的技能
  不进索引、`skill` 工具也取不到（工具侧即时，索引按会话冻结）。`SKILLS_ADMIN=false` 时启停端点随整组不挂。
- **内置技能 core（2026-11-16 工具裁剪 A）**：`ts/apps/server/src/core-skills.ts` 的 `CORE_SKILL_NAMES`
  是唯一名单（当前只有 `delegate`），`isCoreSkill(name)` 判定；**只认代码常量，不认技能文件 frontmatter 自封**。
  core 技能始终进索引、始终能被 `skill(name)` 取到，**不受启停位（默认全关）与按人可见性影响**——
  工具政策手册（如 `skills/delegate.md`）关掉就等于让工具描述失去配套说明。实现上 `createSkillStore`
  的可选 `isCore` 让 `canSee` 短路（索引 / `names()` / `manual()` 三处同源），普通技能行为不变。
  管理面：列表 item 增 `core`、单条启停对 core 返回 400、`enabled-all` 跳过 core（`count` 只算普通技能）、
  带 `partnerId` 时 `partnerEnabled` 对 core 也给 `true`；技能页 core 行不渲染开关，只显示只读「内置」标记。
  A 不是开关型能力，回退按提交回退（普通技能零影响）。
- **按人可见（2026-11-15）**：`partners.<id>.enabled` 只存"全局没开、但这个人要开"的技能。
  全局开 → 所有执事可见，个人页锁死不能按人关；全局关 + 覆盖开 → 只对这个人可见；全局关 + 无覆盖 → 不可见。
  按人开关走 `PUT /api/v1/partners/:id/skills/:name/enabled`（见分册4）：全局已开 **409**，全局未开写/删覆盖位。
  可见性只在会话第一次渲染索引时冻结，改开关对下一个会话生效。
- **用量账（2026-11-10 批 17 §四）**：`skill` 工具每**取到**一份手册给该技能 +1，落
  `.data/skill-usage.json`（`AGENT_SKILL_USAGE_PATH` 可换）＝`{usage:{name:{count,lastUsedAt}}}`。
  列表回 `usageCount` / `lastUsedAt`；距 `lastUsedAt ?? 文件 mtime` 超过 **90 天**标 `stale: true`。
  **只标记，不删、不移**——技能只能由人删；`SKILL_USAGE=false` 时不计数、列表也不回这三个字段（一行回滚）。
- **斜杠调用（2026-11-09 用户口径）**：对话用户消息以 **`/技能名`** 开头（名字规则同管理面白名单，
  后跟空白或行尾）→ 该轮装配时把手册整份作为 system 注入（lifecycle 既有 beforeRequest 通道），
  用户消息其余部分是指令；**不新增契约字段**，手机端同享。关着的技能不注入。

- **写操作锁死在主目录内**：名字白名单挡穿越，写/读/删前再做一次 realpath 复核（复用
  `path-guard.ts` 的 `realTargetOf` / `insideOrEqual`）——目录里若有指向外部的符号链接，读写一律 400 `bad_request`，
  并**不出现在管理列表里**（模型侧加载器仍按原样可用）。
- **正文上限 64KB**（与执事 SOUL/USER/技能单槽同口径）；写盘先临时文件再改名（不产生半份手册）。
- 鉴权与其他 `/api/v1/*` 同（失败 403 空体）；域内错误一律 400 带说明，找不到 404。
- **增删改与启停只影响下一个会话**（D5 既有取舍：技能索引按会话冻结，首轮渲染后不再变；
  `skill` 工具取手册不受此限——启停即时）；设置页文案如实说明。
- ~~已知边界：`.agents\skills` 里的技能会全部进索引~~（2026-11-09 解决：启停位默认**全关**，
  只注入用户开着的技能；原"126 条约 3.2 万字全量注入"的体积 concern 随默认关一并消除）。

### 2.20 插件（行为开关，原「高级开关」；2026-11-09 界面细节批二；`AGENT_FLAGS_UI` 默认开；2026-11-16 独立成页）

把散在 env 里的**用户行为开关**搬进设置 → **插件**（2026-11-15 原名「高级开关」→「行为开关」；2026-11-16
用户拍板整页从「服务」拆出，独立成「插件」——这些开关就是做出来的功能，按插件卡片墙摆；服务页只留
通知 / 鉴权 / 运行时）。机制（`flags.ts`）：
**清单从 JSON 读（运行期）**：`src/plugins.json` 是唯一清单（7 组 + 93 项，含中文名 / 说明 / 分组 / 类型 /
档位 / 默认值 / scope / requires / surface）；`flags.ts` 按 `mtime + size` 运行时读（`AGENT_PLUGINS_PATH` 可换），
`FLAG_DEFS` 是运行期视图，前端不再维护写死的 `FLAG_LABELS` / `FLAG_GROUPS` / `FLAG_CHOICES` /
`FLAG_SECTION_KEYS`。构建把清单复制到 `dist/src/plugins.json`；改清单不用重启，坏清单保留上一版并 warn。
**配置（2026-11-16 再续：plugin 以 JSON 为真源）**：`.data/agent-flags.json`（`AGENT_FLAGS_PATH`）存界面改过的值。
`scope=plugin` 的项在运行时直接读这份 JSON（按 `mtime + size` 缓存；`setFlag` 只写 JSON，不写 `process.env`），
文件里没有该键才回落部署 env / 清单默认值。`scope=core` 的项仍以部署 env 为主：启动 `loadFlagOverrides()`
把文件覆盖写进 `process.env`（在 loadEnvFile / injectProviderKeys 之后、路由挂载之前），`setFlag` 保持
落盘 + 同步写 env 的历史兼容。消费代码统一用 `flagEnabled()` / `flagValue()` 取活读值（plugin 读 JSON，
core 读 env）；`hot:true` 的开关当场生效，启动期冻结类（路由挂载 / 工具注册 / 模块常量）标 `hot:false`；
界面只在改动还没被进程装载时标「待重启」，重启后自动消失。`plugins.json` 也已改成运行期读；
`.data/agent-flags.json` 的 plugin 配置不重启也能被下一次读取看到（带缓存，不是每次重解析）。
`hot:false` 的消费代码仍在启动期冻结，所以这类开关本身改完仍要重启。
**记忆总闸运行时（2026-11-16 父子实现）**：`MEMORY_ENABLED` 仍标 `hot:true`，但引擎是启动期装配；
运行期关掉后 `/memory/*` 的 `enabled` 已改成活读函数（`memory-api.ts` 的 `MemoryApiDeps.enabled` 支持
`() => boolean`），召回 / 任务注入 / 项目索引 / `recallContext` 也都先过 `flagEnabled("MEMORY_ENABLED")`，
所以运行期关闭会立即 404 / 停注入。**边界**：`.env` 本来就是 `MEMORY_ENABLED=false` 时引擎为 null，
运行期再打开仍需重启；如果只是界面覆盖关掉、`.env` 仍为 true，引擎已装好，重开可直接用。要彻底统一需把引擎
改成动态装配（见 `docs/设计方案/2026-11-16-插件中心与父子开关（调查）.md` §3.2）。

  标题固定「按需工具（初始不加载）：…」+ 每行 `- name：一句话摘要`（摘要复用 `toolSummaryOf`）
  + 一句 `tool_search({name})` 提示。只列当前会话 `agent.deferred`（已启用、未被 tool_search 加载）
  的工具，**再剔掉被取消勾选的名字**（同上）；一个都没有 → 整段省略。默认开销页把该段算进基线
  （见接口-端点1 §2.2.5）。
- **与工具勾选（B）的交界**：`applyPartnerToolSelection` 期望 offer 集合 = 非 deferred 未取消
  ∪ 已加载 ∪ **按人提升**，再减取消名单；写 `modelTools` 时把本会话已加载 / 已提升的 deferred
  带回 `add`，被取消的进 `remove`。**只要有被取消的 deferred 就必须写一次**
  （即使集合没变）——否则它留在 deferred 里，既能被加载又出现在清单里。运行时一律认注册对象上的
  `tool.deferred`（不读配置文件），避免"配置已改、Harness 还没重开"时口径漂移。
- **能力声明**（`tool-capability.ts`）：`readOnly:true` / `destructive:false` /
  `sideEffectScope:"none"` / `riskLevel:"low"` / `needsApproval:"never"` / `concurrentSafe:true`，
  说明「只把已注册的延迟工具加载进本会话工具面；不动工作区、不起进程、不写盘」。
  **不进 `WRITE_TOOLS`**（与 `approval-policy.ts` 正交：它只改会话工具面，不写盘、不起进程）。
- **回滚**：`AGENT_TOOL_INDEX=false/0/off`（§6）→ 不打 `deferred`、不注册 `tool_search`、
  不渲染 `tool_index`、默认页也不含该段，一行回到本批之前的全量工具形态。
  与 `PARTNER_TOOLS_ENABLED` 正交：后者管"勾选屏蔽"，本开关管"是否走按需加载"。

#### 2.22.1 全局工具池端点（2026-11-17 设置 → Agent → 工具）

| 端点 | 说明 |
|---|---|
| `GET /api/v1/agent/tool-pool` | `{ok, enabled, deferred:[…], defaults:[…], applied:[…]\|null, restartPending, tools:[{name,summary,description,parameters,chars,tokens,deferred}]}`。`deferred` = 配置文件里的按需名单；`defaults` = 代码默认 8 个（「恢复默认」用）；`applied` = 当前运行的 Harness 实际用的名单（null = 还没装配过）；`restartPending` = 两者不同（已保存待重启）。`tools` 从 `modelToolCatalog()` 现取（含 deferred），`deferred` 按**配置**算；`summary` = 截断摘要（列表行），**`description` = 描述原文、`parameters` = 参数 JSON Schema 原文（2026-11-17 补，展开行看完整定义）**；`chars/tokens` = 工具名 + 描述 + 参数精简 JSON 的估算（口径同设置→上下文，`token-estimate.ts`）。**不返回分组**（2026-11-17 用户拍板：这页不展示硬编码分组，看完整定义就够；分组仍只用于人设页勾选目录）。`enabled` = `AGENT_TOOL_INDEX`；`cache-control: no-store`。鉴权同 `/api/v1/*` |
| `PUT /api/v1/agent/tool-pool` | body `{deferred: string[]}` = 新的按需名单（**全量替换**；空数组 = 全部常驻）。校验：非数组 / 元素非字符串 / >64 → 400；未知名 → 400 带 `unknown`；**`tool_search` → 400**（自锁）。`AGENT_TOOL_INDEX=false` → 400（不可改）。成功原子写 `.data/tool-pool.json` 并返回**同 GET 形状**（`restartPending:true`）。**只写文件，不重开 Harness、不中断正在跑的轮次**；重启服务后生效 |




### 2.23 执行器设置（2026-11-16 多 CLI 打手适配）

任务中心派活用哪个 CLI、每个 CLI 用什么模型 / 权限。落 `.data/executor.json`
（`EXECUTOR_CONFIG_PATH` 可换落点），**每次派单懒读**，改完不需要重启；下一次派活生效。
文件不存在或 `EXECUTOR_CONFIG=false` 时回落 `.env`（`CHANCELLOR_EMPLOYEE` /
`CHANCELLOR_*_MODEL` / `CHANCELLOR_*_PERMISSION`，见主册 §6），行为与加这层之前一致。

| 端点 | 说明 |
|---|---|
| `GET /api/v1/agent/executor` | `{enabled, employee, profiles, kinds, locked, lockedReason?, path}`。`kinds` = 控件元数据（`id / label / selectable / permissions / modelHint / note`）；`profiles` = 每个本地执行器的 `{model?, permission?}`；`locked=true` = 当前执行器是 `.env` 指定的 phone / mcp，界面不改 |
| `PUT /api/v1/agent/executor` | body `{employee, profiles?}`；成功返回与 GET 同形。`employee` 必须是 `native / codebuddy / qoder-intl / qoder-cn / claude-code / codex / opencode` 之一（phone / mcp 不接受）；`permission` 必须是 `read / edit / full`；`model` ≤200 字符。非法值 400 带说明；`EXECUTOR_CONFIG=false` 时 PUT 400 |

- **模型留空 = 跟随 CLI 自己的配置**（Claude `~/.claude/settings.json`、Codex `~/.codex/config.toml`、
  OpenCode 自己的配置）；CodeBuddy / Qoder 留空回落到各自的 env 默认。
- **native 的模型框（2026-11-16 通用 worker 批1）**：留空 = worker 子进程回落启动 env
  （`CHANCELLOR_LLM_MODEL` → `LLM_MODEL` → 默认 `deepseek-v4.1-flash`，百炼兼容端点）；
  填了 = 建单快照带 `profile.model`，chancellor spawn worker 子进程时覆盖 `CHANCELLOR_LLM_MODEL`。
  **刻意没有**：native 不做「检测」按钮、也不跟随设置→模型的运行时主选——worker 子进程只会
  OpenAI 兼容单供应商栈，主选可能是其它协议 / baseUrl，搬运整套 provider 栈收益低风险高
  （2026-11-16 曾有 UI 文案声称"跟随主选"，与实现不符，当日改为如实口径）。
- **权限档只对 Claude Code / Codex / OpenCode 生效**：Claude = `plan / acceptEdits / dangerously-skip`；
  Codex = `read-only / workspace-write / danger-full-access`（`approval_policy="never"`）；
  OpenCode = `plan agent / --auto / --auto`。CodeBuddy / Qoder 非交互模式固定全权，界面显示"固定"。
- **建单快照**：新单把 `employee` 与 `profile` 交给 chancellor，落 `ticket.employee` /
  `ticket.options.employeeProfile`；续跑与崩溃恢复按快照走，改默认只影响新单。
  老单没有 profile 快照（本批之前建的单）→ 回 env 缺省，不追用当前界面设置。
- **分管路径**：`domain` 非空时，执行器与 profile 经 manager 子进程的 env 传给子单
  （`CHANCELLOR_EMPLOYEE` + 对应 `CHANCELLOR_*_MODEL/PERMISSION`）。
- **Windows 启动**：npm `.cmd` shim 由 `chancellor/src/employee/cli.ts` 的 `resolveCliLauncher`
  解到真实 `.exe` / `.js`；`PWD` 对齐 spawn 的 cwd（OpenCode 2.1.1 按 `PWD` 认工作目录，
  2026-11-16 冒烟实测过）。
- **额度边界**：订阅登录下 `claude -p` 的 entrypoint 是 `sdk-cli`，社区实测约为交互式终端的
  1.8–2.9 倍；API Key 计费不受影响。设置页在 Claude Code 卡片上写明这条。
  交互式 TUI 桥（PTY / ConPTY + 粘贴 + transcript 解析）**刻意不做**，见
  `docs/设计方案/2026-11-16-多CLI打手适配与执行器设置.md` §2.2 / §4。
- **回滚**：`EXECUTOR_CONFIG=false/0/off` → 不读文件、一律 env，一行退回本批之前形态。
