### 2.11 执事（2026-11-05 批次B）

长期身份 = 档案（`partners.sqlite`）+ 磁盘家（`partner-homes/<uuid>/`：SOUL.md / memories/USER.md / workspace/ / skills/）。
`COMPANIONS_ENABLED=false` 时本节全部端点不挂载（404 语义 = 未启用）。

| 端点 | 说明 |

| `POST /api/v1/partners` | 建（必填 `name` ≤40 字）。创建即建家 + 首个身份版本。可选 `domain`（小写 ASCII，正则同 chancellor `DOMAIN_PATTERN`）：带则 = **执事**，见下。可选 `soul`（E2 #0，纯增量）：建档成功后 `bumpSoul` 一次写成 v2 自定义版本，把前端「建完补 PATCH」两段式收敛成一段；400 校验照 PATCH 的 64KB 槽位上限（`PARTNER_SLOT_LIMIT`），超上限在建档前就拦；不带 `soul` 行为零变化。可选 `tagline`（2026-11-12 口头禅，纯增量）：与 PATCH **同一份校验**（trim 后按 Unicode code point ≤40 字；`null` / 空串 = 不设；省略 = 不设）；非法类型 / 超长在建档前 400，不留半建档案；响应投影带 `tagline` |

| `GET /api/v1/partners/:id/bundle` | **团队包导出（2026-11-10 批 25 §二）**：200 回单文件 JSON **附件**（`Content-Disposition: attachment`，`filename*=UTF-8''…` 带原始名）。内容：`{format:"lifediary-partner-bundle", version:1, exportedAt, partner:{name,domain,status}, soul, contract, skills:[{name,content}], memories:[{kind,content,importance,createdAt}], safety}`。记忆**只导 `preference` + `experience`**（`work` 履历与规则不导）；导出前字段级打码 + 序列化后按值再打一遍（双重脱敏）。`safety` 固定 `{approvalLevel:"ask-all", skillsEnabled:false, routinesPaused:true}`。执事不存在 → 404；`PARTNER_BUNDLE=false` → 404（两族端点都不挂，见下） |
| `POST /api/v1/partners/import-bundle` | **团队包导入（2026-11-10 批 25 §二）**：body = 导出的 JSON。201 `{ok, partner, imported:{skills,memories,skipped}, safety, warnings}`。**不信包里的 `safety` / `status`**：一律落成 `paused` + `SAFE_ARRIVAL`（`ask-all` / 技能不启用 / 规则全部暂停——团队包本就不导规则）。**领域标签不随包迁移**（连着 chancellor 分管目录与派活路由，避免"导入即接单"），`warnings` 里如实说明；确认后由人单独设置。重名执事 → **400 `duplicate_name`，不覆盖**；格式 / 版本 / 名字不合法 → 400 `invalid_bundle`；建档后写盘失败回滚档案 → 400 `create_failed`。`PARTNER_BUNDLE=false` → 404 |
| `GET /api/v1/partners/:id/skills` | **员工档案 · 技能清单（2026-11-09，只读）**：`{ok, skills:[{name, summary, updatedAt}]}`。读家目录 `skills/`（`store.skillsDirOf(id)`）下的 `*.md`：`name` = 文件名去扩展、`summary` = **第 1 行**（技能手册既有口径：第 1 行 = 索引用摘要，取时 trim 掉首尾空白）、`updatedAt` = 文件 mtime（`toISOString()`）；按 `name` 升序。只认普通文件（符号链接 `isFile()` 为 false，不收）、非 `.md` 不收、单个文件读不了跳过不 500。**目录不存在 / 为空 → `{skills: []}`；执事不存在 → 404 `not_found`；`COMPANIONS_ENABLED=false` → 整组路由不挂 → 404（同本节既有口径）**。总管 `chief` 走同一路径（`chief/skills/`）。零新存储、无开关、不进 `WRITE_TOOLS`、不进 shared；记忆 / 履历 / 例行全部复用既有端点，见 §2.11「员工档案页」 |

**头像格式（2026-11-06 B1）**：`data:image/png;base64,...`，字符串 ≤180000 字符、解码后 ≤128KiB、
PNG 签名 / IHDR / 完整性（以 IEND 结束）/ 单边 1–256px 全部校验；**不收** JPEG、SVG（可执行内容）、
外部 URL、本地路径。服务端只存这一列（`partners.avatar`，旧库自动补列，旧记录为 `null`），
只供浏览器 `<img>` 渲染。客户端负责把用户选的图缩到 ≤256px 并转 PNG；服务端仍全量复核。

**首次问候（2026-11-06 B3）**：生成跑在隔离的 `task-` 会话（工具清空、扩展摘掉、只喂当前 SOUL 快照，
不读 USER.md / 技能 / 历史），结果先落 durable doc（`lifediary.partner-greeting`：`attempt` /
`generationExternalId` / `requestId` / `status` / `text`），再在 canonical 的**一个事务**里复核
"用户是否已说 / 已入队"：已说 → 标 `skipped` 不写；否则 appendEntry 一条 `pi.assistant` 并标 `sent`。
同一进程并发 open 由单飞合并；崩溃遗留的 `pending` 复用同一 `requestId`，不另跑模型；
终态 `unanswered` 才标 `failed`，下次显式点击才 `attempt+1`。**绝不伪造 user 消息**。

执事会话 = 普通会话 + 版本冻结身份提示词，**没有第二套权限系统**（D6 三档 + 审批轴原样生效）；
记忆按 `partner:<uuid>` 键空间隔离（§3）；模型原始文件工具只挂 `workspace/`（pathGuard）；
新写工具 `partner_skill_write` 已进 `WRITE_TOOLS`（§4）。

**执事（2026-11-05 批次D D2）** = 带 `domain` 的执事 = chancellor 里该领域的分管宰相穿上执事身份。
建时：宿主 `ensureManager(domain, { partnerId })` 建宰相目录（meta.json 记 `partner_id`，chancellor 只存不解读）
+ 执事档案（SOUL 播种为「你是 {name}，{domain} 领域的负责人…」一句话版本）
+ `partner_session_links` 记 `role='delegation', routeKey=domain`（role 枚举扩一型；
现有 `UNIQUE (partner_id, role, route_key)` 已覆盖，无约束变更）。
派单：`delegate(domain=x)` 时宿主按 domain 反查执事，命中则请求带
`managerIdentity={name, soul=当前版本快照正文}`（**取快照不取磁盘当前值**，单次派单内不变；
宿主侧按 UTF-8 字节截断 ≤4KB），chancellor 把它原文注入分管提示词的「## 你是谁」节、只透传不解读。
查不到的 domain **照旧**，兼容旧领域。执事 = 干活走 chancellor 全链，记忆仍留在 chancellor
（会话续用 + handoff.md），**不接宿主记忆引擎**、不吃 `partner:<id>` 键空间（登记「刻意没有」）。
`PartnerProfile` 加可选 `domain` 是纯增量：不带该字段的老客户端 / App **零改动**。

**`domain` 降级为可选标签（2026-11-07）**：用户反馈"不知道领域能干什么、也没有地方设置"。
语义变化：

- `POST /partners` **可以不带 `domain`**——照样建成可派活的执事（不建 `managers/<domain>/`，
  不参与按领域的分管派单）。带 `domain` 时行为与之前逐字一致（建分管目录 + delegation 链接）。
- `PATCH /partners/:id` **可以改 `domain`**（原先一律 400「建后固定」）：传字符串 = 改成该标签，
  传空串 = 清掉标签。校验与创建同一套（小写 ASCII、不能抢占别人的）。
- 它**不再是派活路由键**：派活按执事 id / 会话链接判定（见上文"执事直派"）。
  改标签不会让历史任务单找不到负责人。
- 界面：新建弹窗与执事设置都写成「领域标签（可选）」，并说明"留空也行，不影响派活"。

**派发权（2026-11-06，按执事独立·默认关）**：带 domain 的执事多一个 `dispatchAuthority` 布尔
（`PartnerProfile` 可选字段，投影只对带 domain 的执事给，默认 `false`）。开关关 → 派单
`delegate(domain=x)` 命中该执事时**不注入其身份**（请求不带 `managerIdentity`），
chancellor 以默认路径（总管直派 worker）办完这张单，行为等同旧领域，**不拒单**。
开/关切换：`PATCH /api/v1/partners/:id` 带 `dispatchAuthority: true|false`（普通执事 400
「该执事不带 domain，没有派发权可切」）；立即生效（派单时实时查库，无缓存），SQLite 持久。
模型侧 `partner_manage` 工具同步增 `set_dispatch`（`partnerId` + `enabled`），核心实现与端点共用。
回滚总闸 `MINISTER_DISPATCH_AUTHORITY`（§6）。chancellor 仓库与跨仓契约不动。

**执事直派（2026-11-07 消息即引导）**：执事在自己领域内派活时，宿主按 `resolveDelegateRouting`
判定路由，请求带 `managers: false` 且**不注入** `managerIdentity` —— 他本来就是该领域的负责人，
再注入一次等于把同一身份跑两遍（chancellor 会为该领域再起一个分管宰相见）。判定表：

| 调用者 | 请求的 domain | 路由 |
|---|---|---|
| 总管 / 主人会话 | 任意 | 原样：按 domain 注入身份，走分管路径 |
| 执事（有 domain） | 空，或等于自己 | **直派**：`managers:false`，不注入身份；`domain` 仍保留供任务中心展示 |
| 执事（有 domain） | 别人的领域 | **拒绝**：「只能在自己领域内派活」，不静默改道 |
| 普通执事（无 domain） | 任意 | 原样（没有分管身份，等同主人会话） |

回滚 `MINISTER_DIRECT_DISPATCH=false`（§6）→ 一律回到分管路径。**不做**执事互发消息、
不做"执事再建执事"、不改 chancellor 仓库。实现：`ts/apps/server/src/delegate-routing.ts`（纯函数 + 单测）、
`tools.ts` 的 `delegate` 装配处；`DelegationKickoff.managers` 是这条路由唯一的出口。

#### 岗位契约（2026-11-08 员工人格化刀一 E1，`PARTNER_CONTRACT` 默认开）

家目录新增 `CONTRACT.md`，与 `SOUL.md` 并列、**同一套版本化语义**：一个身份版本 =
当时的 SOUL + CONTRACT 对，改任一文本都 bump `partner_versions` 并落双快照
（新列 `contract_source TEXT`，旧库启动时 `ALTER TABLE` 补列，老行为 `null` = 无契约快照）。
改完不当场变身，**下一轮生效**（与 SOUL 完全一致）。

固定四节，**标题逐字**：`## 职责范围` / `## 决策分级` / `## 验收标准` / `## 汇报对象`。
新建执事播种一份**只有四节标题的空模板**；存量执事**不自动补文件**（不越权），
读取时缺失 = 该节为空。单文件 64KB、原子写（`PARTNER_SLOT_LIMIT`，与 SOUL 同口径）。
总管（`chief`）刻意不播种契约。

注入（每轮）：执事轮输入在 SOUL 之后追加两段 system 消息——「【岗位契约】」四节全文
（**空节连标题一起省略**，四节全空则整段不出现）与「【当前在办】」（见下）。
两段都由 `agent/partner-context.ts` 装配，`agent/lifecycle.ts` 的 `beforeRequest` 按会话认执事
后注入；私聊 / 例行专线 / 群成员轮走的是同一条通道，所以只需装配一处（群轮再拼一遍会重复）。
状态段在本轮第一次模型请求时现算（一轮只算一次：扫 runs/ 要开库，别在每个工具回合重算），**不进 transcript**（不像用户正文那样被固化）；契约段取当前版本快照，
老库 / 手工放了文件但没快照的退磁盘当前值。

**当前在办（E5，纯装配 · 零新存储）**：同一段装配的第 3 段，三项全部现查现拼——
① 该执事发起且未终态的派活单（`ticket.json` 的 `originConversationId` 落在他的会话链接里，
含 8g 专线；终态口径同任务中心 `done/needs_you/failed/idle/aborted`）；
② 本会话待审批 pending（`ApprovalStore.pendingOf(会话)`；`findPending` 是「同工具 + 同指纹」
去重查询，不是列清单，别拿它当列表用）；
③ 最近一单的结果行（`lastAction`）。明细各 ≤3 条、超出只报「另有 N 条」；
三项皆空 → 整段不出现。有在办 / 待批时末尾带一句 attention 应答口径
（答得了就答；答不了就让工人「该项先跳过，继续其余部分，这项回头再补」，见 §4 `delegate`）。

回滚：`PARTNER_CONTRACT=false` → 不播种文件、不渲染 / 不注入契约、写端点 400；
SOUL 与「当前在办」行为不变（一行 env 回到纯 SOUL 形态）。

**delegate 任务书四段（E1 消费点 2）**：工具描述与 `requirement` 参数说明升级为
**目标 / 怎么算好 / 可自主范围 / 必须请示**四段；执事带契约时后两段按其「决策分级」
「验收标准」填写。**参数结构不变（仍是 string），chancellor 零改动**（§4）。

#### 工作履历与当前目标（2026-11-08 员工人格化刀二 E2/E4）

### 2.12 例行任务（2026-11-05 批次B）

触发层是 durable 任务（`sleepUntil` 落库），不是扫描定时器（系统架构 §3 口径）。

| 端点 | 说明 |
|---|---|
| `POST /api/v1/routines` | 建（`partnerId/name/prompt≤100k/triggers/sessionMode/enabled`），启用时自动排定时链 |
| `GET /api/v1/routines?partnerId=` / `GET /api/v1/routines/:id/runs` | 列表 / 执行历史（≤50 条有界） |
| `PATCH /api/v1/routines/:id` | 改即 `revision+1`：在飞任务醒来对不上号自动作废，还开着就重排 |
| `DELETE /api/v1/routines/:id` | 删定义；在飞任务醒来作废（没有取消 API 的替代机制） |
| `POST /api/v1/routines/:id/run_now` | 手动跑一次（entrusted，不占定时链） |

triggers 四型：`cron`（5 段：分 时 日 月 周）/ `interval`（seconds ≥60）/ `once`（ISO at）/ `event`
（kind = delegation/tool/phase + match 字段等值过滤；执事自己会话发出的事件不触发——防自环）。
执行铁律：同规则串行（上一轮没跑完下一次 deferred 30s）；终态落盘失败期间后续触发只排队不执行；
重启时 running 一律 interrupted **不自动重放**。例行轮是自主轮（`turnAuthority: autonomous`，
批次C 的高危审批只对它生效）。

**事件触发器三件门（2026-11-10 批 15 §一，`ROUTINE_TRIGGER_GATES` 默认开）**：`event` 触发器可选加
`baseline?: {key, delta}`（比上次观测值变化**超过** delta 才触发；首次记基线那次不受限）、
`edge?: true`（只从假变真那一下触发）、`cooldownSec?: number`（触发后 N 秒内不再触发）。
判定顺序固定 **cooldown → edge → baseline → 原 match**；三者可组合。门状态按
`<规则id>:<触发器序号>` 落 `routines.json` 的 `gates`，坏值/非数字观测值一律不触发
（宁可漏一次，不拿脏值硬比）。`ROUTINE_TRIGGER_GATES=false`/`0`/`off` → 三个字段全部被忽略，
行为回到改动前；纯函数在 `routine-conditions.ts`（`evaluateTriggerGate`）。

**看护单例交接（2026-11-10 批 15 §四，`ROUTINE_WATCH_SINGLETON` 默认开）**：
带 `until` 的"盯到条件达成"类规则，**同一执事同一时刻最多一个在看**。新一轮开始时若已有
别的看护在盯 → 旧规则只暂停（`enabled=false`，`revision+1` 让在飞闹钟作废），
**不删除**；交接账落 `.data/routine-watch.json`（`ROUTINE_WATCH_PATH` 可改）：
`{version:1, watches:{<partnerId>:{routineId,name,since}}, handedTo:{<旧id>:<新id>}}`。
同一对 old→new **只记一次** `handedTo`；规则置停（until 达成 / 跑满 maxRuns）时从 `watches`
摘除（`handedTo` 保留）。删除规则不额外清账——残留条目只是"指向一条不存在的规则"，
下一次同 key 认领会把它当作旧看护一次性交接掉（不删数据、不挡执行）。
`ROUTINE_WATCH_SINGLETON=false` → 不读不写此文件。

**触发来源 `runSource`（2026-11-10 批 15 §三，`RUN_SOURCE` 默认开）**：run 记录新增可空
`runSource`——定时/事件触发 = `routine`；执事 `routine_manage` 自建规则的**首轮** = `routine_self`；
`POST .../run_now` = `script`。`RUN_SOURCE=false`/`0`/`off` → 不写，行为回到改动前。
（派单回执的来源列见 §2.9。）

**条件门控（2026-11-10 批 13 §四，`ROUTINE_CONDITIONAL` 默认开）**：`RoutineDef` 新增两个**可选**
字段——`until?: {note}`（一句文字完成条件；每轮跑完由模型判断，达成时回复末行写
`[[routine-done]]`，服务端把规则 `enabled=false`（**不删**，保留历史））与 `maxRuns?: number`
（自动跑满 N 次即停；手动 `run_now` 不计入）。run 记录新增结构化 `outcome`
（`success|quiet|skipped|failed|done`，`skipped` = 无人值守跳过过步骤）；下一次触发把
"上一次的结果是 X"带给模型。`ROUTINE_CONDITIONAL=false`/`0`/`off` → 两个字段与 `outcome`
全部被忽略，提示词与 run 记录回到改动前（一行回滚）。HTTP 端点本批仍只接受老字段
（`until`/`maxRuns` 目前经 `routine_manage` 工具设置，端点透出为已知边界）。

**触发器 `if` / `ends`（2026-11-10 批 21 §三，沿用 `ROUTINE_CONDITIONAL`）**：任一触发器可带
- `if?: {note}`：触发前**先问一次模型**"这句条件此刻成立吗"（独立 `completeSimple` 调用，
  走 `AUX_MODEL_REVIEW` 可 pin 的小模型，超时 15s，maxTokens 4）。**失败即跳过**：没配模型 /
  faux / 超时 / 报错 / 答案不是明确的 YES/NO → 当"不成立"，记一条 `status:"skipped"`、
  `outcome:"skipped"`、`skipReason:"condition_not_met"` 的 run（不跑模型、不推进游标、
  不消耗 `maxRuns`/`ends.after` 额度）。多个触发器各带 `if` 时**全部成立才跑**；`note` ≤200 字。
- `ends?: {at?, after?}`：`at` = ISO 时间点，到点后该触发器不再被定时/事件唤醒（在飞的 durable
  闹钟到点仍会响一次——它排在 `at` 之前才可能被创建）；`after` = 跑满 N 次停，是 `maxRuns` 的
  别名，两者同时存在取**更小**。`ends` 至少要给一个；非法值在 `validateTriggers` 直接 400。
  运行态判定在 `routine-conditions.ts`（`triggerEndedAt` / `effectiveMaxRuns` / `routineConditionNotes`），
  模型调用在 `routine-gate.ts`。

**游标推进时机（2026-11-10 批 21 §六，沿用 `ROUTINE_QUIET`）**：`routines.json` 新增
`cursors: {<规则id>: ISO}`——"上次看到哪里"的时间水位 = 上一轮**产出被保留**的 `run.endedAt`。
只有 `ok && !quiet && 没跳步` 才推进；quiet（没事）、skipped（跳步）、failed（含读失败）
一律原地不动，下一轮仍从同一处看。有游标时提示词在原文前加
`[上次看到这里] <ISO>；这一轮只看这之后的新内容。`；首次运行没有这一段。
`ROUTINE_QUIET=false` → 不读不写游标（回到"每轮从头看"）。**边界**：宿主只能按 run 终态判，
模型"读失败但照样回了 `[[no-update]]`"这一层无法区分——那是模型自报，不是宿主事实。

**安静契约（2026-11-09 T2）**：例行轮的产出"没有实质内容"时不写汇报——模型侧提示词尾部会要求
"没内容就回 `[[no-update]]`"；服务端再按确定性规则兜底（去空白后 < `ROUTINE_QUIET_MIN_CHARS`（默认 40）
且不含数字/链接/日期 → quiet）。quiet 时 run 记录 `summary:"quiet"`，`[[no-update]]` 标记从产出中剔除，
日志只记"本轮无更新"不记正文。`ROUTINE_QUIET=false` 一行回滚。**边界**：模型这一轮的 assistant
条目由 durable 内核落盘，服务端没有撤回 API，quiet 保证的是"服务端不再写第二遍汇报"，
不是"transcript 里绝对无痕迹"。

**自建巡逻 `routine_manage`（2026-11-08 刀二 E4）**：此前只有 HTTP `POST /api/v1/routines` 能建规则，
现在给**带派发权的执事**一只模型侧的手（工具参数与端点校验共用 `routine-manage.ts` 一份核心实现）：

- `action=create|disable|enable|delete`；create 带 `name` / `prompt` / `triggers` / `sessionMode`，其余带 `id`。
- **只能动自己的**：`partnerId` 由调用者会话认出后绑定，动别人的规则一律 `not_found`（找不到与"不是自己的"同一句话，**不泄存在性**）；主人 / 总管会话明确拒绝。
- **上限**：每执事活动（`enabled`）规则 ≤ **10 条**，create / enable 都先数，超了带说明拒绝。
- **走既有引擎**：create / enable 后由装配层 `routineEngine().ensureScheduled` 排 durable 闹钟；disable / 改期靠 `updateRoutine` 的 `revision+1` 让在飞闹钟作废；delete 直接删定义，在飞闹钟醒来查不到规则自然作废；事件触发的"自我事件不触发自我"防自环原样生效。
- 进 `WRITE_TOOLS` 过闸门；10-C 三档里与 `partner_manage` **同档高危**（`DEFAULT_CRITICAL_TOOLS`，自主轮强制 ask、禁"记住"绕过）。
- 回滚 `ROUTINE_SELF_SERVICE=false`（§6）→ 工具不上架，回到"只有 HTTP 能建规则"的形态。
- **不自动建周回顾规则**；盘点口径见 §2.11「工作履历与当前目标」。

### 2.11.1 自主轮审批（2026-11-05 批次C C2）

`approval` 事件与 `POST /agent/approvals/:callId` 的记录多一个可选字段 `origin: "autonomous"`
（例行任务轮产生的审批；纯增量，老客户端忽略）。自主轮的审批**不认"记住"**：每次都弹卡，
答复端点的 `remember` 参数对自主轮记录忽略。普通轮的审批行为完全不变（审批档口径不动，§2.18）。

观察层（批次C C1）**默认开**（2026-11-13 用户拍板；`AUTONOMY_ENABLED=false / 0` 显式才关）：
开启后把「卡住 / 等你 / 出错 /
用量受限」写成会话内一行（`【需要你】…`，≤140 字，枚举化，不经模型），手机拉 transcript 可见。

**三档（2026-11-09 T2 起；缺省 2026-11-13 起为 on）**：不配或 `=true` = 完整行为；
`=false / 0`（显式关）= 与改动前逐字节一致（不订阅、不判定、不落账）；
`=observe` = 照常订阅与判定，但只把"本来会提醒"追加到 `.data/autonomy-observe.jsonl`
（`{at,type,conversationId,action:"would-remind",summary≤140}`，不存对话内容），**不写会话、不起模型调用**。
观察计数经 `/healthz` 的 `autonomy.observeCount24h` 透出。
