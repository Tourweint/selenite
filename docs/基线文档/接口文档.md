# 接口文档（lifediary-harness）

> 状态：P1（2026-10-25）。**契约总源 = backend 仓库 `docs/基线文档/接口文档.md` §7**；
> 本文档是 §7 在 harness 侧的实现视图，两端必须逐字一致（§7.3：并存期间"切回去就不一样"是事故）。
> 跨仓库改契约必须两边同时出变更记录。

## 0. 鉴权（D2）

- 所有端点要求 `Authorization: Bearer <JWT>`（HS256，与 backend 同一签名密钥 `JWT_SECRET`）；
- 缺失/无效/过期 → **HTTP 403 空响应体**（与 backend 的 Spring Security 行为一致，App 无需区分两端）；
- `JWT_SECRET` 未配置/过短（<32 字节）→ 一切请求 403（fail-closed）。

## 0.1 频控（D4/§8 分工）

按来源 IP 的频次 + 并发闸门（等价 backend `IpRateLimitGuard`）：
`/api/v1/signal/**` 每 IP 每分钟 30 次（`RATE_LIMIT_SIGNAL_PER_MINUTE`）+ 并发 4（`RATE_LIMIT_MAX_CONCURRENT`）。
超限统一 `HTTP 429 + {"code":4290,"message":"操作太频繁了，稍等一会儿再试"}`。
总开关 `RATE_LIMIT_ENABLED`。

## 1. 会话信号（路径 B / Jev，2026-10-22；2026-10-25 迁入 harness）

`POST /api/v1/signal/session`（认证；advisory；**不落盘**；不计额度——非 LLM 调用）

```json
{ "messages": [ { "role": "user", "text": "没了" } ], "today": "2026-10-22" }
```

成功 data（一次 TypeSafe 请求并行四问，归一化后返回；**advisory 不门控**，客户端只用于决定是否浮现收尾提示）：

```json
{ "code": 0, "message": "ok", "data": { "available": true, "sessionState": "wrap_up_confident", "engagement": "perfunctory", "emotion": "none", "endingIntent": 0.97, "confidence": 1.0 } }
```

- 未启用 / 未配 `TYPESAFE_API_KEY` / 上游失败 / 解析失败：`available=false`（客户端回落本地评估），**不报错**；
- 上限 30 条 × 每条 2000 字，超出截断（控制器先截条数，服务层再取最近 3 条组装 state）；
- 隐私口径 = 即取即转（同 LLM 透传），**不落盘、不写含正文的日志**（日志只记枚举结果/耗时/token 数/configVersion）；
- 出口代理（451 解法）：`TYPESAFE_PROXY`（`socks5://` / `http://`，留空直连）；
- 频控超限见 §0.1（4290）。

### 1.1 available=false 的触发路径（测试全覆盖）

| 路径 | 触发 | 行为 |
|---|---|---|
| ①未启用 | `SIGNAL_JEV_ENABLED=false` | 直接返回 empty，不出网 |
| ②无 key | `TYPESAFE_API_KEY` 空/空白 | 直接返回 empty，不出网 |
| ③上游失败 | HTTP 非 2xx（401/451/5xx）、超时、连接失败 | 返回 empty，日志记 HTTP 状态与耗时 |
| ③附解析失败 | 上游 200 但 body 非 JSON/结构不符 | 返回 empty，日志只记异常类型 |

`available=false` 时返回体固定为：
`{"available":false,"sessionState":"continue","engagement":"engaged","emotion":"none","endingIntent":0.0,"confidence":0.0}`。

## 2. LLM 透传代理（P2，2026-10-27；与 backend §3 逐字一致）

`POST /api/v1/llm/chat/completions`（认证；别名 `/chat/completions`——OpenAI 兼容客户端在
baseUrl 后直接拼 `/chat/completions` 的路径兼容随迁）

- 请求体：**OpenAI Chat Completions 原样 JSON**；响应（含 SSE 流式）逐块回写并 flush，零改动接入；
- **先扣再转发（D1）**：转发前调 backend `POST /internal/quota/consume`（幂等 requestId=UUID，kind=LLM）；
  扣失败即拒（fail-closed）；
- 额度耗尽：HTTP 429 + `{"code":4029,"message":"今日额度（N 次）已用完，明天再来"}`——
  **文案由 backend 生成，本服务原样透传**；账号不存在/已注销：HTTP 401 + `{"code":4010}`（App 按"登录已过期"处理）；
  backend 依赖失败/超时：HTTP 503 + `{"code":5001}`（连接 200ms / 读 1s）；
- 模型覆盖：`LLM_MODEL` 非空时转发前覆盖请求体 `model` 字段（调优归服务端，口径随迁）；留空原样透传；
- 上游错误码原样透传；**隐私边界：不落盘请求/响应内容**，日志只记用量/耗时/configVersion；
- **闸门口径**：鉴权挡匿名滥用、每用户每日额度挡刷量，本端点不再叠 IP 频控
  （signal 端点无额度概念才需要 IP 闸；见 §0.1）。

## 3. 对 backend 内部接口的消费（backend 文档 §9）

| 接口 | 用途 | 失败口径 |
|---|---|---|
| `GET /internal/ai-config?since=` | 60s 轮询 `ai.*` 策略参数（增量） | 失败沿用上次成功值 → 再失败用内置默认；不阻塞业务 |
| `POST /internal/quota/consume` | P2 起 LLM 调用前扣额（幂等） | fail-closed：扣不成即拒本次调用 |

内部接口走 `X-Internal-Token`（`INTERNAL_TOKEN`，与 backend 同值）+ 内网，连接 200ms / 读 1s。
