### 2.13 中继与设备矩阵（2026-11-05 多端同步三阶段，设计期方案已落地）

**中继**（独立进程 `ts/apps/relay`，`pnpm --filter @lifediary/relay dev`）：WS `/ws` 信封隧道
（`{v,kind,id,src,dst}`，src 由中继盖章；deliver/result 路由、meta 帧中继自答做执事路由仲裁）
+ REST 管理面。**中继只存路由元数据**（设备、在场、执事→主机），不存会话正文/密钥/记忆。
镜像控制台在 `GET /`（加入码配对→选设备→会话流镜像→发消息→答审批）。

| 端点（中继侧） | 鉴权 | 说明 |
|---|---|---|
| `GET /api/relay/info` | 免 | `{name, protocolVersion, pairing, onlineDevices}` |
| `POST /api/relay/pair/code` | owner（`RELAY_OWNER_TOKEN`；空 = 仅 loopback） | 加入码，5 分钟单次 |
| `POST /api/relay/pair/redeem` | 免 | `{code, deviceName, platform, capabilities?}` → `{deviceId, deviceToken}`；错 5 次作废、同 IP 每分钟 30 次限流 |

| `GET\|POST\|PUT\|PATCH\|DELETE\|HEAD\|OPTIONS /api/v1/*` | 设备令牌 | **反向 HTTP 代理**（2026-11-11 批R R1）：只路由到任务主机（`isHome=true`），无主机/主机离线 **502 `device_offline`**，15 秒无回包 **504 `device_timeout`**，帧超上限 413。status/body 原样回手机，`Content-Type: application/json` |

**harness 侧**（`RELAY_ENABLED=1` 才装配，默认关）：以设备身份出站长连中继（退避 1s→30s），
通道白名单默认拒绝（`info/probe`、`sessions/list`、`chat/send`、`events/subscribe|unsubscribe`、
`approvals/pending|answer`、`mobile/proxy`；矩阵开启再加 `delegation/accept|status`）。
控制端镜像：订阅复用 SSE seq 语义（`sinceSeq` 重放 + 250ms 轮询重放库推 `push/session:<uuid>`，
窗口滑过整段重发标 `resync`）。**已知边界 v1**：事件重放库只收 HTTP 发起的轮次；
服务端直写（sayInChat 类）的帧不进推送流，控制端靠重连重放/`/messages` 对齐。

**名册投影 `RelayDeviceView`（2026-11-05 主机优先制）**：每条设备带 `isHome`（同刻只有一台为 true）
与可选 `description`。`welcome` / meta `devices` / `GET /api/relay/devices` / `relay/overview`
共用同一投影，手机设置页据此显示主机位与描述。meta 新增 `set-home`、`set-description` 两个动作
（中继自答、不转发）。

**手机经中继（2026-11-11 批R/批H，协议仍 v1）**：

- **反代链路**：手机 base 指到 `http://<relay>/api/v1` → 中继收 REST → `invoke` 帧投给任务主机
  → 主机回 `invoke_result` → 中继原样回包。帧契约在 `shared`（`.strict()`）：
  `{kind:"invoke", id, payload:{method, path, query, headers:{authorization}, body}}`（`query` 含前导 `?`，
  `body` 无正文 = null）与 `{kind:"invoke_result", id, payload:{status, body}}`。中继不解析业务语义、
  不改写正文；鉴权失败 403 空体（走 `deviceIdOf`）。
- **已知简化（批R）→ 批H 已在落地端收口**：中继不替换 `Authorization`、也**不存 harness 令牌**；
  手机带来的是中继 `deviceToken`。批R 时要求"手机配的令牌就是 `AGENT_TOKEN`"，扫码加入路径
  做不到（join 发的是中继令牌）；批H 起由 harness 在内部调用时映射成自己的 `AGENT_TOKEN`
  （见下「反代落地端」），手机侧只需保存 join 拿到的 `deviceToken`。
- **反代落地端（2026-11-11 批H H1，`mobile/proxy` 通道）**：中继的 `invoke` 帧由 harness
  `relay-client` 收下（与 routed 并行的第二种入站帧），交给 `relay-channels` 的 `mobile/proxy`
  通道：**本进程内**用 Hono `app.request()` 执行（不真发 HTTP、免端口自环），回
  `invoke_result{status, body}`，status 与正文原样（不解析、不脱敏）。
  - 只放行 `/api/v1/` 前缀；帧形状不对 400，内部异常 500，都不让中继干等超时；
  - **反代不放行 `POST /api/v1/relay/join-code`**（回 404）：加入码是电脑本地管理动作，
    放进来等于任一已加入设备都能替主人继续发码拉新设备，绕过中继 owner-only 口径；
  - **鉴权映射**：手机带的是中继签发的 `deviceToken`，与 harness `AGENT_TOKEN` 不是同一套；
    中继在投 invoke 前已验过设备令牌，所以内部调用**统一使用本进程 `AGENT_TOKEN`**
    （未配置时退回帧里带来的 authorization，再由 harness 自己的鉴权决定放行与否）。
    即"扫码加入某台手机 = 授权它使用这台电脑"，撤销走中继撤设备；
  - 回滚：harness 侧 `RELAY_MOBILE_PROXY_ENABLED=off` → 通道不注册（`dispatchHttp` 不装配），
    中继发来的 invoke 一律回 **404 `{"error":"not_found"}`**；中继侧同名开关是整段 404。
- **「添加设备」弹窗（2026-11-11 批H H2，web 设置 → 连接）**：点「添加设备」调 harness
  `POST /api/v1/relay/join-code`，弹窗展示大字加入码 + 二维码
  （内容 `lifediary://relay/join?u=<中继http地址>&c=<joinCode>`，`u` 做百分号编码）+
  过期倒计时 + 「换新码」；地址默认取 `RELAY_URL` 对外形态、弹窗内可改（改完点「换新码」
  用新地址重新签发）。**不回显手机是否已加入**——扫完去同页「已连接的设备」名册看。
- **presence 广播（R3）**：hello 成功与连接关闭后，向所有在线连接推
  `{kind:"presence", devices:[RelayDeviceView…]}`（全量投影，复用 `store.listDevices`）。
  老客户端按协议约定静默忽略未知 kind（`welcome` / meta `devices` 语义不变）。
- **回滚开关** `RELAY_MOBILE_PROXY_ENABLED`（默认开）：`off/false/0` 时 `/api/v1/*`、
  `/api/relay/join-code`、`/api/relay/join` 整段 404（WS 隧道与既有管理面不受影响）。
- **安全口径**：joinCode / deviceToken 只存 sha256；日志只记计数与 deviceId，不记码、不记路径正文。

**手机端对接（2026-11-05）**：手机**不直连中继 WS**——以上代理面走 `/api/v1` 既有 Bearer 鉴权，手机零新协议（`RelayApi` 落 core:pairing；客户端口径见手机仓 `接口契约.md` §0）。
**手机端 UI 已铺**（2026-11-05 晚）：抽屉「多端」分区（状态）+ 设备页（设主机/写描述/跨机任务近况），
提交 5df44aa；任务中心/远端会话/聊天派活入口在后置池。
手机零新协议（`RelayApi` 落 core:pairing；客户端口径见手机仓 `接口契约.md` §0）。

设备矩阵派活语义：目标机用本地锚点会话（`远端单 <requestId 前 8 位>`）承载 chancellor 单，
回执/requestId 幂等/恢复机制原样工作；发起端轮询 status（快 2s×5 → 闲 15s），相位变化走
既有 delegate 事件，终态把一句话汇报写回发起会话。远端单的续跑（resume）v1 不做。

**`targetDevice="auto"` 决策（v2 主机优先制，2026-11-05）**：候选过滤不变（在线 + `matrix` +
非本机 + 非手机）；设了任务主机且主机在候选里 → **主机未满载永远选主机**（busy 不参与比较，
产品口径），主机满载才把主机剔除、其余按 busy 升序外流；主机离线/未设 → 沿用 v1 全员挑最闲。
挑不出 → fallback 本机（`no_candidate` / `all_busy`）。台账 `RemoteRow.pickedBy=auto` 时另记
`pickedHome`（主机优先为 true，外流为 false），`pickReason` 仍是 `busy=N`。设备描述不参与决策。

执事路由 CAS 在中继（`expected_home_device_id` 乐观锁，冲突 409 带回实际值）；
**凭证不随行**：每台 harness 各自 env 配 key。

### 2.14 群组（2026-11-06 群组方案落地；`GROUPS_ENABLED` 默认开）

群 = 主人 + 2–6 名执事在同一条共享时间线里聊。谁发言由宿主按确定性规则编排：
**@点名 > @所有人 > 值日执事**（无 @ 时按 `responderKind`）。每个执事仍是独立 agent
（自己的会话、SOUL、模型链、闸门——群走 `chatStream` 主链路，D14 红线不变）。
`GROUPS_ENABLED=false` 或 `COMPANIONS_ENABLED=false`：本节端点一个不挂（404 = 未启用）。

**数据模型**（`partners.sqlite` 三张表；群 id = uuid；对外 id 一律 uuid）：
`groups(id, name≤40字, notice≤500字, responder_kind, responder_partner_id, created_at, updated_at)` /
`group_members(group_id, partner_id, position, joined_at)` /
`group_messages(id, group_id, seq 群内单调, kind message|system, author_kind user|partner|system,
author_id, author_name 快照, content≤8000字, at, round_id)`。
作者落**快照**（改名/离群历史不烂）；成员表只存引用不复制人格。

**成员会话**：每成员每群一条、懒建，对外 id `partner-<partnerId>-group-<groupId>`，
链接 `role='group'`、`routeKey=group:<groupId>`。`partner-` 前缀不进会话列表（web 端过滤）。
**群会话不参与记忆引擎**（召回与抽取都跳过，判定 = 链接表存在 `role='group'` 行）；
群内连续性靠会话历史 + 群时间线。

| 端点 | 说明 |
|---|---|
| `POST /api/v1/groups` | `{name, memberIds[2–6], responderKind?, responderPartnerId?, notice?}` → 201 `{ok, group}`。`responderKind` 默认 `member`（值日制）；kind=member 时值日执事必填且必须是成员；重名成员 400（@ 歧义拒绝不猜） |
| `GET /api/v1/groups` | `{ok, groups[]}`（含成员投影） |
| `GET /api/v1/groups/:id` | `{ok, group}`；未知 404 |
| `PATCH /api/v1/groups/:id` | `{name?, notice?, responderKind?, responderPartnerId?, addMemberIds?, removeMemberIds?}`；增删成员后人数仍须 2–6，值日被移除 → 400 要求先换值日 |
| `DELETE /api/v1/groups/:id` | **硬删**：群 + 成员关系 + 消息；成员群会话遗留无害（不进列表） |
| `GET /api/v1/groups/:id/messages?beforeSeq=&limit=` | 时间线升序（默认最后 100 条）；`{ok, messages[], lastSeq}` |
| `POST /api/v1/groups/:id/chat` | `{text≤8000字}` → **SSE**（见下）。running 中再发 → 409（v1 不排队，UI 发送键变停止键） |
| `POST /api/v1/groups/:id/stop` | 停当前发言成员（复用会话 stop 链）+ 作废本轮剩余队列，finishReason=aborted |

**发言路由（纯函数 `resolveGroupSpeakers`）**：解析 @（最长标签优先、词边界、
重名歧义 → 400 拒绝不猜）→ @点名 ≥1 按正文出现顺序串行去重 → @所有人 全员按 position →
无 @ 按 `responderKind`：`member`=值日 / `everyone`=全员 / `mentions`=无人回（落 system 行）。

**@ 唯一长标签（2026-11-08 扫尾批 5，D16 底线不动）**：`@名字·<domain>`（`·` 为中文间隔号，
domain = 成员执事的领域，全局唯一）。解析规则：

- 名字后紧跟 `·` 且后面是领域 token（小写字母/数字/连字符）时按**长标签**解析，
  只认 domain 恰好等于该成员领域的那个；
- 长标签**打错域** → 不命中，按普通文本处理（不回退短名、不猜）；成员没有 domain 时同理；
- 重名成员：**只有正文真的用了那个短名才 400**（没写这个名字时不拦，照常走值日），
  400 载荷为 `{error:"bad_request", message, candidates:[{name, domain}]}`，
  `candidates` 是该重名组的全部成员（前端据此展示「名字（领域）」并插入长标签）；
- 无重名时短名照旧；`@所有人` 优先级不变。

**投影（2026-11-08 扫尾批 5，纯增量）**：`group.members[]` 除 `partnerId/name/status`（status =
档案实时状态，取值枚举 `active/paused/archived`；2026-11-10 契约从裸 string 收紧为 Zod 枚举
`PartnerStatusSchema`，与执事档案同一枚举，线上值不变）外补
`avatar`（档案头像 data URL 或 null，界面用来拼 2×2 复合头像）与 `domain`（领域或 null，
长标签消歧用）；两者都是**实时 join 档案表**得出，`group_members` 不落这两列。
`group.round = {running: boolean, speaker: {partnerId, name} | null}`
（群会话「谁在忙」胶囊读这一段；成员间隙 `speaker=null`，如实不显示）。

**SSE（纯增量，老客户端零感知）**：`start` 加可选
`sender?: {kind: "partner"|"user", id?, name?}`——一轮一个 start，整轮帧归属该 sender；
新事件 `{type:"notice", text}`（成员被跳过 / mentions 无人回 / 岔路说明），同一行落
`group_messages(kind='system')`。逐成员串行；他人消息在成员视角是 user 角色带说话人标签
（`主人: …`），自己的历史回复仍是 assistant。增量投递 = 只喂该成员上次发言之后的新消息
（首建带最近 30 条窗口）。**断线 ≠ 取消**：客户端断开回合照跑完落库，重连拉 messages 补。

**模型侧工具 `group_manage`（2026-11-07 群组入口统一）**：总管在对话里建群 / 看群。
之前只有界面按钮能建群，模型侧没有对应的手——总管说「建个群」只能干看着，与 `partner_manage`
（总管能建/停执事）的能力面不对称。

- 动作只有 `create` 与 `list`：**改名 / 加减人 / 删群不做**（低频、歧义大、删群不可恢复，
  留在界面由人点）。
- 成员与值日都按**名字**指定（`members: string[]`、`responder?: string`），不按 uuid —
  对外 id 一律 uuid 这条口径不破，也避免模型拿着 uuid 乱拼。值日缺省取第一位成员。
- 重名 / 查无此人一律拒并列出可选执事（与群端点的 @ 歧义拒绝同源）。
- 权限与 `partner_manage` 逐字一致：只有总管 / 主对话能调；执事自己的会话返回「只有总管可以建群」。
- 开关=`GROUPS_ENABLED` ∧ `COMPANIONS_ENABLED`（与端点同一个），关掉即不注册（一行回滚）。
- 进 `WRITE_TOOLS` 与自主轮风险表（`new_task`）：建群是"新建常驻多成员会话"，
  会改"谁跟谁在一起"，与 `partner_manage` 同档。
- 核心实现 `group-manage.ts` 的 `createGroupChecked()`：**HTTP 端点与工具共用一份**，
  端点只做形状映射（400 文案逐字未变，groups 探针 21 项回归全绿）。
