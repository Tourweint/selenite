# 手机会话同步回收端点 + 回忆模式退役（2026-11-17）

## 改了什么

两件同日落地的事，方案与取舍见 `docs/设计方案/2026-11-17-手机会话同步回收与回忆模式退役.md`。

### 1. 新增 `POST /api/v1/agent/chats/check`

- 新增 `ts/apps/server/src/agent/chats-check.ts`：纯判定 `missingChatIds(ids, {byExternal, archived, taskPrefix})`。
- `agent/session-index.ts` 新增 `missingChats(ids)`：一次 durable `Chats` 快照 + `chat-meta.archived` 先做便宜判定；
  剩下的 id 逐个读 `readChatStats`——**空会话（`turns == 0`）也算不在**（与 `GET /agent/chats` 可见性同口径）。
  读取异常不判死（留给下次同步）；LLM 未配置时回 `[]`（不把全部当已删）。
- `agent/session.ts` / `agent.ts` 补 re-export；`index.ts` 在 `GET /agent/chats` 之后挂端点
  （body `{ids}` 去重、截 500 条、非法值忽略）。
- `package.json` 测试清单加 `src/agent/chats-check.test.ts`（5 个用例）。
- 文档：`接口-存储工具与配对.md` §5、`接口-端点2-杂项日记与项目.md` 各补一行。

用途：手机同步时把本地绑定过的 conversationId 发来核对，只回已删除 / 已归档 / 任务专线的 id，
手机据此软删本地清单行。**不读正文**，可跟列表刷新同频调用。

### 2. 回忆模式（`interview` / `chapter` 任务）退役

- `tasks.ts` 删除 `interview`（`recall_interview_v2.md`）与 `chapter`（`recall_chapter_v2.md`）两张任务表。
- 删除 `prompts/recall_interview_v1.md`、`recall_interview_v2.md`、`recall_chapter_v1.md`、`recall_chapter_v2.md`。
- `scripts/task-probe.ts`：三个任务的回归用例由 `weekly/segment/interview` 改为 `weekly/segment/question`，
  并从 VARS/PARAMS 里删掉 interview/chapter；黄金用例（模板 ↔ App 资产逐字节）随任务表自动只覆盖剩余任务。
- 文档：`接口-端点1-对话与兼容层.md` 任务名表去掉两项；「客户端接入状态」由 8 个任务改为 6 个，
  并注明 `interview`/`chapter` 与 App 回忆模式同日退役。

App 侧同批删掉「回忆」入口、开场白生成、RECALL 分支与两份提示词资产；
`ThreadKind.RECALL` / `EntrySource.RECALL` 只作历史数据兼容保留。

## 为什么

用户拍板：电脑上删掉的对话，手机同步时应当清掉、不留在本机；
回忆模式"反正也没做"，以后直接跟记日记的执事「小记」聊，连 harness 模板一起删干净。

## 回滚

- 核对端点：手机端在端点 404 时自动跳过回收（无迁移、无状态），删掉调用即回到旧行为；
  服务端删掉路由即可，无落盘数据。
- 任务退役：`git revert` 本批；任务名表与模板同批删除，不存在半套状态。
