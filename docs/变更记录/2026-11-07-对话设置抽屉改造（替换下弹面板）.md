# 2026-11-07 对话设置抽屉改造（替换下弹面板）

## 为什么

上一版（583b6a0）把对话右上角设置做成下弹面板，用户反馈两点：图标自带齿轮中心圆看着像"画了个黑色的圈"很突兀；只能调模型，且下弹形态不是预期交互——预期是点击后从右侧拉起一个抽屉。

方案蓝本：`docs/设计方案/2026-11-07-对话设置抽屉改造方案.md`（实施细节另见同日调研文档）。经两轮调研核对，方案文档三处与代码/现状冲突，按实际口径实施：

1. **policy 接口是 GET + POST，不是方案写的 GET/PATCH**（服务端 `ts/apps/server/src/index.ts:350-352`，前端 `loadPolicy` 两处 POST）。落抽屉时照 POST 写。
2. **权限档二级页轻量重实现**，不复用 `loadPolicy()`——它 `getElementById("policy-switch")` 硬编码且无去重双绑，抽屉里复用会同 ID 相撞、双绑。分段工具 `mountSegmented`/`syncSegmented` 照常复用，抽屉内用 `cs-policy-*` 前缀 id。
3. **通知三时机没有现成逻辑**（现版只有开关单键）。按方案"纯前端、不加端点"定调：新增 `localStorage` 键 `lifediary.notify.timing`（`all | error | attention`，默认 `all` = 现行为），`maybeNotify` 加第 4 参 `kind`（done/error/attention）做过滤：`all` 放行全部；`error` 放行出错+待你处理；`attention` 只放行待你处理。`KEY_NOTIFY` 语义不动，无迁移成本。

## 改了什么

- `index.html`：入口图标换 lucide `Settings2`（横向调节滑轨，无齿轮中心圆），28×28 按钮、`title="对话设置"`、删 `aria-haspopup`；删旧 `#chat-settings-menu` 下弹菜单；body 级新增 `#chat-settings-overlay` 遮罩与 `#chat-settings-drawer`（`role="dialog"`）抽屉壳，内容全由 JS 渲染。
- `style.css`：删 `.top-wrap .composer-pop.drop-down` 一族与 `composerPopInDown/OutDown`、`.chat-settings-menu` 定宽限高；保留 `.chat-settings-batch` 系列（模型二级页继续用，选择器不依赖旧宿主）。新增：抽屉（fixed 贴右、max-width 448px、左缘 1px 分割线、无圆角无阴影）、遮罩（实色 `rgba(0,0,0,.45)`，**禁 backdrop-filter**——WebView2 黑块问题）、250ms `translateX` 进出动画（`prefers-reduced-motion` 归零）、首页四行（min-height 48px + chevron）、56px 二级页头部。
- `app.js`：
  - 状态机替换原 4410-4470 区段：`openDrawer`/`closeDrawer` 照抄 popTimers 模式（`DRAWER_MS=250`、`pop-open`/`pop-closing` 类、定时器播完再 `hidden`，reduced-motion 直接收尾）；底层聊天不卸载只挂浮层，滚动与输入天然保持；页面栈 `csPage = home | model | policy | notify`，返回回首页抽屉不关。
  - 首页四行：模型（副文本=当前模型）、权限档（打开时顺带 `GET /agent/policy`，失败显示 —）、通知（开/关+时机）、全部设置（跳 `#/settings` 并关抽屉）。
  - 模型二级页：原下弹面板的模型菜单 + 批量加模型整体搬入，`renderModelMenu` 零语义改动只换宿主；`syncChatSettingsTarget` 的宿主引用换成抽屉。
  - 权限档二级页：三档分段 + 写操作逐次确认开关 + 待处理审批计数入口（`GET /agent/approvals` 全局 pending，点击跳 `#/settings`）。
  - 通知二级页：主开关（`KEY_NOTIFY` 口径含 `Notification.requestPermission`）+ 三时机选择。
  - 事件：删 document 级 chat-settings 点外关分支（其余监听保留）；Esc 分支补 `isComposing || keyCode === 229` 输入法豁免（放 `modalOpen()` 判定前）；三通道关闭 = Esc / X / 点遮罩。
  - `maybeNotify` 全部 8 个调用点补 `kind` 实参（error→:3860/:3870/:3877，done→:3862，attention→:3734/:3738/:3848/:3854）。
