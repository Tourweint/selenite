# 外观字体设置：全站默认 + 分区字体 / 字号

日期：2026-11-13
状态：已落地（桌面端 web；纯前端 localStorage，无服务端契约）。

## 起因

用户口径：外观里给字体加一个修改按钮；支持宋体、之前的等线 / 无衬线；能按模块分别调
聊天区、设置区等，也可以只改部分区域；还能调字号。

## 改了什么

### 入口

- 设置 → 外观 → 新增「字体」行，右侧「修改」按钮打开字体弹窗。
- 弹窗结构：
  - **全站默认**：宋体 / 等线 / 无衬线；没单独设置的区域都跟随这里。
  - **聊天区 / 设置区 / 其他界面**：各自可选「字体（跟随全站 / 宋体 / 等线 / 无衬线）」
    与「字号（小 / 标准 / 大 / 特大）」。
  - 底部「恢复默认」「完成」；改动即时预览 + 自动保存，不用再点保存。

### 生效方式

- 全站默认写 `:root --font`；分区字体写 `--font-chat` / `--font-settings` / `--font-other`，
  未选「跟随全站」时删除覆盖，回落到 `--font`。
- 字号用 `zoom` 作用在区域根上（聊天 `#view-chat`、设置内容 `#settings-inner`、
  其他整页 `#view-tasks` / `#view-search` / `#view-groups` / `#view-domains`），
  并用 `width: calc(100% / zoom)` 反向补偿，放大后仍贴合容器。弹窗里已注明
  「字号会把区域的文字、间距和控件一起缩放」，不假装只动字形。
- **首页态不缩放**（`#view-chat[data-home="1"]` 强制 zoom:1）：问候与输入卡按
  50vh / 13vh 定位，zoom 会把整组往上抬；首页只有一句问候 + 占位符，字号跟随默认，
  开始对话后再按聊天区字号缩放。
- 弹窗和对话设置抽屉是 body 级元素，按当前路由打 `data-scope`，只跟随所在区域的字体，
  不跟随字号缩放，避免弹窗尺寸随区域字号跳。
- 代码 / 路径仍走 `--mono`；侧栏 / 标题栏不属于三个分区，只跟随全站默认。

### 存储

`localStorage["lifediary.fonts"]`：

```json
{
  "base": "songti",
  "chat": { "font": "inherit", "size": "md" },
  "settings": { "font": "inherit", "size": "md" },
  "other": { "font": "inherit", "size": "md" }
}
```

坏值 / 未知字体 / 未知字号在 `normalizeFontSettings` 里回落到默认，不写进 CSS。
「恢复默认」写回同一份默认对象；清掉这个 key 也等价于默认。

## 刻意没做

- 不做逐像素字号输入：四档缩放够用，也避免每个区域各自维护一套 px 换算。
- 不做独立字体设置页：外观页一行 + 一个弹窗足够，低频配置不占一级位置。
- 不改桌面壳原生消息框 / 壳兜底页字体：那些不是 web 页面，CSS 管不到。

## 验证

- `node --check ts/apps/server/web/app.js` 通过；`style.css` 花括号配平。
- 浏览器实机（IAB，39847 静态资源）：
  - 外观页「字体 → 修改」打开弹窗，三行区域 + 全站默认显示正常；
  - 聊天区改「等线 + 大」，`localStorage` 立即写入；刷新后 computed
    `font-family = DengXian`、`zoom = 1.12` 仍生效；
  - 聊天区在 900px 窄窗下放大后无横向溢出；
  - 首页态（新对话）在聊天区设「大」时位置与默认一致（首页不缩放），开始对话后
    消息区按 1.12 缩放；
  - 「恢复默认」后 computed 回到宋体、zoom=1，清除测试值。
- 未跑服务端单测 / 探针：本次只改 web 静态资源，无 TS 契约改动。
