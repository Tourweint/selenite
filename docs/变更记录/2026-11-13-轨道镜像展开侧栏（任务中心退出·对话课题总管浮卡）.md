# 2026-11-13 收起轨道镜像展开侧栏：任务中心/今日回顾退出，新增对话·课题·总管浮卡

用户口径：收起态要和展开态一一对应（第一个执事、第二个对话、第三个项目、第四个群组），
每个轨道钮悬停都要浮一张小卡；任务中心暂时不进轨道（放哪里另议）。纯前端。

## 改了什么

### ① 轨道顺序 = 展开态分区的镜像（index.html / app.js）
- 旧：总管 / 任务中心 / 今日回顾 / 项目 / 分隔线 / 执事 / 群组 / 课题 / 齿轮（顺序与展开态不一致）。
- 新：总管 / 分隔线 / **执事 / 对话 / 项目 / 群组 / 课题** / 齿轮 —— 与展开态分区顺序逐项对应。
- 任务中心、今日回顾两个轨道钮删除（用户明确：任务中心不用，位置另议；今日回顾是任务中心的视图）。
  入口保留：展开态「对话」分区底部「打开任务中心 →」、任务页底部的「今日回顾 →」；`#/tasks`、`#/review` 路由不变。
- 新增轨道「对话」钮（镜像展开态对话分区）；`applyRoute` 在对话路由下给它 `aria-current`。

### ② 每个轨道钮都有悬停卡（app.js / index.html）
- 已有：项目（`#proj-menu`）、群组（`#rail-groups-menu`）、执事（`#rail-partners-menu`）。
- 新增三张（同一套 `.proj-pop` 壳 + `attachRailCard` 行为）：
  - **对话卡**（`#rail-chats-menu`）：最近会话前 5 条，过滤/排序与展开态分区共用 `recentChatsOrdered()`
    （本次把 renderChats 的内联过滤抽成这个函数，两处不再各写一份）；行点开即进那条对话；
    卡底两行 = 分区头的两个入口（新建对话 / 搜索旧对话）。
  - **课题卡**（`#rail-topics-menu`）：进行中课题（与展开态同一份 `topicsSidebarList`）；点行 = 展开侧栏、
    滚到那条并展开时间线；卡底「展开侧栏查看 →」= 只落到课题分区。悬停时现拉一次 `/topics`。
  - **总管卡**（`#rail-chief-menu`）：头像/名字/总管标记/状态点（与展开态总管条目同一份信息）+「打开对话 →」。
    头像钮的点击仍是直接开对话（与展开态条目一致），卡只做悬停一览；点击前先收卡，
    避免已在对话路由时 hash 不变、applyRoute 不跑而留一张卡在屏上。
- 对话/课题卡的数据现拉（`asyncShow`），等回来时指针若已离开就不弹（与项目卡同一条守卫）。
- **点外关闭白名单修正**：原 document click 只认 `#rail-groups / #rail-partners` 及对应卡，
  新加的对话/课题/总管钮点一下会被「点外」逻辑立刻收掉。改成「`#side-rail` 内 + 任意 `.proj-pop` 内都算里面」。

## 明确不做
- 任务中心放哪（轨道没有、入口暂留分区底部）——用户明确「到时候再处理，需要再考虑」。
- 设置齿轮不出卡（单一动作，没有可总览的内容）。
- 手机端抽屉不动（本次是电脑端收起轨道的对齐）。
- 悬停卡不做键盘悬停等效（Tab 聚焦 + Enter 走点击路径，沿用既有口径）。
