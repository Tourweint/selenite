# 2026-11-24 工具异常处理 M0–M2

方案：`docs/设计方案/2026-11-24-工具异常处理与超时转后台.md`（M0 配置底座 / M1 证据类工具限时 /
M2 shell 策略与后台 generalize）。本批**只做 M0–M2 + 一个日志小修**；M3 / M4 / M5 明确未做（见文末）。

## 改了什么

### M0 配置底座（默认关，不改现有行为）

- 新增 `ts/apps/server/src/tool-policy.ts`：
  - 静态 catalog：能力组（shell / memory / search / collaborate / interaction / skills / meta）、
    工具 → 组、A/B/C/D 类别、`capabilities`（abortable / backgroundable / configurable）、锁定原因、范围。
    v1 可配 = `bash` / `powershell` / `recall` / `web_search`；其余工具是锁定行（只解释、不假装能配）。
    `onTimeout` 的本批结算范围：shell = `fail` / `background` / `cancel`；`recall` / `web_search`
    只允许 `fail`（任务书 M1 口径；`background` / `cancel` PUT 400）。
  - 落点 `.data/tool-policy.json`（`TOOL_POLICY_PATH` 可覆盖）；同目录临时文件 + rename 原子写，
    mtime + size 缓存现读（照 `tool-pool.ts`）。
  - 读盘消毒：未知顶层键 / 未知名字丢；`timeoutMs` 非有限数丢、越界 clamp、小数取整；
    `onTimeout` 不认识或能力不支持时记一条 `on_timeout_unsupported` 后丢；`notify` 非布尔丢；
    三字段全空 = 删除该条。
  - `resolveToolPolicy()` 优先级 `tools > groups > legacy > default`（每层只覆盖显式字段），
    `effective` 带 `timeoutMs / onTimeout / notify / source`。legacy = `AGENT_BASH_TIMEOUT_S`
    （bash）与调用方传入的 `memory-bank.json` 两档。
  - `applyToolPolicyPatch()`：PUT 局部更新（`null` = 删除回继承）；未知工具 / 组 / 注入名、
    锁定工具、不可后台写 background、非数字 timeout、非布尔 notify 各自给稳定错误码。
  - shell 挂点判定 `shellTimeoutInjectionSeconds()` / `shellTimeoutDecision()`：总开关关时
    逐字节回旧行为（只 bash 注入；只认 `AGENT_BASH_BG_TIMEOUT`）。
- 新增 `ts/apps/server/src/tool-policy-api.ts`：`GET/PUT /api/v1/agent/tool-policy`（形状与错误码
  按方案 §3.5）。总开关 `TOOL_TIMEOUT_POLICY` 关 → 两个端点都 404；开关 hot，handler 现读，
  打开 / 关闭下一轮生效，不需要重启。
- `ts/apps/server/src/index.ts` 挂载 `mountToolPolicyRoutes(app)`（`/api/v1/*` 鉴权之后）。
- `src/plugins.json` 新增 `TOOL_TIMEOUT_POLICY`（boolean，默认关，`hot:true`，autonomy 组）。

### M1 证据类工具限时

- `src/memory-bank.ts:bankAsk`（约 972 行）：外部 `recall` 的预算改为
  `resolveToolPolicy(env, { recall: config.timeouts.askMs })`；policy 没有条目时回落
  `timeouts.askMs`（master 关 = 原样）。onTimeout 只按 fail 结算，不转后台。
- `src/search-vendors.ts`：新增 `VendorCallInput.timeoutMs`；单源上限仍是 20s，传了预算时取
  `min(20s, 预算剩余)`；预算路径的 abort 返回稳定 `timeout` 错误码（不传预算 = 旧
  `upstream_error` /「搜索服务不可达」，文案不变）。
- `src/search.ts:webSearch`：新增可选第三参 `{ timeoutMs }`，把它变成**整次调用**的墙钟 deadline；
  每到一源先算剩余；预算耗尽 / 任一源超时且没拿到结果 → `{ ok:false, error:"timeout" }` +
  稳定文案「搜索超时（Ns）：没有拿到结果…」。不传第三参 = 逐字节旧行为。
- `src/agent/lifecycle-harness.ts` 装配 `search` 时包一层：每次调用现读 policy 的
  `tools.web_search.timeoutMs` 再传给 `webSearch`。
- `src/persona-ask.ts`：带 `--vector` 被库拒绝后的重试与第一次**共享同一 deadline**
  （`deadlineAt` 绝对时间；首次耗时算进第二次预算，最坏总耗时不翻倍）。预算已用完时不再 spawn，
  直接按超时结算。**日志小修**：`[persona-ask]` 的 `hits=` 改为优先取 `result.hits?.length`
  （外接库 anyGroups 模式），没有才回落到旧的分组累加——之前 anyGroups 恒记 0。
- **`injections.memoryLight` 已接线（补齐 M1 漏掉的消费点）**：`tool-policy.ts` 新增
  `memoryLightTimeoutMs(legacyLightMs, env)`；lifecycle 的轻召回接线
  （`agent/lifecycle-harness.ts` 约 1301 行）不再直接传 `bankTimeouts().lightMs`，而是
  `memoryLightTimeoutMs(bankTimeouts().lightMs)`。master 开 = policy 的
  `injections.memoryLight.timeoutMs`（显式条目 > legacy > 默认 8s）；master 关 = 旧 `lightMs`
  原样返回（逐字节旧行为）。只在接线处解析一处，`bankTimeouts` 语义不变。

### M2 shell 策略与后台 generalize

- `src/agent/lifecycle-harness.ts` `beforeTool`（约 920 行）：默认超时注入改为
  `shellTimeoutInjectionSeconds()`。master 关：只判 bash、值取模块常量 `BASH_TIMEOUT_S`（旧行为）；
  master 开：bash / powershell 都注入 policy 解析值。模型显式传了 `timeout` 一律不覆盖
  （`tools.bash.timeoutMs` 是默认注入值，不是硬上限，方案 §3.4）。
- `afterTool`（约 1125 行）：超时结算改用 `shellTimeoutDecision()`。master 关：只认
  `AGENT_BASH_BG_TIMEOUT`（background + 恒通知）；master 开：由 policy 的 `onTimeout` 决定
  `fail` / `cancel` / `background`，`notify:false` 时只写 index / log、不写会话、不投唤醒。
  `cancel` 结算 = `isError:true` + `canceled` 诊断 + 「不要重试」文案（只有 bash / powershell 可配）。
- `src/bash-background.ts`：`BgJobRecord` 增加 `tool?` / `kind?`（v1 = `shell`）/ `conversationId?`
  （全部可选，旧记录缺省按 `kind:"shell"`、`tool:null`、`conversationId:null` 读）；
  `moveToBackground` 接受并写入三个字段；`listBgJobs(dir, conversationId?)` 支持按会话过滤；
  新增 `canceledResult()`。
- `src/bg-jobs-api.ts`：`GET /api/v1/agent/bg-jobs` 带出新字段，支持 `?conversationId=`
  （非数字 → 400）；挂载条件从「`AGENT_BASH_BG_TIMEOUT` 开」放宽为「旧开关开 **或**
  master 开且任一工具解析为 `onTimeout:"background"`」。挂载判断在启动时做，
  运行期新开策略要重启后管理面才出现（与方案 §3.5 一致）。

## 回滚

- 整体回到今天：`TOOL_TIMEOUT_POLICY=false`（env 或插件页开关）。端点 404、策略不读、
  bash 注入 / 后台决策 / recall / web-search 全部走旧路径。
- 只回滚某个工具：`PUT` 该工具为 `null`（回继承）。
- 只回滚后台化：`bash.onTimeout="fail"` 或删除 bash 条目。
- 回到旧 bash 后台开关：master 关 + `AGENT_BASH_BG_TIMEOUT=true`。
- 记忆时长回旧入口：master 关，`PUT /memory/bank {timeouts}` 照旧。
