# 后台任务唤醒接线：信封泛化 + bg-jobs 接唤醒 + 变化检测（2026-11-19 批3）

方案：`docs/设计方案/2026-11-19-唤醒管道通用化与后台任务接线.md`（用户拍板："第四个非常好做，做一下"；学 ZCode 派后台任务，终端有变化/结束就拿到消息继续）。

## 改了什么

- **唤醒信封泛化**（`delegation-wake.ts`）：`WakeEnvelope = {source: delegation|bgjob|agent-message, targetPartnerId, payload}`。delegation 路径**逐字节不变**（既有 12 个测试一字未动全绿；纯 delegation 批仍走旧 `buildWakePrompt`）；新来源按 targetPartnerId 路由 + 执事存在且 active 检查。回滚 `WAKE_PIPELINE_V2=false` → 新来源入队与 flush 双处全不投（delegation-only）。
- **落盘兼容**：`.data/wake-pending.json` version 2（条目带 envelopes），启动恢复兼容旧 `reports` 形状（包回 delegation 信封照常跑）。
- **bg 完成唤醒**：`onFinished` 写记录之外投 `source=bgjob` 信封（命令摘要+退出码+尾部≤400字），目标=发起会话所属执事 canonical 主会话。回滚 `BG_JOB_WAKE_ENABLED=false` 回"只写记录"。
- **变化检测**（ZCode 式）：运行中日志有新字节且距上次触发 ≥ `BG_JOB_WATCH_INTERVAL_S`（默认 0=关）→ 投同款信封；监听挂 `moveToBackground` 闭包，进程收口即撤，不建独立注册表。
- **agent-message 入口预留**：`wakeOnAgentMessage` + 提示词已备（当前无调用方）。送达链核实结论：内核空闲 submit 即开轮——**send_to_agent 本就具备等价唤醒**，本批不接线；唯一空缺=对端无会话时送达失败，补 `ensurePartnerSession`（对齐身份+钉工作区、不发问候）。
- **Windows 后台日志缺陷修复（附带发现）**：`detached:true` 在 Windows（DETACHED_PROCESS）下子进程拿不到任何 stdio 句柄——**bg 日志自 2026-11-09 上线起在 Windows 上恒空**（实测：exit 0、日志 0 字节），与本批的尾部摘要/变化检测直接冲突。改 `detached: process.platform !== "win32"`：POSIX 逐字节不变（进程组长 + `kill -pid` 保留）；Windows 子进程照样活过父进程退出（实测）、kill 走 taskkill /T /F 不受影响，日志恢复有内容。

## 验证

- `pnpm typecheck` 全绿；全量单测 1198/1193，5 红与主干既有清单逐名一致（arch-guard×3 / auxiliary split pin / partner-work EPERM）；新增 14 个测试全绿（信封路由×10 + bash-background×4）。
- 变化检测单测用**真进程**（node 渐进输出 + 1s 间隔 → 恰触发一次变化回调、收口恰一次）。
- 端到端探针（真起服务唤醒落会话）随批2/批4 联调统一跑。

## 边界（刻意没有 / 已知限制）

- 投递状态机不做（批5 拍板点到为止）：沿用防抖/退避/落盘恢复，无结算、无重试预算。
- bgjob 目标解析按"发起会话任意 role 链接"：side/群会话跑 → 唤醒落该执事 canonical 主会话；**无主会话的会话（如 worker 任务助手对话）跑 bg 命令 → 不投、只写记录**——worker 会话要不要也投未拍板，先如实登记。
- 变化检测只 tail 唤醒，不把输出实时流进上下文。
