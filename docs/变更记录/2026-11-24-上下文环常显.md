# 2026-11-24 上下文环：每次固定显示（修零用量播报遮真实用量）

## 用户口径

「对话框里的上下文小圆圈有时候不显示、有时候显示。我觉得是每次都重新加载，有加载失误的时候。
调查一下，把它弄好，**每次都固定显示**就行。」

## 根因（证据级：读代码 + 查 `.data/agent.sqlite`）

1. `GET .../chat/:id/context` 的 `used` 取"从末尾往前第一条带 usage 的 `pi.assistant`"，
   但**播报条目**（`lifediary.say`：派活上报 / 进度回写 / 执事问候 / 任务专线）也写成
   `pi.assistant`，usage 全 0，于是被当成最后一次用量 → `used=0` → 接口回 `null` → 环整块隐藏。
   最近 60 条条目里 48 条是 `lifediary.say`；某个会话末尾连续 8 条都是它。
2. 新会话还没有真实用量时，旧实现连 `window` 都不给，环要等第一轮结束才出现。
3. `syncCtxMeter` 的 `catch` 无条件隐藏；一次网络抖动就会让已经画好的环消失。

## 改了什么

| 文件 | 改动 |
|---|---|
| `ts/apps/server/src/agent/session-transcript.ts` | `lastTurnUsageOf` 跳过 prompt 用量为 0 的 assistant 条目（继续往前找真实测量）；`contextUsageOf` 先解析窗口，`used:null` 时仍返回 `{window, breakdown}` |
| `ts/apps/server/web/chat-notice.js` | 有 `window` 就画环；无测量时画空环、卡里写「尚未统计 / 窗口」、`aria-label` 同步；读取失败保留同会话旧画面（换会话首拉失败才隐藏），网络错误重试一次（700ms） |
| `ts/apps/server/web/composer-send.js` | `start` 帧到达即 `syncCtxMeter()`（新会话第一轮期间也有环） |
| `ts/apps/server/web/style-05-message-extras.css` | `.ctx-ring.unmeasured .ctx-track` 虚线轨道，区分「没测过」与「0%」 |
| `ts/apps/server/src/context-inspect.test.ts` | 新增 2 例：零用量播报不遮真实用量；无测量时 `used=null` 但窗口仍在 |
| `ts/apps/server/scripts/http-probe.ts` | §12 先 `POST /say` 再查 `/context`，回归播报条目不遮用量 |

## 为什么这么定

- **跳过零用量而不是"客户端记住最后值"**：`used` 的语义是最后一次**模型请求**的 prompt；
  播报不是请求，往前找才是真实值。客户端缓存在刷新 / 换设备后会丢，且两份事实。
- **`used:null` 不改成 0**：0% 会被读成"真的没占上下文"。空环 + 「尚未统计」如实。
- **窗口与用量分开给**：窗口来自会话模型，和有没有测量无关；老客户端把 `used:null` 当隐藏，
  行为逐字不变。
