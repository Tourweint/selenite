# 2026-11-24 「工作 N 步」与顶栏头像提示退役，顶栏标题不再开选择器

## 改了什么

1. **`web/tool-chips.js`**：行首「工作 N 步」折叠条不再设置 `title`（原为
   「展开这一轮的完整过程 / 收起这一轮的步骤」）。`aria-expanded` 与 `aria-label` 保留，
   开合语义仍可被读屏读到。
2. **`web/partners-status.js`**：对话顶栏头像不再设置 `title`（原为执事名字）；
   整块收起时也不再 `removeAttribute("title")`（已无来源）。头像只画脸，名字由旁边的 `#title` 承担。
3. **顶栏标题的「选择会话」入口整体退役**：
   - `web/chat-open.js`：删 `syncTitleSessionAffordance` / `openCurrentSessionPicker`、
     `#title` 的 click 与 keydown 监听、三处调用与导出；同时去掉 `openPartnerSessions` 的 import。
   - `web/partners-status.js`：删 `loadRoster` 里的两处调用与 import。
   - `web/partner-sessions-ui.js`：`onSideSessionsDisabled` 不再复位顶栏可点态。
   - `web/style-04-chat-base.css`：删 `.top h1.is-session-picker` 的三条样式。
   - `web/state.js`：`sideSessionsEnabled` 注释改成「侧栏右键菜单」，与 2026-11-23 的入口收口对齐。
   - **保留**：侧栏总管 / 执事行的右键菜单「选择会话」、会话地图页的「切换」入口。
4. **头像不再被轮询反复读取（2026-11-24 第二批）**：
   - `web/tasks-live.js`：`autoSyncTick` 的兜底刷新从 `loadRoster()` 换成
     `refreshRosterDomains()`。原实现每 60s（看板 20s）拉一次 `/api/v1/partners`，
     而每条记录都内联头像 base64（实测总管 116,654 字符、小记 129,226 字符）；
     每拉一次就整份花名册重绘，头像跟着闪一次。
   - `web/partner-roster.js`：新增 `refreshRosterDomains()`——只 GET `/api/v1/domains`，
     就地更新行内「N 单」与忙因胶囊（`syncRosterCounts` / `syncRosterBusy`），
     不重建行、不重建头像 `<img>`。待派数字仍按原频率更新。
   - `web/avatar.js`：`paintAvatar` 同图不重画——`src` 没变直接留用现有 `<img>`，
     避免同一节点重复 paint 时重新解码 data URL。
   - 花名册本身仍是「页面刷新 / 启动 / 改执事 / 改头像」时由 `loadRoster` 读一次，
     切页面与心跳轮询不再读。

## 为什么

2026-11-24 用户口径：

- 「工作 N 步」上的原生提示有时悬着不消失，反而挡住下面的步骤；这类解释性文字没必要。
- 顶栏头像旁的悬停提示（名字）同样没必要——名字本来就在旁边。
- 顶栏标题（头像紧贴其左侧）点开选择器容易被误当成头像交互，入口只保留在侧栏右键。
- 头像「读一次就留在前端」；切页面不算刷新，刷新页面时才重新读。原先的 5s 心跳兜底
  每 60s 重拉整份带头像的花名册，是头像反复加载的来源。
