# 2026-11-22 原生菜单行鼠标点击失效（侧栏 ⋯ 菜单点不了）

## 现象

侧栏分区头与会话行右侧的 ⋯ 展开原生小窗菜单后，鼠标点菜单项没有任何反应；
浏览器（DOM 菜单）不受影响。

## 根因

`desktop/popovers.go` 的 `menuView` 从批1 起只接了**悬停高亮**与**键盘 Enter**
（`row.Hovered()` / `c.Shortcut(0, ui.KeyEnter)`），**行从未声明 `Clicked()`**——
按下落在行内的文字子元素（无输入）上，不会回给任何元素，菜单自然"只能看不能点"。

这条一直没暴露，是因为 `Shell.ShowMenu(req, ctx)` 的 ctx 参数位置错了（mygo 只认
`In(0)` 注入），每次原生菜单 Show 后 `ctx.Done()` 当场 panic → 页面粘性关原生 +
开 DOM 兜底菜单；用户实际点到的是**底下那张 DOM 菜单**（"底下那张可点"）。
2026-11-21 双卡根修把 ctx 挪到第一位后兜底退场，原生菜单成为唯一一层，
"点不了"立刻显形。

## 改了什么

`menuView` 的行循环里补上鼠标选中，与键盘 Enter 汇到同一个 `menuPick(i)`：

```go
if !item.Disabled && row.Clicked() {
    menuPick(i)
}
```

- `Clicked()` 同时把 `flagClickable` 记到行上，下一帧按下才会命中这一行（行内文字没有输入）；
- 禁用行不声明可点：点它不选中、菜单不关（与 web 的 `disabled` 同义）；
- 分隔线不是行，不受影响。

  修前红（"鼠标点击菜单行没有把序号回给通道"），修后绿。
- `gofmt` / `go vet ./...` / `go test ./...`（desktop）全绿。

- 用 `build.ps1` 同款参数构建到临时路径通过（未覆盖运行中的 `lifediary-shell.exe`）。

## 没验 / 边界

- 真机壳内点击未复验（需重编 `lifediary-shell.exe` 并重启壳）；测试走的是 mygo 的
  headless 输入管线，与真机同一套状态机，但真机仍建议点一次侧栏 ⋯ 的重命名 / 归档。
- 触屏与右键（`openMenuAt`）走同一个 `menuView`，一并覆盖，同样未真机点验。
