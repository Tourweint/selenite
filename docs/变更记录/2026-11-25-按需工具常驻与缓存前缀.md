# 2026-11-25 按需工具常驻与缓存前缀

前情：`docs/设计方案/2026-11-25-命中率下降与缓存前缀.md`（审计与取舍，本文只记落地）。

## 改了什么

1. **按需工具默认常驻**（`tool-pool.ts`）：`DEFAULT_DEFERRED_TOOL_NAMES` 从 9 个改为 `[]`，
   所有工具默认每轮带完整定义；按需池改为 `.data/tool-pool.json` 显式 opt-in（重启生效）。
   原 9 个名字保留在代码头注释里作回滚参照：
   `routine_manage` / `partner_manage` / `group_manage` / `save_skill_advice` /
   `partner_skill_write` / `propose_project` / `send_to_agent` / `respond_escalation` /
   `save_reminder_advice`。
2. **`tool_index` 改走尾部注入**（`agent/lifecycle-injections.ts`）：channel `system` → `message`、
   scope → `turn`，从 `LIFECYCLE_SECTION_PROVIDERS` 挪到 `LIFECYCLE_MESSAGE_PROVIDERS`；
   `INJECTION_ORDER.tool_index = 70` 的值不变。`agent/lifecycle-harness.ts` 删掉 system 里的
   `tool_index` 段，`beforeRequest` 从 `AgentDoc` 快照（`tools` / `modelTools`）现算当前
   可加载的 deferred（已启用、未加载、未被按人取消），放进注入上下文；首轮实文审计
   （`noteRequestInjections`）现在把 `tool_index` 记在消息注入里。
   `context-defaults.ts` 的 system 段清单 29 → 28，不再有 `tool_index`。
3. **修 `RequestMessageDiff` 的 `replaced` 假阳性**（`request-stats.ts`）：消息层对比改为
   比较两条请求各自**发出去之前**的 prompt（`context({at: 请求 entry 的前一条})`），
   不再把上一条请求自己的回答与内核补的 `Tool result unavailable` 占位算进前缀；
   拿不到前一条时退回旧视图。
4. 设置页文案（`web/settings-tools.js`）：恢复默认按钮的提示改为「当前默认全部常驻」；
   空按需池本身已有「工具面全部常驻」文案，无硬编码名单。

## 为什么

审计会话 `3971` 的四次命中率坍塌：#7（entry 4016，33,043 tokens / 6%）与
#11（entry 4035，35,666 / 5%）都是 `tool_search` 加载低频工具时 `tool_index` 段与工具声明
同时变化；#33（141,295 / 0%）是上游 502 后切换网关，前缀未变；#58（213,804 / 2%）是
`delegate` 描述变更（本次不处理）。

#7/#11 在真实使用里反复发生，不是「一次性代价」。默认常驻后工具面稳定，固定前缀多出
约 2.6k token，由前缀缓存摊薄；按需机制保留为 opt-in，想裁剪的部署仍可显式启用。
`tool_index` 属动态内容，按 2026-11-19 的前缀不变量应走尾部，不该占 system 段。

**缓存前缀变化（有意的、一次性）**：①默认工具面从「12 个左右 + 按需」变为「全部常驻」，
所有部署升级后第一次请求会全量 miss；②system 段去掉 `tool_index`，system 前缀随之变化一次。
之后默认配置下前缀不再因工具加载而断。工具 name / description / 注册顺序均未改动。

- `tool_index` 尾部注入：代码回滚（provider 的 channel / scope + 注册表位置 + lifecycle
