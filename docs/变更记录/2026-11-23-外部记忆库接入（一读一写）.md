## 改了什么

索引页顶部可以切「原生（本机） / 外部接入」，**工具名不变**：`recall` 读当前库、
`remember` 写当前库。外部库只经两个 Python 文件：`ask.py`（读）/ `repair.py`（写）；
Lifediary 不打开外部数据库、不跑 SQL、不知道表名。

1. **新模块 `apps/server/src/memory-bank.ts`**
   - 配置 `.data/memory-bank.json`（`MEMORY_BANK_PATH` 可覆盖，原子写、mtime 缓存）：
     `{v:1, active:"builtin"|"external", external:{id,name,root,ask,repair,python,origin,addedAt}|null}`。
   - 首次启动且文件不存在时按 `PERSONA_MEMORY_ASK` 播种 external（`active` 仍为 builtin）；
     文件一旦存在 = 唯一事实源。
   - 查找：`<root>/ask.py` → `<root>/analysis/ask.py`；`repair.py` 取 `ask.py` 同目录。
     root 必须绝对路径且存在；脚本解析后必须仍在 root 内（`..` + realpath 双重检查）。
   - 能力：`activeBank` / `isExternalBankActive` / `bankWritable` / `bankCatalog`（10 分钟缓存）/
     `probeBank` / `setExternalBank` / `deleteExternalBank` / `bankAsk` / `bankWrite`。
   - 不 import `agent/*` 与 `tools.ts`（避免环）。
2. **端点**（`memory-api.ts`，全部挂 `/api/v1/agent/memory`，走现有鉴权；静态段在 `/:id` 前）：
   `GET /bank`、`PUT /bank`、`POST /bank/probe`、`PUT /bank/external`、`DELETE /bank/external`、
   `GET /bank/catalog`、`POST /bank/search`。旧 `GET /memory/external` **原样保留**。
3. **工具路由**（`tools.ts`）：
   - `ToolDeps.memoryBank`（结构注入，不 import memory-bank）。
   - `recall`：external 走 `bankAsk`，输出仍用 `renderPersonaAsk()`，形状仍是 `{count,message}`；
     失败返回 `err("memory_unavailable", ...)`，**不抛、不回落内置库**。
   - `remember`：external 调 `repair.py statement`（`body=args.content`、`why="用户让记住"`）；
     `kind/scope/project/importance/expiresInDays/taught` 不生效，消息里明说；
     写开关关 / 只读库返回「写入未开启」，**不 spawn**。
4. **装配与闸门**（`agent/lifecycle-harness.ts`）：
   - `MEMORY_BANK=true`：不传 `personaAsk`/`personaWrite`，改传 `memoryBank`；两者互斥。
   - 外部 `remember` 按写工具对待：`AGENT_TOOL_POLICY=read-only` 必须拦（文案说明换档 /
     `MEMORY_BANK=false` 切回原生）；审批按 critical——`ask-critical`/`ask-all` 都问，
     `approval=none` 显式不问，且**不复用内置 remember 的「本会话记住该工具」一次性放行**；
     无人值守按 `persona_write` 能力声明判 `skip`。判定提成纯函数
     `externalRememberBlockReason()` / `externalRememberApproval()`（可单测）；内置模式判定逐字节不变。
   - 注入：external → `persona_catalog` + 轻召回走当前 bank，内置 `memoryRecallProvider` 跳过；
     builtin → 目录与轻召回都不注，`memoryRecallProvider` 照旧；`projectIndexProvider` /
     `taskMemoryProvider` 不动。`MEMORY_BANK=false` 完全回到旧注入（env + `PERSONA_MEMORY_INJECT`）。
   - 目录刷新定时器按槽位二选一（`startBankCatalogRefresh` / `startPersonaCatalogRefresh`）。
5. **开关**：`plugins.json` 新增 `MEMORY_BANK`（memory 组、boolean、默认 true、`hot:false`、
   `scope=core`）；`.env.example` 补 `MEMORY_BANK` / `MEMORY_BANK_PATH`（只写变量名）。
6. **工具面变化（缓存前缀资产，必须登记）**：
   - `MEMORY_BANK=true`（默认）：`persona_recall` / `persona_write` **不再注册**，
     由 `recall` / `remember` 覆盖；无论 `active` 是 builtin 还是 external，工具名都是这两个
     （外部只读库时 `remember` 仍注册，调用返回只读错误；不动态摘工具）。
   - `MEMORY_BANK=false`：今天的 `recall`/`remember`/`persona_recall`/`persona_write` 原样。
   - 工具描述 / schema / 注册顺序未改；只是条件注册的两个工具在默认形态下消失。

## 为什么这么做

- 用户口径（2026-11-23 晚）：外部库只暴露 `ask.py` / `repair.py`，harness 只起进程、传 argv、
  读 stdout；库内表结构、打分、内化、定时任务归库主。跨仓契约越小越稳。
- 换库不改工具名：模型和旧会话不需要知道「背后换了一个库」；回滚只需 `MEMORY_BANK=false`。
- 外部写必须过闸门：`remember` 内置形态只写可清理的小库，外部形态是「起进程写用户一生的库」，
  按写工具 + critical 对待是硬约束，不是模型自觉。

## 回滚

- 一行：`MEMORY_BANK=false`（重启生效）→ 旧工具面 + env 注入 + 内置库；外部库配置保留。
- 单库回滚：界面「移除」或删 `.data/memory-bank.json`。
- 写回滚：`PERSONA_WRITE_ENABLED=false`（外部 `remember` 回「写入未开启」，不 spawn）。

## 前端（同日收口）

- 索引页顶部「记忆库」卡拆成**上块切换 / 下块内容**：上块 = 原生/外部段控 + 当前库状态 +
  文字链；下块只在外部态出现 = 库边界 + 搜索，中间一条分隔线。
- 动作收成文字链：`接入外部库` / `更换目录` / `移除`；原来的「切回原生」「切换到此库」
  两颗主按钮合并进「原生 / 外部」段控，不再重复。
- `操作手册` 弹层 + 复制按钮：两个入口文件契约、当前 Python 运行器说明、表/内化/召回边界；
  UI 文案不再写死 `.py`（表单说「两个入口文件」，检测说「读入口 / 写入口」）。
- 只读库：状态显示「只读」；检测结果显示「只读（没有写入口）」；切换 toast 明确
  「recall 读它，remember 不能写」。
- 卡上不再放固定解释行；「工具名不变」放进标题 tooltip。工具描述 / schema / 注册顺序未改。

## 联调补修（2026-11-23 收口）

真起后端 + 真页面联调时发现并修掉两处契约边：

1. **外接库组名不固定**：原实现复用 persona 的六组解析，第三方库返回 `groups: {"notes": [...]}`
   会被整段丢掉、`groups: {}` 会被当成结构不符。改为外接库走 `anyGroups` 模式：
   `Object.entries(groups)` 全量扁平化成 `hits`（`hit.group` 原样带出），空 `groups` = 合法空结果；
   渲染改用 `renderExternalBankAsk()`，轻召回 / 页面搜索也吃扁平 `hits`。内置 persona 六组路径不变。
2. **外接库目录标题**：原文案写「可用 persona_recall 工具查询」，但槽位模式下该工具已不注册；
   新增 `EXTERNAL_BANK_CATALOG_TITLE`（「可用 recall 工具查询」），只用于外接库目录段。

顺手补了 `flags.test.ts` 的本地类型（`UI_SELECT_MENU` 的 `group` 断言），属测试类型遗漏，不改行为。

## 入口不限语言（2026-11-23 收口）

原来只认 `ask.py` / `repair.py` + `PERSONA_PYTHON`。用户口径：不一定是 Python。
现在：

- 文件名固定为 `ask` / `repair`，**扩展名决定运行器**：
  `.py` → `PERSONA_PYTHON`（缺省 `python`）、`.js`/`.mjs`/`.cjs` → `process.execPath`（宿主 node）、
  `.sh` → `bash`、`.ps1` → `powershell -NoProfile -ExecutionPolicy Bypass -File`、
  其他 / 无扩展名 → 直接执行该文件。
- 查找：`<root>/ask.<ext>` → `<root>/analysis/ask.<ext>`，扩展名顺序
  `.py → .js → .mjs → .cjs → .sh → .ps1 → .exe → 无`；写入口只找读入口同目录。
- 子进程 `cwd` = 库根目录（入口里用相对路径可用）。
- 实现：`persona-ask.ts` / `persona-write.ts` 新增 `command` + `cwd` 注入（外接库走它；
  内置 env 路径仍走 `PERSONA_MEMORY_ASK` / `PERSONA_PYTHON`，逐字节不变）；
  `memory-bank.ts` 的 `resolveExternalBank` 多给 `askCommand` / `repairCommand`，
  `bankAskCommand()` 供注入层取命令。`repair` 允许为空（只读库），探测结果里省略该字段。
- 手册与 UI：接入手册新增「必须提供什么」一表 + JS 最小示例；界面「操作手册」同步改写，
  表单文案改为 `ask（读，必填）+ repair（写，可选）`。
