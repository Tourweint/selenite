# 2026-11-25 侧栏收起/展开：图标不再消失重画，同一个图标跟着侧栏走

## 用户口径

「希望这个图标不要再有变化，就是这一个图标。现在应该是展开的时候把侧边栏的这个图标消失，
然后再产生一个新的对应。」选定范围：**全部分区图标**（总管、执事、任务、项目、群组、设置齿轮）。

## 改了什么

1. **`web/sidebar-morph.js`（新增）**：收起/展开动画期间的图标飞行。
   - 轨道层（`.side-rail`）临时锁成收起宽度（宽屏 `var(--rail)` = 72px、窄屏 48px），
     否则 `align-items:center` 会让图标跟着列宽右移；同时强制可见、`z-index:3`
     （压过展开层底栏的 `z-index:2`，否则飞到齿轮槽位时会被底栏底盖住）。
   - 只让**图标本体**（`#rail-chief .pt-avatar` / 各 `rail-* svg`）按实测的
     `translate + scale` 飞向展开层自己的槽位：22px → 分区头 20px（×0.909），
     头像与齿轮尺寸不变。展开层对应图标先置 `opacity:0` 占位（`.is-flight-hidden`），
     布局不跳。
   - **颜色与有效透明度一起插值**：分区图标轨道是 `text-2`、展开是 `text-3`；
     禁用占位（群组）轨道按钮 `.38`、展开分区头 `.5`。只飞位置会在换手那一帧跳色/跳灰，
     所以把轨道按钮自己的 opacity 临时让位给图标本体，按「祖先 opacity 乘积」从起点
     过渡到终点（颜色同样读两端的 computed color）。
   - 落定那一帧交换两层：摘内联 transform / color / opacity、摘占位类、轨道层钉到最终可见性
     （`.is-icon-flight-end`），全程只看得见一个图标；不会在轨道槽位留下淡出的重影。
     压过渡用的 `transition:none` 也在落定后收掉，图标上不留内联样式。
   - 动画没完又点一次时按当前帧接着反飞（`midRects`），图标不跳。
2. **`web/shell.js`**：`toggleSidebar()` 写完 `data-sidebar` / inert 后调 `animateSidebarIcons()`。
3. **`web/style-02-sidebar.css`**：
   - 飞行期间轨道层的锁定规则、`.is-icon-flight-end`、图标占位与
     `rail-btn` 背景压平（否则 `aria-current` 的黄底会留在轨道槽位）；
   - `.rail-sep` 加 140ms opacity 过渡（分隔线跟着淡出，不硬切）；
   - 内容淡入延后：`html[data-sidebar-flight="on"] .sidebar-inner`
     从 80ms 起跳改成 **200ms 起跳 + 160ms**。图标飞行时文字先别抢，200ms 时图标已基本
     落到各自分区头，文字再补上；200 + 160 = 360ms，与展开时长同一拍，总时长没变。
     这个属性由飞行模块置位，回滚关掉飞行时淡入回到原来的 80ms 起跳。
4. **`web/style-11-composer-tools.css`**：窄屏媒体块补 `:root { --rail: 48px; }`，
   收起宽度与飞行共用同一口径（原来 48 只在 `.sidebar` 里硬写）。

## 为什么这么做

展开层与轨道层是两套 DOM，原来的交接是「轨道淡出 180ms / 内层延迟 80ms 淡入 220ms」，
每个图标都会先消失、再在另一个位置出现。用户要的是**同一个图标元素**全程可见，
所以只能把轨道图标当唯一可见层飞过去，落定后再换手；单纯调淡入淡出时长解决不了
「两个元素」这件事。

## 回滚

- URL 带 `?iconflight=off`，或 localStorage `lifediary.sidebarIconFlight = "off"`，刷新即回到原形态
  （`data-sidebar-flight` 置 `off`、不匹配延后规则，内容淡入也回到 80ms）。
- `prefers-reduced-motion: reduce` 下直接跳过飞行。

## 验证

- 真服务 39847 + headless Chrome 真页面（1280×820）：
  - 收起 → 展开：rAF 采样 71 帧，轨道层全程锁 72px，`groups` 图标 y 从 248 平滑到 587.6，
    落定后 `transform:none`、无占位类；截图逐帧看过，任意时刻只有一套图标。
  - 展开 → 收起：图标从展开槽位飞回 248，内层 110ms 淡出，落定无重影。
  - 动画中途（130ms）再点一次：收起中途 / 展开中途两个方向都试过，从当前帧继续反飞，
    无跳变，最终态正确。
  - 颜色与有效透明度：展开时 `groups` 图标 color 从 `rgb(110,107,126)` 连续插到
    `rgb(154,151,165)`；落定后图标上没有任何内联 `style`（transform/color/opacity/transition
    全部收回），`transform:none`、无占位类。群组禁用态本环境未出现，另用 CDP 临时把
    轨道钮与分区头都设 `disabled` 验过一次：飞行中 20ms 采样 `opacity 0.404`（从 .38 往 .5 走）、
    颜色在 text-2 → text-3 之间插值。
  - `?iconflight=off`：无飞行类、轨道按旧路径淡出、内容 80ms 起跳（旧手感）。
  - 窄屏 560×820：收起态 `.sidebar-inner` 是 `display:none`，展开槽位用一次临时摊开量出
    （同一任务内还原）；收起时 `groups` 从 597.6 飞回 248，轨道锁 48px。
- `node --check web/sidebar-morph.js`、`node --check web/shell.js`。
- **没跑**服务端单测 / 探针：改动只在 web 静态层，未动 HTTP 契约或服务端逻辑。
- **没验**桌面壳内嵌页面（同一份 web 资源，未在壳里逐帧看）；也没在真机窗口里看手感，
  只看了 headless 帧与量测。

## 已知边界

- **窄屏**展开时 `.sidebar-inner` 从 `display:none` 直接切 `display:flex`（原有形态），
  没有淡入过程，所以图标飞行会经过已经可见的内容；宽屏有 200ms 的延迟淡入错开。
- 分区图标落在**折叠线以下**时（窗口很矮 / 列表很长），目标本来就在可视区外，
  图标会飞出视口，落定后也仍在折叠线外——与最终布局一致，没有额外处理。
- 无项目时 `#rail-proj` 是 `hidden`，这一对跳过飞行，展开层图标按原路径淡入。
