## 为什么这么做（取舍摘要，详见方案）

- **ChatGPT / Claude 不是漏做**：它们的记忆在 OpenAI / Anthropic 账号服务端，本机只有
  会话缓存/导出文件，没有记忆条目库；A 版取消文件导入后只能灰着。Claude Code 是本地
  `~/.claude/projects/<项目>/memory/*.md`，已接；Codex CLI 本地库空，灰。
- **项目级记忆进 global**：沿用同日补充轮的口径——召回是相关性打分 + 窗口截断，不是
  全量注入；命中登记项目则落 `project:<uuid>`，没命中才加【项目名】前缀。
- **不做会话蒸馏 / 云端在线拉取 / 服务端批量端点**：会话是"说过什么"，记忆是"关于你
  留下了什么"；批量由前端循环，少一个要维护的契约。
- **默认全选**：图"一键"；导入只增不改、重复跳过，用户可先全不选再逐家勾。

## 2026-11-15 逐条分类（第四轮）

用户问「导入的这些记忆，它是按照偏好、事实、经历怎么分类的？这个是不是没有啊？
我感觉不多，做得可能不详细」。先查了库和代码，答案是：**旧版确实基本没有按条分类**。

- 旧版 kind 主要是文件级/来源级 fallback：`kindFromMeta` 看 frontmatter，`qoderCategoryKind`
  看目录 `user_`，`kindFromFileName` 看文件名 `user_/feedback_/project_`；
  `parseSourceFile` 把整份文件的所有 section 共用一个 kind。标题写成 `【用户偏好】`
  「【完成情况】」也不参与判断。
- 本机 `source like 'import:%'` 的 193 条：**fact 163 / preference 30 / episode 0**。
  项目日志、用户偏好大量被压进事实，经历一条都没有。

改动：

1. **`memory-import-sources.ts` 新增逐条分类器**：`kindFromMetaOrNull` 区分"显式 meta"与
   fallback；`fileKindHint` 识别 `USER.md / feedback / preference` 和
   `episodes / session / daily`；`classifySourceKind(text, fallback, {file, explicit})`
   对每个 section 判一次。优先级见方案 §3.1。
2. **占位过滤**：`isHeadingOnly`（只有一行 `# 标题`）与 `empty — no memories saved yet`、
   `PLACEHOLDER`、`待填充`、`暂无记录` 等标记不产出条目；OpenClaw / AutoClaw 的空模板
   不再变成"偏好"。
3. **边界**：技术文本里的「风格一致 / 组件规范」留在 fact；用户明确说「不喜欢紫色 /
   偏好深蓝」、`USER.md`、`用户 + 希望/不要/反对` 落 preference；`## 任务描述 +
   ## 执行过程 + mermaid`、`【完成情况】`、日期 + 已修复/已落地 落 episode。
4. **已有 193 条回填**：只回填明确可判的 10 条（9 条经历 + 1 条偏好），不整库重刷；
   回填前先做 SQLite backup 到 `%TEMP%\lifediary-memory-before-kind-reclass.db`。
   回填后 `import:%` = **preference 31 / fact 153 / episode 9**。

验证：

- `pnpm typecheck` 通过。
- `memory-import-sources.test.ts` **18/18** 通过（新增「按单条内容区分偏好 / 事实 / 经历」
  用例；OpenClaw 的「不喜欢紫色」断言从旧的 fact 修正为 preference）。
- `memory-api.test.ts` + `partner-relay.test.ts` **46/46** 通过。
- 重启 39847 后浏览器：项目 `lifediary-harness` 75 条显示 `偏好 5 / 事实 67 / 经历 3`；
  「我的记忆」42 条仍是 `偏好 15 / 事实 22 / 经历 5`（global 本轮没有回填）。

## 还有哪些不确定

- **条数会漂**：`count` 是解析后条目数，跟各家自己的"记忆条数"不一定一一对应；
  ZCode 本机从 212 涨到 213/218 就是新写入的文件；2026-11-15 下午实测总数为 459。
- **灰态清单会过时**：目录名/产品名会变；本表是 2026-11-15 本机实测，路径改了要重盘。
  ChatGPT / Claude 已按用户要求删除；如果以后接了账号导出，再另立来源，不直接复活灰卡。
- **「没检测到本地记忆」默认展开**：用户要求"都列出来"，所以没有默认折叠；18 张灰卡
  会让弹窗正文较长（底条仍可见）。若用户嫌长，下一轮改默认折叠即可。
- **来源组合并的不是记忆内容**：合并的是导入弹窗里的**来源卡**——例如原来 `Qoder CLI`
  和 `Qoder CLI（项目）` 两张卡，现在折成一行「Qoder CLI 25 条 · 全局 2 · 项目 23」，
  点开才看到两张子卡。导入时仍分别落 global / 项目 scope，重复的跳过；记忆页顶部
  「我的记忆 / 各执事 / 各项目」tab 没有合并。
- **global / project 合并列表未做**：本轮合并的是导入弹窗里的**来源**（同一 Agent 的全局/
  项目子项）。记忆页「我的记忆」与各项目 tab 仍是分开的；如果用户要的是阅读列表合并，
  需要单独立项（还要处理整理按钮只支持单 scope 的约束）。
- **跨 scope 去重只按规范化正文**：不做语义相似 / simhash；语义重复仍可能共存。
- **分类是规则不是模型**：当前靠标题/关键词/日期/文件 hint 打分，边界（尤其"项目日志"
  该算事实还是经历）仍需用户验收；后续如果要更准，得引入小模型或人工标注，不应继续堆正则。
- **legacy 旧页文件导入**：`MEMORY_PAGE_A=false` 的回滚形态未动。
