# 供应商删除不再保护默认与在用（没供应商也能跑）

> 2026-11-23。用户口径：设置 → 模型里默认供应商删不掉，"不需要这个默认的供应商了，没供应商也没关系"。
> 方案：`docs/设计方案/2026-11-23-供应商删除不再拦默认与在用.md`；决策：`系统架构.md` D41。

## 为什么改

2026-11-04 批次五（S4）定了两条删除不变量：删默认供应商 → 400 `provider_is_default`，
删当前选中供应商 → 400 `provider_in_use`，提示"先切走 / 先改 defaultSelection"。
但同一批的落地记录写明 `defaultSelection` **没有修改端点**——默认是"删/建后按第一个模型兜底"出来的。
两条合起来就是死结：默认供应商永远删不掉，界面也没有任何办法把默认改到别家。

另外 `resolveSelection()` 的兜底顺序是 运行时选择 > `defaultSelection` > 第一家，
所以"当前选中"在多数时候就是默认那家：即使只放开 `provider_is_default`，删默认仍会撞 `provider_in_use`。

## 改了什么

服务端 `provider.ts` / `index.ts`：

- `removeProvider()` 删掉 `provider_is_default` / `provider_in_use` 两道 400。
  默认、当前在用、最后一家都允许删除。
- 删的是 `defaultSelection` 指向的那家时，默认**顺延**到剩余供应商里第一家 `models[]` 非空的，
  取其 `models[0]`；一家都没有（或都还没模型）则置 `null`。
- 新增 `clearStoredSelectionIf()`：`runtime.json` 的 `model` 指向被删供应商时一并写掉（保留 `thinking`）。
  不然是条死引用，且同 id 重建后旧选择会"复活"。
- 零供应商 = 合法状态：`readLlmConfig()` 返回 null，`/healthz` 的 `llm` 落 `mock`，
  对话走 mock 回显；`providers.json` 还在（空清单）时不会按 env 重新播种。
- 编辑侧 `selected_model_missing` **保留**：那条不是死结（可以切走或删掉这家）。

前端：

- 供应商表单的删除钮不再因 `isDefault` 给禁用提示；`provider-save.js` 不再拦截默认供应商。
- 删除确认弹窗补一句结果说明：默认 → "默认模型会落到下一家还有模型的供应商"；
  最后一家 → "删掉后没有可用模型，对话会走 mock 回显"。
- `providers.js` 删掉 `provider_is_default` / `provider_in_use` 两条已死的错误文案映射。
- 设置 → 模型顶部默认模型卡：没有任何可用模型时不再只说"配好 LLM_API_KEY 会播种"，
  改为"在下方添加供应商；没有时对话走 mock 回显"（零供应商现在也是用户可停的状态）。

文档：`接口-端点3` §2.10 删除不变量表重写；`系统架构.md` 加 D41。

- `pnpm --filter @lifediary/server providers`：全绿。真 HTTP 覆盖：删当前选中 → 当前回落默认；
  删默认 → 默认顺延到下一家有模型的 D（跳过空清单的 E）且新会话打到 D 的地址；
  删到最后一家 → `/healthz` 降 `mock`、`/agent/model` current=null、对话走 mock 回显；
  重启后仍是零供应商（空清单文件不按 env 复活）；faux 下也都能删。
- 全量单测 `pnpm --filter @lifediary/server test`：1456/1456 通过。
- `pnpm probe` / `http` 探针**没跑**：本次没动内核语义与这些探针覆盖的端点
  （`index.ts` 只改了一行注释），相关的是 `providers` 探针，已跑。

## 已知边界

- **不加回滚 env 开关**：这不是新增能力，而是撤掉一道把用户堵死的闸；旧形态（默认永远删不掉）
  本身就是这次要修的缺陷。真想回到"有默认"的状态，重新添加一家供应商即可。
- 存量会话里指向被删供应商的模型引用**不在删除时改写**：下一轮由 `ensureConversationModel()`
  修复（回退全局默认）；全局也已无供应商时，`/chat` 在入口处走 mock，不打扰 durable 会话。
- `defaultSelection` 的语义没变：仍是"新会话创建时读一次的全局默认"，不引入多默认 / 按场景默认。
- 服务端改动需重启 node 服务才生效；前端静态 JS 按请求读盘、刷新即生效（但旧服务仍会按老规则拦删除）。
