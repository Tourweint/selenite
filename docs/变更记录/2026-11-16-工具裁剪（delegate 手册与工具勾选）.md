## A 段：delegate 政策进内置技能

### 改了什么

1. **新增 `apps/server/skills/delegate.md`**：扁平形态（第 1 行 = 索引摘要，空行后是完整手册）。
   从 `tools.ts` 的 `delegate` 描述里**原文搬运**：任务书四段与岗位契约对应、`steps` 规则、
   `need_input / need_decision / need_action` 处理、`resume` 全部细节（含「对方这句话本身就是要交回的内容」）、
   `REPORT_FOUR_LINES` 四行回报原文、`RULING_DISCIPLINE` 裁决纪律原文、设备 / 手机 caveat 全文。
   手册开头写明「第一次派活前读这一份；工具描述只讲何时用、怎么调」。
2. **`delegate` 描述瘦身**：只保留「何时用 / 怎么调」——做什么 / 适合 / 不适合、派出去立即返回 +
   不要等 / 不要反复查 / 不要重复派、`project` 必填与 `needs_project` 流程、设备活豁免、
   `resume:true` 只写用户那句回答不要重派、`domain` 小写 ASCII + 当前领域清单、`steps` 一句（≤12 条）、
   相对路径 + 手机工人碰不到电脑文件一句，末尾加指路句
   `**第一次派活前先调 skill({name:"delegate"}) 读完整手册**：任务书四段 / steps / resume / 四行回报 / 裁决纪律。`
   参数 schema、工具顺序、其它工具一个字未动。`REPORT_FOUR_LINES` / `RULING_DISCIPLINE` 在 `tools.ts`
   再无用途 → 删掉 import（`turn-gate.ts` 里 `RULING_DISCIPLINE` 仍被 `partner-context.ts` 用，未删）。
3. **core 机制（内置技能）**：新增 `src/core-skills.ts`：`CORE_SKILL_NAMES = new Set(["delegate"])` +
   `isCoreSkill(name)`；**只认代码名单，不认 frontmatter 自封**，普通技能行为不变。
   `createSkillStore` 加可选 `isCore`（默认 `() => false`，旧测试零改动），`canSee` 改成
   `isCore(name) || 可见性判定`，索引 / `names()` / `manual()` 三处自动一致。
   `assist.ts` 总管链 + 全局链两处调用都传 `isCore: isCoreSkill`；`skillVisible` / `skillVisibleFor` 不动
   （core 由 store 内部短路，不走这两个函数）。
4. **管理面**：`GET /agent/skills` item 增 `core: boolean`，`core=true` 时 `enabled` 恒 `true`；
   `PUT /agent/skills/:name/enabled` 对 core 返回 `400 {"error":"bad_request","message":"系统内置技能，始终可用，不能关闭"}`；
   `enabled-all` 跳过 core（不统计、不写入），带 `partnerId` 时 core 的 `partnerEnabled` 也报 `true`。
   同类防御：`PUT /agent/skills/advice` 也跳过 core（快照里就算出现内置名也不写启停位）。
5. **技能页 UI**：core 行不渲染可点开关，改只读「内置」标记（`data-tip="系统内置技能，始终可用"`，
   `.sk-core` 小字样式加在 `style-18-groups-settings-memory.css`）；`toggleSkillEnabled` 入口判 core 直接 return；
   `applySkillAdvice` 请求前过滤 core 名单（服务端也跳，双保险）。其它行的布局 / 顺序 / 分组未动。

### 为什么

方案 §1 实测：总管默认 22 工具 ≈7,922 token 占固定前缀 84%，`delegate` 一个 2,114 token（描述 1,316 + 参数 796），
描述里堆了任务书四段、steps、resume、四行回报、裁决纪律。这些是**每次调用都要看一次的流程政策**，
但一开始派活就要读完整套，没必要塞进每轮固定前缀。把全文挪进技能手册后，工具描述只留「何时用、怎么调」+
显式指路句（工具名与技能名都写全，老会话没有索引也能取到）。

技能默认全关（2026-11-09 用户拍板），把手册放进普通技能会让 `delegate` 失去说明 → 必须有 core 例外：
core 技能始终进索引 / 始终可按名取手册，没有启停位，只能按提交回退（普通技能零影响）。
这是方案 §4「不改参数 schema、不改工具顺序、A 只动描述与新增手册」的口径。

### delegate 描述体积（实测）

- **本地 `createTools` 单测口径**：改前 1,648 字符 → 改后 776 字符（-53%）；本机领域清单为
  `inbox / beta / alpha / calendar / forge`，不同部署的领域数不同。
- **活服务 39847 实际 payload（2026-11-16 重启后）**：`delegate` 的紧凑 JSON
  **2,996 字符 / 2,128 token → 2,116 字符 / 1,333 token**（token 为上下文页估算口径）。
- **固定前缀总量**：总计 9,393 → **8,629 token（-764，-8.1%）**；工具块 7,922 → **7,127**；
  技能块 727 → 758（+31，`delegate` 索引行）。这是 A 的实际收益。
- 测量方式：活服务 `GET /agent/context-defaults?role=chief`；与页面同一条估算口径，不是真 tokenizer。
  没有为了压数字改写关键约束——保留项逐条见上。

### 缓存前缀影响

按 AGENTS.md 硬约束「工具描述与注册顺序是缓存前缀资产」：本次**改了 `delegate` 的描述**，
会打掉一次上游 prompt cache；这是 A 的预期代价。工具顺序、其它工具描述、参数 schema 均未改。

## B 段：人设页工具勾选

### 改了什么

1. **存储**：`partners` 表加 `disabled_tools TEXT`（新库 CREATE TABLE + 老库 `migrate()` 的 `ALTER TABLE` 补列，沿用既有 `ensureColumn` 写法）。`PartnerRow.disabledTools: string[]`（**只存被取消的工具名，空 = 全开，不版本化**）；`toPartner` 经 `toDisabledTools()` 解析（非数组 / 坏 JSON / 非字符串项当空，参照 `toProjectIds`）。`partnersStore.setDisabledTools(id, names)` 一条 UPDATE 只写 `disabled_tools` + `updated_at`，不 bump 身份、不碰 SOUL / 契约，不存在返回 null。团队包**不带**这项（同 `personaModules` / `projectIds` 口径）。
2. **新模块 `src/partner-tools.ts`**：`modelToolCatalog()` 从真实 extension 现取（过滤 deferred / `callers` 不含 model、按名去重、保持顺序，不手抄清单）；`PARTNER_TOOL_GROUPS` 六组固定顺序 + `toolGroupOf` / `toolSummaryOf`（首句 / 首行**去掉 Markdown 强调 / 行内码标记**后截 80 字）；`partnerToolsView()` 按人算 enabled；`sanitizeDisabledTools()` 收口 PUT 入参（非数组 / 非字符串 / >64 / 未知名 400，去重，空数组合法）；`applyPartnerToolSelection()` 按目录内工具名集合比较，不同才 `configure({modelTools:{remove}})` / 清空写 `null`，失败只 warn 不抛。`partnerToolsEnabled()` 读 `PARTNER_TOOLS_ENABLED`（false/0/off 关）。
3. **运行时接线**：`agent/session-stream.ts` 的 `chatStream` 在 `conversation.submit(...)` 之前，按 `partnerIdOfSession` 优先、否则 `chatKind === "chief"` 取总管，解析 owner 后调 `applyPartnerToolSelection`。一处覆盖总管主会话 / 执事专线 / 执事群 / 例行会话；worker 开发会话与 `task-*` 不参与。不放进 `openChat`（读端点无副作用），不动 `openPartnerConversation` / 群运行时。
4. **端点**：`GET /api/v1/partners/:id/tools`（getHarness 确保 extension 已装、失败 503；开关关仍 200 空形状；`cache-control: no-store`）、`PUT /api/v1/partners/:id/tools`（body `{disabled}`，未知名 400、开关关 400、只写这一列、返回同 GET 形状）。**联调补丁**：`delegate` 描述依赖 `skill` 读手册，因此目录里同时有这两项时，只关 `skill` 不关 `delegate` → 400（两者一起关合法），避免留下“派活没有手册”的坏组合。
5. **默认开销页**：`context-defaults.ts` 的 `defaultTools()` 按 role 对应人设行的 `disabledTools` 过滤（chief → 总管、partner → 该执事、worker 不过滤），读库失败 / 开关关时不过滤，别让整页 503。
6. **人设页 UI**：`web/partner-profile.js` 在「按相关度召回」与「高级开关」之间新增「能用的工具」一节，一张卡显示 `已开 N / M`；点开弹层按组列勾选框（勾 = 可用），全选 / 全不选 / 保存（保存未勾选名单），成功 toast「已保存，下一轮生效」并回写卡片计数，失败在提示行显示原因不关弹层。GET 失败卡片显示原因 + 可重试；`enabled:false` 整段隐藏。总管页同样显示（作用于总管主会话）。`web/style-22-partner-profile.css` 只加勾选行的最小样式。
7. **开关与文档**：`.env.example` / `接口文档.md` §6 加 `PARTNER_TOOLS_ENABLED`；`系统架构.md` 模块表加 `partner-tools.ts` + §4.3 补工具面按人过滤；`接口-端点4` 加两行端点；`接口-端点1` §2.2.5 补默认工具按人过滤；`package.json` 的 test 清单加 `partner-tools.test.ts`（在 `context-inspect.test.ts` 附近）。

### 为什么

方案 §1 实测工具定义是固定前缀的大头，而工具在 extension 里全局安装、所有人看到同一份。存"取消名单"而非"勾选名单"是刻意选择：以后新增工具默认对所有人可见，不会因为老档案冻结而消失；只有显式关掉的才从上下文里摘掉。运行时按**集合**比较、相同不写，是为了不在每轮产生新的 agent 配置写入（缓存前缀资产也别无故打掉）。失败只 warn 不抛，是因为工具面读不到不该挡住对话这条主链路。B 不改工具实现 / 顺序 / 参数 schema，不碰审批闸门；C（deferred + tool_search）按方案 §4 仍明确不做。

### 没做 / 不确定

- **C（`deferred` + `tool_search` 懒加载）按方案 §4 明确不做**；本批只做"取消名单"式的可见性裁剪，没有引入工具懒加载与 `tool_search`。
- **不按角色自动推断工具面**，只做人设页手工勾选；worker 默认页仍按现有口径（不过滤）。
- **不写团队包 / 手机端**：`disabledTools` 不随包迁移，手机端零改动。
- `toolSummaryOf` 按**代码点**截 80 字（中文一字符算一字），没用真 tokenizer；UI 摘要只是扫读用，不进 token 计费口径。
- **静态 JS 有模块缓存**：人设页模块在页面打开时加载一次；升级后需要刷新页面才会出现「能用的工具」一节（实测活服务 hash 路由切页不重载模块，F5 后才显示）。
- 真实上游（非 faux）下的工具面变化没有专门跑一轮对话验收；运行时逻辑与 faux 共用同一条 `chatStream`，faux 已验证 configure + context-inspect 生效。
