# 归档模块：会话与项目目录统一归档

日期：2026-11-13
状态：已落地（服务端 + 桌面端 + 文档 + 验证）；方案见
`docs/设计方案/2026-11-12-归档模块（会话与项目目录统一归档）.md`。

## 起因

用户口径（2026-11-12）：把已删除的都改成归档，做一个归档模块；项目目录（子项目目录）的退场也叫归档；
归档界面要能看到"没什么用的对话"；把已删除的字段都改掉。没有删除按钮，只有归档（上一轮已拍板）。
上一轮遗留的"移除项目时把项目内所有对话放进已归档"，这次补上。

## 改了什么

### 服务端（契约 + 数据）

- `agent/session.ts`：`chat-meta.json` 的 `hidden` → `archived`，新增 `archivedAt`；
  读兼容旧键、写只写新键。新增 `archiveChat` / `unarchiveChat` / `restoreArchivedChats` /
  `chatMetaSummary() → {archived}`；`listChats` 过滤改新键。
- 新增 `listArchivedChats(limit=200)`：按 `chat-meta.archived` 反查，不受活跃清单 `slice(-limit)` 截断；
  返回 `archivedAt` 与（有归属时的）`projectId` / `projectName`。
- 新增 durable doc `lifediary.chat-projects`（`{byInternal: Record<internalId, projectId>}`）：
  新建普通会话（`chatKind=worker`）时记录当前项目；编辑重发的 fork 继承原会话归属；
  群 / 任务 / OpenAI 兼容自动建会话不记。
- 新增 `archiveChatsOfProject(projectId)`：项目归档时按创建时归属批量归档，跳过 `task-` / `partner-`；
  旧会话不回溯。
- `index.ts`：`GET /agent/chats` 返回 `{chats, archived}`（原 `removed` 删除）；
  新增 `GET /agent/chats/archived`、`POST /chat/:id/archive`（`/hide` 别名）、
  `POST /chat/:id/unarchive`；`/chats/restore` 保留。
- `projects.ts`：`POST /projects/:id/archive` 升为主入口（`/remove` 别名），响应加 `archivedChats`；
  `PROJECT_ARCHIVE_CHATS=false` 关闭连带归档。

### 桌面端

- 设置左栏新增「归档」（排在「项目」后），归档页两张卡：
  **已归档的会话**（标题/首句、轮数、最后一句时间、项目标签、归档时间；筛选、单条恢复、全部恢复）与
  **已归档的项目目录**（名称、只读路径、目录丢失标记、恢复）。
- 设置 → 会话的「已归档的会话 N [恢复]」改成常驻入口「归档的会话 N [打开归档]」。
- 设置 → 项目只渲染活跃项目，底部「已归档的项目目录（N）[查看归档]」；
  项目动作「移除」→「归档」，确认弹窗说明磁盘不动、项目下新建会话会一起归档、旧会话不回溯；
  恢复项目提示"会话仍在归档里，需要单独恢复"。
- 侧栏会话悬停归档按钮改走 `/archive`；`state.removed` → `state.archived`；
  项目归档态标签/类名「已移除」→「已归档」。
- CSS：新增归档页样式（`.archive-*`、`.proj-archive-entry`），`.is-removed` → `.is-archived`；
  删除项目页旧的「已移除」折叠区样式。

## 刻意没做

- 不把硬删除对象改成归档：技能 / 记忆 / 供应商 / 例行任务 / 群 / 设备 / 搜索源仍是物理删除，
  保留「删除」字样与确认。归档承诺"数据还在"，硬删做不到。
- 归档页不提供「永久删除」；用户明确"没有删除按钮，只有归档"。归档会一直留着，磁盘只增不减。
- 不回溯旧会话的项目归属：没有创建时 `projectId` 就不猜。
- 恢复项目不自动恢复会话（会话归档是独立动作）。
- 不改 `diary.deleted` 字段（跨仓库同步协议的墓碑，不是用户归档）。
- 不做执事归档页；执事已有 active/paused/archived 状态，另立项。
