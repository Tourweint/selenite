# 滚动条只留主对话，其余地方不画

> 用户一次提了三处一起收：换模型弹层右侧、设置页，以及「还有挺多」。处置是全局收口，只给 `#scroll` 留条子。

## 用户原话

> 「很多地方都有上下滑动的滚动条，但大部分地方我们不需要，只在主对话界面保留。……换模型时右边那个上下拉的滑动条不应该留，不需要吧？设置里的那些应该也不需要吧？还有挺多，你再找找吧，反正很多都不需要。」

用户点名两处、放开范围让我自己找。所以不按「点名的两处各改一条」做，而是找根因：条子是一条全局规则给的，全局收掉、只开一个口子，才算把「还有挺多」一起解决。

## 结论

1. **根因是一条全局规则**：`style-11-composer-tools.css` 里的 `::-webkit-scrollbar { width: 10px; height: 10px }` + `::-webkit-scrollbar-thumb` 是给**所有**滚动容器配的条子。全站 30 个 `overflow-y: auto` / `overflow: auto` 容器（侧栏、设置内容列、换模型弹层、抽屉、项目弹层、任务看板、记忆页、工具块限高……）共用它，所以条子到处冒。
2. **处置：全局钉成 0 宽，只给 `#scroll` 开回 10px**。`*:not(#scroll) { scrollbar-width: none }` + `::-webkit-scrollbar { width: 0; height: 0 }`；`#scroll` 单独写回 10px 的细小条与 thumb。
3. **只藏条子，不动 overflow**。滚动能力全保留：wheel / 键盘 / 触控板 / 触屏照旧。**不能**改成 `overflow: hidden` —— 那是把内容裁掉，不是「不显示条子」。
4. **`#scroll` 刻意不写 `scrollbar-width`**。Chromium 里元素一旦写了非 `auto` 的 `scrollbar-width`，它自己的 `::-webkit-scrollbar` 自定义就整段失效，条子会退回系统默认的 15px 宽条——比原来更丑。所以例外元素只走 webkit 伪元素这条路；`scrollbar-width: none` 只加在**非** `#scroll` 的元素上，顺带给 Firefox 兜底（那边不认 webkit 伪元素）。
5. **两处「为条子留的位」一起撤**：
   - `.set-scroll` 原来是 `padding: 0 24px 0 16px` + `scrollbar-gutter: stable`，右侧那 8px 是给 10px 条子做视觉配重的。条子不画了，这份配重让整列左偏 4px；改成左右对称 16px，槽位一并撤掉（没条子可留，留着只会在右边压出一条看不见的空带）。
   - `.pf`（人设二级页）原来 `padding-right: 6px` 让开 gutter 预留的布局宽；gutter 撤了，它变成纯右缩进，右对齐的注脚反而不齐左边，删掉。

## 为什么不按「逐处关」

逐处加 `scrollbar-width: none` 会漏：全站 30 个滚动容器分散在 20 个分部文件里，新增一个也记不住。一条全局规则 + 一个例外，漏不掉，也不再需要每次新增滚动容器时记得补一句。

## 落点

| 文件 | 改动 |
|---|---|
| `web/style-11-composer-tools.css` | 「滚动条」一节重写：全局 0 宽（`*:not(#scroll)` 的 `scrollbar-width: none` + 通用 `::-webkit-scrollbar`），`#scroll` 例外开回 10px；原 thumb/track 规则收进 `#scroll` 作用域 |
| `web/style-07-composer.css` | `.set-scroll` 内边距改对称 16px，删掉 `scrollbar-gutter: stable` |
| `web/style-22-partner-profile.css` | `.pf` 删掉 `padding-right: 6px`（原为让开 gutter 预留宽） |

没有 JS 改动：`hover-tip.js` 的「是否溢出」判据用的是 `scrollHeight` / `clientHeight`，与条子宽无关；`ui-atoms.js` 弹层动画期间写 `overflow: hidden` 再放开，也不受影响。

## 这条会怎么错

- **组件内的滚动失去了「还有内容」的提示**。表现最明显的是换模型弹层：以前右侧那条灰杠在说「下面还有」，现在只剩被 sticky 档位条压住的半行模型名。用户要是反馈「菜单里找不到某个模型」，第一件事就是这里——改法是整条弹层加高，或给末尾补一道渐隐。
- **触屏 / 纯键盘用户不好发现可滚区**。桌面壳是鼠标加滚轮，影响小；手机端走的是另一套界面，不受这条规则影响。真要用在没有滚轮的设备上，得给关键容器补「渐隐遮罩」式的可滚提示。
- **`*:not(#scroll)` 是「默认全关」**。将来某个容器**必须**看到条子（比如超长的可编辑区、可拖拽的表格），得把它加进例外列表；不做这一步，它就会悄悄变成不能滚的样子（内容还在，只是没有条）。
- **`::-webkit-scrollbar` 的 0 宽在非 Chromium 内核不生效**。Firefox 只认 `scrollbar-width: none`（已加），Safari / WebKitGTK 认伪元素（已覆盖）。真要支持某个第三内核，先确认它认哪一条，别以为改了 CSS 就全平台生效。
- **`#scroll` 的条子是常驻的**，不是悬停才出现。嫌它一直在，可以改成 thumb 平时透明、`#scroll:hover` 才显色；这轮没做，因为用户说的是「保留」，不是「只在悬停时露」。
