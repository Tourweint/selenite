# 空态第一屏的身份（2026-11-16）

> 新建会话那一刻，屏幕上没有任何东西回答「我在跟谁说话」。补这一处，走了四版才定：
> 最后不写字，把身份放到左首那枚图标上。

## 结论

空态左首的图标按身份换：

| 会话 | 图标 |
|---|---|
| 执事专线（`partner-<id>`，且该执事有头像） | 该执事头像（1.8em 圆形） |
| 总管（`chatKind=chief`，且总管有头像） | 总管头像 |
| 普通 worker / 没有头像的人 | 项目水晶（原样） |

问候语只剩一句「天黑了，正好收个尾。」，名字不再出现在文字里。

## 四版怎么走的

| 版 | 长相 | 结果 |
|---|---|---|
| v1 | 问候语上方另起一行 13px「在跟 助手 说话」 | 否。像系统注释，把 30px 题头压成附注 |
| v2 | 并进句子：「我是助手。天黑了，正好收个尾。」 | 否。像客服开场白 |
| v3 | 名字站句首、同字号、一个「·」：「助手 · 天黑了，正好收个尾。」 | 否。仍是在句子里塞信息 |
| v4 | 名字整句删掉，身份放到图标上：有脸画脸，没脸画水晶 | 当前。用户原话「图片比较直观」 |

结论：这件事不该用文字解决。一屏只有一句 30px 衬线话，任何名字挤进去都会改变它的重心；
而图标本来就占着「起首」的位置——把身份放进去，等于不多占一个像素。

## 改了什么

### 1) 空态结构

文件：`ts/apps/server/web/index.html`、`web/dom.js`、`web/style-04-chat-base.css`

```html
<span class="empty-mark" id="empty-mark"><img src="/assets/crystal-mark.png" alt="" aria-hidden="true"></span>
<div class="empty-text">
  <p class="empty-greet" id="empty-greet">说吧，我在。</p>
</div>
```

- `.empty-mark` 从 `<img>` 变成容器：`display:flex; height:1.8em`，里面的 `img` 决定形态。
- `.empty-mark[data-kind="mark"] img`：`height:1.8em; width:auto`，保留原来的水晶投影。
- `.empty-mark[data-kind="face"] img`：`width/height:1.8em; object-fit:cover; border-radius:50%`。
- 两种形态落点相同（容器高 1.8em），换人时整组不会跳；宽度会从 33 → 54（水晶是 0.6 宽高比）。

### 2) 画谁：`chatIdentityFace()` / `syncEmptyMark()`

文件：`ts/apps/server/web/partners-status.js`

```js
partner- 前缀 → { avatar: 该执事.avatar, name: 该执事名 }
chatKind=worker → null（不是某个人 → 水晶）
其余（chief / 缺字段旧会话）→ { avatar: 总管.avatar, name: 总管名 }
```

- `syncEmptyMark(face = chatIdentityFace())`：有 `avatar` 就 `<img src=头像>` + `aria-label="在跟 X 说话"`；
  没有就水晶 + `aria-hidden`。传 `null` = 强制回水晶。
- 头像比花名册晚到时（首屏先画水晶），`loadRoster()` 末尾补一次 `syncEmptyMark()`。
- `chatIdentityName()` 保留：只给 `aria-label` 用，不再进页面文字。

### 3) 出现与收走

文件：`ts/apps/server/web/chat-thread.js`、`web/chat-open.js`、`web/app.js`

- `clearThread()` 里 `syncEmptyMark(null)`——切会话的第一帧先回水晶，不挂着上一个人的脸。
- `openChat` 在 `chatKind` 回读之后补画；`startNewChat` 在 state 定好后直接画；
  `app.js` 首屏路径（没落盘会话）补一次——这条路径不经过 `clearThread`。
- 第一条消息进来 `hideEmpty()` 整块收走，顶栏标题此时已变成首句。
  两块各管一件事：**这一处管「谁」，`#title` 管「这条叫什么」**。

## 为什么（根因没变）

用户原话：「新开对话的时候，他看不到我在跟哪个人说话，就是这个聊天框在中间的时候」；
「那就把缺口加上就行，对话进行中其实没关系」；「名字是后来才加的……我发完消息，题目就会变化」；
「感觉真的不美观呀……再设计设计吧」；最后：「水晶换成这个头像吧。没有头像的用水晶。
然后把这文字删掉吧……图片比较直观吧」。

根因是布局：`style-07-composer.css` 里 `.main[data-home="1"] .top { display: none; }`，
首页态（= 无消息的空态）整条顶栏不渲染。那一屏里连「普通对话」都看不到，身份只能长在空态里。

取舍：

- **不碰 `#title`**：它由 `composer-send.js`（首句前 40 字）、`chat-open.js`（存储标题）、
  `chats-list.js`（改名）三处共同维护，天生是会话名。
- **首页第一眼仍是水晶**：新建对话默认 `startNewChat("worker")`，worker 没有脸，
  所以「水晶 + 一句话」这个品牌首屏原样保住；只有打开总管 / 执事会话才换成脸。
- **对话进行中不加锚点**：用户明确说没关系；顶栏头像仍按原口径（只给某个人），不改。
- **不引入第二套头像渲染**：`paintAvatar` 的回落是「名字首字」，空态要的是「水晶」，
  所以这里单独构造 `<img>`，没有复用 `paintAvatar`。

## 边界 / 待看

- **总管 / 执事若没设头像，会回落成水晶**，与普通对话撞脸；这时空态就分不出「在跟总管」还是「在跟普通对话」。
  要补的话，给「有人名但没头像」的档位画一枚首字圆牌（侧栏执事没头像时就是这么显示的），
  但那就不再是「没有头像的用水晶」了，等用户表态。
- 身份只在空态存在；对话进行中没有身份锚点（用户接受）。
- 群会话走 `view-groups`，不经过 `.empty`，群里「谁在说话」由群成员头像负责，本次没动。
- 空态图标与 `#title` 可能不一致（图标是脸 / 标题写「普通对话」），但不同屏出现：空态时顶栏 `display:none`。
- worker 的名字仍是常量 `WORKER_DISPLAY_NAME = "助手"`，只用于无障碍标签；要可改得走「worker 进 partners 表」的方案。
