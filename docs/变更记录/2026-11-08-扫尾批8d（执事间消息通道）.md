## 工具 schema

```jsonc
{
  "name": "send_to_agent",
  "parameters": {
    "target":  "string",  // 执事名 / 领域 / 「名字·领域」长标签
    "message": "string"   // ≤ 4000 字；含 [relay hop=1] 一律拒绝（转述 = 两跳）
  }
}
```

- 名字唯一 → 命中；重名 → 返回 `同名·alpha / 同名·beta` 候选（不猜）；
- 领域（大小写不敏感）唯一 → 命中；长标签写错域 → 不命中、不回退短名（与群组 @ 同一纪律）；
- 查无此人 → 列出"总管、信使甲·inbox"这类现有清单；
- 指向自己 / 总管 / 暂停或归档的执事 → 各自一句说明。

## 摘除实现（防乒乓的结构保证）

1. 送达时 `markRelayTarget(目标会话内部 id)`（**先于 submit**），提交失败则 `clearRelayTarget`；
2. 目标那一轮的第一个 `beforeRequest` 认领这份一次性标记，把"这一轮是递话触发的"记在 run 键上
   （run 键 = `${会话 id}:${run.inputs[0] ?? run.taskId}`，与回合上限计数同一口径）；
3. `beforeTool` 见 `send_to_agent` 先过通道闸：`isRelayRun(会话, 当前 run 键)` → 直接 block。
   **工具面没重建**（方案 §一.5 允许 beforeTool 拦截），模型再想递也递不出去；
4. 下一轮（主人自己说的）run 键变了，标记自然不命中 → 工具复活。

另两条：每 run 3 条（第 4 条起回"合并成一条"的引导，不是报错）；`message` 含 hop 标记直接拒。

## 通知形态

- 递话成功 → `emitChiefNotice("执事「A」→「B」：递了一条话（正文不在这里，点开「B」的会话可看）。")`；
- `chatStream` 只在**主人的对话**（`chatKindOfInternal === "chief"`）上订阅，作为既有 `notice` 帧吐出，
  `index.ts` 的 SSE 透传无改动（`notice` 早就在白名单里）；
- 与派单进度同款：进程内轻事件，**没开流就收不到、不落盘**——刻意不写一条 `pi.assistant`
  （那等于伪造主人/助手说过的话，污染上下文），也不落 SSE 重放库（那是"外发过的帧"的账）。

## 已知边界（写下来，别当成缺失去补齐）

- **目标会话被 abort 时排队会撤回**：内核 `abort()` 会一并撤回排队输入，所以"B 正忙 + 撞回合上限硬停 / 被 `/stop`"
  这一种情况下已排队的递话会落地失败（内核语义，不是本功能丢的）。正常收尾 / 失败（`afterFailedRun=keep`）时排队都在。
  要彻底兜住得加信箱表，方案 §二 明确不做。
- **主人通知只在开流时可见**：与派单进度同款。主人没打开那条主对话的流时收不到，也不补历史。
- **没建过会话的执事递不进去**：返回"先在侧栏点开它一次"，不代建（代建要跑身份对齐，属装配层）。
- **工具面仍是全局注册**："主人对话不挂"由 `beforeTool` 的会话身份闸兜住（主人对话/总管/群会话/自主轮各有一句拒绝语），
  不是从工具清单里物理摘掉——per-conversation 摘工具要改扩展装配，批内不做。
- 探针的 ② 需要"一轮正常收尾"，faux 做不到（只会一直调工具），所以那一段关掉回合上限与防打转守卫、
  让 B 的这轮以 `model_error` 收尾并 `AGENT_AFTER_FAILED_RUN=continue`；验证的仍是"final 边界放置排队输入"这条产品语义，
  真模型下由派单人真机手验（方案 §三 末条）。
