# 手机 worker 通道（电脑侧）

- 日期：2026-11-02
- 范围：`chancellor` 的 `src/employee/phone.ts`（新）、`src/types.ts`、`src/config.ts`、
  `src/employee/index.ts`、`src/index.ts`；harness 的 `apps/server/src/phone-worker.ts`（新）、
  `apps/server/src/index.ts`、`apps/server/scripts/phone-worker-probe.ts`（新）、
  `apps/server/package.json`
- 依据：`docs/设计方案/2026-11-02-手机worker通道契约.md`

## 决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | `PhoneTransport` 定义在 chancellor，实现在 harness | 契约和验收在 chancellor；HTTP / 内存队列是 harness 的事 |
| 2 | 队列只放内存，不落库 | 原型阶段不背过期/恢复/多实例；重启丢单由 chancellor 判 idle |
| 3 | 超时由 transport 的定时器 reject，chancellor 收成 `waiting` | 预算到了是「还在干」，不是 failed；进程不挂死 |
| 4 | `resume` 不覆写，默认重跑 | 手机卡住后重派比「续上」简单 |
| 5 | 三个接口不自己判鉴权 | 统一走 `/api/v1/*` 现有中间件，失败 403 空体只写在一处 |
| 6 | `/worker/model` 只回字节，不解析 | 手机那边的提示词/工具格式不能被电脑改写；失败只回 502 + 脱敏说明 |

`canWriteFiles=true` 是按契约声明的（summary 由 chancellor 落成 `result.md`，验收产物在任务目录）。
注意拆单器仍可能把 `done_when` 写成「生成 answer.txt」；手机只交一句话，所以真实需求里应把完成标准
写成「`result.md` 里说清 X」。

## 改了什么

- chancellor：`EmployeeKind` 加 `"phone"`；新增 `PhoneTask` / `PhoneResult` / `PhoneTransport`；
  `createPhoneEmployee()` 按结果组装 REPORT（done→ready+`result.md`，blocked→blocked+attention，
  failed→failed，超时→waiting）；`registerPhoneTransport()` 给 harness 注册实现；
  `capabilitiesOf("phone")` 声明 `artifacts=taskDir, canWriteFiles=true`
- harness `phone-worker.ts`：`Map<taskId, {resolve,timer}>` 内存队列 + 长轮询挂起（Promise + 定时器，
  同设备新 poll 顶掉旧的）+ 模型转发（流式透传 SSE，非流式原样返回字节）+ 结果唤醒；启动时注册 transport
- harness `index.ts`：`mountPhoneWorker(app)`，路由落在已有鉴权中间件之后
- `scripts/phone-worker-probe.ts`：假手机客户端，完整跑 done / blocked / timeout 三轮

## 怎么跑验收

```bash
cd ts
pnpm --filter @lifediary/server phone
```

需要 `LLM_API_KEY`（或 `DASHSCOPE_API_KEY`，探针会映射过去），拆单/验收还需要 chancellor 配好的
qoder CLI。探针在**本进程**里 `import src/index.ts`，真的监听 `127.0.0.1:8193`，然后用真正的
`delegate` 工具派活；假手机只走 HTTP，不碰 mock。

实测输出（2026-11-02）：

```
✓ 无凭据 poll → 403 空体
✓ 同一设备新 poll 顶掉旧 poll — 旧=204，5ms 内返回
✓ 非流式 /worker/model 200 — 链路已通。
✓ 流式 /worker/model 原样透传 SSE
✓ done：整单 done，REPORT ready，result.md 落盘
✓ blocked：整单 needs_you，attention.kind=need_action，问题原样带回
✓ timeout：整单 idle，REPORT waiting，迟到结果 404
```

回归：两个仓库的 `npm run typecheck` 均通过。

## 没验证到的

1. 真手机客户端没接；探针是 Node 版假客户端。
2. 多设备：现在谁先 poll 谁拿活，没有按设备定向分发。
3. 电脑重启丢单：内存队列清空后手机交结果会 404，这条按契约由手机重新 poll；没在真机上演练。
4. 流式请求中途断网：只验了透传，没验上游/下游任一端断开时的回收。
