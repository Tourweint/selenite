# 2026-11-13 提醒：频率（每天）+ 目标执事 + 取消

## 背景

桌面提醒页 2026-11-12 重做后仍是**一次性**（`{text, at}`）：没有「每天」、没有目标执事、没有取消接口。
手机端当时只有旧的「每日提醒时间」（日记问题的 21:30±60），不是提醒列表。
日记 v2 需要「每天 21:30 叫一下日记执事」；用户拍板把两端合成一套提醒。

## 改了什么

### 契约 / 服务端

- `ts/apps/server/src/reminder.ts`：`ReminderInput` 加 `repeat: "none"|"daily"`、`reminderId`（稳定 id，每日续排沿用）、
  `partnerId`。`deliver` 里写 entry 后，`daily` 的**同一事务**再排下一天（`nextDailyAt`：进程晚醒跨过几天也落在未来）。
- `ts/apps/server/src/agent/session.ts`：
  - `listReminders()` 按 `reminderId` 归组，每组只给一个代表（活的优先，都结束了给最新一条）——
    否则每日提醒会一天多一行「已结束」把桌面页刷屏；返回 `{id, reminderId, status, text, at, repeat, partnerId, until?, conversationId}`。
  - `addReminder` 生成 `reminderId`；新增 `cancelReminder(taskId)`：先对列表校验只允许取消真实提醒
    （避免任意 taskId 误 abort 对话轮），再 `harness.abortTask`。
- `ts/apps/server/src/index.ts`：
  - `POST /agent/reminders` 接 `repeat`（缺省 none）与 `partnerId`（有值时 `ensurePartnerSession` 建在该执事会话；不存在/暂停 → 404）；非法 → 400。
  - 新增 `DELETE /agent/reminders/:taskId`（成功 `{ok:true}`，不存在/已结束 404）。
- `ts/apps/server/src/agent.ts` 导出 `cancelReminder`；`http-probe.ts` 增加「每日提醒 + 取消」断言。
- `docs/基线文档/接口文档.md` §2.13：列表形状、POST 新字段、DELETE 行。

### 桌面端（纯前端）

- 手动弹窗加「每天重复」开关，POST 带 `repeat`。
- 列表：每天显示「每天 HH:mm」+「· 每天重复」；未结束的行有「取消」（DELETE 后重绘）。
- 新增 `startReminderWatch()`：页面开着时每 30s 拉一次，到点弹浏览器通知（同 reminderId+触发时刻只弹一次；无权限静默）。

- 手机端：模拟器建每日提醒 → 列表显示「每天 21:30 · 总管」；API 建的一次性提醒到点弹出通知
  （通知栏「提醒 / notify test 2」）；取消后列表清空。

## 刻意没有 / 已知边界

- 桌面通知只覆盖「页面开着」；没有系统级推送通道（与旧闻一致）。
- 提醒条目仍写 `lifediary.reminder` entry，但 web 对话页不渲染它；桌面靠 30s 轮询的通知，
  手机靠本地闹钟——到点提醒不再依赖会话 entry。
- 目标执事名没有进 `GET` 投影（只给 partnerId）；两端都用各自的执事名册映射。
- 旧 `set_reminder` 工具（Agent 自建）仍只建一次性提醒；本条只扩 HTTP 面，工具可选后续跟进。

## 回滚

- 服务端：`repeat` / `partnerId` / DELETE 都是纯增量；旧客户端不带字段 = none / null。
- 桌面：去掉「每天重复」开关与 `startReminderWatch()` 即回到一次性列表。
- 手机：见同批手机仓变更记录。

## 补充（2026-11-13 当日）：到点开口 + 用户可见名称

用户口径：这不是「提醒」，是**定时任务**——到点执事主动来找你、跟你说一句话，点开就聊。

- `reminder.ts` 加 `setReminderDeliverer` 注册回调；`deliver` 落完记录后调用（同一进程内）。
  由 `index.ts` 注册为 `sayInConversation(conversationId, text)`：到点在会话里写一条 assistant 消息。
  用回调而不是直接 import，避免 `reminder.ts ↔ agent/lifecycle.ts` 循环依赖。
- 桌面端用户可见名称改「定时任务」：侧栏、页标题、空态、手填弹窗、到点浏览器通知。
- 手机端用户可见名称同步改「定时任务」：页面、设置行、通知渠道、无目标时的兜底标题。
- 接口路径仍叫 `/agent/reminders`（契约不改），只在文档里注明用户可见名称。
