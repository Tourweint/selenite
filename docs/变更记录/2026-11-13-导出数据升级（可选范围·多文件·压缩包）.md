## 做了什么

| 层 | 文件 | 内容 |
|---|---|---|
| 新模块 | `ts/apps/server/src/zip.ts` | 极简 zip 写入器：`node:zlib` deflate + 自算 CRC32，STORE/deflate 自动择优，文件名 UTF-8（bit 11）。不引新依赖 |
| 新模块 | `ts/apps/server/src/export-bundle.ts` | 五块采集 + 拼包：`conversations` / `memory` / `library` / `team` / `config`，逐块 `ok\|empty\|failed`，`README.md` + `manifest.json`，`413` 上限 |
| 会话读取 | `ts/apps/server/src/agent/session.ts` | 新增 `listChatsForExport()`：**把归档会话算进来**（老导出走 `listChats` 会悄悄漏掉归档），仍排除 `task-`；按会话补项目标签 |
| 端点 | `ts/apps/server/src/index.ts` | `format=zip` 分支 + 参数校验（`parts` / `images`）+ `X-Export-*` 头 + `EXPORT_BUNDLE` 回滚开关；`format=json` 原样保留 |
| 界面 | `ts/apps/server/web/app.js` | 「导出…」弹层：五个复选项 + 图片二级开关；`pickExportTarget()` 先定落点（页面保存框 → 壳 → 下载目录），再取数据 |
| 样式 | `ts/apps/server/web/style.css` | `.export-part*`：带说明的复选行 |
| 桌面壳 | `desktop/main.go` | `Shell.SaveExport(suggestedName, dataBase64)`：系统另存为 + 写盘，>96MB 明确拒绝（桥传字节有上限） |
| 测试 | `src/zip.test.ts`（4 条）/ `src/export-bundle.test.ts`（8 条）/ `scripts/http-probe.ts`（§17 新增 16 条断言） | zip 往返自解包、CRC、中文名；包结构、manifest、README、路径前缀；端到端 zip 字节与清单 |

## 关键取舍（为什么不是别的做法）

| 决定 | 备选 | 为什么这么定 |
|---|---|---|
| 自己写 zip（~130 行） | 引 `jszip` / `archiver` | 只有文本 + 图片、只打包不读包；一个依赖换不来什么，且内置 `zlib` 已够。代价：不支持 zip64 / 加密 / 分卷（超 4GB 另立项） |
| `format=zip` 新增分支，`json` 一字不动 | 直接改老形态 | 老客户端、探针、回滚都还在用 JSON；新形态可独退回滚，风险隔离 |
| 一会话一文件夹 | 全部消息塞一份 `messages.jsonl` | 单独拿一段对话给人看时直接拿文件夹；人读 md 与机读 json 同处，不互相找路径 |
| 图片落真文件 | JSON 里留 base64 | base64 会把包撑大数倍且人打不开；`messages.json` 只留路径 + sha256 |
| 集合类用 jsonl | 大数组 json | 一行坏不掉整份、可 `grep`、可追加 |
| 逐块隔离、失败只标该块 | 任一步失败整体 503（老口径） | 多块导出里"一个块读不出来"不该毁掉整份档案；代价是界面必须读 `X-Export-Partial` 提醒，已在 toast 里做 |
| 导归档会话、任务专线仍排除 | 全都要 / 全都不要 | 归档是用户自己的对话，漏掉就是"全部数据"名不副实；`task-` 首句是机器指令，侧栏本来也不列 |
| 保存位置交给页面 / 壳 | 服务端写盘 | 延续"导出不落服务端磁盘"的隐私口径；壳里 `SaveExport` 只写用户亲手选的那个路径 |
