# 契约包 `index.ts` 拆成 7 个分区（1,335 行 → 23 行纯桶 + 7 个 82–276 行文件）

> 把 `ts/packages/shared/src/index.ts` 这份单文件契约按行区间整段切开，入口只留 `re-export`，对外符号一个不少。

## 结论

| 项 | 结论 |
|---|---|
| 拆分前 | `index.ts` 单文件 1,335 行，145 条顶层声明（Zod schema + 类型 + 少量纯函数），0 副作用 |
| 拆分后 | `index.ts` 23 行纯桶（只有 `export … from "./分区"`）；7 个分区文件 50–276 行 |
| 最大分区 | `relay-schemas.ts` 276 行（中继/派活帧，10 组 schema） |
| 对外 API | 不变。`@lifediary/shared` 仍指向 `src/index.ts`，服务端与 App 的导入路径零改动 |
| 依赖 | 分区之间**无环**（脚本每次跑都断言），所以不存在 const 求值期的 TDZ |
| 验证 | `packages/shared` `tsc --noEmit` 0 错；`apps/server` `tsc --noEmit` 0 错；`snapshot.test.ts` 6/6 过（真运行时跑，能抓 TDZ） |

## 为什么按「行区间」切，而不是「按主题重组」

这份文件里 schema 之间是**网状引用**（`ContentPartSchema` 引用三个分段 schema、`ChatEvent` 引用 `TurnPhase`/`Usage`、中继帧引用 `ChatEvent`、头像 schema 引用 PNG 校验函数）。按主题重组等于把声明在文件里重新排序，而 ESM 的求值顺序由 import 图决定，一旦两边互相引用就是 const 循环 → 运行时 TDZ，`tsc` 抓不到。

所以切法只有一条：**保持原有顺序，按行区间整段搬**。这样每个分区内部顺序与原文一致，分区之间的边方向也跟原文顺序一致，环的概率最低；真出现环，脚本直接退出要求改边界（这次就靠它抓到 `chat-events ↔ relay-schemas` 一处环，把 SSE 编解码单独切成 `chat-codec.ts` 才消掉）。

## 一处必要的补充导出

原文里有几个**模块私有**的辅助（`B64_ALPHABET`、`isChunkType`、`pngCrc32`、`be32`、`pngProblem`、`base64Decode` 之类）被别的分区用到，切出去后必须能跨文件取，所以对这些**原本没 export 的**声明补了 `export`。原文件已 export 的声明一律不动（重复写一遍会 `Cannot redeclare`，这次踩到并修了）。

桶里只 re-export **原本就对外公开**的名字，私有辅助不外泄，包 API 与拆分前一致。

## 做法（可复用）

`ts-partition.js`（在工具目录，不在仓库里）：

1. 用 TypeScript 编译器 API 取每条顶层声明的 1-based 起止行，按行区间归桶，**任何声明跨桶边界就报错退出**（这次报过 L1180–1186 一处，把头像区间尾改到 1191 才好）。
2. 用「词边界出现」判定分区之间的引用（不用 AST 自由名：Zod `z.object({ role: … })` 的键名会被误判成未解析标识符，之前正是这个把 247 个键名报成告警）。
3. 分区间依赖图找环，有环就退出。
4. 生成分区文件（头注释 + 跨区 import + 原文正文 + 私有声明补 export），`index.ts` 写成纯桶。
5. 带护栏：输入声明数 < 100 就判定「已经拆过了」，直接退出（避免把桶再拆一次；这个坑也踩过一次，靠 `git checkout` 恢复原文）。
