# 切会话输入框先居中再落下（载入期锁首页态）

**日期**：2026-11-19。
**范围**：纯前端（`web/shell.js`、`web/chat-open.js`、`web/app.js`、`web/style-07-composer.css`）。
不碰契约、不碰服务端；刷新即生效。

## 问题（2026-11-19 用户反馈）

从设置 / 任务 / 会话画板回到对话，或点侧栏切会话时，输入框会**先在屏幕中间出现，再被快速拉到底部**——
一下多余的位移动画。用户的原话：「这个动画不是只在第一次说话时才有吗？」

## 根因

首页态（输入框竖向居中）与对话态（贴底）是同一个 `.composer`，靠 `#view-chat[data-home]` 切换，
CSS 给 `bottom` 挂了 `--dur-enter` 过渡（style-07-composer.css）。

而 `openChat()` 一进来就必须 `clearThread()`（停旧审批计时器、清待发附件），线程被清空后
`updateHomeMode()`（shell.js）按「线程里有没有 `.msg`」判断，立刻判成**空会话 → 首页态**：
输入框抬到中间。等 `GET /messages` 异步回来、历史渲染进线程，又判回对话态，输入框再落回底部。
两条路径（`clearThread` 与 `addMessage`）都走同一个 `updateHomeMode`，所以每次打开已有会话都会触发一遍。

从设置 / 画板回来时更明显：`go("chat")` 先把视图 `hidden` 撤掉，此时输入框已经按首页态居中，
历史回来才落下去——正是用户看到的「先中间、再被拉下来」。
第一次说话时的下滑本来也是这个 `data-home` 切换，只是那次是用户动作，本该有动画。

## 改了什么

- **`shell.js`**
  - 新增 `beginHomeSettle(token)` / `endHomeSettle(token)` / `cancelHomeSettle()`：
    载入期给 `#view-chat` 挂 `data-home-lock`（`updateHomeMode` 直接 return，不判空 / 非空）
    与 `data-home-settling`（关位移过渡），并先把 `data-home` 定成对话态 `0`（贴底）。
  - 锁带 token（沿用 `state.navToken`）：并发 / 被顶掉的旧 `openChat` 收尾不会拆新请求的锁。
  - `updateHomeMode({ animate = true })`：`animate: false` 时临时挂 `data-home-settling`，
    改完 `data-home` 后用一次强制 reflow（读 `el.composer.offsetHeight`）把「无过渡 + 新位置」
    钉进样式，再摘属性——同一任务里改两次属性浏览器只做一次样式计算，不加 reflow 直接摘属性
    会把这次位移重新变成动画。不用 rAF：后台 / 不可见窗口的帧回调会被节流甚至不跑，
    属性会一直挂着（2026-11-19 IAB 实测 rAF 回调 0 次）。
- **`chat-open.js`**
  - `openChat()`：`clearThread()` 前 `beginHomeSettle(token)`，`finally` 里 `endHomeSettle(token)`，
    历史画完（或失败 / stale）再一次性结算首页态；stale 时 `endHomeSettle` 自行忽略。
  - `startNewChat()`：清完线程后调用 `cancelHomeSettle()` —— 新建会话不等一条已被顶掉的 `openChat`
    收尾才把输入框抬回中间。
- **`app.js`**：首屏那次 `updateHomeMode({ animate: false })`。刷新后输入框直接落在最终位置，
  不再从底部升到中间（无会话）或从中间落回底部（恢复上次会话）。
- **`style-07-composer.css`**
  - `.main[data-home-settling] .composer { transition: none; }`
  - `.main[data-home-lock] .empty { display: none; }`：历史回来前不知道是不是空会话，
    空态问候也先不画，避免闪一下。

**保留的行为**：用户发第一句话（`addMessage` → `updateHomeMode()` 默认 `animate: true`）仍是从中间
下滑到底部；新建对话仍是从底部升到中间。载入 / 首屏 / 结算都不再有位移。

## 验了什么

- `node --check`（`shell.js` / `chat-open.js` / `app.js`）过。
- `npx tsx --test src/web-imports.test.mjs …`：web 相关 6 个测试文件 24 条全绿
  （含命名导出护栏——新增的 3 个导出都能被静态导入检查找到）。
- 浏览器（IAB，127.0.0.1:39847）用 `MutationObserver` 记录 `data-home*` 变化与输入卡 `top`：
  - 首页 → 点已有会话：`home` 只从 `1 → 0`，载入全程 `top` 恒为 617（贴底），没有回中间。
  - 设置页 → 点总管条目：撤掉 `hidden` 那一刻输入卡已在 `top=617`，载入前后不变。
  - 会话地图 → 返回：同样 `home` 保持 `0`，载入前后位置不变。
  - 新建对话：`home=1`，输入卡居中（`top=278` / `bottom=419`，视口 720），
    `data-home-settling` 已摘、`transition-property` 恢复为 `bottom, width, border-radius…`。
  - 刷新首屏：无会话时一步居中（`top=278`），不再有升降过程。
- **没验成的**：IAB 不产帧（`rAF` 从不回调、`setInterval` 严重节流），动画本身无法逐帧观察；
  结论来自属性 / 位置日志与 `transition-property` 状态，真实浏览器需肉眼确认一次。
