# 对话设置抽屉精简（B 版 · 值优先）（2026-11-13）

状态：**已落地**（2026-11-13，主会话直接实施）。视觉基准：
`docs/设计方案/原型/16-对话设置-四版.html` 的 `data-v="b"` 各屏；落地后六屏对照：
`docs/设计方案/原型/17-对话设置-B版落地-六屏.png`。
本次只改前端（`web/app.js` / `web/style.css`），无新增端点、无新增存储。

## 结论

抽屉从「一人一页 + 通知页」收成**五个页**（home / persona / model / policy / archives）：
主页只留两个值格与档案四行，模型与备选合成一页，通知不再单独设页，档案四类改成一页四分段且只读。

| 旧 | 新 |
|---|---|
| 首页 4 行入口：主选模型 / 备选模型 / 权限 / 通知 | 首页 2 格（模型 / 权限）+ 档案卡 4 行 |
| 主选、备选各占一页（同一件事两个入口） | 一个「模型」入口，一页两段：主选 + 备选链 |
| 通知页（时间点 / 免打扰） | 删除；跟全站 `设置 → 桌面通知` |
| 权限页三档并排文字 | 三档竖排选项行（每档一句解释）+ 审批三档分段 |
| 档案四页（records / memories / routines / skills 各一页） | 一页四分段，切段不换页 |
| 首页一条「人设 v14」入口 + 身份卡 | 只留身份卡（两个入口指同一页，删掉行） |

## 改了什么

### 1. 首页：两个值格（`renderCsHome`）

- 身份块 `csIdentityNode` 仍是唯一人设入口（点头像 / 名字整块进 persona）。
- `.cs-tiles` 两格：
  - **模型**：值 = 当前 `modelId`（16px 等宽感）；副文 = 执事会话「备选 N 条 · 只在试跑与例行任务换」，
    没配备选写「没配备选 · 主对话只有这一条」，普通助手会话写「全局模型，所有对话共用」。
  - **权限**：值 = 访问档（完全访问 / 只读 / 不跑命令）；副文 = `审批 · <审批档>`。
    加「审批 · 」前缀是因为「完全访问 / 只问重要的」并排会被读成同一根轴上的两个值。
- 「档案 · 只读」卡四行：工作履历 / 记忆 / 例行规则 / 技能；每行 = 图标 + 名称 + 最近一条摘要
  + 右值（`N 条` / `N 个`）+ chevron；点行落到同一页的对应分段。
- 无标题单行「全部设置」卡（供应商、密钥、记忆、连接手机…）。
- 脚注「通知与外观跟随全局设置，这里不再重复一遍。」
- 打开抽屉时后台预取一次档案（`csPrimeArchive`），回来只在仍停首页时补画条数；失败保持副文占位。

### 2. 模型：主选 + 备选合成一页

`csPage` 只剩 `model` 一个入口。页内仍是原有的 `csPrimaryCard` 下拉 + `csFallbackCard` 链编辑器
（上移 / 下移 / 删 / 加一条，最多 5 条），POST 口径不变。

### 3. 权限页（`renderCsPolicyPage`）

- 标题「权限」，副题「它能替你动到什么程度」。
- 授权三档从分段改成竖排 `.cs-opt` 选项行：每档一行标题 + 一句解释 + 右侧单选点：
  - 完全访问 = 能改文件、能跑命令
  - 只读 = 能看，不改，不跑
  - 不跑命令 = 改文件可以，命令一律不跑
  三档并排时「只读」和「不跑命令」的差别得靠猜，竖排才写得到解释。
- 审批三档仍用分段（三个词够直白），`mountSegmented` / `syncSegmented` 原样。
- 选中行用底色 + 1px 描边，不用彩色填充（避免整块偏紫）。
- 提交仍分两次 POST `access` / `approvalLevel`；失败 toast + `refreshCsPolicy` 回滚。

### 4. 通知：抽屉不再设页

删掉 `renderCsNotifyPage` 与 `CS_TIMING_LABEL`；`KEY_NOTIFY` / `KEY_NOTIFY_TIMING` 与
全局设置页的「桌面通知」分组不动。抽屉首页只留一句脚注指向全局。

### 5. 档案：一页四分段（`renderCsArchivesPage`）

- 页首一句：「总管 · 只读。履历是结算过的单子，记忆是它自己攒的；规则在例行任务里改，技能是家目录里的文件。」
- 分段条：履历 / 记忆 / 规则 / 技能，各带条数，`aria-selected`，点击只重画面板。
- 单张 `.cs-arch-panel` 清单，四种画法：
  - **履历**：左日期 + 正文 + 时间，按 `createdAt` 新到旧；
  - **记忆**：正文 + 种类 chip（偏好 / 打算 / 事实 / 经验 / 经历 / 人事物）+ 来源与日期；
  - **规则**：绿点（启用）/ 灰点（停用）+ 名称 + `cron · 表达式` 或 `event · kind`，右值新会话 / 同会话 / **停用**；
  - **技能**：名称 + 一句说明 + 最近改动日期，按 `updatedAt` 新到旧。
- 数据一次拉全：`GET /agent/memory?scope=partner:<id>&limit=2000`（`kind=work` 归履历、其余归记忆）、
  `GET /routines?partnerId=`、`GET /partners/:id/skills`；同一目标并行只拉一次，结果留到下次打开抽屉前
  （`openDrawerAt` 清空，条数可能被上一轮对话改过）。
- 普通助手会话（`csTarget=null`）只给一句说明，不摆四行入口——点进去只有说明等于噪声。
- 旧深链兼容：`openPartnerProfile(id, page)` 仍传 `records/memories/routines/skills`，
  `renderCsPage` 命中 `CS_PROFILE_PAGES` 时转成 `archives` + `csArchiveTab`。

### 6. 样式（`style.css`，只加不改）

新增 `.cs-tiles / .cs-tile(-label/-value/-sub)`、`.cs-arch-tabs / .cs-arch-tab[aria-selected] /
.cs-arch-panel / .cs-arch-row / .cs-arch-date / .cs-arch-dot(.off) / .cs-arch-main / .cs-arch-text /
.cs-arch-meta / .cs-arch-right`、`.cs-policy-list / .cs-opt[aria-checked] / .cs-opt-main /
.cs-opt-title / .cs-opt-sub / .cs-opt-dot`。全部只用既有 token（`--card` / `--card-border` /
`--r-lg` / `--divider` / `--surface-low` / `--outline` / `--accent` / `--accent-line` / `--ok` / `--shadow`），
不引入新颜色。

## 员工档案为什么只读

- 档案页是**读数页**，不是编辑面。四类各自的改动入口本来就在别处：
  - 人设（SOUL / 契约 / 目标）→ 身份卡进人设页三卡；
  - 记忆（删 / 标过时 / 整理）→ 设置 → 记忆；
  - 例行规则（改名 / 改触发 / 停用）→ 例行任务页；
  - 技能 → 家目录里的技能文件（抽屉只列文件名与说明）。
- 只读不等于被动：写作侧一直在跑（派单结算写履历、对话里「记住…」写记忆、例行任务每轮结算），
  档案页负责让人一眼看清「它记住了什么、最近做了什么」。

- 未跑：真机连真实数据的抽屉（本轮只跑桩数据）；手机端不涉及。

## 已知边界 / 刻意不做

- 首页不再有独立的「人设 v14」行：身份卡已是唯一入口，两个入口指同一页只会多点一次。
- 档案条数与摘要来自一次 2000 条上限的记忆拉取；超过上限的部分不进档案页（与记忆页同口径）。
- 档案四段都不提供「改」的按钮，也不做跳转按钮（页首那句话用文字指路）；跳转留给后续判断。
- 不做档案搜索、筛选、分页；四段都按「全部列出来」画。
- 通知页删了，但 `KEY_NOTIFY` 的读写逻辑与桌面通知分组保持原样。
