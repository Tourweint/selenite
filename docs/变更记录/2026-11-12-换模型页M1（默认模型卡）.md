# 变更记录：2026-11-12 换模型页 M1（默认模型卡 + 供应商整理）

> 上位：用户当日口径「设置页现在挺满意，主要问题是风格不统一 + 解释性文字太多；**先改换模型页**」。
> 三版/两版设计预览见手机仓 `docs/设计预览/2026-11-12-电脑设置与模型页方案.html`（本件落 **M1**）。
> 范围：`web/app.js` + `web/style.css`。**零契约改动**（shared / 接口文档 / 服务端路由一律不动）。

## 改了什么

| # | 落点 | 改动 |
|---|---|---|
| M1-1 | `app.js` 模型页模板 | 「默认模型」从一行 `row-label` + 原生 `<select>` 升成**当前模型卡**：`mdl-name`（18px 600）当页面第一眼，`mdl-hint` 收「供应商 · 切换后下一轮生效」；右侧「更换」按钮。弹层挂在卡片外层 `.mdl-wrap`（`.card` 有 `overflow:hidden`，浮层放卡里会被裁） |
| M1-2 | `renderDefaultModelRow()` | 重写：三态（未配置 / faux / 正常）+ `total < 2` 不出按钮；点「更换」现拉目录并复用 `renderModelMenu()`（供应商分段 + 模型行），`data-no-thinking="1"` 关掉对话页那排思考强度分段（那是会话级偏好，不属于「换默认模型」）。弹层里选完由 `modelchange` 收起并重填本卡。`change.onclick` 用赋值不用 `addEventListener`，避免卡片重绘后监听叠加 |
| M1-3 | 弹层关闭三通道 | 点外（`.mdl-wrap` 之外）、Esc、选完自动收。**弹层内 `click` 停冒泡**——切供应商分段会就地重渲染，被点按钮随即脱离 DOM，冒到 document 时 `closest(".mdl-wrap")` 找不到祖先，会被误判成"点外面"（真机实测：点分段弹层直接关掉） |
| M1-4 | `renderProviderModelList()` | 元信息从「上下文 131K · 输出 4K · 思考 关/低/中/高」压成行尾定宽列 `131K · 4K`，完整口径进 `title` 悬停 |
| M1-5 | `renderProviderNav()` | 供应商行尾加模型个数（只给数字，不写「个模型」——224 宽多两个字就挤掉名字） |
| M1-6 | `style.css` | 新增 `.mdl-*` 六条（卡片横排 / 名字 / 副行 / 弹层向下展开）；`.svc-model-*` 从"一张模型一张套框小卡"改成卡内平铺行 + 行底细线 + 行尾定宽列；新增 `.svc-row-count`；删掉退役的 `.model-select`（全仓已无引用） |
| M1-7 | 文案 | 供应商页头「填 API Key 就能用：Key 只存在本机服务端，不进 git、不进日志、不下发手机。保存后下一轮对话生效。」→「Key 只留在本机服务端，不进 git、不进日志、不下发手机。」（env 模式同步收短）；API Key 输入框下方那条重复的密钥纪律删掉（页头已有）；模型区「每个模型单独配置上下文与思考档；保存供应商时一起写入」→「每个模型可单独配置，随供应商一起保存」 |

## 刻意没做

- **设置页整体重排**：用户明确「先改这个换模型的就行」，三版设置页方案暂缓；
- **左侧导航分块（日常/助手/系统）**：同上，属设置页范畴；
- **模型清单搜索 / 排序**：现状 14–21 个，滚动可及，不引入输入态；
- **`model-select` 样式保留**：全仓 grep 无引用，直接删；若将来别处要用，重新写比留死代码便宜。

## 验证（真跑 + 看输出）

- 内嵌浏览器（1440×900）实拍 `#/settings/models`：
  - 当前模型卡：`auto/glm-5.3-flash` + 「magpie 本地网关 · 切换后下一轮生效」+ 右侧「更换」；
  - 点「更换」→ 弹层在卡片下方展开，供应商分段（百炼 / magpie 本地网关）+ 模型行；
  - 点分段「magpie 本地网关」→ 列表就地换成 21 个 magpie 模型，弹层**不关**（修复前会误关）；
  - 点 `auto/glm-5.3-flash` → 弹层收起、toast「下一轮起用 magpie 本地网关 · auto/glm-5.3-flash」、卡片保持；
  - Esc 收起：`isVisible` true → false；点「供应商」标题（弹层外）：true → false。
- 供应商编辑器：模型清单平铺成行，行尾 `131K · 4K` 右对齐成一列；供应商行尾出模型个数（百炼 14 / magpie 21）。
- 未跑：`pnpm typecheck`（本件只改 `web/` 下的纯前端 JS/CSS，不进 TS 编译）；`pnpm --filter @lifediary/server http`（模型相关端点未改动，前端只换调用方式）。

## 已知边界

- 弹层高度固定 `max-height: 320px`（沿用 `.model-menu`）：magpie 21 个模型需要滚动；未做"当前模型自动滚进视野"。
- `data-no-thinking` 是挂在菜单元素上的运行时标记，只在本次打开期间有效；关闭后不清除（下次打开前会被 `renderModelMenu` 重写，无残留影响）。
- 切到缺 key 的供应商时仍沿用 `chooseModel` 原逻辑：照常切换 + toast 提醒补 key（与对话 pill 一致）。

单提交 revert 本件即可：`app.js` 三处（模型页模板、`renderDefaultModelRow`、`renderProviderModelList` / `renderProviderNav`）+ `style.css` 两段。无数据迁移、无契约变化、无 env 开关需要。
