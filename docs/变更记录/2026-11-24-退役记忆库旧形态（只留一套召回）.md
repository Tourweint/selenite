# 2026-11-24 退役记忆库旧形态（只留一套 recall / remember）

**方案**：`docs/设计方案/2026-11-24-外部记忆库向量检索与检索超时.md` §十二（退役批）。
前置：deep（`external.deep`）与两档超时（`timeouts`）已落地并 1500/1500 绿；本批只删旧形态，
**不改 deep / 超时语义**。

## 改了什么

### 1. 删总闸 `MEMORY_BANK` 与整条双路径

- `src/plugins.json`：删记忆组 `keys` 里的 `MEMORY_BANK` 与整张「记忆库槽位」卡。
- `.env.example`：删 `MEMORY_BANK` 及说明；`PERSONA_MEMORY_ASK` / `PERSONA_MEMORY_INJECT`
  的说明改成"只播种 / 只在当前槽位 external 时生效"。
- `src/memory-bank.ts`：删 `memoryBankEnabled()` 与全部调用点；播种改为无条件（文件不存在
  且 `PERSONA_MEMORY_ASK` 是绝对路径就播种）；`activeBank()` / `bankSpawnEnv()` /
  `bankAskCommand()` / `refreshBankCatalogInjection()` 不再看总闸；
  `memoryBankState()` 的 `enabled` 恒为 `true`（字段保留，响应形状不变）；
  `tools` 恒为 `["recall","remember"]`（删 `toolsOf()` 的旧双闸分支）。
- `src/memory-api.ts`：`bankGuard` 只判 `MEMORY_ENABLED`；`GET/PUT /bank` 等端点不再因旧总闸 404。
- `src/flags.test.ts`：核心里表删 `MEMORY_BANK` 及两条 scope/hot 断言。
- `web/memory-page.js`：删 `bankMode="disabled"` 分支、`data.enabled === false` 分支与 7 处
  `MEMORY_BANK` 文案；槽位卡恒在（读不到状态 = 卡上错误行 + 重试）；旧页脚仍不渲染
  （与 2026-11-23 默认形态一致），`MEMORY_EXTERNAL` 开关与 `GET /memory/external` 端点保留。
- `scripts/memory-bank-probe.ts`：删「实例 C」（旧总闸 → 404 / `persona_recall`），
  头部说明改成两件事。

### 2. 删工具 `persona_recall` / `persona_write`

- `src/tools.ts`：删两块条件注册、`ToolDeps.personaAsk` / `ToolDeps.personaWrite`；
  `recall` / `remember` 的**描述文本一字未改**（prompt cache）。
- `src/agent/lifecycle-harness.ts`：删两个 deps 注入；`memoryBank` 恒注入。
- `src/tool-capability.ts`：删两条能力声明。
- `src/approval-policy.ts`：`WRITE_TOOLS` 删两行、`DEFAULT_CRITICAL_TOOLS` 删 `persona_write`。
- `src/partner-tools.ts`：删两个分组标签；`src/tool-result.ts` 迁移进度注释同步。
- `src/agent/policy.ts`：外部 remember 的只读拦截改为直接按 `read-only` 判（不再借
  `persona_write` 的工具名）；新增 `EXTERNAL_REMEMBER_CAPABILITY`（不登记进
  `TOOL_CAPABILITIES`，只给无人值守三态判定用）；两处文案删「切回原生记忆库（MEMORY_BANK=false）」。
- `src/eval-pool-approval-cases.ts`：删 `persona_recall` 案例；holdout 补
  `partner_skill_write → skip` 保持 6/6 表形（10–15 条、tune/holdout 各半）。

### 3. 双路径分支合并

- `lifecycle-harness.ts`：轻召回只在外接槽位跑（env 路径分支删除）；
  `persona_catalog` 只走 `externalBankCatalogProvider`；启动恒 `startBankCatalogRefresh()`。
- `persona-inject.ts`：`personaInjectGatesClosed()` 改为 `PERSONA_MEMORY_INJECT` ×
  `bankReadable()`（= `PERSONA_MEMORY_ENABLED` × 当前槽位 external × 读入口存在）；
  删 env 路径的目录缓存 / 刷新 / 定时器（`PERSONA_CATALOG_TITLE`、`personaCatalogCachedText`、
  `refreshPersonaCatalogInjection`、`startPersonaCatalogRefresh`、`stopPersonaCatalogTimer`、
  `resetPersonaCatalogForTests`），保留 `personaCatalogTrim()` 与
  `EXTERNAL_BANK_CATALOG_TITLE`。
- `lifecycle-injections.ts` / `injection-registry.ts`：目录 provider 换成
  `externalBankCatalogProvider`（保留群聊 / 非 chief 执事 / 开关闸）。
- `memory-bank.ts` 的 `refreshBankCatalogInjection(env, deps?)` 加可选 `spawnFn`（只为测试注入假子进程）。

### 4. 闸门与端点

- `bankReadable()` 成为唯一读判据（槽位 external + 入口在 + `PERSONA_MEMORY_ENABLED`）。
- `GET /api/v1/agent/memory/external`：数据源改成**当前槽位**（`activeBank()` + `bankCatalog()`），
  URL 与响应字段（`ok/configured/ready/provider/catalog?/reason?`）不动；槽位不是 external
  → `configured:false` + `reason:"not_configured"`。
- `GET /bank` 不再因 `MEMORY_BANK=false` 404；`MEMORY_ENABLED=false` 仍整组 404（新测试覆盖）。

## 缓存前缀说明（硬约束要求）

- **两个工具被删 = 工具面从「最多 4 个」收敛为恒 2 个**（`recall` / `remember`）。
  这是提示词前缀资产变化：上游 prompt cache 会在升级后失效一次。
- `recall` / `remember` 的**工具描述文本、schema、注册顺序一字未改**；
  `tool-schema-guard.test.ts` 的顺序快照删了 `persona_recall` / `persona_write` 两项，
  并新增「最小 / 全开装配都不得出现旧工具」断言。
- `persona_catalog` 注入标题文本未变（`EXTERNAL_BANK_CATALOG_TITLE` 仍是 2026-11-23 那句）。
