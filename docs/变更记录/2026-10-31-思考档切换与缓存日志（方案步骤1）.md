# 思考档切换与缓存日志（App 方案《Agent 化与上下文分层》§6 步骤 1）

- 日期：2026-10-31
- 方案：App 仓库 `docs/设计方案/2026-10-31-Agent化与上下文分层（只追加）.md` v1.1
  （D1 快/深同模型、D2 快慢只用 `enable_thinking`、D3 短会话首次调工具切一次、D3a 阈值测量主体 = harness）

## 背景

换模型升级深档的链路在 D1（快/深同款）下变成 no-op；方案把快慢语义全部移到
`enable_thinking`，并要求每轮打 `cacheRead` 日志支撑 §7 验收指标。

## 决策

1. 档位 = 同模型的两条**思考变体**（派生模型 `#think-on` / `#think-off`，
   `enable_thinking` 走 `samplingParams` 透传，与任务派生模型同机制）；
2. 首次工具调用时按**上一轮 `usage.input`**（D3a）判阈值，`< 4000` 切一次并保持，
   `≥ 4000` 不切；首轮无 usage 视为短会话；
3. 任务通道一律思考开（`enable_thinking: true` 进派生 key，派生 id 变更 → 旧任务会话存量引用失配，
   任务是一次性会话，可接受）；
4. `LLM_MODEL_FAST` / `X-Mode` 降级为部署别名（HTTP 契约不变，`X-Mode` 仍可用）。

## 变更清单

- `apps/server/src/provider.ts`：新增 `chatModelRef(thinking)`；`taskModelRef` 加 `enable_thinking: true`（variantKey 加 `th1`）；
- `apps/server/src/agent.ts`：`applyChatMode` 改思考变体 + 切过即保持；`upgradeOnTool` → `switchThinkingOnTool`
  （阈值判定 + `thinkingSwitched`/`thinkingRefused` 记账，`AGENT_TOOL_UPGRADE=off` 仍为总开关）；
  新增 `lastTurnInputTokens` / `thinkingTokenLimit`（`AGENT_THINK_TOKEN_LIMIT`，默认 4000）；
  chatStream settle 时打 `[usage]` 行；`usageSummary` 加 `cacheReadTokens`/`cacheWriteTokens`；
  新建会话默认模型 = 思考关变体；
- `apps/server/src/openai-compat.ts`：`decideMode` 的"调过工具→deep"改为"已切思考开→保持"；
  通用聊天默认建思考关变体；
- `apps/server/scripts/task-probe.ts`：快档断言改为"真实模型名 + `enable_thinking=false`"。

## 影响范围

- 部署需同步 `LLM_MODEL = LLM_MODEL_FAST = deepseek-v4.1-flash`（env，不在本仓库提交）；
- 旧聊天会话（存量模型引用）首次发消息会被配到思考关变体，**前缀变一次、缓存重算一次**（一次性成本）；
- 旧派生任务模型 id（无 `th1` 后缀）不再注册；任务会话一次性，无实际影响。

## 验证结果

- `pnpm typecheck` 通过；
- `pnpm probe`（durable 内核语义）全部通过；
- `pnpm --filter @lifediary/server tasks`（任务通道探针）全部通过（含更新后的思考关断言）；
- 独立实例（`PORT=18082 LLM_PROVIDER=faux` 临时库）`pnpm smoke` 全过，
  `[usage]` 日志按轮打印（`input=1023 cacheRead=0 cacheWrite=1023 output=4` → 第二轮 `cacheRead=2`，faux 模拟值）。
  真实上游的 cacheRead 数字待联调时核对（§7 指标）。

## 回滚建议

单提交回滚即可；env 不用动（`LLM_MODEL_FAST` 仍被装配，仅语义降级）。
回滚后任务派生 id 恢复旧公式，与回滚前的存量任务会话一致。
