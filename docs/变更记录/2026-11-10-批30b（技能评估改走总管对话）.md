## 改了什么、为什么

**v1（批 30 初版）**：设置页按钮 → 后端独立模型调用（候选链盲扫 provider×model）→ 快照。
用户两条反馈否了它：评估应该发生在用户眼皮底下、用用户自己选的模型；盲扫不知道会撞上什么。

**v2（本批）**：
```
设置页「让 Agent 评估」
  → GET /agent/skills/advice 拿预填提示词（服务端拼好：判据 + save_skill_advice 指引 + 122 条技能清单 JSON 行）
  → 前端 openChiefChat()（切到总管最新会话或新开）+ el.input.value = prompt（预填，不自动发送）
  → 用户看过点发送 → 总管在用户选的模型上逐条评估
  → 总管调 save_skill_advice 工具把 [bucket, frequency, reason] 一次性写进快照
  → 用户回技能页：分栏已更新 → 「一键采纳」写启停位（PUT，名字必须来自快照的闸门不变）
```

- **撤掉的东西**：`generateAdvice` / `adviceOnce` / 候选链 / `adviceSystemPrompt`（独立模型调用整套）、
  `AuxUse` 的 `advice` 用途（revert auxiliary 到批 30 前）、前端 POST 等待逻辑（145s 转圈不再存在）。
- **新增的东西**：`save_skill_advice` 工具（条件注册：`SKILL_ADVICE=false` → 不上架，一行回滚；
  `TOOL_CAPABILITIES` 登记 readOnly=false / destructive=false / sideEffect=workspace / risk=low——
  只写建议快照，不碰启停位，采纳仍是人的动作）；POST 端点改为"导入总管评估完的 JSON"
  （与工具同一条清洗口径：非法条目丢弃、全非法 400）；GET 附 `prompt` 字段。
- **新会话才见工具**：`save_skill_advice` 经注册进 tools 数组=进 API 请求的 tools（工具描述是缓存
  前缀资产）——已在批 30 记过该纪律，本批注册面变化随本记录入账。

## 模型与账单（用户插话的回答，核对结论一并登记）

- **子代理（宰相派活的工人 / 任务专线）现状就是主对话模型**：`taskModelRef`（provider.ts:1324）
  从 `readLlmConfig()` 当前模型派生，只加"思考开"采样参数，没有独立子代理模型目录——
  "子代理用了贵模型"的风险现状为零，不需要改。
- **辅助用途**（`AUX_MODEL_EXTRACT` / `AUX_MODEL_REVIEW`）：`.env` 均未配置 → 回落当前模型，
  同样与主对话一致；`AUX_MODEL_ADVICE` 随本批撤销，不再存在。
- **"引导 Agent 对话"作为通用模式**（用户插话点名）：定时任务模块等"需要模型决定"的场景
  照本批模子做——界面预填提示词 → Agent 在用户选定的模型上干 → 结果经受闸门的工具落盘。
  已登记为后续批次的指导口径（任务书修订节）。
