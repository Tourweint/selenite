# 上下文压缩设置落地（只两档 · 默认 70%）

> 2026-11-14。方案：`docs/设计方案/2026-11-14-上下文压缩设置（全局·按模型·百分比或绝对K）.md`。
> 一句话：自动压缩从"内核写死 16384 白"变成设置 → 会话里的两档选择，默认按窗口 70% 压。

## 用户两次拍板（第二次是纠偏，以第二次为准）

1. 第一版：全局 + 按模型，三档（跟随默认 / 百分比 / 绝对 K）+ 四个数值旋钮。
2. 第二版（用户当场否掉第一版）：**只留「按百分比 / 按 token」两档**，**默认 70%**；
   保留原文、后台提前**删掉**（"这都没有用"）；界面上那条"读不到开关"要能消失。

## 改了什么

| 层 | 改动 |

## 口径（与代码一致）

- **触发**：内核判据 `估算 token > contextWindow - reserveTokens`；界面说的"到多少压" = 触发点，
  服务端换算 `reserve = window - trigger`。
  **用户口径原话**：窗口 100K、按 token 填 70 → 到 70K 压一次、压完接着跑这一轮（不是压完就停）。
- **粒度**：全局 + 按模型。**没有每会话一份**——`Conversation.configure()` 不收 compaction，
  `HarnessOptions.settings` 的访问器也没有会话参数。要做只能自建压缩，已登记"明确不做"。
- **默认**：`percent` + 70，不设就是它（不再有"跟随内核"档；旧值 `default` 回落 `percent`）。
- **删掉的两个旋钮**：保留原文 / 后台提前一律吃内核默认 20000 / 32768。
- **提示行**：不再渲染常驻的"读不到开关"。读失败只影响回显、静默按默认显示；写失败走 toast。
  （上一版那条不会自愈也关不掉，用户实测反馈"保存成功了它还挂着"。）

## 还有哪些不确定

- **没跑过真实长会话**：换算与"下一轮生效"由单测 + 内核源码（`harness.js:123` 访问器、
  `generation.js:236-246` 判据、`compaction.js:194-203` 精确查表）推出，**没有**在真模型上把上下文
  撑到阈值看它压一次。要实测就保持 70% 跑一段长对话，看启动日志 `[压缩]` 与压缩条目。
- **估算口径的偏差**：内核 `estimateContext` 只算计划提交的条目，不含系统提示 / 工具描述，
  所以"70%"大约是历史条目到 70%，不是"窗口已用 70%"。界面不报"离触发还有多远"，就是这个原因。
- **`modelOverrides` 只覆盖目录里的模型**：faux / 未配置供应商时窗口表为空，回落内核 16384。
- **手机端没有入口**：设置卡在 web（桌面壳内嵌页）；手机端要同步得另开一批（跨仓库契约）。
- **界面没实渲染过**：本机服务当时没在跑，没开浏览器截图；只做了 `node --check` + 沿用既有
  `rowMarkup / sectionMarkup / switchMarkup / segmented` 三件套。要看效果：起服务 → 设置 → 会话，
  "上下文压缩"是最后一张卡。
