# 反向补课：没有开关的功能抠成插件（12 张）

**日期**：2026-11-18  **状态**：已落地（消费代码需重启；清单本身热更新）

## 改了什么

接续同日早上的「行为开关收进插件中心」（44→81 项）之后的反向问题：**压根没有开关的硬编码功能**，
按同一判据审计一遍，够格的抠出开关并补卡。插件清单 81 项 → **93 项 / 7 组**。

## 插件边界（本轮定稿的判据）

**抠成插件，四条同时满足**：
1. 用户认得出的能力——能一句话说清开了是什么样、关了回到什么旧形态；
2. 关掉是合理使用方式，不是自残（修复 / 兜底 / 可靠性机制不进：关掉只会变坏）；
3. 有真实的关闭动机（省额度 / 管行为 / 回滚），不是「没人会去碰的内部账本」；
4. 改动可控——不为做开关把子系统拆散，也不给一行文案一个开关（太简单的不做）。

**core 与 env / JSON 分流**：`scope=core` 只收**决定子系统边界**的总闸（现 5 项：记忆 / 执事体系 /
宰相 / 自主轮 / 工具写权限——env 兜底，`loadFlagOverrides` 启动写回 env）；本轮 12 张全部
`scope=plugin`（JSON 真源，界面改即时或下轮生效）——没有一个候选到「子系统边界」的量级。

## 刻意不做（本轮审计后排除的）

- **`TURN_TIMELINE`**：前端零消费的纯观测账本 + 只读端点——判据第 3 条不过（没人会去关）。
- **`BRIEF_CARD_RULES`**（纪律段简报卡规则）：提示词内部结构，用户认不出差异。
- **`AGENT_CONFIRM_WORLD_STATE` / `AGENT_UNATTENDED*` / `AUTONOMY_NO_ESCALATION` /
  `AGENT_TAKEOVER_HINT` / `MEMORY_IMPORT`（整理建议内的导入动作解析）**：机制 / 调试 / 观望中的可靠性实验。
- **`EXPLORER_OPEN` / `EXPLORER_FOCUS` / `CHANCELLOR_EMPLOYEE` / `RELAY_LINK_UI`**：壳侧行为与部署形态（executor.json 界面已管用户可见部分）。
- **消息时刻、思考块并入灰块、悬停修复**：太细的 UI 改动，不做开关。

## 语义变化

- `CHAT_EXPORT_HANDOFF` / `EXPORT_BUNDLE` / `FILE_BROWSE` / `SKILL_STATE` / `EXECUTOR_PROBE` /
  `AGENT_PROGRESS_REPORT` / `AGENT_VERIFIED_ANSWER` / `MEMORY_SPLIT` / `MEMORY_IMPORT_SOURCES`：
  布尔判定收紧到统一口径 `false / 0 / off` 算关（原「只有显式 false 才关」，`chat-handoff.test` 断言同步）。
- `MEMORY_PROACTIVE` **反向保持**严格 opt-in（垃圾值不开）——观望型能力拼错不该开。
- 新键只有 `CHAT_BRANCH_ENABLED`；其余 11 个键早已存在，只是从裸 env 挪进清单（JSON 覆盖优先于 env）。
