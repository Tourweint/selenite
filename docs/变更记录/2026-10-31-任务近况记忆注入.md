# 2026-10-31 · 任务会话的近况记忆注入（记忆 B 路）

## 背景

上位方案 `2026-10-31-Agent化与上下文分层（只追加）.md` 的 D9 把任务拆成两类：
- **成稿类**（收敛/成章/周报/视角/分段）**不注入记忆**——收敛曾把记忆当事实写进草稿；
- **需要"最近记了什么"的**（`question`、`diary_review`）**要注入**，但只能读、不能写。

同时 App 侧提问一直是"自己把画像 + 近三天 + 今日速记拼进 system"，那是两处真相，
且前缀随数据抖动（缓存整段重算）。这一轮把上下文收回服务端。

## 决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 取数走 **B（日记镜像）**：`diary.sqlite` 近 3 天 `CONFIRMED` | 零新接口、隐私面不变；速记/画像留给后续的 A 路 |
| 2 | 注入位置 = **instructions 尾部的 `<memory>` 块** | 模板前缀不变（缓存照旧命中），只有近况这一小段是新的 |
| 3 | 由任务表声明 `memory: "diary"`，不是"所有任务都注入" | 与 D9 对齐；成稿类必须只引用给到的原话 |
| 4 | 读失败**静默降级为空** | 镜像可能还没建库；绝不能让任务因为记忆失败而失败 |

## 变更清单

- `DiaryStore.recent(sinceDate, limit)`：只读"已确认 + 未删除"，按 `entry_date` 倒序；
- `agent.taskMemoryBlock(days=3, limit=12)`：拼 `<memory>最近 N 天你自己记下的（只作参考：可以呼应，不要逐条复述，也不要评价记多记少）…</memory>`；
- `tasks.ts`：`TaskSpec.memory?: "diary"`，`question` 与 `diary_review` 打开；
- `openai-compat.ts`：任务分支里 `promptWithMemory = prompt + "\n\n" + memory`，并打日志 `[compat task question@…] 注入近况记忆 N 字符`；
- 探针新增 §0（用 `/diary/sync` 造 3 天 fixture，独立 `DIARY_DB_PATH`，不碰生产镜像）与 §6b
  （`question` 的 system 含 `<memory>` 与 fixture 内容；`converge` 不含）。

```

```

即模型确实用上了"近况"（fixture 里 10-29 那条"方案改成两步走"），且没有逐条复述、没有负向表述。
