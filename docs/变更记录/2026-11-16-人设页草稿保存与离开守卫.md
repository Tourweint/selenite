# 人设页：草稿保存 + 离开守卫（2026-11-16）

## 背景

用户口径：人设页上的开关以前是「点一下立即 PUT」，误触之后容易忘了自己改过什么。
要求：必须点保存才生效；带着未保存改动退出页面时，弹「还没保存，是否保存并退出？」。

## 改动

- `web/partner-profile.js`
  - 人格页的**一触即存**全部改成草稿：预设、14 个模块开关、挂念 / 记忆召回子开关、
    结果整理 / 日记执事两行。点一下只改本地 `persona` / `partner` 字段，不请求服务端。
  - 新增底部 sticky 保存条（`#pf-savebar`）：`N 处改动未保存` + 撤销 + 保存。
    保存一次按需发 `PUT /partners/:id/persona`（preset + modules + switches）和
    `PATCH /partners/:id`（tool_projection / diary）；成功后服务端回读值成为新基准。
  - 保存条覆盖整页：人设正文（名字 / 头像 / SOUL）的既有草稿也计入同一条的计数与保存 / 撤销。
  - 预设点击先在本地铺默认开关（`PF_PERSONA_PRESET_MODULES`，与服务端 `PERSONA_PRESETS`
    同步）；改任一模块后本地按最终表推导预设，页面高亮与服务端保存后的结果一致。
  - 弹层里的保存仍然即时（静态内容 / 活状态 / 契约 / 目标 / 纪律 / 工具 / 人设库）：
    它们只改内容，保存后用 `applyServerPersona(data, keepDraft)` / `pfApplyPersonaData(..., true)`
    把页面里未保存的开关草稿叠回去，不让回读值冲掉草稿。人设库「应用」是整份替换，
    反而会把草稿基线一起换掉。
  - 离开守卫：路由切换前弹三选一「取消 / 不保存退出 / 保存并退出」；取消用
    `history.replaceState` 把地址改回详情页（不触发 hashchange，草稿保留）。刷新 / 关窗
    另挂 `beforeunload`。暂停 / 恢复会整页重渲染，有草稿时先拦住。
- `web/route.js`
  - 新增 `setRouteGuard(fn)`：`applyRoute()` 先问同步守卫，`false` 就不换页；
    放行一次即卸任，页面若仍是自己会重新注册。
- `web/style-22-partner-profile.css`
  - `.pf-savebar`：底部 sticky、有改动才出现；没有改动时整条隐藏。

## 为什么不用运行时开关

这是页面防误触的交互修正，不是新的 agent 能力；保留一条「立即保存」的旧路径会让两套
写状态逻辑并存（草稿与即时保存的基线互相踩）。要回退直接回退本次改动，不设 flag。

## 验证

- `node --check web/partner-profile.js` / `web/route.js`；`pnpm typecheck` 通过。
- 真浏览器（39847 实例）验收总管 / 小记两页：
  - 点开关：服务端 `GET /persona` 仍为旧值，保存条出现并计数；点保存后落库、条消失。
  - 带改动点面包屑 / 设置顶栏「返回」：都弹「还没保存」，三个按钮齐全；
    取消 → hash 回到详情页且草稿保留；不保存退出 → 服务端不变；保存并退出 → 落库后离开。
  - 人设正文 + 开关同时改：一条保存条同时保存两处；撤销把人设正文与开关一起还原。
  - 关着的模块点卡「打开并编辑」：开关只进草稿，编辑层保存内容后草稿仍在。
  - 小记页同链路复跑；测试后已把总管 / 小记恢复原状（总管 work、口吻关；小记 custom、心情关）。
- 未跑：完整 `pnpm test` 套件（本次只改前端静态 JS，无 TS / 契约改动）。

## 已知边界

- 桌面壳会缓存静态 JS，验收 / 使用前要 F5 一次。
- 同页重渲染（地址已是当前详情页）不会弹离开提示，也不会冲掉草稿；这是有意的。
- `beforeunload` 的文案由浏览器决定，不能自定义成「是否保存并退出」。
