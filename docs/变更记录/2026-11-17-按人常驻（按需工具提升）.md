# 按人常驻：按需工具可提升成常驻

**日期**：2026-11-17 当日方案落地。
**方案**：`docs/设计方案/2026-11-17-按人常驻（按需工具提升）.md`；结论已下沉
`接口-端点4-执事例行与自主轮.md` §2.11（GET/PUT 形状、校验、生效与边界）与
`系统架构.md`（`partner-tools.ts` 模块行）。

## 背景

2026-11-16 C 段把 8 个低频工具做成 deferred，但名单是代码常量 `DEFERRED_TOOL_NAMES`
（源码注释自承"改清单 = 改代码"），人设页只能「用 / 不用」。2026-11-17 工具调用计数落地后，
`count` / `loads` 能看出"藏错了"；本批补上"改得动"的那一环。

## 改了什么

- **存储**：`partners.promoted_tools TEXT`（JSON 数组，只存被提升的 deferred 工具名；空 = 全按需）。
  旧库 `ALTER TABLE` 补列；`PartnerRow.promotedTools`；解析复用取消名单那套 JSON 数组口径
  （`toToolNames`，旧名 `toDisabledTools` 保留别名）。
- **视图**：`GET /partners/:id/tools` 多带 `promoted:[...]`，每项多带 `promoted:boolean`；
  `PARTNER_TOOLS_ENABLED=false` 的空形状同步带 `promoted:[]`。
- **端点**：`PUT` body 扩 `{disabled, promoted?}`。**不带 `promoted` = 不改原名单**（旧客户端兼容）；
  带 = 全量替换。校验：非 deferred 400 `只能提升按需工具：…`；未知名 400；
  与 `disabled` 冲突 400；`sanitizePromotedTools` 去重、≤64。
- **依赖收口**：新增「取消 `tool_search` → 400」——它是按需工具唯一入口（`toolDependencyError` 第一条）。
- **运行时**：`applyPartnerToolSelection` 早退判据从"非 deferred 集合"改为**期望 offer 集合**
  （非 deferred 未取消 ∪ 已加载 ∪ 已提升 − 取消），否则提升变化不触发写；
  `add` 带上"已加载 ∪ 已提升且未取消"的 deferred。提升写进会话 `modelTools.add`（内核
  「延迟 − 已 offer」），**不用改内核、不用重启，下一次请求生效**。
- **前端人设页**（`web/partner-profile.js` + `style-22-partner-profile.css`）：deferred 行加可点胶囊
  「按需 / 常驻」（放在 label 里，点击由 JS 拦住默认勾选行为），并行拉 `/agent/tool-usage`
  显示「用过 N 次 · 搜出 M 次」作为判据；保存时一起提交 `promoted`。用量读不到不显示、不挡保存。
- **测试**：`partner-tools.test.ts` 补 sanitize / 冲突 / tool_search 守卫 / apply 四条（含边界）；
  `companion-api.test.ts` 补端点级一条（回读、旧形状不清空、非按需 400、冲突 400、守卫 400、收回）。

## 已知边界（写进接口文档）

内核只认「延迟 − 已 offer」，**区分不出"被 tool_search 加载"和"被人提升"**。所以：
- 提升：下一次请求即生效（含老会话，写 add 幂等）；
- **收回：只对还没 offer 过它的会话（新会话）生效**；某个会话里已 offer 的，收回后仍留着，
  与 "tool_search 加载过即不可逆" 同一语义。

## 刻意不做

- 不改全局 `DEFERRED_TOOL_NAMES`（全局高频仍要改代码；先看按人提升够不够用）。
- 不做自动提升 / 自动收敛（账只给判据，人来点——"自动化必须可见"）。
- 不给非 deferred 工具开放"改为按需"（那等于改全局名单，是另一件事）。
- 不动工具描述 / 注册顺序 / 内核。
