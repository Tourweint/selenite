# 2026-11-15 改人设页二次重构（岗位能力并入全卡片化）+ 列表卡⋯菜单与删除执事

## 改了什么

承接同日《执事招聘模板与改人设页重构》第一批后的用户反馈，两块改动：

### 一、执事列表卡（partner-modals.js）

- **「试跑」「暂停」「改人设」全部收进 ⋯**（二轮反馈：改人设也进菜单），卡面只剩一个裸「⋯」（无外框，hover 才浮浅底；用户口径"不需要外边那个圆框"）。
- **⋯菜单**（复用项目卡的 `openProjMenu`，挂 body + fixed 不吃容器裁切）：试跑 / 暂停（恢复）/ **删除执事**（danger，总管没有此项）。
- **删除执事**：DELETE `/api/v1/partners/:id` 端点与 `store.delete`（档案行+版本+会话链接+例行任务+群成员+家目录整体）**早就有、UI 一直没入口**——这次只补界面：输名字确认（照会话永久删除的防误触模式），删完若正开着他的档案页跳回列表。零新端点。

### 二、改人设页二次重构（partner-profile.js）

岗位、能力两个 section **并入人格模块**，一列卡片 + 组标题（怎么说 / 岗位 / 心里长的 / 能力），全部开关式：

- **带开关的卡**（开关式，用户拍板的统一语义）：**开 = 可点开编辑 + 进提示词；关 = 不能改 + 不进提示词（内容保留）**——关着的内容卡降半档视觉（is-off），点了提示「先打开『X』再改内容」。
- **不带开关的卡**（用户口径"必须做的直接放外边"）：负责项目 / 备选模型 / 例行任务 / 技能——点开即用（弹层）。
- 编辑层全部弹层化（原就地编辑搬进 modal，组件原样复用零重写）：岗位契约（套用模板/撤销/保存都在）、当前目标、负责项目（项目下拉）、备选模型（mountChainEditor）、例行任务（ptRenderRoutineList+新建表单）、技能（全量列表）。
- 原「注入细节」折叠**取消**：契约/目标/纪律/履历/在办 5 个全部升级成与其他模块一样的卡（契约/目标带编辑器，纪律/履历/在办是纯开关，点卡=切）。
- 接派单/结果契约（三态循环）/日记执事（唯一位）做成岗位组的开关卡，PATCH 逻辑原样搬运。
- 卡片摘要新增：契约带版本与字数（`v3·272 字`）、目标带截断预览、能力三样带异步计数（例行/技能/项目名 `pfPrefetchCardSummaries`）。
- `PARTNER_PERSONA_MODULES=false`（回滚档）：模块卡不带开关、恒可编辑（旧行为"谁也不裁"），岗位动作卡与能力卡照常。

## 为什么

用户反馈（语音转述）：改人设页"全做成人格模块这种的，开启就能选、可以展开；关了就没法修改、也不进提示词"；岗位+能力"全合并成一个，全是开关式的"；负责项目"不知道在哪里"（原来埋在岗位卡深处）；列表卡试跑/暂停没用、删除执事没有入口。

## 坑

- `openProjMenu` 的 `separator` 是**挂在条目上**的属性（先画分隔线再画同一条目的按钮），独立传 `{separator:true}` 会画出 "undefined" 空按钮——首验抓到，改为并进删除项。
- `openModal(title, build, options)` 宽档参数在**第三位**，传成第二参会把 build 整个换成对象。
- 带内层 `await` 的 modal build 回调要写成 `async (body) => {...}`（openModal 不 await build，回调内部自洽即可）。
