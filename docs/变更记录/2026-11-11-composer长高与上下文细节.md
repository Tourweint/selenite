# composer 输入栏长高 + 底缝遮衬 + 上下文环挪位与 K 格式

日期：2026-11-11
状态：已落地（typecheck ✅ / 745 单测 ✅ / 浏览器实机四场景 ✅，纯 web 三件、零契约）

## 起因（用户口径，2026-11-11）

1. **输入栏必须能长高**（"这个也是必须做的"）：学 ZCode——字多时输入栏自动变高、把聊天区撑起来；
   现在"变不了，就很难受"。
2. **输入栏底下那条缝不许露字**：composer 浮在滚动区上，滚轮回看时消息文字会从卡底下 14px 的缝里透出来
   （"无论用什么方式遮挡也好，或者把消失的端点改个位置也好"）。
3. 小细节顺手做：上下文框挪到选模型左边；上下文数字的单位改成 K 这类（"就比如 K 吧"）。

## 改了什么

### 1. 输入栏实时长高（学 ZCode）

- 真相：`resize()`（`height = min(scrollHeight, 200)`）**早就存在**，但只在发送清空后调用——
  打字过程中从不触发，所以"永远一行"。本次只补一行：`el.input.addEventListener("input", resize)`。
- 上限不变：textarea `max-height: 200px`，超出内部滚动；卡片 `max-height: 300px` 兜底。

### 2. 消息区让位跟实测卡高走（长高的配套）

- 原来消息区让位是写死的 `padding-bottom: 108px`（只够一行高的卡）；输入栏一长高，最后一条消息就被压在卡下。
- 现在：ResizeObserver **常驻**观察 composer 卡（原来只在首页态挂，对话态"卡高变化与定位无关"的前提被长高打破了），
  实测高度写进 `--composer-h`；`.thread` 的 padding-bottom 改为 `calc(var(--composer-h, 86px) + 22px)`。
  长高、错误卡（批 32）、附件行出现，一个来源、一处同步。
- 首页态居中沿用同一观察器：卡在首页长高时 `--composer-home-offset` 同步重算，
  几何上空态与卡片顶边的间距恒为 18px（公式两端都吃同一实测高度），推演自洽。

### 3. 底缝遮衬

- `.main[data-home]::after`：18px 高、与主区同色（`var(--surface)`，实色 #fdf9f2）的衬条垫到卡底下，
  比 14px 的缝高 4px，上缘藏进卡影里；`pointer-events:none`。
- 层级：衬条 `z-index:1`（压过消息流），`.composer` 提到 `z-index:2`（衬条不许盖卡）。
  消息泡非定位元素（`.msg` 是普通 flex），paint 顺序在 z1 之下。
- 首页/对话两态都垫（选择器 `[data-home]` 不分值），首页那条下面本来没有内容。

### 4. 上下文环：挪到模型 pill 左边 + 数字 K 格式

- index.html 里 `<span class="ctx-ring">` 挪到 `.composer-wrap`（模型 pill）之前，
  composer 右组变成 **环 → 模型 → 发送**（原来是模型 → 环 → 发送）。
- 环边数字从百分比 `${pct}%` 改为**已用 token 的 K/M 格式**：`formatTokenCount(data.used)`（"4K" / "1.2M"），
  复用设置页/模型菜单同款函数（13866 行起），不新增格式化逻辑。
- **细节全收进悬停（2026-11-11 用户再拍板）**：title = `用了 4K · 顶了 3% · 最多 128K`——
  用了（当前占用）/ 顶了（占上限比例）/ 最多（模型窗口），不出现「已用 token」这类字样；
  接口本来就回 `used` + `window` 两个数，纯前端拼装，零契约。
- 环弧仍按占比画，warn/danger 阈值逻辑不动。

## 验证（浏览器实机，隔离实例 PORT=39999 + faux）

- **长高**：灌 6 行文本 → `#input` inline style `height: 141px`（对话态 7 行 → 154px），实时生效 ✅。
- **上下文环**：faux 真发一条消息后环出现，可访问树顺序 = 环 → 模型 → 发送（环在模型左）✅；
  环边文字 "3K" ✅；悬停名 "上下文已用 2%（3K / 128K tokens）" ✅（当轮口径；后被用户改为「用了/顶了/最多」，见下）。
- **底缝遮衬**：压矮视口 + 真发长消息撑出滚动，滚轮滚到中段让长消息从卡片后面穿过 →
  整页截图卡片底下缝是干净底色，无文字 ✅。
  （插曲：IAB 截图后端在视口 resize 后会合成陈旧帧出"鬼影"——一张图里出现两个 composer 的 + 按钮；

## 悬停口径二次修改（2026-11-11 当天，用户再拍板）

用户："还是小圆圈是 4K，鼠标放在上面显示用了多少 K、顶了多少 K、最多是多少 K，
不要在旁边又显示已用的 token，只需要鼠标放上去浮起的小框显示。"

- 环边不变：仍是已用 token 的 K/M（`4K`）。
- 悬停 title 改为 **`用了 4K · 顶了 3% · 最多 128K`**——三项口语词，不出现「已用 token」「上下文」等字样。
- 纯 app.js 一行改动 + 变更记录；接口零变化（`used` + `window` 两个数前端拼装）。
- 验证：IAB 动作通道当轮被卡死的截图队列堵死（读活着、点不动，多形态重试均超时），
  改走三件套断言——①线上代码含新模板、不含旧文案「上下文已用」；
  ②SSE 真发一条消息拿真实用量（`used:3229, window:128000`）；
  ③用线上同款 `formatTokenCount` 演算：环边 `3K`、悬停 `用了 3K · 顶了 3% · 最多 128K`，无违禁字样。
  浏览器悬停人工看一眼即知（悬停文案就是 title 属性，行为无歧义）。

## 刻意没做

- 没引 `field-sizing: content`（新 CSS，等浏览器基线统一，JS 路径已闭环）。
- 没动卡片 `max-height: 300px` 上限；错误卡 + 附件 + 满高输入同时出现时可超——原有限流未变，非本次引入。
