# 2026-11-13 对话末尾与输入框的尾缝

## 改了什么

- **`ts/apps/server/web/style.css`**：`.thread` 的 `padding-bottom` 由
  `calc(var(--composer-h, 86px) + 22px)` 改成 `calc(var(--composer-h, 86px) + 14px + 44px)`。
  只动这一条规则，注释重写成"卡高 + 卡底距 + 尾缝"三段的算式。

## 为什么

用户报「对话变多以后，最后一条贴输入框太近，看着不舒服」。

原来是 `卡高 + 22px`，但 composer 自己是 `bottom: 14px`（离窗口底），两笔一扣，
最后一条消息底边到卡片顶边只剩 **8px** 净空——正好是一条消息的底沿蹭在卡沿上，
消息越多越明显。把卡底那 14px 显式写进算式之后，`+ 44px` 才是真正看得见的尾缝。

44px 取「≈ 一条消息框的高度」：用户原话是"大概也就是复制这一条框的长度"。
备选值实测对比过（尾缝 20 / 32 / 42px），20 仍偏窄、42 与 44 视觉上无差别，
取整数 44 落地。

## 验证

- 浏览器（产品浏览器，http://127.0.0.1:39847，815×912）：
  - 改前：8 条消息堆满滚动区，`composer.top - 最后一条.bottom = 8`，`padding-bottom: 108px`。
  - 改后：同场景 `= 44`，`padding-bottom: 144px`（= 86 卡高 + 14 + 44）。
  - 首页态（`data-home=1`）：`padding-bottom` 仍走 `.main[data-home="1"] .thread` 的
    `calc(50vh + offset + 42)`，实测 556.5px，问候语与居中卡的位置一格没动。
- 截图（临时留存，`.screenshots/` 不进 git）：`.screenshots/gap/gap-34.png`、`gap-46.png`、
  `gap-56.png`、`after-44.png`、`home-after.png`；改前那帧（8px）只留了实测数值，没落盘。
- **没验的**：真机窄屏（≤800px）下的手感没实拍；输入卡长高（多行 / 附件 / 错误卡）时
  `--composer-h` 变化后的尾缝只按算式推过，没逐个造场景量。长高时尾缝恒定，算式本身对。

## 已知边界

- 首页态不吃这条：它整条覆写 `padding-bottom`，本次不动。
- 手机端（lifediary，Kotlin/Compose）是另一套布局，不在本批。
- 尾缝是"最后一条到卡顶边"的净空，不随消息类型（气泡 / 工作卡 / 出错卡）变化。
