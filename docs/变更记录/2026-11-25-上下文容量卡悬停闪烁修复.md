# 2026-11-25 上下文容量卡悬停闪烁修复

## 现象

悬停 composer 右下那枚 16px 的上下文环，弹出的「上下文容量」卡「不稳定、会闪」：

- 从环往卡上移，卡会在指针下面淡出消失（甚至指针已经停在卡里也照样消失）；
- 手轻微抖出环外再回来，卡收起又弹出，来回闪；
- 观感像「每次悬停都在重新拉取、重新画」。

## 原因（2026-11-25 复核）

1. **环与卡之间有 10px 视觉缝，是命中死区。** 环 `pointerleave` 后 140ms 就起收起动画；
   人手慢一点，跨过这 10px 花的时间就超过 140ms，进卡时卡已经在淡出。
2. **卡的 `pointerenter` 只清计时器，不管已经在跑的收起。** `closeCtxCard()` 一旦起跑就
   设 `ctxCardShown=false`，140ms 后 `hidden=true`；此时只 `cancelCtxClose()` 什么也救不回，
   指针停在卡里卡也会消失。
3. **环本体只有 16×24。** 手稍微一歪就离开元素，收起/重开来回切，就是看到的「闪烁」。

**不是每次悬停重新拉取。** 悬停不发请求（CDP Network 记录：悬停 3s 期间只有 `healthz`
与 `approvals` 两条后台轮询，0 条 `/context`）；数据一直是 `syncCtxMeter()` 上一次拉回的
`ctxPayload`，悬停只做重绘，没有「缓存没做」的问题。

## 改了什么

- `web/chat-notice.js`
  - `placeCtxCard()` 写 `data-side`（`above` / `below`），给桥接层决定贴哪条边；
  - 卡的 `pointerenter` 改走 `keepCtxCardOpen()`：取消收起计时；**已经在收起就重新
    `openCtxCard()`**，不让卡在指针下淡出；
  - 收起宽限 140 → 200ms（只是宽限，关掉仍然只多等 60ms）。
- `web/style-05-message-extras.css`
  - `.ctx-ring::before` 命中区外扩（上下 6px / 左右 5px，绝对定位不占布局）；
  - `.ctx-card::before` 11px 透明桥接层吃掉环与卡之间的缝，按 `data-side` 贴在卡的下/上缘。

## 验了什么

CDP 真页面（headless Chrome 1200×760，接 `:39847` 真服务、真会话）：

- 静止悬停稳定，无开合抖动；
- 慢速（40px/s）从环往卡里移、到达后停 0.7s / 1.2s：卡保持可见（修复前同样的动作
  结束时 `hidden=true, opacity=0`）；
- 逐 y 命中检查：环上缘 618 → 卡下缘 608 连续命中 `ctx-ring`/`ctx-card`，中间无死区；
- 离开环/卡 700ms 后正常关闭；点击环钉住后移开保持、再点关闭；Enter 打开 / Escape 关闭；
- 悬停 3s 期间网络只有 `healthz`、`approvals`（确认没有 `/context` 请求）；
- 截图核对卡面渲染正常（桥接层不可见）；
- `node --check web/chat-notice.js`；CSS 花括号配平。
