## 关键机制（实测，2026-11-23）

- **stdout 接匿名管道必挂**：`doubao -p ... | cat` 稳定报
  `internal_error: 无法启动主任务。请稍后重试。`（exit 1）；同一命令 `> file` 正常。
  原生日志真因：`Cannot duplicate CLI output for Worker: overlapped output handles are not supported`
  （Windows 匿名管道不支持重叠句柄）。所以 `runCliProcess` 加 `stdoutFile`，豆包用它。
- 成功时 stdout 只有一行 `{"type":"result",...,"result":{"type":"text","content":"..."},"session_id":"..."}`；
  `[cli-chat]` 进度日志全在 stderr。正文取 `.result.content`，不能用 `parseCliStdout`（会把对象 stringify）。
- `-C` 必须是**第一个参数**；放到 `--permission-mode` 之后会 `invalid_arguments`。
- 权限：`read` → `ask_risky`；`edit` / `full` → `always_allow`。实测 `ask_risky` 下普通写文件
  会直接执行（不是拒绝），豆包没有只读沙箱。
- 模型：`model list` 14 个，默认 `person-deepseek-v4-1-flash-261017`（DeepSeek V4.1 Flash），
  另有 V4 Pro / Kimi K3 / GLM 5.3 / Qwen / Doubao / Auto。id 必须带 `person-` 前缀。

## 没做 / 边界

- 不做只读沙箱：豆包只有 `ask_always / ask_risky / always_allow`，`read` 档只能退到 `ask_risky`，
  普通文件写入仍会执行；界面的 note 已写明。
- 不接 `--service-start` 远程任务服务、不解析 `stream-json`、不做按单选执行器、不做交互式 TUI 桥。
- `run.cjs` 在发现新版本时会读 stdin 问是否更新；当前 2.37.2 为最新，暂不受影响。
  将来若撞上，表现为无输出失败（stdin 为 ignore 时 readline 立即关闭），排障先看 `doubao -v`。
- 全套 `pnpm --filter @lifediary/server test` **1422/1422 通过**；`pnpm typecheck` 通过。
- HTTP 探针（`pnpm --filter @lifediary/server http`）**169 ✓ / 8 ✗**：失败全在「建普通会话 / 归档」
  段（`POST /chat` 400 后连坐 404），属工作树里另一批在途的「普通助手会话退役」，本批没有改
  chat / archive 路由（推断：失败链路与本批文件不相交）。http-probe 本身没有 executor 段，
  执行器链路由单测 + 真机 probe + `runDoubao` 端到端覆盖。
