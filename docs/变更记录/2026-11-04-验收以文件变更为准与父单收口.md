# 验收以文件变更为准、父单收口与两处派单摩擦（2026-11-04）

## 改了什么

- **验收改为文件为准**（chancellor `review.ts` / `scheduler.ts` / `isolation.ts`）
  - 任务声明了 `writes` 时，执行前后对声明路径做工作区快照（具体路径记 sha1，`dir/**` 递归记文件）；
    worktree 模式在合并后再核对项目根。声明路径真实新增/修改即 `pass`，一个都没变则 `fail`，
    原因固定为 `声明了 N 个路径，实际 0 个变更`。
  - `artifacts` 降级为附加校对：清单路径缺失/越界只记 `Review.warnings`，不判失败；读取时仍只读通过安全检查的产物。
  - 保留硬边界：未声明路径写入仍按越权失败，worktree 合并失败仍失败，外部 CLI 的 `ok` 四条件不变。
  - 从磁盘恢复（续跑）的 run 没有前后快照，按项目根现存声明文件兜底，避免旧单被误判为 0 变更。
- **父单收口**（chancellor `stage.ts` / `index.ts`）：父单声称 `done` 时，只要有子单处于
  `failed` / `needs_you`，父单改走 `needs_you`，汇报行点名子单 id 与原因；其余未终态子单仍按 `idle` 等。
- **派单摩擦**（harness `tools.ts` + chancellor `manager/registry.ts`）
  - `delegate` 的 `domain` 描述写明「必须小写 ASCII」，并列出当前已有领域。
  - 非法领域名（含中文）在工具入口直接返回「可用领域：…」，不建单；chancellor 的 `validateDomain`
    也带上可用清单，CLI 路径同样能照着选。
  - 同一 `requestId` 内容不同时不再返回 `request_conflict`，改为返回原任务单并提示
    「该请求号已受理过，返回原单」。

## 验证

- `pnpm typecheck`（chancellor / harness）通过。
- server 测试 108 项全过，新增：
  - 真实 git 临时仓库：worktree 下文件写了 → `pass`，声明了没写 → `fail`；
  - direct 模式执行前后快照识别真实写入；
  - artifacts 缺失不判失败、清单对不上只记 warning；
  - 父单在子单 `failed` / `needs_you` 时强制 `needs_you`；
  - 非法领域名返回可用清单、不建单；同 `requestId` 不同内容返回原单。

## 明确不做 / 仍存在的限制

> 2026-11-04 后续《验收补缝：删除、粗判、崩续跑与中止子单》已补齐下列前两条：
> 删除计入变更；`dir/**` 改为 `mtime+size` 两级筛选并支持粗判；续跑改为读回
> `snapshot-before.json` 做严格对比，不再用现存文件兜底；`aborted` 子单也会拦父单。

- 删除文件不算「完成」：声明路径被删且没有新增/修改时按 0 变更处理。
- `dir/**` 快照会递归读取该目录并计算 sha1，目录很大时有一次 I/O 成本。
- 只读任务（未声明 `writes`）仍走 LLM 核对 REPORT；本次只保证 artifacts 缺失不再直接判失败。
