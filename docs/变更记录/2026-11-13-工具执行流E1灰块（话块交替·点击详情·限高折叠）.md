# 2026-11-13 工具执行流 E1 灰块（话块交替 · 点击详情 · 限高折叠）

## 改了什么

**形状**：一轮回答从原来的「正文 + 一块工作过程面板」改成 **话 → 一组灰块 → 话 → 一组灰块**。
模型说一句、动一次手、再说一句；说出来的话留在正文，动手缩成一枚 24px 小灰块。
主界面不再写"几步/几秒"；步数、耗时、命令、输出、diff 全在点击灰块后的详情里。

- 新增 `web/tool-chips.js`：
  - 灰块渲染：运行中 accent 底 + 底边 1.2s 扫光；完成变灰 + ✓；失败红；已转后台空心边。
  - 点击详情：内联展开（默认）/ 附近小窗（可设置），含命令、用时、改动摘要、输出或 diff。
  - **详情面板限高 260px**，内部滚动；长输出/长 diff 不撑正文。
  - **超过 8 枚先收「+N」**，点开铺全部、可再收起；**运行中的块永远可见**（不被 +N 收走）。
- 新增 `web/tool-meta.js`：工具名 → 图标 / 动词 / 时长文案（从旧工作面板拆出）。
- 重写 `web/tool-flow.js`：`createToolFlow`（现场）/ `toolFlowFromSteps`（历史回读）；
  按"中间夹了说就另起一组"落 DOM，历史也保持同样顺序。
- 删除 `web/work-panel.js`（旧"已工作 Ns · M 步"面板整块退役）。
- `web/composer-send.js`：`send()` 改成 `.flow` + 段模型——每段话一个 `.body`，工具动手时封口当前段、灰块接在后面；连续两次动手留在一组；`foldSpoken` 退役。
- `web/chat-open.js`：历史回读改 `toolFlowFromSteps`（原来调旧 `workPanelFromSteps`）。
- `web/chat-thread.js`：复制按钮改成拼接所有正文段（话/块交替后一轮有多段），不把灰块算进正文。
- `web/chat-notice.js` / `web/app.js`：改从 `tool-meta.js` 取图标常量，去掉 `work-panel.js` 引用。
- 设置 → 外观 新增「工具详情」：`原地展开`（默认）/ `附近小窗`；纯前端 `localStorage: lifediary.toolDetail`，改完下一次点块即生效，不走服务端开关。
- `web/style.css`：删旧 `.wp*` 工作面板样式（约 220 行），加 `.flow` / `.tchips*` / `.tchip*` / `.tdetail*` / `.tchips-pop`。

## 为什么

原型对比后用户拍板 E1：工具是小灰色小块，"走了几步/进行了几秒"解释文字太多，应点开看细节。
批 32 的"中间话折进面板"在 E1 下退役——E1 要的就是话留在正文、工具缩成块的交替阅读。

## 已知边界

- 详情卡里对 `read`/`write` 这类工具显示「参数」（JSON），不假装是 shell 命令；只有行为空的工具才用目标当"命令"占位。
- 灰块分组以"中间有没有说话"为界；模型连续调 20 个工具时会收成「+N」，展开后一行会较高（用户主动展开）。
- `style.css` 仍是单文件（约 7.4k 行）；这轮只做 JS 拆分与 E1，CSS 拆分需要单独做视觉回归，未在本批。
- 旧 `qa/work-panel.check.mjs`（`.wp` 选择器）已删除，换成 `qa/tool-chips.check.mjs`（灰块/详情/限高/回读）。
