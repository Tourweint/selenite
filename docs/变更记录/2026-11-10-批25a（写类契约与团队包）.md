## 二、团队包导出 / 导入（§二）

新增 `ts/apps/server/src/partner-bundle.ts`（核心实现）与 `companion-api.ts` 两个端点：

- `GET /api/v1/partners/:id/bundle`：JSON **附件**（`Content-Disposition`，中文名走 RFC 5987）。
  内容 = 档案（name/domain/status）+ 当前 SOUL + 当前 CONTRACT + 技能（名+正文）
  + 记忆（**只 `preference` + `experience`**，`work` 履历与 rules 不导）+ `safety`。
- `POST /api/v1/partners/import-bundle`：201；**不信包里的 `safety` / `status`**，
  一律落 `paused` + `SAFE_ARRIVAL`；重名 → 400 `duplicate_name` 不覆盖；格式 / 版本 / 名字
  不合法 → 400 `invalid_bundle`；建档后写盘失败回滚档案 → 400 `create_failed`。
- 开关 `PARTNER_BUNDLE` 默认开；`false`/`0` → **两个端点都 404**（能力未启用）。

**双重脱敏（实现细节，值得记一笔）**：第一遍按字段打码；第二遍在 `JSON.stringify` 之后执行，
但**不是直接把整串丢给 `redactSecrets`**——键值规则会把 JSON 的结尾引号当成值的一部分
（`api_key=«redacted»"` → 引号被吃掉），输出就不是合法 JSON。做法是「序列化 → 解回来 →
逐字符串值再打一遍 → 重新序列化」，语义仍是序列化后二次脱敏，附件保证可解析。
单测构造了带 `sk-…` 与 `password=…` 的 SOUL / 技能 / 记忆，断言导出文本里没有原文。

## 已知边界 / 没做

- **领域标签不随包迁移**：它连着 chancellor 的 `managers/<domain>/` 与派活路由，继承等于
  「导入即接单」。导入响应在 `warnings` 里如实说明，确认后由人单独设置。
- **导入落 `paused` 而不是 active**：包里即便写 `status:"active"` 也不采信。这是"到货默认
  安全态"的落点——确认之前不跑回合，技能 / 记忆只是落盘。`safety` 的三项里
  `approvalLevel` 是全局策略（`agent/policy.ts`），导入**不去改全局档位**，只以 paused 达到
  同等以上的保守程度。
- 团队包**不导 routines**、不导 `work`、不导头像与模型链：前两者按任务书，后两者这次没列，
  将来要导得先定"模型链里的 keyEnv 到新机是否还存在"这类问题。
- `partner_skill_write` 的 `empty_summary` 分支实际不可达（`content.trim()` 为空时先被同一
  条件的前半段拦下）；为保持文案与行为不变没有改判定，只在测试里覆盖空内容这一路。
- 端点未进 `WRITE_TOOLS`：它们是**人操作**的 HTTP 端点，不是模型工具，不经工具闸门；
  鉴权沿用整站 `AGENT_TOKEN`。
