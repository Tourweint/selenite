# 通用 worker 配置统一（三批落地）

**日期**：2026-11-16 方案定稿（`docs/设计方案/2026-11-16-通用worker配置统一.md`），2026-11-17 实施；同日追加批 4（见文末）。
**方案**：D1 人设共享 / D2 native 模型可调 / D3 worker 页开关 / D4 native 工具面勾选；本文为落地记录，结论已下沉
系统架构.md **D27**、接口文档主册 env 表（`WORKER_PERSONA_DISPATCH` / `WORKER_TOOLS_PATH` / `WORKER_TOOLS_DISPATCH`）、分册4 §2.11、分册7 §2.23。

## 背景

普通助手会话（chatKind=worker）与派活的 native / 外部 CLI worker 是两条线各自长出来的：
前者有完整 harness（人设 / 记忆 / 全量工具），后者 0 个可设置字段（模型=启动 env、人设=写死
WORKER_RULES、工具=写死 4 个）。用户拍板「这俩其实就是一个东西，必要限制就一个项目名」。
另：native 执行器卡片此前声称「模型由设置→模型主选决定」与实现不符（worker-main 只读启动 env），
2026-11-16 已先行改为如实口径（见 `2026-11-16-native执行器模型口径修正.md`）。

## 批 1：native 模型框

- `executor-config.ts`：`executorForDelegation` 撤掉 native 特例（不再硬回 `{}`），native 与
  其它档同走 profile 通道；native 卡 `modelHint` / `note` 改为「留空跟随启动 env」语义。
- `web/settings-executor.js`：native 卡渲染模型输入框（无清单下拉、无「检测」按钮——刻意没有）；
  保存循环不再跳过 native。
- chancellor `employee/native.ts`：新增纯函数 `childEnvWithModel`——建单快照 `settings.model`
  非空时 spawn env 覆盖 `CHANCELLOR_LLM_MODEL`（worker-main 的读取优先级本来就是它最高），
  留空 / 未传 / 空白串一律不覆盖（= 今天之前的行为）。
- 测试：`executor-config.test.ts` 补「填了 进建单快照 / 留空 不带」两态。

## 批 2：人设共享（派活工人同吃 `.data/worker-persona.md`）

- chancellor 新模块 `worker-persona-source.ts`：`setWorkerPersonaSource` 注入口 +
  `workerPersonaText()`（未注入 / 抛错 / 空串 → 空串），依赖方向 server 推、chancellor 收
  （`setInternalAsk` 同款先例，chancellor 不读宿主文件）。
- chancellor `worker-prompt.ts`：`buildWorkerPrompt` 在身份行之后、任务段之前插入
  「## 你是谁」段（含「冲突以任务要求为准」尾注）；TASK.md 是 native 与外部 CLI 的共同唯一
  上下文，一个位置覆盖两边。
- server `worker-persona.ts`：默认正文拆层——文件里只存身份与作风（**新增**「做不到、做不完或
  做偏了就如实说，不硬凑结果，更不谎报完成」一句，用户口径"肯定要加上一些东西"）；
  remember / recall / set_reminder 工具提示改为 `WORKER_PERSONA_CHAT_TOOLS` 代码常量，
  由 `lifecycle-injections.ts` 的 persona provider 只在 chatKind=worker 会话拼接
  （派活工人没有这三件工具）。⚠️ 默认文案变更 = worker 会话打掉一次上游缓存前缀。
- server `index.ts`：启动时 `installWorkerPersonaDispatch()`（紧随 `installInternalAsk`），
  把惰性来源推给 chancellor；`WORKER_PERSONA_DISPATCH=false/0/off` 回滚到无身份 TASK.md。
- 测试：server `worker-persona.test.ts` 补拆层 / 开关 / 装配三态；chancellor
  `worker-persona-source.test.ts`（新文件，进 npm test 清单）钉 TASK.md 三态 + env 覆盖。

## 批 3：派活带项目记忆进界面

- `plugins.json`：`DELEGATION_PROJECT_MEMORY` 登记为 core 插件（autonomy 组，
  `requires: ["CHANCELLOR_ENABLED"]`，hot）。消费处 `delegationProjectMemoryEnabled()` 读
  process.env 不变——core 开关的 setFlag / 启动装载本来就同步 env，零消费代码改动。
- `web/worker-profile.js`：普通助手页新增「派活」区，开关 = 同一颗 `DELEGATION_PROJECT_MEMORY`
  （GET/PUT `/api/v1/agent/flags`）；父闸关 → 显示关、拨不动（存储值保留）；插件页关闭
  （`AGENT_FLAGS_UI=false`）→ 整段隐藏走 env。页面同步新默认文案 + 说明更新
  （会话与派活工人共用；Worker 不绑项目，项目在派单时指定）。
- 测试：`flags.test.ts` 两处计数 / core 清单更新（40→41、加 `DELEGATION_PROJECT_MEMORY`）。

## 批 4：native 工具面可勾选（2026-11-17 用户追加）

**用户口径**：worker 能用的工具也让用户勾；只做本机的，外部 CLI 不碰（"人家自己带记忆，
把任务发好就行"）。原方案「明确不做：工具勾选」就此翻案，per-dispatch 指定工具仍不做（见下）。

**改了什么**：

- chancellor 新模块 `worker-tools-source.ts`：canonical 四件（`WORKER_TOOL_NAMES`）搬到这里
  （worker-main 引用，测试不再 import 会跑 main 的 worker-main）；
  `effectiveWorkerTools()` 纯函数收敛宿主名单（只认四件、去重、保序、空集如实为零）；
  `setWorkerToolsSource` 注入口 + `workerToolsArgValue()`（null = 不传参数 = 全开）。
- chancellor `worker-main.ts`：parseArgs 加 `--tools`（逗号分隔）；**undefined 与空串分开**——
  没传 = 全开（旧行为逐字一致），传了（哪怕空串 / 全乱值）= 交集跑，筛空就是真零工具；
  启动日志从"注册清单"改为"实际下发清单"（隔离验收证据更真）。
- chancellor `employee/native.ts`：spawn 前 `workerToolsArgValue()`，非 null 追加
  `--tools <值>`（与既有 `--dir` / `--work-dir` 同路）。
- server 新模块 `worker-tools.ts`：`.data/worker-tools.json` 存取消名单（照抄执事语义：
  存关掉的，未来加新工具默认可见）；目录 = canonical 四件 + 中文名（server 不新增工具）；
  GET/PUT `/api/v1/agent/worker-tools`（未知工具 400 带 `unknown` 名单，坏 JSON 回落全开不卡派活）；
  `installWorkerToolsDispatch()` 启动装配（index.ts，紧随人设装配），每张单现读文件，
  `WORKER_TOOLS_DISPATCH=false` 回滚全开。
- web `worker-profile.js`：普通助手页新增「能用的工具」区（借执事工具勾选样式：行 + 开关 +
  悬停边界说明），右上角小字显示「实际下发：…」；一件不剩时给诚实警告（工人交不出 REPORT.md）；
  改完下一次派活生效。

**刻意没有（per-dispatch 指定工具）**：总管/执事派单时按单指定工人工具，不做。理由：
派活方很少比全局默认更懂该关哪件，delegate 契约加参数收益低、审批边界交互复杂；真要做时
口子已留好——`EmployeeProfile` 快照本就全量下发到雇员、native spawn 已参数化，届时在
`EmployeeProfile.tools` 加一列传下去即可（记入 D27，需单独立项过审批评估）。

**顺手修**：`worker-tools` 端点初版 PUT 写死 `process.env` 路径，单测跑了真 .data——
改为 env 注入并清掉误写文件（本地开发库，无生产影响）。

**验证**：chancellor `npm test` 30/30（含新 4 条）；server worker-tools 6/6；双仓 typecheck 过；
`pnpm --filter @lifediary/server http` 425 项全绿。未跑 `pnpm probe`（内核链路零改动）。
