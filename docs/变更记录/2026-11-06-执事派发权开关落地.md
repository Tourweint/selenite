# 2026-11-06 执事派发权开关落地（按执事独立·默认关）

方案：`docs/设计方案/2026-11-06-执事派发权开关（按执事独立·默认关）.md`。取舍与「明确不做」见方案，此处只记做了什么。

## 改了什么

- **存储**：`partners` 表新列 `dispatch_authority INTEGER NOT NULL DEFAULT 0`（PRAGMA+ALTER 旧库补列，旧记录读为 false）；`PartnerRow.dispatchAuthority: boolean`；新 `setDispatchAuthority(id, enabled)`。
- **闸门**：纯函数 `ministerDispatchAllowed(store, domain)` + 总闸 `ministerDispatchMasterEnabled()`（`MINISTER_DISPATCH_AUTHORITY`，默认开，明确 `false`/`0` 才关）落在 `partners.ts`；`tools.ts` 的 `localIdentityHit` 先过闸再查身份——关着时不注入 `managerIdentity`，chancellor 总管直派，**不拒单**（语义理由见方案 §决策1）。
- **契约**：shared `PartnerProfileSchema` 增可选 `dispatchAuthority: boolean`（只对带 domain 的执事投影）；`PATCH /api/v1/partners/:id` 接受 `dispatchAuthority`（普通执事 400）；`partner_manage` 工具增 `set_dispatch` action（核心 `setMinisterDispatchAuthority` 与端点共用）；`listMinisterPartners` 投影增字段（list 行尾多「· 派发权开/关」）。
- **界面**：侧栏花名册带 domain 的执事行加小拨杆 pill（派·开/派·关），点击 PATCH 切换、失败原地提示；样式用 `--ok/--muted` 令牌。
- **文档**：接口文档 §2.11 执事段 + §6 env 表；设计方案文首已标「已落地」。
