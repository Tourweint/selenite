# 人设页精简：四段变三段、解释句退场、字段标清「进不进提示词」

用户原话：

- "点击改人设进入这一页，真是相当乱，非常乱。你先看看怎么精简，去掉解释性文字。"
- "不同字段最后注入的是文字，但说的文字还是要确保规格清楚，比如我的同事有哪些接口、我的员工有哪些接口。"
- "他的记忆从整个记忆模块看就行。"

这一轮只动人设详情页的**视图与文案**，不改字段语义、不改接口、不删数据。

## 结论

1. 页面从「人设 / 岗位 / 能力 / 档案」四段改为**三段**：人设、岗位、能力。档案整段撤掉，履历与记忆统一去 `设置 → 记忆` 看。
2. 页面从「四段全展开」改为**只展开主线**：岗位契约、备选模型、例行任务、技能默认收起；摘要行只留「是什么 + 几条」。
3. 解释性长句全部删掉；只在三个真正进提示词的地方留了 4–5 字标记：`每轮进提示词`。领域留 `只用于派单`。
4. 每段常驻的「没有改动 / 撤销 / 保存」改成**有改动才出现**；身份与契约各一套，不再每段各摆一条。
5. 口头禅从这一页撤掉（数据库字段与接口都没动）。它不进任何提示词，页面也没有第二个消费点，留着只会让人误以为它会影响说话。

## 字段 → 提示词 → 接口

这张表就是用户要的"规格"。以 `agent/partner-context.ts` 的 `buildPartnerTurnContext()` 为准，不按字段名猜。

| 页面字段 | 存在哪 | 进不进提示词 | 走哪个接口 |
|---|---|---|---|
| 名字 | `partners.name` | 单执事轮**不进**；群聊里会以「你是『名字』」出现 | `PATCH /api/v1/partners/:id` |
| 领域 | `partners.domain` | **不进**；只用于派单路由/筛选 | `PATCH /api/v1/partners/:id` |
| 头像 | `partners.avatar` | **不进**；纯界面 | `PATCH /api/v1/partners/:id` |
| 正文 | `soul` / `soulSource` | **每轮进**，放在 instructions | `PATCH /api/v1/partners/:id { soul }` |
| 岗位契约 | `contract` / 版本快照 | **每轮进**，渲染成 `【岗位契约】…` 段 | `PUT /api/v1/partners/:id/contract` |
| 当前目标 | `currentGoal` | **每轮进**，渲染成 `【当前目标】…` 一行 | `PATCH /api/v1/partners/:id { currentGoal }` |
| 接派单 / 日记执事 | `dispatchAuthority` / `diary` | **不进**；行为开关 | `PATCH /api/v1/partners/:id` |
| 备选模型 | `modelChain` | **不进**；只在主模型失败时按链换 | `PATCH /api/v1/partners/:id { modelChain }` |
| 例行任务 | routines 表 | **不进**；按触发器单独起轮 | `GET /api/v1/routines?partnerId=…`、`POST /api/v1/routines` |
| 技能 | 家目录技能文件 | **不进**；供试跑/例行读取 | `GET /api/v1/partners/:id/skills` |
| 口头禅 | `partners.tagline` | **不进**；服务端只存储/投影，前端无消费点 | 页面已撤；DB 字段保留，接口仍收 |

真正作为"人设文字"每轮注入的只有三样：**正文、岗位契约、当前目标**。名字、领域、口头禅、开关、模型链都不是。

## "同事"和"员工"到底是不是两套接口

不是。数据模型里只有一个实体 `partners`，没有第二套"员工 API"。

| 叫法 | 是什么 | 读写面 |
|---|---|---|
| 同事 / 执事 / 总管 | 同一个 `partners` 实体，区别只是 `partner:<id>` / `global` 记忆 scope、总管或执事身份 | 人设页：`GET/PATCH /api/v1/partners/:id`、`PUT /:id/contract`、`GET /routines?partnerId=`、`GET /:id/skills` |
| 员工档案（旧视图） | 2026-11-14 晚已拆：工作履历进记忆页，记忆本来就在记忆页，例行/技能在人设页能力里 | 只读：`GET /api/v1/agent/memory?scope=partner:<id>`、`GET /routines?partnerId=`、`GET /:id/skills`；不写 |

所以不存在"我的同事有哪些接口、我的员工有哪些接口"两组不同端点；是**同一组端点，两个视图**。人设页负责写，记忆页负责看；旧员工档案视图不再挂入口。

## 改了什么

### 1. 撤掉「档案」整段

- 删除工作履历 / 记忆条数 / 最近一条，以及"履历是结算过的单子…"那句。
- 删除 `pfLoadArchive()` 与 `csLoadProfileMemory` import；人设页不再请求 `agent/memory`。
- 记忆统一去 `设置 → 记忆`：那里已经有一排人、按 scope 查看、整理入口，是唯一真相。

### 2. 四段变三段，长块默认收起

- 人设：名字 + 领域一行，正文一张卡。
- 岗位：岗位契约（折叠，摘要带版本）/ 当前目标 / 两枚开关。
- 能力：备选模型 / 例行任务 / 技能三行折叠，摘要只写条数。
- 折叠条共用一套 `details > summary` 样式，箭头、行高、分隔线与"新建例行任务"一致。

### 3. 保存栏按需出现

- 身份卡：没有 dirty 时整条 `没有改动 / 撤销 / 保存` 不显示；改动后出现，保存成功再消失。
- 契约卡同理。
- 目标只有一个输入 + 一个保存按钮，保持常驻（它本身就是一行操作，不值得再藏）。

### 4. 解释性文字删减

删掉：

- `契约与目标改完，下一轮起用` → 留 `下一轮起用` 四个字
- `关掉后派单不经过它，等同没有分管领域`
- `总管本身不接派单，这里没有开关`
- `开了它接「今天」类的话；同一时间只有一个执事能开`
- `主模型那一轮没应答、且原因可切…` 整段
- `还没有备选。主模型失败时直接报错，不会自动换。` → `还没有备选。`
- `还没有例行任务，用下面的表单加一条。` → `还没有例行任务`
- `还没有技能文件。技能是家目录里的一本本手册…` → `还没有技能`
- `留空保存 = 清除目标` → 收进 placeholder `留空 = 清除`
- `试跑与例行里才用得上` 段落注脚

### 5. 字段标记

- 正文、岗位契约、当前目标：`每轮进提示词`
- 领域：`只用于派单`
- 名字不加标记：它是页面标题与群聊称呼，单执事轮不注入；领域已经用一句话说明了"不进"，名字再挂一个"界面用"会变成新的噪声。

### 6. 口头禅撤出页面

`tagline` 仍是 `partners` 的字段，`PATCH` 仍接收；只是这一页不再渲染输入框。已存的值不会丢，后续如果决定把它注入提示词，再加回来。
