## 2. 思考强度档位（契约改动）

- 快/深两档 → **off / low / medium / high**（shared 新增 `ThinkingLevelSchema`）；真实请求映射：`off → enable_thinking:false`（原状），`low/medium/high → reasoning_effort:<档>`；派生变体 `#think-<档>`，旧 `#think-on/#think-off` 读兼容（=high/off）。
- providers.json 供应商可选 `modelThinkingLevels: Record<modelId, tiers>`（缺省 `["off","low","high"]`；**medium 声明制**——glm-5.3 对 medium 实测 400）。`/mode` 收 `{thinking}`、旧 `{mode}` 兼容映射；`X-Mode` 四值 + 别名、越界按支持域落回；D3 目标档 `AGENT_THINK_TOOL_LEVEL=low`；换模型时档位越界自动落回 ≤ 当前档的最高档（off 兜底）。
- `GET /agent/model` 的 `models` 行升级为 `{id, thinkingLevels}`；`POST /agent/model` 响应保持扁平（旧字段兼容）。
- 契约回写：`接口文档.md` §2.4.1 重写 + `/mode` 首次登记、§2.8 模型目录新形状、§6 env 表（`AGENT_THINK_TOOL_LEVEL`）、JEV 行档位映射。

## 4. 已知边界 / 行为变化（刻意登记）

- 当前思考档 UI 以 localStorage 为准（契约无"当前档查询"端点）；跨设备改档本机不感知，下次本机切换覆盖。
- 模型菜单里**非当前行**点档位 = 「切模型 + 落档」两次请求（/mode 只作用于当前会话模型）。
- 显式 `/mode off` 现在会真正关回思考（旧实现 D3 切过后 fast 被忽略）——与 §2.4.1 优先级表一致，属修正。
- `AGENT_THINK_TOOL_LEVEL=off` = 关闭自动升档（不切），而非切到 off 变体。
- 换模型档位回退分支无独立探针覆盖（现有探针模型都是缺省支持域），由类型与代码路径保证。
- `modelThinkingLevels` 暂只能手改 providers.json；设置 API 不收该字段（添加模型页任务 C 的候选增强）。
