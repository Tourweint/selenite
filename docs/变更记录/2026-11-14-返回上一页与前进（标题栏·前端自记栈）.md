# 返回上一页 / 前进（标题栏·前端自记栈）

用户原话：「我们还需要在上面实现回到上一页的功能，或者回到上一页后点击下一页。」
（"在上面"＝窗口顶栏；"把它放在哪里" 由实现方定，本记录写的就是落点与理由。）

## 结论

标题栏品牌右侧多了一对**浏览器同款的「‹ 返回上一页 / › 前进」**，
位置、图形、语义都跟浏览器一致：栈自己记、退回去还能再前进。
两枚都不可用时**整组 hidden**——首屏（刚打开、一步没走过）跟改动前逐像素一致，
不白占标题栏一个位。

| 项 | 结论 |
|---|---|
| 落点 | 顶栏左侧，`Selenite` 右边、侧栏开关左边（浏览器的位置感） |
| 触发 | 点按钮；`Alt+←` / `Alt+→` |
| 栈 | 前端自记（`web/nav-history.js`），不依赖 `history.back()` |
| 显隐 | 有历史才出现；不可用的那一枚留原位、变灰、不接指针 |
| 提示 | 悬停直接说去处：`返回上一页 · 设置 (Alt+←)` |

## 为什么要有这一层

界面上每跨一页（对话 ↔ 设置 ↔ 搜索 ↔ 任务中心 ↔ 群组 ↔ 人设页…）都是一次
`location.hash` 跳转，但**壳（MyGo 的 webview）里没有浏览器的后退按钮，也没有工具栏**——
进了整页就只剩「再点一次侧栏」这一条回头路。而页面上原有的那几枚返回是**写死上一级**的，
不是真的上一页：

- 搜索页「返回」→ 永远回对话；
- 任务单「返回」→ 永远回看板；
- 人设详情「返回」→ 永远回人设列表。

从会话设置抽屉里跳到 `#/settings/partners/<id>` 时，那枚按钮回的是列表，不是你刚才的对话。
所以这次不是给某一页补一枚返回，而是补**一条真正的访问栈**，所有整页共用。

## 语义（与浏览器对齐，不给按钮许空诺）

- **栈顶 = 现在这页**；每次真实 hash 变化压一条（`#/` 也算合法一项）。
- **返回** = 栈顶挪进前进栈；**前进** = 挪回来。
- **任何新导航清空前进栈**：退回去再点别的，「前进」就没了。用户说的「回到上一页后点击下一页」
  走的就是这两步：退回去 → 点旁边的页（新的下一步）／点 › 回到刚才那页。
- **同一地址不重复压栈**：换会话不换 hash（`#/`），那不叫换页，不该多一条。
- 深度上限 40 条，超了从栈底丢（防长久开着越攒越长）。

**刻意不用 `history.back()`**：webview 的历史里掺着 `replaceState`（任务筛选、工单详情都走它）
与外部跳转，退到哪儿不可控，按钮上没法承诺「上一页」。自己拿栈，才能每次都给出确定的那一页。

**刻意不记**：滚动位置、表单草稿、抽屉开关。这些是各页自己的事，不该由导航层假装保管。

## 与既有机制的关系

- 路由本身**没动**：仍是 `location.hash` → `net.js` 的 hashchange → `applyRoute()`。
  新模块只旁听同一批 hashchange，不碰 `state.selfNavHash` / `routeGen` / `navToken`。
- 我们自己写 hash 时置一个 `pending` 哨兵，那次 hashchange 认领掉不压栈；其余一律算新导航。
  （哨兵用 `null` 判有/无，因为对话页的 hash 就是空串，空串也是合法目标。）
- 页面上原有的返回按钮**全部保留**：它们是"就地回上一级"，语义不同，不去合并。

## 验证（2026-11-14，真浏览器 · 1280×960 · 真 click / 真 keydown）

`node --check`（复制成 `.mjs`）三个改动文件全过；全程 `console_messages()` 为空。

| 场景 | 结果 |
|---|---|
| 首屏（`#/`，一步没走） | 整组 hidden、两枚 disabled —— 与改动前一致 |
| 对话 → 搜索 | 返回出现，提示「返回上一页 · 对话」 |
| 点返回 | 回 `#/`，返回变灰、前进亮起，提示「前进 · 搜索」 |
| 点前进 | 回 `#/search` |
| 对话 → 设置 → 人设列表 → 人设详情（`#/settings/partners/chief`） | 逐级压栈 |
| 详情页连点两次返回 | 列表 → 设置，每步提示各自对得上（人设页 / 设置 / 对话） |
| 再连点两次前进 | 一路回到详情页 |
| 退回列表后改点「记忆」分区 | 前进栈**清空**（› 立刻变灰）——浏览器同语义 |

| 设置页左上「返回」→ 对话 | 也算一步，返回能回到 `#/settings/memory` |

## 回滚

`?nav=off`，或 `localStorage.setItem("lifediary.navBack","off")` —— 那两枚钮不渲染，其余行为与改动前完全一致。

## 没验证 / 要注意

1. **没在 MyGo 壳里实跑**（本轮只在浏览器里点）。壳里 `Alt+←/→` 会不会先被 WebView2 当成自己的
   前进后退，没验；鼠标点这两枚是一定通的（都已标 `-webkit-app-region: no-drag`，不会被拖拽区吞掉）。
2. **手机端网页没实拍**（中继过来的同一套页面也有这两枚钮，理论上更该有——手机上更没处退）。
3. 任务单详情、做工单筛选走的是 `replaceState`（不产生 hashchange），所以**不开新栈项**；
   那一页的「返回看板」仍由它自己的按钮负责，返回键退的是"进任务中心之前"那一页。
4. 顺手发现一个**老问题（本轮没改）**：侧栏底部那枚「设置」齿轮被"已连接"状态块压住了交互点
   （1280 宽下 `BU_TARGET_OBSCURED`，点不进去），本轮验证是用 DOM 点击绕过的。
   它跟返回功能无关，按"不做与本需求无关的重构"留着，要修单独立一条。
