# 首页问候语：句池 2→6、选句由轮换改洗牌

**日期**：2026-11-18。
**范围**：纯前端（`web/shell.js` 一处）；不碰契约、不碰服务端。刷新页面即生效（静态 JS 直接吃磁盘文件，浏览器缓存可能要 Ctrl+F5）。

## 问题（2026-11-18 用户反馈）

每段只有两句，见几天就腻了；希望「每个时间点都丰富一点」，多备几句、
有随机感地挑。另点名：`这么晚还没睡。` 的句号是文案的一部分，改的时候不能丢。

## 改了什么

- **句池**：四段各 2 句 → 各 6 句，旧句全保留。句式混着来（问句 / 陈述 / 观察 / 邀请），
  文案口径不变：短、第一人称、不催不迎、不提模型和功能；句尾标点照原样写。
- **选句**：原来 `(天序号 + 段序号) % 2` 的固定轮换，改成**按段做种子的固定洗牌顺序
  （FNV-1a 散列，不用 Math.random）**，日子在洗好的句序里往前走、一轮 6 天用完重来：
  - 跨天像随机换句，且洗牌保证一轮之内句句不重、不会连着两天撞同一句；
  - 同一天同一段里刷新、重开仍是同一句——2026-11-07 定下的「不随刷新跳变」底线没动，
    随机感来自句序是乱序，不是来自每次加载现抽。
- 段边界不动：05–10 早 / 10–18 白天 / 18–23 晚 / 23–05 夜（凌晨归夜）。
- 注释同步改写：句池丰富与洗牌的缘由、标点是文案一部分这条口径写进块注释。

## 没做什么

- 手机端 `ChatScreen.kt` 的 `?: "说吧，我在。"` 是总管 tagline 的兜底静态文案，跟时间段无关，
  不属于这套机制，不动。
- `index.html` 里 `#empty-greet` 的初始文案（JS 接管前的占位）不动。

## 验了什么

- `node --check` 过。
- 从 `shell.js` 切出**真实源码段**在 node 里跑 26 项断言全过：每段 6 句且句尾带标点、
  「这么晚还没睡。」原样在池、10 个段边界小时全对、段内刷新/重开同一句、
  连续 60 天逐段无相邻重句且一轮 6 天全覆盖、同日跨段换句。
- 没跑浏览器：逻辑层已用真实源码验证，渲染入口（`syncGreeting`）没动。
