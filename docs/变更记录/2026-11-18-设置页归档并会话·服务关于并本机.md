# 变更记录：2026-11-18 设置页归档并入会话、服务+关于并入本机

> 范围：纯前端 `ts/apps/server/web/`（settings-base / route / settings-router / app / settings-projects / topic-proposal）。零契约、零服务端改动。上接 2026-11-17「四分区合并为 Agent」（左栏 17→14），本批 14→**11**。

## 为什么

用户拍板继续合并（上一批的候选清单）：
- **归档 → 会话**：归档本质是会话的视图，会话页本来就挂着「打开归档」入口；
- **连接 + 服务 + 关于 → 本机**：配对/中继/设备、通知/鉴权、Node 运行时、版本，说的都是「这台电脑这件事」。

## 改了什么

- 左栏分区表删 `archive` / `service` / `about` 三项；`connect` 改名**「本机」**（Lucide monitor 图标，id 保留 connect——连接页两个轮询守卫与旧书签零改动）。
- **会话页** = 行为设置（搜索 / 回车 / 导出 → 权限 → 上下文压缩）+ 归档组（自动归档 → 已归档的会话 → 已归档的项目目录），归档两节的标记与接线原样从 archive 分支搬来；删掉「归档的会话」跳转行（归档已在同页，入口冗余）。
- **本机页** = 连接状态 → 本地连接 → 远程连接 → 已连接的设备 → 服务（通知/鉴权）→ 运行时 → 关于，一页竖排不挂 tab（连接是操作顺序流，服务/关于只是几张小卡）；服务三节用 `insertAdjacentHTML` 追加在连接 DOM 之后（监听已挂，追加不打扰）。
- **别名账收口**：新增 `SETTINGS_ALIASES`（settings-base.js 导出）= `{ sessions→chats, avatars→agent, archive→chats, service→connect, about→connect }`，`currentSettingsPage()` 与 app.js 深链合法性检查共用这一份，不再各写各的 if。
- `settings-projects.js` 四处 `currentSettingsPage()==="archive"` 改认 `"chats"`（项目归档/删除/合并后刷新归档列表的守卫）；`topic-proposal.js` 的「去设置里配搜索」跳转 `service`→`connect`。
- `renderSettings` 删掉兜底 else（原「未知页显示关于」）——关于已并入本机，且 `currentSettingsPage()` 只会返回有分支的 id（未知 hash 落「外观」）。

## 刻意不做

- 不给会话页挂「设置/归档」tab：归档列表默认按项目折叠、体量不大，竖排一页比再来一套 tab 便宜。
- 服务页 2026-11-13 退役的两行（地址、累计 token）不借合并复活：地址在连接状态链路图里，token 在「用量」页。
- 不把权限/压缩挪去 Agent 分区：它们跟回车发送一样是"这条会话怎么表现"，留在会话页；Agent 分区四个 tab 已经够满。
