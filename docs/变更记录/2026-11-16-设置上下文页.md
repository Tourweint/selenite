# 设置新增「上下文」页（2026-11-16）

## 改了什么

设置页在「会话」之后、「项目」之前新增一个独立分区「上下文」（id `context`，图标 `layers-3`）。
一页只做一件事：**看当前会话每轮开头真正进入的固定前缀**，方便看、学习、调整；不做请求历史，
不学 magpie 的「只保留最近十条」。

### 页面

- 顶部一张总览：固定前缀总字符数 + `系统 N 段 · 工具 N 个 · 技能 N 个 · 记忆 N 条/待下一轮`，
  四段 `--ctx-seg-*` 分段条与图例，右上真实 `used / window token · %`，底部缓存提示。
- 四张可展开卡：
  - 系统提示词：系统底稿 + 各 section，带固定 / 每轮现算徽标与字符数，点开 `<pre>` 原文；
  - 工具定义：名称 / 说明 / 字符数，点开 pretty JSON Schema，带筛选与展开全部；
  - 技能：索引原文、按会话冻结徽标、管理技能入口；
  - 记忆：预算、上次注入时间、本轮召回实文、按本轮消息临时插入徽标、管理记忆入口。
- 最后一张「会变的部分」：三格只报对话消息 / 工具调用 / 工具结果的条数与字符；不展开正文。
- 空会话不做「0 段 · 0 个」四连击：总览显示「— / 这个会话还没有可读的上下文」，
  四个固定块整段隐藏，只留一句「先发一条消息，下一次打开这里就能看到这一轮固定前缀」。
- 窄屏只做基本不溢出；手机端页面明确不做。

## 为什么

用户口径：magpie 的 Usage → Context 页把一次请求的上下文分段展示、点开能读原文，这个形状值得学；
但 magpie 只保留最近十条请求，**咱们不是**。我们只要「每轮固定进入」的四块——系统提示词、工具定义、
技能、记忆——会变的部分单独一块，只提示/报数量，不展开正文。

三条实现判断：

1. **记忆不能为了预览重跑召回**：`recall()` 会回写 `lastRecalledAt` / `usageCount`，等于打开设置页就改记忆账本。
   所以只在 `beforeRequest` 首轮把实际注入的 `{id,text}` 记在进程内，读端点只读记录。
2. **系统提示词 / 工具 / 技能不能另算一份**：从 `ContextView` 重放当前真正会发出去的那份，避免「展示口径」与
   「请求口径」两套漂移；工具描述与顺序是缓存前缀资产，本次一条未改。
3. **不做历史**：一页 = 一个会话的当前装配，不做时间线、不做最近 N 条；这样页面回答的是「现在这一轮开头有什么」，
   而不是「过去发过什么」。

## 还有哪些不确定 / 未做

- **活服务当前没有普通会话**：`.data/agent.sqlite` 里 `conversations=74`、`entries=0`，`/agent/chats` 返回空列表；
  所以 39847 的上下文页当前只能看到空态。隔离实例里造了一轮测试对话才验证到完整页面。若用户打开活服务仍空，

- **记忆重启后显示「待下一轮」**：进程内记录不落盘；重启后第一次打开页面，记忆块显示
  「当前进程还没跑过这个会话的一轮请求」。这是不重跑召回的安全代价，不是 bug。

  如果用户希望它和系统提示词一样标成「固定」，需要再拍板。
- **物理顺序未画顺序条**：真实请求里临时 system 注入压在主 system prompt 之前；页面说明了来源，但没有画
  「临时注入 → 系统前缀 → 对话 / 工具结果」的顺序条，等用户看过再决定要不要加。
- **工具数量多时的分组**：当前 21 个工具整列 + 筛选 + 展开全部；若真实会话工具更多，可再考虑分组/默认折叠。

## 再追加：页面改按 token 估算，`used` 改成完整 prompt tokens（2026-11-16 同日）

用户原话：“**咱们这个工具调用的字数是不是太多了？然后这个页面咱们应该按 token 算吧，而不是按照我几个字几个字的算。**”
先核数再改：工具定义的 16,163 字不是算错，是紧凑 JSON 的真实长度（22 个工具逐项相加正好 16,163，没有重复计数）；
按 cl100k 实测同一份内容的 token：系统 865 / 工具 8,337 / 技能 682，**字符和 token 的换算比例差很多**
（中文 ≈0.85 token/字，工具 JSON ≈0.52 token/字），所以字符数看起来比真实成本吓人。

### 服务端

- 新增 `ts/apps/server/src/token-estimate.ts`：`estimateTokens(text)` = CJK 1 token/字 + 其它 1 token/4 字符，向上取整。
  2026-11-16 对 cl100k 校准：中文段 -14%、紧凑工具 JSON -5%、英文技能索引 +8%、合计 -5%。
  不用内核 `estimateTextTokens`（chars / 3.5）：中文低报约 2/3；不接真 tokenizer：模型来自多家，词表只对其中一家准。
- `context-inspect.ts`：`ContextSectionView` / `ContextToolView` / `ContextCountView` 全加 `tokens`，
  `system` / `tools` / `skills` / `memory.last` / `memory.last.others` / `changing` 各层同层增加；
  `chars` 全部保留（纯增量，页面不再主显）。工具 token 按**紧凑 JSON**（与请求同一条）估，不按 pretty schema。
- `agent/session-transcript.ts`：`contextUsageOf` 的 `used` 从 `usage.input` 改成
  `input + cacheRead + cacheWrite`。pi-ai 的 `input` 是未命中缓存的输入（OpenAI 系 = prompt - cached - write，
  Anthropic 的 `input_tokens` 也不含 cache），原实现命中缓存时低报、全命中时 `used=0` 整块 ring 直接消失；
  改后 `/context` 两个消费方（composer ring / 容量卡、设置页）都拿到完整 prompt token。
  `TurnUsage`（SSE 契约）不变，本地读数单独带 `cacheWrite`。
