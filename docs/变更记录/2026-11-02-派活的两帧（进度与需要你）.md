# 派活的两帧：进度与「需要你」

- 日期：2026-11-02
- 范围：`src/delegation.ts`（新）、`src/tools.ts`、`src/agent.ts`、`src/openai-compat.ts`、
  `src/index.ts`、`scripts/delegate-chain-probe.ts`
- 依据：`lifediary/docs/设计方案/2026-11-02-派活的体验设计.md`

## 背景

`delegate` 装上之后，主 agent 派活那几分钟里客户端是**死的**——只有一个 `working` 阶段，
说不出"第几件 / 共几件 / 在干什么"。用户看到的是空白。

同时，worker 卡住要人回答时，harness 只回一句结论。客户端只能从这句话里**猜**它在等什么，
没法出「需要你」的卡片。

## 决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 事件通道单独一个模块 `delegation.ts` | 发事件的是 `tools.ts`、收事件的是 `agent.ts`，两者本来就互相引用，塞进任何一边都会成环 |
| 2 | 不复用 `phaseSinks` | 那个通道只有"在想/在动手"两个值，表达不了「1/2 · rewrite-s1」和「它在等你回答什么」 |
| 3 | 走兼容层的非标准字段（`lifediary_delegate` / `lifediary_attention`） | App 走的是 OpenAI 兼容层，不是自有 SSE。跟 `lifediary_progress` 同一个做法，客户端解析器忽略未知字段 |
| 4 | 自有 SSE 端点**不加**新事件 | 沿用 2026-10-29 的决定：不加新事件避免破坏老客户端。App 不需要它 |
| 5 | `attention` 只在**有具体问题**时发 | worker 报 `blocked` 但没写 `attention` 时不发帧——那说明它自己也没想清要什么，出卡片也是废卡 |

### 为什么进度帧要带 `current`

只给 `1/2` 的话，用户只知道进度不知道在办什么。带上 `current`（任务 slug）才能显示
「正在办 · 1/2 · rewrite-s1-to-final1」。这是"不占注意力"的前提——**一句话说清，比三条消息有用**。

## 改了什么

- `src/delegation.ts`（新）：`DelegationEvent` 两种（进度 / 需要人）、`watchDelegation` / `emitDelegation`
- `src/tools.ts`：`delegate` 工具接 `onEvent`，把 chancellor 的 `planned`/`task-start`/`task-done`/`reviewing`
  翻译成进度帧；返回后若有 `attention` 再发一条
- `src/agent.ts`：`ChatStreamEvent` 加 `delegate` / `attention` 两种；`chatStream` 订阅并 yield
- `src/openai-compat.ts`：流式映射成 `lifediary_delegate` / `lifediary_attention`；非流式跳过这两类
- `src/index.ts`：自有 SSE 跳过这两类（同 `progress`）
- `scripts/delegate-chain-probe.ts`：改走兼容层，统计进度帧与需要人帧

## 验证

真模型（`deepseek-v4.1-flash`）两步依赖任务，客户端实际收到的帧：

```
事件流：progress:working → delegate ×7 → progress:thinking → delta ×8
派活进度帧（7）：0/2 拆好了，开始派 | 0/2 create-s1 | 1/2 create-s1 |
                1/2 rewrite-s1-to-final1 | 2/2 rewrite-s1-to-final1 | 2/2 核对 | 2/2 核对
```

回归：

```
> pnpm --filter @lifediary/server tasks    → ✓ 任务通道全部通过
> pnpm --filter @lifediary/server gate read-only → ✓ read-only 闸门正确
> pnpm --filter @lifediary/server http     → ✓ 端到端全部通过
> npm run typecheck                        → exit 0
```

## 没验证到的

1. **`attention` 帧没在真模型上跑到**：这次跑的任务没卡住，所以只验了进度帧。需要构造一个必然卡住的活。
2. **App 侧还没接**：这两帧目前只有探针在读，`core:ai` 的解析和 UI 都还没动。
3. **进度帧的节流**：现在每个 `task-start`/`task-done` 都发一帧，两件活 7 帧。
   活多了会不会太密没测（设计文档里说 App 侧节流 150ms，还没做）。
4. **非流式路径**：跳过这两类，没验证非流式客户端拿到的是什么（应该是纯文本，没变）。
