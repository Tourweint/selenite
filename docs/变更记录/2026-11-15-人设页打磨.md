# 人设页打磨（2026-11-15，前端为主 + 两条语义变化）

方案与取舍见 `docs/设计方案/2026-11-15-人设页打磨.md`。这篇只记「改了什么、为什么」。

## 起因

用户从上到下过了一遍人设（执事档案）页，提了一串问题：主动性看不懂、接派单不知道干嘛、
结果契约看不懂也不该关、纪律/履历/在办只看不了、俩按钮丑、预设不跟着开关跳、弹层大小不一。

## 契约变化（两条）

1. **预设枚举扩两档 + 保存时推导**：`PartnerPersonaPresetSchema` 加 `allrounder`（全才）/
   `apprentice`（学徒）。`PUT /persona` 落库的 `preset` 不再取请求值，而是由最终开关表
   `derivePresetFromModules()` 算出——表匹配某预设就标它，否则 `custom`；比较只看 12 个可配置 id。
   效果：改任一开关自动跳「自定义」，改回原样自动跳回预设。人设库 `apply` 同样按推导名字落库。
2. **`workHistory` / `currentWork` 停止作为注入闸**：两段固定注入（现查现拼，没活干时整段
   本来就不出现，常开零成本）。`effectivePersonaModules` 里恒置 `true`；旧行上的 `false`
   保留在存储里但不再生效（不做数据迁移，语义上等于忽略）。

新端点 `GET /api/v1/partners/:id/injection-preview`：`{discipline, currentWork, workHistory}`，
与真实轮次**同一装配函数**现拼（`agent/partner-context`），只读、不进 shared。

## 界面

- 顶栏：「试跑」按钮退役（列表页 ⋯ 菜单还有入口）；暂停/恢复收成 30×30 图标钮 + `data-tip`。
- 「人格模块」右侧常驻解释删掉，挪到标题 `data-tip`（悬停黑框）。
- 卡墙：接派单卡退役（机制与端点保留，见系统架构 §516 登记）；纪律/履历/在办搬出卡墙。
- 新增两个分区：**注入的内容**（纪律 / 在办状态 / 履历摘要，点卡开只读弹层看实际注入原文，
  纪律保留开关）+ **高级开关**（结果整理 / 日记执事，默认全开，只做"对他一个人"的例外）。
- 「结果契约」改名**「结果整理」**，三态循环收成两态（开 = 跟随全局默认 / 关 = 只他一个回原始结果；
  行上仍存 `null|0|1`，界面不再产生 `1`）。
- 弹层统一：岗位契约 / 当前目标 / 负责项目三个弹层同宽同结构（大文本框 + 撤销/保存 + 关闭）。
- 预设条五档；主动性 tip 改大白话（"不是定时任务"写在第一句）。

## 坑

- **读取层白名单会吃掉新预设**：`partner-rows.ts` 的 `toPersonaPreset` 只认旧三值，脏值一律
  降级 `work`——新预设写进去读出来变 `work`。加预设必须同步这处（单测 `companion-api` 先红的
  就是这个）。
- 页面委托原来挂在 `#pf-persona` 上，新增两个分区在它外面 → 点击不响应；改挂整页 `.pf`。
- 注入区三张卡都写「点开看注入原文」太吵（用户口径：解释文字别常驻）→ 右侧一枚小箭头 +
  纪律只显示「开/关」。

## 验证

`pnpm typecheck` clean；`pnpm --filter @lifediary/server test` **961 项全绿**（新增
`src/partner-persona.test.ts` 4 项 + `companion-api.test.ts` 2 项，改 3 项旧断言）；
`pnpm --filter @lifediary/server http` 端到端全过；浏览器（agent-browser）实测：
结构断言（试跑已无、三个分区归位、预设五档）、点纪律卡出 953 字原文、
履历摘要空态、全才/岗位/自定义三向自动跳转、结果整理两态、两个弹层结构一致、截图目检。

**没验的**：手机端（persona 端点手机未引用该枚举，理论零波及，未实机跑）；
`TOOL_PROJECTION=0`（强制开）这条老路径不再从界面产生，只在 API 层保留。

## 第二轮（同日，用户看完第一版后追加）

1. **挂念拆成独立卡**：原来「主动性」卡右侧带着「挂念」子开关，两个开关并排——
   用户明确不接受。现在主动性只讲追问（一个开关），挂念单独一张卡。挂念依赖主动性
   在跑（服务端 `nudgeEnabledOn` 要求 `proactivity` 模块开），所以点开它时若主动性关着，
   一次 PUT 把两件一起落，并明说"顺手把主动性也打开了"。
2. **「记忆」注入卡 + 开关**：注入区新增一张卡（纪律 / 记忆 / 在办 / 履历四张）。
   契约：`PartnerPersonaSwitchesSchema` 加 `memoryRecallEnabled`（默认开，未写 = 开）；
   `memoryRecallProvider` 前置一道闸——这一位的会话关掉就不再自动带记忆（`recall` 工具照旧能查）。
   点卡不给"原文预览"：记忆是每轮按你说的话现查的，没有固定原文——弹层如实说明 + 「去记忆页」入口。
3. **纪律「为什么改不了」**：弹层改成三条原因（安全边界不是文案 / 固定字节兼着缓存与跨执事一致 /
   自己的规矩写岗位契约）+ 原文 + 「去岗位契约」；卡片 tip 同步。
4. **高级开关不再写「默认全开」**：日记执事是"全家只有一位"的指派，不是默认开——
   常驻字删掉，改成标题悬停里说清各自语义。

文档同步：`接口-端点4` 的 `switches` 描述加 `memoryRecallEnabled`。

验证：typecheck clean；单测 **974 项全绿**（新增记忆开关套件）；http 探针全过；
浏览器实测：挂念独立卡 + 联动开主动性、记忆开关切关/开、记忆弹层、纪律弹层（1399 字原文）、
注入区四卡、高级开关无"默认全开"字样。

## 第三轮（同日，用户纠正概念后）

用户指出：那两块不是一个机制——**「注入」= 100% 每句话都带；「记忆」= 先打分相关的才浮出**。
上一版把记忆塞进"注入的内容"区，正好把这两件事混了。

- **区块改名 + 拆成两节**：
  - 「每轮固定注入」（原「注入的内容」）—— 纪律 / 在办状态 / 履历摘要 / **负责项目**；
  - 「按相关度召回」（新）—— 记忆四类 + 挂载项目的记忆，带 `memoryRecallEnabled` 开关。
- **「负责项目」从人格模块·岗位组移到「每轮固定注入」**：它带来两件事，界面与弹层都写明白——
  ①每轮固定收到一行「你负责的项目：…」（100% 注入，和纪律同性质）；②这些项目的记忆进召回池打分。
  项目弹层里实时显示"他现在每轮固定收到：你负责的项目：A、B。"（跟着勾选变），
  没挂时显示"这一行不出现"。
- 记忆弹层文案改为「记忆怎么被召回」，并指路"想让某个项目的记忆进打分池，去挂上它"。

验证：typecheck clean；单测 **975 项全绿**；浏览器实测（两节归位、项目卡在注入区、弹层那行预览、
召回区记忆卡与弹层、截图目检）。

## 第四轮（2026-11-16，父子关系补齐）

用户点明结构：**每个执事级开关都该有一个服务级总闸做「父」**，执事页上的只是「子开关」。
复查后发现「记忆召回」这个新开关只有子没有父，补上：

- `PARTNER_MEMORY_RECALL` 进 `flags.ts`（行为开关表，默认开、hot），消费处在
  `agent/assist.ts` 的 `memoryRecallOff()`：父闸关 → 所有会话都不自动带记忆；
  子开关关 → 只那一位不带；读不到 / 非执事会话只受父闸管。
- 界面：`settings-switches.js` 给中文名「记忆召回（总闸）」+ 说明（讲清它和「记忆」分组里
  那些开关的区别：那些管记忆库本身，这个只管每轮自动注入），归入「记忆」分组
  （之前裸 key 落进"其他"组、没有说明）。
- 各卡片 tip 标出父闸位置（记忆 / 结果整理 / 负责项目），父子关系在界面上看得见。
- `.env.example` 补上总闸与父子说明。

**现有的父子对照**（供后来者按同一套加开关）：人格模块 14 个 ← `PARTNER_PERSONA_MODULES`；
结果整理 ← `TOOL_PROJECTION`；负责项目 ← `PARTNER_PROJECT_MEMORY`；接派单 ←
`MINISTER_DISPATCH_AUTHORITY`；记忆召回 ← `PARTNER_MEMORY_RECALL`。日记执事没有父闸：
"全家只有一位"是指派，不需要全局关（默认就没人是指派）。

验证：typecheck clean；单测 **976 项全绿**（新增总闸注册断言）；浏览器实测服务页
「记忆」组出现「记忆召回（总闸）」并有说明、不再落"其他"。
