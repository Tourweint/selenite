## 一、确定性巩固（memory 包，自动）

- `consolidate.ts`：新增 `normalizeContent()`（全角→半角 + 空白折叠 + trim + 剥句末标点；
  **不**做大小写折叠 / 不剥括号引号）。规则 1 从"原始全等"升级为
  **同 scope + 同 kind + 规范化全等** → 不新增、importance +0.1。
  kind 不同不合并（偏好 vs 经历是两种用途）；措辞不同不合并（那属于语义，只走建议制）。
- 强化上限从 `1` 放宽到 `10`（`IMPORTANCE_CEIL`）：召回强化可能把值推过 1，
  原来的 `Math.min(1, …)` 会把它按回去。
- 新文件 `decay.ts`（纯函数）：
  - `decayedImportance(importance, anchorIso, now, daily)` = `importance * daily^天数`，
    下限 `0.1`、上限 `10`；`daily<=0` / `>=1` / 锚点解析失败 → 原值返回（不改数）；
  - `reinforcedImportance(value, step=0.05)` 封顶 10。
- 递归落点 `recall.ts`：
  - `WeightedRetriever` 新增 `decayDaily`：打分用"这一刻衰减后"的 importance
    （打分侧按 0..1 归一，涨过 1 只代表"排得更前"，不把权重设计挤变形）；
  - `touchRecall` 一次做完"衰减 → +0.05 → 锚点推到 now"。**写回只发生在召回命中**，
    且锚点跟着值走，所以同一个值不会被反复乘（单测用注入时钟验过）。
- 装配：`agent.ts` 的 `memoryDecayDaily()` 读 `MEMORY_DECAY_DAILY`（默认 0.99、`0` 关、
  坏值回落默认），经 `createMemoryEngine({decayDaily})` 传入。
- 刻意**不做**扫描 cron（既有"刻意没有"不变）；**不删**任何因病衰减到下限的记忆。

## 二、模型辅助巩固（server，人拍板）

- 新文件 `memory-consolidate.ts`：
  - `POST /api/v1/memory/consolidate/review`：取该 scope 最近 ≤200 条（不含已被取代），
    一次独立模型调用（30s 超时、≤50 条建议、prompt 明写"只建议、不执行"），
    按清单复核 id（编造 / 自指 / 重复对丢弃），待决建议落 `.data/memory-proposals.json`
    （按 scope 存、原子写、`MEMORY_PROPOSALS_PATH` 可覆盖）。
  - 失败如实 5xx：无可用模型 / faux → 503 `llm_not_configured`；
    调用失败 / 超时 / 输出不是可解析 JSON → 502 `llm_failed`。
  - `POST /api/v1/memory/consolidate/apply`：幂等 `supersede(dropId → keepId)`；
    `dropId` 已指向同一 keep → `alreadyApplied:true`；指向别的记录 → 400；跨 scope → 404。
    成功后从待决文件摘掉该条。
- 界面（设置 → 记忆）：新增「范围」下拉（总管 global / 各执事 partner）与「整理记忆」；
  建议卡 = 保留句 / 收编句 / 理由 + 逐条「应用 / 忽略」；结果行"已应用 N / 忽略 M"。
  **忽略 = 前端直接销卡，不发请求**（所以无副作用）。没有"全部应用"。
- 回滚：`MEMORY_CONSOLIDATE_LLM=false` → 两个端点 404、`canConsolidate=false`、按钮不渲染。

## 三、导入（server，只增不改）

- `memory` 包新增 `importMemories()` + `MemoryEngine.importItems()`：
  逐条校验（空文本 / 超 2000 字 / 认不出的 kind → 跳过），规范化等价跳过并计数，
  批内重复也跳过，已被取代的记录算"已存在"（不复活），`source/veracity=imported`，
  缺省 importance 0.5、夹到 `[0.1, 1]`，合法 createdAt 保留、未来裁到 now。
  **绝不覆盖 / 删除 / 修改已有记录**（不提升别人 importance），只被别人收敛。
- `POST /api/v1/memory/import`：`{scope, items[]}` → `{ok, added, skipped, total}`；
  单次上限 5000 条；scope 只认 `global` / `partner:<id>`。
- 界面：设置 → 记忆「导入记忆」→ 选 `.json` → 前端只解析计数（不预检内容）→ 确认 →
  结果行"新增 N 条 / 跳过 M 条"。文件格式：裸数组或 `{"items":[...]}`（接口文档 §2.15.2）。
- 回滚：`MEMORY_IMPORT=false` → 端点 404、按钮隐藏。

## 六、已知边界

- 召回命中才写回衰减值：没被想起过的记忆，库里的 importance 保持最后写入值，
  只在每次读取打分时按锚点现算（同一套公式，结果一致；不写回避免每轮全表更新）。
- `MEMORY_DECAY_DAILY=0` 只关**衰减**，不关"命中 +0.05"强化（方案 §一 把两者分开写）。
- 整理建议是**易失**的：刷新页面不回放，重新整理会覆盖同一 scope 的待决文件。
- 执事记忆的「整理」需要执事列表可读（`COMPANIONS_ENABLED=false` 时下拉只有总管）。
