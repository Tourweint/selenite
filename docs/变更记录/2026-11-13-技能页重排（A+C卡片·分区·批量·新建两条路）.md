# 技能页重排（卡片墙 A+C + 分区 / 筛选排序 / 批量确认）

日期：2026-11-13
范围：harness 仓 `ts/apps/server/web/`（app.js / style.css）。无契约、无服务端改动。

## 改了什么

**列表：一人一行 → 卡片墙（用户拍板 A+C 版）**

- `grid auto-fill minmax(250px, 1fr)`，1000px 内容宽下 3 列（每张 324px），卡片**定高 132px**；
  窄窗 2 列 / 1 列自适应。摘要最多两行（悬停 `title` 看全文，点开弹窗看完整内容）。
- 卡片分层：**名字当主角**（mono 13px、`--text` 正文最亮一档）+ 右上角建议「6px 色点 + 四个字」
  （建议开启 / 按场景 / 建议不开 / 待复核 / 未评估；频率与理由收进 hover）→ 摘要两行 →
  底部「用过几次 · 多久前」+ `只读` / `90 天未用` 文案 + 开关 / 垃圾桶图标。
- 卡片上**撤掉**：秒级更新时间、文件大小、建议频率长文案。这三样改在点开的弹窗里补一行
  「更新于 … · 大小 · 用量 · 来自 …」；卡片 meta 的 `title` 也留了完整版。
- 删除从文字按钮降成 13px 垃圾桶图标（24px 热区，hover 变红）；只读卡片没有删除。
  开关去掉「启用」二字，回到标准开关形态（页头悬停说明已有）。

**详情弹窗**

- 摘要拆成独立一栏（第 1 行），正文另一栏；保存时按 `摘要 + "\n" + 正文` 拼回整份 content
  （正文原样保留，含开头空行）。新建技能同样两栏，摘要不能为空。
- 只读技能：目录形态（`<名>/SKILL.md`，如 `.agents/skills`）与 `.agents` 的扁平文件在弹窗里
  只读——摘要整段换行显示（目录形态取 frontmatter `description`），原文用 `<pre>` 保留排版，
  不给保存按钮。原因：`PUT` 只会写扁平 `<名>.md`，对目录形态保存等于另存一份，语义不同。
  内置手册（app 目录）仍可编辑，弹窗里写明「保存会在你的技能目录里建一份同名副本」
  （沿用 9-S 合并语义）；卡片 `只读` 的 hover 按这两种来源分别说明。
- 弹窗开头补一行 `.sk-detail-meta`（更新于 / 大小 / 用量 / 来源）；只读详情不渲染输入框，
  `openModal` 的「聚焦并全选第一个输入框」落到「关闭」按钮上——长摘要不会一开就被卷到末尾。

**页面控制（同日二轮，用户口径「页面按钮有点多」）**

- **列表分两区**：已开启在上、未开启在下；每区独立计数、独立排序（排序不跨区）。
- 顶部原来 5 个按钮（让 Agent 评估 / 一键采纳 / 全开 / 全关 / 新建技能）收成 2 个
  （让 Agent 评估、新建技能）；分类 chips 收成一个下拉（全部 / 建议开启 / 按场景 /
  建议不开 / 未评估，带计数）；新增排序下拉（默认 / 使用频率 / Agent 建议；没有建议
  快照时第三项不出现）。
- **全开 / 全关合并成一个状态相关按钮**（全部开启 ↔ 全部关闭），点击先弹确认框；
  混着开 / 关时弹窗同时给「全部开启」「全部关闭」两个方向（避免想全关得先全开一次）。
- **Agent 建议条**：有快照就常驻在工具栏上方，写明建议分布（开启 N 个 · 不开 M 个，
  有「待复核」时一并列出）与对齐状态（建议开启没开 X 个、建议不开开着 Y 个 / 已按建议对齐）。
  右侧「按建议调整」批量执行两个方向：建议开启的打开、建议不开的关闭；按场景 / 未评估 /
  待复核不动，点击先弹确认框（列出两个方向的条数）。没有快照时这一行给指引（先点
  「让 Agent 评估」）；SKILL_ADVICE=false（端点 404）整行不出现。
- **新建技能先选两条路**：① 让 Agent 帮我写——跳总管对话并预填提示词（带技能目录的
  Windows / MSYS 两种路径，让总管问清用途与步骤后用 bash 写文件；写不进则让总管把
  Markdown 发回来，用户贴进「自己填」）；② 自己填——原来的名字 / 摘要 / 正文表单。
- 选择器与确认框都是纯前端；服务端仍用既有 `enabled-all` / `skills/advice` / `PUT` 端点。

## 设计取舍（为什么会改成这样）

2026-11-13 第一版卡片墙（168px、建议长徽章 + 时间/大小/用量堆在 meta 行）给用户看后反馈
「有点乱糟糟，信息都在但有些奇怪」。诊断四条：

1. 名字 12px 灰字，建议徽章反而最亮——主次颠倒；
2. meta 一行堆 5 件事（秒级时间 / 大小 / 用量 / 只读 / 90 天未用），读起来像日志；
3. 「建议不开 · 几乎用不上」长徽章在 66 张卡上重复；
4. 开关 +「启用」+ 删除排成一行，像表单控件，抢摘要的戏。

同日做了四版 HTML 原型（`docs/设计方案/2026-11-13-技能卡片样式原型.html`，A 名字优先 /
B 图标卡 / C 色点 / D 最紧凑，浏览器逐版截图验收），用户拍板 **A 的布局 + C 的色点**，即本版。

## 刻意不做

- **不改技能名（文件名）**。技能名同时是服务端三份账的键（`skills-state.json` 启停、
  `skill-usage.json` 用量、`skills-advice.json` 评估建议），还出现在对话里的 `/技能名`
  和历史指令中；改名要同步搬三份账、处理历史引用，属于新契约，单独立项再做。
- 不改服务端 / 不改契约：仍用 `PUT` 整份 `content`；弹窗按 `GET /skills/:name` 既有的
  `form` / `origin` / `writable` 分栏渲染。
- 不做卡片上的「建议理由」常驻：理由与频率留在 hover（C 版口径，信息密度优先）。
- 筛选 / 排序不写 localStorage：会话内保留，刷新回默认。先看手感，需要再持久化。
