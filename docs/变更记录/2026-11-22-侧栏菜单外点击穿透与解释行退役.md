# 2026-11-22 侧栏菜单「再点一下闪一下」+ 菜单解释行退役

## 改了什么

1. **原生菜单的外点击不再穿透到页面**（`web/sec-menu.js`）。菜单开着时在页面上按下一次，
   记一笔并吞掉紧跟的 click；菜单自身的选中仍在原生小窗里完成，不受影响。
2. **侧栏三张菜单去掉解释行**（用户口径「解释性文字不需要」）：任务 ⋯（新建任务 / 新建助手对话）、
   项目 ⋯（新建项目 / 添加项目）、执事右键（人设档案）。`SecMenuItem.hint` 的渲染、
   原生菜单 payload 的 `hint` 字段、`.sec-menu-item.is-rich` / `.sec-menu-hint` 一并退役。
   （`desktop/popovers.go` 的 `MenuItem.Hint` 保留：桥字段向后兼容，当前无调用方。）

## 为什么「再点一下」会闪

用户报：侧栏展开后点 ⋯，再点一下，菜单卡片闪一下。帧序列实测是 **关掉后约 14ms 又打开**，
不是纯视觉闪烁。

根因在壳的弹出层实现与 WebView 的边界：mygo 的 Focusable flyout 在 Windows 上按下时会
「激活父窗并吃掉这一下」（`WM_MOUSEACTIVATE` → `maActivateAndEat`），所以菜单会先关；
但这条是给壳自己的窗口的，WebView 子窗不是那个窗口，click 照常交给页面。页面里的
`openSecMenu` 收到同一次点击的 click，又调了一次 `Shell.ShowMenu` → 关掉马上重开。
同一个缺口也让「菜单开着点别处」误触底下的行。

修法不碰壳协议：按下时记一笔、吞掉紧跟的 click，回到 Windows 菜单「第一下只关、不选」的
口径。只在 Windows 生效（macOS 的弹出层本来就允许外点击继续落到下面，框架明确保持那个手感）。

## 验证

- `node --check` 改动的四个 JS 全过。
- 真机（lifediary-shell，刷新页面后）：连点同一个 ⋯ → 菜单关闭且**保持关闭**（16 帧一致）；
  菜单开着点另一分区 ⋯ → 只关、不打开，再点一下正常打开；任务/项目菜单文案已无解释行。
- 浏览器（无壳、DOM 路线）打开任务菜单正常，四项文案正确；守卫只在 `nativeMenusOpen > 0` 时生效，
  DOM 路线不受影响。

## 没做 / 边界

- 守卫用 1.5s 计时兜底「按下后拖走、没有 click」的情况；极长的按住再松开仍会吞掉那一次 click
  （这正是想要的：那一下本来就只是关菜单）。
- 原生菜单的 `hint` 字段未从壳侧删除；等下次动 `popovers.go` 时一并收。浏览器 DOM 菜单已无此概念。
