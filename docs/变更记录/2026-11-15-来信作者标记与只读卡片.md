# 来信作者标记与只读卡片（执事之间递话的记录长什么样）

方案：`docs/设计方案/2026-11-15-Agent间通信记录（作者标记与只读来信）.md`。
参照对象是 cindy 的来源体系（`docs/product-rules/message-source.md`，2026-10-05 裁决）：
**界面标签与模型说明同源；非主人来源不占右侧**。

## 改了什么（按契约顺序）

**1. 契约（`ts/packages/shared/src/index.ts`）**

- 新增 `TranscriptAuthorSchema`：`{ kind: "partner", id, name, domain?, hop? }`。
  `kind` 只有 `partner` 一个值——**主人自己的输入不带 `author`**（对齐 cindy"本机输入不盖章"）。
- `TranscriptMessageSchema` 增可选 `author`；不带 = 主人本人在说。
- `snapshot.test.ts` 的 `MESSAGE_SHAPE` 同步增 `author` 形状（契约快照 6 条）。

**2. 落库（`partner-relay.ts` + `agent/lifecycle-harness.ts`）**

- `deliverPartnerRelay` 提交时不再落 `pi.user`，改落应用条目
  `entry: { kind: "relay.message", data: { kind:"partner", id, name, domain?, hop:1 } }`
  （durable 的 input 支持 `entry`；kind 不许以 `pi.` 开头，所以常量定为 `relay.message`）。
- 模型看到的**仍是那一条 user 消息**：`entry` 只决定"落成哪条条目"，不改变给模型的内容。
- `RelaySenderContext` 增 `domain`，工具调用处传 `self.domain`。
- 回滚：`PARTNER_RELAY_ENVELOPE`（默认开；`false`/`0`/`off` 关，回到 8d 的纯 `pi.user` 形态）。

**3. 回读（`agent/session-transcript.ts`）**

- `foldTranscriptEntries` 认 `relay.message` 与 `pi.user` 同一分支——**必须同时认**，
  否则来信整条从历史里消失（只在内存里活一条）。
- 新增导出 `relayAuthorOf(entry)`：从 `entry.data` 还原作者结构；
  `data` 缺失 / 形状不对 → 返回 `undefined`，退回"普通 user 消息"（老库老数据的安全网）。
- 来信**不给 `id`**：前端所有编辑入口都挂在 `.msg.user` 的可寻址消息上，没有 `id` 就天然没有
  "编辑重发"（主人能看、不能改，是结构决定的，不是按钮藏起来）。
- 正文用 `relayDisplayText()` 剥掉模型侧三段说明（`[relay hop=1]`、`[来自执事 X（域）]`、末尾
  括注的出口指引）——抬头已经写了谁发来的，正文只留原话。

**4. 分轮（`agent/transcript-page.ts`）**

- 新增本地 `startsTurn(kind)`：`pi.user` 与 `relay.message` 都算"一轮的开头"，
  `turnStartOf` / `splitTurns` / 扫描条件三处统一用它。来信自成一轮，不并进 B 自己的上一轮。

**5. 会话状态（`partner-runtime-do-open-partner-conversation.ts`）**

- `hasDialogueInTx` 把 relay 条目也算"有过往来"：只有收到来信、还没回过话的会话，
  不会被再插一条开场问候。

**6. 前端（`web/chat-thread.js` / `chat-open.js` / `style-05-message-extras.css`）**

- `addMessage` 增 `options.author`：有作者 → `.msg.letter`（左侧来信卡），无 → 仍是右侧气泡。
- 卡片结构：抬头 `执事「名」· 域 发来` + 时间；正文首行折叠、点一下展开（`.letter-toggle`）。
- `renderTranscriptMessage` 把 `message.author` 传下去。
- **SSE 现场只推落库正文，不推 `author`**：来信只在回读（刷新 / 切会话）时显示成卡片（已知边界）。

**7. 刻意没改**

- `session-index`（会话标题 / 轮数）：来信不当会话标题。
- `session-search`（`recall_sessions` 跨会话检索）：来信不进检索。
- `forkForEdit`：只认 `pi.user`，来信不可被"编辑后分叉"。
- 主人发言落库署名：不做（主人本人在说，右侧本来就是他的）。

## 开关名

| 开关 | 位置 | 含义 |
|---|---|---|
| `PARTNER_RELAY_ENVELOPE` | env（本批新增，默认开） | false / 0 / off = 回到纯 `pi.user`，界面按老样子画成右侧 |

## 可见规则（改这些常量 = 改行为）

- `RELAY_ENTRY_KIND = "relay.message"`（不得以 `pi.` 开头，durable 会拒）。
- `RELAY_FROM_PATTERN`：正文前缀 `[relay hop=1][来自执事 名（域）]`，是**转述检测的唯一判据**，
  也是 `data` 缺失时的兜底展示来源。
- `hop` 当前恒 `1`（只允许一跳，两跳未做）。

## 与方案的偏差（如实列出）

- 方案写的是"落成 `relay.message` 应用条目"，实现照做；但探针第一条断言原脚本按"正文里找前缀"验，
  前缀被剥后必然红，遂把断言改成读 `author`——**契约没变，验法跟着变**。
- 前端卡片只做了静态渲染 + 单测覆盖不到的人工路径；没有为来信补 per-conversation notice。

## 已知边界（未做 / 未验证，2026-11-15）

- **跨会话"两人私聊视图"不做**：来信只出现在收件方自己的会话里，主人看的是"乙的会话里有一段甲说的话"。
- **信箱表 / 离线队列 / 已读回执不做**：B 不在线时递话走的是既有 followUp 排队，不新造栈。
- **hop > 1（A→B→C 两跳）不做**：第二跳在结构上摘掉 `send_to_agent`，不是靠提示词劝。
- **来信进会话标题 / 轮数 / `recall_sessions` 检索**：不做，来信不改变"这个会话是谁的"。
- **手机端**：`author` 字段可忽略，手机端仍按普通文案渲染（不显示卡片）。
- **通知落盘**：主人侧那条"谁给谁递了话"的轻事件不落库，刷新即失。
- **来信卡的目视确认没做**：验到的是"回读层给到 `author`、前端按 `author` 走来信分支、文案与样式都在"，
  真实浏览器里刷新 B 的会话看那张卡片，仍需人眼过一遍（我这边没有打开界面截图确认）。
