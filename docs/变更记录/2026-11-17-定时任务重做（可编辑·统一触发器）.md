# 定时任务重做：能改内容 + 与例行任务同一套界面/触发词

用户原话：

- "现在改不了内容，这比较逆天。"
- "它到底是做什么？就这一句话，可能做也可能做不到。"
- "定时任务要跟人设页里的例行任务对齐。你看这个例行任务可以改，对吧？好像也改不了，我只能暂停、改时间之类的。"
- "还有展开历史这块，只能新建一个指令，但触发类型还不一样，我们要统一。"

## 根因（2026-11-17 核实）

1. `GET /api/v1/routines` 的投影**不返回 `prompt`**，例行列表拿不到指令正文。
2. `PATCH /agent/reminders/:taskId` 只收时间规则，**不收 `text`**。
3. 定时任务页用「单日/区间/每天/每周/每月」，人设页例行新建暴露 `cron / interval / once / event` 原始字段；两边各缺一半动作。

## 改了什么

### 服务端

- `routineProjection` 增加 `prompt`；`PATCH /routines/:id` 补 `name` / `prompt` 校验（非空、≤40 / ≤100k）。
- `ReminderInput` 增加 `enabled`（暂停）与 `visibility`（`hidden` / `visible`）；deliver：暂停只续排不跑模型，可见触发不加 `[lifediary.proactive]` 标记。
- `GET /agent/reminders` 列表项多 `enabled` / `visibility`，新增 `?includePaused=1`；不带时过滤暂停项（手机端继续只同步真会响的）。
- `POST /agent/reminders` 接受并校验 `enabled` / `visibility`；`PATCH /agent/reminders/:taskId` 支持 `{text?, enabled?, visibility?, at?...}`——只给前三者时沿用原时间规则，仍是"取消原任务 + 同 reminderId 重排"。
- 新增 `POST /agent/reminders/:taskId/run_now`（不动定时链、记 `manual` 历史；`SCHEDULED_TASK_MODEL_RUN=false` 时 400）。
- 新增 `GET /agent/reminders/:reminderId/runs`；执行历史落 `.data/reminder-runs.json`（`REMINDER_RUNS_STATE_PATH`，全局 ≤500、坏文件当空、只存枚举与 ≤200 字摘要，**不存原始错误**）。
- 新增 `scheduled-run-context.ts`：抽出 `SCHEDULED_RUN_HEADER` 与 `stripScheduledRunHeader()`；`partner-runtime-run-partner-turn.ts` 用它拼头，`session-transcript.ts` / `session-search.ts` 回读时剥掉——可见触发不再把 `[Scheduled run context]` 露给用户。
- 手动 UI 选总管时传 `partnerId="chief"`，不再传 null（null 会新建空会话）。

### 前端

- `settings-reminders.js`：`openReminderModal` → `openScheduledTaskModal`，四种入口（新建 / 编辑提醒 / 编辑例行 / 改记忆时间）共用日历 + 滚轮；新建统一 `POST /agent/reminders`（可见/隐藏都走这套，手机本地闹钟不丢）；删除原先"可见→routines、隐藏→reminders"的分叉。
- 新增 `renderScheduledTaskList()`：统一行、按人筛选、指令预览、`编辑 / 暂停·启用 / 立即跑 / 历史 / 删除`、行内历史、删除确认。
- 例行编辑：`prompt` + `name` + 友好时间 → `PATCH /routines/:id`；复杂触发（interval / event / 多触发器）只读，保存内容时不动 `triggers`；简单触发改时间时保留 `if` / `ends.after`。
- `settings-router.js`：hero 文案改成"到点让 TA 自己跑一轮"；`手动设置` 开新编辑器。
- `partner-routines.js`：新建表单换成「新建定时任务」按钮；列表同时拉该人的 routines 与 reminders，共用渲染器。
- `partner-profile.js`：例行卡改名「定时任务」，计数 = 两类之和；记忆改时间走同一编辑器。
- `style-14-settings-pages.css`：`.rm-instr` / `.rm-runs` / `.rm-run` / `.rm-textarea`，`.rm-row-actions` 换行；`.rm-title` 单行省略。
- HTML 属性值统一走 `attr()`（名称 / 指令里带双引号不会破行），正文仍走 `esc()`。

## 明确没做

- 不合并 reminders / routines 两套引擎，不迁移已有提醒；手动新建走 reminders 是为了不丢手机本地闹钟。
- 不改手机端；暂停任务不进默认 reminders 列表，因此不推本地闹钟。
- 不给 `set_reminder` / `routine_manage` 加参数（工具描述与注册顺序是缓存前缀资产）。
- 不做事件/间隔的手动编辑；不做批量编辑、任务模板、换到点叫谁。
- 一次性提醒不提供暂停（没有可恢复的持久定义，UI 不显示该按钮）。

## 回滚

本批是**纯增量字段 + 前端**：老数据缺 `enabled` / `visibility` 时按启用 / 隐藏处理，老客户端忽略新字段，零行为变化。需要回到旧界面 = 回退前端三个文件（`settings-reminders.js` / `partner-routines.js` / `partner-profile.js`）；需要回到旧闹钟（不调模型、写死消息）= `SCHEDULED_TASK_MODEL_RUN=false`（既有开关，本批未改）。

## 已知边界

- 编辑提醒文本会取消原任务并用同 `reminderId` 重排，下一次触发时间按规则归一化；跨过触发点会跳过一次（与现有改时间同口径）。
- 手动新建的定时任务固定「接着聊」（reminders 引擎落目标执事主会话）；「每次新开」只在 Agent / 高级例行规则的编辑面里可用。
- `enabled=false` 的一次性任务到点静默终止（API 允许，UI 不提供）。
- 提醒执行历史从本批上线后开始记；旧任务没有历史。
- 可见触发的技术头只在回读展示/搜索里剥掉；落盘 entries 与模型上下文不变。
