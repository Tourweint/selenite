# 2026-11-15 「改人设」改叫「编辑这个人」：整理记忆进例行卡，技能分两层

> 一句话：这一页不再是"改人设"，是这个人的全部档案；例行卡里必须有每晚整理记忆，技能卡要区分全局技能和他自带的技能。

## 为什么

用户反馈（语音转述）两件事：

1. 每个执事都应该有一个例行任务叫「整理记忆」，但在这页看不见。
2. 技能到底怎么加载？技能不应该是全局的吗？这页列的是什么，额外再加载吗？

### 整理记忆为什么看不见

它不是 `/api/v1/routines` 表里的记录。`memory-nightly.ts` 是进程内调度器，按 scope 挂人：
`global`（总管）+ `partner:<id>`（每个执事）。2026-11-14 定时任务页已经把它和 routine 合成一张清单，
但「编辑这个人」页的例行卡只读了 routines 表 → 0 条、空白。两处数据源没合并，不是任务不存在。

### 技能是两层，不是一层

- **全局技能**：`SKILLS_DIRS`（内置 + `~/.lifediary/skills` + `~/.agents/skills`）按启停位过滤，
  进所有会话的 system 技能索引；`skill(name)` 取正文。执事的会话同样有这一层。
- **他自带的技能**：`partner-homes/<id>/skills/*.md`，由 `partner_skill_write` 写；
  只把名字 + 摘要拼进他的身份提示词。这是额外加的一层，只对他生效，不是替代全局。

页面之前只列第二层，所以看起来像"没用全局技能"。

## 为什么改技能路径

执事会话的 cwd 是当前项目 / 工作区，不是他的家目录。身份提示词原来写"直接读 skills/<名>.md"，
模型会在工作区里找，找不到；同名还会读到 `ts/apps/server/skills` 里的内置手册。
索引里改成 `partner-homes/<id>/skills/<名>.md` 的绝对路径后 `read` 能直接取（read 不设路径边界）。
这不是新增机制，是把原来写错的相对路径改对。

## 坑

- 总管（chief）的整理记忆 scope 是 `global`，不是 `partner:chief`；其余执事才是 `partner:<id>`。
- 「改时间」改的是全家共用的每晚时刻（`PATCH /api/v1/agent/memory/nightly` 只有一个 `at`），
  页面上已写明"所有人一起变"。
- `openReminderModal` 原先没有完成回调，停在这页改完时间后弹层直接关掉、看不到结果；
  这次加了可选 `onDone`，改完重开例行弹层。
- 已删除的整理任务不会自动回来（`memoryNightlyScopes` 过滤 deleted，PATCH 也不认），
  所以这页只给暂停 / 启用，不给删除入口；删除仍在定时任务页。
- 没有新端点、没有契约改动。

## 刻意没做

- 没把整理记忆做成 `/api/v1/routines` 里的一条：它是进程内调度，硬塞进 routine 表会多一套生命周期和状态，反而容易两边打架。
- 没给非总管执事做一个能按名字取自带技能的 `skill` 工具：那要动工具注册和每会话技能库，属于新机制；现在用绝对路径直读已经通。
- 没在「编辑这个人」页做整理记忆的删除入口：删除不可恢复，留在定时任务页做防误触更合适。

## 发现但没动

- 执事身份里「写文件默认落在你的 workspace/」同样不成立：会话 cwd 是当前项目 / 工作区，`path-guard` 也只守工作区根 + 已登记项目根，执事家目录不在根集合里。要修得动会话 cwd 和写边界，属于另一套方案，这轮没碰。
