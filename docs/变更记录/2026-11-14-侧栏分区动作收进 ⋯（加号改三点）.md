# 侧栏分区动作收进 ⋯（加号改三点）

> 用户原话：「继续调整侧边栏，展开时右边现在全是加号，改成三个小点点，点开就能选择新建还是搜索，比如对话有新建、有搜索，但其他现在只有新建。多了不太好看，统一放在右边，留三个小点点即可。」

## 结论

执事 / 对话 / 项目 / 群组四个分区头，行尾统一只剩一颗 ⋯；点开是一张短菜单，这一区能做的事都在里面。对话原来并排的「放大镜 + ＋」收成一颗 ⋯ 里的两项（新建对话 / 搜索旧对话）。四个菜单共用一个组件 `web/sec-menu.js`，项目原来那套独立菜单下线。

## 改了什么、为什么

### 1. 一列加号的问题不在"加号"，在四颗同形按钮抢注意力

改之前：四个分区头各挂一颗 24×24 的 ＋（`color: text-2`，常驻可见），「对话」那颗旁边还并排一颗放大镜。视觉上侧栏右缘是一条由四颗图标组成的竖线，每区一个，形状一致、语义不同（新建执事 / 新建对话 / 新建项目 / 新建群组），分区名反而退到次要位置。

现在：一颗 ⋯ 代替一区所有动作，颜色仍是 `--text-2`，hover / 菜单展开时转 accent + `--card-high` 底。分区头的网格、36px 行高、20px 图标一个没动——只换行尾那颗。

### 2. 每区菜单内容

| 分区 | 菜单项 | 说明 |
|---|---|---|
| 执事 | 新建执事 | 复用既有「新建执事」模态 |
| 对话 | 新建对话（`Ctrl+K`）/ 搜索旧对话 | 新建 = 新开普通 worker 会话；搜索 = 进 `#/search` |
| 项目 | 新建项目 / 添加项目 | 两项各带一行解释（建目录 vs 只登记已有目录） |
| 群组 | 新建群组 | 先 `go("groups")` 再开建群流程，与旧按钮一致 |
| 课题 | —— | 本来就没有手动新建入口（课题来自主管提议），不硬加 |

### 3. 菜单形态与交互

- 挂 `body` + `position: fixed`：`.side-sec-clip` 是 `overflow: hidden`，行内绝对定位会被整块裁掉（项目文件夹浮卡 2026-11-13 踩过）。
- 定位：右缘对齐按钮右缘、下方 6px；下面放不下翻到上方；左右各留 8px；顶部不低于 8px。
- 宽度：`min-width 176px`，`max-width: min(216px, 86vw)`。216 是贴着 232px 侧栏定的——第一版给到 280，左缘被顶到 8px、右缘探进主区 56px，观感像从侧栏"漏"出去（实测截图后收紧）。
- 同一时刻只开一张；同一颗 ⋯ 再点一次就关；点外面 / 滚动 / 改窗口尺寸都关。
- Esc 走 window 捕获 + `stopPropagation`：不捕获的话，设置页/任务页的全局 Esc 会把页面一起退掉（设置页 ⋯ 菜单 2026-11-14 同款踩法）。
- 键盘：打开即聚焦第一项；↑/↓ 在项间循环；Tab 收起菜单并把焦点交回 ⋯；Esc 收起后焦点回到 ⋯。
- 无障碍：button 带 `aria-haspopup="menu"` / `aria-expanded`，菜单 `role="menu"`，项 `role="menuitem"`。

### 4. 一套组件，两套旧实现下线

- 新增 `web/sec-menu.js`：`openSecMenu(button, items)` / `closeSecMenu()`。`items` 为 `{ label, hint?, kbd?, disabled?, run }`；有 `hint` 的项排成两行（项目那两项）。
- 删除 `project-modal.js` 里的 `openProjectAddMenu` / `closeProjectAddMenu`（自建 DOM + 自定位 + 自挂 pointerdown 的一整套），项目改走 `openSecMenu`。
- 样式 `.proj-add-menu / .proj-add-item / .proj-add-label / .proj-add-hint` 改名 `.sec-menu / .sec-menu-item / .sec-menu-label / .sec-menu-hint`，尺寸从 236/300 收到 176/216。

## 顺手修的（这一个是真 bug，不是文案）

定位阶段的 pointerdown 判断原来写的是 `target === button`。⋯ 按钮 24×24，中间全是 `<circle>`，鼠标落在按钮中心时 `event.target` 是圆点、不是 button → 被判成"点外面"：先关，紧跟着的 click 又开，同一颗 ⋯ **永远关不掉**。改为 `button.contains(target)` 后复测通过。这个问题在截图里看不出来，是 `bu` 真点两下才暴露的。

## 刻意不做

- **课题分区不加 ⋯**：它没有"新建"，硬塞一个菜单只会多一个空壳。
- **项目行里的 ▾ / ＋ 不动**：那是"展开这个项目的文件夹 / 在这个项目里新开一条对话"，是行级动作不是分区动作，和本次不是一件事。
- **不做"悬停才出现"**：⋯ 常驻但压到 `text-2`，靠三个点的形状比加号轻。真嫌占位，下一步才是 hover 显形——但那样又回到"看不见的按钮等于没有"。
- **不加分隔线 / 二级菜单**：现在每张菜单最多 2 项，分隔线只会让 45px 的菜单看起来更碎。

## 这条会怎么错

- **可发现性下降**：⋯ 比 ＋ 抽象，新用户未必知道里面是"新建"。缓解只有 `aria-label` / `data-tip`（"对话：新建或搜索"）和 hover 底色；若实际使用中没人点，正解是把最高频的那一项（对话的新建）拎回行内，其余留 ⋯，而不是退回四颗加号。
- **新建多一次点击**：对话 / 执事 / 群组的新建从 1 击变 2 击（项目本来就是 2 击）。`Ctrl+K` 仍是 1 击，属于补偿路径；不用快捷键的人是实打实的成本。
- **216px 宽度上限**：项目两项的解释文案在这档宽度下是两行，再长会变三行、菜单继续变高；若以后有人在菜单里塞长句，需要改成"标题 + 悬浮提示"而不是继续加宽（加宽就会探进主区）。
- **菜单是纯文字**：没有图标。若之后菜单项超过 4 项或跨区混排，纯文字列表的扫读速度会掉，那时才值得给每项加 14px 图标。
- **新分区会漏**：以后再加一个侧栏分区，得记得同时给 `sec-menu.js` 的 wiring 补一处；现在没有"分区自动带 ⋯"的机制。
