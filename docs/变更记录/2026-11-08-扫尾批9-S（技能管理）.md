## 目录解析的语义（接线时必须照这个来）

`resolveSkillsDir()` 回答的是「**可写的那一个**目录」，不是"技能库的全集"。技能库要保住两条内置手册时：

```ts
const resolved = resolveSkillsDir();
const dirs = [resolved.dir, APP_SKILLS_DIR]; // origin=app 时单目录即可
createSkillStore(dirs);
```

同名时先到的用户目录覆盖内置——这样用户目录首访为空（自动建出来的）也不会让 `meeting_guide` / `recall_guide` 消失。
本批**没有**改 `agent/lifecycle.ts`（任务书明确留给派单人），所以现在运行时仍是旧口径（`AGENT_SKILLS_DIR` 或应用目录）。

| 端点 | 成功 | 失败 |
|---|---|---|
| `GET /api/v1/agent/skills` | `{ok, dir, origin, items[]}` | — |
| `GET /api/v1/agent/skills/:name` | `{ok, name, content}` | 名字不合法 / 越界 400；不存在 404 |
| `PUT /api/v1/agent/skills/:name` | `{ok, name, created}` | 名字 / 超 64KB / 只有一行 / 越界 400 |
| `DELETE /api/v1/agent/skills/:name` | `{ok, name}` | 名字 / 越界 400；不存在 404 |

鉴权沿用 `/api/v1/*` 中间件（失败 403 空体）。契约见接口文档 §2.19，环境变量见 §6。

## 已知边界

- **管理列表只列白名单文件名**：手工放进目录的中文名 `.md` 仍会被模型侧加载，但管理面看不到（端点按白名单读写，列出来也点不开）。要支持任意名字需要另定 id 编码方案。
- **`origin=app` 时可写内置目录**：这是解析顺序的直接结果（用户目录建不出来才落这里），不是额外保护缺口；正常情况下首访已经把用户目录建出来。
- **改目录解析但未接运行时**：本批落地的是函数 + 管理面；运行时的技能库仍用旧口径，直到派单人补 `agent/lifecycle.ts` 的一行接线（届时按上文"目录解析的语义"传目录数组）。
