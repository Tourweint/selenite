# 2026-11-24 插件中心「已改」徽标改为本次进页

## 改了什么

1. **`web/settings-switches.js`**：
   - 新增本次进页的值基线 `flagBaseline`（`resetFlagBaseline()` 清空）：`renderFlagRows()` 在本页第一次
     成功渲染时把每个开关读到的 `value` 记下来；父开关触发的整页回读不重置，避免刚拨的总闸徽标闪一下就没。
   - `flagTags()` 的「已改」从「当前值 ≠ `plugins.json` 出厂默认」改成「当前值 ≠ 本次进页时读到的值」。
   - 新增 `paintFlagTags(key)`：PUT 成功、缓存行更新后就地重画这张卡（以及打开着的同键弹层）的徽标，
     不整页重画，卡片墙滚动位置不动。
2. **`web/settings-router.js`**：每次进入「设置 → 插件」子页时调 `resetFlagBaseline()`，
   刷新 / 重进页面 / 重启服务（重启按钮本身会 `location.reload()`）后徽标自动消失。

## 为什么

2026-11-24 用户口径：插件中心改过一次之后，「已改」小标签在刷新、重启服务后还一直挂着，不能接受；
每次刷新 / 重启都要回到"没有改过"的样子。同时明确：**「默认」指第一次下载软件时的出厂默认，
不是每次重启都变成默认**——所以存下来的开关值一律保留，只清徽标。

「已改」现在的含义是"这次打开页面之后我动过它"，不是"它跟出厂默认不同"。后者在刷新后仍会显示，
就成了永久标签；与出厂默认的差异改由详情弹层的「当前 / 默认」两行表达（这两行一直都有）。

副作用（符合新口径）：历史上改过、但本次进页没动的开关不再挂「已改」（例：本机 `口述落库（写）`
存的是 `true`、出厂默认 `false`，页面只显示「默认关」）。要看它跟默认不同，点卡看「当前 / 默认」。

## 验证

- `node --check web/settings-switches.js web/settings-router.js`；`node --test src/web-imports.test.mjs`；
  `pnpm typecheck` 全过。
- 真服务 39847 真页面（IAB）：进页无「已改」→ 拨「布局调试描边」开关 → 该卡立刻出现「已改」→
  刷新 → **全页 0 个「已改」、开关仍保持拨后的值** → 拨回原值 → 再刷新仍干净；
  `.data/agent-flags.json` 的 `DEV_LAYOUT_INSPECT` 回到原值 `"false"`（测试未留改动）。
- 同时核对了长期存差异的场景：「口述落库（写）」`value=true` / 默认 `false`，刷新后只显示「默认关」，
  不再挂「已改」。
- **没验**：桌面壳内 webview 重启后的表现（按代码，设置页「重启」按钮在 `RestartRuntime` 后直接
  `location.reload()`，与浏览器刷新同路径）；详情弹层开着时拨开关的徽标联动只按代码走查。
