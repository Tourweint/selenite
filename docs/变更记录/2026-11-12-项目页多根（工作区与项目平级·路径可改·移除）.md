# 项目页多根：工作区与项目平级、路径可改、移除/恢复

日期：2026-11-12
状态：已落地（桌面端设置 → 项目 + 服务端多根边界）；方案见
`docs/设计方案/2026-11-12-项目多根模型（工作区与项目平级）.md`。

## 起因

用户口径（2026-11-12）：工作区根和项目应该是平级的，项目不要求在工作区下面；
子项目名字显示两遍、路径不能改、只能删了重加；「归档」看不懂，希望目录叫「移除」、
会话叫「归档」。对照 ZCode：项目 roots 平级、全部可读写，项目没有归档，只有移除/恢复。

## 改了什么

### 服务端（契约 + 边界）

- `projects.ts`：项目根可以是任意绝对路径（必须已存在、可写、非盘符根/主目录/系统目录）；
  新增 `validateProjectRoot`、`updateProjectRoot`、`assertProjectRootAvailable`（同路径/嵌套/包含都拒）。
  `proposeProject` 的 `path` 支持绝对路径；`confirmProposal` 绝对路径只复核不建目录，相对路径仍建在工作区下。
  当前项目、派单复核、恢复不再要求工作区内（回滚开关下仍要求）。
- `workspaceRootsReal()`：工作区根 + 全部未移除项目根的 realpath 集合；`path-guard.ts` /
  `read-allowlist.ts` 改为"落在任一根内即放行"，空集合旁路/不放行。
  错误文案改为"请到 设置 → 项目 里添加该目录"，不再暗示"完全访问档能绕过"（它不能）。
- `files.ts`：`GET /api/v1/files*` 支持 `projectId`，`path` 相对该项目根；开资源管理器同样可对外部项目。
- API：`PATCH /projects/:id` 接受 `rootPath`；新增 `POST /:id/remove` / `restore`，
  旧 `/archive` / `/unarchive` 保留为别名；`DELETE` 保留但界面不再使用。
- 回滚：`PROJECT_OUTSIDE_WORKSPACE=false` 恢复单根口径（校验、根集合、当前项目、派单都退回旧行为）。

### 桌面端

- 设置 → 项目：只剩一节「项目」，「工作区根目录」与项目同一种行、同一字号；
  每行路径是可直接编辑的输入框 + 保存；工作区行标「默认目录」，项目行显示版本控制。
- 项目动作只有「改名」「移除」；「移除」弹窗说明：从列表和派活里消失、磁盘不动、
  历史任务/会话都还在、可在「已移除」恢复。已移除区可恢复。删掉了「删除登记」按钮。
- 侧栏：工作区行标「默认」，项目行不再标「不在工作区」；文件浏览按 `projectId` 打开，
  外部项目也能看文件。添加项目弹窗允许任意绝对路径。
- 术语：会话列表「从列表移除」→「归档」（✕ 换成归档盒图标，避免读成删除）；设置页「已移除的会话」→「已归档的会话」。
- CSS：`.proj-card` 改为平级单行（flex-wrap），路径输入 `.proj-path-input`，移除状态淡化。

## 刻意没做

- **项目移除不连带批量归档普通会话**：普通会话没有 projectId 归属（只有派活回执/任务单有），
  做不到"项目内所有会话"；先保证不删任何记录，会话归档仍是独立动作。要按项目归档需先加会话归属，另立项。
- 不做"一个项目多 roots"（ZCode 的项目容器形态）；一个项目仍对应一个目录。
- 不做"完全访问 = 任意路径可写"；边界只随显式登记根扩展。
- 不改审批策略与派单权限。
