## 为什么

- 用户拍板：内部拆单/验收/目标核对不能用外部 CLI，应该用核心 PI。
- 本机 Qoder 国际版二进制已缺失，继续用它拆单会直接失败。
- 用户要求设置页能选模型，并加检测按钮。
- 用户要求“告诉派活的人”：总管/执事要能回答派给谁、什么模型、什么权限。

## 回滚

- `CHANCELLOR_INTERNAL=qoder` → 内部质检回 Qoder CLI（需 Qoder 可用）。
- `EXECUTOR_PROBE=false/0/off` → 检测端点 400，不 spawn CLI。
- `EXECUTOR_CONFIG=false/0/off` → 执行器配置回 env。
- `CHANCELLOR_ENABLED=false` → `delegate_executor` 系统段不渲染，派活工具也不上架。

## 已知边界 / 不确定

- 本机 Qoder 国际版已修复（坏软链 → 1.1.81）；其他机器若路径不存在，
  `runQoderWith` 会明确报“未安装”（不再只留 spawn ENOENT）。本批没有下载/安装新的第三方 CLI。
- 检测是真实小调用，可能消耗少量额度；按钮上已写明。
- OpenCode 只读档的探测回复可能不是 “OK”（本机回了 Plan 模式说明），只要进程成功就判可用。
- Codex 未登录时可能挂起，检测会等 60 秒后回“超时：Codex 未登录时可能挂起”。
- 系统提示 `delegate_executor` 段属于固定前缀，设置一改会失效一次缓存（用户主动改的预期）。
- 内部模型固定用已连接供应商的当前运行时模型，一次普通模型请求；
  不提供 `CHANCELLOR_INTERNAL_MODEL`，也不按单选择不同工人（用户 2026-11-16 明确两项都不做）。
