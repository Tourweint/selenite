# 2026-11-19 元宝搜索回包字段是小写，解析器按大写读导致「0 条」

> 结论：key 有效、上游正常。设置页测试显示「搜索通了，返回 0 条」不是失败，是适配层把每条结果都丢光了。

## 现象

用户在 设置 → 模型 → 搜索 添加元宝搜索并保存 key，点「测试」得到 `ok:true, hits:0`（界面文案「搜索通了，返回 0 条」），看起来像没通。

## 排查（真实请求，非推测）

1. 用 `.data/provider-keys.json` 里的 key 直接 POST `https://api.wsa.cloud.tencent.com/SearchPro`：
   `HTTP 200`，`Response.Pages` 10 条，无 `Response.Error`。**key 与鉴权都没有问题**。
2. 看页对象字段：实际是 `passage / score / date / title / url / content / site / favicon / pics`，**全小写**。
3. `search-vendors.ts` 的 `readYuanbaoPages` 按 `Title / URL / Passage / Content` 读（文档示例与单测都是大写），
   `url` 取不到 → 每行 `continue` → 返回 `[]`；测试端点把「0 条」当成功，于是显示「通了」。

## 改了什么

- `ts/apps/server/src/search-vendors.ts` `readYuanbaoPages`：页对象键统一折成小写再读，**大写回包也照旧认**；
  摘要仍取 `passage`，缺了用 `content`。
- `ts/apps/server/src/search.test.ts` 元宝用例：夹具换成实测的小写形状，另保留一条大写行验证兼容。

## 验证

- `npx tsx --test src/search.test.ts src/search-api.test.ts` → 20/20 通过
- `pnpm typecheck` → 无报错
- 真 key + 真上游调 `callSearchVendor`（`三星堆的由来`）→ 5 条，标题 / URL / 摘要完整
- 服务重启后设置页测试端点 → `{"ok":true,"vendor":"yuanbao","hits":1,"message":"搜索通了，返回 1 条"}`
  （测试 query 固定为「连接测试」、count=1；上游对该 query 返回 9 条）

## 刻意没做

- **没改「0 条算成功」的测试文案**：连通性和「这次没命中」是两件事，目前如实报 0 条；
  若希望对「0 条」加一句提示，属于 UI 文案改动，另开。
- **没动其他源的解析**：只按实测元宝回包修；没有证据表明别家也大小写漂移。
