# 2026-11-23 全站下拉框统一（C 版：浅底行 + 右侧对勾）

## 改了什么

**原生 `<select>` → 自绘面板，渐进增强、调用方零改动。**

- `web/select-menu.js`（新）：
  - 原 `<select>` 留在 DOM 里当唯一数据源（`id` / `value` / `options` / `change` 事件全部照旧），加 `sel-src` 类隐藏；按钮插在它后面，**原样复制它的 className**，高度 / 边框 / 字号 / flex 与 grid 槽位仍由页面自己的 `.set-input` / `.modal-input` / `.font-select` / `.rm-filter-select` / `.archive-select` / `.ctx-select` / `.cs-input` / `.map-window` 管。
  - 面板挂在 `body` 下、`fixed` 定位（卡片与弹窗都 `overflow` 裁剪，absolute 会被切）：宽按内容量、钳 420px / 视口内，下方放不下自动翻到上方。
  - 每次打开时现读 `<select>` 的选项，动态重建（归档页按数据重建项目、模型链换供应商）不需要钩子；`optgroup` 画分组头，`option.disabled` / 整组禁用只画不可点，>600 项截断并提示。
  - 键位：↑↓ 移动（跳禁用项）、Home/End、Enter/Space 选中、Esc 关闭、Tab 移走即关、首字母连续跳转；焦点始终在按钮上，`aria-activedescendant` 跟手。
  - 状态同步：`change` 事件 + 每个 `<select>` 的 MutationObserver（选项重建 / `disabled` / `hidden` / `aria-label`）+ 实例级覆写 `value` setter（外观页「恢复默认字体」这类直接赋值不触发 change，也能更新按钮文案）。
  - 生命周期：`MutationObserver` 发现新增 `<select>` 就增强；整段 DOM 被替换时把对应按钮一并摘掉（弹窗反复开合实测无残留）。
- `web/style-28-select.css`（新，`style.css` 末尾导入）：按钮共通排版 + chevron 留位；面板圆角 12 / `--card` 底 / `shadow-menu` / 淡入；选中行 `--accent-soft` 浅底 + 右侧 `--accent` 对勾，禁用项降透明；`.sel-btn[hidden]` 显式 `display:none`（作者样式的 display 会盖掉 UA 的 `[hidden]`）。
- `web/app.js`：`ensureFlag("UI_SELECT_MENU", true)` 之后再 `initSelectMenus()`——关着时页面就是原生下拉，不做「先绘后撤」。
- `web/ui-atoms.js`：`openModal` 找「首个控件」时排除被藏起来的 `select.sel-src`；增强时如果原 `<select>` 正握着焦点，转给触发钮——否则弹窗打开时的初始焦点会掉到 `body`。
- `src/plugins.json`：新增 `UI_SELECT_MENU`（ui 组，默认开，hot）——**回滚开关**，关 = 不启动增强、刷新后回到原生下拉。`flags.test.ts` 补断言。
- 顺手修一个被这批照出来的老 bug：`select.set-input` 放在 `.modal-field`（column flex）里时，`.set-input` 的 `flex: 1 1 220px` 被当成高度基准，关系温度 / 心情下拉一直是 220px 高。`style-28` 里补 `.modal-field > .set-input { flex: 0 0 auto; }`（与既有的 `.modal-field > .modal-input` 同一条规则）。

## 设计过程（用户拍板）

先出三版设计稿（同一触发器外壳，只差选中态），用真实 token 与三个真实场景（上下文页会话 / 模型页分组备选 / 添加搜索源）在 39847 上比稿：

- **A 派活同款**：选中行主题色加粗，不加勾。最省事，但米黄主题下 `--accent`（#3e4a8c）与正文对比偏弱。
- **B 勾选方框**：每行前面 15px 方框，选中 = 主题色实心 + 白勾。最像「复选框」，但纯单选下拉用方框会暗示多选。
- **C 浅底行 + 右侧对勾**：选中行 `--accent-soft` 浅底 + 右侧主题色勾。单选语义正确、分组与长列表里最清楚——**用户选 C**。

## 为什么这么做

- 2026-11-21 那批只换了触发器上的灰三角（`style-27` 的 data-URI），展开列表仍是系统画的；这版把「触发器 + 列表」一起收进同一套自绘语言。
- 不做 22 处调用方改造：`<select>` 仍是数据源与 change 事件源，`document.getElementById(...)`、`.value`、`options`、`disabled`、`hidden` 全部照旧。任何页面新增下拉也自动被接管（`MutationObserver`），不会再出现「这页是原生、那页是自绘」。
- 面板不进 `.card` / `.modal` 的 DOM：那些容器都有 `overflow` 裁剪（派活页模型面板同款绕法）。
- 单选不用方框（B）：勾选框在多选场景是正确语义，在单选下拉里会让人以为能勾多个。

## 边界 / 没做的

- 只接管单选普通下拉；`multiple` / `size>1` 一律跳过（本仓当前没有）。
- 面板不做输入筛选（派活的模型面板有筛选框，那是它自己的输入框）；>600 项截断。
- 触发钮的 `title` 不复制（原下拉本就没有依赖它）；无 `aria-label` 的字段靠按钮可见文本作为可访问名。
- 回滚是**刷新生效**（`UI_SELECT_MENU` 只在启动时读一次），不是热回收；flush 中已打开的面板刷新即消失。
- 设计稿临时页 `web/select-preview.html` 已在定稿后删除，不进仓库。
