# 模型分工：规划模型与干活模型（2026-11-19）

方案：`docs/设计方案/2026-11-19-模型分工（规划模型与干活模型）.md`。
长期口径：`docs/基线文档/接口文档.md` §6、`docs/基线文档/接口-端点7-权限技能与开关.md` §2.23、
`docs/基线文档/系统架构.md` D33。

## 改了什么

- **两条模型车道**：
  - 规划 / 对话 = 现有默认模型（设置 → 模型，`.data/runtime.json`），总管、执事、
    普通会话、内部拆单/验收继续用；
  - 干活 = 本机内核派活工人（native）单独一条，存 `.data/executor.json` 的
    `profiles.native.model`；留空 = 跟随运行时默认，非空 = 工人单独用该模型。
- **修复两个老 bug**：
  - `chancellor/src/config.ts` 的 `resolveProfile()` 对 native 直接 `return {}`，
    把 executor 设置里填的工人模型丢掉；现在保留 `model` / `modelRoute`。
  - native 留空过去只读启动 env，不跟随设置 → 模型的运行时主选；现在默认跟随，
    `EXECUTOR_NATIVE_FOLLOW_DEFAULT=false/0/off` 回滚到旧行为。
- **跨供应商干活模型**：`profiles.native.providerId` 可选（供应商 id，不是密钥）；
  解析到 route 时建单快照带 `EmployeeProfile.modelRoute={baseUrl,keyEnv}`（keyEnv 只是变量名），
  native 子进程从宿主 env 取 key 设 `CHANCELLOR_LLM_API_KEY`，并设
  `CHANCELLOR_LLM_BASE_URL` / `CHANCELLOR_LLM_MODEL`。找不到供应商 / key 没配 →
  只带模型名，回落启动 env 的地址与 key（服务端 warn）。
- **设置 → 派活 native 卡**：模型框右侧加箭头，展开已连接供应商的模型清单
  （来自 `GET /api/v1/agent/model`，不 spawn CLI）；第一行「跟随默认模型（当前 X）」；
  选中后保存 `providerId`，刷新回显。留空占位改成「跟随默认模型」。
- **知情文本**：系统提示 `<delegate_executor>` 的 native 行改为
  「干活模型跟随默认（X）」/「干活模型 X」/「干活模型跟随启动 env」（回滚时）；
  `delegate` 工具返回的 native 摘要带上实际模型。外部 CLI 的文本不变。
- **分管路径**：`profileEnv()` 对 native 也映射模型路由，分管宰相子进程再派 native 子单时
  靠 env 继承。

## 没改什么

- 普通 Worker 会话（`chatKind=worker`）仍用规划模型；模型 pill 是全局的，硬拆会让显示与实际不一致。
- 外部 CLI（Claude / Codex / OpenCode / CodeBuddy / Qoder）的模型语义不变：留空跟随各自配置。
- 内部拆单 / 验收 / 目标核对仍用规划模型（D26 的 2026-11-16 拍板不翻）。
- 不按人设 / 按任务 / 按项目选模型；不做 native 检测按钮；不做按单覆盖干活模型。

## 契约 / 存储 / 回滚

- `.data/executor.json` 的 `profiles.native` 多一个可选 `providerId`；旧文件没有该字段照常读。
- `GET/PUT /api/v1/agent/executor` 的 `profiles` 形状扩 `providerId`（仅 native 使用）；
  `providerId` ≤100 字符，非法类型 400。其余执行器不变。
- `ticket.options.employeeProfile` 的 native 快照可能带 `modelRoute`（baseUrl/keyEnv，无密钥值）。
- 回滚：`EXECUTOR_NATIVE_FOLLOW_DEFAULT=false/0/off`（只回 native 留空跟随默认）；
  `EXECUTOR_CONFIG=false/0/off`（整层回 env）。

## 已知边界 / 不确定

- native worker 仍只支持 OpenAI 兼容端点；当前 `providers.json` 的供应商都走
  `openAICompletionsApi`（2026-11-19 复核），跨协议供应商不能选给 native。
- native worker 的上下文窗口仍是 `worker-main` 写死的 131072（manager 另算），
  不随干活模型变；选了窗口更小的模型时可能顶到上游上限，要按模型配窗口需另立项。
- 干活模型选了某个供应商但该供应商的 key 没配：route 会被丢弃，worker 用启动 env 的
  baseUrl/key；可能报上游 401，任务汇报会如实失败（不伪造成功）。
- 普通 worker 会话是否也该用便宜模型，本批刻意没做；要做得先解决模型 pill 的全局显示。
