# 2026-11-05 界面第十一轮（任务中心重设计：主视图三列 + 已完结折叠退场）

用户第十一轮需求（"任务中心不知道干啥、做完的太多不该显示——只留进行中+失败待处理，做完/取消的隐藏"）。
探子调查 → 总管设计定稿 → 派 CodeBuddy 一批（K1，纯前端零契约改动），交工实机验收。

## 1. 根因（调查核实）

看板四列里"已完成"与进行中列同等地位且无限堆积（实测 44 张单全在一页，done 13 张占一整列）；
done 数据在 chancellor 永久保留（设计如此），但前端不该把它当"新闻"渲染。
另发现前后端"终态"口径不一致（服务端 TERMINAL 含 idle/needs_you，前端只算三态）——本轮徽标口径顺手校准。

## 2. 设计定稿（用户原则的翻译）

- **主视图 = "现在需要我知道什么"**：三列——排队/等文件（received/planning/planned/idle）、执行中（dispatching/reviewing）、待你处理（needs_you/failed）。
- **做完的不消失，只是退场**：底部「已完结 N 个（已完成 / 已停止）▸」折叠横条（N=done+aborted），点开单列简卡（单号+120字截断+终态徽章+相对时间，弱化样式），点击仍可进详情；展开态存会话内存。
- **空状态会说话**：三列全空显示「没有正在跑的活」+说明句，不再摆空架子。
- **徽标口径校准**：侧栏徽标 = 主视图三列并集显式排除 failed（语义="正在跑的活"；失败单在列里可见但不"在跑"）。旧公式数值相同，变化在语义与可维护性（列调整时徽标自动跟随 TASK_COLUMNS 推导）。
- 看板网格 4 列→3 列；折叠区放看板网格外（窄屏不用横滚到底才能点）。

## 3. 实施（K1，web 三件套）

`TASK_COLUMNS` 三列化 + `TASK_ARCHIVE_STATUSES`（done/aborted）+ `archiveRow/renderArchive/boardEmptyNote`；看板渲染改 main/archive 二分；点击委托扩展到简卡（详情可达）；空列统一「无」。样式全走 token。**保持只读**（取消/重试是接口级改动，单独立项）。

## 4. 实机验收（39847）

- 主视图三列正确（排队 5 / 执行中 2 / 待你处理 24）；**已完成列从主视图消失**（DOM 断言 `heading "已完成"` 不存在）。
- 折叠条「已完结 13 个（已完成 / 已停止）▸」在位；点开 13 张简卡全部列出（单号/截断/徽章/时间），样式弱化。
- 首次截图出现旧四列 = 内嵌浏览器缓存了旧 app.js（cache-bust 后消失）——非产品问题，登记验证方法：改动后验证需带 `?v=` 或硬刷新。

## 5. 遗留

- 取消/重试按钮需后端端点（设计文档预留 `POST /delegations/:id/cancel` 未实现）——单独立项。
- 顶部统计卡仍显示全口径汇总（含已完成 13）——保留（那是"库存"视角，看板是"现在"视角）；用户嫌混可再收。
- "已完结"无分页（当前 13 张折叠条够用；堆积到几百张时再考虑）。
