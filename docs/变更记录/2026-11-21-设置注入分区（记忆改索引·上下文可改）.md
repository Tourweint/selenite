# 2026-11-21 设置页收口「注入」分区（人设 / 技能并入·上下文可改）

> 范围：前端 `ts/apps/server/web/` + `ts/apps/server/src/context-inspect.ts` 的 `SECTION_META` 两行。
> 零新端点、零存储结构、零契约字段形状变化（`editable` 的值有两处变化，见下）。

## 为什么

用户对设置页的定位提了两点：

- 「记忆」这个名字不准确：记忆是**索引**，先挑有用的，再按相关度**注入**；不是存了就全量带上。
- 注入内容要能在**一个页面里改**。当时 Agent → 上下文只读、工具只能改常驻/按需，
  「主要是用来看的，不是用来改的」。

用户同时要求把工具也放进「注入」；同日又追加：

- **人设、技能也收进注入**，Agent 分区只保留「派活」（派出打手 / 默认工人 / 各 CLI 权限）。
- 左栏顺序：注入排第二栏（Agent 组）第一个，后面是模型、派活；技能不再占一级。
- 注入的 tab 按上下文位置排：**人设 → 工具 → 关于我 → 索引 → 技能 → 上下文**。

## 改了什么

### 左栏与路由

- 新增一级分区 **「注入」**（Lucide arrow-down-to-line）：下挂六个人设 / 工具 / 关于我 / 索引 / 技能 / 上下文 tab。
  tab 的 route 就是六页原来的 hash：`partners / tools / about-me / memory / skills / context`，老书签零改动。
- **Agent 分区只剩「派活」一页**（`#/settings/agent`；旧 `#/settings/executor` 别名回来），不再挂 tab 条；
  分区标签从「Agent」改成「派活」，组标题仍是「Agent」。
- `settings-base.js`：`SETTINGS_SECTIONS` 用一条 `inject` 换掉 `about-me` / `memory` / `skills`；
  `AGENT_TABS` 整体删除，`INJECT_TABS` 扩成六条（按上下文顺序）；`tabsMarkup()` 抽成通用，
  `injectTabsMarkup()` 六卡三列两行（窄屏两列）。
- `route.js`：新增 `currentInjectTab()` / `injectTabOfRoute()`；`currentSettingsPage()` 把六条旧子路由认成
  `inject`；删除 `currentAgentTab()`；`executor` 进 `SETTINGS_ALIASES` → `agent`，`avatars` 改落 `inject`。
- `settings-router.js`：`page === "agent"` 直接渲染执行器；`page === "inject"` 六个分支；
  人设 / 技能两块从原分支搬进注入；删除旧的 `skills` 一级分支；新增 `wireInjectTabs()`。
- `app.js`：壳深链合法性检查只留 `SETTINGS_SECTIONS` + `INJECT_TABS` + 别名账。
- `memory-page.js`：`memoryPageAlive()` 改判「注入分区 + 索引 tab」；页名从「记忆」改成「记忆索引」并加一句定位说明。

### 上下文页恢复就地编辑（翻 2026-11-17 的旧案）

2026-11-17 重画上下文页时曾把页内编辑全部撤掉，只留档案页链接。本批按用户新口径加回来，
但**只对用户自己的注入内容**开放，代码固定段仍只读。

- `settings-context.js`：系统行带 `key` / `editable`；行头多一枚「可编辑」徽标；展开后有「改这一节」。
  `canEditSection()` 按角色过滤：总管 / worker 的执事字段 0 槽位、执事的通用 `persona` 槽位都不给入口。
  新增 `openEditorFor()`，保存成功后重拉这一页。
- 新文件 `settings-context-edit.js`：统一宽档编辑弹层，按 section key 写回各自源头：
  - 总管人设 → `PATCH /partners/chief { soul }`
  - worker 人设 → `PUT /agent/worker-persona { persona }`
  - 关于我 → `PUT /agent/user-profile { content }`
  - 执事 SOUL → `PATCH /partners/:id { soul }`
  - 岗位契约四节 → `PUT /partners/:id/contract`（弹层里是整份契约，四节一起写）
  - 当前目标 → `PATCH /partners/:id { currentGoal }`
  - 七个纪律节 → `GET/PUT /partners/:id/discipline`（只合并当前一节；清空 = 这一条不注入）
  - 总管 / 执事 SOUL 不能清空（PATCH 空串语义是「不改」），空值禁用保存并提示。
- `context-inspect.ts`：`SECTION_META` 两处调整——`partner_soul` 标 `editable: true`；
  `current_project` 去掉 `editable`（由会话项目派生，不是可改写的正文）。
- `style-24-context.css`：`.ctx-badge.is-editable`、`.ctx-edit-row` 两条样式。

### 文案与指路

- 「关于我」页的链接改成「设置 → 注入 → 上下文」。
- 执事档案页「记忆怎么被召回」弹层改成「设置 → 注入 → 索引」/「去索引页」。
- 工具池标题悬停补一句：工具名 / 描述 / 参数是代码资产，这里改不了；按人能不能用去人设页。
- 旧注释里的「设置 → 记忆 / Agent → 上下文」路径同步。

## 契约影响

`GET .../context-inspect` 与 `GET .../context-defaults` 的 `section.editable` 是可选布尔，
形状不变；值有两处变化：

- `partner_soul`：缺省 → `true`（执事 SOUL 现在可在注入页直接改）。
- `current_project`：`true` → 缺省（不再假装可编辑）。

已回写 `docs/基线文档/接口-端点1-对话与兼容层.md` §2.2.4 / §2.2.5 与 `接口文档.md` 的环境变量表。

## 刻意不做

- 不新增统一写端点：五个源头各有自己的端点与护栏，复用即可。
- 不在这一页改记忆正文：记忆是抽取产物；要改就标过时重记。
- 不改工具描述 / 参数：提示词前缀资产，改文案走代码。
- 不把按人工具勾选搬进来：仍在「注入 → 人设 → 某人 → 能用的工具」。
- 不恢复请求历史 / 时间线；不自动应用整理建议。

## 生效边界

- 前端是静态直发 `web/`，刷新即生效（桌面壳会缓存静态 JS；验收前 `?v=` 或重开页面）。

  `current_project` 与执事字段 0 槽位不会给编辑入口；但执事的 `partner_soul` 行要重启后才会出现
  「可编辑」徽标（编辑器本身已经能处理这个 key）。
