下沉：契约 → `接口-端点4-执事例行与自主轮.md`（投影 / PATCH / 存储三处）；机制与取舍 → `系统架构.md` D23；env → `接口文档.md` §6。

## 改了什么

上午批次（另一会话）把项目记忆挂载做成"建会话那一瞬间读全局当前项目"的隐式快照，用户拍板改为**挂载跟人走**：总管 / 执事档案加 `projectId`，人设二级页选"负责项目"，对该人格全部对话生效；worker 干活会话保持文件夹挂载，普通杂事会话不挂。

- **契约**（`packages/shared/src/index.ts`）：`PartnerProfileSchema` 加纯增量可选 `projectId`（uuid nullable optional）。
- **存储**（`partner-store.ts` / `partner-types.ts` / `partner-rows.ts`）：`partners` 表加 `project_id TEXT`（CREATE TABLE + 旧库 PRAGMA 补列，老行读 null）；`setProjectId` 一条 UPDATE 不版本化。
- **端点**（`companion-api.ts`）：PATCH 收 `projectId`（省略不改 / null 清 / 字符串必须命中已登记项目含归档，未知 400 整批不写）；列表与详情投影带 `projectId`；`PARTNER_PROJECT_MEMORY=false` 时投影与回显整字段不出现。
- **开关**（`partner-contract.ts`）：`partnerProjectMemoryEnabled()`（缺省开，`false`/`0` 关）。
- **解析**（`agent/project-scope.ts`）：纯函数 `personaProjectIdOfSession(store, sessionId, kind)` + 两个会话面包装（同步版走 30s TTL 缓存给每轮注入，async 版直查给工具路径）；kind 判定与 `chatKindOfInternal` 同语义（显式 worker 才是 worker）。`ChatKinds` 快照源由 `lifecycle-harness.ts` 注入（`setChatKindsSource`），模块保持零重依赖（只新增 partners.ts / partner-contract.ts——都在 tools.ts 既有加载面里）。
- **召回**（`agent/assist.ts` recallContext + `tools.ts` recall 工具）：人格挂载的项目键空间并进候选（与文件夹挂载并列，互不覆盖）。
- **写入**（`tools.ts` remember）：`scope=project` 解析改"文件夹优先、人格挂载兜底"，两路全空时的报错改成引导话术（去人设页挂）。
- **前端**（`web/partner-profile.js`）：人设二级页「岗位」段加**负责项目**块（下拉选项目 + 独立保存，独立 PATCH 不与 SOUL / 目标混批；已归档项目只在现挂时补进下拉；开关关整块不渲染）。

## 为什么这样改

- 挂载决定从"建会话"挪到"建人格"：身份长期、挂一次管所有对话，会话不用再做选择（用户原话痛点："这个会话挂在项目下还是不挂，怎么确定"）。
- worker 吃总管挂载是错的（干活会话的记忆跟文件夹），所以 kind 判定必须把 worker 排除。
- 总管在花名册里本就是正式档案（`CHIEF_PARTNER_ID`），一份机制同时覆盖总管与执事。

## 刻意没有（方案 §7）

会话级手动挂载、+ 旁加项目选项、Agent 自动判断 / Agent 挂载工具、整理碰项目 scope、手机端展示"负责项目"、记忆页项目分组。
