# 2026-11-24 开场问候请求可见性

方案：`docs/设计方案/2026-11-24-开场问候请求可见性.md`。

## 改了什么

- **新只读端点** `GET /api/v1/partners/:id/greeting`（`src/companion-api.ts`）：
  `{ok, enabled, conversationId}`。在 durable `Chats.byExternal` 里按
  `task-greeting-<canonical内部id>-<attempt>` 匹配、取最大 attempt；没有 canonical 会话 /
  没生成过 → `conversationId: null`。不建会话、不改公文 doc、不调模型。
  回滚：`CHAT_CONTEXT_INSPECT=false` → 404（与上下文页同一行）。
- **人设页新增「一次性请求」区**（`web/partner-profile.js`）：一张「开场问候」卡；
  点开弹层按「已生成 / 还没生成 / 问候开关关着」三种情况给文案，已生成时给按钮
  「在上下文页看这次请求」。
- **上下文页支持深链**（`web/settings-context.js`）：
  `#/settings/context?chat=<外部id>&label=<显示名>` 把不在会话清单里的会话合成一个临时选项
  并优先选中；不并入 `state.chats`、不列其它 `task-` 会话。深链缺席时页面行为逐字不变。
- **口径提示（2026-11-24 追补）**：人设页的卡与弹层、上下文页该会话的顶部提示都写明
  「服务端替助手发起的一次性请求（类似定时任务到点自跑）；首条请求是冷前缀，
  命中率 0 / 第一次打开稍慢属预期；只跑这一次」。免得把这条冷请求当成「缓存掉了」或每轮注入。
- **打开时的等待提示（2026-11-24 追补）**：点执事花名册打开时，若 `GET /partners/:id/greeting`
  显示还没有生成过问候，先弹一条 15 秒的提示「第一次打开会先写一句开场问候（一次模型请求，
  稍等几秒）」。`toast()` 加了可选时长参数（缺省 3.8s，旧调用方行为不变）。
  已生成过 / `PARTNER_GREETING_ENABLED=false` / 旧服务没有该端点时都不弹，不打扰正常打开。
  仍保持**同步生成**：改成后台生成要补一条「晚到的消息怎么推到已打开的会话」的通道，
  为一次性的等待不值得；创建时的等待本来就是设计的一部分（`/open` 等问候写完才返回）。

## 为什么

开场问候生成跑在隐藏会话 `task-greeting-<canonical内部id>-<attempt>` 里
（`partner-runtime-do-open-partner-conversation.ts:194`），那次请求的系统提示词
（当前 SOUL + `GREETING_REQUIREMENTS`）、用户消息（`GREETING_REQUEST`）、工具面（空）与
token 用量都在 durable；但上下文页的会话下拉只列 `listChats` 的会话，`task-` 前缀全部被排除
（`agent/session-index.ts:359-361`），所以这一页从来没读到过它。正式会话里只有一条
`usage=0` 的 `pi.assistant` 写回，请求列表又按 `promptTokens > 0` 过滤
（`request-stats.ts:196-197`），因此也看不到这次请求。

这次只补「入口」：请求正文仍由已有的 `context-inspect` / `requests` 只读链路提供，
不复制第二份记录，不改问候生成 / 投递，不把隐藏请求混进正式会话的请求列表。

## 已知边界

- 只覆盖开场问候这一条隐藏请求；例行 `task-routine-*`、唤醒、池 / 隔离生成会话**不列**，
  要做另立项（方案 §三）。
- 深链只给「这一次渲染」合成选项；页面重渲染时仍会按 hash 重新选中它（深链本意）。
