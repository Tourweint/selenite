# 首页问候语换句动画（旧句淡出、新句淡入）

**日期**：2026-11-19。
**范围**：纯前端（`web/shell.js`、`web/style-04-chat-base.css`、`web/app.js` 仅注释）；不碰契约、不碰服务端。刷新即生效。

## 问题（2026-11-19 用户反馈）

问候语换句（接 2026-11-18 的句池丰富）是一瞬间硬切，希望"消失，然后又出现，渐渐消失，然后出现那种"。

## 改了什么

- **`shell.js`**：`syncGreeting` 检测到换句后不再直接写文本，改走 `swapGreetingText(line)`：
  - 挂 `.greet-out` → 旧句 280ms 淡出 → setTimeout 到点换文本 → 摘类 → 新句 280ms 淡回。
  - `greetingSwapToken` 单令牌防重入：280ms 窗口内又来新句时，旧定时器作废、文本归最新一次写。
  - `prefers-reduced-motion: reduce` 时跳过动画直接切文本（matchMedia 模块级缓存，同 ui-atoms 口径）——
    否则 CSS 过渡被关掉后会变成"消失 280ms 再闪现"，比不动画更糟。
  - 节点始终是同一个（`#empty` 被 chat-thread.js 摘下/挂回时引用不失效），detached 期间定时器照写文本无害，
    反而保证重新挂回时文本已是新的。
- **`style-04-chat-base.css`**：`.empty p.empty-greet` 加 `transition: opacity .28s ease`；
  新增 `.empty p.empty-greet.greet-out { opacity: 0 }`（选择器带全前缀，压过 `.empty p` 的 (0,1,1)，
  这个坑 2026-11-07 注释里记过）；`@media (prefers-reduced-motion: reduce)` 里 `transition: none`。
  时长与 `shell.js` 的 `GREET_OUT_MS = 280` 是一对，注释互相点名，改要一起改。
- **`app.js`**：跨段每分钟轮询那条注释补一句"换句带淡出淡入"，避免注释停留在"不会闪"的旧口径。
- 触发时机不变：页面加载占位符→实际句、重回首页空态、每分钟轮询撞上跨段（app.js:204 的既有定时器）。

## 验了什么

- `node --check`（shell.js / app.js）过。
- 浏览器真机（IAB，127.0.0.1:39847）：新建对话进首页空态，凌晨 0 点正确落在夜段、显示 6 句池新句；
  CSSOM 里 `.greet-out` 规则、`transition: opacity .28s` 都在；加载期换句端到端走通
  （占位符「说吧，我在。」被换成夜段句，只有 `swapGreetingText` 的定时回调真跑完才可能写出）。
- **视觉三连拍**：基线句子清晰 → 挂 `.greet-out` 450ms 后句子淡成残影 → 摘类 450ms 后完全恢复。
- 没验成的：真实鼠标点击（IAB 自动化点击通道失灵，用的 evaluate 派发，见既有记录）；
  当场等到真实跨段边界没等到（跨段触发链路与加载期共用同一函数，风险低）。

## 排查插曲（记给后来人）

IAB 的 `playwright.evaluate` **第二参传不进**（fn 里恒 undefined，类没加上，表象像 CSS 失效）、
**`getComputedStyle` 读陈旧值**（内联 opacity:0 都读回 1）、`document.styleSheets` 只见 @import 入口表
（找规则要钻 `CSSImportRule.styleSheet`）——三者叠加出"过渡没生效"的假象，最后靠截图三连拍定案。
已记入会话记忆。
