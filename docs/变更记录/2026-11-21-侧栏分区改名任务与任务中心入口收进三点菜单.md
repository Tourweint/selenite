# 侧栏分区改名「任务」与任务中心入口收进 ⋯ 菜单

日期：2026-11-21。纯前端（`web/` 四个 JS + `index.html`），不动契约、不动服务端。
用户口径：侧栏「对话」这一列实质就是活计，直接叫「任务」；不属于任何人的内容归一类，不要混在人物组里。

## 改了什么

1. **分区改名 + 换图标**：侧栏分区头「对话」（聊天气泡）→「任务」（清单图标，Lucide list-checks）；
   收起轨道对应圆钮、悬停卡容器与相关 aria-label 跟着改（`index.html`）。
2. **「打开任务中心」收进分区头 ⋯ 菜单**：分区底部文字链接 `#sec-tasks-all` 退役
   （`index.html` 删按钮、`dom.js` 摘引用、`tasks-live.js` 摘接线），⋯ 菜单追加第三项
   （`shell.js`：新建对话 / 搜索旧对话 / 打开任务中心）。`#/tasks` 路由不变。
3. **归属翻案（`chats-groups.js`）**：2026-11-15 设计案里「普通对话派活归总管」（当时的理由：这类单极少），
   用户翻案为「被我创建的东西归为一类」。普通对话（worker 会话）里派出的单改归「其他」组，
   与用户自己的普通对话同组；总管会话派的 / 宿主解析不到的仍归总管。
   判定纯前端：`hostConversationId` 对照 `state.chats` 里 chief 会话清单；**契约 `dispatchedBy`
   两值（chief / 执事 uuid）不变**，服务端零改动。组名「其他对话」→「其他」。
4. **空态小修（`tasks-board.js`）**：`renderSideListEmpty` 判空只认 `.chat` 行、漏任务行——
   只剩任务行时「还没有对话」提示会出现在分组下面，与 2026-11-15 设计口径
   （普通对话行 + 任务行都为零才出现）不符，补上 `.task-row`；文案随分区改名。

## 明确不做

- 轨道悬停卡不加「打开任务中心」：2026-11-13 用户拍板任务中心不进轨道，卡底保持新建 / 搜索两项。
- 服务端 `dispatchedBy` 不细分 chief / user：改枚举就是契约变化（接口文档 + 两端），收益撑不起成本；
  前端用已有的 `hostConversationId` 判定足够。

## 当晚补：二次翻案——「其他」组常驻

用户实测反馈「我现在创建了一个新对话，还是这个……咱们这个在其他区域里，那这个也没有啊」。
根因有两层：① 11-15 口径"一条任务都没有 → 平铺渲染、不套文件夹"（`renderChats` 的 taskChats 闸），
用户身边没活单时整组结构全消失；② 服务 19:17 已重启（tasks 键已下发），但名下活单为 0——
此前派的单全部终态、被自动归档收走，`tasks` 键是空数组，人物组本来就不画（空组不画）。
翻案 ①：**「其他」组常驻**，普通对话永远待在「其他」里（`renderChats` 无条件走 `renderGroupedChats`，
平铺路径退役）；空组仍不画（没有任何行才出空态一句话）。②属既有口径不翻：侧栏任务组只收
还没被自动归档收走的任务专线，历史单去任务中心归档页。
验证：刷新后「其他 3」组出现（三条普通对话含新建的在内）、组头收起/展开正常、`tasks:[]` 实抓确认。

## 当晚补 2：组体展开/收起高度动画

用户点名「点开其他组要有动画，别人的组也要」。照顶层分区 `.side-sec-body` 的既有一套
（grid 1fr↔0fr；展开 240ms 减速 / 收起 160ms 加速 / 收起透明度压在末帧归零，取舍见 style-03 注释）
落到 `.chat-folder`：结构改两层（`.chat-folder-fold` 轨道层 + `.chat-folder-body` 兼裁切层），
开合状态载体从 `body.hidden` 换成 `.chat-folder.is-closed`（`display:none` 会杀过渡）。
`folderSection` 一处改动，其他 / 总管 / 各执事全部组同一动画；组头箭头旋转已由同日箭头统一批
（style-27 `.chev`）覆盖，零改动。`prefers-reduced-motion` 直切兜底同款。
验证：合成开合后 `getAnimations()` 出现 grid-template-rows / opacity 的 CSSTransition（规则命中）；
inline 关过渡直切读终态 = 收起 foldH 0 + opacity 0、展开复原、localStorage 折叠记忆正常
（IAB 无人盯时动画钟不走，逐帧采样不可用——老坑照旧）。

## 当晚补 3：行尾三颗悬停图标收成一颗 ⋯

用户口径「重命名 / 归档 / 置顶这三个小图标都取消——要么做成右边三个点，要么留一个归档，自己选」。
选了 ⋯ 菜单：三个动作一个不少，且与本周方向一致（分区头 / 项目行 / 定时任务行都已收成一颗 ⋯）。
普通对话行（`buildChatRow`）尾部的 ★ / ✎ / 归档盒三颗图标退役，换行尾一颗 ⋯
（`.chat-act.chat-more`，hover 才出现，几何占位不变），菜单走 `openSecMenu`
（重命名 / 置顶 / 归档，与右键菜单同一份口径；壳里自动落原生小窗）。改动面：
- 忙态改在**打开菜单时现算**（建行快照会过时），`data-chat-archive` 联旗退役；
  `setSending` 里原来顺带做的「开跑时收掉行内归档确认条」保留为无条件调用。
- 右键菜单不变（⋯ 与右键互为两个入口）；收起轨道浮卡的 compact 菜单不变；
  任务专线行本来就不带这些动作（动作在任务中心，11-15 口径），不受影响。
验证：新标签页实测——每行 1 颗 ⋯、0 颗旧图标；合成点击 ⋯ → 菜单出「重命名 / 置顶 / 归档(带提示)」、
aria-expanded 正确、不触发行跳转；悬停截图确认视觉。注意抓包时区分新旧标签页
（用户正开着的页还是旧 JS，截图会拍到旧图标——先探测 `.chat-more` 再动手）。

## 当晚补 4：菜单分隔线虚胖根修 + 对话行菜单解释行退役

用户实测「归档离重命名/置顶太远，中间像被截断；定时任务 ⋯ 的删除也一样」。
根因**不是**给删除留空间：`.sec-menu-sep` 的元素是 `<span>`（sec-menu.js），行内元素不吃
`height: 1px`，空的 inline span 按父级 line-height 撑成 ~20px 空盒 + 上下 4px margin
= 28px 大空档。该 bug 自 2026-11-14 建菜单起就存在，凡带分隔线的 ⋯ / 右键菜单全部中招。
修法：CSS 加 `display: block`（`.sec-menu-sep` style-03、`.proj-menu-sep` style-14 同款同修；
`plus-sep` / `proj-sep` 建的是 div 无恙；壳原生菜单 popovers.go 画的就是真 1px，不涉此坑）。
解释行同步退役（用户口径「就重命名、置顶、归档三个就行」）：对话行 ⋯ 与右键菜单的归档项
不再带 hint（忙态用灰置表达，确认条 / 400 toast 兜底不变）；项目菜单的新建/添加 hint
是 2026-11-14 用户拍板过的差异说明，未动。
验证（DOM 量测，IAB 截图拍不到后挂的 fixed 浮层——老坑）：分隔线 h=1px、与相邻项间隙 4px/4px
（修复前 20px 盒 + 4/4）、归档单行 35px（修复前 52px 双行）、菜单总高 154→123px。

## 已知边界

- chief 宿主清单取自 `state.chats`（近 50 条活跃会话）：更早 / 已归档的总管会话派的单会被误归「其他」组。
  旧单本就沉底， cosmetic 级误差，不值得为此动契约。
- 组折叠键仍是 `lifediary.chatFolders` 的 `other`（键没换，用户已收起的组不跳回展开）。
