## 改了什么

### 数据与配置

- 新增 `.data/providers.json`（`PROVIDERS_PATH` 可改），**无密钥结构**：
  `{ schemaVersion:1, providers:[{id,name,baseUrl,keyEnv,models[],createdAt}], defaultSelection }`。
  zod `.strict()`，并显式拒收 `apiKey` / `key` / `headers`（文件与 POST 请求体都拒，不是静默丢弃）。
  `id` 小写 slug（`faux` / `mock` 保留）、`keyEnv` 只接受环境变量名；写入走临时文件 + rename。
- 首启播种：文件不存在且有 `LLM_API_KEY` 且不是 faux → 把 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` / `LLM_MODELS`
  写成默认供应商 + `defaultSelection`，日志说明「env 仅播种，此后以文件为准」。faux / 无 key 不播种。
  `LLM_MODEL_FAST` 不入文件，仍从 env 读。
- 文件损坏 / 目录只读：启动告警并回退 env-only；运行期坏文件保留上一份可用配置（不静默换端点）。
- `PROVIDERS_CONFIG=false`：忽略文件、不播种、纯 env（回滚开关）。
- `runtime.json` 改为 `{model:{providerId,modelId}}`，旧裸 id 仍按默认供应商读；选择优先级
  runtime.json > `defaultSelection` > 第一个供应商。降级回旧代码会丢选择（已写进接口文档）。

### 服务端

- `provider.ts` 重写：
  - **单例 `Models`**：Harness 拿 `currentModels` 访问器，每次访问先查 providers.json 的文件签名/代数，
    变了才 diff 应用 `setProvider` / `deleteProvider`；不每请求重建，也不缓存陈旧目录。
  - 派生模型（`#think-on|off`、任务 `#t…`）按 **`${providerId}|${id}`** 分键，基座模型消失时自动清理；
    换 baseUrl / keyEnv 后同一派生 id 会按新基座重建（请求打新地址）。
  - `chatModelRef` / `applyChatMode` / `syncConversationModel` / `switchThinkingOnTool` 全部改成
    `providerId + modelId` 成对比较：同名模型跨供应商一定触发重配。
  - `syncConversationModel` 对齐失败（例如旧会话引用已删供应商）**真正回退默认供应商**，不再继续拿旧引用打 404。
  - CRUD 不变量：默认 / 当前选中供应商删除 → 400；编辑移除当前（或默认）选中的模型 → 400；改 id → 400。
- 新端点（接口文档 §2.8 / §2.10）：
  - `GET /api/v1/agent/model`：`{current,providers:[{id,name,models,hasKey}]}`，不含 baseUrl/keyEnv；
  - `POST /api/v1/agent/model`：接受 `{providerId,modelId}`，兼容旧 `{model}`；响应保留 `model/models` + 新增 `provider`；
  - `GET /api/v1/agent/providers`：设置页投影，多 `baseUrl/keyEnv/isDefault`；
  - `POST /api/v1/agent/providers`：新增/更新；`modelsUrl` 仅本次请求用（5s 超时、≤1MB、三种响应形状），
    `test:true` 不写文件（只证「钥匙已就位」）；
  - `DELETE /api/v1/agent/providers/:id`。
  - CORS 增加 `DELETE`。
- `/healthz.models` 语义收窄为**默认供应商的模型清单**；web 服务页改走新端点。
- 删除 `openai-compat.ts` 的 `upstreamConfig()` / `upstreamModelId()` 死代码。

## 已知未解决

- **phone 探针的 `[done]` 断言失败**（与本批无关）：任务单报告 `ready`、`result.md` 也落盘，
  但整单因「缺少执行前快照，无法确认声明路径是真的新增 / 修改 / 删除过」被判 `needs_you`。
  这是 2026-11-04「验收以文件实际变更为准」（批次四）与手机通道不产生快照之间的规则冲突；
  本轮没有改验收逻辑（不在图纸范围），如实登记。
- `providers.json` 的 `defaultSelection` 目前没有修改端点（只能删除/新建后按第一个模型兜底）；
  图纸只要求"默认模型选择行"，没有要求改默认供应商。需要时另立方案。
- 逐模型元数据（窗口/价格）未做；自定义供应商统一 `contextWindow=131072 / maxTokens=4096`。
