# 任务中心看板 + 对话派单提示（2026-11-04）

## 做了什么

### 1. 后端补了一个只读列表接口

`GET /api/v1/tickets?domain=&limit=`（[delegation-api.ts](../../ts/apps/server/src/delegation-api.ts)）。

为什么补：原 §2.9 只有 `domains` 与 `tickets/:id`。`domains` 只给计数、不给 id，
看板首屏没法枚举任务单；只靠 SSE 的话刷新一次就空了。新接口跨顶层 `workRoot/`
与各领域 `runs/` 扫 `ticket.json`，按 `updated_at` 倒序，只吐界面需要的字段
（不带绝对路径）。契约已回写 `docs/基线文档/接口文档.md` §2.9。

### 2. 任务中心页（`ts/apps/server/web/`）

- 入口：侧栏底部「任务中心」（与「设置」同一区、同一 `.side-item` 样式，带进行中数量徽标）；
  侧栏收起或窗口 ≤800px 时走 `.side-rail` 的 `rail-tasks`，两种形态都能点到。
- 路由：`#/tasks` 看板，`#/tasks?ticket=<id>` 详情；Esc 先退回看板、再退回对话。
  任务中心**保留侧栏**（入口和回对话都在那儿）；设置页仍隐藏侧栏，行为没改。
- 看板：四列 = 排队/等文件、执行中、待你处理（含失败待看）、已完成；
  `needs_you` 卡片整卡琥珀描边；顶部五格统计（进行中/待你处理/失败待看/已完成/领域）。
  可用宽度不够时四列横向滚动，卡片不被挤扁。
- 详情：状态、领域/项目、任务进度、任务列表、子任务单（可点进子单详情）、最近 6 条验收记录；
  失败原因与「等你」原因用琥珀/红条单独标出。
- 三态：加载（首次扫描）、空（引导回对话派活）、失败（404 提示版本旧 / 500 给重试），都不白屏。
- 视觉全部复用现有 token：`--accent` / `--c-tertiary` / `--c-error` / `--card` / `--divider` /
  `--r-*`，没有新增调色板；卡片、统计格、状态小片都挂了 `.18s ease` 颜色过渡。
- 用词只用：助理 / 负责人 / 执行者 / 任务单 / 待你处理（雇员类型作后缀，如「本机执行者」）。
- 只读：没有改派、没有手动停止、没有悬浮面板、没有头像。

### 3. 对话里的派单提示

- 收到 `delegate` 事件（带 `ticketId`）后，在该轮回复下方挂一条胶囊链接：
  受理阶段「任务已派发，可在任务中心查看。」，后续按 `phase` 更新为
  「已完成 / 需要你处理 / 没做成 / 已中止」，同一任务单只保留一句。
- `attention` 卡片加上「去任务中心处理」链接，不再只有一句纯文本。
- 历史消息里的任务单号（`t-202608…-xxxx`）在 markdown 渲染时自动变成 `.ticket-link`，
  刷新后点「【任务 t-…】已完成」也能直接进详情。

### 4. 自动更新、筛选排序与窄屏（2026-11-04 第二轮，只动 `web/`）

- **自动更新**：
  - 对话流仍在跑时，`delegate` / `attention` 到达即按 `ticketId` 增量更新内存（新单先放临时卡），
    再 900ms 防抖拉一次列表，用落盘数据替换临时摘要；
  - 没有对话流时低频轮询兜底：看板 20s、对话页只更新徽标 60s；页面隐藏时暂停，重新可见立即补一次；
  - 自动刷新详情页时**不重绘 DOM**（只更新内存与徽标），滚动位置和展开状态不受影响；
    看板重绘前记下 `.tasks-scroll` 的横/纵滚动量，重排后原样放回。
- **筛选与排序**：顶栏新增「全部项目」与「最近更新 / 按状态」两个下拉；项目选项来自
  `GET /api/v1/projects`，并补上任务单里出现过的项目名（已归档项目的历史单也能筛出来）；
  筛选/排序写进 hash（`#/tasks?ticket=…&domain=…&project=…&sort=…`，用 `replaceState` 不留历史），
  刷新或重进页面自动恢复。
- **窄窗与触屏**：≤800px 顶栏允许折成两行、看板保持四列横滚；≤560px 隐藏标题副文案、下拉按宽度折行；
  `pointer: coarse` 下轨道按钮 44×44、下拉与刷新 40 高，卡片保持 248 最小宽度。
- **三项新字段兜底**：`lastAction` / `waitingOn` 在卡片上、`lastAction` / `waitingOn` / `lastHeartbeat`
  在详情里都按「有就显示、没有就不渲染」处理。后端已把这三项带进接口（2026-11-04 实测返回字段、老单值为 `null`），
  老单不会留空行，新单落盘后自然显示。

## 验证

两轮都是真起服务（`pnpm --filter @lifediary/server dev`，127.0.0.1:8082）+ headless Chrome。
第二轮补的自动更新/筛选/窄屏用 CDP 拦截造事件或造数据，**下面逐条标明是真的还是造的**。

**真数据链路（第一轮）**
- `/api/v1/tickets` 读到本机 `runs/` 里 36 张真实历史任务单（16 进行中 / 9 待你处理 / 7 失败 / 13 已完成）；
- 看板四列计数 5/2/16/13 与列表一致；点第一张卡进详情，读到真实任务列表与验收记录；
- 详情 404（不存在的 id）落到「找不到这张任务单」并给返回按钮。

**真数据链路（第二轮）**
- 自动轮询：不点刷新，27s 内多出来的那张卡自动出现（轮询的定时器与请求是真的，新增单是代理后注入的）；
- 详情不被打断：停在 `#/tasks?ticket=<真实 id>` 等 20s+ 轮询，详情只发了 1 次请求，DOM marker 未丢、`scrollTop` 180 → 180；
- 看板滚动保持：1520 下 `scrollTop` 240 刷新后仍 240；760 下 `scrollTop` 240、`scrollLeft` 300 刷新后均不变；
- 顶栏：真实 `/api/v1/projects` 返回 0 个项目、真实任务单 `project` 全为 null，所以真数据只有「全部项目」一项；
- 排序：对真实 36 张单切「按状态」，9 张 needs_you 全排在 7 张 failed 之前；
- 窄窗：760 宽侧栏 36 轨道、看板 1040 内容 / 712 可视、卡片 248、文档无横向溢出；
  390 / 375 宽 `pointer: coarse` 命中、轨道按钮 44、下拉 40 高、刷新 51×40、看板 1038 内容 / 342 或 327 可视、可拖横滚；
  两种宽度下点侧栏「任务中心」入口都能进 `route=tasks`。

**造数据（已标明，不是真链路）**
- 失败态：CDP 拦截列表接口返回 500；空态：拦截返回 `tickets: []`；
- 新单出现（SSE）：拦截 `/api/v1/agent/chat` 回放合成 SSE（`delegate` accepted → running、`attention`、`done`）。
  走的是页面真实的事件处理与渲染代码，卡片 500ms 内出现（摘要「合成：刚派出去的任务单」、needs_you、
  `最近 正在改任务中心` / `等文件 ts/apps/server/web/app.js`），900ms 后防抖对账为列表真实摘要与 dispatching；
- 项目筛选：给列表追加两张 `project=fixture-project` 的合成单，筛出 2 张；hash 变
  `#/tasks?project=fixture-project&sort=status`，重载后项目与排序都自动恢复；
- 三项新字段：真实详情没有「最近 / 等文件 / 心跳」三行（兜底生效）；合成详情里三项都显示，
  且 18 个任务 / 4 张子单 / 6 条验收、`scrollTop` 180 在自动刷新后保持。
- 没有跑真实模型派单（会起真执行者、跑真命令），所以「模型自己决定派活」这一段仍未实测。

其它数值：
- 深色主题下 `tk-chip` 过渡 = `background-color, border-color, color 0.18s`；
  卡片颜色从 `rgb(246,241,231)` 过渡到深色档，无硬切。
- 回到对话页：主区 `top=40 / bottom=899`、左上圆角 16px、文档无溢出（上一轮的 40px 问题没回归）。

命令：`node --check ts/apps/server/web/app.js`、`pnpm typecheck` 均通过。

## 没做 / 未验证

- 自动更新只在页面前台生效：`document.hidden` 时暂停轮询，切回来补一次；没有做 SSE 断线重连（沿用原有流的行为）。
- 详情页的自动刷新只更新内存与徽标，**不重绘详情内容**——正在看的长任务进度要等下一次手动进详情才更新。
- 项目筛选用合成数据验证：本机 `/api/v1/projects` 真实返回 0 项、真实任务单 `project` 全为 null，
  真实项目下的筛选行为还没在真数据上跑过。
- 触屏只在 Chrome DevTools 的移动模拟（`pointer: coarse`）下验证，没上真机。
- 9 张 needs_you 排序与 `STATUS_ORDER` 一致；但真实数据没有 `aborted` 单，这一档的排序未实测。
- 真实模型驱动的「派单 → 看板出现新单」未跑。
