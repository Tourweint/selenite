## 一、执事履历升级：经验层 `experience`

- `MemoryKind` 加 `"experience"`（`packages/memory/src/types.ts`）。语义 = 「这类活下次可以怎么做」，
  与 `work`（这单发生过什么）分工：**进召回、不衰减、参与合并**。
- 写入点：`work-record.ts` 的 `recordWorkSettlement`，只在 `status=done` 且过价值门槛时写一条
  `id=experience:<票号>` 到同一 `partner:<id>` scope（稳定 id，终态重入不重复）。
- 门槛（确定性，不调模型）：结果行 ≥40 字 + 含至少一个动作词（改 / 写 / 读 / 跑 / 查 / 整理 / 合并 /
  删除 / 替换 / 核对 / 回滚等）；内容 = `下次同类活可以这样做：<结果行>`。不过门槛一条都不写。
- 召回：与 fact 同组、打分 ×1.08；`recall` / `touchRecall` 对 experience 不做时间衰减；
  会话封顶修剪 `protectKinds` 加 experience（顺手把 `work` 也纳入保护——履历有自己的 200 条封顶，
  不该被通用会话修剪静默删掉）；`list` 排 fact 之后。
- 开关 `PARTNER_EXPERIENCE`（默认 true）：false → 只落 work，一个字节经验都不写。
- 单测：`partner-work.test.ts`（门槛 / done 才写 / 重入不重复 / 开关旁路）+ `memory` selftest §18
  （召回 / 不衰减 / 合并 / 修剪保护）。

## 二、召回注入 proactive 分组

- `InjectOptions` 加 `proactive?: boolean`；`buildContext` 在【偏好】【打算】【其它】之后加第四组
  `【也许值得提起】`：importance ≥ 0.7、距 `lastRecalledAt ?? createdAt` > 7 天、与当前话题无关键词
  交集，最多 2 条、每条 ≤80 字；被挑中的从【其它】移走，不重复出现。
- 开关 `MEMORY_PROACTIVE`（默认 **false**）。装配在 `agent/assist.ts` 的 `recallContext`：
  只有总管主对话传 true；执事轮一律不注入（`memory-proactive.ts` 纯函数）。
- 单测：selftest §19（进组 / 新记忆不进 / 直接相关不进 / 最多 2 条 / 长度 / 默认关）+
  `memory-proactive.test.ts`（默认关 / 显式开 / 执事轮不注入）。

## 三、记忆巩固两阶段：usage 排序 + 未用淘汰 + 审计 diff

- `MemoryRecord` 加可选 `usageCount` / `lastUsedAt`；SQLite 两列（旧库 ALTER 补列），
  `InMemoryStore` 同口径；召回命中时与 `recallCount` 同点 +1 / 置 now。
- 新纯函数 `consolidateScope(store, scope, { now, usageRanking })`（`packages/memory/src/consolidate.ts`）：
  - 保留优先级 = `usageCount` 降序 → `lastUsedAt` 降序 → `createdAt` 降序；
  - 合并建议 = 同 kind + 规范化等价（work / intention 除外）；
  - 淘汰建议 = >90 天未用（`lastUsedAt ?? lastRecalledAt ?? createdAt`）、importance < 0.5、
    kind 不在 preference / experience / work（有效 intention 同样豁免）；
  - 产出 `{ scope, generatedAt, kept, merged[], retired[] }`，**只读，不改库、不删**。
- 服务端 `memory-consolidate-pass.ts`：读 `MEMORY_USAGE_RANKING`（默认 true），把 diff 原子写
  `.data/memory-consolidate-diff.json`（`MEMORY_CONSOLIDATE_DIFF_PATH` 可换；只 id / kind / ≤40 字摘要）。
- 端点（`memory-api.ts`）：`POST /api/v1/agent/memory/consolidate/pass`、`GET .../consolidate/diff`；
  `POST .../review` 成功后自动跑一次审计（模型失败不落快照）。
- 单测：selftest §20（usage 排序 / 淘汰只列不删 / kept / 开关回滚 / 使用账 +1）+
  `memory-api.test.ts`（端点、diff 文件形状、库不变、读回、回滚、坏 scope）。

## 四、技能 curator

## 七、已知边界

- 经验层只在派单 `done` 时写，且不做语义总结：内容 = 结果行原样加前缀，门槛是确定性筛子。
- `experience` 被会话封顶修剪保护，partner scope 可能因经验积累略超 `MEMORY_SESSION_CAP`；
  没有单独的经验条数上限（任务书未要求，先不引入）。
- 巩固审计是**快照**不是事务：并发写发生在扫描与落盘之间时，diff 可能少一条；只影响参考文件。
- proactive 只从当轮召回命中里挑，不做二次检索；命中窗口外的旧记忆不会被主动提起。
- 技能用量是进程内同步读写 JSON，并发调用极端情况下可能覆盖一次计数（个人量级可接受）。
- 界面（桌面 / 手机）尚未消费 `usageCount` / `stale` / diff 端点；本批只做后端与契约。
