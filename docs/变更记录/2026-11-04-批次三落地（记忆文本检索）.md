# 2026-11-04 批次三落地（记忆文本检索）

方案：`docs/设计方案/2026-11-04-批次三细化（记忆文本检索）.md`（第三轮审查后的施工图纸）。
范围 = 图纸 §一 store 层、§二 recall 层、§三 装配、§四 测试、§五 文档。
无对外契约改动（`RecallQuery` / `Retriever` 接口未动）；新增一个回滚 env。

## 改了什么

### 1. store 层（`ts/packages/memory/src/store.ts`）

- `SearchFilter.text` 语义改为**候选集来源提示**：store 自己决定用不用。
  - 删掉旧的 `content LIKE ?` 死分支（从未有调用方传 text）。
  - FTS 可用且查询能切出 3-gram → trigram 候选集；切不出（短查询）/ FTS 不可用 → 静默忽略 text，走原窗口 SQL。
- `MemoryStore` 加能力位 `ftsAvailable(): boolean`；`InMemoryStore` 恒 `false`，并**彻底删掉 `text` 子串过滤**
  （批次一"灯塔"窗口用例靠这一点原样成立）。
- Sqlite 构造加 `SqliteMemoryStoreOptions { fts?: boolean }`（默认 true）。
  - 构造内 try/catch 建 `memory_fts`（`fts5(content, content_id UNINDEXED, tokenize='trigram')`）；失败 → `ftsEnabled=false`。
  - 对账：`count(memory_fts) != count(memories)` → 清空重灌（批次三之前的旧库无痛补索引）。
- 镜像维护：`put` 一律 delete+insert；`patch` 只在 `content` 变化时重灌。superseded 的记录仍在镜像里，
  但候选查询外层 `superseded_by IS NULL` 把它们挡掉。
- 查询构造：清洗口径复用 `extractKeywords` 的正则 → 每个分词块做三字滑窗 → 去重、截 24 个 →
  每个整体双引号、内部 `"` 转义 `""` → ` OR ` 拼接 → `MATCH`。
  - SQL 形态是 `id IN (SELECT content_id FROM memory_fts WHERE memory_fts MATCH ?)` + 原 WHERE；
    比字面 JOIN 少一层列名歧义。
  - `MATCH` 抛错 try/catch 静默回落窗口路径；命中 0 由 retriever 回落（见下）。

### 2. recall 层（`ts/packages/memory/src/recall.ts`）

- `WeightedRetriever.recall`：`query.text` 非空时透传 `store.search({..., text})`；
  候选为空且带了 text → 再查一次不带 text 的窗口路径。
- 打分四项权重、`extractKeywords` / `keywordScore`、`slice(0, limit)` 全不动。
- 头注释的 TODO 从"FTS5/子串"改成"embedding"（FTS5 已落地为候选集）。

### 3. 装配（`ts/apps/server/src/agent.ts`）

- 新增 `memoryFtsEnabled()`：读 `MEMORY_RETRIEVER`，只有显式 `js` 才关 FTS（默认 auto）。
- `createMemoryEngine` 加 `fts?: boolean` 并透传给 `SqliteMemoryStore` —— **memory 包不读新 env**，
  `MEMORY_DB_PATH` 的既有读法不动。

## 与图纸的偏差

1. **候选集用子查询而非字面 JOIN**：`id IN (SELECT content_id FROM memory_fts WHERE memory_fts MATCH ?)`。
   JOIN 后 `content` / `content_id` 列名容易撞；子查询语义等价，superseded 仍由外层 `superseded_by IS NULL` 过滤。
2. **`ftsAvailable()` 只给测试/验证用**：retriever 不读能力位，一直传 text、由 store 判断要不要用。
   这样"忽略 text"只有一处实现，避免两处开关互相打架。
3. **3-gram 按清洗后的分词块滑窗**：不跨空格/标点拼接，非汉字段转小写；与 `extractKeywords` 口径一致。
4. **测试编号**：图纸 §四 的 1–7 实现为 selftest 8.1–8.7；2 字查询复用同一 120 条夹具
   （第 0 条正文同时含"妈妈"），窗口口径与批次一一致。
5. **`memory-ingest.ts` 的独立 store 连接不读 `MEMORY_RETRIEVER`**，始终维护 FTS 镜像。
   它只写（`diary:*` 的 upsert）、不参与召回；若随开关关镜像，`js → auto` 切换后会因行数不变
   而对账不出内容漂移。主引擎（召回侧）在 `js` 下不建表、不用 FTS，行为回到批次一。

## 挂起点

- **语义召回（embedding）**：仍未做；3-gram 词袋只解决"字面重合"。
- **FTS 对账只比行数**：内容变了但行数不变就发现不了（正常路径 put/patch 会同步镜像，
  只有外部进程绕过 store 直写 memories 才会漂移）。
- **候选集截断按 `created_at DESC`**：FTS 命中超过窗口时只留最新的一批；BM25 rank 没有参与截断
  （图纸明确"rank 不影响最终排序"，但也没用它来挑哪 200 条）。
