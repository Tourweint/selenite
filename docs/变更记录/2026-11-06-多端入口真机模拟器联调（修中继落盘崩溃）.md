# 真机/模拟器联调：多端入口实测通过 + 修中继落盘崩溃 bug

日期：2026-11-06
类型：联调验证 + 缺陷修复

## 联调环境（本次真实跑通的完整链路）

中继（:8084，书房主机+vivo手机双设备名册）→ harness（:39847，RELAY_ENABLED=1 出站长连，
已设为主机）→ 手机 App（真机 V2238A 装 arm64 release；模拟器 Pixel_6a 装 x86_64 debug）。

## 实测通过的功能（模拟器全链路操作，真机已装同版包）

1. **抽屉「多端」分区**：历史对话之后出现「多端 · 已接入」状态行（中继没开时整段不渲染的
   红线也验证过——配对错误令牌期间分区正确消失）；
2. **设备页**：名册两行（书房主机=主机标记+本机+描述行；vivo手机=设为主机钮），刷新钮；
3. **描述编辑**：点描述行弹对话框（字数 0/200 计数器），保存后「已保存」回显，
   **中结名册实时更新**（端到端写路径：手机 UI → harness 透传 → 中继落盘）；
4. **设为主机/取消主机**：点 vivo 行「设为主机」→「已设为主机」回显 + 名册 `isHome`
   实时迁移 + 按钮变「取消主机」；点「取消主机」→ 名册主机位清空。动作回环完整。

## 联调中发现并修复的真 bug

**中继名册落盘崩溃（`ts/apps/relay/src/store.ts` `save()`）**：Windows 上 rename 撞
文件锁（EPERM）时异常沿 WS 消息回调把**整个中继进程**干掉（真机联调时实测崩过一次，
期间所有设备失联）。修复：rename 重试 3 次（每次忙等 50ms），仍失败则放弃本次落盘、
内存态继续——崩溃的代价远大于丢一次 lastSeenAt 级别的写盘。

## 手机端联调踩的三个环境坑（都有结论，记录给下次）

1. **手机存的地址是旧端口 8082**（第 7 轮改 39847 前的遗留）：设置页已改 39847；
   `adb reverse tcp:8082 tcp:39847` 可作兼容桥；
2. **手机 deviceToken 在 harness 设备表已不存在**（.data 清过）：设置页重新配对/手填
   即可。注意配对对象——手机连的是 **harness**（`/api/v1/pair/redeem`），不是中继；
   给手机发 token 用 harness 的配对端点签发；
3. **模拟器时钟错 4 天**（Pixel_6a AVD 自动时间同步到错误日期）：production 镜像
   `adb root` 不可用、`date -s` 无权限，时钟没法修；TLS 证书校验会因此失败——
   **本次实测没拦住**（OkHttp 对 127.0.0.1 明文 HTTP 不走 TLS），但任何 https 上游
   请求都会挂。结论：模拟器联调前先 `adb shell date` 对表，修不了就换真机。

## AGENTS.md 补充（模拟器调试口径）

模拟器（Pixel_6a，`emulator -avd Pixel_6a -grpc 8554`）作为真机锁屏时的调试替身：
- 装 `app-x86_64-debug.apk`（debug 包可 run-as 拉库核对配置）；
- 联调前 `adb shell date` 对表（production 镜像时钟可能错数天且无法 root 修正）；
- 输入法坑：`text` 中文输入在某些对话框里会静默失败（IME 会话不接广播），ASCII 可进；
  长文本清空用「点框聚焦 → `input keycombination 113 29`（Ctrl+A）→ keyevent 67（DEL）」，
  逐字 keyevent 67 会被长文本拖死。
