# 右键菜单：壳里自绘，Web 保留原生（2026-11-16）

## 改了什么

### 1. 桌面壳输入框：自绘菜单（全选 / 复制 / 粘贴）

`ts/apps/server/web/context-menu.js`：

- 只有壳里（`window.isMyGo()`）才接管。**普通浏览器一行都不拦**，原生右键照旧。
- 输入框范围：`textarea` / 文本类 `input`（text/search/url/tel/password）/ `contenteditable`。
  右键弹自绘菜单，三项：
  - **全选**（Ctrl+A）
  - **复制**（Ctrl+C，没有选中文字时置灰）
  - **粘贴**（Ctrl+V，只读 / 禁用字段置灰）
- 粘贴实现：
  - input/textarea：`setRangeText(text, start, end, "end")` + 手动派发 `input` 事件，
    输入框自己的长高、发送态监听照常跑；插入位置用右键那一刻捕获的选区，不靠失焦后的光标。
  - contenteditable：把 Range 恢复到右键位置后 `execCommand("insertText")`，失败再走 Range 插入。
- 剪贴板读写：
  - 读取只走壳新增的 `Shell.ReadClipboard`；**不退回 `navigator.clipboard`**——
    WebView2 对异步读取要 ClipboardRead 权限，壳没处理 `PermissionRequested`，
    第一次会弹权限框（2026-11-16 用户反馈）。
  - 写入走 `Shell.WriteClipboard`；老壳可退回 `navigator.clipboard`（写剪贴板不需要授权框）。
  - 读取失败时提示「右键粘贴暂时用不了，先按 Ctrl+V 贴上」，不弹权限框、不静默失败。
- 非输入区（壳里）：原生菜单仍然关掉；选中文字时给一条「复制」。
- 设置页非输入区：不弹自定义菜单（沿用 2026-11-16 口径）；设置页的输入框照样是自绘三件套。

### 2. 壳新增剪贴板桥

`desktop/clipboard.go`：

- `func (Shell) ReadClipboard() string` → `mygo.Clipboard.ReadText()`
- `func (Shell) WriteClipboard(text string) error` → `mygo.Clipboard.WriteText(text)`

原因：WebView2 的 `navigator.clipboard.readText()` 默认没有 `ClipboardRead` 权限，壳不处理
`PermissionRequested` 时会被拒；MyGo 的 `Clipboard` 直接走系统剪贴板，是壳里确定能用的那条路。
壳已重编并替换 `desktop/lifediary-shell.exe`；旧壳进程已停、旧文件已删除，新壳已启动。

### 3. 侧栏行菜单只在壳里生效

各列表行的 `contextmenu` 统一加 `if (!inShell()) return;`：

| 行 | 菜单项（壳内） |
|---|---|
| 对话行（展开侧栏） | 打开 / 重命名 / 置顶·取消置顶 / 归档（运行中禁用） |
| 对话行（收起轨道浮卡） | 打开 / 置顶·取消置顶（浮卡是临时预览，行内改名/归档确认留不住） |
| 执事行 | 打开对话 / 人设档案 / 看「领域」的任务（有领域才多这条） |
| 项目行 | 查看此项目（当前项禁用）/ 项目设置 |
| 群组行 | 打开群聊 / 所有群聊 |
| 课题行 | 展开·收起详情 / 暂停·恢复研究 |

Web 端这些行也保留原生右键（同一道 `inShell()` 闸）。

### 4. Ctrl+R / F5 不变

`nav-history.js` 顶层的刷新兜底保留：壳里浏览器加速键默认关（MyGo 0.7.3 的
`AreBrowserAcceleratorKeysEnabled = DevTools`），页面自己补 `Ctrl+R` / `F5`；浏览器里与默认行为等价。

## 为什么

用户口径（2026-11-16）：

- 「桌面端的右键输入框，你自己画、自绘一个。应该是粘贴功能，就保留选中、复制和粘贴。」
- 「这个 Web 端你就不用管了，该用就用吧，右键不禁用也没事。」

因此：桌面壳 = 原生菜单关、输入框自绘、侧栏行给小菜单；普通浏览器 = 完全保留原生右键，
不做任何接管。上一版「Web 端也全局关原生菜单」的口径按这次调整撤回。

## 刻意不做

- **不做剪切 / 撤销 / 重做**：用户点名只留全选、复制、粘贴；其余靠键盘。
- **右键粘贴只处理纯文本**：图片粘贴仍走 Ctrl+V（页面自己的 paste 监听）或「+」菜单；
  自绘菜单读不到图片时提示「剪贴板里没有文字；图片请按 Ctrl+V 粘贴」。
- **select / checkbox / 日期输入等保留原生菜单**：自绘菜单帮不上忙，硬接管只会更难用。
- **Web 端不做任何右键改造**：用户明确说不用管。
- **设置页非输入区不做自定义菜单**：沿用上一轮口径。
- **手机端不做**：这次只谈电脑端。

## 当天返修（用户报的两个桌面端问题）

1. **第一次粘贴弹权限框**：根因是读取剪贴板退回了 `navigator.clipboard.readText()`——WebView2 的
   ClipboardRead 没有授权，壳没处理 `PermissionRequested`，第一次就弹框。现在壳内读取只走
   `Shell.ReadClipboard`，读不到就提示「右键粘贴暂时用不了，先按 Ctrl+V 贴上」；同时重启壳换上新
   exe（含剪贴板桥），右键粘贴不再经过浏览器权限。
2. **右键后「全选」被黑框框住**：菜单打开时会把焦点放到第一项，浏览器默认焦点框就画成了黑框。
   `style-03-sidebar-zones.css` 里给 `.sec-menu-item` 加了 `:focus { outline: none; }`，
   `:focus-visible` 改用与悬停相同的底纹表示键盘位置。

## 回滚

- Web 端本来就零改动，不需要回滚。
- 壳内输入框恢复原生菜单：删掉 `context-menu.js` 里的输入框分支（或让 `inShell()` 恒 false）；
- 侧栏行菜单消失：删掉各列表里的 `contextmenu` 监听；
- 剪贴板桥：删 `desktop/clipboard.go` 并重编 exe（页面侧读取会提示按 Ctrl+V，写入仍可退回 navigator）。
