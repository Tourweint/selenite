# 打手工具结果整理开关（2026-11-16）

## 改了什么

工具结果投影（`tool-projection.ts`，2026-11-13 三批落地的能力）此前对「普通打手」
（`chatKind === "worker"`：子任务 / 派单执行者）是**写死默认开**，界面上只有全局回滚闸
`TOOL_PROJECTION` 和每执事三态 `partners.tool_projection`，没有"只关打手、别动别人"的档。

本次补一个独立开关：

- `flags.ts`：新增 `TOOL_PROJECTION_WORKER`（true/false，`defaultValue: "true"`，`hot: true`）。
- `tool-projection.ts`：
  - 新增 `toolProjectionWorkerEnabled(env)`：缺省 / 空串 = 开，只有明确 `false` 才关
    （与 `toolProjectionEnvEnabled` 同口径）。
  - `projectionDecision` 入参加 `workerDefault: boolean`；`chatKind === "worker"` 分支由
    恒 `true` 改为 `return input.workerDefault`。
  - `projectionEnabledFor` 传入 `toolProjectionWorkerEnabled()`。
- `web/settings-switches.js`：设置 → 开关 → 「任务与界面」组里 `TOOL_PROJECTION` 后新增一行
  「打手工具结果整理」，文案写明"只管本机内核打手；外接 CLI 打手不经过这层"；同时把
  `TOOL_PROJECTION` 的摘要补成「总闸，关 = 所有会话一律原样透传」。
- 测试（`tool-projection.test.ts` ⑪~⑭）：打手开关关 → worker 不开；同场景执事三态 `1` → 开
  （三态压过默认）；env 总闸 `false` → 一律不开；`workerDefault=true` 时行为与改动前一致
  （含"不越界影响主人会话 / 带 domain 的执事会话"）。

判定优先级（未变，只是第三层换成了可配默认）：

1. `TOOL_PROJECTION=false` → 恒关（能力整体下线）；
2. 执事三态 `1` / `0` → 压过一切默认；
3. `chatKind === "worker"` → 走 `TOOL_PROJECTION_WORKER`；
4. 其余 → 带 `domain` 的执事会话开，主人会话 / 无 domain 聊天执事不开。

## 为什么

用户口径：打手跑的命令输出常常又长又吵（`grep` 无匹配、超时、大输出），要不要整理应当能在界面上
单独决定，而不是只能通过"整块能力下线"或"逐执事改三态"绕过。默认值保持开，与改动前行为一致，
所以这是一次「默认值不变、只把写死的值换成开关」的改动，不引入行为突变。

## 外接打手为什么没有、也不该有这个开关

CodeBuddy / Qoder / Claude Code / Codex / OpenCode 是**外接 CLI 打手**：它们在自己的进程里跑自己的
工具，结果投影（`wrapShellTool` 包装内核 bash/powershell）根本不经过它们，所以开关对它们既不生效、
也不该出现在它们的配置里——写进设置页说明，是为了避免"打手开关关了但外接打手还在整理"这种误判。
