# 消息时刻：回答显示几点答完（对齐 ZCode）

**日期**：2026-11-17。
**方案**：本条只落"时间"；会话分叉另见 `docs/设计方案/2026-11-17-会话分叉（从某条回答另开一支）.md`（未实现）。

## 背景

对话里只有 `data-at`（给搜索定位用），界面上看不到任何时刻：回头翻时不知道
那条回答几点答完。ZCode 的消息时刻口径是"今天只写时分、昨天带昨天、同年写月日、跨年才带年份"，
照这个口径抄；显示位置收在回答脚注里，跟复制、用时同一行，hover 才出现。

## 改了什么

- **契约 `endedAt`（纯增量）**：`TranscriptMessageSchema` 与 server 侧 `TranscriptMessage`
  同时加 `endedAt`。`at` 是这次请求的开始，翻译成"几点答完"要加 `durationMs`：
  服务端在 `foldTranscriptEntries` 里按 `at + durationMs` 算，旧记录没有 `durationMs` 就退回 `at`；
  只有步骤、没有正文的收尾轮用最后一条的时间。只挂 assistant。
- **`web/msg-clock.js`（新）**：纯格式化，`今天 HH:mm` / `昨天 HH:mm` / `M月D日 HH:mm` /
  `YYYY年M月D日 HH:mm`；时间无效返回空串、节点隐藏（不写 0 点）。DOM 挂载留在 `chat-thread.js`。
- **`chat-thread.js`**：只给 assistant 建 `.msg-clock`，塞在 `.msg-foot` 里**紧挨复制图标**；
  用户消息不再显示发送时刻（2026-11-17 晚间用户口径）。新增 `stampMessageClock`，
  流式回答拿到 `done` 才落笔。
- **`composer-send.js`**：主链路与补帧两条 `done` 都调 `stampMessageClock`。
- **`chat-open.js`**：历史回读只给 assistant 传 `clockAt = endedAt || at`；来信（letter）
  仍用自己的抬头时间，不重复。
- **`chat-notice.js`（`attachUsage`）**：脚注里的用量只留**秒数**，去掉 `tok` 数——
  token 对"这轮等了多久"没用，还把 11px 的脚注撑成两截数字；没耗时就不挂。
- **CSS（style-04）**：脚注平时整条是空的，复制 / 收尾时刻 / 用时三项都 hover 或聚焦才淡入；
  时刻不再 `margin-left:auto` 钉最右，改为跟着复制图标顺排；留 20px 最小高度不变，
  避免鼠标划过时消息上下抖。
- **文档**：接口文档分册1 §2.2 补 `endedAt` 口径。

### 晚间追加：日期分隔收细（用户口径：太明显了）

- 原来左右两条 `flex:1` 的线各占半屏，读起来像表格硬切；现在只留**两截 56px 短线**，
  从日期往外渐隐（`linear-gradient`），不再是贯通横线。
- 日期本身从 12px 收到 **11px**、加 `.12em` 字距，上下留白放到 `20px / 10px`——
  靠空白分天，不靠线。
- `.msg-day`（私聊）与 `.group-day`（群聊）同时改，避免两套日历口径又长歪。
- 没做"隐藏今天的分隔 / 相对时间 / 吸顶日期条"：那些会改变定位语义，不只是视觉。

## 刻意不做

- 不显示秒、不做"3 分钟前"相对时间：回头翻账时绝对时刻更有用。
- 不算"思考耗时 / 每个工具耗时"上屏：工具灰块详情里已有自己的耗时，脚注不再叠一层。
- 手机端零改动：新字段纯增量，Kotlin 只读 `role` / `text` / `at`。
- 会话分叉本轮**只出方案**、不动代码；方案已按"复制式分叉 + 总管/执事接替主线"改到第二版，
  改动面涉及 assistant 消息 id、条目重放、身份链接与列表，等拍板。
