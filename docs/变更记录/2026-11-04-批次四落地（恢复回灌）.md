## 背景

启动恢复（`recoverDelegations`）只返回汇总计数。A3a 已把「ticketId → 内部会话 id」
写进受理回执，但恢复时拿不到逐单结果，重启后用户在原对话里看不到那些单最后怎么了。
本批让 chancellor 逐单回传结算结果，宿主过滤终态、查回执、经 `sayInChat` 回灌一行状态。

## 改了什么

1. **chancellor**（详见其变更记录）：`recoverDelegations` 增加 `onTicket`，
   结算循环集中打点；`RecoveredTicket.status` 复用对外五态。汇总返回值与 inflight 结构不变。
2. **新模块 `recovery-report.ts`**：`formatRecoveryLine()` 纯函数（≤80 字、按 status 原词，
   failed/aborted 不会写成「完成」）+ `reportRecoveredTickets()` 可注入
   （`receipts.lookupByTicket` / `say` / `log` 全是参数，测试不建库、不起服务）。
3. **`agent.ts`**：从 `reportDelegationResult` 抽出并导出 `sayInConversation(internalId, text)`，
   原函数改成调用它；汇报路径与恢复回灌共用同一段提交逻辑，没有复制。
4. **`index.ts` 启动接线**：`onTicket` 收集 entries → 结算完 `reportRecoveries()`：
   开关开、有 LLM 配置、且有 entries 时才打开回执库；失败只 warn，不阻断汇总。
5. **回滚开关**：`DELEGATION_RECOVER_REPORT=false` → 不查回执、不写会话（零查询）。
   `.env.example` 与 `接口文档.md` §6 各一行。
6. `delegation.ts` 的 `truncate` 改为导出，供状态行复用（不复制一份）。
7. 文档口径：`系统架构.md` §7 改成「已落库（A3a）+ 启动恢复终态状态行回灌（A3b）」，
   并登记覆盖缺口（`resumeTicket` 不写回执；用户 resume 过的单、续跑中单的完成都不回灌）；
   调研方案 A3 标已落地；图纸文首补状态与落地偏差表。
