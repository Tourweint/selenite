# 2026-11-23 设置 → 注入 → 技能页去掉解释性文字

## 用户口径

「这一页解释性文字真是太多了」——只留能操作、能看状态的东西，能从上下的信息里推出来的说明句不写：

- 「技能库」旁边的「共 N 个 · 已开启 M 个」：下面本来就分「已开启 / 未开启」两区，数得出来。
- 标题下的「开了才进索引；对话里输入 /技能名 直接调用。技能库可以放在多个位置，下面按优先级排列。」
- 「技能库位置 N 个位置 · N 个可写」：本页是只读的，写落到哪里不在这里决定；而且都是本地文件，
  开了访问就都能写，这个区分对用户没有意义。
- 技能卡 meta 行里的「只读」小字：不会在设置页改技能，顶多看看、开关；这个标注只会让卡片变吵。

## 改了什么

| 文件 | 改动 |
|---|---|
| `web/settings-router.js` | 删 `.sk-sub` 说明行；标题里的 `#skill-count` 改为空、默认 `hidden`（只留刷新失败提示位） |
| `web/skills-settings.js` | `applySkillPageMeta` 不再写计数文案；正常态清空并隐藏计数位；刷新失败时仍置 `刷新失败：…` 并显示（404 / 清空两处同步隐藏） |
| `web/skills-locations.js` | 位置卡删「N 个位置 · N 个可写」摘要；行尾「可写 / 只读」状态标记退役，「不存在」保留（它解释技能为什么读不到，是真异常） |
| `web/skills-list.js` | 技能卡 meta 行不再渲染 `.sk-ro`「只读」；对应的 `readOnlyTip` 删除。`readOnly` 本身仍决定「点开=查看」与不给删除按钮 |
| `web/style-18-groups-settings-memory.css` | 删 `.sk-sub` / `.sk-sub b` / `.sk-loc-sum` / `.sk-loc-state.is-writable` / `.sk-ro`；相关注释同步 |

`#skill-count` 元素保留但默认隐藏：后台刷新失败（有缓存、不重画列表）时它是唯一的提示位，
删掉元素等于把这条失败信号吞掉——那是状态，不是解释性文字。

## 没做 / 边界

- 标题上的 hover `data-tip`（技能的完整解释）保留：悬停才出现，不属于常驻解释性文字。
- 技能卡 meta 行的 hover title 仍带「来自 …（只读）」：同上，只在悬停时说。
- 「内置」小字（core 技能无启停位）保留：它替代开关，是状态不是说明。
- 工具栏、Agent 建议条、空态文案不动。
