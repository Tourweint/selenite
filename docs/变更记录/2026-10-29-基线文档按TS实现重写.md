## 1. 背景

`docs/` 下的两份基线文档停留在 **Java/Spring 版**（2026-10-25 P1 立项、2026-10-27 P2）：
描述的是"无状态单体、与 backend 同 HS256 `JWT_SECRET`、先扣额再透传、`/signal/session` 四问、`ai-config` 60s 轮询"。
而实现早在 2026-10-28 换成了 **Node + TypeScript（Hono + SSE）+ `pi-durable@1.4.0` + SQLite**，
Java 版代码已删除、backend 仓库整体退役（App 侧同步去账号化）。

结果：任何人（包括 AI）读这份文档都会得出与代码相反的结论。本次按**实读代码**重写，代码为准。

## 2. 重写后的现行口径（要点）

| 主题 | 现行 |
|---|---|
| 鉴权 | 共享令牌 `AGENT_TOKEN`（Bearer，403 空体）；未配令牌只放行 loopback。**不是 JWT，不带用户身份** |
| 状态 | **有状态**：会话/任务/工具结果落 SQLite（`AGENT_DB_PATH`），记忆四层另库 |
| 额度 | **没有**额度与计费；不调任何内部接口 |
| 信号 | **没有** `/signal/session`（Jev 四问随 Java 版退役） |
| 会话 id | 对外 uuid（服务端生成），内部自增整数不外泄；映射在 `lifediary.chats` |
| 断开语义 | 客户端断开**不中止**那一轮；真停走 `POST .../stop` |
| 兼容层 | `POST /api/v1/llm/chat/completions`（给 App 的 OpenAI 协议），内部仍走 agent |
| 工具 | 7 个；闸门是骨架（`read-only` / 黑名单），无逐次确认 |
| 响应形态 | 裸 JSON / SSE `data:` 行；**没有** `{code,message,data}` 信封 |
