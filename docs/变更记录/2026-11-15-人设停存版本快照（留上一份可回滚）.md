方案：`docs/设计方案/2026-11-15-人设停存版本快照（留上一份可回滚）.md`（含全量消费方核对结论）。
用户拍板：自动版本历史没用人（没有历史页、没有回滚入口、老快照零读取），不做；保存后的退路用「上一份 + 提示可回滚」兜住。

## 改了什么

**服务端（harness 仓）**

- `partner_versions` 表整表退役：`bumpSoul` / `bumpContract` / `setModelChain` / 建档 / 总管播种不再插快照行，只写磁盘 + `partners.current_version` 计数 +1；老库启动时把当前版本行 `capabilities.modelChain` 搬进执事家目录 `model-chain.json`（幂等），随后 `DROP TABLE`。新库不建该表。
- 磁盘成为当前值唯一事实源：prompt 组装（`partner-context.ts` 契约与 SOUL）、身份对齐（专线 `partner-runtime-run-partner-turn.ts` / 群 `group-runtime.ts`）、派单身份（`partner-api.ts`）、总管身份（`partner-rows.ts chiefSoul`）、导出（`partner-bundle.ts`）、问候生成全部改读盘。原「快照优先、磁盘兜底」的读法（批次D 时代口径）随表退役；「磁盘手改下一轮生效」成为统一口径。
- 计数语义保留：`soulVersion` / `contractVersion` 契约字段不动，值 = 保存计数（下一轮生效的记账位）；`applied_version` 会话比对逻辑不变。
- **留上一份**：`bumpSoul` 写盘前把当前 SOUL 存 `SOUL.prev.md`（单槽）；新端点 `POST /api/v1/partners/:id/soul/rollback` 把两文件**交换**（再按一次 = 撤销回滚），计数 +1，返回 `{ok, soul, soulVersion}`；没有上一份 → 400 带说明；不存在 → 404。契约刻意不做上一份/回滚（低频慎重、有弹窗确认）。
- 无 env 回滚开关：摘的是只写不读的死数据，当前值全在盘上，没有数据丢失面（方案「明确不做」）。

**电脑端 web**

- 摘版本展示：人设二级页「人设 v14」徽章、执事列表「人设 v1」kv、执事编辑弹窗版本行、契约行「v14·N 字」→「N 字」、设置抽屉身份块副行；保存提示「已保存为 v15，下一轮起用。」→「已保存，下一轮起用。」。
- 新组件 `web/soul-rollback.js`：保存成功后在提示行给「回到上一版」按钮（三处保存共用：人设二级页 / 设置→总管人设 / 执事编辑弹窗），点击回滚后正文回填、字数标签同步；回滚完成即摘按钮。
- 契约编辑只摘版本文案，不给回滚钮。

**手机端（lifediary 仓，未提交）**

- `PartnerEditScreen.kt` 摘「SOUL 版本 v14」行（API 层 `soulVersion` 字段保留，服务端仍在发）。
