# 验收补缝：删除、粗判、崩续跑与中止子单（2026-11-04）

## 改了什么

- **删除也算完成**（chancellor `isolation.ts` / `scheduler.ts` / `review.ts`）
  - 声明路径从「执行前存在」变成「执行后不存在」记一次有效变更；新增、修改、删除任意一种即 `pass`。
  - 只有声明路径一个都没变才 `fail`，原因固定为 `声明了 N 个路径，实际 0 个变更（新增 / 修改 / 删除都没有）`。
  - 安全边界不变：worktree 里删除**未声明**路径仍计入 `collectTaskChanges`，按越权写入整批拒绝合并。
- **目录指纹成本**（chancellor `isolation.ts` / `config.ts`）
  - 快照从「路径 → sha1」改成「路径 → `{size, mtimeMs, hash?}`」。
  - `dir/**` 递归后先比 `mtime+size`；没变化的文件直接沿用上一次指纹，只有疑似变化的文件才读内容算 sha1。
  - 单目录文件数超过 `CHANCELLOR_SNAPSHOT_COARSE_FILE_LIMIT`（默认 2000）时退化为纯元数据粗判，
    并在 `Review.warnings` 记 `目录过大，使用粗粒度比对`。
- **崩溃续跑不再靠估算**（chancellor `scheduler.ts` / `store.ts` / `index.ts`）
  - 任务开工时把执行前快照写入 `snapshot-before.json`（task 目录内），带 `ticketId` / `seq` 归属。
  - 崩溃恢复时 `runFromDisk` 和自动续跑按 ticketId/seq 读回；续跑直接拿它当「执行前」状态，
    崩溃前已经写进项目的内容也算这个任务做的，结束后仍做严格前后对比。
  - 没有快照的续跑不再用「现存文件」兜底：验收返回 `blocked`，明确说无法确认是否真的变更。
  - 清理：`done / failed / aborted` 终态清掉该单所有 task 快照；`needs_you / idle` 保留，
    因为用户回答后还可能 `resume`，续跑要靠它。
  - 跨合并点仍按原方案转「待你处理」，不因有快照就自动合并。
- **aborted 子单也拦父单**（chancellor `stage.ts`）
  - 父单声称 `done` 时，子单 `failed / needs_you / aborted` 都改走 `needs_you`。
  - 汇报点名子单 id、状态（`aborted` 显示为「已中止」）和原因。

## 验证

- `pnpm typecheck`（chancellor / harness）通过。
- server 测试 `118` 项全过；本轮新增 5 项：
  - worktree 删除未声明路径 → 越权失败，且整批不合并；
  - direct 模式只删除声明文件 → `pass`；
  - 快照落盘后按 ticketId/seq 读回，删除仍能做严格前后对比（换 ticketId 读不到）；
  - 目录超阈值 → 快照 `coarse`，验收带「目录过大，使用粗粒度比对」warning；
  - 子单 `aborted` → 父单 `needs_you`，汇报含 id / 已中止 / 原因。
- 真实 git 临时仓库（Windows 本机，跑完清理）：
  - 写文件 `new.txt` → `pass`，`changed=["new.txt"]`；
  - 只删声明文件 `base.txt` → `pass`，`changed=["base.txt"]`，未声明的 `other.txt` 保留；
  - 声明 `base.txt` 但没增没删没改 → `fail`，`changed=[]`；
  - 未声明删除 `base.txt` → `changes=["base.txt:D"]`，不算被 `writes` 覆盖；
  - 子单 `aborted` → 父单 `needs_you`，汇报行点名「已中止」。
- 快照耗时（真实数据，800 个 32KB 文件，改 1 个，热缓存，3 轮中位数）：
  - 全量快照（读内容算 sha1）：**445.86 ms**
  - 增量快照（`mtime+size` 先筛，只算变化文件）：**31.29 ms**
- 崩续跑模拟：进程 A 把快照写入 `snapshot-before.json` 后退出；另一个进程 B 读回旧快照，
  删掉声明文件后做严格对比，得到 `changed=["base.txt"]`，且用别的 ticketId 读不到这张快照。

## 明确不做 / 仍存在的限制

- 粗判只看 `mtime+size`：同尺寸、同时间戳的内容替换会漏掉；这是为了大目录成本刻意接受的误差。
- 「未变化的目录整体跳过」实现为**跳过着 sha1 计算**，仍会 `readdir + lstat` 每个文件；
  目录 mtime 不能证明文件内容没变，直接跳过枚举会漏改动。
- 崩溃续跑的完整「执行中途杀进程 → 启动恢复自动重跑」链路没有端到端演练；
  已验证的是快照落盘、跨进程读回、读回后严格对比，以及 `runFromDisk` / 续跑入口的读回接线。
- 只读任务（未声明 `writes`）仍走 LLM 核对 REPORT，不在本次口径内。
