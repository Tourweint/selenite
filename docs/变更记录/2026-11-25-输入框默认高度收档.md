# 2026-11-25 输入框默认高度收档

## 改了什么

1. **`web/style-07-composer.css`**：
   - `.composer`：`padding 11/11/6 → 10/11/5`、`gap 6 → 5`、`min-height 86 → 82`；
   - `.composer textarea`：`min-height 32 → 30`、`padding-top 8 → 7`；
   - `.composer-foot`：`min-height 32 → 30`；
   - `.composer-add`：保持 30（首版收到 28 后已回退）；
   - 首页档 `.main[data-home="1"] .composer textarea`：`min-height 84 → 72`（仍高出对话态一档）。
2. **`web/style-11-composer-tools.css`**：`.composer-pill` 高度保持 30（首版收到 28 后已回退）。
3. **`web/style-04-chat-base.css`**：`--composer-h` 的 CSS 回退值 `86 → 82`（两处），首帧让位与卡高一致。
4. **`web/chat-open.js`**：`openChat()` 在 `beginHomeSettle()` 之后补一次 `resize()`。
   首页档的高度是内联 `height`，切进对话态后 `min-height` 变小但内联值还在，空框会一直顶着
   首页那一档，直到第一次打字；补这一次重算是顺手修掉的老问题（原来首页 84 时更明显）。

## 为什么

2026-11-25 用户口径：空态输入框太大，默认收小，随文字增长、到上限后内部滚动。
先收过一版（对话 74 / 首页 110），用户判「收得过头、有点窄」，回调到对话 82 / 首页 124，
比原值各小 7 / 17px。

实测（headless Chrome + CDP，1440×900，真页面）：

| 状态 | 原值 | 首版 | 定稿 |
| --- | --- | --- | --- |
| 首页空态（整卡） | 141px | 110px | 124px |
| 对话空态（整卡） | 89px | 74px | 82px |
| 对话 3 行（整卡） | — | 118px | 125px |
| 40 行（textarea） | — | 200px 封顶，内部滚动 | 200px 封顶，`scrollHeight 887 > clientHeight 200`，`overflow-y:auto` |

长高与滚动上限原本就在（`resize()` 里 `Math.min(scrollHeight, 200)` + CSS `max-height:200px`），
本轮只调默认档与间距，未改机制。

## 验了什么

- CDP 真页面量测：上面四个状态的高度、`overflow-y`、`scrollHeight/clientHeight`；
- 截图核对首页 / 对话两态观感（`composer-home-final.png` / `composer-chat-final.png`）；
- `node --check web/chat-open.js`。

## 没验

- 未跑 `pnpm typecheck`：本轮没有 TS 改动（纯 CSS + 一个前端 JS 文件）。

## 回滚
