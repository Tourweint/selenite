# 记忆页长列表回顶 + 偏好说明文案纠正（2026-11-16）

> 用户口径：设置 → 记忆页展开后是「一个全部的大长条」，往下翻再翻回去太难；另外偏好组头写「每轮都会想起 / 每轮禁忌」不对，它只是召回时分数靠前，不是每轮必进，解释文字删掉。

## 改了什么

### 1) 记忆页加「回到顶部」浮动按钮

文件：`ts/apps/server/web/memory-page.js`、`ts/apps/server/web/style-21-answer-memory.css`

- 记忆页正文末尾加一枚 `position: fixed` 的回顶按钮（右下角，圆形上箭头）。
- 跟随设置内容列 `#settings-scroll` 滚动：`scrollTop >= 240` 显示，回到顶部自动隐藏。
- 点击直接把 `scrollTop` 归零。刻意不用 `scrollTo({behavior:"smooth"})` / rAF 缓动：
  内嵌 webview 里两者都是 no-op（实测 rAF 一帧都不发），一步到顶最可靠。
- 监听随记忆页重新装配装卸：`wireMemorySettings` 里 `stopMemoryBacktop()` + `wireMemoryBacktop(gen)`；
  **不能**塞进 `stopMemoryPolling()`——后者每次读整理状态都会调，会把回顶监听一起摘掉（踩过这个坑）。

### 2) 展开的长列表仍走整页滚动，不加内层滚动框

同日「前端细节五件」已定调：上下文页展开原文去掉内层滚动，理由是「滚轮被困在小框里，外面怎么滚都不动」。
记忆页若给分组 / 原文档案套 `max-height + overflow + overscroll-behavior: contain` 会复现同一个毛病，
所以**不改滚动结构**，长条问题由上面的回顶按钮解决。

### 3) 删掉「每轮都会想起」的错误解释

文件：`ts/apps/server/web/memory-page.js`（`memoryGroupHint`）、`ts/apps/server/web/settings-memory.js`（`MEMORY_KIND_TIPS` 与旧版「当前状态」行）

- 偏好组头的 `每轮都会想起` 删除；偏好 tooltip 改为「召回时排在前面成段，不相关时不会带」。
- 旧版 A/B 页的「偏好会在每轮对话开头被想起」同步改为「记忆按相关度召回；命中的偏好排在前面成段，不相关时不会带」。

事实依据（`ts/packages/memory/src/engine.ts` `buildContext`，2026-11-16 核对）：
偏好只是召回命中后按 kind 稳定分组、排在最前成段；**不进当轮候选集时一样不会带**。
它不是每轮恒定注入的段落，原文案会让人误以为「每轮进入记忆 / 每轮禁忌」，故删。

## 验证

- `pnpm typecheck` 通过；`node --check memory-page.js` 通过。
- 浏览器（内嵌 webview，真页面）实测：偏好组头无 hint、tooltip 为新文案；展开 26 条原文档案后滚到底部回顶按钮出现、点后 `scrollTop` 从 908 → 0、按钮自动隐藏。截图确认按钮位置与外观正常。
- 单测：`pnpm --filter @lifediary/server test` 1066 条，6 红——均为并行在途的 `tool_search` 闸门 / 注册顺序、`pin` 变量名、`partner-work` 失败，与本批（纯前端）无关；记忆相关用例全绿。

## 明确不做

- 不改召回算法 / 注入逻辑（偏好仍按原样成段排前，只改说明文字）。
- 不给长列表加内层滚动框（违反同日「外面继续滚」口径）。
- 不碰并行的「记忆原子化 / 原文档案」在途改动（本批只用定点 Edit 改上述三处）。
