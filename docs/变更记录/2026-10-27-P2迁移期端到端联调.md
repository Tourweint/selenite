# P2 迁移期端到端联调（backend × harness 双服务实测）

> 日期：2026-10-27。零代码改动（除 LlmProxyApiIntegrationTest 的时序修复，见同日提交）。
> 目的：迁移期双端点并存前，用真实进程验证 P2 全链路，不等 App 侧真机联调。

## 环境与口径

- backend 与 harness 同机起真实进程：backend 用**独立 H2 文件**（`lifediary-e2e`，
  **不带 AUTO_SERVER**——AUTO_SERVER 需在本机 IP 开 TCP 端口，本次会话本机 127.0.0.1/局域网自连
  被 WFP 层吞包，H2 起不来；e2e 数据文件测完即删，不动正式 `lifediary.mv.db`）；
- 互访全走 `<VPN_IP>`（aTrust VNIC 自连是本机唯一可用回环路径，`OPENSHIFT_IP`/
  `BACKEND_INTERNAL_URL` 指向它）；JWT_SECRET 两端同源注入；backend 注入
  `APP_AI_BASE_URL=http://…:8081` 模拟「管理端已把 AI 通道切到 harness」。

## 验证结果（全部符合预期）

| 项 | 结果 |
|---|---|
| JWT 共享密钥鉴权（D2） | ✅ backend 注册签发的 JWT 直打 harness 被接受；无令牌 403 |
| `/me/preferences` 下发 `aiBaseUrl` | ✅ 响应含 `"aiBaseUrl":"http://…:8081"`（P0 链路） |
| D1 扣额联动 | ✅ 每次经 harness 的 LLM 调用后 backend `quotaUsed` +1（上游失败也计次，符合设计）；quota 4029 语义由单测覆盖 |
| LLM 透传（P2） | ✅ `qwen-flash` 真实响应经 harness 全链路返回；服务端持有 key（未配 key 时上游回"没带 key"、配了之后错误变为上游业务错误，证明 key 注入路径正确）；qwen-turbo 一度 `limit_requests` 系模型级限流，与链路无关 |
| signal 端点（P1） | ✅ 规范 advisory 信封返回；上游 TypeSafe 直连被区域封锁时按设计回落 `available:false`（advisory 不门控） |

## 已知小瑕疵（不改，留 P3 备忘）

- 请求体 JSON 解析失败（如畸形编码）落到全局 5000「服务开小差了」，语义上更接近 4000 参数错误；
  **两端一致**（backend 同款兜底），改需双端同步 + 接口文档补页，App 恒发合法 JSON 故低优先。
