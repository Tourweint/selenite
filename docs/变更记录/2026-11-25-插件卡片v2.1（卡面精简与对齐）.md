# 2026-11-25 插件卡片 v2.1（卡面精简与对齐）

前情：`docs/变更记录/2026-11-25-插件卡片详情与依赖.md`（卡片 v2）、
`docs/设计方案/2026-11-25-插件卡片详情与就近设置.md`（§5.1 落地形态）。
本次是 v2 落地后按用户当天的反馈做的卡面收口，只动前端展示，不动契约、服务端与 `plugins.json`。

## 改了什么

1. **卡面只留四块**（`web/settings-switches.js` 的 `flagCardMarkup`）：
   名字 + 状态徽标（靠右）+ 说明全文 + 卡尾（「设置」/「被 N 项依赖」/ 原控件）。
   - 从卡面拿掉：`KEY`、组名、「类型 · 当前 · 默认 · 生效 · 存储」元信息行、
     「无依赖 / 无额外设置」两个灰字、前置与被依赖的 chips。
   - 这些都还在：`KEY` 进详情弹层的「标识」行；当前 / 默认 / 生效 / 存储本来就在弹层；
     前置与被依赖改成弹层里的 chips（点 chip 关弹层、滚到那张卡并闪边）。
   - 有子插件的卡在卡尾写一行灰字「被 N 项依赖」，悬停列出子插件名。
     「被父关」仍由状态徽标表示（服务端 `lockedBy`），具体是哪个父在徽标悬停 + 详情弹层里。
2. **徽标顺序**（`flagBadges` / `paintFlagTags`）：例外徽标（系统核心 / 待重启 / 已改）在前，状态（开 / 关 / 被父关 / 常开）在最后。
   整组靠右，状态永远贴着卡片右缘，不随例外徽标的数量左右跑。
3. **排版（`web/style-14-settings-pages.css`）**：
   - `.flag-grid` 从 `align-items:start` 改为 `stretch`，`.flag-item` 加 `height:100%`，卡尾 `margin-top:auto`：
     同排卡一律等高，卡尾控件贴同一底线；说明长短只影响卡内留白，不影响卡尾位置。
   - 头部 `flex-wrap` 改为不换行：名字 `flex:1` + 省略号，徽标整组 `margin-left:auto`，`›` 收尾。
     窄卡不再把徽标挤到第二行。
   - 搜索框、计数行、组标题、卡片、页脚各去掉 2px 内缩，统一贴同一条左缘（原来搜索 / 组头在 348、卡片在 346）。
4. **`web/plugin-settings.js`**：删掉只服务于「无额外设置」灰字的 `pluginSettingsRegistered`（不再有调用方）；
   设置按钮与面板的逻辑没动。

## 为什么

2026-11-25 用户看 v2 真页面后的口径：
- 卡面文字太多，技术元信息不该摆在外面（详情弹层里已经有了）；
- 有前置 / 被依赖的插件把卡撑得很高（`MEMORY_ENABLED` 的 12 个被依赖 chips 最多铺 4 行），
  同排卡片高低不齐、内部每块也对不齐；
- 要的是能扫一眼的卡片墙，不是每张卡都当详情页。

所以把「解释性文字」从卡面收进弹层，卡面只保留扫读需要的名字、状态、说明和控件；
用等高网格把卡尾对齐，用固定头部结构把状态徽标对齐。

## 明确没做

- 不截断说明：`summary` 仍全文直出（v2 的用户口径），只靠等高网格消化长短差异。
- 不改 `plugins.json` 的 `requires` / `summary` / 分组（契约改动另立项）。
- 不动「工具与命令」组（`settings-tool-policy.js`）的卡片形态；它跟着网格等高，内容与样式不变。
- 卡面不另加开关：这是纯前端展示收口，要退回 v2 卡面就是回退这三个文件（`settings-switches.js`、
  `plugin-settings.js`、`style-14-settings-pages.css`）的本次改动。
