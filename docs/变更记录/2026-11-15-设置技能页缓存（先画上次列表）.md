# 设置技能页缓存（先画上次列表）

> 用户口径：每次点设置里的「技能」都要重新加载，先把上次内容留着，后台再更新。

## 结论

`skills-settings.js` 的 `loadSkills` 现在先画上一次成功读到的列表，再在后台拉
`/api/v1/agent/skills` 与建议快照；只有内容真变了才重画 DOM。刷新失败也保留旧列表，
只把位置行改成「刷新失败」。

## 做了什么

- 模块级 `skillCache = { data, advice, signature }`，只放进程内，不写 localStorage。
- 页面进入时 `paintSkillCache` 同步渲染：路径行、筛选/排序、已开启/未开启两区都直接出来，
  不再先显示「读取中…」。
- 拉回数据后算 `skillPageSignature`（dir / origin / items / advice）；和缓存一致就不重画，
  避免后台刷新打断滚动或已经展开的筛选菜单。
- 变了才更新缓存并 `renderSkillList`。
- 刷新失败：有缓存就保留旧列表，路径行追加失败原因；没有缓存才显示错误块。
- 404（`SKILLS_ADMIN=false`）清缓存，按未启用展示。
- 缓存不跨浏览器刷新/重启；要跨刷新得换 sessionStorage，这次没做。

## 验证

- `node --check ts/apps/server/web/skills-settings.js` 通过。
- 浏览器（`bu`）：设置技能页先加载一次；把 `/api/v1/agent/skills` 人为延迟 2s；
  切到「编辑这个人」再切回「技能」——0.2s 内已经显示上次的 18 个已开启列表和路径，
  2s 后数据回来、内容没变就不重画。
- 没有动真实技能开关/正文。

## 刻意没做

- 不持久化到 localStorage / sessionStorage：技能文件会被外部改，缓存跨重启容易变成假真相。
- 不做定时轮询：只在进入页面时后台刷新一次；技能页是设置页，不需要常驻监听。
