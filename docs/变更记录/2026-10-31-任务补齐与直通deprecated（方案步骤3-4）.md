# 任务补齐与直通 deprecated（App 方案《Agent 化与上下文分层》§6 步骤 3-4）

- 日期：2026-10-31
- 方案：App 仓库 `docs/设计方案/2026-10-31-Agent化与上下文分层（只追加）.md` v1.1（D7 任务一律一次调用、D10 直通 deprecated）

## 变更清单

**步骤 3a（本仓库）**：`tasks.ts` 登记 5 个新任务，模板逐字节复制自 App 资产（探针黄金用例自动纳入对照）：

| 任务 | 资产 | 变量 |
|---|---|---|
| `entry_view_polish` | `entry_view_polish_v1.md` | `original_text` |
| `entry_view_digest` | `entry_view_digest_v1.md` | `original_text` |
| `emotion_deep_dive` | `emotion_deep_dive_v1.md` | `recent_messages` / `style_constraints` |
| `memory_curation` | `memory_curation_v2.md` | `entry_text` / `current_memory` |
| `memory_merge` | `memory_merge_v2.md` | `blocks_json` / `new_facts` / `word_limit` |

注意：变量名**跟模板占位符走**，与方案 §5 表里的示意名（`entry_text`/`emotion_tag`）不同——资产是权威。

**步骤 3b（App 仓库）**：`LlmTask` 枚举加 5 个取值；`EntryViewService`（视角×2）、
`DeepDiveQuestionGenerator`（情绪深挖问题）、`MemoryCurator`（策展 + 合并）改发
`X-Task` + `task_vars`，不再塞 SYSTEM 模板；`promptVersion` 仍记 App 资产版本号（溯源口径不变）。
core:emotion 里 `data.model.LlmTask`（队列枚举）与 `ai.model.LlmTask`（通道枚举）重名，后者 import 别名 `WireLlmTask`。

**步骤 4（本仓库）**：`openai-compat.ts` 直通入口打 DEPRECATED 告警（每次调用一行，带序号与 system 长度）。

## 刻意不做的

- **`question` 未切**：模板缺画像/近况变量，且上下文来源（记忆块 vs App 拼）是方案 §9.1 待定项，等需求方拍板；
- **`memory_curation_v3` / `emotion_deep_dive_v2` 未登记**：App 主代码没用它们（V2/V3 是备了没用的新版），
  登记了也没调用方——等切换版本时一并升版登记；
- **`diary_review` 未开始**：新任务，模板与 App UI 都要新做，另开变更记录。

## 影响范围

- App 侧 HTTP 契约不变（仍走 `POST /chat/completions`，只是任务名变多）；
- harness 任务会话多 5 个模板，探针黄金用例逐字节对照 App 资产；
- 直通调用现在会打 `[compat passthrough] DEPRECATED` 告警——观察期口径，不是错误。

## 验证结果

- harness：`pnpm typecheck`、`tasks` 探针（11 个任务字节对照全过）、`http` 探针全过；
- App：`./gradlew :core:ai:test :core:emotion:test :core:memory:test` 全过（JDK 17 需显式 `JAVA_HOME`），
  `spotlessCheck` 通过（DeepDive 有一处 import 格式已自动修）；新增 `all_task_wire_names_match_harness_specs`
  防呆断言（10 个取值逐字钉死）。
