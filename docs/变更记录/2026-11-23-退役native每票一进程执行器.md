# 2026-11-23 退役 native「每票一进程」执行器

> 方案：`docs/设计方案/2026-11-23-退役native每票一进程执行器.md`
>
> 一句话：本机派活只剩执行器池（pool）；旧的 native（每张单 spawn 一个
> `worker-main.ts` 子进程）整档删除。外部 CLI（CodeBuddy / Qoder / Claude Code /
> Codex / OpenCode / 豆包）不变。

## 一、改了什么

### chancellor（`ts/packages/chancellor/`）

- 删 `src/employee/native.ts`（spawn / stdout-stderr / stdin 插话 / 进程注册表 /
  `childEnvWithModel`）。
- `employee/index.ts`：去 native 的能力声明 / 工厂 / 导出；`createEmployee("pool")`
  不再回落 native——池未接线时由 `createPoolEmployee().run()` 返回结构化失败。
- `types.ts`：`EmployeeKind` 去 `native`；`EmployeeProfile.modelRoute` 注释改为
  本机池共用。
- `config.ts`：`CHANCELLOR_EMPLOYEE` 缺省 `native → pool`；历史值 `native` 映射到
  pool 并 warn 一次；`resolveProfile` / `profileEnv` 只保留 pool 分支。
- `index.ts` `workerKindOf()`：历史 `ticket.json.employee="native"` 映射到 pool
  （避免老单恢复时被当前 `CHANCELLOR_EMPLOYEE` 带去外部 CLI）。
- `worker-tools-source.ts`：删只有 native 用的 `workerToolsArgValue()`。
- `worker-main.ts` **保留**：分管宰相（`--role manager`）仍在用它；worker 角色
  变为不可达死分支（见 §四）。

### 宿主（`ts/apps/server/`）

- `executor-config.ts`：`EXECUTOR_KINDS` / 可选项 / 卡片元数据去 native；
  「干活模型 + providerId」解析从 native 平移到 pool；老配置 `employee:"native"`
  与 `profiles.native` 读成 pool（显式 `profiles.pool` 优先，不丢用户设置）。
- `worker-control.ts`：去 native stdin 转发；`pool` / 历史 `native` / 无 employee
  字段的老单一律走池控制面。
- `delegation-actions.ts`：去 `abortNativeWorker`；没有票级控制器时统一按池取消。
- `index.ts`：池入口不存在时日志改为「本机派活不可用」；`POOL_MANAGER_BRIDGE`
  退役（池可用即起桥）。
- `executor-probe.ts`：native 的「本机不探测」分支改挂 pool。
- `pool/pool-settings.ts`：新增 `WORKER_POOL_MAX_TURNS`（池单轮工具回合上限），
  不设仍沿用 `AGENT_MAX_TURNS`。起因：探针把宿主 faux 压到 1 时池被连带压死，
  上报后第二步写 REPORT 被「工具调用已达上限」拦掉（2026-11-23 实测）。
- `pool/supervisor.ts`：构造器读 `WORKER_POOL_DB_DIR`（探针 / 多实例隔离）。
- 设置页 `web/settings-executor.js`：去 native 卡；模型清单 / providerId 改挂 pool。
- `send_to_agent` 的工具描述里「native worker」改为「执行器池里的 worker」
  （工具描述属缓存前缀资产，本次一并说明）。

### 探针与单测

- `escalation-probe`：改真池 + `WORKER_POOL_FAUX_MODE=escalate` + 隔离池库
  + `WORKER_POOL_MAX_TURNS=100`；全链路通过（上报 → 挂起 → 答复 → 续跑 → done）。
- `delegate-wake-probe` / `delegate-chain-probe` / `matrix-probe`：默认执行器改 pool，

- `worktree-cleanup-probe`：改「pool 标签 + 替身 PoolClient」。它验的是 worktree

## 二、兼容与迁移

- `CHANCELLOR_EMPLOYEE=native` → `pool`（宿主与 chancellor 两侧都映射，日志留一行）。
- `.data/executor.json` 的 `employee:"native"` → `pool`；只写了 `profiles.native`
  的文件，其 model / permission / providerId 当作 `profiles.pool` 的缺省读出来。
- 历史 `ticket.json.employee="native"` → pool（同内核、同 REPORT 契约；native 的
  会话号本来就不参与续接）。
- 回滚：native 已无代码级开关；池出问题用 git revert，或把「设置 → 派活」切到
  外部 CLI。`POOL_MANAGER_BRIDGE=false` 不再是有效形态（关掉 = manager 子单必失败）。

## 四、已知边界 / 刻意不做

- **dist 单文件产物**：池入口是源码 `.ts`（tsx 起），`node dist/index.js` 下
  `available()=false`，本机派活会如实报「池执行器未接线」。桌面壳与日常都走源码，
  dist 仍只保证「能起、能服务」；要支持就把 `pool-main.ts` 加成第二构建入口，单独立项。
- **`worker-main.ts` 的 worker 角色**：native 退役后不可达，但和 manager 角色共用
  Harness / 工具 / 续行主体；本批不拆，等 manager 换实现时一起收。
- **worker 会话（chatKind=worker）**：与本次删的执行器无关，仍按 2026-11-23 的
  「退役新建、历史可读」口径。
