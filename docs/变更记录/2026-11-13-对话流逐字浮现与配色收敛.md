# 2026-11-13 对话流逐字浮现与配色收敛

- **新增 `ts/apps/server/web/stream-reveal.js`**：流式回答的逐字/逐词浮现。
  - 中日文按单字、英文按词；只动 opacity，300ms ease-out，排 `transition-delay`（0–40ms 间隔、最晚 250ms 开始）。
  - 与上一轮 DOM 做 text-run 前缀 diff：旧 span 不重建，只追加新单元；拉丁词续写只改旧 span 文本。
  - 非前缀 / 单帧 >600 字符 / 正文 >8000 字符 / 连续三次更新 >28ms / reduced-motion / flag=false → 静态整块渲染。

  - `addMessage(..., {fresh})`：只有 `send` / `followUp` / `steer` 播入场；`openChat` 历史回读不播。
  - 思考卡：14px conic 彗星环 + 4s 扫光文案，`data-live=0` 后停。
  - 工作过程：`.is-live` 面板头行 2px 不确定进度扫光；新步骤行 220ms 入场；状态点落定 260ms 弹一下；历史面板不加。
  - 派活行：`event.domain` 首字 16px chip，运行中 accent 环。
  - `ensureTasksRedesignFlag()` 收成通用 `ensureFlag(key, fallback)`，复用同一次 `GET /api/v1/agent/flags`。

- **文档**：本变更记录 + `docs/设计方案/2026-11-13-对话流动画与配色（对齐ZCode与DS-Bot）.md` + `docs/基线文档/系统架构.md` 已知边界。

## 为什么

旧版 `paint()` 每帧 `body.innerHTML = renderMarkdown(answer)`，正文子节点动画每帧被重置，文字只能成块蹦出；历史回读又和现场消息共用入场动画，打开旧会话整屏同时入场。逐字浮现必须"只追加、不重建旧 span"，所以引入独立的增量渲染模块。

## 已知边界

同 `docs/基线文档/系统架构.md`「对话流逐字浮现的已知边界」：只覆盖电脑端单聊；非前缀/大增量/长文退回静态；收尾最多丢 250ms 尾巴；flag 或 reduced-motion 回旧路径。
