### 2. 前置连开 / 父项连带关（`ts/apps/server/src/flags.ts`）

四个端点，挂在 `mountFlags()` 内，继承既有 `/api/v1` 鉴权与 `AGENT_FLAGS_UI` 早退：

| 端点 | 语义 |
|---|---|
| `GET /api/v1/agent/flags/:key/enable-plan` | 只读：缺哪些祖先（拓扑序）、每个写什么值、会连带恢复谁、哪些要选档位 |
| `POST /api/v1/agent/flags/:key/enable` | `{confirm:true, values?}`；服务端重新推演后按拓扑序逐键写；目标已开 `alreadyOn` |
| `GET /api/v1/agent/flags/:key/disable-plan` | 只读：关值 + 会被连带关掉的后代 |
| `POST /api/v1/agent/flags/:key/disable` | `{confirm:true}`；只写父，子项存储值不动；目标已关 `alreadyOff` |

实现口径（Qoder 三轮验收后定稿）：

- `willWrite` = 自身存储值就是关值；存储值开、只被父锁 → `false`，父开自动恢复，不写。
- 布尔键（`values` 只有 true/false）一律可关，关值 `"false"`；枚举/数值键无 `offValue` → 400 `flag_not_disableable`。
- `revive` 排除 `missing ∪ {key}`，并**模拟计划写完后**的生效值——二层恢复（如 `MEMORY_ENABLED` 关 → 开
  `MEMORY_EXTRACT` 时 `PARTNER_MEMORY_RECALL` / `MEMORY_INJECT_DEDUPE` 一起恢复）必须列出来。
- `AGENT_TOOL_POLICY` 这类关值是 `"full"` 的枚举，按自己的 `offValue` 判关，不能只认 false/0/off。
- 逐键写 JSON 不是事务；中途失败 500 `partial`，带已写前缀。

## 回滚

| 回滚 | 做法 |
|---|---|
| 四条端点 | `FLAG_CASCADE_ENABLE=false` → 整组 404；前端按钮按 `flagCascade` 隐藏 |
| `MEMORY_IMPORT` 登记 | **必须原子回滚**：清单删键 + 消费点改回 env 读法。只删清单项会让 `flagEnabled` 对未知键返回 false，导入永久关闭 |
| 9 条 requires | 删对应 `requires` 行；父锁变回未锁 |
| 前端连开 UI | 随 `FLAG_CASCADE_ENABLE=false` 自动隐藏；也可删 `settings-switches.js` 的 `data-flag-enable-plan` 分支 |

## 没验证 / 已知边界

- `hot:false` 的开关：界面立刻收，后端能力重启后才停；插件卡上的「待重启」是唯一徽标位。
- `AGENT_FLAGS_UI=false` 时 `/agent/flags` 404，显隐注册表 fail-open（全部按开），
  「关了界面就消失」在该部署下不成立。
- plan 无版本号；`GET plan` 与 `POST confirm` 之间别的标签页改了父键，POST 以当时状态重新推演。
- 并发两条 enable 打同一棵链没有互斥（单进程 + 逐键原子写，幂等但可能重复写同一值）。
- 手机端不改；`PUT` 仍是单键旧语义，手机端继续可用。
