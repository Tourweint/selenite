# 普通对话加「回到底部」按钮（2026-11-16）

> 用户口径：普通对话往上翻之后，最底下的内容不好找，加一个「回到底部」按钮——内容长、往上翻的时候在底下浮出来。

## 改了什么

文件：`ts/apps/server/web/index.html`、`ts/apps/server/web/style-04-chat-base.css`、`ts/apps/server/web/chat-notice.js`

- 对话主区加一枚 `#chat-backbottom` 浮动按钮（圆形下箭头），绝对定位在输入卡正上方、消息列中轴。
  `bottom` 跟着实测卡高 `--composer-h` 走，输入卡长高时自动上移；首页态（`data-home="1"`）CSS 兜底永不显示。
- 显隐挂在**既有滚动监听**上（`chat-notice.js` 的 `el.scroll` `scroll` 监听，本来就算了 `distance`），
  不另起监听：离底部 `distance >= 300`（一屏内）才显示，贴近底部自动隐藏。复用同一份计算，零额外滚动开销。
- 点击走已有的 `scrollToEnd()`（直接 `scrollTop = scrollHeight`，一步到最新），随后立即隐藏按钮。
  内嵌 webview 里平滑滚动 / rAF 都是 no-op（同日记忆页回顶已实测），所以照旧一步到顶最可靠。

## 为什么这样放

- 位置：贴着 composer 上沿居中，是「回到最新」的直觉落点；不遮消息、不遮输入。
- 逻辑：与 `state.stick`（距底 < 80 视为贴底）共用同一 scroll 事件，避免出现「贴底了按钮还挂着」的两套状态。
- 没有 inner scroll / 没动历史分页：滑到顶照旧自动续上一页，按钮只是附加的快捷跳转。

## 验证

- `node --check chat-notice.js`、`pnpm typecheck` 均通过。
- 浏览器（内嵌 webview）实测：注入 30 条测试消息撑高到 scrollHeight 1529 / 视口 632；
  滚到顶（离底 897px）按钮出现，滚到底消失；点按钮 `scrollTop` 0 → 897（= 底部）且按钮隐藏；
  截图确认按钮浮在输入卡正上方、外观正常。刷新后测试消息清除、按钮回到隐藏态。
- 没跑单测：本批是纯前端 DOM/CSS/事件改动，不碰 TS 运行时；typecheck 干净。

## 明确不做

- 不加平滑滚动（webview 无效且属多余动画）。
- 不改 `state.stick` / 历史分页 / 通知等既有滚动语义。
- 群组 / 任务中心等其它视图不加——本批只做普通对话。
