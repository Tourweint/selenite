### 2. 记忆凭据打码（P1）

- **新文件 `ts/packages/memory/src/redact.ts`**：`redactSecrets(text)` 纯函数，零依赖。
  命中 `sk-` / `pk-` / `rk-` / `ghp_` / `github_pat_` / `xox*-`、`Bearer …`、JWT、
  `api_key=` / `token:` / `secret=` / `password=` / `密码：` / `口令=` 等，以及 ≥32 位 base64/hex；
  一律替换为 `«redacted»`（带字段名的形态保留字段名，读得懂"这里原来是什么"）。
  幂等；手机号、生日、地址、人名**故意放行**。
- **唯一收口点 = store 的 `put()` / `patch(content)`**（`store.ts`，两种 store 都改）。
  选它而不是 `engine.remember()`：`memory-ingest.ts` 的日记摄入直接调 `store.put()`，
  只有 put 能覆盖工具 / 抽取 / 导入 / 巩固 / 摄入**全部**写入方。
- 开关 `MEMORY_REDACT`（默认开；`false`/`0` 直通）。store 构造时读取，`memory-ingest`
  直接 new store 也同一口径。
- **只治理写入**：召回、列表、读取路径不再打码，避免二次处理。
- `engine.remember()` 改为回读 store 再返回——调用方拿到的是真正入库的那份，工具不会把原文再吐一遍。
- 测试（`packages/memory/scripts/selftest.ts` §16）：14 个正例、6 个反例、幂等、put/patch 收口、
  `redact:false` 旁路与 `MEMORY_REDACT` 解析。

### 3. 记忆 `intention` 类型（P1）

- `MemoryKind` 增加 `intention`；`MemoryRecord` / `MemoryCandidate` / `RememberInput` 增加可选
  `expiresAt`。**`MemoryKind` 在 `packages/memory`，`shared` 零改动**（先核对后动手）。
- SQLite：`memories` 表加 `expires_at TEXT`；老库靠 `ensureColumns()` 的
  `PRAGMA table_info` + `ALTER TABLE` 补列，不引迁移框架、不用迁移脚本。
- **过期降级选"读时惰性"**（`engine.recall()` / `engine.list()` 开头扫 `kind=intention` 的窗口，
  `expiresAt < now` 就 `patch({kind:"fact", expiresAt:null})`）。
  理由：不建定时器；巩固只在会话边界跑，跨天回来先读后巩固会看到已过期的 kind；
  读时做才能保证"看到的 kind 一定没过期"。只扫意图窗口，规模不随记忆总量增长。
- 召回注入新增第三组 `【打算】`（紧随 `【用户偏好】`，排在其它之前）；过期的已在 recall 开头
  降级为 fact，按普通规则走。
- `remember` 工具：`MEMORY_KINDS` 加 `intention`，新增可选 `expiresInDays`（1..365，仅
  `kind=intention` 时换算成 `expiresAt`；其它 kind 传了忽略）。描述补"我打算…"用法。
- 巩固：`intention` 与 `work` 同待遇——不查重、不合并、不强化；写入保留 `expiresAt`。
- 衰减：retriever 打分与 `touchRecall` 写回都跳过 intention 的 importance 衰减（到期由
  `expiresAt` 管，不该二次惩罚）；命中强化照旧。
- 会话封顶修剪：`pruneSessionScopes` 的 `protectKinds` 加 `intention`。
- 前端（`web/app.js` + `style.css`）：只加 `intention` 一处映射——标签/排序/悬停解释，
  条目 meta 加一个"打算"徽章；其余 kind 展示不动。
- 测试（selftest §17）：写入带 `expiresAt`、过期读到 `kind=fact` 且正文不删、未过期优先注入、
  无 `expiresAt` 不过期且不衰减、巩固同正文各记一条不强化。

### 4. 会话考古 `recall_sessions`（P2）

- **新文件 `ts/apps/server/src/agent/session-search.ts`**：
  - 纯核心 `searchTranscriptLines(sources, query, {days,limit}, now)`：跨会话子串检索、
    `days` 默认 30（1..365）、`limit` 默认 5（1..20）、snippet 从命中处前 100 字起裁 200、
    出口过 `redactSecrets`；无命中返回空数组。
  - durable 适配 `searchSessions(reader, …)`：读 `Chats.byExternal` **全部会话**
    （含执事 / 群 / `task-` 专线，含列表里隐藏的），逐会话读 transcript；标题取
    `.data/chat-meta.json` 的改名，否则首句（标题也过打码）。
  - 只依赖 `agent/shared.ts`，不 import `session.ts` / `lifecycle.ts`，避免装配环。
- 复用说明：任务书点的 `search.ts` / `search-api.ts` 实际是**网络搜索**（DeepSeek
  `/v1/tools/search`），真正的会话检索基线是 `agent/session.ts:searchTranscripts`
  （逐会话读 transcript 做 LIKE）。它刻意跳过任务专线与隐藏会话，无法满足"全部会话"，
  因此本批照它的形状另写跨会话版本，不改列表搜索的语义。
- `tools.ts`：新增条件注册工具 `recall_sessions`（`ToolDeps.recallSessions` 注入；
  不传 = 不上架）。只读，**不进 `WRITE_TOOLS`**；不影响基线 10 个工具。
- `agent/lifecycle.ts`：`AGENT_RECALL_SESSIONS`（默认开，`false`/`0`/`off` 关）为真时注入
  `getHarness().then(h => searchSessions(h, …))`（惰性取，工具执行时 harness 已就绪）。
- 输出：`[{conversationId, title, at, snippet}]` 渲染成 `日期｜标题（uuid）+ …片段…`；
  日志只记 query 字数与条数。
- 测试（`agent/session-search.test.ts`，5 条）：跨两会话命中、snippet 截断（200 字、命中词前
  恰好 100 字）、days/limit、无命中空数组、snippet 打码、含 `task-` 专线的假 reader、
  开关与条件注册。

## 已知边界 / 刻意没做

- 打码是正则形状匹配，不是密钥识别器：**宁可多打**（≥32 位字母数字串会被当随机串打掉）；
  形态之外的自定义密钥（如"暗号是…"）不会命中。
- `MEMORY_REDACT` 在 store 构造时读取，运行中改 env 不生效（与 `MEMORY_*` 其它开关同口径）。
- intention 不传 `expiresInDays` = 永不过期；过期降级不改 `importance`，也不写 `supersededBy`
  （历史链不需要，正文与时间都在）。
- `recall_sessions` 是子串检索，不做分词 / 不做向量 / 不建索引；逐会话打开 transcript，
  代价与 `listChats` 同口径，会话特别多时会慢（显式调用可接受）。
- snippet 是固定 200 字窗口，长命中词（>100 字）会被截断；`query` 少于 2 字直接返回空（与
  `searchTranscripts` 同口径）。
- 只查本机库；不含远程/跨设备会话。
- 未跑：`pnpm probe`（本批未改内核提交/流式/闸门/睡眠语义）、`providers` / `diary` / `tasks` /
  `phone` 等专线探针。
