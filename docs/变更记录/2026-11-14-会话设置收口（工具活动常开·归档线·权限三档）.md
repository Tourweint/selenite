# 会话设置收口（工具活动常开 / 自动归档少一根线 / 权限三档重排）

用户这一轮八句话，落成五件事："设置里的工具活动还能打开和关闭。我不知道你放这是什么意图，我不相信有人会关闭这个东西""底下这个自动归档，第一次自动归档的线好像画多了，好像画的是两条线……保留天数底下的这条横线颜色比较深""把工具活动放到高级指令里头……好像叫高级开关吧""底下这个权限也不对劲……应该是完全访问""在工作区内修改""制度（只读）和不跑命令这两个是一件事，把它们俩融合一下，加上一个在工作区内修改""审批就没问题""把这几个的方向换一下，完全访问应该放在最右边"。

## 改了什么、为什么

### 1. 工具活动不再能关（`会话` 页那一行整体撤走）

**没有理由让人关它。** 一段回答里少了「读了哪个文件、跑了什么命令、花了多久」，事后就无从复核它到底动过什么——这条不是偏好，是审计凭据。

- 撤 `会话` 卡里的「工具活动」开关（`data-acts-switch`）；
- `applyActPref()` 连同 `KEY_ACTS`（`lifediary.showActs`）一起删：不再写这个 key，也不再读。老机器里存过 `"0"` 的，现在一律按"显示"走——不迁移、不提示，因为那个值本来就不该存在；
- `style-06-tool-blocks.css` 里 `html[data-acts="0"] .tchips-wrap { display:none }` 同步删掉。留着它等于留一条能把灰块藏起来的暗道，和"常开"自相矛盾。

### 2. 工具活动挪进 `服务` → `高级开关`，只报状态不给开关

`高级开关` 这一节现在是两张卡：上面一张只有一行「工具活动 · 常开」，下面才是服务端开关表（`#flags-card`）。

分成两张卡而不是塞进 `#flags-card`，是因为那张卡每次 `loadFlagsSettings()` 都 `replaceChildren()` 重建，静态行混进去会被刷掉；而且开关表是"改了就生效"的东西，常开状态不是。

### 3. 自动归档卡：那根"颜色比较深"的线是两根叠在一起

不是错觉。原结构是

```
行(自动归档旧会话) / divider / 行(保留天数) / divider / <div class="row" hidden>
```

提示行 `hidden` 时占 0 高，但它**前面那根 divider 还在**——于是最后一根 1px 分隔线正好贴在卡片自己的 1px 底边上，两根叠成一根，看起来又深又像画了两道。

修法是让分隔线和提示行同生共死：外面套一个 `#archive-auto-hint-wrap`，divider 放进 wrapper 里，`hidden` 加在 wrapper 上（`settings-switches.js` 的 `hintWrap.hidden = !hint?.textContent` 同步改）。没有提示时，卡片最后一根线就是它自己的边框。

### 4. 权限三档：只读 → 在工作区内修改 → 完全访问（完全访问恒在最右）

| 档 | 对外文案 | 服务端 `access` | 实际拦什么 |
|---|---|---|---|
| 只读 | 能看，不改文件，不跑命令 | `read-only` | `WRITE_TOOLS`（写/改/派活/建群…） |
| 在工作区内修改 | 只能改工作区和项目里的文件，命令不跑 | `no-shell` | `bash` / `powershell` |
| 完全访问 | 能改文件、能跑命令 | `full` | 都不拦（`blocked` 黑名单除外） |

**顺序改了，值没改。** `POST /agent/policy` 仍然收 `full` / `read-only` / `no-shell`，老客户端、手机端不用跟着动；变的只有 `label` 的中文名（`no-shell` → 「在工作区内修改」）和界面上的左右次序（最保守在左，完全访问压在最右）。

**"只读"和"不跑命令"其实不是一件事**（一个拦写、一个拦命令），但摆在一起时用户读不出差别，这也是当初抽屉里改成竖排的原因。这一轮按用户的口径收成三档：保守档只留「只读」（不改也不跑），中间那档给"能改、但只在工作区里改"一个名字。中间档仍然不跑命令——`bash` / `powershell` 不做命令文本扫描（`系统架构.md` 已登记的已知边界），放开命令就说不清它到底在哪动手，所以文案写的是"命令不跑"，不写"命令只准在工作区跑"。

同一份三档在两处出现，一起改：全屏设置页（`settings-router.js` 的分段控件）和对话设置抽屉（`settings-permission.js` 的竖排选项行）。抽屉里从上到下也是 只读 → 在工作区内修改 → 完全访问。

### 5. 审批档没动

用户说"审批就没问题"，`全部问我 / 只问重要的 / 全不问` 原样保留。

## 这条会怎么错

- **中间档叫"在工作区内修改"，但没有"在工作区里跑命令"这回事。** 想干需要跑命令的活，只能上完全访问。如果之后真把命令文本扫描或沙箱做出来，这一档的文案要跟着改成"命令也限工作区"，否则名字会一直比能力大。
- **"只读"吞掉了"不跑命令"。** 原来的 `no-shell` 其实允许改文件，现在对外只承诺"在工作区内修改"，有机会被读成"改文件的地方限制在工作区"而不是"命令不跑"。真被误读的话，正解是副文里把"命令不跑"往前挪，而不是把档拆回四个。
- **旧 key 没清。** `lifediary.showActs=0` 还留在一些机器的 localStorage 里，现在没人读了。将来谁再引入"隐藏工具活动"的功能，别复用它，否则老机器一升级就是默认关。
- **`#acts-card` 和 `#flags-card` 是两张卡。** 如果以后还要往这一节加静态状态行，得继续往第一张卡里加，别往 `#flags-card` 里塞——那张卡每次读 flag 都会重建。
