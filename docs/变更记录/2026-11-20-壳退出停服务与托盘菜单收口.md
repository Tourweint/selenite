# 壳退出停服务与托盘菜单收口（2026-11-20）

免写方案（桌面壳行为微调，不涉及服务端契约 / 跨仓库契约）。只改 `desktop/`。

## 背景

窗口 X 的既有语义是「最小化到托盘」：壳隐藏、Node 服务照跑（手机连接、提醒、后台任务都要它）。
但托盘「退出」此前也只关壳——服务是 `DETACHED_PROCESS` 起的，会留在后台。结果是
**桌面上找不到它、也没有入口停**，用户只能去任务管理器翻 node 进程。托盘原来还有一个
「设置」项，与页面内的设置入口重复。

## 改了什么

- **托盘菜单**：`显示/隐藏 / 重新连接 / ─── / 退出并停止服务`。
  - 删「设置」（页面内可进；`LIFEDIARY_VIEW=settings` 深链保留给命令行/调试）。
  - 「退出」→「退出并停止服务」，`Role: RoleQuit` 与原有确认链不变。
- **退出链**（`desktop/tray-features.go`）：`OnBeforeQuit` 挂起退出后异步做两件事——
  1. 查 `GET /api/v1/tickets`，有在飞单就确认（文案改为「退出会停止服务并中断它们」）；
  2. `runtime.Stop()` 停 Node 服务；停不掉时弹「重试 / 仍然退出 / 取消退出」，
     不静默带着一个活着的 node 退出。
  两关都过才放行 `App.Quit`。
- **在飞单集合按现口径修正**：非终态 = `received / planning / planned / dispatching`。
  删掉 `reviewing`（2026-11-19 验收层退役）与 `idle`（终态；等子单，子单自己也在列表里，算两遍会多报）。
- **`runtime.Stop` 两个小补**：
  - 查 PID 与 `taskkill` 之间进程自己退了会报「找不到」，此时端口已空 = 目的达成，按成功处理；
  - 端口上没人、要回落到记忆里的旧 PID 时，先用 `tasklist` 确认它还是 `node.exe`——
    Windows 会回收 PID，服务崩掉后对着旧数字 `taskkill /T` 可能误杀无关进程。
- **首次关窗提示**补一句出路：「要连服务一起关，用托盘的『退出并停止服务』」。
- **托盘悬停提示只留名字**：tooltip 从「Selenite <version> — 服务状态」收成「Selenite」，
  状态继续由图标颜色表达（彩色 = 运行/启动中，灰 = 停止/异常）；版本号改为启动时记一行日志。
  `trayStateText` 随之删除。
- **回滚开关**：`LIFEDIARY_QUIT_STOP_SERVICE=off` 回到旧形态（退出只关壳，服务留后台）。

## 刻意没有

- 窗口 X 仍只隐藏，不退出——手机与提醒要靠服务常驻。
- 不新增「只退出壳、保留服务」的第二个菜单项，也不按 `Owned` 区分谁拉起的服务
  （与设置页「停止」按钮同口径：停的是端口上那个）。开发者想保留服务用回滚 env。
- 不碰服务端契约、不加新端点。
