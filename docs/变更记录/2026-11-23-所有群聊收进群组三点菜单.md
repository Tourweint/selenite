# 2026-11-23 「所有群聊」从分区底部收进群组 ⋯ 菜单

## 用户口径

「把侧边栏的打开所有群聊放到右边三个点菜单里」。

取代 2026-11-07 那一版「放在群组展开之后的底下」：展开态分区体内不再留独立链接行，
入口和「新建群组」一样挂在分区头的 ⋯ 上。

## 改了什么

| 文件 | 改动 |
|---|---|
| `web/index.html` | 删掉分区体内的 `#sec-groups-all`（`所有群聊 →` 那行） |
| `web/groups-settings-panels.js` | ⋯ 菜单加第二项「所有群聊」（`go("groups")`）；删掉底行按钮的点击绑定 |
| `web/groups-base.js` | 可用性同步不再管底行；⋯ 未启用时整颗 disabled，两个菜单项一起不可点 |
| `web/route.js` | 删掉 `applyRoute` 里给 `#sec-groups-all` 写 `aria-current` 的那一段 |
| `web/dom.js` | 摘掉 `secGroupsAll` 引用 |
| `web/style-03-sidebar-zones.css` | 删掉 `.sec-foot-link[aria-current="true"]`（唯一使用者已移除，规则成死码） |

菜单顺序：`新建群组` / `所有群聊`。建群路径不变（先落群组页再开建群弹窗），
「所有群聊」仍是 `#/groups` 列表态，群会话里点它也不必先按顶栏返回。

## 为什么不再做选中态

底行那颗按钮原来在群列表态会亮（`aria-current`），因为它常驻、能表示「你正站在这片列表上」。
菜单项是一次性动作，选完就关；群列表态的位置感由轨道钮 / 分区行的选中态承担
（`syncRailCurrent` / `syncSideRowsCurrent` 未动）。

## 没做 / 边界

- **收起轨道的群组悬停卡仍保留底部「所有群聊 →」**：那张卡没有 ⋯ 菜单，它是收起态唯一的列表入口，
  这次只动展开态分区头。
- 群会话顶栏返回键保留（两层退法不变）。
- 群组未启用时 ⋯ 整颗 disabled，与改前一致；没有出现「⋯ 可点但菜单项全灰」的半残态。
