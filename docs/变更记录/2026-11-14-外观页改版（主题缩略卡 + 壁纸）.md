# 外观页改版：主题换成缩略卡，加上壁纸

> 记录一次用户拍板后的落地：外观页「主题 / 主题色」换成 A 版（缩略界面卡），并新增「壁纸」一节（无 / 内置 / 自定义 + 可见度 + 模糊）。

## 用户原话

> 「可以，就用 A，我觉得没啥关系。那么就是 BCD 太乱了，然后你新加的这个加上，OK，就这样。」

上一轮给的四版草图（A 缩略界面卡 / B 大预览 + 列表 / C 明暗分段 + 两家族 / D 材质色带）里，用户只要 A，并且要壁纸那块一起上。B、C、D 不做，也不做「主题家族 × 明暗模式」的模型改造——四套主题仍并列，切换即固定。

## 结论

1. **主题块换成缩略界面卡，一排五张**：每张卡是一个 58px 高的微缩界面（左 30% 侧栏 + 两条气泡 + 一个强调点），卡底铺该主题的 card-high，所以五张卡读起来就是五张纸。选中态是强调色描边 + 右上角对勾。卡宽 ~178（原来是四个 233 撑满），比例 3:1；行距上下各留出空隙，离底下的分割线 18px。
2. **主题色十档 + 自定义取色**（2026-11-14 后加）：靛蓝 / 暖金 / 琥珀 三档仍是手机端色板原色（值一个字节没动），后面补 玫瑰 / 松绿 / 石青 / 赭石 / 藤紫 / 墨灰 / 珊瑚 七档，成对的浅底值 + 夜底值写死在 `style-01-tokens.css`；第十一个圆点是虚线圈，点开系统色盘，选什么色当场算 `--accent`（夜主题自动提亮到 62%、容器压深）。名字那一栏预设显中文，自定义显 `#RRGGBB`。
3. **壁纸一排五格**：无 / 宣纸纹 / 细格 / 云纹 / 自定义。新补的两档都是纯 CSS 纹理（细格 = 1px 方格 14px；云纹 = 三层大尺度墨晕），跟着主题墨色走，夜主题不会冒出暖白。说明文字（格式、20 MB、换图会覆盖）全部收进「壁纸」标签的悬停提示，行里不再摆一行灰字。
4. **第五套主题「青瓷」（2026-11-14 后加）**：淡青瓷纸 `#f1f5f1` + 墨绿字 `#1e2a25` + 灰绿描边，冷调低饱和。强调色仍走靛蓝原色（只是容器色改成灰绿），所以换到这套是"换了张纸"，不是换一套颜色语言——和其余四套同一套规则。
5. **主题色从三个方块改成三个圆点 + 当前那档的名字**：方块读起来像按钮，圆点才是取色；选中只加一圈强调色描边，不换填充（换填充会把颜色本身盖掉）。
6. **壁纸只铺主区那张纸**（`.main`），不动侧栏、标题栏；气泡、卡片、composer 保持不透明。让"纸"换材质，不让界面变成一层蒙版。
7. **自定义图先裁剪再上传**（2026-11-14 晚加）：选完图不是直接 cover，而是弹一个和主区同比例的取景框——拖动选位置、滑杆缩放（100–400%）、三分线对位，确定后只把框里那一块用 `canvas.drawImage` 裁出来、压成 JPEG(0.9) 再 POST。存下来的图比例就是主区比例，铺上去"正好铺满、不再二次裁"。已经存过的图也能重新裁（按钮「裁剪」读服务端那张图再进同一个框）。
8. **换图不再需要先移除**：「换一张 / 裁剪 / 移除」三个按钮只要服务端存着图就一直在；点已选中的自定义格也会直接开选图框。以前是"必须移除再选一张"，根因是把"有图"判成 `source === "custom" && etag`，切去别的壁纸后这个条件为假，界面就以为没图。
9. **壁纸要铺到最底**：主区底部那条不透明的「底缝衬条」（`.main[data-home]::after`，18px、`--surface`）会在壁纸下方横出一条没有壁纸的带子。有壁纸时它 `content: none` 收起来——挡滚动的活本来就是 `.thread` 的 `padding-bottom`（卡高 + 14 + 44）在干，跟这条衬条无关。

## 壁纸契约

| 端点 | 行为 |
|---|---|
| `GET /api/v1/appearance/wallpaper/meta` | `{present:false}` 或 `{present:true,mime,bytes,etag,savedAt}`，`no-store` |
| `GET /api/v1/appearance/wallpaper` | 回图本体（mime 按**内容嗅探**定，不信客户端 type），带 `?v=<etag>` 时长期缓存；没图 404 |
| `POST /api/v1/appearance/wallpaper` | multipart，字段名 `file`；PNG / JPEG / WebP，≤ 20 MB；非图 415、超大 413；返回同 meta |
| `DELETE /api/v1/appearance/wallpaper` | 删图与 meta，回 `{present:false}` |

存储：`.data/appearance/`（`AGENT_WALLPAPER_DIR` 可改）下的 `wallpaper.<ext>` + `wallpaper.json`，单张覆盖写，png 换 jpg 时清掉旧扩展名。**只有图和 mime 在服务端**；「用哪张 / 可见度 / 模糊」跟主题、强调色一样在 localStorage（`lifediary.wallpaper`）。

为什么必须走服务端：界面是 http 页面（桌面壳与浏览器都是），`file://` 背景图会被同源策略挡掉；Cindy 那套 `cindy-media://` 协议我们没有。

## 两个前端细节（都是踩过才知道的）

- **内置「宣纸纹」不吃模糊滑块**。它是 1px 纤维，`blur` 一开就糊成一片灰——第一版就是这样，截图里几乎看不见。改成 `html[data-wallpaper="paper"] ::before { filter:none }`，同时把这一档的模糊滑杆置灰（`disabled`），并在标签上写明"只对自定义图生效"。
- **`data-wall-remove=""` 的 dataset 值是空字符串**。第一版用 `if (target.dataset.wallRemove)` 判，空串是假值，于是「移除」点了没反应、状态卡在 custom。改用 `hasAttribute`。
- **壁纸那三格的内容原来贴边**。第一版纹理/预览图直接铺满 tile，用户一句「把框全占满了，左右至少留点间距」。改成 tile 内留 8px、内容收进一条带 1px 描边的圆角框里（主题卡的缩略图本来就这么做，两边终于一致）。改的时候踩到一个坑：绝对定位的 `<img>` 只写 `inset: 8px`、不写 width/height 时，替换元素按 intrinsic 尺寸出宽（1282px，直接糊出格），必须显式 `width: calc(100% - 16px)`。
- **内置纹理在同样的可见度下比照片淡一大截**。第一版细格 / 云纹按 38% 可见度铺出来几乎看不见（内置底色就是 `--bg`，两层色差只有 5%）。改法：内置三档（宣纸纹 / 细格 / 云纹）在 `::before` 上补 `opacity: min(1, calc(var(--wallpaper-alpha) * 2.2))`，38% 实际画成 ~84%；自定义照片仍是线性 1:1，不会因为这道放大把正文压没。**代价：可见度滑杆在两个档位上手感不一样了——38% 在照片里是淡，在内置纹里是"看得清"。**
- **自定义主题色的选中描边漏了一家**：`syncThemeControls` 只遍历 `[data-accent-choice]`，而开色盘的那个虚线圈用的是 `[data-accent-pick]`，所以选了自定义色之后没有描边。补一行单独同步。
- **裁剪框的量尺量错了页**。第一版 `mainAspect()` 抓 `#view-chat`，可在外观页它是 `hidden`（`clientWidth = 0`），一头栽进 16:9 兜底 → 裁出来 1.78 的图，铺回 1048×920（1.14）的对话页还要再 cover 一次，等于白裁。第二版改成"取当前可见的那个 `.main`"，又踩一次：设置页的 `.main` 是**整窗宽 1280×920（1.39）**，对话页是 1048×920（1.14），照样对不上。最终做法：只在对话页能看见时现量，并把比例写进 `lifediary.wallAspect`；看不见就读这个缓存。启动默认停在聊天页，所以第一次一定量得到。
- **底缝衬条会把壁纸截掉一条**。`.main[data-home]::after` 是 18px、不透明 `--surface`、`z-index:1`（压在所有内容之上），它存在的理由是遮住滚到输入框底下的文字。壁纸一上，它就成了"主区最底下一条没有壁纸的横带"。有壁纸时 `content: none`。衬条本来只是保险：文字到不了那条缝，靠的是 `.thread` 的 `padding-bottom`。
- **"有图"不能用 `source` 判**。原来 `hasImage = source === "custom" && etag`；切去细格再切回自定义，条件为假 → 又弹选图框、按钮也不出现，用户就以为"必须先把图移除才能换"。改成只看 `etag`。
- **卡片里的整块内容没跟 `.row` 对齐**（用户第二次提的才是这个）。`.theme-cards` / `.wallpapers` / `.wall-slider-row` 都是 `.card` 的直接子元素，没吃到 `.row` 的 `padding: 12px 16px`，于是四张主题卡、三格壁纸、两条滑杆（连"可见度 / 模糊"两个标签）全都从卡片左边框一直顶到右边框。改法：这一组统一补 16px 左右内缩；主题卡另按用户要求收窄（先 ≤200 四张居中，后改成五张一排各 178）。夜主题下"无"那格的斜纹也压到 3%，否则近黑底上像警示条。**教训：往 `.card` 里塞自定义块，必须自己补左右内缩，`.row` 的 padding 不会外溢。**

## 这条会怎么错

- **缩略卡是"示意"，不是真界面**。它画的是抽象侧栏和两条灰条，将来主界面大改（比如去掉侧栏）时，这张卡会变得不只是抽象、而是过时。改主界面布局时顺手看一眼这五张卡。
- **五套主题里三浅两深**，浅色那三套（米黄 / 暖白 / 青瓷）靠色相区分，不是靠明度；挤到 178px 宽的缩略卡上，青瓷和暖白在第一眼容易看混。要再加主题的话，优先加深色或加明显材质差，别再往浅底里塞第四种。
- **新主题要改三处**（`style-01-tokens.css` 的 token 块、`theme.js` 的 THEMES、`index.html` 首帧白名单），漏掉最后那个会在刷新时闪回米黄一帧。
- **壁纸只铺主区，模型页/任务页也一起铺**。如果哪天某个视图自己带不透明底（比如用量页是整块卡），那个视图里就看不到壁纸——这是"每个视图自己管底"的代价，不是 bug 但会显得不一致。
- **可见度拉高会牺牲文字对比**。65% 以上压深色照片时正文已经吃力；我们没有加"自动压罩"，只在默认值上把 38% 当安全档。真要用照片壁纸的人得自己回调。内置三档另有 ×2.2 的放大（见上），所以同一个 38% 在照片和纹理上不是同一种强度。
- **十档主题色只做了浅底/夜底两档**，中间没有第三档（比如"阴天灰底"那种中等明度主题进来时得再补一组值）；新增主题时记得连带看一眼这七档的成对值是否还够对比。
- **自定义取色的容器色是 `color-mix` 现算的**，浏览器要是哪天变了 `color-mix` 的百分比解析，`--accent-container` 会静默退回无色（不会报错，只是块变透明）。真出问题就把它改成 JS 算好 hex 再写行内变量。
- **图片缓存是 immutable（一年）**，换图靠 URL 上的 `?v=<etag>`。如果哪天服务端图被手删、而本地 localStorage 还留着旧 etag，界面会继续显示浏览器缓存里那张旧图（服务端已 404）——看到"删了还在"先查这两个地方。
- **重新裁剪是在已裁的图上再裁**。服务端只存一张图、不留原图，所以第二次「裁剪」拿到的是上一条 JPEG，再裁再压一档（0.9）。裁一两次看不出来，反复裁就会软。要无损就得让服务端同时存原图 + 裁剪参数，那是另一套接口，这轮没做。
- **裁剪框比例按"当时的窗口形状"定**。窗口拉成很宽或很窄以后再打开外观页，主区比例变了，`cover` 会再裁掉一条边——不是错位，是 cover 的固有行为；在意的话重新点一次「裁剪」就行。
- **比例缓存 `lifediary.wallAspect` 可能过期**：它是"上次在对话页量到的比例"。如果用户从此只在外观页操作（对话页再没打开过）又改了窗口大小，裁剪框还会用旧比例。代价是 cover 再裁一条边，不影响可用。
