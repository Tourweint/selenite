# 普通对话跟随当前项目 · 工作区可见 · 任务中心分人

日期：2026-11-16
状态：已落地（服务端 + 桌面端 web；手机端不涉及）
方案：`docs/设计方案/2026-11-16-对话归工作区与项目归任务.md`（文内记录了同日方向翻转）

## 起因

用户发现侧栏项目行右边有一个小加号能建会话，问「这啥意思？和普通对话有什么区别？」。
核实（2026-11-16 全量审计）：它不是新会话类型，是「切当前项目 + 开普通 worker 对话」的
快捷按钮（`project-switch.js` 的 `newChatInProject`）；它是 silent 的，但会**改全局当前项目**，
之后所有新对话默认落这个项目，用户无感知。

同日的方向翻转（如实记录）：

1. 第一版按「普通对话归主工作区、项目只归任务」做了一轮（会话不再绑 `ChatProjects`）；
2. 用户随后纠正：「**普通对话相当于一个 Worker，肯定要带项目记忆**」——
   第一版把项目记忆切断了，违背原则，当日回滚；
3. 最终口径：**普通对话继续跟随「当前项目」**（带项目记忆）；没选项目时落主工作区；
   只删掉那个 silent 改全局的「＋」，工作区补回可见入口。

## 改了什么

### 服务端

- `agent/session-open.ts`：普通会话继续读「当前项目」，写 `ChatProjects` 归属，并把项目主
  文件夹钉进 `pi.agent.cwd`（2026-11-13 行为保持不变；第一版的「固定落工作区」已回滚）。
- `agent/shared.ts`：`sessionCwd()` 兜底补**主工作区根**：
  会话快照 → 当前项目主文件夹 → 主工作区根 → `AGENT_WORKDIR`。
  （之前没项目时直接掉到进程 cwd；现在落 `<主工作区>` 这类默认目录。）
- `agent/lifecycle-injections.ts`：系统提示改为同时写明
  **主工作区路径 + 当前项目 + 主文件夹 + 已登记项目全清单**（项目名 + 路径，多根缩进）。
  之前只说过「文件操作默认在主工作区」，路径从未出现过。
- `delegation-summary.ts` + `delegation-jobs.ts`：`TicketSummary` 纯增量补
  `dispatcher: {id, name, kind}`——`originConversationId` → `partnerIdOfSession` 反查执事；
  总管会话 / 直派单 / 查不到兜底 `{id:null, name:"总管", kind:"chief"}`。

### 前端

- `project-switch.js`：项目行行尾删除「＋」；右键菜单删除「在这里新开对话」；
  点项目行的 toast 从「已选中：下一个新对话落在这个项目里」改为「已切换到「X」」；
  删除 `newChatInProject` 与 `PROJECT_ICONS.plus`。
  **展开态项目分区顶部加「工作区」一行**（`<主工作区>` 看得见；点它 = 回工作区，
  即取消当前项目，普通对话落这里）。
- `project-browser.js` + `style-13-projects-modal.css`：收起轨道的项目弹层顶部加
  「主工作区 · 默认对话」块（名字 + 路径，点它回工作区）。
- `tasks-redesign.js` + `state.js` + `style-20-tasks-redesign.css`：
  - 「等你回话」按派活人分小节：总管排第一，其余按名字；每个人独立「还有更早的」折叠
    （`state.tasksNeedsOlderOpen` 从 boolean 改为 `Set<personKey>`）。
  - 每个对话组头显示项目名；消息气泡的署名/头像改用派活人名（不再一律写死「总管」）。
  - 「在跑」小卡副行改为「状态 · 项目 · 派活人 · 时间」，窄了用省略号收尾。
  - 「打手手风琴」保留（用户拍板），作为按执行者看的次要视角。

### 契约 / 文档

- `接口-端点2`：`PUT /workspaces/current-project` = 决定下一个新普通对话的项目归属
  （`null` = 落主工作区）；`currentProjectId` 口径同步。
- `接口-端点3`：`GET /tickets` 响应字段补 `dispatcher`。
- `接口文档` §6：`CURRENT_PROJECT` 补「主工作区路径进提示」；无新增 env。
- `系统架构`：当前项目=逻辑归属（补主工作区兜底与可见行）、会话 cwd 优先级、提示词注入表、
  项目连带、D23 项目记忆、刻意不做表（项目行新建对话 / 项目下搜索）。

## 明确不做

- **不做项目行新建对话 / 「项目会话」类型**：项目是任务容器；普通对话跟随当前项目，
  换项目先点项目行选中、再点「对话」分区新建。
- **不做项目下搜索**（用户口径：只有一个全局搜索）。
- **不把项目挂到「人」身上**：worker 是一类人（全局 Worker 人设），项目逐会话/逐单子定；
  派出去的 worker 的项目由单子里的 `project` 决定（派单必须带 project）。
- 手机端不改（不调用 `current-project`，本轮也没有新字段）。
