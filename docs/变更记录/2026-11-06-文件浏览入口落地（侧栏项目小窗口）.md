# 文件浏览入口落地（侧栏项目小窗口 · 桌面资源管理器 + 手机端只读浏览）

- 日期：2026-11-06
- 方案：`docs/设计方案/2026-11-06-文件浏览入口（桌面资源管理器与手机端）.md`（文首已补用户调整：入口从右上角按钮改为侧边栏项目小窗口，按项目根打开）

## 改了什么

- **契约**（`ts/packages/shared/src/index.ts`）：新增 `OpenExplorerRequestSchema`、`FileEntrySchema`、`FileListResponseSchema`、`FileContentResponseSchema`。
- **服务端**（`ts/apps/server/src/files.ts` 新文件，`index.ts` 挂载）：
  - `POST /api/v1/workspaces/open-explorer`：缺省开工作区根；带 `projectId` 开该项目自己的根（复用 `resolveForUse` 派单同款复核）。
  - `GET /api/v1/files` / `GET /api/v1/files/content`：工作区只读浏览。相对路径字形校验 + realpath 复核（与 `path-guard.ts` 同口径，符号链接逃逸拦住）；根层 `.data` 屏蔽（400 `blocked_path`，列表也不出现）；正文只回 UTF-8 ≤512KB。
  - 回滚开关：`EXPLORER_OPEN=false` → 400 `explorer_disabled`；`FILE_BROWSE=false` → 两端点 404。
- **界面**（`web/app.js` / `web/style.css`）：项目总览弹层里，主项目与每个健康的子项目行尾加两颗小钮——「浏览文件」（界面内只读文件浏览器：面包屑 + 列表 + 文本预览）与「在资源管理器中打开」。目录异常（不在了/跑出工作区）的行不出现入口。子项目浏览器起点 = 项目在工作区内的相对路径，按项目直达。
- **验证**：`files.test.ts` 单测 7 项（含越权路径、.data 屏蔽、符号链接逃逸、双开关）；新探针 `scripts/files-probe.ts`（`pnpm --filter @lifediary/server files`）真起服务 16 项全过。`EXPLORER_OPEN` 开启路径由单测注入 opener 覆盖，探针保持开关关闭——不在用户桌面弹资源管理器。

## 为什么入口在侧栏

用户拍板：不做右上角按钮。诉求是「多个工作区不知道打开哪个」——入口必须长在项目旁边，按项目精确对应到自己的文件夹，而不是一个全局按钮开了让用户再猜。

## 手机端

本次不动（契约落 shared 即可），files 两个端点留给 lifediary 后续批次接。

## 没做 / 不确定

- 手机端消费、二进制预览、下载、搜索、实时监听：方案「明确不做」段照旧。
- `EXPLORER_OPEN` 开启时在真实桌面的表现只做了手工可验路径（探针不弹窗），未逐平台实测 macOS/Linux。
