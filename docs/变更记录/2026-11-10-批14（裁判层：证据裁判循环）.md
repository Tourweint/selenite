   `requestRepair` **之前**发生，否则 `slot.requested` 已经被填上，必然返工。
3. **能不能给 chancellor 换"带工具的会话"**：不能。`chancellor/src/employee/qoder.ts` 只有
   `tools:"none"`（`--tools ""`，6 轮上限）与 worker 的全权限（40 轮）两档；chancellor 又是纯库、
   硬约束不许 import harness。**选了宿主侧路线**：服务端已经有 `chatStream` + 工具白名单装配
   （`configureResearchChat` 同款），裁判做成 `ts/apps/server` 的一个 read-only 子会话，
   结论经新增的 `ChancellorOptions.judge` 回传给 chancellor 的返工判定。
   好处：只读白名单复用 `read-allowlist.ts` 既有词表；chancellor 只多一个可选回调，依赖方向不变。

## 判定口径（落地后的实际行为）

- **时机**：review 判 fail / 整体目标核对判未达成 → 叫裁判；验收 pass 不叫（快路径不变）；
  验收判 `blocked` 不叫（那是工人卡住，不是"验收判太严"）；进程级硬失败（worker 崩溃 /
  REPORT 缺失 / 退出码异常）不叫——那是事实，不是判断。
- **四态处置**：`done` → 按完成收，`judge.json` 记 warning 与证据（不改写 `review.json` 的 fail）；
  `continue` → 裁判 reason 进返工提示词新段 `## 裁判复核意见`；`blocked` → `needs_you` +
  attention（need_input）；`wait` → `needs_you` + 「在等外部条件」文案（attention need_action）。
- **铁律**：`toolsUsed === 0` 或 evidence 全空 → `done` 降级 `continue` + warning；
  同一 reason 连续两次（去全部空白后比较）→ `blocked` + warning。
- **轮次**：`DELEGATION_JUDGE_MAX_ROUNDS`（默认 3）按 `judge.json.calls.length` 计；
  用完不再叫，按原有失败路径走。
- **审计**：`<ticketDir>/judge.json` 记每次 `round / verdict / raw_verdict / reason / evidence /
  tools_used / warnings / created_at`；裁判异常也记一条 `verdict:"error"`。

单测钉死的四件事：

1. **裁判只能读**（`delegation-judge.test.ts`）：工具名恰好 `["read","bash"]`；
   `write` / `edit` / `delegate` / `powershell` / `partner_manage` / `routine_manage` 一个都不在，
   且它们仍在 `WRITE_TOOLS` 里（对照）。bash 白名单：`ls` / `cat` / `grep` / `rg` / `wc` 放行；
   `rm -rf .` / `npm test` / `git commit` / `cat /etc/passwd` / 管道 / 重定向 / `cd` 一律拒；
   子目录相对路径仍限在工作区内。`read` 的越界路径（`../outside.txt`、绝对路径）直接回错误、不读盘。
   工具上限：第 3 次调用不执行、回固定话术。
2. **done 无证据 → continue**（`chancellor/src/judge.test.ts`）：`toolsUsed=0` 或 evidence 全空
   → 降级 + warning；正常 done 原样放行。
3. **同一 reason 连续两次 → blocked**（空白差异不算不同）；不同 reason 照常 continue；
   上一次是 done 不触发。
4. **开关默认关**：`judgeEnabled({}) === false`；开闸判据 `shouldConsultJudge` 在
   关 / 没注入 / 轮次用完 / 已中止时恒 false（测试里用假裁判计数断言一次都没被调用）；
   返工提示词不传 `judgeReason` 时与旧文本逐字节一致（断言无 `## 裁判复核意见`）。

## 没验证到的

- **真模型裁判没跑**（任务书明确归派单人）：mock/faux 只会产出非 JSON，验不出裁判好不好使。
  开 `DELEGATION_JUDGE=true` 后需真跑一张会失败的验收单，看 `judge.json` 的证据是否真实。
- **工具上限的"模型侧"行为**：只验了执行层（超限不 spawn）；模型收到"不要再查了"之后会不会
  老实收尾，要在真模型下看。
- **只读白名单不含 `npm` / `git`**：裁判只能读文件（grep/cat/ls），**不能重跑测试**；
  "测试全绿"类证据仍要人复核。这是刻意口径（复用既有安全词表），已登记到系统架构 §7。
- 分管单（`domain` + `managers!=false`）不适用（验收在宰相子进程里）；
  崩溃恢复续跑不叫裁判（没有宿主连接）。
