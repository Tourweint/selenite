# 2026-11-24 默认开销去掉「普通 worker」档

## 用户口径

设置 → 注入 → 上下文 · 默认开销的角色选择器里还能看到「普通 worker（已退役）」。
普通助手会话 2026-11-23 已产品退役（`WORKER_CHAT_ENABLED` 默认关），这一档没有对应的真实会话可看，
「把它去掉就可以了」。

## 改了什么

| 文件 | 改动 |
|---|---|
| `src/context-defaults.ts` | `contextDefaultRoles()` 不再 push `worker` 角色（目录只剩总管 / 活跃执事 / 派活工人（池））；随之删掉只服务这一档的分支：worker 人设拼接（`readWorkerPersona + WORKER_PERSONA_CHAT_TOOLS`）、worker 技能命名空间（`WORKER_SKILL_OWNER`）、工具面「worker 不过滤」豁免 |
| `web/settings-context.js` | 前端兜底花名册去掉 `worker`；深链白名单 `DEEP_LINK_ROLES` 去掉 `worker`（旧链接 `?role=worker` 回落总管，不弹错） |
| `src/context-defaults.test.ts` | 原先拿 worker 当「不过滤基线」的用例改用总管（先取基线、再关总管的 `read`，结束还原），并新增一条「worker 档已移除 / `role=worker` 返回 null」 |
| `scripts/http-probe.ts` | 「关于我」段里原来的 `?role=worker` 0 字槽位断言改为断言 `404`（角色已退役） |

## 为什么

- 默认开销回答的是「这个角色真正开一条新会话要花多少」。普通 worker 会话已经不能新建，
  这一档只是让人误以为还有这个入口；`role=worker` 现在同未知角色处理（`404 unknown_role`）。
- 池工人的默认开销（`role=dispatch-worker`）不受影响，仍然是九段 + 五件工具。

## 没做 / 边界

- 已落盘的普通 worker 老会话仍可按原身份续话；「当前会话」视图里的 `persona` 编辑目标
  （`roleId=worker` → `worker-persona.md`）保留，不因这次移除而失效。
- 不恢复 `WORKER_CHAT_ENABLED=true` 时把这一档加回来：恢复入口只影响能否新建会话，
  默认开销目录不再随它变化。
