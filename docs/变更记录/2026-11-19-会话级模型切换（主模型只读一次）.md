# 会话级模型切换（主模型只读一次）（2026-11-19）

方案：`docs/设计方案/2026-11-19-会话级模型切换（主模型只读一次）.md`。
长期口径：`docs/基线文档/接口文档.md` §6、`接口-端点3-模型任务与供应商.md` §2.8、
`接口-端点1-对话与兼容层.md` §2.1、`系统架构.md` D34。

## 改了什么

- **全局默认只读一次**：新会话用当时的全局默认（或 `ChatRequest.model` 带的一次选择）；
  之后 durable 会话自己记模型。全局 `POST /agent/model` 只影响之后新建的会话。
- **停止每轮全局对齐**：`syncConversationModel` → `ensureConversationModel`，正常路径零 configure；
  只有模型 / 供应商被删、思考变体缺失、档位越界时才修一次（回退 / clamp）。
  任务参数变体（`<模型>#t…`）不碰，避免把任务采样参数换成 thinking 变体。
- **本会话切模型**：新增 `POST /api/v1/agent/chat/:conversationId/model`，只改这一条；
  `thinking` 缺省保留当前档，按新模型支持域 clamp；下一轮生效。
- **本会话模型投影**：`GET /api/v1/agent/model?chat=<id>` 返回这条会话的 `current` / `thinking` /
  `thinkingLevels` / `default` / `sessionModel`；不带 chat 仍是全局投影。
- **新建会话带初始模型**：shared `ChatRequestSchema` 加可选
  `model: {providerId, modelId, thinking?}`（纯增量；手机不发行为不变）。
- **`/mode` 按本会话模型支持域校验**，不再看全局；faux 下同模型换档仍记账（修了一个
  `applyChatMode` 提前 return 不 `rememberLevel` 的旧边角）。
- **执事备选链重试后恢复本会话原模型**：旧实现靠下一轮全局对齐把兜底模型带回；现在不全局对齐了，
  所以 `runPartnerTurn` 在重试循环结束后显式恢复原模型，避免一次 unanswered 把执事的主模型
  永久改成链里的候选。备选链仍然"只改本轮"。
- **前端 pill 本会话级**：
  - 已有会话 → 写本会话端点，只影响这一条；
  - 新会话屏 → 先记 `state.pendingModel`，第一条消息随 `ChatRequest.model` 建会话；
  - 打开 / 新建会话时拉 `GET /agent/model?chat=` 刷新模型与档位；
  - 群聊等非普通会话查不到时回退全局投影，不让 pill 打不开。
- **右上角去掉重复主选**：删「主选模型」卡和首页「模型」值格；执事只留「备选模型」链
  （自动重试），非执事不再出现模型入口。设置 → 模型仍是全局默认。
- **回滚**：`CHAT_SESSION_MODEL=false/0/off` → `ensureConversationModel` 回到旧的全局对齐，
  本会话端点 400 `session_model_disabled`，`GET /agent/model` 带 `sessionModel:false`，
  pill 回到全局切换，`ChatRequest.model` 忽略。

## 为什么

旧文档（2026-11-04 §2.8）早就写「会话创建即绑模型、旧会话不跟随全局切模型、全局切换只影响新会话」，
但 `syncConversationModel` 实际每轮把会话对齐到全局，代码与文档漂移。用户 2026-11-19 要求：
额度用完时只换一条会话，不要动全局；同一会话可以来回切；右上角不再放第二个主选入口。

  - 新会话屏选 model-b → pill 显示 model-b、提示「新会话将使用」；发第一条消息后会话建成、pill 保持 model-b；
  - 再新建一条对话 → pill 显示 model-a（全局默认没被第一条会话带走）；
  - 回到第一条会话 → pill 仍是 model-b；在已有会话里切 model-a / 切回 model-b，提示「下一轮起这条会话用」，不碰全局；
  - 右上角：普通会话只有「权限」，没有「模型」；执事会话是「权限 + 备选模型」；备选页只剩链编辑器与说明。
- **未验**：真模型多会话长跑；群聊 / 任务专线的模型选择（本批刻意不做 UI）。

## 已知边界

- 群成员会话 / 例行任务会话 / 任务专线没有模型选择 UI；它们建会话时取当时的默认，之后保留。
  群聊里 pill 查不到会话时回退全局投影；要给群也做 per-session 需另立项。
- 备选链语义不变：只在执事试跑 / 例行任务轮次里自动重试，不升成主模型。
- 会话模型绑定是"当时那一个 providerId+modelId"；供应商被删后回退全局默认（日志可见）。
- 全局默认改完只影响新会话；旧会话不追——这是本批的明确语义，不是遗漏。
