# 2026-11-22 托盘补「只退出壳（服务继续跑）」

## 改了什么

`desktop/main.go` 托盘菜单补回一个轻出口，「退出」从一项变两项：

```text
显示/隐藏
重新连接
─────────
只退出壳（服务继续跑）   ← 2026-11-22 新增
退出并停止服务
```

`desktop/tray-features.go` 新增 `quitShellOnly()`：`RunOnMain` 里置 `quitting = true`
再 `mygo.App.Quit()`。`OnBeforeQuit` 看到 `quitting` 直接放行，`checkBeforeQuit`
（在飞单确认 + `runtime.Stop()`）整轮跳过；服务以 `DETACHED_PROCESS` 留着跑，
手机、提醒、后台任务都不受影响。

## 为什么

2026-11-20 把托盘唯一一个「退出」改成了「停服务 + 退壳」，理由是 Node 服务
`DETACHED_PROCESS` 脱离壳后没有可见入口停。但代价是 **想重编壳时没有干净出口**：
Windows 上运行中的 `lifediary-shell.exe` 被进程独占，`go build -o` 会 Access denied；
而「退出并停止服务」会顺带停掉服务——重编壳不应该要求停服务。

用户 2026-11-22 明确要「只退出这个壳子」的入口。

## 边界 / 取舍

- **不弹确认框**：只是关窗，任务不中断，没有可确认的后果（与「退出并停止服务」
  的在飞单确认区分开）。
- **没有托盘图标残留**：走的是正常 `App.Quit` → `OnWillQuit` 销毁 tray，不是 taskkill。
- **孤儿 node 的旧问题不在本批治**：只退壳后 node 留在后台，这是轻出口的语义；
  要一起收走仍是「退出并停止服务」。`LIFEDIARY_QUIT_STOP_SERVICE=off` 回滚开关保留
  （它作用在完整退出项上，与新增项无关）。

## 验证

- `gofmt` / `go vet ./...` / `go test ./...`（desktop）全绿；`TestQuitStopsServiceSwitch` 仍绿。
- 重编 `lifediary-shell.exe` 并重启壳；`GET http://127.0.0.1:39847/` 仍 200（服务未受退壳影响）。
- 菜单项与「只退出壳」的真机点击未验（需要用户在托盘右键点一次）。
