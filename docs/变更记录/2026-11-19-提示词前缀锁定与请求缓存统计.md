# 2026-11-19 提示词前缀锁定与请求缓存统计

**改了什么**

1. **固定前缀不再自动变**
   - `current_project` 拆两半：system 只留主工作区 / 本会话工作目录快照 / 全部已登记项目 /
     同名文件纪律；「当前项目 / 主文件夹 / 相对路径基准」→ 新消息注入 `current_project_live`。
   - `topics` 拆两半：system 只留固定的课题嗅探判据；「在跟的课题」清单 + 攒着的简报 →
     新消息注入 `topics_live`。
   - 两个新 order：`current_project_live = 45`、`topics_live = 65`，都 `channel: "message"`、
     `scope: "turn"`。

2. **消息注入改 user 角色 + 追加到请求尾部**
   - `lifecycle-harness.ts` 的 `beforeRequest` 不再 `[{role:"system"}, ...request.messages]`；
     合成一条以 `INJECTION_CONTEXT_HEADER` 开头的 user 消息追加到 **尾部**。
   - 原因：OpenAI 兼容适配层对不支持「中途 system」的模型走 `collapseSystemMessages()`，
     任何 system 消息（放哪都一样）都会被合并进第一条 system。放尾部 + user 角色才躲得开。

3. **设置 → 上下文新增「请求与缓存」**
   - `request-stats.ts`：从 durable `pi.assistant` entry 的 usage 还原请求列表（最近 500 条、
     每页 100 条），命中率 = `cacheRead / (input + cacheRead + cacheWrite)`，汇总按 token 加权。
   - 点一行看当时上下文：`conversation.context({ at: entryId })` 重放固定前缀 + 已存档消息，
     并与上一条请求对比 system 段 / 工具面是否变化。
   - **骤降定位（本轮最重要）**：列表扫描时按 entry id 升序增量重放 `pi.system`，给每条请求算
     system / tools 指纹；`drop` = 命中率从 ≥50% 掉到 <20%，`flag` 区分
     `prefix_change_drop`（骤降 + system 前缀变了 → 红色报警）、`prefix_change`（前缀变了没骤降）、
     `tools_change` / `tools_change_drop`（工具面）、`drop_unchanged`（大概率缓存过期 / 上游）、
     `compacted`（压缩 / 重置）。页面顶部有红色横幅，行尾有 `!` / `↑` / `T` / `·` / `C` 标记。
   - 新端点：§2.2.11 `GET .../requests`、§2.2.12 `GET .../requests/:entryId/context`。
   - 开关 `CHAT_CACHE_STATS`（默认开，false → 两个端点 404、页面不画）。

4. **人设保存时说明一次缓存代价（2026-11-20 补）**
   - 总管人设（`persona`）与「关于我」（`user_profile`）在固定前缀里：保存成功后提示
     「本会话下次请求会重建一次，缓存掉一截属正常」。
   - 只在这两处提示：执事 SOUL / 契约 / 在办走每轮尾部消息注入，不改前缀；技能索引按会话冻结。
     到处提示是假警报，也会把真正的前缀变化淹掉。

**为什么**

实测总管会话 3112：69 次请求、总 prompt 2,064,728 token、命中 1,845,888（89.4%），
其中 6 次完全未命中（134,847 token）。两个可复现的坏点：

- 新一轮用户消息 → `memory_recall` 文本变化 → 作为 system 拼在最前面 → 整段前缀作废；
- 建课题 → durable 追加 `pi.system` 补丁（`sections.topics`）→ 下一请求前缀作废。

**验证**

- `pnpm typecheck` 干净。
- `tsx --test src/agent/injection.test.ts` 24/24；`src/context-inspect.test.ts`；
  `src/request-stats.test.ts` 4/4；`src/context-defaults.test.ts` 5/5；`src/flags.test.ts` 14/14；
  `src/web-imports.test.mjs` 1/1（合计 60/60）。

  - `/requests` 返回 2 条、带 prompt / 命中率与加权汇总；
  - 两条请求的 `system.hash` 相同（证明没有追加 `pi.system` 补丁）；
  - 详情对比 `systemChanged=false` / `toolsChanged=false`；非请求 entry → 404。
- 隔离实例 + 浏览器实测设置 → 上下文页：69 条真实请求、89% 命中率、6 次全未命中；
  点开 #62（建课题后那条）显示「system 变了 课题（判据）」；点开 #69（最后一条全未命中）
  显示「固定前缀与工具面都没变」——说明那一次是上游缓存不稳定，不是前缀被改。
- 未做：真模型连续两轮的 cacheRead 实测（需要重启服务后聊两轮；数据会出现在新页面里）。
  这是下一步验收，不是代码缺口。

**回滚**

- `CHAT_CACHE_STATS=false` → 两个端点 404、页面整块隐藏。
- `PROMPT_TAIL_INJECTION=false` → 动态注入回到旧形态（system 拼在请求最前面）。
  默认开；关掉会把缓存前缀问题带回来，只用于兼容性排查，不推荐。
