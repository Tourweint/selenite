# 2026-11-03 自绘标题栏与设置整页

## 改了什么

### 顶栏（全局唯一）

- 新增 40px 自绘标题栏，横贯侧栏与主区之上：左侧品牌「阿月」，接着是侧栏开关 +
  功能菜单（原 `.chrome`），右侧是设置齿轮、窗口三键。
- 原固定定位的 `.chrome` 取消，整体收进标题栏；主区 `.app` 下移
  `--titlebar-h`，侧栏顶部不再给固定按钮留 50px。
- 空白区 `-webkit-app-region: drag`，可双击最大化；按钮、菜单、设置、侧栏开关
  全部 `no-drag`，点击不会被拖拽区吞掉。
- 窗口三键（最小化 / 切换最大化-还原 / 关闭）接 `window.mygo.window`；
  只有 `window.isMyGo()` 为真且存在该 API 时才取消 `hidden`。普通浏览器不渲染，
  避免出现点了没反应的按钮。最大化图标与 `aria-label` 跟随 `IsMaximized()`
  和 `resize` 切换。
- 首页问候语按整窗高度算的 `22vh` 减去标题栏高度，位置不因顶栏下移而错位。

### 设置页

- 设置变成独立整页：`html[data-route="settings"] .sidebar` 不占位，
  `.main.settings` 去掉外边距、圆角、边框和投影，铺满标题栏以下区域。
- 设置分类栏由百分比定宽改为固定 220px（收起 60px），不再和内容区按比例分账。
- 侧栏开关只在聊天页显示：`applyRoute()` 同步 `document.documentElement.dataset.route`
  并切换 `#toggle-sidebar.hidden`。
- 设置入口从功能菜单移到标题栏右侧齿轮，菜单里只剩「新对话」。

### 主题控件

- 去掉「深色模式 + 跟随系统」两个开关，恢复为一条滑轨上的三段滑块：
  跟随系统 / 浅色 / 深色。
- 滑块尺寸与位置由 JS 按选中按钮的 `offsetWidth/offsetHeight/offsetTop` 量出，
  再用 `transform` 移动（同 cindy 的 plate 做法）。不用百分比切三段，因为
  「跟随系统」比「浅色 / 深色」宽，按百分比切会和文字错位。
- 窗口 resize 时重新量一次，避免三段宽度重排后滑块偏位。

## 为什么

用户要求窗口顶栏完全自绘（接受失去 Win11 贴靠布局），设置页独立成整页，
并明确要求主题是分段滑块而不是开关。三者共用同一套顶部骨架，一起收口。

本次覆盖《2026-11-03-首页顶栏与浮层》里「设置入口放在功能菜单」的决定。

## 补记：入口挪到侧栏底部、主区铺满

- 设置入口从标题栏齿轮挪到侧栏底部常驻区（`.side-foot` 内的 32px 胶囊行，
  hover/选中态与「新对话」等侧栏项一致）。设置页隐藏侧栏，顶栏左侧保留返回按钮。
- 主区不再做浮起卡片：去掉 8px 外边距、边框、28px 圆角与投影，改为
  `border-radius: 16px 0 0 0`，右、下两边贴住窗口。参考 deepseek-harness 的
  Windows 做法（centerCol `border-radius: 16px 0 0 0`），窗口圆角交给壳。
- 入场动画从位移改为透明度，避免铺满后滑动时短暂露出背景。
- 已知限制：侧栏收起或视口 ≤800px 时，侧栏底部的设置入口不可见/不可达。

## 补记：窗口 API 大小写

壳侧确认 MyGo 运行时暴露的方法是首字母小写
（`minimize / toggleMaximize / isMaximized / close`），且 `window.mygo.window`
是冻结对象、`window.mygo` 不可写，壳无法补首字母大写别名。页面里原先按
`Minimize / ToggleMaximize / IsMaximized / Close` 取值，可选链取不到后静默，
表现为按钮渲染了但点击无动作。

处置：`app.js` 的四处调用改为小写，并在 `shellWindow` 旁注明大小写原因。
普通浏览器行为不变（`isMyGo()` 不存在时三键仍不渲染）。

## 补记：40px 文档溢出（左上圆角消失 + 上下横条）

用户反馈「用一会儿主区 16px 圆角没了，顶部和底部各多出一条横条」。
排查结论（2026-11-03 实测确认，Chrome 1520×899 + 真实 MyGo 壳 `PrintWindow` 像素扫描）：

- 根因不是任何设置开关，而是 **margin collapsing**：`.app { margin-top: 40px;
  height: calc(100% - 40px) }` 的 margin 与 `body` 折叠，文档高度比视口多 40px
  （实测 `scrollHeight=939` vs `clientHeight=899`）。`body { overflow: hidden }`
  只禁用户滚动，不禁编程滚动——设置页左侧导航的
  `scrollIntoView({ block: "start" })` 会把根节点 `scrollTop` 变成 40，返回聊天后
  整页上移：左上圆角被 fixed 标题栏盖住（看起来变直角），底部露出 40px
  `--backdrop` 横条，顶部同样多一条。
- 没有代码给聊天 `.main` 写 `border-radius: 0`；也没有额外 fixed/sticky 条，
  `.main` 的 padding 未被改动。`.main.settings { border-radius: 0 }` 只作用于设置页。
- 修法：`body` 用 `padding-top: var(--titlebar-h)` 预留标题栏高度，`.app`
  去掉 `margin-top`、`height` 改 `100%`，从根上消除折叠。
- 验证：`scrollHeight = clientHeight = 899`；强制 `scrollTop=40` 被钳回 0；
  设置页点完 6 个分类后 `scrollTop=0`；返回聊天 `mainTop=40 / mainBottom=899`，
  右下角与底部均无背景横条。

## 补记：主题过渡覆盖底部控件

发送键、工具区（`.act-block`）、活动区（`details.acts` / `.attention`）、
权限区（`.segmented`）此前只换色不渐变，跟 body 的 `.18s ease` 不同步。
统一补上 `background-color / border-color / color .18s ease`（只过渡颜色类属性，
不新增 `box-shadow`、`filter` 之外的布局属性，避免多余重绘）。实测切换主题后
`.send` 背景在 0ms 不变、90ms 为中间值、260ms 到终值，确认是渐变而非硬切。

## 补记：底部输入区加宽

对话态 `.composer`：`min(700px, calc(100% - 40px))` → `min(920px, calc(100% - 32px))`。
首页态：`min(820px, calc(100% - 88px))` → `min(920px, calc(100% - 32px))`（与对话态同档，
只靠高度区分主次）。1520 宽窗口、侧栏 232 时主区宽 1288，输入框左右留白
294 → 184px（单侧）；最小窗口下两边总留白 40/88 → 32px。
