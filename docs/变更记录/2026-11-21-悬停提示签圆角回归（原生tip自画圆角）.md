# 2026-11-21 弹出层圆角回归 + 菜单双层卡根修（Shell.ShowMenu 的 ctx 契约）

## 改了什么

`desktop/popovers.go` 两类改动：

1. **圆角（tipView / menuView）**：Root 全透明（`ui.Color{}`），底色 + `Radius(12)`（= web 的 `--r-md`）画在填满窗口的 Column 上，四角经 flyout 的 DirectComposition alpha 透出去。menuView 另加 1px 描边（`popoverColors.border`，五主题对齐 CSS 的 `--composer-border`）。圆角第一帧就有，不等 DWM。
2. **根修双层卡：`ShowMenu` 签名改 `func (Shell) ShowMenu(ctx context.Context, req MenuRequest)`**——ctx 挪到第一位。这是本批真正的根因修复，见下。
3. **`ShowMenu` 里 Show 前 `CapturePage()` 预渲**：把真内容这一帧先渲进复用窗的表面（隐藏窗不画帧，fit_content.go 明说；`Invalidate` 只排程、不动表面），盖掉上一帧残像素。

## 根因（用户报「双层卡片、底下那张可点」，四路数据钉死）

**mygo 的绑定约定：`context.Context` 必须是方法的第一个参数**（`newMethod` 只认 `In(0)`）。批1 起签名写成 `(req MenuRequest, ctx context.Context)`——ctx 排第二 → 框架不注入 → 参数不足用 `reflect.Zero` 补位 → **ctx = 类型化 nil** → 菜单 Show 之后 select 里 `ctx.Done()` **当场 panic**。桥的 recover 把 panic 转成 reject 发回页面，于是：

- 页面 `markNativePopupsBroken()`（粘性关原生）+ `domFallback()` → **DOM 兜底菜单出现，而原生 flyout 还开着**（panic 杀死了阻塞的调用协程，没人收窗）→ 两层卡、底下那张（DOM）可点；
- 原生窗泄漏在屏幕上，帧停在最后一次渲染 → 用户早先报的「底下多了一圈」「过一会儿才正常」都是这个泄漏的旧帧；
- 粘性失效只在当次页面会话内，刷新后第一次点击又是原生 → 又泄漏 → 用户「刷新后直接点开就有」完全吻合；
- 批1 的「粘贴 e2e 闭环」实为 DOM 兜底跑通的，把此 bug 掩盖至今。

排查手段（可复用）：页面侧 `_debug-note` 上报 + 壳侧 `dbgLog` 打点对时间线，一次复现即锁定 `REJECT panic`；panic 栈直指 `popovers.go:377` 的 `ctx.Done()`。

## 为什么 CapturePage 还留着

ctx 修掉 panic 后，复用窗缩高时「改尺寸在画帧之前」的竞态仍在（D3D11 resize 后缓冲内容失效，首帧可能空/旧）。Show 前预渲真内容一帧是廉价且无害的兜底，实测空闲与繁忙均干净，保留。

## 验证

- `go vet` / `go test ./...` / `pnpm typecheck` 全绿；`node --check` 改动 JS 通过。
- 修后真机（用户亲手点，四路数据同验）：页面日志 4 次菜单全程 `resolve -1`、**零 REJECT / 零 panic / 零 DOM 兜底**；壳日志每次 `menu-in` 配 `menu-out picked=-1`；窗口枚举每次只有一个 flyout、开合干净无泄漏。
- 圆角/描边：批内先经 `ui.NewTester` 无窗口渲染目检（paper 主题描边连续、圆角完整），后经真机截图目检（12px 四角弧、发丝线）。
- 修复前的旧 exe 上复现过双卡 + 直角基线，对照成立。

## 没做 / 边界

- **投影未恢复（用户拍板先不动）**：需要 DWM 阴影（= 会复发 mygo v0.10.0「阴影辅助窗露内衬」怪癖）或自画软阴影；框架修了再开 `Shadow: true` 一并拿回 DWM 圆角+投影，届时自画圆角可退。
- **复现台留了**：`LIFEDIARY_DEBUG_FLYOUT=1` 走 `debug_flyout.go`（迷你父窗+真实 menuView 的 flyout，种子帧→缩高→Show 三阶段，stdout 打点），本次排查靠它绕开「真机盲点跨屏」；日常零影响。
- 描边画在卡片边缘，外半像素理论上可能被窗边裁掉一半；无窗口渲染目检是完整发丝线，真机嫌细再内缩。
- 浏览器（无壳）走 DOM 路线，从未受影响。

## 明确不做

- 不给 ShowTip/HideTip 补 ctx（它们没有 ctx 参数，无此坑）；其它桥方法逐一核对过，仅 ShowMenu 有 ctx。
