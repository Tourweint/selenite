# 2026-11-14 连接方式两分（本地连接 · 远程连接经中继）

> 落地记录：把连接页从「同一个 WiFi / 不在同一个 WiFi」改成「本地连接 / 远程连接（经过中继）」，
> 并让每台设备显示它是怎么连进来的、上一次走的是哪条路。

## 结论

- 分节改名：**本地连接**（同一 WiFi、数据线、USB 共享网络都算）/ **远程连接**（第一块就是「经过中继」）。
- 连接方式**由服务端按请求对端地址判定**，手机不上报、协议一个字没改：
  `usb`（回环 = 数据线 / `adb reverse`）、`local`（内网 = 同一 WiFi / USB 共享）、`direct`（公网直连）。
- 「已连接的设备」现在一份列表三份事实：本地配对名册、中继名册（一律标「远程连接（经中继）」）、
  **用主令牌直连但没配对的外部设备**（此前谁的名册都不进，所以"看不见"）。
- 撤销过的配对设备不再被藏掉：留一行标「已移除」，说明它的凭据已经 403、重扫一次码就能回来。

## 关于「平板看不到连接」

实机查到的现状是：本地配对名册里有一台 **`平板自检`（id <DEVICE_ID_C>，已撤销）**，还有一台 `vivo手机`（未撤销、离线）。
如果平板用的正是那枚**已撤销**的凭据，它的请求会被直接 `403`，而旧页面又把撤销设备整条过滤掉——表现就是"平板说连不上、电脑这边什么也看不到"。
本轮把撤销项留在列表里标「已移除」，并且新增"未配对设备"一行（用主令牌直连的情况也会现形）。

## 没做 / 没验证

1. **没有浏览器实机点验**（本机没开图形化点验授权）：DOM 渲染与 10 秒刷新的视觉效果只做了静态检查 + 接口级验证。
2. **没有跑真机平板**：本地配对设备的 `lastTransport` 只有单测覆盖，没在真手机上走一遍"数据线 / 同一 WiFi"两条路。
3. 手机端（`<lifediary 手机仓>`）文案未动，仍可能出现「点经中继添加设备」这类旧措辞。
4. 中继名册的"在线"是 `lastSeenAt` 语义，跨网络长时间挂着的手机如果 90s 内没有请求，会显示离线（按设计如此）。

## 回滚

- 只有前端文案与展示口径时：改回 `settings-router.js` 的两节标题即可，后端字段是纯增量，不读也不影响。
- 后端字段是**纯增量**（`lastTransport` 等仅新增，不参与鉴权判定），`getConnInfo` 取不到地址时按 `direct` 处理，不影响原有鉴权结论；不需要开关。
