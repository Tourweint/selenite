# 2026-11-06 侧栏项目面板总览化（去切换）

## 问题（用户原话口径）

「子项目识别到了，但是主项目好像没有识别到。展开那个项目的时候，应该都能够看见吧，后边标注着这个是主项目，底下那些是子项目。切换这个也不用切换吧，基本也没人说一定要在哪个工作区干活。」

侧栏项目 pill 此前是"当前项目切换器"：没切项目时显示「杂事 · 主工作区」，主项目（工作区根，如 `<主工作区>`）在界面任何地方都不出现——用户看到的正是"主项目没被识别"。

## 改动（纯前端：web/app.js + index.html + style.css，零契约变更）

- **pill = 主项目**：显示工作区根目录名（如 `Workspace`），hover 出「主项目：<主工作区> · N 个子项目」。
- **弹层 = 只读总览**：主项目行带「主项目」行尾标注；子项目列在下面，目录丢失标黄「目录不在了」、跑出工作区标灰「不在工作区」——不再隐藏异常项（总览就该都能看见）。没有子项目时给一句空态提示。
- **切换语义整体撤掉**：不再渲染「杂事 · 主工作区」单选项、✓、menuitemradio；删掉 `switchProject`（PUT 调用）、`PROJECT_SWITCH_ERROR`、首字徽标（轨道按钮恒显图标）。行不可点，管理动作仍在底部三入口（添加子项目 / 添加主项目 / 管理项目 → 设置）。
- 数据面顺带简化：只打 `GET /api/v1/projects`（本身就带 workspace），不再并发打 `/api/v1/workspaces`。
- E5 降级先例保留：接口读不到时 pill 变「项目不可用」，点一下重试，不藏入口。

## 后端刻意不动

- `PUT /api/v1/workspaces/current-project`、`currentProjectId`、`CURRENT_PROJECT=false` 回滚开关原样保留（http-probe §14/§15 照绿）——接口文档 §2.7 已注明"侧栏不再切换，端点保留作程序化入口与回滚面"。
- agent.ts 的 current_project 系统提示节与 cwd 逻辑不动：库里 current_project_id 为空时行为与原「杂事模式」完全一致。已知边角：若历史库里存过 current_project_id，界面不再显示/清除它（当前库为空，实际无影响）。

## 验证

- 起 server + 浏览器实测（见验收记录）：pill 显示 `Workspace`，弹层「Workspace [主项目] / tmp-ws-test」，行无 hover 反馈、底部三入口可点。
- `pnpm typecheck` 过（后端未动，跑一遍兜底）；http-probe 复跑确认契约面无回归。
