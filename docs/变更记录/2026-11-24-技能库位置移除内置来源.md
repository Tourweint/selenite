# 2026-11-24 技能库位置：内置来源可移除

## 用户口径

「技能库能够加载不同的目录，但这个目录没有办法删，应该做出一个删除按钮，就是不再从这个目录里读取了；
无论是添加一个还是删除一个，都得更新一下这个页面。」

口径确认（AskUserQuestion）：**主目录保留、其余可删**——主目录是新建技能的默认落点，
移除后会出现"写进去读不到"，所以不提供移除；`.agents/skills`、内置目录、自加位置都能删。

## 改了什么

### 服务端

| 文件 | 改动 |
|---|---|
| `src/skills-dirs.ts` | 登记表扩成 `{dirs:[...], excluded:[路径]}`（旧裸数组格式继续认）；新增 `readExcludedSkillDirs()` / `excludeSkillDir()`；`addCustomSkillDir()` 重新登记同一路径时顺手解排除 |
| `src/skills.ts` | `resolveSkillsDir()` 读排除名单并跳过对应来源（自加位置 / `.agents` / 内置目录）；**主目录先入链、不受名单影响**；`agents` / `app` 来源标 `removable: true`（兜底主位仍不可移除） |
| `src/skills-api.ts` | `DELETE /agent/skill-dirs?path=` 扩成"移除位置"：自加位置删登记，`.agents` / 内置目录记排除名单；主目录 → 400；响应加 `removed: "unregistered" \| "excluded"`；两类都 `notifyChange()`（运行中技能库就地重扫） |

## 为什么这么定

- **用排除名单，不往 `dirs` 里塞负登记**：`.agents` / 内置目录不是用户登记进来的，删 `dirs` 行对它们无意义；
  单开 `excluded` 还保持 `dirs` 的"登记顺序 = 优先级"语义不变。
- **主目录不可删**：它是 `PUT /skills/:name` 不带 `dir` 时的写目标；可删就会变成"写进去却读不到"。
- **移除只改读取清单**：与 11-23「移除登记不删磁盘文件」同一条纪律，误点不会丢文件。
- **恢复复用「添加位置」**：同一路径重新登记即解排除，不额外做一颗「恢复」按钮；代价是恢复后来源变成自加位置（可写）。

## 验证

- `tsx --test src/skills.test.ts`：29/29 通过。
- 全量 server 单测：**1507/1507 通过，fail 0**；`tsc --noEmit` 绿。
- 技能管理探针全绿（G2 段真 HTTP：移除 `.agents` → 200 `excluded`，行与技能同时消失、文件仍在；重新添加 → 以 `custom` 身份回来）。
- 隔离实例（独立端口 8124 + 临时 `USERPROFILE`，不碰真实数据）+ headless Chrome 真页面走完：
  - 初始位置卡：主目录（无移除）/ `.agents`（移除）/ 内置（移除）；
  - 点 `.agents`「移除」→ 确认弹窗 → 行消失、toast「已不再读取这个目录（文件没动）」；
  - 再点「添加位置」加一个临时目录 → 新行出现（页面自动刷新）。
- 真实 39847 服务的页面未重启验证；服务端改动要重启才生效。

## 没做 / 边界

- 不提供"恢复已排除来源"的独立入口（用「添加位置」填同一路径）。
- 排除名单不跨 `SKILLS_EXTRA_DIRS=false` 生效：开关关 = 整层回到旧读取链（排除名单与自加位置一起忽略）。
- 不改执事私有技能目录 / 总管私技能目录的链（仍不在本页管理）。
