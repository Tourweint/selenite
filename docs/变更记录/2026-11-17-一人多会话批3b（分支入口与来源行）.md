## 改了什么

- **`GET /agent/chat/:id/messages` 补 `origin?`（只增不改）**：`index.ts` 读一次
  `ChatOrigins` 快照，有值才带 `{source, sourceTitle?, at}`；分页 / 全量与补帧（`sinceSeq`）
  两条响应都带。老客户端忽略未知字段即可。
- **`POST /agent/chat/:id/branches` 拒绝群/例行/课题专线**：`link` 存在且 role 不是
  `canonical` / `side` → `400 branch_not_supported`；否则会落到 worker/chief 分支，把群成员
  会话复制成一条总管会话、身份丢失。canonical/side 的 `side_sessions_disabled` 400 保持现状。
- **`web/branch.js`（新，纯函数）**：`formatBranchOrigin()` 产出 `{text, source}`
  （`副本 · 来自 <标题|一条会话> · <时间>`，时间取 `msg-clock` 的 `formatMessageClock`，无效 `at` 省略）；
  `branchErrorText()` 把错误码翻成一句人话（未知码给通用句）。
- **`web/chat-thread.js`**：回答脚注在复制按钮之后、时钟之前加「从这里分支」（Lucide git-branch，
  同一套 `footSvg`）；只在有正文的回答、且这一屏支持分支时挂（worker/chief 显示，
  执事 canonical/side 仅 `sideSessionsEnabled` 时显示，group / `task-` 不显示）。
  点击时用 `dataset.messageId` 或 `resolveMessageId` 拿 assistant id → `POST /branches`，
  成功 toast + `openChat(新 id)`，失败 toast 对应文案，期间按钮禁用。
  `resolveMessageId` 从"只回填 user"扩成按角色（user / assistant）从末尾对齐回填。
- **`web/chat-open.js`**：模块初始化时创建 `#branch-origin` 并插在 `el.thread` 之前（不改
  index.html）；`renderBranchOrigin` 按 `formatBranchOrigin` 写入 `textContent`、点击回原会话；
  `openChat` 每次切会话先收起、拿到响应后按 `data.origin` 再摆；`startNewChat` / 404 重开收起。
- **`web/style-04-chat-base.css`**：`#branch-origin` 一行小字（muted、hover 变 `--text`、可点）；
  `.branch-btn` 复用复制按钮的 hover 淡入与图标尺寸。
- **单测** `src/web-branch.test.mjs`（已加入 test 清单）。

## 为什么

来源行是"我在看副本、能回去"的唯一线索；只有副本才有，所以由 `/messages` 的 `origin` 驱动，
前端不额外查 `ChatOrigins`（避免多一次请求与契约分叉）。入口放在回答脚注而不是会话列表：
分叉点是"某条回答"，放在回答旁边才指得清。群/例行会话没有"同一人设的 side"语义，
落到 worker/chief 会把身份复制丢，所以服务端显式拒绝，而不是让前端猜。
