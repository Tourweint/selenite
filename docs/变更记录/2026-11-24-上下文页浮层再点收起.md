# 2026-11-24 上下文页浮层：再点同一主题就收起

## 用户口径

设置 → 注入 → 上下文：点「全部」「记忆」「技能」「工具定义」或棋盘格子会浮起一张详情卡。
以前点完标签后再点同一个标签，只会把卡片原样重开一次；用户要求「再点这个部分的主题，
小方块就自动消失，和点其他地方一样」。当前会话与默认开销两个模式都要。

## 改了什么

| 文件 | 改动 |
|---|---|
| `web/settings-context.js` | `openPopover()` 多收一个 `key`，记在浮层 DOM 的 `data-pop-key` 上；新增 `popoverShowing(key)`（开着且主题相同才算）。`openGroup()` 与 `openRequestDetail()` 进门先判同主题 → `closePopover()` 并返回，否则照旧打开/替换。点同组的另一格、同一条请求行，与点标签同效 |
| 同上 | 请求详情是异步的，补一道「迟到响应不重开」：响应/失败回来时若浮层已不是这个主题（用户已收起、点了别的行、切了会话），直接丢弃，不再 `openPopover` |
| 同上 | 全局 `pointerdown` 的「点外面收起」排除名单加上 `[data-ctx-req]`，否则请求行会在 `pointerdown` 先被关掉、`click` 又当成新点击重开 |

## 为什么

- 触发元素本身就是最好的收起开关：浮层离得不远，用户不想每次去点空白处。
- 请求行的异步重开是 toggle 带来的新风险：点开→立刻再点收起→详情回来又把卡片弹出来。
  顺手同时修掉「点了 A 行、A 的响应回来覆盖 B 行」这个既有竞态。

## 没做 / 边界

- 浮层盖住触发标签时（如「工具定义」贴着浮层上沿）仍然点不到标签，靠点外面或 Esc 收起；
  不为此改浮层定位。
- 不改浮层的打开动画与定位规则。

## 验证

- `node --check apps/server/web/settings-context.js` 通过。
- 真页面验收（39847，无头 Chrome + CDP，脚本在仓库外）：当前会话模式点 `system` 标签打开 →
  再点收起 → 再点能重开；点 `system` 后改点 `tools` 直接换主题且保持打开；「全部」打开/再点收起；
  默认开销模式同样 12/12 全过。
- 请求行的收起路径没在真页面点到：本机只有一个可选会话、没有任何模型请求记录（`[data-ctx-req]` 为 0），
  该段只做了语法与代码审查，未跑交互。
