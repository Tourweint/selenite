# 2026-11-23 任务中心幽灵单与「等你回话」卡片收口

**改了什么**

1. **索引里的幽灵单不再出现在任务列表**（`packages/chancellor/src/store.ts`）。
   `listTickets()` 现在只返回 `runs/<id>/ticket.json` 还在的行，并多取一段窗口（`max(limit*2, limit+50)`）
   再按文件过滤，避免幽灵行把 `limit` 名额吃光。
2. **「在跑」计数只数真正在跑的单**（`web/tasks-redesign.js`）。
   原来的 `aliveTicketCount()` 把 `needs_you` 也算进「N 件事在跑」，于是页头写着
   「1 件事在跑」、下面的「在跑」区却写着「现在没有在跑的事」。改为按聚合灯
   `ticketLamp(ticket) === "run"` 计数，函数改名 `runningTicketCount()`。
3. **「等你回话」卡片压扁**（`web/tasks-redesign.js` + `web/style-20-tasks-redesign.css`）。
   - 只有一条留言的组不再「组头 + 留言气泡」套两层：派活人、等待时长、引文收进组头；
     直派单的标题本身就是 prompt 摘要时不再重复一遍引文。
   - 只有一个人（总管 / 某位执事）时不再显示「总管 1」小节头（页头计数已经说了）。
   - 大区、组卡、气泡的纵向 padding / 行高小幅收紧。
   单条场景实测高度 255.6px → 116px（1280×720 视口）。
4. **刷新后不再空等一轮轮询**（`web/tasks-kanban.js`）。
   首屏徽标预拉是 `render:false`，路由 `openTasks` 的 `loadTickets()` 因 `ticketsLoading`
   提前返回，页面直接落在任务中心时要空到下一拍（最长 20s）。现在后到的渲染请求记为
   `renderPending`，这批数据回来补画一次。

**为什么**

- 11-22 的池 e2e 测试在 `ts/apps/server/runs/` 下留了 11 张单；22:51 明文目录被整体清掉，
  但 `data/chancellor.db` 的索引行还在。列表只信索引，于是任务中心挂出一张
  `needs_you`（错误为「分管宰相结论：blocked」）的幽灵单：点「看这张单」必然 404，
  侧栏徽标也一直显示 1 单。
- 那张单的 blocked 结论来自 13:49 的 e2e 现场（它创建前 0.1 秒刚有一张池单被停止）；
  `ticket.json` / `plan.json` 已被清掉，原始收尾句无法恢复。当前列表里没有任何
  `received/planning/dispatching` 的单，进程也是 22:51 新起的，没有还在排队的活。
- `Store` 的既定口径是「sqlite 只是索引，runs/ 明文才是事实源」，列表读索引却不校验
  明文，属于实现与口径不一致；这次把校验补在 `listTickets()`，列表 / CLI status /
  领域计数 / 执事状态段共用同一份事实。
- 卡片：一张单套两层卡（组头 + 气泡）在单条场景多出 100 多像素，标题与引文又常常
  是同一句派活说明，信息密度不划算。

**验证**

- `pnpm typecheck` 通过。
- `pnpm --filter @lifediary/server test`：1410/1410 通过（含新增用例）。
- `npx tsx --test src/delegation-api.test.ts`：12/12，新增「明文已清理的索引行不再冒充任务」。
- 浏览器实页：重启服务后列表 0 条、侧栏徽标 0、任务中心显示「都回完了，都在歇着」；
  刷新后 4s 内自动渲染（此前要等轮询）；卡片 255.6px → 116px，页头由
  「1 条等你回话 · 1 件事在跑」变为「0 条等你回话 · 0 件事在跑」。

**没做 / 边界**

- 不删 sqlite 里的旧索引行（只读过滤；索引行留着不影响事实源，删行属于破坏性操作）。
- 不动「打手」区的「在跑 N」口径（它数的是「手上有多少还没终结的单」，含等你回话的单，
  语义与任务中心页头的「在跑」不同）；要统一另立项。
- 不调查那批 e2e 数据是谁清理的（只确认 22:51 目录为空、索引尚在）。
