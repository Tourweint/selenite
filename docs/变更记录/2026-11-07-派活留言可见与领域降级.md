# 派活留言可见 + 领域降级为标签（落地）

- 日期：2026-11-07
- 方案：`docs/设计方案/2026-11-07-派活留言可见.md`
- 前置：`docs/变更记录/2026-11-07-消息即引导与执事直派.md`

## 背景：用户指出的两个真问题

1. **「你在任务里应该能看到总管或者其他执事发给任务的那条消息，对吧？」**
   —— 看不到。当时派活走 `spawn --requirement=<原文>`，需求只是 `ticket.json.prompt`
   里一段裸文本：没有发送者、没有时间、没有"这是一条对我说的话"的位置。
   实测确认：`GET /api/v1/tickets/:id` 只返回 `prompt` 与 `chiefName`（后者还是按 domain 反查的）。

2. **「我不太懂这个领域是干什么的，他们也设置不了这个领域」**
   —— 准确。`domain` 当时是建执事必填、建后不可改、界面上没有编辑入口、
   对用户没有任何可见作用；它只是宿主内部的路由键，却被摆成了用户必须回答的问题。

## 改了什么

### 一、派活留言（新）

| 文件 | 改动 |
|---|---|
| `ts/apps/server/src/delegation-messages.ts` | 新增：`delegation_messages` 表（与回执同库），`append` / `list` |
| `ts/apps/server/src/delegation.ts` | `DelegationKickoff.sender`；受理落一条 `out`，终态落一条 `in`；续跑标注"（回答上一轮的提问）" |
| `ts/apps/server/src/tools.ts` | `senderOf(conversationId)`：执事会话 → 执事名，主人/总管 → 总管 |
| `ts/apps/server/src/delegation-api.ts` | 详情返回 `messages`（老单空数组，不报错） |
| `ts/apps/server/web/app.js` | 详情页「派活往来」区块：`来自 X` / `回到 X` + 时间 + 正文 |
| `ts/apps/server/web/style.css` | `.td-msg`：出方向强调色竖线，回方向绿色，system 虚线 |

写失败**不挡派单**：留言是簿记，派单是主链路；丢一段来历 < 丢一张单。

### 二、domain 降级为可选标签

| 位置 | 改动 |
|---|---|
| `POST /api/v1/partners` | `domain` 可不传；不传也建成可派活的执事（不建 `managers/<domain>/`） |
| `PATCH /api/v1/partners/:id` | `domain` 可改（原「建后固定」400 取消）；空串 = 清标签 |
| `partners.ts` | 新增 `setDomain`；`delegationSoulSeed` 支持无领域（不再硬编领域名） |
| `partner-manage.ts` | `CreateMinisterInput.domain` 变可选；空则跳过 `ensureManager` |
| `tools.ts` | `partner_manage.create` 不再要求 domain；文案改成"（领域标签：x）" |
| `web/app.js` | 新建弹窗与执事设置都写「领域标签（可选）」+ 说明；设置页可保存；详情顶部不再显示「总管（未分配）」 |

**语义**：domain 不再是派活路由键（路由按执事 id / 会话链接）。改标签不会让历史单找不到负责人。

## 没能验到的（如实标注）

1. **真实派单产生的留言没跑通端到端**：`LLM_FAUX_TOOL=delegate` 会让 faux 无限调同一个工具，
   被防打转硬停（日志里 `铁证中断 pattern=repeat count=30`），走不到"派单成功"。
   所以留言链路改用 `startDelegation` 直接驱动（真实代码路径，非 mock），加上存储单测覆盖。
2. **详情页的「任务 0/0」是探针夹具问题**：我手写的 `plan.json` 不会被 `tasksOf` 读到
   （它读 sqlite 的 `tasks` 表），真实派单会正常填充。不是产品缺陷。
3. 截图里两个执事名显示乱码，是 Windows 终端 curl 传 UTF-8 的编码问题，不是产品缺陷。

## 已知边界

- 留言是**只读旁路记录**，不是"任务即对话"：任务里回话仍走 `resume`。
- 不伪造 `pi.user` 进任务会话（任务不是会话，结构性改造另立项）。
- 老的 `managers/<domain>/` 目录结构保留，未迁移；已有 domain 的老执事继续能按领域派单。
