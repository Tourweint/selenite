## 逐条根因（可复核）

### arch-guard #1：名单滞后

测试自己的恒等式是「注册全集 ⊆ `WRITE_TOOLS ∪ READ_TOOLS`」。两个工具都是默认在架的非写工具：

- `respond_escalation`：`escalation.ts` 注释写明"不写盘、不起进程、不派活——只经批1 steer
  通道投一条答复 / 把问题转挂 `ask_user` 卡，不进 `WRITE_TOOLS` / 高危清单"。
- `tool_search`：只查本地工具索引（`tools.ts` 末段），不产生副作用。

它们不在 `WRITE_TOOLS` 是刻意的，正确落点是 `READ_TOOLS`。

### arch-guard #2/#3：测试隔离（关键）

`arch-guard.test.ts` 原先在文件顶部静态 `import { createTools } from "./tools.ts"`，
而 `tools.ts` 的静态图当前可达 `agent/policy.ts`：

```text
tools.ts → partner-manage.ts → delegation.ts → delegation-delegation-kickoff.ts
→ task-conversation.ts → agent/shared.ts → projects.ts → project-api.ts
→ agent/session.ts → agent/session-open.ts → agent/lifecycle.ts
→ agent/lifecycle-harness.ts → delegation-wake.ts → partner-runtime.ts
→ partner-runtime-run-partner-turn.ts → agent.ts → agent/policy.ts
```

`agent/policy.ts` 在模块顶层就算出 `POLICY_PATH` 并执行 `loadPolicy()`。于是测试后面再设
`AGENT_TOOL_POLICY=read-only` / `AGENT_BLOCKED_TOOLS=ghost_blocked` 已经晚了：实际读到的是
仓库本机的 `.data/policy.json`（实测 `{"access":"full","blocked":[]}`），
`write` 不拦、`ghost_blocked` 也不禁。

这正是 `delegation-authority.ts` 注释里警告过的坑（"`tools.ts` 的模块图若静态可达
`agent/policy.ts`，policy 会在测试设 env 之前就加载好初值"）。本次只在测试侧规避：
`ToolDeps` 用 `import type`（编译期擦除，不触发加载），`createTools` 改成设完 env 后
`await import("./tools.ts")`。

**未处置的债**：生产链上 `tools.ts` 静态可达 `policy.ts`，与该注释的约束相反。
破链是生产重构，影响面大，按 AGENTS.md"不做与本需求无关的重构"单独立项，不混进本次修测试。

## 以后怎么快速判断新失败是不是自己弄的

1. **先看自己的改动集**：`git status --porcelain` / `git diff --name-only`。
2. **跑基线哨兵**（三条与业务无关、必须常绿）：

   ```bash
   node ts/apps/server/scripts/test-baseline.mjs
   ```

   - 绿：已知噪音不在，继续第 3 步。
   - 红：先对照本文件，别先改业务代码。
3. **跑全量并留日志**：

   ```bash
   cd ts
   pnpm --filter @lifediary/server test 2>&1 | tee /tmp/server-test.log
   ```

4. **抽出失败文件**：

   ```bash
   grep -oE '^test at [^:]+' /tmp/server-test.log | sed 's/^test at //' | sort -u
   ```

5. **判定**：
   - 失败文件在**你的改动集**里 → 基本就是你弄的，先查自己的 diff。
   - 不在你的改动集 → 单跑该文件排除串扰：
     `cd ts/apps/server && ../../node_modules/.bin/tsx --test src/xxx.test.ts`
     - 单跑绿、全量红 → 串扰/环境（端口、临时目录、共享 `.data/`、Windows 句柄）。
     - 单跑也红且不在你的改动集 → 主干问题，按本文件格式登记归属，别顺手改业务。
6. **常见环境噪音**：Windows 临时目录 EPERM；多个测试文件共用 `.data/` 或固定端口；
   兄弟进程未退出。先单跑，再谈代码。
