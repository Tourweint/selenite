## 改了什么

### 1. 整理记忆：从"一次性请求"改成有状态的后台任务

旧行为：点「整理记忆」= 一个最长 30s 的同步请求；按钮只在当前 DOM 变「整理中…」。
切页回来页面重渲染，在飞请求的结果写进已脱离文档的卡片；再点一次就是第二发模型调用。
待决建议虽然落在 `.data/memory-proposals.json`，但只有写、没有读口；「忽略」也只删客户端卡片。

现在：

- `POST /api/v1/agent/memory/consolidate/review?background=1` 立即 **202**
  `{running, startedAt}`；接口层按 scope 单飞（同一 scope 在跑时返回 `alreadyRunning:true`，
  不重复调模型）。不带 `background` 保持旧同步响应（旧页/旧探针兼容）。
- 新增 `GET /api/v1/agent/memory/consolidate/state?scope=`：
  `{running, startedAt, generatedAt, proposals, source, error, audit}`。
  `source=live` 是本次进程结果（含 evidence 引文）；进程重启后 `source=pending`
  从待决文件读回（无引文，卡片注明「存档建议」）。
- 新增 `POST /api/v1/agent/memory/consolidate/dismiss`：忽略会从待决文件与内存结果一起摘掉，
  刷新不再回来（不写库、不删记忆）。
- 失败不再只靠一次 HTTP 5xx：后台失败落 `state.error`，页面显示「上次整理失败：…」并可重试。
- `MEMORY_CONSOLIDATE_JOB=false` 一行回同步等待。

### 2. 记忆页 A 版（设置 → 记忆）

- 大字概览：真实总条数 + 分类计数片（唯一筛选，点一下只看该类）+ 右侧上次整理/审计状态。
- 搜索：正文精确子串（`q`），250ms 防抖；搜索时匹配分组自动展开。
- 分组折叠：偏好/打算默认展开；事实/经验/人事物/**经历默认收起**；每组 20 条一页加载。
- 行：正文 + Why/How + 日期/来源/被想起次数；「标过时 / 删除」收成悬停图标钮。
- 补上 `experience` / `work` 中文标签（旧实现把认不出的 kind 一律归成「事实」）。
- 「整理记忆」悬停说明（含 `?`）：整理是回看记忆和原始对话找重复/过时，只给建议、逐条应用才改、
  不会自动删。`hover-tip` 增加 `white-space: pre-line`，支持多行说明。
- 导入按钮保留但**先占位**：点了说明"现在没有统一记忆格式，等格式定了再做"；
  端点与旧页的文件导入逻辑保留。
- 页脚「一生记忆库」：无绿点、一行库边界；未配置显示"在 .env 配 PERSONA_MEMORY_ASK 后重启"；
  「查看」弹层显示 `ask.py --catalog-only` 的全部边界行。不做查询页（后续独立）。
- `MEMORY_PAGE_A=false` 回到旧页（旧 DOM / 旧逻辑整套保留）。

### 3. 列表读数：真实计数 / 搜索 / 分页

`GET /api/v1/agent/memory` 新增 `q` / `kind` / `excludeKinds` / `offset`（`limit=0` 只回计数）；
`total` / `byKind` 从"当前返回窗口的计数"改为**真实计数**；新增 `counts`
`{all, byKind, superseded}` 与 `items.lastRecalledAt / usageCount / expiresAt`。
`memoryEngine.browse()` / `counts()` 与 store 的 `countMatching()` / `countByKind()` 是同一套 where 条件，
搜索/计数/分页不会各算一套。

### 4. 规则抽取噪声过滤（`MEMORY_EXTRACT_NOISE` 默认开）

`HeuristicExtractor` 增加质量闸（默认关闭 = 旧行为；server 装配层显式打开）：

- 跳过已知合成前缀（`用户已批准` / `用户拒绝` / `主人回答了你刚才的问题` / 撞上限与防打转话术等）；
- 跳过命令句（`请/帮我/不要/直接/用/把/写/改/查/...` 开头）与问句；
- 每轮最多 5 条，同轮同文去重。

`MEMORY_EXTRACT=rule` 仍走旧引擎（逐字节回滚口径不变）。审批续跑那两条
「用户已批准 `write`…」「不要换成别的工具…」不再写成经历。

### 5. 外接记忆库最小只读状态

新增 `GET /api/v1/agent/memory/external`：`ask.py --catalog-only`（15s 超时、成功缓存 10 分钟），
未配置不 spawn；返回 `configured/ready/provider/catalog.lines/reason`。
`MEMORY_EXTERNAL=false` → 404 且设置页不显示页脚。不碰 persona.db、不调模型；
日志只记行数/耗时/ok。通用 provider 注册表与查询页**不做**（后续独立立项）。

## 已知边界 / 刻意不做

- 后台任务状态在内存里；服务进程重启会丢"在跑"，待决文件仍在（`source=pending`）。
- 引文不落盘（沿用 2026-11-10 口径）：重启后读回的建议没有 evidence，卡片明确标注。
- 导入只占位，没有统一格式；不对旧 JSON 文件做界面引导。
- 外接库页脚不是查询页：只显示边界；`persona_recall` 工具仍按 `PERSONA_MEMORY_ASK` 双闸。
- 不做编辑、向量检索、自动整理 cron、自动应用、全部应用/全部忽略、跨设备同步、移动端记忆页。
