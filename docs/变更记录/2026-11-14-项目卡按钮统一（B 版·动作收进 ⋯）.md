# 项目卡按钮统一（B 版：动作收进 ⋯）

用户看完落地的项目容器界面后连说两句："这个前端风格不够统一，你这乱七八糟的按钮长得都不一样""主次也不分明"。要求先出几版 HTML 看，选定后再改代码。给了三版（16a 一档尺寸 / 16b 动作收进 ⋯ / 16c 分级底色），**用户选 B 版**。

## 改了什么、为什么

### 1. 尺寸收敛成两档

问题不是"按钮不好看"，是**没有一个统一的尺寸表**：改之前同时存在 26（`.ghost.is-mini`）/ 28（`.ghost`）/ 30（`.btn-primary`、`.proj-path-input`）/ 34（`.set-path-row` 强制）四档，字号 11.5 / 12.5 两档，圆角 `--r-sm` 8 与 `--r-md` 12 混用。眼睛看到的"按钮各不相同"其实是这四档高度在打架。

现在：**28 = 卡内 / 行内 / 图标按钮；34 = 与输入框同一行的表单**（输入框 34 时按钮必须 34，否则同排一高一矮）；
圆角一律 `--r-md`；`.ghost.is-mini` 26→28；`.btn-primary` 30→28；`.proj-path-input` 30→34。

### 2. 主次靠"层次 + 密度"表达，不靠堆按钮

| 层 | 长相 | 用在哪 |
|---|---|---|
| 一级 | 深靛实底 + 白字（`.btn-primary`） | 页面主操作：「添加项目」、「保存」根目录 |
| 二级 | 淡靛底 + 靛字（`.btn-primary.is-quiet`，走 `--accent-container`） | 卡内主操作：「＋ 添加文件夹」、编辑态「保存」 |
| 三级 | 描边 + 灰字（`.ghost`） | 其余明确动作（恢复、编辑态「取消」、查看归档） |
| 图标 | 28×28 无边框 ⋯ | 行尾 / 卡头：把 2–3 个同级动作收进去 |

密度反过来：一行里最多只留**一个**可见控件（⋯），主文件夹靠"左侧 3px 靛蓝竖条 + 「主」徽标 + 名字加粗"认，不靠再加小圆点和一排按钮。

### 3. 交互：动作收进菜单

- 文件夹行：⋯ → `改路径 ⏎ / 设为主文件夹 / ─── / 从项目移除`
  - 主行只有「改路径」（主文件夹不可能"设为主"）；
  - 只剩一个文件夹时**不给移除**（移完这个项目就没有主文件夹了，服务端也不允许）；
  - 「移除」用 `separator` 跟上面一组隔开，平时灰字，只有 hover 才变 `--c-error`。
- 项目卡头：`＋ 添加文件夹`（二级按钮，常驻，高频）+ ⋯（`重命名项目 / ─── / 归档项目`）。
- 改路径的代价从"点一下"变成"点两下"——所以它在菜单第一项，并标 `⏎`。

### 4. 菜单挂 body + fixed

卡片容器（设置卡 / `set-scroll`）带 overflow，挂在行内的绝对定位菜单会被整块裁掉（侧栏浮卡 2026-11-13 已经踩过一次同样的坑）。所以菜单 `document.body.append` + `position:fixed`，坐标按入口按钮实测：右对齐到按钮右缘、放不下就翻到上方、左右各留 8px 边距；点外面 / Esc / 滚动 / 改尺寸都关，同一时刻只开一张。

Esc 用 **window 捕获**监听并 `stopPropagation`：设置页自己也吃 Esc（返回上一级），不用捕获的话"菜单开着按 Esc"会连页面一起退出（实测复现过）。

## 顺手修的

- 工作区根目录那行输入框 30 + 「保存」28 → 现在是 34/34，同排不再一高一矮。
- `.proj-card-line > .btn-primary / > .ghost` 抬到 34 的规则只作用于**直接子元素**，卡头的「＋ 添加文件夹」（在 `.proj-card-actions` 里）仍是 28，不会跟着变形。
- 文件夹区第一行原来没有上边线（`:first-child { border-top: 0 }`），标题行和第一行粘在一起；现在每行都有边线，标题与文件夹之间有分隔。

- 临时实例（PORT 39899 + `$TEMP\lifediary-ui-check` 独立库）上真点：
  - 行尾 ⋯ 打开菜单；主行 1 项、附加行 3 项（含分隔线与移除）；
  - 菜单里「设为主文件夹」→ 服务端生效、列表重排（备份行升到第一并带「主」）；
  - 「改路径」→ 路径变输入框、⋯ 变「保存 / 取消」、点「取消」回列表；
  - 项目级 ⋯ → 「重命名项目 / 归档项目」；
  - Esc 只关菜单不退出设置页（window 捕获后复验通过）。

## 刻意不做

- 侧栏项目行不动：它已经是"行 + 图标按钮（▾ / ＋）"，密度本来就低；这次只统一设置页。要不要把 ▾ 也换成 ⋯ 菜单，等用户看到实际效果再说。
- 不引入第二套按钮组件（没有新建 `.btn` 基类）：`.btn-primary` / `.ghost` 就是基类，只改尺寸与用法，避免全站重构。
- 归档页的 `恢复` 仍是 `.ghost` 一档，不改成菜单——它只有一个动作。

## 这条会怎么错

- **34 档只给表单行**：若以后有人在卡头塞输入框，同排按钮会 34/28 打架，需要按 `proj-card-line > *` 重新对齐。
- **菜单被理解为"藏功能"**：改路径是高频动作，多一次点击是有代价的；用户若嫌烦，正解是把「改路径」单独拎回行内常驻，其余收进菜单（16a 与 16b 的混合），而不是退回四个并排按钮。
- **⋯ 的可发现性**：图标按钮没有文字，新用户可能不知道能点。现在给了 `aria-label` / `title`（"文件夹动作"）和 hover 浅底，但这是弱提示；若实际使用中没人点，需要退回 A 版。
