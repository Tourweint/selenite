# 记忆注入预算开关（默认 8→16 条 / 1200→2000 字）· 2026-11-15

**承接**：`2026-11-15-项目记忆多挂载（执事跨项目）.md`。多挂载落地后立刻暴露的一个老数，单独立一小批。

## 为什么改

多挂载让"每轮注入"里多了项目记忆这一路，于是有人问"1200 字是不是太短"。核实后真问题不在字数：

1. **两个闸取更严**：每轮注入 = `limit`（条数）与 `maxChars`（字数）双约束，任一先到就停；
2. **条数先到**：旧值 `limit = 8` 硬编码在 `@lifediary/memory` 的 `buildContext` 默认值里，而**偏好记忆永不删除且优先成段**——偏好攒到 8 条后，`【打算】`/`【其它】`/项目记忆一条都进不来，1200 字预算根本用不满；
3. **没有任何开关能调**（grep 确认：`maxChars` 只有 engine 默认值、生产调用方不传，也没有 `MEMORY_INJECT_*` 之类的 env）。

## 改了什么

- 新增 `apps/server/src/memory-inject.ts`（纯函数收 env，同 `memory-proactive.ts` 惯例）：
  `MEMORY_INJECT_LIMIT`（默认 **16**，clamp `1..40`）、`MEMORY_INJECT_MAX_CHARS`（默认 **2000**，clamp `200..8000`）。
- `assist.ts` 的 `recallContext` 显式传 `limit` 与 `maxChars`；`@lifediary/memory` 包**未改**（默认值仍 8/1200，作为库的保守默认）。
- 非法值 / 越界一律 clamp 或回落默认，**不关能力**（关记忆是 `MEMORY_ENABLED=false`）。
- 只管自动注入；`recall` 工具的 limit 仍由模型按需决定。

## 回滚

`MEMORY_INJECT_LIMIT=8` + `MEMORY_INJECT_MAX_CHARS=1200` = 逐字节回到旧形态，一行环境变量，不改代码。

## 已知边界

- 项目记忆与个人 / 执事记忆**仍共用同一份预算**（不是各自一份）。这次只放宽了总额；要"分开额度"需要改注入分组逻辑，另立项。
- 条数放宽后，每轮进提示词的旧信息变多——理论上会略微稀释注意力。真觉得吵就调回 `MEMORY_INJECT_LIMIT=10` 之类，不必改代码。
