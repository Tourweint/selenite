# 2026-11-21 工作 N 步折叠条收口为唯一开合开关

**改了什么**

对话流里工具灰块的开合交互收成一处（`web/tool-chips.js` + `web/style-06-tool-blocks.css`，纯前端）：

1. **折叠条挪到行首、位置永不移动。** 原来「工作 N 步」是收尾后行尾的折叠条，点开后整条消失、
   行尾另出一枚「收起」按钮——要把摊开的步骤合上，鼠标得挪到最末尾。现在折叠条是这一组
   **唯一的开合开关**：钉在行首，收起时它是正文里唯一的东西，展开时它留在原地当标题
   （箭头转 90° 指下），再点一下就收回去。
2. **跑动中就常驻报数。** 原来「跑的过程中不出现，进度靠灰块本身」；现在只要一组里有两枚块，
   行首就出现「工作 N 步」随每步递增（每次思考过程都看得到干到第几步）。一块仍不配计数条
   （它本身就一行，报数是多余一层）。
3. **「收起」按钮与「+N」退役。** 计数条本身报总数，装不下被收住的块点条就能全看，
   不再要第二个开关；`more` 按钮与其点击逻辑、`.tchips-more` 样式整块删除。
   展开态不裁剪的口径不变（用户点名要看全部，多行正是他要的）。
4. **用户手动摊开的组，收尾时不强行收。** `finish()` 原来无条件 `expanded=false` 折回折叠条；
   现在只折「没动过的」——正看着的过程保持原样，想合上自己再点一下。
5. **箭头接进 11-21 统一批**：折叠条 SVG 换 `icons.js` 的 `chevSvg("chev")`，
   `aria-expanded` 驱动 style-27 的旋转。上一批变更记录里「工作 N 步判定保持静态：它展开后
   整条消失，箭头没有可见的第二态」自此翻案——条不再消失，箭头有了第二态。
6. 排版：`planRowChips` 的 `moreWidth` 语义从「+N 按钮宽」改为「行首固定占位（折叠条）连一个
   gap 的宽」，函数本体零改动；折叠条宽度直接量现成节点，「+N 估了再校」的三轮循环随之删除。
   一行放不下的收法照旧（运行中的块仍 pinned 不被收走）。

**为什么**

用户口径（原话转述）：「点击『工作多少步』这个按钮能展开、能收起，鼠标只需要点在一处，
不需要移动」「每次思考过程中显示工作多少步」「工作 21 步不要隐藏，把底下收起取消掉」。
想简单看看 Agent 做了什么时，一处点击的展开/收起对用户最省事。

**验证**（2026-11-21，隔离实例 + IAB 真机）

- `node --test src/tool-chips-row.test.mjs` 6/6 绿（顺带实证 `tool-chips.js → icons.js` 导入链在
  node 下可用）；`pnpm typecheck` 绿。
- 隔离实例（探针口径 env 全隔离 + `LLM_FAUX_TOOL=recall` + `AGENT_MAX_TURNS=3`，8398 端口，
  跑完即删）浏览器实测：跑动中行首出现「工作 3 步」与灰块同排；收尾折回只剩计数条；
  点条展开——条在行首不动、箭头指下、三枚块全摊开、无「收起」无「+N」（DOM 断言
  `collapseBtnCount:0 / moreBtnCount:0`）；再点收回；刷新后历史回读同样收成计数条。
- 悬停提示：折叠条的 `title` 被全站 tooltip 体系收进 `data-tip`（悬停仍出字），符合既有口径。
- 探针老坑再现并按既有结论处理：IAB 里 rAF 排队不走帧，点完立即读 DOM 读到的是旧状态；
  截图强制合成器帧后再读才是终态。**本轮实测把这条坑的边界又推了一步**：不只是 evaluate
  挂起期间，页面无人盯时排版帧整个不跑——发消息后 0.8s 回合跑完，`finish()` 的排队布局
  直到截图才落地。读数"卡住"均为伪影，非代码 bug。
- 验证过程确认一处**与本批无关的既有形状**：撞回合上限的轮，被闸门拦下的工具调用也进历史
  steps（一次真跑 + 拦下数），历史回读每组块数比现场多——旧代码同样画，不属本批修。

**回滚**：纯前端交互批，无 env 开关（沿「前端细节五件」先例），回滚 = revert 本批。

**明确不做**：给单块组配计数条；历史 steps 里拦下调用的过滤/去重（数据形状是闸门口径的事，
另案）；手机端（手机端无此组件）。
