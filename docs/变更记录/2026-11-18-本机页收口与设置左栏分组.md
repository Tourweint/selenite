# 变更记录：2026-11-18 本机页收口（7 节 → 3 节）与设置左栏分组

> 范围：纯前端 `ts/apps/server/web/`（settings-base / settings-router / settings-connection / approval-pop / settings-tools / search-sources / style-07 / style-08 / style-11）。零契约、零服务端改动。

## 为什么

用户 2026-11-18 三条口径：

1. **本机页做得不太美观，分得特别碎，块也比较小**——7 个分节标题 + 7 张小卡（连接状态 / 本地连接 / 远程连接 / 已连接的设备 / 服务 / 运行时 / 关于），其实是同一件事被切成了七段。
2. **把设置最左边一级菜单的排序理一理**——左栏 11 项按历史追加顺序平铺（外观 / 会话 / Agent / 项目 / 定时任务 / 本机 / 模型 / 插件 / 用量 / 记忆 / 技能），读起来没有主线（「本机」夹在「定时任务」和「模型」之间、「技能」「记忆」落在「用量」「插件」后面）。
3. **两个「添加手机」其实是一件事**——扫码连接手机（本地）与远程添加手机做成同一张浮起来的卡，卡里选本地 / 远程，并写清什么时候用哪个；本地二维码原来内联在卡片里，形态也和远程的弹窗不一致。

## 改了什么

### 一、本机页：三节三卡

| 节 | 内容 |
| --- | --- |
| 连接 | 星图 + 状态提示 + 中继地址（接入 / 断开）+ 添加手机（一个入口，第二轮的浮层卡里选本地 / 远程）——几块本来就是同一条操作链（状态 → 接入 → 手机两条路），收进一张卡 |
| 已连接的设备 | 设备名册单独一节（行数会变；塞进连接卡会被读成操作流程的一部分） |
| 服务与关于 | 桌面通知 / 鉴权 / Node 服务 / 开机自启 / Selenite 版本——都是「这台电脑怎么跑」；「关于」不再单独占一张小卡，版本作为最后一行（0.1.0），描述与 MIT 许可收进悬停 |

- DOM id（`conn-star` / `relay-*` / `pair-*` / `device-card` / `runtime-*` / `autostart-*` / `svc-*`）全部保留，`settings-connection.js` 与 `approval-pop.js` 的读写零改动；原 `insertAdjacentHTML` 追加区块已并进同一段模板。
- 星图（画布口径）：`360×252` → `720×240`，`.conn-star` 显式 `width:100%`。并卡后它是一个 flex 列里的项，只写 `margin:0 auto` 会按内容宽度收缩到 300px，在 980px 的卡里两侧空得像没画完；宽画布按 1:1 铺开，文字保持 10.5–12.5px 的正常字号。
- 设备落点：原先从 `1.5π` 起算，只有一台设备时它总在右上角、图的下半张一直空着；改成以水平方向为轴在右半圈对称成扇（一台 = 一条「本机 ← 中继 → 手机」横线，多台上下均匀铺开）。

### 二、左栏一级菜单：三组 + 顺序

- `settings-base.js` 新增 `SETTINGS_GROUPS`，数组顺序 = 显示顺序：
  - **日常**：外观 / 会话 / 项目 / 定时任务
  - **Agent**：Agent / 模型 / 技能 / 记忆
  - **系统**：用量 / 插件 / 本机
- `SETTINGS_SECTIONS` 退成**注册表**（id / label / icon / desc），不再决定顺序；`renderSettingsNav` 按分组渲染，组前插一条不可点的 `.set-nav-group` 小标题（`role="presentation"`）。
- 防漂移：新分区漏写进分组表不会消失，会落末尾「其他」组；分组表里写错 id 只跳过该项，其余照常渲染。
- 窄屏（≤800px）左栏改横排时分组标题整条隐藏（`.set-nav-group { display:none }`），胶囊本身按组连着排；宽屏标题字号 11px / `--text-3`，只当分隔不当二级导航。

### 三、失效文案同步

- 设备空态：「上面「本地连接」扫一次码，或「远程连接」点「添加手机」」→「上面「扫码连接手机」出一枚码，或「远程添加手机」加一台」。
- 未配对设备的「去配对」浮签：「上方的本地连接码」→「上方「扫码连接手机」出的码」。
- 工具池保存提示：「设置 → 服务 → 重启」→「设置 → 本机 → Node 服务 → 重启」。
- 搜索源旧服务报错：「去 设置 → 服务 点「重启」」→「去 设置 → 本机 点「重启」」。

### 四、添加手机：两行并成一张浮层卡（同日第二轮）

用户口径：两个「添加手机」其实是一件事，合并后在卡片里选远程 / 本地；扫码连接手机的二维码也改成浮起来的卡片（和远程一致），并标注两者不一样；卡里要写清什么时候用远程、什么时候用本地。

- 页面只留一行 **添加手机**（本地：同一 WiFi / 数据线 · 远程：经中继），点开是一张浮层卡：
  - 顶部 `.segmented.slide` 二选一 **本地连接 / 远程连接**（滑行高亮复用 `settings-atoms` 的 mountSegmented / syncSegmented）；
  - **本地连接**：`/api/v1/pair/qr` 配对二维码 + 机器名 + 「N 分钟内有效 · 扫完即配对」+「换新码」；只在停在本地面板时每 100 秒自动换一张（原页面内的 `pair-qr-box` 轮询退役）；
  - **远程连接**：`/api/v1/relay/join-code` 一次性加入码 + 倒计时 +「换新码」+「手机连不上？改对外地址」；中继没连上时先给「接入中继 / 重新检测」这一格（永不置灰），连上后才取码。
  - 2026-11-18 同日第三轮（用户口径：去掉解释性文字、两个按钮叫同一个名字）：删掉本地「手机 App 扫这个码就连上这台电脑，不用输令牌」与远程「手机 App 扫这个码加入；加入码只能用一次……」两句常驻说明；远程那一行只留给「正在取码 / 取码失败」（取到码即清空并隐藏）；两边按钮统一叫 **换新码**。
  - 卡底常驻 **「什么时候用哪个」**：本地 = 同一 WiFi / 数据线 / USB 共享网络（局域网直连、最快、不占中继）；远程 = 人不在电脑边或手机用流量（经中继，前提是电脑已接入中继）；两种都配过时同一网络自动走本地。
- `loadPair()` → `loadLocalPair(root)`（只动浮层里的节点）；`openAddDeviceModal()` → `openAddPhoneModal(mode)`；设备行「去配对」改为直接开本地面板；`paintNextStep` 的「添加手机」同走一个入口；`paintRelaySection` 里改文案的 `#relay-add-device` 分支删除。
- 页面内联的 `#pair-qr-box / #pair-qr / #pair-meta / #pair-refresh` 与对应 `.pair*` 样式全部退役（二维码统一用 `.relay-join*` 的左码右字）。
- 新增样式 `.phone-mode / .phone-pane / .phone-gate / .phone-when*`（style-08）。

## 刻意不做

- 不给本机页挂 tab（连接 / 设备 / 服务与关于 一条竖排就够；三节再拆 tab 反而回到「碎」）。
- 不动中继、设备名册、配对码的任何语义与接口；星图只改画布与落点。
- 不记住上次选的连接方式：浮层每次从「本地连接」起（多数人就在电脑边；远程在卡里一眼能切）。
- 远程面板不在中继断开时自动重试取码（加入码一次性，猛重试只会消耗凭据）；只给「重新检测」按钮。
- 不加 env 开关：纯 UI 结构重组，回滚就是 revert。
