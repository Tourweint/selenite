# 2026-11-04 批次二落地（六件）

方案：`docs/设计方案/2026-11-04-批次二方案（通知·上下文·排队·搜索·表格·壳）.md`（落地顺序按其 §七：
表格 → 上下文 → 通知 → 搜索 → 壳 → 排队）。与并行会话的任务中心工作在同一批文件上交错进行，
每次编辑前都重新读取了最新版本（他们的 delegate/attention 卡片增强与本批改动无冲突）。

## 改了什么

契约（接口文档 §2.5 先行）：

- `GET /api/v1/agent/chat/:conversationId/context`：`{used, window}`。
  **方案偏差**：used 不从 ContextView 自算 token，改取本轮最后一次请求的 `usage.input`
  （上游真实测量的 prompt 大小，压缩效果已含在内，比自算准）；window 取模型目录 contextWindow。
- `GET /api/v1/agent/search?q=&limit=20`：内容级跨会话搜索，`q` 最少 2 字符，
  片段 ±40/80 字；实现为逐会话读 transcript 的 LIKE 过滤（FTS5 后置，方案已登记）。

服务端（agent.ts / index.ts）：

- `contextUsageOf()`：复用批次一的 `readLastTurnUsage`；`searchTranscripts()`：listChats 索引 + 逐会话过滤。
- mock 流补一张示例表——表格渲染在无 key 环境也有得验（同批次一给 mock 加代码块的先例）。

界面（web/）：

1. **表格渲染**：renderMarkdown 行扫描加表格分支；判定保守（下一行是纯 `-/:" 分隔行才成表，
   带竖线的普通句子不误吞）；对齐 `:---`/`---:`；单元格走 inline。CSS：`.table-wrap` 横滚 +
   `--divider` 边框 + 表头 `--card-high`。
2. **上下文徽标**：标题栏右侧文本徽标 `12k/131k`（**不做圆环**，方案已定），≥70% 警示色、≥90% 错误色；
   done 后与切会话时刷新；mock 下隐藏。
3. **桌面通知**：Web Notification API；三时机 done / error / attention（attention 点击直达会话）；
   **静默判定是前置条件**——窗口可见且正看该会话不通知；开关在设置-服务分区（默认关，
   开启时才请求系统权限，被拒退回关闭并提示）。
4. **内容搜索**：设置-会话的搜索框升级——本地标题/首句过滤照旧，≥2 字符加 300ms 防抖的服务端正文搜索，
   命中句 `<mark>` 高亮 + 会话/角色/时间，点击直达会话。
5. **排队插话**：忙时发送不再被拒——进 composer 上方的队列面板（FIFO、可撤回，上限 10 条）；
   本轮 done 后自动依次真发（发送仍走现有 /chat，以 SSE start 为成功依据）；停止 = 中断当前轮 +
   队列保留 + 面板出「继续发送」按钮。**队列只存内存，刷新即丢**（方案 §三登记的边界）。
6. **壳三小项**（`desktop/main.go` + 新 `desktop/window-state.go`）：
   - 窗口几何持久化：OnMove/OnResize/最大化切换防抖 800ms 落盘（`%AppConfigDir%/Selenite/window.json`，
     临时文件 + rename 原子写），启动恢复；损坏/过小的存档回退比例算法。
   - 首次隐藏告知：第一次关窗弹原生说明框（mygo Dialog.Message），ack 落文件后永不复发。
   - 运行期守护：10s 探活，连续 3 次失败自动重拉服务（30s 防抖）；页面自己的 checkHealth 负责界面恢复；
     `LIFEDIARY_SHELL_WATCH=off` 一行回滚。**方案偏差**：没做托盘图标变灰（MyGo 托盘换图标未验证，
     留待需要时补），守护只做自动重拉。

## 为什么

批次二方案（2026-11-04）定的六件，用户拍板"那就开始吧"。顺序按方案 §七——排队最后做，
因为它动 composer 的核心时序。

- `pnpm typecheck` ✓；`node --check web/app.js` ✓；`pnpm --filter @lifediary/server http` 全绿
  （新增 §12：context 端点 200 / used=1698 window=131072 / 未知会话 404 / 搜索命中「团子」/ 单字符防全表扫）；
  `pnpm probe`（内核）全部通过。
- 浏览器实测（mock 8127 + faux 8127 双轮，隔离数据，跑完清理）：
  - mock：忙时第二条入队（面板"排队中 1 条"+可撤回）→ 第一轮 done 后**自动续发**第二条
    （两条回复、面板收起）；表格渲染（两条回复各一张表，表头/对齐正确）；ctx 徽标隐藏（mock 无数据）✓。
  - faux：ctx 徽标显示"2k/128k"，title"上下文已用 1%（1,616 / 128,000 tokens）"；
    搜索"徽标"命中本轮原句且 `<mark>` 高亮，hint 带会话/角色/时间；通知开关渲染与默认态正确。
- 壳：`go vet` + `go build` 通过；**运行时冒烟没做成**——用户自己的壳正在运行（单实例锁挡住测试实例），
  新行为在下次重启壳时生效。正式 `desktop/lifediary-shell.exe` 已用新代码重编。
- **没验的**：真模型下 thinking/表格/长对话的搜索性能；通知的系统级弹窗（IAB 无通知权限，
  权限请求→授权→弹窗链路要在壳/真浏览器里走一遍）；窗口几何的跨显示器恢复。
