# 2026-11-23 注入页「关于我」改名「偏好」，读取开关搬进人设页

## 改了什么

1. **改名**：设置 → 注入 里的 tab 与页面内容，`关于我` → `偏好`；tab 注脚
   **仍是「固定注入」**（用户明确要求这四个字不能改）。同一批同步了会露出旧名字的几处展示：
   `context-inspect.ts` 的段标签（`偏好`）、`settings-context-edit.js` 的行内编辑标题、
   `plugins.json` 里 `USER_PROFILE_ENABLED` 的 label，以及 `user-profile.ts` 的三条
   对外错误文案（「偏好」已关闭 / 超过字节上限 / 普通 worker 不读）。
   注入段头 `【关于我】` 与内部 key `user_profile` **不动**（前者是提示词前缀资产，
   后者是存储与契约名）。
2. **删解释性文案**（`web/settings-about-me.js`）：
   - 卡片顶部的「每轮作为系统提示词注入……改完下一轮生效」整句；
   - 输入时的「保存后下一轮生效；这段在固定前缀里……」；
   - 保存后的缓存重建说明（只留 toast「已保存」）；
   - 原先「谁读」卡下面的「开关下一轮生效。派活工人（池）固定不读。」与那条
     `去 设置 → 注入 → 上下文 看实际注入` 的链接；
   - 占位符去掉「比如：」，三行保留。
3. **「谁读」从偏好页搬进人设页**（用户口径：每个人面向这个人来设更合适）：
   - 偏好页现在只有一张正文卡（改正文 + 撤销 / 保存 / 字节数），没有第二块；
   - 每个人的人设页（`#/settings/partners/<id>`，总管与执事同页）在
     **「每轮固定注入」** 区新增第一张卡「偏好」：开 / 关 + 一行摘要
     （`开 · 固定注入` / `关` / 总闸关着），点卡或开关立即落库、下一轮生效；
   - 开关仍落 `partners.user_profile_read`，走 `PUT /agent/user-profile/agents/:id`，
     **不进页面草稿、不受底部保存条管**（它不属性格内容）；
   - 总闸 `USER_PROFILE_ENABLED=false` 时卡片显示「总闸关着」且开关禁用；
     读不到列表时这一张卡不画，页面其余部分照常。
4. **版式收口**（只作用于偏好页，`style-14-settings-pages.css` 的 `.up-*`）：
   卡片内边距 16/18/14 → 12/16/10，卡内 gap 12 → 8；去掉与 tab 重名的页内大标题。

## 为什么改

用户口径：这一页「『关于我』不太好，改成『偏好』之类的名字」；
「解释性文字太多了」；「距离上下容器上下的间距太大」；
链接与「开关下一轮生效」这类提示「都没有用了」；
「这个开关就放在这个人设页里头，每个人面向这个人来做的这个东西比较好」。

## 明确没做

- 「究竟在哪注入」（装配顺序 / system 段位置）没有动，仍紧跟人设、只对会读的 Agent 注入。
- 注入段头、`user_profile` 契约名、`partners.user_profile_read` 存储列都不改名。
- 上下文页「实际注入」为什么看起来没用：没有在这一批里查。

- `pnpm typecheck` 绿。

- 真机页面（127.0.0.1:39847）：

  - 总管人设页「每轮固定注入」第一张卡为「偏好 · 开 · 固定注入」，与纪律 / 在办 / 履历 / 负责项目同尺寸（44px）；
  - 点开关两次（关 → 开）都即时返回 toast（已设为不读偏好 / 已设为读取偏好），
