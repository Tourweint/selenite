## 改了什么

### 契约与文档（先于代码）

- `接口文档.md` §2.5：`GET /api/v1/agent/approvals` 的 `conversationId` 改为**可选**。不带 / 空串 = 全局待办：

  只回 pending、按 `createdAt` 升序、`limit` 默认 50；带参仍是原语义与原形状。补「数据边界」一段：
  全局列表把各会话的 `args` 给任一已配对设备，与 `GET /agent/chats` 既有边界一致，不是新增提权；
  任务会话无审批、隐藏会话可能出现（标题可空）。
- `接口文档.md` §2.7：确认 / 拒绝路由勘误为 `POST /api/v1/projects/:id/confirm|reject`（`:id` 为 proposal id），

### 服务端

- `approvals.ts`：新增 `pendingAll()`——跨会话、只回 `status === "pending"`、按 `createdAt` 升序。
- `agent.ts`：新增 `externalChatIds()`（`Chats.byExternal` 反向快照，内部 id → 对外 uuid，不逐会话 `openChat`）
  与 `chatTitles()`（只读 `chat-meta.json` 的 `titles`）。
- `approval-api.ts`：`GET /agent/approvals` 分支——
  - 先判 `readLlmConfig()`，未配置 → 503（与带参路径一致）；
  - 无参 / 空串：`pendingAll()` + 反查 uuid + 改名表标题；没有标题就**省略** `chatTitle`（不报错、不编值）；
    没有对外映射的内部会话跳过（宁可少一条也不编 id）；`limit` 非法或 ≤0 回落 50；
  - 带参：原 `openChat` → `pendingOf` 路径不动。
- `tools.ts`：`propose_project` 的返回话术「工作区设置」→「项目设置」。

### web 设置页

- `SETTINGS_SECTIONS` 新增一级分区「项目」（在「会话」之后）；`renderSettings` 增加 `projects` 分支，
  不再落到默认「关于」。
- 工作区卡：显示当前 `rootPath`（未设时给引导语）+「设定 / 更换」行内表单；失败按 `ProjectError.code`
  显示中文原因（`bad_path` / `outside_workspace` / `no_workspace` 等）。
- 项目列表：名称、**相对路径由前端用 `workspace.rootPath` 计算**（接口无 `relativePath`，服务端零改动）、

- 待确认提案：`GET /projects/proposals?status=pending` → 确认 / 拒绝 → `POST /projects/:id/confirm|reject`

### 探针与单测

- 新增 `ts/apps/server/scripts/settings-probe.ts`（`pnpm --filter @lifediary/server settings`）：

## 已知边界 / 风险（未在本批处理）

- **全局待办的权限面**：任一已配对设备能看到所有会话的待批 `args`。图纸判定与 `GET /agent/chats` 既有边界一致
  （持令牌者可列全部会话并按 id 回读），不是新提权；已写进接口文档 §2.5。
- **设置页待办是一次性快照**：打开页面时拉一次，倒计时不逐秒走、也不自动刷新；聊天卡片仍由 SSE 实时更新，
  手机侧按其轮询节奏自行刷新。若以后要长驻设置页，可加定时重拉（本批不做）。
- **无对外映射的 pending 会被跳过**：`byExternal` 目前只增不减，正常不会出现；真删映射时宁可少展示一条，
  也不伪造 uuid。审批本身仍会按超时/停止结算。
- **未做浏览器视觉核对**：类名与布局沿用现有设置页，但没在真浏览器里点过整条 UI 链；如需验收请起真服务走一遍。
- **未提交**：按指示没有 `git commit` / `git push`；工作区里还叠着批次五等未提交改动。
