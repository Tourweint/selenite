# 归档 / 删除项目退出召回库 · 2026-11-16

**用户口径**：项目一旦归档或删除，这个项目的记忆就不要再进入召回库——记忆本身不删、还能看，
只是不再被"想起来"。归档项目也不再接收新记忆（写进去也召回不到，等于死账）。

## 改了什么

- **`agent/project-scope.ts`**：新增项目状态解析（`ProjectState = active | archived | missing`）
  与过滤函数：
  - `setProjectStateResolver` / `projectStateOf`：按项目 id 现查状态，由 lifecycle-harness 接线
    （`projectsStore().findProject(id)`：查不到 = `missing`，`archived` 位 = `archived`）；
    未接线 / 抛错一律按 `active`（退回旧行为，记忆不能因为一次辅助读取失败就不召回）。
  - `projectMemoryStateOf`：记忆闸看到的状态——`PROJECT_MEMORY_ACTIVE_ONLY=false` 时一律
    `active`（一行回滚）。
  - `isRecallableProjectId` / `recallableProjectIds`：只有 `active` 项目进召回池。
- **三条召回入口装配前过滤**（旧会话的 `ChatProjects` 绑定与人格挂载都可能指向死项目：
  归档不摘挂载、删除不清旧会话绑定，所以必须现查，不能在归档 / 删除时清数据——
  归档可恢复，清了绑定就回不来）：
  1. `agent/assist.ts` `recallContext`：绑定项目非 `active` 时不再进主列，人格挂载先过滤再
     进 `fullKeys` / `gatedScopes`；
  2. `agent/assist.ts` `projectIndexProvider`：归档 / 删除的项目不再出现在「你负责的项目」索引行；
  3. `tools.ts` `recall` 工具：主动查同样不放行（规则是"不进召回库"，不是"只是不自动注入"）。
- **`tools.ts` `remember scope=project`**：解析出的目标项目非 `active` 时报
  `project_inactive`——归档项目提示"先恢复项目再记"，已删除项目提示"登记没了，记成普通记忆"。
- **回滚开关** `PROJECT_MEMORY_ACTIVE_ONLY`（默认开；`false` / `0` = 旧形态：归档项目照旧召回、
  照旧接收记忆）。落点 `partner-contract.ts`。

## 刻意没做

- **不删记忆、不清数据**：归档 / 删除期间记忆仍在库里；记忆页照旧能看（范围清单仍列归档项目），
  导出照旧包含；恢复归档后自动回到召回池。
- **不动会话绑定与人格挂载**：归档不摘 `partner.projectIds`，删除不补清 `ChatProjects`
  （删除时本来就只摘执事挂载），过滤发生在召回装配层。
- **不改记忆页 / 导出 / 手动搜索**：那些是"看"，不是"召回"。
- **不改自动抽取、巩固、每晚整理**：项目 scope 本来就不进自动抽取；整理不受影响。

## 边界 / 不确定

- 没有起真服务跑"归档 → 旧会话再聊 → 看注入"的端到端；装配路径由纯函数单测 + 代码接线保证。
- 项目状态解析器读失败时按 `active` 降级：那一刻归档项目的记忆仍可能被召回（宁可多召回，
  不让记忆因为辅助读取失败整体消失）。这是有意的降级口径。
- 已删除项目的记忆仍留库，但记忆页范围清单按"已登记项目"列（删除后没有 tab）——既有行为，
  本批不改；导出仍包含。
