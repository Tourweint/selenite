# 任务单近况落盘：最近动作 / 心跳 / 等待文件

> 2026-11-04。对应接口文档 §2.1 `delegate` 行与 §2.9 任务中心只读接口。

## 改了什么

- `Ticket` 新增 `lastAction` / `lastHeartbeat` / `waitingOn` 三个可选字段，写进 `ticket.json`。
- `Store.saveTicketProgress`：动作或等待对象变了立刻写；只有心跳变化时最多每 10 秒写一次。
  只写明文，不动 sqlite 的 `updated_at`，避免近况刷新打乱看板按 `updated_at` 的排序。
- 事件出口统一接一层：`runChancellor` / `resumeTicket` 的 `emit` 先落进度再推给宿主；
  自动续跑（无宿主连接）也落盘，重启后的看板仍能看到它跑到哪。
- 状态变化时刷新 `lastHeartbeat`，终态保留最后一次的值。
- `GET /api/v1/tickets` 列表补三个字段；`GET /api/v1/tickets/:id` 的 `ticket` 是本单明文，直接带上。

## 为什么

三项原先只在 SSE 的 `delegate` 事件里，进程一重启或看板晚打开就什么都看不到；
`ticket.json` 本来就是任务单的持久事实源，近况应当跟它走。之所以节流，是因为心跳比任务动作密，
每次都写盘会把一个展示字段变成磁盘写放大。

## 验证

- `pnpm typecheck`（chancellor 与 harness 两仓）通过。
- `pnpm --filter @lifediary/server test` 通过；新增两个用例：只读接口列表/详情带回三项、
  `saveTicketProgress` 的「动作变化立刻写 + 纯心跳节流 + 新进程读回」。
