# 2026-11-23 调度简化：总管直接拆单 + 容量放大

## 结论

拆单器（chancellor 内部的拆单模型调用）退役：**总管 / 领域经理在 `delegate` 时直接给
`tasks`**；没给的入口（前端直派、手机、远端设备）退化成**整单一个任务**。
同时放大默认容量：同时活跃单 3→8、同领域准入 1→4、池进程 4→8、外部 CLI 车道
Claude/Codex 2→4、OpenCode/Qoder/CodeBuddy 1→2。
终止回执补上结构化 `failure`（失败类型 / 可重试 / 超时 / 中止），随唤醒提示词交给派活人。

设计依据：`docs/设计方案/2026-11-23-调度简化（总管直接拆单·容量放大）.md`。

## 改了什么

### 1. 拆单器退役

> 缓存提示：`delegate` 工具描述与参数面变了（新增 `tasks`、描述从 steps 改 tasks），
> 上游 prompt cache 会被打掉一次；这是功能变更的必要代价，登记在此。

- `packages/chancellor/src/plan.ts`：删 `planTicket()` / `buildPlanPrompt()` / `askInternal` 依赖；
  保留并复用 `validatePlan()` 的规范化；新增：
  - `validateTaskInput(raw, maxTasks)`：tasks 必须是数组、1..maxTasks、四项必填、slug 合法、
    `writes` 必须显式给（只读给 `[]`）。
  - `singleTaskFromRequirement(requirement, steps?)`：整单兜底任务，
    `slug:"task"`、`writes:["**"]`、`done_when` 为通用可验证句。
  - `resolveRequestTasks()`：有 tasks → 校验直用（source `dispatcher`）；没有 → 单任务（source `single`）；
    `CHANCELLOR_TASKS_DIRECT=false/0/off` → 忽略 tasks、一律单任务。
- `packages/chancellor/src/index.ts`：`runRound` 不再 await 拆单模型；`plan.json` 增 `source`，
  `attempts` 恒空；校验失败转 `needs_you`（`invalid_tasks` 文案）。
- 宿主 `tools.ts` 的 `delegate` 与领域经理的 `delegate` 都新增 `tasks` 参数（title / slug /
  instruction / done_when / dependsOn / writes），入参前用同一份 `validateTaskInput` 校验。
- 项目记忆不丢：原来拼进 requirement 交给拆单器分发；现在**每个 task 的 instruction 尾部**
  追加同一段项目记忆（只影响派活输入，不参与幂等指纹）。
- `steps` 保留但降级：只用于任务详情展示；单任务兜底时按 `appendPlanSteps()` 拼进 instruction。
- 领域经理 prompt 与 `skills/delegate.md` 改成“拆单是你的活，直接给 tasks”。

### 2. 写集 `**`

- `paths.ts` 的 `writeCovers()` 支持 `declared === "**"` = 整项目；租约按字面量 `"**"` 建锁，
  两个兜底任务之间串行。
- 池 profile 与 TASK.md 的「工作边界」在 writes 含 `**` 时显示“项目内任意路径（**）”。
- 已知小风险：`**` 与具体路径租约不互斥；worktree + 合并冲突检查仍是最后一道闸（用户已接受
  小概率碰撞）。

### 3. 容量默认值

| 变量 | 旧 | 新 |
|---|---|---|
| `CHANCELLOR_MAX_ACTIVE_TICKETS` | 3 | **8**（文档推荐上限 16） |
| `CHANCELLOR_MAX_ACTIVE_PER_DOMAIN` | 1 | **4** |
| `WORKER_POOL_SIZE`（旧名 `SUPERVISOR_POOL_SIZE` 兼容） | 4 | **8** |
| `CHANCELLOR_LANE_CAPS` 缺省 claude-code / codex | 2 / 2 | **4 / 4** |
| 缺省 opencode / qoder-intl / qoder-cn / codebuddy | 1 | **2** |
| phone / mcp | 1 | 1 |

- `WORKER_POOL_SIZE` 成为优先读的名字，`SUPERVISOR_POOL_SIZE` 兼容；修了“文档写
  `WORKER_POOL_SIZE`、代码只读 `SUPERVISOR_POOL_SIZE`”的旧漂移。
- **同领域 manager 仍串行**（领域闸 1）：manager 是长期会话 + 单份 `.agent.sqlite`，
  两个进程会抢同一个 `conversation_id`；准入层同领域放到 4 已经让单子不再互相挡。

### 4. 终止回执

- `TicketResult.failure?: {class, retryable, canceled?, timedOut?}`；`finishRuns` 汇总：
  中止 → `aborted`；有失败 task → 该 task 的 `failureClass` + `failureIsRetryable()`；
  超时/中止打标。
- `DelegationReport.failure` 复制到宿主；`buildWakePrompt()` 渲染
  `终止：<class>（可重试/不可重试，超时，已中止）`；直派任务专线汇报尾部也追加同一句。
- 失败分类与“可不可重试”复用 `failure-class.ts` 的 `retryDecision()`，不另立一套。

### 5. 池 `writes` 接线（收口补）

2026-11-22 引入 `TaskProfileInput.writes` 时漏了从宿主到池的线：池工人的「工作边界」
一直显示“本任务为只读”。本批接上：

- `EmployeeTask.writes` → `dispatch.ts` 构造 employeeTask 时带 `task.writes` →
  `employee/pool.ts` 的 `PoolClient.run` 透传。
- 池 `/run` 契约（`QueuedRun` / `pool-server.parseRun` / `bridge.parseRun` / `supervisor.toRunBody`）
  新增可选 `writes: string[]`（最多 200 条，非字符串数组 400）。
- `pool-main.ts` 装配 `buildTaskProfile({ writes: run.writes })`；边界段现在按真实写集显示，
  `["**"]` 显示“项目内任意路径（**）”，只读任务仍显示“本任务为只读”。
- 测试：`pool-server.test.ts`（带 writes 接受 / 非数组 400）、`bridge.test.ts`（桥透传）、
  `task-profile.test.ts`（边界文案既有断言）。

## 回滚

- 拆单：`CHANCELLOR_TASKS_DIRECT=false/0/off` → 忽略 `tasks`，一律单任务；
  要恢复拆单器本身需 `git revert` 本批（模型调用代码已删）。
- 容量：全是 env，改回旧值即可（如 `CHANCELLOR_MAX_ACTIVE_TICKETS=3`、
  `CHANCELLOR_MAX_ACTIVE_PER_DOMAIN=1`、`WORKER_POOL_SIZE=4`）。
- `**` 写集：无开关；调用方不给 tasks 时才会出现。
