# 2026-11-25 刷新续看与派活回执

前情 / 方案：`docs/设计方案/2026-11-25-刷新续看与派活回执可见性.md`。
本次涉及服务端 `index.ts` / `tools.ts`、前端 `chat-open.js` / `net.js` / `composer-send.js` /
`tasks-redesign.js`，以及契约文档 §2.2。

## 改了什么

1. **`GET /agent/chat/:id/messages` 加 `running`**（纯增量）：
   `conversationIsBusy(chat.conversation)` 读 durable 的 `LiveDoc.run`；带不带
   `sinceSeq` 的两个响应都带。老客户端忽略即可。
2. **刷新后自动续看**（`chat-open.js`）：`openChat` 读回 `running=true` 时追加一行
   「这一轮还在后台跑，完成后会自动刷新。」，每 2 秒查一次 `limit=1`；跑完自动
   `openChat` 重建并提示「这一轮跑完了，内容已刷新。」。本地 `state.sending` 为真时
   不轮询，交给现有流；20 分钟仍未收尾则停止轮询。
3. **断流 / 断网提示**：
   - `net.js` 新增全站固定横幅 `.conn-banner`：断网 → 「网络已断开，正在等待恢复…」、
     服务失联 → 「与服务的连接中断，正在自动重连…」、恢复 → 「已重新连接」（2.4s 收起）；
     首屏首次连接成功不弹。浏览器 `online/offline` 事件先到先提示，8 秒健康轮询兜底。
   - `composer-send.js`：流在没有 `done` 的情况下结束（fetch 没抛错）时也带
     `sinceSeq` 补一次缺帧并 `addNotice` 说明；异常断流同样在错误卡之外补一句
     「断线期间的事件已自动补上；回答正文可能不完整」。两种情形都接着启动
     `watchRunningTurn`：服务端还在跑就等它收尾自动重读；用户主动停止时不启动。
4. **派活回执说清成功 / 失败**（`tools.ts`）：
   - 新增 `delegateFailedResult` / `delegateNeedsProject`：`delegate` 所有「没受理」
     分支（`needs_project`、`invalid_steps/tasks/isolation`、`delegate_rejected`、
     `auto_disabled`、设备矩阵不可用、`remote_resume_unsupported`、`bad_workdir`、
     `uncertain`、远端派发异常、同步派单异常）仍保留原 JSON（候选项目清单等不丢），
     但工具结果加 `isError: true`；聊天灰块会画成失败，不再绿勾。
   - 返回文案统一开头：「派活成功：」「派活失败：」「派活已提交：」；还没拿到单号
     时如实说「任务单还在受理中（还没拿到单号）」，不冒充已受理。
   - `delegate` 工具 description 追加一句：**先看工具结果第一句**，写「派活成功」
     才可告诉用户已派出。工具描述是缓存前缀资产，本批改了这一句，按规定记录。
5. **任务中心补「无来源对话」的在跑 / 出错单**（`tasks-redesign.js`）：
   `runBlockHtml` 接收 `direct`，把 `conversationId` 为空的 run/fail 单渲染成小卡，
   点开走 `#/tasks?ticket=`。以前只渲染对话卡，SSE 刚派出去、会话映射还没补齐的单
   会短暂完全不可见。
6. **跑动中的回答不挂复制 / 分支脚注**（见同批 `2026-11-25-工作步骤一轮一份（合并折叠条）.md`）。

## 为什么

用户当天反馈：
- 「刷新一下前端，正在运行的东西好像卡住了，工作也没继续」——服务端其实还在跑，
  只是客户端没有任何「还在跑」的表达；刷新后也看不到后续。
- 「派活派出去了，任务中心里也没看到；成功还是失败，你倒是给工具返回一个提示」——
  失败最常见的是 `needs_project`，不建单；但工具结果 `isError` 为假，界面画成成功。
- 「网断了，自动重连也没有提示」——只有侧栏状态点，视野里没有一句话。
