## 一、项目入口回归（最高优先）

### 现象与根因

展开态侧栏没有项目 pill、收起轨道也没有项目按钮；点不了项目，注册后也用不上。

根因不在 E4 的 DOM 重排，而在**失败路径把入口藏掉了**：

1. `fetchProjectSwitchData()` 对 `/api/v1/workspaces`、`/api/v1/projects` 的 404/5xx
   一律返回 `null`（只把 403 留给令牌门）；
2. `refreshProjectPill()` 拿到 `null` 后直接 `return`（原注释：读不到就保持隐藏）；
3. `#side-proj` 与 `#rail-proj` 在 HTML 里初始 `hidden`，只有 `syncProjectPill()` 会去掉
   `hidden`；于是接口不可用时它们**永远不出现**，看起来就是「项目凭空没了」。

用隔离 faux 服务 + 只把项目两个端点改成 404 的反代复现：`sideProjHidden=true`、
`railProjHidden=true`，侧栏文本里没有项目项。这与线上「老后端进程还没重启 / 接口暂时不可用」
的观感一致（2026-11-06 核对：当前 39847 进程已重启，接口正常；旧进程需要重启才带新路由）。

### 处置

- 接口不可用时不再隐藏入口：pill/轨道降级成「项目不可用」的可见态（`.is-unavailable`，
  仍可点击），点一下先重试，仍读不到就 toast「读不到项目接口，重启服务后再试」；
  `hashchange` / 启动 / 下次点击会自动恢复。
- 仅 403（令牌门）保持隐藏，避免在没登录时露一个点了必然失败的空壳。
- `CURRENT_PROJECT=false` 的静默 `return` 补 toast：「项目功能已关闭（CURRENT_PROJECT=false）」；
  切换命中回滚开关时也保留原有「当前项目功能已关闭」提示。
- 顺手修了轨道项目按钮的 SVG 隐藏 bug：`SVGElement` 没有 `hidden` IDL 属性，
  原来 `.hidden = true` 只挂了个 JS 属性，`[hidden]` 样式不生效，选了项目后文件夹图标
  和首字会同时出现。改为 `toggleAttribute("hidden", active)`。

## 三、无归属的活归总管

- 总管条目右侧新增 `.side-count`：「无 domain 且未终态」的单数（复用
  `TASK_BADGE_STATUSES` 口径）；为 0 不显示；`<span>` 不可点击。
- 任务中心的 domain 筛选里，`__none__` 的文案从「未分领域」改为「总管（未分配）」；
  任务详情里的 domain 兜底文案同步改。
- 口径：无 domain 的单 = 总管直接派发给无主工人的活。

### 顺带修掉的真实 bug：任务中心徽标

`syncTasksBadge()` 里 `alive` 原来写成收**数组**的函数，却直接传给
`direct.filter(alive)`；只要存在一张没有来源对话的直派单，就会在
`ticket.some is not a function` 处抛错，被 `loadTickets` 的 catch 吞掉，
导致任务中心徽标与本次新增的总管计数都不更新。改成 `alive(ticket)` 后，
卡内用 `.some(alive)`、直派用 `filter(alive)`，两处口径一致。
