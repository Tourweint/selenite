# 定时任务图形化创建（重复规则 + 改时间）

用户对 2026-11-12 那版手动提醒页的评价是："界面不好看，还有很多错误""几点还是尽量让用户自己调""你现在还得手动输入，比较麻烦，需要做成图形化的，比如滚动的时间、日期"。这一轮把"手动设置"从「左日历 + 右时段按钮 + 自定义 HH:mm 输入 + 每天重复 checkbox」重做成手机闹钟/日程表式的弹窗，并把服务端的周期规则补到能用。

定稿口径（用户逐条确认）：

- 时间不再手打 `HH:mm`，改成上下滚动的小时 / 分钟两列滚轮，点击也能跳；
- 重复方式五个：单日 / 区间 / 每天 / 每周 / 每月；
- 选了「每天」就不再出现日期选择；「区间」是每天重复，带开始与结束日期；
- 「每周」七个星期几可多选；「每月」1–31 的方格，小月按月末；
- 列表行不出现"明天几点 · 18 小时后"这类预测；
- 「提醒什么」只在新建时出现；改时间页只读展示原内容，不出输入框；
- 列表行上下留白加大，宽度基本不动；
- 「交给 Agent」只预填"帮我定个提醒："，时间与内容由 Agent 自己调工具决定。

## 为什么先改服务端

旧的 `ReminderInput` 只有 `repeat: none | daily`。前端就算画出"每周五""每月 15 号"，服务端也存不下、排不出。所以先把周期模型补齐，再改界面：

- `ReminderRepeat` 扩成 `none | daily | weekly | monthly`；
- 新增 `weekdays`（0 = 周日 … 6 = 周六，可多选）、`dayOfMonth`（1–31）、`until`（区间结束，含当天最后一毫秒）；
- 新增 `nextReminderAt(input, now)` 统一算下一跳：daily 按 wall clock 推、weekly 在 now 之后 7 天里找选中的星期几、monthly 按锚定几号翻月（31 号遇到 2 月落 28/29，下个月仍回 31），超过 `until` 返回 `null`；
- `deliver` 阶段改调 `nextReminderAt`，不再只认 daily；续排仍在"写提醒记录"的同一事务里，崩在中间最多漏一次，不会断链。

**`at` 的语义**：对周期提醒，`at` 只是「几点」的锚点，不是首次日期。POST / PATCH / Agent 工具都会把它推到 `now` 之后的第一跳再建任务。这样两件事同时成立：

1. 用户选"每周五"时，不会因为默认日期是明天周日就先在周日错响一次；
2. 编辑一条"今天 09:00 已经响过"的每日提醒、把时间改成 09:00 时，也不会因为 `at` 在过去而报错，服务端直接排到明天 09:00。

## 界面怎么画

弹窗宽度加到 `670px`，从上到下四段：提醒内容（仅新建）→ 重复方式 chip → 日期/星期/每月网格 → 两列时间滚轮。

| 模式 | 日期区 | 提交映射 |
|---|---|---|
| 单日 | 自绘月历，点哪天选哪天 | `repeat: "none"` |
| 区间 | 同一月历选起止：第一次点结束；再点一次重开；开始之后的日期浅色高亮 | `repeat: "daily"` + `until`（结束日 23:59:59.999） |
| 每天 | 只显示"每天 / 不用选日期"，没有日期控件 | `repeat: "daily"` |
| 每周 | 七个星期几 chip，可多选 | `repeat: "weekly"` + `weekdays` |
| 每月 | 1–31 方格，选中的实心；31 号旁注"小月按月末" | `repeat: "monthly"` + `dayOfMonth` |

时间滚轮：两列 `36px` 行高、`scroll-snap-align: center`，上下用渐隐遮住半行，中间一条 `--surface-low` 选中带；小时 `00–23`、分钟 `00–59`，点击某一项会平滑滚到中间。

交互上刻意不做"即时标红"：切到「区间」但还没选结束日期时，「添加」保持可用；点下去才在底部提示"再选一个结束日期"。"每天"模式下没有任何日期入口，从结构上保证"每天重复不能再选日期"。

## 改时间

列表每行新增「改时间」。点开后：

- 标题变「改时间」，不再渲染 `#reminder-text`，只读展示原提醒内容；
- 重复方式、日期/星期/每月、时间滚轮按原任务回填（区间回填起止、每周回填 weekdays、每月回填 dayOfMonth）；
- 保存走新的 `PATCH /api/v1/agent/reminders/:taskId`。

服务端 `rescheduleReminder(taskId, input)` 的做法是：先 `abortTask` 原任务，再用**同一个 `reminderId`** 创建新任务，内容和执事沿用原任务。为什么不原地改：durable 的睡眠状态是提交过的，直接改输入需要内核级支持；重排一条同 id 的任务更稳，而且列表按 `reminderId` 归组，不会多出一行"已结束"。

## Agent 入口

`settings-router.js` 的提醒页 hero 从「标题 + 自然语言输入框 + 日历图标 + 两个按钮」压成「标题 + 手动设置 + 交给 Agent」。`sendToAgent` 只写：

```js
el.input.value = "帮我定个提醒：";
```

不再拼"明天早上"之类的时间模板。建什么、怎么建由 Agent 自己调 `set_reminder`。工具侧同步扩了 `repeat / weekdays / dayOfMonth / until` 参数，并按同一套规则把 `at` 推到第一跳，保证 Agent 随手给一个 `at` 也不会错响。

## 列表

- 行高 `58px → 68px`，padding `10px 16px → 14px 18px`；
- 左侧仍是「日期/周期 + 时间」，中间内容，右侧「改时间 / 取消」；
- meta 只在区间时显示 `11月15日–11月20日`。每天/每周/每月不再重复一遍左侧已经写过的"每天""每周二、五""每月 20 号"；
- 删掉 `rmRelativeText` 及所有"X 小时后 / 明天几点"预测；
- 最多显示 20 条（原有上限，未改）。

## 接口口径（摘要）

- `POST /api/v1/agent/reminders` body `{conversationId?, text, at, repeat?, weekdays?, dayOfMonth?, until?, partnerId?}`；
- `PATCH /api/v1/agent/reminders/:taskId` body `{at, repeat?, weekdays?, dayOfMonth?, until?}`，不含 `text/partnerId`；
- weekly 必须带非空 `weekdays`（0–6，去重排序）；monthly 必须带 `dayOfMonth`（1–31）；
- `until` 只对周期提醒生效，必须晚于第一次触发；
- `GET` 每项带 `weekdays?`（仅 weekly）、`dayOfMonth?`（仅 monthly）、`until?`（区间），`conversationId` 为对外 id；
- PATCH 成功返回归一化后的 `at`，`taskId` 是新任务 id，但 `reminderId` 不变。

## 影响范围

- 只动提醒：`reminder.ts`、提醒 HTTP 路由、`ReminderSummary`、`set_reminder` 工具、设置页提醒模块及其样式；
- 旧客户端兼容：`repeat` 缺省仍是 `none`，新增字段都是可选的，GET 只是多字段；
- 桌面壳 / 手机端没有消费 `repeat/weekdays/dayOfMonth` 的新界面；它们仍按 `text + at` 展示，不会因为多字段报错；
- 旧的一次性提醒、已有每日提醒数据不变；列表归组仍按 `reminderId`；
- Agent 入口的消息模板变了（变短），属于用户明确要求的界面行为变更。

## 回滚建议

- 界面回滚：恢复本文件列出的三个 web 文件到上一版即可；服务端新增字段是纯增量，旧界面只发 `repeat: none|daily`，不受影响。
- 服务端回滚：把 `ReminderRepeat` 收回 `none|daily`、`parseReminderSchedule` 去掉 weekly/monthly 分支、`deliver` 改回 `nextDailyAt`；PATCH 路由必须一起下线，否则会出现"能改时间但排不出周期"的半截状态。
- 已用 weekly/monthly 建过任务的库，回滚前先把这些任务取消；否则旧 `deliver` 不认识 `repeat`，可能按一次性处理或报错。
