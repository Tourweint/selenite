# 2026-11-23 设置 → 注入 → 上下文：请求列表补「未命中」、把「写出」换成「输出」

## 用户口径

「请求这一行信息有点少」：

- 每行的 prompt 应该等于**命中 + 未命中**，现在只写了命中，未命中没写；两条都写出来。
- 「写出」那一列全是空的（看不懂是什么字段），去掉；改成「输出」——就是模型输出的 token。
- 首字耗时 / 整体耗时 / 多少 token 每秒：**不加**（用户原话「没啥必要了」）。

## 口径

- **未命中 = prompt − 命中**（即 `input + cacheWrite`）。这样每行恒有
  `命中 + 未命中 = prompt`，和「命中率 = 命中 / prompt」自洽；不需要新增接口字段
  （`inputTokens` / `outputTokens` / `cacheReadTokens` 本来就在 2.2.11 的响应里）。
- **「写出」退役**：它显示的是 `cacheWriteTokens`（写进缓存的 token），当前供应商适配层
  不回报这一项，整列恒为空（2026-11-23 实测 `partner-chief` 33 条请求全为 0）。
  接口字段保留（不删契约），只是页面不再展示。
- 数字沿用 `≈` 前缀（页面既有 token 估算口径），不做四舍五入以外的换算。

## 没做 / 边界

- 首字耗时、整体耗时、token/s 不做：durable 只存最终 usage，没有首字时间戳；
  要算得新增计时与存储，超出本次口径。
- 详情浮层头部仍只写 `prompt + 命中率`，未加未命中 / 输出；需要时再补，避免同一次改动铺开。
- 首行/汇总卡片（命中率、前缀变化、骤降、完全未命中）不动。
