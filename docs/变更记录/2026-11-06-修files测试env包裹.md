# 2026-11-06 修 files 测试的 env 包裹（既有失败）

## 是什么

`ts/apps/server/src/files.test.ts` 有两个用例**长期恒失败**（不是本次记忆改动引入，
2026-11-06 全量跑 258/259 时唯一红项就是它）：

- `open-explorer：未知项目 400；EXPLORER_OPEN=false 回 400 且不起进程`
- `FILE_BROWSE=false：两个 files 端点整体下线（404）`

## 为什么

测试自己的 helper 写错了，不是 `files.ts` 的行为问题：

```ts
// 改之前
function withEnv(key: string, value: string, run: () => void): void {
  process.env[key] = value;
  try { run(); } finally { /* 还原 */ }   // ← run() 返回 Promise，没人 await
}
```

两处调用都传了 `async () => { ... }`，`run()` 的 Promise 被丢掉，`finally` 在请求**发出前**
就把 env 还原了；而 `explorerEnabled()` / `filesEnabled()` 是每次请求现读 `process.env`
（`files.ts:38`），所以断言里的 400 / 404 永远等不到，实际恒为 200。

第二处更隐蔽：它甚至没报成用例失败，而是 `generated asynchronous activity after the test ended`
→ `unhandledRejection`，最后把**整个测试文件**标红（8 tests / 7 pass / 1 fail）。

## 改了什么

- `files.test.ts`：新增 `withEnvAsync(key, value, run: () => Promise<void>)`（`await run()` 真正包住）；
  两处调用改用它，并把请求挪进回调里；删掉已无调用点的同步版 `withEnv`（留着就会再被误用）。
- 两处都补了注释说明"开关是每请求现读 env 的"，避免以后有人又把请求写到回调外。

生产代码 `files.ts` **未改动**——它本来就是对的。

## 验证

- `npx tsx --test apps/server/src/files.test.ts` → **7/7 通过**（改之前 7 pass + 文件级 fail）。
- `pnpm typecheck` → 0 错。
- 服务端全量 `tsx --test apps/server/src/*.test.ts` → **271/271 通过**（改之前 258/259）。
- 页面无回归：Chromium 打开 `/`、`#/settings/{appearance,chats,service,partners,memory}`、`#/tasks`
  共 7 个路由，未捕获异常 0，各页 `data-route` 与分区渲染正常。
