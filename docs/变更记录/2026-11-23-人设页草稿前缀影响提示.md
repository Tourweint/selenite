# 2026-11-23 人设页草稿加「前缀 / 尾部」影响提示

## 改了什么

1. **底部保存条多一行影响提示**（`web/partner-profile.js` 的 `#pf-savebar-impact`）。
   有草稿时按当前脏字段分三组显示：
   - `会重建前缀`：保存后下次请求固定前缀（system + tools）会重算一次；
   - `只追加尾部`：只进本轮请求尾部的 `user` 消息，不动固定前缀；
   - `不进提示词`：名字 / 头像 / 结果整理这类改动不碰上下文。
   线条右侧按本次实际改动列名字（超过 2 项折成「等 N 项」），悬停 `data-tip` 给完整三组清单。
2. **「还没保存」三选一弹层加影响表**（`pfPromptLeave`）。在原来的「N 处改动没保存」下面
   用三行列本次草稿的去向（会重建固定前缀 / 只追加本轮尾部 / 不进提示词），
   并注明「前缀 = 系统提示词 + 工具定义；重建后下一次请求从头算一次缓存」。
   「保存并退出」按这张表生效，「不保存退出」仍是什么都不落库。
3. **顺手修正人设页内一条旧提示**。原先只有总管 SOUL 的输入/保存提示会说
   「在固定前缀里」，执事的提示按「走每轮尾部消息、不改前缀」处理；现在统一说
   「人设正文在固定前缀（系统提示词）里」，因为执事专线的 SOUL 走
   `renderPartnerIdentity` → `conversation.configure({ instructions })`，
   instructions 就是系统提示词（`partner-context.ts` 的注释也写明「SOUL 在 instructions 里」）。

口径来源：`agent/lifecycle-injections.ts`（`personaProvider` / `LIFECYCLE_MESSAGE_PROVIDERS`）、
`agent/partner-context.ts`（`partner_context` 走 message；SOUL 在 instructions）、
`partner-runtime-run-partner-turn.ts`（`alignPartnerSession` 用 `renderPartnerIdentity` 重配 instructions）、
`partner-persona.ts`（静态人格签名变更触发重配）。

**没有进这张表的**：工具勾选 / 偏好读取 / 口吻·里子·处境正文编辑。它们是点卡后立即保存的另一条路，
不归底部保存条管；其中工具勾选和偏好读取同样会改前缀，但这次只按用户口径处理「草稿」。

## 为什么改

用户口径：人设页会改上下文，有草稿时要在底部说明「上下文会变、前缀会变」；
现在只提示「N 处改动未保存」，返回时也一样；有些东西只是追加、有些会改前缀，要区分开，
可以列表说明；重点是底部保存和直接点返回两处。

## 明确没做

- 没有改后端注入通道、契约、存储或端点。
- 没有把工具勾选 / 偏好读取 / 技能开关混进草稿影响表（各自有独立入口与生效时机）。
- **总管主对话的行为没动**：代码里总管主对话只读 SOUL（lifecycle `persona` 段），
  口吻 / 里子 / 处境等模块只在群聊身份的 `renderPartnerIdentity` 里读。本批按这个现状，
  在总管页把模块改动标成「不影响主对话」；没有把它们补进总管主对话（那是独立缺口）。
- 聊天右侧抽屉的人设页（`settings-persona.js`）里同款旧提示「只有总管人设在固定前缀里」
  未在本批改动；它是另一页，等拍板再统一。
- 没有改总管页的人格模块实际注入行为（本次只做提示，模块是否该在总管主对话生效不在本批范围）。
