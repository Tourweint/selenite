# 悬停提示点击不弹（点击不再闪一下小黑块）

**日期**：2026-11-17。
**范围**：只动 `web/hover-tip.js` 的事件处理，不碰契约、不碰服务端、不改提示文案与延迟。

## 背景

用户反馈：鼠标悬停出解释性小黑块本身没问题，但**点击时它会冒出来一下**——
点击的目的是操作，不是读解释。左键、右键都有。

## 根因

提示有两条弹出路径：

1. `mouseover` → 等 450ms → 弹（悬停路径，符合预期）；
2. `focusin` → **立即**弹（键盘 Tab 可达路径）。

浏览器在 `mousedown` 的默认动作里给按钮聚焦，于是点击序列变成：
`pointerdown → mousedown → focusin（立即弹）→ mouseup → click（收起）`。
按住到松开之间提示就闪一下；点完指针还停在按钮上时，轻微挪动又会重新起 450ms 计时再弹一次。

## 改了什么

`web/hover-tip.js`：

- **`pointerdown`（capture）**：按下即收提示，并记下 `pressedAnchor`（按在哪个 `[data-tip]` 上）。
- **`focusin`**：`pointerdown` 后 600ms 内的焦点算「点出来的」，不弹；键盘 Tab 没有前置
  `pointerdown`，仍然立即弹（原有可达性不变）。
- **`pressedAnchor` 抑制**：指针离开按下的元素之前，该元素不再因悬停/挪动弹提示；
  移到别的提示元素不受影响。离开（`mouseout` 到外部、移出窗口）即解除。
- **`contextmenu`** 兜底再收一次（右键场景 pointerdown 已收，防个别路径只来 contextmenu）。

## 验证

浏览器（IAB，真页面 + 真模块）内按事件序列逐条断言，全过：

- 悬停 450ms 仍正常弹出；离开即收（原行为未回退）。
- `pointerdown` + 随后 `focusin`（模拟 mousedown 默认聚焦）→ 不弹；按住期间悬停 520ms → 仍不弹。
- 点完指针停在原地、`mouseover` 轻微挪动 → 不弹。
- 离开元素后再悬停 → 正常弹出（抑制解除，没有变成"永久不弹"）。
- 右键 `pointerdown(button=2)` + `contextmenu` + 悬停 → 不弹；移到另一个提示元素 → 正常弹。
- 无前置 `pointerdown` 的 `focusin`（键盘 Tab 路径）→ 仍然立即弹；`focusout` 收起。
- `node --check web/hover-tip.js` 通过。

## 没验证 / 已知边界

- IAB 页面不在前台时程序化 `.focus()` 不派发 focus 事件，因此「真实点击→浏览器默认聚焦」
  这一步在 IAB 里复现不出来；改用合成 `FocusEvent("focusin")` 覆盖同一处理分支。
  桌面壳（有真实焦点）里的最终观感未实机复核。
- 触屏点按同样会走 `pointerdown` 抑制：提示只在悬停或键盘聚焦时出现，点按不弹。
  本界面定位桌面端，未为此另做触屏提示路径。
