# 打开本地目录：窗口直弹顶层（接替已撤销的顶部提醒方案）

日期：2026-11-11
状态：已落地（typecheck ✅ / 745 单测 ✅ / 真端点端到端探针 ✅：拉起后 0.4s 窗口拿前台）

## 起因

用户口径（2026-11-11）：点项目「在资源管理器中打开」后窗口压在最底层"没有这个感觉"。
先做了界面顶部回执（见《2026-11-11-打开目录顶部提醒.md》），用户拍板体验还是不好——
**撤掉弹条，让资源管理器窗口本身弹到顶层**，另立此项。

## 为什么窗口会垫底（2026-11-11 实测）

服务是无窗口的后台进程，Windows 前台规则不给它"抢前台"的权限。实测（同机、GetForegroundWindow 轮询采样）：

- 裸 `spawn("explorer", [dir])`（原实现）：3.6s 内不拿前台；
- `Shell.Application` COM 裸开：也不拿前台；
- **COM 开窗 + 等到窗口句柄后 `SwitchToThisWindow(hwnd, true)`：拿前台，且连续 6 次采样稳定在前台；
  模拟服务端拉起后 1s 内完成，真端点探针 0.4s 完成。**

`SwitchToThisWindow` 是 user32 未文档化但长期稳定的 API（explorer 任务栏同款），配回滚开关兜底。

## 改了什么（仅 `ts/apps/server/src/files.ts` + 文档，零契约变化）

- `platformOpen`（win32 且 `EXPLORER_FOCUS` 非 false）走焦点式打开：
  1. 把内置 PowerShell 脚本写到 `%TEMP%\lifediary-open-focus.ps1`（内容纯 ASCII，用户路径经 argv 传入）；
  2. `spawn("powershell", ["-NoProfile","-NonInteractive","-ExecutionPolicy","Bypass","-File", <脚本>, "-Dir", <dir>])`；
  3. 脚本：COM `Open(dir)` → 按 `LocationURL` 轮询（≤3s）拿新窗口句柄 → `Add-Type` 编译 `SwitchToThisWindow` → 切前台。
  句柄 3s 没等到就放弃（窗口已开出，只是可能垫底，与旧行为一致）；脚本写盘失败也退回裸 spawn。
- mac / Linux 分支不变（`open` / `xdg-open`）。
- 回滚开关：`EXPLORER_FOCUS=false` → 完全回到旧形态（裸 spawn explorer）。已登记 `接口文档.md` §6。

## 踩到的两个 Windows 坑（都在同机二分定位，2026-11-11）

1. **`-EncodedCommand` 形态下 Shell COM 开不出窗口**：`-File` ± `-NonInteractive` 都正常，
   EncodedCommand 必挂（脚本跑完但一个窗口都没有）。所以放弃 EncodedCommand 改走 `-File` + 临时脚本文件，
   顺带把用户路径从脚本内容挪到 argv，绕开 PS 5.1 读无 BOM 文件的编码坑。
2. **`spawn` 不能带 `detached: true`**：DETACHED_PROCESS 下 PowerShell 没有控制台直接起不来
   （脚本一个字都不执行）；`windowsHide: true` 单独用完全正常，且已给子进程独立隐藏控制台，
   不会被服务端 Ctrl+C 连带杀掉。`child.unref()` 保留（服务端不等它）。

## 刻意没做 / 已知边界

- `SwitchToThisWindow` 未在非 Windows、老版本 Windows、 elevated 资源管理器（以管理员跑服务时 UIPI 可能拦）上验证——
  真遇到就 `EXPLORER_FOCUS=false` 退回旧形态，界面无回执的旧感知也一并回来（这是旧形态的已知边界，不是这次引入的）。
- 拉起耗时比裸 spawn 多 0.5~1.5s（PowerShell 冷启动 + Add-Type 编译），点击后窗口晚 ~1s 出现，换"必到前台"。
