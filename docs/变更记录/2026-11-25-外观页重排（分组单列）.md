# 2026-11-25 外观页重排（分组单列 + 修外溢）

对比稿与核对脚本在 `.box-agent-scratch/design/appearance-2026-11-25/`（scratch，不入库）。
四版可点对比稿里用户选定 A 版（分组单列）。

## 改了什么

只动四个前端文件，没动服务端、契约、`shared`、`localStorage` 键。

1. **`web/settings-router.js`**（外观分支）：一张「外观」大卡拆成五节，从上到下
   主题 → 颜色 → 文字 → 对话外观 → 工具展示。
   - 主题卡的行内标签「主题」去掉（和节标题重复），悬停提示挪到节标题上；
   - 「对话外观」节的卡里留两个槽位 `[data-wallpaper-slot]` / `[data-bubble-slot]`，中间一根分隔线；
     壁纸槽和分隔线默认 `hidden`，壁纸模块挂上才显示；
   - 去掉主题卡的 `wireDragScroll`（改网格后不出横滚）及其 import。
2. **`web/appearance-wallpaper.js`**、**`web/bubble-mode.js`**：不再自建 `<section>`、不再自己找位置插，
   改成把各自的内容渲染进槽位。卡片里的行、事件、状态读写、`mountSection()` 防重复挂载都原样保留。
   - 页面标记从 `#font-open` 换成槽位本身（`#font-open` 还在，只是不再兼任标记）；
   - 壁纸端点 404（`AGENT_APPEARANCE_WALLPAPER=0`）时：清空槽位、把槽和分隔线一起藏起来，回答两行照常显示。
3. **`web/style-23-appearance.css`**：
   - `.theme-cards`：flex 横滚 → `grid`，`repeat(3, minmax(0, 1fr))`；`.theme-card` 去掉 `flex: 1 0 160px`，加 `min-width: 0`；
   - `.wallpapers`：flex 横滚 → `grid`，`repeat(5, minmax(0, 1fr))`；`.wall-choice` 同上；
   - 新增一条媒体查询：`≤1120px` 时主题卡两列、壁纸 3 + 2。

## 为什么选 A

用户原话是「不同的修改都乱七八糟的，有的修改加在两个修改中间」。根因是三处各写各的：
壁纸节按「插到某某旁边」定位，工具详情那一行留在卡里，结果对话行为被排在字体后面、壁纸前面。
A 版给每类设置一个固定的节，不引入新的版式语言，卡片 / 行 / 分隔线 / 控件全部复用现有的。
D（最小改动）只解决错位、不解决归类；C（二级导航）成本高且「文字」「其他」两小节各只有一行；
B（双栏）要窗口约 1500 以上才是两栏。

## 两个外溢的修法

| | 改法 | 结果 |
|---|---|---|
| 六张主题卡一排放不下 | 改网格：每行 3 张，≤1120 两列 | 1440–720 七档窗口宽全部 0 外溢 |
| 壁纸五格一排放不下 | 改网格：五格平分，≤1120 折 3 + 2 | 同上 |

「改前」是把 11-15 的旧规则（`flex: 1 0 160px` + `overflow-x: auto`）注回同一个页面量的。

## 与任务书的两处出入（都是实测后改的）

1. **没有做「≤720 全部单列」。** 设置路由下应用侧栏不显示，窗口 720 时设置左栏也已不占位，内容区还有 692 宽。
   做了单列试过：每张主题卡 658 宽、六张叠起来，页高 1400 → 2050。所以 ≤1120 以下一律两列 / 3 + 2，没有更窄的档。
2. **「回答」没有单独的子标题。** 「对话外观」是一张卡：壁纸行 → 分隔线 → 气泡 / 气泡宽度两行，和用户选定的对比稿 A 一致
   （气泡两行自带标签，再加一行「回答」会变成三层标题）。要加的话是在 `bubble-mode.js` 的子块开头补一行。

## 回滚

**没有 env 开关。** 纯前端布局，env 到不了浏览器（口径同 `2026-11-25-插件卡内设置`）。
要退回只能把上面四个文件里「改了什么」列的那几处改回去。
注意 `settings-router.js` 和 `appearance-wallpaper.js` 里同时有别的会话未提交的改动
（界面显隐、`saveWallpaperState` 导出），不能整文件 `git checkout`。

## 发现但没动

- **旧实现的一个隐患（代码走查结论，没实测）**：壁纸功能关着时，旧 `syncWithServer` 是把整节从 `#settings-inner` 里
  `remove()` 掉；而本模块的 `MutationObserver` 正盯着这个容器的 childList，删完会再触发一次 `mountSection()` 重挂，
  然后再 404、再删。新实现不再往该容器删节点（只清空槽位），这条路径不存在了。
- **对比稿报告里「1280 窗口下外溢 296 / 126」量错了场景**：还原稿留着应用侧栏，按内容区 756 算的；
  真实的 1280 窗口内容区是 988，旧排法只外溢 64 / 0。已在 scratch 的 README 和报告里订正。
