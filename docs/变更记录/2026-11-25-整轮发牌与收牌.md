## 改了什么

### 展开：整轮发牌

1. **整轮所有组都发牌**（`createTurnWork().prepareOpen`）：点「工作 N 步」时把折叠条的
   位置交给**每一组**，不再只给首组锚点；排队号按整轮连号写（首组 0..n-1，下一组接着
   n 往下，24 号封顶）。后几组的牌从同一个折叠条依次飞回自己的格子，不再"闪出来"。
2. **行高从 0 长出来**（`animateRow`）：非首组收起时整条 `.tchips-wrap` 是 `hidden`，
   旧代码 `if (!from) return` 把"0 → 内容高"当成没变化直接跳过，于是后几组和下面的
   正文一起瞬移。现在允许 `from=0`，行高按 240ms 长开，主对话跟着平滑下移。
3. **发牌途中不裁行**（`.tchips-row.is-dealing { overflow: visible }`）：后几组的牌
   要越过中间的正文才落到自己那格，行还裁着就只看得见落地那一下。发牌结束（按本组
   最后一枚的排队号算）或中途收起时摘掉这个类，恢复裁剪。
4. **行高过渡先取消上一次**：收合/展开连点时旧动画还在跑，`getBoundingClientRect`
   量到的"目标高度"其实是旧动画的中间值（实测 0→18.5 而不是 0→24）。现在先量当前值、
   取消旧动画、再量自然目标高度。

### 收起：整轮收牌（同日晚追加）

5. **收起也按牌收回**（`playCollapse`）：点折叠条收起、或整轮收尾自动收起时，当前
   露着的牌按发牌的**反序**飞回折叠条（最后发出去的先收，`--ci` 由
   `turn.prepareCollapse` 按整轮逆序写）；时长 220ms + 16ms/枚，24 号封顶。
6. **两段式：先收牌，再收行**（`playCollapse` → `collapseAway`）：收牌期间布局完全不动
   （块还在原位飞，正文不挪）；收牌走到 **85%**（用户口径「80% 或 90% 的时候」，
   `turn.collapseDelay = (最慢一枚的 --ci × 16 + 220) × 0.85`，全组共用同一个时刻）时，
   所有组的行一起用 240ms 收起来，落定（`settleCollapse`）后才真正 `hidden`、把非首组
   整条 wrap 藏掉。85% 时缓动已把牌推到折叠条附近、近乎全透明，重叠看不出来，也不冷场。
   第一版是"收牌和收行同时跑"，用户真页面反馈正文先挪回来，和还在飞的牌叠字。
7. **收行期间禁止重排抢戏**（`collapsing` 旗标）：`collapseAway` 藏块会让灰块行尺寸变，
   触发 `ResizeObserver` → 又来一次"收起态排版"；旧代码在里面直接把非首组 wrap
   `hidden`，行高过渡被掐掉、正文"一瞬间上来了"（用户反馈）。现在收牌/收行期间
   任何重排只更新折叠条状态，真正隐藏只由 `settleCollapse` 做。
8. **收起时行不裁**（`.tchips-row.is-collapsing`）：牌要越过中间的正文飞回折叠条，
   裁着就只看得见消失那一下。
9. **间隙跟着行高一起收**（`collapseAway`）：flex 的 gap 与 wrap 下外边距只在
   `display:none` 那一刻才消失，光做行高的话正文会在落定时再跳 12px（真页面实测）。
   所以 `margin-bottom` 同步收到 `-(margin-top + gap)`，落定隐藏不产生二次跳动。
10. **不播收牌的两处**：历史回读（`everShown` 判据——打开旧会话从没露过块，直接收，
    不闪）；`prefers-reduced-motion: reduce`（直接到位）。
11. **展开/收起互切**：收牌途中再点开，`stopCollapse` 清掉计时器 / `collapse-out` /
    `is-collapsing` / 间隙动画，交给发牌重新铺开。

### 共用

12. **减少动态效果补漏**：`@media (prefers-reduced-motion: reduce)` 里的
    `.tchips.expand-in .tchip { animation: none }` 写在发牌规则**前面**，同特异性被
    盖掉了——减少动态效果时其实一直在播。文件后部补一段关掉（发牌与收牌都关）；
    JS 侧高度过渡与 `is-dealing` 也按 `prefers-reduced-motion` 跳过（这个文件原来
    没有这条判断）。

## 为什么

2026-11-25 用户真页面反馈四条：

- 一轮里「工作几步 → 说一句 → 再工作几步 → 再说」，点开「工作 N 步」时只有第一句话
  之前那组灰块有发牌动画，后几组直接闪出来；主对话往下移动也要有动画。
- 收起时也要按发牌的收牌收回去（不要整行瞬切）。
- 第一版收起是"收牌和收行同时跑"：牌还没飞完，正文就先挪回位置，压到牌上叠字。
  用户口径「先牌收完，然后正常对话框再动画回来」——改成两段式。
- 第二版两段式里，收行仍是一瞬间：`collapseAway` 藏块触发 `ResizeObserver`，
  紧接着的重排把非首组 wrap 直接 `hidden` 了，行高过渡没播出来。
  用户建议「收牌动画完成 80% 或 90% 的时候」开始往上，遂定为 85% + 重排护栏。

## 明确没做

- **「+N」翻页每批的排队号仍从 0 起**（`revealMore` 自己写 inline animation），
  没有接着整轮的发牌序号；一次翻页就是一批新牌。
- 历史回读（`toolFlowFromSteps`）不播入场、不播收牌：打开旧会话满屏块不动。
- 不改 `push` 时写在块上的 `--i`（展开途中新进的块仍就地浮现）。
- 收起只收到折叠条（首组 24px），不把折叠条本身也做缩放。
