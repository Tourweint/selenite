## 改了什么、为什么

1. **浏览器能力以"官方技能手册 + 现有 bash 工具"接入本机 ego lite（0.6.2.8）**。
   零服务端代码：agent 跑 `ego-browser.exe nodejs`（官方 CLI，Chromium 内部 IPC，不开端口），
   手册 = 官方 SKILL.md（`~/.agents/skills/ego-browser`，目录形态 frontmatter，读取链第 3 站原生识别）。
   实测（全过）：开 Space → goto → 语义快照（多语言正文齐）→ 跨进程按名续用 Space → screenshot 落盘。
   细节与备选对比（playwright-core 自研路线落选理由）见方案文档。
2. **生产服务开启该技能**：`PUT /api/v1/agent/skills/ego-browser/enabled` → 200（Bearer AGENT_TOKEN，
   token 未落任何输出）；`.data/skills-state.json` = `{"enabled":{"ego-browser":true}}`。
   `skill("ego-browser")` 立即生效；L1 索引随**下一个会话**出现（索引按会话冻结，D5 口径，接口 note 原文确认）。
3. **skills-probe 存量断言修复**：批 11（dc12c74）把内置手册 2 → 6 条后没人重跑探针，
   断言停在 `initialItems.length === 2`（本次 V3 回归时撞见，先于本次落地就存在）。
   改为按 `apps/server/skills/` 目录自同步（`BUILTIN_NAMES`），两处"两条"标签改"内置手册全部可见"。

## 落地偏差（与方案对照）

- **V2 结论比预想更好**：app 未运行时 CLI **自己把 ego lite 拉起来**——`Stop-Process` 杀净（0 进程）→
  跑 CLI → 脚本直通，且未手动启动的情况下 ego 进程自动涨到 10 个。方案里"没跑就先起 app 再重试一次"不需要；
  连接错误仅在指定不存在的 `--ego-server-name` 或安装损坏时出现（实测：`Failed to connect to ego_cli bootstrap`
  + Agent note 建议手动启动，文案对 agent 友好）。
- **设置页看不到该技能**：`~/.agents/skills/ego-browser` 是符号链接（→ `~/.local/share/ego/ego-skills`），
  管理列表按 path-guard 挡"指向外部的符号链接"（skills-api.ts:186 注释：内容可能是任意文件）——**有意设计**。
  agent 侧加载器无此闸（实测 `ego-indexed: true`，manual 1007 字节）。因此"设置页开启"落地为"API 开启"；
  日常回滚也走 API / 删 state 条目，不走界面。已随此差异在系统架构 §7 登记第四条边界。
- 启停接口的存在性检查（`findSkillInDir`，无 realpath 闸）与管理列表的守卫口径不同——现状够用
  （enabled 只写服务端 state，不写技能目录），随差异记下，统一口径另立项。
