# 2026-11-23 普通助手会话退役 + 派活工人（池）配置页

## 结论

普通助手（`chatKind=worker` 的普通会话）产品线退役：前端不再有任何新建入口，后端
`WORKER_CHAT_ENABLED` 默认改成关。本机唯一的工人配置入口换成
**设置 → 注入 → 人设 → 派活工人（池）**（`#/settings/partners/pool`）。

历史 worker 会话**不删**：照旧可读可续，身份不被重解释；删它们等于删用户聊天记录。

## 改了什么

### 1. 新建链路（前端）

| 入口 | 原来 | 现在 |
|---|---|---|
| 侧栏「任务」⋯ 菜单 | 新建任务 / 新建助手对话（Ctrl+K） | 只剩新建任务（Ctrl+K 也给它） |
| 会话区 ＋（`plus-menu`） | 新开 worker 会话 | 打开「新建任务」弹窗 |
| 会话卡右键（`rail-card`） | 新建对话 = worker | 新建任务 |
| 托盘 / 窗口菜单「新建」 | worker 会话 | 新建任务 |
| 深链 `?view=new` | worker 会话 | 新建任务 |
| 首屏空态第一条消息 | 建 worker 会话 | 建**总管**会话（`chatKind: chief`） |
| `startNewChat()` 缺省 | worker | chief；只保留「原会话没了按原身份重开」这条兜底给历史 worker 会话 |

### 2. 后端（只关生产线，不删历史数据）

- `plugins.json`：`WORKER_CHAT_ENABLED` 默认 `true → false`，卡片改「普通助手会话（已退役）」。
  语义不变：只拦新建，返回 `400 worker_chat_disabled`；已落盘的 worker 照常续话。
- `index.ts` 那条拦截的文案改成「已退役，新活走新建任务（派给池）」。
- 刻意**不删** worker 的运行时分支（人格 / 技能命名空间 / 工具面 / 记忆规则）：历史会话还要跑，
  删了就等于把旧会话打残。开关开回 `true` 可临时恢复旧入口。

### 3. 设置 → 注入 → 人设

- 列表置顶卡：**普通助手 → 派活工人（池）**（标签「本机派活共用」），点进
  `#/settings/partners/pool`；旧地址 `#/settings/partners/worker` 自动改写过去。
- 删除 `web/worker-profile.js`（旧页含「会话 / 技能覆盖」两段，随 worker 会话一起退役）。
- 新增 `web/pool-worker.js`，四段：
  1. **人设正文**：`GET/PUT /api/v1/agent/worker-persona`（池工人与外部 CLI 共用一份，下一单生效）；
     撤销 / 恢复默认（写空串 = 删文件回默认）/ 保存；带草稿离开确认。
  2. **工具**：`GET/PUT /api/v1/agent/worker-tools`，四件勾选进 ⋯ 弹层；上报 escalate 恒开只读。
  3. **模型与权限**：只读读 `GET /api/v1/agent/executor` 的 `profiles.pool.model`；权限「本机策略管」；
     点行跳「派活 → 执行器」；默认执行器不是池时如实标「新单暂不落池」。
  4. **上下文**：只读读 `context-defaults?role=dispatch-worker` 的九段（段名 + 字数），
     点行走「注入 → 上下文」看原文。
- 「关于我」页那行「普通 worker 固定不读」改成「派活工人（池）固定不读」。
- 上下文页的角色下拉：`普通 worker` 改标「普通 worker（已退役）」（仍保留，只为看历史会话）。

## 为什么不删 ChatKind 的 worker 值

`packages/shared` 的 `ChatKind` 是跨端契约（手机端/旧调用方），且历史会话的 kind 存在 durable
`lifediary.chat-kinds` 里。删掉枚举值 = 旧会话打不开、旧客户端直接报错。所以退役的是
**生产线与配置面**，不是枚举值。
