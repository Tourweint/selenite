# 变更记录 · 连接页直连画线与未登记凭据认领（2026-11-14 五次打磨）

> 方案：`docs/设计方案/2026-11-14-连接页直连画线与未登记凭据认领.md`。
> 用户原话：「有一个未知平距（按语境是「未知凭据」，语音输入错字），这应该是我的平板，它应该直接连接了我的电脑，所以图里应该画出它连的是电脑，而不是经过中继。你现在什么都没画，它是一个孤立的状态」「已经移除的平板自检可以删除」「你连接的设备为什么只有它，我这个手机有移除，别的没有移除」。

## 没做 / 没验证

- **`PAIR_ADOPT=false` 的回滚路径没实跑**（只做了代码级判断：端点 404、`unclaimed` 恒空）；跑它要另起进程，本轮没做。
- **平板真机没点过「认领」**：整条链路是用陌生令牌模拟的，真机上那枚令牌的哈希对不上任何记录这件事本身仍成立——它点认领之前，每个请求照样 403。
- **中继方向没动**，也没验证"经中继的设备"在星形上的实际观感（当前名册里那台是离线）。
- **没做设备级转发/接力控制**（见方案结论 6）：一台设备只能控制它连着的那个 harness；跨机只能靠中继矩阵派活。
- 手机端没改。

## 回滚

- 后端：`PAIR_ADOPT=false` 关掉认领与 `unclaimed`；要连"剪枝/幽灵过滤"一起退，删掉 `GET pair/devices` 里那两个 filter 即可（纯展示口径，不动数据）。
- 前端：`git checkout -- ts/apps/server/web/settings-connection.js web/approval-pop.js web/ui-atoms.js`。
- 数据：`removeDevice` 只动名册；`unclaimed` 是新增字段，删掉整个 key 即回到上一形态。
