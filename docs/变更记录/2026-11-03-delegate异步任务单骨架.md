# delegate 异步任务单骨架（P0）

- 日期：2026-11-03
- 范围：`ts/packages/shared/src/index.ts`、`ts/apps/server/src/delegation.ts`、
  `src/tools.ts`、`src/agent.ts`、`src/index.ts`、`src/openai-compat.ts`、
  `src/delegation.test.ts`（新）、`scripts/delegate-resume-probe.ts`、`package.json`
- 依据：`docs/设计方案/2026-11-03-宰相层（分管子代理）.md` §5.2 / §5.9

## 背景

2026-11-02 装上 `delegate` 之后有两个断点：

1. **领域负责人召不到**：工具从来没有把 `domain` 传给 `runChancellor`，
   助理只能走 v0.3 的"直接派 worker"路径，分管层等于没接上。
2. **派单占住对话**：工具 `await runChancellor(...)`，几分钟里主 agent 的这一轮
   一直不结束，用户既不能继续聊，也看不到进度以外的任何东西。

本次只做最小可用的 P0：打通 `domain`、把派单改成"立即受理 + 后台执行 + 完成后回灌"、
补齐事件字段。三个外部 CLI 适配、worktree 租约与合并、任务中心看板、上下文换段都**没做**。

## 决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | `delegate` 增加可选 `domain`，原样塞进 `ChancellorRequest.domain` | 分管路径已经实现，缺的只是这一句转发；不填仍走旧路径，不破坏现有调用 |
| 2 | 同步拿任务单号，不预生成、不改 chancellor 契约 | `runChancellor` 在第一次 `await` 之前就会发 `ticket` 或 `manager` 事件，两者都带 `ticketId` |
| 3 | 后台任务**不挂** `context.abortSignal` | 用户结束这一轮 / 客户端断开都不该杀掉已受理的活；旧同步路径仍保留原信号 |
| 4 | 完成后用 `sayInChat` 写一条 `pi.assistant` 回灌 | 它就是"助手主动说一句"的现成入口：不调模型，会话忙时 durable 自动排到本轮结束 |
| 5 | 事件补 `ticketId / domain / phase`，两套协议都透传 | 自有 SSE 与 OpenAI 兼容层（App 实际走这条）都要能让前端按单归并 |
| 6 | 两个回滚开关 | `DELEGATION_ASYNC=false` 回到 2026-11-02 的同步阻塞；`DELEGATION_AUTO_REPORT=false` 只发事件不写汇报 |
| 7 | 终态与「需要你」拆两帧 | 终态说"这单什么结果"，`attention` 说"它在等你什么"，前端才能分别出卡片 |

### 为什么 `startDelegation` 单独一层

发事件的是工具（`tools.ts`），收事件的是对话流（`agent.ts`），两者本来就互相引用。
把"受理 → 翻译 chancellor 事件 → 终态 / 汇报"放进 `delegation.ts` 后，
两边只依赖这个中间层，也不会成环。

## 改了什么

- `ts/packages/shared/src/index.ts`：`ChatEvent` 增加 `delegate`（含 `ticketId/domain/phase/done/total/current/message?`）
  与 `attention`（含 `ticketId/domain/kind/question`）；新增 `DelegationPhase` 八态。
- `src/delegation.ts`：新增 `DelegationReport`、`DelegationRuntime`、`DelegationKickoff`、
  `startDelegation`、`formatReport`；原有 `watchDelegation` / `emitDelegation` 保留。
- `src/tools.ts`：`delegate` 增加 `domain` 参数；改为调用 `startDelegation` 立即返回任务单；
  续跑被拒 / 无老单时改派新单；异步默认开，`DELEGATION_ASYNC=false` 保留旧同步路径与旧文案。
- `src/agent.ts`：`ChatStreamEvent` 的 `delegate` / `attention` 补新字段并透传；
  `createTools` 注入 `reportDelegation`；新增 `reportDelegationResult`（`harness.conversation` → `sayInChat`，
  失败只 `console.warn`）。
- `src/index.ts`：自有 SSE 不再丢弃 `delegate` / `attention`，按 `type` 原样下发。
- `src/openai-compat.ts`：`lifediary_delegate` / `lifediary_attention` 补 `ticketId/domain/phase`（含 `message`）。
- `src/delegation.test.ts`（新）：同步受理、终态 + attention + 汇报、续跑兜底、80 字截断、SSE 往返。
- `package.json`：`test` 纳入新测试文件。
- `scripts/delegate-resume-probe.ts`：固定 `DELEGATION_ASYNC=false`（该探针验路由，不验异步编排）；
  修正了两处与 2026-11-02 改动已不一致的断言（续跑成功时返回文案带说明、续跑拒绝发生在派活前）。


## 没验证到的

1. **真 chancellor + 真模型**：没有跑端到端派单（需要外部 CLI / 模型额度）。本次用假 `run` 覆盖了编排，
   真链路仍要靠后续 `chain` / `phone` 探针。
2. **"空闲起一轮汇报"的实际表现**：现在回灌是一条 `pi.assistant` 消息，**不调模型**。
   聊天端如果没有正在读的流，这条消息不会主动推送，需要 App 下次拉取或重新连接才能看到。
   真正"空闲时主动推一轮"要不要调模型 / 走推送，留给前端与下一阶段定。
3. **多张单并发**：事件已经带 `ticketId` 可归并，但同一会话同时派多张单时的顺序与节流没测。
4. **进程重启**：后台 Promise 不落库；重启后未完成的任务单只能靠 chancellor 自己的恢复，harness 不会重新接上。
5. **`openai-compat` 非流式**：仍然跳过这两类事件（行为不变），没验证非流式客户端。
