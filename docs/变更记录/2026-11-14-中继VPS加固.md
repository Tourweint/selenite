# 2026-11-14 中继 VPS 加固（SSH 入口、服务韧性、探活与日志）

> 一句话：把 `<VPS_IP>` 上这台中继机从"能跑"收拾成"能长期放着跑、且不该开的门都关上"，并把改动同步回仓库源码。

## 起因

用户把多设备那条线交给另一个会话，只留一句："你把这个 VPS 这一块弄好就行了。" 同一轮之前他还说过"密码你改吧，vps 安全性你需要保证""它时而连上时而连不上，把这处理一下"（原密码是 8 位常见词，明文不再记进仓库）。

登上去实测，发现四个真问题：

| 问题 | 实测证据 |
|---|---|
| 公网 SSH 用弱口令就能进 | `sshd -T`：`permitrootlogin yes`、`passwordauthentication yes`；`/root/.ssh/authorized_keys` 是 **0 字节空文件**（一台密钥都没装过）；root 密码是 8 位常见词 |
| 中继根路径每个探测都炸一次栈 | `/opt/lifediary-relay/www/index.html` 不存在 → `GET /` 抛 `ENOENT`，journal 里 18:00、18:28、19:07、20:38、20:55 各一条完整栈（也顺带把部署路径写进日志） |
| journal 无上限 | `journalctl --disk-usage` = **344 MB**，`journald.conf` 没写 `SystemMaxUse`（默认按 4G/10% 走，40G 盘迟早被日志吃掉一块） |
| 中继数据文件世界可读 | `.data/` 0755、`relay-state.json` 0644（里面有设备令牌的 sha256 与加入码哈希） |
| owner 令牌比较非常量时间 | `server.ts` 的 `isOwner` 用 `===` 比 `RELAY_OWNER_TOKEN` |

顺带排除了一个"假故障"：日志里那些 `bye → hello` 成对出现（20:00、20:39、20:41），时间点全部对得上**我在本机重启 harness**的几次，`relay/status` 的 `reconnects` 也是两次；不是链路抖动。真抖动要看 `lastCloseCode`（1006/1001 是中途网络掐断，4402 是握手超时，1013 是中继过载）。

## 改了什么

### 1. SSH：从"密码可进"改成"只认密钥"

| 项 | 之前 | 现在 |
|---|---|---|
| root 公钥登录 | 空 `authorized_keys` | 本机 `id_ed25519` 已装（101 字节，`/root/.ssh` 700、`authorized_keys` 600） |
| 密码登录 | `yes` | **`PasswordAuthentication no`** |
| root 登录方式 | `yes`（密码/密钥都行） | `PermitRootLogin prohibit-password`（只认密钥） |
| 键盘交互 | `no` | 保持 `no`（再加到 drop-in 里固定住） |
| 最大尝试 / 宽限期 / X11 | `6` / 默认 / `yes` | `3` / `30s` / `no` |
| 空闲探测 | 无 | `ClientAliveInterval 120` + `ClientAliveCountMax 2`（半死连接 4 分钟内回收） |
| root 密码 | 8 位常见词（口令强度不够） | **换成 28 位随机**，只写在 `/root/.root-password-20261114`（600，给云控制台救援用，不进日志、不回显） |

落点：`/etc/ssh/sshd_config.d/99-lifediary-hardening.conf`（`sshd_config` 第 12 行已经 `Include` 这个目录，先见优先，drop-in 稳赢）。原 `sshd_config` 备份在 `/root/sshd_config.bak-20261114`。

**做法上刻意绕开了"把自己锁在外面"**：先装公钥 → 用本机 `ssh -i` 实连一次确认 `KEY_OK` → 才动 sshd；改完 `sshd -t` 自检 → reload → **再连一次**；随后用只带密码的客户端做负向验证（`auth_none` 回 `allowed types: ['publickey']`，纯密码连接被拒）。中途第一版 reload 没让守护进程重读（密码仍能进），当场按"负向验证必须过"的标准判为不通过并回滚过一次，找到原因（需要 HUP 到 master）后重做。

### 2. 中继服务

- **`/healthz`**：`{ok:true, onlineDevices}`。公网 `GET http://<VPS_IP>:8084/healthz` → `200 {"ok":true,"onlineDevices":1}`。不含版本、不含令牌、不含设备信息。
- **`UMask=0077`**（2026-11-15 补）：`relay-state.json` 手工改成 600 后，服务下一次落盘会按默认 umask 重建成 **644**（实测 01:41 就被冲回去了）。unit 加 `UMask=0077` 之后重建也是 600（实测 01:43 `-rw------- relay relay`）。
- **`GET /` 与 `/app.js` 缺文件回 404**：`wwwFile` 改成"读不到就 null"，路由回 404 空体，不再抛 `ENOENT` 栈。公网实测 `root=404`（原来是 500）。
- **owner 令牌常量时间比较**：`isOwner` 改成长度先比 + `timingSafeEqual`，和 harness `auth.ts` 同口径。
- **unit 加固**（`/etc/systemd/system/lifediary-relay.service`，旧文件备份在 `/root/lifediary-relay.service.bak-20261114`）：
  - `Restart=on-failure` → **`Restart=always`**（正常退出也拉起来），`RestartSec=2`，并限定 `StartLimitIntervalSec=60` / `StartLimitBurst=10`（崩了别无限重启刷日志）；
  - 新增 `PrivateDevices`、`ProtectKernelTunables`、`ProtectKernelModules`、`ProtectControlGroups`、`RestrictSUIDSGID`、`SystemCallArchitectures=native`；原有的 `NoNewPrivileges / PrivateTmp / ProtectSystem=full / ProtectHome / RestrictAddressFamilies / MemoryMax=256M` 都保留。
- **数据文件**：`.data/` → 700，`relay-state.json` → 600（属主仍是 `relay:relay`，服务照常读写）。
- **日志**：`/etc/systemd/journald.conf.d/99-lifediary.conf` → `SystemMaxUse=200M`、`SystemMaxFileSize=50M`，并 `journalctl --vacuum-size=180M`，当前占用 344M → **168M**。

### 3. 源码同步

改的是**仓库里的** `ts/apps/relay/src/server.ts`，再整份推到 VPS（`/opt/lifediary-relay/src/server.ts`，旧文件留 `server.ts.bak-20261114-security`）。本地跑 `store.test.ts` + `hub.test.ts` = **18/18 通过**；推送前后两次重启都在 5 秒内恢复，主机按 4409/1006 语义自动重连（`reconnects` 加 1，`hello online=1`）。

## 明确没做（以及为什么）

- **没给 8084 上 TLS**。中继现在是 `http://`，`Authorization: Bearer` 明文过公网（手机侧同理）。要改就得有域名 + 证书（Let's Encrypt 不签 IP），并且 harness 客户端与手机端都要改信任链——这不是"收拾一下 VPS"能顺手做完的，硬上自签反而逼客户端关校验、比明文更糟。已记录为已知限制，下一步要么买域名上 Caddy，要么在中继层套一层应用级加密。
- **没动 22 端口的来源限制**。`ufw` 仍然 22/8084 全网放行；密码入口关掉后爆破面已经没了，fail2ban（sshd jail）继续兜底，再叠一层白名单会把"人在外面应急"也一起挡掉。
- **没碰机器上的其它服务**（另有几个与本中继无关的服务在跑），也没改安全组。
- **没有"时而连不上"的直接证据**。本轮日志里的断连都能对上我自己的重启；真要定位手机侧抖动，下一步看 harness `relay/status` 的 `lastCloseCode` 与手机端重连时间戳是否成对。

## 关掉密码后，其它电脑怎么进（以及怎么保证永远进得去）

关密码登录的目的是"服务别被公网爆破打挂"，不是"只让一台电脑能管"。进这台机器现在有三条路：

| 进路 | 谁用 | 怎么开 |
|---|---|---|
| ① 已有的那把密钥 | 这台电脑（`~/.ssh/id_ed25519`） | 已在 `authorized_keys` 里，`ssh root@<VPS_IP>` 直接进 |
| ② 再加一把密钥 | 第二台/第三台电脑 | 新电脑 `ssh-keygen -t ed25519` 生成 → 把 `id_ed25519.pub` 内容拿到任意一台能进的电脑 → `ssh root@<VPS_IP> "echo '<公钥>' >> /root/.ssh/authorized_keys"`。每台电脑各一把，撤销某台就删对应那一行 |
| ③ 临时开密码入口 | 新电脑还没配密钥、只想先进去一次 | 见下方命令；**用完必须关** |

**临时密码入口（要 98- 前缀，不能 99-）**：

```bash
# 开（10 分钟够用）
ssh root@<VPS_IP> "printf 'PasswordAuthentication yes\nPermitRootLogin yes\n' > /etc/ssh/sshd_config.d/98-temp-password.conf && systemctl reload ssh"
# 关
ssh root@<VPS_IP> "rm -f /etc/ssh/sshd_config.d/98-temp-password.conf && systemctl reload ssh"
```

前缀必须是 `98-`：sshd 对同一配置项**先见优先**，`99-lifediary-hardening.conf` 里已经写了 `PasswordAuthentication no` / `PermitRootLogin prohibit-password`，字典序在它后面的文件压不过它。

**最后一道兜底（不依赖 SSH 也不依赖这台电脑）**：阿里云控制台 → 实例 → 远程连接（VNC/Workbench），用 root 密码登录。这个随机密码在两处各存一份：VPS 上 `/root/.root-password-20261114`（600），以及**本机** `~/.ssh/<redacted-root-password-file>.txt`（仅当前用户可读写，不进仓库、不进日志）。之所以要在本机也留一份：如果哪天 `authorized_keys` 被写坏、所有密钥都进不去，VNC 登录本身也要密码，光存在 VPS 上等于鸡生蛋。

## 回滚

- SSH：`rm /etc/ssh/sshd_config.d/99-lifediary-hardening.conf && cp -p /root/sshd_config.bak-20261114 /etc/ssh/sshd_config && systemctl reload ssh`（root 密码文件仍留一份，回滚后可用密钥进，不必靠密码）。
- 中继代码：`cp -p /opt/lifediary-relay/src/server.ts.bak-20261114-security /opt/lifediary-relay/src/server.ts && systemctl restart lifediary-relay`。
- unit：`cp -p /root/lifediary-relay.service.bak-20261114 /etc/systemd/system/lifediary-relay.service && systemctl daemon-reload && systemctl restart lifediary-relay`。
- journal：删 `/etc/systemd/journald.conf.d/99-lifediary.conf` 后 `systemctl restart systemd-journald`。
- 数据权限：`chmod 755 /opt/lifediary-relay/.data && chmod 644 /opt/lifediary-relay/.data/relay-state.json`（服务以 `relay` 用户写，属主不用动）。
