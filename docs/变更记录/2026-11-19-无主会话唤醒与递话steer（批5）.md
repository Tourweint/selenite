# 无主会话唤醒 + 递话一律 steer（2026-11-19 批5）

承接四批主动性落地。用户 2026-11-19 拍板两条：
- "需要我派发的是两个 Docker 的会话。如果运行后台命令或者打开子智能体，肯定也需要被唤醒。"
- "执事之间传递话的时候，肯定是引导，它们全是引导。我觉得排队没什么用，我基本也不怎么用。"

## 改了什么

### A. 无主会话唤醒：谁起的命令/派的话唤醒谁

- **bgjob**（`delegation-wake.ts`）：`WakeEnvelope` 加可选 `targetConversationId`（内部会话 id，只进 `.data` 唤醒队列与进程内 Map，不进对外 API——对外 id 一律 uuid 的硬约束不受影响）。`wakeOnBgJobFinish` 解析不出执事归属时投会话目标；`guardWake` 返回 `{kind:"partner"|"session"}`，会话路径整批必须同会话、队列键一致、`targetPartnerId` 为空（防脏落盘串会话）；flush 会话路径复查会话存在后直接 `continueConversation`（不走 ensureSession/runTurn/忙退避，忙时天然跟随批1 缺省 steer）。链保险丝/失败重排保留；存在性检查抛错按"未知"重排，确认已删记 `target_gone` 清队列。
- **delegation**（批5-C，同形）：无主会话用 `delegate` 派活后原本只写一条 assistant 记录、不启动 run（真实缺口，批5 报告挖出）。现在同样兜底到会话路径，提示词沿用 `buildWakePrompt`；`DELEGATION_WAKE_ENABLED=false` 仍全局关派活唤醒（含会话路径——派活专属闸，与 bgjob 不同）。
- 开关：`BG_JOB_WAKE_SESSION`（默认开）/ `DELEGATION_WAKE_SESSION`（默认开），false → 逐字节回批3/批4 前行为。

### B. 执事递话一律 steer

- `partner-relay.ts` 新 `partnerRelayWhenBusy()`（`PARTNER_RELAY_STEER` 默认开）；`deliverPartnerRelay` 的 `whenBusy` 由硬编码 `"followUp"` 改读它。两态回执（queued/settled）零改动。
- **防乒乓闸核实（本批关键结论）**：成立，且 steer 不扩大空窗。`markRelayTarget` 在 `submit` 前；认领在 `beforeRequest`（内核每次模型请求前都跑）；steer 忙时进 inbox、下一边界（postTools 同 run 或 final 起新 run）落盘——两种情况下下一次 `beforeRequest` 都发生在模型看到递话正文之前，必认领并摘 `send_to_agent`。唯一空窗（submit 时已生成的工具调用仍执行）在 followUp 下同样存在，且 steer 因为常在 postTools 同 run 落盘反而更紧。

### C. 派活唤醒覆盖无主会话（批5-C，代理在 A 中挖出的真缺口）

- `wakeOnDelegationReport`：`DELEGATION_WAKE_ENABLED=false` 仍是总闸 → canonical 非 null 走原批29 路径（逐字节不变）→ canonical 为 null 且 `DELEGATION_WAKE_SESSION`（新开关，默认开）→ 投会话目标；`guardWake` 的旧 partner 形态在 canonical 消失时（排队期间链接被删/恢复的旧队列）也按同开关回落；canonical 存在但停用不回落。
- 核实结论：能派活的会话=普通 worker 对话 / 总管主对话 / 群会话 / 例行专线 / 副会话（都 canonical-null → 唤醒自己）；课题专线与任务专线（`task-<票号>`）没有 `delegate` 工具，不会产生派活汇报（修正批5 报告里"worker 任务对话会派活"的前提）。
- 新增单测 10 条（delegation-wake 共 40 条全绿）：无 canonical 走会话路径 / 有 canonical 回归 / 停用不回落 / 双开关回滚 / 落盘恢复 / 目标已删不炸 / 旧形态 flush 回落 / 混批两段提示词。

## 边界（如实）

- 会话路径用 `continueConversation`，其内部吞异常只 warn——模型轮失败时正文已 durable 落库、不重复投递（与 `runPartnerTurn` 的 ok/error 口径不同）。
- **会话路径起的是普通轮，不是 autonomy 标记轮**（与 escalation 的 `continueTurn` 同口径）——自主轮的扩权限制（如 `send_to_agent` 拦截）在这条唤醒轮里不生效；要保自主轮限制需另做机制（未做）。
- 递话忙时回执文案仍是"排在它本轮之后"（两态回执按"不变"口径未动），实际语义已是"插进下一边界"。
- 会话路径不查 `COMPANIONS_ENABLED`（不依赖执事体系）；`DELEGATION_WAKE_ENABLED` 只管 delegation 来源，bgjob 侧受 `BG_JOB_WAKE_SESSION` 管；两者都受 `WAKE_PIPELINE_V2` 管。
