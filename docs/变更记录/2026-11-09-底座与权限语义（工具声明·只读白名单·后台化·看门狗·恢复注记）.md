## 改了什么

### 1. 工具能力声明结构化（新文件 `src/tool-capability.ts` + 单测）

- 为 18 个已注册工具 + 预登记的 `ask_user` 各写一份 `ToolCapability`
  （`readOnly / destructive / sideEffectScope / riskLevel / needsApproval / concurrentSafe / notes`），
  导出 `TOOL_CAPABILITIES` / `capabilityOf()` / `declaredToolNames()`。
- **只登记、不接管**：`needsApproval()` 仍读老的 `WRITE_TOOLS` 与 `DEFAULT_CRITICAL_TOOLS`，
  `readOnlyBlockReason()` 同理，运行时判定零变化。文件头写清了"下一批再让闸门读声明"。
- `needsApproval` 的口径写在文件头：它是**该工具自身要求的审批下限**——
  `critical` = 进高危清单（`ask-critical` 也问）；`write` / `edit` 是 `never`，因为它们
  只在 `ask-all` 档被写类集合带出来，不是工具自己的下限。
- 一致性守卫（`tool-capability.test.ts`）：
  - 声明表 == 已知工具全集（新增工具漏登记 → 红）；
  - 实际 `createTools()` 注册的每个工具都有声明；
  - `destructive ⇔ WRITE_TOOLS`（双向）；
  - `{needsApproval !== "never"} == DEFAULT_CRITICAL_TOOLS`；
  - 只读工具不得是 `destructive` / `workspace` / `process`。

### 2. 只读白名单（新文件 `src/read-allowlist.ts` + 单测 + `lifecycle.ts` 一处判定）

- `isReadOnlyShellCommand(toolName, args, workspaceRoot, cwd)`：纯函数，可单测。
- 词表：`cat head tail grep rg ls dir type where file stat wc sort uniq find`；
  只对 `bash` / `powershell` 生效；必须设了工作区根，且每个路径 token 用
  `path-guard.ts` 的 `realTargetOf` + `insideOrEqual` 判在根内。
- 命令里出现 `| < > ; & $ % * ?` 反引号 / `()` / `!` / 换行 → 一律不放行；
  以 `~` 开头的 token（家目录展开）→ 不放行。
  （`~` 不在字符黑名单里：Windows 8.3 短路径 `TOURWE~1` 合法带这个字符，只在 token 层判。）
- 判定顺序：既有 `readOnlyBlockReason` → `pathGuard` → `loopGuard` → **本白名单** → 审批。
  代码上只把 `verdict.kind === "ask"` 改成 `allow`，且 `!risk.forceAsk`
  （**自主轮的强制问不被放宽**）。`block` 分支一个字没动。
- 开关 `AGENT_READ_ALLOWLIST`，**默认关**（这是放宽行为，先观望）。
- 单测：10 个正例 + 17 个反例（管道 / 重定向 / 分隔符 / 变量 / glob / 反引号 / 子 shell /
  越界绝对路径 / `..` / `~` / 写命令 / 未知命令）+ "只对 shell 工具、必须有工作区根"。

### 3. bash 超时转后台（新文件 `src/bash-background.ts` + 单测 + `lifecycle.ts` afterTool）

- **探针结论（先跑再写）**：`pnpm --filter @lifediary/server bash-timeout` 实测，
  内核 `bash.js` 超时后 `afterTool` 拿到的是 `isError: true`、
  `output` 文本 = `Command timed out after 1 seconds`（diagnostics 里也可带同一句）。
  所以识别只匹配这一句固定文案，不用宽泛的 "timeout"（避免把真错误转后台再跑一遍）。
- 命中后由服务端自己 `spawn(command, { shell:true, cwd, detached:true })` 重跑，
  输出写 `.data/bg-jobs/<id>.log`；`.data/bg-jobs/index.json`（原子写）记录
  `id / 命令摘要≤120字 / 起止 / 退出码 / 状态`，**完整命令只在 log 里**。
- 工具结果替换为「命令超过 N 秒仍在跑，已转到后台（任务 …），完成后会告诉你结果。
  别再重复执行同一条命令。」（`isError:false`，`structuredOutput.exitCode=-1` 表示"尚未结束"）。
- 任务结束时通过 `sayInConversation` 往会话补一条完成消息（退出码 + 日志尾部 ≤2000 字）；
  走新的一轮之外，不打断当前对话。
- 开关 `AGENT_BASH_BG_TIMEOUT`，**默认关**。
- 单测：超时识别三种形状 + 非超时不识别 + 真起进程（`node -e "setTimeout(...)"` 300ms）落 index。

### 4. stream_stalled 看门狗（新文件 `src/watchdog.ts` + 单测 + `index.ts` 收口函数）

- `StallWatchdog`：`note(conversationId, eventType)` / `finish(conversationId)` / `scan()`；
  时钟与定时器可注入，单测不睡觉。
- 落点 = `index.ts` 里 `POST /api/v1/agent/chat` 的 SSE 收口 `send()`：
  每帧 `note()`，流结束 `finish()`。30 秒扫一次。
- 超过 `AGENT_STALL_TIMEOUT_S`（默认 180）无事件 → 往 `.data/stall-audit.jsonl`
  追加一条 `{at, conversationId, elapsedMs, lastEvent}`（**不含任何对话内容**）；
  同一段卡死只记一条，下一个事件重置。
- **不改行为、不中断**：不 abort、不补帧、不通知模型。开关 `AGENT_STALL_AUDIT` 默认 true。
- 单测：两分钟无事件 → 一条；继续卡着不刷屏；有事件后重新计时；`finish` 后不记。

### 5. 恢复注记：先查后动（新文件 `src/agent/recover-note.ts` + 单测 + 两个调用点）

- 固定文案 `RECOVER_NOTE`（<300 字）："你刚从一次中断里恢复。**先查再动**……"。
- 记账：进程内 `Map<会话, 待注入次数>`（与 `resumeCount` 同族，**不新建存储**）；
  `takeRecoverNote()` 取一次即核销 → 每张单最多注入一次。
- 两个标记点：
  1. `delegate` 工具带 `resume:true`（在 `afterTool` 里认，`tools.ts` 零改动）；
  2. 启动时 `recoverDelegations` 返回的 `still_running`（自动续跑）单，经回执表映射到会话。
- 注入点：`beforeRequest` 拼一条 system 消息（每次模型请求都会走，标记后第一次生效）。
- 开关 `AGENT_RECOVER_NOTE` 默认 true（不改行为，只是多一段提示）。

## 已知边界

1. **只读白名单的词表是 Unix 口径**。PowerShell 的 `Get-Content` 之类不会命中（照常问），
   只有 `cat` / `ls` 这种能在 PowerShell 里跑的别名才降噪。这是刻意的保守。
2. **白名单不放宽自主轮**：例行轮里 `bash` 一律仍按 `risk.forceAsk` 问。想让它也降噪，
   需要单独方案（那是在放宽安全边界，不属于本批）。
3. **后台任务没有生命周期管理**：不列表、不 kill、不重启续跑；`index.json` 只追加不清理
   （`bg-jobs/` 会慢慢变大，日志按需人工清）。任务只在本次进程内被回调通知；进程重启后
   正在跑的后台进程仍在，但完成消息不会再回灌。
4. **看门狗只覆盖 `/chat` 这条 SSE**。编辑重发（`/edit`）没有客户端流，不跟踪；
   中继通道的流也不跟踪。
5. **恢复注记的启动路径依赖回执映射**：`still_running` 单若没有 `conversation_id` 回执
   （`DELEGATION_MAP_PERSIST=false` 或老单），标不到会话 → 不注入。durable 自身的
   `harness.resume()` 没有暴露"恢复了哪些会话"的入口，本批不去猜。
6. **能力声明尚未成为事实源**：改声明不会改变任何闸门行为（本批就是"登记"）。
   下一批切到声明驱动时，`WRITE_TOOLS` / `DEFAULT_CRITICAL_TOOLS` 才是要退役的那份。
7. **恢复注记带有效期外的"下一次请求"口径**：启动自动续跑打的标记，会落在该会话
   **下一次**模型请求上；如果用户先发了一句无关的话，那句也会带上注记（一次性的，
   只多一段提示、不改行为）。刻意不做超时过期——那要引入新状态，与"不新建存储"冲突。
8. 真模型手验未做（归派单人）。
