## 修了什么、为什么

1. **群 @ 按钮是死按钮**（web）：`#group-at-btn` 只进了 el 表，没绑 click。
   现在点击把 `@` 打到光标处并走 `updateGroupAtPop()` 弹候选——与手输 @ 同一条路径；
   光标前已有半截 @ 就不重复插，只弹候选。

2. **成功派活被谎报「N 步失败」**（web）：delegate 进度帧也进了工作过程块的 open 队列，
   但派活的终态帧经常晚于本轮收尾（chancellor 比轮活得久），`finish()` 把没等到结果的
   行判成失败。改成 `WorkBlock.track()`：派活行**不进** open 队列，按 ticketId 一单一行，
   终态帧（done/needs_you/aborted/failed）显式 `close`，轮收尾还没终态的画 `back`
   （中空点 = 已转后台，不算失败也不算成功）。

3. **抽屉切模型静默重置思考档**（web）：抽屉调 `chooseModel(..., null, ...)`，
   `clampThinking(level, null)` 恒回 `"off"`——每切一次模型思考档就被清掉。
   现在选项构建时把 `normalizeModelRow` 的支持域落在 `option.dataset`，切换时随行走；
   支持域未知（模型不在清单）就**不动**本地档，宁可保留也不静默清。

4. **插话竞态丢回答**（shared + agent + web）：客户端以为忙时发插话，但服务端刚好收尾，
   这句补充就成了**新的一轮**——而插话那条短连接按约定只收回执、不画正文，
   新一轮的回答没有任何连接在画，刷新前永远不上屏。
   修法：notice 帧加机器可读 `steer: "inserted" | "new-turn"`（契约 §2.1），
   客户端只认标记不猜文案；`new-turn` 时安排回读——轮询 transcript 尾条从 user 变
   assistant（轮落盘）后全量回读一次补屏。顺带修了回执本身会丢的问题：
   原来读到 `start` 帧就断流，而回执在 `start` 之后才 yield，几乎必然不在同一
   chunk——改成读到 notice 为止（64 帧上限防失联挂死）。
