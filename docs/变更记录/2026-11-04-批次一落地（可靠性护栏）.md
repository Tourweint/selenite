## 改了什么

### 1. A3a：回执表加会话列

- `ts/apps/server/src/delegation-receipts.ts`
  - 构造时 `PRAGMA table_info` 检查 `conversation_id`，缺列就 `ALTER TABLE ... ADD COLUMN conversation_id INTEGER`
    （对旧 `.data/delegations.sqlite` 安全）。旧行永远是 NULL，**A3b 无法回填**（代码注释已写明）。
  - 建 `idx_delegation_receipts_ticket` 索引。
  - `DelegationReceipt` 加 `conversationId: number | null`；`accept(requestId, ticketId, conversationId?)`
    用 `!== undefined` 判断（不是 truthy，防 id=0）。
  - `lookupByTicket()`：`ORDER BY updated_at DESC, rowid DESC LIMIT 1`；标 `@internal` + "A3b 专用，当前无生产调用方"。
  - 回滚开关 `DELEGATION_MAP_PERSIST`：默认落库，`false` 时不写会话列；**每次 accept 现读 env**，不缓存。
- `ts/apps/server/src/tools.ts`：两处 `accept` 调用点（立即受理与 outcome 后补）都传 `conversationId`。
- 幂等语义（`begin` / `lookup` / `markFailed` / `reinsert`）零改动。

### 2. A4：settings 显式化 + bash 默认超时

- 新建 `ts/apps/server/src/reliability.ts`（无副作用纯函数；不 import agent.ts）：
  `buildHarnessSettings(env)`、`bashTimeoutSeconds(env)`、`reliabilitySummary(env)`。
  - env 全空 → 返回 `undefined`，`Harness.open` 干脆不传 settings。
  - `AGENT_STREAM_TIMEOUT_MS`（正整数）→ `stream.timeoutMs`；`AGENT_AFTER_FAILED_RUN`
    （`keep|continue|withdraw`）→ `afterFailedRun`；其余旋钮吃内核默认（注释引 `agent.js:41-61` 默认值表）。
  - `AGENT_BASH_TIMEOUT_S` 默认 900；`0` 或非法值 = 0 = 不做默认超时。
- `ts/apps/server/src/agent.ts`
  - `Harness.open` options 加 `...(settings ? { settings } : {})`；启动打一行实际解析值。
  - 用现有 `lifediaryExt` 的 `beforeTool`：模型没传 `timeout` 时返回 `{ arguments: { ...a, timeout } }`；
    内核会拿新参数重新校验。`timeout=0` 不注入（内核 `validateTimeout` 对 `<=0` 抛错）。
- `ts/apps/server/.env.example`：补 `AGENT_STREAM_TIMEOUT_MS` / `AGENT_AFTER_FAILED_RUN` /
  `AGENT_BASH_TIMEOUT_S` / `MEMORY_CANDIDATE_FLOOR` / `DELEGATION_MAP_PERSIST` 五项。

## 与图纸的偏差

1. **bash 注入分支不提前 return**：图纸给的片段在注入处直接 `return { arguments }`，照抄会跳过同一钩子后面的
   `emitPhase` / `emitTool` / `switchThinkingOnTool`（工具状态条与思考档切换全丢）。实现改成先算 `injected`，
   跑完事件与切档后在钩子末尾统一返回，注入语义不变。
2. **selftest 用例的 limit**：图纸要求 `limit ≥ 120`，但候选窗口是 `max(limit*5, floor)`，120*5=600 会把 floor=50/200
   完全盖住，用例必然假通过（实测 floor=50 也含最老记录）。改为 `limit=20`（20*5=100，正好落在 50 与 200 之间），
   并让老记录靠关键词排到第 1 避免被 `slice` 切掉；墙钟断言不变。
3. 图纸说 `reliability.ts` 只列了两个函数，实现多了 `reliabilitySummary()`（启动日志复用同一套解析，避免解析逻辑写两份）。
