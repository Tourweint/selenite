# 多 CLI 打手适配与执行器设置（2026-11-16）

## 改了什么

任务中心原来只能派给 CodeBuddy / Qoder 国际 / Qoder 国内，由 `CHANCELLOR_EMPLOYEE` 一个
全局 env 在进程启动时冻结。本批加三档外接 CLI，并把"派给谁、用什么模型 / 权限"搬进桌面端。

### chancellor（外部仓库）

- `src/types.ts`：`EmployeeKind` 加 `claude-code` / `codex` / `opencode`；
  新增 `EmployeeProfile`（`model?` + `permission?: read|edit|full`）；
  `TicketOptions.employeeProfile`、`ChancellorRequest.employee` / `.employeeProfile`。
- 新增 `src/employee/claude.ts`：
  - `-p [prompt] --output-format json --permission-mode plan|acceptEdits | --dangerously-skip-permissions
    [--model m] [--resume id]`；短提示进 argv、长提示走 stdin；
  - 复用 `type=result` 解析；与 CodeBuddy/Qoder 只差一条——不要求 `result` 非空
    （Claude 干完活最后一句可能只写文件，交付物仍看 `REPORT.md`），`is_error` / `permission_denials` 照样判失败。
- 新增 `src/employee/codex.ts`：
  - `exec [resume] --json --skip-git-repo-check [-m m] -s read-only|workspace-write|danger-full-access
    -c approval_policy="never" [id] [prompt|-]`；
  - 解析 JSONL：`thread.started.thread_id` 拿会话号、`turn.completed` 判完成、
    `turn.failed` / `type=error` / `item.type=error` 判失败；兼容未来 `method/params` 形态。
- 新增 `src/employee/opencode.ts`：
  - `run --standalone --format json [-m provider/model] [--session id] [--agent plan|--auto] [prompt]`；
  - 解析 JSONL：`type=text` 收文本与 `sessionID`、`type=error` / `part.type=error` 判失败。
    **实测退出码 0 也可能带 error 事件**（模型不可用），不能只看退出码。
  - `--standalone` 必需：默认后台常驻服务的目录是它第一次启动的地方，会把产物写进宿主目录。
- `src/employee/cli.ts`：
  - 新增 `resolveCliLauncher`：Windows 上把 npm `.cmd` shim 解成真实 `.exe` / `.js`
    （Claude → `claude.exe`，OpenCode → `opencode.exe`，Codex → `node .../codex.js`）；
  - `runCliProcess` 加 `interpret` 钩子（Codex / OpenCode 的 JSONL 判定）；
  - spawn 时把 `PWD` 对齐 `call.cwd`。**OpenCode 2.1.1 按继承的 `PWD` 认工作目录，不认 spawn 的 cwd**
    （冒烟实测：产物写进 `ts/apps/server`）。这条对所有外部 CLI 都生效。
- `src/employee/index.ts`：新工厂 + 能力声明（三者都 `resumeWithSession: true`）+ 新 kind 导出。
- `src/dispatch.ts` / `src/scheduler.ts` / `src/index.ts`：按单传 `employeeKind` + `employeeProfile`；
  新单落 `ticket.options.employeeProfile`，续跑 / 崩溃恢复按快照走。
- `src/employee/manager.ts`：分管路径把执行器与 profile 写进 manager 子进程 env，子单继承。
- `src/config.ts`：三档 `*_BIN` / `*_MODEL` / `*_PERMISSION`；`readEmployee` 白名单扩三档；
  `defaultProfileFor` / `resolveProfile` / `profileEnv`。
- `src/employee/codebuddy.ts` / `qoder.ts`：模型改从 `task.settings.model` 读（空 = 回 env 默认）。

### harness

- 新增 `src/executor-config.ts`：`.data/executor.json`（`EXECUTOR_CONFIG_PATH` 可换），
  形状 `{employee, profiles:{kind:{model?,permission?}}}`；每次派单懒读（mtime+size 缓存）；
  文件不存在 / `EXECUTOR_CONFIG=false` 时回落 env。非法值在 `parseExecutorInput` 拦下。
- 新增 `src/executor-mount.ts` + `index.ts` 挂载：
  - `GET /api/v1/agent/executor`：当前执行器 + 各档 profile + 控件元数据 + 锁定原因；

- `src/delegation-start-delegation.ts`：`launch()` 每次懒读执行器设置，把 `employee` +
  `employeeProfile` 放进 `ChancellorRequest`；续跑时 chancellor 按原单快照走，不会被改派。
- 前端：
  - 新增 `web/settings-executor.js` + `SETTINGS_SECTIONS` 的「派活」分区 +
    `settings-router.js` 分支；
  - 页面：当前执行器下拉 + 每个可选 CLI 一张卡（模型输入 + 权限三档 / 固定说明）+ 保存；
    phone / mcp 由 `.env` 指定时只读并说明；
  - Claude Code 卡片写明订阅套餐约 1.8–2.9 倍额度、API Key 不受影响、交互式桥本批不做；
  - `web/tasks-model.js` / `web/tasks-redesign.js`：新执行器标签与打手卡（Claude / Codex / OpenCode）。
- `.env.example`：补三档 bin/model/permission、`EXECUTOR_CONFIG` / `EXECUTOR_CONFIG_PATH`；
  顺手把误写的 `CHANCELLOR_RUNS_DIR` 改成代码真正读的 `CHANCELLOR_WORK_ROOT`。
- 文档：`接口文档.md` §6 env 表补执行器相关行、`CHANCELLOR_WORK_ROOT` 默认值按代码校正；
  `接口-端点7` 新增 §2.23；`系统架构.md` 新增 D25 与「刻意没有」条目；
  方案 `docs/设计方案/2026-11-16-多CLI打手适配与执行器设置.md`。

## 为什么

- 用户点名要 Codex CLI / Claude Code CLI / OpenCode CLI（PI CLI 本机没有，不凭空适配），
  并要求桌面端能选模型、最好也能选权限。
- 参考项目 `agent-autoloop` 的适配器契约（`command(turn)` + `read(stdout)`）和
  magpie 的 Claude 订阅桥调查：`claude -p` 在订阅登录下按 `sdk-cli` 计费，社区实测约
  1.8–2.9 倍；交互式 TUI 桥能省额度，但工程量约一个独立子项目。本批按用户"非交互够用"的口径
  只做非交互，边界写在设置页与文档里。

## 回滚

- 执行器界面层：`EXECUTOR_CONFIG=false/0/off` → 不读 `.data/executor.json`，执行器与模型/权限
  一律按 `.env`，一行回到本批之前形态。
- 单档退回：`CHANCELLOR_EMPLOYEE=codebuddy`（或 native）仍生效。
- 新适配器没有独立的"关闭开关"：不选它就不启用；chancellor 里新增的 kind 不影响旧 kind 的分支。

## 已知边界 / 不确定

- Claude 订阅套餐下 `-p` 的额度倍率来自社区实测与 magpie 注释，不是 Anthropic 官方文档；
  官方 2026-06-15 曾公告拆分计费但随后暂停，2026-10-07 口径仍是走订阅额度。用 API Key 时无此问题。
- Codex 的事件名按 0.163.0 的 `type` 形态实现，同时兼容 `method/params`；未真跑（未登录）。
- OpenCode 的 `--agent plan` 是否在只读档完全拒写，未单独验证（本批只验证了 full）；
  `edit` 与 `full` 在 OpenCode 上映射相同（都 `--auto`），这是它 CLI 的边界。
- 任务中心新增三张打手卡后是 7 行手风琴；没做"按使用频率收起/排序"。
