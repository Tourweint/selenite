# 对话设置收口 + 工作履历并入记忆

用户原话：

- "工作履历在哪啊？员工档案在哪啊？是不是对话栏右上角的设置，也就是会话设置，对吧？"
- "工作履历可能要进入记忆这一栏了，员工档案也要跟记忆合并一下。"
- "现在右上角总管的那些设置，这里就不要改总管的东西了。可以弄一个超链接，直接链接到改人设那个页面。"
- "总管就是比较简单的一些设置，只保留简单的设置就行，就是对话设置里头吧。"

## 先回答"在哪"

**是，右上角那个齿轮就是「对话设置」。** 改之前，工作履历和员工档案都在这个抽屉里的一张「档案 · 只读」卡：

```text
对话设置
├─ 总管（点头像/名字 → 抽屉内人设页）
├─ 模型
├─ 权限
├─ 档案 · 只读
│   ├─ 工作履历   N 条
│   ├─ 记忆       N 条
│   ├─ 例行规则   N 条
│   └─ 技能       N 个
└─ 全部设置
```

工作履历是 `agent/memory` 里 `kind=work` 的派单结算记录；员工档案是同一批 `partners` 数据的只读汇总页。不是两套实体，也不是两套接口。

## 改成了什么

### 1. 对话设置只留简单设置

现在抽屉首页：

```text
对话设置
├─ 总管 / 记账助手 …  人设 vN · 去人设页改   →
├─ 模型
├─ 权限
└─ 全部设置
```

- 身份块不再是"在这里改人设"，改成**跳转链接**：点它关闭抽屉，直接去
  `#/settings/partners/<id>`，也就是「设置 → 人设 → 改人设」那一页。
- 「档案 · 只读」整张卡撤掉，不再在对话设置里看履历 / 记忆 / 例行 / 技能。
- 员工档案页不再挂入口；它的内容按下面拆开。

### 2. 工作履历进记忆页

`设置 → 记忆` 切到某个同事后，记忆分组下面多一条折叠：

```text
工作履历  3   派单结算 · 只读
  11-08  给周报配数据来源
         终态=canceled · 作废：来源缺失…
  11-07  整理跟进事项清单并按负责人分组
         终态=done · ✓ 1/1 过。产物：followups.md
```

- 只对 `partner:<id>` scope 显示；「我的记忆（global）」不显示，因为 `recordWorkSettlement`
  只给执事落履历，总管没有派单履历。
- 读的是 `GET /api/v1/agent/memory?scope=partner:<id>&kind=work&limit=200`，没有新端点。
- 只读，没有删除 / 忽略 / 应用动作；和记忆本体分开，不混进 `N 条记忆` 的计数。
- 行内容拆成「任务标题 + 终态/产物」两行，去掉 `work:demo-…` 这类机器前缀。

### 3. 员工档案的四个分段去了哪

| 原分段 | 现在在哪 |
|---|---|
| 工作履历 | 记忆页 →「工作履历」折叠 |
| 记忆 | 记忆页本体（本来就在） |
| 例行规则 | 人设页 →「能力」→ 例行任务（本来就在） |
| 技能 | 人设页 →「能力」→ 技能（本来就在） |

所以不再单独维护一个"员工档案"页；同一份数据不摆第二个入口。`settings-employee.js`
保留为数据助手（读取与行渲染），旧的一页四分段代码还在，但界面不再挂入口。

## 接口与口径

- 范围清单 `GET /api/v1/agent/memory/scopes` 的 `count` 仍然**排除 work**：页签上的
  `记账助手 0` 是"记忆 0 条"，下面的工作履历另算 `3 条`，两个数不混。
- 工作履历仍是 `kind=work`，来源 `source=work`，只增不改；整理记忆不会把它当普通记忆合并。
- 人设页的「能力」仍用 `GET /routines?partnerId=` 与 `GET /partners/:id/skills`，没有搬家接口。
- 对话设置的身份跳转对总管和执事都走 `#/settings/partners/<id>`；普通助手会话（worker）没有角色，照旧不显示身份块。

## 验证

- 总管对话：右上角齿轮 → 只剩身份跳转、模型、权限、全部设置；点身份块落到 `#/settings/partners/chief`，抽屉关闭。
- 记账助手对话：同样只剩简单设置；点身份块落到记账助手的人设页。
- 记忆页：默认「我的记忆」不出现工作履历；切到纪要员出现「工作履历 3」，展开是三条两行式履历；切到阅读助手显示 `0` 与空态。
- `node --check` 通过：`memory-page.js`、`settings-drawer.js`、`settings-employee.js`。
- 页面控制台 0 条报错。
