# 外部导入区撤回 + 记忆分组默认收起（2026-11-15）

同日早些时候落了「项目记忆与外部导入区」（见 `2026-11-15-项目记忆与外部导入区.md`，未提交）。
用户在记忆页复核后提了三件事，全部当日处置：

## 改了什么

1. **外部导入区整体撤回**（用户拍板：「外部导入的记忆已经导入了进来，就算咱们自己的记忆」）：
   - 服务端：`GET /agent/memory` 的 `veracity=imported` 跨 scope 视图与响应 `bySource` 删除
     （`session-index.ts` memoryOverview + `memory-api.ts` 参数解析）；
     `GET /agent/memory/scopes` 不再下发伪 scope `__imported__`（kind:"external"）。
   - 前端：`memory-page.js` 删按来源分节的 `renderExternalGroups` / `EXTERNAL_SOURCE_LABEL`、
     `__imported__` 伪 scope 分支、「外部导入」tab 徽章；老服务端若仍下发该伪 tab，前端直接滤掉。
   - 保留：导入功能本身（右上「导入」按钮 + 三来源白名单 + 文件导入）不动；条目落库照旧记
     `veracity="imported"`、`source=import:<sourceId>`，记忆页条目来源标「导入」照旧。
2. **记忆分组全部默认收起**：`MEMORY_A_DEFAULT_OPEN` 从 `{preference, intention}` 改为空集；
   页面只显示分组头与计数，展开才按需拉正文。搜索命中仍会展开命中分组（原行为不动）。
3. **顺手修掉「收起再展开显示读不到记忆」**：根因是外部导入区的组是整包渲染（不走
   `loadMemoryGroup` 的分页装载），`loaded` 永远是 false——收起再展开时走了
   `loadMemoryGroup("src:<sourceId>")`，拿不是记忆类型的 kind 去调真接口，服务端 400，
   分组体就渲染成「读不到记忆：…」。撤区后该路径整体消失，普通 kind 分组不受影响
   （它们展开即装载、装载成功置 loaded）。

## 为什么撤

导入的记忆本来就是落在 global / 项目 scope 的普通记录（kind ∈ fact/preference/entity/episode），
照常参与召回（召回链路从不按 veracity 过滤，2026-11-15 核对）；单独一个查看区反而让人
分不清「这些是不是自己的、用不用」。撤区后它们就在「我的记忆」的普通分组里，带「导入」来源标。
