# 2026-11-21 思考强度换填充滑块

**改了什么**

composer 模型菜单底栏的思考强度从一排分段按钮（关/低/中/高）换成**填充滑块**（用户从三版对比页
挑定 B 版，"发牌"批的对比页同一份临时服务）。`web/hover-tip.js` 的 `thinkingFoot` 重写 +
`web/style-12-drawer.css` 加 `.think-slider` 族样式；`web/shell.js` 的 `syncThinkingSegments`
改为给滑块发 `think-sync` 事件（`/mode` 被 clamp 改写实际档时滑块跟回服务端说的那一档）。

- 轨道等分到**当前模型的支持档**上：换模型重开菜单自动重画（只支持 关/高 的模型退化成双态）；
- 点轨道 / 拖旋钮均可吸附，**拖动过程只画不发包、松手才提交一次**（`chooseCurrentThinking`
  原链路：localStorage + `/mode`）；拖动挂 `.is-dragging` 关过渡跟手；
- 已选段 `scaleX` 填满 + 右侧大字报当前档（compositor 变换不碰布局，用户担心的"卡"防在这里）；
- 键盘可操作（role=slider，方向键跳档提交）；
- 设置页默认模型卡的分段行保持不变（同族控件两种摆位；要换同款滑动块说一声）。

**为什么**：用户口径「底下的思考强度的块儿太丑了……人家都用滑动块，咱们也用滑动块吧；
先选模型，底下滑动块再变化，从低到高，或者开或关」。三版对比（A 刻度 / B 填充 / C 分段）用户选 B，
附言担心"有点卡"——已用轻量手段规避：动效只落在 14px 旋钮与 4px 填充条上（transform/compositor）、
拖动期无过渡直跟手、发包只在松手一次。

**验证**（2026-11-21，隔离实例 + fetch 桩 + IAB）：typecheck 绿。faux 的目录投影没有可切模型，
用 fetch 桩注入富目录（四档 + 两档模型）验前端全链路：菜单底栏滑块按模型支持域渲染（四档/两档）；
初值取目录回的档；拖拽吸附（0.55 处松手 → 中，fill scaleX 2/3）；**提交恰好一次**
（POST /mode ["medium"]，localStorage medium + thinkingTouched=1）；键盘左键退一档；/mode 被
clamp 改写时 think-sync 跟回。真机手感等服务重启后菜单里直接试。

**回滚**：revert 本批（thinkingFoot 恢复分段按钮即可；`.think-seg/.think-opt` 样式保留未删，
设置页还在用）。

**明确不做**：设置页默认模型卡的分段也换滑块（用户没点名，要换说一声）；拖动中途实时发包
（拖一发一，避免请求风暴）。
