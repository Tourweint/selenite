# 变更记录：2026-11-12 搜索独立成页（一个输入 · 按对话分组去重）

> 上位：用户连续两轮否掉前两版——"感觉还是两个搜索""一搜能搜出同一个人说的两句话来""太潦草了"。
> 终态：**独立搜索页 `#/search`**。一个输入框，标题和原文一起搜；结果**按对话分组**，
> 同一段话只出现一次；点片段跳回原会话定位到那一句。范围：`web/index.html` +
> `web/app.js` + `web/style.css` + 接口文档 §2.5/环境变量表。**零契约改动**。

## 为什么前两版不行（根因）

1. **"两个搜索"**：界面把结果排成上下两组——「标题/首句命中」和「正文命中」。
   两个组长得一样、都叫命中，用户只能理解成"两个搜索"。
2. **同一句出现两遍**：会话标题默认就是第一条用户消息。搜"你好"时，
   标题组出一条「你好，先起个头 1 轮」，正文组又出一条「你好，先起个头 · 时间」——
   同一条消息被画了两次。不是数据重复，是**渲染重复**。
3. **空间不够**：搜索结果塞在设置页的卡片行里，一条命中一行、没有分组，
   稍微多几条就像流水账，"太潦草"是必然的。

## 终态长什么样

- 入口：侧栏「对话」区头的放大镜（常驻）+ 设置 → 会话 →「搜索旧对话 / 打开搜索」。
  设置页**不再有输入框**——全应用只有一个搜索。
- 页面：`#/search`，一个 48px 输入框（进页自动聚焦）+ 说明；结果区 720px 宽。
- 结果 = **一条对话一张卡**：
  - **改过名的会话**：组头显示标题（命中词高亮）+「N 处命中 · 时间」，下面是最多 3 条命中片段，
    点哪条回原会话定位到哪句；多于 3 条显示「还有 N 处」就地展开；
  - **没改过名的会话**（标题默认取第一条用户消息）：标题和某条命中是同一句话，
    再当组头就是在重复正文——这类组不显示标题：单条命中直接一行结果，多条命中先给一行
    「N 处命中 · 时间」计数（不可点），**每一处命中各自可点定位**。
- 标题命中（本地可见会话）与正文命中（服务端全量）按 `conversationId` **合并成同一张卡**；
  只在标题里命中的会话补一条「标题命中 · N 轮」，不会和正文行重复。
- 空态/单字/无结果都有话说："再输一个字就能搜原文。""没有找到。换个词试试。"

## 刻意没做

- **筛选 / 排序 / 搜索历史**：先把"一处搜、点得到"做对，别又堆一排没人用的开关。
- **跨对话去重**：同一句话出现在两条不同对话里是两条独立记录（例如同一句问候进了两个会话），
  按对话分组后它们本来就在不同的卡里，不算重复；不合并。
- **搜索页里编辑 / 继续聊**：点片段只负责"回到当时那句"，接着做什么在原会话里做。
- **放宽 365 天窗口**：端点 `days` 上限仍是 365（§2.5），所以页面如实写"最近一年"，
  没有假装搜了全部历史；要放宽属于契约改动，另立项。

## 已知边界

- 原文检索默认窗口 = 最近 365 天；更早的内容要点底部「搜索更早的历史」（见下方 11-13 追记）。
- 标题筛只覆盖侧栏可见会话；已归档会话只能靠正文命中被搜出来（标题里独有的词搜不到它）。
- 正文结果不带"我 / Selenite"角色（`/sessions/search` 不返回 role）；片段本身一般能看出谁说的。
- 同毫秒的 user/assistant 消息按 `at` 定位会取第一条；概率极低，不为它改契约。
- 2026-11-12 当天先后出现过的三个形态（设置页内嵌搜索 / 记忆页「旧事」/ 合并成设置页一个搜索）
  都已退役，以本件终态为准；前两件的变更记录已按"未落地即改写"处理，不留在库里当历史。

## 追记（2026-11-13）：分页与历史窗口

用户口径：默认一年，「查看更多」放到底部；会话多了要不要翻页由我考虑。

- **接口**（契约变更，已下沉 §2.5，方案见 `docs/设计方案/2026-11-13-搜索分页与历史窗口.md`）：
  `days` 上限 365 → 36500（默认仍 30，工具不受影响）；新增 `offset`（0–1000000，默认 0）；
  响应新增 `total`（未分页命中总数，同一次扫描算出）；`hits` 形状不变。
- **页面**：默认 `days=365`、单页 20；底部「查看更多（还有 N 处）」按 `offset` 追加并重新分组，
  「搜索更早的历史（一年以前）」改 `days=36500` 从第一页重来，扩过后显示「已搜索全部历史」；
  换查询词窗口回一年、`offset` 归零。1 个字、空态、无结果状态不受影响。
- **旧服务端降级**：响应没有 `total`（服务还没重启）时，底部只显示
  「服务端是旧版本：重启服务后才能查看更多、搜更早的历史」，不摆点了没用的按钮。
- **可扩展性**：分页不改扫描代价（每页重扫全部会话）；不引入缓存（失效规则比省下的时间贵）。
  FTS 的触发条件写死在方案里：>500 个会话或单次搜索 >500ms 时立项。
- **验证**：`session-search.test.ts` 11 条全绿（新增时间窗、offset/total、越界空页、
  parse 参数、工具侧形状分离）；页面用 `fetch` mock（45 条命中）验过
  「已显示 20/45」→ 查看更多（offset=20、40 行、还有 5 处）→ 更早的历史（days=36500、回第一页、已搜索全部历史）；
  `node --check` + `pnpm typecheck` 通过。
- **未验**：真实服务端进程（桌面壳拉起的非 watch 进程，本批未重启），重启后需复跑一次真实响应。
