# 2026-11-23 分区头悬停「一整条」：头 + 行尾 ⋯ 收进同一条底

## 用户口径

「侧边栏展开时，鼠标放在任务上，不会包括右边那三个点」；
「鼠标放在任务上时，会有淡淡变亮的背景……你把这一整条做出来，应该包括右边的小三个点。包括之后，三个点也应该显示」；
「鼠标放在三个小点上时，那个浮起的块到底要不要显示？你看看吧」。

## 先记一笔改错的地方

第一版把「任务」当成了**会话行**（`.chat`），只改了会话行的右内边距和三个点的自带底。
用户回「没有任何用，正常刷新都能看到」——刷新是有效的，是我改错了元素。
用户指的是**分区头那一行**（执事 / 任务 / 项目 / 群组的标题行），不是列表里的会话行。

## 问题

`.side-sec` 是一行两格网格（`grid-template-columns: 1fr auto`）：

| 元素 | 位置 | 悬停时 |
|---|---|---|
| `.side-sec-head`（图标 + 名称 + 计数） | 第一格 `1fr`，实测 10→194px | 自己画一层 `--card` 底 |
| `.sec-more`（行尾 ⋯） | 第二格 `auto`，实测 194→218px | 自己画一层 `--card-high` 底 |

所以头一 hover，底只铺到 194 就断成一条直角边；⋯ 落在裸侧栏上；
指到 ⋯ 时头那层底又消失、换成 ⋯ 自己的方块——两块来回切，就是用户说的「浮起来的小方块」。

## 改法

| 文件 | 改动 |
|---|---|
| `index.html` | 四个分区的 `<section>` 里，把头按钮与 ⋯ 包进 `<div class="side-sec-top">`（ID / class / 事件绑定全部不动） |
| `style-03-sidebar-zones.css` | 新增 `.side-sec-top`（`grid-column: 1 / -1`、flex、`r-md`）；底改铺在整条上；`.side-sec-head` 改为 `flex: 1 1 auto` 并去掉自己的 hover 底；`.sec-more` 去掉 hover 底，只换色 |
| 同上 | `:has()` 让「指到头」和「指到 ⋯」都点亮同一条：`.side-sec-top:has(> .side-sec-head:hover:not(:disabled))` / `:has(> .sec-more:hover:not(:disabled))` |

判断：**那块浮起的小方块不再显示**。整条底已经表示「你在这条上」，⋯ 再叠一层等于同一状态画两个块；
点它是否有反应，靠颜色（行悬停 `text-2` → `text`，指到点上 → `accent`，菜单开着也是 `accent`）。

## 验证（无头 Chrome + CDP，1440×900 实拉 39847）

| 量 | 结果 |
|---|---|
| `.side-sec-top` | x 10→222，高 36 |
| `.side-sec-head` | x 10→194（仍在第一段） |
| `.sec-more` | x 194→218（落在整条里，右侧留 4px） |
| 指到头 | `top` 底 = `rgb(246,241,231)`；⋯ 底透明 |
| 指到 ⋯ | `top` 底仍是 `rgb(246,241,231)`；⋯ 底透明、字色 `rgb(62,74,140)`（accent） |
| 截图 | 头悬停 / ⋯ 悬停各一张，均是一条 10→222 的圆角块，⋯ 在块内、不再有独立方块 |

行为未变：点头 = 开合分区，点 ⋯ = 弹「新建 / 搜索 / 打开任务中心」那一套菜单。

## 没做 / 边界

- 群组分区的头与 ⋯ 都是 `disabled`：`:has(... :not(:disabled))` 兜住，不给底、不亮 ⋯。
- 会话行 / 项目行 / 执事行各有各的入口图标，本批只动分区头这一种。
- 收起轨道（rail）里的分区按钮是另一套结构，不涉及。
- 第一版改的会话行样式（`padding: 8px 12px`、⋯ 不落底）保留：它同样属于「一行一块」，与本条不冲突。
