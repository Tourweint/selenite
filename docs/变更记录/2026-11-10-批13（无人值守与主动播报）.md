任务书：`docs/设计方案/2026-11-10-批13任务书（CodeBuddy·无人值守与主动播报）.md`

## 一、改了什么

### 1. 无人值守权限语义（七 #17）

- 新增 `src/unattended.ts`：
  - `isUnattended(conversationId)` —— 例行轮 / 自主轮 / `task-` 会话 / `AGENT_UNATTENDED=1` 四源合一。
    例行轮标记独立于 `AUTONOMY_ENABLED`（那个总闸默认关，但例行任务照常跑）；`task-` 会话在
    `agent/session.ts` 打开时登记内部 id（`isUnattended` 是同步判定，durable 映射是异步的）。
  - `resolveUnattendedVerdict(tool, capability)` —— 三态 `allow` / `skip` / `deny`：
    纯读与只写内部状态放行；写盘 / 起进程 / 派活 / 要审批 / 提问一律 skip；
    `partner_manage` / `group_manage` / `routine_manage` / `send_to_agent` / 删除类 deny。
  - 进程内跳过账：`noteUnattendedSkip` / `takeUnattendedSkips`（只记工具名，取走即清）。
- `agent/lifecycle.ts` 的 beforeTool **在一切审批判定之前**接入三态分支：
  deny → 显式拒绝；skip → 回 `UNATTENDED_SKIP_MESSAGE`、工具不执行；allow → 执行且**不再走审批**
  （含自定义 `AGENT_APPROVAL_CRITICAL_TOOLS`；黑名单 / 只读档这类显式 block 仍优先）。
  **绝不落 pending 等人**——这是本批最核心的一条，单测按"需要审批的工具不可能 allow"钉死。
- 开关 `AGENT_UNATTENDED_POLICY` 默认 **false**：关着时整块不执行，行为与改动前逐字节一致。

### 2. 跳过花钱步 + 明说（七 #28）

- `UNATTENDED_SKIP_MESSAGE`（固定话术，任务书 §二.1 逐字）：告诉模型继续做不花钱的部分，
  并在结果里写明跳过了什么、为什么。
- `partner-runtime.ts`：每轮开头清跳过账、收尾取走，`PartnerTurnResult.skipped` 带出工具名枚举。
- `RoutineRunRecord` 新增 `skipped` / `skipReason`（`unattended:bash,write` 这种枚举串，不记参数与正文）；
  `outcome` 在跳过过步骤时记 `skipped`。

### 3. agent → 用户中途播报（七 #18）

- 新增 `src/progress-report.ts` + `report_progress` 工具：`{message ≤200 字}`，**不结束本轮**。
- 送达：`emitDelegation(当前会话, {type:"notice", text:"【进度】…"})`，`agent/session.ts` 把这条
  翻译成既有 `notice` 帧；当前会话正好是任务专线时，`task-conversation.ts` 再镜像一条。
  **不落盘，没开流就收不到**（不伪造主人的时间线）。
- 频率闸：同一会话每轮最多 3 条（run 键与 relay / turn-gate 同口径），第 4 条起回
  "合并成一条再说"的引导话术（不是错误）。
- 上架范围：执事轮 / 任务专线；主人（总管）对话与群会话由 lifecycle 结构性拦下。
- `tool-capability.ts` 登记 `report_progress`（`sideEffectScope:"none"`, `riskLevel:"low"`,
  `destructive:false`）；**不进 `WRITE_TOOLS`**。一致性守卫单测与 arch-guard 白名单已同步。
- 开关 `AGENT_PROGRESS_REPORT` 默认 **true**；false → 工具不注册（启动时冻结）。

### 4. 例行任务条件门控（七 #19）

- 新增 `src/routine-conditions.ts`（纯逻辑，可单测）：
  - `buildRoutinePrompt`：上一轮结局 + 规则正文 + 完成条件（顺序固定）；`ROUTINE_CONDITIONAL=false`
    时原样返回正文（逐字节回滚）。
  - `extractRoutineDone`：认 `[[routine-done]]` 并从产出里剔除（标记不写进摘要）。
  - `routineRunVerdict`：结局（`success|quiet|skipped|failed|done`）与是否停表。
- `RoutineDef` 新增可选 `until?: {note}` / `maxRuns?: number`；`partners.sqlite` 的 routines 表
  新增 `until_note` / `max_runs` 两列（旧库 `ALTER TABLE` 补 nullable 列，老规则读出 undefined）。
- `routines.ts`：runOnce 组装提示词、写 `outcome` / `skipped` / `skipReason`；until 达成或跑满
  `maxRuns` → `enabled=false`（不删规则，revision+1 让在飞闹钟作废）；`lastOutcomeOf` 把上一次
  结局带给下一次触发；手动 `run_now` 也记 outcome / skipped，但不计入 maxRuns。
- `routine_manage` 工具 create 新增可选 `untilNote`（≤200 字）/ `maxRuns`（1..1000 的整数）。
- 开关 `ROUTINE_CONDITIONAL` 默认 **true**；false → until / maxRuns / outcome 全部忽略。

## 二、装配点

- `agent/lifecycle.ts` beforeTool 顺序变为：回合上限 → **无人值守三态** → **播报上架范围** →
  `ask_user` 挂起 → 自主轮结构性拒绝 → 递话通道闸 → 读档 / 自主轮风险 / 审批 → pathGuard → loopGuard。
  无人值守分支前移的原因：它必须挡住 `ask_user` 与 async 审批——两者都会让"没人看着"的轮次停住。
- `tools.ts` createTools：`deps.progressReport === true` 才注册 `report_progress`（照
  `routineSelfService` 的条件注册先例）。

## 四、已知边界

- **`isUnattended` 的 task- 判定是进程内的**：会话必须在本进程打开过（能跑工具的轮次必然满足）。
  进程重启后、durable 自动续跑的极端场景下，若没走 `openChat`，`task-` 判定会暂时失效；
  例行轮另有独立标记兜底，`AGENT_UNATTENDED=1` 可一键覆盖。
- **无人值守 allow 会跳过自主轮强制 ask**：这是"绝不挂起"的直接后果。allow 集合已限制为
  纯读 / 只写内部状态 / 本身不要审批 / 不在自主轮风险表里的工具；`set_reminder` 因在风险表里
  被归为 skip，不是 allow。
- **判定按当前能力声明 + 自主轮风险表**，不读审批档的运行时覆盖（`AGENT_APPROVAL_CRITICAL_TOOLS`
  的自定义清单不改变三态）；口径是"这一步本身要不要人点头"，不是"这一档现在问不问"。
- **until 的"达成"靠模型自觉**：宿主只认 `[[routine-done]]` 标记，不解析条件文本，也不做表达式引擎；
  模型不写标记就不会停（maxRuns 是确定性兜底）。
- **"置为 done"= `enabled=false` + run.outcome="done"**：`RoutineDef` 没有新增 done 状态列
  （任务书只要求两个可选字段），界面上与手动停用不可区分；历史 run 记录保留。
- **HTTP 例行端点（§2.12）本批不接 until/maxRuns**：只有 `routine_manage` 工具能设置；
  `GET /routines` 的 projection 也暂不透出这两个字段（避免在没写契约的情况下悄悄改响应）。
- **`report_progress` 只在执事轮/任务专线**：任务专线本身 `tools: []`，所以实际上产路径是执事会话；
  专线镜像分支保留给"以后给专线装工具"的形态，当前不可达。工具注册是**全局**的（一张
  extension 装全部会话），所以主人对话里模型仍可能在工具清单里看到它；调用会被 beforeTool
  拦下并回一句"这个会话不需要中途播报"。要做到"清单里也不出现"需要按会话拆工具集（架构改动），
  本批不做。
- 播报的每轮计数在进程内存，重启即清零；没有开流时 notice 本来就收不到，不存在补发。
- 跳过原因只记工具名枚举；不记参数、不记正文、不进日志正文。
