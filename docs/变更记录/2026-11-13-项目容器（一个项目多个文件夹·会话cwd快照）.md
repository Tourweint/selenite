# 项目容器（一个项目多个文件夹 · 会话 cwd 快照）

日期：2026-11-13
状态：已落地（服务端 + 桌面端 web；手机端只保证字段纯增量，未改 UI）。

## 起因

用户口径（2026-11-13，原话要点）：

- 「咱们现在只能设置一个工作区的根目录，以及其他的目录，也就是子项目吧，它啥都可以干的。
  咱们不应该这样，子项目应该有项目名称，然后可以添加多个文件夹」。
- 「如果我们用我的这个智能体进行一些开发任务呢？那不就可能会分不清路嘛」——
  一个项目拆在几个仓库/目录里时，助手要知道"这是同一个项目的哪几个文件夹"。
- 「侧边栏也需要改」「主要是前端的主题统一一点就行」「主要还是得用按钮，不能直勾勾的」。

方案：`docs/设计方案/2026-11-13-项目容器（一个项目多个文件夹）.md`；
原型第二版（Paper token）：`docs/设计方案/原型/15-项目容器-侧栏与设置.html`。

## 改了什么

### 数据（`ts/apps/server/src/projects.ts`）

- 新增 `ProjectRoot{id,projectId,label,path,role:"primary"|"extra",vcs,head,createdAt}`；
  `Project` 增必填 `roots: ProjectRoot[]`；`ProjectRef` 增**可选** `roots`（纯增量）。
- 新表 `project_roots`（`path_norm` 小写+正斜杠归一键，`UNIQUE INDEX idx_root_path` 保证
  一个文件夹只属于一个项目；`position` 排序）。`project_proposals` 加 `folders TEXT`。
- 启动时 `migrate()`：旧库（只有 `projects.root_path`）给每个项目补一条 `primary`
  根（`label=目录名`、路径取原 `root_path`），幂等。
- `projectFromRow` 降级为 `Omit<Project,"roots">`，所有返回点统一走 `toProject`——
  以 `primary` 覆盖顶层 `rootPath/vcs/head`，老调用方（手机端、delegate）零改动。
- 新方法：`rootsOf / addRoot / updateRootPath / renameRoot / promoteRoot / removeRoot /
  resolveRootLabel / uniqueRootLabel / assertRootPathAllowed`。
  `assertRootPathAllowed` 拦：等于/包含工作区根、与任意项目任意根同路径或互相包含。
  错误码 `duplicate_root` / `duplicate_label` / `root_is_primary` / `last_root` / `bad_path`。
- `proposeProject(name, path, folders)` 复核 folders（绝对、已存在、互不重叠）写进 proposal；
  `confirmProposal` 校验后先插 projects 再插根，失败回滚（删 `project_roots` + 删 `projects`）。
- `workspaceRootsReal` 改为遍历所有项目所有根的并集（工作区外项目/多根都算进来）。

### 契约（`ts/apps/server/src/index.ts` / `src/files.ts`）

- `GET /projects`：每项带 `roots[{...root, exists, insideWorkspace}]`，响应新增 `currentProjectId`。
- `POST /projects`：接受 `primaryPath`（优先于 `path`）与 `folders`。
- 新增 `POST /projects/:id/roots`、`PATCH /projects/:id/roots/:rootId`、
  `POST /projects/:id/roots/:rootId/promote`、`DELETE /projects/:id/roots/:rootId`。
- `files.ts`：`rootFor` 支持 `rootId`（`root_not_found` / `root_missing`）；
  `open-explorer` 接受 `rootId` 直达某个文件夹。

### 会话 cwd（`agent/shared.ts` / `session.ts` / `lifecycle.ts` / `lifecycle-injections.ts`）

- `openChat` 建 `worker` 会话时，在 `init` 事务里 `configure(tx, conversationId, {cwd: projectRoot})`，
  把当时的项目主文件夹钉进 durable 的 `pi.agent.cwd`。`chief` 暂不绑（留可调口）。
- `sessionCwd()` 优先级改为：会话快照（内存 `sessionCwds` 命中且目录还在）→ 全局当前项目主文件夹
  → `AGENT_WORKDIR`；新增 `sessionBoundCwd()` 只回答"这个会话有没有自己的快照"。
- `lifecycle.ts` 的 `env` 工厂从 `({conversationId}) => new NodeExecutionEnv({cwd: sessionCwd()})`
  改为接收 `cwd`，命中就 `noteSessionCwd` 回填；全文件 5 处 `sessionCwd()` 带上 `api.conversationId`
  （path-guard 主闸门、只读 shell 判定、worldState×2、审批复判、bash 后台搬运）。
- `currentProjectProvider` 改为多根口径：输出「当前项目：名（N 个文件夹）」+「主文件夹」+
  （若快照≠主文件夹）「本会话的工作目录（创建时快照）」+ 每个根的 `label（主）/ 路径`，
  并提醒"相对路径以主文件夹为基准、多个文件夹可能有同名文件，动手前先看路径"。

### 前端（`web/app.js` / `web/style.css`）

- 设置 → 项目：项目卡改成"标题行（项目名 + N 个文件夹 · vcs + 添加文件夹/改名/归档项目）"
  + 文件夹行（dot + label(+主) + 等宽路径 + 动作按钮）。行内动作**全部是按钮**
  （`.ghost.is-mini`，26px）：主行只有「改路径」，附加行「改路径/设为主/移除」。
- 「改路径」把该行路径就地换成 `input` + 「保存/取消」；「移除」走统一确认框；
  「添加文件夹」走弹窗（路径 + 可选显示名，桌面壳下带「选择」）。
- 侧栏：工作区不再占「项目」分区的一行（它只服务杂事态，位置在设置页第一块，卡里写明
  "它不是项目"）。项目行 = `div.side-item.proj-row.is-project` + `role=button` +
  `aria-current`（选中）+ 文件夹数徽标 + `▾`（文件夹清单浮卡）+ `＋`（在这个项目里新开对话）。
- 新增 `selectProject`（`PUT /workspaces/current-project`，成功重绘 + 刷新会话列表）、
  `newChatInProject`（先选中再 `startNewChat("worker")`）。
- 文件夹清单浮卡改挂 `document.body` + `position:fixed`：侧栏每个分区都被
  `.side-sec-clip` 的 `overflow:hidden` 裁着（折叠动画必需），留在行内会被整块裁掉。
  点外面 / Esc / 滚动 / 改尺寸都关，同一时刻只开一张。
- `openExplorerInOs` / `openFileBrowser` 支持 `rootId`；收起轨道的弹层同步撤掉工作区行、
  项目行加「N 个文件夹」tag。
- CSS 只吃现有 token（`--surface` / `--composer-border` / `--r-sm` / `--accent` / `--mono` /
  `--shadow-menu`），强调色只出现在：主文件夹实心点、选中项目行、主按钮。

## 刻意没做

- **`GET /agent/chats` 没加 `projectId/projectName`**：方案里列为契约变化，但界面不需要
  （会话归属已由 `lifediary.chat-projects` 承接）；留给真正要"按项目分组会话"的那一批。
- **`chief` 会话不绑项目 cwd**：总管本来就跨项目，绑定会误导；留作可调参数。
- **不做 `@别名` 指向附加文件夹**：用户明确否掉，多根只影响"能去哪儿"，不做符号替换。
- **手机端 UI 不动**：`ProjectsApi.kt` 只读 `name/rootPath/exists`，这批字段纯增量，
  `rootPath` 仍是主文件夹。
- **没有把附加文件夹做成"子项目"**：语义上一个项目就是一个整体，附加文件夹是它的组成部分，
  不是一个独立可派活的对象。
