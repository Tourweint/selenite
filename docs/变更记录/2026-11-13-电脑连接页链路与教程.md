# 2026-11-13 电脑端「连接」页：链路图 + 两条路 + 中继挂载教程

## 背景

用户 2026-11-13：「电脑连接页面也做一下吧，现在看着不太舒服，你把它改得好看一点」「这里还有较多解释性文字」
「我也不清楚这个中继，电脑是怎么挂载的，对吧？你再弄一下这块」。

原页面（`设置 → 连接`）的问题：

- 只有一节「连接手机」，二维码 + 一长串原始 URL 挤在一起，URL 没人念得出来；
- 「经中继添加设备」行下面挂着一整句说明（10 分钟有效 / 只能用一次 / 扫完去设备列表），
  用户明确不想要这种常驻解释；
- 完全看不到链路：不知道电脑有没有连上中继、中继在哪、手机是否已加入；
- 电脑怎么挂上中继（env / 令牌）没有任何指引。

## 决策

重排为四段，与手机端中继页同一套语言：

1. **连接状态**（链路图）：`这台电脑 — 中继（VPS）— 手机` 三格 + 一行断点提示。
   - 这台电脑：在线；
   - 中继：已连上 / 未连上 / 没开 / 读不到；
   - 手机：`N 台`（来自已配对设备数）；
   - 断点提示只报一句：`电脑没开中继` / `电脑没连上中继` / `中继已连上，还没有手机加入` / `N 台手机已连`。
2. **同一个 WiFi**：二维码 + 机器名 · 有效期 + 换一个码。原始配对 URL 不再铺在页面上。
3. **不在同一个 WiFi**：`经中继添加设备` 行（短状态「可以出加入码 / 先让电脑连上中继」+ 添加设备按钮）；
   中继未连上时**自动展开三步教程**（电脑怎么挂载中继）：
   1. 在 VPS 上跑中继（`ts/apps/relay`）；
   2. 这台电脑的 `.env` 填 `RELAY_URL`、`RELAY_TOKEN`，开 `RELAY_ENABLED=1`；
   3. 重启服务；上面变成「已连上」后就能加设备。
4. **已连接的设备**：原样保留（名字 + 最近使用 + 移除）。

数据复用现有端点，零契约改动：`GET /api/v1/relay/status`（电脑→中继状态）、
`GET /api/v1/pair/devices`（手机数量）、`GET /api/v1/pair/qr`（二维码）。

刻意没做：

- **不在网页里改 relay 配置**：`RELAY_URL / RELAY_TOKEN / RELAY_ENABLED` 仍是服务端 env（密钥纪律：
  令牌不进页面、不进日志）；所以给的是"在电脑上怎么填"的教程，不是网页表单。
- **不保留原始配对 URL**：二维码足够；URL 太长且没人会手抄。
- **不新增后端端点**：链路图全部由现有两个只读接口拼出来。

## 补充（同日，用户拍板）：部署方式 = 用户自部署，桌面端不做一键部署

- **决策**：中继在 VPS 上的部署保持**用户自行部署**（现状 Node20 + systemd），桌面端**不做**
  cindy 式「SSH 一键部署」——那要把 SSH 凭据收进桌面程序、维护 Node 引导 / 证书 / systemd
  自动化，换来的只是一个一次性动作（用户原话：「不建议用咱们电脑端的桌面程序直接部署，还是让用户自己部署」）。
- **落点**：部署与"电脑怎么挂载"的完整命令固化在 `ts/apps/relay/README.md`（新增）：
  systemd 单元示例、env 表、给电脑签 `RELAY_TOKEN` 的两条 curl、两端挂载口径、安全清单。
  连接页教程第 1 步改为指向该指南；第 2 步补上 RELAY_TOKEN 的来历（中继签发）。
- **登记**：系统架构.md「刻意没有」新增一条（桌面端不做一键部署中继；将来要做，cindy 部署流水线是蓝本）。
