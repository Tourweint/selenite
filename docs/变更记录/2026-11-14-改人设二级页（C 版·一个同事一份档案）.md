# 改人设二级页（C 版 / 一个同事一份档案）

用户看过三版原型后选了 C：**"第三个，因为这个比较好拓展，后期我们有很多东西需要拓展。因为说作为一个同事，他有很多我们关于同事的这个模块，这也跟人设有很大的关系。"** 落地要求是 **"不仅要显示他这些比较基础的东西，比较多的也需要显示"**——所以这一页不是"人设编辑器"，是一个同事的档案页：人设只是第一段。

## 结论

「改人设」从弹窗换成设置内的二级页：`#/settings/partners/<id>`。一页四段，段与段之间不折叠、不套二级抽屉：

| 段 | 回答的问题 | 里面的东西 |
|---|---|---|
| 它在扮演谁 | 它是谁 | 名字 / 领域标签 / 口头禅 / 头像 / 人设正文（一次保存） |
| 岗位 | 它管什么、能自己定什么 | 岗位契约（独立版本）/ 当前目标 / 接派单 / 日记执事 |
| 能力 | 它靠什么干活 | 备选模型链 / 例行任务（列表 + 新建）/ 技能（只读前 6 本） |
| 档案 | 它攒下了什么 | 工作履历条数 / 记忆条数 / 记忆最近一条时间（只读） |

后面要加模块（比如它最近干的活、它的失败记录、它用过的模型、它欠的账），**往对应那一段里塞一块，或者在四段后面再加一段**——不用再挤弹窗的高度。

## 为什么不是弹窗

上一轮实拍过旧弹窗：760×868 的面板里 `#modal-body` 内容 1308px，要滚两屏；三套保存按钮（保存人设 / 改名 / 领域）并排；备选模型与例行任务本来是空的，却常驻一整套新建表单。根子在**弹窗天生只有一个视口高度**，而同事的字段是会长的。二级页把高度交还给页面滚动，弹窗那点限制就没了。

## 路由与入口

- `#/settings/partners` 仍是列表；点卡片上的「改人设」不再开弹窗，直接改 hash 进详情页。
- `web/route.js`：`currentSettingsPage()` 原先拿 `#/settings/` 后面整段去匹配分区 id，`partners/chief` 对不上任何 id 会掉回「外观」；现在先按 `/` 切第一段，另导出 `currentPartnerProfileId()` 取详情 id（`^#\/settings\/partners\/([A-Za-z0-9-]+)`）。
- `web/settings-router.js`：`page === "partners"` 分支先看有没有 id，有就交给 `renderPartnerProfilePage()` 并 return；进任何设置分区都会先摘掉 `#settings-inner` 上的 `is-partner-profile`（同一个节点实例，不摘会把 900 宽带到别的页）。
- 列表入口刻意**不 import** `partner-profile.js`（`partner-modals.js` 反向 import 会成环），只写 hash，交给 hashchange 重画。
- 详情页返回按钮写回 `#/settings/partners`。

## 四段的字段与语义

### 它在扮演谁（一次 PATCH）

名字、领域、口头禅、头像、正文是**同一份草稿**：脏计数显示「n 处改动未保存」，保存时只把真正变了的槽位塞进 `PATCH /api/v1/partners/:id`（服务端本来就支持 name/domain/soul/avatar/tagline 同批提交、整体校验后一次写入）。保存成功以服务端回读值做新基准，再点保存不会重复提交。

两处前端先拦：

- **领域**：只收 `^[a-z0-9]+(?:-[a-z0-9]+)*$`（前后端同一套正则），输入时就标红 + 提示「中文会存不进去」，并禁用保存——不是等到点保存才被打回 400；
- **名字 / 正文**：空名字、空正文在本地拦下（服务端语义是「SOUL 空串 = 不改」，本地放过去就会变成一个永远点不动的保存按钮）。

头像点圆形头像开选图浮层（复用 `openAvatarPanel`，锚在头像上、溢出时自动翻到上方），选中即是草稿的一部分，点保存才落库。

### 岗位

- **岗位契约**是独立端点（`PUT /partners/:id/contract`），与 SOUL 共用版本号，右上角回显 `vN`；
- 契约空着时右上角给一个「套用模板」（填 `CS_CONTRACT_TEMPLATE` 的四节骨架），有内容就自动收起——空 textarea 里的灰字只是 placeholder，不点模板就得从零打字；
- **当前目标**一行输入 + 保存，留空保存 = 清除；
- **接派单**：只在有 `dispatchAuthority` 时出现开关（总管不接派单，这里是一句说明，不给开关）；
- **日记执事**：开的时候把其它执事的缓存标记清掉（同一时间只有一个）。

### 能力

原先三块各占一张卡，现在是**一张卡三块 + 分块细线**，和「岗位」同一套语法（`.pf-block` + `.pf-div`）——三张卡挨着摆时右边会露出台阶状的缝。

- 备选模型：`mountChainEditor` 原样挂进来（最多 5 条，只存变量名）；
- 例行任务：`ptRenderRoutineList` + `ptRoutineFormMarkup`，新建表单收进 `<details>`（摘要就是「＋ 新建例行任务」），里面的同名标题和外层边框都去掉了（不然是盒中盒）；
- 技能：只读前 6 本 + 总数，多的让人去「设置 → 技能」。

### 档案

只读一段：履历条数、记忆条数、最近一条时间。它回答「这个同事干了多少活、记住了什么」，真正的清理入口还在「设置 → 记忆」。

## 视图规则（这一页的口径）

- 内容列宽 900（其它设置分区 1000）；`.pf` 再让 6px 给滚动条槽——铺满 900 时右对齐的注脚最后一个字会被压在槽里，看着像被切一半。
- 段标题在卡外（16px / 500），注脚右对齐（11.5px / `--text-3`）；卡内小标题 13px，区块右上角是等宽小字（条数 / 版本 / 上限）。
- 头像 72，名字 22px；状态点、`人设 vN`、`建于` 排在名字下面一行。
- 两个大文本框定高、去掉原生 resize 抓手：正文 240、契约 300（四节模板刚好装下，再短就会把「汇报对象」裁掉）。
- 主题跟现有 token 走（米黄 / 暖白 / 靛蓝夜 / 炭黑四套都实测过，不额外写颜色）。

## 顺手修的三处

1. `ptConfirmDeleteRoutine` 加 `onDone`：删例行任务成功或取消后，有回调就 `closeModal()` 再回调，没回调才退回旧行为（重开编辑弹窗）。页面上删完就地重画这一页，不会再弹出一个大编辑窗。
2. `mountChainEditor` 会带一条空的 `.cs-hint`（`margin: 12px 0`），在抽屉里是留白，在这一页撑出 41px 空档——`:empty` 时隐藏。
3. `ptRoutineFormMarkup` 的 textarea 原生 resize 抓手指针撞在这页的定高排版上，页内统一 `resize: none`。

- `node --check`（复制成 `.mjs`）五个改动文件全过；仓库 `tsc --noEmit` 退出 0。
- 相邻服务端用例：`companion-api.test.ts` + `partners.test.ts` + `partner-work.test.ts`，34 项全过。
- CDP 实拍（1440×900，米黄与靛蓝夜各三张）+ 交互脚本：
  - 列表点「改人设」→ hash 变 `#/settings/partners/chief`，标题「总管」，`#settings-inner` 拿到 `is-partner-profile` 且 max-width=900；返回后回到 1000 宽、4 张卡还在；
  - 改名字 → 「1 处改动未保存」、保存从 disabled 变可用；撤销 → 值还原、按钮回 disabled；
  - 领域填「写作」→ 输入框标红 + 「领域只能用小写字母、数字和连字符…」、保存置灰（前后端同一套正则）；
  - 点头像 → 浮层 332×468 出现在头像下方，点空白处关闭；
  - 契约输一个字 → 「有改动未保存」、保存契约可用；
  - 展开「新建例行任务」→ 表单在卡内正确排布，无盒中盒、无缩进错位；
  - 保存链路用 `Fetch.requestPaused` 拦在服务端之前：`PATCH /partners/chief` 的 body 只有 `{tagline:…}`（名字带尾随空格被 trim 成等值、没进 payload 是对的），契约走 `PUT /partners/chief/contract`，两者都被 `failRequest` 掐掉，页面回「没存成：Failed to fetch」且草稿不丢——**没有写库**。
- 控制台全程无报错。

## 这次留下的痕迹（如实记）

验证「加一条备选」时它**即时保存**（`mountChainEditor` 的既有语义：点一次就 `PATCH modelChain`），当场给总管加了一条 `bailian / deepseek-v4.1-flash`。已用同一个控件的「删掉这条」删回 `[]`，接口读数确认 `modelChain: []`，正文、名字、头像、目标、口头禅都没动。

但 `setModelChain` 会写版本快照，一来一回把 `soulVersion` 从 **v14 推到 v16**（页面上显示「人设 v16」）。版本号只增不减，没有回退接口，所以留着；**内容未变，只是号走了两格。**

## 还没定、要你拍板

1. **领域这一栏留不留**：你上一轮就质疑过「有些他都没用」。它现在只是备注，且只收小写 ASCII，占了一行两列里的一半。
2. **例行任务挂在哪**：现在挂在人设页的「能力」里（它是这个执事自己的 routines）。「定时任务」页是另一批数据（`/api/v1/agent/reminders`），两边不是一回事——要不要合并、还是各留一份。
3. **离开页面要不要拦**：现在只有脏计数，没有离开确认，切走就丢草稿。
4. **备选链的即时保存**与其余字段的「草稿 + 保存」不是一套语义：点了就落库，页脚那句「没有改动」对它不成立。要统一成草稿，还是让它就这么「点一下即生效」。
5. **正文框 240 定高**：正文短（现在只有 11 字）时看着空。要不要改成跟着内容长（160 起、超过 480 再内部滚）。
