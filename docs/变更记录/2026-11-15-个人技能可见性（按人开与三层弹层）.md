# 2026-11-15 个人技能可见性（全局锁死 + 按人开 + 三层弹层）

方案：[docs/设计方案/2026-11-15-个人技能可见性（全局锁死与按人开）.md](../设计方案/2026-11-15-个人技能可见性（全局锁死与按人开）.md)

用户口径：所有技能都放在全局库；全局已开的技能所有人都有，个人页锁死不能按人关；
全局未开的可以在某个执事页单独给他开；个人页新建技能先落全局库（默认关），再只给这个人打开；
新建/编辑尽量引导去和执事对话；搜索式技能索引不做。

## 改了什么

**1. 按人状态（`ts/apps/server/src/skill-state.ts`）**

- `.data/skills-state.json` 增加 `partners.<id>.enabled` 覆盖层，只存"全局没开、但这个人要开"的技能。
- 新增 `isEnabledFor / isOverridden / setEnabledFor / partnerNames`。
- 判定：全局开 → 所有人可见、个人页锁死；全局关 + 该人覆盖开 → 只对他可见；全局关 + 无覆盖 → 不可见。
- 落盘写 `partners.<id>.enabled.<name>`；读取同时兼容早先误写成的扁平形状
  `partners.<id>.<name>`，避免已经点过的开关在重读时丢掉。

**2. 索引与工具按会话执事过滤**

- `ts/apps/server/src/skills.ts`：`SkillStore` 的 `names / manual / indexFor` 接收可选 `partnerId`；
  新增 `visibleFor(partnerId, name)`；索引冻结键从 `conversationId` 改成 `conversationId|partnerId`。
- `ts/apps/server/src/agent/assist.ts`：`skillVisibleFor = 全局开 || 该人覆盖开`。
  同时修正 `SKILL_STATE=false` 逃生门——原实现写成 `skillStateEnabled() && 开关`，反而把技能全藏了；
  现在是 `!skillStateEnabled() || 开关`，关掉过滤 = 全进索引。
- `ts/apps/server/src/agent/lifecycle-injections.ts`：新增 `skillPartnerOf(ctx)`：
  执事会话用 `ctx.partnerId`，主对话回落 `effectivePartnerIdOfSession`（= chief）；
  `skillsProvider` / `skillSlashProvider` 都按这个 partnerId 过滤。
- `ts/apps/server/src/tools.ts` 的 `skill` 工具：按当前会话 effective partnerId 取 `manual / names`，
  别的执事看不到这个人独开的技能。

**3. 端点**

- `GET /api/v1/agent/skills?partnerId=<id>`：每项追加 `partnerEnabled`（该人实际可用）与
  `partnerOverride`（全局没开、该人独开）；不带 `partnerId` 时形状不变。
  `SKILL_STATE=false` 时 `enabled / partnerEnabled` 按全开显示，`partnerOverride` 为 false。
- `PUT /api/v1/partners/:id/skills/:name/enabled`：body `{enabled: boolean}`。
  执事不存在 404；技能名不合法 400；技能不存在 404；全局已开 409
  （「全局已开启，所有人都有；个人不能关」）；`SKILL_STATE=false` 也 409
  （「技能过滤已关闭，所有人都有；个人不能开关」）。全局未开则写/删覆盖位。

**4. 「编辑这个人」技能弹层（`ts/apps/server/web/partner-profile.js`）**

- 三层清单：
  1. **全局已开（所有人都有）**：只读行，右侧「已开 · 锁」；
  2. **全局未开（只给这个人开）**：每行开关，调上面的 PUT；关 = 删覆盖位；
  3. **他自带的技能**：只读 + 每行「让他改」。
- 顶部按钮改为「让他自己写」在前、「手动新建全局技能」在后。前者关闭弹层、打开这个执事的会话
  并在 `#input` 预填「帮我写一份技能：先把这套流程的步骤、判据和常见坑问清楚，再落成技能；第一行写一句摘要。」
  后者复用设置页 `openCreateSkillModal`，建完自动调 PUT 只给当前人打开。
- 弹层文案明确：全局技能正文去「设置 → 技能」改；新建/编辑优先走对话。
- 卡片摘要从「全局 已开/总数 · 自带 N」改成「全局 N · 独开 M · 自带 K」，
  M = 全局没开但给这个人开的数量。

**5. 共用新建弹层（`ts/apps/server/web/skills-modals.js`）**

- `openCreateSkillModal(options)` 新增 `onCreated(name)` 与 `existingHint`：
  个人页建完自动给当前人开；同名已存在时提示「改正文去设置 → 技能；只想让他按新流程做，用『让他自己写』」。

## 为什么

- 没有按人复制技能文件：全局库仍是唯一正文源，个人页只存"谁能看见"的开关，回滚删
  `partners` 字段即可。
- 全局已开锁死，是为了避免"在个人页误关一个所有人都在用的技能"；要关只能去全局设置页改。
- 新建先落全局库默认关、再只给当前人开，避免新建一个技能就影响所有执事。
- 索引仍是"名字 + 一行摘要"按人过滤后整段注入，正文走 `skill(name)` 按需取；
  用户明确不要的 `skill_search` 没有做。

## 坑（这次验证抓到的）

- **开关写完读不回来**：`setEnabledFor` 内部把状态写成 `partners.<id>.<技能名>`，`readState` 却按
  `partners.<id>.enabled.<技能名>` 读；PUT 返回 200，下一次判定就是 false。已改成内部扁平、
  落盘 `enabled` 层，并兼容旧的扁平写法；回归测试断言了文件形状与重开读回。
- **逃生门写反**：`SKILL_STATE=false` 原本应"全进索引"，但 `assist.ts` 的 `&&` 让它变成全藏。
  已改成 `!skillStateEnabled() || ...`，并补了 `hidden-skill` 测试。
- **测试夹具互相踩**：`skill-state.test.ts` 第一个用例把共享临时根删了，第二个用例的
  `skillsDir` 不存在，`createSkillStore` 返回 null。改成 `after` 统一清理。
- **冻结索引断言写反**：`doesNotMatch /alpha/` 与用例名"覆盖还在"矛盾，实际应 `match`；
  已修正。
- **点技能卡看起来没反应**：`pfOpenSkillsModal` 原来先 `await Promise.all`，再 `report()`
  （里面会 `paint()`），最后才 `openModal`。接口慢、`paint()` 抛错或组件未挂上时，点击就
  完全没有可见反馈。现在改成：点击先立刻开「正在读取技能…」弹层，再拉三层数据；
  `report()` 包 `try/catch`；数据回来只在弹层仍开着、标题仍是「技能」时重画。
  另加了一个代次号：连点或「新建后重开」时只有最后一次请求能回填，旧响应不会盖掉新弹层。
- **真正原因（2026-11-16 复查）：面板被挤到屏幕外，不是弹层被关闭。**
  技能列表的摘要带 `white-space: nowrap`，把 `.modal` 的 grid auto 列撑到约 6374px；
  `place-items: center` 又把 760px 宽的面板居中到这个超宽列里，面板实际落在 x≈2807，
  整个在视口外。`#modal.hidden` 一直是 `false`，所以只看开关状态会误判成「没关」。
  已在 `style-13-projects-modal.css` 把 `.modal` 的单列改成 `grid-template-columns: minmax(0, 1fr)`，
  并给 `.modal-panel` / `.modal-body` 加 `min-width: 0`；面板回到视口内（756 视口下 x=16、宽 724）。
- **另一个独立问题：双击触发钮会把刚开的弹层立刻关掉**：第一下点击开弹层，第二下落在刚铺开的
  `#modal-mask` 上，`closeModal` 把新弹层关了，表现也是「闪一下消失」。
  已在 `ui-atoms.js` 加三层防误触：`openModal` 记 `modalOpenedAt` 与最近一次点击落点；
  遮罩点击在 500ms 内直接忽略；同一落点（48px 内）的连点在 2s 内也忽略；
  右上角 ✕ 同样在 500ms 内不接；技能弹层另外传 `closeOnMask: false`，遮罩完全不关它，
  只能走 ✕ / Esc。其他弹层默认仍可按遮罩关闭。
- **旧页面不会自动换 ESM**：改动前已经打开的 Selenite / 浏览器页面仍跑旧模块，
  必须刷新一次（Ctrl+R 或关掉重开）才会用新代码；否则看到的是旧的三层前界面。
  静态资源本身是 `Cache-Control: no-store`，刷新后不会命中旧缓存。

## 刻意没做

- **工作区改造**：执事 cwd 仍是当前项目/工作区，等注册项目落地再做会话级根。
- **总管改其他员工设置**：`partner_manage update`、`partner_skill_write` 加 chief-only
  `partnerId` 这批跟注册项目一起做，现在不把权限口子开一半。
- **个人页全局技能正文编辑**：全局正文仍归「设置 → 技能」；自带技能正文走「让他改」对话。
- **自带技能独立开关**：自带技能默认全部对他生效，目前只提供「让他改」，没有按人关。
  如果用户要求"自带技能也能关"，下一批再加。
- **从全局未开列表批量全选 / 搜索式技能索引**：都不做。
