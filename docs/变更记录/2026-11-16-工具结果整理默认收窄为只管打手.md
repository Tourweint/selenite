# 工具结果整理默认收窄为「只管打手」（2026-11-16）

## 改了什么

上一单（`e23ef85` 打手工具结果整理开关）之后，投影的默认口径里还留着一条历史遗留：
`projectionDecision` 的 `if (partner && partner.domain) return true;`——带 domain 的执事会话
默认走结果整理。本次把这条默认删掉。

- `ts/apps/server/src/tool-projection.ts`：
  - `projectionDecision` 删掉 `if (partner && partner.domain) return true;`，落到 `return false`；
    判定注释改成「默认只管打手」，并写明删这条的原因与执事要用时怎么开。
  - 保留：`TOOL_PROJECTION=false` → 一律关；执事三态 `toolProjection=1/0` 压过默认；
    `chatKind === "worker"` 走 `TOOL_PROJECTION_WORKER`（默认开）。
- `ts/apps/server/src/tool-projection.test.ts`：
  - ⑧ 改为「默认只管打手」：`worker` 按 `workerDefault`（缺省开 / 显式 `false` 关）；
    带 domain 的执事无显式设置 → **不开**；同一执事 `toolProjection=1` → 开。
  - ⑩ 补一条「总闸 `false` 时显式开也关」。
  - ⑭ 把「带 domain 的执事跟打手开关无关」的断言从 `true` 改成 `false`。
- `ts/apps/server/web/settings-switches.js`：`TOOL_PROJECTION` / `TOOL_PROJECTION_WORKER`
  两行说明重写——默认只对打手生效；执事与总管默认不整理，需要时在执事个人页开；
  总闸关 = 全关（含显式开过的执事）。
- `docs/基线文档/接口-端点4-执事例行与自主轮.md`：`toolProjection` 三态的「跟随默认」说明同步。
- `docs/基线文档/接口文档.md` §6：`TOOL_PROJECTION` / `TOOL_PROJECTION_WORKER` 两行同步。

## 为什么

执事（`domain` 非空）与总管基本不写代码，实际很少跑 bash / powershell；让它们默认走投影只是
当年「有领域 = 干活的一方」的遗留口径（领域已在 2026-11-15 退役，见
`2026-11-15-新建执事详细设置与领域退役.md`，监工模板当时用 `toolProjection: 1` 显式钉住了原行为）。
现在默认口径收窄为「只管打手」：打手跑命令最多、输出最吵，他们才真正需要这层整理。

执事的能力没有下线——`partners.tool_projection` 三态照旧，需要时在执事个人页设成「强制开」即可。
这与「**新能力给回滚开关**」不冲突：回滚路径是总闸 `TOOL_PROJECTION=false`（全关），
以及逐执事三态（单开/单关）。

结果判定优先级（改动后）：

1. `TOOL_PROJECTION=false` → 恒关（能力整体下线）；
2. 执事三态 `1` / `0` → 压过一切默认；
3. `chatKind === "worker"` → 走 `TOOL_PROJECTION_WORKER`（默认开）；
4. 其余（主人会话、执事会话无论带不带 domain、聊天型伙伴）→ 不开。

## 行为变化

- 带 domain 的执事会话：改前默认整理，改后默认**不整理**（要整理就显式设三态 1）。
  总管、主人会话、无 domain 聊天型伙伴、打手会话的行为不变。
- 监工模板（`web/partner-templates.js`）本就用 `toolProjection: 1` 显式钉住，因此监工新档不受影响。
