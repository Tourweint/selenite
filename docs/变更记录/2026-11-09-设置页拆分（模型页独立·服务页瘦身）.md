# 设置页拆分：模型页独立，服务页瘦身

日期：2026-11-09 · 纯前端（web/app.js），零契约、零服务端

## 改了什么

设置页新增「模型」分区（侧栏排在「服务」前，Lucide sparkles 图标），把两块从服务页搬过去：

- **默认模型行**（下拉切全局模型，POST /agent/model 那套，原样搬）
- **供应商双栏**（列表 + 详情表单整节，原样搬）

服务页拆完只剩：地址 / 桌面通知 / 鉴权 / 累计 token（+按模型明细）/ 运行时 / 高级开关 / 搜索。

## 为什么

服务页那时候已经五节起步，"配上游"（模型、供应商、key）跟"服务状态"（地址、进程、开关）不是一个话题，挤在一页找东西要滚三屏。

## 顺手修的连带

- 元素 id `svc-model-control/hint/model/select` → `mdl-control/hint/current/select`：整块搬走了，id 留着 svc- 前缀会骗人。引用全在 `renderDefaultModelRow` 与新 `loadModelsInfo` 内，无外漏。
- 通知行报错原来写进模型行的 hint（`#svc-model-hint`）——模型行搬走后会指空，给它配了自己的 `#svc-notify-hint`（默认 hidden，报错才现形）。
- `loadServiceInfo` 拆成两个：服务页读地址/鉴权/用量；模型页走新 `loadModelsInfo`（目录 + 默认模型行 + 供应商）。模型目录启动时本就另有一份（composer pill 依赖），pill 不受影响。
- 三处用户指引文案"设置 → 服务"改"设置 → 模型"：模型菜单空态（还没有可选模型）、执事模型页 keyEnv 缺失提示、以及对应注释。

## 深链兼容

`#/settings/models` 直接可用（`currentSettingsPage()` 按 SETTINGS_SECTIONS 校验，新 id 自动生效）；`?view=settings/模型页 id` 深链同理。旧 `#/settings/service` 书签仍落服务页，服务页没消失，无需别名。
