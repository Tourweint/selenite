# 2026-11-24 派活工人访问项目全部文件夹 + 外部库项目索引文案

## 结论

1. **派活按项目下发全部文件夹**：`ProjectRef.roots` 不再在 chancellor 入口被剥掉，
   一路带到 external CLI 的 `TASK.md`、本机池的 task profile / run payload、经理提示词，
   以及池 `read` / `write` / `edit` 的路径边界。主文件夹仍是唯一的 worktree / 合并 / 租约单位；
   其他文件夹共享读写真实目录（沿用 2026-11-13 项目容器方案已登记的边界）。
2. **回滚开关** `DELEGATION_PROJECT_ROOTS=0/false/off` 回到"只给主文件夹"。
3. **外部记忆库槽位的 `project_index` 文案按行为改写**：不再承诺"项目记忆会自动想起"，
   也不再提示 `remember` 的 `project` 参数（external 槽位下两者都不成立）。

## 为什么

用户口径（2026-11-24）："派活的工人肯定是能够进入他的这个项目的，而不是说定死了文件夹；
发消息是按项目，不是按文件夹；不只是主文件夹，别的也都要进入。"

2026-11-13 项目容器方案已经定了 `ProjectRef.roots[]` 与"附加根共享读写、不进 worktree"，
但落地时 chancellor 的 `normalizeProject` 把 `roots` 剥掉了，派活链路只剩 `rootPath`：
TASK.md 只写主文件夹、池边界只有 `[taskDir, workDir]`、经理提示词只有根目录。
本次是把已定的语义真正接线。

外部库文案：`project_index` 原写"聊到哪个项目，相关的项目记忆会自动想起；多挂载时用
remember 的 project 参数指名写"。external 槽位下 `recallContext` 整条跳过、`remember`
的 `scope=project` 被忽略，两句话都与实际行为不符（文档滞后即 bug）。

## 改了什么

### 1. chancellor 下发链路

| 文件 | 改动 |
|---|---|
| `packages/chancellor/src/types.ts` | `ProjectRef.roots?: ProjectRootRef[]`（id / label / path / role） |
| `packages/chancellor/src/index.ts` | `normalizeProject` 保留并收敛 roots（只收绝对路径；label 缺省目录名；role 两值） |
| `packages/chancellor/src/config.ts` | 回滚开关 `projectRootsDispatchEnabled()`（`DELEGATION_PROJECT_ROOTS`，默认开） |
| `packages/chancellor/src/scheduler.ts` | `taskProjectRoots(project, isolated)`：隔离形态只下发 `role=extra`（真实主文件夹不下发）；非隔离形态全部下发；回滚关 = undefined。两处 runner 调用都带上 |
| `packages/chancellor/src/dispatch.ts` | `DispatchOptions.projectRoots` → `EmployeeTask.projectRoots` → `buildWorkerPrompt` 第五参 |
| `packages/chancellor/src/employee/{index,pool}.ts` | EmployeeTask / 池 run payload 增加 `projectRoots` |
| `packages/chancellor/src/worker-prompt.ts` | TASK.md 出「项目的文件夹 / 项目其他文件夹」段；边界规则改为"项目文件夹（含其他根）可写"；没有 roots 时逐字保持旧文案 |
| `packages/chancellor/src/manager-prompt.ts` | 经理提示词列出项目全部文件夹（派给工人的活可用绝对路径进入） |
| `packages/chancellor/src/employee/manager.ts` + `worker-main.ts` | 经理子进程经 `--project-roots`（JSON）继承 roots；坏值忽略，子单退回只给主文件夹，不炸经理 |

### 2. 本机池

| 文件 | 改动 |
|---|---|
| `apps/server/src/pool/run-queue.ts` | `QueuedRun.roots` + `parsePoolRoots`（bridge / pool-server 共用的入参收敛：绝对路径、role 两档、≤32 条） |
| `apps/server/src/pool/bridge.ts` / `pool-server.ts` | `/run` 接受并校验 `roots` |
| `apps/server/src/pool/supervisor.ts` | `toRunBody` 透传 roots |
| `apps/server/src/pool/pool-main.ts` | 当前票保存 roots；`currentDirs` 加入 roots；profile 传入 roots |
| `apps/server/src/pool/pool-tools.ts` | `poolBoundaryDirs(taskDir, workDir, roots)` 纯函数（去重）；路径边界放行其他文件夹 |
| `apps/server/src/pool/task-profile.ts` | 「工作边界」列出项目文件夹；工人纪律第 1 条改为"任务目录 / 工作目录 / 项目文件夹" |

### 3. 项目索引文案

`apps/server/src/agent/assist.ts` 的 `projectIndexProvider`：
- builtin 槽位：文案不变；
- external 槽位：「项目记忆不会自动带进上下文；要查项目口径就用 recall（当前接的是外部记忆库，按关键词查）」，
  不再提示 remember 的 project 参数。

## 明确不做

- 其他文件夹的 worktree / 复制 / 合并 / 独立租约 / 冲突检测。
- 外部 CLI 厂商沙箱的强制放行：TASK.md 给路径，能否写到 cwd 之外由各 CLI 原生沙箱决定。
- 删除 `delegate` 的 `workdir` 参数 / 会话 cwd 快照。
- 项目记忆写入在 external 槽位下的行为（现状：只写原话进外部库、`scope=project` 不生效；用户已确认接受）。
- 普通助手会话退役的既有事实：新建会话已是总管（`chatKind=chief`），历史 worker 会话只兼容打开；
  本次不改这条链路。

## 回滚

回到只给主文件夹的旧形态。代码结构保留，不需要改代码。
