## 一、会话导出「接续文件」（§一）

- **新建**端点 `GET /api/v1/agent/chat/:conversationId/export?format=handoff&limit=30`。
  前置勘察确认原先**没有**会话导出端点（2026-11-10 核实），所以不是升级。
- 新模块 `chat-handoff.ts`（纯文本拼装，不读盘 / 不碰会话）：
  - 四块：角色说明（chief / worker / partner 各一句）、读取说明、记忆摘要（最多 20 条）、最近 N 轮原文；
  - `limit` 默认 30、1–200；按 **user 消息**起算轮次，不把某轮回答切一半；被截断时文里写「更早的 N 条未包含」；
  - 记忆摘要取 `preferenceScopeOf` 的作用域（主对话 `global` / 执事 `partner:<uuid>`），
    只收 `preference` + `experience`，不导 `session:` 沉淀；
  - 记忆未启用 / 读取失败 / 池子为空各有明确一句，不冒充完整。
- 响应是 `text/markdown` + `Content-Disposition: attachment`，**一次性响应体，不落服务端磁盘**、
  `Cache-Control: no-store`；文件名只带会话 uuid 前 8 位。
- 开关 `CHAT_EXPORT_HANDOFF`（默认开；false → 404）。

## 二、auxiliary LLM 一等化（§二）

- 新模块 `auxiliary.ts`：用途枚举 `title` / `compact` / `review` / `extract`；
  `AUX_MODEL_<USE>` 可给单个用途 pin 模型；解析顺序 = 当前供应商 → 目录顺序找同名 →
  找不到回落当前模型并 warn（不静默换不存在路由）。
- 总开关 `AUX_LLM`（默认开；false → 全部回落当前模型）。
- **本批只接线 `extract`**：`memory-extract.ts` 的 `generateOnce()` 把"当前模型"换成
  `auxiliaryModel("extract")`，没配时与改动前逐字节一致。
- `title` **不接线**：2026-11-10 核实当前没有自动标题生成（只有显式 `rename`），按任务书"有就接没有就跳过"。
  `compact` / `review` 只留枚举接口，未接。

## 四、旧会话定点找回（§四）

- 前置勘察确认 transcript **没有 seq**，所以用 **`aroundIndex`（消息数组下标，从 0 开始）**，
  不为这个改内核；接口为 `GET /api/v1/agent/chat/:conversationId/context?aroundIndex=<n>&radius=5`。
- 新模块 `chat-context.ts`：`radius` 默认 5、0–50；窗口两端自然截断；`total` / `from` / `to` 如实返回；
  每条带 `index`（绝对下标），user 消息带可寻址 `id`；**不回放图片与步骤**。
- **路径冲突的处理（本批新发现）**：同路径早已存在「上下文占用」端点（§2.5，`{used, window}`，
  2026-11-04 批次二）。2026-11-10 起按参数分流：**不带 `aroundIndex` 时逐字节保持旧语义**，
  带 `aroundIndex` 才走定点找回；`CHAT_CONTEXT_LOOKUP=false` 只关新语义，不影响旧端点。
- 越界 `aroundIndex` → 400 且 body 带 `total`；空会话 → 200 + 空窗口；只做后端，不做界面 / fork。

## 六、边界与刻意不做

- **导出不落服务端磁盘**：只有 HTTP 响应体；记忆摘要只读不改；导出成功不追踪对方是否接收（文件里写明）。
- 导出不含 `session:` 原始记忆、不含工作步骤 / 图片；接续文件是"能接着聊"的片段，不是归档。
- `title` 未接线（当前没有自动标题）；`compact` / `review` 只有枚举。
- 定点找回按数组下标，不是 seq；不做界面、不做 fork；图片 / 步骤不回放。
- 零 `shared` 改动、零 chancellor 改动；未 commit。
