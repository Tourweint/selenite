## 改了什么

1. **服务端 `context-defaults` 加 `dispatch-worker` 角色**（`src/context-defaults.ts`）：
   「派活工人（池）」用 `pool/task-profile.ts` 的真实段生成默认上下文：
   工人纪律 / 注入防线 / 验证铁律 / 人设 / 任务与完成标准 / 项目记忆（0 槽）/
   前置任务结果（0 槽）/ 交付契约 / 工作边界；工具五件（按 worker-tools 勾选过滤，
   escalate 恒开）。人设段可编辑，写回共用的 `worker-persona`。
2. **服务端 `pool/task-profile.ts` 结构化**：导出 `buildTaskProfileSections()`，
   `buildTaskProfile()` 改为调用它；systemPrompt 与现有段顺序/文字一致。
3. **服务端 `pool/pool-tools.ts` 导出 `poolToolCatalog()`**：read/write/edit/bash + escalate
   的只读目录（escalate 传 preview 桩），供设置页展示，不注册不执行。
4. **新端点 `GET /api/v1/agent/assistant-surfaces`**（`src/assistant-surfaces.ts`）：
   总管 / 活跃执事 / 普通助手 / 派活工人（池）的人设预览（≤160 字）+ 工具名 + 可调/固定项 +
   站内 hash（改人设 / 调工具 / 模型 / 看上下文）；只读、不返回正文/密钥。
5. **前端「助手的人设与工具」卡**（`web/settings-router.js` + 新 `web/assistant-surfaces.js`
   + `style-14-settings-pages.css`）：注入 → 人设顶部按档列行，显示人设预览、工具 chips、
   可调/固定标签与动作；端点读不到时整卡隐藏，不挡原总管与执事列表。
6. **上下文深链**（`web/settings-context.js`）：支持 `#/settings/context?role=dispatch-worker`
   （也认 worker / partner:<id>）；无效值回落 chief，无 query 行为不变。
   `web/settings-context-edit.js` 对 `dispatch-worker` 的 persona 段也写回 `worker-persona`。

    看不到前序改动而 blocked；票终态 failed。
- 根因：池工人的 worktree 合并只把**新文件**落回主工作区，**tracked 文件**的 diff
  没有落回（脏工作区下 `git apply` 不成立）。最终由人工把两个 worktree 的 patch
  应用到主仓，并补齐缺失的 `poolToolCatalog` 与服务端汇总端点。
- 结论：**脏工作区上派多文件任务，必须派完核对主仓 git status / grep 关键符号**，
  不能只看任务 REPORT 的 ready。
