# 2026-11-20 人设页「负责项目」文案：写明只管记忆、不管目录权限

> 纯前端文案。挂载的作用不变，只是把「负责项目」容易被读成「他能改哪些项目」的歧义写清楚。

## 为什么改

「负责项目」这个名字容易让人以为它是工作范围：挂上哪个项目，执事/总管就只能动哪个项目。实际不是——
文件读写边界是**全部已登记根并集**（主工作区 + 所有项目文件夹），与人格挂载无关；挂载只决定
每轮项目索引和项目记忆的可达性。派出去的 worker 才是按单子所属项目限定在单个项目内。

（2026-11-20 核对：`path-guard.ts` 的 `workspaceRoots` 来自 `workspaceRootsReal()`，不读 `partner.projectIds`；
`agent/project-scope.ts` 的 `personaProjectIdsOfSession` 对 worker 返回空数组，worker 走 `ChatProjects` 绑定。）

## 改了什么

- `ts/apps/server/web/partner-profile.js`
  - 「每轮固定注入 → 负责项目」卡片悬停提示：开头改为「只管记忆，不限定他能改哪些目录」，并补一句
    「所有已登记的工作区 / 项目本来就都能读写（文件边界是登记根并集）；派出去的 worker 才按单子绑定的项目限定」。
  - 「负责项目」弹层说明：同步补「只影响记忆，不限定目录」与「往项目记忆里写也只写进挂上的这些项目」，
    并加一行灰色提示说明总管/执事与 worker 的边界差异。

## 验证

- 未改任何端点、字段或服务端逻辑，契约无变化。

## 刻意没做

- **没改字段名 / 端点 / 存储**：`projectIds` 语义本来就是记忆可达性，问题只在文案。
- **没在卡片上写设备活豁免**：人设页这张卡讲的是人格挂载，worker 的边界只做一句概括；
  设备 worker（`phone` / `targetDevice`）的既有限定仍在 `tools.ts` 的 `isDeviceWorkerDelegation`。
