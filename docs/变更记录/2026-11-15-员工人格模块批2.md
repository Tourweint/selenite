# 员工人格模块 · 批2（印象 / 心情 / 内心生活）

方案：`docs/设计方案/2026-11-14-员工人格模块（开关化拟人）.md`（§6 活模块机制是本批口径）。
批1 骨架见 `docs/变更记录/2026-11-14-员工人格模块批1.md`；批3（学习 / 主动性 / 人设库 / 手机端）不在本批。

## 改了什么（按契约顺序）

**1. 契约（`ts/packages/shared/src/index.ts` + `docs/基线文档/接口-端点4-执事例行与自主轮.md`）**

- 新增 `PARTNER_OWNER_TIERS`（五档文字）、`PARTNER_MOODS`（五种）、`PARTNER_LIVING_LIMITS`（活内容上限唯一落点，
  按 Unicode code point 计长）。
- 新增四份 schema：`PartnerImpressionSchema`（带 `subject` / `event` / `tierChange`）、
  `PartnerDiaryEntrySchema`、`PartnerWishListSchema`、`PartnerLivingPatchSchema`（PUT 的 `living` 段，
  按条目动作：印象 `add|update|remove`、日记 `add|edit|like|unlike|remove`）。
- 新增 `PartnerPersonaSwitchesSchema`（`moodAffectTone`）与 `PartnerLivingView`（端点投影）。
- `PartnerPersonaView` 增 `switches` / `living`（`enabled=false` 时 `living=null`）/ `limits.living`；
  `PartnerPersonaPatchSchema` 增 `switches` / `living`（`.strict()`，任一不合法 400 且不写）。

**2. 存储**

- `partners` 表七列：`persona_switches` / `owner_tier` / `nearby` / `mood` / `mood_reason` /
  `mood_updated_at` / `mood_source`（旧库 `PRAGMA` + `ALTER TABLE` 补列）。老行读 `null`：
  温度按 `生疏`、心情按 `平静`、子开关按关兜底（`toPartner` 统一处理，不补数据）。
- 温度 / 心情 / 近况都放 **PartnerRow**（不是独立小表）：与 `currentGoal` / `tagline` 是同一类
  "现取现用的状态"，一条 UPDATE、不版本化；拆表要多一次 join，收益为零。
- `setPersona` 增可选 `switches`；新增 `setOwnerTier` / `setLivingState`（省略字段保持原值）。
- 印象进记忆库：`MemoryKind` 新增 `"impression"`；与 `work` 同待遇——不进语义召回、不衰减、
  不参与巩固合并、会话封顶修剪受保护，记忆管理端点的 kind 全集收它。

**3. 活模块实现（新文件 `ts/apps/server/src/partner-living.ts`）**

- 没有塞进 `partner-persona.ts`：那里是"开关怎么算、静态身份怎么渲染"；活模块要开会话记忆库、
  读家目录、接三个钩子，职责不同。静态 / 活的边界按"他是谁 / 他现在怎样"拆。
- 印象：单对象总条数 ≤20（跨档记录不淘汰）、append-only；写入只两路（结算钩子 `generated`、
  端点手改 `manual`），模型工具不可伪造。
- 温度：档内微调 = 每次致谢加一条；跨档阈值 3 / 5 / 8 / 12 次致谢，写 `tierChange` 账；
  **不自动降档**（降档只能手改，手改同样写账）。
- 心情：三条可见规则（被谢→愉悦、连败两单→低落、72h 无新单→平静）+ 低落被一单成功捞回→平静；
  `烦躁` / `疲惫` 只作手改选项（不做生理拟真）。值不变不写，保住 `mood_updated_at` 的可读性。
- 内心生活：`persona/diary.jsonl`（≤300 字 ×500 条，另有 512KB 文件护栏）、`growth.md`
  （≤400 字 ×40 节）、`wishes.json`（≤10×40）。日记 / 成长用自带原子写（不走 64KB 槽位护栏——
  那是给身份文件的，套在日记上写满就炸）。
- 日志纪律：印象 / 日记 / 成长只记条数与枚举（`thanks` / `correction` / `group` / `generated`），
  写失败只 warn 错误摘要。

**4. 钩子**

- **会话结算**（`agent/settled.ts`）：只认执事的 **canonical 主会话**、只看**最后一条用户消息**；
  致谢 / 纠正两类事件。放在 `memoryEngine` 判空之前——印象有自己的库，不依赖记忆引擎开没开。
- **派单结算**（`delegation-start-delegation.ts`）：与 work 履历同一处结算点、同一判据认执事，
  连败两单→低落。
- **群成员轮**（`group-runtime.ts`）：只记"本回合别人点名了我"（`subject`=那位成员 id），
  同一天同名事件不重复记。
- **周盘点**（`routines.ts` 的 `runOnce`）：`heart` 开 + 规则名/指令带盘点关键词时，提示词末尾追加
  `PERSONA_DIGEST_INSTRUCTION`；模型按 `[[日记]] / [[成长]] / [[周报]]` 收尾，服务端
  `applyRoutineDigest` 摘出日记 / 成长落盘，**`[[周报]]` 一句留在可见正文末尾**。
  不新造调度、不改 routine 表结构、不改 `routine_manage` 契约。

**5. 注入（`agent/partner-context.ts` + `agent/injection.ts`）**

- 新增三段 `partner_impression: 310` / `partner_mood: 320` / `partner_heart: 330`，挂在在办之后。
- 各段按模块开关裁剪；`PARTNER_PERSONA_MODULES=false` 或模块关 → 整段不出现。
- 空内容一律不注（没有印象 / 初始心情态 / 愿望与成长笔记都空）。
- `INJECTION_ORDER` 是缓存前缀资产：本批**有意**新增三个 id（顺序快照测试已同步）。

**6. 端点（`companion-api.ts`）**

- GET 回 `switches` / `living` / `limits.living`；`living` 含温度、跨档说明、心情、全部印象
  （附 `subjectName`）、最近 50 条日记 + 条数 + 最新预览、成长笔记最近一节、愿望。
- PUT 收 `switches` / `living`；全量过 zod，任一不合法 400 且不写；手改写 `manual` 标记；
  改 / 删不存在的条目 400 带说明。系统更新与手改走 `partner-living.ts` 的同一条写路径。

**7. 前端（`web/partner-profile.js` + `style-22-partner-profile.css`）**

- 人格模块区补齐三行：印象（`温度 · 条数`）、心情（`状态 · 原因 · 时间`）、内心生活（`日记 N 条 · 最新预览`），
  各带「查看」。
- 印象弹层：五档温度下拉 + 全部条目（可改正文 / 可删）+ 加一条对主人的印象。
- 心情弹层：五种枚举 + 原因 + 近况，规则说明常驻在弹层里。
- 内心生活弹层：愿望清单可改；日记列表可赞 / 可删 / 可补一条；成长笔记只读展示。
- 总开关关着整块隐藏（`enabled=false` 时 `living=null`，不假装有状态）。

## 开关名

| 开关 | 位置 | 含义 |
|---|---|---|
| `PARTNER_PERSONA_MODULES` | env（批1 已有） | 总开关；false = 活模块不更新、不注入，`living=null` |
| `impression` / `mood` / `heart` | 每员工模块表 | 模块关 = 停更 + 不注；**内容保留**，重开即回 |
| `moodAffectTone` | `persona_switches`（子开关） | 心情是否影响口吻（多一行提示），默认关 |

本批**没有新增 env**：回滚沿用模块开关与总开关，不需要改代码。

## 可见规则（改这些常量 = 改行为）

- 温度阈值 `TIER_THANKS_NEEDED`（3 / 5 / 8 / 12；到顶不再升）。
- 致谢词 / 纠正词 `THANKS_WORDS` / `CORRECTION_WORDS`。
- 心情 `MOOD_FAIL_STREAK=2`、`MOOD_IDLE_HOURS=72`。
- 盘点识别 `REVIEW_ROUTINE_WORDS`（盘点 / 回顾 / 周报 / 周总结）。

## 刻意没有（复核 `系统架构.md` §七，无新增）

- **数值好感度 / 关系分**：温度只有五档文字，跨档必须能指到一条 `tierChange` 账。
- **假装身体的生理状态**：`烦躁` / `疲惫` 只作手改选项，规则不生成、描述里不写身体感受。
- **agent 回写 SOUL 本体**：成长笔记落 `persona/growth.md`（独立附注层），测试断言 SOUL 字节不变。

## 与任务书 / 方案的一处偏差（已按实情落地）

- 任务书把活状态读写预期在 `partner-persona.ts`，实际拆到新文件 `partner-living.ts`：
  静态身份与活状态的依赖面完全不同（一个只读 JSON，一个要开记忆库 + 读写家目录 + 接钩子），
  混在一个文件里会变成第二个"什么都管"的 800 行模块。函数边界不变，端点注入仍是同一套。
- 盘点目标**不是新调度、也不是新字段**：按规则名 / 指令里的关键词识别（常量可见、可测）；
  没有关键词的自建盘点不挂生成。这是本批的**已知边界**，写在接口文档里。
- 群成员印象只覆盖"被点名"这一种事件（不做读发言 / 争论 / 协作推断）。

## 已知边界（未做 / 未验证，2026-11-15）

- `runNow`（手动试跑盘点）不落日记 / 成长：手跑不该产生"这周"的记录。
- 印象提炼是确定性字符串匹配，不做模型总结；因此只认致谢 / 纠正，不生成"他喜欢先看结论"这类判断。
- 成长笔记 / 日记只做长度与结构校验，不做事实核查（模型仍可能写得不像）。
- 手机端、团队包、备份导出不搬运活内容（批3 / 与人格模块同口径）。
