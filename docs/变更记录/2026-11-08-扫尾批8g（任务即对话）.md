## 改了什么

**新文件**
- `src/task-conversation.ts`：任务专线会话。
  - `ensureTaskConversation(ticketId)`：`task-<票号>` 前缀（复用 `TASK_CONVERSATION_PREFIX`），并发合并 + 进程内缓存；`configureTaskChat` 摘掉 `lifediaryExt`（无工具、无记忆注入、无人格）。
  - `appendTaskEvent(ticketId, entry)`：`pi.assistant` 条目（形状同 `sayInChat`），**按单串行队列**保证条目顺序 = 事件顺序。
  - `getTaskConversation(ticketId)`：确定性 id，不打开 Harness（避免只读详情触发 durable resume）。
  - `submitTaskReply(ticketId, text)`：`submit({type:"input", whenBusy:"followUp"})`。
  - `TASK_AS_CONVERSATION` 回滚：ensure/get/append 全旁路。

**改的文件**
- `src/delegation.ts`
  - `DelegationRuntime.mirror?`：进度 / REPORT / out 留言同一处镜像（同步入队）。
  - `DelegationKickoff.resumeOnly?`：续跑被拒不按新活派（任务回话专用）。
  - `DelegationKickoff.skipMessageMirror?`：`/say` 已写用户条目，不再重复镜像留言。
  - `formatProgressLine` / `formatMessageLine` 纯函数；`fail` 的失败归属优先原单号。
- `src/tools.ts` / `src/agent/lifecycle.ts`：delegate 运行时新增可选 `mirrorDelegation` 注入位，只由装配层（lifecycle）传 `taskConversationMirror`。**刻意不在 tools.ts 里直连**：探针/单测也调 `createTools`，那里没有 durable 上下文，不能因为默认值就去开真实 Harness。
- `src/index.ts`：`turnSettledHandler` 对 `task-` 前缀会话跳过记忆抽取——专线可被"打开对话"后直接在会话页续聊，不能因为换了个入口就把任务过程沉淀成记忆。
- `src/relay-matrix.ts`：远程单的本机运行时也接 `mirror`（任务详情同样有专线）。
- `src/delegation-api.ts`
  - `POST /api/v1/tickets/:id/say`（开关关着不挂 → 404）：submit 专线 + `startDelegation(resumeOnly)` 续跑，202 受理；终态/作废/无来源会话/专线不可用分别 400/503。

  - `defaultRetryRuntime` 补 `mirror`（重试出来的单同样双写）。
- `web/app.js`、`web/style.css`：任务详情新增「任务对话」区——回读 `GET messages`、回话 POST `/say`、发完重绘、`打开对话` 走 `openConversation`。

## 不确定 / 边界

- 任务专线的模型回合：`/say` 的 `submit` 会触发一轮无工具模型回答（方案要求 submit；答复由模型按会话内进度生成）。若只想留记录不想让模型说话，需要改成 write user 条目——当前按任务书执行。
- 回读任务专线目前是一次性 GET（发完重绘），不走 SSE；专线是慢通道，够用，但长任务进行中打开详情需要手动刷新。
