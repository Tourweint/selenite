# 项目页简化（有框分区 / 单按钮 / 去版本控制）

B 版落地后用户说："去掉解释性文字""后面那个点加上'默认目录'也不要了，只留一个选择""用不用框都无所谓，不用框也没关系""版本控制没有用，因为项目有没有版本控制跟文件夹有关，跟项目没关系，所以也不要检测了""项目名左边的彩色竖条也不用了""主要是简化一下，这页还是不够美观"。

先做了一版"整页一条竖线清单、完全不套框"，用户看过当场否掉：**"不行，还不如原来那个呢，肯定要有框，不同区域都要分辨好。这个首先要清晰。"** 于是定稿是：**框留着，简化只落在文字、按钮数量和颜色上。**

## 改了什么、为什么

### 1. 分区靠"框 + 间距"，不靠一条线（这一条走过弯路）

- 第一版（被否）：`.proj-card` 去边、去底、去圆角，只在段与段之间留一条 1px `--divider`。干净是干净了，但项目一多就分不出哪几行属于哪个项目——**用户的原话是"首先要清晰"**。
- 定稿：每块一张卡——工作区一块、每个项目一块，`padding: 10px 12px`、1px `--composer-border`、`--r-md`、`--surface` 底、块间 10px 空隙。**卡里面**才用 `--divider` 分行，卡与卡之间不堆线。
- 工作区卡比项目卡矮一档（`8px 12px`）：它只有一个标签 + 一条路径 + 一个按钮，没有标题行。

### 2. 工作区那行只剩一个按钮

改之前：`[路径输入框] · 默认目录 [选择] [保存]`，下面还有一句"没有项目时，助手在这里干活……"。三个东西都在说同一件事，用户的原话是"只留一个选择"。

现在：`工作区根目录   C:\...路径...   [选择 / 保存]`。

- **桌面壳里按钮是「选择」**：点了直接开目录对话框，选完就存，不给第二步；
- **浏览器里按钮是「保存 / 设定」**：浏览器没有目录选择器，只能手输路径后点保存；
- 路径框退掉边框，平时就是一行等宽文字，hover 出下划线、聚焦变强调色下划线；`Enter` 也提交。

### 3. 删掉所有解释性文字

- 工作区卡下的"没有项目时，助手在这里干活。它不是项目（没有名字、不能加文件夹），所以不在下面的列表里。"——整段删。
- 空态从"点右上角「添加项目」登记一个已有目录；项目可以在任意位置……一个项目可以再加多个文件夹，其中一个是主文件夹。"压成一句 `还没有项目。点右上角「添加项目」。`
- "待确认的请求"空态的第二行（"助理提出新建项目后会出现在这里；确认才建目录、登记。"）删掉，只留 `没有待确认的请求`；提案行尾巴上的"· 确认后才建目录、登记"也删。
- `REPLACE_WORKSPACE_WARNING`（"更换根目录会清空当前项目选择（回到主工作区）"）连同它的提示逻辑一起删——这条后果仍然存在，只是不再写在界面上说。

### 4. 不再显示版本控制

`Project.vcs / head` 是文件夹（仓库）维度的属性。项目是"名字 + 一组文件夹"的容器，把 git 状态摆在项目标题后面，等于说"这个项目是 git 项目"，而实际上三个文件夹里可能只有一个有 `.git`。所以卡片 meta 只剩 `N 个文件夹`。

**这只改了显示**：服务端 `detectVcs`（`src/project-rows.ts:29`）在登记文件夹时仍会对每个路径跑一次 `git rev-parse HEAD` 并写库。原因是 `Project.vcs / head` 是既有接口契约（顶层 `vcs/head` 恒等于主文件夹那份），手机端 / 桌面端可能依赖它；删字段要动 schema、迁移和 `projects.test.ts` 的断言，不属于"简化这一页"。要不要连检测一起去，需要单独确认。

### 5. 主文件夹不画彩色竖条

`.proj-root-row` 去掉 `border-left: 3px`，只保留「主」徽标 + 名字加粗。颜色在这一页只剩两处：页面级主按钮（深靛）和「主」徽标。

### 6. 同类动作收敛到同一档

改之前这一页有四种长相：实心主按钮、淡靛软底、描边 ghost、无边框 ⋯。用户的原话是"主要还是这个按钮的事儿，咱们主要还是得用按钮，不能直勾勾的"——所以**同类动作统一到同一档**：

| 层 | 长相 | 用在哪 |
|---|---|---|
| 页面级主操作 | 深靛实底 + 白字（`.btn-primary`） | 「＋ 添加项目」 |
| 卡内 / 行内动作 | 淡靛软底 + 靛字（`.btn-primary.is-quiet`） | 保存根目录、＋ 添加文件夹、查看归档、待确认请求的「确认」、归档页「恢复」 |
| 次一级 / 取消 | 描边 ghost（全站既有，与弹窗「取消」同一档） | 编辑态「取消」、「拒绝」 |
| 图标动作 | 28×28 无边框 ⋯ | 行尾 / 卡头把 2–3 个同级动作收进去 |

关键是同一类东西不再有两种长相：以前「查看归档」是描边、「＋ 添加文件夹」是软底，同级却长得不一样；归档页「恢复」是描边，项目页「恢复」也该跟着改。

### 7. 列对齐与路径字体

- 工作区标签列固定 `150px`，与文件夹行的名字列同宽 → 两条路径对齐成一条竖线；
- 文件夹路径补上 `font-family: var(--mono)`：以前工作区路径是等宽、文件夹路径是宋体，同一页两种字体；
- 路径统一 `11.5px / --text-2`；文件夹行加了 `hover` 浅底，鼠标扫过能看出是一行。

## 顺手修的（这条差点把整页打死）

删 `REPLACE_WORKSPACE_WARNING` 时，`let settingsWorkspace = null;` 那行被一起带走了，导出表里还留着 `settingsWorkspace` → 浏览器报 `Uncaught SyntaxError: Export 'settingsWorkspace' is not defined in module`，**整个设置页模块加载失败**，表现是"点设置没反应、深链一律落回聊天页"。排查时先怀疑路由，实际是模块级语法错误。`tsc --noEmit` 对这一层是瞎的（它不检查 `web/*.js`），是 `bu.console_messages()` 抓到的。

修完补了一个粗校验：把导出表里的每个名字回查 `function|const|let|var` 定义，`missing: none`。

  - 控制台 0 error（修 `settingsWorkspace` 之后）；
  - 工作区行只有一个按钮，点它提交成功、列表重建、路径仍在；

## 刻意不做

- **侧栏没动**：侧栏的项目行是 `▾ / ＋` 两个图标按钮 + 浮卡，密度本来就低，而且它是"选中项目"的入口，和设置页的"管理项目"不是一件事。要不要把 ▾ 也换成 ⋯ 菜单，等这版看过再说。
- **没删 `detectVcs`**：理由见上面 §4，属接口契约。
- **没给工作区卡换一种形态**：第一版曾用 `--surface-low` 把它压暗，实测与页面底色几乎一样，看不出是"另一种东西"，干脆和项目卡同一副长相、只靠内容区分。

## 这条会怎么错

- **"框"回来了，就可能再被说"太碎"**：一屏里如果挂六个项目，就是六个框 + 一条外层大卡，密度偏高。真嫌碎的话，正解是"外层大卡不要、每个项目一块卡"，而不是再退回无框清单——**用户已经明确说过"首先要清晰"**。
- **单按钮的两种身份**（选 / 保存）依赖 `inShell()`：桌面壳里叫「选择」，浏览器里叫「保存」，同一个控件两种行为。如果以后桌面壳也想支持手输路径，这个按钮就得再拆回两个。
- **版本控制还在跑**：界面上看不到，但 `detectVcs` 每次登记文件夹都会跑 `git rev-parse`。网络盘上登记一批文件夹会变慢；真成了问题再去去掉字段。
- **删掉的提示语还会回来**：换根目录确实会清空当前项目选择，现在界面上不提了。用户真被清空一次之后，可能会要求把这句加回去——那时应该加在"换根目录"的确认弹窗里，而不是常驻在页面上。

## 追加：第四轮（行尾只剩 ⋯ / 主文件夹按钮常驻 / 砍归档与提案入口）

用户这一轮四句话："添加文件夹就放在右边三个小点点里吧""工作区根目录也可以放那里，这样比较简洁""已经归档的项目不用在这里做超链接，也不会出现""下面这个确认请求，就是新建目录的请求，你觉得有没有用？我觉得没啥用吧"。

同时他问了一句更要紧的话："把这个主文件夹作为一个文件夹有啥用？"——这句话决定了「设为主」不能继续藏在菜单里。

### 改了什么

| 改点 | 之前 | 现在 |
|---|---|---|
| 添加文件夹 | 卡头一个常驻软底按钮 | 进项目卡头的 ⋯（第一项；与重命名之间有一条分隔线） |
| 工作区动作 | 行内一个「选择 / 保存」按钮 | 进工作区行的 ⋯，菜单只有一项：桌面壳「选择目录」、浏览器「保存路径」（**第五轮又改回显式按钮**，见下） |
| 行尾动作 | 每行一个 ⋯ | 主行仍只有 ⋯；附加行 = 常驻「设为主」+ ⋯（改路径 / 从项目移除） |
| 已归档项目 | 项目页底部「已归档的项目目录（N）+ 查看归档」一行 | 整行删除。归档在设置左侧「归档」分区，这一页不再做入口 |
| 待确认的请求 | 独立分区 + 常驻空卡 + 一句解释 | 不再有独立分区；只在 `proposals.length > 0` 时出现在项目卡顶部（`#proposal-list` 默认 `hidden`） |

### 为什么「设为主」要常驻，而「添加文件夹」可以进菜单

「设为主」改的是**之后新建会话的 cwd**——它是这一页唯一会改变"助手在哪干活"的开关。同类产品的做法也说明这一条不能藏（见下）。「添加文件夹」只是登记一个已存在的目录，低频，进菜单没有代价。

### 参考了谁

| 产品 | 多目录怎么表达 | 「主」在哪 |
|---|---|---|
| Claude Code | 一个启动目录（cwd）是基准，`permissions.additionalDirectories` / `--add-dir` 只扩大读写范围；相对路径按启动目录解析 | 启动目录就是主，且**不可在会话中切换**——要换就换启动位置 |
| VS Code | 多根工作区里各文件夹**平权**，没有"主"；`${workspaceFolder}` / `${workspaceFolder:名字}` 分别取，任务的 `cwd` 自己指定 | 没有主，代价是"任务到底在哪跑"要每个任务自己写清楚 |
| JetBrains | content root 可以多个，但项目只有一个项目根，运行配置的 working dir 默认取它 | 项目根 = 主 |

我们这一版走的是 Claude Code 那一路（主目录 + 额外目录），但补了两点：**允许切换**（VS Code / JetBrains 都要重启或重开工程才能换），并且切换只影响之后新建的会话（老会话 cwd 是快照，不能悄悄搬家）。

### 验证

- `tsc --noEmit` exit 0；`bu` 上控制台 0 error。
- 真点：项目卡 ⋯ → 添加文件夹 / 重命名项目 / 归档项目；工作区 ⋯ → 保存路径；附加行「设为主」→ 服务端生效、列表重排（app1 升为第一并带「主」），再点回 app2 复原；行尾 ⋯ 仍是改路径 / 从项目移除。
- 截图：`.screenshots/settings-project-primary.png`（1280@2x，带 ⋯ 与「设为主」）。

### 这条会怎么错

- **「设为主」常驻 = 每行多一个按钮**：文件夹多时行尾会有两个控件，跟"一行只留一个 ⋯"的极简目标冲突。如果实际用下来觉得吵，正解是把它做成行首名字旁的「主」徽标可点（点击即切换），而不是塞回菜单。
- **工作区 ⋯ 里只有一项**：单项菜单天生别扭。真正该做的是让路径框旁有一个"未保存"的轻提示，点 ⋯ 保存；否则用户改完路径不点菜单会以为已经生效（现在只有 Enter 能救）。
- **提案块被藏起来**：`propose_project` 是真实存在的 agent 工具，助理提议后如果用户从不打开项目页，提案就一直挂着。现在只保证"不占地方"，没解决"怎么让人看见"——将来可能要在侧栏项目区给一个点。


## 追加：第五轮（工作区保存明着摆出来）

用户原话："如果保存比较重要，你要额外做一个按钮，放在整个大块的右下角，和左上角、右上角的'添加项目'一样。如果不重要，可以自动保存，或者做一个小提示菜单，比如截完页面时提示'还没保存'。思考一下，用什么方式都可以。"

### 判断：保存是重要动作，必须显式

理由不是审美，是后果：**换掉工作区根目录会清空当前项目选择**（会话/项目跟着重置），而且它是全局唯一的入口。

- 自动保存（失焦即存）会把"路过点了一下输入框"变成一次全局重置，不能接受。
- 只做小提示（"还没保存"）等于把唯一的全局开关藏在一句小字后面。
- 折中版是「⋯ 里一项 保存路径」——第四轮做过，问题很直接：**单项菜单**，而且用户根本不会去点。

所以：**右下角一个实心「保存」**，与卡头「添加项目」同档（`.btn-primary` 实心 accent），永远可点（保存同一路径只是空跑一次，不做禁用灰态——灰按钮会被读成不可用）。改过没存时，同一行动作条左侧出一句浅灰「还没保存」（`--text-3`，`is-info`），不是红字。

桌面壳多一个软底「选择目录」（`.btn-primary.is-quiet`）：**选完只把路径填进输入框，仍然要点保存**才生效，避免开个对话框就等于重置。浏览器里没有这个按钮（读不到本地目录）。

### 改了什么

- `workspaceRowMarkup`：去掉行尾 ⋯，改成 `.proj-ws-row`（标签 + 路径）+ `.proj-ws-foot`（左：`#workspace-hint`；右：`#workspace-pick` 仅 `inShell()`、`#workspace-save`）。
- `wireWorkspaceRow`：记住 `initial` 值；`input` 事件比对后出「还没保存」；保存成功后 `loadProjectsSettings()` 重渲染，提示自然消失；Enter 仍等于保存；`选择目录` 只填值并 focus 保存。
- CSS：`.proj-card.is-workspace{padding:10px 12px}`、`.proj-ws-foot{display:flex;align-items:center;gap:8px}`、`.proj-ws-actions{margin-left:auto}`、`.proj-card-hint.is-info{color:var(--text-3)}`。
- 删掉 `#workspace-menu` 与那段 `openProjMenu` 单项菜单。

### 验证

- `bu` 上真点：改路径 → 出现「还没保存」；填一个不存在的目录 → 保存后出红字「工作区目录不存在」；改回原目录 → 保存成功后提示消失、列表重渲染。控制台 0 error。
- `tsc --noEmit` exit 0（不覆盖 `web/*.js`，语法错误只在浏览器里暴露，已用 `bu.console_messages()` 核过）。
- 截图：`.screenshots/settings-project-save.png`（已保存态）、`.screenshots/settings-project-unsaved.png`（改过未保存 →「还没保存」）。

### 这条会怎么错

- **一个按钮孤零零挂在右下角**：卡片左侧会留出一块空白。项目少的时候还行，项目多、页面变长时，这个按钮离"工作区根目录"这个标签会很远，可能又被说"不知道这按钮管哪一段"。真出现的话，正解是给工作区卡加一个卡头标题（"工作区"），而不是把按钮搬回行内。
- **永远可点 + 空跑**：用户点保存但没改任何东西，仍会弹「根目录已更新」。噪声小，但如果被抱怨，就改成"值没变就只关提示、不发请求"。
- **桌面壳两步走**（选目录 → 再点保存）比原来的"选完直接存"多一步。这一步是故意的，但确实慢了半拍。
