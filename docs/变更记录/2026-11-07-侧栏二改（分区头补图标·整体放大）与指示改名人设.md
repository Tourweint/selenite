# 2026-11-07 侧栏二改（分区头补图标 + 整体放大）与「指示」改名「人设」

用户原话：

> 「但是现在这个图标没了，字体也比较小，你把这个调大点吧。那个叫"改指示"的，你把它
> 起一个更好的名字指示啊，你把它起一个更好的名字。」

两件独立的收尾问题：上一轮统一侧栏形态时**把分区图标丢了**，字号也压得太小；
以及设置页那个叫「指示」的东西名字不好懂。

## 一、分区头补回图标 + 整体放大

### 根因（图标去哪了）

上一轮重写侧栏结构时，分区头只保留了「箭头 + 名称 + ＋」三件，图标在从旧的一体式
入口（`.side-item` 自带 svg）改成 `.sec-*` 结构时**没有跟着搬过来**。不是样式隐藏，
是 HTML 里根本没写——所以看着是"图标没了"。

### 改了什么

| 项 | 改前 | 改后 |
|---|---|---|
| 分区图标 | 无 | **20px 线描图标**（会话=气泡 / 任务=清单 / 项目=文件夹 / 执事=双人 / 群组=气泡群） |
| 折叠箭头 | 12px | **16px**，收起仍右转 -90°；颜色 `text-3 → text-2`（深色下不再先糊掉） |
| 分区名 | 12.5px / 500 / text-3 | **14px / 600 / text（主文字色）** |
| 行尾 ＋ | 20×20 命中区 / 14px 图标 / text-3 | **24×24 / 16px / text-2** |
| 分区头行高 | 28px | **34px** |
| 会话行 | 13px | **14px**（与分区头同档，靠字重/颜色分层） |
| 执事·群组·项目行 | 13px | **14px** |
| 行尾小字（人数/空闲） | 11px | **12px** |
| 「打开任务中心 →」/「管理项目 → 设置」 | 12px / 26px | **13px / 30px** |
| 空态文案 | 12～12.5px | **13px**，会话空态缩短为「还没有会话。用 ＋ 新建一条。」（原来在 232px 栏里折行） |

深色主题复核：箭头与 ＋ 原来都是 `--text-3`，在 indigo/black 下几乎融进背景；这两枚是
**操作入口**不是装饰，统一提到 `--text-2`，hover 再到 `--text`。

## 二、「指示」改名「人设」

### 为什么改

「指示」是 instructions 的直译，在中文里更像"操作提示 / 指示牌"，读不出"这个角色是谁"。
那块内容实际是：**头像 + 它是谁 + 怎么说话 + 守什么规矩**（SOUL），外加模型候选链、
例行任务，合起来正是**人设**。

### 改到的地方（只改文案，字段名不动）

- 设置左侧导航分区：`指示` → **`人设`**；
- 分区页标题与说明：「点『改人设』进弹窗…」；
- 卡片操作按钮：`改指示` → **`改人设`**；
- 版本标签：`指示 vN` → **`人设 vN`**（卡片与弹窗内两处）；
- 弹窗标题：`指示 · 阿岚` → **`人设 · 阿岚`**；
- 主按钮：`保存指示` → **`保存人设`**；正文 `aria-label` 同步；
- 校验/提示文案：「人设不能是空的。」「头像已选好，点『保存人设』生效。」；
- 注释层一并统一（历史说明保留语义，只换称谓）。

**没动**：`soul` / `soulVersion` 字段名、`PATCH /api/v1/partners/:id` 契约、存储列、
服务端任何代码。这是界面文案层改名。

## 刻意没有

- **不把「执事」也改掉**：执事是角色称谓（总管 / 执事），人设是这个角色的设定——
  两个词是不同层级，不是同义词。混成一个反而说不清"谁的人设"。
- **不改 URL**：路由仍是 `#/settings/partners`（改路由会让书签失效，收益为零）。
- **不动「环形指示」**：那是 composer 的上下文用量色环，跟人设无关。
- **不再加大到 16px**：232px 栏宽下，五个分区名 + ＋ + 箭头已经占满一行，
  再大一档「最近会话」就会和 ＋ 挤在一起。

## 验证（2026-11-07，本机 39847，Playwright 实测）

- 结构：5 个 `.sec-ico` 全部渲染（20×20），`.sec-chev` 16×16，`.sec-add` 24×24；
  分区名字号 14px，`.side-item` 14px。
- 改名链路全绿：导航「人设」/ 页标题「人设」/ 三张卡片按钮「改人设」/
  三处「人设 v2」/ 弹窗标题「人设 · 总管」/ 按钮「保存人设」/ aria「人设正文」。
- 按钮态：未改动时 `disabled=true`（浅色禁用态），改一个字后 `disabled=false`，
  实色 `rgb(62,74,140)` + 白字——之前截图看着"浅"，是禁用态而非样式缺陷。
- 四主题（paper / white / indigo / black）分区侧栏均无横向溢出；760px 窄屏仍只剩 48px 轨道。
- 侧栏回归脚本 17/17 通过；`node --check web/app.js` ✔；无 `pageerror`。

## 遗留

- 字号只到 14px（正文一档）。若还要再大，需要同时把侧栏宽度从 232px 调到 252px 左右，
  否则「最近会话」+ ＋ 会挤；那是另一个决定（侧栏宽度），本轮没顺手改。

## 三、三改（同日）：箭头挪到 ＋ 右边

用户原话：「把这个小箭头放在加号的右边吧，这样是不是好一点」。

### 改了什么

分区头行序从 `[⌄ 图标 名称] …… [＋]` 改成 **`[图标 名称] …… [＋] [⌄]`**：
箭头从「名字左边的装饰」变成「行尾的折叠把手」，和 ＋ 并肩站在右侧。

同时把两个把手的职责分开了（原来挤在一起，容易误触）：

| 点哪里 | 做什么 |
|---|---|
| 图标 + 名字 | **进这个分区**（会话=新开一条 / 任务中心 / 设置·项目 / 设置·人设 / 群组页） |
| ＋ | 新建（新会话 / 打开任务中心 / 加子项目 / 建执事 / 建群） |
| ⌄ | **只收放**，不改路由、不新建 |

- 箭头做成独立的 `<button class="sec-chev-btn">`，24×24 命中区、16px 图标，
  与 ＋ 同一尺寸同一右对齐线（实测两者 left 分别为 170 / 196，五个分区完全一致）。
- 群组未启用时，**三个入口一起禁用**（轨道圆钮 / 分区名 / ＋ / 箭头）——
  箭头是后来才独立出来的，原来的禁用清单里没有它，会留一个"点了没反应"的活扣。
  已用 route 拦截 `/api/v1/groups` 返回 404 实测：三处 `disabled=true`，title「群组未启用」。

### 为什么顺带补名字的点击

箭头还在名字左边时，"点名字 = 收起"是唯一的折叠方式，所以名字的点击被折叠占用了。
箭头挪走后如果名字不接任何动作，它就成了**点了没反应的死按钮**——比原来更糟。
因此给每个分区的名字补了明确去处（见上表），并把「最近会话」的名字定成"新开一条"，
和它的 ＋ 保持一致。

### 验证（2026-11-07，本机 39847）

- 结构：5 个分区全部是「名称 + ＋ + 箭头」，＋/箭头 left 坐标逐一相同。
- 行为：点名字 → `#/tasks` / `#/settings/projects` / `#/settings/partners` / `#/groups`，
  与期望一致，且**不触发收起**；点箭头 → 收起/展开、写 localStorage、改 hash 前后不变。
- 群组禁用链路：模拟 404 后名字/＋/箭头三者同时禁用。
- 四主题无横向溢出；侧栏回归脚本 17/17 通过；无 `pageerror`。
