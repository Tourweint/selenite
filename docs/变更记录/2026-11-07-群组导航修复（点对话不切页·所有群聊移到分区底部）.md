# 群组导航修复（点对话不切页 · 所有群聊移到群组分区底部）

> 2026-11-07。用户口径两条：
> 1. 「点击群聊之后，再点击其他的（比如点击对话），界面切换不了」；
> 2. 「现在点进群聊后，点击返回才能看到所有群聊。把『所有群聊』的按钮放在群组展开之后的底下，
>    就不要放在返回之后了」。
>
> 判定：**免写方案类**（AGENTS.md：单函数内的修正 + 文案/样式）。后端零改动、无新端点、
> 无新 env、无契约变化。

## 改了什么

### 1. 点会话行不切路由（真 bug）

**根因**：侧栏会话行的点击写的是 `openChat(conversationId)`。`openChat` 只做两件事——
换 `state.conversationId`、把历史灌进 `#thread`；**它不动路由**。视图切换在 `applyRoute()`
里，只由 hashchange 触发。所以：

- 在对话页点会话行 → 碰巧看着正常（屏幕本来就是对话页，内容就地换了）；
- 在群聊 / 任务中心 / 设置页点会话行 → 数据在背后换了、屏幕还停在原页。
  用户看到的就是「点了没反应、界面切换不了」。实测复现：点完之后 `location.hash` 仍是
  `#/group/<id>`、`data-route="group"`、`#view-groups` 未隐藏，只有 `#title` 悄悄变了。

**处置**：新增 `openConversation(conversationId)` 作为「从任何地方打开一条对话」的唯一入口——
`go("chat")` 切路由，再 `openChat()` 回读。四个调用点统一收口：

| 调用点 | 改前 | 改后 |
|---|---|---|
| 侧栏会话行（点击 / Enter / 空格） | 只 `openChat` | `openConversation` |
| 任务中心卡头 / 已完结简卡 | 手写 `go("chat")` + `openChat` | `openConversation` |
| 设置页会话搜索命中 | 手写同样两行 | `openConversation` |
| 桌面通知点击 | 只 `openChat`（在群聊页收到通知同样切不过去） | `openConversation` |

顺序不能反：先 `go("chat")` 再 `openChat()`。反过来的话 `applyRoute` 可能带着旧会话先重绘一次。

### 2. 「所有群聊」移到群组分区底部

群列表页（`#/groups`）原来唯一的入口是群会话顶栏的返回键（`#groups-back`），
用户要先「返回」才看得到全部群聊。

现在侧栏「群组」分区的展开体内，群行之后加了 `#sec-groups-all`（`所有群聊 →`），
与「对话」分区的「打开任务中心 →」、「项目」分区的「管理项目 → 设置」**同一条
`.sec-foot-link` 样式**，位置、字号、内边距逐字一致。行为：

- 点它 = `go("groups")`，落到 `#/groups` 列表态；
- 在群会话里点它同样直接回列表，不必先按顶栏返回键；
- 列表态时它带 `aria-current="true"`（浅底 + 主色，`.sec-foot-link[aria-current="true"]`），
  群会话里不高亮——它指的是那片列表，不是某一个群；
- 群组未启用（`GROUPS_ENABLED=false` / `COMPANIONS_ENABLED=false`）时跟着整节一起隐藏。

**顶栏返回键保留**：它现在只是「从群会话回群列表」的一条近路，不再是唯一入口。
两条路都能到列表，不构成两套语义。

### 3. 顺手修掉的三处位置感 / 承诺不符（同一批实测发现）

- **侧栏选中态跟着路由复位**：会话行的 `aria-current` 原来只判「是不是当前会话」，
  进了群组页还亮着（截图里群列表旁边同时亮着一条会话，看着像站在两个地方）。
  现在 `renderChats()` 里加 `currentRoute() === "chat"` 条件，`applyRoute()` 里在离开
  对话页时摘掉、回来时补上（只改属性，不重排 DOM）。
- **群组分区四个按钮的 title 被写串**：`applyGroupsAvailability()` 原来用一个循环把
  轨道钮 / 分区名 / 行尾 ＋ 的 title 全写成「群组」，＋ 按钮的「新建群组」被顺手冲掉。
  现在逐项给标题（＋ = 新建群组，底行 = 查看全部群聊）。
- **群组顶栏返回键的文案与实际行为不符**：`aria-label="返回对话" title="返回对话 (Esc)"`，
  但它一直落到「群会话 → 群列表、列表 → 对话页」；而 `Esc` 压根没绑。
  现在：文案改成「返回」，并按任务页同一套两层退法补上 Esc——群会话按一次退群列表，
  列表再按一次回对话。断言覆盖了两层。

## 验证

- `node --check web/app.js` 通过；`pnpm typecheck` 通过。
- 单测 `group-routing.test.ts` + `group-manage.test.ts` **21/21**。
- `pnpm --filter @lifediary/server groups` **全绿**（21 项，真起服务 + 真 SSE）。
- 浏览器实测（本机 39847，真实群「书房小事」+ 真实历史会话）：
  - 改前复现：群聊里点对话行 → hash 仍 `#/group/<id>`、`route=group`、`#view-groups` 未隐藏（脚本判红）；
  - 改后：`#/` + `route=chat` + `#view-chat` 可见 + 标题换成那条会话（脚本判绿）；
  - 群会话 → 点「所有群聊」→ `#/groups` 列表态，不经返回键；
  - 群会话按返回 → 仍落列表（原行为未破）；
  - 群会话 Esc / 群列表 Esc 两层退法；
  - 任务页 / 设置页 → 点会话行 → 都落到对话页；
  - 群聊 → 总管 / 执事 / 任务中心 / 设置 四个入口逐个点过，均真正切页；
  - 列表态高亮 / 群会话内不高亮 / 离开群组页后不复位残留 —— 三种态逐一断言；
  - console 无报错。

## 已知边界

- 「所有群聊」入口只在**展开态**侧栏有；收起成 72px 轨道时仍只有那颗群组圆钮
  （点它进列表态，等价）。没给轨道加第二个按钮——一列图标里再塞一个"群组列表"会分不清。
- 群会话顶栏返回键与侧栏底行并存，两条路都到 `#/groups`；没有做「按一次退一层」的
  历史栈语义（群组页本来只有两层）。
