### 为什么

用户口径（方案 §来源①）：「人设页应该给 Worker 的设置做一下，很多内容都不用……所有 Worker 用一种就行，
主要还是任劳任怨」。所以 worker 只保留一份正文：不做每会话一份、不做人格模块 / 印象心情 / 纪律覆盖 /
工具勾选。默认文案补的「任劳任怨」一句是这次的唯一字节变化——它进固定前缀，所以固定字节、顺序不改，
改它等于打掉一次上游 prompt cache（已记在此）。

**回滚**：`WORKER_PERSONA_EDIT=false` 一行让 PUT 400、界面只读；要彻底回到「常量直读」形态，
删掉人设文件即可（provider 回落默认），无需改代码。

   group_manage / save_skill_advice / partner_skill_write / propose_project / propose_topic /

   markDeferred(raw)`；既有工具描述与注册顺序一个字节未动。`tools.ts` 末尾（原 `return tools;` 之前）

4. **与工具勾选（B）协作**：`modelToolCatalog()` 不再过滤 deferred、view 每项加 `deferred:boolean`；

### 为什么

用户要省固定前缀 token：8 个管理型工具低频却每个都带完整 schema 常驻请求里。用内核原生 `deferred` +
`control.addTools`，不改基座、不引第三方；清单是代码常量（不做"自动判断低频"）。两处字节变化（section
末尾追加、`tool_search` 注册在末尾）都打在末尾、前面前缀不动，**各打掉一次上游 prompt cache**，属预期，
记在此备查。

**回滚**：`AGENT_TOOL_INDEX=false`/`0`/`off` → 不打 deferred、不注册 tool_search、不渲染 tool_index、
默认页也不含该段，一行回到 22 个全量工具；与 `PARTNER_TOOLS_ENABLED=false`（回勾选前形态）正交。

### 联调补丁（2026-11-16 同日，验收时发现并修）

真起服务实测发现三个 CodeBuddy 交付里没有覆盖的问题，均已修：

1. **取消勾选的 deferred 仍可被加载**（真 bug）：`applyPartnerToolSelection` 原来在
   「非 deferred 集合没变」时直接 return，导致被取消的 deferred 从未写进 `modelTools.remove`；
   而内核的 `agent.deferred` 是「延迟 − 已 offer」，它照样留在可加载清单里。
   现在：只要有被取消的 deferred，即使非 deferred 集合相同也写一次
   （`disabledDeferred` 判定；等值写入内核不记变更，重复写无副作用）。
   实测 39899：取消 `routine_manage` 后 `tool_search({name:"routine_manage"})` 返回
   `tool_not_loaded`，工具数 15、`tool_index` 里也没有它。
2. **`tool_index` 与 `tool_search` 都不认取消名单**：新增 `src/tool-visibility.ts`
   （`disabledToolsOfConversation` + 进程内会话种类小表 `noteSessionChatKind` / LRU 256，
   不落盘不进日志），section render 与 `tool_search` 的可用清单都按它过滤。
   单独成模块是为了避开 `partner-tools.ts ↔ lifecycle-harness.ts` 的 import 环。
3. **测试钉住了旧行为**：`partner-tools.test.ts` 原来断言「只取消 deferred 时不写」，
   正是上面那个 bug；已改成「必须写 remove」+ 新增「全开且无已加载 deferred 时不写」一条。
