> 方案：`docs/设计方案/2026-11-17-一人多会话（一主多副·插件）.md`；服务端契约见批1 变更记录。

## 复核修正（批2）

复核发现三处必修 + 一条防回归测试，已定点修正：

1. **致命：命名导入不存在（`partner-sessions-ui.js`）**。原文件从 `partners-status.js` 导入
   `renderRoster` / `rosterDomain` / `syncChiefSessionsButton` / `chiefDisplayName` /
   `partnerDisplayName`，其中 `renderRoster` 并未被 `partners-status.js` 导出（它只是自己
   import 来用）——浏览器会报 `does not provide an export named 'renderRoster'`，整页白屏，
   而 `node --check` 查不出。修法：删掉对 `partners-status.js` 的全部导入（同时解掉一条循环依赖）；
   人设名改用本地 `displayNameOf()` 从 `state.partners` 取（chief 缺省「总管」、执事缺省「执事」）；
   `onSideSessionsDisabled()` 改为直接 `document.querySelectorAll(".roster-sessions, .chief-sessions")`
   移除按钮 + 清顶栏可点态，不再回写花名册。

2. **忙因 / 待办归属回归（`partners-status.js`）**。`partnerPendingCounts` 用
   `partnerIdOfConversation()` 时，`partner-<id>-group-<gid>` 返回 `""`（那是"执事专线选中态"的口径），
   群成员轮的待办不再算到该执事头上。改用 `parsePartnerExternalId(id)?.partnerId`，
   canonical / side / group 三种形态都算，恢复改动前口径。

3. **选择器竞态（`partner-sessions-ui.js`）**。`openModal` 复用同一个 `el.modalBody`：
   A 的 `/sessions` 请求未回就关掉再开 B，A 回来时 `modalOpen()` 为真，会用 A 的内容覆盖 B
   （A 的 400 分支甚至会关掉 B）。加模块级 `pickerGeneration`，每次打开递增；所有 `await`
   之后、`closeModal()` / `toast()` / `replaceChildren()` 之前统一 `gen !== pickerGeneration || !modalOpen()`
   判过期，过期响应直接丢弃；`onSideSessionsDisabled()` 只在当前 generation 的分支里执行。

4. **防回归测试**：新建 `src/web-imports.test.mjs`（node:test，无第三方依赖），扫描 `web/*.js`
   的命名导出（`export function/const/...`、`export { a, b as c }`、`export { ... } from "./x"` 转出），
   逐一核对相对命名导入是否能找到；忽略非相对路径 / `import * as` / `default`，缺口一次列全。
   已加入 `apps/server/package.json` 的 test 清单；当前扫描结果 **0 条缺口**。

复核后验证：`pnpm typecheck` 通过；`pnpm --filter @lifediary/server test` 1136 项 /
1131 通过 / 5 失败（既有 5 红照旧：arch-guard 3、auxiliary split、partner-work EPERM）；
所有改过的 web JS `node --check` 通过。未提交、未 push、未碰服务端逻辑。

## 浏览器验收修正

真实浏览器验收又发现四处，已定点修正（本批收尾）：

1. **总管选择器空会话噪声（服务端，`companion-api.ts`）**：`GET /partners/chief/sessions`
   的 `listChats(200, true)` 把 21 条 `turns=0` 的历史空壳全列出来，选择器一片「新会话」。
   加 `.filter((chat) => chat.turns > 0 || Boolean(chat.title))`：有标题的空会话保留（用户可能刚建并命名），
   无名空壳不显示。`includeEmpty=true` 本身保留——它只为让"刚建且命名过"的空会话可见。
2. **主对话行不显示首句原文（`partner-sessions-ui.js`）**：真实数据里主行标题是
   `[Scheduled run context]\nturnAuthority: a` 这类系统指令原文。主行名字固定「主对话」；
   次要信息改为 `turns > 0 ? "N 轮 · 相对时间" : "还没开始"`；不再用 `partnerSessionLabel()` 取 firstText。
3. **副会话空行重复「新会话」（`partner-sessions-ui.js`）**：名字已是「新会话」时 meta 又写「新会话」。
   现在只在 `turns > 0` 时 append meta（"N 轮 · 相对时间"），`turns === 0` 不挂 meta。
4. **首条消息覆盖顶栏人设前缀（`composer-send.js`）**：`firstTurn` 时无条件写 `text.slice(0, 40)`，
   副会话顶栏从「小记 · 新会话」变成纯标题。改为先 `parsePartnerExternalId(state.conversationId)`：
   side → `${partnerDisplayName(partnerId)} · ${label}`；canonical → 不改（保持人设名，loadRoster 兜底）；
   其它（worker / chief / 无 partner）→ 维持原逻辑 `label`。

验证：`pnpm typecheck` 通过；`pnpm --filter @lifediary/server test` 1136 项 / 1131 通过 /
5 失败（既有 5 红照旧）；改过的 web JS `node --check` 全过；`web-imports.test.mjs` 0 缺口。

最后两处身份解析残留：`web/approval-card.js` 的 `approvalSourceLabel()` 改走
`parsePartnerExternalId()`（保留最前面的群成员解析），canonical / side 都显示真名，不再切出
`id-side-token`；`web/settings-context.js` 的 `partnerIdOfChat()` 同样改走解析器，
副会话的上下文页执事名与「去档案页」链接不再落空（同名会话仍靠补时间消歧）。

**验收补刀（2026-11-17，验收方）**：刷新时名册晚于会话加载，副会话顶栏会先写成
「执事 · 标题」；`loadRoster` 原来只回补 canonical。已扩到 side（用 `state.chats` 的标题或
现有标题尾巴重建，并重挂可点态），刷新后稳定显示「小记 · …」。
