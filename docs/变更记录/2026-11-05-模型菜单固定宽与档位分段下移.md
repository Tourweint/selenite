# 2026-11-05 模型菜单固定宽 · 档位分段下移（纯前端零契约）

## 问题（用户报障 + 实测复现）

composer 的模型菜单弹层宽度是**内容自适应**（`min-width: 240 / max-width: min(380px, 88vw)`），
切供应商时整个列表换内容，弹层宽度跟着最长模型名、当前行档位分段的有无跳变。
用户观感是「切换不同供应商时，小框的左右间距会变化」。

实测（2026-11-05，39847 实机，1280 视口）：

- magpie（当前行带 4 档分段，最长名 sensenova 全名 269px）→ 弹层 **307px**；
- 百炼（当次无选中行，最长名 172px）→ 弹层缩到 **240px**。

附带两个同源小毛病：

- 当前行「模型名 + 分段」横排，分段（~103px）挤占行宽，长模型名被压出省略号；
- `data-current` 写的是 `"true"/"false"`，而 `syncThinkingSegments()` 和选中后焦点回位
  选择器都按 `"1"` 找——**两处从未命中过**（选中态其实靠渲染时顺手 set 才看起来正常，
  焦点回位则一直失效）。

## 处置（用户两案取一案一：宽度不再变；分段出现补了轻动画）

- **弹层宽度钉死 `width: min(320px, 88vw)`**：切供应商只换内容不改框。
  320 容得下当前最长模型名（实测含内边距 ~297），更长的名字照旧省略号截断。
- **档位分段从当前行名字右边挪到下面一行**（`.model-row[data-current="1"]` 改纵排）：
  行宽只由模型名决定，换模型 / 换供应商时行内左右间距不再跳，长名字不再被压窄。
  交互口径不变（思考档位方案 D2：分段只属于当前模型行，先选模型再选强度）。
- 分段出现时 160ms 轻落淡入（60ms 后起、与弹层 220ms morph 同拍收），换档位只改
  选中态不重建节点、不会反复播；`prefers-reduced-motion` 下不播。
- **窄屏（≤560px）**：固定 320px 贴 pill 左缘会探出视口。断点里让 `.composer-wrap`
  让出定位，弹层改锚整张 composer 卡（`.composer` 是定位祖先），`width: min(320px, 100%)` 按卡收。
  **教训：这个断点块必须排在 `.model-menu` / `.composer-wrap` 本体定义之后**——
  同权重时后者赢，放前面会被顶掉（首版放进了任务区的 560px 块，实测没生效）。
- `data-current` 统一写 `"1"/"0"`，修活 `syncThinkingSegments()` 与焦点回位。

## 不做

- 不做弹层宽度补间动画：宽度已恒定，没有可动画的变化量（用户方案 2 由此失去对象）。
- 不动契约、不动档位语义与 D2 交互口径、不动供应商分段行。

## 验证（2026-11-05 实机 39847，真浏览器量测）

- magpie / 百炼 两家弹层均 **320px**，切家时框边不动；
- 当前行 66px：模型名一行、分段落下方且与名字左对齐，长名（269px）不再截断；
- 键盘路径：回选当前模型后焦点回到该行 `.model-item`（修复前丢失）；
- 390 视口：菜单 308px（按卡收）、右缘 373 < 390，整体悬在 composer 上方不遮不溢；
- 回选用的是**当前模型本身**（同模型回选），服务端当前模型未变；
  验证产生的 `lifediary.modelProvider` 偏好为百炼，打开菜单仍优先当前供应商（magpie），无用户可见影响。

## 第二轮（同日用户反馈三件）

用户确认方向可用后追加了三件，参考两家的做法（cindy / ZCode 源码调研，2026-11-05）：

1. **弹层定住，不受底下模型名伸缩带动**。根因：弹层贴 pill **左缘**锚（`.composer-pop { left: 0 }`），
   换模型 pill 文字一变长/变短，左缘就跑，弹层跟着拖。参照 cindy `MorphPopover align="end"`
   （`morph-popover.tsx:319-333`：面板右缘锚 chip 右缘，内容加宽向左扩）——pill 右缘挨着发送键是稳定的，
   改 `.model-menu { left: auto; right: 0 }`。实测 pill 316↔222 伸缩，弹层右缘/左缘坐标一字不动。
2. **选中行去掉 ✓**。同 cindy `UnifiedModelRow.tsx:344-346` 行内注释的裁决（Chris 2026-08-13：
   选中已有整行强调，再加勾是重复信号还吃宽度）；我们这边选中态 = 强调色 + 加粗 + 档位分段。
   删了 `.model-check` 渲染与样式。
3. **切模型的小动画**。抄 ZCode `RollingToolbarLabel.tsx`（motion/react 版）：pill 文字
   **旧字向上滚出淡去、新字从下方滚入**，200ms / `cubic-bezier(.4,0,.2,1)` / 0.75em，同拍。
   vanilla 实现：`#model-pill-label` 外层当裁切罩，内层 `.pill-label-text` 播进出两段 keyframes，
   exit 用 absolute 盖原位；`animationend` 收尾 + 300ms 定时器兜底；文字没变不播；
   `prefers-reduced-motion` 双侧（JS 早退 + CSS 归零）都不播。

### 本轮验证（2026-11-05 实机）

- 切 group/cheap（pill 316.4→221.8）再切回 codearts/deepseek-v4.1-flash（→316.4）：
  弹层 x=848 / 右缘 1168 两次完全一致——框定住了；滚动动画进行中抓到 enter/exit 双字在播，
  结束后 DOM 收干净（一次观测到兜底定时器被后台节流拖晚，最终态正确）；
- `.model-check` 全菜单 0 个；测试后模型已切回用户所选（codearts/deepseek-v4.1-flash）。
