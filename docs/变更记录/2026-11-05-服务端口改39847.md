# 2026-11-05 服务端口 8082 → 39847

## 改了什么

默认监听端口从 `8082` 换成 `39847`（冷门端口，避开常见开发端口与 Windows 动态端口区 49152+）。
`PORT` 环境变量照旧可覆盖，接口语义、配对流程、存储结构一律不动。

逐处：

- `ts/apps/server/.env` / `.env.example`：加 `PORT=39847`（示例文件补了「冷门端口，防撞车」注释）。
- `ts/apps/server/src/index.ts`：两处兜底默认值 `process.env.PORT ?? 39847`
  （`currentPort()` 用于配对二维码，末尾 `serve()` 用于监听；两处必须同值）。
- `desktop/main.go`：`defaultBaseURL` 改 39847（注释同步）；`LIFEDIARY_BASE_URL` 覆盖机制不变。
  `desktop/lifediary-shell.exe` 已按 `go build -ldflags="-H windowsgui"` 重编（否则双击壳仍探 8082）。
- `ts/apps/server/scripts/smoke.ts`：`SMOKE_BASE_URL` 的兜底值改 39847。
- 文档：`docs/基线文档/接口文档.md`（基址 + §6 `PORT` 行）、`docs/基线文档/系统架构.md`、
  `ts/README.md`、`ts/docs/auth.md`、`desktop/README.md`。

## 为什么改

8082 太热门，本机同时开几个开发服务就会撞端口；39847 落在注册端口区间内且不与常见工具冲突。

## 没改的

- `docs/变更记录/`、`docs/设计方案/` 里的旧 `8082`：那是当时的事实，保留不动。
- 各探针（http / task / phone / providers / settings / diary / approval / thinking / delegate-*）：
  本来就走 `PROBE_PORT` 或各自的固定端口（8097/8098/8106/8190/8193…），不读 8082，无需改动。
- 手机端仓库（`<lifediary 手机仓>`）不动；配对地址由服务端按实际端口生成。
- `.data/` 与端口无关，不迁移。

## 顺带发现（未处理）

`ts/apps/server/.env` 当前没有被任何启动脚本加载（`dev`/`start` 都是 `tsx src/index.ts`，
代码里也没有 `dotenv` 或 `--env-file`）。所以实际生效的端口来源是
「shell 环境变量 → 源码兜底值」；`.env` 只有在启动前被显式 source / 由启动器注入时才起作用。
本次把源码兜底值一并改成 39847，正是为了让没加载 `.env` 的场景也落在新端口上。
