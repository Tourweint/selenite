# 统一确认框与宋体正文

日期：2026-11-13
状态：已落地（桌面端 web；服务端无契约改动）。

## 起因

用户口径（2026-11-13）：重启时弹的原生窗口要美化；页面里还有很多这种弹窗；
字体换成宋体，或者用壳子自带的字体。

## 改了什么

### 统一确认框：原生 confirm / alert 退役

- 新增 `openConfirm({ title, message, detail, confirmText, cancelText, danger })`：
  复用现有 `.modal`，返回 `Promise<boolean>`；确认 = true，取消 / 遮罩 / ✕ / Esc = false。
- 新增 `showAlert(title, message)`：单颗「知道了」，替换原生 alert。
- 确认框视觉：左侧 34px 圆角图标（普通 = 问号 + accent，危险 = 叹号 + `--c-error`），
  右侧标题 / 说明 / 次要提示；危险动作只用图标和确认钮的红，不铺整块红底。
- 替换全部 9 处原生 `window.confirm` / `confirm`：导入记忆、标记忆过时、删除记忆、
  停止服务、重启服务、移除搜索源、移出群成员、改全员回、删除群组；以及 2 处 `alert`
  （停止失败、开机自启失败）。
- `openModal` 增加可选 `onClose`，`closeModal` 在真正收起时回调；确认框靠它处理
  遮罩 / ✕ / Esc 的取消路径（不会悬着不 resolve）。

### 字体：全文宋体

- `--font` 从系统无衬线（Segoe UI / 微软雅黑）改为宋体优先：
  `"Songti SC", "Noto Serif SC", "Source Han Serif SC", "STSong", "SimSun", "Microsoft YaHei", serif`。
  Windows 落 SimSun，macOS 落 Songti SC / STSong；都没有才落系统衬线。
- `--font-display` 直接复用 `--font`；层级靠字号 / 字重 / 字距，不再维护第二套字体。
- `select` 补进 `button, input, textarea { font: inherit }` 一组，避免下拉框还停在 UA 字体。
- 代码 / 路径仍走 `--mono`，没有改成宋体。

## 刻意没做

- 没有改桌面壳的原生消息框（托盘退出、熔断提示走 MyGo `Dialog.Message`，OS 画，
  CSS 管不到）；这次只收页面内的弹窗。
- 没有加字体设置项：目前只有一套宋体口径，真需要再立"外观 → 字体"。

## 验证

- `node --check ts/apps/server/web/app.js` 通过；`style.css` 花括号配平。
- 浏览器实机（IAB，当前 39847 静态资源）：设置 → 项目页宋体生效、侧栏「归档」正常；
  打开「删除记忆」确认框，图标 / 标题 / 说明 / 取消 / 删除按钮与遮罩层显示正常，
  取消后弹窗关闭。

  「仅桌面端可操作」，未在壳内点按；代码路径与删除确认共用一份）。
- 未跑服务端单测 / 探针：本次只改 web 静态资源与文案样式，无 TS 契约改动。
