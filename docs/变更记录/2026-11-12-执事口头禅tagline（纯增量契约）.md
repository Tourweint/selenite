# 执事口头禅 `tagline`（纯增量契约）

日期：2026-11-12
上位：《2026-11-12-方案（手机对话身份与顶栏设置收敛）》§四（批 B）。
范围：harness 仓；手机仓未动。

## 改了什么

- **契约**：shared `PartnerProfileSchema` 增可选 `tagline: string | null`；`docs/基线文档/接口文档.md` §2.11 回写。
- **存储**：`partners` 表加 `tagline TEXT`（旧库 `PRAGMA` + `ALTER TABLE` 补列，老行读 `null`，不补数据、不版本化）。
- **端点**：`POST /api/v1/partners` 建档时可直接带 `tagline`（与 PATCH 共用同一份 `parseTagline`：trim 后按 Unicode code point ≤40 字；`null` / 空串 = 不设；非法在建档前 400，不留半建档案；响应投影带 `tagline`）；`PATCH /api/v1/partners/:id` 接受 `tagline`（`null` / 空串 = 清除；省略 = 不改；非法整批 400、不写）；`GET /api/v1/partners` 与 `GET /api/v1/partners/:id` 投影都带 `tagline`（未设置给 `null`）。
- **测试**：companion-api 覆盖 POST 建档带 tagline → 响应/列表/详情读回、非法不建档；PATCH 设置 → 列表/详情读回 → 清除 → 超长/非法 400 且旧值不变 → 老库缺列迁移；partner-relay 的 `PartnerRow` 夹具补 `tagline: null`。

## 刻意不做

- 不版本化：不 bump `partner_versions`、不动 SOUL / 契约；不新增 env（空 = 不显示，天然回滚）。
- 不做「建完再 PATCH」的两段式：新建时填的口头禅随建档一次落库，避免中途丢失。

## 验证

- `pnpm typecheck`：0 错。
- `pnpm --filter @lifediary/server test`：764 pass / 0 fail（含本次新增 3 条 tagline 用例）。
