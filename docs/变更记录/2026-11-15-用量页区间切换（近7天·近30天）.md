# 用量页区间切换（近 7 天 · 近 30 天 · 全部）

承接 `docs/设计方案/2026-11-13-用量页版式（ZCode累计条·Cindy明细）.md`。
那份方案当时判「区间切换不用」，理由是 `pi.usage` 只有按会话的累计快照、没有逐日流水。
**这个前提只对 `pi.usage` 成立**：每条 `pi.assistant` 的 `model[0]` 自带 `timestamp` 与 `usage`，
把本机会话的 entry 扫一遍就能还原每一天——只读，不新增存储、不做每日快照。

## 改了什么

**1. 服务端聚合（新增 `src/agent/usage-range.ts`）**

- `usageSampleOf(entry)`：`pi.assistant` → `{at, model, usage}`；`model` = `provider/modelId#variant`，
  与 `pi.usage.models` 的 key 同形；没时间 / 没用量 / 非 assistant → 跳过。
- `startOfUsageWindow(days, now)`：本地日历日口径。近 7 天 = 今天与之前 6 个自然日，
  从第 1 天 00:00 起算；**不是"现在往前推 168 小时"**——按小时推，同一天上午与下午看到的数会不一样。
- `aggregateUsageWindow(samples, since)`：只收窗口内、按模型合并、数活跃日；
  累计 0 的模型不进区间表（`lifediary.say` 这类播报列出来只是多一行 0%）。
- `usageInWindow(days)`：从 `Chats.byExternal` 逐会话 `conversation.entries()`，单会话读失败只跳过它。
  **fork 子会话的 `entries()` 会从父会话 fork 点接着往前读**（durable 的 fork 是引用不是复制），
  逐会话相加会把父会话那段 assistant 再算一遍；用全库唯一的 entry id 去重，不依赖遍历顺序。
  代价与 `searchSessions` / `listChats` 同口径；实测本机 74 个会话、499 条 assistant：100ms（冷）/ 31ms（热）。

**2. 汇总入口（`src/agent/session-transcript.ts`）**

- `usageSummary({days?})`：不带参数 = 原行为（`harness.usage()` 的 `pi.usage` 累计）；
  `days: 7 | 30` → `usageInWindow`，返回 `range` / `since` / `activeDays`。
- `UsageSummary` 增 `range`、`since?`、`activeDays?` 三个字段；`models` 形状不变。

**3. 端点（`src/index.ts`）**

- `GET /api/v1/agent/usage?range=7d|30d`；不带或未知值 = `all`。旧客户端零改动。

**4. 前端（`web/settings-usage.js` / `web/settings-router.js` / `web/style-10-tasks-detail.css`）**

- 节标题从「累计用量」改为「用量」，右侧加分段控件（近 7 天 / 近 30 天 / 全部）+ 刷新，同一行。
- 档位存 `localStorage["lifediary.usage.range"]`，默认 `7d`；换页/重进保持上次选择。
- 三张卡（累计条 / 按模型 / 明细）跟着区间一起重算；注脚写清区间起止与"有几天产生用量"。
- 空态分两种：`all` →「还没有用量」；区间 →「这段时间没有用量，切到全部看历史」。
- 连点档位时用请求序号，只让最后一次响应落地。
- 复用 `settings-atoms.js` 的 `mountSegmented` / `syncSegmented`（滑行胶囊），不新造控件。

**5. 探针（`scripts/http-probe.ts`）**

§4 加 5 条 check：`7d` 回显 `range`、带 `since`、刚跑的对话算进区间；`30d` 回显 `range`、有记录。

## 口径（写进页面注脚的那几句话）

| 项 | 规则 |
|---|---|
| 窗口 | 本地自然日，含今天；7d = 今天 + 前 6 天，30d = 今天 + 前 29 天 |
| 归日 | assistant 回复的 `timestamp`（完成时间），不是提问时间 |
| 来源 | 逐条回复自带的 usage；没有逐日账本 |
| 删会话 | 三档都会跟着少——账记在会话上，和原口径一致 |
| 金额 | 仍不折算（服务端 `cost` 恒 0） |
| 零用量模型 | 区间档不显示（`lifediary.say`）；`all` 保持旧样子 |

## 刻意不做

- **逐日日柱 / 热力图**：这一版只做三档切换；日图要另设计（30 天窗口里当前只有 6 天有数据，画出来大半是空柱）。
- **每日快照 / 事件流水落库**：不需要。entry 自带时间戳，读时还原即可；真到扫不动的规模再立项。
- **按会话 / 按任务维度**：仍不做（要逐会话开 session，成本高）。
- **新 env 开关**：这是只读筛选，且旧契约（不传 `range`）字节不变；回滚形态 = 不传 `range`，
  前端把 `lifediary.usage.range` 设为 `all` 即回到旧的单视图。没有另加 env 的价值。

## 验证

- **单测**：`npx tsx --test src/agent/usage-range.test.ts` → **6 通过 / 0 失败**
  （窗口切法、跨天合并、窗口外排除、0 用量模型、entry → 样本、本地日键）。
- **真库只读探针**（`sqlite3.backup` 复制一份 `agent.sqlite` 再开 harness，不动正在跑的服务）：
  - `7d`：**669,311** tokens / 4 个活跃日 / 5 个模型档位
  - `30d`：**2,494,648** tokens / 6 个活跃日 / 11 个模型档位
  - `all`：**2,494,648** tokens / 11 个模型档位
  - 与直接 SQL 聚合 `entries` 的预期**逐模型完全一致**；`all` 与 `pi.usage` 文档求和也一致。
  - 扫描耗时：100ms（冷）/ 31ms（热）。
- **HTTP 探针**：`pnpm --filter @lifediary/server http` 的 §4 六条 check 全绿
  （含原「有用量记录」）；**该探针在 §11 之后的「重启进程切供应商」段落失败**
  （`服务没能启动`，dummy-key 供应商重启步骤），与用量无关；失败点在用量断言之后。
- **类型检查**：`tsc --noEmit` 只报仓库里既有的 `PartnersStore` 改动错误
  （`partner-context` / `chief` / `partner-store` 等 20 余处），本次新增/修改文件不在错误列表里。
- **前端语法**：`node --check settings-usage.js settings-router.js` 通过。
- **真实界面（headless Edge + 隔离服务 + 复制库，1280×960）**：
  - 首屏默认「近 7 天」：**669,311** / 1 个模型 · 5 个档位 / 注脚「11-09 至 11-15 · 4 天有用量」；
  - 点「近 30 天」：**2,494,648** / 4 个模型 · 11 个档位 / 注脚「10-17 至 11-15 · 6 天有用量」；
  - 点「全部」：**2,494,648** / 同上，注脚回到 `pi.usage` 口径；
  - 点回「近 7 天」：数字回到 669,311；
  - 每次点击后 `localStorage["lifediary.usage.range"]` 依次为 `30d` / `all` / `7d`，滑行胶囊与 `aria-checked` 同步。

## 已知边界（未做 / 未验证，2026-11-15）

- **617 级窄窗没实拍**：分段控件复用现成的 `.segmented.slide`，样式只加了三行
  （24px 高、10px 内边距、节标题负外边距）；1280×960 已实拍，617 宽度只有算术（约 314px，能放进内容区）。
- **压缩过的会话**：`conversation.entries()` 是 fork-aware 历史；如果某会话被压缩后旧条目不再可见，
  区间数会少算那一段。当前库没有压缩条目（`pi.compaction` = 0），暂未触发。
- **fork 去重没有实测**：按 entry id 去重的代码路径已写，但当前库 fork 数 = 0，没造一个真 fork 验证；
  如果将来 fork 语义变化（子会话不再继承父条目，或 id 不再全库唯一），这里要重看。
- **工具消耗**不在本页口径：只算 assistant 模型；`pi.usage.tools` 本来就没展示。
- **默认档变化**：首次进页面从「全部」改成「近 7 天」；老用户会先看到较小的数，
  点「全部」即可回到旧视图（这是这次需求的本意，但在支持渠道里要说一句）。
