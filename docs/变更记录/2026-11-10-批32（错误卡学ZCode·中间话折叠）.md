# 批 32：错误卡（学 ZCode）+ 中间话折叠（只留结尾）

日期：2026-11-10
状态：已落地（typecheck ✅ / 744 单测 ✅ / http 探针 ✅ / 浏览器真 error 帧实测 ✅；历史 say 步回放按代码审查，待真模型验收顺手看一眼）

## 起因

用户口径（2026-11-10）：**"上游会返回错误信息，前端要做一个小标注、附一个小卡片，就在对话框上面；
再看 ZCode 怎么做的，学它前端交互体验。"** 两件事：

1. **错误卡**：MyGo 以前把错误往消息流里插一行红字（`.msg.error` + 重试按钮）。问题：正文被挤乱、
   滚动跳位、重试按钮悬在流里没有归处；而且服务端只发一句笼统的「生成失败，请稍后重试」，
   看不出是限流、密钥还是连不上——三种错三种动作，全靠猜。
2. **中间话折叠**：模型一轮里常先说话再动工具（"我先看看这个文件…"），这些中间话以前全堆在正文里；
   ZCode 的做法是**只把最后一段正文留在折叠区外面**，之前的过程（含中间话）全收进折叠头。

## 学 ZCode 学到什么（`<reference>\ZCode`，2026-11-10 核对）

- **`ChatErrorBanner`（packages/ui/src/ChatErrorBanner.tsx）**：一行摘要 + 动作按钮（详情 / 复制 /
  反馈 / 重试 / ×）；**详情才进独立 Dialog**——它的注释写明理由：内嵌展开会把消息区撑高、聊天滚动跳动
  （我们实测前也踩了：第一版放外部静态流，composer 是绝对定位，卡直接叠在它上面）。
  稳定 `code` 决定动作分支，不解析 message 文案。
- **轮次收折（packages/ui/src/v4/ConversationTurnGroup.tsx + conversationTurnWorkSegments.ts）**：
  `assistantHistory`（工具行 + 中间正文行）全部进 `Collapsible`，头行「已工作 Xs」；
  `assistantText`（最后一段正文）留在外面。`visibleAssistantTextRow` 之后的行跟着外置。
  我们已有的「工作过程」块与其同构（2026-11-07 就是对齐它做的），这次只补"中间话"这一块。

## 改了什么

### 服务端

- **`shared`（契约，纯增量两处）**：
  - `error` 帧加 `code?`（`StreamErrorCode`：rate_limited / auth / timeout / network / context_overflow /
    model_error / unknown）与 `detail?`（脱敏摘要）。
  - `TranscriptStep` 加 `format?: "md"`（「说」步的渲染档）。
  - `packages/shared/src/snapshot.test.ts` 的 STEP_SHAPE 快照同步（契约快照的职责就在这）。
- **新文件 `apps/server/src/stream-error.ts`**：纯函数分类器。
  `describeStreamError(reason, detail)` → `{code, message, detail?}` | `null`：
  - `aborted` / `reset` → `null`（人自己停的，前端已有「已中断生成」，再报就是报二遍）；
  - `no_model` → `auth`（动作都是"去设置页"）；
  - `model_error`（及其它 reason）读原文关键词分类（限流/密钥/超时/连不上/上下文超长/兜底 model_error）；
  - `detail` 三步脱敏：`redactSecrets`（memory 包的凭据打码）→ 剥上游主机（留路径形状）→ 截 400 字符。
  **原始上游错误绝不下发**（可能带 key 片段），完整原文照旧只进服务端日志。
- **`agent/session.ts`**：`unanswered` 收尾从一句笼统话改为走分类器；`ChatStreamEvent` 的
  `unanswered` 成员加 `code?/detail?`。`aborted/reset` 现在**不发** unanswered 帧了。
- **`index.ts`**：`unanswered` 透成 `error` 帧时带上 `code/detail`；外层 catch（服务端自身异常）
  也走同一分类器。
- **`readTranscript`**：带工具调用的中间回合，`toolCall` 之外的正文块收成一步
  `{"name":"say","ok":true,"format":"md","output":…}`（以前直接丢掉，历史回读看不到这段话）。
- 单测 `stream-error.test.ts` 9 项：aborted 不发 / no_model 归 auth / 限流中英文 / key 打码 /
  超时与连不上分开 / 上下文超长 / 认不出归 model_error / 地址剥主机 / 截断。

### 前端（web/ 三件套）

- **错误卡**（`#chat-error`，在 composer 容器卡内部第一格、textarea 上方）：
  一行摘要 + 详情（进现有 `openModal` 小窗）/ 复制（明说"已脱敏"）/ 重试 / ×。
  `addError()` 改为驱动这张卡（签名兼容，`opts.detail` 新增）；流内红字行退役
  （`.msg.error` CSS 保留——执事打开失败卡还在用）。
- **退场时机**：切会话（`clearThread`）/ 发出新消息（`send` 开头）→ `hideChatError()`。
  同一轮接连报错后到覆盖先到。重试动作会顺带关卡。
- **中间话折叠（现场路径）**：`send()` 里工具 start / 派活帧到达时，`answer` 里已累积的正文
  折成工作过程块的一行「说」（`panel.say()`，图标 = 气泡引号），正文清零等下一段——
  **正文区从此只留最后一段回答**。刻意等"动手"才折：纯说话的轮次一段到底，不折腾。
  展开块 `format:"md"` 按 markdown 渲染（`.wp-pre-md`），不用 pre——列表加粗不该显示成星号。
- **中间话折叠（历史路径）**：`workPanelFromSteps` 认 `name==="say" && format==="md"`，还原成同一行。

## 踩的坑

1. **composer 是绝对定位（`bottom:14px`）**：错误卡第一版放在外部静态流里（composer 标签前），
   实测直接叠在 composer 上（`diff:-90px`）。修正：卡放进 composer 容器卡内部第一格——
   观感与 ZCode「横幅在输入框上方」一致，还不占外部流。
2. **faux 探针的两副面孔**：`LLM_FAUX_TOOL=1` 会永远调工具（验证回合上限用）；测错误卡
   重启时忘了摘，整条流全是 bash。另外 **faux 队列耗尽后**的失败正好产出真实
   `model_error` + `errorMessage` 原文，反而成了错误卡/详情弹窗的天然验收素材。
3. **`LIFEDIARY_DATA_DIR` 不是真 env**：验证服务写库的位置跟 cwd 走。本次验证服务落在
   `ts/.data/`（gitignored，独立库），**没有**碰用户真库 `apps/server/.data/`（已核对今天只有
   用户自己的两条会话）。以后起隔离验收实例要么 cd 到独立目录，要么改用 AGENT_*_PATH 全套。
4. **ego-browser 的 `page.waitForFunction`**：options 必须是第三参；`.modal` 的关闭动画 100ms，
   waitForFunction 紧跟 click 会竞态，sleep 800ms 再断言。

## 刻意没有

- **不做自动重试/自动降级**：错误卡只报错 + 给动作，不替人决定"等 30 秒再试一次"。
- **不做按 code 的差异化图标/配色**：一律错误红；`code` 先把口子留在契约上，UI 需要时再接。
- **不给 faux 加"错误响应"env**：本轮用队列耗尽的自然失败完成验收；真要钉分类器的分类正确性，
  单测已覆盖（分类是纯函数，不依赖真上游）。
