# 思考块并入工具灰块（退役独立思考折叠卡）

**日期**：2026-11-17。
**范围**：只动前端呈现，不碰契约、不碰服务端事件（thinking 事件形状不变）。

## 背景

E1 之后工具的呈现只有一种形状：24px 灰块，icon + 动词 + 目标，跑完打勾；
步数、耗时、命令、输出、diff 全在点击后的详情里，主界面不写"几步/几秒"。
思考还留着 2026-11-04 的另一套：消息最顶上、`<details>` 展开式折叠卡、
流式中 summary 跳秒"思考中… Ns"。同一轮里两套形状并排，思考那条还固定钉在
消息顶上——哪怕它其实发生在两次工具之间，位置也是假的。

用户 2026-11-17 口径：思考也做成工具灰块那样。

## 怎么定的

| 项 | 决策 | 理由 |
|---|---|---|
| 形状 | 和工具同一枚 `.tchip`（24px、等宽字体、运行中 accent + 扫光、完成打勾） | 同一类"工作过程"只留一种形状；用户点过一次就认得 |
| 文案 | 灰块只写「思考」，不写秒数 | 与 E1「主界面不写几步/几秒」同一条规矩；原来跳秒是在反复提醒"你在等" |
| 时长 | 进详情「用时」一行 | 想知道的人点开就有，不想知道的人不用被计时器催 |
| 正文 | 进详情，限高 260px、内部滚动 | E1 原有的两条硬约束（限高、超过 8 块收进「+N」）原样覆盖思考 |
| 位置 | 插在 `.flow` 里，按真实发生顺序排；与相邻的连续动作为同一组 | 原来 `prepend` 到消息顶是"假位置"；现在"思考 → 工具 → 说话"就是读到的顺序 |
| 定格时机 | 第一句正文开写、或第一次动手（工具 / 派活）之前 | 用时只算思考本身，不把后面几十秒的工具执行算进"思考 40s" |

## 改了什么

- **`web/tool-meta.js`**：新增 `think` 图标（四角星）——11px 下比脑子线条更认得出。
- **`web/tool-flow.js`**：新增 `think()`：同一组里 push 一枚「思考」块，
  返回 `append(增量)` / `finish()`；`finish()` 落「用时」并定格（落到**创建它的那一组**，
  中途被 `breakGroup` 切走也不丢终态）。
- **`web/tool-chips.js`**：详情卡认 `kind: "think"`（标题「思考」、状态「思考中」→「完成」、
  不画「命令」行、正文小标题「过程」——卡头已有「思考」，不重复）、新增 `__streamText`——流式中只改已打开面板的
  那段文本并跟到底部，不重建卡（重建会冲掉滚动位置和选中文字）；`settle` 补写
  `spec.state` 并统一走 `__refresh`（顺手修了"块上画失败、面板还写运行中"的旧偏差）。
- **`web/composer-send.js`**：删掉 `<details class="think">`、`setInterval` 计时与
  `prepend`；thinking 事件改走 `beginThink() / append() / endThink()`。
  `breakForTool` 改名 `breakForWork`（工具、派活、思考共用同一套"封口 + 另起一组"）。
- **`web/style-05-message-extras.css`**：`.think / .think-orb / .think-body` 规则整段退役，
  原地留一行说明。
- **`web/style-21-answer-memory.css`**：气泡模式里的宽度规则只留 `.tchips-wrap`
  （思考块已在其中），不会再有"比气泡宽的黑边"。
- **`qa/thinking-chip.check.mjs`**：新增浏览器验收（见下）。

## 验证

- `node --check`：`tool-meta.js / tool-chips.js / tool-flow.js / composer-send.js` 全过。
- `pnpm typecheck`：exit 0（前端 `web/*.js` 不在 tsc 范围，靠下面的浏览器验收兜）。
- 浏览器验收：`BASE_URL=http://127.0.0.1:39901 node qa/thinking-chip.check.mjs` 全部通过。
  - 隔离环境：临时目录起 mock 服务（无 key、独立 `.data`），不碰本机 `.data` 与 39847 活服务；
  - 段 1（真 SSE、mock 一条 thinking）：思考渲染成一枚 24px 灰块、只写「思考」、无秒数、
    排在正文之前；
  - 段 2：点开详情——标题「思考」、状态「完成」、正文内部滚动、面板高 127px（≤260）；
  - 段 3（Playwright 拦截 POST 回固定 SSE，不碰模型）：`思考 → 工具 → 说话` 落在同一组，
    顺序 `think:0 → bash → 正文`，两枚都定格；
  - 页面无脚本错误。
  - 截图：`qa/thinking-chip-live.png` / `qa/thinking-chip-detail.png` / `qa/thinking-with-tool.png`。

## 没验证 / 已知边界

- **真实上游的多段思考 + 多次工具交替**只做了 SSE 回放模拟，没有用真模型跑过
  （真模型才会在工具结果之后再来一段 thinking）。逻辑上每段 thinking 都会得到
  自己的一枚块，但"一天里的第一轮真跑"值得看一眼。
- **刷新后看不到思考块**：thinking 事件本来就不进 steps / durable（改之前也没有），
  历史回读只有"话 + 工具块"。这不是本批引入的，要补属于契约级改动，另立项。
- 派活行（`delegate:*`）在收尾时仍按原规则保留为「已转后台」，不受本次影响。

## 刻意不做

- 不给思考块加秒数、字数、首句摘要——主界面保持一枚「思考」。
- 不改 `thinking` 事件的形状与节奏（契约不动）。
- 不做"思考可折叠/可隐藏"的开关：E1 已经把工作过程收成小块，再加开关等于把复杂度还给用户。
