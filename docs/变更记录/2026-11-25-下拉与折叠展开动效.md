# 下拉与折叠展开动效（2026-11-25）

## 问题

全站大量下拉、弹出菜单、流内折叠块是硬切：

- 挂载/卸载式：`document.body.append(menu)` → `menu.remove()`，没有任何进出场；
- `hidden` 直切式：`body.hidden = !open`，而全局 `[hidden]{display:none!important}`
  （`style-01-tokens.css:556`）让 CSS transition 根本播不出来；
- 原生 `<details>`：浏览器瞬开。

用户口径：下拉、复选框等「展开的框」不够美观，展开没有动画。

## 落地

### 1. 共用浮层动画 `web/pop-anim.js`（新增）

WAAPI：入场 160ms `cubic-bezier(0,0,.2,1)`（opacity 0→1、`translateY(-4px)`→0、`scale(.98)`→1），
出场 140ms `cubic-bezier(.4,0,1,1)` 反向。两函数都先 `getAnimations().cancel()` 防连点堆叠，
`prefers-reduced-motion: reduce` 时直接 resolve，返回 `finished.catch(()=>{})`。

为什么用 WAAPI 不用 CSS transition：挂载/卸载与 `display:none !important` 都会杀掉 transition，
WAAPI 可以在拔节点/置 hidden 之前把动画跑完。

### 2. 挂载/卸载式菜单接入（4 处）

| 组件 | 文件 |
|---|---|
| 分区 ⋯ 菜单 `#sec-menu` | `sec-menu.js` openSecMenu / closeSecMenu |
| 侧栏项目浮卡 | `project-switch.js` toggleProjectFlyout / closeProjectFlyout |
| 设置页项目行 ⋯ 菜单 | `settings-projects.js` openProjMenu / closeProjMenu |
| 群成员右键菜单 | `groups-thread.js` openGroupMemberMenu / closeGroupMemberMenu |

close 都是「先置空模块引用 → 动画 → remove」，动画期间重复关闭直接 return。

### 3. `hidden` / `display` 直切下拉接入（4 处）

| 组件 | 文件 | 备注 |
|---|---|---|
| 技能分类/排序下拉 `.sk-select-menu` | `skills-list.js` | 代际号按菜单 WeakMap（分类/排序可并排）；收起 140ms 内再点同一按钮会立即拉回重开 |
| 斜杠技能补全 `#skill-suggest` | `skill-picker.js` | 只在隐藏→显示播一次，输入每个字符不重播；键盘判据改逻辑态，避免收起窗口内 Enter 命中旧候选 |
| 群 @ 候选 `.group-atpop` | `groups-composer.js` | 逻辑态 `groupAtShown` 独立于 hidden |
| 对话页上下文容量卡 `.ctx-card` | `chat-notice.js` | 与 hover 开合共用代际守卫 |

### 4. 流内折叠

| 组件 | 文件 | 做法 |
|---|---|---|
| 记忆索引页分组 `.mem-a-gbody` | `memory-page.js` | WAAPI height+opacity，展开 200ms / 收起 160ms；代际按 body 节点 WeakMap |
| 任务页「今天派活」「更早」两组 | `tasks-redesign.js` | 实为整块重渲染（innerHTML 替换），高度动画没有对象；改为点击展开时对新容器播 160ms 淡入落下，收起仍瞬切 |
| 上下文页行 `.ctx-row-body`、浮层分组 `.ctx-group-body` | `settings-context.js` | 同一 `animateCtxFold`；浮层「往上提」挪到展开动画结束后量（中途量到半高会提不够） |
| 文件清单 `.fsum-files` | `chat-notice.js` | 展开先 `dataset.open=1` 让 display:flex 生效再量高度；收起动画到 0 才归 0 |
| 来信正文 `.letter-body` | `chat-thread.js` | 只动 max-height（折叠态留首行，不淡出以免首行闪）；折叠高度按 CSS 的 `1.65em` 取 `fontSize × 1.65` |

代际守卫统一为「每个可开合节点各记一份」（WeakMap / dataset），不用模块级单计数器：
同一页可同时开多个，单计数器会让先开的节点收尾回调被后来者作废，留下清不掉的 inline height。

### 5. 原生 `<details>` 渐进动画

`style-27-chevron.css` 追加 `@supports (interpolate-size: allow-keywords)` 包裹的
`details::details-content` block-size 过渡（200ms，`--ease-decelerate`）+ `content-visibility` allow-discrete；
不支持该特性的浏览器整段不生效，保持原生瞬开。reduced-motion 下显式 `transition: none`
（全局兜底选择器不含 `::details-content`）。

`chat-map.js` 的 chevron WAAPI 补了 reduced-motion 判断（不创建动画，直接落最终状态）。

## 明确没做

- 任务页两个组的收起退场（要退场得改整块重渲染架构，不在本批）。
- `tool-chips.js` 行高 WAAPI 的 reduced-motion 补判（该文件另有会话在改，未碰）。
- 原生 `<select>` 系统下拉（拿不到可靠开合事件，已有注释说明）。
- 各浮层观感参数（4px / 0.98 / 160ms）未按组件微调，统一口径。

## 回滚

- 浮层：删对应文件里的 `popAnimateIn/Out` import 与调用，恢复同步 remove / hidden 直切。
- 折叠：删 `animate*` 函数与调用，恢复 `hidden` / dataset / class 直切。
- details：删 `style-27-chevron.css` 末尾 `@supports` 段即可。
- 均无契约、存储、开关变化；不需要重启服务（前端静态文件刷新即生效）。

- `node --check`：`pop-anim.js`、批1/2/3 涉及的 12 个 JS 全过。
- 真页面（headless Chrome 158 + CDP，39847 实际服务，非 mock）：
  - 侧栏 ⋯ 菜单打开 → `#sec-menu` 160ms 动画 running；
  - 技能分类下拉打开 → `.sk-select-menu` 160ms running；再点 → 140ms running、菜单仍在 DOM、`popClosing=1`；
