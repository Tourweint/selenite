# 本机 cookie 密钥落盘（重启不再重填令牌）

- 日期：2026-11-05
- 范围：`ts/apps/server/src/auth.ts`、`ts/apps/server/scripts/http-probe.ts`、`接口文档.md` §1/§6
- 类型：缺陷修复（无契约变化，无客户端改动）

## 问题

前端一直开着，后端一重启就被踢回令牌框，要重新输一遍 `AGENT_TOKEN`。

根因在服务端不在前端：本机页面的自动放行靠 `/` 下发的一枚 HttpOnly cookie
（2026-11-03 批次），但这枚 cookie 的密钥是**每次进程启动时 `randomBytes` 现生成**的
（`auth.ts` 里的 `LOCAL_SECRET`）。重启即换钥，页面里的旧 cookie 立刻失效 → 403。
而用户通常从没手填过令牌（一直是 cookie 放行），localStorage 里也没有，
所以只能手输——桌面壳只有在它自己重启时才会通过 `#token=` 重新带入。

## 处置

密钥落盘保底：首用时写 `.data/local-secret`（`AGENT_LOCAL_SECRET_PATH` 可改），
重启复用同一枚。

- **惰性解析**：模块加载零副作用（单测红线"不碰 .data"不破），首个请求才读/写盘。
- **只认 48 位 hex**：文件缺失或内容损坏都当没有，自动补新枚。
- **并发启动**：`wx` 独占创建，EEXIST 读回对齐（两个实例不各持一枚互相踢）。
- **坏文件自愈**：EEXIST 且盘上是坏值时，用新枚覆盖回去（普通写），自愈值也持久。
- **落盘失败退回旧口径**：缓存进程内随机，同进程内始终一致；下次启动再试落盘。

安全边界没有变宽：能读这个文件的本机进程，本来就读得到 `.env` 里的
`AGENT_TOKEN`。放行条件不变——仍然只有 loopback + 带这枚 cookie。

## 刻意不做

- **cookie 不加 maxAge**：用户场景是"页面一直开着"，session cookie 够用；
  持久化 cookie 会把免令牌扩到"浏览器重开也算"，超出本次需求。
- **前端不存 AGENT_TOKEN 兜底**：本机场景页面手里本来就不该有令牌明文，
  让前端替后端保底是边界倒置。

## 验证（2026-11-05 实测）

- 专项重启演练（临时目录，不碰真实 `.data/`）13 项全绿：密钥落盘 hex 形状、
  带 cookie 200 / 无 cookie 403、**密钥跨重启不变 + 同一 cookie 重启后仍放行（修复点）**、
  坏文件旧 cookie 403 不误放行、坏文件自动覆盖重生成、自愈值再跨一次重启仍放行。
  演练教训：Git Bash 的 `kill` 杀不干净 node（SIGTERM 对 node 无效的场景），
  第一版脚本三轮"重启"其实一直连着同一个旧进程；换 node `child.kill()`
  （Windows = TerminateProcess）并以"端口不再应答"为停干净判据后才可信。
- `pnpm typecheck` 干净；`pnpm --filter @lifediary/server http` 端到端全绿；
  单元测试 225/225。

## 回滚

删掉 `.data/local-secret` 并回退本次提交即回到旧口径（进程内随机，重启重填令牌）；
不改代码时该文件也不影响任何其他行为。
