## 改了什么

**开关**：`plugins.json` 的 autonomy 组加 `PARTNER_SIDE_SESSIONS`（默认 `"true"`、hot、
`requires: ["COMPANIONS_ENABLED"]`，并在分组 keys 末尾登记，否则启动校验报引用缺失）；
`.env.example` 同步注释与默认值；新模块 `partner-session-role.ts` 用 `flagEnabled` 包装出
`sideSessionsEnabled()`（父开关关时也关）。

**数据模型（不加表不加列）**：`PartnerSessionLinkRow.role` 加 `"side"`，
`routeKey = 副会话对外 id`，复用 `UNIQUE(partner_id, role, route_key)`。
`partner-store.ts` 加三个只读方法 `linkOfSession` / `sideLinksOf` / `sessionLinksMap`；
`sessionIdOfPartner` 与 `canonicalPartnerIdOfSession` **没动**（仍只认 canonical）。

**纯函数**：`partner-session-role.ts` 的 `parsePartnerExternalId` 按 side → group → canonical
顺序用正则解析（禁止 `split("-")`，partnerId 含 `-` 也正确）；`partnerContinuePlan` 决定
canonical 折回 / side 放行 / side 开关关拒绝；`task-chat-owner.ts` 的 `dispatchOwnerOf`
改走解析器，顺手修掉群会话被当成 `<id>-group-<gid>` 的旧 bug。

**副会话创建与身份对齐**：`partner-runtime-run-partner-turn.ts` 导出 `partnerSideExternalId`；
把 `openPartnerSession` 的身份对齐段原样抽成 `alignPartnerSession`（canonical 行为不变）；
新增 `createPartnerSideSession`（开关 / active / 建会话 / 登记 side 链接 / 对齐身份 / 钉工作区，
id 碰撞重生成一次）与 `alignPartnerSideSession`（续话重新对齐 + 钉目录，执事失效返 false）。

**两个端点**：`GET /api/v1/partners/:id/sessions` 列会话（chief 特例：列非 `partner-` 前缀的
`chatKind=chief` 会话、每条 `role:"chief"`；执事：canonical 第一 + side 按 `lastAt` 倒序、
归档不返回）；`POST /api/v1/partners/:id/sessions` 建会话（可选 `title` ≤80 字走 `renameChat`，
**不发问候、不写任何消息**）。开关关两者都 400 `side_sessions_disabled`。

**索引与续话分流**：`ChatIndexEntry` 加 `partnerId` / `sessionRole` / `isCanonical`（只增不改）；
`chatEntryOf` 加可选 `link` 参数，由调用方传快照（`listChats` / `listChatsForExport` /
`listArchivedChats` 各开头取一次 `sessionLinksMap()`，不在 `chatEntryOf` 里查库）；
新增 `chatIndexEntriesOf(ids)` 给列表端点用，避开 `listChats(limit)` 截断丢老 canonical。
`/agent/chat` 的 `kind === "partner"` 分支按链接角色分流：side 对齐自身不再调
`ensurePartnerSession`，开关关 409 `side_session_disabled`；canonical / group / routine 保留原分支。

**文档**：分册1 §2.1（续话分流 + `/agent/chats` 增量字段）、分册4 §2.11.2（两端点完整口径）、
`接口文档.md` §6（新 env 行）、`系统架构.md` D29 + §7 会话管理 + §7.1 拒绝概念表；
`接口-存储工具与配对.md` 的 `GET /agent/chats` 权威字段表同步补三个增量字段（避免文档自相矛盾）。

**测试**：新增 `partner-session-role.test.ts`（解析 / 决策 / 开关 / 归属）、
`partner-side-sessions.test.ts`（临时库验证三个只读方法 + canonical 唯一性 + `ChatIndexEntry`
字段）；两个文件已加入 server 的 `test` 脚本清单。

## 为什么

C 版取舍：**主会话是"身份的代表"，副会话是"这个人的工作台"**。上下文隔离 + 同时干两件事，
但 A 全并行要把记忆 / 心情 / 唤醒 / 派活回灌四套规则全重定，代价不值。副会话共用同一份人设，
所以不需要复制 SOUL / 人格模块 / 岗位契约；三条自动流程本就只认 canonical，改动集中在
"别把副会话误折回主会话"和"界面能选会话"。开关默认开、hot，关掉 = 不列不建；已存在历史
仍可读、不能继续发消息（409），不做"关开关 = 数据消失"。

## 复核修正（2026-11-17，同一工作树）

复核发现两处"空会话在选择器里看不见"，已定点修正（只改点名位置，`listChats` 既有行为默认不变）：

- **`agent/session-index.ts`**：`chatIndexEntriesOf` 对"明确请求且存在于 Chats 的 id"，
  `readChatStats` 返回 null（turns=0）时不再 continue，改用零值
  `{ firstText:"", turns:0, createdAt:0, lastAt:0 }` 照常 `chatEntryOf`（保留 title / pinned / link）。
  覆盖两种现场：新建副会话在发出第一条消息前就能在选择器里出现；canonical 只有问候
  （assistant 不计 turns）时也能出现。
- **`listChats(limit, includeEmpty = false)`**：新增可选参数，默认 false 逐字节保持原行为
  （活跃清单仍不收空壳）；`companion-api.ts` 的 `GET /partners/chief/sessions` 传 `true`，
  chief 的空会话也用同一份零值兜底。没有为它扫全部会话统计、没有改其它调用方。

**补探针 §33（一人多会话）**：沿用隔离环境造执事 → `GET sessions` 至少返回 canonical →
`POST sessions` 的 `conversationId` 含 `-side-` → 再 GET 空副会话在列表里（`turns=0`）→
`POST /agent/chat` 续副会话，SSE `start.conversationId` 等于副会话 id（不折回 canonical）→
另起 `PARTNER_SIDE_SESSIONS=false` 的服务，GET sessions 400、续话 409。
