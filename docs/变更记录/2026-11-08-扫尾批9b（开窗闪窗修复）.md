# 2026-11-08 扫尾批 9b：壳启动闪窗修复（desktop/）

- 依据：`docs/设计方案/2026-11-08-扫尾批9b任务书（CodeBuddy·开窗闪窗修复）.md`。
- 范围：仅 `desktop/`；`LIFEDIARY_SHELL_*` / `LIFEDIARY_TRAY_STATE` 行为不变，服务端与手机端零改动。
- 落地：2026-11-08。

## 症状与结论

症状：打开壳时经常闪一个窗口，几十毫秒级。

结论：**不是 node，也不是 WebView2 白闪，是 `netstat`**。

- `node` 那条路早在 `desktop/service_windows.go` 就挂了 `hideWindow`（`DETACHED_PROCESS|CREATE_NEW_PROCESS_GROUP`
  \+ `HideWindow`），它根本不建控制台，与"服务没在跑才 spawn"这个条件无关——服务常在跑时也照样闪。
- `pidOnPort()` 里的 `exec.Command("netstat", ...)` 是**裸 exec**：壳是 `-H windowsgui` 的 GUI 进程，
  没有控制台，Windows 给控制台子进程新建一个控制台窗口。而它跑得很勤：
  `startTrayStateWatcher` 在 `WhenReady` 后立刻 `apply()` 一次 `runtime.Status()` → `pidOnPort` → netstat，
  之后每 5s 一次；服务没起时 `Start()` / `Status()` 还会再加几次。
- `taskkill` 同理（只在人点"停止"/重启时跑，闪在那一刻）。
- WebView2 白闪可排除：窗口创建时已设 `BackgroundColor: #181818`，且 `loadService` 先同步
  `LoadHTML(connectingPage)` 再异步换真页面。

## 改法

- 新增 `desktop/hidden-exec.go`：子进程启动的唯一入口，三个封装——
  `startHidden`（只 Start）、`runHidden`（Start+Wait）、`outputHidden`（Start+Wait+捕获 stdout）。
- `desktop/service_windows.go` 增加 `applyNoWindow()`：`HideWindow: true` + `CreationFlags: 0x08000000`
  （`CREATE_NO_WINDOW`）。**只在调用方没写 CreationFlags 时才补**：node 那条路要的是
  `DETACHED_PROCESS`，两者与 `CREATE_NO_WINDOW` 互斥，覆盖了会让服务失去"活过壳"的语义。
  `service_other.go` 给非 Windows 的空实现。
- 三个 exec 点全部改走封装：netstat → `outputHidden`，taskkill → `runHidden`，node → `startHidden`
  （`hideWindow` 保留在它前面）。stdout/stderr 语义不变：netstat 仍捕获输出，taskkill 仍只看成功与否，
  node 仍不重定向。
- 文档注释写明规矩：`desktop/` 里不许裸调 `cmd.Start()/Run()/Output()`。

## 验证（2026-11-08 本机）

- `go vet ./... && go build ./...`：通过。
- `go test -run TestStartHiddenCreatesNoVisibleWindow`：PASS（1.84s）。对照组用 `CREATE_NEW_CONSOLE`
  故意开控制台并置唯一标题，`EnumWindows` 能枚举到该**可见**窗口（证明探测器有效）；
  实验组同一条命令走 `startHidden`，1.5s 内无可同名可见窗口。
- 既有 `desktop` 单测（端口解析 / pidOnPort / stopped 闩 / 幂等 Stop / 状态区分 / netstat 可用）：全 PASS。
- 临时用例确认 `outputHidden` 能捕获 stdout，且 `pidOnPort` 在真实 netstat 输出上仍解析出 PID
  （本机 `:39847` → 54208），即"换成捕获式启动"没有破坏解析。
