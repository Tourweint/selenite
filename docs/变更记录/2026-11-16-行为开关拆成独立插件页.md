# 行为开关拆成独立「插件」页（2026-11-16）

## 改了什么

设置页从「服务」里把「行为开关」整块搬出来，独立成一个新分区「插件」：

- `web/settings-base.js`：`SETTINGS_SECTIONS` 在「服务」后新增 `{ id: "plugins", label: "插件", desc: "功能开关中心：默认开，按需关" }`；
  图标用 Lucide `puzzle`（0.468 原图元）。「服务」的 desc 从「桌面通知、鉴权、运行时与行为开关」收回成
  「桌面通知、鉴权与运行时」。
- `web/settings-router.js`：
  - `page === "service"` 只留通知 / 鉴权 / 运行时，删掉「行为开关」区块与 `loadFlagsSettings()` 调用；
  - 新增 `page === "plugins"` 分支：`sectionMarkup("插件", <div id="flags-card">…)` + `loadFlagsSettings()`；
  - 页面仍不套 `.card`——卡片墙直接铺在设置页背景上，避免嵌套卡片。
- `web/settings-switches.js`：
  - 文件头注释改成「插件页」，写清 2026-11-16 拆出；
  - 页首计数从「N 个开关」改成「N 个插件」，其余口径不变（默认开 / 默认关、当前开 / 当前关）；
  - 「记忆总闸」的悬停说明补全：拆页当时写的是「重启前召回 / 整理仍可用；启动时关着再打开也要重启才真正上架」。
    同日父子实现把 `/memory/*` 与召回改成活读 gate，这句已过时；当前文案是「关掉后新记忆停写、召回与记忆页接口
    立即停；已经加载进内存的库要重启服务才彻底卸下。启动时本来是关的，再打开要重启才上架」。
  - 顺手修掉一个裸英文键：`SIDEBAR_TASK_GROUPS` 之前没进 `FLAG_LABELS` / `FLAG_GROUPS`，会落到「其他」组并显示
    env 原名；本次补中文名「侧栏按创建者分组」+ 简介，并归进「任务与界面」组（该组 6 → 7 项）。
- `web/style-14-settings-pages.css`：区块注释从「行为开关」改成「插件页」；样式本身一字未动。
- `web/partner-profile.js`：两处「总闸在 设置 → 服务 → 行为开关」改成「设置 → 插件」。
  `PARTNER_PROJECT_MEMORY` 那条不是插件页卡片（该键只在 env，不在 `FLAG_DEFS`），文案改成「部署配置，不在插件页（缺省开）」。
- `agent/assist.ts`：`PARTNER_MEMORY_RECALL` 的注释同步改成「设置 → 插件」。

## 为什么

用户口径：这些开关本来就是「做出来的功能」，不是服务状态；应该按插件中心的卡片墙独立成页，
服务页只回答「服务自己在不在跑、通知和鉴权通不通」。2026-11-15 已经先把「高级开关」改名「行为开关」
并按插件卡片墙排，这次只差把它从服务页搬出去，所以整块搬运、不改判定与接口。

## 还有哪些不确定 / 未做

- **`MEMORY_ENABLED` 的启动边界**：`.env` 为 `MEMORY_ENABLED=false` 时引擎是 null，运行期在插件页打开仍要重启；
  如果只是界面覆盖关掉、`.env` 仍为 true，引擎已在，重开可直接用。彻底统一要把引擎改成动态装配。
- **`hot:false` 父的锁时点**：`COMPANIONS_ENABLED` 等父切到关闭后，子卡按新保存值立刻锁，父自身可能仍在
  「待重启」窗口；当前按「配置意图」锁，尚未改成按 boot 值锁。
- **语义锁不是函数门**：`MINISTER_DISPATCH_AUTHORITY` / `PARTNER_TEMPLATES` 挂在 `COMPANIONS_ENABLED` 下，
  但消费函数没有直接读父；父关时页面不可达，内部调用仍可能绕过。
- **人物页直接 API**：跨层子项的服务端写入没有拦，运行时 gate 保证不生效，但存储值会变；要彻底拒绝需在
  `companion-api` 补 `400 flag_locked`。
- **`scope` 现在有真实存储差异**：`plugin` 读 `.data/agent-flags.json`（文件缺键才回 env / 默认值），
  `core` 仍读 env；`core` 仍可被界面写（`setFlag` 保留落盘 + 同步 env 的历史兼容），若以后要求系统核心只能改
  `.env`、界面只读，需要再加 `editable` / `scope=deployment` 并在 `setFlag` 拒绝，不能只靠徽标。
- **`plugins.json` 是运行期清单**：按 `mtime + size` 重新装载，改名称 / 说明 / 分组 / 档位 / 父子关系
  不需要重启；坏清单保留上一版并 warn。`.data/agent-flags.json` 的 plugin 配置同样是运行时直读；
  `hot:false` 的消费处仍在模块加载 / 路由挂载时冻结，所以这类开关本身改完仍要重启。
- **当前仓库工作区有其它未提交改动**：`git status` 显示大面积 `M`，本次未提交、未动其它工作线的 diff 块。

## 同日再续（晚）：普通插件配置改成 JSON 真源

用户口径：「普通插件配置都走 env 不合理，早晚要从 JSON 读配置。」落实为两条路径：

| scope | 存储 / 取数 | `setFlag` | 启动 |
|---|---|---|---|
| `plugin` | `.data/agent-flags.json` 唯一真源；文件缺键才回落 env / 清单默认值 | 只写 JSON，不写 `process.env` | 不物化进 env |
| `core` | 部署 env 为主 | 保留落盘 + 同步 env 的历史兼容 | `loadFlagOverrides()` 把文件覆盖写进 env |

`flags.ts` 的关键改动：

- 新增 `flagValue(key, env)` 返回原始存储值；`storedFlagValue()` 对 plugin 读 JSON 缓存 map，文件缺键才回
  `env[key]` / `defaultValue`；core 仍读 env。消费代码统一改用 `flagEnabled()` / `flagValue()`。
- `pluginStoreApplies(env)`：只有 `env === process.env` 或显式给了 `AGENT_FLAGS_PATH` 时才读 JSON。单测 / 探针
  传普通 env 对象仍是纯 env 夹具，不会被开发机真实 `.data` 串味；这是修掉 compaction / attachments /
  delegation-wake / tool-projection 等测试失败的关键。
- `readOverrideMap()` 按路径缓存 `{mtimeMs,size,map}`，外部改 JSON 后下一次读取能失效；`writeOverrideMap()`
  原子写后删缓存。`loadFlagOverrides()` 只把 `scope=core` 写进 env，plugin 条目不再灌 env，但仍校验非法配置并 warn。
- `setFlag()`：plugin 只改 JSON；core 仍写 JSON + env。数值型空值删除 JSON 覆盖行；plugin 不删 env，core 仍删 env。
- `captureBootValues()` 改用 `storedFlagValue()`；`listFlags.pendingRestart` 用当前存储值比较，避免 plugin 从 env 比较。
- `flagIsOff()` 统一 `false` / `0` / `off`；`effectiveFlagValue()` 自身或父的 off 值都归一成 `"false"`；
  `lockingFlag` 与 `flagEnabled` 共用同一判据。`chatHistoryPagingEnabled` 也改 `flagEnabled("CHAT_HISTORY_PAGING_ENABLED")`。
- 清单不再静态 `import`：`flags.ts` 按 `mtime + size` 运行时读 `plugins.json`，支持 `AGENT_PLUGINS_PATH`
  覆盖；读到坏清单 / 文件暂时不存在时保留上一版并 warn。`scripts/build.mjs` 把清单复制到
  `dist/src/plugins.json`，源码态和 dist 态都用 `import.meta.url` 相对路径。

消费入口迁移：`ask-user`、`attachments`、`compaction-settings`、`auto-archive`、`durable-delete-delete-subtree-rows`、
`project-types`、`delegation-wake`、`relay-config`、`group-manage`、`memory-consolidate-parse-proposal-json`、
`memory-api`、`memory-extract`、`memory-inject`、`partner-api`、`work-record`、`persona-export`、`persona-ask`、
`routines`、`skills`、`skills-api`、`tool-projection`、`topics`、`task-chat-owner`。
剩余直接 `process.env` 的清单键只有 core：`AUTONOMY_ENABLED`、`MEMORY_ENABLED`、`COMPANIONS_ENABLED`、
`CHANCELLOR_ENABLED`。`relay-matrix` / `relay-mobile-proxy` / `tools` 里的 `DEVICE_AUTO_DISPATCH` 只是错误文案，
实际判定走 `deviceAutoDispatchEnabled()`。

测试适配：`flags.test.ts` 改为临时 JSON 夹具，新增「plugin 文件值压过 env」「外部改 JSON 后缓存失效」
