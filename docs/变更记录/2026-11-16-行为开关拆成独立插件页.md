# 行为开关拆成独立「插件」页（2026-11-16）

## 改了什么

设置页从「服务」里把「行为开关」整块搬出来，独立成一个新分区「插件」：

- `web/settings-base.js`：`SETTINGS_SECTIONS` 在「服务」后新增 `{ id: "plugins", label: "插件", desc: "功能开关中心：默认开，按需关" }`；
  图标用 Lucide `puzzle`（0.468 原图元）。「服务」的 desc 从「桌面通知、鉴权、运行时与行为开关」收回成
  「桌面通知、鉴权与运行时」。
- `web/settings-router.js`：
  - `page === "service"` 只留通知 / 鉴权 / 运行时，删掉「行为开关」区块与 `loadFlagsSettings()` 调用；
  - 新增 `page === "plugins"` 分支：`sectionMarkup("插件", <div id="flags-card">…)` + `loadFlagsSettings()`；
  - 页面仍不套 `.card`——卡片墙直接铺在设置页背景上，避免嵌套卡片。
- `web/settings-switches.js`：
  - 文件头注释改成「插件页」，写清 2026-11-16 拆出；
  - 页首计数从「N 个开关」改成「N 个插件」，其余口径不变（默认开 / 默认关、当前开 / 当前关）；
  - 「记忆总闸」的悬停说明补全：原文只写「关掉后新记忆立即停写，已加载的库要重启才彻底卸下」；
    实际运行期关掉时 `/memory/*` 与召回仍在跑，反过来启动时关着再打开也要重启才上架。改成
    「重启前召回 / 整理仍可用；启动时关着再打开也要重启才真正上架」。
  - 顺手修掉一个裸英文键：`SIDEBAR_TASK_GROUPS` 之前没进 `FLAG_LABELS` / `FLAG_GROUPS`，会落到「其他」组并显示
    env 原名；本次补中文名「侧栏按创建者分组」+ 简介，并归进「任务与界面」组（该组 6 → 7 项）。
- `web/style-14-settings-pages.css`：区块注释从「行为开关」改成「插件页」；样式本身一字未动。
- `web/partner-profile.js`：两处「总闸在 设置 → 服务 → 行为开关」改成「设置 → 插件」。
  `PARTNER_PROJECT_MEMORY` 那条不是插件页卡片（该键只在 env，不在 `FLAG_DEFS`），文案改成「部署配置，不在插件页（缺省开）」。
- `agent/assist.ts`：`PARTNER_MEMORY_RECALL` 的注释同步改成「设置 → 插件」。

## 为什么

用户口径：这些开关本来就是「做出来的功能」，不是服务状态；应该按插件中心的卡片墙独立成页，
服务页只回答「服务自己在不在跑、通知和鉴权通不通」。2026-11-15 已经先把「高级开关」改名「行为开关」
并按插件卡片墙排，这次只差把它从服务页搬出去，所以整块搬运、不改判定与接口。

- `node --check`：`settings-base.js` / `settings-router.js` / `settings-switches.js` / `partner-profile.js` 全过。

    「任务与界面」7 项，`SIDEBAR_TASK_GROUPS` 显示中文名，底部不再有「其他」组、不再有裸 env key。
  - `#/settings/service`：只剩通知 / 鉴权 / 运行时，无「行为开关」区块。
- 未跑服务端单测：本次只动前端分区与文案 + 一行代码注释；`flags.ts` 白名单、`PUT /agent/flags` 契约未动。

  运行期再打开不会重建引擎；启动时开着、运行期再关掉也不会让已装配的 `/memory/*` 变 404（只是自动抽取停）。
  两个方向都要重启才彻底（见调查文档 §5）。本次未改，属父子开关落地前的前置补丁。
