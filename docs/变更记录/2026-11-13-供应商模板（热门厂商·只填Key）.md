# 变更记录：2026-11-13 供应商模板（热门厂商 + 套餐，只填 Key）

> 上位：用户当日两轮口径——①「把几个热门供应商配一下，让人直接输入 API 就行」，照
> `<reference>\magpie` 学但**不用太多**；②「有些厂家不只提供 API，还出售套餐，比如 Token Plan，
> 你再仔细调查一下」——所以模板里带**套餐**（按量 / Token Plan / Coding Plan…），不是只给一个按量地址。
> 契约：`docs/基线文档/接口文档.md` §2.10（`modelsUrl` 的用法回写）。模块：`docs/基线文档/系统架构.md`
> （「不做预设模板」这条按本节收窄）。只改前端（`web/app.js` / `web/style.css`），服务端零改动。

## 结论先说：为什么「套餐」必须进模板

同一家厂商的按量 API 和套餐是**不同端点、不同 Key**，选错就 401（magpie 的 `KeyPlans` / `Regions` 就是为此）。
magpie 按套餐拆 `Regions`；本仓库的模板没有 region 概念，所以实现成「一张厂商卡 + 卡内套餐分段」，
不把 20 多张套餐卡铺到模板格里。

## 刻意不做

- 不做登录 / 套餐**自动识别**（magpie 能按 key 前缀分 plan，我们不做——用户自己选，选错会 401，提示已经在卡上）；
- 不做套餐额度 / 余量展示（要调各家用量 API，是另一件事）；
- 不做编辑态换套餐（只在新建时给选择器，避免把已存的模型清单冲掉）；
- 不做每家全部套餐（腾讯企业版 / 百度企业版 / 小米三 region / 各家国际站都没列，理由见上表）；
- 不做套餐模型的自动刷新（写死的清单会过期，但套餐端点大多没 `/models` 可问；模型行可自己改）。

## 回滚

- 模板多了不影响老数据：已建的供应商照旧，`providers.json` 形状不变。
- 只想退回「只填地址」：删 `PROVIDER_TEMPLATES` 里新增的条目（纯前端数据）。
- 想退回「不自动拉清单」：删 `saveProviderFlow` 的 ③；`modelsUrl` 与旧客户端兼容，删了不影响。
- 套餐分段是新增 DOM，删掉 `#pv-plan-field` 那段即回到「一个模板一个地址」。

## 已知边界 / 不确定

- **图标是品牌商标**：取自 magpie 打包的 lobe-icons 资产，商标归各家；本项目只作本地识别用，不对外分发。
- **没有真 Key 连各家生产 API**：端点取自 magpie 的 `presets.go` 与 bundled catalog（2026-11-13 读），
  套餐档的模型清单也来自这两处；哪家实际改了端点 / 模型，第一次真接入会以 401 或 404 暴露，改 `PLAN_MODELS` 一行即可。
- **百炼 Coding Plan 端点（`coding.dashscope.aliyuncs.com/v1`）只在 catalog 里出现**，magpie 的 `presets.go`
  没有这个预设；协议标的是 `@ai-sdk/openai-compatible`，但没被 magpie 实测过，属本次最不确定的一条。
- **腾讯 Token Plan** 用的是 magpie 11-02 迁移后的 `tokenhub.tencentmaas.com/plan/v3`；catalog 里还是旧 host
  `api.lkeap.cloud.tencent.com/plan/v3`，以 magpie 的迁移记录为准。
- 套餐清单是**静态快照**：上游上/下模型不会自动更新，用户要自己加 / 删模型行（行内可编辑）。
- 桌面壳里「获取 Key ↗」`target="_blank"` 是否真拉起系统浏览器**未验证**（与搜索源那张卡同款）。
- 截图没取到（CDP `Page.captureScreenshot` 本次会话连续超时，png / jpeg、fromSurface 开关都试过），
  视觉用几何量测代替：模板卡图标 22×22、左栏图标 15×15、卡片高度仍 65px、单色图标取到 `--text-2`、
  彩色图标保留品牌色、分段轨道 168×30 且高亮与选中按钮对齐。**没有像素级截图复核**。
