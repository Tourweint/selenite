# 变更记录：2026-11-17 设置页四分区合并为「Agent」

> 范围：纯前端 `ts/apps/server/web/`（settings-base / route / settings-router / app / style-14）。零契约、零服务端改动。

## 为什么

设置页左栏 17 个分区太长。用户口径：**人设 / 上下文 / 工具 / 派活** 四页都是"对发出去的那条消息做调整"（由谁说、带什么、能用什么、活给谁干），合成一个入口。

## 改了什么

- 左栏合并成一项 **「Agent」**（Lucide bot 图标，排在「会话」后），17 → 14 项。
- 内容顶部一条**四分段 tab**（`.set-tabs` / `.set-tab`，形态沿用抽屉档案分段 `.cs-arch-tabs` 的语言），顺序 = 人设 → 上下文 → 工具 → 派活；`#/settings/agent` 不带子路由时默认落**人设**。
- 四个 tab 的内容就是原来四页的渲染分支，原样搬运（`contextSettingsMarkup` / `toolPoolMarkup` / `executorSectionMarkup` / 人设列表），只在前面拼一段 tab 条。

## 路由口径（关键）

- **四个旧 hash 原样保留**，就是四个 tab 的地址：`#/settings/partners`、`#/settings/context`、`#/settings/tools`、`#/settings/executor`。老书签、抽屉「去编辑这个人」、上下文页里的人设跳转、记忆页跳转**零改动**。
- `currentSettingsPage()` 把四个旧 id 与旧书签 `#/settings/avatars` 都别名到 `agent`；`currentAgentTab()` 从同一 hash 认回具体 tab。
- 人设详情 `#/settings/partners/<id>`（含 worker）仍是钻进某人档案的二级页：不挂 tab 条，自带返回键回列表。
- 壳的深链 `?view=settings/<旧 id>` 继续可达（app.js 的合法性检查补了 AGENT_TABS.route）。

## 坑

- `route.js` ↔ `settings-base.js` 是循环引用：**模块顶层不许 map / find AGENT_TABS**（另一条 import 顺序会 TDZ，见 settings-base.js 文件头的拆分口径），只在函数调用时读。
- `.set-tabs` 占了 `#settings-inner` 的 `:first-child`，原来的 `.set-sec:first-child { padding-top: 0 }` 会失配，补了 `.set-tabs + .set-sec { padding-top: 0 }`，否则 tab 条与第一节之间多出 18px。

## 刻意不做

- 不并「技能」「记忆」「用量」：用户只点名这四个；技能是全局手册库、记忆是策展面，混进来只会让这组 tab 变成杂物抽屉。
- tab 条不做 sticky：内容都不长，粘条反而挡卡片。

## 回滚

无 env 开关（纯 UI 结构重组，没有行为分叉可切）。回滚 = revert 本批五个文件：
`web/settings-base.js`、`web/route.js`、`web/settings-router.js`、`web/app.js`、`web/style-14-settings-pages.css`。
