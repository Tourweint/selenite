# 2026-11-05 界面第十二轮（任务中心重定位：一张卡 = 一次派活，子单收进卡片）

## 1. 定位修正（核心）

- **旧模型迷糊的根源**：卡片粒度错——展示底层执行单，一次派活拆出的每张子单都平铺，44 张卡里大半是碎片。
- **新模型（对标 CINDY 会话卡片）**：一张卡 = 一次派活（父单）；子单收进卡片内部「子单 N ▸」展开区；卡片正文显示**最近正在干的动作**（CINDY SessionCard 优先级：子单等你文案 > 子单出错文案 > lastAction > prompt 截断）。

## 2. L1 后端（跨仓库：chancellor + harness）

- chancellor：`ChancellorRequest.originConversationId`（照抄 managerIdentity"只透传不解读"先例）→ `intake` 第 7 参落 ticket.json → `runManagerTicket` → spawn 参数（`employee/manager.ts` 三行必要越界，已批准）→ 子单继承。**总管手改契约登记**（§2.9 列表行 + 明细段）。
- harness：`delegation.ts` 请求组装带 `kick.conversationId`；`TicketSummary.conversationId` 取值 = 透传值 ?? `receipts.lookupByTicket` 回执回查 ?? null；**出接口前内部 id 经 `externalChatIds()` 换成对外 uuid**（硬约束：内部自增 id 不外泄）。
- 探针 §18 七项全绿（首层=对话 uuid、子单继承、历史回查、null 兜底）；harness 225 测试 + chancellor 6 测试全过。

## 3. L2 前端（web 三件套）

- `parentTickets()/childTicketsOf()` 客户端分组：**主视图只渲染父单**，子单收进卡内展开区（`state.tasksChildrenOpen` Set）。
- 聚合徽章（只读派生，照 CINDY 优先级）：子单 needs_you→"子单等你"(蓝) > 子单 failed/aborted→"子单出错"(红) > 父单 idle 有子单→"执行中·等子单" > 自身状态。
- 进度加总 = 父单 + children 的 passed/total（**口径核实**：chancellor tasks 表按 ticket_id 隔离，子单是独立行，加总不重复）。
- "来自对话"行（防御式：conversationId null 整行不渲染）+ 点击跳回原对话（复用 openChat）。
- SSE 子单事件 → 触发父卡重绘；已完结折叠区同步只列父单、简卡走聚合徽章；侧栏徽标与顶部统计输入也换成父单（口径跟看板一致）。
