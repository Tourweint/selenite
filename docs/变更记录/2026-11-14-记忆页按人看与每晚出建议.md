# 记忆页按人看 + 每晚出建议（选人弹框 / 全部逐个 / 03:30）

用户原话：

- "记忆主要看我的记忆。"
- "每天泡一遍记忆整理记忆都可以，和手动整理建议一样……整理建议还要拉出小框，到底整理谁的，还是全部整理？"
- "给项目也带上记忆也可以。记忆比较散落，就这样做。"
- "人设这些还要改，不过不着急，你先弄吧。"

这一轮只做前三条里"记忆页"能装下的部分；项目级 scope 与人设页耦合明确留到后面。

## 改了什么、为什么

### 1. 顶部从"下拉选范围"改成一排人

改之前：一个 `<select>` 选 `global / partner:<id>`，用户得先知道 scope 是什么。
现在：一排横滑的页签——`我的记忆 6` · `阅读助手 同事 0` · `记账助手 同事 0` · `纪要员 同事 4`，
点谁看谁。当前人高亮，条数直接长在页签上；右侧搜索、分类片、列表都跟着当前人走。

位置从原来的"搜索下面"挪到**概览卡下面、整理建议上面**：先选人，再看"这个人的"建议与列表。
原来建议卡一长就把人排挤到折叠下方，等于把主入口藏了。CSS 用 `nowrap + overflow-x:auto`
（实测 4 个 32px 高的页签单行排开），人再多横向滑，不换行堆两排。

**为什么加 `GET /api/v1/agent/memory/scopes`**：条数要一次问清。前端自己拿 `/partners`
再逐人打 `limit=0` 也能拼出来，但那是 N+1 个请求、而且"谁算在职执事"的口径要在两处各写一遍
（排除总管、排除 archived）。服务端一处给齐 `{scope, label, count, kind}`，前端只负责画。

**旧进程兼容**：网页文件是磁盘直出、进程是 `tsx src/index.ts`（非 watch），会出现"新页面 +
旧路由"的中间态。前端见 404 就退回 `/partners` + 逐 scope 计数，页面不会只剩一行"我的记忆"；
新进程起来后自动走单请求路径。实测这次就是旧进程（`/scopes` 404），页面靠回退正常显示。

### 2.「整理记忆」先问"整理谁的"

点按钮不再直接开跑，先弹一个小框：

```text
整理谁的记忆
只出建议，不会自动改；应用要你逐条点。
（上次还有 N 条没处理；重新整理会替换它们，已应用的不受影响。）
  ● 我的记忆                      6
  ○ 阅读助手  同事                    0
  ○ 记账助手  同事                    0
  ○ 纪要员 同事                   4
  ○ 全部（逐个整理）              10
                         [取消] [开始整理]
```

几个决定：

- **默认选中"当前正在看的这个人"**，不是永远选"我的记忆"——用户已经在看纪要员，多半就是要整理他。
- **"重新整理会替换旧建议"折进这个框的第二行**，不再先弹一次确认。原来"确认替换 → 再选人"要连点两次，
  而替换只影响没应用的**建议**（不动记忆本体），不值得单独拦一道。
- **全部 = 逐个跑，不是并发**。一个 scope 跑完再跑下一个；某个人失败不影响后面的人，
  汇总卡上每条建议标"来自：纪要员"，应用/忽略按卡片自带的 scope 走，不会串到当前页签。
- 跑完/跑到一半切人不会串台：单人的状态按 scope 存，全部整理的汇总单独存 `batch`，切页时只清"已结束"的旧汇总。

### 3. 每天 03:30 自动跑一遍，只出建议

`memory-nightly.ts`（新）：

- 每天 `MEMORY_NIGHTLY_AT`（默认 `03:30`，本地时区）触发，`global` 一次 + 每个在职执事各一次，**串行**。
- 走的是手动同一条 `startReview`（同提示词、同证据、同审计 `pass`），**没有第二套整理实现**；
  区别只有触发者。
- **只写建议，不应用、不删除**（D18 底线不变）；早上人打开记忆页，看到的就是昨晚那一批。
- 服务 03:30 没开着 → 启动 90 秒后补跑；当天跑没跑过看 `.data/memory-nightly.json` 的 `lastRunDay`，
  跨重启不重复。`MEMORY_NIGHTLY_REVIEW=false` 一行关掉。
- 某个 scope 不足 2 条记忆时 `reviewScope` 自己早退，不打模型、不写待决文件——空执事不烧钱。
- 日志只记 scope / 条数 / 耗时，不记正文（D8）。

**为什么不照抄 cindy 的"夜里再抽一遍"**：我们的抽取在每轮对话就做完了（规则记经历、模型记偏好），
夜里再抽是二次加工，只会把同一句话换个说法再存一遍。夜里只做"看有没有重复、要不要合并"，
这是手动"整理记忆"本来就在做的事，只是改由闹钟触发。

### 4. 样式只加人排与选择框

`style-21-answer-memory.css` 追加 `.mem-a-people` / `.mem-a-person` / `.mem-a-person-tag` /
`.mem-prop-scope` / `.mem-pick` / `.mem-pick-row`：人排横向滚动、不换行；选中用浅底 + 主色字，
和既有分类片同一档；"同事"是小号弱化标签。没有改版式、没有新配色。

## 刻意没做

- **项目级记忆**（`topic` / `project` scope）：`memory/types.ts` 有类型、没有写入路径，
  要动抽取与召回两处；用户说"也可以、不着急"。
- **人设页与记忆的耦合**：人设页现在只读不写记忆，两边共用的只有 partner id；
  用户明确"不着急"，先不动。
- **自动应用 / 自动删除 / 全部应用**：仍然是 0。每晚只出建议。
- **给每个 scope 单独配时间**：现在一个全局时刻，够用。

## 回滚

- 每晚整理：`MEMORY_NIGHTLY_REVIEW=false`（不挂定时器，手动整理照常）。
- 触发时刻：`MEMORY_NIGHTLY_AT=HH:MM`。
- 记忆页整页回旧版：`MEMORY_PAGE_A=false`（旧 DOM 与旧逻辑仍在）。
