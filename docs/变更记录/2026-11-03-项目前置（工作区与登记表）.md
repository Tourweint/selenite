# 2026-11-03 项目前置：工作区、项目登记表与派单硬前置

## 背景

方案 `docs/设计方案/2026-11-03-宰相层（分管子代理）.md` §5.5 要求：派单必须带 `project`，
项目必须已登记且落在用户选定的工作区内；新起项目根目录必须用户确认。
这一段是"领域负责人"后端六阶段中的**阶段 2**，界面（`ts/apps/server/web/`、`desktop/`）本次不动。

## 做了什么

### 1. 工作区与项目登记（`ts/apps/server/src/projects.ts`）

- 独立 SQLite：`.data/projects.sqlite`（`PROJECTS_DB_PATH` 可改），懒建，不混进 pi-durable 的表。
- 单工作区：`POST /api/v1/workspaces` 设置根目录；`GET /api/v1/workspaces` 读取。
- 工作区校验：必须是绝对路径、存在、是目录、可写；拒绝盘符根、用户主目录（及其上级）、系统目录。
- 项目登记字段：`id(uuid) / workspaceId / name / rootPath(realpath) / vcs / head / createdAt / archived`。
  `vcs=git` 且读得到时记录当前 HEAD。

### 2. 新建项目根目录 = 助理发起 + 用户确认

- `POST /api/v1/projects` **只提交待确认请求**（proposal），返回 202；此阶段不建目录、不写项目登记表。
- `GET /api/v1/projects/proposals?status=pending` 供设置页列出待确认项。
- `POST /api/v1/projects/proposals/:id/confirm` 是**用户确认**入口：这一步才 `mkdir` + realpath 复核 + 登记。
- `POST /api/v1/projects/proposals/:id/reject`：什么都不建。
- 助理侧工具 `propose_project(name, path)`：只提交 proposal，并明确告诉模型"确认前不要派工、不要自己建目录"。

> 与方案原文的一处落地差异：`POST /api/v1/projects` 被拆成"提交请求"与"确认"两步。
> 原因是没有界面的情况下，无法仅凭接口调用判断"用户真的点了确认"；拆两步才能让"确认"成为可审计的独立动作。

### 3. 派单硬前置

- `delegate` 新参数 `project`（已登记项目名或 uuid）。派新活时没带 / 没登记 / 目录不存在 / 已出工作区，
  统一返回 `{"error":"needs_project","message":…,"projects":[…]}`，**不建单、不建目录、不写文件**。
- 续跑（`resume`）沿用原单的项目；改派新单时沿用本会话上一轮记住的项目。
- 回滚开关：`DELEGATION_PROJECT_REQUIRED=false` 回到 2026-11-02 的无项目行为。

### 4. 项目穿透到任务单

- `DelegationKickoff.project` → `ChancellorRequest.project` → `ticket.options.project`。
- 分管负责人通过 `--project-id / --project-name / --project-root` 收到本项目，并在提示词里看到项目根；
  它派出的子任务继续带同一个 `project`（只做记录与透传，不改执行目录）。

### 5. 边界（刻意没做）

- **不动界面**：新增的确认/列表接口留给后续设置页与任务中心；本次没有改 `web/`、`desktop/`。
- **不把执行者 cwd 改到项目根**：worktree 隔离与写入租约是阶段 3；在租约落地前直接写项目会绕过并发控制。
  负责人提示词已写明"隔离执行与租约落地前，不要直接往项目根里写文件"。
- 不做项目归档/改名/删除接口（方案未要求；后续任务中心再补）。
- 不做"负责人自建项目"：负责人的工具里没有建项目，也没有建领域。

## 已知问题 / 待拍板

- **手机操作用户没有磁盘项目**：`verify-live-dispatch.ts` 这类纯手机链路现在只能显式设
  `DELEGATION_PROJECT_REQUIRED=false`。是否给"设备类任务"一个豁免（例如 `project` 允许为空且 `domain` 为空），
  需要产品口径确认；当前严格按方案"派单必填 project"执行。
- **切换工作区会让旧项目不可用**：登记表不迁项目，派单时按当前工作区复核；已有项目若在新工作区外会被拒绝。
  这一行为符合"工作区外一律拒绝"，但没有迁移/提示接口。
