## followUp 指令最终文案

- 工具被拦（回给模型，本轮收尾）：
  「这个操作在等用户批准，本轮没有执行。不要原样重试（重试也只会继续等）；你可以先把不需要批准的部分做完，或者直接告诉用户在等批准。批准后我会继续。」
- 批准（提交给会话，落成一条 user 消息）：
  「用户已批准 \`<tool>\`：<参数摘要，单行 ≤300 字>——立即重新发起同一个工具调用（工具与参数保持完全一致），完成后继续原本的工作。不要换成别的工具或别的参数。」
- 拒绝：
  「用户拒绝了 \`<tool>\`：这个调用不要执行，也不要原样重试。请继续其余工作，能做多少做多少；确实有必要换个做法，就提出新的调用（它仍会重新征求用户批准）。」

## 放行清单实现

- 批准时由 store 记 `{callId(源审批，仅排障), conversationId, tool, argsHash, grantedAt}`；同会话同工具同指纹不重复记。
- 闸门每次 `ask` 先 `consumeGrant(conversationId, tool, argsHash)`：命中即**删除**（一次性）并继续走原放行路径（含只读 / 路径复判）；换参数 / 换工具 / 换会话都不命中，重新挂审批。
- 没有 `argsHash` 的老记录（升级前遗留）批准后**不生成放行**（宁可重新问一次）。
- 清理：放行 24h 过期（`load` 与 `persist` 两处）；`/stop` 按 `aborted` 结算 pending 时一并清掉该会话放行（停止 = 撤销）。
