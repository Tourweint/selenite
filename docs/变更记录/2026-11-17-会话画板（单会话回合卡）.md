对应《2026-11-17-会话分叉（从某条回答另开一支）》的 **P4 单会话画板**——此前只写在方案里，没有实现（2026-11-17 核实）。
方案：`docs/设计方案/2026-11-17-会话画板（单会话回合卡）.md`。

## 改了什么

### 服务端

- 新增 `src/agent/chat-map.ts`：
  - `projectChatMapTurns()`：把回合投影成"一问一答两张卡"——一条 user / 来信开一轮，同轮多条 assistant 正文**最后一条有正文的胜出**，工具只计数（`steps` 里 `name !== "say"`），预览问 400 字 / 答 1200 字；
  - `resolveBranchStart()`：分叉点解析——优先 `origin.atMessageId` 在母会话回合里找答卡；老副本按"提问时间 ≤ `origin.at` 的回合都是复制前缀"兜底；两条都读不出来**不猜**（返回空回合，前端画空分支占位卡）；
  - `buildChatMap()`：从请求的会话沿 `ChatOrigins` 向上找根（防环 64 跳）、向下 BFS 装配整棵树；节点 ≤ 24、每节点 ≤ 400 轮，超了 `truncated: true`；删掉的会话保留 `missing: true` 占位节点；
  - `readSingleTranscriptMessage()`：按可寻址 id 取单条消息全文（画板详情用）；
  - `chatMapEnabled()`：`CHAT_MAP_ENABLED=false|0|off` 关（回滚开关，缺省开）。
- `src/agent/session-transcript.ts`：`foldTranscriptEntries()` 加 `options.includeHidden`——画板要保留**隐藏的定时触发那一轮**（否则它的回答会被并进上一轮）；打开时隐藏轮以 `hidden: true` + 空正文 + **无 id** 下发。`/messages` 端点永远不传，线上形状不变（`proactive-hidden.test.ts` 原断言全过）。
- `src/agent/shared.ts`：`ChatOrigins` 的条目增加可选 `atMessageId`（分叉点那条 assistant 的 id）。
- `src/index.ts`：
  - 分支端点写 origin 时带上 `atMessageId`（两条路径共用一个 origin 对象）；
  - 新增 `GET /api/v1/agent/chat/:conversationId/map`（404 `chat_map_disabled` 当开关关）；
  - 新增 `GET /api/v1/agent/chat/:conversationId/messages/:messageId`（`404 unknown_message`；隐藏触发不在列表里，也就取不到）；
  - `GET /agent/policy` 投影增加 `chatMap`（前端据此收起入口）。

### 前端

- 新增 `web/chat-map.js`（画板全部交互）：
  - 模型：节点 → 卡片（`${nodeId}:t${index}:q|a`）、车道（根第 0 道，分支按深度优先各一道）、自然坐标（父答卡 + 308px）；手动拖动位置存 `localStorage["lifediary.chatmap.positions.v1"]`，拖问卡带着答卡走，后续回合不跟（与 dsh-synapse 同口径）；
  - 相机：滚轮以鼠标为锚缩放（0.25–3，对数插值 90ms 指数追赶）、空白处拖拽平移、`定位`居中当前会话最后一轮、`整理`清手动位置 + 重拉 + 回 100%；
  - 卡片：问卡浅底 / 答卡白底，头部 `问/答 · 第 N 轮 · 工具 N · 自动`，正文 2 行截断，悬停出「进入 / 分支」；**空分支**（分叉后没说话 / 老数据读不出分叉点）画虚线占位卡，点开进会话；
  - 连线：SVG 贝塞尔——问→答竖向 S 曲线，答→下一问右中→左中 S 曲线，分支边虚线强调色；拖动只重算与该卡相连的线；
  - 详情抽屉：点卡片开，显示整轮问 / 答（答走 markdown）；全文按需 `GET /messages/:id` 补，取不到就保留预览；`进入会话` / `从这里分支`（与分支端点同一套 `branchable` 判据）；
  - 视口裁剪：只挂可见 ±700px 的卡片，平移缩放 rAF 合并；`#/map/<id>` 深链、浏览器前进后退可用；
  - 分支动作：成功后 toast + 直接进新副本（和会话页脚注的分支同一条端点）。
- `web/index.html`：会话顶栏加「会话地图」图标按钮（齿轮左侧）；`#view-chat` 尾部加画板骨架（顶栏 / 视口 / 详情抽屉）。
- `web/route.js`：新路由 `#/map/<id>`（`viewChat` 对 chat / map 都可见，画板整块盖上去）；画板路由的轨道高亮与侧栏行选中沿用对话页口径，深链到别的会话时把不属于当前地址的高亮摘掉。
- `web/style-26-chat-map.css`（新增，`style.css` 末尾引入）：`.map-*` 全套外观；`html[data-route="map"]` 下收起对话页三件套；窄屏（≤920px）详情抽屉改浮层。
- `web/state.js` / `web/plus-menu.js`：`capabilities.chatMap`（缺省 true，policy 说不开就收起按钮）。
- `web/nav-history.js`：`#/map/` 页名「会话地图」。
- 几何常量：卡片 252×104、问→答间距 18、回合步长 308、车道高 266、原点 (72,64)——照 dsh-synapse 的数，卡片加高放得下宋体两行 + 脚注。

## 明确没做（与方案一致）

- 不做工作区画布 / 跨会话总览 / 会话切换器——作用域写死在一个会话 id。
- 不在画板里写消息：没有草稿卡、继续追问、常用短语；写消息回会话页。
- 不做排列方位切换、子树折叠、卡片展开、工具过程展开。
- 不做实时流式更新：画板是进入时的快照，跑完一轮重进或点「整理」。
- 布局只存浏览器 localStorage：换机器 / 清缓存只是排版回自动布局，不丢会话。

## 回滚

`CHAT_MAP_ENABLED=false` 一行：地图与单条消息端点 404、policy `chatMap=false`、顶栏按钮收起、直链显示「已关闭」。前端文件留着不影响对话页。老数据兼容：`origin.atMessageId` 是可选字段，老副本走时间戳兜底，再读不出就画空分支占位卡（不猜）。

## 已知边界

- 隐藏定时轮在画板里是"自动"问卡（正文不显示、不给 id，详情取不到全文）——与 `/messages` 的隐藏口径一致。
- 分支节点显示的「第 N 轮」是**该会话内的绝对轮次**（含复制前缀），所以副本的新回合可能从"第 2 轮"起——刻意的：与母会话的答卡号对得上。
- 长会话：每节点最多回 400 轮（取最后 400），超过 `truncated: true`；预览问 400 字 / 答 1200 字，详情另取全文。
- 画板是快照：会话还在跑时最后一张答卡显示「还没有回答」，不轮询。
- 共享服务（39847）**没有重启**，重启后新端点与界面才在生产生效；桌面壳 / 浏览器要完整重启或硬刷新（ESM 缓存）。
