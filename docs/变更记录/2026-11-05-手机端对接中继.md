# 手机端对接中继（手机代理面 + RelayApi + 设置页多端区块）

日期：2026-11-05
类型：功能落地（多端同步方案的客户端对接；跨仓库：harness + lifediary App）

## 关键取舍：手机不直连中继 WS

v1 手机**不加 WebSocket 客户端**——Kotlin 侧信封/重连/顶替是一整套新链路，而手机与自家
harness 之间已有走稳的 HTTP + Bearer 通道。所以跨设备信息由 harness 经
**手机代理面**（`relay-mobile-proxy.ts`，五个端点）代理成普通 REST，走 `/api/v1` 既有鉴权
（403 空体口径不变），手机零新协议。手机直连中继 WS 是后续演进项，不是缺口。

## harness 侧（本仓）

- `relay-mobile-proxy.ts`：`GET /relay/overview`（连接面+名册，**实时拉新**）、
  `GET /relay/matrix/remote`（远端单列表）、`POST /relay/matrix/agent-delegate`
  （**手机跨机派活**：手机会话当发起会话，进度/终态汇报写回它，手机回读 transcript 即见）、
  `GET /relay/mirror/chats`、`GET /relay/home/overview`。单测 6 条挂全量。
- **修了名册过期缺口**：welcome 快照只反映连上那一刻，中间上线的设备"不存在"。
  中继 meta 加 `devices` 动作；`refreshDevices()` 在 overview / dispatch 前实时拉新
  （替身/老实现无此方法时防御跳过）。
- `dispatchRemoteDelegation` 改 async（要先 await 拉新名册）。

## 手机侧（lifediary 仓，提交 d8f3f29 + 契约提交）

- `core:pairing/RelayApi.kt`：三个调用点（overview / remoteDelegations / homeOverview），
  **失败一律返回 null 不抛异常**——这不是"用户操作有错"的场景（对齐 PairingApi 的
  异常语义分工）；Bearer 走现有通道。
- 设置页「多端」区块（`RelaySection.kt`）：**没数据不渲染整块**（中继没开时手机照常用
  局域网直连，不该占一张永远空着的卡）；状态词两三个字；远端单近况 ≤5 行；
  `ConnectionViewModel.refreshRelay()` 进设置页即拉 + 手动刷新按钮。
- 契约表 15→18 调用点（`接口契约.md` §0）。

## 验证

- harness：typecheck 0 错；单测 **180/180**；relay 探针 + matrix 探针复跑全绿。
- **端到端（真三进程）**：中继 + 甲机 + 乙机，按手机路径走通：
  overview（名册实时含两机）→ 建会话 → agent-delegate 点名乙机（202 + requestId）→
  乙机受理执行（`t-20261105-113917`）→ 终态 `needs_you`（faux 假模型没产生真实文件变更，
  被验收拦截——链路正确）→ 发起会话收到汇报「远端单 … 需要你：缺少执行前快照…」，
  手机回读 transcript 即见。
- 手机仓：`compileDebugKotlin` 过（core:pairing + feature:settings）；模块单测过；
  spotlessCheck 过。**真机安装与设置页实拍未做**（构建口約件见手机仓 AGENTS.md）。

  走的是电脑端会话，两条路都通。
- 伙伴归属 UI 未消费 `homeOverview`（客户端已带能力，接伙伴列表页时用）。
