# 2026-11-04 批次八落地：验收定夺权下放

## 背景

图纸 `docs/设计方案/2026-11-04-批次八细化（验收定夺权下放）.md`：手机任务文件级验证天然不可能，
改走「汇报验收」；负责人能定就定，真拿不准才报人。

实现全部在 chancellor 仓库（`<chancellor>`），harness **零服务端改动**。
本仓库只动验证脚本：`ts/apps/server/scripts/phone-worker-probe.ts` 增加「手机单 plan.json
writes 为空」断言，让「writes 置空」这条根修有直接证据，而不是只靠 done 间接推出。

## 做了什么

- chancellor `src/plan.ts`：`applyEmployeePlanPolicy` 对 `employee === "phone"` 确定性置空 writes。
- chancellor `src/review.ts`：`run.employee === "phone"` 整体跳过文件对比（无快照 / 0 变更两条路），
  落 LLM 验收 + `warnings: ["按汇报验收…"]`；`REVIEW_TRUST_REPORT=false` 恢复旧行为。
- chancellor `src/goal.ts`：手机单追加 `result.md` 全文；`inconclusive` → needs_you。
- 本仓库 `phone-worker-probe.ts`：新增 plan writes 与 review.json warning 断言。
- 回归验证覆盖 harness 全量单测与各探针，见下。

## 没验证到的

- **真机**：手机客户端未接，`phone` 探针用的是 HTTP 假客户端，真机不做（图纸允许）。
- **验收模型误判的长期概率**：确定性用例固定 verdict，只能证明分支走向；「汇报自吹自擂被当真」
  是已登记残余风险，靠桌面看结果 + `REVIEW_TRUST_REPORT=false` 回退兜底。
- **老单 / 续跑单的 plan.json 不回写**：新代码只在 review 时按 `run.employee` 降级；
  老 `plan.json` 里的 writes 仍是旧值，不追改历史文件。
- **chain 探针未在默认提示词下走到派活链路**：这是主 agent 的判断，不是链路回归；
  强制提示词下已确认派活帧正常。
