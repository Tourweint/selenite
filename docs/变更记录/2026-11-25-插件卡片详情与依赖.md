## 与任务书不一样的三处

1. **网格最小列宽用 380，不是 320。** `.set-page` 上限 1000、左右各 4px 内边距，内容列内宽 992；`minmax(320px,1fr)` 在 992 下放得下三列
   （3×320+2×10=980），与「1000px 两列」矛盾。380 时三列要 1160、两列要 770，两条结果都成立。
2. **「存储」写的是 `面板覆盖 / env / 默认`，不是 `env 覆盖 / 默认`。** 接口的 `overridden` 指的是 `agent-flags.json` 里有这个键
   （`flags.ts` 的 `listFlags`），不是 env；没覆盖但值 ≠ 默认才是 env 里配的。
3. **没做「当前被 X 关闭」高亮句和「打开前置」按钮**（方案 §5 设计期有，本轮任务书没列）。被锁的解释在徽标悬停提示、
   元信息「当前 关（被 X 关）」、父 chip 的警示色和详情弹层里。

另有一处是我自己定的：去掉了「默认关」徽标（元信息行已有「默认 关」）。要留回来是 `flagTags` 里加一行的事。

## 返工（同日）：数字型开关没有控件

**问题**：`flagControlMarkup` 只有「多档」和「布尔」两条路，`type: "number"` 的 `GOAL_MAX_ROUNDS` 落进布尔兜底——徽标「开」、拨杆「关」，
点拨杆会把值写成 `false` / `true`，卡上没法改这个数。

**改了什么**（只动 `settings-switches.js` 与 `style-14-settings-pages.css`）：

- 数字型卡尾换成数字输入框（`numberControlMarkup` / `commitFlagNumber`）：回车或失焦提交，留空 = 回到默认（PUT 空串，服务端已有这口径）；
  非整数就地 toast、不提交、回填当前值。被父关时禁用，显示它自己存的值。
- 徽标改「数字」；元信息「当前」显示数值本身；`applyFlagControlValue` 同步数字框；「留空回到默认」成功后整页回读一次。
- 页首计数不把数字型算进「N 个开关」和开 / 关，单列「另有 1 项是数字」。

**没做到位的一处**：接口 `GET /api/v1/agent/flags` 不下发 `min` / `max`（`flags.ts` 的 `listFlags` 没有这两个字段，`min: 1, max: 200` 只在清单里、
服务端自己校验用），用户口径是不改接口，所以前端不知道上界。现在输入框的 `max` 是兜底的 `999999`；
越界值（如 500）前端拦不住，会发一次 PUT，由服务端回 400、它的原话进 toast、输入框回填。「非整数不提交」做到了，「越界不提交」没做到。
前端已按「接口给了就用」写好：`listFlags` 补上 `min` / `max` 后不用再改前端（那是契约新增，要同步回写 `接口文档.md`）。

**验了什么**：`node --check` 通过；6 个 web 测试文件 30 项全过；jsdom 走查 65 项全过（原 53 + 新 12，含任务书点名的两条）；
假服务端已改成和真接口同形（不再把清单里的 `min` / `max` 漏给前端）。
**没验的**：没在真实服务上看；数字卡的截图生成了但我没读成（读取失败两次）；步进钮连点的防抖没评估。
