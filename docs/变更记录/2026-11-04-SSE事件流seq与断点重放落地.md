# 2026-11-04 SSE 事件流 seq 与断点重放落地（调研方案建议③）

## 做了什么

聊天 SSE 流的每一帧带会话内单调 `seq`，先落库再外发；客户端断流后带 `sinceSeq` 回
`GET /messages` 精确补缺帧。方案 = `docs/设计方案/2026-11-04-SSE事件流seq与断点重放.md`
（含落地偏差表 7 条），来源 = 参考项目调研建议③，用户批准后实施。

## 实施中抓出的三个坑（探针价值所在）

1. **落库帧必须带 seq**：第一版先落原始帧、外发时才补 seq——重放出来的帧缺 seq，
   探针"重放与实发一一对应"抓出。修正为落库的就是完整帧。
2. **fromSeq 语义**：第一版返回"窗口下限"，正确口径是"返回首条的真实 seq"（一条没有 = since+1），
   自己的单测预期先纠回来，口径写进了 chat-events.ts 与接口文档。
3. **探针 env 断链**：§12 重启服务时没把 `AGENT_SSE_SEQ_DB_PATH` 带下去，§13 落到默认库、
   seq 从别的段落残留帧接着数（[4,5,6]）。修法 = 各段重启都显式带路径，探针注释记了这笔。

## 已知边界

- web 端只做断流兜底补帧，没有"自动重连续流"（手写 fetch 流重建渲染状态超出本批）；
  刷新页面走 openChat 全量回读，不受影响。
- 事件库不是审计日志：滑窗 500 条，窗口外的缺口客户端按 fromSeq 判断全量重建。
- OpenAI 兼容层不动（手机走全局待办轮询，不走这条流）。
- 新测试 `chat-events.test.ts` 已挂进 `pnpm test` 清单（吸取上次教训，当场挂上）。

## 回滚

`AGENT_SSE_SEQ=off` 一行环境变量回到无 seq 形态（已实测）；删 `.data/chat-events.sqlite` 即清掉事件库。
