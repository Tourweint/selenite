## 一、回信送达兜底

### 审计结论（2026-11-15，静态只读，HEAD 前 `13cbbd8`）

正常路径稳：settle 三写（留言表 in + 任务专线镜像 + 会话正文）+ 完成即唤醒；忙时正文走 durable inbox；
会话归档不影响写回。四个真口子：

1. **终态落盘 → 汇报写回之间进程崩溃**：chancellor 落终态即删 inflight，恢复扫描跳过该单，汇报正文永久丢。
2. **重试路径不唤醒**：`defaultRetryRuntime.report` 只写汇报、不唤醒，异常还被 `.catch(() => undefined)` 吞掉。
3. **忙退避耗尽 / 链保险丝 → 唤醒队列内存清空**：正文在会话里，但执事不再被叫醒；重启也丢 pending。
4. **唤醒轮模型失败 → pending 已被取走，不重试不回灌**。

### 改了什么

| 改动 | 位置 | 说明 |
|---|---|---|
| `delivered` 列（0 待送达 / 1 已送达 / 2 跳过） | `delegation-messages.ts` | 老库自动 `ALTER TABLE ADD COLUMN` 默认 1（历史行不触发批量补送）；`append` 返回行 id；新增 `markDelivery` / `listUndelivered` |
| settle 落 in 行记待送达、行 id 随汇报带出 | `delegation-start-delegation.ts` + `DelegationReport.deliveryMessageId`（内部字段，不进契约） | idle / autoReport 关 / 无 report 通道 → 当场销 2（设计内不写回，不是丢失） |
| 写回结果三态 | `agent/lifecycle-thinking.ts` `reportDelegationResult` → `"ok" \| "missing" \| "error"` | ok 销 1、missing 销 2、error 留 0 等下次启动补送 |
| 启动补送扫描 | `recovery-report.ts` `redeliverUndeliveredReports` + `index.ts` 启动段 | 正文 = 留言表原文 + 「（重启补送）」前缀；成功走完成即唤醒；票已清掉 / 会话不存在销 2 不反复扫；开关 `DELEGATION_REPORT_REDELIVERY` |
| 重试单也唤醒、失败不静默 | `delegation-actions.ts` | `.catch` 改为 warn 一行；补 `wakeOnDelegationReport` |
| 唤醒队列落盘 + 启动恢复 | `delegation-wake.ts` `restoreDelegationWakeQueue`、`.data/wake-pending.json` | 原子写（临时文件 + rename）；`AGENT_WAKE_PENDING_PATH` 供测试隔离 |
| 耗尽 / 失败改有限次重排（翻案） | `delegation-wake.ts` | 忙退避耗尽 / 链保险丝 / 唤醒轮失败 → 保留 pending、10 分钟后再跑，最多 3 次；放弃必留一行 warn。**翻案登记**：批 29 的"耗尽即放弃"按用户"确保收到回信"口径收紧 |
| 重排计数只在队列真清空时归零 | `delegation-wake.ts` | 首轮实现按"唤醒轮成功"清零，链式唤醒每轮都成功 → 保险丝重排永远攒不起次数；单测抓到后改掉 |

**刻意不做**：补"派活方会话被永久删除"（删除有闸门挡着；missing 销 2 已如实记账）；回执 accept 前的极窄崩溃窗；
`DELEGATION_WAKE_ENABLED=false` / 非 canonical 会话维持"裸汇报无唤醒"设计形态；不改 chancellor 的 inflight 时序（跨仓契约）。

## 二、侧栏对话按创建者分组

### 契约（增量）

`GET /api/v1/agent/chats` 追加 `tasks` 键：`{conversationId(task-<票号>), ticketId, title(需求首行≤60字),
status(作废投影), canceled, originStatus?, lastAt, dispatchedBy("chief"|执事uuid), dispatchedByName, hostConversationId?}`。
只收 durable 里**真实存在**的任务专线（`TASK_AS_CONVERSATION` 关闭 / 8g 前旧单不出现）、只收根单、归档排除、
孤儿会话跳过。`limit` 与 chats 同参。手机端 / 旧客户端忽略未知键。

新增：`task-chat-index.ts`（索引）、`task-chat-owner.ts`（归属 / 标题 / 开关三个纯函数）。

### 界面

- `web/chats-groups.js`：`其他对话`（用户自己的普通对话，原有行原样）→ `总管` → 各执事，组头可收起
  （localStorage `lifediary.chatFolders`）；任务行 = 灯 + 需求首行 + 相对时间，点击直接打开任务专线会话。
- `web/chats-list.js`：行构建抽成 `buildChatRow`，`renderChats` 按开关分流新旧渲染。
- `web/tasks-cards.js`：分组形态下 `renderTasksMini` 清空让位（旧版平铺由 `SIDEBAR_TASK_GROUPS=false` 恢复）。
- `web/style-02-sidebar.css`：`.chat-folder*` 几何对齐既有 `.chat` / `.side-sec-head`。

**回滚**：`SIDEBAR_TASK_GROUPS=false`（flags hot）→ 服务端不下发 `tasks`、前端回旧版平铺列表。

**刻意不做**：人物列表按创建者挂文件夹（用户只要求会话）；手工把普通对话挪进人物名下；任务行置顶 / 改名 / 归档
（管理去任务中心）；组内二级折叠；手机端。

## 四、已知边界

- 宿主会话写回连续失败且长期不重启期间，宿主会话里会晚一条；任务中心 / 留言表 / 专线镜像始终有结论原文。
- 唤醒重排 3 次封顶：超过就放弃转述轮（正文仍在会话里）。
- 普通对话里派出的活归「总管」名下（宿主不是 `partner-` 前缀一律 chief）；群成员会话派活按成员执事归组。
