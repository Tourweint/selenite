# 插话统一：忙时消息全 steer + 打手插话通道（2026-11-19 批1）

方案：`docs/设计方案/2026-11-19-插话统一（全steer·插件卡·worker通道）.md`（用户 2026-11-19 拍板：忙时消息全改插话、followUp 想留就进插件卡、多条插话都要生效、加标记、打手可被人和任何 agent 插话）。

## 改了什么

- **缺省翻转**：`DEFAULT_USER_INPUT_WHEN_BUSY` followUp→steer（`agent/user-input.ts`），产品承诺口径同步改（"人的消息永远插得上话"不变，落点从"排队到收尾"变"插进当前轮，没赶上边界如实回执"）。回滚 `AGENT_STEER_DEFAULT=false`（走 flags/插件卡"忙时消息"，即时生效）。
- **多条插话全生效**：会话装配恒带内核 `steeringMode:"all"`（`reliability.ts`），回滚 `AGENT_STEERING_MODE=one-at-a-time`。
- **插话标记**：忙时 steer 的提交正文第一行加 `[插话]`（`session-stream.ts`，模型可见、历史可见、durable 重放存活）；前端检测前缀剥标 + 挂「插话」徽标（`chat-thread.js` + `style-05-message-extras.css`，复用任务中心 tk-badge 皮）。
- **打手插话通道**：chancellor `worker-main.ts` stdin 一行 JSON `{"type":"message","mode","text"}` → `conversation.submit`；`employee/native.ts` spawn stdin ignore→pipe、按单号注册活子进程、导出 `forwardNativeWorkerMessage` / `WorkerNotRunningError`。端点 `POST /api/v1/agent/delegations/:ticketId/message`（`delegation-mount.ts` + `delegation-actions.ts`），只认来源会话（`not_authorized`）；agent 侧 `send_to_agent` 加 `mode` 参数（单号目标走此通道）。
- ZCode 会话引导三条原则照抄：不可引导优雅回退（steer 提交永被 inbox 收下，无拒绝路径）、诚实回执不变（inserted/new-turn）、引导消息有投影（徽标）。

## 缓存前缀资产说明（工具描述）

`send_to_agent` 描述仅在 `WORKER_STEER_ENABLED` 开时多一段"给正在跑的本机打手半路补话，target 写单号，mode=steer 插进它当前轮（默认）/followUp 排到收尾"；关=描述与改动前逐字节一致（工具本体在 `partner-relay.ts`，回滚形态=不注入 forward 依赖）。

## 验证

- `pnpm typecheck` 全绿；全量单测 5 红经 HEAD 基线 worktree 对照确认全部为主干既有（arch-guard×3 / auxiliary split 钉死断言 / partner-work Windows EPERM），受影响文件子集 168 条全绿。
- worker 通道两轮实机：faux 模型下 steer+followUp 双写落库、坏 JSON 忽略；真 dispatchTask→native 全链，单号注册生效、进程退场后写=可识别报错。
- 端点实机：404 / 400 空 text / 400 坏 mode / 下架 400 worker_steer_disabled；`node --check` 三个 web js 过。

## 边界（刻意没有 / 已知限制）

- 外部 CLI（claude/codex/qoder）没有插话通道（非交互锁死、无内核 inbox）——如实报 `worker_not_running`。
- 不带 whenBusy 的老调用方（手机）跟随新缺省=steer（跨端语义变化，本端零改动）。
- 插话不写 `delegation_messages` 留言表、不镜像专线（只在打手 durable 上下文可见）。
- 插话窗口=子进程存活期；"最后一次输入收尾→退出"的极窄窗口内写入可能被管道收下但丢失（代码注释如实写）；收尾后写入一律可识别报错。
- 前端按 `[插话]` 前缀检测徽标，用户手打该前缀会被当插话渲染（约定优先，未防伪）。
