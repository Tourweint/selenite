## 为什么做这一批

用户口径：先自己调查 Cindy 的记忆系统怎么实现（"咱们也要做一个"），同时看 ZCode；
重点是**运行时怎么记住用户偏好**；**已经存好的记忆后期再接入**。

调查结论（两家源码实读，2026-11-06）：

- **cindy**：`packages/maker-core/src/memory/` 一条事实一个 `<type>_<slug>.md`，
  `MEMORY.md` 索引由 `write()/delete()` **同步重建**（刻意反 Claude Code 的"让模型手写索引"）；
  四类分片 `user/feedback/project/reference` + 内部 `digest`；`feedback` 类**强制**写
  `**Why:**` 与 `**How to apply:**`；工具面是 `list_tools`/`call_tool` 两个入口 +
  7 个内部工具（省 token）；`memory_review` 只出建议不动手。
- **ZCode**：`docs/design/v2/memory/README.md` 是验收级 spec；事实文件 frontmatter 由运行时补
  `node_type` + `originSessionId`；检索两条**互斥**分支（`default-index` 索引常驻 /
  `semantic-recall` 用 Lite model 做 selector，当前恒为前者）；后台 Extraction 是
  fire-and-forget 子 Agent（1 running + 1 latest-pending，最多 5 turn，无操作回 `Nothing to save.`）；
  Dream 设计完整但**故意不接自动触发**。
- **我们**：四层框架齐全，但 `HeuristicExtractor` 恒把每句记成 `episode`——
  `preference` / `fact` / `entity` 三个 kind 从抽取层**永远产不出来**，偏好只能靠模型主动调
  `remember`，实测基本不记。这是本次要补的真缺口。

## 改了什么

### 1. memory 包（`ts/packages/memory/`）

- `src/extract.ts`：新增
  - `PreferenceExtractor`：模型调用**注入**（`(messages) => Promise<string|null>`），
    包内不碰模型/env/配置；抛出按"这轮没抽到"处理，绝不冒泡。
  - `parsePreferenceJson`：纯函数，**永不抛**。容忍 ```json 围栏、前后解释、
    `{preferences:[…]}` 包装；`confidence < 0.6` 丢弃；最多 5 条。
  - `renderPreference`：`偏好\nWhy: …\nHow: …`（两段可缺），单条上限 400 字。
  - `renderTranscript`：只留用户原话 + 助手首句，从最新往前取，总预算 6000 字。
  - `PREFERENCE_PROMPT`：只抽"长期偏好"，明确列出三类反例（这次的要求 / 事实经历 / 提问）。
  - `HeuristicExtractor` **一字未动**（含它"一律 episode"的取舍）。
- `src/engine.ts`：
  - `ingestTurn(messages, scope, { preferenceScope })`：`kind === "preference"` 的候选
    写入前改挂 `preferenceScope`。抽取器只回答"是不是偏好"，"该存哪"是装配层的知识。
  - `buildContext`：偏好单独成段排最前（`【用户偏好】` / `【其它】`）。
    **没有偏好时输出与旧版逐字节一致**（不出现任何分组标题）。
  - 新增 `supersede(id, byId)`（替代者必须存在、不能自指）、`forget(id)`、
    `list({scopes, limit, includeSuperseded})`（分组：preference → fact → entity → episode）。
- `src/store.ts`：`MemoryStore` 加 `remove(id)`；SQLite 实现同时清 FTS 镜像行。
- `src/index.ts`：`createMemoryEngine` 收 `extractor?`（不传 = 原行为）。

### 2. server 装配

- `src/memory-extract.ts`（新）：`MEMORY_EXTRACT` 三档（`auto`/`llm`/`rule`）、
  一次性调用（`completeSimple`，20s 超时，`maxTokens=600`，`temperature=0`）、
  `LayeredExtractor` = 偏好走 LLM + 其余走规则（两套 kind 不相交）。
  **faux 模式视为"没有模型"**——否则假文本会被写成偏好。
- `src/agent.ts`：引擎装配传 extractor；`preferenceScopeOf()`（主对话 `global` / 执事 `partner:<id>`）；
  `memoryOverview` / `forgetMemory` / `supersedeMemory` 三个导出。
- `src/index.ts`：会话结束时 `ingestTurn(..., { preferenceScope })`。
- `src/memory-api.ts`（新）+ `index.ts` 挂载：三个端点（见接口文档 §2.15）。

### 3. 设置页（`web/app.js` + `style.css`）

新增「记忆」分区（Lucide `brain` 完整八图元）：当前状态 / 抽取方式两行 + 分组列表
（偏好 / 事实 / 人事物 / 经历），每条显示正文、`Why/How`、日期、召回次数，
带「标过时」「删除」两个动作（都需 confirm，删除是硬删）。空态与未启用态各有文案。

**刻意没有**：编辑、搜索、导出、分页（千级以内滚动足够）。

## 不确定 / 待观察

1. **抽取质量**：prompt 是窄口径（只抽偏好 + 三条反例），但真模型下"这次的要求"被误判成
   "长期偏好"的概率只能靠实跑观察。缓解手段：`confidence < 0.6` 丢弃、单轮最多 5 条、
   正文带 `Why/How`（人一眼能看出是不是），以及设置页可删可下线。
2. **成本**：每轮结束一次小请求（≤600 字输入、`maxTokens=600`）。长会话多时是可见增量；
   `MEMORY_EXTRACT=rule` 可整体关掉。
3. **`session` scope 的沉淀会持续增长**；设置页只看 `global`，清理仍走删会话——若后续
   session 记忆成为噪声源，需要单独立项做保留策略（本批明确不做）。
4. **已存记忆的接入**按用户口径留到后期：`veracity` 已有 `imported` 值、`source` 是自由字符串，
   导入器可以直接落 `source: "import:<来源>"` 而不动契约。
