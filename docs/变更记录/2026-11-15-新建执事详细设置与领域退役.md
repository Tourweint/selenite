# 2026-11-15 新建执事弹窗详细设置 + 领域标签退役

## 改了什么

### 一、新建执事弹窗：改个名字就能详细设置（用户口径）

选模板不再是"只预填一句话"——弹窗升级**宽档**，模板条 + 名字 + **「详细设置（可选）」**五个折叠块：
一句话身份 / 口吻 / 里子 / 处境 / 岗位契约。

- 选模板 → 五块全按模板预填（口吻里子处境用档案页同款字段表 `PF_PERSONA_EDITORS` 渲染，
  `pfPersonaFieldMarkup` / `pfPersonaValue` 已从 partner-profile.js 导出复用，ESM 环双方顶层只声明）；
- 任何一块都能展开改，改了按改的入库，不改就按模板入库；
- 空白新建也能细配：填了哪块就开哪块（静态三开关随内容开）；
- 提交统一走 `applyTemplateChain` 四步链，新增 `opts.contentsOverride`（逐块覆盖模板值）/
  `opts.contractOverride`；空白新建 = 空白伪模板（`PT_BLANK_TPL`，work 预设铺底）。

### 二、领域标签退役（用户口径"领域现在没啥用了"）

核实（2026-11-15）：日常派活路由按**执事 id / 会话链接**走（2026-11-07 起），domain 只剩
minister dispatch 老链路（默认关）与任务中心展示。**UI 全撤、服务端字段保留**：

- 新建弹窗领域输入框、招聘确认弹层领域必填、档案页领域编辑（hero tag + 字段 + wire + 校验）、
  列表卡领域显示、编辑弹窗领域行——全部移除；
- 监工模板去领域（"一摊事的负责人"），`toolProjection: 1` 显式钉住（原"带领域→结果契约跟随默认开"的行为保持）；
- **服务端一处放宽（契约语义变化）**：PATCH `dispatchAuthority` 不再要求执事带 domain
  （原 400"该执事不带 domain，没有派发权可切"是 2026-11-06 派活按 domain 找人时代的检查）；
  列表投影 `dispatchAuthority` 也改为按布尔存在性给（原按 domain）。
  **接口文档回写**：接口-端点4（见下）。

## 为什么

- 用户：选模板只改名字，"对这个人物的定义比较多"的详细设置够不着——模板的价值就在详细内容，
  建档时就该可见可改。
- 用户：领域"填了没反馈"，日常派活根本不用它——留着是空牌。

## 坑

- 第一次验收抓到：监工模板 PATCH dispatchAuthority 被服务端 400 拒（无 domain）——
  领域退役必须连带放宽这个旧检查，否则监工模板建不出"接派单"的人。
- 首次失败尝试会留下"半个人"（POST 成功、PATCH 失败）——建档链中间步失败本就可接受
  （档案页补得回来），本次测试数据用删除入口清掉。
- openProjMenu 的 separator 是挂在条目上的属性；openModal 宽档参数在第三位；build 回调带 await 要 async。
