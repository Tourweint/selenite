**方案**：`docs/设计方案/2026-11-24-外部记忆库向量检索与检索超时.md`（设计期稿；本次按任务书落地，
与方案原稿的 env 口径不同——深检索与两档超时**落在 `.data/memory-bank.json`**，**不新增 env**）。

**范围**：只加 harness 侧的调用面、配置字段与页面入口。**不动** `persona_recall` / `persona_write` /
`MEMORY_BANK` 退役（下一批），不动库侧实现、不改 JSON 输出形状、不改工具描述与注册顺序。

## 改了什么

1. **`apps/server/src/persona-ask.ts`**
   - `PersonaAskOptions.deep?: boolean`：true 时在 argv **末尾**追加 `--deep`（位置在 `--limit N` 之后）；
     不传 / false = argv 与旧版逐字节相同。
   - 超时文案动态化：`persona 检索超时（${Math.round(timeoutMs / 1000)}s）`。
   - 新增 `PERSONA_LIGHT_TIMEOUT_MS = 8_000`；`PERSONA_ASK_TIMEOUT_MS = 15_000` 保留为工具侧兜底。
   - `askPersonaCatalog`（`--catalog-only` / 接入检测）不接收 deep，argv 仍是 `<entry> --catalog-only`。
   - `PersonaAskResult.timedOut?: boolean`：**只有超时分支**置 true，其余失败不置。
2. **`apps/server/src/tools.ts`（2026-11-24 收口）**
   - 结构孪生 `PersonaRecallResult.timedOut?: boolean` 同步加。
   - `recall` 外部槽 / `persona_recall` 的 `!ok` 分支：**只有 `timedOut === true`** 把 `result.error`
     （如「persona 检索超时（15s）」）作为 `err()` 的 message 给模型，hint =
     「告诉主人这次查得太慢、没查完；可以换更短的关键词再试一次，别连续重试同一个查询」。
     其余失败（退出码 / 结构不符 / 关闭态）维持原通用文案，不透传 error。
   - 工具描述 / schema / 注册顺序逐字节未动。
3. **`apps/server/src/memory-bank.ts`**
   - `ExternalBankRecord.deep: boolean`（默认 false，只认 JSON 里的 `true`）。
   - `MemoryBankConfig.timeouts: {lightMs, askMs}`（默认 8000 / 15000）；解析时缺失 / 非数字回落默认，
     数字越界 clamp（light 500..30000、ask 1000..120000），小数取整；不支持 0 = 不超时。
   - 原子写回覆盖新字段，并**保留未知字段**（顶层 + 同一库 external 行上的扩展字段；换库不带过去）。
   - `bankAsk` / `MemoryBankAccess.ask`：把 `external.deep` 与 `timeouts.askMs` 传给 `askPersona`。
     页面搜索 `POST /bank/search` 也走同一条 `bankAsk`，**与工具调用一致，跟随 `external.deep`**
     （召回只有一套口径，不加调用方开关）。
   - 新增 `setMemoryBankTimeouts()`（局部更新）、`bankTimeouts()`（轻召回取 lightMs）；
     `memoryBankState` 投影带出 `deep` 与 `timeouts`。
4. **`apps/server/src/persona-inject.ts`**
   - `PersonaLightRecallOptions.timeoutMs?`：传给 `askPersona`；缺省
     `PERSONA_LIGHT_TIMEOUT_MS`（8s）。轻召回**永远不传 deep**。
   - 外接库槽位的 lightMs 接线：`agent/lifecycle-injections.ts` 的 `personaRecallLightTextFor`
     新增 `timeoutMs?`；`agent/lifecycle-harness.ts` 外部槽位传 `bankTimeouts().lightMs`
     （内置 / `MEMORY_BANK=false` 路径不传，仍走 8s 兜底）。
5. **`apps/server/src/memory-api.ts`**
   - `GET /api/v1/agent/memory/bank`：返回值带出 `external.deep` 与 `timeouts`。
   - `PUT /api/v1/agent/memory/bank`：**局部更新**，body 可只给 `active`、只给 `timeouts` 或两者都给；
     缺省字段不动（老客户端 `{active}` 形状继续有效）。`timeouts` 只认数字（类型不对 400
     `bad_request`），越界由服务端 clamp。
   - `PUT /api/v1/agent/memory/bank/external`：支持 `deep`（布尔；非布尔 400），缺省 false。
6. **前端（`web/memory-page.js` + `web/style-21-answer-memory.css`）**
   - 记忆页「记忆库」卡的接入表单新增勾选「支持深检索（这个库理解 --deep）」，保存时写
     `external.deep`；旁边一行「检索密钥由记忆库自己保管，Lifediary 不存」。已接入的库在状态行尾
     显示「· 深检索」。
   - 「记忆库」卡新增一行「记忆工具时长」（轻召回 Ns / 工具 Ns）+「调整」：弹层里编辑两个毫秒值，
     保存到 `PUT /bank {timeouts}`。
   - 页内操作手册补 `[--deep]` 与密钥边界说明。
7. **文档**
   - `docs/基线文档/接口-端点6-记忆课题与搜索.md` §2.15.11：配置示例、GET/PUT `/bank`、
     PUT `/bank/external` 字段表、读写路由（含超时透传与页面搜索跟随 `external.deep`）、
     注入、回滚、刻意不做。
   - `docs/基线文档/接口文档.md` §6 `MEMORY_BANK_PATH` 行：配置形状补 `deep` / `timeouts`，
     注明**不新增 env**。
   - `docs/接入手册/外部记忆库接入（两个文件）.md` §2.1：命令加 `[--deep]`、旧库两种失败形态、

   - `docs/设计方案/2026-11-24-外部记忆库向量检索与检索超时.md`：§3.2 / §十的页面搜索口径改为

## 默认值与回滚

| 项 | 默认 | 回滚 |
|---|---|---|
| `external.deep` | `false`（argv 与 2026-11-23 版逐字节相同） | PUT `/bank/external` 带 `deep:false`，或改 `memory-bank.json`；立即生效（每次调用现读配置） |
| `timeouts.lightMs` | `8000` | PUT `/bank` `{timeouts:{lightMs:15000, askMs:15000}}` 回到"两处都 15s" |
| `timeouts.askMs` | `15000` | 同上；删掉 `timeouts` 字段 = 8000 / 15000 |
| 整体 | — | 不动 `MEMORY_BANK`（本批不退役）；`MEMORY_BANK=false` 仍回旧形态 |

- 旧 `.data/memory-bank.json`（只有 `v/active/external`）读进来即按默认工作：`deep=false`、
  `timeouts={lightMs:8000, askMs:15000}`；写回时补字段并保留未知字段。
- 密钥边界：配置里只有一个布尔 `deep`。检索密钥（如 `DASHSCOPE_API_KEY`）由库自己的环境保管，
  harness 不读、不存、不传；页面说明里也写明。
