## 1. 背景

App 端删掉了账号体系（`core:auth` / `core:billing` / `core:sync` 全部退役），
但 harness 仍要回答"这台手机是不是被允许的"。需求方定案：**一步到位做成一次性配对码**——
二维码里只放短期、单次、可作废的短码，扫码换长期设备凭据；不做"码里塞长期令牌"的过渡版。

同时手机端不再保留对话正文、只留会话清单，因此需要一个**只含元数据的会话索引**，
给重装 / 换机兜底（正文仍按 id 现取）。

## 2. 新增

| 文件 | 内容 |
|---|---|
| `apps/server/src/pairing.ts` | `PairingStore`：码签发 / 兑换 / 校验 / 设备列表 / 撤销；文件存储 `.data/pairing.json`（`PAIRING_STORE_PATH` 可改）；**码与令牌都只存 sha256**；设备上限 32（按最久未用淘汰，撤销的不占额度）；`buildPairUrl` / `resolvePairBase` |
| `apps/server/src/pair-page.ts` | `/pair` 页面：每次打开换新码、二维码（PNG data URL）、剩余秒数；带 `?token=` 时额外列出已配对设备并可一键撤销 |
| `apps/server/src/agent.ts` | `listChats(limit)`：会话索引（`conversationId` / `createdAt` / `lastAt` / `firstText` / `turns`），按 `lastAt` 倒序 |
| 依赖 | `qrcode` + `@types/qrcode`（服务端渲染二维码，App 不参与，无需引二维码库） |

配对链接形态：`lifediary-pair://v1?base=<origin>&code=<6 位码>`——
自定义 scheme 由 App 自己 parse；**码里只有短码，不含任何长期密钥**，截图泄露的是废码。
`base` 默认取首个非回环 IPv4 + 端口，可用 `PAIR_BASE_URL` 覆盖（USB 反代场景）。

## 3. 改动

- `auth.ts`：`createAuthMiddleware(expectedToken, { verifyDeviceToken })` —— `Bearer` 现在接受
  **共享令牌 ∪ 设备凭据**；未配 `AGENT_TOKEN` 时 loopback 直通、局域网必须持有效 deviceToken。
  令牌 / 哈希比较仍是定长比较（不让计时侧信道说出"前缀对了"）。
- `index.ts`：挂 `/pair`、`/api/v1/pair/{info,code,redeem,devices,devices/:id/revoke}`、`/api/v1/agent/chats`；
  **`pair/info` 与 `pair/redeem` 明确免鉴权**（手机此刻手里还没有任何凭据）；redeem 每 IP 每分钟 10 次；
  启动日志多一行配对页地址，鉴权那行改成"共享令牌 + 配对设备凭据"。
- `.data/` 下新增 `pairing.json`（运行期生成，不进版本库）；不新开 SQLite schema，
  也刻意不混进 `pi-durable` 的表（内核管的表混外部数据，升级会痛）。

## 4. 安全口径

- **码**：6 位数字、默认 300 秒（`PAIR_CODE_TTL_SECONDS`）、单次、同一时刻只留一枚（新码顶掉旧码）、
  **同一枚码错 5 次即作废**、redeem 每 IP 每分钟 10 次（防暴力枚举）。
- **存储**：码和设备令牌都只存 sha256，库文件泄露 ≠ 凭据可用；设备令牌 32 字节随机（base64url，43 字符）。
  写入用 tmp + rename，避免半截文件。
- **撤销**：电脑上（`/pair?token=…`）一键撤销，该 deviceToken **下一次请求即 403**。
- **展示**：二维码只出现在 harness 本机页面 / 控制台；`pair/info` 只回 `{name, version, pairing}`，不含密钥。
- **免鉴权面**：只有 `pair/info`（纯探活）和 `pair/redeem`（必须带有效码）两个，其余 `/api/v1/*` 照旧要凭据。

## 5. 验证（2026-10-29 复跑，真实进程）

两次独立起服务：主用例 `:8099`（`AGENT_TOKEN=test-shared-token`），过期用例 `:8098`（`PAIR_CODE_TTL_SECONDS=1`）；
存储与库文件都指向临时路径，没碰正式 `.data/`。

## 6. 已知取舍与局限（如实登记）

- **会话索引是"逐个会话读一遍 context"**：为了拿首句和时间，`listChats` 会对每个会话开一次上下文，
  会话数量上来会明显变慢；且 `byExternal` 取的是最后 `limit` 条（映射插入序）再按 `lastAt` 排序，
  不是严格的"最近 N 个"。真到那时应改用 durable 的 entries 分页 + 单独维护索引表。
- **未配 `LLM_API_KEY` 时**索引直接返回空数组（mock 模式不落库，没有会话可列）。
- **单文件 JSON + 全量重写**：进程内没加锁，隐含契约是"一个 harness 只跑一个进程"。
  多实例共享同一个 `pairing.json` 会互相覆盖。
- **redeem 限流是进程内 Map**：重启清零，不认 `X-Forwarded-For`（本机/局域网场景够用，挂反代后要改）。
- **撤销只挡新请求**：已经在跑的 SSE 流不会被掐断（要停那一轮用 `POST .../stop`）。
- **配对页每次刷新都作废旧码**：这是刻意的"一次性"语义，别在两台手机上同时开着这一页等扫。
