## 刻意不做

- 不做 key 轮换 / 额度统计 / 自动计费；
- 不做每家的代理、站点过滤、时间范围等高级参数；
- 不做手机端搜索源配置（手机不配上游，沿用既有分工）；
- 不做搜索源插件 / 动态加载；新增一家 = 目录加一条 + 映射函数；
- 不做模型供应商原生搜索；`web_search` 仍由本仓适配层回答；
- 不做搜索历史持久化 / 去重 / 缓存；
- UI 只给 SearXNG 暴露地址输入；其他源可用 API 的 `baseUrl` 覆盖，但界面未展开（避免行内再堆一层字段）。

## 回滚

- 一行 env：`SEARCH_MULTI_VENDOR=false` / `0` / `off` → 只读 DeepSeek 一条源，目录只剩 DeepSeek，
  PUT 其他源返回 `multi_vendor_disabled`；旧 `.env` key 照旧可用。
- 删除 `.data/search.json` 会回到「从 env key 反推源」的旧形态。
- 设置页入口回滚：单提交 revert 本件即可（无数据迁移；`search.json` 留着不影响旧代码）。

## 同日线上修复（用户实测「点了没反应」）

- **根因**：运行中的服务进程还是本件之前的旧代码（新前端 + 旧后端）。旧 GET 只回
  `{ok,keyEnv,hasKey}`，没有 `sources/vendors`，前端于是没有目录可加，点「添加搜索源」
  只弹「搜索源目录还没读到，刷新页面再试」。
- **处置**：重启服务进程（桌面壳守护自动拉起新进程）；线上 GET 已回 `sources[] + vendors[]`。
- **前端兜底**：GET 缺 `sources`/`vendors` 时，列表直接写「服务端还是旧版本：去 设置 → 服务
  点「重启」，再刷新这一页。」，加源按钮也复用同一句，不再只给模糊的「刷新页面」。
- **按钮**：`添加搜索源` 从 `.ghost` 改成 `.btn-primary`。`.ghost` 不设 flex / nowrap，
  内联 SVG 会独占一行、中文换行，按钮被撑成上下两块；`.btn-primary` 自带 inline-flex +
  nowrap + 14px SVG，与「新建供应商」同款。
- **线上复测**：重启后在 `#/settings/models` 添加 SearXNG（地址指本地 healthz）→ 行内测试
  返回 404（预期，健康检查不是搜索结果）→ 移除；三步都通。测完删掉空的
  `.data/search.json`，恢复「没文件时从 env 反推源」的旧形态。

## 已知边界 / 不确定

- **没有真 key 连各家生产 API**：适配层用本地 stub 验了请求路径、认证头、回包映射；
  百度的 `references`、元宝的 `Response.Pages` 按官方文档 + magpie 同款实现，真 key 首次接入时若字段有出入，
  改 `search-vendors.ts` 对应读取即可（契约不变）。
- **百度选的是千帆 AI 搜索** `POST /v2/ai_search/web_search`（`qianfan.baidubce.com`，Bearer）。
  若用户说的是百度搜索开放平台另一条接口，需要换适配器。
- **「REX」已确认就是 Exa**（用户 2026-11-12 回复「对，就是 exa」）。
- UI 的「添加搜索源」按搜索源目录顺序列出未添加的源，不支持自定义排序目录；顺序在已添加行上用↑↓调。
- 搜索源 key 的落点/优先级沿用供应商纪律：`.env` 已有值优先于 `.data/provider-keys.json`；
  界面直填会热注入当前进程，重启后若 `.env` 有旧值仍以 `.env` 为准。
