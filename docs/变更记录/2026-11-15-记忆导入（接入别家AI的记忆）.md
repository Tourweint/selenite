# 记忆导入：接入别家 AI 的记忆（2026-11-15）

方案：`docs/设计方案/2026-11-15-记忆导入（接入别家AI的记忆）.md`（含 magpie 机制调查与本机货源盘点）。
契约：`接口-端点6-记忆课题与搜索.md` §2.15.6（新增）+ §2.15.2（占位翻篇）；env 表补 `MEMORY_IMPORT_SOURCES`。

## 改了什么

1. **`memory-import-sources.ts`（新）**：本机来源注册表 + 解析器。白名单三家——
   Qoder CLI（`~/.qoder/memories/<hash>/global/<分类>/*.md`，`user_*` → preference、其余 fact）、
   Qoder Work awareness（`~/.qoderworkcn|.qoderwork/awareness/main/{MEMORY.md,USER.md}`，
   `§` 行分节，USER.md → preference）、CodeBuddy（`%LOCALAPPDATA%/CodeBuddyExtension/Data/Public/.memories/*.mdc`，
   `enabled:false` 跳过，frontmatter `updatedAt` → createdAt，否则 mtime）。
   硬口径：客户端只能报来源 id 不传路径；只读；长度/去重/打码不做第二遍（全交 `importMemory`）。
2. **`memory-api.ts`**：挂 `GET /api/v1/agent/memory/import/sources` 与
   `POST /api/v1/agent/memory/import/sources/:id`（解析 → `importMemory("global", entries)`，
   口径与手工导入一致）。开关 `MEMORY_IMPORT_SOURCES`（默认开）叠在既有
   `MEMORY_ENABLED` / `MEMORY_IMPORT` 之上。
3. **前端**：`memory-page.js` 的 `openMemoryImportPlaceholder`（2026-11-13 拍板的占位）
   换成 `openMemoryImportDialog`：来源列表（条数/说明/一键导入）+「从文件导入」
   （数组或 `{"items":[...]}`，确认后走既有 `POST /memory/import`，scope 固定 `global`）；
   导完 `loadMemorySummary` 刷新。`style-21-answer-memory.css` 补 `.mem-import-row` 一小节。
   legacy 旧页不动（它的文件导入本来就能用）。
4. **`.env.example`**：补 `MEMORY_IMPORT_SOURCES` 注释行。

## 为什么这么做（取舍摘要，详见方案）

- 只接 global 语义来源：导入 scope 只有 global/partner，召回装配从不带 topic——
  项目级记忆（ZCode 227 个 md、Qoder projects/）导进来是死数据，刻意不接。
- 会话蒸馏导入（Claude Code 23 个 jsonl / Codex 18 个 rollout，magpie memdistill 式）
  另立项，本批不碰。
- ima / WorkBuddy / DSH / OpenClaw 等本机实测无有效记忆内容，登记不接。
- 复用 2026-11-08 的导入管线（只增不改、规范化等价去重、`veracity=imported`、SQLite 落库
  自动 `redactSecrets`），本批零新增存储策略。

## 验了什么

- `pnpm typecheck` 干净；`memory-import-sources.test.ts` 6 项全绿（tmpdir 造真实目录形状，
  覆盖 frontmatter 剥壳、§ 分节、`enabled:false` 跳过、projects/ 子树不碰、未知 id、空来源）。
- server 单测全量、http 探针、浏览器验收：见当日验收记录（本批落地当轮跑）。

## 还有哪些不确定

- 探针暂未给新端点加专项条目（探针文件本次未动）；已由单测 + http 探针整链路覆盖，如需
  常驻探针项另批补。
- ChatGPT / Claude 的服务端记忆没有本地库，只能靠用户导出文件走「从文件导入」；
  各家导出格式若变，前端只认数组 / `{"items":[...]}` 两种形状。
