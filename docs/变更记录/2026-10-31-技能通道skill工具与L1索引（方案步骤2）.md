# 技能通道：`skill` 工具 + L1 索引（App 方案《Agent 化与上下文分层》§6 步骤 2）

- 日期：2026-10-31
- 方案：App 仓库 `docs/设计方案/2026-10-31-Agent化与上下文分层（只追加）.md` v1.1（D4 三层上下文、D5 技能通道）

## 背景

流程类能力（会议回顾引导、回忆引导）如果写进 persona：改一次重开缓存、技能多了常驻 token 膨胀；
每轮追加全文：尾部不命中、每轮都付。方案定的是**索引在 L1 + 正文走工具按需取**。

## 决策

1. 技能 = `AGENT_SKILLS_DIR`（默认 `apps/server/skills/`）下的 `*.md`：文件名 = 技能名，
   第 1 行 = 索引摘要，其余 = 完整手册。不建库、不做管理端点（技能会话级冻结，改文件即改资产）。
2. **索引按会话冻结**：durable 对 section 是最小补丁语义（渲染值不变就不追加 `pi.system`），
   所以 `skills` section 在会话首轮渲染时记下当时的索引，之后技能目录再变也不改写本会话
   ——严格满足方案不变量「所有 system 在首轮 user 前写齐，此后冻结」；
   「技能增删只影响下一个会话」是 D5 的刻意取舍。
3. 正文不进 system：模型按需调 `skill(name)`，走 L2（toolResult，每轮追加）。
4. 任务会话摘除整个扩展（现状不变）：无技能、无工具。
5. 先放 2 条验证（方案 §6 步骤 2）：`meeting_guide` / `recall_guide`，内容为**草案 v0**，真机验证后定稿。

## 变更清单

- 新增 `apps/server/src/skills.ts`：技能目录加载 + 按会话冻结的索引；
- 新增 `apps/server/skills/meeting_guide.md`、`recall_guide.md`（草案 v0）；
- `tools.ts`：新增 `skill` 工具（目录为空时不上，工具数 7→8）；
- `agent.ts`：`AGENT_SKILLS_DIR` + `skillStore` 装配；扩展加 `skills` section（persona 之后，无技能时整个省略）；
- `task-probe.ts`：通用聊天回归断言补「L1 索引在 system、skill 在工具清单」；
- 文档：接口文档.md §4（工具数、技能通道）、`.env.example`（`AGENT_SKILLS_DIR`）。

## 影响范围

- 存量聊天会话首次请求会追加一条 tools+skills 的 `pi.system` 补丁（工具清单 7→8、多一个 section）
  ——**一次性缓存重算**，与思考变体切换同一批成本；新会话无此成本。
- App 侧无需改动（索引/工具都只影响模型上下文，HTTP 契约不变）。

## 验证结果

- `pnpm typecheck` 通过；`pnpm probe` 全过；`pnpm --filter @lifediary/server tasks` 全过
  （含新断言：system 含「可用技能/meeting_guide/recall_guide」，工具清单含 `skill`，
  实测清单 = read/write/edit/bash/remember/recall/set_reminder/skill）。
- 技能正文端到端（模型真的调 `skill()`）待真机联调时验（faux 模型不会主动调工具）。

## 回滚建议

单提交回滚；回滚后存量会话的 tools 补丁会再打一次（恢复 7 个），同样一次性成本。
