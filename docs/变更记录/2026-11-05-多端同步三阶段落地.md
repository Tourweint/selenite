并行说明：同一工作日另一会话落地了批次A/B/C（防打转/回执补差/伙伴/例行/自主审批），

## 做了什么

**中继服务（新 app `ts/apps/relay`，块0）**
- WS `/ws` 信封隧道（协议 v1，契约在 `@lifediary/shared`）：`deliver/routed/result` 按 dst
  路由、**src 由中继覆写**（不信任连接自报）；`meta` 帧中继自答（伙伴路由仲裁，唯一的
  "中继看得懂"的业务帧，存的是路由元数据）；同设备重连顶替（4409）；单帧 2MiB 上限。
- REST 管理面：info / 加入码签发（owner 或 loopback）/ 兑换（限流 30/min、错 5 次作废）/
  名册 / 撤销（踢在线连接）。码与令牌只存 sha256（`relay-state.json`）。
- 镜像控制台 `GET /`：加入码配对 → 设备下拉 → 会话流镜像 → 发消息 → 答审批。

**阶段一（harness 中继客户端）**
- `relay-client.ts`：出站长连、退避 1s→30s（稳定 10s 归零）、invoke 超时回执、push 单向帧、
  meta 帧。`relay-config.ts`：`RELAY_ENABLED` 默认**关**（一行回滚）。
- `relay-channels.ts`：通道白名单**默认拒绝**（七条阶段一通道；`channel_not_allowed` 兼作
  能力探测）。事件镜像不挂内核热路径：250ms 轮询重放库（persist-before-publish 的副产品），
  窗口滑过整段重发标 `resync`；`chat/send` 有伙伴降级守卫钩子。

**阶段二（设备矩阵，`relay-matrix.ts`）**
- `delegate` 工具新增 `targetDevice` 参数（远程分支：本机项目前置不参与，project 语义归
  目标机；离线 fail-fast 不排队；远端单不支持 resume——如实回给模型）。
- HTTP 入口 `POST /api/v1/relay/matrix/delegate`（探针/界面用，与工具同一条派发函数）。
- 目标机受理：本地锚点会话（`远端单 <id8>`，写一行受理回执进锚点）+ 回执先落再入队
  （requestId 幂等、恢复机制原样工作）；发起端轮询 status（2s×5 → 15s），相位变化走既有
  delegate 事件，终态一句话汇报写回发起会话。

**阶段三（伙伴认主机底座，`relay-home.ts` + 中继 actors 路由表）**
- 中继存"伙伴→主机"路由表并做 **CAS 仲裁**（`expected_home_device_id` 乐观锁，冲突带回
  实际值；这是路由元数据不是业务数据——哑中继边界不变）。
- harness：创建抢占 / 换家（先读实际值再 CAS，照抄 cindy 顺序：先写中继→再动本机；
  本地无档案也可接管）/ 60s 周期 + 重连触发对齐降级位 / **降级机发送一律拒**（fail-closed，
  且发送前以中继为准复核）。
- 凭证不随行：每台 harness 各自 env 配 key（架构断言，批次B 伙伴档案落地后对接 actorId）。

## 已知边界（如实登记，详见 系统架构.md §7）

1. 事件重放库只收 **HTTP 发起**的轮次；服务端直写（sayInChat 类）不进推送流，
   控制端靠重连重放 / `/messages` 对齐。
2. 远端锚点会话 / 伙伴专线会话在 durable `Chats` 快照的**列表可见性未定**
   （探针实测有时不可见；受理回执行已写进锚点，正文可按 id 回读）。
3. 中继 owner 令牌为空时仅 loopback 可管理——**公网部署必须配 `RELAY_OWNER_TOKEN`**。
