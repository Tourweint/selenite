# 插件多档开关（开关与档位）

**日期**：2026-11-18（同日第二批，接「插件页卡片弹层与开关形态」）。
**范围**：`plugins.json`（5 个多档插件的 offValue / 关档）、`flags.ts`（可选字段 + 校验 + API 透出）、
`memory-extract.ts` / `agent/assist.ts`（`MEMORY_EXTRACT=off`）、`partner-learning.ts`（`off`）、
`web/settings-switches.js` + `style-14-settings-pages.css`（开关右置 / 档位左置）、文档。

## 问题（2026-11-18 用户反馈）

1. 还有多档插件没有开关：记忆提取方式、学习反思频率、工具读写权限（现名「工具权限限制」）、内部质检模型。
2. 开关位置不对：自主轮的拨杆在左、档位在右。用户要求**开关固定在右下角，档位往左放**。

上一版把没关档的多档当「纯档位」解释，用户不接受。这次不是造假开关，而是把「关」定义清楚：
清单新增可选 `offValue`，界面据它画开关；每个多档插件明确「关 = 哪个值、关掉意味着什么」。

## 改了什么

- **清单字段 `offValue`**（`flags.ts` + `plugins.json`）：可选、必须属于 `values`；启动校验；
  `GET /agent/flags` 原样透出。没有这个字段的开关保持旧控件形态。
- **五个多档插件的关语义**：
  | key | 开档（在左） | 关 | 语义 / 后端 |
  |---|---|---|---|
  | `AUTONOMY_ENABLED` | 只观察 / 开 | `false` | 已有 |
  | `MEMORY_EXTRACT` | 自动 / 模型 / 规则 | `off`（新增值） | 不自动抽取新记忆；召回 / 记忆页 / 手动 remember / 导入照常；装配 no-op 抽取器；**改 hot:false**（引擎装配时取一次，旧文案「下一轮生效」修正） |
  | `PARTNER_LEARNING_FREQUENCY` | 每周盘点时 / 结算时抽查 | `off`（新增值） | 不做模型反思提炼；句长 / 称呼统计与已有规则注入照常 |
  | `CHANCELLOR_INTERNAL` | 核心模型 | `qoder`（既有档） | 关 = 不用核心模型，回到外部 CLI；不新增行为 |
  | `AGENT_TOOL_POLICY` | 禁命令行 / 只读 | `full`（既有档） | 关 = 完全访问（不限）；卡片名改「工具权限限制」，防止「关 = 不限」被读成「只读」 |
- **控件布局**：多档 = 档位（开态选项）在左 + 拨杆在右；只有一档开态的多档（内部质检）在左显示
  当前模式文字（核心模型 / 外部 CLI）。关态下档位禁用、滑动高亮隐藏；开时回到本次最后选过的开档。
- **弹层说明**：有关档的多档在详情层写明「关 = 某档」或「开关决定开不开」；"当前"那一行跟着切档实时更新。
- **记忆页（旧版）**：`data.extract === "off"` 显示「不抽取」（新版记忆页本来就不显示抽取方式）。

## 验证

- `pnpm typecheck` 通过。
- `tsx --test src/flags.test.ts src/partner-learning.test.ts src/memory-api.test.ts`：40/40 通过
  （含 `MEMORY_EXTRACT` 档位快照、`offValue` 透出、`learningFrequency({PARTNER_LEARNING_FREQUENCY:"off"}) === "off"`）。
- 直接调 `memoryExtractMode` / `preferenceExtractor` / `memoryFallbackExtractor` / `preferenceExtractionEnabled` /
  `NOOP_EXTRACTOR`（临时 `AGENT_FLAGS_PATH`，不碰真实配置）：mode=`off`、两个 extractor 均为 null、
  `extractionEnabled=false`、noop 抽取 0 条；再用真实 `MemoryEngine` + 临时 DB 跑 `ingestTurn`：
  `offAdded=0, offReinforced=0`。
- 浏览器实测（本地 39847，真数据）：
  - 五个多档卡：档位在左、开关在右（自主轮 / 记忆提取方式 / 学习反思频率 / 工具权限限制；
    内部质检 = 模式文字在左 + 开关在右）。
  - 每个开关关 → 开一轮：API 依次写入 `false` / `off` / `off` / `qoder` / `full`，界面同步；
    再开/关回到原值；关态下档位按钮全部禁用。
  - 内部质检关掉时左侧文字从「核心模型」变「外部 CLI」，开回来恢复。
  - 工具权限默认 `full` → 开关关、档位禁用；打开选 `no-shell`，再关回 `full`。
  - 测试后 `.data/agent-flags.json` 已还原成测试前的 11 个键。
- 未做：真实会话的抽取条数观察（用引擎级 `ingestTurn` 验的 0 条）；手机端（不涉及）。

## 刻意不做

- 不给 `CHANCELLOR_INTERNAL` 造「完全不做质检」：拆单 / 验收 / 目标核对必须有判官，
  没有核心模型时本来就回落 Qoder；关只能是「走外部 CLI」。
- 不给 `AGENT_TOOL_POLICY` 造第二个「关」值：`full` 本来就是完全访问，再加一个 `off` 是重复语义。
- 不改 `MEMORY_EXTRACT=rule` 的逐字节回滚口径；`off` 是第四档，不替换 `rule`。
- 不新增端点、不改已有字段语义；不改非多档插件的控件形态。
