## 语义

| 档 | 行为 | 等价旧形态 |
|---|---|---|
| `ask-all` | `WRITE_TOOLS` ∪ 高危清单全问（写 / 改 / 跑命令 / 派活 / 建群 / 执事管理 / 递话） | `confirmWrites:true` |
| `ask-critical` | 只问高危清单；文件 write / edit 等常规写自动放行 | 新增 |
| `none` | 全不问 | `confirmWrites:false`（默认） |

`ask-critical` 缺省清单（`AGENT_APPROVAL_CRITICAL_TOOLS` 可整体覆盖）：
`bash`、`powershell`、`delegate`、`partner_manage`、`send_to_agent`——会起执行 / 烧 token 的动作。
`send_to_agent` 不在 `WRITE_TOOLS`（不写文件），但会起对方一轮模型调用，单列进高危清单。

## 兼容与落盘

- **旧客户端**：`GET /policy` 仍回 `confirmWrites`（派生布尔），旧界面开关语义不变
  （`true` ⇔ 至少有一部分操作会问）。
- **旧写入口**：`POST {confirmWrites:true/false}` 映射 `ask-all` / `none`；非布尔照旧 400。
- **老 `policy.json`**：只有 `confirmWrites` 的按布尔映射；新写入只存 `approvalLevel`（不再写旧字段）。
- **env 初值**：`AGENT_CONFIRM_WRITES` 保留为初值来源（true → `ask-all`，否则 `none`）；
  没改 env 名，回滚无需改配置。
- **无新回滚开关的必要**：新增档位本身是纯增量；要回旧行为就选「全不问」（或 `AGENT_CONFIRM_WRITES` 留空）。
