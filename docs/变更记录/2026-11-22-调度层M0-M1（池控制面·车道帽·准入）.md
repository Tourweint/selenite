# 2026-11-22 调度层 M0–M1（池控制面 · 车道帽 · 准入）

**改了什么**

按《2026-11-22-调度层与执行器池的合并方案》落地 M0 / M1a / M1b 三批，未提交 git。

### M0：池控制面接回宿主 + 取消语义

- 新增 `ts/apps/server/src/worker-control.ts`：按 `ticket.employee` 分派的窄桥。
  - `abortTicket(ticketId)`：票级 `AbortController` 注册表；取消时 abort，signal 经
    `supervisor.run` / `employee.run` 停掉 pool / native / 外部 CLI。
  - `sayWorker(employee, ticketId, text, mode)`：pool → `supervisor.say`；native → stdin；
    外部 CLI / mcp / phone 如实回“没有注入口”。
  - `setPoolControl()` 由 `index.ts` 与 `setPoolClient` 并排注入；不 import index，避免环。
- `delegation-start-delegation.ts`：每次派单建一个 `AbortController`，单号一出现就注册；
  resume 在 launch 前按原单号注册；settle / fail / resumeOnly 被拒都注销。
- `tools.ts`：async 模式只挂票级 signal；同步回滚路径与聊天 `abortSignal` 合并（`AbortSignal.any`）。
- `delegation-actions.ts`：取消改 `abortTicket`；插话 / 上报答复改 `sayWorker`。
  旧进程里没有控制器的 native 单保留 `abortNativeWorker` 兜底。
- `employee/pool.ts`：`aborted` 映射 `signal.aborted || reason === "aborted"`。
- `scheduler.ts`：runner 返回后先判 `signal.aborted || run.aborted`；中止时仍收集
  `changedPaths`，但跳过越权判定 / 合并 / 标记已合并，worktree 原样保留。
- `dispatch.ts`：signal 已中止时直接回一张 aborted 的 `TaskRun`，不建 TASK.md、不起雇员，
  避免“排队中被取消还去拉进程”。

### M1a：任务车道帽 + 同领域串行

- 新增 `ts/packages/chancellor/src/lane.ts`：
  - `FifoGate`：容量满排队、priority 小者先（0 最高）、release 幂等、排队中可 abort；
  - `acquireLane(employeeKind)`：pool/native 共用 native 车道（容量 `SUPERVISOR_POOL_SIZE`，默认 4）；
    claude-code 2、codex 2、opencode 1、qoder/codebuddy/phone/mcp 1，其它回落 `MAX_PARALLEL_TASKS`；
    `CHANCELLOR_LANE_CAPS` 覆盖。
  - `acquireDomain(domain)`：同领域 manager 串行，`CHANCELLOR_MAX_ACTIVE_PER_DOMAIN` 默认 1。
  - `CHANCELLOR_SCHEDULER=false` 时两者直通。
- `scheduler.ts`：`executeTask` 在文件租约之前拿车道（车道 → 租约 → spawn，避免死锁）；
  等槽时发 `task-waiting`，`waitingOn="执行器槽位（claude-code 1/2）"`；finally 释放。
- `index.ts`：`runManagerTicket` 在起 manager 前拿领域租约，排队发 `manager` 事件；
  dry/取消/异常所有出口都释放。

### M1b：ticket 准入 + 优先级 + manager 子单串行

- 新增 `ts/packages/chancellor/src/admission.ts`：
  - `TicketAdmissionGate` 同时守全局与 per-domain；priority 小者先、同级 FIFO；
  - `CHANCELLOR_MAX_ACTIVE_TICKETS=3`、`CHANCELLOR_MAX_ACTIVE_PER_DOMAIN=1`、
    `CHANCELLOR_QUEUE_MAX=64`（0 = 不排队）；0/负数上限 = 不限；
  - 排队中 abort 摘出队列返回 aborted；队列满返回 queue_full；`CHANCELLOR_SCHEDULER=false` 直通。
- `runChancellor`：intake 之后、planning 之前过准入；`ticket` 单号事件先同步发出，
  排队/拒绝都还能立即返回单号；queue_full → failed「排队已满」，aborted → aborted；
  所有出口 finally 释放。manager 分支改为 `return await`，避免名额在 manager 跑完前释放。
- `resumeTicket`：续跑 / 重试也过同一准入，不许绕过上限。
- 优先级：`run-source.ts` 新增 `priorityOfRunSource()`（human 0 / device 1 / routine 2 /
  script 3 / test 9 / 未知 5）；`tools.ts` 把 runSource 判定提成共用变量，经
  `DelegationKickoff.priority` → `ChancellorRequest.priority` 传给 chancellor。
- `employee/manager.ts`：manager 子进程显式带
  `CHANCELLOR_MAX_ACTIVE_TICKETS=CHANCELLOR_MANAGER_MAX_ACTIVE_TICKETS || 1`，
  不靠继承宿主的 3。

**顺手修**

- `ts/apps/server/package.json` 的 test 脚本原本是 `tsx --test tsx --test src/...`，
  多了一个 `tsx` 参数，`pnpm --filter @lifediary/server test` 直接报 `'tsx' 不是内部或外部命令`。
  去掉重复前缀后恢复可跑。

**为什么**

- 宿主默认执行器已切 pool；但取消 / 插话 / 上报答复的宿主路径仍只认 native，
  切池后这三条线实际上是断的。M0 先把控制面补回“执行器无关”。
- 单票 `MAX_PARALLEL_TASKS=3` 只管一张票；跨 ticket 与外部 CLI 没有总闸。M1a 补任务车道，
  M1b 补 ticket 准入，避免“一次连派 30 单 = 30 次拆单模型调用 + 30 个 CLI 排队”。
- 原方案承诺的“同领域串行”一直没实现；M1a 补上，避免两个同领域 manager 并发写同一份领域状态。

**没做 / 没验（如实登记）**

- 没真起池进程做端到端取消 / 插话 / 上报答复（M0 只验到 signal 与路由分派；
  `/abort`、`/say` HTTP 一跳是既有 supervisor 代码，未改也未实跑）。
- 没真跑“连派 30 单 + 真模型拆单”；准入只用单测 + `runChancellor` 拒绝路径集成测试。
- manager 子进程的实际 env 未起真进程核对。
- 车道 / 领域 / 准入都是**进程内**状态：manager 子进程、远程设备各自一份；
  manager 路径仍可能超过宿主 native 车道帽（已知边界，M4 把 manager 收进池后再收口）。
- 车道排队已支持 signal 取消；但 **manager 等领域时取消**依赖 `runManagerTicket` 的
  signal，已接；真实 manager 等待场景未实跑。
- 远程设备单（relay-matrix）没传 priority，默认 5；device 优先级 1 只在本地 delegate 路径生效。
- 优先级目前只影响 ticket 准入；任务车道仍用默认 0（M1a 未接 ticket 优先级）。

**回滚**

- 调度层整体：`CHANCELLOR_SCHEDULER=false`（车道 / 领域 / 准入全部直通，旧行为）。
- 执行器：`CHANCELLOR_EMPLOYEE=native` 回到每票一进程（不回滚 M0 取消语义）。
- 并发数：`CHANCELLOR_MAX_ACTIVE_TICKETS` / `CHANCELLOR_MAX_ACTIVE_PER_DOMAIN` /
  `CHANCELLOR_QUEUE_MAX` / `CHANCELLOR_LANE_CAPS` 都可用 env 放宽或收紧。
- M0 的“取消不合并”是行为修正，没有单独开关；要回到旧行为需 revert 本批相关文件。
