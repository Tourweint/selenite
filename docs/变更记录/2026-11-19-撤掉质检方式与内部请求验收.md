## 第一轮：撤掉质检方式与内部请求

## 改了什么

- **删掉「设置 → 派活」的「质检方式」下拉**（`web/settings-executor.js`），`.data/executor.json` 的 `qa` 字段、`CHANCELLOR_QA_MODE` env、接口文档 §6 对应行一并删除。旧配置文件里残留的 `qa` 字段被忽略（读配置只认 `employee` / `profiles`，不认识不报错）。
- **删掉「内部一次请求」验收**（`packages/chancellor/src/review.ts`）：`reviewWithLlm` / `buildReviewPrompt` / `parseVerdict` / `ReviewDeps` / `ReviewOptions` / `safeArtifacts` 全删。验收不再调用任何模型。
- **删掉「整体目标核对」**（同一类内部请求）：`packages/chancellor/src/goal.ts` 整文件删除；`index.ts` 的全部任务通过后再让核心模型判一次用户原话的逻辑删除；`stage.ts` 的 `decideAfterReview(reviews, goal)` 收成 `decideAfterReview(reviews)`；`GoalCheckResult` / `GoalOutcome` / `"goal"` 事件类型删除；server 侧 `case "goal"` 删除。
- **删掉「派质检 worker」自动派单路径**（同批新增、同日撤回）：`qa.ts`、`qa.test.ts`、`templates/qa.md`、`apps/server/src/qa-bridge.ts` 删除；`ChancellorRequest.qaWorker` 与 `mountQaRunner()` 装配删除。

## 验收现在只剩什么（全部是代码，0 token）

`reviewTask(run, ticket)`：

1. 进程层：`aborted` / `timedOut` / 退出码 / `processOk`。
2. 报告层：`REPORT.md` 存在；`status = waiting / dropped / progress / blocked / failed` 各自收口。
3. 文件层：声明了 `writes` 的任务，用执行前快照比对声明路径是否有真实新增/修改/删除——有变更才过，0 变更判失败；`artifacts` 只做附加校对（对不上只记 warning）。
4. **没声明 `writes` 的只读/汇报型任务：执行成功 + 汇报有终态结论即通过**，原因写明「未声明 writes：执行与汇报通过机械校验（不做模型判读）」。

手机雇员仍走汇报验收（`REVIEW_TRUST_REPORT`），`artifacts` 内容读取（≤2KB）保留给返工要求使用（`scheduler.ts`）。

## 语义验收以后怎么做

不再由宿主做。要真验收，由 Agent 按**项目规则 / 提示词**自己派一单质检 worker（用既有 `delegate`，零新代码）。项目规则里可以写类似：

```text
做完不要只报「完成」。至少派一单质检：让一个独立的 worker 亲自读产物 / 跑验证命令，
不要只信你的汇报原文。质检结论只写一行：
DONE: <一句话>
CONTINUE: <还差什么，具体到能直接照着做>
BLOCKED: <卡在哪，需要人做什么>
```

（这是撤回的 `templates/qa.md` 的要点；文件本身已删，避免留下无调用方的死代码。）

## 影响与边界（如实）

- **行为变化**：只读/汇报型任务以前会被核心模型判一次，现在机械通过即算过；整单也不再做「用户原话是否达成」的最后核对。这是拍板接受的代价——语义验收交给 Agent 自己。
- **回滚**：没有开关——本批是删除，回滚 = git revert 本笔。旧 `review.json` 里 `stage:"llm"` 的历史记录仍可读（纯 JSON，不做枚举校验）；旧 `goal.json` 残留文件不读、无害。
- **未动**：证据裁判（`DELEGATION_JUDGE`，默认关）仍保留——它是 read-only 子会话（Agent，不是内部请求），触发条件从「review fail / 目标核对未通过」收窄为「review fail」。拆单（`planTicket`）仍用一次内部请求：它负责「把需求拆成任务」，不是判对错，不在本次撤回范围。
- **验证**：`pnpm typecheck` 全绿；全量单测重跑（见下）。
