# 原生截图工具（壳内框选与窗口吸附）

**日期**：2026-11-25　**范围**：`desktop/snapshot*.go`（新增）、`desktop/popovers.go`（Capabilities 加一个字段）、`web/attachments.js`、`web/plus-menu.js`、`web/ui-atoms.js`；HTTP 契约与 shared 不动，无新端点。
**方案**：`docs/设计方案/2026-11-25-原生截图工具（壳内框选与窗口吸附）.md`　**长期口径**：`系统架构.md` §6.1、`desktop/README.md` 开关表。

## 为什么

加号 →「截图」在桌面壳里弹的是 WebView2 自带的共享选择器：第三方观感、不能拖拽框选、不吸附窗口。用户要求换成壳自己的原生工具。

## 改了什么

1. **壳侧**
   - `snapshot.go`：`Shell.CaptureSnapshot(ctx)`——先 GDI 抓鼠标所在显示器的一帧，再铺遮罩，等结论后销毁遮罩、主窗口拉回前台、编码返回。回滚开关 `LIFEDIARY_NATIVE_SNAPSHOT`（缺省开；`off` / `false` / `0` 关）。同一时刻只许一张遮罩。
   - `snapshot_view.go`：遮罩 = mygo 原生窗口（`Frameless / AlwaysOnTop / SkipTaskbar / DisableResize / DisableMove`）+ `ui.View`，不是第二个 WebView 页面。指针用 `Element.PointerPosition / PressedButton`，键盘用 `Context.Shortcut(0, ui.KeyEscape)`（以 v0.10.0 源码为准）。
   - `snapshot_geom.go`：纯函数——裁剪、DIP↔物理像素、压暗条带、拖动状态机、PNG→JPEG(90)→缩宽(≤2560) 回退。
   - `snapshot_windows.go`：Win32（标准库 `syscall`）；`snapshot_other.go` 是别的平台的空实现。
   - `popovers.go`：`ShellCapabilities` 加 `nativeScreenshot`。
2. **页面侧**
   - `attachments.js`：`captureScreenshot()` 先试壳；用户取消 = 到此为止；壳出错 / 没返回图片 → toast 后走原来的路（改名 `captureScreenShare`，正文未动）。
   - `plus-menu.js`：截图项显示条件 = 壳能力 `nativeScreenshot` **或** `getDisplayMedia`；tooltip 分两种。
   - `ui-atoms.js`：同一次 `Shell.Capabilities` 探测顺带读 `nativeScreenshot`，导出 `nativeScreenshotReady()`。

## 设计取舍

- **取消 ≠ 回退**：Esc / 右键什么都不产出，不再弹共享选择器；只有失败才回退。
- **窗口吸附绕开自己**：遮罩压在最上，`WindowFromPoint` 多半回它；命中自己就按 Z 序找第一个可截且盖住该点的窗口。
- **坐标**：Win32 物理像素、mygo DIP，换算只在 `dipToPx / pxToDip`；遮罩原点取自遮罩窗自己的 `GetWindowRect`。
- **Win32 调用用标准库 `syscall`**，没按任务书「x/sys 或 purego 二选一」：`x/sys` 要过 `sum.golang.org`（本机不通，未绕过校验），`purego` v0.11.1 在 Windows 上仍要标准库加载器。结果是不加任何依赖，字面偏离，**待确认**。

## 验证（2026-11-25）

- `go build ./...`、`go vet .` 通过；`gofmt -l` 空。
- `go test -count=1 ./...` 全绿；本批 15 个测试：开关、DIP↔px、选框往返、裁剪、压暗条带、标签定位、拖动状态机、像素转换、抠图、编码回退链、缩放、显示器匹配、遮罩无窗口渲染、无悬停窗口时提示条常显、Win32 冒烟（真抓 64×64、真找到光标下窗口）。
- `node --check` 三个 JS 通过。
- 测试当场抓到并修掉：DLL 名被批量改名改坏、`GetDC` 放错 DLL、松开帧没取最终坐标。

## 未验（如实写）

- **交互遮罩未真机验证**：框选、悬停高亮、单击吸附、右键取消、焦点回主窗口。
- < 200ms 出遮罩、150% / 200% 真实对齐、mygo 显示器匹配、全屏置顶 Frameless 窗是否被裁/切圆角。
- 没跑 `build.ps1`、`pnpm typecheck`（本批不改 TS）。

**手工验收**：托盘「只退出壳」→ `powershell -ExecutionPolicy Bypass -File .\build.ps1` → 重开 → 加号「截图」→ 拖框 / 悬停窗口 / 单击 / Esc → 看待发条；改 150%、200% 缩放各来一遍。

## 返工（同日）：顶部提示条必须常显

审代码发现：顶部提示条画在 `if !dragging && !hovering { return }` **之后**。光标落在桌面 / 任务栏 / 桌面壳上
（没有可高亮的窗口）时 `hovering=false`，整块提示条不画，用户只看到全屏压暗、没有任何操作说明。
原来的 `TestSnapshotViewWindowless` 能过，只是因为测试进程里 (0,0) 碰巧命中了某个窗口。

- `desktop/snapshot_view.go`：提示条移到该 return 之前，**每一帧都画**；选框边线与尺寸标签仍只在拖动 / 悬停窗口时画。
- `desktop/snapshot_test.go`：补 `TestSnapshotViewHintWithoutHover`。预置「这个位置查过了、没有窗口」的状态，
  不依赖测试机上开着什么窗；断言那一帧画面里**只有提示条**一段文字。有 bug 的代码上红、修复后绿。
- Esc / 右键取消、单击吸附、拖框、DPI 换算的代码都没动。构建 / vet / 全套测试通过；**未验证清单不变**。

## 回滚

`LIFEDIARY_NATIVE_SNAPSHOT=off` 重开壳：Capabilities 报 `nativeScreenshot=false`，页面回到 `getDisplayMedia`。老壳 exe 也自动回退（没有 `CaptureSnapshot` 方法，调用 reject）。`LIFEDIARY_SHELL_BINDINGS=off` 仍整组摘掉 Shell。
