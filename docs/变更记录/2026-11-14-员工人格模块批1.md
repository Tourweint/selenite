# 员工人格模块 · 批1（开关骨架 + 静态模块 + 预设 + 前端开关区）

方案：`docs/设计方案/2026-11-14-员工人格模块（开关化拟人）.md`（本批唯一设计口径）。
批2（印象 / 心情 / 日记）与批3（学习 / 主动性 / 人设库）不在本批。

## 改了什么（按契约顺序）

**1. 契约（`ts/packages/shared/src/index.ts` + `docs/基线文档/接口-端点4-执事例行与自主轮.md`）**

- 新增 14 个模块 id（`PartnerPersonaModuleIds`）与三预设枚举（`work` / `companion` / `custom`）。
- 新增 `PARTNER_PERSONA_LIMITS`（字段上限唯一落点）与三份内容 schema（`PartnerPersonaStyleSchema` /
  `PartnerPersonaValuesSchema` / `PartnerPersonaScenarioSchema`，全字段可选、`.strict()`）与
  `PartnerPersonaPatchSchema`（PUT body）、`PartnerPersonaView`（响应形状）。
- 上限用 **Unicode code point** 计（`[...s].length`），与既有 tagline 口径一致，不用 UTF-16 `length`。

**2. 存储（`partner-store.ts` / `partner-rows.ts` / `partner-types.ts`）**

- `partners` 表加 `persona_preset TEXT` / `persona_modules TEXT`（JSON）；旧库 `PRAGMA` + `ALTER TABLE` 补列。
  老行 `null` → 预设按 `work`、开关按预设默认算（**不是"全关"**）。
- `PartnerRow` 加 `personaPreset` / `personaModules`；`setPersona()` 一条 UPDATE 落地，
  **不版本化**（人格不是身份，不 bump `partner_versions`、不动 SOUL / 契约）。
- 开关列只认 14 个 id 且值为布尔；坏 JSON / 脏值当"没显式改过"。

**3. 人格层（新文件 `ts/apps/server/src/partner-persona.ts`）**

- `PERSONA_PRESETS` 预设映射（见下表）、`effectivePersonaModules()`（预设默认 + 行上显式值）、
  `personaModuleOn()`（回滚开关关着时一律 true）。
- 静态内容读写：家目录 `persona/style.json` / `values.json` / `scenario.json`，`atomicWrite` 原子写；
  读时同一份 zod 复核（手改磁盘留下的脏值 / 越界字段当没填）。
- 渲染：`renderPersonaBlocks()` 固定顺序 **【口吻】→【里子】→【处境】**，空模块 / 空字段整段 / 整行跳过。
- `personaSignature()` + `personaRefreshNeeded()`：人格不版本化，靠进程内签名判断要不要重配 instructions
  （见下"缓存前缀影响"）。

**4. 端点（`companion-api.ts`）**

- `GET /api/v1/partners/:id/persona`：`{ok, enabled, preset, modules, contents, limits}`；
  `modules` 永远给完整有效表。
- `PUT /api/v1/partners/:id/persona`：`{preset?, modules?, contents?}` 按模块部分更新；
  只给预设 = 一键填开关；`contents` 按**字段**合并（省略不动，空串 / 空数组 = 清空）。
  全量过 zod，任一不合法 400 且一个字节都不写。写盘在前、落库在后（写盘失败不留"开关变了内容没变"）。
- 不存在 404；鉴权失败 403 空体（全局中间件，同本节其它端点）。

**5. 注入**

- 静态模块进 **instructions**：`renderPartnerIdentity()` 在 SOUL 之后、USER.md 之前拼人格段。
- 岗位类进每轮 system：`buildPartnerTurnContext()` 按 `contract` / `goal` / `discipline` /
  `workHistory` / `currentWork` 裁剪；**`discipline` 关掉只留「【主人数据红线】」**（必选核心）。
- 会话刷新：`openPartnerSession` / `ensureGroupMemberSession` 原来只比 `appliedVersion`；
  人格改完不 bump 版本，所以另加内容签名（进程内 Map，上限 500 条，超了清空重来）。
  改口吻 / 里子 / 处境 → **下一轮**生效；重启后第一次打开会话多配一次（无害），不落库、零新存储。

**6. 前端（`web/partner-profile.js` + `web/style-22-partner-profile.css`）**

- 人设二级页在「人设」与「岗位」之间加「人格模块」区：预设三选一 + 八个开关。
- 模块名挂 `data-tip`（悬停才出解释，不常驻）；静态模块「编辑」开弹层（复用 `modal-field` /
  `modal-input` / `pt-ta`），字段按上限先拦。批2 / 批3 的模块行**不显示**。
- 开关 / 预设改完立即 PUT（与会话开关同款），不做草稿；`enabled=false` 时整块隐藏。

## 缓存前缀影响

- **工具描述与注册顺序：未动**（本批不碰缓存前缀资产）。
- **instructions 会变**：填了静态内容且对应模块开着时，instructions 在 SOUL 之后多一段（口吻 / 里子 / 处境）。
  这是"他自己是谁"的一部分，只随用户编辑变化，不随轮次变化——与身份版本同一条缓存线段。
- **每轮 system 的段顺序未变**：契约 → 目标 → 纪律 → 在办，仍由 `INJECTION_ORDER` 排；
  本批只做"这一段要不要出现"，没有新 id、没有动态排序。
- 关掉某模块 = 该段消失 = 前缀变短（预期内，属用户主动编辑）。

## 与设计文档的一处偏差（**需要用户拍板**）

设计方案 §7 的预设表把 `expression` 在 **work（默认）**下写成「开」；本批任务书写的预设映射是
「work：expression / values / scenario 关」。**本批按任务书实现**（工作执事连口吻都不配，
与"干活执事没有情感是设定本身"更一致，且给了 UI 一个干净的默认态）。
若按设计方案，只需把 `PERSONA_PRESETS.work.expression` 改成 `true`——但已建执事不会自动跟着变
（它们存的是完整开关表），要一起迁就另开一条数据修正。

## 已知边界（未做 / 未验，不冒充已知）

- 批2 / 批3 模块只有开关位，不注入、不更新（`impression` / `mood` / `heart` / `learning` /
  `proactivity` / `profiles`）。
- 手机端不做（批3）；团队包（`GET /partners/:id/bundle`）**不搬运**人格内容与开关，导出的
  伙伴到新家是默认 work 预设 + 空内容。
- `PartnerProfileSchema` 投影**不带** `personaPreset` / `personaModules`（列表形状不变）；
  手机端要读走 persona 端点。
- 人格内容是"提示词素材"，日志不记内容（沿用日志只记条数 / 枚举口径）；本批没有新增含内容的日志。
- 静态人格只在会话 `configure` 时生效；**正在跑的同一轮**不会半路换口吻（下一轮生效，与 SOUL 同口径）。
