# 记忆外挂源与分层召回（大库接进每轮召回）

**日期**：2026-11-22 设计、2026-11-23 落地验收
**方案**：`docs/设计方案/2026-11-22-记忆外挂源与分层召回.md`（含现状盘点、设计依据、明确不做清单）

## 改了什么

一生记忆库（persona-metric，60 表 / rag_unit 1.6 万条）此前只有 `persona_recall` 工具——赌模型每轮"记得去查"。本批把它接进**每轮自动召回**，分层设计（大库条目不进小库打分池）：

1. **轻召回**（新文件 `persona-inject.ts`）：每轮消息尾部 ≤3 条 / 800 字【更早的记录】组，独立于小库 16 条 / 2000 字预算。链路：总闸+父闸 → 有效汉字 <6 前置过滤（不 spawn）→ 60s 节流/单飞（按会话）→ `ask.py --json --limit 2`（实测 0.8s）→ echo 抑制（query 与正文近重复不注）→ 内容词门槛（关键词命中类须与 query 有内容双字命中）→ Jaccard ≥0.8 去重 → 限额截断。
2. **库目录常驻**：`ask.py --catalog-only` 裁到 ≤600 字，system 段 `persona_catalog`（order 46，紧跟 current_project）进静态前缀；10 分钟刷新 + 失败 60s 冷却 + 失败保留旧文本。

## 新 env

`PERSONA_MEMORY_INJECT`（默认开）：轻召回 + 目录常驻总闸；`false` 回到"只有 persona_recall 工具"。父闸 = `PERSONA_MEMORY_ASK` 已配置 + `PERSONA_MEMORY_ENABLED` 未显式关。已进接口文档 §6、`.env.example`、插件页 persona 组卡片（requires 父闸、hot）。

## 为什么这么做

- DSH 插件市场调研（2026-11-22）三个校准点：分层注入是成熟做法（auto-memory Tier0/1/2）；"不依赖模型记得去查"（工具赌每轮都查，忘一次记忆就等于不存在）；echo trap（复述问句相似分必然最高却最不该注入）。
- 大库条目与小库不同构（rag_unit 是证据片，无 kind/importance 语义），进同一打分池会互相污染；独立预算分层配额干净（auto-memory 实测：单层能吃光全部预算，"分层"退化成单层——所以预算写死独立）。
- 中间件放 server 不放 memory 包：spawn python 是装配事，依赖方向单向。

## 真库冒烟（2026-11-23，两轮）

- `毕设答辩那阵子怎么样了` → 恰 3 条（答辩日记忆、毕设项目记忆、"太简"用户亲口确认），全 ≤120 带省略号 ✓
- `今天天气真不错啊` → 首轮漏 2 条无关片（"真不""不错"双字在正文里恰好出现，门槛放行）→ **校准**：门槛从"双字交集"升级为内容词门槛（`INFORMATIVE_FILLER` 虚词剥离表），复验归零 ✓
- `嗯` → 前置过滤空 ✓；catalog 152–161ms 拉取正常 ✓；persona.db 只读未写 ✓

## 坑与顺手修

- **persona-inject.test.ts 起初漏挂 package.json 测试清单**（同 request-stats.test.ts 旧坑）：全量 1399 跑不含它，直接 `tsx --test` 才 9 测过——已补挂（`src/persona-ask.test.ts` 旁），全量变 1409。
- `flagEnabled` 对 plugins.json 未登记键恒 false："默认开"必须登记卡片，不是加一行 flags 就完。
- 注入框架 provider 契约是同步的：async 轻召回不能进 `LIFECYCLE_MESSAGE_PROVIDERS`，在 lifecycle-harness beforeRequest 里 await 后按 order 插回。
