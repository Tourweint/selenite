# 2026-11-17 例行轮工作区与工具报错兜底

> 一句话：08:30 的「早上问安」跑到别的仓库、读失败还静默，四处一起修。

规则配置同步改了两项（走 PATCH API，revision 1 → 2）：

- `sessionMode`：`persistent` → **`fresh`**（用户原话：按钮忘了改成「每次新开」）；
- `prompt`：不再让它「去找挂着的事」，明确「不用翻文件、不用查历史会话，没有就只打招呼」。

## 为什么

`agent.sqlite`（会话 2903）+ `.data/routines.json` 的现场：

- 注入 `当前项目：student-milk-order`，会话 cwd 就是该项目目录；
- `read(path: "workspace")` → `ENOENT ...\student-milk-order\workspace`；
- 模型没有重试，回 `[[no-update]]`；安静契约虽被工具报错压成「非安静」，但正文被剔成空串；
- `routines.json` 记 `status=success`、`summary="[工具报错:read] "`，并把游标推到 08:30。

四个独立缺口：cwd 跟全局项目走、相对路径歧义、错误没有方位信息、空产出仍算成功。

详细根因见方案：`docs/设计方案/2026-11-17-例行轮工作区与工具报错兜底.md`。

## 已知边界

- 执事默认目录是主工作区（相对路径基准），**不是边界**；`path-guard` 根集合是"主工作区 + 所有非归档项目根"，勾选项目只影响记忆召回（用户 2026-11-17 拍板：两件事解耦）。
- 路径提示只认 `ENOENT`，权限类错误（EPERM / EACCES）不补这段话。
- 兜底消息只在「有工具报错且正文为空」时加；模型报错后仍写了正文时按有内容处理，不重复补。
- 本次没有改项目选择交互，也没有改 worker 会话的创建时快照语义。
