# 自动归档开关回填不再滑动（会话页的开关状态就地落位）

用户报的是这一句："从设置页的其他页面切换到对话这一页时，其他按钮没什么事，主要是自动归档，它就会滑这个键……为什么它不能一直开启？"

## 结论

**开关一直是开着的，从来没被关掉。** 服务端 `.data/agent-flags.json` 里 `ARCHIVE_AUTO_ENABLED: "true"`（2026-11-14 20:00 写盘，本轮核对）。滑的那一下不是"它又开了一次"，是**先把开关画成"关"、等接口回来再改成"开"**，两次状态之间那段 CSS 过渡（`--dur-fast` 120ms，thumb 位移 + 轨道变色 + 轻微回弹）被看见了。

## 为什么只有它滑

设置页每次进子页都是整块重建 DOM（`el.settingsInner.innerHTML = ...`，`settings-router.js` `page === "chats"` 分支）：

| 控件 | 进页时的初始值 | 之后要不要改 |
|---|---|---|
| 回车发送 | `localStorage` 同步读，一次画对 | 不再改 |
| 权限 / 审批分段 | 三个按钮全 `false`，`loadPolicy()` 回来再点亮 | 亮的是按钮底色 + 胶囊首帧无动画 |
| 自动归档 | `switchMarkup(false, …)` **硬编码 false** | `loadAutoArchiveSettings()` await `GET /agent/flags` 后才 `aria-checked="true"` → **这一改就跑过渡** |

所以同一张卡上，只有这一行会"滑"：它的初始态是占位值，真值要等一次网络往返。

## 改法

两条，各管一半：

1. **不该有动画的写入就不要动画**（`settings-atoms.js` 新增 `setSwitchChecked(sw, checked, { animate = false })`）：挂 `data-no-anim` → 写 `aria-checked` → 强制回流 → 摘标记，终态就地落地。套路与 `syncSegmented` 的"首帧定位不滑进来"完全一致，不是新发明。用户自己点的那一下仍走 `sw.setAttribute` 原路径，动画照旧。
   CSS 侧一行 `.switch[data-no-anim] { transition: none }`（含 `.switch-thumb`）。
2. **进页先按上次读到的值画**（`settings-switches.js` 加 `archiveAutoSnapshot`）：本页面进程内记住最后一次回读到的 `{ enabled, days }`，`loadAutoArchiveSettings()` 在 `await` **之前**先按它描好；请求回来只在数值不同时纠正（纠正也不带动画）。`toggleFlag` / `saveAutoArchiveDays` 成功后同步更新快照。

顺带修掉一个同源的错：读失败时原来一律画回缺省（`false / 30`），等于把已知的"开"改回"关"；现在读过就不回退，提示文案也按"先按上次读到的值展示 / 先按默认展示"分开写。

## 落点

| 文件 | 改什么 |
|---|---|
| `web/settings-atoms.js` | 新增 `setSwitchChecked`（含导出）；`switchMarkup` 不动 |
| `web/style-08-search-gate.css` | `.switch[data-no-anim]` 关过渡 |
| `web/settings-switches.js` | `archiveAutoSnapshot` + `paintArchiveAuto`；`loadAutoArchiveSettings` 预描与"读失败不回退"；`toggleFlag` / `saveAutoArchiveDays` 同步快照 |

契约零变化，端点零变化，手机端零影响。

## 验证

- `node --check`：`settings-atoms.js`、`settings-switches.js`、`settings-router.js` 三文件 exit 0（`web/*.js` 不在 `tsc --noEmit` 覆盖里）。
- `bu` 连真服务（PORT 39847，`tsx watch` 只热重载 TS，web 静态文件每次读盘，刷新即生效）：
  - **热路径**：在会话页挂 `transitionrun` 计数（只数 `.switch-thumb`），来回"服务 → 会话"两趟，`transitionRuns = 0`，`aria-checked = true`，thumb 已在位移位（无 hover 时 `translateX=16px`）。
  - **冷路径**（等价于刷新后第一次进这一页，快照为空）：整页重载停在"服务"页，先在 document 上挂计数，再首次进"会话"页 → `transitionRuns = 0`，`checked = true`、`days = 30`。
  - **量具有效性 + 用户点击仍有动画**：点一下开关（关）计到 9 次过渡，再点一下（开）累计 13 次，终态 `checked = true`（`agent-flags.json` 已核对回到 `"true"`）。
  - 控制台 0 error；`data-no-anim` 无残留。
- 没跑：全量 `test`、`pnpm --filter @lifediary/server settings` 探针——本次只动三处选择器的绘制时序，不碰 flags 读写与 HTTP 契约。

## 这条会怎么错

- **快照只活在"一个页面进程"里。** 整页刷新后第一次进这一页，仍有一帧"关 → 开"的**瞬时跳变**（已无动画，但位置会跳一下）。要彻底没有，得把最后一次回读值落 `localStorage`；本轮没做：多一个会过期的缓存键，代价比一帧跳变高。
- **读失败时沿用旧值。** 若别的设备改了开关、本地又读不到 flags，界面会停在旧态（改前是停在缺省"关"，同样不准，只是方向相反）。真正要一致，得等 flags 推送或轮询，本轮不做。
- **`setSwitchChecked` 依赖强制回流。** 把开关挪进 `display:none` 的容器里量，回流不保证生效；那种场景要把 `data-no-anim` 保留到可见首帧之后，而不是当场摘。
