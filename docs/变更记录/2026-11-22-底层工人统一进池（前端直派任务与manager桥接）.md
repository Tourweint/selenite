# 2026-11-22 底层工人统一进池（前端直派任务与 manager 桥接）

## 改了什么

1. **前端「新建任务」直接派活**（`web/tasks-create.js`、`web/shell.js`）：
   侧栏「任务」⋯ 第一项改为「新建任务」——弹窗写需求 + 选项目，
   `POST /api/v1/agent/tasks` 直接建票；原来「新建对话」保留为「新建助手对话」。
2. **直派任务端点**（`src/direct-task.ts`、`src/delegation-mount.ts`）：
   预分配单号 → 建 `task-<票号>` 专线 → 写入真 `pi.user` → `startDelegation`；
   缺省强制 `employee=pool`（`DIRECT_TASK_POOL=false` 跟随派活设置）。
3. **任务线程可发话**（`web/task-thread.js`、`web/composer-send.js`、`web/plus-menu.js`）：
   `task-` 会话的输入不再走 `/agent/chat`；跑动中 steer、等回答 / 空闲走
   `/tickets/:id/say`；轮询线程消息，把 mirror 的进度 / 汇报 / 上报补到屏幕。
4. **manager 子单进池**（`src/pool/bridge.ts`、`src/index.ts`、chancellor `employee/pool.ts`
   / `employee/manager.ts`）：宿主起仅 loopback 的 HTTP+SSE 池桥，endpoint/token 经 env
   交给 manager 子进程；子进程的 `createEmployee("pool")` 用 HTTP 客户端投子单。
   上报由池桥读子单 `originConversationId` 转回父单来源会话；取消在无票级控制器时
   回落 `supervisor.abort`。`POOL_MANAGER_BRIDGE=false` 回滚。
5. **manager 子进程的内部模型**（`worker-main.ts` 的 `installManagerInternalAsk`）：
   manager 子进程没有宿主的 `installInternalAsk()`，子单拆单回落 Qoder CLI，
   本机未配置 → `qoder-intl 子进程 ENOENT`，所有 managed 子单 `needs_you`。
   改用 manager 自己的 `models` / `model` 做纯文本完成。实测 managed 子单 `employee=pool`
   且真进池 dispatch / settle。
6. **修三个真 bug**：
   - `workerKindOf` 漏 `"pool"`：宿主传 `employee=pool` 被静默回落 native
     （实测直派任务的任务行全是 native）。
   - `supervisor.postAbort` 打 `/abort`（池服务端是 `/run/:id/abort`）→ 404，
     取消只能等 10 秒断流杀进程。
   - 池 `run.tools` 一路传到 `pool-main` 但没被使用；worker 工具勾选对池不生效。
7. **任务线不跑宿主投影模型**（`src/task-conversation.ts`）：`submitTaskReply` 从
   `type:"input"` 改为写真 `pi.user`（`type:"write"`），不再触发专线投影一轮；
   `defaultRetryRuntime.report` 发现回写目标就是任务线程时跳过“汇报 + 唤醒”。
8. **文案与标签**（`executor-config.ts`、`web/tasks-model.js`、`web/chat-open.js`）：
   池改为「底层 worker 运行时（独立进程）」并排第一；native 改为「旧：每票一进程（回滚用）」；
   任务行 `employee=pool` 显示「池（独立进程）」；任务线程顶栏显示「任务 · 首句」。
   `partners-status.js` 的总管表头刷新加 `task-` 排除——否则名册晚到会把「任务 · …」冲回「总管」
   （浏览器实测抓到）。

## 回滚

| 开关 | 作用 |
|---|---|
| `CHANCELLOR_EMPLOYEE=native` | 全部新单回 native（每票子进程） |
| `DIRECT_TASK_POOL=false` | 直派任务跟随派活设置（可回 native / 外部 CLI） |
| `POOL_MANAGER_BRIDGE=false` | 不起池桥，manager 子单回落 native |
| `WORKER_TOOLS_DISPATCH=false` | 池 / native 都不按勾选过滤，工具全开 |

## 已知边界

- manager 子单的 `modelRoute` 只继承 `baseUrl + keyEnv` 变量名；供应商 key 必须在
  宿主 pool 进程 env 里存在。
- 任务线程只收文字（附件不进池票面）。
- 票在 `planning`（还没起 worker）时发话会提示稍后再发，不做队列缓冲。
- 普通助手会话（`chatKind=worker`）仍跑宿主 Harness；本批“会话进池”指任务线程的执行在池。
