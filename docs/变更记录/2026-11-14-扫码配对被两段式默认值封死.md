# 2026-11-14 扫码配对一直「码已过期」：两段式默认值把单段路封了

> 现象：平板扫电脑 `/pair` 页的码，App 一律提示「码已过期（5 分钟）」，点「换一枚」重扫也一样。

## 根因

| 环节 | 事实 |
|---|---|
| 服务端默认 | `PAIR_TWO_STEP` 默认 `true`（2026-11-10 批28 收紧） |
| 兑换 | `POST /api/v1/pair/redeem` 恒返回 `410 {"error":"two_step_required"}` |
| 手机端 | 只实现单段 redeem，且把 410 一律映射成「码已过期」 |
| 电脑端 | `/pair` 页只出单段码（`pairing.issueCode`），没有两段式的确认界面 |

结论：默认配置下扫码这条路是死的——两端都没有两段式的客户端，接口却把单段关着。

## 处置

- `ts/apps/server/.env` 追加 `PAIR_TWO_STEP=false`（就是批28 里写的回滚开关），重启服务。
- 验证：`/pair/code` 出码 → `/pair/redeem` 返回 **200** 并发放 deviceToken（自检设备已撤销）。

## 遗留

- 两段式（`/pairing/begin` + `/pairing/confirm`）**有接口没有客户端**：确认动作在电脑端，
  deviceToken 是返回给调用方（电脑）的，手机那一侧拿不到。真要上两段式，得先定
  「电脑确认之后令牌怎么交到手机手上」（手输 / 二次扫码），否则别打开这个开关。
