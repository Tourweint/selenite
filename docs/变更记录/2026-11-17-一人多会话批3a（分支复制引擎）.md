## 改了什么

- **`agent/session-transcript.ts`**：`TranscriptMessage.id` 扩到 assistant（含"只有步骤、正文为空"的
  兜底 assistant），带 `author` 的 relay 来信仍不给 id——分叉端点靠这个 id 指定从哪条回答另开一支。
- **`agent/shared.ts`**：新增 durable 文档 `ChatOrigins`（对外 id → `{source, sourceTitle?, at}`），
  只用于展示与回跳，不参与历史解析；新库旧库走 durable 文档迁移，无 ALTER。
- **`agent/branch-copy.ts`（新）**：纯函数 `planBranchCopy()` 产出复制计划——复制 `0..targetIndex`
  全部条目（不挑 kind）、历史 `usage` 全 0 同形、`pi.compaction.head` 摘掉并记 `headRemaps`
  （复制下标）、丢弃 head 越界的压缩条并计数、超过 400 条 / 64MB 返回 `too_large` 不截断。
- **`index.ts`**：`POST /api/v1/agent/chat/:conversationId/branches`（body `{atMessageId, title?}`）。
  忙态 409、分叉点定位（只认 assistant 且用 `messageIdOf` 精确匹配）、错误码分流；
  **执事**走 `createPartnerSideSession` 在同一人设下建 side 并在 commit 事务里 append 条目 + 写来源；
  **worker / chief** 用 `createConversation` 的 init 同一事务里写 `Chats` / `ChatKinds` /
  `ChatProjects` / `ChatOrigins` 并逐条 append，继承种类 / 项目 / 工作目录 / 当前模型；
  追加时按 `headRemaps` 用真实新 id 回填 `head`。不设 durable `parent`，不改源会话。
- **`scripts/http-probe.ts`** §34、单测 `agent/branch-copy.test.ts`（已加入 test 清单）。

## 为什么（复制口径的取舍）

分叉是"这个人的另一张工作台"，不是新身份：沿用 D29 的 side 底座，就不必重定义人格 / 记忆 /
唤醒规则，也不做"新会话接替主线 + 旧主线 retired"——canonical 永远一条。
durable 没有跨会话引用，所以只能复制历史；`parent` 会让同一段历史在源与副本各出现一遍，
故只在 `ChatOrigins` 记来源。复制不挑 kind（未知 kind 照抄）是为了上下文一致；
历史 usage 清零是因为账按条目扫，复制一份会翻倍；上限与拒绝而非截断是为了不悄悄丢内容。
"head 重映射"实现上选了**返回 `headIndex` 由调用方在事务里回填**（durable 1.4.0 的 `EntryDraft.head`
是条目顶层字段，不是 `data.head`；已按 d.ts 核实），纯函数不碰 append。

## 复核修正（批3a）

复核发现两处内核语义没接住 + 一处错误码误导，已定点修正：

1. **`edits[].target` 重映射**：`ContextEdit.target` 是源会话的旧条目 id，原样抄到新会话对不上，
   上下文覆盖会静默失效。`planBranchCopy` 现在浅拷贝 `edits` 与每个 edit，`target` 用 `indexById`
   换成复制下标并暂时摘掉，记进新字段 `editRemaps`；目标不在复制范围就丢掉该条 edit，过滤后为空则删 `edits`。
   `appendBranchEntries` 追加前克隆 `draft.edits`，按 `editRemaps` 回填真实新 id；目标尚未分配就删该条 edit
   （不改计划对象）。
2. **真实 compaction 的前向 head = 显式展平**：内核 `head` 指向 compaction **之后**的 first kept entry，
   是前向引用——追加到它时目标还没落库。`planBranchCopy` 遇 `headIndex >= index` 直接删 head、
   不记 `headRemaps`，另计 `flattenedCompaction`；只有后向引用（历史 / 合成数据）才走回填。
   副本里 compaction 退化为普通摘要条目（`model: [UserMessage(<summary>)]` 照常进上下文），
   上下文与源等价；未来再压缩会重新折叠。`index.ts` 日志带上展平条数。
3. **插件关时执事分支错误码**：`POST /branches` 判定 `isPartnerLine` 后若 `!sideSessionsEnabled()`，
   返回 `400 {error:"side_sessions_disabled", message:"副会话已关闭"}`；不再落到
   `createPartnerSideSession → null → 409 partner_inactive`（误导成执事不可用）。

补单测 3 项（前向 head 展平 / edits 重映射 / edits 目标越界丢弃），原有 5 项继续过。
验证：`pnpm typecheck` 通过；`pnpm --filter @lifediary/server test` 既有 5 红照旧、新增全过；
`pnpm --filter @lifediary/server http` §34 仍全绿（tool-usage 1 红无关）。
