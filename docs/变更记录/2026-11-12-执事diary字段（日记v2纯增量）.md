# 2026-11-12 执事 `diary` 字段（日记 v2 纯增量契约）

## 背景

手机仓 2026-11-12 拍板日记 v2：不立「小记」内置角色，用户建一个普通执事、把它标记成日记执事；
日记 = 这个执事对话里用户的原话按天归档。手机侧需要服务端能标记/查询「哪个执事是日记执事」。

## 改动

- `ts/packages/shared/src/index.ts`：`PartnerProfileSchema` 加可选 `diary: boolean`。
- `ts/apps/server/src/partners.ts`：
  - `partners` 表加 `diary INTEGER NOT NULL DEFAULT 0`；旧库 `PRAGMA` + `ALTER TABLE` 补列。
  - `PartnerRow.diary`；`toPartner` 映射。
  - `setDiary(id, enabled)`：置 true 时**同一事务**把其他执事的 `diary` 清 0（全局至多一个）。
    用显式 `BEGIN/COMMIT/ROLLBACK`（node:sqlite 的 `DatabaseSync` 没有 better-sqlite3 的 `db.transaction`）。
  - **不版本化**：不 bump `partner_versions`、不动 SOUL / 契约、不参与派活路由。
- `ts/apps/server/src/companion-api.ts`：`PATCH /api/v1/partners/:id` 接 `diary`。
  - 非布尔 → 400 且整批不写（与 tagline 同一套「先校验后写」纪律）。
  - 列表 / 详情投影都带 `diary`；PATCH 响应回显一份。
- `docs/基线文档/接口文档.md` §2.11：建档/列表/PATCH 行与字段说明补口径。

## 验证

- `pnpm typecheck`：通过。
- `npx tsx --test src/companion-api.test.ts`：**13/13 通过**，新增用例覆盖
  「置 true 全局唯一（甲自动清）→ false 取消 → 省略不改 → 非布尔 400 且同批 name 不写」。

## 不做

- 不提供「按 diary 查执事」的专用端点：手机拉一次 `GET /partners` 自己找 `diary=true`
  （列表很小，零新增查询面）。
- 不在 POST 建档时接 `diary`：先建出来再在编辑页切，避免「建的时候开了但没带上」的假象。
- 不改 `routine`（定时任务）契约：那是另一侧的批。
