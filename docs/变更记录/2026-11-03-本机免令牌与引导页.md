# 2026-11-03 本机免令牌与引导页

## 改了什么

- 鉴权新增「本机页面凭据」：从 loopback 打开 `/` 时下发一枚进程内 `lifediary_local` cookie
  （HttpOnly、SameSite=Strict）；来自 loopback 且带这枚 cookie 的 `/api/v1/*` 请求直通。
  桌面壳、本机浏览器不再要求手填 `AGENT_TOKEN`；跨设备/远程访问仍需令牌。
- 令牌门去掉「取消」（原按钮实际等于跳过），只保留「保存并继续」，输入框加 `required`。
- 令牌门文案改成说明「本机打开不需要它」；同一组输入/按钮统一为 40px 高、`--r-md` 圆角。
- Web 页面面向用户显示的应用名统一为「阿月」：`<title>`、侧栏品牌名、设置页「关于」行；
  内部 storage key、包名、路径不动，`desktop/` 不碰（另一会话在改）。
- 侧栏顶部去掉「阿月」品牌行，直接是段标题「对话」；其下「新对话」改成 cindy 风格的 32px 胶囊行
  （透明底、左对齐图标+文字、hover 变底色），不再是宽按钮。结构：`对话` → `新对话` → 历史列表。
- 修复「双击壳仍弹令牌门」：根因是 8082 上还跑着 16:22 启动的旧进程（旧鉴权代码，`/` 不下发本地 cookie，
  且配了 `AGENT_TOKEN` 时连 loopback 也要求 Bearer）。壳探活成功后会复用已有服务，所以新代码根本没生效。
  已停旧进程并用新代码重启 8082；壳本身加载的是 `http://127.0.0.1:8082`，路径无问题，重连/重开即可。
- 契约与机制同步到 `接口文档.md` §1/§6、`系统架构.md` 模块表/D1；
  取舍见 `docs/设计方案/2026-11-03-本机自动连接与令牌门.md`。

## 为什么

用户首次进入被要求填令牌，但令牌只对跨设备有意义；本机桌面壳与服务同机，
不应把无必要的门槛改成必填。去掉「跳过」的同时，必须让本机真正自动连上。

## 验证

- `node --check ts/apps/server/web/app.js`
- `pnpm typecheck`（`ts/` 下）
- `pnpm --filter @lifediary/server test`
- 起服务并设 `AGENT_TOKEN`：
  - 不带 cookie 请求 `/api/v1/agent/chats` → 403 空体（curl/探针仍受保护）
  - 先取 `/`（拿到 `Set-Cookie: lifediary_local=…; HttpOnly; SameSite=Strict`）再请求 → 200
- 浏览器打开 `http://127.0.0.1:8082/`：无令牌门；侧栏顶部是「对话」+「新对话」，无品牌行。
- 桌面壳（WebView2，加载 `http://127.0.0.1:8082`）：刷新后无令牌门，对话正常显示。
- 2026-11-03 实测确认：旧 `8082` 进程不返回 `Set-Cookie`（旧代码），这就是壳里弹门的直接原因。

## 明确没做

- 未改桌面壳 Go 文件与托盘。
- 未改 `AGENT_TOKEN` 的生成方式。
- 未处理既有问题：`AGENT_TOKEN` 为空时 loopback 无条件放行，而 CORS 是 `origin: *`；
  这是改动前就存在的风险，本次只在配了令牌的路径上加 cookie，不扩大也不顺手重构。
