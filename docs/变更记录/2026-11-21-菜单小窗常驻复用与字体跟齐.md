# 菜单小窗常驻复用与字体跟齐（点 ⋯ 立刻开）

**日期**：2026-11-21　**范围**：`desktop/popovers.go`、`desktop/main.go`、`desktop/popovers_test.go`；契约不动（桥上方法与载荷一字未改）。

## 用户报的两个毛病

1. **侧栏 ⋯ 点开要等一会儿**：「字体或者排布局之类的东西需要加载……有时候点一下，它就不能立刻加载……是每次重新读取，还是其他方式？最好做个小缓存。」
2. **「有时候点一次，形态不是很好看，风格也不太统一」**。

## 根因（都查实了）

- **不是每次重新读数据**：菜单项是页面里现成的，点开就整包传给壳，没有网络 / 存储读取。慢在**壳这边每次点开都 `NewFlyout` 新建一张独立小窗**——建窗、起 DirectComposition 表面、FitContent 量内容再改尺寸、首帧绘制；第一次还额外冷启动字体管线（DirectWrite 字体枚举 + 字形栅格化，全进程一套 `text.Shared()`）。主窗口忙（模型流式输出等）时更明显。
- **风格不统一**：全应用是「纸感宋体」（`--font` → Windows 落 SimSun），但 `ui.Text` 不设 Family 画的是**框架默认无衬线**——就弹出层一家跟全应用字体对不上。

## 改了什么

1. **菜单小窗常驻复用（用户要的「小缓存」）**：每个摆位一张常驻小窗（`menuPool`，实际用到 bottom-start / bottom-end 两种）；关闭只 `Hide` 不销毁——框架的外点击 / Esc 收走也走 `OnClose` 拦截（`PreventDefault` + 藏窗 + 放走 waiter）；再开 = 换内容 + `SetAnchor` + `Show`（`fitBeforeShow` 先量新内容再显示，不闪旧尺寸）。建窗成本从每次点击挪到第一次，再由预热挪到启动。
2. **启动预热 `PrewarmMenus`**：主窗建好后预建两个常用摆位的窗（建窗即触发 `AttachContent` → 框架自己 `go text.Shared().Preload()`），再对种子菜单（各分区 ⋯ / 右键菜单常见字）各 `CapturePage()` 渲一帧——`windowHost.capture` 自带 `runFrame`，隐藏窗也能纯软件光栅化，把宋体 face 与常用字形一次性栅格化进 Shared 图集。窗全程不 Show，页面无感；种子用 CAS 收回，真开了菜单也不冲突。开关关（`LIFEDIARY_NATIVE_POPOVERS=off`）不预建。
3. **字体跟齐**：`popoverFont` 常量 = `--font` 逐值（Songti SC → … → SimSun → Microsoft YaHei），菜单 label / kbd / hint 与提示签文字都显式 `.Font(popoverFont)`。

## 状态机要点（错一层就「新菜单秒关」）

`menuNow`（当前那张：窗 + 本次应答通道）用 CAS 收放：三条收起路（框架 OnClose / 行选中 menuPick / 页面导航 ctx.Done）都汇进 `dismissMenu`，**只收自己还「在位」的那张**——并发的下一次 ShowMenu 会复用同一张窗、换上自己的新 waiter，旧调用迟到的收起不得误伤（`TestDismissMenuGuard` 钉住）。

## 验证

- `go vet` / `go test ./...` 全绿（`-count=1` 重跑弹出层五测：开关、摆位白名单、色板、menuView 无窗口真渲染、收起状态机）。
- `go build` 到临时目录编译通过（正式 `lifediary-shell.exe` 被运行中的壳占用，重编需先退出壳）。
- **未验（如实写）**：真机手感——复用窗的 `fitBeforeShow` 重排版、OnClose 拦截在真实外点击 / Esc 下的行为、宋体 600 伪粗观感、预热帧对启动耗时的影响。**需重编重启壳后真机点验**；不顺手就 `LIFEDIARY_NATIVE_POPOVERS=off` 回 DOM 旧路。

## 刻意不做

- 提示签（tip）窗的生命周期未动：它批1 起就有「同锚复用」，首帧成本已被预热兜住；要同款常驻化另立一笔。
- 批2 候选（skill-picker / plus-menu / 执行器模型下拉）走同一条 `ShowMenu` 通道，自动吃到本次复用与字体，无需再改。
