# 权限三档收口与恢复归档重叠校验

- 日期：2026-11-20
- 方案：`docs/设计方案/2026-11-20-权限三档收口（完全访问不设限·受限档限读·文件夹重叠）.md`
- 用户口径：只读不用改；在工作区内修改 = 文件读写和查看都只能在根内；完全访问 = 完全不受权限约束；取消归档时冲突要说清为什么恢复不了；多文件夹项目的文件夹重叠要能限定。

## 改了什么

### 1. 完全访问：文件工具不再过路径闸门

- `ts/apps/server/src/path-guard.ts`：`PathGuardInput` 增加 `access`；`access === "full"` 且未开
  `AGENT_FULL_ACCESS_PATH_GUARD` 时直接放行（write / edit / read 三个文件工具）。
- `ts/apps/server/src/agent/lifecycle-harness.ts`：beforeTool 与两处批准后复判都传 `policy.access`；
  复判仍然生效——等审批期间把档位切回受限，批准了也按新档拦。
- 审批轴（`approvalLevel`）与工具黑名单（`blocked`）不动：那是确认策略 / 工具禁用，不是能力边界。

### 2. 受限两档：read 也限根

- `path-guard.ts`：`read` 进受守集合；`read-only` / `no-shell` 下目标路径必须落在已登记根集合内。
- **用户附件例外**：`PathGuardInput.allowedFiles` 命中的文件对 `read` 放行（只按同一个文件判，
  不放开所在目录）；`write` / `edit` 不享受这个例外。
- `ts/apps/server/src/agent/shared.ts`：新增 `noteSessionFiles` / `sessionFilesOf`（进程内、单会话上限 1024，
  超出按插入顺序丢最老的）。
- `ts/apps/server/src/index.ts`：`/chat` 在 `start` 之后把当前消息的 `assembled.value.files`
  与上行历史 `content` 里的 `type:"file"` 路径记进会话白名单。服务重启后由下一次上行的历史重新补齐。
- 回滚：`AGENT_READ_PATH_GUARD=0/false/off` → read 回到“不过闸门”。

### 3. 恢复归档前逐根复核重叠

- `ts/apps/server/src/project-store.ts`：`setArchived(id, false)` 在翻位前调 `assertRestorable(id)`；
  对项目的每个根跑 `assertRootPathAllowed`（与新建 / 加根 / 改路径同一套规则），任一冲突即整单拒。
- 冲突统一抛 `ProjectError("restore_conflict", "无法恢复项目「A」：文件夹「x」……", 409)`；
  服务端 message 说清跟哪个项目、哪个文件夹冲突，界面沿用 `doProjectAction` 的 toast 显示 message。
- 目录不存在 / 不可达的根跳过校验（它本来就不进根集合，恢复后项目卡会提示「目录不在」）。
- `ts/apps/server/src/project-types.ts`：新增 `projectRestoreOverlapCheckEnabled()`；
  `PROJECT_RESTORE_OVERLAP_CHECK=false/0/off` 可跳过复核（回滚开关，只认 env）。
- **多文件夹项目**：比对单位是“根”不是“项目”，项目的每个根都和所有活跃项目的根两两比；
  这次没有新增项目级概念。归档项目不参与重叠校验（既有口径），恢复时把缺的那次校验补上。

### 4. 文案

- `web/settings-router.js`、`web/settings-permission.js`：三档副文改成
  “查看也限工作区和项目里”“完全访问 = 文件读写和命令都不受工作区限制”。
- `tool-capability.ts` 的 read 注释同步（原文写“边界由 path-guard 之外的语义兜”，实际没有）。

## 还有哪些不确定

- 附件白名单是进程内缓存：服务重启后，如果客户端下一次上行不带历史附件路径，老附件在受限档下会读不到。
  正常客户端每次上行带 `messages` 历史，会补回；这一点没有做跨重启持久化。
- `read` 只是“文件工具”这一层：技能正文走 `skill` 工具（不过这道闸），技能目录本身不因受限档被挡住。
- 完全访问下 `bash` / `powershell` 仍不扫命令文本（既有已知边界，本次未动）：cwd 在根内，
  命令里写绝对路径仍可逃逸，靠审批兜底。
- 历史脏数据（2026-11-20 前通过“归档→登记子目录→恢复”造出的嵌套活跃项目）不会自动清理；
  恢复入口之后不会再新增。需要的话另立审计 / 修数据专项。
