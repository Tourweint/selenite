# 2026-11-24 命名统一（深检索 → 向量检索）+ 旧库兜底

**方案**：`docs/设计方案/2026-11-24-外部记忆库向量检索与检索超时.md`（文件名保留；正文已随本批改为
`vector` / 向量检索，文首注明）。本批是**纯改名 + 一条异常兜底**：配置字段 `deep` → `vector`、
argv `--deep` → `--vector`，默认行为与改名前逐字节一致（向量检索默认关）。

**范围**：只动「深检索」这条链路。**不动**工具描述与注册顺序（prompt cache 资产）、
不改 JSON 输出形状、不改两档超时语义、不做 `deep` 别名 / 迁移。

## 改了什么

### 1. 改名（deep / 深检索 → vector / 向量检索）

| 文件 | 改动 |

**兼容口径**：`external.deep` 是刚落地未发布的过渡字段，**不做别名**。读配置时旧 `deep` 直接忽略
（`vector` 按默认 `false`）；`.data/memory-bank.json` 目前（2026-11-24 审计）没有该字段，不需要迁移。
`PUT /bank/external` 不带 `vector` = 按未勾处理（false），与旧行为一致。
（写回保留"同一库 external 行上的未知扩展字段"是既有设计，所以旧 `deep` 若真出现在文件里会被原样留在
盘上，但不参与任何语义判断；删掉它不影响行为。）

### 2. 旧库兜底（`persona-ask.ts`）

命中条件（全部满足）：

- 本次调用是 `vector: true`；
- 子进程**非超时**失败（超时分支 `timedOut=true`，不重试）；
- 退出码 **2**；
- stderr 命中 argparse 参数拒绝特征之一：`unrecognized arguments` / `unknown option` /
  `invalid option` / `usage:`。

行为：

- 自动用**不带 `--vector` 的同一命令**重试**一次**（同 limit / question / 超时预算）；
- 结果照常返回，并带 `vectorUnsupported: true`；
- 日志一行：`[persona-ask] 库不认识 --vector，已改用普通检索`；
- 工具层不把 `vectorUnsupported` 当失败（重试成功即 `ok:true`），只在 `[recall]` 日志留痕。

**不重试**：超时（避免多等一个 timeoutMs）、其它退出码 / 启动失败 / 结构不符 / JSON 解析失败。
**只重试一次**：重试结果（无论成败）直接返回，不再判断。
