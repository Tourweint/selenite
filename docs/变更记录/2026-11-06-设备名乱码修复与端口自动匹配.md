# 设备名乱码修复（中继改名端点）+ 手机端口自动匹配

日期：2026-11-06
类型：缺陷修复 + 手机端自愈能力（真机/模拟器联调发现的两个问题）

## 问题一：手机上设备名乱码

**根因**：联调时用 Git Bash 的 `curl -d` 直发中文设备名——Windows 下 curl 按 GBK 处理
命令行参数，UTF-8 字节被写坏进中结名册（`锟斤拷` 系列双编码乱码）。数据是坏的，不是
App 显示问题。

**修复**：
- 中继加改名端点 `POST /api/relay/devices/:id/name`（owner 或该设备自己；≤40 字截断；
  `store.renameDevice`）；`RelayApi.renameDevice` 手机侧同补（对齐 setHomeDevice 语义）；
- 数据修复：以 Python（UTF-8 安全）调用改名端点，字节级核对名册恢复「书房主机」/「vivo手机」；
- **预防规矩**（已写进 接口文档.md 中继节）：Windows Git Bash curl 直发中文会 GBK 化，
  联调发中文 JSON 一律走 Python/Node 客户端。

## 问题二：服务换端口后手机静默失联（要手动改地址）

**根因**：手机存的 `serverBaseUrl` 是死的——服务第 7 轮把 8082 改成 39847 后，存量手机
配置静默失效（`overview` 全部失败，多端分区消失，用户无从下手）。

**修复（端口自动匹配 + 自愈落盘）**：`ConnectionViewModel.refreshRelay` 在 overview 失败时，
按已知端口候选（39847 现行 / 8082 遗留）用免鉴权的 `pair/info` 探测，探到能用就用该地址
拉取数据并**写回偏好**——一次自愈，聊天/审批/日记同步全部跟着修好。`relayPortCandidates`
纯函数只换端口、当前端口排除、解析不出返回空表（不碰奇怪输入）。

## 验证

- harness：typecheck 0 错；改名端点字节级核对（`书房主机`/`vivo手机` 正确入库）；
- 手机：单测全绿（`RelayPortCandidatesTest` 6 条）；spotless 过；debug/release 双包构建过；
- **模拟器实测自愈回环**：设置页故意存回 8082 → 保存 → 抽屉刷新 → `overview` 自动探到
  39847 → 落盘值已变 39847（run-as 读偏好核对）→ 设备页名字/主机位/描述全部正确渲染；
- 真机 release 包已构建好待装（真机中途锁屏拔出；装包口令不变）。

## 回滚

改名端点与自愈逻辑各自独立：自愈出问题删 `refreshRelay` 里的候选循环即回旧行为
（存什么用什么）；改名端点不动名册结构，无迁移。
