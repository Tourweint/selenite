# lifediary-harness

**一个人的通用 Agent。** 跑在自己机器上：模型、记忆、会话、密钥都不外流。

记录（日记、流水账、随手的想法）是它用得最多的场景，但**不是它的边界** ——
同一个 Agent 也能读文件、翻历史、按你的要求动手把事情做完。

手机端是独立仓库的原生 Android 工程（Kotlin + Compose），通过 HTTP + SSE 连过来。

## 定位

| | |
|---|---|
| **通用**，不是某个 App 的后端插件 | 今天记一整天，明天整理文件夹、查资料、跑个命令，用的是同一个 Agent 和同一份记忆 |
| **个人**，不是平台 | 一个用户、一台机器、一份数据。不做多租户、不做账号体系、不做计费 |
| **自有** | 记忆、会话、密钥全在本机；换模型只改一行 env |

「记录」是重点方向，因为它决定了三件事，而这三件事对通用 Agent 同样成立：

- 记忆要按**时间**切分（不是按项目）
- 工具要能**写**（只读的 Agent 记不下东西）
- 交互成本要**极低**（随手一句就能记，否则没人用）

## 结构

```
ts/

```

## 工具与信任

已注册 6 个工具：

| 工具 | 能力 | 风险 |
|---|---|---|
| `read_file` | 读文本文件（100KB / 2000 行上限） | 只读 |
| `list_dir` | 列目录 | 只读 |
| `write_file` | 写文件，覆盖原内容 | **不可撤销** |
| `run_command` | 执行 shell 命令（30s 超时） | **等价于你的账号权限** |
| `remember` | 写一条长期记忆 | 可撤回（删库记录） |
| `recall` | 检索旧记忆 | 只读 |

**没有权限闸门。** 这是照 pi 的行为来的 —— pi 本身不带权限系统，
只在 `beforeToolCall` 留了一个钩子给扩展挂策略。

所以这个 Agent 的可信边界等于：**你愿意让自己的账号在这台机器上做什么**。
本地自用没问题；一旦要接 IM 网关、暴露到局域网、或者让它跑无人值守的任务，
这条边界必须重新评估 —— 那时候才需要闸门和审计，现在不用提前造。
