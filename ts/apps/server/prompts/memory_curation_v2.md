# 记忆策展 v2

## 任务

从下面这条**已确认入库**的日记里维护这个人的长期记忆。输出两类动作：

1. **ops**：对已有记忆做 ADD / UPDATE / DELETE / SKIP 决策（mem0 模式）——作用于三块画像（identity 身份 / topics 长期主题 / relations 重要关系）与 recent_buffer（最近缓冲）；
2. **episodes**：情节事实——这条日记里「以后可能有下文」的事（正在进行的计划、项目、约定、提到的具体人物/事件），将来可以追问「上次说的 X 怎么样了」。

## 铁律：Default Deny

**默认不记**。ops 为空数组是完全正常的、甚至是常见的正确结果；拿不准就 SKIP。
只有当你确信这条信息在几个月后仍然有用、且属于这个人的长期属性时，才进 ops。

## 必须排除（ops 与 episodes 都一律不提）

- 一次性琐事（今天买了什么、几点开会、和谁吃了饭）
- 天气、日期、地点流水
- 票号、金额、订单号
- 当日情绪波动（"今天有点烦"）
- 任何会自然过期的事件性信息

## ops 各动作的口径

- **ADD**：出现**新的**长期属性/主题/关系 → `{"op":"ADD","scope":"identity|topics|relations|buffer","text":"…"}`
- **UPDATE**：已有记忆**过时或需要修正** → `{"op":"UPDATE","scope":"…","match":"被替换的原句（原样摘抄）","text":"新句子"}`
- **DELETE**：已有记忆**明显不再成立**（如项目终止、关系结束）→ `{"op":"DELETE","scope":"…","match":"要删除的原句（原样摘抄）"}`
- **SKIP**：无变化（不输出 SKIP，直接不写该条）。
- `match` 必须**原样摘抄**当前记忆里的句子，改写过的 match 视为无效。
- 临时信息、没有变化、拿不准 → 不输出任何 op。

## episodes 口径

- 每条一句完整的话，不超过 40 字，不写日期（日期由系统另记）。
- 与 ops 的区别：ops 记「这个人是什么样」，episodes 记「这个人生活里正在发生什么」。
- episodes 允许比 ops 宽松：只要将来对话里可能自然接上、又不属于"必须排除"清单，就值得一条。
- 没有就输出空数组。

## 输出格式

只输出 JSON，形如：

```json
{
  "ops": [
    {"op": "ADD", "scope": "topics", "text": "在准备一项长期考试"},
    {"op": "UPDATE", "scope": "identity", "match": "在做副业，方向是效率工具", "text": "副业转向日记工具方向"},
    {"op": "DELETE", "scope": "relations", "match": "和老王每周打球"}
  ],
  "episodes": ["约定下周和编辑谈新书大纲"]
}
```

- 没有值得记的就输出 `{"ops": [], "episodes": []}`。
- 不要输出 JSON 以外的任何内容。
