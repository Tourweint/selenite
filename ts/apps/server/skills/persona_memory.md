一生记忆检索：查很久以前的事、要原文出处时，用 persona_recall 的证据包，不靠猜

用途：本地 `recall` 只覆盖最近与偏好；问到去年、2024 年、某个人、某段经历、某个决定的来龙去脉，
或者对方要“原文出处”时，用 `persona_recall` 查主人的长期记忆库（persona-metric 的 `ask.py`）。

一、先分清该查哪边
- 最近几周、偏好、习惯、当前在办 → 先用 `recall`。
- 很久以前、跨很多年、要证据 / 出处 / 当时原话 → 用 `persona_recall`。
- 两边都可能有：先 `recall`，不够再 `persona_recall`，不要一上来就查大库。

二、怎么问（一次只问一件事）
- 一次调用只放一个问题。不要在一句里塞“我 2024 年为什么换工作、后来又怎么学编程、家里怎么看”。
- 把时间、人物、项目名放进去，`ask.py` 会自己解析时间窗：
  - “2024 年秋天我在忙什么”
  - “毕设怎么一步步做出来的”
  - “我妈住院那阵子”
  - “我是什么样的人 / 别人眼里我什么样”
- 查不到就换一个锚点再查一次（换时间、换人名、换项目名），最多两三次；不要连续猜十条。

三、怎么读返回
`persona_recall` 返回六组证据，按这个顺序看：
1. `memory_day`：某一天的日记忆（先建立时间感）
2. `event`：事件与弧线（立场→触发→新立场）
3. `fact`：长期事实（偏好 / 身份 / 行为模式）
4. `segment`：原文片（最细的证据）
5. `entity`：人物 / 项目
6. `tension`：张力对（什么情况下会切到另一面）

重点看返回里的 `coverage` / `unknown` / `gaps`：
- “没查什么 / 没入库什么 / 缺哪几个月”要说出来，不要当成“没有这回事”。
- 六组全空时，明确说“这个库没查到”，并给一个更窄或更宽的下一问；不要编。

四、怎么答
- 先说结论，再给时间与证据；能用日期 / 年份 / 人物串起来就串起来。
- 引用原文片时给 `segment` 的 id 或日期，方便对方回查；不要伪造 id。
- 别人的话只转述意思（库里存的是释义），不要假装是原话。
- 不要把 `persona_recall` 的结果和本地 `recall` 混成一条；哪条来自哪个库，心里要分清。

五、边界
- 群聊 / 别人的私聊不走个人记忆库；群里的内容以群聊记录为准。
- 这个库是只读的；不要试图通过 `persona_recall` 写回或改库。
- 查库失败（工具返回 `persona_unavailable`）时，如实说“暂时查不了”，先用本地记忆回答能回答的部分。
