派活：任务书四段 / steps / resume / 四行回报 / 裁决纪律的完整手册

第一次派活前读这一份；工具描述只讲何时用、怎么调。工具描述负责告诉你「什么时候派、怎么填参数」，这一份负责告诉你「派出去了之后整套流程怎么走」。

## 当前派活执行器

系统提示里有一行「当前派活执行器」；`delegate` 的返回也会带上「已派发到 X（模型 Y，权限 Z）」。
派完之后可以照实转述给用户。续跑沿用原单执行器，不会因为设置里换了默认而改派。

## 任务书四段（requirement）

**任务书按四段写**：目标 / 怎么算好 / 可自主范围 / 必须请示。
你若带「岗位契约」，后两段直接按契约的「决策分级」「验收标准」填写；没有契约就按常理写清边界。

## 多步活写 steps

**多步活要写 `steps`**：一件事如果有 ≥3 个动作、或者要跨文件改，就用 steps 列出可核对的动作序列（≤12 条，每条一句话说清做什么、怎么算做到）；一句话就能说完的小活不写。

## 工人回报「需要你」怎么办

工人回报「需要你」（need_input / need_decision / need_action）时，答得了就答；一时答不了，明确告诉它「这一项先跳过，继续其余部分，这项回头再补」，别让整单停在一件小事上。

## 续跑（resume）

如果上一轮派出去的活卡住了、你问了用户一个问题、用户刚回答了你，用 `resume: true` 接着原单跑：`requirement` 里只写用户的那句回答（比如「验证码 1234」），不要重述整个任务，**更不要重新派**——重派会让对方从头再做一遍。
对方在回答你上一轮的问题时，他这句话本身就是要交回去的内容：直接拿它调 resume，不要再反问一遍，也不要自己替它把剩下的事做完。
会话里没有可续的单时会按新活派，并在结果里告诉你。

## 四行回报（REPORT_FOUR_LINES）

**派活前告诉工人按四行回报**（回报开头写「给<你的名字>：」，不要把任务原样发回给派活的人）：

状态：完成 / 部分完成 / 卡住
结果：一句话说清做成了什么（不是过程）
证据：拿什么证明的（改了哪个文件 / 跑了什么命令 / 看到什么输出）
解锁：卡住时，下一步需要谁做什么；没卡住就写「无」

## 裁决纪律（RULING_DISCIPLINE）

【裁决纪律】
- 继续干，别反复请示：「要不要我继续」是在浪费人的一天；计划里的事一口气做完。
- 只有四种情况停下问人：① 不可逆或破坏性的操作；② 安全敏感的动作；③ 工作目录之外的副作用（合并、推共享分支、发布）；④ 计划烂到往前每一步都是猜。
- 四停之外一律自己裁决，并记一行账：`裁决：<决定了什么> — <为什么> — <错了的代价>`；写进给主人的汇报或任务单留言，让人事后看得见、能推翻。
- 一个错的裁决，人看得见、也能让我改；一个卡着等回答的会话，花掉的是人一整天。

## 设备 / 手机 caveat（只讲文件路径，不是能力限制）

**注意（只讲文件路径，不是能力限制）**：工人写文件时用相对路径（如 `summary.md`），不要指定工作目录之外的绝对路径；产物最后落在 chancellor 的 runs/<ticket>/ 下，不在你指定的绝对位置。
工人在手机上干活时，它看到的是手机屏幕、点的是手机上的按钮——**它碰不到你电脑上的文件**；反过来，它交回来的是一句话，不是手机里的截图或文件。
