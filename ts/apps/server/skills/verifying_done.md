验证完成：这一轮没真的跑过，就不能说完成了

铁律：没有在这一轮里真的跑过验证，就不能说「完成了」「改好了」「应该没问题」。
上一轮的通过结果不算，别人说通过了也不算，看代码觉得对更不算。

五步，按顺序走：

1. 认清要验什么
   - 把要说出口的那句话拆成可核对的事实。「文件整理好了」= 目标文件夹里有这些文件、数量对、能打开。
   - 一次只验一句话；说过三句就拆成三次验。

2. 真的跑
   - 用和用户相同的方式做一遍：打开那个文件、走一遍那个流程、重新导出一次。
   - 不能只看生成过程没报错，要看最后拿到的结果。
   - 验证要留下痕迹：输出文字、截图、文件清单、条数，任选能复查的一种。

3. 读输出
   - 逐行读，不要只看最后一行。注意警告、跳过、0 条、空结果。
   - 数字对不上就是有问题，不要用「大概」「差不多」盖过去。

4. 对账
   - 拿实际结果和计划里的验收标准一条条对：过 / 不过，不过的写原因。
   - 只对了一部分就说「验了哪几条、哪几条没验」，不要说成全部通过。

5. 才敢说
   - 全部对上才说完成。有没验的部分，明确说没验。

主张 ↔ 证据对照：
- 说「整理好了」→ 要有目标目录的实际清单（文件名 + 数量）。
- 说「文字改对了」→ 要有改后的原文片段，且原问题确实消失。
- 说「流程能走通」→ 要有从第一步走到最后一步的实际记录。
- 说「都检查过了」→ 要有逐条结果，不是一句总结。

红旗（出现任意一条，就是在糊弄，回头去跑）：
- 「应该」「大概」「理论上」「应该没问题」。
- 语气很满意，但说不出刚才具体看到了什么。
- 只描述了改动，没描述改动后的结果。
- 用「之前试过」代替这一轮的验证。
