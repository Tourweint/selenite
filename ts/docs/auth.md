# 鉴权

> 这份文档是 2026-10-28 从 Java 版归档（`docs/基线文档/系统架构.md` D2/D6、
> `接口文档.md` §0）里捞回来的设计，并按"通用个人 Agent"的新定位重新表述。
> 原实现的代码已删除，设计本身仍然有效。

## 一句话

**校验在 harness 本地，后端只负责签发和管额度。** 不是"每个请求都去问后端这个 token 有没有效"。

## 原来的三段式（App → Agent → 后端）

```
App
 │  Authorization: Bearer <JWT>   ← backend 签发，HS256
 ▼
harness（本仓库）
 │  ① 用同一把 JWT_SECRET 本地验签 → 拿到 subject = userId
 │  ② 需要配置/额度时，用 X-Internal-Token 走内网问 backend
 ▼
backend
   · GET /api/v1/internal/ai-config?since=<version>   非秘密的策略参数
   · 扣额接口（先扣再转发，幂等）
```

为什么是"同密钥本地验签"而不是"回调 backend 校验"：

- 每个对话请求都多一跳内网往返，延迟和故障面都变大；
- backend 挂掉时 harness 应该还能用（只要不涉及扣额）；
- JWT 是自包含的，签名一致就能验，没有必须问后端的理由。

**所以严格说：App 找 Agent，Agent 自己验，只有"要用户配置 / 要扣钱"时才找后端。**

## 原来的约束（逐条抄录，仍有参考价值）

| 约束 | 内容 |
|---|---|
| 密钥同源 | harness 与 backend 用**同一把** `JWT_SECRET`；换密钥必须同时换 |
| fail-closed | `JWT_SECRET` 未配置或短于 32 字节 → 一切请求 403 |
| 拒绝形态 | 缺 / 无效 / 过期 → **HTTP 403 空响应体**（和 backend 的 Spring Security 一样，App 不用区分两端） |
| 内部接口 | `X-Internal-Token` 与 backend 同值，只走内网；连接 200ms / 读 1s |
| 配置拉取 | `ai-config` 60s 缓存 + version 增量；失败沿用上次成功值，从不成功则用内置默认 |
| 频控分工 | 有额度的端点靠"鉴权 + 扣额"挡刷量；无额度的端点（如信号评估）才按 IP 限流 |

这套东西的服务对象是**多用户 SaaS**：要区分"是谁"、要管"有没有钱"。

## 现在该怎么做

新定位是**一个人的通用 Agent**：单用户、跑在自己机器上。鉴权的目标变了 ——
不再是"区分用户"，而是"**挡住局域网/公网上的陌生人**"。

分两档，按需要往上走：

### 第一档：单用户静态令牌（现在够用）

```
App  ──Bearer <自己设的 AGENT_TOKEN>──▶  harness ──▶ 模型
```

- `AGENT_TOKEN` 走环境变量，App 里配一次；调试页用 `http://127.0.0.1:8082/?token=xxx` 打开；
- 校验失败 → **403 空响应体**（口径和上面保持一致，将来换 JWT 时 App 不用改错误处理）；
- 比较用 `timingSafeEqual`，不把令牌长度泄露给计时攻击；
- **没配 `AGENT_TOKEN` 时不裸奔**：只放行本机回环地址（`127.0.0.1` / `::1`），
  其他来源一律 403。这样开发时不用配令牌，但也不会被局域网里的人直接用。

已实现（`apps/server/src/auth.ts`），只挂在 `/api/v1/*` 上；`/`（调试页静态 UI）
和 `/healthz` 不拦。

### 第二档：JWT 同源（接回 backend 账号时）

原设计原样照搬：同一把 `JWT_SECRET`、本地验签、403 空体、`ai-config` 与扣额走
`X-Internal-Token` 内网。

切换成本低，因为第一档已经把"403 空体"这个口径固定下来了。

## 什么时候必须做

| 场景 | 需要哪档 |
|---|---|
| 只在 `127.0.0.1` 自用 | 已默认保护（本机回环自动放行，其他 403） |
| 手机在同一个 Wi-Fi 里连电脑 | **第一档，必须**（不配令牌，手机连不上） |
| 接 Telegram / IM 网关 | 第一档 + 网关侧自己的鉴权 |
| 部署到 VPS、多用户、多设备 | 第二档 |

## 和记忆绑定的一件事

会话是**按 `conversationId` 落盘**的（`.data/sessions/*.jsonl`），而 `conversationId`
目前由客户端传。**没有鉴权的现在，拿到 id 就能读到别人的历史。**

接入第一档后，要么把 `conversationId` 和令牌绑定（一个令牌对应一个人），
要么改用服务端生成的 id + 令牌校验归属。这件事要在做鉴权时一并做掉，别分开做。
